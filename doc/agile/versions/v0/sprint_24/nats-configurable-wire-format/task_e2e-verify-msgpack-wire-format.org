* Goal

With every layer migrated onto the injected =wire_codec=, flip a test
environment's =.env= to =ORES_NATS_WIRE_FORMAT=msgpack= and verify
round-trip correctness end to end: Qt client to service, and shell
client to service, across a representative spread of message types
including the image-batch flows that originally surfaced this whole
investigation. Confirms the
[[id:77F77107-23CE-46B4-B51E-F7DBAC742C3D][raw-bytes-not-base64-for-images]]
task's goal is achieved for free -- =reflect-cpp='s =msgpack= writer
already packs =std::vector<uint8_t>= as native binary, no custom code
needed.

Record the =.env= config knob in the relevant How-do-I recipe so
switching format is discoverable, and abandon the superseded
raw-bytes task at this story's close (already marked ABANDONED with a
pointer here; confirm and finalise).

* Notes

Discovered during the [[id:12674934-6F8E-40C9-A8D7-ED29B0ADF322][ClientManager migration task]]'s live msgpack
smoke test ([[id:E0570F22-B925-4BCF-BB1F-48F74BC04278][test scenario]]) -- fix before or as part of this task's
own environment-wide msgpack pass:

- =ores.iam.client::service_token_provider= hard-coded =rfl::json=
  for every service's self-authentication at startup (a universal
  blocker: no service could even authenticate under =msgpack=, let
  alone serve requests). *Already fixed* in the ClientManager task's
  commit, migrated onto =ores::nats::default_wire_codec()= -- verify
  it stays fixed, don't re-discover it.
- =ClientManagerTradeInstrument.cpp='s decode side
  (=parse_trade_instrument()=, in =ores.qt.headless=) is still
  =rfl::json=-only -- a JSON-specific two-phase parser that would
  fail under =msgpack= (request/response format-mismatched). Needs
  its own migration (swap the =rfl::json::read<T>= calls in
  =try_parse<T>()= for =ores::nats::default_wire_codec().decode<T>()=,
  which should work unchanged for the two-phase peek-and-reparse
  technique) before =getTradeInstrument()= works under =msgpack=.
- A repo-wide sweep (=grep -rl rfl::json ... | xargs grep -l
  request_sync=) found more service-to-service NATS call sites
  bypassing =handler_helpers=, outside every completed task's audited
  file list: =ores.iam.core/service/cache/party_cache.hpp=,
  =ores.iam.core/messaging/tenant_handler.hpp=,
  =ores.marketdata.client/crm_client.cpp=,
  =ores.refdata.client/service/cache/currency_pair_convention_cache.hpp=,
  =ores.reporting.core/messaging/report_definition_template_handler.hpp=,
  =ores.trading.core/messaging/trade_handler.hpp=. Each needs the same
  =default_wire_codec()= migration; none block =json= (today's
  default), but any one of them left unmigrated will break under a
  full-environment =msgpack= switch. Grep for =rfl::json= combined
  with =request_sync=/=nats_.request_sync=/=\.request_sync(= across
  the repo again once these are fixed, to confirm the sweep is clean
  before declaring this task's acceptance criteria met.
