* Acceptance

- A report run has a read the BFF serves and a page the job page links to.
- A batch that the shell dispatched states that no report is behind it.

* Plan

The reporting service reads a run by id through its list filter =id_one_of=, so no model changes. The BFF serves =GET /api/operations/grid/report-runs/:id= with the run, its health word and the batch that names it. The web gets the page =/operations/grid/report-runs/:id=. The job page links to it when the batch's =external_ref= is an id, and states that no report is behind the batch when it is not.

* Notes

The health word and the batch are decorations. A failed read of either leaves the cell empty and does not fail the page. The operator gets a 404 for a run, because the run belongs to a tenant party. The sample run in the dev database has no state, so the page reads "No word" for it.

* Result

The job page links to a report run page for a batch named by a run id. A batch the shell dispatched says no report is behind it. A live check as four accounts found that the party member and the tenant administrator read the run, the member of another party gets 404, and the operator gets 404. The BFF has six tests for the route and the web has four for the page and two for the link. The TypeScript suites pass.
