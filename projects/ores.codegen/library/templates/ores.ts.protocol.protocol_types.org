Wire payload interfaces and NATS subject constants for one protocol. The
TypeScript twin of [[id:E9A47FBA-7799-4D6B-AD1A-144B2F740F0F][ores.cpp.protocol.protocol_header]]: both render from
the same model, so a field added to one appears in the other.

An operation model declares its messages, and this template renders
them. An entity model declares no messages, so the loader derives its
standard CRUD set in =org_loader.entity_protocol_messages= — the same
messages, in the same order, under the same conditionals as
=cpp_protocol.hpp.mustache='s entity block. The C++ header still renders
from the raw flags, so its output is unchanged; the derived list is the
TypeScript twin's model.

A junction model declares no messages either: the loader derives the generic
relationship protocol in =org_loader.junction_protocol_messages= from the
junction's two sides, their =:list_by:= and =:replace_by:= flags, and the
sides' =:enrich_code:= declarations. It is the entity protocol's shape plus
the relationship verbs: the unscoped paged read, a by-side read per
=:list_by:= side that returns the view, a batch additive =save=, a batch
=delete= by the pair, an opt-in =replace_by_<side>=, a count per side, and
the =<junction>_view= type. The C++ header's junction block states the same
set, so the two twins cannot drift apart on a field.

One exported interface per message, named in PascalCase. Field names stay
snake_case, because they are the JSON keys =rfl::json= writes from the C++
member names.

An entity protocol carries the entity's domain type, so its module
imports the interface =ores.ts.domain= emits for it. An operation
protocol imports the same way when one of its fields names a domain
type: the loader derives the distinct interfaces in
=org_loader.ts_domain_imports=, and the module imports each one. A field
whose C++ type has no TypeScript projection stops the model loading —
see =org_loader._reject_silent_ts_gap= — rather than rendering an
interface with the field missing.

The =subjects= constant collects the NATS subjects a message carries. A
message with no subject — a plain payload such as =party_summary= — gets an
interface and no entry in the constant.

See the [[id:C4E8A91F-3B7D-4F2E-85A6-1D9C7E3B2F4A][Template variable reference]] for the complete list of available
variables and their semantics.
