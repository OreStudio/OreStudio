* Goal

The nightly CDash dynamic analysis stops flagging the NATS C library's
one-time global init blocks (still reachable) on the trading,
reporting and refdata eventing tests, so real valgrind defects stand
out. The triage procedure is captured in a recipe.

* Acceptance

- The three failing components (ores.trading.core.tests,
  ores.reporting.core.tests, ores.refdata.core.tests) run clean under
  valgrind with the committed suppression file.
- Each suppression entry names the library and the cause; entries are
  anchored on the NATS library init so no real leak is masked.
- A recipe documents the suppression file path and the triage
  procedure.

* Plan

1. Classify the CDash dynamic analysis failures: all 54 records (21
   per component) are still-reachable blocks from the NATS C library's
   one-time global init (nats_openLib: dispatcher pool, mutexes,
   conditions, thread structs), reached via
   =ores::nats::service::client::connect()=. Not a leak: the library
   holds live pointers and frees them only in =nats_library_cleanup=,
   which the client layer must not call (global teardown is unsafe
   while other subsystems may still use NATS). CDash flags them only
   because CTest.cmake passes =--show-reachable=yes=.
2. Add one suppression per allocation site to
   =build/valgrind/custom.supp=, =match-leak-kinds: reachable=,
   anchored on =fun:nats_openLib= so any real leak through another
   call path still surfaces. Intermediate frames use =...= (the local
   run showed three stack shapes: allocator direct under
   =nats_openLib=, allocator via =nats_initDispatcherPool=, and pool
   growth via =_growPool=).
3. Create the =How do I fix valgrind errors?= recipe with compass add,
   listing the suppression file path and the triage procedure.
4. Verify locally: run the three failing eventing test cases under
   valgrind with the nightly's exact options and the suppression file,
   NATS server running (port 20605); confirm zero remaining records.

* Result

fix 73a1ad5b6, recipe 32caf593c):

  =nats_initDispatcherPool=, and pool growth via =_growPool=.

  documents the suppression file path, the triage procedure (real
  defects fixed in code; third-party one-time init suppressed), and
  the local reproduction command; wired into the cmake recipe
  inventory.
- Verified: the three failing eventing test cases
  (=write_fx_forward_instrument_publishes_nats_changed_event=,
  =write_report_definition_publishes_nats_changed_event=,
  =write_tenor_anchor_publishes_nats_changed_event=) pass under

  remaining records; without the suppressions the same run flags the
  still-reachable records.
