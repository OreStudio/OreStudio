* Result

The generator is =projects/ores.ore/scripts/generate_xml_bindings.py=, with
=regenerate_xml_bindings.sh= as the lever that invokes it for each family. It
reads the schema and emits both the C++ records and the codec tables, so the
hand-written calendar table is gone and the family is entirely generated.

What it derives from the schema: which complexTypes exist, their order, which
children are elements and which are attributes, cardinality, enumerations, and
which simpleType restricts to which primitive. What it cannot derive, and takes
from this project instead, is what a numeric element *means*: ORE types the
same money concept as xs:float, xs:double and xs:string in three places, so the
money list is an argument rather than a reading.

Verified: the same 7 binding cases pass against the generated records, the whole
=ore xml= suite is 517 cases and 63,550 assertions, and re-running the generator
produces byte-identical output, which is what a drift check will need.

A second family, =currencyConfig=, is generated as well. It is shaped
differently on purpose: an =xs:all= rather than a sequence, an enumeration, and
a repeated child two levels up. It binds the thirteen currency documents in the
corpus, over a thousand currencies in all.

The drift check is =build/scripts/check_xml_bindings_drift.py=. It regenerates
into a temporary root and compares, so a hand edit to a generated file and a
schema change the tables did not follow fail the same way.

The corpus found one real defect in the engine. ORE writes =<Symbol></Symbol>=
for a required element with no value, and the presence bit was set only when
text arrived, so an empty element read as missing. The bit now means "this
element appeared", which is what it was always meant to mean.

Three defects the wiring found, both of the same kind as the earlier ones. The
generated source was not in =component_files.cmake=, so it compiled nowhere.
And the accessor needed the export macro, because the library is built with
hidden visibility and a generated function has no more right to the symbol
table than a hand-written one did.
