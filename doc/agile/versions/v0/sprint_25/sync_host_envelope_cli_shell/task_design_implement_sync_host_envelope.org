* Goal

Extract the shared parse/init-logging/log/try-construct-run/catch-diagnostic
shape common to =ores.cli= and =ores.shell='s =host::execute= into a
new sync sibling of =run_host_async=, parameterised by an
application-construction callable (since neither tool's constructor
is uniform with the other) and an optional early-exit hook (for
cli's DB-free =ore_roundtrip= branch). Rebuild both tools' =host.cpp=
on the new helper without changing observable behaviour.

* Plan

Added =ores.service='s =run_host_sync= (=host_runner_sync.hpp=/=_impl.hpp=),
a template sibling of the existing async =run_host_async=, in the same
component so both live next to each other:

- Signature: =run_host_sync<Parser>(args, std_output, error_output, lg,
  early_exit, run_application, opts)=. =early_exit= is a callable
  =(const cfg&) -> std::optional<int>= run *before* the try/catch, so a
  handled branch never goes through the generic failure-log path — this is
  what keeps =ores.cli='s =ore_roundtrip= branch's own "Roundtrip error:"
  logging isolated from the generic "Error:"/"Failed to execute command."
  pair, preserving its current behaviour exactly. =run_application= is a
  callable =(const cfg&) -> void= that owns application construction and
  the run() call — deliberately *not* unified across the two tools, since
  =ores.cli='s constructor takes an output stream + database options while
  =ores.shell='s takes NATS/login/script options.
- =ores.cli/app/host.cpp=: =early_exit= wraps the roundtrip branch verbatim
  (same try/catch, same output formatting); =run_application= constructs
  =application(std_output, cfg.database)= and calls =app.run(cfg)=.
- =ores.shell/app/host.cpp=: =early_exit= is a no-op lambda returning
  =std::nullopt=; =run_application= constructs
  =application(cfg.connection, cfg.login, cfg.script_path)= and calls
  =app.run()=.
- Both tools now link =ores.service.lib= (previously unused by either);
  wired via =target_link_libraries= in each =src/CMakeLists.txt=, and the
  two new headers added to =ores.service='s =component_files.cmake=
  (regenerated via =regenerate_cmake_component_files.py=, no drift
  elsewhere).
- Verified via full rebuild of =ores.cli.exe=/=ores.shell.exe=/
  =*.tests= and running both test binaries against the local DB:
  =ores.cli.tests= 382 assertions/119 cases passed, =ores.shell.tests= 80
  assertions/26 cases passed — both unchanged from pre-refactor baselines,
  confirming no behavioural change.
