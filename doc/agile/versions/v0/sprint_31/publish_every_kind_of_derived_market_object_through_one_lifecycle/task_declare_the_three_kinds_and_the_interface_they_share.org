* Goal

* Acceptance

- The declaration names the subject, the compute, the checks and the two approval kinds, and the three kinds declare theirs in one place each.
- The interface carries the four facts the lifecycle needs from a kind, and no step of raise, apply, supersede or notice reads a kind code.
- A test proves that a kind which declares no withdrawal kind is refused a withdrawal, and that the refusal names the kind. The shared raise calls it in the next task.

* Plan

The declaration is data and the interface is the seam the shared lifecycle calls.
This task fixes both, and the next task builds the acts over them.

The declaration is one row per kind: the publish approval kind, the withdrawal
approval kind or none, and the table its subject part lives in. The array is the
only place a kind is named, and the kind codes are the constants the handlers
already pass to =raise_permission_of=, so a rename reaches the declaration
without a second edit.

The interface carries the four facts of the acceptance, and each is per-kind code
today, sitting inside its own service:

| Part | What the lifecycle needs from the kind | Where it lives today |
|------+----------------------------------------+----------------------|
| Subject | Resolve a party, a subject and an as-of into the subject and its output series, refusing another party's subject | =resolve_publish_subject= for a curve; the forward ladder's pair and curves; the surface blueprint |
| Compute | Compute a candidate for a subject at an as-of, and store it with its checks | the curve bootstrap; the forward compute; the surface calibration |
| Checks | The blocking failure that refuses a raise, or nothing | the curve's non-convergence; the forward set's input state; =blocking_failure_of= for a surface |
| Approval kinds | The publish kind and the withdrawal kind, read at the raise | the inbox kind rows, named by the declaration above |

The methods the next task introduces, one per fact the shared acts need, are
=resolve_subject=, =blocking_failure=, =write_publish=, =supersede_live_sets=,
=mark_withdrawn=, =announce_published= and =announce_withdrawn=. Each kind
implements them by calling what it already does, so the shared acts are a
sequence and no kind loses behaviour.

The one rule this task enforces already is the withdrawal: a kind that declares
no withdrawal kind cannot take a set out of use, and the refusal is answered
where the withdrawal is raised and not where it would be applied.

* Result

The declaration is in the tree as data, with three rows and one rule.

=derived_market_object_kind.hpp= holds the array, and each row names the publish
approval kind, the withdrawal approval kind or none, and the subject part's
table. The kind codes are the constants the handlers already pass to
=raise_permission_of=, so a rename reaches the declaration without a second edit.
=declaration_of= and =declaration_of_publish_kind= are the two lookups, and
=withdrawal_refusal_of_publish_kind= is the rule: a kind that declares no
withdrawal kind is refused a withdrawal, and the refusal names the kind and says
why the set stays in use.

The test states four things: every kind is found by its publish kind and by its
own value; an unknown publish kind names no declaration and its refusal names the
code asked for; only the curve can take a set out of use; and the forward set and
the surface are refused with a message that names them and the absent kind.

Building it broke =rate_ladder_reader.cpp=, which reads the context without
including it: the new source changed the unity order and the file saw only the
forward declaration. Twelve service sources read the context that way, so each
now includes the header it uses. That is a fix to a latent defect and not to the
declaration, and it is recorded here because it was found by this task.

The full gate: 14 of 14 checks pass, with ctest at 108 of 108 suites.

The first full run lost three database suites to =connection refused= on the
pooler's port: the suites passed when re-run on their own and again in a second
full run, so the cause was the pooler not accepting connections during the
transition out of the database recreate and not the code. It is recorded because
a gate that flakes is worth knowing about, and because the three suites were the
only thing between the first run and green.
