* Goal

One page states the flow of a report run end to end, and what post-processing
does with the output, in enough detail that a person can follow a run without
reading the code.

It covers the phases the workflow invokes, what each hands the next, how the
engine's output becomes rows in the two stores, which component owns which
format, and why the shapes are what they are.

* Acceptance

- A knowledge page states the run's phases in order, with what each consumes,
  produces and hands on.
- It states what post-processing does: which readers run, which tables are
  written, how a family's shape decides between them, and what happens to a file
  no family covers.
- It states the ownership rule: the format belongs to ores.ore, the table to the
  component that stores it, and no screen learns a family.
- It states the cost shape: one object per file, blocks of rows, and the market
  state in the object store.
- The existing pipeline page points at it, and the ORE output processing page
  links to it.

* Plan

The page lives under =doc/knowledge/architecture/= beside the pipeline page it
completes, and the pipeline page keeps the phase table while the new page keeps
the detail of what post-processing writes.

The page is updated as the three tasks that change the cost shape land, so it
never states a flow the code does not take.
