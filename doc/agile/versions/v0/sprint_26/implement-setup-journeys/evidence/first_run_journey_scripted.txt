--- What the walk is ---

It is not a recording of a browser. It is the browser's own client
(`packages/web/src/api/client.ts`), its own request-building
(`journeys/state.ts`: `detailsFor`, `provisionRequest`, `tenantPrincipal`,
`administratorPassword`) and its own password rules
(`ui/passwordPolicy.ts`), run in the journey's order against the real BFF. An
answer the browser could not parse fails the walk, because the browser's schema
is the one that parses it. The two things a browser supplies and Node does not
are supplied by the script: a base address for the relative paths, and a jar for
the session cookie.

Its first assertion is that the installation is empty. A deployment that is
already set up is refused rather than half-walked, because the first run is the
one path that cannot happen twice.

--- What the run left, and one warning ---

The run's `import_lei_hierarchy` step completed with warnings, and the walk is
what asked it to: the *Operational* starting point declares `root_lei`
optional, the walk -- like the shell's `tenant_provision` recipe -- names no
value for it, and the step states that it had nothing to import rather than
failing. The tenant's administrator therefore works in the tenant's system
party, which is the party the provisioner creates. A person who names a legal
entity the deployment holds gets its hierarchy as the tenant's parties instead.

The recreate also applied main's schema fix: the three reporting tables that
carried `tenant_id` with no isolation now each hold one row-level policy.

--- How the first walk failed, and why that matters ---

The first run of the script was green on every system check and red on one
assertion of the script's own: it compared the tenant administrator's login
principal (`northwind_admin@northwind.example.com`) against the session's
username (`northwind_admin`). The session names the account, which is stored
under its username; the hostname part of the principal is the tenant's and only
routes the request. The assertion was corrected and the walk re-run from an
empty installation. No product code changed.
