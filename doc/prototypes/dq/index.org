* Summary

Staged reference data and the act of publishing it: whether the installation
holds what its valuations read, and what a publish does to the tables that carry
it. Two prototypes answer to this group. The first draws the coverage screen, a
roster by level beside the members of one bundle and the reason a member is not
ready. The second draws the publish itself as five steps, with the preview that
makes a run readable before it happens.

Each one is a static page under =doc/prototypes/=, opens with no build and no
session, and reads mock data only. The table below opens each one and says what it
argues. Neither carries a review yet, so the review column says =none= for both.

[[file:../index.org][Prototypes]] is the top page and the only inventory.

* Adding a prototype

Create =doc/prototypes/dq/<name>/= with an =index.html=, and a =prototype.css=
and =prototype.js= when it needs them. Open the page with the links table every
prototype carries, and leave its review row at =none=. Add a row to the table
above, with the design note beside the prototype. Stop there: the site build
finds every prototype under this tree, so no build file names it.

A review goes at =doc/prototypes/dq/<name>/review/=, with an =index.html= that
lists its screens. The row names it.
[[file:../index.org][Prototypes]] states the whole method and the rules that
hold for every group.
