#+title: Write books without an approval request where no approval is needed
#+description: Every book write now passes an approval gate, so the ORE import cannot create the books it imports into, and a sandbox import fails the same way. A sandbox, and any context that needs no four-eyes control, must be able to write books directly.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Let a book be written without raising an approval request where no
four-eyes control applies: in a sandbox, whose virtual books hold only
drafts, tests and hypotheticals, and in the ORE import, which creates the
books a document's directory tree names. Today the book service refuses
every write it is not handed an approved request for.

* Why

The ORE import cannot create its books, so it fails on its first write
unless it is pointed at an existing book with a choices file, and the
recipe that round trips an ORE document through the database cannot run as
written. An import into a sandbox fails the same way, though nothing there
is an actual deal.
