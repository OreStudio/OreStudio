#+title: DQ journeys
#+description: What a data quality operator does with staged reference data: reading whether the tenant holds what it needs, publishing a dataset and a bundle, correcting one artefact, and tracing a published value to the trade it belongs to.
#+type: knowledge
#+level: cross
#+filetags: :knowledge:user_journey:dq:
#+created: 2026-11-22
#+updated: 2026-11-22

These are the journeys of the person who moves staged reference data into the
services that read it. The data is not authored here: it is curated in a
dataset, staged in an artefact table, and published by a function into the
tables a valuation reads. What the person needs is to know what arrived, what
did not, and what a run would do before they run it.

The group sits beside the topic groups rather than inside them. A conventions
journey asks what a term means and which list it picks from; this one asks
whether the term is in the tenant at all. Where the two meet, the topic journey
owns the meaning and a journey here owns the move. The precedent is
[[id:99481EA8-1D2B-426D-A4E6-5E834FF5FFCE][Publish conventions from data
quality]], which is a topic journey that publishes one catalogue and reads its
receipt.

The Qt client did this from one window, and that window went with the client.
What it offered is inventoried in
[[id:D53501D6-5FF5-44BF-B389-AAA727ACAE6F][Qt DQ surface inventory]], because
these journeys are argued from what a person needs and not from what Qt drew.

One property is shared by every journey here. A publication runs as a workflow
instance, so the progress is read from the instance and not kept by the screen;
the journey itself carries no state. See
[[id:3361CF92-89B0-481E-9E51-ACE2FEEF2FAA][Journey execution]].

* Journeys

#+ATTR_HTML: :class hug-leading
| Journey | Actor | Gist |
|---------+-------+------|
| [[id:5344ADC1-E729-4846-BE07-C6BC2169C4C9][Is my reference data complete?]] | data quality operator, tenant administrator | Read what the tenant holds at each level, name why a member is not ready, and publish what fills the gap |
| [[id:23E34C1D-4C42-450A-BF19-E5165739D20C][Publish a dataset]] | data quality operator | Publish one catalogue, read the preview, and read what the run wrote |
| [[id:4E233C8D-E3CA-4D37-AC43-1F81EF3AA133][Publish a bundle]] | data quality operator | Publish a set in dependency order, with its optional members and a receipt per member |
| [[id:FC857853-3657-4B61-AB19-4E264B28EB88][Correct one artefact]] | data quality operator | Change one staged value and republish the dataset, and read that the other rows were skipped |
| [[id:84DB1AC9-9384-43BB-A97A-2A17261DA50F][Find the trade a published value belongs to]] | data quality operator, market risk analyst | Walk a value back to the dataset that published it, and forward to what references it |

The five cover the question, the two doors into a publish, the correction and the
trace. Two of them are partly answered by the tree and say so: the trace cannot
find the trades that reference a value, because the reference is text and no
subject searches it.
