This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

A contract test that encodes every request the web client sends, as the
client encodes it, and decodes it with the C++ struct the server reads it
into. One such test exists for the workflow summaries list: the web test
writes a fixture and an =ores.workflow.api= test decodes it. The idea is to
cover every subject the web client calls, rather than one.

* Why

The web server tests stub the server, so a request the server's decoder
refuses passes them. The decoder requires every member, optional ones
included. When PR #2588 added an optional filter to the generated list
requests, seven web routes whose requests were built from hand-written
schemas answered 502 live, and every web test stayed green. The hotfix
holds those schemas to the generated types with =satisfies=, but a request
body built by hand outside a schema has no such guard.
