#+title: Codegen input org-file schema reference
#+description: Schema for every org-mode document type consumed by ores.codegen as a generator input: required frontmatter keywords, section hierarchy, and PROPERTIES drawer keys for each of the nine entity-model types and the three generator-config types.
#+type: knowledge
#+level: cross
#+filetags: :codegen:schema:knowledge:
#+created: 2026-06-11
#+updated: 2026-06-11

This document is the authoritative schema reference for all org-mode files that
feed into [[id:08FBD248-257A-A474-DD43-DB08949978F1][ores.codegen]].  It covers three layers:

- *Entity-model types* — org files that describe a single logical entity and
  drive code generation across multiple technical spaces (C++, SQL,
  TypeScript).
- *Generator-config types* — org files that configure the generator itself
  (profiles, components, modelines).

For the code that reads these files see [[id:FE693595-6693-459B-AD9B-EB7E3ABBBC88][ores.codegen architecture]].

* Entity-model schemas

** ores.codegen.entity

Full-fidelity entity: drives C++ (domain class, mapper, repo, service),
SQL (table DDL, triggers, constraints) and TypeScript (protocol and domain interfaces).  The largest doc type (~83 files).

*** Frontmatter keywords

| Keyword | Required | Notes |
|---------+----------+-------|
| =#+type= | yes | =ores.codegen.entity= |
| =#+component= | yes | Short component name (=refdata=, =trading=, …) |
| =#+entity_singular= | yes | snake_case singular noun (=pricing_engine_type=) |
| =#+entity_plural= | yes | snake_case plural noun (=pricing_engine_types=) |
| =#+entity_title= | yes | Title-case display name (=Pricing Engine Type=) |
| =#+brief= | yes | One-line description; populates C++ namespace comment |
| =#+filetags= | yes | At minimum =:model:entity:{component}:= |

*** Section hierarchy

#+begin_example
* Flags                    — PROPERTIES: schema, product, component, has_tenant_id
* Columns
  ** <column_name>         — PROPERTIES: type, cpp_type, nullable, default (opt),
                             primary_key (opt), natural_key (opt),
                             server_owned (opt)
* SQL
  ** Flags                 — PROPERTIES: tablename
* C++
  ** Flags                 — PROPERTIES: component_include, component_core (opt),
                             service_find_by_uuid (opt),
                             service_find_by_code_column (opt),
                             service_find_by_code_parent_column (opt)
  ** Repository            — PROPERTIES: entity_singular_short, entity_plural_short, ...
  ** Domain includes       — #+begin_src cpp :name includes
  ** Entity includes       — #+begin_src cpp :name includes (opt)
  ** Conventions           — PROPERTIES: iterator_var
  ** Table display         — | column | header | table
  ** Presentation          — PROPERTIES: many (key_field, collection_name, …)
     *** Detail fields     — | field | label | widget | type | is_key | view_group (opt) | … | table
     *** Columns           — | enum_name | field | header | type | width | table
  ** Custom repository methods — freeform
* See also                 — org-roam links
#+end_example

A column marked =:primary_key: true= or =:natural_key: true= leaves the plain
=Columns= bucket for the key bucket it names; a column carries at most one of
the two, and the order the key columns appear in the =Columns= section is their
order in the key. Every =natural_key= column joins one composite unique index,
so a model states its identity once and both the store and the readers take it
from there. A natural key is not required to be non-nullable, but a column that
is half of an identity usually is.

A key column marked =:server_owned: true= stays in the key and the unique index
but leaves the write record, so a caller never states it and the service stamps
it from the session. A per-party row keyed by a surrogate id uses this for its
=party_id=: the unique index still scopes the row to its party, and the write
cannot name a party other than the session's. The flag is refused on any column
the specification does not list as server-owned, so a caller-owned field is not
silently dropped from the wire.

*** service_find_by_code (C++ Flags)

=:service_find_by_code_column:= names the column, or the whitespace-separated
columns, a =find_X_by_code= service method and its =read_latest_by_code=
repository method read. =:service_find_by_code_parent_column:= names the parent
column they read first, for an identity whose first column is a foreign key.
A composite value generates one finder over the parent and every named code
column, so a hand-written method never has to restate an identity the model
already declares.

*** view_group (Detail fields)

An optional cell on each =Detail fields= row naming which
detail-dialog tab that field belongs to. Fields sharing the same
=view_group= value land in the same tab, in the order they appear in
the table; tabs themselves appear in first-appearance order across the
table. Fields with no =view_group= all fall into one implicit tab, so
an entity that never sets it generates exactly the single tab codegen
always produced before this existed — adding =view_group= to one
entity's model has no effect on any other entity's generated dialog.

Named generically (not e.g. =tab=) since it models "which projection
of the entity a field belongs to" rather than committing to tabs
specifically — the detail dialog is its only consumer today.

*** ORE Studio MASD stereotypes

These heading tags appear inside =* Columns= sub-headings on occasion; they are not
yet systematically applied.  Future work: review whether =:attribute:= on each
column heading would clarify the structure.

** ores.codegen.table (retired)

Was an SQL-only reference-data table with no C++ or presentation layer. Every
=*_table.org= model was migrated into its =ores.codegen.entity= counterpart
(the =* Validation function= / =* Insert trigger= sections moved across
unchanged) and the type's dispatch removed from =get_model_type()=/
=load_model()= — see [[id:9023BDE0-979F-422F-BC73-985D6A80E7CB][Retire legacy codegen profile system; add junction support to physical-space codegen]].
SQL-only entities (no C++/UI layer, e.g. =currency=) are expressed as an
=ores.codegen.entity= with no =** Presentation= section rather than a
distinct type.

** ores.codegen.junction

A SQL join table and its C++ counterpart (struct + repository).  Has two
mandatory FK sides (=* Left=, =* Right=) and optional extra columns.

*** Frontmatter keywords

| Keyword | Required | Notes |
|---------+----------+-------|
| =#+type= | yes | =ores.codegen.junction= |
| =#+component= | yes | Short component name |
| =#+name= | yes | snake_case plural (=badge_mappings=) |
| =#+name_singular= | yes | snake_case singular (=badge_mapping=) |
| =#+name_title= | yes | Title-case display name |
| =#+name_singular_words= | yes | Space-separated words |
| =#+brief= | yes | One-line description |
| =#+product= | yes | =ores= |
| =#+schema= | yes | PostgreSQL schema (=public=) |
| =#+has_tenant_id= | yes | =true= / =false= |

*** Section hierarchy

#+begin_example
* Left                     — PROPERTIES: column, column_short, column_title,
                             type, cpp_type, index_comment, list_by (optional,
                             default false — generates a paginated
                             read_latest_by_<column>(value, offset, limit) +
                             get_total_<entity>_count_by_<column> pair through
                             the repository and service layers, mirroring the
                             domain_entity foreign_keys.list_by knob)
  — Body: domain prose; optional #+begin_src cpp :name generator
* Right                    — same shape as * Left
* Columns
  ** <column_name>         — PROPERTIES: type, cpp_type, nullable
* SQL
  ** Flags                 — PROPERTIES: tablename
* Repository               — PROPERTIES: name_singular_short, name_short,
                             name_singular_words, name_words, order_column
* C++
  ** Domain includes       — #+begin_src cpp :name includes
  ** Entity includes       — #+begin_src cpp :name includes
  ** Conventions           — PROPERTIES: iterator_var
  ** Table display         — | column | header | table
* See also
#+end_example

** ores.codegen.family

The protocol of a composite entity: one central row plus its parts.  It
derives the family's records and its four message pairs — =get=,
=get_many=, =put= and =put_many= — and drives the C++ protocol header and
its TypeScript twin from one derivation.  It derives no domain type, SQL
table or service; see [[id:87E3F021-1C69-48DE-9139-32C44C99B3B9][Codegen patterns: choosing a model shape]],
section "The generic put and the family put".

*** Frontmatter keywords

| Keyword | Required | Notes |
|---------+----------+-------|
| =#+type= | yes | =ores.codegen.family= |
| =#+component= | yes | Short component name; the central entity and the parts are found in its =modeling/= dir |
| =#+entity_singular= | yes | snake_case singular of the family |
| =#+entity_plural= | yes | snake_case plural |
| =#+entity_title= | yes | Title-case display name |
| =#+brief= | yes | One-line description |
| =#+filetags= | yes | At minimum =:model:family:{component}:= |

*** Section hierarchy

#+begin_example
* Flags                    — PROPERTIES: central_entity
* Parts                    — | part | entity | table
* See also
#+end_example

=central_entity= names another model in the same component's modeling
directory whose =#+type:= is =ores.codegen.entity=; its C++ domain type is
=ores::<component>::domain::<central_entity>=.  Each row of the =* Parts=
table names a part shim (the C++ member name, first column) and the entity
model that backs it (second column).  Each part must be an
=ores.codegen.entity= in the same component with a foreign key whose
=:parent_entity:= is the central entity and whose
=:bump_parent_version:=, =:list_by:=, =:list_by_uuid:= and
=:list_by_as_of:= are all =true=; a part that does not satisfy that fails
the load.

The family derives =<family_singular>_key= (copied from the central
entity's own key record), =<family_singular>_item= (the key, the central
row and one typed array per part) and =<family_singular>_write= (the
central change and one typed array of part changes per part), then the
four request/response pairs.  Subjects use the family plural, so they do
not collide with the central entity's own derived subjects.

** ores.codegen.service_registry
Catalogue of ORE Studio backend services.  Each top-level heading is one service.
Drives PostgreSQL GRANT scripts and shell variable declarations.

|---------+----------+-------|

* Generator-config schemas

** ores.codegen.facet_catalogue (retired)

/Retired/ — declared every codegen profile: which templates each facet
activated, the model types each template bound to, and how composite
facet groups composed leaf facets. Superseded by the
[[id:D7D53D71-C9E8-43AE-AA42-E58E57CD76C8][ores physical-space graph]], where this information now lives directly
on each facet's own node (its Archetypes table) instead of in one
central file. Kept here for the historical schema shape.

*** Section hierarchy

#+begin_example
* Facets
  ** <facet_name> :facet:  — PROPERTIES: description, model_types
     *** Templates         — | template | output | model_types (opt) | table
* Facet groups
  ** <group_name> :facet_group: — PROPERTIES: description
     | facet | include | table
#+end_example

** ores.codegen.component_catalogue

Maps each named component to its model-discovery roots.  Read at startup by
=manifest.py=.

*** Section hierarchy

#+begin_example
* Components
  | name | models_dir | entity_glob | exclude_suffix | modeling_dir | table
#+end_example

*** Column semantics

| Column | Description |
|--------+-------------|
| =name= | Short component id (=refdata=, =trading=, …) |
| =models_dir= | Path to legacy JSON models directory |
| =entity_glob= | Glob pattern for JSON model files |
| =exclude_suffix= | Suffix to exclude (e.g. =_domain_entity.json=) or =null= |
| =modeling_dir= | Path to co-located org models; =null= if none |
