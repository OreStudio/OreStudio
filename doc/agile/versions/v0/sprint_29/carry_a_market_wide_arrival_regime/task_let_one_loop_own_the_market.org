* Goal

The synthetic service runs one loop that owns the market and the feeds. The market_owner thread is gone, and the handlers that pin the regime, set the chain and heat, and start or stop a feed post commands to the loop.

* Acceptance

- No thread but the loop writes the regime, the heat or tau.
- A pin from the screen or the shell is in force at the next instant of the loop, with no refresh period.
- The run seed comes from configuration and is logged when the run starts.
- market_regime and shared_intensity are deleted: the loop owns one operational_clock.
