* Goal

Write the target-state architecture of the data path as atomic notes ordered by a
structure note, describing only the state the story delivers, and align every
related note to it so no note states a different target.

* Acceptance

- One structure note orders the cluster and argues its order; each atomic note
  makes one claim, in the present tense, with no current state and no history.
- Every note the target changes either states the target or links to it.
- The structure-note, pattern-use and link checks pass.

* Plan

1. Write the structure note [[id:CE41E828-18EB-4E88-BB02-6A4930E7B67C][The data path]] and thirteen atomic notes, one claim each.
2. Reframe the tick storage note as the store-once target.
3. Read every note on connections, sessions, the tick store, the ingest, the
   compute claim and ownership, and change each statement that names another
   target.
4. Link the pattern pages both ways, add the hub to the knowledge index, and
   run the structure-note and pattern checks.

* Result

The data path cluster is written: the structure note [[id:CE41E828-18EB-4E88-BB02-6A4930E7B67C][The data path]] orders thirteen
notes, from the workload through connections, the transaction context, the unit
of work, typed statements, error classes and the bounded handler pool, to the
store-once tick store, its lanes, its bounds, the pooler, the pushed grid and
the published numbers. The ingest loop, the ingest pipeline, the PostgreSQL,
time, ownership, history-call, series, bootstrap and compute queue notes now
state the same target, and the market data and storage structure notes and the
knowledge index link the cluster.
