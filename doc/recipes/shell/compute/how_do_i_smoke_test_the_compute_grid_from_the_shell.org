The compute grid verbs live in the shell's =compute= menu. They talk
to the ~ores.compute~ service over NATS; the domain shapes and table
renderers come from ~ores.compute.api~.

* Question

How do I smoke test the compute grid from the shell?

* Answer

Run the library script =ores.shell/scripts/library/compute/how_do_i_smoke_test_the_compute_grid_from_the_shell.ores= against a live serving environment. It adds a batch with 10 to 20 jobs, dispatches them to the target app version, watches =compute grid-stats --watch --smoke= until the batch drains, and asserts every online host was exercised and every result has outcome Success. The script fails if either assert does not hold.

#+name: smoke-test-compute-grid
#+begin_src ores-shell :exports none
connect $ORES_NATS_URL
login super_admin@localhost Secure-Password-123
compute add-batch smoke-$SMOKE_REF 15 --smoke
compute dispatch-batch smoke-$SMOKE_REF 15 $APP_VERSION_ID $INPUT_DIR
compute grid-stats --watch smoke-$SMOKE_REF --smoke
logout
exit
#+end_src

#+begin_src sh :noweb yes :results output :wrap example
./ores.shell ${log_args} ${connect_args} << 'EOF'
<<smoke-test-compute-grid>>
EOF
#+end_src

The batch external reference is =smoke-$SMOKE_REF=; set =SMOKE_REF= to
anything unique. The job count is 15; the =--smoke= switch bounds it
to the 10 to 20 range. =grid-stats --watch --smoke= polls every 10
seconds until the batch drains, then asserts every host online at the
drain transition was exercised and every result has outcome Success.
The script fails if either check does not hold.
