The schedule is the value of the system setting
inbox.approval_expiry.schedule, which the inbox read over the wire at start
before it wrote the job row. The job's action is nats_publish, so firing it
publishes inbox.v1.ops.expire_overdue_approvals rather than running SQL: the
close and the notice are one act, and a function in the store tells nobody.

Both firings landed on a five-minute boundary, which is the setting's doing
and not the component's: nothing in the inbox states how often the sweep runs.
