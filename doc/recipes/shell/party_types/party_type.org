#+title: How do I run the party_types commands from the shell?
#+description: Every command the party_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:party_types:

This file documents the party_types resource at the shell, one section per command. Every command is a subcommand of =party_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: AF0643FC-5E07-5D0A-8F3C-458C4FB739DB
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
party_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.party_types.list=.

#+name: party_types-list
#+begin_src ores-shell :tangle party_types-list.ores :exports none
party_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 415E4640-EE25-5D08-89EC-AE365DE8FB74
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
party_types get <code>
#+end_example

It is addressed at =refdata.v1.party_types.get=.

#+name: party_types-get
#+begin_src ores-shell :tangle party_types-get.ores :exports none
party_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 167DB0AD-B6F1-5419-9C3B-DB76927F23B5
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
party_types add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.party_types.put=.

#+name: party_types-add
#+begin_src ores-shell :tangle party_types-add.ores :exports none
party_types add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: A3168D4C-FD37-5878-B638-8307C6FCC5E0
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
party_types set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.party_types.put=.

#+name: party_types-set
#+begin_src ores-shell :tangle party_types-set.ores :exports none
party_types set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
