* Goal

The checks exist before the screens change, so the first screen work proves the checks. A failing check names the rule identifier it breaks. The reviewer has one procedure to sign off a screen: run the harness, walk the lines the harness cannot check, and record the outcome on the task.

* Acceptance

- Playwright runs against the environment ores.web, signs in as a seeded Acme user and opens a record screen, from one command.
- The harness discovers the record kinds from the wire protocol registries (records, classifications, convention kinds) and runs the same checks over each.
- Each structural rule the settled standard marks as checkable has one check, and the check reports the rule identifier on failure.
- The harness runs over today's screens and the failures are recorded as the baseline, one capture or task per screen family.
- A recipe states how a reviewer signs off a screen: the harness, the manual lines, and where the outcome is recorded.
- The Allium specification propagates tests where it can, and the harness carries the rest.

* Decisions

- Playwright drives the running web of the environment; the harness starts no
  server and is not part of =npm test=, because it needs Acme provisioned.
- The screens come from the registries the BFF reads, through a hand table of
  routes that refuses a kind it does not place; a new kind is checked or
  stopped, never skipped in silence.
- A test is titled by the rule identifier it asserts and its describe names
  the screen, so the JSON report folds into rule against screen with no other
  knowledge of the tests.
- A row that opens no page skips the record checks with the reason; RS-LIST-10
  reports the list once.
- The breadcrumb's last crumb is the key or the title, as the standard's
  sketch draws it; the check was corrected, not the screen.
- Refresh on a list keeps the page the person was on (RS-LIST-19, decided on
  2026-10-25 in the Allium task).
- The baseline is a measurement page the next run replaces, with one capture
  per broken rule in the next bucket, not a work list.
- Sign off is one sheet per screen: the harness marks the lines it checks and
  a person walks the rest with Meets, Gap, N/A or Not checked; a screen is
  signed off only with no ✗, no Gap and no Not checked.
