* Summary

=ores.storage= is the client half of ORE Studio's object storage. It moves
files between a local disk and an S3-shaped HTTP API that keeps objects
under a bucket and a key, and it holds no bucket names of its own: a caller
names its bucket, the way =ores.compute= names its package bucket and
=ores.ore= its import and report buckets.

Four types carry that work. =net/storage_paths= builds the
=/api/v1/storage/{bucket}/{key}= path and URL. =net/http_client= is the
synchronous HTTP/1.1 GET and PUT over Boost.Beast, streaming file bodies
rather than buffering them, and it is the only piece that knows about
sockets. =filesystem/archiver= packs and extracts =tar.gz= trees through
libarchive. =net/storage_transfer= composes the three into the atomic
=pack=, =unpack=, =upload= and =download= operations, plus the composite
=pack_and_upload=, =fetch_and_unpack=, =upload_blob= and =download_blob=
helpers that every caller actually uses.

The component is model-free. It owns no entity, no junction, no NATS
subject and no protocol header, so none of its types is generated and none
appears on the wire; its wire contract is the HTTP path shape above, which
it documents rather than declares. Everything it exposes is hand-written.

Every operation is synchronous and blocking, and the callers run them on
background threads. The composite helpers stage through a temporary file
under the system temporary directory.

* Facets

- =filesystem/= — =archiver=, the libarchive =pack= and =extract= pair for
  =tar.gz= trees, including the platform difference in how libarchive is
  handed a path.
- =net/= — =storage_paths= for the bucket and key path and URL,
  =http_client= for the GET and PUT primitive, and =storage_transfer= for
  the atomic and composite operations built on the two.

* Inputs

- A local directory or file to pack, upload or download.
- A storage endpoint: the HTTP base URL, a bucket name and an object key.
- A =tar.gz= archive to extract.
- An in-memory blob to upload, and the compressed bytes to decode on the
  way back.

* Outputs

- Files written to a local path, or objects written to the remote bucket.
- Extracted directory trees.
- The server's response body, for the uploads that read a server-computed
  checksum out of it.
- Decompressed blobs in memory.

* Entry points

- =include/ores.storage/ores.storage.hpp= — the namespace =@brief= doxygen

- =include/ores.storage/net/storage_transfer.hpp= — the composite helpers

- =include/ores.storage/net/storage_paths.hpp= — bucket and key to path and
  URL.
- =include/ores.storage/net/http_client.hpp= — the GET and PUT primitive.
- =include/ores.storage/filesystem/archiver.hpp= — =tar.gz= pack and
  extract.

* Dependencies

- =ores.utility= — gzip, for the in-memory blob transfers.
- =ores.platform= — the scoped temporary file the composite helpers stage
  through.
- LibArchive — the =tar.gz= pack and extract.
- Boost.Beast and Boost.Asio — the HTTP client.

=ores.logging= is linked but is the ubiquitous logging dependency every
component carries.
