* Plan

The artefact column list under =* Artefact columns= in
=projects/ores.refdata/modeling/ores.refdata.book.org= is hand-maintained and
duplicates each column's SQL-side default. =is_sweepable= carries
=:default: false= there; =book_purpose_type= and =ledger_feed_type= carried
nothing, so =sql_schema_domain_entity_artefact_create.mustache= emitted them
as bare =not null=.

The defaults live in two different keys, and confusing them is what caused
this. =:default:= is the SQL default the templates render as a DEFAULT
clause; =:default_value:= is the C++ member initialiser. The book's *columns*
carry =:default_value: "Trading"= (a string default, correctly quoted for
C++), which is why the model read as if the default was already stated. Both
columns are text, so =org_loader._column_node_to_dict= SQL-quotes the
artefact-side =:default:= for us: the model writes the plain code, and the
single quotes are the template's business. =:default: 'Trading'= is also
accepted, and is the form =ores.refdata.currency.org= uses.

So the fix is to mirror the defaults in the artefact list, regenerate
=ores.sql.schema= for the book entity, and change nothing else. Fixing it in
the model rather than in the five seeds keeps the seeds honest -- they insert
a book, not a book plus two columns the database can already supply -- and it
repairs the four ACME seeds without touching them.

* Notes

=compass db recreate -y -k= was run against this tree and exited 0, printing
its full populate summary. That is the acceptance criterion met on the real
artefact rather than on a proxy.

A static check written to find this class of break -- a populate =INSERT= that
omits a not-null, no-default column -- reports 597 hits naively, 10 once the
columns a BEFORE INSERT trigger fills (=valid_from=, =valid_to=,
=performed_by=, =modified_by=, ...) are set aside, and 0 for a recreate's
reachable seeds once the check is made comment- and quote-aware. Two of the
six surviving hits are trigger-filled after all (=version= on
=scheduler_job_definitions=, =codename= on =parties=); one is a manual psql
entry point the WIRE gate ignores (=ip2country_import.sql=, which inserts
=(ip_range, country_code)= into a table whose =tenant_id= is not-null and has
no default, and so cannot run as written); and the rest insert into tables
whose =version= arrives from the same trigger machinery. The check is not
landed with this fix -- it wants its own gate and its own story -- but it is
what shows this break is alone, and the =ip2country= finding is recorded here
so it is not lost.
