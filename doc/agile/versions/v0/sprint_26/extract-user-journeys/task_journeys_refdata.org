  =delete=, =delete_many=, and =<plural>_versions.list= and =.get=.

  =calendar_adjustments.export=.

** Legacy Qt screens

Every Qt list window had Add, Edit, Delete, History and Reload. Some had
buttons that opened a related lookup list. Currency alone had CSV export, ORE
XML export and ORE XML import. The shared history dialog listed versions,
showed a field diff, opened a version read-only, and reverted to it. Special
screens: party and counterparty child tables and hierarchy tabs, the curve
builder workbench, and the market series and bootstrap config pickers.

| Qt action | Disposition |
|-----------+-------------|
| Add, Edit, Delete, Reload on every list window | Kept: a step of the journey that owns the record |
| History, open version, revert | Changed: a History panel on the journey screen, reading =refdata.v1.history.get= |
| Related-lookup buttons | Changed: pickers on the record, and a link to the classification list |
| Currency CSV export | Dropped: the ORE XML export covers exchange, and a list screen can export what it shows |
| Currency ORE XML export and import | Kept: Add or correct a currency, step 9, with gaps |
| Curve builder workbench, pickers | Deferred to the marketdata and analytics extractions |

** Recurring gaps

1. No role below =TenantAdmin= can maintain reference data. =Operations=
   writes currency records but cannot read the lists its pickers need.
2. Deleting a lookup row is not refused while records still use the code;
   those records then fail validation on their next save.
3. ORE-defined vocabularies (day counters, calendar names, floating index
   types, leg types, business day conventions) are editable; only calendars
   carry an =is_editable= marker.
4. No server-side ORE XML export for currencies; the calendar export returns
   data, not the document.
5. Business days are rebuilt only on request, with no record of when.
6. Business days cannot be read by date range.
7. Holiday rules and business days carry no holiday name.
8. Externally sourced holidays are not gated by authorisation.
9. =display_order= is not unique within a list.
