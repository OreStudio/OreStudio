* Acceptance

- A route lists the scenarios, a route reads one with its steps and the ids of its story and task, a route reads a doc by id, and a route saves a run.
- The routes require a signed-in session and refuse a request with no session.
- A save that names a step the scenario does not have is refused with a clear message.
- BFF tests cover the routes with the store replaced by an in-memory one.

* Plan

=registerQaRoutes= in =packages/bff/src/qa.ts= serves four routes, all behind =requireSession= and none behind a permission, because a trader may run scenarios.

| Route | Answers |
|-------+---------|
| GET /api/qa/scenarios | the scenario summaries: state, waiting or done, target, story, task, step counts |
| GET /api/qa/scenarios/:id | one scenario with its steps and the ids of its story and task |
| GET /api/qa/docs/:id | a story, a task or a scenario by :ID:, as org text for the browser to render |
| PUT /api/qa/scenarios/:id/run | a save, which returns the scenario, its new state and the steps it wrote |

The shapes are zod schemas in =@ores/contracts= (=qa.ts=). The tests parse every response with them, so the browser can parse the same schemas.

Decisions:

- A save carries no overall state and no time. The server works out the state from the merged steps and stamps the time. A scenario closes when no step is pending, and then it is FAILED if a step failed, else PASSED. A save that leaves a step pending clears the completion time. The codec from task 2 changed for this: =RunInput= lost its =state=.
- A save may mark a step PENDING, PASS or FAIL. DROPPED is read, never written.
- The doc route serves stories, tasks and scenarios only. Another type answers not found, so the rest of the doc root stays unread.
- The server takes its store from =dependencies.scenarios=, else it builds a file store from =ORES_WEB_DOC_ROOT=. With neither, every route answers not found and names the setting.
- Errors: a bad id or save is 400, a missing scenario 404, a doc in the wrong format 422, a file error 503, and anything else 500 with no message.

* Notes

- Any signed-in session reads every story, task and scenario under the doc root. That is open for production: the doc root should hold only what a tester may read.
- The tests replace the store with an in-memory one that runs the real codec, and one test runs the file store through =ORES_WEB_DOC_ROOT=.
- Map the store errors to statuses: =InvalidDocIdError= to 400, =ScenarioNotFoundError= to 404, =UnknownStepError=, =AmbiguousStepError= and =DuplicateOutcomeError= to 400, =ScenarioFormatError= to 422, =PathEscapeError= to 500 and a log line.
- A scan can throw, for example on an unreadable folder. The route must answer 503 and not crash.
