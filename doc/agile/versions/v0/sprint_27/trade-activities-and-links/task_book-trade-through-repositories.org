* Acceptance

- ores.database offers a unit of work: repository writes made through it share one connection and one transaction, and commit or roll back together.
- book_trade writes the trade, the activity, the booking and the state through their repositories inside one unit of work; a failure in any write leaves none, and a second booking of the same trade is still reported as a conflict.
- ores_trading_book_trade_fn is deleted; no SQL function or hand-written C++ inserts into, updates or deletes from an entity table outside the generated repositories and the sanctioned purge.
- An architectural rule states the policy, and a check run locally and in CI fails on a direct entity-table write outside the repositories, with the purge and test fixtures as its stated exceptions.
- The round trip stays at in-scope lost 0; build, ctest, pgTAP under RLS and the local check set pass.
