* Result

The schema fingerprint is the first sixteen hex digits of a sha256 over the
SQL compass db recreate reads (every .sql under create/, populate/ and
instance/ and at the top of projects/ores.sql), defined once in
=projects/ores.sql/schema_fingerprint.cmake= and implemented again in
=compass_db.schema_fingerprint=; =test_schema_fingerprint.py= runs both on
the real tree and on a small one and requires the same answer.

- =compass db recreate= stamps it into =ores_database_info_tbl=, whose
  =schema_version= column (the CMake project version, which never tracked the
  schema) is replaced by =schema_fingerprint=. Every service user may read
  the table.
- The build compiles it into =ores.database=, regenerating the header when an
  SQL file changes. =context_factory::make_context=, which every service, the
  HTTP server and the test database manager call, logs the expected and the
  recorded fingerprint and throws =schema_mismatch_exception= on a mismatch.
  Each service main prints the message and exits with the new
  =exit_code::schema_mismatch= (7), and the systemd units do not restart on
  it.
- =compass services start= checks first and refuses with the same banner;
  =compass db status=, =compass bearings= and =compass env status= report
  in sync or out of sync instead of guessing drift from the commit date, and
  the environment dashboard shows both fingerprints.

Verified on 2026-10-03: build clean; database recreated; ctest 90/90; compass
tests 301 passed; dashboard tests 42 passed. With the database's fingerprint
changed to deadbeefdeadbeef, =compass services start= refused with both
fingerprints and the fix, and the refdata unit, restarted through systemd,
logged the FATAL banner (expected ceb50d4c0e992073, actual deadbeefdeadbeef,
the commit the database was built from, and the fix) and failed with exit
status 7 and no restarts. Recreated, the services started and logged the
check as passed.

The banner appears three times in a refusing service's log: once from the
context factory, and twice from the service host's existing generic error
handler, which logs every startup exception's message.
