* Goal

ores.orgmode is a single library at the component's root. Make it a compound component, as ores.marketdata and ores.analytics are: move the existing parser into ores.orgmode.parser, with ores.shell and the tests on the new includes, and scaffold ores.orgmode.api, ores.orgmode.core and ores.orgmode.service through the codegen so the next tasks have somewhere to go.

* Acceptance

- The parser lives in ores.orgmode.parser and parses every org file of the repository as before; the corpus test passes unchanged.
- ores.shell builds and runs on the moved parser.
- ores.orgmode is a compound component with its parser part, generated from its overviews. (Changed 2026-11-21: the api, core and service parts are added by the tasks that give them real code, because the gate refuses scaffold stubs in the tree and a service part needs a real core; see Notes.)

* Plan

Move the existing library into a =parser= part with a script, not by hand, so
the move is reviewable and behaviour-preserving: =git mv= the directories, then
rewrite includes, namespaces, the export macro and the target name in
=ores.orgmode= and its one consumer, =ores.shell=. Record the parser tests
before and after. Generate every build file from the overviews through codegen.
