** Planted violations

One throwaway commit on top of main planted one violation for each of 10
gates that were green in both tools: an uppercase filetag (lint), a colon link
(org-links), a changed tangled HTTP recipe block (tangle-http), =<stop_token>=
outside ores.platform (portable-stop), a duplicate index (sql-hygiene), a
source missing from component_files.cmake (cmake-sources), the same
file-local name in two sources of one target (unity-collisions), a second
definition of =ores::refdata::domain::currency= (unique-type-names), a raw SQL
write to an entity table (entity-writes) and a hand edit in a generated
repository (component-drift). Both tools reported all 10. The first plant for
tangle-http was in =assign_role.org=, which is not a tangled recipe; neither
tool reported it, which is correct.

** Defects found on the way

- *compass-ng shadows the Python compass.* =~/.local/bin/compass= is
  compass-ng, so =compass services status= fails with =unknown command:
  services=. The docs and bearings tell agents to type =compass <verb>=.
- *--commit and --ratchet without .compass.org.* On a commit that has no
  =.compass.org=, compass runs its defaults (document_index and
  required_sections on) and reports 4,762 findings, without a warning.
- *The guide names a rule table page ORE Studio does not have*
  (=doc/knowledge/compass/rule_table.org=); the pilot ran with rule_table off.
- *The hook reports findings that were in the file before the edit.* Until
  the baselines are inline exceptions it will block on every edit to an
  entity writer or a mustache template.
- *A hand edit compass generate would delete.*
  =market_fixing_repository.cpp= has a hand-written
  =read_latest_for_series= in a generated file; compass generate (and
  ores.codegen) would remove it.
- *Python tangle-shell and tangle-http write into the tree* and leave it
  dirty (52 and 1 files here).
- *Python component-drift renders into the shared /tmp tmpfs* and crashed
  with ENOSPC on one run when the fleet had filled it.

** Verdict

compass-ng is ready to run next to the Python gates now, and ready to replace
them once the drift is fixed and the baselines are exceptions. It gives the
same verdict as Python on every gate it could be compared on except
er-diagram, where it misses the RLS validation. It catches every planted
violation, and it is about 400 times faster warm (4.7 s against 1,844 s of
gate time), and 28 times faster even cold. It is not ready for CI or external
developers: there is no released binary yet.
