* Goal

A position nested in a total return swap reaches its own trade's key instead of being written as a central equity row, so the routing and the stored type no longer disagree. The 13 unrouted codes stay unrouted.

The 17 routed codes are *not* re-pointed here. The catalogue's =instrument= column names the table that holds a code, and under the atomised shape the central row is what holds an instrument; a part reaches its central row by the key and is never a routing target. The re-pointing therefore lands in unit 5 with the header it names.

* Result

A total return swap is now the composite the catalogue says it is. The
import mapper no longer diverts a swap whose underlying is an equity
position into the equity family, so no =equity_position_instrument= row is
written for a trade whose type is a swap, and the routing and the stored
type agree (E6).

The old path is removed rather than accommodated, per the operator: no
compatibility branch, no migration, and the database was recreated.
=underlying_sub_trade_type=, =nested_sub_trade= and the two fall-backs are
deleted, and both reverse mappers lost =outer_trade_type= and the wrapper
that rebuilt a swap around a position. Five files, 47 insertions and 112
deletions.

=ores.ore.core.tests= passes: 483705 assertions in 718 cases.

The corpus has no top-level position document, so the mapper test takes the
sub-trade out of the swap fixture and maps it as the top-level trade it now
is. That is a compromise worth naming: the position path is covered through
a constructed top-level trade, not a documented one. A real top-level
position fixture would be better and does not exist today.
