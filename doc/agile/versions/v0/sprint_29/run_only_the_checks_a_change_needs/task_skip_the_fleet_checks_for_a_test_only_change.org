* Goal

A change that reaches only test binaries runs build and ctest but not the database rebuild, the tick smoke or the step-consumer check.

* Acceptance

- A change to a header only test code includes skips db, ticks-smoke and step-consumers, and the report names why
- A change that reaches a library or a service still runs them

* Plan

Decide the skip after =build= passes, from =ninja -t deps=, because only a log
from after the build describes the tree under test. Map each changed compiled
path to the targets whose objects read it. Skip the three fleet checks when
every target is a =.tests= binary. Keep =db= when the database schema does not
match the checkout, because main moves under a branch.

* Result

The runner skips =db=, =ticks-smoke= and =step-consumers= when a change
compiles only into test binaries. It reads the reach from the ninja
dependency log after the build. A new file, a build description, a SQL script
or an unclassified path keeps the checks. =db= also runs when the database
schema fingerprint does not match the checkout. =--all= and =--only= skip
nothing. The report names each skipped check and the test binaries behind the
skip. Both acceptance items are met: the gate on a test source skipped the
three checks and ctest passed, and the tests prove that a library reach keeps
them.
