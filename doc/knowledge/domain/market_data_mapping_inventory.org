#+title: The mapping inventory lists the vendor instruments each provider carries
#+description: Which vendor instruments the catalogue installs for Bloomberg, LSEG and the fictional provider Demo, what each maps to, which rows need a check against the vendor, and how the rate curve pillars come from the feeds themselves.
#+type: knowledge
#+level: cross
#+filetags: :marketdata:catalogue:mapping:inventory:
#+created: 2026-10-23
#+updated: 2026-10-26

* Summary

The inventory lists the vendor instruments that the system bundle installs and the oresmd item that each
maps to. It covers two markets.

The 26 FX spot pairs the simulated feeds quote, in the notation of Bloomberg, LSEG and Demo. The three
providers quote the same item, so a party that changes its provider keeps its series. The rows that name a
market with a non-deliverable variant are marked for a check against the vendor's own screen.

The pillars of every interest rate curve the synthetic feeds quote, in the notation of the provider of the
curve's own collection. The seed holds no list of them: it reads each curve config's Curve Template and
writes one row for each entry, so a provider's catalogue is exactly the set of ids its feeds serve.

ICE and Tradeweb still have no rows: no notation is written for their ids.

* Detail

** How the ids are written

- Bloomberg: the pair as six letters, a space and the yellow key =Curncy=, with the field =PX_LAST=.
  See [[id:89B7883C-6F06-457B-A9A5-B78257C5C9FC][Bloomberg data format]].
- LSEG: the currency that is not USD, followed by an equals sign, with the field =BID=. See
  [[id:A5EC1229-18D7-4F2F-8E9D-2D02768B6E0D][LSEG data format]].
- Demo: the pair with a slash, =<base>/<quote>=, with the field =value=. The provider is fictional and exists
  for exercises and demonstrations.

No id is minted. Each follows the vendor's own notation, so no row needs a deviation note.

** Rows to confirm

Six currencies trade as deliverable spot and as a non-deliverable forward: INR, KRW, TWD, BRL, CLP and COP.
For these the plain ticker or RIC may name the onshore market or the offshore one, and a pricing source may
be needed. The rows are installed as written and marked =to confirm=. A person with access to the vendor's
screen confirms or corrects them before a live adapter relies on them. The simulator publishes them as
they stand.

** The rate curve pillars

A pillar is the quote that ends where the pillar ends, on the curve of one currency and one index. Its
row names the currency, the index family, the instrument, the tenor the pillar starts at and the tenor it
ends at, each in the words the curve template uses. Its item is the datum the pillar's own quote key
names: the currency, the index tenor of the curve, and the two tenors of the pillar.

The rows come from the feeds, and no list of them is written here. For each IR curve config of each
synthetic feeds collection, the seed emits one row for each Curve Template entry, in the notation of the
provider the collection names. Today that is the 28 currencies of =synthetic.feeds.bloomberg= with their
twelve-pillar spot-starting ladders, the 20 currencies of =synthetic.feeds.uniform_demo= with their
three-pillar templates, and the five index curves of each of =synthetic.feeds.ice= and
=synthetic.feeds.tradeweb=, which carry no id.

A pillar whose provider cannot write it has no row. The meeting-dated short end of the Bloomberg USD
curve is spelled with meeting codes such as =1F=, and no notation writes those, so the FOMC curve is
quoted inside the system and not through an adapter.

** Not inventoried yet

- *ICE and Tradeweb.* The feeds quote index curves these providers carry in the real market, but their
  public documents give no id grammar for the asset classes they serve, so no notation is written for
  them and the seed has no row for their pillars. See
  [[id:72848BB7-9ADE-49CF-8D33-008ED7C1DF29][ICE data format]] and
  [[id:22DDAB03-5CD7-4E14-B1B0-23DB61F2DC95][Tradeweb data format]].
- *The FX pairs a collection does not quote.* The FX rows are one list for the three providers, so a
  provider's FX catalogue names the 26 USD pairs whether or not its own collection quotes them. LSEG's
  collection quotes 14 crosses, and Demo's quotes eleven of the pairs. A demand for the FX item of a pair
  a collection does not quote is rejected as =unknown_id= until the FX rows are generated the same way.
- *Other fields.* Only one field of each id is mapped: the last price for Bloomberg, the bid for LSEG.
  A bid and ask series, or a mid, is a further row for each field.

** Checked against the identifier survey

The notation agrees with the examples of [[id:F3010EA7-6A0E-405C-81FA-1EF051749B5E][External market data identifiers]]:
=EURUSD Curncy= is a Bloomberg ticker with its yellow key, and ~EUR=~ is an FX spot RIC. The survey says the authoritative definitions of Bloomberg and LSEG notation are behind
the vendors' logins, so the rows marked =standard= follow their documented examples and the common
convention, and a person with a login confirms them with the rows marked =to confirm=.

** Where the rows come from

The rows are installed by =marketdata_vendor_instruments_populate.sql=. The FX rows are written in that
script. The rate curve ids and items are written by =tools/ir_catalogue=, which calls the provider's own
notation for each id, calls =make_pillar_quote_key= and =pillar_datum_uri= for each item, and reads every
id it wrote back to prove it names the same pillar; the script's header holds the command that
regenerates them. So the ids of this page and the ids the runtime writes cannot drift.

The ids of the vendor instruments come from their identity, so a second run writes the same rows. The
mapping of each row holds from 2026-01-01.
