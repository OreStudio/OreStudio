* Acceptance

- Report execution at scale links Scheduled Work Acting as a Tenant and states
  only reporting's role, audience, resource and grant moments.
- The generic mechanism lives on one IAM page that any component can use.
- No page links the moved diagrams by their old paths.

* Plan

Splitting the reporting section showed a third layer between the pattern and
reporting: IAM's implementation, the same for every component. Move the grant
entity, the exchange checks, the claims, the cache rules, the load and the trust
boundaries to a new page in the security cluster, with the three generic
diagrams. Keep the role, the audience, the resource and the grant moments on the
reporting page.

* Result

The identity section of Report execution at scale now has four short parts:
the grants reporting creates, when it grants and revokes, the =ReportRun= role,
and its exchange load. It links the composite pattern and the new IAM page.

The new page, [[id:78B82824-0BBB-4442-A9FA-E1F265DF57BD][Run grants and run
tokens]], holds the four IAM operations, the grant entity and its states, the
exchange checks and the claims, how a data owner sees a run token, the cache
rules and its states, the load on IAM, and the trust boundaries. It ends with the
list of what a component that uses run grants must state. The three generic
diagrams moved to =doc/knowledge/security/= with the reporting words removed.
The Grant Management, Token Exchange and composite pages, and the IAM hub, link
the new page.
