* Goal

Give the prototypes a shape a person can walk: one top page that names the
journey groups and what each gathers, one page per group that lists its
prototypes and what each argues, and one folder per group that holds them.
Put the Gemini review screens beside the prototypes they review, and mark on
every index page which prototypes carry a review.

* Plan

The work is one move, one copy and a documentation pass.

1. *Move.* Every prototype directory goes under its journey group folder, as
   =doc/prototypes/<group>/<name>/=. The seven design notes that sit directly
   under =doc/prototypes/= go to =doc/prototypes/<group>/<name>.org=, beside
   the prototype they describe.
2. *Repair links.* A prototype page reaches the journey documents with
   =../../knowledge/=, which becomes =../../../knowledge/= at the new depth.
3. *Copy the reviews.* Six of the eight Gemini files are complete pages. Two
   are byte-for-byte truncated prefixes of two others, so they are dropped.
   Each complete page is renamed for the screen it draws and placed in the
   =review/= folder of the prototype it reviews.
4. *Write the pages.* A group page per group, and a new top page.
5. *Encode the shape.* The guard learns groups, group pages and reviews. The
   site build discovers the prototypes instead of naming all 46, so a new
   prototype needs no change there.
6. *Tell every environment.* The memory, the journey document type, the
   journeys hub, the synthetic-data knowledge page and the journey documents
   that name a prototype path all move to the new one.

Group assignment is by journey topic, taken from the mapping each journey
document already states. Two calls are judgement, and the group pages record
them: =navigation= joins =tenancy= rather than =profile=, because the home
screen that replaced it, and the sign-in that decides what the shell shows,
both belong to the tenant; and =trade-entry= joins =books=, because no
trading group exists and the prototype books a structure into a book.

* Notes

The eight Gemini files are two design families. Five draw the person record:
two tabs of it that answer to the Profile prototype, and one that answers to
the Access prototype's person screen. Three draw the tenant administration
console, the people roster and a trading terminal, which answer to the
Application shell prototype, so their reviews sit under =tenancy/navigation=.

Two of the eight are byte-for-byte truncated prefixes of two others, with no
closing tags: =gemini-code-1791449283112.html= stops inside an attribute of
the Person detail page, and =gemini-code-1791450752832.html= stops inside an
=img= tag of the Person contact details page. They are copy artefacts, not
variants, so only the complete pages are kept.

The first full site build failed on an unrelated, pre-existing dangling id
link in =doc/agile/versions/v0/sprint_27/instruments-rates/design.org=: the
link used uppercase where the target declares lowercase, and org resolves an id
by exact string. It is fixed in =4f161ac260=, in a commit of its own, and the
page then exported cleanly.

* Result

The prototypes are grouped and readable. The top page names the eighteen
journey groups and what each gathers, fourteen of them hold prototypes, and
each of those has a page listing its prototypes, what each argues, how to open
one, and which carry a Gemini review. Every prototype sits under the journey
topic it answers to.

The whole protection moved with the shape rather than being rewritten around
it. The guard now enforces the group pages, the review listings and the top
page, and the site build discovers the prototypes under the group folders
instead of naming all 46, so a new prototype needs an edit to no build file at
all. That retires 200 lines of near-identical deployment calls.

Every document that named a prototype path names the new one, which includes
eleven journey documents that had pointed at the React tree deleted in
October: their prototype sections now name a page that exists, and the backlog
capture that recorded the stale pointers is resolved.

Seven of the eight Gemini files are kept as six review screens, and the two
truncated prefixes are dropped.

No page is processed at deploy and no page carries anything the site adds. The
review pages lost the site stylesheet and header first, which were moving every
rem measurement and adding a whole menu bar, and the prototypes then lost them
for the same reason: the root font size went from 16px to 17px and the body
line height from 21px to 24.5px. A links table was tried in their place and
taken out again, because a reader judging a layout is judging everything above
the first pixel of the design. Every prototype page, design note and review
page is byte-identical to its source, and the whole tree renders exactly as its
author wrote it.

The unreviewed set moved to the page that already registers a prototype: the
group page's review cell says =none= for a prototype nobody has reviewed, and
the guard holds that cell to the review directory, so the grep stays
trustworthy.

  grep -rn '| none |$' doc/prototypes/*/index.org

No page is processed at deploy: the review pages lost the site chrome first,
which was moving every rem measurement and a whole menu bar, and then the
prototypes lost it too, for the same reason: the root font size went from 16px
to 17px and the body line height from 21px to 24.5px. Every deployed file is
byte-identical to its source, and the served page renders pixel-identical to
the file on disk.

Checks on =4f161ac260=: the guard passes; =compass lint= passes; the org link
check resolves every link; a scan of all 93 prototype paths named anywhere in
=doc/= finds each one on disk; the top page and all fourteen group pages are
published, and their links resolve to directories that exist; the built group
pages carry exactly three review links, one for each prototype that has a
review; and the four affected pages, including the repaired design document,
export with =0 failure(s)=. =ores-deploy-prototypes= was also run into a
scratch directory: it produced the grouped tree, put the site chrome on every
prototype and every review page, and preserved the review pages' body
attributes.

The full =compass build --direct site= was not run to completion. It passed
the page that used to abort it and was still exporting the older-sprint
backlog after an hour, so it was stopped. The scoped export is the decisive
check for this change; the full build is the job CI runs on =main=.
