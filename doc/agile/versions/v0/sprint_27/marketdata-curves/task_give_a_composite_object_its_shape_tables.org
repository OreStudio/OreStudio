* Goal

A term structure is drawn today from whatever pillars happen to be stored, so a caller cannot say what the object's shape is, what a missing point is missing from, or which points were added and dropped between two instants. Record the object's axes and their ordered values, so the shape is data rather than an inference from the points. Write it from the pillars a build produces, and validate every axis value that is a term against the reference tenor codes. The point-write check and the import declaration are the next task, not this one.

* Acceptance

- A composite object carries its axes and the ordered values of each, so its shape is readable without reading its points.
- A build declares the shape of the series it publishes, from the points it produced.
- Every axis value that is a term is a code the reference tenor table holds, and a value that is not is refused before any row is written.
- A series whose instrument type declares no coordinate gets no shape rather than an empty one.
- The existing series and points are unaffected: no point write changes, and a series with no shape declared still reads.

* Plan

Two current-state tables join the series by =series_id=, and a writer in =ores.marketdata.service= fills them.

The tables are codegen entities with the same shape the identity projection uses: current state, no audit columns, tenant isolation, and no wire surface, because the service writes them and a query reads them. The axes table holds one row per coordinate field of the series' instrument type, and the values table one row per value, both ordered by a =sequence= column.

The writer derives the axes from the instrument type's schema row, so the axes are the coordinate fields the codec already declares and no second vocabulary is invented. The values are the distinct texts the published points hold for each axis, in the order the build produced them. Every value of a term-kind axis is checked against =refdata_tenors= before anything is written, so a refused shape leaves no rows behind. The tenor read happens only when an axis is a term.

The hook is in =curve_republish_service::republish=, after the observations are written and before the lineage, so a curve's shape lands with the points it describes.

Out of this task, and recorded as the next one:

- The write-time check that refuses a point whose coordinate is not a declared axis value. It needs a hook on the observation write path, which is generated, so it is its own change.
- The import path writing a shape from the declaration it carries.
