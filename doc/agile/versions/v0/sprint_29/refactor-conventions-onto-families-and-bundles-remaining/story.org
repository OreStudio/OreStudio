* Goal

A convention is declared once, in its own entity, and carries only its own fields. When this story closes, nothing in the code holds every family at the same time, so a change to one family cannot break another family's build. An import applies the families it carries as one unit of work, and a failure names the family that failed. The ORE conventions file is a package the boundary maps, not a type the components share.

* Acceptance

- Each convention family has its own operation model, generated from its entity, and no reflected type in refdata carries every family.
- One generated list names the families, their scope, and their repository, and nothing hand-maintained duplicates it.
- An import applies its families in one unit of work and reports an outcome for each family. A failure rolls the whole import back and leaves it staging.
- The ORE conventions file crosses into and out of refdata as a package. No component shares a type that holds every family.
- The web reads the family list from the generated registry rather than a hand-written table.
- The configuration document protocol compiles on MSVC without a compiler flag that deepens constexpr evaluation.
- Every read an export takes is taken at one bitemporal instant.
