* Result

The relink blast radius is the version stamp, not the version API.

=cmake/generate_version.cmake= stamped =version.cpp= with the git hash and
compiled it into =ores.utility.lib=, alongside all of utility
(=set(lib_files ${files} "${version_cpp_out}")=). With =BUILD_SHARED_LIBS= on
that is a 12.7 MB =libores.utility.so=, and =ninja -t query= gives **179
targets** that hold it as a direct link input, from **154**
=target_link_libraries= sites naming =ores.utility.lib=. **45** translation
units include =version.hpp=.

So a commit had this shape: new hash, =version.cpp= recompiles, the library
relinks, and every target that links it relinks. With shared libraries that
relink is not required for correctness, but ninja does it because the =.so=
is a link input whose timestamp moved.

Two facts made the extraction clean, and both were checked rather than
assumed: nothing inside =ores.utility= uses version, so it is an orphan
there; and =ores.platform='s library does not link =ores.utility=, so
depending on =ores.platform= for the executable path creates no cycle.

The stale stamp was already as cheap as it could be before the work started:
=copy_if_different= meant the file was only rewritten when git state changed,
and the wall-clock time was never stamped. The cost was per commit, not per
build.

179 is the direct dependents. The transitive set is larger, because many of
the 179 are themselves shared libraries with dependents of their own; the
closure script did not finish, so treat 179 as a floor.
