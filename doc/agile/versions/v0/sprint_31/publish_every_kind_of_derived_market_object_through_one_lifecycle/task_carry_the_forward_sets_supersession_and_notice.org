* Goal

An FX forward publish supersedes the set it replaces and writes its notice, so the forward set behaves as the curve and the surface do. The pair is the forward's series, so one set of a pair is in use and the notice names the pair.

* Acceptance

- The forward publish row holds the superseded instant, the replacing request and the replacing as-of, and the apply writes them.
- The market data seed names the forward publish notice, and the apply writes it in the same transaction as the publish.
- A test proves that a second publish supersedes the first and that a reader receives the notice.

* Plan

Four edits, and one of them is the act's, not the kind's.

The columns go in the model, which is where codegen reads them, and they are the
three the curve and the surface already carry: =superseded_at=,
=superseded_by_request_id= and =superseded_as_of=, with the three checks that
keep them consistent with each other and with =published_at=. The regenerate
writes the entity, the mapper, the SQL and the web protocol type, so no hand
edit touches a generated file.

The supersession is the kind's. A forward set has no output series, so its
series is the pair: every live set of the pair and the party ends in the same
transaction that writes the successor, which is what the curve does with its
series. The kind reads the pair's published sets, which it already has, and ends
the ones no supersession or withdrawal has ended.

The notice is also the kind's, and the seed row is the only per-kind part of it:
=marketdata.fx_forward_published=, beside the three the market data seed already
names.

The act changes once. The doc states that the notice is a row written in the
transaction that publishes the set, so =apply_publication= now calls the
announcer with that transaction for every kind, instead of after the commit. A
publish that rolls back therefore never told anyone of a move that did not
happen.

The test sits in the notices suite, which already has the reader account a notice
needs: it writes a live set and a candidate of one pair, runs the kind's publish
and announce in one transaction, and reads back the four fields, the live set and
the notice the reader was given.

* Result

The forward set now behaves as the curve and the surface do: a publish ends the
set it replaces and tells the party's readers.

The three columns are in the model, so codegen wrote the entity, the mapper, the
SQL and the web protocol type, and the checks that tie them to =published_at= are
the ones the other two kinds carry. The supersession is the kind's: a forward set
has no output series, so its series is the pair, and every live set of the pair
and party ends in the transaction that writes the successor. The notice is the
kind's too, and its seed row is the only per-kind part of it.

The act changed once, for every kind. =apply_publication= now raises the notice
with the transaction that publishes the set, and commits both together, which is
what [[id:B3F03DBB-EBD1-4649-94E5-6C5C1B67A084][Announcement of change in a published market data set]] states: a
publish that rolls back never told its readers of a move that did not happen.
Before this, every kind announced after its commit.

The test writes a live set and a candidate of one pair, runs the kind's publish
and announce in one transaction, and reads back the four fields, the pair's one
live set, and the notice the reader was given. Two things it taught, both
recorded in the case: the store validates every account a row names, so the
publisher must be an account the store holds; and the notice names the account
that acted, so the apply runs under a context with that actor.

The gate: 100 of 108 suites pass in the parallel run. Four fail, and none is
this branch's:

- =ores.reporting.core.tests= is the break PR #5118 put on main, handed to the
  =solid_dirac= environment.
- =ores.inbox.core.tests=, =ores.refdata.core.tests= and
  =ores.workflow.core.tests= fail under =ctest -j= and pass when run alone on a
  freshly recreated database. The inbox suite's failure is a test tenant another
  suite left inactive; the other two are the pooler. This is a cross-suite race
  in the gate, not a defect of the change, and the blame recipe's first step is
  what separates it from a break.
