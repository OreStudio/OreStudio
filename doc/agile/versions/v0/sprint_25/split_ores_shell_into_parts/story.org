* Goal

=ores.shell= is one component with one CMake target, so a domain adapter
cannot link the shell plumbing without also pulling in the REPL host, and
codegen has no part to write a generated command unit into. Split the
component into parts behind one CMake root, declare it a codegen composite
so the root is generated rather than hand-maintained, and confirm the
result builds and tests as before.

* Decisions

- *Parts, not one target.* The split follows =ores.qt=: an =api= part holding
  the plumbing and an =application= part holding the runnable host. The
  naming rule for a part named after a component is now written into the
  component architecture catalogue, because the next wave adds
  =ores.shell.<domain>= parts and the name repeats at two levels of the tree.
- *The root is generated.* =ores.shell= is the first Application-layer
  component declared with =#+component_kind: composite=, so its root is
  codegen output like every other composite root.
- *No build-slice change.* The measured peak (one gcc translation unit at
  6.76 GiB against =MemoryHigh=8G) is recorded in the drop-in, but the values
  are left for a separate decision.

* Out of scope

- The per-domain adapter parts (=ores.shell.trading= and its siblings). This
  story only makes the split that lets them exist.
- The shell-command codegen facet, which the next wave picks up.
