* Notes

Split out of [[id:A8C22E8A-E9BD-4539-BEC4-A55451B325AC][Give the party
memberships their versions, and filter the business units]]. That task's other
two parts — the business-unit party filter and the level-rule refusal — shipped
on their own. This part is a codegen change, and it carries a design question
the other two did not, so it is its own task.

*The design question, which is unanswered.* Journey 6 says the screen shows
"when and by whom a membership was closed". That reads like a history dialog,
which is the generic diff route: =refdata.v1.history.get=, whose provider
interface is =(const context&, const std::string& entity_id)=
(=projects/ores.history.core/include/ores.history.core/service/dispatch_registry.hpp=).
A junction has no single-string id — its identity is the pair — so a junction
cannot be registered there without a composite-id representation decision. No
=party_country_history_provider_registrar= exists, and the history-provider
facet is =#+model_types: domain_entity=
(=projects/ores.codegen/library/templates/ores.cpp.history-provider-registrar.org=),
so junctions never render one. The versions sub-resource is *not* blocked on
that decision, but if the journey wants a field-level diff rather than a list of
versions, the sub-resource alone will not satisfy it. Settle this first.

*The mechanical change, which is well understood.* A junction is an entity whose
key spans the two sides it links, and its table already keeps the records: the
DDL carries =version=, =modified_by=, =valid_from= and =valid_to=, the insert
trigger does version management, and the delete rule closes =valid_to= rather
than removing the row (=sql_schema_junction_create.mustache=). What is missing
is the derivation. =junction_entity_shape()=, in
=projects/ores.codegen/src/codegen/org_loader.py=, returns a fixed literal that
sets =current_state: True= and never sets =has_audit_columns=. The versions
sub-resource is gated on =has_audit_columns=, and the service's
=get_<entity>_history= block sits inside ={{^current_state}}=. Its docstring
claims a junction "carries no =valid_from=/=valid_to= axis", which the DDL
contradicts.

The recommended shape is an opt-in drawer flag, because the alternative of
setting =has_audit_columns= in the shape would give the versions sub-resource to
all 20 junction models and change 20 components' protocols:

1. =junction_entity_shape()=: read =junction.get("list_versions", False)= into
   =has_audit_columns=, and correct the docstring. A new =* Flags= key needs no
   catalogue work — root Flags are copied to the junction dict verbatim
   (=org_loader.py=, the junction loader), and =check_model_drift.py= only
   compares features a bound profile fixes.
2. =:list_versions: true= in the =* Flags= of
   =ores.refdata.party_country_junction.org= and
   =ores.refdata.party_currency_junction.org=.
3. The tangled template sources, whose junction blocks have no versions bodies.
   These are the real work: =ores.cpp.repository.repository_header.org=
   (junction block), =ores.cpp.repository.repository_impl.org= (junction
   block) and =ores.cpp.service.service_impl.org= (junction block). The junction
   repository has no =read_all= and no =read_at_version=, and the junction
   service block has no ={{#list_versions_operations}}=/={{#get_version_operations}}=
   loop, so the header would declare methods the handler calls and nothing
   would define them. There are no paste points inside those blocks, so the
   templates themselves must change.
4. Tangle with =./compass.sh build --direct codegen_templates=, then regenerate
   refdata, then re-tangle the shell scripts and refresh the two inventories.

Everything else is free: the protocol header, the TypeScript twin, the handler,
the registrar, the shell commands and their tests, the shell recipe, the service
header and the domain type all walk ={{#messages}}=/={{#operations}}=, and the
shell plan already defines =list_versions= and =get_version=
(=org_loader.py=, the shell operation map). =refdata::party_countries:read= is
already seeded, so no new permission is needed. No CMake file changes, because
no new file appears.

The derived shapes are keyed by the link, which is the right key: the versions
list by =party_country_key= (both sides), and get by
=party_country_version_key { party_country; version }=. The =facet_stem= is the
singular, so the subjects are exactly =refdata.v1.party_countries_versions.list=,
=.get= and =refdata.v1.party_currencies_versions.list=, =.get=.

Two pinned codegen tests would break only under the unconditional variant, not
under the flag: =test_junction_protocol_verbs.py='s exact message-list assertion
and its =offset=/=limit= counts. A new case asserting the flag yields the six
version messages belongs beside them.
