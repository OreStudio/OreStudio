* Plan

No backwards compatibility. The old run names are deleted, not kept beside the
new ones.

1. Remove the controller's run surface. =/api/synthetic/running=,
   =runningFeeds()=, =useRunningFeeds()=, the folder fields =running_feeds=,
   =idle_auto_feeds= and =running=, and the totals that sum them. The feed page
   reads the adapter status, as the two tabs do.
2. The feed page needs its provider. Expose the provider on the feed read in
   the BFF, from the collection the feed sits under, and use the same
   provider-level source rule: serving and demanded. The feed status, Start and
   Stop, the Ticks tab and the process tab's running note follow it.
3. Names follow the service and the standard. Source and adapter for the market
   data side, provider for the vendor, demand for what makes a feed run, feed,
   process and engine for the record. Start and Stop are the operator test
   control. Delete every "should run", "running feeds" and "auto-start" used to
   mean demand.
4. The process tab's recorded gaps: render the engine-change notice that exists
   in the catalogue, add the missing column tooltips and the engine note, and
   show the simple-mode reason instead of falling back silently.
5. Run the BFF, web typecheck and web tests, then the gate. No screen, route or
   word beyond these.

* UX revision, agreed after the live check

The counters do not reconcile because two rules feed the same tree. The
provider roll uses the source rule (serving and demanded), while the asset
class and folder rolls still use the service's controller counts. One rule
must drive every level.

- Every feed has one state: serving when its provider's source serves and is
  demanded at least one id. Every roll, every tag and every tile counts that
  state, and no other count is added beside it.
- The Synthetic screen becomes a dashboard, in the dashboard language: total
  providers, feeds serving, feeds stopped, ids demanded and ticks, then the
  provider list. The banner stays only for the demanded feeds that are not
  serving.
- The provider's screen gets a tab called Provider, not Feed tree. A provider
  combo at the top chooses the provider, a tree on the left shows only that
  provider, and the grid on the right lists its feeds.
- The grid loses the oresmd URI column, which breaks its width. The series is
  reached from the feed page as it already is.
