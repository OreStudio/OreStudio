* What

Build the five DQ screens in ores.web from the signed-off prototypes: reference
data coverage, publish a dataset, publish a bundle, correct one artefact, and
trace a published value. Each prototype is the design record under
=doc/prototypes/dq/=, and each journey under =doc/knowledge/journeys/dq/= states
the operations its screen needs and whether the server serves them.

* Why

The design is finished and signed off; the product has no DQ screen at all,
which is why an empty catalogue after a recreate went unnoticed. Three of the
five journeys cannot be built as drawn until the server carries what they read:

- a coverage operation that answers readiness, member counts and the preview —
  =ores_dq_bundles_list_fn=, =ores_dq_bundle_datasets_list_fn= and
  =ores_dq_bundle_preview_fn= compute all three and no subject serves them;
- a per-dataset preview, and a published-row count per dataset;
- any read or write of an =ores_dq_*_artefact_tbl=, without which the artefact
  correction cannot start;
- a used-by path from a published value to the trades that reference it, which
  needs the reference to be an identifier or the text to be indexed.

The run log also has no writer, so no screen can show a publication history
until one exists.
