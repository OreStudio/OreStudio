* Acceptance

- The check passes with no new baseline entry.

* Plan

A teammate's local check failed on main. =check_entity_table_writes.py= reported two new writers, =work_ledger_repository.cpp= and =work_tenant_repository.cpp=. Both are the hand-written repositories of installation-owned tables that have no entity model, so no generated repository exists for them. The check could not tell such a repository from code that bypasses one, and its own advice, to move the write into the repository, was already done.

- A hand-written file named =<name>_repository= is the repository of =ores_<component>_<name>_tbl=, with the name singular or plural. The check lets it write that table.
- A repository that also writes another table, a file that is not a repository, and a repository of another name are still reported.
- The scheduler's =job_instance_repository.cpp= was in the baseline as a writer that predates the check. It is the repository of its own table, so the check no longer reports it and the stale entry is dropped. The baseline shrinks from 124 to 123.
- No baseline entry is added for the two new files.
