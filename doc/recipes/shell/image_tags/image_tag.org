#+title: How do I run the image_tags commands from the shell?
#+description: Every command the image_tags submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:image_tags:

This file documents the image_tags resource at the shell, one section per command. Every command is a subcommand of =image_tags=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 90326854-5566-529B-A360-C4FD384A2490
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
image_tags list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =assets.v1.image_tags.list=.

#+name: image_tags-list
#+begin_src ores-shell :tangle image_tags-list.ores :exports none
image_tags list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: F70B2DFD-D359-5EA0-8632-5CB2E19F2B6F
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
image_tags get <image_id> <tag_id>
#+end_example

It is addressed at =assets.v1.image_tags.get=.

#+name: image_tags-get
#+begin_src ores-shell :tangle image_tags-get.ores :exports none
image_tags get 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000
#+end_src

** =add=
:PROPERTIES:
:ID: 80BEFDB2-C74A-5229-B0CF-94A4D205A599
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
image_tags add <image_id> <tag_id> <assigned_by> <assigned_at> <reason> <commentary>
#+end_example

It is addressed at =assets.v1.image_tags.put=.

#+name: image_tags-add
#+begin_src ores-shell :tangle image_tags-add.ores :exports none
image_tags add 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 __none__ 1970-01-01T00:00:00Z system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: AA8CBBB7-4141-5050-9FFC-408B71045C80
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
image_tags set <image_id> <tag_id> <assigned_by> <assigned_at> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =assets.v1.image_tags.put=.

#+name: image_tags-set
#+begin_src ores-shell :tangle image_tags-set.ores :exports none

#+end_src

** =by-image-id=
:PROPERTIES:
:ID: 9FAC9655-8528-59C9-A0FD-DA9E5C2710FA
:END:

Reads one page of the rows that share a relation value. The relation is part of the address rather than a filter applied after the read.


The command is shaped like this:
