#+title: A system bundle installs the catalogue and the simulator installs its own universe
#+description: Where each market data definition lives, which component installs it, and how an adapter's advertised universe is only a check.
#+type: knowledge
#+level: cross
#+filetags: :marketdata:catalogue:bundle:provisioning:
#+created: 2026-10-22
#+updated: 2026-10-22

* Summary

Every definition has one home. The market data service holds the catalogue:
providers, sources, vendor instruments, mappings and rate cards. The simulator
holds its generators and its universe. A system bundle installs both, in the
system tenant and the system party. An adapter's announced universe is checked
against the catalogue and never defines it.

* Detail

** Where each definition lives

| Definition | Home | Installed by | Changed by |
|------------+------+--------------+------------|
| Provider, source, rate card | =ores.marketdata= | System bundle | System administrator |
| Vendor instrument and mapping | =ores.marketdata= | System bundle | System administrator |
| Generator, collection, folder | =ores.marketdata.synthetic= | System bundle | Simulator author |
| Simulator universe | =ores.marketdata.synthetic= | System bundle (from the generators) | Simulator author |
| Subscription and route | =ores.marketdata= | Profile or party administrator | Party administrator |

This table answers the question of where a feed is defined. The provider's feed is
a set of catalogue rows. The simulator's way to produce it is a generator.

** The universe check

At announce, the adapter sends its universe. The service compares it with the
catalogue rows of its provider.

- An id in the catalogue and in the universe is served.
- An id in the catalogue and not in the universe cannot be demanded. The source
  screen lists it.
- An id in the universe and not in the catalogue is ignored and logged.

** Why two homes

The service must own the catalogue because the mapping is the same for every
source of a provider. The simulator must own its generators because only it needs
them. A real adapter has no generators.

** The system bundle

The bundle publishes into the system tenant only. A tenant's own setup never
writes the catalogue. A new tenant gets no market data rows, only subscriptions
and routes.
