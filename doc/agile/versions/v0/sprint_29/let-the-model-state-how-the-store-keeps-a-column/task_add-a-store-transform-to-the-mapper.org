* Acceptance

- A column states a store transform and the header that declares it
- The generated mapper calls the transform on the way into the row, and not on the way out of it
- A column whose domain member is optional keeps absence absent through the transform
- The eleven refdata convention columns state the transform in their models, and a regeneration keeps the call and its include

* Plan

The mapper template already branches on the shape of a column, and the store
transform has to follow the same three shapes: a plain column passes the value,
a nullable string passes the value or the empty string, and a column whose
domain member is =std::optional<T>= maps inside the optional. The first two
branches took the transform, and the third is what the convention columns
actually are: their models state =:cpp_type: std::optional<std::string>= with
=:nullable: true=, so the mapper reaches them through =is_already_optional=.

The header is a gate like the enum and date includes: the model names it, the
gate lists it once, and the template emits it in the same include block.

The eleven columns then state the transform, and a regeneration writes the
call. The hand edit is gone, so nothing has to be re-applied after a codegen
run.

* Result

The transform is a property of the model. A generated mapper applies it on the

includes the header once. The eleven convention columns state it, and a
regeneration against the tree changes nothing.

The document round trip and the ORE example suite both pass, so the store keeps
the seven codes while the documents keep the spellings they state.
