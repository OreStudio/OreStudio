* Goal

The compass- prefix separates our skills from every plugin skill the harness also loads. The rename touches the source directory, the deployed directory, the name field in each skill's frontmatter, the generated catalogue, the org-roam links that reach each skill, the runbooks, the memories, CLAUDE.md, and the settings file. Deployment does not remove stale directories, so each old deployed directory must be deleted by hand. Build the rename as a script rather than by hand, so a reviewer can re-run it and so the next rename is cheap.

* Plan

The rename is a script, as the goal asks. Doing it by hand across 271 files
is how a reference gets missed, and the script makes the next namespace
change cheap rather than another week of the same work.

=build/scripts/rename_skills_to_compass_namespace.py= moves each source
directory with =git mv=, rewrites every mention across the repository, and
purges the deployed directories deployment would otherwise leave behind. The
rewrite orders names longest first, so renaming a shorter name never eats a
longer one that contains it, and it matches on word boundaries that treat the
hyphen as part of the name. The =name:= field the harness reads is rewritten
by the same pass, because it is just another mention.

The script is idempotent: a skill already carrying the prefix is skipped, so
a second run reports nothing to do. =--check= makes that an assertion, and it
runs in the Doc Lint workflow, so a skill added without the prefix now fails
CI rather than sitting outside the namespace until someone notices.

* Notes

The catalogue generator grouped skills by their first segment, which after
the rename is =compass= for all 69. It now strips the namespace before
grouping, so the domain register still drives the sections.

Two generator scripts under =build/= were missed on the first run: the
script skipped =build/= wholesale, which is reasonable for 40G of output and
wrong for the scripts beside it. The skip is now by subdirectory, and the
two files carry the names a fresh run produces.

Three classes of survivor are deliberate. Discarded captures and closed
sprint records that name skills retired in the previous task keep their
text, because the successor did not exist when they were written and
rewriting them would falsify the record. =pstack.org= names upstream skills,
which the registers do not govern. =compass_timeline.py='s =pr-opened= and
=pr-merged= are event names that merely look like skill names.
