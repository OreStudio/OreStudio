* Acceptance

- Every point's source kind is recorded, quoted, derived or manual.
- A manual point records the actor, the time and the reason.
- There is one annex. It broadens =observation_lineage= or renames it, rather
  than standing as a second cold table beside it.
- The annex is keyed by the point's natural key and read on the point path only
  when provenance is asked for.

* Plan

The annex already exists. =observation_lineage= carries =point_source_kind=
(=derived= or =manual=, with quoted as the absence of a row), the actor, the
reason and the record time, and =write_manual_point= writes it with the point in
one transaction. What no read did was return it. So the work is the read:

1. Add =observation_lineage_repository::read_latest_for_points=, which reads the
   current annex rows of the points a caller states and nothing else.
2. Add =include_provenance= to the snapshot request and a =provenance= entry per
   node to the response, in the operations model, then regenerate the header and
   its TypeScript twin.
3. In =series_snapshot_reader=, read the annex only when asked and only for the
   points the read placed.
4. Test quoted, manual and hole entries, and that a caller who does not ask gets
   none.

Decision: provenance rides on the snapshot, because the snapshot is the read that
returns the value, and a flag keeps the annex off the point path. The evolution
read does not carry it. It returns many instants, so a per-instant annex read
would need its own decision.

* Result

A reader can now tell a quoted point from a derived one from a manual override,
and name who over-keyed a manual point and why.

The annex was already one table. =observation_lineage= carries =point_source_kind=,
the actor, the reason and the record time, and =write_manual_point= writes it with
the point in one transaction. A point with no row is quoted. What no read did was
return it, so this task adds the read.

- =get_curve_snapshot_request= takes =include_provenance=. The response then
  carries one =point_provenance= per node: the source kind, who set the point, the
  reason code and commentary, and when the annex row was recorded. A hole has an
  empty entry.
- =observation_lineage_repository::read_latest_for_points= reads the annex rows of
  the points the snapshot placed and nothing else. The snapshot reader calls it
  only when asked, so a caller that does not ask pays nothing.
- The method is in the lineage model, not hand-written, so the codegen drift check
  stays clean. The header and its TypeScript twin regenerate from the operations
  model.

Two tests cover it. One reads a quoted node, a manual node with its actor, reason
and time, and a hole. The other shows a caller that does not ask gets none.

Not done here. The evolution read does not carry provenance. It returns many
instants, so a per-instant annex read needs its own decision.
