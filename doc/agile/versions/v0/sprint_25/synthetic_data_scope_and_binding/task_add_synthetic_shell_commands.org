These commands enable non-GUI market simulator operations, scripting, and testing without requiring the Qt client.

* Acceptance

- `synthetic list folders` shows only folders visible to the logged-in party (via RLS filtering)
- `synthetic list configs` shows only market_data_generation_configs visible to the logged-in party/tenant (system/tenant/party scope filtering)
- `synthetic start <feed>` and `synthetic stop <feed>` start/stop individual feeds or folders of feeds
- `synthetic validate-vintage <feed>` validates vintage data availability for a feed
- All commands respect RLS and scope-based filtering (same as Market Simulator Qt client)

* Plan

** Extend ores.shell.synthetic_commands
- Add `list folders [--config-id=<id>]` subcommand
  - Calls `get_folders_request` with viewer's context (RLS automatically filters by party)
  - Displays folder hierarchy (root > collection > asset class > instrument type)
  - Optional --config-id filters to children of a specific collection

- Add `list configs [--scope=system|tenant|party]` subcommand
  - Calls `get_market_data_generation_configs_request`
  - RLS automatically filters by scope (system/tenant/party)
  - Optional --scope flag filters to specific scope level(s)
  - Display: name, id, scope, party_id, binding_mode, enabled status

- Add `start <folder-id>` and `stop <folder-id>` subcommands
  - Folder-scoped: calls `start_feeds_under_folder_request` / `stop_feeds_under_folder_request`
  - Resolves to all FX pairs and IR curves under the folder

- Add `start <feed-id>` and `stop <feed-id>` subcommands for individual feeds
  - Per-feed: calls `start_feed_binding_request` / `stop_feed_binding_request`

- Add `validate-vintage <feed-id>` subcommand
  - Calls `get_vintage_validity_request` to check data availability
  - Displays vintage validity status (pass/fail + reason)

** Implementation details
- Add methods to synthetic_commands class for each subcommand
- Reuse existing NATS request/response patterns from MarketSimulatorWindow
- All commands inherit viewer context automatically (via process_authenticated_request)
- Error handling: report RLS violations, missing entities, feed state errors
