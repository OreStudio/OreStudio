* Acceptance

- The codegen reads both declarations.
- A field added later is economic or not by declaration, not by default.

* Plan

*Not started.* The digest task ships without this one, using a name-based rule
in =ores.trading.api/domain/economic_digest.hpp=: a fixed list of identity and
audit names, an =_id= suffix rule, and a small allow-list of =*_id= names that
are external identifiers rather than foreign keys. That rule lives in code, so
it is the very thing this task exists to replace.

Two things the code rule cannot do, with a worked reason for each:

- It cannot tell a money field from a continuous one that shares a name shape.
  A field called =amount= is economic, and a field called =accrual_amount= is
  too, but the rule sees only the token.
- It cannot tell an external identifier from a foreign key when neither is in
  the allow-list. =security_id= is in it today because a trade re-pointed at a
  different security is a change the customer agreed to; the next such field
  needs another line of C++.

What the task adds, in order:

1. A =:economic:= knob on a column in the entity model, and a way to state the
   components that make up a shape.
2. Codegen that emits the declaration — a per-entity list of economic field
   names the digest can consume.
3. The models declare it, so =economic_digest= stops consulting a name list.

The knob is also where a per-field =economic= marking closes the gap recorded
in =doc/knowledge/architecture/exact_numbers_and_economic_change.org=, if the
two turn out to be the same declaration.
