#+title: ores.trading.bond_leg
#+description: Codegen entity model for the trading =bond_leg= table. Drives the C++ domain class, mapper, repository, service, generator, and SQL schema generation from a single literate source.
#+type: ores.codegen.entity
#+component: trading
#+filetags: :model:entity:trading:
#+brief: One leg a trade's product states, keyed to the trade, the leg's role and its ordinal.
#+entity_singular: bond_leg
#+entity_plural: bond_legs
#+entity_title: Bond Leg
#+created: 2026-09-11
#+updated: 2026-09-11

One row per leg a trade's product states, keyed to the trade, the list
the leg belongs to and the leg's ordinal within that list.

The total return swap, the repo and the ascot each state at most one
leg of their own, and all three are the same leg shape. One table holds
them and =leg_role= says which list the row belongs to. The bond's own
legs belong to the security and are held by =bond_issue_leg=.

The row carries the leg's payment terms, its day counters, its
settlement block and the two flags the schema states on the leg itself.
Everything else the leg states lives in a table of its own: the
schedules in =instrument_schedule=, the amortizations, the named
amounts and the rate group below. Those tables key on =leg_role= as
well, so a schedule or an amount reaches the leg that stated it.

Every member the schema declares optional is nullable here and an
=std::optional= in C++, so a member the document states and the row
cannot hold stays distinguishable from one the document omits.

* Columns

** trade_id
:PROPERTIES:
:type:        uuid
:cpp_type:    boost::uuids::uuid
:primary_key: true
:supplied_by:  user
:END:

The trade this leg belongs to.

The trade row carries the workspace and the party. The
leg rows are family-owned and ride the trade's scope, so no
workspace column rides them.

** leg_role
:PROPERTIES:
:type:        text
:cpp_type:    std::string
:primary_key: true
:END:

Which leg list of the trade this row belongs to: =trs_funding=,
=repo= or =ascot_swap=, the single leg of a total return swap, a repo
or an ascot.

A document states each of the three as at most one leg. They are the
same leg shape, so one table holds them and the role says which member
of the document a reader rebuilds. Without the role a leg numbered one
would be ambiguous between them.

The bond's own legs are stated by the security rather than the trade,
so they live in =bond_issue_leg= and never carry a role here.

** leg_number
:PROPERTIES:
:type:        integer
:cpp_type:    int
:primary_key: true
:END:

Ordinal of the leg within its list, counting from one.

Each of the three roles carries one leg, which is always number one.

** payer
:PROPERTIES:
:type:     boolean
:cpp_type: std::optional<bool>
:nullable: true
:END:

True when the leg's payer is the trade's counterparty rather than the
party.

** leg_type
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

The leg's type as the document spells it, such as =Fixed= or
=Floating=.

The type is the document's own member and drives which arm of the rate
group a document states. It is kept as text, not decoded, so export
re-emits the spelling.

Soft FK to ores_refdata_leg_types_tbl: leg types belong to ores.refdata (Fixed, Floating, OIS, CMS, ...), so the dependency is recorded rather than copied. PR 4 tightens the soft reference into a real foreign key.

** currency
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

ISO 4217 currency code of the leg.

Soft FK to ores_refdata_currencies_tbl: ISO 4217 currency codes belong to ores.refdata, so the dependency is recorded rather than copied. PR 4 tightens the soft reference into a real foreign key.

True when the leg's notional exchanges fall on the schedule's dates

** indexings_from_asset_leg
:PROPERTIES:
:type:     boolean
:cpp_type: std::optional<bool>
:nullable: true
:END:

True when the leg takes its indexings from the asset leg rather than
stating them.

** settlement_fx_index
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

FX index the leg's settlement block fixes against.

The block is present when this column is set. The schema requires the
index on a settlement block, so a null column and an absent block are
the same statement, and one column carries both.

** settlement_fixing_date
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

Date the settlement block's FX index fixes on (ISO 8601 date string).
