* Acceptance

- The four new instrument tables carry a tenant isolation policy and a restrictive party isolation policy.
- Every permission code the new handlers check is seeded.
- The committed ER diagrams match the schema, and the strict parser reports no warning.

* Plan

The four defects are one omission seen four ways: the tables were added to
the schema and to the code, and not to the three things that surround a
trading table. So each fix puts the table where its neighbours already are
rather than inventing a new arrangement.

Row-level security lives in one file per component,
=trading_rls_policies_create.sql=, and not in the table's own script, so
the four blocks go there, in the shape the FX instrument blocks use. The
permission codes live in the IAM seed and follow its alphabetical order
within the component block. The diagrams are generated, so the fix is to
run their generator rather than to edit them.

One thing is not a fix and is left alone: the reconciliation between the
four checks and the four tables is a coincidence of naming. The
=er-diagram= check failed because the strict parser refuses a warning at
all, and the warnings were the missing policies; the =handler-permissions=
check failed because the handlers name codes the seed does not hold. A
later table that omits either will fail the same two checks, which is what
they are for.

* Result

The four checks pass on this branch. The tables are isolated the way the
tables beside them are, the codes their handlers check are seeded, and the
strict parser reports no warning.

This is proved against a database rather than against the text: the
database was rebuilt from the schema, and the four tables come back with
=relrowsecurity= true and eight policies, four permissive tenant policies
and four restrictive party policies. Reading the SQL alone would not show
whether a policy names a function that exists or a column that does not.

*Gate.* =compass check --exclude-heavy= passed 20 of 20 checks for this
diff, which classifies as =docs= and =sql=. No build was needed: the change
holds no C++, so the heavy checks (build, database, ctest, smoke) test
nothing it can break, and were skipped.

*What this does not fix.* Four other checks are red on this branch for
reasons that predate it and that this change does not touch. They are
listed so the next reader does not mistake them for fallout:

- =component-drift=: 26 generated files differ from their models, starting
  with the claim rows of =script_variant_repository.cpp=.
- =money-decimal-columns=: =volatility= in =equity_position_instrument= and
  =quantity= in =equity_position_option_underlying= are exact decimals for
  quantities the check treats as continuous.
- =bff-list-requests=: the generated list request table is stale.
- =codegen-tests=: 4 of 1809 tests fail, on the RLS junction flag, the
  trade type catalogue and the domain includes.

Each is a separate defect with its own owner and needs its own change.
