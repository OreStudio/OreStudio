#+title: How do I run the results commands from the shell?
#+description: Every command the results submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:results:

This file documents the results resource at the shell, one section per command. Every command is a subcommand of =results=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: D1FEF7ED-CA8A-508D-85A2-21C35524B812
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
results list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =compute.v1.results.list=.

#+name: results-list
#+begin_src ores-shell :tangle results-list.ores :exports none
results list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: E978EBC6-DA6E-5729-A910-B5D36CBDF152
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
results get <id>
#+end_example

It is addressed at =compute.v1.results.get=.

#+name: results-get
#+begin_src ores-shell :tangle results-get.ores :exports none
results get 00000000-0000-0000-0000-000000000000
#+end_src

** =add=
:PROPERTIES:
:ID: 24409BC2-B5EA-572F-A901-959A4C776F54
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
results add <id> <workunit_id> <host_id> <pgmq_msg_id> <server_state> <outcome> <output_uri> <error_message> <received_at> <reason> <commentary>
#+end_example

It is addressed at =compute.v1.results.put=.

#+begin_src ores-shell :tangle results-add.ores :exports none
results add 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 0 0 0 __none__ __none__ 1970-01-01T00:00:00Z system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 17599E39-944B-5E72-8273-355384277BC1
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
results set <id> <workunit_id> <host_id> <pgmq_msg_id> <server_state> <outcome> <output_uri> <error_message> <received_at> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =compute.v1.results.put=.
