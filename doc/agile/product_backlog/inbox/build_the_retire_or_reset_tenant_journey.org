* What

Build [[id:00179132-3463-45E9-A6FC-75B0F3EBCC8E][Retire or reset a tenant]]. Its
coverage table records what is missing:

- *Suspend* has no operation. The status row, the permission
  (=iam::tenants:suspend=) and the promise that users cannot sign in exist; the
  subject and the function that writes the status do not.
- *Terminate, deprovision and purge* have SQL functions
  (=ores_iam_terminate_tenant_fn=, =ores_iam_deprovision_tenant_fn=,
  =ores_iam_purge_tenant_fn=) and no subjects.
- *A party-level reset* (=ores_iam_reset_tenant_fn=) has no subject; the one
  that exists sends the tenant back to bootstrapping.

Then the roster's row menu offers *Retire or reset*, which it shows as not
built until then.

* Why

Found while building the roster's row actions: the menu's destructive item has
no server path, and the journey says the screen must not offer what the server
cannot do. Two related defects -- the unguarded system-tenant delete and the
sign-in path that ignores a suspended tenant -- are already a task:
[[id:8DE384EE-E273-42AA-B0B6-81B2AE759BD4][Fix the security defects the ores.iam clean-up recorded]].
