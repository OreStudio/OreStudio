* Goal

An installation ships with every store it keeps already bounded. The store
catalogue states a default retention policy for each store that can take one — a
quarter for report output, a month for delivery counters, a week for job inputs, a
day for scratch — and provisioning creates the policy, so nobody has to notice
the absence before the store starts growing. A store without a policy then means
one of two things, and both are worth a person's attention: the store's bound
cannot be expressed as an age, or somebody removed the default.

* Acceptance

- The store catalogue states, for each store, whether it carries a policy and the default period and action when it does
- Provisioning creates the policy for every store that states one, in the tenant that owns the store, and a second provision leaves exactly one policy per store
- The default period follows the kind of data: run output a quarter, counters a month, job inputs a week, scratch a day
- The policy rows are delivered as platform data like the sweep itself, so a default changes without a schema rebuild
- A store whose bound cannot be expressed as an age (the calendar dates) states that, rather than carrying a default that does nothing
