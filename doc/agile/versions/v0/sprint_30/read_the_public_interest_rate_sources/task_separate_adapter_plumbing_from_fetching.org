* Goal

Each public source has its own adapter, because each publisher has its own API, its own format and its own terms. The code that does not depend on the publisher is shared: the announce, the demand set, the backfill from the latest stored fixing, the refresh and the publish of ticks. An adapter supplies a fetcher for its publisher, which names its adapter code and the notation of its ids, and nothing more. The process hosts every adapter, as =ores.synthetic.service= hosts the simulator and the derived source. The Frankfurter adapter is the first fetcher, and its behaviour does not change.

* Acceptance

- The shared half holds the code that does not depend on the publisher, and the Frankfurter adapter uses it through a fetcher.
- The shared half does not name a publisher, a publisher's key or a publisher's format.
- A source names the adapter that reads it, and the process refuses a source whose adapter it does not host.
- The tests of the Frankfurter adapter pass with no change to what they assert, and a fresh environment stores the same count of FX fixings as before.
- A new adapter supplies its fetcher and its settings, and nothing else.

* Plan

The process stays one process. =ores.synthetic.service= already hosts two adapters, the simulator and the derived FX volatility source, so a process that hosts several adapters is the existing pattern, not a new one.

- =domain::fetcher= is the specialised half: the adapter code, the id scheme and field, the universe of a key, and the fixings of a key over a window, as =published_fixing= values.
- =frankfurter_fetcher= implements it. The pivot and the refusal of a rate in another base stay inside it, because they are Frankfurter's.
- =source_feed= reads through a =fetcher&= and speaks its notation, so it no longer names a currency or a rate.
- =hosted_source= gains =adapter_code= and renames =frankfurter_key= to =key=. A =--source= is =<source name>:<provider code>:<adapter code>:<key>=, and the service registry's four sources name =frankfurter=.
- =official_adapter= takes the fetchers it hosts and gives each source the one its adapter code names. The announce takes its adapter code from that fetcher.

* Notes

Today the adapter knows only Frankfurter. =source_feed= takes a =frankfurter_fetcher=, =hosted_source= has a =frankfurter_key=, and =official_adapter.cpp= sets the adapter code to ="frankfurter"=. The synthetic simulator and the derived FX volatility source in =ores.synthetic= are adapters too, and one process hosts both.

Two publishers share one adapter only when their API and format are the same, as the Frankfurter providers are. Otherwise each publisher has its own adapter.

* Result

The official adapter is now a host of specialised adapters. =domain::fetcher= is the specialised half, which names its adapter code and the notation of its ids, and reads its publisher's universe and its fixings over a window. =frankfurter_fetcher= is the first fetcher, and the pivot and the refusal of a rate in another base stay inside it. =source_feed= and =official_adapter= are the shared half and name no publisher. A =--source= names its adapter, =<source name>:<provider code>:<adapter code>:<key>=, and the process refuses a source whose adapter it does not host.

The behaviour of the Frankfurter sources did not change. The nine existing cases pass with only their construction changed. A restart of the running service with the new binary announced the four sources with no unknown id and sent their backfill, and the store added nothing, as it skips what it holds. Seven new cases cover a fetcher in another notation, a read of fixings before the universe, the source format, a source whose adapter is not hosted, and two fetchers of one adapter.

The component overview, its diagram and the architecture note now describe one adapter for each access route.
