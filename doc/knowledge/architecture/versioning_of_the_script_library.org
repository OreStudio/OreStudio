#+title: Versioning of the Script Library
#+description: The script library as versioned reference data of the system tenant, the sources from which its versions arise, and the processing applied when a script is loaded or published.

* Summary

The library of payoff scripts is reference data of the system tenant. Each
script, each of its variants (a variant serving a purpose such as =FD= or
=AMC=), and its inputs, results and calibrations are held as rows
([[id:833F8F79-7FF0-42B0-8C52-E3ED6596843E][ores.trading.script]], [[id:A2BE6361-0489-4A63-A1B7-6B07BB3F6000][ores.trading.script_variant]], [[id:F08D458F-B694-4B2F-A945-E22544A9222F][ores.trading.script_input]]). Every change constitutes a
version, whether it arises from a new release of ORE's library, from a
correction ORE Studio applies to a script that ORE distributes, or from the
publication of a user's own script. Since a trade records the version on which
it was booked ([[id:358CC548-3892-45A1-A916-DF4A48ADED03][Library and Inline Scripts in Scripted Trades]]), no change to the library silently alters the
valuation of a booked trade.

* Detail

** Sources of versions

- *ORE's library.* The seed reproduces every script of ORE's
  =scriptlibrary.xml= as ORE distributes it. It is generated by compass-ng's
  =script_library_seed= codec and is never edited by hand.
- *Corrections.* Where ORE distributes a script that ORE itself cannot execute,
  a correction writes a new version of the affected variant after the seed has
  been loaded (=trading_script_library_corrections_populate.sql=). A correction
  applies only when its text occurs exactly once, has no effect once the code
  already contains its replacement, and otherwise causes the load to fail, so
  that any change ORE makes to the script is reviewed. At present it corrects a
  missing semicolon in =WorstOfBasketSwap= and the =FD= variant of
  =GenericBarrierOption=, which rolled its values back only as far as the first
  monitoring date.
- *User scripts.* The publication of a user's script is a change to reference
  data like any other, and is preceded by parsing ([[id:8FD7BD95-AAEC-4CF9-A9F4-D609A9DEFBD8][Script Parsing with ORE's Grammar]]).

** Processing on publication

A script is parsed when it is published, not when ORE first executes it. A
script that fails to parse is rejected at load or publication, with the line and
column reported by ORE's grammar. Its inputs are derived from its text
([[id:92449D70-09E2-4391-B716-A1001F22B271][Derivation of Script Inputs from Free Variables]]) and stored with it.

** Delivery to the engine

Each run writes the library from the stored rows, so that a script absent from
the store causes the failure of any run that requires it, and the engine reads
the stored versions rather than the copy distributed with ORE ([[id:708554F7-FA3A-49E1-8A11-4AE968C76758][Script Execution and Compilation in ORE]]).

** Divergence from the current implementation

The inputs are extracted into the seed by a text-processing script rather than
derived by a parser, and no script is parsed before ORE parses it; the syntax
error in =WorstOfBasketSwap= was discovered through a failed ORE run. A trade
records no library version.
