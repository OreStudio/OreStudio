* Result

A report in the reporting area now carries the result of its latest run.

The page has three tabs. *Definition* is the record as before. *Runs* lists the
report's runs newest first, each with its state and when it started and finished,
and each opens the run it names. *Results* reads =npv.csv= from the latest run's
output archive and draws the trade count and the total of each currency first,
then one row per trade with its type, NPV, base NPV, notional and counterparty.
No other screen carries a copy: the run page links here.

The run that proves it is =9ff0e92e-f21d-4137-bb24-ad4956fa99f0=, on the NPV
definition of ACME Corporation HK Ltd. It completed, and its Results tab shows
eight bond trades and a total NPV of =31,607,092.99= HKD. The Runs tab shows the six
runs of that definition, one completed and five failed, which is the history of
the market data work that led here.

The market data the run priced against is hand crafted: 521 swap series for
fourteen currencies, each with an observation at 2026-05-05, in the shape the
engine names (=IR_SWAP/RATE/<ccy>/0D/1D/<term>=, with the term in the months or
years the engine asks for).

The answer carries a reason code rather than a sentence, so the screen words
an empty run, an output with no =npv.csv= and a file with no figures in the
reader's language.

Three things are deliberately not here yet. The comparison against a previous
run, the book tree and the plots are the rest of variant A. The counterparty
column shows the id the engine writes, not a name. And the reports list pages at
fifteen rows, so a person finds an =NPV= report by searching for it.
