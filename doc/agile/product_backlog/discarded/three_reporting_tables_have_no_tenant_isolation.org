#+title: Three new reporting tables carry tenant_id and no tenant isolation
#+description: The strict SQL validator fails on main: ores_reporting_report_analytics_tbl and ores_reporting_report_run_setups_tbl declare :has_tenant_id: true with no profile, so the RLS policy generator emits no policy for them, and ores_reporting_analytic_types_tbl is a simple-lookup table in the same state. The live database confirms it: pg_policies has zero rows for all three. A table with tenant_id and no policy is one tenant reading another's rows. reporting_rls_policies_create.sql enables row level security for the tables that do declare a profile, and the validator's ignore file suppresses RLS_001 for the ones known to be handled elsewhere, which is why no PR can be green until this is fixed. Arrived with the reporting run document and analytics work.
