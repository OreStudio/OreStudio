* Acceptance

- The family tasks are done: credit, interest rate, FX, bond, equity, commodity and scripted.
- A run of the Acme reports after provisioning records no Trade errors, only market data errors.
- The recorded trades' known lists end empty, or with a stated reason per entry.
- Every remaining =construct_*= function and =*_terms= struct is deleted.
- Catalogue trade types the generator does not book are recorded as not generated, each with its reason.
- =CommodityPairwiseVarianceSwap= leaves the generator or takes a real ORE trade name, because ORE has no such trade.
- Tests catch the FxOption style and FxSwap far leg defects that the first Acme run found.

* Notes

** From the review of PR #4474

Points the review raised on the recorded-trades test and the writer, left
for this task because it edits both:

- =state_reason= in the writer skips a row with none of the three audit
  shapes without a word; end it with a =static_assert= so a new row type
  that fits none fails to compile.
- =known_refusals()= mixes writer refusals with the three bond types the
  in-memory path cannot join; split the test-only ones into a list of their
  own, so the case's name says what it asserts.
- =sample_requirements()= should =REQUIRE= the corpus directory, for a
  clear failure when =external/ore= is missing.
- The recorded files compare as exact text; check line endings
  (=.gitattributes= for =tests/data=) and number formatting on the Windows
  build.
