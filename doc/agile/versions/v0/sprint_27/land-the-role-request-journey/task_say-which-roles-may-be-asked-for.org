* Goal

A tenant administrator can say which roles a member may ask for. Today every role in the tenant is on offer: the screens filter the list and the ask operation refuses what it should, so the rule lives in two places and the tenant can state it in neither. Add is_requestable to ores.iam.role, in the shape of is_registration_default, and let the ask operation and the screens read it.

* Acceptance

- ores.iam.role carries is_requestable, in the shape and with the defaults of is_registration_default.
- The field is projected across the whole stack: the model, the SQL, the C++ domain and repositories, the protocol twins, the BFF and the web screens.
- A role the tenant has not made requestable cannot be asked for: the ask operation refuses it and the screen does not offer it.
- The role screens let a tenant administrator set the flag.

* Plan

The flag goes on the role row, in the shape of =is_registration_default=,
because row-level security already decides who may write a role row and the
tenant administrator is that person. Nothing new is needed to guard it.

It defaults true, so a role a tenant administrator creates is offered to the
members without further ceremony, and the rule is stated by exception: the
seed clears it on the service roles and on the two that grant everything,
which are the roles the screens used to filter out by name. Defaulting false
was rejected: it would silently withdraw every role in every existing tenant
until an administrator opted each one back in, which is a different change
from the one the journey asks for.

=ores_iam_roles_upsert_fn= takes the flag, so the seed names it in one place.
=create or replace= does not replace a function whose argument list changed,
so an existing database would keep the old three-argument version; the drop
script covers it, because it drops by name and so removes every overload.

The rule leaves the screens. The picker filters on the flag rather than on a
name ending in =Service= and a permission code of =*=, and the ask operation
refuses a role the tenant has not offered with its own outcome code, so the
refusal is a value rather than a sentence to match.
