* Acceptance

- [X] Each ores.dq type's JSON and MessagePack functions are generated into its own translation unit.
- [X] ores::nats::wire_codec calls the generated functions, not reflect-cpp.
- [X] For each type, a test compares the generated bytes with reflect-cpp's, in both formats.
- [X] ores.dq's suites pass, and the generated code builds as a unity build.

The first is true for twenty-five of the component's twenty-six domain types,
which are the ones the models own; the twenty-sixth is hand-written and its
codec is hand-written with the same shape. The second is true for a domain type
and is proved on one; the component's *messages* still travel through
reflect-cpp, because a message struct is generated by the protocol templates and
this task generated codecs for the domain half only. See the last Note.

* Plan

** Two halves, and the seam between them

=ores::nats::wire_codec= is a template over the message type: =encode<T>= calls
=rfl::json::write= or =rfl::msgpack::write=, and =decode<T>= the matching reader.
A generated codec cannot be called by name from a template that knows no type,
so the codec gains a seam: a traits template whose primary form keeps
reflect-cpp, and which a generated codec specialises in the type's own
translation unit.

#+begin_src cpp
namespace ores::utility::codec {

template <typename T>
struct wire_traits;   // write_json/read_json, write_msgpack/read_msgpack

}
#+end_src

=wire_codec= calls =wire_traits<T>= and nothing else. Every type that has no
generated codec keeps reflect-cpp through the primary template, which is what
lets this land one component at a time; step 7 deletes the primary template and
with it the last reflect-cpp dependency.

** The generated codec

The per-type translation unit already exists: =api/src/domain/<type>_json_io.cpp=
is where the type's =operator<<= lives today. The codec template adds to it the
four functions over the carriers step 5 built -- =to_json=, =from_json=,
=to_msgpack=, =from_msgpack= -- and the =wire_traits= specialisation that names
them.

The body is the type's field list, which the generator already holds: each field
is written as an object member, and read back by name. A field's own form is the
carrier's for its type -- a string, a decimal, an instant, a uuid -- and a field
that is itself a generated type recurses into that type's functions, so one
template serves every shape the models state.

** How it is proved

Three ways, because the acceptance names three. Each generated codec's bytes are
compared with reflect-cpp's for the same value, in both formats, for every
ores.dq type -- the same proof step 5 used, one level up. =wire_codec= is tested
with a type whose codec is generated and a type whose codec is not, so the seam
is proved in both directions rather than only where the generated half is. And
ores.dq is built as a unity build, which is what the acceptance's last line
names and what a per-type translation unit can quietly break.

** What the implementation changed about this plan

Three things the plan stated turned out differently, each for a reason that
would have bitten later:

- The =wire_traits= specialisation is in a *header*, not in the type's
  translation unit. A template argument the compiler cannot see here resolves
  against the primary template there, so a specialisation defined in one unit
  only is an ODR violation that silently leaves every other unit encoding the
  type through reflect-cpp, with no diagnostic. It is stated in the codec
  header, which every sender includes anyway.
- The four functions are static members of a =<type>_codec= struct, not free
  functions. Two types differing only in what they return cannot be an overload
  set in one namespace, and the read direction is exactly that: =from_json= for
  every type in =ores::dq::domain= is one signature away from a redefinition.
- The codec is a new opt-in facet rather than an addition to the existing
  =_json_io= archetypes. Those archetypes render for every component's every
  entity, so a change there would have regenerated every domain header in the
  estate and forced the full sweep this story deliberately avoids; a facet
  disabled by default changes nothing for a component that has not opted in.

* Notes

Twenty-five of the component's twenty-six domain types now carry generated
codecs, and =dataset_dependency= -- the one the models do not own -- carries a
hand-written one of the same shape. The generated unit is the type's field list
and four one-line functions over it: the shape of the object is the generator's,
the encoding is =ores::utility::codec::object='s.

Two carriers were missing and landed first. A model states versions, display
orders and flags as well as text, and the carriers covered only text: an integer
is the format's number now and a truth value its own word, in both formats, with
the MessagePack frame chosen for the value rather than the member's width --
which is what reflect-cpp asks of the same packer, so the bytes agree and not
only the value.

The absent optional is the wire's rule, not the helper's: reflect-cpp omits an
empty optional from a JSON object and carries it as nil in MessagePack. Both
formats state that in one place now, and both readers accept an absent member as
the absent value.

Proving that rule found a live bug in the helper this task is built on:
=object::write_json= handed the mutable document a pointer to a temporary's text
as the member name, and yyjson's mutable API stores that pointer rather than
copying it. The utility cases passed by luck -- the freed bytes still held the
name -- while the dq cases rendered unmapped memory as keys. The name is copied
into the document now, and the omission and the nil are both pinned against
reflect-cpp.

The proof is one case over all twenty-six types: the bytes are reflect-cpp's for
the same value, the reader agrees with reflect-cpp's reader on those bytes, and
the seam resolved to the type's own specialisation rather than falling through
to the reflector. A second case sends a real dq type through
=ores::nats::wire_codec= in both formats.

What this task does not switch is the component's *messages*. A dq process puts
=catalog_event=, =list_catalogs_response= and their kin on the wire, and those
structs come from the protocol templates, which state no field list yet. So dq's
traffic still goes through reflect-cpp end to end: what is generated and proved
here is the layer a message will name. The protocol archetypes are the next unit
of work in this component.

The pre-existing blockers are unchanged and are not this branch's: the refdata
=messaging/registrar.cpp= still calls the pre-rename
=publish_legal_entities_from_dq_request=, which is what stops a full estate
sweep, and the codegen suite reports one failure of its own --
=ores.refdata: 1 registrar(s) not composed: legal_entity=.
