* Result

- local_checks.py runs one compass-ng check --ratchet against the base in
  place of the 75 gates compass-ng ports, and reports each gate by its own id;
  COMPASS_CODECS maps every gate to the codecs that answer for it. Without
  compass-ng on the PATH the gates run as scripts, and a compass-ng run that
  stops before checking fails every gate it answers for.
- Still Python: boost-deps, xml-benchmark-recorded, format,
  no-committed-credentials, xml-bindings-drift, file-types-seed,
  ore-parameters-seed, site-page, web, the tool test suites and the build,
  database and test checks.
- Planted-violation proof (evidence/plant_proof.txt, plant_every_gate.py.txt):
  one violation per gate. compass-ng 21ae16d fails all 75 gates in one 7.9 s
  run. The Python scripts fail 67 of 74 in 1,834 s; of their 7 passes, 3 are
  expected and 4 are script gaps compass-ng catches (no-pr-triggers,
  structure-notes, route-inventory, template-sections).
- Wall time, gate run without the heavy checks, load 7 to 10: a docs-only
  change 13 s with the scripts and 22 s with compass-ng (site-page, then one
  compass-ng ratchet of 7.5 s over every codec); a model change 1,151 s with
  the scripts and 109 s with compass-ng, of which about 100 s is the codegen
  test suite both run.
- The planted gates also found two compass-ng defects, fixed upstream before
  the switch: the unit_of_work.hpp false positive and curve_sections_wiring
  missing its two C++ outputs.
