* Goal

A person looking for a prototype finds it by the journey topic it answers to,
not by scanning one flat list of 46 directories. Every prototype carries its
Gemini review beside it, and every index page says which prototypes have one.

* Decisions

- *Group by journey topic, not by component.* The group folder carries the
  journey group's own name, so a reader who knows which journey a prototype
  answers to knows where the file is without a lookup.
- *The pages are org.* The site build already publishes org to HTML, so the
  index pages are searchable, tagged and linked like the rest of the corpus,
  and the prototypes they describe stay HTML.
- *The site build discovers the prototypes.* Naming all 46 in
  =ores-build-site.el= is what let the list and the tree drift, so the build
  walks the group folders instead. Adding a prototype now touches no build
  file.
- *Reviews live inside the prototype.* A review is not a prototype of its own
  and must never be read as the agreed design, so =name/review/= keeps the
  association and the page says so in a banner.
- *The shell answers to Tenancy, not Profile.* The shell's landing page was
  replaced by the home screen, and both read the tenant the sign-in chose, so
  the group that owns the tenant owns the shell.
- *Fix the unrelated site-build break in its own commit.* The rates-family
  design document links an id in the wrong case, which aborts the whole site
  export. It is pre-existing and belongs to another story, so it is one commit
  on this branch rather than folded into the prototype work.

* Out of scope

- Filling the prototype gap in the four groups that have none: Membership,
