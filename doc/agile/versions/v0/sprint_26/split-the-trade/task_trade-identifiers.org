* Acceptance

- trade_identifier is keyed by (trade, scheme), with value and issuer; the scheme is a trade_id_type code and ORE is one of them.
- trade_party_role is keyed by (trade, role) and holds only roles other than the counterparty, which the anchor holds.
- trade_additional_field is keyed by (trade, order) with name and value.
- All three reference the anchor with an enforced foreign key, carry the anchor's party for row-level security, and have no workspace.
- Build, ctest, pgTAP and the local check set pass.

* Plan

- =trade_identifier= and =trade_party_role= are reshaped in place: nothing
  outside generated code writes them, so they move onto the anchor without a
  table beside them. =trade_additional_field= is new, beside the envelope's
  additional field table, which the ORE import still writes until its own task.
- Keys: identifier (trade, scheme); party role (trade, role); additional field
  (trade, ordinal). Each has an enforced foreign key to the anchor and a party
  copy pinned to it for row-level security, and none has a workspace.
- The scheme is a =trade_id_type= code, checked against the catalogue rather
  than a check list; the catalogue gains =ORE= for =Trade/@id=.
- A party role refuses =Counterparty=: the anchor holds the counterparty.
- The ORE envelope view joined the =Counterparty= role, so it could never
  return a row again. Nothing read it, so it goes, with its test. The old
  identifier and party role pgTAP tests, which tested the wide trade's shapes
  and already stopped at their fixtures, are replaced by one test of the three
  tables.
