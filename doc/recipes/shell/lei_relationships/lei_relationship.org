#+title: How do I run the lei_relationships commands from the shell?
#+description: Every command the lei_relationships submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:lei_relationships:

This file documents the lei_relationships resource at the shell, one section per command. Every command is a subcommand of =lei_relationships=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 442C1938-62CD-50F7-97E2-2F1276902F60
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
lei_relationships list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =dq.v1.lei_relationships.list=.

#+name: lei_relationships-list
#+begin_src ores-shell :tangle lei_relationships-list.ores :exports none
lei_relationships list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 04FDF610-3F61-544D-BD61-39F802F81E8D
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
lei_relationships get <relationship_start_node_node_id>
#+end_example

It is addressed at =dq.v1.lei_relationships.get=.

#+name: lei_relationships-get
#+begin_src ores-shell :tangle lei_relationships-get.ores :exports none
lei_relationships get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 455C674E-EA5A-5A6E-B399-B416650FD4D4
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
lei_relationships add <relationship_start_node_node_id> <relationship_start_node_node_id_type> <relationship_end_node_node_id> <relationship_end_node_node_id_type> <relationship_relationship_type> <relationship_relationship_status> <relationship_period_1_start_date> <relationship_period_1_end_date> <registration_initial_registration_date> <registration_last_update_date> <registration_registration_status> <registration_validation_sources> <reason> <commentary>
#+end_example

It is addressed at =dq.v1.lei_relationships.put=.

#+name: lei_relationships-add
#+begin_src ores-shell :tangle lei_relationships-add.ores :exports none
lei_relationships add __none__ __none__ __none__ __none__ __none__ __none__ - - - - - - system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: DBA12778-BE72-5196-9BF4-15E151BD659D
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:
