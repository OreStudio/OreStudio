* Goal

Record one run of a process over a set of trades: its identity, its
state machine, the process it is a run of, and the trade groups that
carry what the run read and what it wrote. The record is what lets a
process be undone or repeated.

* Acceptance

- The process enumeration is seeded, so a run names which process ran.
- A run has an identity and a state machine over its evolution.
- A trade group carries a foreign key to its run, and its membership names each trade and the role it played.
- One detail table per kind of run records what that kind of run records.
- An ORE import is one run.

* Decisions

** The run is modelled against a client process, not in the abstract

Taken 2026-10-08 with the owner. A process run exists so that a process
can be undone and repeated, and no process is implemented. Modelling a
run before a process has a client would fix its shape against nothing.
This story therefore waits on one process with a real client, the funding
roll or the spot sweep, and the first task after the scaffold is to
settle the run against that pilot.

The trade set model settled on 2026-10-08 supplies what the run needs and
did not have: the trade group, its membership, the read and write sets,
and the roles the process declares. That work is in
[[id:2AF58405-4F3D-4B74-AAD0-6A97E7DA215F][Trade sets and trade groups]].

The shape is written down in
[[id:A7381409-AFD0-4F0E-BAB4-61CD35341AA8][Trace a process run over a set of trades]].
It is roughly the shape and not yet a design.
