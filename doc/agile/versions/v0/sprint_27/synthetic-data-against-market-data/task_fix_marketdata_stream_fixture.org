* Result

The fixture now provisions =marketdata_ticks= with
=market_tick_wildcard()=, the same subject the service provisions at
startup, so the republish finds a stream and the test proves the store
path rather than the fixture.

Reproduced before the fix. The stream was deleted from JetStream, which is
the state CI starts from, and the test failed at
=app_feed_ingest_loop_tests.cpp:128= with exactly the reported message:
=JetStream publish failed: No responders available for request=. After the
fix, with the stream deleted again, =ores.marketdata.service.tests= passes
226 assertions across 40 cases, and the stream it creates carries
=ores.dev.prime_origin.marketdata.v1.tick.>=.

Why it passed locally and failed in CI: a service had provisioned the
stream correctly on 2026-09-26, and =ensure_stream= returns early when the
stream already exists, so the fixture's narrower subject was never
applied. Any environment where the stream already exists from an older
start hides the defect.
