* Decisions

*The first screen is the one with the fewest reasons to be in the BFF.* Sign in, one
list and the change stream are the three pieces the C++ server already answers, and
they are the whole of a screen's life: it opens, it reads, it follows. A screen that
needs no composed view proves the path without porting a view.

*The switch is a flag, not a rewrite.* Both servers answer the same request while the
flag is on, so the same screen can be compared against either, and a failure is one
flag away from being undone. The flag is the shape of the whole port: every later
increment moves one more screen across and leaves the switch behind.
