- =usernameEdit= must be non-empty after trim, else warning =Validation Error= / =Username is required.= (=ACC.cpp:535-539=).

- Submit gating: Save is enabled only when something is dirty (=updateSaveResetButtonState=, =ACC.cpp:1131-1152=).

* 4. CHILD ENTITY TABLES

** 4.1 Generic widget — =ChildEntityTableWidget=

Entity-agnostic; it knows nothing about any service/domain (=CETW.hpp:34-43=). Constructor takes =(columnHeaders, addLabel, deleteLabel, parent)= (=CETW.hpp:53-56=). It builds:

- =QVBoxLayout= containing a =QToolBar= and a =QTableWidget= (=CETW.cpp:34-57=).
- Toolbar icon size 16×16; Add action icon =Icon::Add= label/tooltip = =addLabel=; Delete action icon =Icon::Delete= label/tooltip = =deleteLabel= (=CETW.cpp:38-42=).
- =addRequested()= emitted on Add; =deleteRequested(int row)= emitted on Delete with the table's =currentRow()= (=CETW.cpp:43-46=).
- Table: column count/labels from =columnHeaders=, =horizontalHeader()->setStretchLastSection(true)=, selection behavior =SelectRows=, selection mode =SingleSelection=, /edit triggers =NoEditTriggers=/, vertical header hidden (=CETW.cpp:48-54=).
- API: =setRows(const std::vector<QStringList>&)= replaces all rows and =resizeColumnsToContents()= (=CETW.cpp:62-70=); =currentRow()=; =table()= for finer control (=CETW.hpp:60-66=).

There is no inline editing: the only edit path is a double-click, wired by the host (=ACET.cpp:55-58=).

** 4.2 Account host — =AccountChildEntityTables=

A =QObject= that owns exactly one =ChildEntityTableWidget= for account contact information (=ACET.hpp:39-48=), constructed as:

#+begin_src text
new ChildEntityTableWidget({"Email", "Country", "Street", "City", "Phone"},
                           "Add Contact", "Delete Contact", dialogParent)
#+end_src
=ACET.cpp:39-45=. This yields a table with columns /Email, Country, Street, City, Phone/ and toolbar tooltips /Add Contact/ / /Delete Contact/.

- =attachTo(QTabWidget*)= inserts it before the last tab under title =Contact Information= (=ACET.cpp:61-65=).
- =reload(accountId, clientManager, username, imageCache, changeReasonCache)= fans out =get_account_contact_informations_by_account_id_request= (limit 1000) and maps each record to the 5 cells =email, country_code, street_line_1, city, phone= (=ACET.cpp:67-123=). No-op if the id is nil, no client manager, or disconnected (=ACET.cpp:77-79=).
- =setReadOnly(bool)= sets a flag consulted by every mutating path (=ACET.cpp:82-84=).
- /Add/: guarded by read-only; if the parent id is nil it warns =Save Required= / =Save the account first, then add contact information.=; if disconnected warns =Disconnected= / =Cannot add contact while disconnected from server.= (=ACET.cpp:125-138=). It opens a modal =QDialog= wrapper titled =Add Contact=, hosts an =AccountContactInformationDetailDialog=, injects client manager / change-reason cache / image cache / username, calls =setCreateMode(true)=, assigns a random UUID and the parent =account_id=, and reloads on =QDialog::Accepted= (=ACET.cpp:140-166=).
- /Delete/: guarded; deletes by id via =delete_account_contact_information_request=; on failure warns =Delete Failed=; on success reloads (=ACET.cpp:168-196=). Note it does /not/ prompt a change reason for the child delete.
- /Edit/: double-click opens the same dialog wrapped in a =QDialog= titled =Contact Information Details=, =setCreateMode(false)=, =setReadOnly(readOnly_ || !connected)=, and reloads on accept (=ACET.cpp:198-225=).

* 5. SAVE FLOW

Entry point =onSaveClicked()= (=ACC.cpp:517-964=); =save()= is a public thin wrapper (=ACC.cpp:489-491=).

** 5.0 Pre-flight (both modes)

1. /Connection guard/: if =!clientManager_ || !clientManager_->isConnected()= → log warn, =emit errorMessage("Not connected to server. Please login.")=, return (=ACC.cpp:518-522=).
2. /Party-readiness guard/: if =partiesWidget_ && !partiesWidget_->isDefaultPartyReady()= → =emit errorMessage("Still loading account data — please try again in a moment.")=, return (=ACC.cpp:524-532=). (Save is normally disabled in this window — =ACC.cpp:1149-1150=.)
3. /Username required/: trimmed empty → =MessageBoxHelper::warning(this, "Validation Error", "Username is required.")=, return (=ACC.cpp:534-539=).
4. /Password rules (create mode only)/: the three checks/messages listed in §2 (=ACC.cpp:541-566=).

** 5.1 Create branch (=isAddMode_ == true=) — =ACC.cpp:570-724=

1. /Party warning/: if no pending party change and =!partiesWidget_->hasAvailableParties()=, warn =No Parties Available= / ="No parties are defined in the system. The account will be created without a party assignment and will not be able to log in until a party is assigned."= (non-blocking, =ACC.cpp:573-581=). Otherwise ask =No Party Assigned= / ="No party has been assigned to this account.\n\nAccounts without a party assignment cannot log in to any party context.\n\nCreate the account without a party?"= with Yes|No; No aborts (=ACC.cpp:583-592=).
2. /Capture staged child adds/: =partiesWidget_->pendingAdds()=, =rolesWidget_->pendingAdds()= (=ACC.cpp:595-601=).
3. /Copy form values/ to locals: username, password, email, account_type (=ACC.cpp:603-608=).
4. /Async/ =QtConcurrent::run= (=ACC.cpp:610-677=):

** 7.2 What the user supplies

- /Change reason code/: chosen from a filtered, sorted list in =ChangeReasonDialog=; /mandatory in the sense that the dialog cannot be accepted without a selection/, but it can be cancelled (in which case the whole save/delete aborts).

- /=modified_by=/: never user-editable. For account it is injected as =modifiedByUsername_.empty() ? "qt_user" : modifiedByUsername_= in =getAccount()= (=ACC.cpp:369=); =setUsername()= sets it from the controller (=ACC.hpp:75=, =CTRL:398=). ** 7.3 Where reasons come from

- =ChangeReasonCache= is a shared, event-refreshed cache created once and injected via =setChangeReasonCache()= (=DDB.hpp:118-127=; =CTRL:399, 489=). The controller receives =changeReasonCache_=/=badgeCache_= in its constructor and calls =setImageCache(imageCache)= (=CTRL:55-62=).
- It loads all reasons + categories via =loadAll()=, listens for =change_reason_changed= events, and exposes =getReasonsForNew/Amend/Delete(category_code)= filtering by =applies_to_new/amend/delete= /and/ =category_code=, sorted ascending by =display_order= (=CRC.hpp:99-117=, =ChangeReasonCache.cpp:240-290=), plus =getReasonByCode=, =isValidReasonCode=, =allReasons=, =allCategories=, and signals =loaded=/=loadError=/=refreshed= (=CRC.hpp:142-156=).
- Categories in use: =system= (create), =common= (amend/delete) — constants ="system"= / ="common"= (=CRCONST.hpp:83, 88=).
- Reason codes: =system.new_record=, =system.external_data_import=, =common.non_material_update=, =system.new= (synthetic), =system.test= (synthetic) (=CRCONST.hpp:36-61=). =common.non_material_update= is the special "touch" reason: allowed only when no field changed; every other reason is allowed only when a field changed (create ignores the toggle) (=CRD.cpp:96-124=, =CRD.hpp:69-73=).

** 10.5 Account-specific deviations from the generated standard (important for a faithful React port)

1. /Hand-written/, not generated (=AccountDetailDialog.hpp:1-20= has no AUTO-GENERATED banner; =AccountContactInformationDetailDialog.hpp:20-24= does).
2. /6 tabs, not one group per view_group/: =General=, =Security=, =Login Status=, =Roles=, =Parties=, =Contact Information= (runtime), =Provenance=; the generated standard emits one tab per =view_group= plus =Provenance=.
3. /Create mode does not prompt a change reason at all/ and =save_account_request= has no audit fields (=ACCTP.hpp:45-53=), whereas the template prompts Create with category =system=.
4. /Edit mode prompts a change reason only when parties/roles changed/, and the account =update_account_request= is sent with empty audit fields even though it has them (=ACC.cpp:766-775, 814-821=; =ACCTP.hpp:85-86=). A pure email/full-name/job-title edit is therefore un-audited.
5. /Delete does not prompt a change reason/ (=ACC.cpp:971-1049=), unlike the template (=T-cpp:1446-1448=).
6. /Password fields/ exist and are create-only (a hand-written concern absent from the generic template).
7. /Admin checkbox row/ exists but is permanently hidden (=ACC.ui:94-112=).
8. Uses the /legacy =AccountHistoryDialog=/ rather than the generic =HistoryDialog=; its Changes diff only covers =Username= and =Email= (=ACH.cpp:84-94=).
9. =code()= is not overridden for the account dialog; identity is exposed as =accountId()= returning the UUID string (=ACC.hpp:141=; =ACC.cpp:1168-1170=) and the controller matches notifications on it (=CTRL:259=).
10. Extra inline help absent from the generic template: password match border, party default tooltip/badge, account-type-driven party warning, reports-to async combo.
