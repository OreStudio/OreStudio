* Goal

The previous task generated the wire form of dq's *domain* types. A dq process
does not send domain types: it sends =catalog_event=, =list_catalogs_response=
and their kin, which come from the protocol templates. Those still go through
reflect-cpp, so the component's actual traffic is unchanged. This task gives the
protocol messages the same treatment, and takes the chance to state each type's
field list once instead of twice.

* Acceptance

- Every protocol message of an opted-in entity states its own field list, next to the struct and from the same template iteration, so member order is written once.
- Each message's JSON and MessagePack functions are generated into the component's translation unit, and the protocol header names them, so a translation unit that sends a message reaches the generated code without including anything by hand.
- For each message, a test compares the generated bytes with reflect-cpp's, in both formats.
- A message that holds a domain type, another message, a vector of either, or an optional of either, encodes and reads back.
- The previous task's per-type byte comparison still passes: the domain types' field lists move into their own headers with no change to the bytes.
- dq's suites pass, and the generated code builds as a unity build.

* Plan

** Why the messages are a task of their own

The previous task proved the seam on domain types. A message is a different
shape: it holds domain types, other messages, vectors and optionals of both, and
it is the type the wire actually carries. Its codec also has to be reachable
from a translation unit that only saw the struct, which the domain half did not
need.

** The shape of the type is stated once, by the template that declares it

A codec file that repeats a struct's member list is a second statement of the
same fact, and the two drift. The template that already iterates a message's
fields to write its struct writes a =wire_fields= function beside it, and the
codec iterates neither: it calls the function. The same move
retires the domain half's field list from its =.cpp= and puts it next to the
class.

=wire_fields= is a free function found by argument-dependent lookup, so the
carrier layer can ask any type whether it has one: the two carriers,
=json_codec<T>= and =msgpack_codec<T>=, grow one =if constexpr= -- a type with a
=wire_fields= is an object, everything else keeps its text form. That is
what makes a message holding a domain type work: the encoder recurses through
the field list rather than knowing the type.

** Where the code lives

One codec pair per entity -- ={entity}_protocol_codec.\{hpp,cpp\}= -- not one
per struct: a protocol header declares a dozen structs, and a file each would
triple the file count for nothing. The header declares a =<message>_codec= struct
per message and the =wire_traits= specialisation that names it; the translation
unit defines them, which is the containment the previous task proved.

The protocol header includes the codec header at its end, so a translation unit
that sends a message sees the specialisation. Without that include the seam
silently falls back to reflect-cpp -- the failure mode the previous task's review
found and fixed.

** How it is proved

The per-message byte comparison, in both formats, over values the component's
own generators produce. Plus the domain half's existing comparison, which must
stay byte-identical while its field lists move out of the codec units.
