* Goal

A new standalone Qt dialog rendering a graphical, card-based org
chart for the current tenant's staff: one box per account (photo,
full name, job title), connected by lines to its manager
(=reports_to_account_id=), auto-laid-out top-down by reporting depth
-- no manual dragging or saved positions. Reference style: rounded
cards with a coloured header per top-level branch, circular photo,
name, job title pill underneath (see attached reference screenshots).
Opened from a menu action in the Accounts area.

* Acceptance

- A new dialog (opened via a menu action near the Accounts view)
  renders every account in the current tenant as a card: circular
  photo (=ImageCache=, falling back to a placeholder when
  =image_id= is unset), full name, and job title.
- Cards are connected to their manager's card
  (=reports_to_account_id=) by lines; accounts with no manager are
  roots, laid out side by side across the top.
- Layout is fully automatic (layered by reporting depth, siblings
  centred under their parent) -- no manual positioning, no saved
  layout state.
- Tested against Acme's ~59-account staff hierarchy: renders without
  overlap, scrolls/pans for a tree too large for the viewport.

* Plan

- Fetch every account for the current tenant (full_name, job_title,
  image_id, reports_to_account_id) via the existing account list
  API (mirroring =ClientAccountModel='s fetch).
- Build the tree in plain C++ (no new domain/service code): group by
  =reports_to_account_id=, roots = accounts with it unset.
- Layered layout algorithm: BFS by depth, position siblings left to
  right, centre each parent over its children's midpoint (simple
  Reingold-Tilford-style pass, not a general graph-layout library).
- Render via =QGraphicsScene=/=QGraphicsView=: one card item per
  account (rounded rect + circular photo pixmap via =ImageCache= +
  two text labels), one line item per edge.
- New =OrgChartWidget= (a plain =QWidget=, not =QDialog=, so it embeds
  as a normal maximizable MDI subwindow like the accounts list window)
  in =ores.qt.iam=, wired to a new =User Accounts > Org Chart= menu
  action.
- Colour per depth-1 branch (e.g. one colour per office), not per
  independent root -- the true root(s) (group/holding level, no
  manager) get a neutral dark colour instead.
- Each card also shows the account's office/party affiliation
  (resolved once per branch anchor via =get_account_parties_by_account_request=
  + =get_parties_request=, then propagated down that branch -- not a
  per-account fetch) and highlights the currently logged-in user's own
  card.
- Provisioning gap discovered and fixed along the way: the holding
  company (Acme Corporation Plc) had no staff of its own, so the chart
  had three disconnected per-office roots instead of one real tree.
  Added a new =acme_group= dataset/bundle (a Group CEO, "Adrian
  Vance") and rewired the three Country Heads to report to them.
