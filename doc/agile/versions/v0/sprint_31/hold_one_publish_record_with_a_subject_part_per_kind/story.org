* Goal

The tree holds one publish record whose columns every kind shares, and one subject part per kind that says what the set is of. A reader of any kind reads one shape, and a withdrawal writes one set of columns instead of a set per kind.

* Acceptance

- One table holds the columns every kind shares, and a subject part table per kind holds what that kind's set is of, keyed by the publish.
- The calibration's verdict moves off the publish record and onto the candidate version the decision covered.
- Every read and every repository returns the same facts for each kind as before, and a party's published sets survive the migration.
- The schema, the migrations, the ER diagram and the seeds are regenerated, and the database rebuilds from empty with the new shape.
- The notification triggers exist on the new tables and fire for the same acts as before.
