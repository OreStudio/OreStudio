* Plan

Twenty-six tenancy and assets routes ores.web calls lack a C++ route at their
own address. This task serves the four of the image screens in
=ores.http.assets=, =image_screen_routes=: a page of the tenant's images, one
image's bytes, the upload policy and an upload, the upload within the BFF's 4
MiB body. The image map is a composed view and has its own task.

An image is answered by one helper in =ores.http.api=, =image_answer=, which
the account picture now uses too: the BFF's private five-minute cache, nosniff
and sandbox headers, and a stored type served only when it names an image.

The refusal, the guarded forward and the character count the access units
kept in =access_screen_answers= are needed by a second part, so they move to
the shared layers: =refused= and =characters_of= to =record_routes=, =guarded=
to =forwarding=. Every access unit is migrated and the header is deleted.

The 21 tenancy routes move to [[id:8B40FAA3-24D5-4F54-9779-FF45B0BDC8F1][Serve the tenancy routes]].

* Result

The C++ server answers the four image routes at the addresses ores.web calls,
each paired in the inventory. The image answer and the route helpers are shared
across the parts that need them, with no copy left. The tests prove the page
and upload limits, the refusals before forwarding, and the image answer's
headers and types.
