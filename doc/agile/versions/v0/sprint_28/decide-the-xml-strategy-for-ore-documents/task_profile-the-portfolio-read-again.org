* Notes

- The 466 million instructions of =sha256_block_data_order_avx2= are not XML
  work. The test fixture opens database connections, and each login runs the
  SCRAM password exchange. The fixture costs 835 million instructions in all.
  That is more than the import it serves.
- The fix is in =file::read_content=, which the importer calls. A seekable
  stream now reads in one bulk read. A stream that cannot seek keeps the
  iterator copy. Two new tests cover a stream that starts mid-way and a stream
  that cannot seek.
- Each holder of a trade owns one =trade_kind_columns= of 3,576 bytes. A
  portfolio document has one holder for all its trades, so the cost is 3.5 KB per
  document and not per trade. A composite trade adds one holder per component
  that holds a trade.
- Before the columns, a trade was 346,624 bytes. The 314 trades of the largest
  file would have needed 108.8 MB for the trade vector alone. This is
  arithmetic, not a measurement. The measured peak for the whole import is
  14.5 MB above the small-import baseline.
- Candidate: =read_rate_instrument= costs about 59,000 instructions per trade.
  It is the largest part of the map. A profile of that function by line would show
  whether it is string work or decimal work.
- Candidate: =append_to<leg_data>= costs about 13,000 instructions per leg. The
  =leg_data= record is large, and each append zero-fills it.

* Result

The file read copied each file one character at a time and cost 11.7 percent of
the portfolio read test. A seekable stream now reads in one call. The test falls
from 1,864,312,400 to 1,646,496,411 instructions. Peak heap of the all-examples
import is 40.5 MB, 14.5 MB above a small import. The trade columns cost 3.5 KB
per document, not per trade. The affected test binaries pass: platform,
marketdata core, testing, storage core and ore core.
