* Goal

A system administrator edits a source's transport in the screen, and the
adapter runs with those values instead of command-line flags. The provider keeps
the credential reference, so a test source and a production source of one
provider can differ in endpoint and secret without a redeploy.

* Acceptance

- The source record carries the endpoint, the path, the poll interval and the
  backfill window. The provider keeps the credential reference.
- The adapter reads the transport of each source and reports the values it uses;
  no endpoint or interval comes from a service flag.
- A secret is a reference. A read never returns its value, and a write sets or
  rotates it.
- The source is the configured instance: =ecb-frankfurter= and =bloomberg-b= are
  two sources, and a test environment is a source of kind =test=.
- The prototype's *not persisted yet* marker disappears from the Adapter tab.

* Decisions

- The entity is the *source*, not a "connection". The code already has
  =market_data_source= as one adapter instance of a provider; a new entity would
  duplicate it.
- The *adapter* is the runtime, known by its adapter id, and the adapter id is
  the source name. There is no "driver": the kind of code is not a row.
- The *provider* is whoever owns the ids and the terms: a central bank, a
  treasury, or a data vendor. The credential reference stays on the provider.
- A party routes one source for each provider. A provider may have several
  sources, and one is the default.
- The ECB has an FX source (=ecb-frankfurter=) and an IR source
  (=ecb-ecb-data=). Under the current route rule a party cannot read both. This
  story does not change the rule; the IR story settles whether a source serves
  every asset class or the rule changes.
