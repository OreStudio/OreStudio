* Acceptance

- No workflow has a =pull_request= trigger.
- The twelve workflows keep their =push= to =main= trigger and their
  =workflow_dispatch= trigger, so a defect that escapes still shows on main.
- Every comment that claimed a check ran on the pull request is corrected.
- The scheduled continuous builds, the nightlies, the site deploy, CodeQL and
  the bots keep running.

* Plan

Strip the =pull_request= block from the twelve workflows that carry one, and
correct the job comments that explain why the check runs on a pull request.
The local runner replaces the pull-request gate; it arrives on its own task.
The knowledge document and the raise-a-PR skill are rewritten on that task,
because they must name the runner and it does not exist yet.

* Result

The twelve pull-request gates no longer trigger on =pull_request=:
codegen-drift, codegen-sweep, doc-lint, dsh-environment, dsh-kanban,
event-registrar-composition, header-hygiene, populate-reference-drift,
rls-system-tenant-widenings, shell-script-drift, template-drift and
typescript. All twelve keep their =push= to =main= trigger, so they remain a
post-merge backstop, and their =workflow_dispatch= trigger. Three job
comments that named the pull request as the reason for the check were
corrected. Nothing else changed: the continuous builds, the nightlies, the
site deploy, CodeQL and the two bots still run as before.
