* Goal

Add a new codegen metatype (=ores.codegen.oresmd_quote_type=) and profile
so that adding an oresmd quote-type family (extending an existing asset
class, or creating a new one) requires only a compact org-model spec file
— the enum, struct fields, parser branches, query-key validation,
projection functions, resolver wiring, dispatch updates, and test cases
are all generated, producing zero diffs against the hand-crafted 7-asset-class
implementation.

* Plan

** Analysis

The 7 oresmd quote-type implementations share a mechanical six-file
pattern per asset class. The invariants are:

| What varies per asset class | What is completely mechanical |
|-----------------------------+-------------------------------|
| Quote type names, ORE TYPE/METRIC strings | Enum definition and =magic_enum= integration |
| Struct field names and types | Field addition to identifier/requirement structs |
| Query-key allow/reject list | =query_params= field + =from()= dispatch |
| Whether index appears in qualifier | =parse_*= function skeleton + =to_uri= branch |
| Point format (scalar, tenor-only, composite) | =quote_key_*= dispatch body |
| Test-case URIs and expected strings | Round-trip, projection, rejection test scaffolding |

The codegen approach captures the variable parts in a spec file and
generates the mechanical parts deterministically — same pattern as how
=ores.codegen.entity= captures column/FK/display metadata and generates
SQL, C++ domain, repository, service, protocol, and Qt layers.

** Spec model design (draft)

An oresmd quote-type spec file would be an org-mode document with
=#+type: ores.codegen.oresmd_quote_type= frontmatter and these sections:

- =* Quote types=: org table mapping enum name → ORE TYPE → ORE METRIC →
  qualifier shape (includes_index, no_index, curve_id, mult_literal)
- =* Fields=: org table of struct fields (name, C++ type, mandatory,
  query_key, non-IR reject?)
- =* Point semantics=: per-quote-type point format (scalar, 1-part,
  2-part, 3-part composite)
- =* Test cases=: org table of URI → expected projection string

** Profile design

A new codegen profile (=ores.marketdata.oresmd_quote_type= address) that
reads the org spec and generates into the ores.marketdata component's
physical space. It would use the existing =ores.codegen= profile
infrastructure (Jinja2 templates) and follow the same
=generate()= / =diff()= / =check_staleness()= contract as existing
profiles.
