One row per notional a tranche states, keyed to the instrument, the
tranche and the notional's ordinal within that tranche.

A tranche's notional amortises, so the document states a list of notionals,
each dated from the day it applies. The first notional states no date and
applies from the start of the swap. The export writes the rows back in the
order the document stated them.

* SQL

The table name is shorter than the conventional composition. The longest
identifier the generator derives from the table name, the delete rule, adds
eleven characters, and PostgreSQL cuts an identifier at 63; the conventional
name would run past that and the generated SQL would no longer name the table
the C++ entity names.

** Custom repository methods

The trade read path fetches the tranche notionals of many instruments at once
when it assembles the export payload, and no generated read covers that.
The batch read below is one statement over the instrument set.

*** read_by_instruments_batch

:END:

balance_guaranteed_swap_tranche_notional_repository::read_by_instruments_batch(
    context ctx, const std::vector<std::string>& trade_ids) {
    if (trade_ids.empty())
        return {};
    static const auto max(make_timestamp(MAX_TIMESTAMP, lg()));
    const auto tid = ctx.tenant_id().to_string();
    const auto query = sqlgen::read<std::vector<balance_guaranteed_swap_tranche_notional_entity>> |
                       where("tenant_id"_c == tid && "trade_id"_c.in(trade_ids) &&
                             "valid_to"_c == max.value()) |
                       order_by("trade_id"_c, "tranche_number"_c, "sequence_number"_c);
    return execute_read_query<balance_guaranteed_swap_tranche_notional_entity, domain::balance_guaranteed_swap_tranche_notional>(
        ctx,
        query,
        [](const auto& entities) { return balance_guaranteed_swap_tranche_notional_mapper::map(entities); },
        lg(),
        "Reading balance guaranteed swap tranche notionals for multiple instruments.");
}
