* What

The system administrator has no screen for the yield curve process types. The
journey [[id:AFABC8A2-61A8-486E-80EC-65856914AA17][Manage the yield curve process types]]
keeps the short-rate models the IR curve editor offers and the parameters each
model takes. The web client has no page, and no HTTP route or shell verb reaches
either catalogue. The system home shows it as an upcoming card.

* Why

Reads and writes exist as generated subjects:
=synthetic.v1.yield_curve_process_types.list=, =.get_many=, =.put_many=, and the
same set for the parameter definitions. Today the catalogues change only by seed
SQL and migration. The journey lists the gaps: the catalogue and the build
disagree about which engines work, saving a type is not atomic, no list is scoped
to a type, a definition is addressed by a name several types share, and a removal
is unguarded.

The first slice is a read-only page that groups the definitions by type on the
page. Writes wait on the atomic apply operation and the guarded removal.
