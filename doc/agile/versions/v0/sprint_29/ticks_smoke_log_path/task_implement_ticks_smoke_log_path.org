* Acceptance

- The check finds demand replies in the log of each marketdata replica.
- The check reads no other service's log.
- The ticks smoke passes on a healthy system.

* Plan

Read every file that matches =ores.marketdata.service.*.log=. The launcher names a single replica =.0.log= and each replica of a scaled service =.N.log=. Look the files up on each poll, because the service creates its log after the check starts.

* Result

The check named =ores.marketdata.service.log=. The launcher writes =ores.marketdata.service.0.log=, and the systemd journal for the unit was empty. The check therefore found no demand reply and failed on a healthy system with "no adapter got a demand set".

=_log_files= in =compass_smoke.py= now finds the log of each replica and excludes the sibling =ores.marketdata.official= log. Three new tests cover the single replica, several replicas and the sibling log. The three tests failed before the fix.

=./compass.sh smoke ticks --fresh= passed with this change. The service binaries came from main at 634b748b71, because the change is Python only. The log held 189 demand replies, all from this run. The check accepts stale lines by design if a log is kept across runs. This task did not change that behaviour.
