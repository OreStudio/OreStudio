* What the Windows job says first

The task's premise is that the MSVC build fails on C1202 in the reflected
aggregate. On 2026-10-28 it does not: the nightly run
[[https://github.com/OreStudio/OreStudio/actions/runs/40643890504][40643890504]]
contains no C1202 at all, because the build stops earlier:

#+begin_example
real_environment_provider.cpp(28): error C2220: the following warning is
treated as an error
clang-cl: error: 'getenv' is deprecated [-Wdeprecated-declarations]
#+end_example

That is a unity-build effect: the file defined _CRT_SECURE_NO_WARNINGS, which
arrives after the CRT has already been included by an earlier file in the same
unity unit, so it suppressed nothing. Fixed by reading the environment with
_dupenv_s on Windows and dropping the define.

The consequence for this task is an order, not a change of goal: the C1202
cannot be observed, let alone measured, until the build gets past the errors in
front of it. The Windows job also reports =nats-server did not become ready
within 30s=, which is its own problem and does not stop the compile.

* Plan

** The order of work

1. Clear the compile errors the job reports before C1202, one at a time, and
   keep the C1202 question open until the build reaches the aggregate.
2. Re-run the nightly and read the first error again. The curve configuration
   document may turn out to have been fixed by other work, in which case this
   task becomes a measurement rather than a split, and the story closes with
   the evidence.
3. Only if C1202 appears, split on the seam: no translation unit's encode path
   may reach every convention and curve type at once.
