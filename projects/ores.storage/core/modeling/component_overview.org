* Summary

=ores.storage.core= is where the bytes actually move. =net/http_client= is the
synchronous Beast GET, PUT and DELETE that streams file bodies rather than
buffering them; =filesystem/archiver= packs and extracts =tar.gz= trees through
libarchive; and =net/storage_transfer= composes the two into the atomic and
composite operations the callers use. =messaging/= holds the handler that
answers the operation set on NATS.

Every operation is synchronous and blocking, and the callers run them on
background threads. The composite helpers stage through a temporary file under
the system temporary directory.

* Inputs

- A local directory or file to pack, upload or download.
- A storage endpoint: the HTTP base URL, a bucket name and an object key.
- A =tar.gz= archive to extract.
- An in-memory blob to upload, and the compressed bytes to decode on the way back.

* Outputs

- Files written to a local path, or objects written to the remote bucket.
- Extracted directory trees.
- The server's response body, for the uploads that read a server-computed
  checksum out of it.
- Decompressed blobs in memory.

* Entry points

- =include/ores.storage.core/net/storage_transfer.hpp= — the composite helpers the callers use.
- =include/ores.storage.core/net/http_client.hpp= — the GET, PUT and DELETE primitive.
- =include/ores.storage.core/filesystem/archiver.hpp= — =tar.gz= pack and extract.
- =include/ores.storage.core/messaging/= — the NATS handler.
