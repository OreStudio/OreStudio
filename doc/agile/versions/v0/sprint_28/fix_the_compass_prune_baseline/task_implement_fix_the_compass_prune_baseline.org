* Result

=compass branches prune= now deletes every branch it reports safe to prune,
whatever is checked out, and still refuses one that main does not hold.

The set is defined as "merged into =origin/main=", but the delete asked
=git branch -d=, which answers whether a branch is merged into *HEAD* or its
own upstream. So a branch that main holds survived whenever the checked-out
branch was older than it -- my own case, where the message blamed unmerged
commits that did not exist.

Each name is now re-checked against =origin/main= with =merge-base
--is-ancestor= immediately before deleting, and the delete uses =-D=. The
re-check also closes the gap between reporting and deleting, where a fetch
can move a branch.

Six tests, and the behavioural one fails on the old code for the right
reason: the branch survives with the warning that blamed unmerged commits.
The test needs a branch with *no upstream*, because =-d= consults the
upstream when there is one -- that detail is the difference between a test
that reproduces the defect and one that passes for the wrong reason.
