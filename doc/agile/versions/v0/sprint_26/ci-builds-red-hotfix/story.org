* Goal

Every continuous build on main is red. Each red job stops on a different
defect, and each defect is independent of the others:

| Job | Where it stops | Root cause |
|-----+----------------+------------|
| Continuous Linux (4 of 4 jobs) | =validate_schemas.sh= | Four regenerated =ores.workspace= SQL files define the same table, indexes and insert function as the hand-written, wired schema, and no aggregator includes them, so the strict wire check refuses the tree. |
| Continuous macOS (2 of 2 jobs) | compile of =ores.iam= | Both iam handlers declare =std::atomic<std::shared_ptr<const token_settings>>=. libc++ has no such specialisation, so the name resolves to the generic =std::atomic<T>= primary template, which static_asserts that T is trivially copyable. |
| Continuous Windows (4 of 4 jobs) | =compass db recreate=, Phase 2 | =populate/iam/iam_service_account_roles_populate.sql= uses =:'storage_service_user'=, which the psql invocation did not define. |
| Nightly Linux (2 of 2 jobs) | =compass db recreate=, Phase 2 | The same undefined =storage_service_user=. |
| Product website and CDash site | =org-publish= of one page | The dq artefact task carried =[[file:...org_loader.py::943]]=. Org cannot resolve a line-number search inside a Python file. |

The storage defect and the site defect are already fixed on main: the
storage service was added to =service_registry.org=, to the generated
=service_vars.sh= and to the =env configure= output, and the dq page now
links through the =proj:= link type, which renders a GitHub URL and
searches nothing. The Linux and macOS defects are still red, and this
hotfix carries those two.

The macOS defect is the one with a design decision behind it. The estate
already met it once, in =crm_ingest_bridge=, and chose a mutex-guarded
=shared_ptr= there, recording the reasoning in
[[id:2CA8864F-336E-4632-A510-FC503213165B][Revisit std::atomic<std::shared_ptr<T>> once macOS libc++ supports it]].
The iam handlers were written with the atomic form afterwards and never
met a macOS compiler, because the macOS build had been red on other
grounds for long enough that nobody saw the failure. The fix puts the
portable form in =ores.platform=, so the decision is made once and the
callers carry no preprocessor branch.

The workspace defect is wiring debt that one commit created. It is not a
defect in the workspace feature itself.

* Decisions

- The workspace entity's SQL facet is switched off in its model rather
  than silenced in =validation_ignore.txt=. The generated schema cannot
  be wired while the model is stale, because it drops =party_id= and
  =name=, which the hand-written schema and the hand-written repository
  both use. A disabled facet is reversible in one line and the generator
  enforces it; an ignore entry leaves two competing definitions of the
  same table in the tree for the next reader to wire by mistake.
- The portable snapshot joins =ores.platform=, not =ores.utility=. The
  choice it encodes is a standard-library gap, which is what that
  component exists for, and both iam handlers already link it.
- The portable snapshot is mutex-backed on every platform, not
  atomic-backed on the platforms that support it. One code path ships
  everywhere and the tests exercise it everywhere; a conditional would
  leave the macOS path compiled only on macOS.

* Out of scope

- The =ores.shell.trading= translation unit that MSVC and clang-cl cannot
  compile. Continuous Windows stays red on it, by agreement.
- =ores.refdata.core.tests=, and the ten eventing assertions behind it.
  The capture that already owns that condition decides between a
  version-aware write in the tests and work on the notification chain;
  this hotfix records the run that isolated it to one target and does not
  pre-empt the decision.
- The workspace model migration itself, which moves =name= into
  =* Columns= as a flagged natural key, states =party_id= the way the
  other models state it, and reconciles the generated schema with the
  hand-written one. [[id:EF349D87-4D3A-4F98-A454-7DBB2A80E48B][Fix workspace entity model drift]]
  owns it; re-enabling the facet is part of that work.
- Moving =crm_ingest_bridge= onto the platform snapshot. It keeps its own
  mutex for now; the capture that records the switch-back now names the
  shim as the place the switch-back happens.
