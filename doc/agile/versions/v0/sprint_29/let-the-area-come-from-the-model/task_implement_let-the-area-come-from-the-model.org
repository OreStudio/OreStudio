* Acceptance

- [X] An entity that declares =#+http_area:= renders its routes under that area.
- [X] An entity that declares no area renders under its component, so no existing URL moves.
- [X] A declared area that is not in the published list fails a check.

* Plan

The declaration is a frontmatter scalar, read the way =#+entity_plural:= is read, and
resolved in =entity_http_route_plan= where the path base is built. The default is the
component, which is what every route answers on today, so this task changes no URL and a
reader can see the mechanism without a migration in the same diff.

The published list is the one the inventory is classified against, so the tree keeps one
list of areas instead of two.

* Notes

- The end-to-end proof moved the currency routes and was reverted in the same pass, because
  moving a URL belongs to the task that also updates the client and the tests. What this
  task proves is that the mechanism resolves and renders, not that a route moved.

task can move one component at a time under a gate that already knows what an area is.
