* Result

The first half is delivered; the task is not closed.

- The 34 refdata vocabulary tables the provisioner copied are no longer copied.
  Each one's model declares `:rls_own_or_system_tenant_rows:` and
  `:system_tenant_visible:`, so its policy admits the system tenant's rows and
  its repository reads them beside the caller's. The generated SQL, the C++ and
  the ER diagrams follow from the models.
- The validators already read the system tenant, so removing the copies changes
  no check: a tenant's party type is validated against the system catalogue
  whether or not the tenant holds a copy.
- =parties= and =business_centres= stay, and they are not copies: the provisioner
  creates the tenant's own system party and business centre with its own code
  and identifier.
- A recreate passed end to end with the policies and the shortened provisioner,
  and `compass db status` reports the schema in sync.

What remains, and it is the larger half:

- The provisioner still copies 24 more statements: the DQ registries (artefact
  types, dataset bundles, coding schemes, dimensions, change reasons), IAM roles
  and permissions, trading activity types and structure kinds, and the
  marketdata series classification rules, plus =party_categories=, which has no
  model to state a policy on.
- The DQ registry copies cannot go until the runtime publish path reads a
  dataset from the system tenant. =publish_service= resolves a dataset in the
  caller's tenant today, so a tenant's publication depends on its own copy of
  the dataset row even though the bring-up publishes from the system tenant's.
- The tenant bootstrap itself is still unnamed: what a new tenant is seeded with
  is stated by these insert statements and not by the bundle map.
