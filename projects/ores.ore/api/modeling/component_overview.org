* Summary

=ores.ore.api= is the shared contract of the component. It carries the
series key shape entity with its JSON and table I/O, its generated NATS
protocol and change events, and its sample generator; the protocols for
importing an ORE directory and for locating the import tarball in object
storage; and the workflow registration the ORE import runs under.

It is a shared library, not a header-only one: the sources under =src/=
build =ores.ore.api.lib= and install it with a version.

* Inputs

- Entity rows and protocol requests, at the boundary of the generated
  entity stack.
- Workflow definitions registered by the engine at startup.

* Outputs

- The generated entity protocol, its events, and the serializer and
  table renderers the shell and the wire protocol use.
- The import and storage protocol schemas consumed by =ores.ore.service=.

* Entry points

- =include/ores.ore.api/domain/= — the series key shape entity and its I/O.
- =include/ores.ore.api/messaging/= — the entity protocol and the import protocols.
- =include/ores.ore.api/eventing/= — the entity change events.
- =include/ores.ore.api/generators/= — the sample entity generator.
- =include/ores.ore.api/net/= — the import tarball bucket and key helpers.
- =include/ores.ore.api/workflow/= — the ORE import workflow registration.

* Dependencies

- =ores.platform=, =ores.storage=, =ores.logging=, =ores.workflow.api= and
  =ores.eventing.api= — linked publicly, so consumers inherit them.
- =ores.utility=, =faker-cxx= and =libfort= — linked privately.

=ores.storage= is public because the import target helpers name a bucket,
so every consumer of this part inherits the object-storage client.
