This page documents a [[id:F44766FA-1E9C-416F-849A-E131101B2ECA][user journey]]: An operations user writes a set of trades out as the ORE portfolio the engine reads.

A user journey describes what one person is trying to do, before anything is
built. It is a design document that outlives any sprint, so it names the
screens, the entity fields each screen shows, and the operations and messages
each step needs.

* Goal

"I want the ORE portfolio the engine reads, made from the firm's trades, so that a run
uses what the firm holds." The journey is done when the person has the file, or the file
is in storage for a run, and the person knows which trades it holds.

* Actor and trigger

The actor is an operations user, or the compute grid acting for one. The trigger is a run
that needs a portfolio. The journey starts with a choice of trades and ends with a file or
a storage reference.

* Steps

1. *Choose the trades.* The person chooses a book, a portfolio or a list of trades.
2. *Check them.* The system says which trades it cannot export and why.
3. *Export.* The system writes the portfolio file, or writes it to storage.
4. *Read the result.* The system reports the number of trades and the location of the
   file.

* Screens and wireframes

This journey is a use case. It is the Export action in the Workflows menu of the trade
list. It also serves the compute journeys, which need a portfolio in storage.

No wireframe is drawn here. The prototype story draws the screens, from the user
interface standards and from this use case.

* Entities composed

This journey adds no entity of its own. It reads and writes the trade and the records on its page.

* Operations and messages

#+ATTR_HTML: :class hug-leading
| Step | Operation | Subject | Status |
|------+-----------+---------+--------|
| Export | Export the portfolio to the caller | =trading.v1.ops.export_portfolio= | exists |
| Export | Export the trades to storage | =trading.v1.ops.export_trades_to_storage= | exists |

Status is one of =exists=, =partial=, or =missing=. A subject that contains
=<instrument>= stands for the one instrument table the trade type routes to.

* What is missing

- The choice of trades by portfolio, by book and by list is not verified against the two
  requests.
- A trade the export cannot write is reported how? Check the response.
- The task "Export the trades as the ORE portfolio the engine reads" is in flight in another
  environment. Read it before this journey is built.
