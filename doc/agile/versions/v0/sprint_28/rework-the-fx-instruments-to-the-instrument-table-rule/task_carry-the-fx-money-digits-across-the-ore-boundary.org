* Goal

Make every FX money value keep the digits the ORE document wrote. Today each
FX money leaf is a plain =float= in the binding, so the XML parse discards the
text and the mapper's =exact_decimal= call takes the =from_double= overload.
The stored decimal is therefore the binary float's spelling, not the document's
number.

This unit comes first because it moves the goldens.

* Acceptance

- Every FX money leaf in the binding is a lexical leaf, and each one is patched by =scripts/reapply_ore_lexical_form.py=, never by hand.
- The script handles a required plain =float= member, or it refuses the shape with a stated reason. Today it handles =xsd::optional<float>= only, and most FX money members are required.
- Every FX money field that has a continuous sibling stays a binary float. A variance strike, a ratio and a quantity are not money.
- The forward mapping reads each money leaf with the =xsd::base<T>= overload of =exact_decimal=, and the reverse mapping writes each one with =set_exact=.
- A mapper test holds the digits of each money member: a value with more significant digits than a float carries survives the round trip.
- No golden that changes has a non-numeric change.

* Plan

1. Classify every FX binding member as money or continuous, with the exact-money rule of the data-oriented design page.
2. Extend =scripts/reapply_ore_lexical_form.py= to a required member, with a self-test for the new shape.
3. Add the FX money members to the script's table and run it. Check the diff by hand: the struct, the getter, the element info and the serializer of each member.
4. Replace the reverse casts with =set_exact=.
5. Add the digit tests, then regenerate the goldens and read every changed line.
6. Run the ORE core and trading core suites, and the codegen tests.

* Notes

- The evidence for this task is [[id:38931409-479B-40C3-A118-16D234C687C9][Investigation: FX family data model review]], finding 1. Measured there: 35 =exact_decimal= call sites in =fx_instrument_mapper.cpp=, 0 =set_exact= sites, and 6 money leaves carrying the lexical form in the whole tree.
- The credit task [[id:C5829235-D255-4C13-9EC1-6658CA518B02][Carry the credit instruments' digits]] is the template for the shape of this unit.
- *The lever was broken before this unit started.* The nightly clang-format run reflowed =_moneyFloat_Info= in =domain.cpp=, and the script's byte-exact "already applied" test then reported a half-applied patch and refused to run. Its own =--self-test= failed on =main=. The script now recognises a patch modulo whitespace, writes the declaration where the earliest user needs it rather than inside the FRA edit, and runs clang-format over what it writes. Both self-tests pass again.
- *The reach is wider than the family.* The leaf types are shared, so the commodity and equity variance-swap mappers and the equity accumulator and TaRF mappers now write their money with =set_exact=. Their goldens do not change; the three that do are the FX digital option, the FX digital barrier option and the exotic FX TaRF, one numeric line each.
- *Two money members are deliberately left for other units:* =barrierData_Levels_t.Level= is a vector, so the script does not yet patch it, and =rangeBound= is the accumulator's encoded child, which the range-bounds unit removes.

* Result

The FX family now carries the digits its documents state. 23 money members
across the seven products are lexical leaves, the reverse mapping writes them
with =set_exact=, and a mapper test holds a 16-digit amount through both
directions. The ORE core suite passes: 668 cases, 483,175 assertions.

The unit also repaired the lever it depends on. =reapply_ore_lexical_form.py=
could not run on =main= at all, because the nightly format run had reflowed one
of its anchors and its own self-test failed. It now recognises a patch modulo
whitespace, places the leaf declaration before the earliest user rather than
inside the FRA edit, and formats what it writes.

Three goldens changed, one numeric line each, and the whole diff was read. The
reach of the shared leaf types was checked: the commodity and equity variance
swaps and the equity accumulator and TaRF map their money with =set_exact= now,
and their goldens do not move.

Left for other units: the barrier level vectors, which the script does not yet
patch, and the accumulator's encoded range bounds, which its own unit removes.
