* Result

No code changed on this branch. The fix shipped in =b4d21a8822= ("Bump the
trade's version from every bond part write", 2026-10-15). The loader reads
=bump_parent_version= from a child's Foreign keys section. The trade-anchor
parts declared it in Columns, so no child bumped anything. The commit moved
the flag into the section that is read, and set it on =bond_instrument= and
the four leg tables. It gave the four leg tables =list_by_as_of=. The task
"Prove a bond rewrite versions the parent" (PR #3407) proved both on rows
read from the database.

Gaps left open, with where each is recorded:

- =bond_instrument= has the bump and no as-of read.
- An as-of read of a parent window can report two child versions. The
  trigger bumps the parent before it closes the child's own row. The
  proof task has the trade id and the timestamps.
- A bond issue leg names no trade and declares no bump. The generator
  writes issue legs, so =bond_legs= stays empty in the ACME population.
- =bond_issue= and its children, =bond_forward=, =bond_future=,
  =bond_option=, =bond_repo= and =bond_trs= declare neither flag. I did
  not check whether they hold rows keyed by a trade.
