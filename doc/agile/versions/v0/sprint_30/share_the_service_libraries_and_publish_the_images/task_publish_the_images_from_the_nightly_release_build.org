* Result

compass image has three subcommands: stage (fetch the binary list from the
service registry, strip, partition into shared libraries plus one directory
per service), build (base, library image, per-service images, NATS), and
publish (tag every image as <registry>/<name>:<version>-<commit>, skip a tag
the registry already holds, optional --alias moving tag, --dry-run to list).
--engine selects docker or podman, --preset overrides ORES_PRESET and
--from-stage builds without staging again.

The nightly build calls compass image stage in the clang-release job, uploads
build/docker-stage (625 MB of libraries plus 3.3 MB of binaries), and a new
publish_images job downloads it and runs compass image publish --from-stage
--engine docker --registry ghcr.io/orestudio --alias main with
packages: write. Only the release configuration is published. A wrapper
script was considered and rejected: the logic belongs in compass, where it
is tested and where env deploy can reuse it.
