This page documents a [[id:699A8D45-B67E-4D3E-9206-24FA17C51ADA][story]] in [[id:F05B672B-C054-42DF-91B5-27B47B72EAA3][Sprint 29]]. It captures the goal, current status, acceptance criteria, and the tasks that compose it.

* Goal

Connections and handlers share one thread today. A route that forwards to a
service blocks that thread inside =request_sync=, with a 30 s default timeout,
and the session byte counters run a synchronous PostgreSQL write on the same
thread after every authenticated request. One slow service therefore stalls every
connection on the server, including the ones that only read a file or answer
=/health=, and a busy request rate turns the counter write into a database round
trip per request.

After this story, no I/O thread blocks. Handler work runs on a bounded pool of
worker threads and resumes the connection's coroutine when it finishes, and the
counters accumulate in memory and flush on a timer. The behaviour the caller sees
is the same, except that one slow service now costs latency for the requests that
depend on it and nothing for the ones that do not.

* Acceptance

- A route handler never executes on an I/O thread. A test fails if one does.
- A downstream service that takes 2 s to answer moves neither =/health= nor a
  static file, measured by a test that stalls the service and reads both.
- The worker pool is bounded: queue depth and thread count are configuration, and
  a saturated pool answers 503 instead of growing.
- The handler's timeout is enforced by the gateway and is shorter than the pool's
  patience, so a hung service cannot hold a worker for the life of the process.
- No session counter write runs on an I/O thread. The counters accumulate in
  memory and flush on a timer, and a restart loses at most one flush interval.
- The existing route tests and the =ores.http= integration suite stay green.

* Decisions

- Handler work moves to a worker pool rather than rewriting the 24 generated
  route units to asynchronous NATS calls. The generated units keep calling
  =authenticated_request= synchronously; what changes is where that call runs.
  This is the smaller change, it fixes the stall, and it leaves the per-call
  asynchronous path to R1 where the route table is rewritten anyway.
