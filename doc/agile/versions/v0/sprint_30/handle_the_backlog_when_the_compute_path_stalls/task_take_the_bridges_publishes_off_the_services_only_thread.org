#+title: Task: Take the bridge's publishes off the service's only thread
#+description: batch_workflow_bridge::poll_once walks every pending link and calls nats_.js_publish synchronously. One link whose ack never arrives blocks the coroutine for the client's five second default, and because the bridge, the grid poller and every request handler share one io_context, the whole service stops with it. Cap the work a single poll may do, publish without blocking the executor, and back off when a publish fails instead of retrying every link in turn.

* Result

=js_publish= takes the wait it allows for the acknowledgement, defaulting to
=client::default_js_publish_ack_wait=, and passes the server's JetStream error
code into the failure it throws. The batch workflow bridge allows one second
per completion and ends its poll on the first failure, so a store that cannot
acknowledge costs the service's shared thread one second rather than five
seconds once per pending link.

This bounds the damage but does not remove the cause: a link the store never
accepts still holds the ones behind it, and the store's own reason for
refusing is only visible once =js_publish= reports it. Both are covered by
the story's remaining tasks.

PR #4879. =compass check --exclude-heavy=: 47/47 passed. The nats and compute
service unity units build clean. No test drives a stream into refusing an
acknowledgement, so the bound and the early exit rest on inspection and the
gate.
