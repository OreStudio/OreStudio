* Summary

=ores.http.scheduler= is the adapter part that projects the scheduler's
operational surface onto the HTTP server's REST surface. Its first unit is the
housekeeping screen's: the stores the installation keeps, one store's series,
and the write that changes a bound.

The part declares =#+component_kind: adapter=. Its =CMakeLists.txt= files are
hand-authored, because the link libraries belong to the HTTP surface rather than
to the domain, and codegen writes only the two =component_files.cmake= lists.

* Inputs

- HTTP requests on the =/api/operations/housekeeping/...= paths the unit
  registers.
- The caller's bearer token, forwarded to the service on every NATS request.
- The connected NATS client the hand-written aggregator passes to
  =register_routes=.

* Outputs

- The housekeeping routes and their OpenAPI schemas, registered on the router
  and the endpoint registry.
- NATS request messages to the scheduler service, one per route.

* Entry points

- =include/ores.http/routes/scheduler/= -- the unit headers.
- =src/routes/scheduler/= -- the unit implementations.
- =scheduler_routes= -- the aggregate the host calls to install every unit.

* Dependencies

- =ores.http.api= -- the router, the route builder and the OpenAPI registry.
- =ores.http.nats= -- the gateway's one forwarding step to the services.
- =ores.nats= -- NATS transport for service calls.
- =ores.scheduler.api= -- the protocol messages the units send.
- =ores.utility= -- the codecs and the wire support types.
