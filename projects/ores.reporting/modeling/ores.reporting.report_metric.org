One figure a run produced, at one subject and one observation date, with the
qualifiers that say what the figure is about. Every family whose row is keys,
qualifiers and figures lands here, and =family= says which family it came from.

The row is written once, with the run, and never edited; a correction is a new
run. A figure the engine stated as its null string is not here at all, because
there is nothing to store. The =subject_id= is the engine's own identifier, such
as a trade id or a netting set id, so it is text and not a uuid.

* SQL

** Flags
:PROPERTIES:
:tablename:                    ores_reporting_report_metrics_tbl
:hypertable:                   true
:hypertable_partition_column:  valid_from
:hypertable_chunk_interval:    1 day
:hypertable_retention_interval: 90 days
:append_insert:                true
:bitemporal_trigger:           soft_update_delete
:no_audit_columns:             true
:rls_tenant_isolation:         true
:rls_party_isolation:          true
:suppress_nk_index:            true
:END:

The chunk is a day of runs, not a span of valuation dates. A run states a
figure at the date the file dates it, which for a projected measure is years
ahead, so a chunk that aged out on =as_of= would hold next to nothing.
=valid_from= is the run's own time, because the table is written once with the
run and never edited, so a day's chunk holds the runs of that day and dropping
it drops whole runs.

The period is a quarter. A run's figures are read while the run is recent, and
the comparison that needs two runs at once is the movement against the run
before it. Beyond the quarter the record of a run is its document and the cut it
priced from, and a rerun against that cut reproduces the rows, so this table is
a working copy of the runs in use rather than the archive.

** Bitemporal natural keys

A run's figures are its own. The key is where the engine stated the figure: the
result, the file, the line and the heading. The insert trigger closes the current
row of the same key, and the key names the run, so posting one run never closes
another run's rows.

** Indexes

| name            | columns                                                                                                    | unique | current_only | where_extra |
|-----------------+------------------------------------------------------------------------------------------------------------+--------+--------------+-------------|
| run_natural_key | tenant_id, party_id, report_instance_id, result_id, source, line, as_of, measure, valid_from               | true   | true         |             |

The unique index is declared here rather than generated from the natural keys,
because it carries =valid_from= and a unique index on a hypertable must include
the partitioning column. The column admits no duplicate the key does not already
refuse: the insert trigger closes a re-posted key before the new row lands, and
every row of a run shares the run's write time.
