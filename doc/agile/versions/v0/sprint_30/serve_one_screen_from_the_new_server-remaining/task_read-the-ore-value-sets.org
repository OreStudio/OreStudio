* Goal

The gateway has no reader of the ORE value sets. Add the C++ form of the BFF's
=readValueSets=, and serve the one route that needs nothing else:
=GET /api/reporting/engine-settings/documentation=. The route states, for each
group of settings, what each setting means and which values it accepts, so a
person editing a document reads the engine's own answer and not a second
statement of it.

* Acceptance

- The C++ server answers =GET /api/reporting/engine-settings/documentation= at
  the BFF's path, with the BFF's member names and status codes.
- The value set reader is the C++ form of the BFF's =readValueSets=, and it
  lives where the reporting part and the reference data part can both read it.
- A value set whose kind this build does not know is refused, with a sentence
  that names the set and the kind, and is not drawn as a control that checks
  nothing.
- A catalogue relation is read once, however many sets name it.
- A test proves the route against the answer the BFF gives, and a test proves
  the reader's refusals.
- Each route in scope names its C++ equivalent in the inventory.
- The local gate is green.

* Plan

Branch =feature/serve-the-ore-value-sets=.

The reader goes in =projects/ores.http/core/=, under =routes/=, beside
=history_routes= and =change_routes=. The reporting part and the reference data
part both read value sets, and the reporting part already links
=ores.refdata.api=, so a reader in the reporting part would close a cycle
between two part libraries.

The reader answers the same seven fields the BFF's does: the set's code, its
kind, the catalogue it draws on, its choices, its minimum, its maximum and its
pattern. It takes the four tables as the service returned them, so it needs no
entity type from the reporting part and the shared part gains no new link. It
answers a fixed list of catalogue relations, and a set that names another one is
a seed error that is refused rather than drawn empty.

The documentation route is the reader's first consumer and its proof. It joins
three reads: the groups of settings, the settings of each group, and the
=ore.xsd= / =Setup= parameters. It states each setting's documentation from the
parameter and its fields from the value set. It lives in the reporting part, in
an =engine_settings_rows= unit that the reads task extends.
