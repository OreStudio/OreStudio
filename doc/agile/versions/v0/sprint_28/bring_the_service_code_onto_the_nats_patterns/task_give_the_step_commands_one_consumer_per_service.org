* Goal

Give the step commands the three things at-least-once delivery needs around a
durable consumer, as [[id:CE441C28-5ED0-45BF-B442-708AE4EFB1C5][At Least Once
Prerequisites]] states them.

- The work survives a repeat. The handler answers its own delivery, so a path
  that records no outcome is redelivered rather than acknowledged as done.
- One service owns the consumer. A service declares its whole family of step
  commands in one =step_routes= table, serves it on one durable consumer, and
  prunes the consumers it no longer declares.
- The retention matches the message. A step-command stream removes a command as
  soon as the consumer has acknowledged it, with a one-day age limit as the
  backstop for a command no consumer can take.

* Acceptance

- Every service that serves workflow step commands serves them on one durable
  consumer per stream, declared from one =step_routes= table.
- A consumer this service no longer declares is deleted at start, so the
  pre-change per-subject consumers are gone after the first restart.
- Every step handler answers its own delivery: =ack.accept()= where the step's
  outcome is recorded, =ack.reject()= for a delivery nothing can ever serve, and
  no answer on any other exit.
- A step-command stream uses =interest= retention with a one-day backstop.
- The pattern library and the JetStream architecture page describe the shipped
  state.
- A fresh database provision and a report run complete end to end.

* Plan

Five units, each with its own check.

1. Reconcile a durable by updating its stored configuration in place, so a
   filter change keeps the consumer's position instead of replaying the stream.
   Check: =ores.nats.lib= builds, and a live probe shows the position preserved.
2. Declare a family once. Add =step_routes= and =serve_step_commands= to
   =ores.service=, subscribe one consumer for the whole family, and delete the
   single-subject API. Check: the first service builds.
3. Move the ack into the handler for every step family the registrar used to
   answer for, and rewire the remaining registrars. Check: each service builds.
4. Own and prune the consumers, then bound the retention. Check: the consumer
   shape check flips from FAIL to PASS across all step streams.
5. Write the pattern page and refresh the architecture catalogue. Check:
   =compass lint=.

Then the two gaps the first pass left, as their own units.

6. Make step completion an atomic claim. A lease table in the workflow schema,
   written by hand the way the compute work ledger is, and a claim the engine
   serves over NATS. The transport takes the claim before it dispatches to a
   handler, so exactly one delivery does a step's work. Check: the claim
   statement takes once and refuses a live second, and a duplicate delivery
   leaves one attempt.
7. Grant the report run role the compute reads it makes. The run token carried
   the write half of the batch only, so collecting the results was refused.
   Check: a report instance reaches completed rather than compensated.

Deferred, and why. The entity-mirror reconciliation stays out: it is a separate
defect in event delivery, not in the step-command path.
