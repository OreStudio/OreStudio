* Goal

A person arrives with the trader's question -- what date does this tenor give on this day, on this calendar -- and reads the answer without authoring anything. The page is read-only, asks only for the four things resolution needs, and reuses the resolve operation the server already serves.

* Acceptance

- Choosing a convention, a tenor, a calendar and a horizon answers with the anchor date, the date before the roll, the adjusted date, the roll rule and the calendar.
- The tenor picker offers only the tenors the chosen convention resolves, so a pair the server cannot resolve is not offered.
- A refusal shows the server's code, its message and the field at fault, keeps every pick the person made, and never reads as a network failure.
- Nothing on the page writes: no save, no intent, no membership row.
- The BFF route and the web page are tested, the workspace suites pass, and the local gate is green.
