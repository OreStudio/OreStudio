* Plan

The routes are =GET /api/bootstrap=, =POST /api/bootstrap/administrator=,
=POST /api/bootstrap/complete=, =GET /api/tenant-setup= and
=GET /api/registration-policy=. The first two run with no session. The bootstrap
read states whether the browser holds a session, so it may wait for
[[id:D4275B6D-BF22-4A77-9F00-018D776966CB][Serve the browser's session routes, sign-up and password]].
The BFF rate limits the policy read, which the C++ server cannot do yet.

- An open route did not read the browser's session at all. The session path
  in =http_session= now reads a live session on an open read, never requires
  one, and gives the request its claims and token. It does so only on a read
  that carries no bearer token of its own: an open write has no proof of
  intent, so it must not act as the browser's session.
- =bootstrap_screen_routes= is a new unit in the IAM part, registered by the
  application beside the session routes because the status says whether the
  browser sent the session cookie, and so needs the deployment's cookie.
- =GET /api/bootstrap= reads the status with no session, and the two wizard
  settings through the browser's session when it has one; a read that fails
  answers false, as the BFF did. =POST /api/bootstrap/administrator= refuses
  unless the deployment is still in bootstrap mode, because the create grants
  SuperAdmin and does not check the flag. =POST /api/bootstrap/complete= and
  =GET /api/tenant-setup= need a session. =GET /api/registration-policy= takes
  the tenant from the host the request arrived at, without its port, as the
  BFF read it.
- The BFF rate limited the policy read at 120 a minute for each address. The
  C++ server has no limiter yet, so the policy read goes unlimited.
- The IAM part takes =ores.variability.api= for the settings and the end of
  first-run setup.

* Result

The C++ server answers the bootstrap status, the first administrator, the end
of first-run setup, a tenant's own setup run and the registration policy at the
BFF's addresses and in its shapes, and the inventory pairs each. An open read
now sees the browser's live session. Tests compare each shape exactly, prove
which routes are open, the administrator refusal before any forward, the host
reading, and the session read on open routes. The policy read has no rate limit
yet.
