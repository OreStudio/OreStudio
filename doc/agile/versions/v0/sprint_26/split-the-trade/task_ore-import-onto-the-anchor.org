* Goal

An imported ORE trade lives in the anchor and its components, with its envelope resolved to entities: a counterparty that does not resolve rejects the trade, and a netting set that does not exist is created for it.

* Acceptance

- The import books each trade's anchor, booking and state in one write, with entry channel stp.
- ORE's Trade/@id is a trade_identifier row under the ORE scheme, and each envelope additional field is a trade_additional_field row.
- An envelope counterparty is resolved by name; a name that matches no counterparty is an item error and nothing is written for the trade. The default counterparty applies only when the envelope names none.
- An envelope netting set is resolved by code; one that does not exist is created under the trade's counterparty and party.
- The wide trade and the envelope are still written, so export and the instruments keep working until their own tasks.
- Build, ctest, pgTAP and the local check set pass.
