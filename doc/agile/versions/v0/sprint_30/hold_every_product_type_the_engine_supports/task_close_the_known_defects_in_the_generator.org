* Acceptance

- the bond planner draws its product and its book independently, so every product reaches every book
- a generation config of any size the seed states is recorded without overflow
- the bond issue bad_alloc is reproduced and fixed, or a stress run of the bond population shows it no longer occurs
- a closed either-or such as long or short, payer or receiver, call or put is drawn both ways across a population
- a bond issue names its issuer by a readable legal entity, and two parties' configs that name one security mean one issue or two named ones, without aborting
- each named defect has a test that fails without its fix, or evidence that it was already fixed

* Plan

1. Measure first: two tests plan every asset class at 64 trades per book and fail on a trade type that misses a book, or on an either-or column one type only ever states one way.
2. Give each slot a turn, how many times the class's types have cycled before it; shift the book by the turn once per books' worth of turns, and pick every either-or from the turn.
3. Draw the directions six products fixed as constants, adding the term to the builder where the builder fixed it.
4. Carry each issuer's legal name beside its id, so a bond issue names its issuer by name while the id still names the security.
5. For the int overflow and the two-configs collision, find the fix that already landed and its evidence; for the bad_alloc, run a stress test of the issue write.

** What each named defect came to

- *Product and book by position.* The type, the book and every either-or were read from the slot's position, so with two books and an even type count a type reached one book and stated one direction. Fixed by the turn. The first formula rounded the cycle up to a whole number of books, which cancelled the shift for an odd type count; the test caught it on the commodity class, and the grid check confirmed the corrected one.
- *Directions fixed as constants.* The Ascot's option, the bond TRS's return side, the equity swap's position, the average forward's fixed payer, the commodity barrier and spread options' call or put, and the equity option position's option type were constants. The equity swap was worse than constant: it stated Long while its legs paid the equity's return. Each is now drawn, and the swap's legs follow its position.
- *Structural either-ors.* A bond's legs, a cap's leg and an option strip's leg state the security's or the option's own direction, and the average forward's =long_short= is a label ORE does not read. The test holds them in a closed list with the reason.
- *Int overflow.* Already fixed by =bde83272d4= on 2026-10-25 (=trades_per_book= is =int=, as its column is). The bad_alloc capture records a full provision on 2026-11-13 that wrote 6,541 trades through the same step.
- *Two parties' configs, one security.* Already fixed by =fbc205fa74= on 2026-10-31, which names a security by its issuer; =a_security_is_named_by_its_issuer= and the tests beside it hold it.
- *Issuer as a party id.* Fixed: the issue names its issuer by the counterparty's legal name.
- *bad_alloc.* Not reproduced. The issue rows hold no uninitialised number, and the write sizes nothing from a drawn value. The stress run writes 2,304 issues of 24 populations with no failure. It runs in process, so it does not cross the NATS decode the failing request went through.
