* Goal

An agent holding a UUID, a PR number, a branch, a component or a failing test has no way to ask what it can do with it; it must already know the skill's name. Build Embark's act for our catalogue. Given a target, resolve its type from the type keyword or from compass for the non-document targets, look up the verbs registered against that type filtered by the session's level, present them with a recommendation, and run the chosen action. Add act-all to fan one action over a collection, and export to hand a result set to the artefact type that owns that payload. The verb table must be generated from the catalogue, the way the skills inventory already is; a hand-maintained table will drift within a sprint, and if we cannot generate it we should not build this.

* Acceptance

- compass-act resolves a target's type for documents, branches, pull requests, worktrees, services and test failures.
- The verb table is generated from the catalogue, and a new action appears in the dispatcher without anyone editing a table.
- The presented verbs are filtered by the session's declared level.
- compass-act-all fans one action over a collection.
- compass-export hands a result set to the artefact type that owns the payload, and never invents a new container.
- The division against agile-find-heading is documented: heading picks the work, act picks the verb.
- Blocking, from the council review: every non-document target kind is enumerated with the source its type comes from, before any dispatcher code is written. A target whose type cannot be resolved is out of scope until it can be.
