The service liveness surface: one heartbeat every service publishes, and one
request/reply that lists the latest sample per running instance.

These are operations rather than entity verbs. A heartbeat arrives from
outside the service and is stored as it arrives, and the list is read from
the newest sample of every instance rather than addressed by key, so neither
is a row a caller reaches by primary key.

* Physical space

The shell commands are switched off. The shell has no telemetry part, so a
generated unit would have nowhere to land. Every service writes the heartbeat,
and the operations dashboard reads the samples.
