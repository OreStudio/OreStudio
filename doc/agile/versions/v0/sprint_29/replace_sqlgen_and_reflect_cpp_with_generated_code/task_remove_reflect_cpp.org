* Acceptance

- The 106 uses of rfl::Generic and rfl::Object use yyjson.
- Enum tables and JSON schemas come from the generator.
- Nothing in ores.database, ores.diff, ores.eventing, ores.logging, ores.nats, ores.orgmode, ores.platform, ores.service, ores.storage or ores.utility includes reflect-cpp.
- vcpkg.json and every CMakeLists.txt no longer name reflect-cpp.
- A codec precompiled header holding =ores.utility/codec/struct_codec.hpp=
  takes the place of =ores.rfl.pch= in every library that encodes, so the
  codec headers' leaf includes are parsed once per library, not once per unit.
- No doc outside the agile history and the plans names reflect-cpp or rfl:
  the knowledge docs, the component overviews and the codegen template docs
  describe the generated codecs. Most of the 53 docs that name it today are
  codegen template docs, whose source tangles into the templates, so each
  codec task updates the template docs it changes.
- The whole tree builds and every suite passes.

* Plan

A survey at fc4f559dfb found 193 files that name rfl, 6 of them generated.
Each step below is one PR that ends in a green build.

1. Shapes first. Turn the generated wire codec on for the seven operation
   models in the notes, and state a shape for every other type a hand-written
   call encodes, so no type falls back to the reflect-cpp primary of
   =wire_traits=.
2. Calls. Move the 293 direct =rfl::json= and =rfl::msgpack= calls in 104
   files onto the codec carriers of =ores.utility/codec=, component by
   component.
3. Dynamic JSON. Move the 113 uses of =rfl::Generic= and =rfl::Object= in ten
   files onto yyjson.
4. Schemas, Skip and Rename. Generate the three JSON schemas; state the
   skipped and renamed members in their models.
5. Removal. Delete the custom reflectors, =reflectors.hpp=, the reflect-cpp
   primary of =wire_traits= and =ores.rfl.pch=; put the codec precompiled
   header in its place; drop reflect-cpp from vcpkg.json and every
   CMakeLists.txt.
6. Docs. Rewrite the docs that still describe reflect-cpp.

* Notes

Seven operation models still have no generated wire codec, so their messages
go through reflect-cpp. Each needs =:ores.cpp.wire-codec.enabled: true= and a
regeneration before the dependency can go. Found by "State a type's wire shape
by its type" on 2026-11-04:

- =ores.history.history_messages=
- =ores.refdata.publish_operations=
- =ores.refdata.calendar_adjustment_messages=
- =ores.refdata.bundle_import_operations=
- =ores.refdata.counterparty_proposal_operations=
- =ores.refdata.calendar_materialisation_messages=
- =ores.refdata.book_proposal_operations=

**The conventions path waits on its own story.** =run_configuration_operations.cpp=
uses =rfl::Generic= for the conventions export, and ores.ore core encodes
convention rows with reflect-cpp in =conventions_family_pack.hpp=,
=conventions_diff.cpp= and =conventions_family_cross_currency_fix_float.cpp=.
The ores.ore codec task leaves them, because
[[id:60EDB576-96B3-433A-9CDA-9FA70CEE20ED][Import and export conventions without a document aggregate]]
replaces that code with typed family messages and a typed package. This task
cannot close before that story does.


**The byte tests lose their reference.** =message_codec_tests.cpp= and the
codec enum tests compare the generated codec with the reflector's output. When
reflect-cpp goes, they have nothing to compare with. Before the dependency is
dropped, replace them with a read-after-write round trip over every generated
codec, generated from the same facet, so each shape is tested without the
reflector. The PR #4278 review asked for this (finding 6).
