* When to use this skill

A gate is red for a reason that is not in your diff, or a behaviour broke on
main and you need to know whose it is before you decide what to do about it.

* How to use this skill

The commands are in [[id:477E9949-CFA4-44D8-A021-D7463BEC4C0D][How do I blame a break on main?]]. This skill holds
the judgement: the disposition, and the shape of the report.

1. /Separate the break from the environment./ Re-run the failing check alone,
   then each failing suite alone. A failure that comes back alone is a break;
   one that goes green alone is a race and leaves the investigation. Done when
   every red is classified as one or the other.

2. /Attribute it./ Work the recipe: the commit that changed the behaviour, the
   trailers that name the work, the fleet row that names the environment, and
   the task record that says what its own gate measured. Done when the report's
   owner table is full and the commit chain is complete.

3. /Explain it./ State the rule that was broken, the path that breaks it, and
   the observation. Keep the reproduction verbatim. Done when a reader who
   knows the subsystem can predict the failure and run the reproduction.

4. /Decide the disposition/ with the rule below. Done when the report names one
   and its reason cites the rule.

5. /Deliver it./ Fixing inline means the fix goes on your branch, the
   reproduction becomes the regression, and the commit body and the task's
   =* Result= say the break was not yours. Handing back means the report goes on
   the owner's task and the user is told which environment holds it. Done when
   the report sits where its reader will find it.

* The report

Four sections, in this order. No section is optional, and a section with
nothing in it says so.

#+begin_example
# Blame: <what failed, in one line>

## Owner
| Field        | Value |
|--------------+-------|
| Environment  | <the commit's Environment trailer> |
| Agent        | <the commit's Co-Authored-By> |
| Person       | <the commit's author> |
| Work         | <Story-ID> / <Task-ID>, with their titles |
| Pull request | #<n>, and its title |

## Related commits
| Commit | What it did |
|--------+-------------|
| <sha>  | <the rule it changed, in one line> |

## Technical description
<The rule that was broken.>
<The code path that breaks it.>
<The observation, with the command that produced it and its output verbatim.>

## Disposition
<Fix inline. | Hand it back to <environment>.> Because <the reason, citing the rule>.
<What happens next: the change and the check it needs, or where the report goes.>
#+end_example

* The disposition rule

The owner is an environment, not a person: the environment holds the branch,
the task and the session that made the change, and =compass fleet= is where it
is read.

- /Fix inline/ when three things hold: the change sits inside your diff's blast
  radius (an include, a declaration, a default, a line your branch already
  edits), the break blocks your gate, and no live branch of another environment
  touches the file.
- /Hand it back/ when the change touches schema, behaviour or a contract, or
  when a live branch of another environment owns the file.
- When both read true, hand it back. The owner holds the context, and an inline
  patch over another environment's design hides the break from the person who
  has to fix its cause.
- A break nobody can attribute yet is not this skill's answer: it is a
  [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] filed before the session ends, so the next gate does not
  rediscover it.
