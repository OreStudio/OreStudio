This page defines the [[id:68FAC606-569C-4B9B-932B-3B3A0181AC8B][service architecture pattern]]
Log Aggregation in the [[id:EA249899-6611-407F-A43A-B37019EBD1A7][pattern language]].
Every service's logs are collected where they can be searched together. In ORE
Studio the services log to the console, systemd keeps it in the journal, and
the telemetry log store holds the records the logs screen reads.

* Also known as

- /Centralised logging/.

* Context

Many services on several hosts each write their own logs. A failure's cause and
its symptom are in different services.

* Problem

How does a person search the logs of every service at once?

* Forces

- Logs on each host are read one host at a time.
- Files written by each service need rotation and collection.
- A search across services needs a common key.

* Solution

Each service writes to standard output, and the host's supervisor collects it.
Records also go to a central store with their time, level, source and identifiers.
A person searches the store, and a [[id:4F11D22B-2830-4E8E-B752-552F0C59CD07][Correlation Identifier]] joins the lines
of one request.

* Failure handling

#+ATTR_HTML: :class hug-leading
| Concern | What the pattern does |
|---------+-----------------------|
| Errors | An ingest that fails does not fail the service that logged. |
| Timeouts | Does not apply. |
| Retries | Ingest retries; a record may be delivered twice. |
| Idempotency | Duplicate records are tolerated, or keyed by their source and time. |
| Observability | This is the pattern's purpose. |

* Pitfalls

- *No common key.* The lines of one request cannot be joined; see [[id:4F11D22B-2830-4E8E-B752-552F0C59CD07][Correlation Identifier]].
- *Secrets in log lines.* A central store spreads them; never log tokens or passwords.
- *A log file as a readiness signal.* Removing the file then breaks the start-up; the journal story removed this dependency.

* Security

The store holds every service's lines, so reading it is a privileged act: the logs screen is for the system administrator. Lines must not carry credentials.

* Resulting context

- Benefits :: One search across services, and one place to read a failure's whole story.
- Liabilities :: A store to run, and volume to retain.
