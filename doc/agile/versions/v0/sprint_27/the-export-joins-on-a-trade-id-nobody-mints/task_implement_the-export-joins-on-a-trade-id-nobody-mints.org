* Goal

Give every trade in a payload built without the planner an id, and stamp the
same id on its instrument, so the export's join resolves to the trade's own
instrument.

* Acceptance

- =xml::roundtrip()= mints one id per trade and stamps it onto the instrument.
- The exporter tests build payloads through one shared helper that does the same.
- Their assertions are unchanged, and the importer still leaves ids unset.

* Plan

=export_portfolio= joins a trade to its instrument by =item.anchor.id=, and
=rebuild_instrument= keys the batch by the instrument's identity =trade_id=.
Two payload builders bypass the planner: =xml::roundtrip()= and the exporter
tests. Both left every id nil and the uuid default, so the join matched the
first row of whichever typed array was searched first.

The roundtrip walk now mints an id with =boost::uuids::random_generator=,
stamps it on the instrument through =trading::domain::stamp_ids=, and carries it
on the anchor -- exactly what the planner does. The exporter tests share one
=make_export_payload= helper that does the same, which replaces the duplicate
nil ids they used to feed.

which threw =std::get<cap_floor_instrument>= and lost =IR_DurAdjusted_CMS.xml=
and its ten trades; an Ascot resolving to a swap, which wrote a type and an
envelope with no =AscotData=; and the exporter tests feeding duplicate nil ids.

The fix was written in another worktree against a prebuilt tree and not
executed there. It is executed here.
