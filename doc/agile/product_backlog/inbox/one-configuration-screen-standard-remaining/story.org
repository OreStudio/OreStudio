* Goal

One screen standard covers every configuration that comes off an ORE XML
document: the same list, the same record page, the same sections, the same
documentation, the same reach, the same history, the same import and the same
lifecycle. A person who learns one configuration screen knows them all.

Two configurations carry the word "engine" and a person confuses them today.
The standard gives each one a name that says what it decides, and every page
says what the configuration is and which other configurations the same report
binds.

* Acceptance

- One knowledge page states the standard for every configuration screen, and
  the UX hub and the screen review checklist point to it.
- The screen words are fixed for every configuration kind, and no two kinds
  share a head noun.
- Every configuration page says what it decides and lists the other
  configurations the same report binds.
- The engine run settings keep the pattern they set, and the pricing engine
  configuration follows it.
- A change that alters the numbers a run computes goes through a proposal and a
  sign-off, whichever kind it is.
- The two configuration prototypes follow the standard and the owner signs them
  off before any code change.
