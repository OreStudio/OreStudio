* Acceptance

- A restart with marketdata not yet running starts every auto-start feed once marketdata answers.
- A provision starts the system feeds without a restart.
- A person's Start of a feed creates the binding of the person's party.
- Reporting creates its run grant through the shared client call.
- Every feed group shows the documented behaviour across a stop and a start of the services.

* Plan

The note =feed_execution_identity.org= is the target. The code follows it.

The test of every feed group, on a fresh database with ACME provisioned, found
four faults. Each one has a cause that was read in the code or reproduced.

- A restart with marketdata down fails the 13 vintage-priced Bloomberg FX feeds
  with "no service is handling subject", and nothing tries them again.
  Reproduced by stopping marketdata and restarting the synthetic service.
- =market_data_client::save_feed_binding= never copies =producer_kind= into the
  wire record, so the database refuses the binding of every Start by a person.
  The Start succeeds and the log carries a warning.
- The system provision creates the system collections and starts none of them,
  so the 24 system feeds wait for the next restart.
- Reporting keeps its own copy of the grant create call.

Work, in order:

1. =restore_retry.hpp=: the policy and the loop, as a template over a pass and a
   sleep, so a test drives it without a clock.
2. =feed_restore.hpp=: the pass moves out of =application.cpp=. A pass reports the
   feeds that failed. The boot walk tries the failed feeds again by the policy.
3. =restore_feeds= operation: the request, the handler, the registration, and the
   call from the system provision step.
4. =save_feed_binding= copies =producer_kind=. A test asserts the wire record.
5. Reporting calls =create_run_grant=.
