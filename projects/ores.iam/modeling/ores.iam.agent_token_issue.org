#+entity_title: Agent Token Issue
#+brief: One agent key exchange that reached the log, issued or refused; a TimescaleDB hypertable partitioned by issued_at.
#+created: 2026-11-22
#+updated: 2026-11-22

A row says that ores.http exchanged an LLM agent's key, for which grant, key and
session, from which client address, and whether the token was issued or
refused. It never holds the key. The exchange reads it to find a key's open
session, and the grants page reads it for each key's last use. The rows are
append-only, so the model states =:current_state:=.

The table is an audit log like the run token issue log, and follows it: its
=tenant_id= is an ordinary text column isolated by a policy in
=iam_rls_policies_create.sql=, and only IAM's own exchange writes it, each row
through a session of its own tenant. No retention policy is set.

The table is internal, so only the data layer and the SQL schema are generated.
The reads stay hand-written in =agent_token_issue_log=.
