This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

A smokehouse run now gathers the FX spots its trades convert at, and one of its
three trades prices. The other two still record no NPV, and each names an object
the market configuration cannot resolve:

#+begin_example
fx vol curve building failed: Convention 'EUR-GBP-FX' not found.
did not find object 'GBP-LIBOR-12M' of type ibor index under configuration 'default'
#+end_example

* Why

The first is the FX convention and its calendars. The conventions file the run
builds does carry =EUR-GBP-FX=:

#+begin_example
<FX>
  <Id>EUR-GBP-FX</Id>
  <AdvanceCalendar>TARGET,UnitedKingdom.Settlement</AdvanceCalendar>
  ...
</FX>
#+end_example

ORE parses that entry, cannot convert =UnitedKingdom.Settlement= to a calendar,
and drops the convention — which is why a curve that names it says it is not
found. The engine warns about exactly this for every pair whose calendars come
from a country:

#+begin_example
Exception parsing convention AUD-CAD-FX: Cannot convert "Australia,Canada.Settlement"
to Calendar … This is only a problem if this convention is used later on.
#+end_example

The calendar codes are QuantLib's own (=UnitedKingdom.Settlement=), and ORE's
conventions accept the short aliases its built-in index catalogue uses
(=TARGET=, and the =fixingCalendar= spellings there). The mapping between the two
is what is missing. Every FX trade on a pair with a country calendar is blocked by
it, not only this one.

The second is the interest rate swap. The trade draws a convention whose index is
=GBP-LIBOR-12M=, the curve configuration models overnight discount curves and
volatility surfaces and no IBOR curve, and the today's market maps no forwarding
curve for the index. A LIBOR-based swap therefore has nothing to read, however
complete the rest of the market is. The same is true of the template's own
documents, so no ACME LIBOR swap prices either.
