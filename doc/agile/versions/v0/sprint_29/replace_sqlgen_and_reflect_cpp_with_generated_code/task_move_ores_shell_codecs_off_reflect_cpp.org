* Notes

** Models the component tasks missed

dq's =lei_entity_summary=, =report_definition_template=, =publish_bundle= and
=publish_datasets= were never opted into the codec, so their generated commands
kept reflect-cpp after the template change. They are opted in here.

** Storage stays on the fallback

Storage's =objects= model is not opted in. Its codec would make
=ores.storage.api= a compiled library that links =ores.utility=, and the part
is header-only on purpose: its model says a consumer linking it takes on no
socket, no archive library and no logging. So the storage messages keep the
reflect-cpp fallback, and =objects_operations_commands.cpp= and
=raw_storage_commands.cpp= keep reflect-cpp. Whether storage trades that for a
codec is the storage owner's call; the fallback capture lists it.

** What keeps reflect-cpp

Fourteen hand-written shell files still include the reflectors without calling
reflect-cpp. Some calls they make still cross NATS through the reflect-cpp
fallback of =wire_traits=, for example the synthetic market regime messages,
whose hand-written protocol has no wire fields. The capture
=find-the-nats-types-still-on-the-reflector-fallback= owns finding every such
type before [[id:7A1D09B8-B3F2-4E02-9669-3C2F6CC2C6EC][Remove reflect-cpp]] deletes
the fallback, and that task drops the includes.
