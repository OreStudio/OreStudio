* Result

The generated command for =iam.v1.bootstrap.status= was =bootstrap-status=,
because a message named =bootstrap_status_request= becomes the command
=bootstrap-status= and the menu is already =bootstrap=. A caller therefore typed
=bootstrap bootstrap-status=, which is the menu twice, next to =bootstrap setup=
and =bootstrap create-initial-admin=, which read properly.

The generator now reads a =:shell_command:= property on a message, so a model
that names a message after the artefact and the action both can state the verb
a person types. The bootstrap status read states =status=, and a verb that is
not lowercase words joined by hyphens is refused where the model is read, so a
typo fails the model rather than producing a command no one can type.

The command name is also what the generated recipe documents and what the
tangled script runs, so both follow: the script library holds
=bootstrap-status.ores= containing =bootstrap status=, and the stale
script the tangle left behind is removed.

The codegen suite grew five cases for the new property, including one measured
on the real bootstrap model rather than restated, and every gate is green.
