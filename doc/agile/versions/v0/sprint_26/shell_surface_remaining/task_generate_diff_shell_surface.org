* Plan

diff cannot render a shell unit, so the task proves that rather than changing it,
and leaves the proof where the next reader meets it.

Three checks establish it. The profile: =table-less-record= disables every facet
at the root and lets only the C++ and TypeScript domain types back in, so there is
no protocol and no subject for a command to address. The tree: the component has
no part under =projects/ores.shell=, so no generated unit has anywhere to land.
The shell: no hand-written unit registers a diff menu.

Then each of the four models gains a =* Physical space= section stating why, which
is the shape =ores.scheduler.job_definition= already uses.

* Notes

The four models are the diff vocabulary the compare engine emits: an entry, the
result that holds entries, a span inside a value, and a named value. None is
stored and none is addressed by identity, so none has a subject.

That is why the shell cannot carry a command for them. A command is a NATS caller,
and there is no subject to call. A person meets a diff through the history
command's diff renderer, which lives in the shell's own API part; the component
supplies the vocabulary and the shell renders it.

The repository already had the shape for this note. =ores.scheduler.job_definition=
states why its shell facet is off in its own =* Physical space= section, so the
four diff models follow that precedent rather than inventing one. Each says it in
its own words, because a span and a result are absent for different reasons.

The profile does the withholding, so no model names an override row: the root is
disabled and only two facets are let back in.
