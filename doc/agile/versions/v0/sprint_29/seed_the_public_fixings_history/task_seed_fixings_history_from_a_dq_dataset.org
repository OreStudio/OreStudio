* Goal

A new environment gets years of public fixings without calling the publishers' API. A DQ dataset holds a static snapshot of five years of daily fixings for every supported currency, and each environment loads it through DQ publishing. The snapshot is refreshed only now and then, by hand. Everything after its last day is the adapter's job: for each item it fetches from the latest stored fixing to today, whether the gap is a day or months. The derived vol source and the GARCH calibration need this depth of history.

* Acceptance

- A DQ dataset holds a static snapshot of five years of daily fixings for every catalogued provider and pair, with the date it was taken. No scheduled job writes it; a documented command refreshes it when someone chooses to.
- DQ publishing loads the dataset as durable fixing ticks with their provider, time and credit, the same rows the adapter would write.
- The public sources adapter fetches, for each item, only the days from its latest stored fixing to today, so an environment loaded from an old snapshot catches up in one fetch per item.
- Each provider's terms allow the dataset to be redistributed in the public repository, or that provider is left out of the dataset and stays adapter-only.

* Notes

- Why: every environment backfills its window from the publishers' API when
  it starts. With about ten environments recreated often, the same history is
  fetched again and again, and a rate limit or a ban is likely soon.
- This changes the decision of 2026-10-28 in
  [[id:F4BBEF34-D84C-4AE6-A3AA-DC47C3EE06EE][Public sources publish daily fixings through an adapter]],
  that DQ is for canned data and the adapter carries the public sources. Both
  hold after this task: the dataset is a canned history up to its last day, and
  the adapter carries every day after it. The note records the change.
- A dataset in the repository is published, not only stored, because the
  repository is public. Storage permission is not enough: each provider's terms
  must allow redistribution. The ECB allows reuse of unmodified statistics with
  the credit "Source: ECB statistics". A provider whose terms do not allow it
  stays adapter-only.
- The snapshot is static and refreshed rarely, by a command someone runs, not
  by a nightly job. An old snapshot is not a fault: the adapter fills the gap.
  A refresh only shortens the gap the environments fetch.
- The fixings are durable and keyed by item, provider and date, so a second
  load of the same days is a no-op, and the snapshot and the adapter can overlap.
