* Goal

Collapse the spurious asset-class forks that remain in the synthetic
generation control plane onto the one pipeline, so an asset class varies
only in its datum shape, its configuration fields and its process maths.
Every other concern — the tick clock, the vintage read, the registry
instance, and the handler plumbing — exists once over registered kinds
instead of once per asset class. A collapse deletes one of two copies; it
does not add a branch that moves the fork.

* Notes

** Behaviour deltas introduced by the collapses

- The shared tick clock's catch-and-continue guard now covers the whole
  tick, including the process step. Both producers previously advanced the
  process /outside/ the guard, so a process that threw would have
  terminated the service rather than skipping the tick. Neither process can
  throw on any exercised path, and no test covers it, but the change is a
  real one and is recorded rather than chosen silently.
- Unifying the vintage read's lookup-failure text changed one string for IR
  only: "Failed to look up series '<uri>':" became "Failed to look up
  series for '<uri>':". FX and =feed_controller= already used the "for"
  form, so the helper matches the majority. No test asserts either string.
- The "no vintage data" message stays caller-owned and is unchanged for all
  three callers: they name different anchors (FX's SPOT datum, IR's anchor
  pillar, an ORE key), and the helper takes that message as an argument.

** Coverage limits

- =find_vintage_observation()='s paged scan needs a live marketdata
  service, so it has no unit test; it is covered by the build and by the
  handler suites, which exercise the fixed/disabled/error surface but not
  the paging loop. =select_vintage_anchor_entry()= remains unit-tested.
- The tick clock has three new unit cases in =tick_clock_tests.cpp=; the
  producers' own =start()= loops are still only covered indirectly.

**Spurious forks confirmed present and not yet collapsed

- =feed_config_handler= resolves the kind by probing the FX then the IR
  repository, in both =start()= and =stop()=.
- =feed_config_handler::start_fx= and =start_ir= each re-implement the auth,
  enabled-and-container gate, child loading and error reply.
- =folder_feed_control_handler= runs one start loop and one stop loop per
  kind, and assembles =by_kind=/=stopped_by_kind= from two hardcoded entries.
- The config-read permission pair is hardcoded at every verb.
- =vintage_validity_handler= reads only FX rows and returns an FX-shaped
  response.
- The simulate and preview sampling loop and protocol envelope are
  duplicated between =simulate_handler= and =ir_curve_preview_handler=.
- The common config plumbing fields (=source_name=, =ticks_per_hour=,
  =process_type=, =enabled=, =auto_start=, =price_source=, =vintage_source=,
  =vintage_date=, =folder_id= and the audit block) are copied across the two
  config entities. Collapsing these changes the persisted schema, so it
  needs a model change and regeneration rather than a code edit.
