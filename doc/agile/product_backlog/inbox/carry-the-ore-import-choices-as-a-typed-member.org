#+description: Carry the ORE import choices as a typed member, not a JSON string. ore_import_request and ore_import_execute_request carry import_choices_json, a string the shell fills with rfl::json::write(choices) (projects/ores.shell/application/src/app/commands/trading/ore_commands.cpp:637) and the execute handler parses back (ore_import_execute_handler.cpp, step 3). The web protocol twin declares it as a string too. That is untyped data on the wire: nothing checks the choices' shape until the handler runs. Model the choices in ores.ore.api (planner::import_choices lives in ores.ore.core, which the api cannot name), make the member typed in both requests, and move the shell and web callers. The ore codec task gave import_choices wire_fields and enum text forms, so the typed member needs no new codec.
