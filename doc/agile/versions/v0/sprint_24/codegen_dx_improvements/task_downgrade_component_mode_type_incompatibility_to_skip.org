* Goal

Running an address against a =--component= that contains entity types
the address does not support (e.g. =ores.cpp.qt= against
=refdata-cpp=, which mixes =domain_entity=, =table=, and =junction=
models) currently emits one ERROR per incompatible entity and
inflates the run's final error count, even though these are expected,
harmless skips rather than genuine failures.

In =projects/ores.codegen/src/codegen/core.py=, detect model-type/
address incompatibility when running in =--component= mode and skip
those entities silently (DEBUG-level log line, not counted as an
error) instead of emitting ERROR and incrementing the error counter.
Explicit single-entity invocations (=--entity <name> --address <addr>=
naming a type the address doesn't support) must still raise an ERROR
— that is a caller mistake, not automatic-discovery noise.

* Acceptance

- Running =codegen.sh regenerate --component refdata-cpp --address ores.cpp.qt=
  produces *zero* ERROR or WARNING lines for models whose type
  (=table=, =junction=) is not supported by that address; those models
  are silently skipped (DEBUG log only), and the run's error count is
  unaffected by them.
- An explicit single-entity invocation naming an entity whose type is
  incompatible with the requested address (e.g. =--entity
  rounding_type --address ores.cpp.qt= against a =table= model) still
  raises an ERROR and a non-zero exit code — this task only changes
  the automatic-discovery (=--component=) path.
- All other existing codegen runs are unaffected and produce identical
  output to today.
- CI passes; no production source files (only =ores.codegen= tooling)
  are changed by this task.
