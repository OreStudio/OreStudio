* Goal

The local gate stops spending most of its time on work the branch did not
touch, so it is cheap enough to run per change. The measurements and the
four proposed changes are in the captures filed with this story: the two
drift checks at 436s of the 785s non-heavy total, the site page check at
115-900s, the corpus that fifteen checks each re-parse, and the serial
heavy tier.

* Decisions

- Render only what the branch changed, in both drift checks. The gate measures
  a branch's own changes; pre-existing drift in an untouched component belongs
  to that component's clean-up, which the hourly validation covers. Both
  checks select on the modeling directory and render the whole corpus when the
  change reaches the generator, a template or the registry, or changes no
  model at all.
- Publish only the pages the branch changed. The mtime rule republished the
  corpus on a fresh checkout, because a checkout gives every source a new
  mtime. The org-id map is still rebuilt every run: skipping it behind
  =--no-index= turned a stale map into a false failure on the first link to a
  page added since the last scan.
- The non-heavy total falls from 785s to roughly 255s on a one-component
  branch: =component-drift= 239.9s to ~11s, =drift-sweep= 195.9s to ~1s and
  =site-page= 114.9s to ~8s. A cold site cache no longer times out at 900s.

* Out of scope

* Result

The acceptance holds: the three biggest checks now measure the branch instead
of the tree, so a one-component branch runs the non-heavy checks in about a
third of the former time.
