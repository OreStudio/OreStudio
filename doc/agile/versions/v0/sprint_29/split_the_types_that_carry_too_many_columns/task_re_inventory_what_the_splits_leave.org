** What is re-read

The lever again, on the tree the splits produce:

#+begin_src sh :results verbatim
python3 build/scripts/inventory_entity_columns.py --summary
#+end_src

Three things come out of it, and each is decided here rather than left for the
next person:

- the types the first inventory marked =group=, which were deferred on purpose:
  =csa=, =book_change=, =commodity_instrument=, =inflation_curve_config=,
  =ir_curve_generation_config= and =dataset=. A group is a block that belongs
  together inside one component, so each is either grouped or argued down to
  =keep= with a reason;
- any type the splits moved across the threshold. A split can widen a type it
  did not touch — a part's key, or a shared field that moved to the centre — and
  the inventory is the only thing that notices;
- the C1202 the story started from. It is checked against the widest remaining
  entity's binding count, which is its model columns plus the scaffold's eight.

** The rule that ends the story

The story closes when the widest remaining type is a shape
[[id:BBD43BF2-9FEE-42B0-A667-9468AF759DC2][the data-oriented model]] allows: one
component, one key, one invariant. Not when a number is under a threshold -- the
threshold was a work list, and a type under it can still be two components badly
joined. If the inventory and the model disagree, the model wins and the report
says why.

** The rule in code

The inventory is a manual pass, and a manual pass is done once. Before the story
closes, the three shapes it found are a check a new model fails: a =has_*= flag
followed by the block it governs, a discriminator followed by one column per
value, and a pair of per-direction columns. That check belongs in codegen, where
a model is read, so the next wide type is refused at review with a reason.

** The C1202

The C1202 does not come from width. On 2026-10-31 and 2026-11-01, after the
volatility and conventions splits, MSVC stopped with the same
=tuple(320)= error on two entities of 12 columns and 19 bindings. The entity that
started the story was down from 39 columns to 31 by then, and the failure moved
to entities a third of its width. The cause was the query builder: each =operator|=
grew a =std::tuple= one column longer, so a list of n columns instantiated every
prefix. =6feebec946= holds the columns in flat slots instead.

That fix has no Windows proof yet. The first nightly that has it, on 2026-11-02,
stopped at database setup before it compiled, on =\o /dev/null= in
=setup_schema.sql=. That is captured as
[[id:3997C7F7-B6DB-4103-98D9-21D9082A3AB9][Database setup on Windows fails on
psql's \o /dev/null]]. The splits did not cause the C1202 and could not have
ended it. That is the story's decision that no split is made for a compiler,
now measured.

** The rule

The three shapes are a decision check on
[[id:BBD43BF2-9FEE-42B0-A667-9468AF759DC2][Data-Oriented Design in ORE
Studio]], under the Regime 2 checklist, as "One component per row". The check
also says when a pair is not two legs, which is the =csa= reading. A codegen
check cannot see the second shape, because nothing in a model says which
columns belong to which value of a discriminator. So the rule is on the page,
which the acceptance allows, and not in codegen.

* Result

The lever ran on =691b269fe2=, and =evidence/entity_columns.tsv= holds its
output. 19 types carry 20 members or more, against 24 at the first run, and the
refdata ones went from 14 to 6.

Every type at 20 or more has a verdict in the Notes. Of the six refdata types,
four are kept with a reason and two split: the swaption smile and the inflation
seasonality, which [[id:06F7D57F-82C7-440D-91D7-54EED11EBB85][a new task]] in this
story does. The six =group= verdicts are gone: =csa=, =book_change= and
=dataset= are kept, =inflation_curve_config= and =ir_curve_generation_config=
split, and =commodity_instrument= stays with the trading task. Two readings
outside refdata are captured for their owners, one for reporting and one for
synthetic.

The C1202 did not come from width. After the splits, MSVC stopped on two
entities of 12 columns, and the cause was the query builder's tuple, which
=6feebec946= replaced. The Windows nightly has not yet compiled that fix,
because database setup fails on Windows first. That defect is captured.

The rule is a Regime 2 decision check on the data-oriented design page, "One
component per row". It names the three shapes and says when a pair of values
is not two legs.

The story does not close with this task. The widest refdata type is now a shape
the model allows, but the swaption and inflation splits, and the trading and
market data tasks, are still open.
