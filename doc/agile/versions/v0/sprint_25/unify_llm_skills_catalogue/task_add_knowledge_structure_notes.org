* Goal

Luhmann's slip-box had structure notes, the entry points that list a cluster's notes in an argued order with the relationships spelled out. Ours has none. The knowledge index is a flat list of eighty-eight entries; it tells an agent that a page exists but not which seven to read, in what order, to be competent at interest rate curves. Search finds a page; a structure note builds a model. Write one structure note per domain cluster, starting with market data, IR curves, volatility, entity lifecycle, codegen and identity management. The links already exist, so the work is the argued ordering and the relationships, not new research.

* Acceptance

- Each named domain cluster has a structure note giving an argued reading order and the relationships between its pages.
- Every structure note is reachable from the knowledge index and from the documents it orders.
- A structure note explains why the order is what it is; a bare list is not acceptable.
- The Zettelkasten knowledge page documents structure notes as part of how we hold the graph.
- The grounding phase of the method plane can name a cluster and get a reading path.
