* Goal

The structure tables and the code generated around them are the deviation the plan names: a second way to state a package, with no book, date or state. After the completion writes a composite and the blotter reads one, nothing needs them.

This task deletes them: the models and their tables for structures, structure members, structure identifiers, structure templates and structure kinds; the repositories, services, handlers, protocols, generators, shell commands and tests; and the web structure pages and grouping journey, the last only once the sibling story that points the grouping screen at the completion has landed, because that screen calls the structure writes today.

Deletion is the test: the build names no structure subject, table or model, and the blotter, the trade page and the grouping journey still pass.

* Notes

- Deletion order matters: the web callers first, then the C++ subjects and their
  handlers, then the models and the tables. A table dropped while a handler
  still registers its subject leaves a service that fails its first message.
- The models are the source: the table, the repository, the mapper, the codec,
  the generator and the tests are generated from the six =.org= files. Deleting
  the models and regenerating removes most of the 205 files.
- The web's five files go with the sibling story, not this one: it owns the
  grouping journey and the structure pages. This task deletes them only once
  that story has landed, which is why it is blocked on it.
- =structure_kind= and =structure_template= are reference data with seeded rows.
  Check what seeds them before the tables go, and retire the seed data with them.
