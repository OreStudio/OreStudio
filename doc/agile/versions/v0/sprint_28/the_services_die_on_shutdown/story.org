* Goal

A service survives stopping. Every service that owns a NATS subscription can
reach a handler that is already running while the state that handler writes to
is being destroyed, and dies on a core dump instead of exiting. The fix goes at
the subscription handle: destroying it must wait for the dispatch thread to
return from the handler, because the handler reaches the owner's state.

The recorded failure is =ores.marketdata.service= on 2026-10-18 at 09:55:24. The
shutdown had already logged "Shutdown complete"; the ingest loop was then
destroyed while a tick was still being handled, and the dispatch thread reached
the freed rate engine:

* Acceptance

- Destroying a subscription returns only after the dispatch thread has left any
  handler it was running.
- =client::drain()= returns only after the connection has closed, as its
  documentation already promised.
- A full fleet start and stop leaves every unit stopped and none failed.
- The suite still passes: 96 of 96 ctest cases.
