* Notes

** Why the macOS job runs out of room

The runner image carries several Xcode installations, simulator runtimes
and language SDKs that a ctest run never loads, and the macOS workflow
never freed any of it. The Linux workflow has freed disk before its build
since its own debug job failed linking with "No space left on device".

** What is removed, and what is kept

Xcode applications whose name does not contain =Xcode_16=, CoreSimulator
runtimes, Xcode DerivedData and device support, the Android SDK, the
dotnet and Haskell toolchains, and Homebrew's download cache. The Xcode 16
installation is kept, because the next step selects it, and the step prints
=df= before and after so a run states what it reclaimed.

** Not a substitute for the memory question

A =Killed: 9= from clang is SIGKILL, which on macOS is usually the
out-of-memory killer rather than a full disk. This step addresses the disk
failure observed in this repository, not that one.
