* Goal

A response body is one string, so it exists in full before it is written and nothing
can be sent until it does. A response needs a body it can read from in pieces.

* Acceptance

- =http_response= may name a =body_source=, and the session writes it in chunks.
- A source that states its length is answered with =Content-Length=; one that does
  not is answered with chunked framing.
- A body larger than one write buffer arrives whole.
- A source that fails mid-body closes the connection instead of leaving the client
  waiting.
- A =HEAD= request answers the headers and no body.
- The storage download uses it, and a download larger than a buffer is byte for
  byte what was uploaded.

* Plan

1. Add =domain::body_source=: an optional length and a read into a buffer that says
   how much it filled, with zero meaning the end.
2. Add =http_response::body_source= as a shared pointer, because a response outlives
   the handler that made it.
3. Serialise through =http::response_serializer<http::buffer_body>=: the header once,
   then a write per chunk, with =more= telling Beast when the body ends.
4. Give the storage download a source over =asio::stream_file=, and delete the
   whole-object read from the route.
5. Test the length-known, length-unknown, large and failing cases through a real
   server, and the download end to end.
