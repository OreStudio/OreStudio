* Plan

Each check is one defect with its own cause, so the work is six small fixes
rather than one change:

- =component-drift= names eight generated files. Six are hand edits that the
  model never learned, and two are stale models; each is fixed in the model and
  the component is regenerated, never in the generated file.
- =unity-collisions= finds six file-local names that one unity target holds
  twice. The colliding names are renamed for what they do.
- =er-diagram= and =bff-list-requests= are regenerated from the tools that own
  them.
- =money-decimal-columns= reports seven columns that hold a continuous
  quantity -- a quantity, a weight, a CPI level -- typed as an exact decimal.
  ORE's schema reads those leaves as =xs:float=, so the columns become binary
  floats and the ORE projections convert at the boundary.
- =ticks-smoke= fails booking a bond whose call date the run already stored.
  The population writer books the trade with the issue's own rows after the
  composite write stored them, and the store refuses the second create.

* Notes

**The eight drifted files, and which side was wrong.** Six were hand edits to
generated files, so the model learned what the tree already did:
=ores.http.server= options gained =web_session_path=, whose parser and
application already read it; =marketdata.api= states =Boost::url=, because its
datum codecs include =boost/url.hpp=; =synthetic.core= tests state
=ores.ore.core.lib=, because the export tests use =ores::ore::xml=; and the bond
instrument field group states the =instrument_underlyings= basket member the
projection reads. Two models were stale instead: =marketdata.core= had carried
=Boost::url= since the codecs moved out of it, and the trading CMakeLists read
a column the generator renders differently. The http client test main's timeout
listener was the seventh hand edit, and it is dropped: a listener is a
whole-suite policy, and a capture records putting it in the template with a
per-component opt-in.

**Two columns in the same table stayed decimal.** =equity_initial_price= and
=initial_fixing= sit beside the retyped =equity_quantity= and =quantity=, and
they are money, so they stay exact. Only the leaves ORE reads as =xs:float=
became floats.

**The projections convert once.** The ORE layer keeps the XML tables as exact
decimals, so the boundary helpers =decimal_as_double=, =decimal_from_double= and
=set_decimal_from_double= moved into one header that the four projections
include. The commodity quantities already used the same conversion.

**Why the booking carried the issue's rows.** The writer copies the slot's
instrument batch whole, and the batch's append moves a product's call dates and
conversion targets into it. The composite write stores those rows with the
issue, so the booking asked the store to create them a second time at version
zero, and the store refused. The booking now states none of the issue's own
rows.

* Result

Six checks the gate failed on main pass on this branch: =component-drift= with
no file left to render, =unity-collisions= with no name held twice, =er-diagram=,
=money-decimal-columns= with no continuous column typed exact, =bff-list-requests=
and =ticks-smoke=. The build succeeds and every suite passes except one, and that
one is not this work's: =ores.marketdata.service.tests= fails two of its
ingest-loop cases only when three other heavy suites run beside it under =-j 4=.
It passes when the suite is run alone, it failed the same way on main before
this branch started, and it still fails that way after the rebase onto
=4323f8e73e=. Its two cases wait on a wall-clock deadline for a
loop that is competing for the machine, so the fix is in that suite's timing
design and has its own capture.

The capture the http work needed is filed: the test timeout listener belongs in
the test-main template behind a per-component opt-in, not in one generated file.

The rebase onto =4323f8e73e= moved the ORE projections into the marketdata api
and touched the projection header the boundary conversions left, which resolved
by keeping main's file and deleting the duplicate definitions. On that base the
whole tree builds, =ticks-smoke= passes, the nine suites the change touches pass
and the nine checks the fix turns on pass.
