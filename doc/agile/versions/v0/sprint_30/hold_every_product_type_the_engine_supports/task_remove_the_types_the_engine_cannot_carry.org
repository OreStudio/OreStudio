* Goal

The catalogue states, for every type, whether ORE supports it. A type ORE cannot
read stays in the catalogue, tagged unsupported with its reason and ORE's
evidence, so a person sees it; nothing can route, book, import or generate it;
and a check fails when a later ORE release starts supporting it.

* Acceptance

- the catalogue states a support status per type, and CommodityPairwiseVarianceSwap
  and ForwardVolatilityAgreement are tagged unsupported as trade types, each with
  its reason, the ORE source that shows it, and the library script that carries
  the product as a generic ScriptedTrade
- the generator books the product of each through its library script, in the
  script tasks, so the product is still tested
- an unsupported type routes to no table: booking, importing or generating a
  trade of it is refused with the reason
- the generator books no unsupported type, and the recorded trades hold none
- a check reads ORE's trade builder registrations and fails when an unsupported
  type gains a builder, or a supported type loses one
