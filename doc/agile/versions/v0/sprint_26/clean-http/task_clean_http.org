* Plan

Work the [[id:7B477025-132E-4B20-80B4-D8C9420880B8][Component Clean Standard]] in its section order and record each item's result in the table below.

1. Baseline and inventory (B01 to B06).
2. Models (M01 to M10).
3. Protocol (P01 to P06).
4. Generation (G01 to G08).
5. Wiring and data (W01 to W04).
6. Shell (S01, S02).
7. Structure and hygiene (H01 to H05).
8. Verification (V01 to V08), ending with the registry entry.

Scope. The decomposition that landed in sprint 26 split the component
into six parts. =api=, =core= and =server= are hand-written: the server
library, the route engine, the OpenAPI registry, the process entry point
and the storage and variability routes. =assets=, =refdata= and =iam=
hold route units generated from the assets, refdata and iam models. The
pass covers all six parts.

Applicability. The Protocol items apply, because the gateway serves
=http-server.v1.info.get= and sends the subject of every route it
proxies. The Entity items do not apply: the component declares no entity,
junction or operation model of its own, so it has no table, no repository,
no service and no generated shell unit or recipe. Its routes are generated
for it by the source components, which own the entity work.

A prior pass on this task was abandoned when the decomposition landed.
It worked against the pre-decomposition three-part shape, and 593 commits
have reached main since its base. Eleven of the files it touched no
longer exist. That work is preserved by the tag
=archive/clean-http-pre-restructure= and is not rebased; this pass redoes
the survey against the tree that exists.
