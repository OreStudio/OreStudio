* Goal

Verification is a ladder, not a final phase, and work never skips a rung below where it stops. Rung zero is that anything structural is generated; a generator that cannot express something is a gap in the generator, never a licence to hand-write around it. Rung one is that regeneration changed only what it should. Rungs zero and one share a stack discipline built from mechanisms we already have: the gap or the drift is filed as a discovered task, the current task goes BLOCKED with blocked_on naming it, the discovered task is taken to DONE on its own branch and pull request, and only then does the original resume. Fixing a generator inside a feature branch is wrong twice: the reviewer cannot separate the feature from the generator change, and an improvement every component wants is buried inside a feature nobody else reads. Rung two is tests that fail before the change and pass after, exercising the real path. Rung three is a committed ores.shell script verifying every task and story through the real interface. Rung four is Qt, only when Qt is affected.

* Acceptance

- The ladder is implemented in the method plane: a method cannot report done having skipped a rung below where it stopped.
- A generator gap found mid-task produces a discovered task, blocks the current task, and is landed on its own pull request before the original resumes.
- Drift found mid-task follows the same discipline and is never carried forward inside a feature branch.
- Every task and story carries a committed ores.shell scenario that a reviewer can re-run.
- A behaviour that cannot be scripted through the shell is recorded as a gap rather than waived.
- Qt verification runs only when the work affects Qt, through the mechanism settled by its own task.
- The ladder is exercised end to end on one real feature before the task closes.
