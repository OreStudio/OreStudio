* Plan

The task began with eighteen tenancy routes. On 2026-11-11 the sixteen that
need the roster, the setup state, a read inside another tenant or a
provisioning journey moved to [[id:169CA9EA-6515-45B6-9F9F-7385FCF53C98][Serve the tenant roster, setup and provisioning routes]],
so this task serves the two party reads.

- =GET /api/me/parties= joins the account screen routes in the IAM part: it is
  the caller's own read, answered as the BFF named each party.
- =GET /api/parties= is a new unit in the refdata part, =party_page_routes=. It
  refuses a system administration session, as the BFF did, because the system
  tenant's party policy reads every tenant's parties. It names each parent,
  reading parents on other pages in one call, and paints each row with its
  business centre's flag. A flag read that fails leaves the flags out.
- =party_page_routes::read_page= reads with the request's token, so the read
  inside a tenant can reuse it with a request that carries that tenant's token.
- Seven routes refused a failed operation by hand as the BFF did, a 409 named
  =invalid-request=. That rule is now =record_routes::require_done=, and the
  seven sites use it.
