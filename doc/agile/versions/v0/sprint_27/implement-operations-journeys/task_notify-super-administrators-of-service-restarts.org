* Goal

A super administrator learns that a service restarted without watching the
services screen. When telemetry records a =started= event for a service that
has run before, it raises a =service_restarted= notification through the
inbox to the system tenant's super administrators. The notification names the
service, the instance and the host, and says whether the previous instance
stopped gracefully or was lost.

* Acceptance

- A =service_restarted= notification kind is seeded, with its message in
  every locale the inbox carries.
- Telemetry raises it to the holders of =telemetry::samples:read= in the
  system tenant when a service starts after an earlier instance; the first
  start after a database is created raises nothing.
- The notification says whether the previous instance stopped gracefully or
  was lost, and links to the services screen.
- Raising never fails the event's storage: an unsuccessful raise is logged.
- A test proves a restart raises one notification and a first start raises
  none.

* Notes

Settled with the operator on 2026-10-06: super administrators only, for now.
A raise reaches the permission holders of the raiser's own tenant
(=ores_iam_current_tenant_id_fn()= in =notification_center.cpp=), and
telemetry acts in the system tenant, so its raise reaches the super
administrators. Telling each tenant's administrators would need the raise to
fan out across tenants, which the inbox does not do; that stays out of scope.

A service cannot announce its own restart, because the inbox and IAM may not
be up while it starts, so telemetry raises on the event it records.
