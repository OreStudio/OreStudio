* Acceptance

- Two members of one type get different values in sample(0) and in sample(1)
- The same-type-mixup mutation in the story's evidence/mutate.py fails the generated case
- Every suite still passes

* Plan

Number the samples. =sample<T>(n)= takes any number, and each leaf type
gives a different value for each number, keeping its values for 0 and 1. Member
j of a struct takes =sample_unlike(default, 2j)=, which is =sample(2j)= unless
that is the default, then =sample(2j + 1)=; the struct's second sample takes the
other of the two. A nested struct's number moves its members' numbers by a block
of twice its member count, so two members of one struct type differ too. A
vector or map at an even number holds the samples at that number and the next.

Integers stay inside their range and away from zero, so a narrow integer never
wraps to its default. bool, an enumeration, the error code and a type with only
two sample texts have fewer values than a struct can have members, so they
repeat. A date's year stays in 2000 to 2199, because an instant is built from
the date and the clock's nanosecond count holds only the years 1678 to 2261.
