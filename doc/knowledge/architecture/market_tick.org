* Summary

=market_tick= is the tick that a party receives for every asset class. It is
declared in =ores.marketdata.api/messaging/operations_protocol.hpp=. The
service builds it after mapping and storage. It is a different message from the
adapter tick: the adapter tick carries a vendor id, and the party tick carries
the internal item.

* Detail

** The fields

- =oresmd_uri= is the quote URI of the item observed.
- =value= is the observed value as decimal text, so the digits survive the trip.
- =observation_time= is the vendor time of the value.
- =provider= is the provider code of the series.
- =source= is the id of the source that produced the value. It is information
  for the party. A party can use it to find out that the source is simulated.
  No logic may depend on it. See [[id:F64DB34E-084D-4437-B536-392AA26D8B77][No code path may behave differently because a source is simulated]].

The tick carries no tenant and no party. The subject carries them.

** How the datum URI carries the asset identity

A URI such as
=oresmd://ir/USD?type=quote&instrument=ir_swap&quote=rate&fwd_start=0D&tenor=3M&term=5Y=
names the instrument type, the quote type and every coordinate field of the
datum. =oresmd_uri_codec::read= is strict, so a URI names exactly one datum or
is refused. See [[id:CE99CD2A-B31F-4306-865F-CBC519FBC1B8][The oresmd datum identity]].

** The subject

=market_tick_subject(tenant, party, oresmd_uri)= builds
=marketdata.v1.ops.market_tick.<tenant>.<party>.<token>=. See [[id:97208391-AE4B-4032-9744-8F8B228FD567][The adapter subjects]].
