#+title: A publish raise names one candidate version, in one transaction
#+description: The raise checks the party, the open requests and the live set, and writes the request and the subject naming the candidate's version in one transaction.

* Summary

A raise asks for one candidate version to become the live set of its series. It refuses a subject of another party, a second open request for the same subject and as-of, and a candidate older than the live set. The request and the subject record, which names the candidate's version, are written in one transaction, so no request ever names nothing and no subject record waits without a request. When a stated rule closes the request as it is raised, the raise applies it in the same call.

** What a raise refuses

| Refusal | Why |
|---------+-----|
| The subject belongs to another party | A party publishes only its own sets. The party is the session's, and the subject's party must match it. |
| No candidate exists for the subject and as-of | There is nothing to decide. |
| A request for the same subject and as-of is waiting or approved | One open request per subject, as [[id:0FE6BDD9-EB24-4B07-8B0C-D816AAF1BEBF][Approval requests]] states for every kind. |
| The candidate's as-of is older than the live set's | A publish never puts older data in place of newer. A correction is a newer as-of. |
| No reason is given | The decider reads a reason. |

** One transaction

The request, written by the inbox, and the subject record, written by market data, are one transaction, as [[id:E21DFC83-9F3F-45BE-AD3F-48262126DFAC][Four-eyes framework]] states for every raise. The raise reads the approval kind and the approvals mode before it opens that transaction, under the tenant and with no party restriction, because a transaction's tenant and parties are fixed when it opens ([[id:31F9FEF5-4693-4C63-AE93-E74BA88DE175][A context bound to a transaction cannot change its tenant or party]]).

** When a rule closes the request

If [[id:71146F3F-B884-4E61-BA8B-A8A0731703C6][A request closes without a person only under a stated rule]] closes the request as it is raised, the raise goes on to the apply in the same call, so a trader who needs no decider publishes in one act. The apply makes every check it makes for a person's approval.
