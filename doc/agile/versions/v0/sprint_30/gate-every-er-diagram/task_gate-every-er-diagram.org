* Acceptance

- The check compares every generated group file and the index, discovered from the model rather than a hard-coded list.
- Adding a package or a table without regenerating turns the check red.
- The check runs where the current one does and costs no more than a few seconds.

* Plan

- Ground first. Since adc5954e60 (2026-10-09) the generator renders one file
  per package of the model and the index, and =--check= compares every render.
  The local gate, the CI step in =codegen-drift.yml= and
  =plantuml_er_generate.sh= all pass =--index-template=, so all three compare
  every group. Acceptance 1 and 2 already held; prove them rather than redo them.
- One gap is left: a renamed or removed package leaves its old file beside
  the index. Nothing renders it, so the check never sees it, and the wrapper
  still draws it. =orphan_group_files= finds such files; =--check= fails on
  them, and a regeneration removes them and their drawing, so regenerating
  clears the check.
