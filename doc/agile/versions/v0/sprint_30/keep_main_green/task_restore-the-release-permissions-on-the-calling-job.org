* Result

Two separate faults, both introduced by the composite refactor, and both found
by dispatching Continuous Linux on the branch rather than by waiting for the
nightly.

The first refused the whole workflow at start: a called workflow can only
downgrade the token its caller passes, so the three that attach a package have
to grant =contents: write= and =actions: read= themselves. Without the grant the
run reported =startup_failure= with no jobs at all, which is the same symptom a
malformed file gives.

The second was the guard. Its checkout lived inside the action, and a local
action is read from the workspace: the job failed with "Can't find 'action.yml'
... Did you forget to run actions/checkout before running your local action?".
The checkout moved to the caller, and then a second dispatch failed the same way,
because the conditional checkout was skipped on a dispatch and an empty
workspace is an unreadable action. It is now unconditional, and a wasted shallow
clone on a manual or tag run is the price.

The CI YAML check learned both lessons: a job that calls a local action must
check out, and must not check out under a condition.

Evidence: run 46135042813, dispatched on the branch after the second fix, reports
=relevance-guard= and =ci-image-ref= green and both Linux legs running.
