* Plan

One model declares one area, and the generator writes everything that follows from it: the
route unit and its header, the route tests, the recipe page, and the ten hurl scripts tangled
from the recipe. Nothing is edited by hand except the two classification rules that decide
the path, because the decisions live outside the generator.

The move was kept to one entity on purpose. It is the first URL this project has moved, so
the whole chain is exercised once before it is repeated eleven times for the rest of the
generated collections.

* Notes

- The build of =ores.http.refdata.tests= was started and did not finish inside fifty
  minutes, and it was cancelled. What stands in its place is weaker than a run: the generated
  test file carries the new path 20 times and the old path none, and the change to the
  compiled unit is the same string literal in a route registration. A stale binary from
  before the move would test the old paths, so it was not run either.
- The tangle gate fails on an uncommitted tree by construction, because it compares the
  recipe with the committed scripts. It passes once the change is committed.
- The design's route-table sample named the old path. It now names the new one, so the plan
  does not teach a URL the tree no longer answers.

* Result

The currency collection answers on =/api/v1/reference-data/currencies=. Ten routes, ten hurl
scripts, the generated tests, the recipe page and the inventory all state that path, and no
source in the tree names the old one. The chain works, and the remaining generated
collections can follow it one component at a time.
