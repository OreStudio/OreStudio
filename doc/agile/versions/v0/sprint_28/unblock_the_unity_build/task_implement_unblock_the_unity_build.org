* Notes

** Why an anonymous namespace did not help

Five of the six files already wrapped the value in an anonymous namespace
and one defined it directly. A unity build concatenates the files into a
single translation unit, which merges every unnamed namespace into one, so
the same name is then declared repeatedly in one namespace. Internal
linkage is no protection.

** Why a public header

The value is one concept shared by six sibling files, so it belongs in one
place. It sits in the component's public include tree with the rest of the
process layer, and every consumer that includes the header gets it.

** Why inline const and not inline constexpr

The house style for public constants is =inline constexpr=, but
=std::sqrt= is not =constexpr= in this toolchain: clang reports
=non-constexpr function 'sqrt' cannot be used in a constant expression=.
=inline const= keeps one definition and leaves the derivation readable
rather than hard-coding =2^-26=.
