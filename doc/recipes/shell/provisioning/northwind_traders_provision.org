#+title: How do I provision a second tenant with Northwind Traders?
#+description: Provision the Northwind Traders demonstration tenant after ACME, from the shell, with its own party, organisation, staff and reports.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:provisioning:northwind:
#+created: 2026-10-24
#+updated: 2026-10-24

Northwind Traders is the second demonstration tenant: a fictional UK trading
company built from the classic Northwind Traders sample. It exists so the
system can be exercised with more than one tenant — the grid's per-tenant
attribution, the scheduler's per-tenant work, and any screen whose answer must
not leak across tenants — without a second ACME-sized dataset.

It is deliberately lighter than
[[id:45B89A49-B2B8-4C1C-9BB7-09EB27E4D50C][Acme Corporation]]: one legal
entity, one party, nine staff, six portfolios and seven books. Unlike ACME it
carries its own report configuration documents, so its reports are configured
with the documents they read and not only defined. The =ores-shell= block below is tangled into the runnable
script library as =northwind_traders_provision.ores=.

* Question

How do I add a second, ready-to-run tenant to a system that already holds ACME?

* Answer

Log in as =super_admin=, provision =northwind= from the =northwind= starting
point, then log in as its administrator and set the party the account works in.
The starting point's own steps do the rest server-side: they publish the firm's
counterparties and reference data, import its synthetic legal entity, provision
the party, load the nine staff, set their password, and generate two bond
populations. =load='s stop-on-error semantics guarantee an error-free run ends
fully provisioned.

Expectations: the services are up (=compass services start=), the database is
fresh (=compass db recreate -y -k=), and ACME is already provisioned — this
script runs the tenant stage only, so it needs the system's first administrator
and the system tenant's data.

The tenant details are passed explicitly rather than read from the profile,
because the shell sends what it is given: the browser's form is prefilled from
the profile, the shell is not. The values match the profile's own prefill.

=connect= takes the endpoint from =$ORES_NATS_URL= and inherits the subject
prefix and TLS context the shell was started with.

** Which company the data is

The nine staff accounts, their addresses, phone numbers, cities and reporting
line come from the sample's =Employees= table, vendored under
=projects/ores.seeder/datasets/northwind_traders/source/=. The party countries
come from the countries the sample's customers and suppliers trade from.

The company's own details are Northwind's. The sample has no registered office,
so the London office its London staff work from is the company's own address.
Its LEI is synthetic: =9695NORTHWIND0000065=, checksum-valid on the test prefix
ACME uses, because a fictional company has no entry in the public register.

The business units, portfolios and books are Northwind's own, because the
sample's food categories do not describe an ORE book. The books are named for
what ORE's trade population writes into them.

** Running it again

The tenant stage refuses a tenant code it already holds, so a second run
against the same database fails before it creates anything. Reset the database
(=compass db recreate -y -k=), provision ACME, then run this script again.

#+name: northwind-traders-provision
#+begin_src ores-shell :exports none
connect $ORES_NATS_URL

login super_admin Secure-Password-123
provision tenant --tenant-code northwind --tenant-name "Northwind Traders" --tenant-hostname northwind --tenant-admin-email admin@northwind --tenant-admin-password Secure-Password-123 --profile northwind
logout

login tenant_admin@northwind Secure-Password-123
accounts set-default-party "Northwind Traders Ltd"
logout

exit
#+end_src

Run it from a connected shell, or load the generated script:

#+begin_src sh :noweb yes :results output :wrap example
./ores.shell ${log_args} ${connect_args} << 'EOF'
<<northwind-traders-provision>>
EOF
#+end_src

* Tested by

Manual: =compass shell -f northwind_traders_provision.ores= against a freshly
recreated database with ACME present. Proven on 2026-10-24 against
=brave_hopper=: the tenant run completed all seven steps, =Northwind Traders
Ltd= came out active under the synthetic LEI =9695NORTHWIND0000065=, and the
party carried 6 business units, 6 portfolios, 7 books, 9 staff with their
manager chain from the sample, 24 report definitions each bound to all six
configuration documents, and 16 generated bonds.

The tenant's own run is the child run the parent hands its work to, so a caller
that cannot read the parent's progress read sees the command report a timeout
and abort the script while the tenant's setup carries on. Reconnect and follow
the child instance the parent's step result names; it is the run that ends with
the tenant =active=.
