* Result

The story's three loose ends are tied, and the corpus walk is the acceptance
rather than a thing nobody ran.

- The walk is promoted out of =[.corpus-full]= and runs by default. It takes
  about thirty minutes, which is why it was hidden; hiding it also hid the
  acceptance, so a change that broke the walk could merge green. The scheduled
  =continuous-linux= job carries the cost.
- Its suite runs alone (=RUN_SERIAL=). Promotion put a half-hour,
  database-heavy suite beside every other suite in a parallel run, and that was
  enough to lose a race in =report_definition_eventing_integration_tests=: the
  test asserts its version history is unchanged immediately after a delete,
  while the service's notification re-drive can still be writing. The check is
  green in the serialized set and red in the parallel one, which is a defect in
  that generated test rather than in the walk; the serialization keeps the
  default set honest until the assertion is fixed.
- The record describes the grammar that ships: =market_data_urn.org= was rewritten
  in the generation unit, and the codegen coordinate gate checks the new spelling
  rather than the retired =point= bag.
- =todaysmarket.xml= is recorded as =ores.refdata='s beside =curveconfig.xml=, with
  the rule that decides it (a document that names curves is reference data; a
  document that configures an analytic's market is =ores.analytics=; a run
  document is =ores.reporting=). The story's Decisions section carries it, and
  =report_market_binding='s comment no longer calls the file market data that
  belongs to another component.

Verified by the previous unit's run: the walk green, all 89 ctest suites green,
and the database rebuilt from the branch.
