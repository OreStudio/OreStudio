#+title: Every generated NATS handler says its reads check the permission a write needs
#+description: cpp_nats_handler.hpp.mustache carries one comment above every handler it emits: 'The adapter decides nothing: it proves the request, checks the permission a write needs, decodes the canonical request, calls the service and replies with the response the service filled.' The sentence is written once and emitted for every verb, so a read verb's comment claims a write permission and a delete verb's claims a write too. The generated handlers for ores.iam.sessions are the concrete example: list, get and get_many are now guarded with iam::sessions:read, and all seven verbs carry the same comment. The fix belongs in the template, not in one generated file, and the template is itself tangled from its org source, so the change has to be made there. Raised during the review of PR #2465, where the same rewording had been applied by hand to one generated file and was reverted by regeneration.
