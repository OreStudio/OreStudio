* Goal

The recorded spot series of every fixing-sourced feed is continuous from its first tick. A seeded system route no longer starts a feed the moment its adapter is accepted: each asset class carries a release state, and the synthetic adapters of a class that is not released do not announce, so no demand reaches them. Releasing a class is an explicit act, recorded with who and when: an operator's "Start feeds" on the Calibration screen, or the release step a provisioning profile orders. A feed of a released class starts from the level its last calibration stored.

* Acceptance

- On a fresh installation, no synthetic feed publishes a tick before its class is released.
- Releasing a class starts its demanded feeds, and each fixing-sourced feed records a start from its fixing whose first stored spot is within the feed's spread of that fixing.
- The release is recorded with who released the class and when, and the Calibration screen shows each class's release state.
- The calibration workflow note and the provisioning documentation state the order: load the public rates, calibrate, approve, release.
