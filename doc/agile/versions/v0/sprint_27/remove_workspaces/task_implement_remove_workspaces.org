This page documents a [[id:31C868B9-306E-4282-BA8C-07E647021B34][task]] in the [[id:8421A419-0311-4CC8-9384-D1097477813F][Remove workspaces from every component]] story. It captures the goal, current status, acceptance, and any notes or results.

* Goal

No component carries a workspace: no table has a workspace_id, no request or session carries a workspace context, and ores.workspace is gone. Sandboxes and virtual books, which replaced workspaces in the trade shape design, are the only way to keep work apart from official data.

* Acceptance

- No codegen profile or model sets has_workspace_id, and no generated or hand-written table has a workspace_id column.
- No request context, NATS header, session or database setting carries a workspace; ores_utility_live_workspace_id_fn and its kin are gone.
- The ores.workspace component, its tables, protocol, shell and web surfaces are removed, with no references left.
- Every component builds and its tests pass after each step; main is never half migrated.
- The trading part is done by the trade shape story, Split the trade into an anchor and its components; this story covers the rest.

* Plan

Measure the tree with a script a reviewer can rerun, check who still
selects a workspace other than Live, and turn the story's proposed
sequence into tasks. Settle the story it conflicts with,
[[id:603F4845-B4A0-41EB-ACF9-B0FC1387E1C4][Workspaces: finish the feature]].

The order follows one rule: a column goes before the function that
defaults or validates it. =ores_utility_live_workspace_id_fn= is the
default and =ores_workspace_validate_fn= the insert check of every
=workspace_id= column, so the columns go first and the component, which
owns those functions, goes last.

1. [[id:96B95473-3D50-4FF7-9584-FB65BB3C967A][Drop the workspace column from every entity]]. Models,
   profiles, SQL, repositories, generated TypeScript, and the hand-written
   resolution code in refdata, analytics, reporting and marketdata.
2. [[id:21D83315-FD24-423E-9882-A9067CB38582][Remove the workspace from the request context]]. Database
   context, NATS headers and client, service request context, ores.web
   client. Needs step 1, because the generated repositories read the
   context's workspace.
3. [[id:2E4E86B0-D873-492A-8048-56DC1A396163][Remove the has_workspace_id feature from codegen]]. Needs
   step 1, so that no model still sets the feature.
4. [[id:8826DA01-FF39-4DDE-B3BB-3768ABEF691E][Remove the ores.workspace component]]. Needs steps 1 and 2:
   the component owns the column functions and the header the context
   reads.

* Notes

Points from the review of the scaffold (PR 2615) for this task to settle:

- Confirm that nothing still relies on workspaces to keep work apart from
  official data, so sandboxes and virtual books are the only way.
- Order the steps so no default, policy or index still calls
  =ores_utility_live_workspace_id_fn= or its kin while a column exists:
  columns go before the functions.
- Record the command and commit behind every inventory count in the
  Measurements section; the trading counts fall as the trade shape story
  lands.

Settled while measuring:

- Nothing keeps work apart with workspaces. No surface selects a workspace
  other than Live: ores.web defines =setWorkspace= and never calls it, no
  service calls =with_workspace_id= or =with_workspace_resolution=, and the
  Qt client that did is gone. Every row a service writes lands in Live,
  so dropping the column loses no data a user can see.
- The trading part is done: PR #2620 removed the workspace from every
  trading entity, so the story waits on nothing. Two trading class
  diagrams still show =workspace_id= members; step 4 sweeps them.
- The five =ores.dsh_kanban= hits are test fixtures that quote old task
  documents, and the GitHub workflow, npm and session hits use the word
  in another sense. They stay.
