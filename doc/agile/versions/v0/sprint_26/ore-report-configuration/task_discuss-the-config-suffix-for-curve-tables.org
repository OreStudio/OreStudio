* Goal

Decide with the operator whether the curve configuration tables take a _config suffix. A row holds the recipe for building a curve, never the curve's data, but names such as yield_curve, fx_volatility and curve_definition read as if they held data.

* Notes

Raised by the operator during step 4b of
[[id:E13E6DCD-0C54-4476-AA0C-18F2E2C8622B][Round trip the curve configuration]]: a curve has data, a curve
configuration has only the shape of that data, and the table names should not
blur the two. The operator asked for this conversation to wait until the curve
configuration work reaches it, so it sits last in the story.

Tables to cover, as of step 4a: =curve_definition=, =yield_curve=,
=equity_curve=, =default_curve=, =inflation_curve=, =commodity_curve=,
=intraday_power_curve=, =curve_security=, =fx_volatility=, =yield_volatility=,
=base_correlation=, =curve_correlation=, and the step 4b to 4d tables. The
lookups (=curve_segment_type=, =day_counter=, =curve_section=) and
=curve_configuration= itself already say what they are.
