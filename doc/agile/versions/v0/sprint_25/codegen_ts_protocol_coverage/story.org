#+title: Story: Generate every protocol message as TypeScript
#+description: Every drift-free component renders its protocol messages to generated C++ headers from the org models, but the TypeScript twin exists for six IAM protocols only. The other components have no TypeScript messages at all, and five IAM protocols switch the TypeScript facet off because their fields reference C++ domain types with no TypeScript projection. This story closes the gap so every message that renders to C++ also renders to TypeScript, one message type per header.

* Goal

Bind every protocol message model to the TypeScript facet and extend the projection until it renders, so a message exists in both targets or not at all. A check proves the two targets stay in step, and the generated tree regenerates with no diff.

* Acceptance

- Every generated protocol header has a TypeScript twin, and a check fails when one is missing.
- Each message type has its own header and its own model, so adding a message does not touch the others.
- No IAM protocol switches the TypeScript facet off.
- The generated tree regenerates with no diff, and ores.web typechecks with its suites passing.
