* Goal

A history provider finds a row by its whole key, so one party's contact never shows another party's history.

Find a row by its whole key in a history provider. A provider reads the newest row that carries the first column of the model's key, and a contact's key is the party and the contact type. Every Acme party has the four contact types, so the history of one party's Legal contact is another party's. The same holds for an identifier read by its value and a business unit read by its code.

Evidence: in the Acme tenant each of the four contact types is held by four parties, and the party timeline drops the versions of every contact that is not the newest row, and says part of the history could not be read.

* Acceptance

- A history provider finds a row by its whole key, so the history of one party's contact is never another party's.
- A link table has a history read, a history provider and a field mapper from its model, and a closed link is still in its history.
- The party timeline shows the opening and closing of a country, a currency and a counterparty link, and states no gap for them.
- The same holds for any entity with a composite key or a link, not only parties.

* Plan

Decision: a row whose declared key other rows share is addressed in the generic
history by its own =id=. A composite string such as =party/type= is not used,
because the addressing page rules out joining a pair into one address. The id is
one row whatever the scope, and every such model already has a read by id.

1. Codegen derives =history_by_row_id= for a model with a declared key that is
   not the storage key, a natural key beyond it and =tenant_id=, and a uuid
   storage key.
2. The history provider template reads by =boost::lexical_cast<uuid>(entity_id)=
   for such a model.
3. Regenerate the ten models the flag selects.
4. The party timeline reads an identifier, a contact and a business unit by the
   row's id, and no longer filters or states a gap for another party's row.

* Result

A history provider no longer finds a row by a key that other rows share.

- Codegen derives =history_by_row_id= for a model whose declared key is not the storage key, with a further natural key and a uuid storage key. The provider of such a model reads by the row's own id.
- Ten models are affected: party and counterparty contacts, party, counterparty and netting set identifiers, business units, portfolios, portfolio rights, CSA eligible currencies and run grants.
- The party timeline reads its identifiers, contacts and business units by row id. It no longer filters by id and no longer states a gap for another party's row. The product owner saw the contact versions and no gap note in the browser.
- Link tables were already covered by the link history task: they read by the parent, and each version names its link as =parent/child=.
- The UX specification and the entity addressing page state both rules.

Not done: the generic shell =history= command now needs the row id for these ten entities, and a stale key returns the dispatcher's error text (bad lexical cast) with no clearer message.
