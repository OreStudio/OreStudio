* Goal

The site page check publishes only the pages the branch changed, instead of
every page whose source mtime beats its published HTML, and it finishes in
seconds whether or not the site cache is warm.

* Acceptance

- The site page check publishes only the pages the branch changed.
- The org-id map is refreshed first, so a link to a page the branch added resolves.

* Plan

Select the pages from the diff against the base rather than from file
mtimes: a fresh checkout gives every source a new mtime, so the mtime rule
republishes the whole corpus whatever the branch touched. =compass site
page= already takes the files to publish, so pass them. Let it rebuild the
org-id map every time: the scan costs seconds, and skipping it behind
=--no-index= turns a stale map into a false failure on the first link to a
page added since the last scan -- which is exactly what happened while
developing this.
