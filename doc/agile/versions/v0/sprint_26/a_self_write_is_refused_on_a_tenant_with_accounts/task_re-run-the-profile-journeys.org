* Plan

1. Recreate the database from the regenerated scripts.
2. Bootstrap the deployment through the shell's =bootstrap
   create-initial-admin=: the initial administrator is what clears
   =system.bootstrap_mode= and lets the BFF's sign-in route answer.
3. Seed the two members with the checker's own prerequisites, audited
   by the shell service account, the member carrying the *Viewer* role.
4. Run the journeys checker and read every failure.
5. Record the run as evidence under the story, close the two journey
   gaps, and close the task.

The order is the whole plan, and the first two attempts are what made
it explicit: the bootstrap expects a system tenant with no current
accounts, so it must precede the seeds, and the sign-in is refused
while bootstrap mode is on, so it must precede the check. The cycle is
recreate, bootstrap, seed, check.
