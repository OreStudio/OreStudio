* Goal

A tenant can run without waiting on approvals, and anyone can see that it does. A recorded per-tenant switch, optionally limited to some approval kinds, closes raises without a person. Provisioning turns it on. The profile says whether it stays on afterwards, so a demonstration can keep it and a normal tenant returns to maker-checker. Nothing about it is hidden from a person troubleshooting.

* Acceptance

- Turning the switch on or off is a versioned record of who, when, why and which kinds, and needs a permission of its own.
- A raise in a tenant with the switch on closes at once, and the request names the rule that closed it and the switch version.
- A raise after the switch goes off waits for a person, with no restart.
- A provisioning profile decides whether the switch stays on when provisioning ends, and the provisioning result says which.
- While the switch is on, the approvals screen and the curve publish screens show it, with who set it and when.
- A request or published set closed by the switch reads as auto-approved wherever it is shown, and the approvals screen filters by it.
- A person whose publish did not wait, or waited, can see why from the request alone.
