* Acceptance

- =fx_barrier_option_instrument= states which barrier levels the =barrier_type= engages, and a check refuses a row that fills a level its type does not use.
- =fx_digital_option_instrument= states the same for =strike=, =lower_barrier= and =upper_barrier=, or records why no discriminator is possible.
- =fx_vanilla_option_instrument= names one closed exercise-style set in its prose and admits the same set in its check. Bermuda is either admitted by both or refused by both, with the reason recorded.
- The four closed vocabularies that are stated in a table and in a check are kept equal by a mechanism, or the duplicate is removed and the reason recorded.

* Decisions

- *The exercise style admits Bermuda.* ORE's =exerciseStyle= is the closed set
  European, Bermudan and American, the lookup already seeds all three, and the
  model's prose states all three, so the check is the one that is wrong. The
  check widens to admit =Bermudan= and the prose states the set once.
- *The lookup table is the single statement of each closed vocabulary.* Five
  vocabularies (=long_short=, =option_type=, =barrier_type=, =exercise_style=,
  =moment_type=) are stated in a lookup and again in the table's check. The
  foreign-key unit keyed every one of them to its lookup, so the check is the
  copy that goes; the lookup is what a reader edits and what the store
  enforces.
- *A single barrier's level sits in the column its direction names.* An
  =Up...= or =FixingCap= style engages the upper level, a =Down...= or
  =FixingFloor= style the lower one, and the other column stays null. The two
  columns are positional today: the mapper writes the document's first level
  into =lower_barrier= whatever the style, so an =UpAndOut= option cannot be
  stated without inventing a lower level.
- *A product that states two levels is the exception, and its trade type says
  so.* A double or generic barrier holds a level per side, so the directional
  check applies to =trade_type_code = 'FxBarrierOption'= alone; the double and
  generic codes require the two levels they read.
- *The digital option keys its levels on the trade type.* =FxDigitalOption=
  states a strike and no barrier, =FxTouchOption= one barrier and no strike,
  =FxDoubleTouchOption= both barriers and no strike, and
  =FxDigitalBarrierOption= a strike and a barrier. The table is shared by the
  four codes, so the check reads =trade_type_code=.

* Plan

The analysis found these disagreements between prose, check and mapper:

| Model | Prose says | The check admits | The mapper writes |
|-------+------------+------------------+-------------------|
| vanilla option | European or American, then the closed ORE set of three | European, American | the document's value |
| barrier option | the style names the direction | any of the ten styles with any level | the first level into =lower_barrier= whatever the style |
| digital option | the four codes state different fields | nothing about levels | one level into =lower_barrier= |

1. Widen the vanilla check to the three ORE styles and state the set once.
2. Delete the five =in (...)= checks whose vocabulary is now a lookup.
3. Make =lower_barrier= nullable, add the directional checks keyed on
   =trade_type_code=, and place the document's level by direction in
   =fill_barrier= and in the two hand-written forward functions.
4. Add the digital option's type-keyed checks.
5. Regenerate, recreate the database, and update the barrier repository test
   that writes =UpAndIn= with a lower level.
6. Add a case per decision that refuses the shape it should refuse.

* Result

The three findings are settled and the tree enforces each one.

The duplicated vocabularies are gone. Ten =in (...)= checks named a set the
lookup table now validates, so the checks were the second copy and are removed.
The vanilla option's check was one of them, which settles the exercise style:
the lookup holds European, Bermudan and American, so the store admits all three
and the prose states that set once instead of contradicting it.

The barrier option now states which level its style engages. A single
=FxBarrierOption= with an Up style or a cap holds its level in =upper_barrier=
and leaves =lower_barrier= null; a Down style or a floor does the reverse; the
styles that name no direction state one of the two. =lower_barrier= became
nullable for that reason, and the mapper places the document's level by
direction instead of by position, so an UpAndOut option no longer needs a lower
level invented for it. A double or generic barrier holds a level per side and
is exempt, because its trade type says so.

The digital option keys its checks on the trade type. Each of its four codes
states the fields it engages: a plain digital a strike, a touch one barrier, a
double touch both barriers, and a digital barrier a strike and a barrier. The
checks require those fields and tolerate another code's, because one table
serves four products and one generator writes a synthetic row for all four, so
a check that refused the others would refuse the only row the generator can
write.
