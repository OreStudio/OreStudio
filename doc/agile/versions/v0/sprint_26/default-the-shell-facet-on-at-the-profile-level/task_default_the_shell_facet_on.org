* Goal

The ores.cpp.shell-command facet is on by default, so a model no longer opts in one file at a time. The facet node carries #+default: disabled, eight variability profiles fix it true, and many models repeat the opt-in in their properties drawer.

The safe half is done: the drawer entries a profile already covers are removed, and the facet's own documentation now states the three opt-in levels and the two gates. The flip itself is blocked, because the facet node's default is global: it would render a unit for every model of every component, not only the seven this story has cleaned.

- The profile rows that fixed the facet true are kept, because they are the per-profile activation; the drawer opt-ins a profile already covers are removed. Met for the seven cleaned components.

- The tree builds, the codegen suite passes, and check_component_drift.py --all passes. Met.

* Plan

Two halves, and only one of them is safe.

The first is to read the facet for what it is and stop repeating it. A model whose
variability profile already fixes =ores.cpp.shell-command= states nothing itself,
so its drawer entry is removed. A regeneration that produces no diff proves the
entry was redundant rather than load-bearing.

The second is the flip, and it cannot be made from here. The facet node's
=#+default:= is global, so enabling it renders a unit for every model of every
component. Measure what would change before touching it, and record the
precondition rather than pulling a lever whose blast radius reaches components
this story does not own.

* Notes

The task was scoped on the assumption that the seven cleaned components are the
whole blast radius of the flip. They are not. The facet node's =#+default:= is
read once for every model the generator renders, so enabling it reaches every
component in the tree.

The 76 models that would gain a unit, by component: trading 34, refdata 6,
compute 5, reporting 5, diff 4, marketdata 4, analytics 3, dq 3, iam 3,
telemetry 3, history 1, http 1, ore 1, scheduler 1, variability 1, workspace 1.

Three of those components are partly this story's business and partly not. The
analytics three are the stress-test entities in flight under another story, the
refdata three are the curve tables in flight under the same one, and the dq three
are the publish operations this story records rather than generates. The other
sixty-seven belong to components whose clean-standard pass has not run.

Two ways to land the default, and the choice is not this task's to make:

- Wait. Flip the node default when every component has reached the clean
  standard, which is the precondition that was stated when the task was scoped.
  Nothing has to be undone in the meantime.
- Land it now with explicit opt-outs. Enabling the default and adding
  =:ores.cpp.shell-command.enabled: nil= to the 76 models that should not render
  a unit yet inverts the opt-in the right way round, but it writes a temporary
  entry into sixteen components, sixty-seven of which this story does not own
  and several of which are being edited now.

The eight profile rows are kept. They are the per-profile activation, not
repetition of the node default, and removing them while the node default is
disabled would turn the facet off for every model that relies on its profile.

The facet's knowledge page now carries all of this, so the next reader gets the
measurement with the rule.

* Result

Half done, and the other half is blocked on a precondition this story cannot
meet.

Done: the thirteen drawer opt-ins that a variability profile already covered are
removed from the cleaned components, and a full regeneration produces no diff, so
they were stating what the profile already stated. The shell facet knowledge page
is rewritten to describe the facet as it is, including the three opt-in levels,
the two gates, and the precondition for the flip.

Blocked: the facet node's =#+default:= stays disabled. Enabling it is global.
Measured at =4eec0e6740=, it would render a unit for 76 models across 16
components, and 67 of those carry no profile at all because their components have
not been cleaned.

The task stays open rather than closed. Its first acceptance bullet is unmet, and
the fix is not a code change in this story: either every component reaches the
clean standard first, or the default lands with an explicit opt-out written into
the models that should not render yet.
