* Plan

The web already draws a calendars screen, so the prototype is not a blank
sheet: it draws the same screens where the standard settles them, moves what
the owner decided (Rebuild into the header, as an operation dialog), adds what
the baseline found missing (Refresh with its load time on the page, the dialog
titles and load times, the Read only mark), and defines the one view no rule
covers, the Business days. Plain HTML, CSS and JavaScript under
=doc/prototypes/calendars/=, as the prototypes page requires, with the query
string as the state so every screen, dialog and reader view has an address a
reviewer can open. The data is the Acme seed for the 61 QuantLib calendars and
three invented user calendars, with the rule engine in the page so the
Business days view is computed and not drawn by hand. The design note cites
the rule identifiers each screen follows, so the review is about the topic.
