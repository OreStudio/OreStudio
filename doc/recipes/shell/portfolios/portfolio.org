#+title: How do I run the portfolios commands from the shell?
#+description: Every command the portfolios submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:portfolios:

This file documents the portfolios resource at the shell, one section per command. Every command is a subcommand of =portfolios=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: D730DD65-951C-54FC-9890-F8EF12E66D8E
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
portfolios list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.portfolios.list=.

#+name: portfolios-list
#+begin_src ores-shell :tangle portfolios-list.ores :exports none
portfolios list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 8CA41926-2EBF-53D3-80EB-BAB6B1966060

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.

** =add=
:PROPERTIES:
:ID: E5329E05-BB8F-596C-9A35-A78FE3CB6EA5
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
portfolios add <id> <name> <description> <parent_portfolio_id> <owner_unit_id> <purpose_type> <aggregation_ccy> <is_virtual> <status> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.portfolios.put=.

** =set=
:PROPERTIES:
:ID: A5D9176C-80E9-5E4F-927D-4575493A8571
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
portfolios set <id> <name> <description> <parent_portfolio_id> <owner_unit_id> <purpose_type> <aggregation_ccy> <is_virtual> <status> <reason> <commentary> [--version <n>]
#+end_example
