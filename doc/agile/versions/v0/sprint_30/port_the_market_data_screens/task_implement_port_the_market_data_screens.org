* Goal

Hedgr prototyped five market-data screens for its own terminal. ORE Studio has no instrument search, no rate ladder and no FX spot montage, and reads a curve and a surface only as a candidate or a publish record. This story brings the five screens into doc/prototypes/market_data, adds the journeys they answer, and adds the server operations the screens read, so both clients draw the same facts and neither derives an identity, an axis order or a staleness verdict.

* Acceptance

- Every hedgr market-data screen is either prototyped in ORE Studio or shown to be covered by an existing journey
- Every new screen has a journey that names its steps, entities and missing reads
- The server states instrument identity, ladder maturity dates, curve analytics, the FX montage, the surface metadata and the staleness verdict

* Plan

Prototypes first, judged screen by screen against hedgr's, then the journeys
they answer, then the server reads those journeys named as missing. Each read
was stated in the protocol model before it was served, and each was built
behind a test that writes its own market rather than depending on a seeded one.
The machinery the screens read already existed, so no quant work was needed:
the bootstrap, the day counts, the forward the surface is struck against and
the grid all had implementations. What remained was presentation and the four
decisions the story records.
