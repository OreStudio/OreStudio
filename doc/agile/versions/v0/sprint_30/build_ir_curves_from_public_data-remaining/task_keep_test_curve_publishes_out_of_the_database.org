* Acceptance

- The integration tests that publish curves write into a tenant of their own, or roll back, and leave no curve publish in a provisioned tenant.
- A provisioned environment holds no curve publish after a full ctest run that it did not hold before.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

The claim was measured before any code changed: curve publishes already
carry the suite tenant, not Acme. The evidence:

- =scoped_database_helper= provisions one tenant per test binary and stamps
  every row with it; =curve_publish_gate= writes =record.tenant_id = ctx.tenant_id()=.
- Acme's 320 publishes are =tenant_admin= rows at the provisioning as-of with
  =system.curve_published=; no test user and no =system.test= reason.
- =system.test= curve publishes anywhere: 0.

The one shared-state breach the tests do cause is elsewhere: the two
zero-approval fixtures write =every_request= into the *system* tenant's
approval kind and restore it by appending a version. An aborted run leaves
=every_request= open, which would approve every tenant's curve publish. So:

1. Make each zero-approval fixture restore the seeded rule before it reads it:
   a kind still carrying =system.test= with another code is put back to
   =system_tenant= first.
2. Prove it: run the marketdata service suite and read the counts before and
   after. Acme's publishes and the =system.test= publishes must not move, and
   the live rule must read =system_tenant=.
3. Capture what is left: the suite tenant is only terminated, not purged, and
   the pre-run sweep that would clean it is never called.

Out of scope: a per-test rollback (a large refactor) and purging the suite
tenant at teardown (captured).

* Result

Met, with the claim corrected. The integration tests do not publish into a
provisioned tenant: the suite helper gives each test binary its own tenant, and
curve publishes take their tenant from the context. Acme's publishes are the
provisioning's own, by =tenant_admin=; a full marketdata suite run left the
count at 320 and wrote no =system.test= publish.

The real shared-state breach was the zero-approval approval-kind swap. Both
fixtures now put the seeded =system_tenant= rule back before reading it, so a
run that aborted mid-test cannot leave =every_request= open and auto-approve
every tenant's publishes. After the suite the live rule reads =system_tenant=.

Captured, not done here: the suite tenant is terminated rather than purged, so
its rows and the tenant row remain; the pre-run sweep that would clean them has
no caller.

Limitations:

- The fixtures still append one version per run (restoring the seeded row), so
  the kind's history grows with a row that carries the seed's reason.
- The curve publishes that remain under terminated suite tenants are not
  removed; the capture states the purge.
- No manual QA scenario; the suite and the SQL counts are the evidence. The
  acceptance's second clause asks for a full ctest run; only the marketdata
  service suite was run.
