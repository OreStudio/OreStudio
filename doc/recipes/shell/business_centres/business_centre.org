#+title: How do I run the business_centres commands from the shell?
#+description: Every command the business_centres submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:business_centres:

This file documents the business_centres resource at the shell, one section per command. Every command is a subcommand of =business_centres=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 4C58E834-3A71-57D2-8D76-60D84E8F79C8
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
business_centres list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.business_centres.list=.

#+name: business_centres-list
#+begin_src ores-shell :tangle business_centres-list.ores :exports none
business_centres list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 893BCE19-48BF-5500-827A-41683285AFA1
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

It is addressed at =refdata.v1.business_centres.get=.

#+name: business_centres-get
#+begin_src ores-shell :tangle business_centres-get.ores :exports none

#+end_src

** =add=
:PROPERTIES:
:ID: BB1B96B7-B99A-521F-8E73-6305F1DAF317
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
business_centres add <code> <source> <description> <city_name> <country_alpha2_code> <coding_scheme_code> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.business_centres.put=.

#+name: business_centres-add
#+begin_src ores-shell :tangle business_centres-add.ores :exports none
business_centres add __none__ __none__ __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: D272C926-7629-57C1-B81B-C75E7A1D3D8C
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
business_centres set <code> <source> <description> <city_name> <country_alpha2_code> <coding_scheme_code> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.business_centres.put=.

#+name: business_centres-set
#+begin_src ores-shell :tangle business_centres-set.ores :exports none
