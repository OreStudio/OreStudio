#+title: How do I run the business_units commands from the shell?
#+description: Every command the business_units submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:business_units:

This file documents the business_units resource at the shell, one section per command. Every command is a subcommand of =business_units=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 4650B7D2-CD82-5C71-89CA-6D687447A6B7
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
business_units list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.business_units.list=.

#+name: business_units-list
#+begin_src ores-shell :tangle business_units-list.ores :exports none
business_units list --limit 1
#+end_src

:PROPERTIES:
:ID: 2B5E014B-C28C-55AF-8C29-11C345370847

** =add=
:PROPERTIES:
:ID: 1414B5E8-04FF-5D7B-BD35-AA8DFC313E37
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
business_units add <id> <unit_name> <parent_business_unit_id> <unit_code> <business_centre_code> <unit_type_id> <status> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.business_units.put=.

** =set=
:PROPERTIES:
:ID: 5FEDF799-A6FB-540E-8E7D-0332A0A61D66
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+end_example
