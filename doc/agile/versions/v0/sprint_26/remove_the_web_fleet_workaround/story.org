This page documents a [[id:699A8D45-B67E-4D3E-9206-24FA17C51ADA][story]] in [[id:2B39B97B-89F9-4320-8BAC-A603D805EBF3][Sprint 26]]. It captures the goal, current status, acceptance criteria, and the tasks that compose it.

* Goal

=ores.web= starts the way every other component starts: the generated fleet,
brought up by =compass services=.

The component carries its own way to start a subset of that fleet.
=scripts/dev-stack.sh= starts NATS, the IAM service, refdata and the BFF as
separate processes, and =scripts/run-service.sh= exists only to be called by
it. They were written because =compass services start= installs systemd units
outside the checkout, which a sandboxed session could not do. The busctl
transport removed that constraint, so the workaround is now a second way to
start the same services, and a second way is a way to drift.

This is housekeeping rather than a feature. It is worth doing because the
workaround is already inconsistent with the thing it duplicates: it starts
four units out of twenty-five, it documents itself in the component README as
the standalone path, and nothing keeps it in step with the fleet.

* Decisions

- *A component does not start services.* The fleet is generated and owned by
  compass, one unit per service, with the certificates, the environment and
  the dependencies that go with it. A script inside a component that starts
  four of those units is a parallel implementation of the fleet, and it can
  only ever be a partial one.
- *The workaround was correct when it was written.* The README's own words
  were that =compass services start= "installs systemd units outside the
  checkout, which needs privileges this workspace does not have". That was
  true, and the script is what made the component testable in the meantime.
  It is not true now, which is the whole of the argument for removing it.
- *The hot-reload path stays, and it stops depending on the caller.* The
  thing worth keeping from the script is a Vite server that proxies to the
  BFF. That already exists as =npm run dev:web=, but it read its ports from
  the environment, so it only worked when the script passed them. It now
  reads the checkout's =.env= directly, which is where the BFF reads them.
- *The historical records are not rewritten.* A sprint 25 review table names
  the script and the file mode it was given. That is a record of a decision
  as it was taken, and it stays.

* Out of scope

- The service units, their dependencies and their credentials. This change
  removes a competing way to start them; it does not touch how the fleet
  works.
- =scripts/emit_protocol_ir.py=, =scripts/make-test-hash.cpp= and
  =scripts/seed-test-account.sh=. They are the component's own tools and
  none of them starts a service.
