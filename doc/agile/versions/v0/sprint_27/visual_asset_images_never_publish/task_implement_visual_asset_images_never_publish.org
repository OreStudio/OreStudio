* Goal

Publish the country flag and cryptocurrency icon datasets to
=ores_assets_images_tbl= when their masters load, so the country publish
resolves a flag for every country and emits no missing-image warning.

* Acceptance

- =populate/flags/flags_populate.sql= and =populate/crypto/crypto_populate.sql=
  each publish their image dataset to the system tenant after the images
  artefact loads.
- A fresh =compass db recreate= emits no =Image ... not found in
  assets_images_tbl= warning.
- =ores_refdata_countries_tbl= carries an =image_id= on all 250 rows after
  a recreate.
- A second publish of either dataset leaves the production row count
  unchanged.

* Plan

Diagnosis. =populate/catalogues/catalogues_populate.sql= loads the flags and
crypto datasets and their images into the DQ artefact table, then ISO and
ACME publish countries. The country publish resolves each country's DQ image
through =ores_dq_images_artefact_tbl= into =ores_assets_images_tbl=, and no
step published the image datasets there. Only
=populate/assets/system_avatars_populate.sql= called
=ores_assets_publish_images_from_dq_fn=.

Fix. Add the same publish call to the flags and crypto master includes,
after their images artefact include, so the images are live before any
country or currency publish reads them. The masters are hand-maintained
today: the flag archetype is retired and the batch-execute master archetype
is bound to no dataset model, so no codegen source produces them.

* Notes

- Root cause: =catalogues_populate.sql= staged the flag and crypto images
  into =ores_dq_images_artefact_tbl= but published nothing into
  =ores_assets_images_tbl=. Only =assets.system_avatars= published its
  images, so the country publish resolved no flag and warned once per
  country.
- The warning came from =refdata_publish_from_dq_create.sql:140=, which
  raises when the country's DQ image key has no matching production row.
- The publish is idempotent: a second run of the flag dataset reported
  =updated 276= and left the production row count unchanged.
- The two bespoke =*_generate_metadata_sql.py= scripts are stale (wrong
  master filename, superseded metadata format) and are not run by the build
  or CI, so the masters are edited directly.
