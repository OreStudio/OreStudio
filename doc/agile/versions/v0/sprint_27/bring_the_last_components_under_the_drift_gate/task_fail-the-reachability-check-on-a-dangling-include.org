* Result

The check skipped any include whose target file did not exist, so a file deleted
but still named by an aggregator passed while psql aborts the build on it. It
now reports such an include, naming the including file, the entry and where it
looked, and fails.

Resolving \i and \ir was also wrong in principle: both were resolved against
the including file, where psql resolves \i against its working directory. They
agreed only because every entry point sits at the schema root.

Proven by appending a dangling include to trading_create.sql and watching the
check name it and exit 1, then restoring and watching it exit 0. Five tests pin
both directions. The check covers create/ only: populate/ and drop/ carry the
same hand-written include graph and nothing verifies it.
