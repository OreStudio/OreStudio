* What

Give the role that the iam pgTAP suites run as permission to execute
=ores_iam_account_exists_fn=, or change the suites so that they do not call it. Then
=iam_accounts_shared_visibility_test.sql= and =iam_service_actor_test.sql= run their plans
to the end.

* Why

On 2026-11-18 the =pgtap= check failed on a branch that changes no iam SQL, after the
database was recreated from that checkout:

- =iam_accounts_shared_visibility_test.sql=, line 65: =ERROR: permission denied for function
  ores_iam_account_exists_fn=. The plan was 15 tests and 0 ran.
- =iam_service_actor_test.sql=, line 74: the same error. The plan was 4 tests and 2 ran.

The other 95 pgTAP files passed. Recent main commits changed the tenant policy suites and the
junction trigger. One of these commits probably caused the failure, but nobody has confirmed
this. While the check is red, every branch that runs =pgtap= reports it, and real failures
are hidden.

* Acceptance

- Both suites run their full plan and pass on a fresh database.
- =./projects/ores.sql/test/run_tests.sh= reports =Result: PASS=.
