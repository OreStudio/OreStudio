* Acceptance

- A step accepts a pasted image and a dropped image file.
- The BFF route accepts only images, limits their size, and saves them beside the scenario doc under a name built from the scenario and the step.
- The saved name appears in the step's Result, as the Qt tool wrote it.
- Tests cover a valid image, a file that is not an image and a file that is too large.

* Plan

The Qt tool saved a screenshot as =<scenario>_step<N>_<yyyyMMdd_HHmmss>.png= beside the scenario doc and appended =[[file:name.png]]= to the step's note. This task does the same from the browser.

- The BFF route is =POST /api/qa/scenarios/:id/steps/:step/images= with a JSON body of a media type and the bytes in base64, as the existing =/api/images= route takes an image. It answers the name the server gave the file.
- =detectImage= in =scenarios/image.ts= decides what the bytes are from their signature: PNG, JPEG, GIF or WebP. A media type that the browser claims is not trusted, and the file extension follows from the signature. An SVG is refused, because it can carry script.
- =saveImage= on the scenario store keeps the file beside the scenario doc. It checks that the scenario exists, that the file is not empty, that it is at most 8 MiB, that it is an image, and that the step number is one of the scenario's steps. The name is built from the doc's file name, made safe, the step number and the UTC time. A file that exists is never overwritten: the name gets a numeric suffix.
- The route answers 415 for a media type or bytes that are not an image, 413 for an image over the limit and for a body past the route limit, and 400 for a bad step or body. Fastify's own 413 was an internal fault before, and =toHttpFailure= now answers it as 413.
- In the browser a paste or a drop anywhere on the step card hands the files to the page. Text pasted into the note stays in the note. The page refuses a file that is not an image, or is over the limit, with a message, uploads the others one by one, and appends =[[file:name]]= on a new line of the note of the step the file was dropped on. Saving writes the note, and with it the link, into the doc.

Decisions:

- A step is named in the route by its number from one among all the steps of the doc, as the Qt tool numbered it.
- The link is added to the note of the draft, and reaches the doc when the tester saves. An image that the tester uploads and then abandons stays as a file beside the doc, as it did in the Qt tool.
- An upload while a save is in flight, or on a closed scenario, is ignored.

* Result

A tester pastes or drops an image on a step, and the step's note links it, as the Qt tool did. The BFF route POST /api/qa/scenarios/:id/steps/:step/images takes a media type and the bytes in base64. The server decides what the bytes are from their signature, accepts a PNG, JPEG, GIF or WebP image of at most 8 MiB, refuses an SVG and anything else, checks the step number, and writes the file beside the scenario doc under a name built from the doc, the step and the UTC time, without overwriting a file. It answers 415 for bytes that are not an image, 413 for too large, and 400 for a bad step or body. The session is checked before the body is read. Fastify's own 413 for a body past the route limit used to come out as a 500, and now it is a 413.

In the browser a paste or a drop of files anywhere on the step card hands them to the page. Text pasted into the note stays in the note. The page refuses a file that is not one of the four kinds, or is too large, with a message, uploads one batch at a time, and puts [[file:name]] on a new line of the note of the step the file was dropped on. Save is held while an image uploads, and a closed scenario takes no image. The next save writes the note, and with it the link, into the doc.

The BFF suite passes with 512 tests, the web suite with 821 and contracts with 10. Removing each guard of the route and the card fails its own test. A throwaway harness drove the real page in headless Chrome with real paste and drop events: 19 checks for the flows and 9 for the review fixes passed with no script errors. The review found four real faults, and all four are fixed. The most serious was a save during an upload that could drop a link.

The runner shows the file name in the note and no thumbnail, because the BFF has no route that serves a saved image. That is a follow-up. An upload that a tester abandons stays as a file beside the doc, as in the Qt tool. The French and Portuguese text is my translation and needs a read by a speaker.
