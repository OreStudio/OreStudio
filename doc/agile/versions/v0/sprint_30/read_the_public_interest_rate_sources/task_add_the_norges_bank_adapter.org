NOWA is stored as fixings in the system tenant, with its history, read from Norges Bank through the SDMX API, =data.norges-bank.no/api/data/SHORT_RATES/B.NOWA.ON.R=, in CSV. * Acceptance

- The adapter reads Norges Bank alone, and it does not copy the announce, the demand, the backfill or the publish code.
- Norges Bank is a supplier in the catalogue, its series maps to the NOK-NOWA item, and a session and a feed scoped to that item are seeded in the system tenant.
- A fresh environment stores the history as fixings within minutes of provisioning, and the log names the source and the count it stored.
- Each fixing is the decimal of the published percent, with the credit Source: Norges Bank.
- The depth of the history is measured and written into the calibration sources note.
- Unit tests parse a recorded response, and a malformed response gives an error, not a fixing.

* Plan

- =norges_bank_fetcher= implements =fetcher=: adapter =nb_sdmx=, scheme =nb_sdmx=, field =OBS_VALUE=. A source's key is =<dataflow>.<series key>=, such as =SHORT_RATES.B.NOWA.ON.R=, as the ECB key is. A read is one GET of =/api/data/<dataflow>/<key>= in CSV, with =locale=en= so that the decimal mark is a point.
- The CSV separates its cells with a semicolon and has no =KEY= column. The query names one series, so each row is an observation of the key. The ECB fetcher's private CSV helpers move to =published_text= as =lines_of=, =cells_of= and =column_of=, and both fetchers use them.
- The API answers both a window with no observation and an unknown series with a 404. A shared helper, =read_window=, asks after a 404 for the series' latest observation, =lastNObservations=1=: a 200 means the window is empty, and anything else is an error. The Riksbank fetcher needs the same rule.
- Option =--norges-bank-url=. The seeds add the =norgesbank= supplier and provider, with the terms-of-use page and the credit "Source: Norges Bank", the =nb_sdmx= adapter, the =norgesbank-data= session, the =norgesbank-nowa= feed scoped to the =NOK-NOWA= item, and the system party's subscription and route.
- NOK has no overnight curve config yet, because the bootstrap engine does not implement the ACT/ACT.ISMA day count that =NOK-NOWA= states. The fixings are stored now, and the calibration reads them when the curve exists.

* Result

NOWA is stored as fixings in the system tenant, read from Norges Bank's SDMX API by a specialised fetcher that the official adapter hosts beside the others. A fresh environment accepted Norges Bank's terms at setup and stored 275 fixings, the last 400 days, with the log line "Sent 275 fixing(s) of 'norgesbank-nowa'". The values are the decimals of the published percents, such as =0.045= for 4.5, and the provider =norgesbank= carries the credit "Source: Norges Bank". The series maps to the =NOK-NOWA= item.

The API answers an empty window and an unknown series with the same 404. A shared helper, =read_window=, asks for the series' latest observation after a 404, so an empty window reads as no fixing and an unknown series is an error. The ECB fetcher's CSV helpers now live in =published_text=. The calibration sources note records the 3,801 rates the route serves from 2011-09-30.

The work also found that the BCB's open licence may not cover the CDI, which B3 computes. The note records it, and the Banco Central do Brasil task is blocked on the CDI's terms.

Unit tests parse a recorded answer and a row with no value, refuse five malformed answers, check the URL of a read, an empty window of a known series, an unknown series, a failed read, and keys that are not series keys.
