* Acceptance

- The strike child records which list its row came from, and its key admits more than one strike per trade.
- Every cap and floor the document states is written, not just the first.
- The corpus collar document proves both lists come back, with the document's own values as the expectation.

* Plan

1. Give =instrument_strikes= a =strike_role= and a =sequence_number=, both in
   the key, mirroring =swap_leg_rates= beside it: that table already carries a
   =rate_role= in its key for exactly this shape, a two-arm closed set that is
   data rather than a table.
2. Write every cap and every floor the document states, each with its role and
   its ordinal, rather than the first of whichever list is filled.
3. Read the role back on export and write the row into the list it names.
4. Prove it on the corpus collar, =IR_CapFloor_on_FedFunds_amortising.xml=,
   which states a cap of 0.03 and a floor of 0.0121 in one trade.

* Decisions

- *The role goes on the strike row, not on the product fact.* A collar states
  both lists in one document, so the arm is a property of the strike, not of the
  product. A =cap_floor_type= column on =cap_floor_instruments= would have been
  cheaper and would have made a collar unrepresentable.
- *The vocabulary is =cap=, =floor= and =single=.* =single= is the one strike a
  bond, a swaption or an index option states, with no arm to name; the column is
  not nullable, so every writer must say what it means rather than leave a hole.
- *Both columns join the key.* One strike per trade is the defect; an ordinal
  alone would let a second cap overwrite the first.

* Notes

- A key change on a shared table has four writers, and the first pass fixed one
  of them. The importer built =put_instrument_strike_request= in three places
  and copied eight of its ten fields in two of them, so a CapFloor or an index
  option strike would have been sent with an empty role and an indeterminate
  ordinal: the service throws and the table refuses it. The three sites now call
  one builder that takes the row, so a new key column cannot be forgotten by two
  of three callers.
- =sequence_number= is generated as a bare =int= with no initialiser, and the
  model has no way to say otherwise: =:default_value:= changes the database
  default, not the C++ member. A missed assignment is therefore undefined rather
  than loud. The single builder is the answer for these three sites, and the
  same pattern is in =swap_leg_rate=, so it is a codegen-wide gap worth its own
  capture if it bites.
- Strike history is now a no-op for this entity. A compound key has no
  single-string id on the =history_provider= interface, so the registrar
  registers nothing, exactly as =swap_leg_rate='s registrar has since it became
  compound; the generated comment states the reason. It is a change for this
  entity, and it is not covered by a test.
- The =trade_id_one_of= filter on the strike protocol is gone, because the
  generator emits it only for a single-key entity. All the sibling protocols
  still declare theirs; the batch read that replaces it takes three parallel key
  vectors.
- Two readers consume strikes without filtering by role: the credit reverse took
  =front()= and now asks for the =single= row; the bond reader assigns into a map
  keyed by trade and keeps the last row, which is safe only while a bond states
  one strike.
- The ordinal now orders the reverse's output. Nothing else reads it, and
  =read_strikes_by_trade_ids= still orders by trade alone.

* Result

A cap/floor's strikes round-trip as the lists the document stated. Every cap and
every floor is its own row, carrying the list it came from and its ordinal, and
the export returns each row to the list its role names.

Proved red first: with the mapper reverted to the merge base the case fails on
=result.strikes.size() == 2= with =1 == 2=, which is the floor being dropped;
with the fix it passes fifteen assertions, on the corpus collar's own values
(=0.03= and =0.0121=).

The arm is data on the row rather than a column on the product, because a collar
states both lists in one document: a =cap_floor_type= on the fact table would
have made a collar unrepresentable. The shape mirrors =swap_leg_rates=, which
already carries a =rate_role= in its key for the same reason.

The role is not nullable, so every writer says what it means: the rates mapper
writes =cap= or =floor=, the credit mapper writes =single= for the one strike an
index option states, and the generator writes =single= rather than a word
outside the set.

Order within a role is preserved on the way out because the reverse sorts by
the ordinal, and a role the product does not state is skipped rather than
rendered as a cap.

The gate: build, db, ctest, ore-xml-roundtrip, pgtap and the static checks with
the fleet down, then =step-consumers= with it up.
