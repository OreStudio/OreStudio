* Acceptance

- The record page has Details, Global parameters, Products, Reports and History, in that order.
- Products is a tree of the configuration's product types by asset class beside the product, and the product takes the rest of the width.
- The product states what it is, its asset class and its instrument, then a Model group and an Engine group. Each group states what a model or an engine is, names the choice, gives its description and lists its parameters.
- Every model, engine and parameter description comes from the server's vocabulary, not from a screen literal. A description the server does not hold says so.
- Global parameters lists the parameters that apply to the whole document, each with its documentation collapsed under it.
- Reports lists the reports that bind the configuration and states the reach rule.
- History is the shared timeline, served by the history read.
- The page is read-only. Edit and the product Edit open the save dialog, which states the difference and asks for a change reason.
- The import follows the standard: the parse on the server, the findings, the difference and the review.

* Plan

The work sits on one branch and goes out as one PR.

1. The BFF joins the product type to its instrument code to carry the asset class, adds the reach to the document read, and allows the configuration's history type.
2. The page draws five tabs through =useTabs=, so the address holds the tab.
3. The Products tab draws the tree by asset class and the workbench, with the model and engine groups and the parameter documentation from the vocabulary.
4. The tests cover the details, the product workbench, the reach, the global parameters and the write actions.
