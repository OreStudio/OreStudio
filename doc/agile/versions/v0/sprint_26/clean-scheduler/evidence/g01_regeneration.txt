Idempotence is the property that matters, and it holds: after the first
in-place run, a second run changed no artefact. The check keeps exiting
non-zero while the artefacts are uncommitted, because its in-place mode
compares the working tree with git and the new files are untracked until the
commit lands; the only difference it then reports is that untracked list.

The generated shell units and recipe are absent by design: the model disables
the =ores.cpp.shell-command= facet in its =* Physical space= table, with the
reason stated there.
