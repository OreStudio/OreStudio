* Acceptance

- A list shows the configurations of the party, with the variant, the product count and the setting count, and it searches and sorts.
- A record page shows one configuration with its products and settings, and offers Change, Add product, Remove and Delete to a person with the write permission only.
- A change states the difference, runs the checks, asks for a reason and saves the whole document against the version it read. A stale version is a conflict, and the dialog offers to read again.
- Authoring is a journey of six steps: name, products, model and engine, settings, check, review and save. It starts empty or from a copy.
- The models, engines, pairs and settings come from two new lookup tables, pricing_model_engine_pair and pricing_pair_setting, seeded from the ORE pricing engine files.
- Saving a document removes the products and parameters that the new version omits.
- The BFF routes, the web client and the screens have unit tests.

* Plan

** What was built

| Layer | What |
|-------+------|
| SQL and analytics | The tables pricing_model_engine_pair and pricing_pair_setting, generated from codegen models, with seeds of 24 pairs and 12 settings. The document save removes omitted rows. |
| BFF | The routes under =/api/reporting/pricing-engines=: list, vocabulary, read, create, save and delete. A create writes the reporting configuration header first and removes it again when the document does not save. |
| Web | The list, the record page with its dialogs, the authoring journey, the card and workflow, the paths, the permissions and the strings in three languages. |

** What is left

- Import. The journey says the parse belongs on the server, so a browser parser cannot drift from it. The work is a server operation that turns a file into a document without saving, then the screen.
- History. The history provider exists on the server. The screen draws the shared timeline when the BFF serves it for this entity.
- The reach of a change. No operation lists the reports that bind a configuration, so the screens say so.
- Deleting a configuration leaves its reporting configuration header. A later change removes both.
