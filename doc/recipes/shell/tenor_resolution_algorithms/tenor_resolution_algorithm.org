#+title: How do I run the tenor_resolution_algorithms commands from the shell?
#+description: Every command the tenor_resolution_algorithms submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tenor_resolution_algorithms:

This file documents the tenor_resolution_algorithms resource at the shell, one section per command. Every command is a subcommand of =tenor_resolution_algorithms=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: EB07E8EE-D7C8-54C5-8079-58F77F5D3D39
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tenor_resolution_algorithms list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.tenor_resolution_algorithms.list=.

#+name: tenor_resolution_algorithms-list
#+begin_src ores-shell :tangle tenor_resolution_algorithms-list.ores :exports none
tenor_resolution_algorithms list --limit 1
#+end_src

** =add=
:PROPERTIES:
:ID: 8E87B84C-0B6A-5012-8149-F613EE89AE88
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tenor_resolution_algorithms add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.tenor_resolution_algorithms.put=.

#+name: tenor_resolution_algorithms-add
#+begin_src ores-shell :tangle tenor_resolution_algorithms-add.ores :exports none
tenor_resolution_algorithms add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 43C36AB5-623C-5C7D-8F4B-B090D3C632D7
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example

#+end_example

It is addressed at =refdata.v1.tenor_resolution_algorithms.put=.

#+begin_src ores-shell :tangle tenor_resolution_algorithms-set.ores :exports none

#+end_src
