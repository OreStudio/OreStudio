* Acceptance

- =/health= states what the server can do: serving, whether a verifier is
  configured, and how many connections are open. It does not refuse while the
  verifier is absent, because a health check that flaps is worse than a field an
  operator can read.
- =/metrics= reports what the server knows: connections, requests by status, refusal
  counts, bytes, and the saturation of the handler pool.
- Both answer without authentication and without touching a database.
- The numbers are the ones the server already keeps, not a second set.

* Plan

1. Decide what health means for this process: serving, and its verifier configured.
2. Render metrics in the text format a scraper reads.
3. Test that a refusal moves the refusal counter and that a healthy server reads as
   healthy.

* Notes

- The counters live in the server and the session increments them, so a metric is
  never computed at request time: a scrape reads what is already there.
- Every answer passes =write_response=, including the refusals, so a status class is
  counted in one place rather than at each site that can write.
- A scrape counts itself in =requests_total=, because a request is counted when it
  is read and not when it is answered. The case says so.
