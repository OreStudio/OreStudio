* Goal

Declare on each page whether it is user-facing, with a tag or a keyword, and mark the domain knowledge, the manual and the glossary. Add a table of raw knowledge pages in the system tenant, read by every tenant: org id as the key, the file's path, its org text unchanged, when it was loaded. Write the script that loads every user-facing page into it, replacing the previous load.

* Acceptance

- A page is user-facing only when it declares it; the default is not, so an
  internal page is never loaded by omission.
- Every user-facing page carries the declaration, and a gate refuses a page whose declaration is malformed.
- The script lists every page it loads, so the set can be reviewed before it
  reaches every tenant.
- The script loads every user-facing page into the raw table as org, unchanged, keyed by its org id; a second run replaces the first.
- Every tenant can read the raw table and none can write it.
- The raw table lives in a new =ores.orgmode.core=, and =ores.orgmode.service=
  joins with it, registered in the service registry with its database role,
  IAM role, units, image and certificate, and running in the fleet. The work is
  in commits =05e0419674= and =b0887787b9= of the split task's branch.

* Plan

The pages reach PostgreSQL the way ORE's other system reference data does, as a
DQ dataset published into the system tenant at bring-up, with one difference
the product owner chose on 2026-11-21: the dataset's populate SQL is generated
by the build and never committed. A committed seed would hold every page's
text, a few megabytes, and every edit to a user-facing page would need it
regenerated or its check would fail.

1. *Declare.* A page opts in with =#+audience: user=; no keyword means not
   user-facing. Mark the domain knowledge, the manual and the glossary. A check
   refuses a malformed value.
2. *Model.* A codegen entity, =ores.orgmode.knowledge_page=, in a new
   =ores.orgmode.core=: org id as the key, the source path, the org text,
   system-tenant rows every tenant reads (=rls_own_or_system_tenant_rows=), and
   its DQ artefact table. A publish function copies the artefact rows into the
   live table and closes the rows of pages no longer loaded, so a load replaces
   the previous one. A dataset, =orgmode.knowledge_pages=, in the =system_core=
   bundle.
3. *Generate.* A generator reads every page that declares =#+audience: user=
   and writes the dataset's populate SQL into =build/output=, listing every page
   it writes. =compass db recreate= runs it and passes its path to the recreate
   script as a psql variable, so the populate runs it with the rest.
4. *Serve.* =ores.orgmode.service= joins, registered as in commits
   =05e0419674= and =b0887787b9=, linking the new core.

   The service serves the knowledge page's generated reads and the publish
   step, =orgmode.v1.ops.publish_knowledge_pages_from_dq=, declared in
   =ores.orgmode.publish_operations= and handled the way assets handles its own.
   The bring-up publish does not need it: the bootstrap publishes the
   =system_core= bundle in SQL. The step serves a later republication.
5. *Read from the shell.* A new adapter part, =ores.shell.orgmode=, holds the
   generated =knowledge_pages= menu. The entity is =client_read_only=, so the
   menu lists and reads and never writes: the dataset is the table's only
   writer.

Measure: the number of pages declared, loaded and readable from a tenant.

* Result

The knowledge base's pages reach PostgreSQL as org, unchanged, keyed by their
org id.

- 273 pages declare =#+audience: user=. A gate, =audience=, refuses a
  malformed declaration.
- The DQ dataset =orgmode.knowledge_pages=, in the =system_core= bundle, stages
  them. Its populate SQL is generated by =compass db recreate= and never
  committed. The generator lists every page it writes, and fails on a page
  without an id or with a duplicate.
- The bootstrap publishes them into the system tenant through
  =ores_orgmode_publish_knowledge_pages_from_dq_fn=. A tenant reads them and
  cannot write them: the entity is =client_read_only=, and its RLS admits the
  system tenant's rows. Acme's administrator lists all 273 from the shell.
- =ores.orgmode.service= is registered, with its database role, IAM role,
  unit, image and certificate, and runs in the fleet. It serves the knowledge
  page's reads and the publish step =orgmode.v1.ops.publish_knowledge_pages_from_dq=.
- =ores.shell.orgmode= gives the shell a read-only =knowledge_pages= menu.

Not proven: the publish step through the workflow. No shell command publishes
one dataset, so only the SQL path the bootstrap runs was exercised. The local
gate was not run green: the product owner chose to merge past it while main's
pooler fixes land (story "Run the tests through the pooler").
