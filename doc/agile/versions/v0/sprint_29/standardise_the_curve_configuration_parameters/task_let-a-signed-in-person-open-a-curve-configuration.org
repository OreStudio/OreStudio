* Notes

- *The page was merged without ever being opened.* Its tests seeded the render,
  so they could not see either fault below. Signing in to the running
  environment and reading the route found both within minutes.
- *A person could not read a curve document.* The document's read checks
  =refdata::curve_configurations:read=, and only =OreService= and =ReportRun=
  held it: a human session got =403=. The sections' read,
  =refdata::curve_sections:read=, was held by no role at all. Both are reads a
  person's screen needs, so the Member role now holds them beside the engine
  settings reads, and the rows stay party-scoped by row-level security.
- *The seed grants reach a tenant at provisioning.* Granting to the system
  tenant alone changed nothing for the demo tenant, which holds its own copy of
  the roles; the environment a person tests needs a recreate or the same grant in
  its own tenant. =compass db recreate -y -k= applies the seed.
- *The import mints identifiers that are not RFC uuids.* The route parsed the
  address with =z.uuid()=, which enforces the RFC's version and variant bits, and
  the ORE bundle import writes ids that carry neither
  (=90e6d408-aa8e-3e14-206b-d510eefb7c29= has variant 2). The whole product's own
  ids are v7 and passed, so only imported data showed it. The route now takes any
  well-formed guid, as the report configuration route does, and a test reads a
  configuration by such an id.
- *What the live read showed.* The Group curve configuration holds four yield
  curves and no entry in any other section; the first is =GBP1D=, a GBP discount
  curve bootstrapped from GBP-SONIA swaps, with its currency, interpolation,
  day counter and tolerance read from its own row. All 48 of its parameters are
  documented, because the sections it uses are the ones the extractor read in
  full. The walk found the gap of the contract in other configurations rather than
  in this one.

* Result

A signed-in person can open the curve configuration the environment holds, and
the two faults that stopped them are fixed:

- The Member role holds =refdata::curve_sections:read= and
  =refdata::curve_configurations:read=, so the page's reads are permitted for a
  person's session and not only for the services.
- The route takes a guid rather than an RFC uuid, so it opens a configuration by
  the identifier the ORE bundle import minted for it. A BFF test reads one by
  such an id.

The change was found and proved against the running stack: the route answered
=200= for =90e6d408-aa8e-3e14-206b-d510eefb7c29= with four yield curves and 48
documented parameters, after the grant and the identifier fix. The environment
in this checkout carries the grant because it was applied to its tenant by hand;
a recreated environment takes it from the seed.
