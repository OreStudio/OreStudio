* Notes

A =nats_subject= constant names a prefix. A JetStream stream and a
subscription need the prefix *and its children*, which is a different
string, and nothing in the tree says so. Four sites need that string and
spell it three ways:

| Site | Subject passed to =ensure_stream= | Spelling |
|------+-----------------------------------+----------|
| =marketdata/service/app/application.cpp= | =market_tick_wildcard()=, =synthetic_tick_wildcard()= | named helper |
| =synthetic/service/app/application.cpp= | ="synthetic.v1.tick.>"=, ="synthetic.v1.sandbox.tick.>"= | hardcoded literal, and the first duplicates the helper above |
| =compute/wrapper/app/application.cpp= | =work_assignment_event::nats_subject + ".>"= | inline concatenation |
| =workflow/service/app/application.cpp= | two exact leaf subjects | no wildcard needed, nothing publishes below them |

The bare constant sitting beside the wildcard is what makes the mistake
easy, and it is not hypothetical: the ingest loop test at
=marketdata/service/tests/app_feed_ingest_loop_tests.cpp= passed the bare
=market_tick::nats_subject= to =ensure_stream=. A stream on a prefix
matches none of its children, so the republish to
=marketdata.v1.tick.<tenant>.<party>.<key>= found no stream and threw
=No responders available for request=. Fixed in PR 2735.

That test passed on a developer machine for a reason worth keeping: the
service had provisioned the stream correctly weeks earlier, and
=ensure_stream= returns early when the stream already exists, so the
fixture's narrower subject was never applied. The defect only appears
against an empty JetStream, which is what CI starts from.

This task also carries the =marketdata.v1.tick= rename that the census
lists as one of the five three-segment subjects. The prefix appears in the
stream name, the consumer subject, both wildcard helpers and both market
data test files, so the rename and the idiom should land together.
