* Goal

Every ORE parameter whose reader accepts more than one rendering of a value is stored in one canonical representation, and the map from a rendering to that representation is data the database holds, not a table compiled into a binary. The value set states both what is accepted and what is canonical, so the screen offers one form and the store keeps one form, and a spelling ORE adds later is a row rather than a release.

* Acceptance

- Every parameter whose reader accepts more than one rendering is named, with the file and line of the reader, the renderings it takes, and whether the comparison ignores case.
- Every such parameter states the spelling the engine's own writer emits, which is the canonical form the story will adopt.
- The census is a table in the story's =* Analysis=, or a document linked from it, and it is produced by a script in the tree rather than by a person reading the source.
- The script is rerunnable: a new ORE version regenerates the table, and a parameter that appears or disappears is visible in the diff.

* Plan

** Extend the extractor

=projects/ores.seeder/datasets/ore_pricing_engines/extract_parameter_types.py=
already resolves the parser of every parameter and the values an enumerated
parser takes. It gains three facts:

- the renderings a parser accepts, including aliases a map holds;
- whether the parser upper-cases its input before comparing, which is what
  makes a word case-insensitive;
- the spelling the engine's writer emits for the value, read from the
  =operator<<= or =to_string= the parser's enum declares.

A parser this scan cannot resolve is reported, not skipped: an unread reader is
the census's own gap and must be visible.

** Classify the parameters by rendering class

The four classes the story's analysis names — alias spellings, case-insensitive
words, flags, and index or code lists — with the parameter, its set and the
reading that puts it in the class.

** State the canonical form

For each parameter, the spelling the engine writes. Where the engine writes
nothing, the class default: =true= and =false= for a flag; the registry's own
code for an index list.

** Write it down

The result is a table in the story, one row per parameter, with the reader as
the evidence and the canonical form as the decision. It is the work list the
remaining tasks take, and the reason a later ORE version changes one file.

* Result

The census is in the story and its output is committed as
=parameter-renderings.json= beside the extractor. Against ORE 1.8.17.0,
seventy-four parameters accept more than one rendering: fifty-two flags,
six case-insensitive words and sixteen alias maps.

Two findings change the story's plan. The engine's writer is not always a
spelling its own parser accepts — =FirstBestFitThenBootsrap= is written and
=FirstBestFitThenBootstrap= is parsed — so the canonical form is a rendering
the parser accepts, and the writer is evidence for it. And sixty-nine
parameters have no writer in this tree because the enumeration belongs to
QuantLib, so their canonical form comes from the registry or from a person's
reading, and the census says which.
