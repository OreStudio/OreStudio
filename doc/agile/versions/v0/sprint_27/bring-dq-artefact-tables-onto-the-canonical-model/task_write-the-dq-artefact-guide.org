* Acceptance

- The page names the canonical way, the pipeline and a checklist.
- The page names each legacy pattern and the task that retires it.

* Plan

Trace the pipeline in the code (the archetype, the dataset and bundle upserts,
the publication workflow, each service's publish handler and SQL function), then
write one page that states the one way, with a checklist and the legacy
patterns, and point the entity skill at it.

* Result


Shipped [[id:F19A6B98-1CAD-4206-913B-A4EAAED2DEAF][DQ artefacts]], ordered by the Data storage structure note. It states:

- the one way: the owning model's artefact flag, with =* Artefact columns= only
  when the staging shape differs, and no DQ model or stack for the artefact;
- the pipeline from the generated table through the hand-written includes and
  drop script, the seeded dataset, the artefact type, the bundle, the
  dependencies, the subject and handler, to the publish function and its test;
- the publish function's contract: signature, modes, idempotence, the clock for
  closing rows, the system-tenant refusal and the entity-writes baseline;
- a checklist, and the four legacy patterns with the task that retires each.

Two facts the code shows and no page said before: the publication orders
datasets by declared dependencies only, not by bundle display order; and the
drop scripts and =dq_create.sql= includes are written by hand for every
artefact. The =compass-codegen-add-entity= skill now says to stage an entity
from its own model and links the page.
