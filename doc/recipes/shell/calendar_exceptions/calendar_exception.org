#+title: How do I run the calendar_exceptions commands from the shell?
#+description: Every command the calendar_exceptions submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:calendar_exceptions:

This file documents the calendar_exceptions resource at the shell, one section per command. Every command is a subcommand of =calendar_exceptions=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: B3CAE284-2267-5070-AB79-12DC8452763D
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
calendar_exceptions list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.calendar_exceptions.list=.

#+name: calendar_exceptions-list
#+begin_src ores-shell :tangle calendar_exceptions-list.ores :exports none
calendar_exceptions list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 87976810-2B37-575E-AB70-134ED14038EB

** =add=
:PROPERTIES:
:ID: D0E110A6-E56D-5699-8FEF-AFAB96E40D50
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
calendar_exceptions add <id> <calendar_code> <exception_date> <is_business_day> <description> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.calendar_exceptions.put=.

#+name: calendar_exceptions-add
#+begin_src ores-shell :tangle calendar_exceptions-add.ores :exports none
calendar_exceptions add 00000000-0000-0000-0000-000000000000 __none__ __none__ false __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: AAE51298-CAAC-5F0D-A20F-1BFFDE41663A
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:
