* Result

The cliquet has its own fact table. It is authored from the ORE cliquet
binding, so every column answers to something the document states: the
underlying, the currency, the notional, long or short, call or put, the
moneyness, the local and global caps and floors, the settlement days, the
premium with its currency and payment date.

Every amount is money and so an exact numeric: the notional, the four caps and
floors and the premium. The moneyness is a ratio rather than an amount, so it
is a continuous quantity and stays a binary float. Every column the binding
makes optional is nullable, so an absent term stays null.

Verification. Full build clean and the whole suite passes 96 of 96 with the
database recreated for the new table.

Not done, and named: no mapper writes this table, and the EquityCliquetOption
code still routes to equity_option_instruments. Both move with the mapper
migration the operator deferred until the XML changes settle.
