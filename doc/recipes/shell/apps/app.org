#+title: How do I run the apps commands from the shell?
#+description: Every command the apps submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:apps:

This file documents the apps resource at the shell, one section per command. Every command is a subcommand of =apps=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: EB97DBD3-931A-5795-AE4A-5866FBF24C2E
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
apps list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =compute.v1.apps.list=.

#+name: apps-list
#+begin_src ores-shell :tangle apps-list.ores :exports none
apps list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 75AC9207-7E4F-5793-B98B-DD60DCC2BA1A
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
apps get <name>
#+end_example

It is addressed at =compute.v1.apps.get=.

#+name: apps-get
#+begin_src ores-shell :tangle apps-get.ores :exports none
apps get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 99F6FA92-1D6E-567F-970A-A3FA6C7ACA21
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
apps add <id> <name> <description> <reason> <commentary>
#+end_example

It is addressed at =compute.v1.apps.put=.

#+name: apps-add
#+begin_src ores-shell :tangle apps-add.ores :exports none
apps add 00000000-0000-0000-0000-000000000000 __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: E3348EE7-265B-596B-941F-5B49A0AF8C4C
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
apps set <id> <name> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =compute.v1.apps.put=.

#+name: apps-set
#+begin_src ores-shell :tangle apps-set.ores :exports none
apps set 00000000-0000-0000-0000-000000000000 __none__ __none__ system.new_record generated_script
#+end_src
