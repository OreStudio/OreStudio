* Goal

The corpus walk checks each file with one query instead of one query per series
in the tenant, so its cost grows with the corpus rather than with its square.

* Acceptance

- After each file, the walk reads that file's rows with one query filtered on
  the file's source tag.
- The check compares (key, value) pairs, not values alone.
- The suite passes locally, and its run time is recorded in =* Measurements=.

* Plan

Diagnosis: after each of about 100 files, =import_and_verify= read every series
in the tenant and then every series' observations, one query per series, to
find the rows stamped with the file's tag. The tenant grows with each file, so
the walk made about 100,000 round trips and read the growing tenant 100 times.
The CMake comment on the suite already measured the walk at about half an hour.

Fix: one query per file, filtered on =source= and the current-row sentinel,
returning (key, value) pairs. The test change only; no production code moves.

* Notes

The local machine shared its CPU with another worktree's build during both
runs, so the absolute times are high; the ratio is the measurement.

What remains of the walk is the import's own cost: one series lookup per
distinct series per file, at about 18 ms of fixed per-query overhead. That is
production code and outside this hotfix; it is captured as
[[id:0669523D-075C-4A7E-921E-83B76E24979C][The marketdata import looks up each
series with its own query]].

The macOS CI failure in the same window is =ores.workflow.core.tests=, not this
suite; it is captured as
[[id:64739960-499A-4B10-AFCF-C8EE3DB87476][The workflow step-deadline tests fail
on macOS]].
