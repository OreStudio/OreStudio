This page documents a [[id:31C868B9-306E-4282-BA8C-07E647021B34][task]] in the [[id:83339FFC-6314-443F-893D-BA053EEC9379][Reach systemd from a sandboxed compass session]] story. It captures the goal, current status, acceptance, and any notes or results.

* Goal

compass env provision and compass env configure write ORES_USE_BUSCTL=1 into the generated .env, so a sandboxed session reaches the user manager through busctl without anyone exporting a variable. Both commands accept --use-busctl and --no-use-busctl, so a host where plain systemctl --user works can switch the transport off, and the choice survives a re-configure.

* Acceptance

- ORES_USE_BUSCTL=1 appears in the .env skeleton that compass env provision writes, and in the .env that compass env configure generates.
- compass env provision --no-use-busctl writes ORES_USE_BUSCTL=0, and compass env configure --no-use-busctl keeps it off across a re-run.
- Every compass command that drives systemd resolves the transport from ORES_USE_BUSCTL in the process environment first and the checkout's .env second, so one command can switch the bus on or off without editing the file.
- An existing .env that lacks the key still configures, and defaults to on.

* Plan

Extract each decision into a pure function so a test can reach it, then wire
the commands to it.

1. =_skeleton_env()= in =env_create.py= builds the provisioned =.env= text. A
   test asserts the transport key without creating a worktree.
2. =compass env provision= gains =--use-busctl= / =--no-use-busctl= through
   =argparse.BooleanOptionalAction=, defaulting to on.
3. =_busctl_setting()= in =env_init.py= resolves the value for =compass env
   configure=. An explicit flag wins, an existing =.env= value stands, and a
   fresh checkout defaults to on.
4. Every module that drives systemd hands its env dict to
   =systemctl_bus.adopt_transport_setting=, and =compass.py= adopts once
   before dispatch so the commands with no pillar of their own are covered.

* Result

The transport defaults on, and an environment can switch it off.

=compass env provision= writes =ORES_USE_BUSCTL=1= into the skeleton =.env=,
and =compass env configure= writes the key into the =.env= it generates. Both
take =--use-busctl= / =--no-use-busctl=. An explicit flag wins, an existing
=.env= value stands, and a fresh checkout defaults to on.

=compass systemd= routes through the bus like every other pillar. The
transport resolves from the process environment, then the checkout's =.env=,
so no command needs a flag of its own to select it.

Evidence. New cases across =test_env_create.py=, =test_env_init.py=,
=test_systemd_generate.py=, =test_compass_services.py= and
=test_compass_transport.py=: #2150 brought the suite to 226, and #2153 to 251
passing with 1 skipped.

The new variable changes the =.env= shape, so the
[[id:BFE330BD-2AF8-43A4-BE8C-D066BD3FB1FD][Environment format version log]]
gains version 24. Without it the existing checkouts stay at versions 21 to 23,
the version check passes, and none of them is told to reconfigure, so the
default would never reach them and the fix would be inert outside a new
worktree. Recorded with =compass env version new=.

Correction, 2026-09-26. The independent verification of #2150 found that the
second and third sentences above described the intent rather than the
behaviour: =ORES_USE_BUSCTL= in =.env= never reached the transport. compass
reads =.env= into a dict and never writes =os.environ=, so =use_busctl()= had
nothing to read. #2153 adds the missing handover, and re-derived on this
worktree it now holds: with the key in a real =.env= and no flag,
=compass services status= reports =stopped=24 missing=0=.

Correction, 2026-09-26 (second). The flag this task added to the runtime
commands was withdrawn. With =ORES_USE_BUSCTL= in =.env= it could only repeat
the value the centre had already adopted before dispatch, and because that
adoption set a hard override the environment could not undo a checkout saying
=1=: a sandbox could switch the bus on, but nobody could switch it off for one
call. =systemctl_bus= now resolves the process environment first and the
=.env= second, in both directions. =--use-busctl= survives only on =compass
env provision= and =compass env configure=, where it decides what the
generated file says, and nowhere else.
