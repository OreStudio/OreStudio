* Goal

A client that asks for access to ORE shows the person a consent screen that states what it asks for — the client's name, the person, the party, the permissions and how long — and approves or refuses it. Approving creates the same agent grant the person creates by hand, and the screen returns the client to where it was going; refusing returns it to an answer that says so, and the screens show a sign-in that happened through a provider as it already shows a password one.

* Acceptance

- The consent screen states the client, the person, the party, the permissions and the term, and nothing the client did not ask for.
- Approving creates an agent grant the person sees in their grants and can revoke like any other.
- Refusing returns the client a refusal, and creates no grant.
- A client's consent page works in the browser a person already uses, with no separate application.
- The screen is pinned by tests, and the strings are translated.
