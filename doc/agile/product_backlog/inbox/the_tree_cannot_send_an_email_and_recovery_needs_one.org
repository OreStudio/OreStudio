#+title: The tree has no way to send an email, and password recovery needs one
#+description: The Rescue access and Entry journeys need a single-use, time-limited password-recovery link delivered to the address on the account. Nothing in the tree can send it: there is no SMTP client, no mail service and no template pipeline, and no table stores a recovery token. ores_iam_accounts_tbl carries email; ores_iam_account_credentials_tbl carries password_hash, service_password_hash and totp_secret; ores_iam_login_info_tbl carries password_reset_required and nothing token-shaped. The candidate subjects are iam.v1.ops.request_password_reset and iam.v1.ops.complete_password_reset, since neither is an entity verb. This is platform capability rather than a credentials screen, because sign-up verification, notifications and alerting will want the same delivery path, and it carries the usual security obligations: token entropy, single use, expiry, rate limiting, and not disclosing whether an address exists. Raised by the product owner while accepting the Rescue access prototype, after the screen was changed from an administrator-typed password to a recovery link.
