#+title: How do I run the report_definitions commands from the shell?
#+description: Every command the report_definitions submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:report_definitions:

This file documents the report_definitions resource at the shell, one section per command. Every command is a subcommand of =report_definitions=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: BCD12877-16E1-52B2-A55F-15D5C0B0F55F
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
report_definitions list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =dq.v1.report_definitions.list=.

#+name: report_definitions-list
#+begin_src ores-shell :tangle report_definitions-list.ores :exports none
report_definitions list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 52904275-B0D3-5618-9A99-ACA7297E0B6A
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
report_definitions get <id>
#+end_example

It is addressed at =dq.v1.report_definitions.get=.

#+name: report_definitions-get
#+begin_src ores-shell :tangle report_definitions-get.ores :exports none
report_definitions get 00000000-0000-0000-0000-000000000000
#+end_src

** =add=
:PROPERTIES:
:ID: 6B560D87-46BA-543D-A19D-9460A8495D69
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
report_definitions add <name> <description> <report_type> <schedule_expression> <concurrency_policy> <display_order> <reason> <commentary>
#+end_example

It is addressed at =dq.v1.report_definitions.put=.

#+name: report_definitions-add
#+begin_src ores-shell :tangle report_definitions-add.ores :exports none
report_definitions add __none__ - __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 0890517F-1FED-5CEA-B798-6B673049F568
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
report_definitions set <id> <name> <description> <report_type> <schedule_expression> <concurrency_policy> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =dq.v1.report_definitions.put=.

#+name: report_definitions-set
#+begin_src ores-shell :tangle report_definitions-set.ores :exports none
report_definitions set 00000000-0000-0000-0000-000000000000 __none__ - __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
