* Summary

=ore.xml= is five parameter lists and the schema constrains nothing in them:
=Parameter/@name= and =Analytic/@type= are free strings. The vocabulary exists
only in the 416 run documents ORE ships, and there it is forty-three setup
parameters, eight named market bindings, and thirty-five analytic types whose
parameter sets barely overlap — around seventy parameters for =xva=, sixty for
=simulation=, thirty for =sensitivity=.

This is the document that decides how a run behaves, and it is the one the
current model represents least: a flat row of switches can say "run NPV" and
nothing else.

* Detail

** The shape

#+begin_src xml
<ORE>
  <Setup>     <Parameter name="asofDate">…</Parameter> … </Setup>
  <Logging>   … </Logging>
  <Markets>   <Parameter name="pricing">…</Parameter> … </Markets>
  <Analytics>
    <Analytic type="npv">   <Parameter name="active">Y</Parameter> … </Analytic>
    <Analytic type="xva">   … </Analytic>
  </Analytics>
  <Restore>   … </Restore>
</ORE>
#+end_src

=Setup= is required, =Analytics= is required, and the other three are optional.
Only =Markets= is a set of *named* bindings: each of its parameters names a
configuration set built in =todaysmarket.xml=, which is market data and out of
scope here.

The parameters are not only numerous, they are different in kind: =xva= carries
allocation methods, curves, MPOR and DIM regression settings; =simm= carries a
version, a calculation currency and an MPOR in days; =smrc= carries one flag.
They also reference the configuration libraries. =sensitivity= names a
=sensitivityConfigFile= and a =stressConfigFile=; =xva= names a
=simulationConfigFile= and a =sensitivityConfigFile=; =simm= names a
=simmCalibration=; =crif= and =bacva= name a =simmVersion=. That is the shape of
the entity model: one row per analytic, a typed parameter entity per analytic
type, and references to the libraries several analytics share.

** Why the current model cannot hold this

=ores_reporting_risk_report_configs_tbl= has =base_currency=,
=observation_model=, =n_threads=, =market_data_type=, =market_data_date=,
twelve =*_enabled= booleans, four XVA columns, =var_quantiles=, =var_method=,
=simm_version= and =simm_calculation_currency=. That is a fraction of =Setup=,
none of =Markets=, and none of =Analytics=. It cannot express which analytics
run, in what order, with which parameters, or against which library — and the
twelve booleans are one row where ORE has a list of thirty-five types.
