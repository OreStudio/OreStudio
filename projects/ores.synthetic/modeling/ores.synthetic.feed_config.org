#+updated: 2026-11-03

The controls that start, stop and list the running feeds.

A feed is not an entity: nothing about it is stored, and a running feed is
process state rather than a row. The three operations here are therefore
modelled as operations rather than derived from a table, and they share one
kind-agnostic shape so a caller does not need to know which asset class a
config belongs to.

The list operation is named for the configs it reports on rather than for the
feeds it answers with, because a caller reads it beside the config list.

#+begin_src cpp :name comment
/**
 * @brief Request to start one feed on demand, keyed by config_id.
 *
 * One kind-agnostic request shape for every asset class: the server resolves
 * the config (of whichever kind it is), its children, and the refdata context
 * from config_id and builds the feed via the producer factory -- the IR curve
 * pattern, applied uniformly. The client never names a source_name or supplies
 * producer parameters; a config's own identity is the whole request. Replaces
 * the per-kind start requests (market_feed_config's client-supplied-params
 * pass-through and ir_curve_feed_config's config_id request).
 */
#+end_src
