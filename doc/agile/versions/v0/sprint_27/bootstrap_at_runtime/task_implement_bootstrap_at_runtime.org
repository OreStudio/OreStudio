* Goal

Remove the build-time reference-data publish, so a fresh database holds the
schema and the staged DQ artefacts only, and give the test suite a shared
helper that publishes the datasets a test needs.

* Acceptance

- =populate.sql= publishes no reference data; the DQ artefacts stay staged.
- =ores.testing= exports =publish_dataset()= and =publish_refdata_dataset()=.
- The FOMC curve test publishes its own chain, coding schemes included.
- The full suite is green after a recreate.

* Plan

Remove the publication. Delete =acme_publish_populate.sql= and the three ore
sample publish scripts, drop their includes and the report-instance fixture
from =populate.sql=, and stop publishing coding schemes, asset classes and
system avatars from their master includes. Publication becomes the runtime
act it was designed to be.

Migrate the tests. =ores.testing= gains a =publish_dataset()= helper that
makes the call the publish service makes: resolve the dataset by code and
invoke the function its artefact type owns, against a tenant. The FOMC curve
test, which leaned on the build-time coding-schemes publish, uses it.

Recreate and run the suite; fix what breaks the same way.

* Notes

- The build-time bootstrap was added in PR #2034 because a fresh database
  held 53 staged books and zero published, so no trade could be booked.
- Two populate scripts became unreachable when their trigger was removed:
  =reporting_test_report_populate.sql=, a walkthrough fixture that a test now
  provides for itself, and =iam_service_account_pictures_populate.sql=, which
  joins the published avatars. The first is deleted; the second is kept and
  named in =validation_ignore.txt=, because attaching the pictures belongs to
  the runtime and is its own change.
- The first full run failed 17 tests; 15 were the stopped fleet. Of the two
  real failures, one was the stale base (#2681 landed after the branch) and
  one was the missing coding schemes. Rebase and the shared helper fixed
  both.
