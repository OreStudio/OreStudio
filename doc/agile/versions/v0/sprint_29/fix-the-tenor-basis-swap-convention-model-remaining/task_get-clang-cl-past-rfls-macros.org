* Plan

** What it stops on

The 2026-10-28 run
[[https://github.com/OreStudio/OreStudio/actions/runs/40722677906][40722677906]]
failed in =windows-clang-release-ninja= inside headers this project does not
own:

#+begin_example
vcpkg_installed/x64-windows/include/rfl/Literal.hpp:413:75: error: too few
arguments provided for function-like macro invocation
vcpkg_installed/x64-windows/include/rfl/Variant.hpp:31:69: (same)
vcpkg_installed/x64-windows/include/rfl/Generic.hpp:211:73: (same)
#+end_example

"Too few arguments provided to function-like macro invocation" is a
preprocessor complaint: a macro is invoked with fewer arguments than it
declares. Under clang-cl the preprocessor is the conforming one, so a variadic
macro that relies on MSVC's traditional leniency expands differently.

** What to try, in order

1. Read the three macro definitions and the invocations the compiler points at.
   The error names the invocation site, so the macro and the argument list are
   both in the message's context.
2. Establish whether a newer =rfl= fixes it. If upstream has the fix, the work
   is a version bump and a rebuild, not a patch to a vendored header.
3. If the two compilers need different preprocessing, say which and why in this
   page before changing anything. Adding a flag to make the macros expand is
   the outcome this task exists to avoid, and the project has a recorded rule
   about suppressing diagnostics rather than fixing them.

** What it is not

It is not the configuration document split. The error appears in headers that
carry no project type, and the split's own failure -- C1202 in the reflected
aggregate -- has not been observed yet because MSVC stops earlier. Keep the two
apart so neither is blamed for the other.
