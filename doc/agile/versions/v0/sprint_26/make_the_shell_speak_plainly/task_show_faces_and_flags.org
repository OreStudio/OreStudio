* Acceptance

- The People tab shows each person's picture, or their initials when they have none.
- The Parties tab shows each party's business centre with the flag of its country.
- The pictures and flags are read inside the tenant, with one entry into the tenant for each page.
- A tenant administrator's own Parties screen shows the same flags.

* Plan

- The account and the party already point at their images: an account by its
  =image_id=, a party through its business centre, whose country holds the
  flag. Carry both through the domain types as =imageId= and =flagImageId=.
- Read the flags with two more reads per party page: the page's business
  centres by code, then their countries by code.
- The images belong to the tenant, so the BFF reads them inside it. A page of
  twenty photos must not cost twenty entries, so the page reads the images it
  names in its own visit and the BFF keeps them in a cache bounded by size.
  The browser then fetches each one by URL from that cache.
- The BFF image routes still sent the old request shapes (=image_ids= and
  =modified_since=), which the server no longer accepts. Replace them with one
  reader that lists images by identifier, and drop the image list route, which
  nothing called.

* Result

A tenant's people and parties now show faces and flags.

- *People.* Each row shows the person's picture, or their initials when they
  have none or the picture fails to load.
- *Parties.* A new *Business centre* column shows the centre's code with the
  flag of its country. The tenant administrator's own Parties screen has the
  same column, read as the session through =/api/images/:id=.
- *One entry per page.* The parties and people pages read the images they name
  in the same visit to the tenant. The BFF keeps them in a cache of 64 MB, keyed
  by tenant, and =GET /api/tenants/:code/images/:id= answers from it. An image
  the cache has let go is read inside the tenant again. A page whose images
  cannot be read is still answered.
- *Image reads fixed.* The BFF reads images with =assets.v1.images.list= by
  identifier. The old request shapes are gone, with the unused list route.

Acceptance is met: the BFF tests check the reads each page makes and that a
named picture is served with no second entry; the screen tests check the
pictures, the initials and the flags. BFF 135, web 231 and protocol 69 tests
pass. Not checked live: signing in needs the administrator's password.
