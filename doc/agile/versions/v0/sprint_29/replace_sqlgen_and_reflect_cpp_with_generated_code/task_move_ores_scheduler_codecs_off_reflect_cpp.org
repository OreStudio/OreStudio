* Acceptance

- ores.scheduler's generated types use the generated codecs.
- ores.scheduler's hand-written JSON uses the generated codecs or yyjson.
- Nothing in ores.scheduler includes reflect-cpp.
- ores.scheduler's suites pass, and its wire bytes match the bytes before the move.

* Plan

- Opt the job definition and scheduling operations models into the wire codec
  and regenerate. The module model is a =ores.codegen.module= and has no codec.
- Move the hand-written action payload types out of the two action handlers
  into =action_payloads.hpp=, give each =wire_fields= and a member-count
  guard, and read them through the struct codec.
- Add =shaped_wire_traits= to utility, so the NATS trigger and reply bodies go
  on the wire through their =wire_fields= and not through the reflect-cpp
  fallback of =wire_traits=.
- Drop the include-only reflect-cpp uses from two handler headers and the
  scheduler loop.
- Prove the payload bytes against reflect-cpp, and prove that the reads keep
  reflect-cpp's tolerance of unknown and absent optional members.

* Notes

** Hand-written wire types fell back to reflect-cpp

=wire_traits<T>= has a reflect-cpp primary template, and only generated types
specialise it. A hand-written type with =wire_fields= therefore still went on
the NATS wire through reflect-cpp. =shaped_wire_traits<T>= routes it through
the struct codec; a type opts in with one line.

** What stays for Remove reflect-cpp

=cron_expression.hpp= keeps =<rfl.hpp>= and its =rfl::Reflector=, and the api
library still links =ores.rfl.pch=. Four test files still include reflect-cpp
to compare bytes. [[id:7A1D09B8-B3F2-4E02-9669-3C2F6CC2C6EC][Remove reflect-cpp]] owns all of these.

expression reflector that Remove reflect-cpp owns. Its two models use the
generated codec, its action handlers read their payloads through the struct
codec, and its NATS bodies go on the wire through =shaped_wire_traits=. The
bytes match reflect-cpp's.
