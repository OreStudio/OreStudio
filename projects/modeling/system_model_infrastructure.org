This page is part of the [[id:D773166D-0C91-8CB4-3323-42166BC07687][System Model]]. Infrastructure owns the transport and
testing contracts. Everything above this layer speaks [[id:C9C24C99-F16C-45BE-A262-1C0F4502765E][ores.nats]]; this layer
provides the client, the service runner, the event bus, and the test fixture
that wires them together. See [[id:608675E1-4284-4902-99AC-4DA565390AFB][Entity lifecycle]] for how [[id:C9C24C99-F16C-45BE-A262-1C0F4502765E][ores.nats]] entities flow
across request/reply pairs.

** ores.nats

[[id:C9C24C99-F16C-45BE-A262-1C0F4502765E][ores.nats]] messaging backbone — client connection management, subject naming
conventions, queue groups, and JetStream configuration and lifecycle. The
primary inter-service transport used by every domain and application component.
See [[id:D9B0988E-D783-43D6-BCCD-CE2F70022B9C][NATS]] for the technology overview.

** ores.testing

Catch2 integration that isolates every test run into its own PostgreSQL tenant
inside the shared database. Each run provisions the tenant, wires up a
per-test logger and a database watchdog, and terminates the tenant at the end —
making tests safe to run in parallel without seeing each other's rows.

** ores.storage

The client half of ORE Studio's object storage. It moves files between a local
disk and an S3-shaped HTTP API that keeps objects under a bucket and a key: it
owns the =/api/v1/storage/{bucket}/{key}= path shape, a synchronous Beast HTTP
GET and PUT that stream file bodies rather than buffering them, a libarchive
=tar.gz= pack and extract, and the atomic and composite transfer helpers the
domain components call. It holds no bucket names of its own, so each caller
names its bucket — =ores.compute= its package bucket, =ores.ore= its import and
report buckets.
