* Acceptance

- A cold run with unreachable GNU archives installs all five site packages.
- A warm =.packages= tree makes =ores-site-ensure-packages= a no-op.
- Both site workflows restore and save =./.packages=.

* Plan

1. Add =ores-site--archives-usable-p=. It reads the refresh outcome from
   =package-archive-contents=, because =package-refresh-contents= only
   warns on a failed archive and never signals.
2. Add =ores-site--refresh-once= and =ores-site--use-archive-mirrors=.
3. Rewrite =ores-site--refresh-with-retries= to try the primary GNU
   archives first, then the mirrors.
4. Cache =./.packages= in =build-site.yml= and =site-cdash.yml=.

* Notes

Root cause: the site packages need =queue= and =compat=, which exist only
on GNU ELPA. The bootstrap fetched them on every run with no CI cache,
and =package-refresh-contents= only warns on a failed archive, so the
three-attempt retry never ran and the =queue= guard failed on the first
pass. An =elpa.gnu.org= outage therefore failed the build for its whole
duration.

Fix: the refresh now reads its outcome from =package-archive-contents=
and retries, then falls back to the BFSU mirrors. Both site workflows
cache =./.packages=, so a warm cache removes the network dependency
entirely.

The mirror is a supply-chain input, so it matters that Emacs checks the
archive signatures against the GNU keyring; a mirror cannot serve
different content.
