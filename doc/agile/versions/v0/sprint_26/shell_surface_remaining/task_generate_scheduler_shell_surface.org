* Notes

This is the one component in the story whose hand-written menu generation would
supersede if it could land. Five of the six verbs send exactly the requests the
generated units would send:

| Verb | Request | Generated unit that would answer it |
|------+---------+-------------------------------------|
| =scheduler jobs= | =list_job_definitions_request= | the =job_definitions= unit |
| =scheduler schedule= | =put_job_definition_request= | the =job_definitions= unit |
| =scheduler remove= | =delete_job_definition_request= | the =job_definitions= unit |
| =scheduler instances= | =get_job_instances_request= | the =scheduling_operations= unit |
| =scheduler status= | =get_scheduler_status_request= | the =scheduling_operations= unit |
| =scheduler watch= | none: it subscribes to the change event | nothing |

The units cannot land, because the component has no part under
=projects/ores.shell=. So the verbs are recorded rather than retired, and the
follow-up is named in both models: add the shell part, register its commands, then
enable the facet. Until that happens the generated scheduler surface does not
exist, which is a gap rather than a duplicate.

=scheduling_operations= unit can land, and the hand-written menu carries the whole
surface.

regeneration produces no diff.
