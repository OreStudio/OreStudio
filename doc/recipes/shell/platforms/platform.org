#+title: How do I run the platforms commands from the shell?
#+description: Every command the platforms submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:platforms:

This file documents the platforms resource at the shell, one section per command. Every command is a subcommand of =platforms=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: FEDEA36D-53A1-515D-9CC8-C810024B9FD5
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
platforms list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =compute.v1.platforms.list=.

#+name: platforms-list
#+begin_src ores-shell :tangle platforms-list.ores :exports none
platforms list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 0013B902-7326-5E95-A41A-C8D51E0D9935
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
platforms get <code>
#+end_example

It is addressed at =compute.v1.platforms.get=.

#+name: platforms-get
#+begin_src ores-shell :tangle platforms-get.ores :exports none
platforms get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: D3A03A9D-975C-53D7-BB70-F3C5EBFFE5AB
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
platforms add <id> <code> <display_name> <description> <os_family> <cpu_arch> <abi> <is_active> <reason> <commentary>
#+end_example

It is addressed at =compute.v1.platforms.put=.

#+name: platforms-add
#+begin_src ores-shell :tangle platforms-add.ores :exports none
platforms add 00000000-0000-0000-0000-000000000000 __none__ __none__ __none__ __none__ __none__ __none__ false system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: FEDB4798-4D92-59DE-B422-C8CF6C3B6C74
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
platforms set <id> <code> <display_name> <description> <os_family> <cpu_arch> <abi> <is_active> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =compute.v1.platforms.put=.

#+name: platforms-set
#+begin_src ores-shell :tangle platforms-set.ores :exports none
platforms set 00000000-0000-0000-0000-000000000000 __none__ __none__ __none__ __none__ __none__ __none__ false system.new_record generated_script
#+end_src
