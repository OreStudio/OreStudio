* Goal

* Plan

Decided on 2026-10-08: the checks are not a merge gate. A C++ change costs
a full build, a database recreate and every test suite, which is an hour or
more on a workstation, and gating merges on that makes the checks the slowest
part of the day. The suite runs about hourly instead, and its report is the
triage queue. This is the reverse of the position this task was written with.

* Result

The question this task asked -- nothing runs the gate -- is answered by
splitting verification from implementation rather than by hooking the gate into
a PR.

The implementing agent inspects the code and runs the checks that need no
build, then raises and merges. It does not build or run the suites. A scheduled
hourly validation in the =ores_dev_swift_curie= worktree builds latest main and
tests every change merged since the previous run, and owns the build lock while
it does.

Two memories record it: =merge_without_waiting_for_the_checks= for the merge
side, and =static_validation_only_the_hourly_run_builds_and_tests= for the
division of labour. Acceptance is met in substance and not in the letter: there
is no mechanism that stops a red tree reaching main, and by decision there is
not meant to be. A finding becomes its own task instead.
