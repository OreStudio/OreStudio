* Goal

A person working in ores.web should have exactly one place that knows how a timestamp is written, read and converted, and no way to hand-roll a second. The server should send every instant in the project's wire shape, independent of the process timezone, and the client should reject anything that is not that shape instead of trusting a bare string.

* Acceptance

- ores.web has one module that owns parsing a server wire timestamp (a space separator, a Z suffix and an optional one-to-six digit fraction), formatting one for the wire, and converting to and from a JS Date and a branded WireTimestamp; no other module reimplements any of them
- every time-valued field in the wire-protocol schemas is typed with that module's schema; none is a plain z.string(); absent values are modelled explicitly instead of passing an empty string that silently satisfies the type
- the server sends every instant in the project's wire shape: auth_event.event_time no longer travels as a database textual rendering, it is formatted by one named function at the boundary, and the emitted string is identical whatever timezone the reading session uses
- an endpoint test feeds a captured live payload through each schema, so server drift fails a test rather than a browser; and the shared module has unit tests for a fraction of six digits, one digit, no fraction, an absent value, a malformed value, an impossible calendar date, and timezone independence
- the work is ordered producer first, then field types, so a silent bug is not converted into a crash and each change can be attributed; the sweep names every endpoint it touched and every field it left alone with a reason
- doc/knowledge/architecture/time_architecture.org states the wire shape once, as the single source of truth, and the TypeScript and C++ references point at it rather than restating it

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

1. Server first. =auth_event.event_time= is a =time_point= in the
   operations protocol, the read renders it in UTC in the wire shape, and
   the handler converts through the shared =timestamp_to_timepoint=. The
   emitted bytes therefore do not depend on the reading session. Every
   other protocol field that still carries database text or a
   T-separated form is named under Notes, with the producer that owns it.
2. One web module. =packages/wire-protocol/src/time.ts= owns parsing,
   formatting, the branded type, the =Date= conversions and the Zod
   schema. =primitives.ts= keeps only UUIDs; no other module carries a
   second pattern.
3. Field types. Every wire-protocol field whose producer writes the wire
   shape is typed with the module's schema, and absence is =null= rather
   than an empty string. Fields whose producer does not yet write the
   shape are listed under Notes and left alone deliberately.
4. Tests. A golden payload captured from the live fleet is committed and
   parsed byte for byte; the module has unit tests for six digits, one
   digit, no fraction, absence, malformed values, impossible dates and
   timezone independence, and the server writer is pinned across a
   timezone change too.
5. Docs. =time_architecture.org= states the shape once; the C++ and
   TypeScript references point at it.

The earlier fix on =fix/the-accounts-wire-timestamp= (=e29fe5cbca=) was
reimplemented inside =time.ts= rather than cherry-picked. That commit
edits =primitives.ts=, which this change dissolves, so carrying it across
would leave two parsers during the move. Its captured live account
fixture is kept and extended by the golden test.

**Why the golden fixture is the contract**

The web's own round trip cannot catch drift: it would show that the parser
agrees with itself. The fixture is the raw reply the running fleet wrote, so a
change to the server's serializer changes the bytes, and recapturing it fails
the web test until the parser is shown to agree. Recapture with
=projects/ores.web/scripts/capture-wire-fixtures.ts=.

**Temporary client failure is expected**

Before the server's producer fix, =event_time= is not the wire shape, so the
strict web schema would refuse it. That is why the producer landed first: a
silent bug was not converted into a crash without the fix beside it.

** The remaining sentinels removed

- =session.end_time= is a nullable =timestamp with time zone=, not =text not
  null default ''=. The domain, entity and protocol hold
  =std::optional<time_point>=, and an open session has no closing instant.
  =GET /api/sessions= returns ="endTime":null= for the open session and
  ="endTime":"2026-10-17 22:09:39.000000Z"= for the closed one, both quoted
  from the same reply.
- The inbox's notification =raised_at=/=read_at= and a part's =decided_at= are
  =time_point=/=optional<time_point>=. The service reads the column through
  =from_db_string= and throws when a non-null column is null; it no longer
  writes the =to_char(... '"T"' ...)= spelling.
- The compute telemetry =sampled_at=, =start_time= and =end_time= are
  =time_point=; the handler no longer parses or formats them itself, and the
  wrapper no longer formats one with =std::format(...T...)=.
- Every instant in =packages/wire-protocol/src= is typed with
  =wireTimestampSchema= or =nullableWireTimestampSchema=. The 50 field
  declarations are listed by
  =git grep -nP "^\s+[a-zA-Z_]+:\s+(nullable)?wireTimestampSchema" -- 'projects/ores.web/packages/wire-protocol/src/*.ts'=.
- =wireTimestampOrAbsentSchema= is deleted: it admitted =''= as a second
  spelling of "no instant". =nullableWireTimestampSchema= is the only one.
- The screen helper no longer parses timestamps itself. It delegates to the
  wire parser, and a value that is not the wire shape is logged with its bytes
  and thrown.
- A change event and a published message that fail to parse are logged and
  thrown, not dropped. The transport logs the error that stops a subscription.
- The =timestamp_to_timepoint= ambiguity was not resolved by =06ddd7ed91=:
  the =std::string_view= call still selected neither overload and the branch
  did not build. The auth-event read now calls
  =datetime::from_iso8601_utc= directly, so the choice is stated.

** The four deferrals, now closed

Each of these was named as a workaround under this story's rule that no
sentinel stands in for an absence. None is deferred any more.

- =marketdata.feed_binding_activity= no longer spells "this source has not
  written" as empty text. =last_tick_at= is
  =std::optional<std::chrono::system_clock::time_point>= and =series_id= is
  =std::optional<boost::uuids::uuid>=, so a binding whose source has written
  nothing states =null= for both on the wire. There is no nullable column to
  change: the absence lives in the join, because the read asks for the source's
  newest observation and a source with none has no row to read.
- =@ores/contracts= gained the one owner through
  =@ores/wire-protocol/time=, a subpath export of =time.ts= that imports only
  Zod, so the HTTP contracts read the same schema the NATS protocol does and
  still carry no Node dependency. No copy of the pattern exists.
- =iam= auth-event and session-statistics =from_time=/=to_time= are
  =std::optional<std::chrono::system_clock::time_point>=: a bound the caller
  states no value for is =nullopt=, which binds as SQL NULL. The generated
  shell commands take the shell's absent token, the HTTP routes read the
  request as a JSON body, and the reads compare the parameter with =is null=
  instead of casting an empty string through =nullif=.
- =login_info.last_login= is a nullable =timestamp with time zone=. An account
  is created before anybody signs into it, so the domain, entity and protocol
  hold =std::optional<time_point>= and the record states =null= until the first
  successful sign-in. =isZeroTimestamp= is deleted: no screen has a zero
  instant to explain, because no writer produces one.
- Every instant in =contracts/= and =web/src/api/= is typed with the shared
  schema or its null union. The fields left as =z.string()= are named under
  Notes as what they are: org-mode dates, identifiers, enums and free text.

** Left alone, with the reason

- An empty =account_id= or =event_type= still means "this filter is off" in the
  auth-event and session-statistics reads. They are identifiers, not instants,
  and the same blank-string-means-unset idiom appears in every list request in
  the product (a search term, an order field, a page cursor). Changing it here
  would leave the rest of the estate on the old idiom, which is worse than the
  consistent line this change holds: an absent *instant* is null.
- =session_statistics_row.day= still crosses the wire as PostgreSQL's own
  rendering, =2026-10-18 00:00:00+00=, because the statistics read selects
  =day::text=. It carries no absence, so no sentinel is involved, and the day
  bucket is a calendar day that the screen prints as one. Making it a wire
  instant changes what the audit screen draws, which is a screen decision of its
  own; it is named here rather than left silent.
