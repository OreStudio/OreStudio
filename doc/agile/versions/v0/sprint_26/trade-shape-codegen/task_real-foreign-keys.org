* Acceptance

- A foreign key marked to be enforced renders a REFERENCES constraint and no trigger check.
- The generator refuses an enforced foreign key whose target is temporal.
- A test shows the database rejecting a row whose key names no target row.

* Plan

- Add =:enforce: true= to a node under =* Foreign keys=. The generator
  reads the target table's model and refuses the flag unless that model
  is immutable.
- An enforced key renders a named constraint,
  =<table>_<column>_fk foreign key (column) references target (target_column)=,
  in both the temporal and the current-state table bodies. It sets
  =skip_check=, so the trigger check for that column is not generated.
- Keys over several columns belong to the composite pinned keys task.

* Result

- A foreign key node with =:enforce: true= renders a named =REFERENCES=
  constraint and no trigger check. A node without it stays a trigger check.
- The generator refuses =:enforce:= when the target model is not immutable.
- Four tests in =projects/ores.codegen/tests/test_enforced_foreign_key.py=
  cover the constraint, the absent trigger check, the unenforced key and the
  refusal.
- In Postgres, a rendered parent and child ran in a transaction that rolled
  back. An insert that named an unknown anchor was refused with SQLSTATE
  23503 by =ores_testcomp_child_records_anchor_id_fk=. An insert that named
  a known anchor was accepted.
- The SQL meta-model page and the variability index now document
  =:immutable:=, which the previous task added. The meta-model page also
  documents =:enforce:=.
