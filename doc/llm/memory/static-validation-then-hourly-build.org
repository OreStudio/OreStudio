#+title: Memory: Every environment builds and tests its own tree
#+description: Each environment compiles and tests its own changes with compass before it opens a pull request; no environment relies on a shared validator. Tune the build's job count to the box, never above five.
#+type: memory
#+memory_subtype: project
#+level: cross
#+filetags: :memory:project:
#+created: 2026-10-09
#+updated: 2026-10-09

Each environment proves its own change. A task is not done until the environment that wrote it has compiled the targets the change touches with compass build, and run the suites it touches. The shared hourly validation environment is gone, so nothing else will catch a compile error or a broken suite. Pick the build's -j from how busy the box is, and never go above 5.

*Why:* The hourly validation environment failed, so every environment was landing changes nothing had compiled. The rule that feature agents validate statically was set on 2026-10-08 and reversed on 2026-10-09 once the validator proved unreliable.

*How to apply:* After implementing a task, before opening the pull request: check the box load, run compass build for the targets the change touches with a -j suited to that load and never above 5, then run ctest for the suites it touches. A schema change still needs compass db recreate first, because the test binaries refuse to start when the schema fingerprint does not match. Record the build target list, the job count and the suite results in the task's Result, so a reader can tell what was proven and what was not.
