It checks the screen as it now stands. A pass means every step held on the running system and every edit was visible after a reload.

* Before you start

The session already did the following. Confirm the system is in this state; do not repeat the work.

- The build is current for the branch this scenario is being run against, and the database was recreated and seeded on it.
- Acme Corporation is provisioned. The account =tenant_admin@acme_corporation= works in five parties; the tenant has 24 pricing configurations and 7 engine settings.
- The HK party holds the configuration this scenario opens, *XVA Overnight*, with 5 products.
- All 24 services are active and the web answers on =http://localhost:21002=.
- You need =tenant_admin@acme_corporation= / =Secure-Password-123=. Choose *ACME Corporation HK Ltd*.
- Use throwaway values for edits; the scenario only checks that an edit is written and reaches the history.

* Notes

- The page is read only until you choose Edit. A change is never made in a field on the page.
- Every parameter carries a label, a help line, a format and the XPath of its leaf. A parameter the contract does not hold says so.
- The model and the engine are choices from the vocabulary; a pair the vocabulary does not hold is marked and never refused.
- The Simple and Advanced choice is remembered for the whole screen family.
- The party filter, the document history, the product names in words and the shared control are the changes since the last run. The previous run's findings are closed.
