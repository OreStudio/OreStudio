* Plan

The id belongs to =doc/knowledge/journeys/reporting/journey_look_back_over_a_reports_history.org=.
It was defined in lower case, and two of its five links were upper case, so the
export could not resolve them:

#+begin_example
doc/knowledge/journeys/conventions/journey_change_the_convention_for_one_kind.org:313
doc/knowledge/journeys/reporting/journey_change_what_a_report_runs.org:436
#+end_example

=doc/meta/document_types.org= requires uppercase hex for the =:ID:= and for
every =[[id:UUID]]= link, so the definition moves up to match the other three
links rather than the links moving down.

Review round 1 corrected two claims this task first carried:

- "=site-page= publishes only the pages a change touches, so a broken link in an
  untouched page never gets exported by it" was true but irrelevant: the two
  links landed in commits that changed their own pages, and publishing either
  page with the upper-case link fails the same way. =site-page= would have
  caught it.
- "=org-links= checks links, but not whether an =id:= link matches by case"
  overstated it: =org-links= only follows colon-prefixed targets and never
  resolves an =id:= at all. =lint= does compare ids, but uppercases both sides
  first, so it is blind to case. That is the real gap, and it is why the tree
  reached a state where a definition and its links disagreed.

* Notes

The failure only appears in a full build. That build is the =deploy_site=
target, which =compass check= does not run, so a gate sweep never sees this
class of break; the page-level gate only sees the pages a change touches.
