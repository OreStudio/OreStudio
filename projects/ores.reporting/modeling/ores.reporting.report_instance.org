A single execution of a report_definition. Created automatically when the
scheduler fires a trigger for an active definition.

Lifecycle is managed through the report_instance_lifecycle FSM machine.
fsm_state_id points to the current state in ores_dq_fsm_states_tbl.

started_at is NULL when the instance is cancelled or skipped before execution
begins. completed_at is NULL while running or in a terminal-before-start state.

** kind
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:default:  production
:default_value: "production"
:filterable: true
:END:

What this instance does: =production= prepares the input, computes it on the grid and
records the results, and =package= prepares the input and stops, so that its packages
can be inspected and run locally. Refers to ores_reporting_report_instance_kinds_tbl.
The scheduler creates =production= instances only, the concurrency policy of the
definition counts them only, and a list shows them unless the caller asks for another
kind.

** run_grant_id
:PROPERTIES:
:type:     uuid
:cpp_type: std::optional<boost::uuids::uuid>
:nullable: true

The IAM run grant that this run acts under, copied from the definition whatever
admitted the run: an on-demand trigger and a scheduled one reach the same
admission. The instance records the grant id so that a later change to the
report's consent cannot change the authority of a run that is already in
flight. IAM owns the grant, so this column is not a checked foreign key.

** trigger_id
:PROPERTIES:
:type:     uuid
:cpp_type: boost::uuids::uuid
:nullable: false
:END:

The trigger that admitted this run. Every instance has one: a run a person asks
for and a run a schedule asks for are admitted the same way, and the database
enforces that this names a trigger. The generated instance names its own uuid as
the trigger, so the trigger it points at is derived from the instance rather
than minted beside it, and a fixture that writes one can write the trigger row
it names from the instance alone.

Report instance kinds are a system-wide lookup seeded for the system tenant only, so
the check reads that tenant whatever tenant owns the instance.

** trigger_id
:PROPERTIES:
:table:             ores_reporting_report_trigger_events_tbl
:enforce:           true
:nullable:          false
:error_message:     Invalid trigger_id: %. No report trigger found with this id.
:END:

A trigger row is immutable, so the database can hold this as a real foreign key
rather than a trigger check, and it does: every instance names the trigger that
admitted it.

The eventing integration test writes the trigger the instance names before it
writes the instance, because the constraint admits no instance without one. The
seed asks the fixture for the trigger row a generated instance names, so the
instance keeps the uuid the generator gave it and the trigger is derived from
the instance rather than minted beside it.
