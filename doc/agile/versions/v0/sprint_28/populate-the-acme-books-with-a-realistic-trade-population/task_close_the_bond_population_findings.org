* Notes

Open items, not done here:

- A cut-short issue is repaired by a run that writes a new trade of that
  security. A run whose trades are all booked does not revisit the issue. No
  run cut an issue short on a database.
- The writer has no automated test against a database. The repair of a trade
  is proven by hand on a provisioned tenant and by the planner tests with a
  recording writer.
- Pricing is not proven. The ORE validator found no quotes for the as-of date.
- The pool is thin: 32 trades over 20 securities. This is a choice of the
  config and of the tenor band, and not a defect.

* Result

A trade that a run booked without its bond instrument is now repaired. The
writer reads whether the trade has an instrument. When it has none, the writer
takes the activity from the Internal identifier of the trade and writes the
instrument. When the trade has no identifier either, the run stops and names
the trade.

On a provisioned tenant I closed the instrument of one trade by hand. The next
run wrote 1 instrument and left the other 31 trades alone. The run after that
wrote 0.

The test that found two books sharing a security by the draw of the seed now
fixes the tenor to five years, so every slot has the same security. Two new tests
cover the repair and the stop.
