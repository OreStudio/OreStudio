* Acceptance

- Continuous Linux no longer enables code coverage.
- Continuous Linux no longer builds the package target.
- The Nightly Build still runs coverage and memcheck.
- The nightly and tag runs still produce their packages.

* Plan

Take coverage and packaging off the continuous run. Coverage both
instruments every translation unit and walks the tree with gcov after the
tests; packaging invokes cpack. Neither proves anything a continuous run
needs, and both already run nightly.

* Notes

** What coverage costs

=code_coverage=1= makes CTest.cmake set =-DWITH_PROFILING=On=. Then
=projects/CMakeLists.txt= appends =-fprofile-arcs= and =-ftest-coverage=
to =CMAKE_CXX_FLAGS=, so every C++ translation unit in the tree is
instrumented. The run also executes =ctest_coverage=, which walks the
whole tree with gcov. Both are real cost, and the Nightly Build already
runs =code_coverage=1,with_memcheck=1=.

** What packaging costs

The build target was =package=, so every continuous release job ran cpack
to produce a =.deb= that nothing consumes. No workflow downloads it: the
=download-artifact= search above returns nothing.

** How the new flag works

CTest.cmake turns every =key=value= in its script argument into a CMake
variable. The new =package= flag defaults to on, so the nightly and tag
runs are unchanged. =continuous-linux.yml= passes =package=0=, which
switches the build target to =all=.

** The decision block is verified on its own

=build/output/pkg-flag-check.cmake= copies the decision block and asserts
the target it selects for seven callers. All seven pass. The continuous
jobs select =all=, the nightly and tag callers still select =package=,
and the Windows and macOS debug path still selects =all=. The script is
a scratch file, so rerun it before the check on a fresh tree.

** Where the continuous job's time actually goes

The last green linux-clang-release job ran 2h54m13s and reports
=Total Test time (real) = 309.26 sec=, with 71 of 71 suites passing. The
configure and the build take the other 2h49m. The suites are about three
per cent of the job, so sharding them across jobs, or moving them out of
the build job entirely, cannot recover meaningful time. That measurement
closes the third item of the objective this story was raised against.
