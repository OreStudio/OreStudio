* Acceptance

- Each of the 18 remaining composites has a root CMakeLists.txt that adds its parts and nothing else.
- projects/CMakeLists.txt contains one add_subdirectory per composite instead of one per part.
- CMake configures clean and every part's translation units still appear in the compile database.
- Dependency order is preserved where a part was deliberately registered away from its siblings, such as ores.history api and core.

* Plan

Take a baseline first. A build-wiring change cannot be read for
correctness, so the only useful evidence is that the configuration
comes out the same afterwards. The target set and translation-unit
count were captured before anything moved.

Collapse mechanically rather than by hand. Each component takes the
position of its first part and keeps the part order it had, which
preserves any deliberate ordering without having to know why it was
deliberate.

* Result

All four acceptance criteria are met, and the codegen half the
operator asked for is done with them.

=projects/CMakeLists.txt= adds components rather than parts: 91
entries become 39, one per component. Each of the 19 remaining
composites gained a root =CMakeLists.txt= that adds its parts and
nothing else, joining =ores.analytics= and =ores.eventing=.

The scatter this removes was real. =ores.history= registered =api= at
line 5 and =core= at line 23; =ores.telemetry= spanned 37 lines.
Ordering is preserved by construction: each component sits where its
first part sat and keeps its internal order, so =ores.ore='s
core-before-api survives.

Codegen generates the file now. =ores.cmake.component.composite_root=
declares =#+component_kind: composite=, the kind no archetype claimed
— the loader described a composite as generating nothing from either
facet by design, so the one file it does own had nowhere to come from.
Part order is declared in =#+parts:= rather than derived, because
alphabetical is wrong for =ores.qt=, which needs =headless= and =api=
ahead of the plugins that link them, and for =ores.eventing=, which
lists =modeling= among its parts.

Verification is a comparison, not an inspection. CMake configures
clean with no errors, and the target set is identical to the baseline:
93 directories and 3957 translation units, none missing and none new.
The generator reproduces all twelve declared composites' roots
byte-identically, =check_component_drift.py --all= passes, the audit
passes at 43 components, and the codegen suite passes at 180 tests.

A composite's parts are checked against the disk. The root renders one
=add_subdirectory= per declared part, so a part omitted from
=#+parts:= would stop being built with nothing to report it —
configure cannot fail over a directory it never hears about, and the
drift check would compare against the same wrong model. Review found
that gap and it is now a hard error.

The drift gate earned its place during this task. My hand-written
licence headers wrapped differently from the generated ones, and the
gate failed on exactly that before anything was pushed.

Eight composites — =ores.assets=, =ores.http=, =ores.marketdata=,
=ores.ore=, =ores.qt=, =ores.synthetic=, =ores.telemetry= and
=ores.variability= — have no group model, so codegen has nothing to
generate their roots from and those stay hand-written. Filed as
[[id:9747E4C5-734E-4F75-AD8B-CEB4C9089B76][Give every composite a group model]].
