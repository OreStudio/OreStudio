* Goal

The story claims a 256 MiB upload costs less than 1 MiB of resident memory. Nothing
measures it, so nothing would notice if streaming regressed to buffering.

* Acceptance

- A test uploads 256 MiB and reads the gateway process's peak resident memory across
  the request.
- The peak moves by less than 1 MiB.
- The grid wrapper's transfer tests pass against the streamed routes.
- The measurement names the commit it ran at.

* Plan

1. Read =VmHWM= from the test process instead of sampling, so the peak is the kernel's
   own number and not a poll that can miss it.
2. Upload 256 MiB that the test generates in chunks, so the client does not hold the
   object either.
3. Assert the delta, and fail with both numbers so the regression is legible.
4. Run the wrapper's transfer tests and record them.
