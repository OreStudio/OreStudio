* Plan

These are the first composed views ores.http serves, so this task also sets
how a view meets the design's four obligations (design section 11.1).

| View | Address | Computation | Cache policy |
|------+---------+-------------+--------------|
| The calibration of an asset class | =GET /api/synthetic/calibration/{assetClass}= | one resolution call, and a read of the policies for the row's version when the class has one | none: =no-store=, a resolution reads the newest fixings |
| The market trace | =GET /api/synthetic/market-trace= | one trace call | =ETag=, fresh for 10 s |
| The synthetic folder tree | =GET /api/synthetic/feed-folders= | one folder call; the service counts | =ETag=, fresh for 60 s |

Decisions:

- *Name and owner.* Each view keeps the BFF's address, as the earlier ports
  did, and its rule in the inventory keeps the view's name, so its obligations
  are stated once. Each lives in the route unit of the screen that calls it, in
  =ores.http.synthetic=: the calibration view beside the calibration actions,
  the trace beside the market regime, the folder tree beside the feed screen.
- *Schema.* Each view is a model type with =wire_fields=, published through the
  route's =response<T>()= and written by the JSON codec, so the schema and the
  bytes come from one model. A pure function builds each view from the
  service's reply, so a test checks the member names the screen reads.
- *Cache policy.* =ores.http.api= gains =view_answer=: a view with a freshness
  rule carries a strong =ETag= over its bytes and =Cache-Control: private,
  max-age=N=, and a request whose =If-None-Match= names the tag answers 304
  with no body. A view with no freshness rule is =no-store=. The gateway keeps
  no copy: the caller's cache holds the view, because each caller's session
  decides what it holds.
- The codec leaves out an empty optional, so the calibration view states no
  =version= for a class with no policy row, where the BFF stated null. The
  published schema already marks it optional, so the screen's schema reads a
  missing version as null; a web test proves both answers read the same. A
  codec type that always writes null would change every component's codec,
  which one member does not earn.
- The synthetic part links =ores.synthetic.api= publicly, because the views'
  model types in its headers hold that component's messages.
- The views refuse what the BFF refused: an unknown query parameter on the
  trace and the folder tree, an asset class or a feed that is not well formed.

* Result

The three synthetic composed views are served by ores.http at the BFF's
addresses, each a published model with its computation and cache policy stated
on the route. =view_answer= gives every later view its =ETag= and freshness
rule. Tests prove the tag, the 304 and the =no-store= answer, the coverage
counts, the member names each screen reads, and each view's refusals.

views live in the synthetic part's route units and the cache answer in the api
part's =net=; =validate_docs.sh= is run before the pull request.
