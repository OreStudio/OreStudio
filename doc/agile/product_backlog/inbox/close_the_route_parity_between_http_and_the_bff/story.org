* Goal

Every route the BFF answers has an equivalent on =ores.http=, and the
behaviours a side-by-side probe of the two servers found different are settled,
so =ores.web= can leave the BFF behind for good.

The acceptance of the story this one continues is met except where the tasks
below say otherwise; the parity was moved here from
[[id:21323568-8E87-4858-98E1-77451E123965][Serve what the BFF serves, then retire it — the remaining work]]
when that story closed on 2026-11-24, shipping 67 of its 82 tasks and moving the
remaining 15 here.

* Acceptance

- [ ] Every composed view the BFF answers is answered by =ores.http= with its
      name, schema, owner, computation and cache policy.
- [ ] The twelve routes the BFF read from the checkout's doc tree are served
      over the org page read, not from the files.
- [ ] HEAD is answered wherever a GET is served.
- [ ] Every generated HTTP recipe sends the body or the parameters its route
      requires, and a check keeps the corpus that way.
- [ ] The differences a probe of the two servers finds — the answer shape, the
      error contract, the session's token, the payload cap — are each closed or
      recorded with the reason they stand.

* Decisions

- *The twelve file-backed routes are not the gateway's* (2026-11-21, task
  46F3605C). Each reads or writes the checkout the server runs in, and a
  deployed gateway holds no checkout, so their owner is the developer tooling.
  Four of them write into the repository, which settles it.
- *A recipe's request is compass's to compose, not this repository's*
  (2026-11-25, task 60BBB3B1). =doc/recipes/http= and the Hurl corpus are both
  written by compass-ng from the entity models, so the missing body cannot be
  fixed here: it needs a compass-ng change and a release. The handover in
  =evidence/compass_handover_send_the_request_body.md= states the change, the
  data contract this repository's template will consume, and how to prove it.
- *These routes take a DELETE's intent as query parameters, not a body*
  (2026-11-25). The generated route registers =.no_body()= and requires
  =reason= and =commentary= in the query, so a DELETE recipe that sends only a
  body still answers 400. The task and the handover carry this; it corrects the
  task's original count of body-carrying methods.
- *A HEAD belongs to the router, not to each route* (2026-11-25, task FC74EFF3).
  Every GET is answered over HEAD from the router's own matching, because the
  session already knew how to send the headers without the body and a second
  declaration per route would double the route table, the inventory and the
  OpenAPI document for a method every client assumes. A path served only by a
  write still answers 404 to a HEAD.
- *The gateway writes one refusal shape* (2026-11-25, task CDEBF21E). Every
  refusal the HTTP layer makes answers ={code, message}=, with the codes the
  browser's own enum states, and the ={"error"}= shape is deleted rather than
  left for the next call site to reach. The session's three cases are named
  apart: =invalid-credentials= for a refused credential, =session-expired= for a
  cookie the server no longer holds, =not-authenticated= for none at all.
- *A read is designed data-oriented* (2026-11-25, task 16F7691D, direction of the
  product owner). Load the data a transformation needs in one batch bounded by
  resources, process it in large collections with standard algorithms, and write
  back in batches with as few transactions as possible. For a composed view that
  means one bulk read of the fact set — not a page per entity — and the join in
  the gateway's memory over sorted collections. The coverage view's 284 forwards
  for 142 series are the worked example of what the rule forbids.
- *The service counts and the gateway joins* (2026-11-25). A composed view's
  aggregate is the owning service's, answered as a vector in one call; the
  gateway joins it to what else the view needs in one pass. A service is not
  asked to shape a screen's answer, and the gateway is not allowed to compute by
  looping over entities.
- *PostgreSQL is considered for each aggregate, and not assumed* (2026-11-25).
  For the coverage read a SQL function, a view and a continuous aggregate were
  each rejected on measurement — the function and the view change no plan, and a
  continuous aggregate would hold as many rows as the base table because the
  data is already one row per series-day. A projection table is the strongest
  PostgreSQL-side answer and is *deferred with a trigger*: add it if the read is
  measured above 200 ms at p95 or a second reader needs the triples, with a
  refresh on both write paths and a drift gate. The reasoning is on the task.
- *A transport that cannot verify believes nobody* (2026-11-25, task 12666A97).
  A message bus with no verifier refuses the request rather than handing it the
  service's own context, whose absent role list authorises everything. The two
  other fallbacks — an empty permission list, and a protected HTTP route on a
  server with no verifier — were already closed, and the task records where.
- *A BFF shape is recorded once and replayed, not compared live* (2026-11-25, task
  CAC61239). The BFF is being retired, so a check that needs both servers stops
  working exactly when it would matter. The BFF's answers are recorded into a
  corpus beside the check — status, member names, nesting and types, no values —
  and the check replays the same requests against the gateway. A pair is compared
  or skipped with its reason, and a pair the corpus does not name fails: the
  coverage is a reviewable artefact rather than a sample. Three facts about the
  data are not facts about the answer and do not count as differences: nullability
  within a page, a member null in every row, and an array no row filled.
- *A difference that is another route's defect is captured, not excused* (2026-11-25,
  task CAC61239). The sweep found the public rates coverage answering no series
  where the BFF answered 142 — the gateway reads the durable fixings table and
  the deployment holds none. The exception names the capture that tracks it
  (2C4E2094), so the gate stays green while the question of which store owns the
  coverage is open, and the exception goes when that capture is answered.
- *The bus cap is transport capacity, and the limit is the validator's* (2026-11-25,
  task 820AC660). The image upload died in the transport before the validator
  could answer, because the bus took the NATS default of 1 MiB and a 2 MiB image
  is 2.8 MB on the wire once base64 has grown it. The cap is now 4 MiB, which
  carries the largest image the validator accepts; the image limit stays where it
  was, in the validator, and the gateway applies that same validator before it
  sends anything, so a refused image never travels. One number states the image
  limit, and the picker reads it from the validator through the policy route.
- *An image stays in the assets record for now* (2026-11-25, task 820AC660). The
  product direction was that an upload larger than 1 MB travels over HTTP
  storage. The tree cannot do that for images yet: the bytes live in the assets
  table, the storage service and the gateway keep their objects in different
  directories, and the read that returns an image still crosses the fabric, so
  moving only the upload would break the journey at its other end. *Deferred with
  a trigger*: move the bytes out and carry a reference if the image limit must
  grow past what the bus can carry, if the bus cap must stay small, or if the
  read path starts returning larger images.
- *A composed view's fact set is read in batches, and the batch read belongs to
  the service that owns the fact* (2026-11-25, task 3E187C09). The calibration
  read's IR coverage joins four collections, and the newest published set of a
  curve is one of them. Asked one curve at a time it is one round trip per
  curve — 38 in today's data, one more for every curve the catalogue gains — so
  it is a batch operation that answers the whole set in one statement, and the
  gateway joins it in memory. Measured, the view is five forwards whatever the
  number of currencies; the BFF made 41 on the same data.
- *A member the BFF omitted is answered empty, not absent* (2026-11-25, task
  3E187C09). The BFF states =ir_curves= only for interest rates and leaves it out
  for every other class; the gateway's codec writes every member, so it answers
  an empty list. The screen's schema already defaults the member to an empty
  list, so the two read alike, and the shape sweep compares a defaulted member
  against its absence rather than treating it as a difference.
- *A permission check is the handler's, and the gate must read it* (2026-11-25,
  task CCB1D9D1). Nothing gates a hand-written handler: the codec checks only
  that the codes handlers use are seeded, so a handler that checks nothing
  passes. The census found 48 of them, and widening the gate's registry turns up
  102 unseeded codes, so the rule, the seeds, the grants and the registry widen
  together or not at all. The gate's rule needs a compass release; its registry
  does not.
- *A composed view states the time it may take* (2026-11-25, task 16F7691D). The
  NATS client waits thirty seconds per request, longer than the HTTP server's
  idle timeout, so one silent service took a socket down instead of answering.
  A view now opens a budget at its first read and passes what is left to each
  forward; a read past the time, or a reply that never came, answers =504=
  =upstream-timeout= in the error contract.
- *The bundle is served from the directory it lives in* (2026-11-25, task
  3F1B0A52). The manifest is a snapshot taken at startup and the files are read
  from disk, so a publish under a running gateway is reconciled on the read
  path: a path the snapshot lacks is asked of the directory, and nothing is
  written back, so no session pays for a lock. The alternative — rescanning the
  directory when the index changes — would lock the table every request reads
  and rescan hundreds of files because one changed.
- *A recipe proves the wiring, not the data* (2026-11-25). A well-formed write
  reaches the service and may come back refused because the row it names does
  not exist; the corpus's own =HTTP 200= line is therefore a claim about wiring
  only. Making every recipe pass needs a seeded fixture set, which is a
  decision this story does not take.
