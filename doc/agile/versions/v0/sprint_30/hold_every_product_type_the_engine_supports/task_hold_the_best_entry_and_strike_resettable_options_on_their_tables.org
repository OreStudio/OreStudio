* Goal

their terms as columns, beside the generic ScriptedTrade form the scripted
table holds.

* Acceptance

- each of the four types routes to a table of its own (one table may serve an equity
  and an fx pair that state the same element), whose columns hold every scalar term the
  element states; lists, baskets and schedules are rows of child tables or of
  the shared rows (options, barriers, underlyings, schedules)
- the projection reads and writes the element from those rows, value for value,
  and a round-trip test reads ORE's or the user guide's example and writes it back
- the builder states the rows, and the generator books the element form
- the class-read entry for the type is removed: the scripted instrument table
  holds no element form of it, only the generic ScriptedTrade form where ORE's
  library carries one
- the catalogue names both forms of the type where ORE carries both
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: nothing is held as text

* Plan

Four tables, one per type per family. ORE states each element in one shape for
both families (=bestEntryOptionData2= and =strikeResettableOptionData2=), so
one projection header, =entry_reset_option_projection.hpp=, reads and writes the
scalars for both. The schema requires every scalar, so every column is
required.

- Best entry: long/short, currency, notional, multiplier, cap, strike, trigger
  level, reset minimum, premium and the four dates are columns. The underlying
  is an underlying row; =StrikeObservationDates= is a dated schedule row under
  the role =strike_observation_schedule=.
- Strike resettable: long/short, option type, currency, strike, reset strike,
  quantity (a double, as a continuous quantity), trigger type, trigger price,
  premium and the three dates are columns. The underlying is an underlying row;
  =ObservationDates= is a dated schedule row under =observation_schedule=. Its
  tables are named =*_strike_reset_option_instruments= to fit the identifier
  budget.
- The builders move from =scripted_builders= to
  =entry_reset_option_builders= and return the family's rows; the planner books
  the element form. The class-read entries are removed.
- The catalogue names =BestEntryOption= as the scripted form of both best-entry
  types. ORE's library has no strike-resettable script, so those types are held
  in their own form only.

* Result

The four types are held natively, each on a table of its own:
=equity_best_entry_option_instruments=, =fx_best_entry_option_instruments=,
=equity_strike_reset_option_instruments= and =fx_strike_reset_option_instruments=.
Every scalar the element states is a column; a strike-resettable quantity is a
double, as a continuous quantity. The underlying is an underlying row, and the
observation dates are a dated schedule row. The projection reads and writes
them, and the round-trip test covers ORE's FX example of each plus an equity
trade of each. The builders return the family's rows, and the generator books
them. The class-read entries are removed. The catalogue names =BestEntryOption=
as the scripted form of the best-entry types; ORE's library has no
strike-resettable script, so those types have only their own form.
