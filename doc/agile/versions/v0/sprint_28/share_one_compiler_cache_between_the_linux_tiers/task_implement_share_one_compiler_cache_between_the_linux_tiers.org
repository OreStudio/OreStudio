* Acceptance

- Both workflows use the same cache key for a given variant, with no workflow prefix.
- The prune leaves one entry per variant whichever tier runs it.
- Every remaining difference between the tiers is stated and shown not to change a compile line.

* Plan

Drop the scope in all four places a key appears in each workflow: the restore
key, the restore-keys prefix, the save key and the prune prefix. Remove the
transitional legacy restore-key from Continuous, because with the scope gone it
is the same string as the primary prefix and would be a duplicate.

Then prove the two workflows agree by resolving them rather than by reading them:
parse both files, substitute one matrix value, and compare the resulting keys.

* Notes

The transitional line had to go rather than stay: it existed only because the
scoped prefix was new and the old entries were worth one last restore. With the
scope removed, the primary restore key *is* that old prefix, so keeping both
would list the same string twice.

Nothing was deleted to make room. Reverting the prefix re-adopts the two legacy
entries as the variant caches, and the first save that lands replaces them
through the prune.

* Result

Both Linux workflows now use one key per variant, with no workflow scope in the
restore key, the restore-keys prefix, the save key or the prune prefix. The
transitional legacy restore-key is gone, because the primary prefix is now the
same string.

The two tiers were proven to agree by resolving the keys from the parsed YAML
with one matrix value substituted: restore key, save key, restore-keys and prune
prefix are identical, and the debug key resolves to
=sccache-linux-clang-debug-ninja-<run_id>=. The one setting that can move a
compile line, =code_coverage=, is on for debug and absent for release in both.

The four duplicate caches that scoping created are gone by construction: there
is now one entry per Linux variant rather than one per variant per tier, which
is the space that pays for the gcc variants when they move into continuous.
