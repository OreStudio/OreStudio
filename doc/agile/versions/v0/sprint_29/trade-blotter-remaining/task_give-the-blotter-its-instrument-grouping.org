* Notes

from the house tokens in =marketdata/assetClassColour.ts=, so the rail reads like
the market data screens. Nothing reads the data-quality badge catalogue, which
also holds an =asset_class_*= row for each class: it files those rows under a

* Result

The blotter reads its third way. The rail offers *Asset class* beside *Portfolio
tree* and *Counterparty*, and choosing it redraws the same rows under the classes
they fall into, each node carrying the class's own name, the house colour dot and
its count. Choosing a class narrows the list to it.

The class comes from the instrument's trade type, through the instrument code
catalogue the read already fetches: no model change, no second read. A structure
has no class, so the rail counts the classed trades and its nodes add up to that
figure, which is why a party's 57 rows show 45 under six classes.

The read serves the grouping in one pass — the same rows, resliced — and the
screen caches the rail separately from the list, so switching views draws at once
instead of waiting or showing the previous grouping's nodes.

Two questions were left open rather than answered inside the blotter, and both
are captured in the inbox: whether the data-quality badge catalogue should be the
one source for a class's colour when it files classes under a severity that means
nothing, and the three spellings the same class code has today.
