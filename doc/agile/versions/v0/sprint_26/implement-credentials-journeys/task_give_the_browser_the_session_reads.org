* Notes

- *An empty active list is the server's answer.* The handler behind
  =iam.v1.sessions.active= replies ={success: true}= with no rows, so the route
  answers ={sessions: []}=. Reporting a failure would break the screen the day
  the handler starts answering, and reporting nothing would hide that the read
  is a stub: the screen says so instead.
- *The count is the wire's =total= again*, as on the accounts page, because IAM
  names it that way and other components do not.
- *No authenticated live call this time.* The database was recreated for the
  previous task, and the fresh one holds no human account whose password is
  known to me — only seeded synthetic users and service accounts — so the live
  check here proves the routes are registered and gated (401, and 404 for a path
  that does not exist) and the behaviour is proven by the route tests. A
  signed-in call should be added when a seeded test account exists again.
