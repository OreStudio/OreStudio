#+title: How do I run the folders commands from the shell?
#+description: Every command the folders submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:folders:

This file documents the folders resource at the shell, one section per command. Every command is a subcommand of =folders=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 97BC6A2D-E765-573A-B42D-1B9E5EE0453F
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
folders list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =synthetic.v1.folders.list=.

#+name: folders-list
#+begin_src ores-shell :tangle folders-list.ores :exports none
folders list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 3C6CCE1B-26BF-5F0A-A3F8-879777A07A32
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
folders get <id>
#+end_example

It is addressed at =synthetic.v1.folders.get=.

#+name: folders-get
#+begin_src ores-shell :tangle folders-get.ores :exports none
folders get 00000000-0000-0000-0000-000000000000
#+end_src

** =add=
:PROPERTIES:
:ID: 73406BFF-0351-57D1-880B-5F00B725E75D
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
folders add <parent_id> <name> <kind> <collection_id> <reason> <commentary>
#+end_example

It is addressed at =synthetic.v1.folders.put=.

#+name: folders-add
#+begin_src ores-shell :tangle folders-add.ores :exports none
folders add __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 2BED276A-38C7-5DD7-B30F-5B8434675170
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
folders set <id> <parent_id> <name> <kind> <collection_id> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =synthetic.v1.folders.put=.

#+name: folders-set
#+begin_src ores-shell :tangle folders-set.ores :exports none
folders set 00000000-0000-0000-0000-000000000000 __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src
