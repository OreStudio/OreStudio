* Goal

A checked-in fixture states, for every ORE key form and every distinct corpus
key, the fields ORE's own =parseMarketDatum= assigns. The new codec is tested
against it. Without it, every round trip compares text with text, and a token
in the wrong field passes.

* Acceptance

- An offline harness, linked against the local =libOREData.so=, reads each key and writes the instrument type, the quote type and every field the =MarketDatum= subclass exposes.
- The input holds every form documented in =OREData/ored/marketdata/marketdatumparser.cpp=, with at least one key per form, plus every distinct key in the corpus market payloads.
- The input also holds keys that ORE rejects, each with ORE's error.
- The fixture, the input list and the harness source are checked in. A recipe states how to rebuild the fixture against a new ORE release.
- The ORE version the fixture came from is recorded in the fixture.

* Plan

1. List every form in =marketdatumparser.cpp=, one key each, with the ORE
   line that reads it.
2. Write the harness as a small tool outside the main build, because the main
   build does not link ORE.
3. Run it over the form list and the corpus keys; check in the output.
