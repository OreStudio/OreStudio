#+title: ores.ore.ore_import_messages
#+description: Codegen operation model for the whole ORE import protocol: the client request and its response, the per-item error they share, and the execute, result and rollback messages the workflow engine exchanges with the saga. Rendered to C++ and TypeScript from one source.
#+type: ores.codegen.operation
#+component: ore
#+subcomponent: api
#+entity_singular: ore_import
#+namespace: ores::ore::messaging
#+brief: The ORE import protocol, client-facing and engine-facing.
#+filetags: :model:operation:ore:
#+created: 2026-09-26
#+updated: 2026-09-26

The ORE import protocol, both halves in one model. The caller uploads the
packed ORE directory to object storage first, then sends the request; the
service answers once the saga has run, or returns a workflow instance id when
it has dispatched the import asynchronously.

The workflow engine then drives the saga itself, publishing the execute command
when the workflow starts and the rollback command when compensation is
triggered. The handler answers each by calling publish_step_completion, so
neither command has a response type. The result is not sent over the wire
either: it travels as the step's response_json, which is why it carries the
saved entity identifiers the rollback needs.

Both halves are one model because they share =ore_import_item_error=. The
generator resolves one model at a time, so a message in one operation model
cannot be referenced from a second model's header or its TypeScript twin; a
single model keeps the shared type local, and the service includes one header
rather than two.
