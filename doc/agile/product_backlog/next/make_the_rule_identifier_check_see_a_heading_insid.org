* What

Make the rule identifier check see a heading inside an org block and a vanished identifier. build/scripts/check_rule_identifiers.py skips bullets inside begin and end blocks but not headings, so an example block with a heading would start a false section. It also cannot see a deleted or renumbered identifier unless the checklist cites it, so the permanence rule the UX hub states is not enforced; comparing against origin/main would catch a removed identifier. Both came from the review of the identifier PR 3758.

* Why

The identifier is the name a check and a reviewer share. A check that can be
fooled by a heading in an example, or that cannot tell a rule vanished, lets
the two drift apart without a word.
