* Goal

A repository on the libpq layer, called with a context bound to a sqlgen
unit of work, runs inside that unit of work's transaction. Components then
move to libpq one at a time, whatever transactions they share.

* Acceptance

- A libpq write inside a sqlgen unit of work rolls back and commits with it.
- A libpq read inside a sqlgen unit of work sees that unit of work's
  uncommitted writes.
- A libpq call outside any unit of work still runs in its own transaction.

* Plan

1. A third patch on the sqlgen overlay port gives =Session= a =conn()= and
   =Connection= a =native_handle()=, so the =PGconn= of an open sqlgen
   transaction can be reached.
2. =pq::connection::borrow= wraps that =PGconn= and never closes it.
3. =pq::transaction::join= runs on the borrowed connection. It sends no
   =begin= and no =set_config=, because the connection is already in the
   transaction with the tenant and party sqlgen set on it. Commit and
   rollback are left to sqlgen. Every statement runs unnamed, because a
   borrowed connection keeps no record of what is prepared on it.
4. =database::transact= joins when the context holds an open sqlgen
   transaction, where it used to refuse.

* Notes

** Why

Moving ores.inbox showed that three hand-written services share one sqlgen
unit of work across components: the book and counterparty proposals of
ores.refdata lock an inbox approval request and apply their change together,
and the curve publish gate of ores.marketdata raises its approval with the
publish. A moved component's repository refused that transaction, so inbox,
refdata and marketdata would have had to move in one PR. The bridge lets each
move alone, and it goes with sqlgen.

* Result

=database::transact= joins an open sqlgen unit of work instead of refusing
it. A third patch on the sqlgen overlay port exposes the connection, a
borrowed =pq::connection= wraps it, and =pq::transaction::join= runs on it
with no =begin=, no =set_config= and unnamed statements, leaving commit and
rollback to sqlgen. Components can now move to libpq in any order.
