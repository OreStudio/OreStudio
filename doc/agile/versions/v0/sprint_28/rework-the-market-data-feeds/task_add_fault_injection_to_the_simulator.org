* Result

A simulator author injects five faults through one request, =synthetic.v1.ops.set_faults=. The request replaces the whole plan, only a session of the system tenant that may run feeds sends it, and every fault is off by default and after a restart. Each fault goes through the adapter contract:
- A lost connection sends no announce, no heartbeat and no demand reply, so the service makes the adapter stale. The adapter resumes when the fault is off.
- A delay gives each tick a vendor time older than the delay. A delay beyond the age limit makes the service drop the tick as =stale=.
- A repeat sends the tick before the new one again, with its older vendor time, so the service drops it as =out_of_order=.
- An out of range value makes each tick carry a value ten times the largest the service accepts, so the service drops it as =out_of_range=.
- A not entitled rejection rejects every id of a demand set as =not_entitled= and stops the generators.

The limits the service applies are now in =ores.marketdata.api= (=adapter_limits=), and the translator and the faults read them from there. A translator test sends a tick one step beyond each limit and shows the drop reason. The fault tests show the tick that each fault makes, the rejection reason and the silence of a lost connection.

Against the rebuilt database: synthetic service 77 cases and marketdata service 162 cases pass.

Left for other tasks:
