* Goal

A person watching a run in the browser sees the progress a running step reports,
and a failure names the work that failed and why.

* Acceptance

- A step in progress shows its latest progress line, and its counts where it
  counts, on the rail.
- A failed step shows the work that failed, the attempts it took and the reason,
  translated where a translation exists.
- The polling stops when the run reaches a terminal state, as it does today.

* Plan

- The wire already carries the progress: PR #4660 put =progress=,
  =progress_done= and =progress_total= on the step summary and in the schema.
  The rail does not read them, so render them.
- Show the line on the rail only when the step reported one. A quiet step
  shows no line, because the rail never invents progress.
- Translate the failure through the same catalogue the rail already uses for
  labels and warnings, so a server sentence a person has translated reads in
  their language.
- Cover the three cases: a running step's line and counts, a step that reported
  nothing, and a failed step's work.

* Result

* Result

The rail reads what the wire already carried. A running step shows what it last
said it was doing, with its counts when it counts:

#+begin_src text
  ◐ Publish each party's volatility surfaces
    progress: ACME: surfaces with their quotes   3 of 10
#+end_src

A step that reported nothing shows no progress line. The rail never invents
one, because the person reading it is deciding whether the step is still alive.

A failure reads as the work, the attempts and the reason, in the words the
catalogue gives:

#+begin_src text
  ✕ Publish each party's volatility surfaces
    ACME: EUR/USD surface calibration failed after 3 attempts: NATS request timed
    out: no reply from 'marketdata.v1.ops.calibrate_fx_vol_surface' within 120000 ms
#+end_src

The failure goes through the same =words= translator the rail already applies to
a step's label, description and warning, so a sentence with a translation reads
in the person's language, and a sentence without one reads as the server wrote
it.

Three cases pin it: a running step's line and counts, a step that reported
nothing, and a failed step whose work is translated.
