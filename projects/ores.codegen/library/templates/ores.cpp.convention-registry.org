* Summary

A convention family is an entity model that declares =#+convention_family:=.
The family list is derived from those declarations, and three C++ artefacts
are rendered from it: a registry header that enumerates every family and its
write mode, an apply fragment that carries one write call per family, and the
includes fragment that names the repositories the apply calls. The fragment
lets the conventions service write every family from the registry instead of
naming each one by hand, so a family added to the modelling tree arrives in
the service on the next regeneration.

The facet is opt-in and renders nothing by default. It is addressed to a
/component/ model rather than to a family, because the artefacts are one set
per component and not one file per entity: the header lands in the component's
API and the two fragments in its core service. The archetypes therefore carry
literal =#+output:= paths, which is the one place in the library a path names
its component rather than spelling it from the model.

The rendering reads the refdata modelling tree, so only =ores.refdata= opts
in. A second component that enables this facet would render refdata's registry
into its own tree, which no component wants.

* Mustache incantations

The archetypes read one context, =convention_registry=, which the generator
builds only for the three templates of this facet. It exposes =component=, the
=families= list in family-key order, the =repositories= list the includes
fragment emits, and the three =party=, =by_id= and =world= groupings of the
same entries. Each family states =key=, =entity=, =domain_type=,
=subject_stem=, =party_scoped=, =write_mode= and the =is_party=, =is_by_id=,
=is_world= one-hot flags the staged branch switches on.
