* Acceptance

- reporting declares no ORE log line format, severity mapping or structured-message decoding.
- The run's errors are recorded from the canonical rows alone, on the success path and on the failure path.
- The refusal paths — a wrong header, a short row, a wrong field count — remain covered by tests.

* Plan

The chain already carries the answer: =post_process_results= runs after
=collect_compute_results=, and it records each result's canonical log rows
through =record_run_log=. The failure path in =collect_results= records the log
of the result that failed, before it refuses. So the archive parser has no job
left on either path, and the collect step stops reading the archive for errors at
all.

Two things move with the parser:

- The row type stays. =engine_log_error= is what the canonical reader produces
  and what the error recorder writes, and its header loses everything that
  decodes the engine's text: the line parser, the archive reader, the JSON
  search, the category mapping and the text-log fallback. The header is renamed
  after the type it holds.
- The rows keep the meaning the table had. The old reader stored warnings and
  errors only; the canonical file holds every line the engine wrote, so the
  recorder keeps the severities the screen shows and drops the rest. A run whose
  log is all notices records nothing, as before.

The refusal paths the task asks about are already stated by the canonical
reader's suite: a wrong header, a short row, a wrong field count, a quote that
never closes and an empty file each have a case.

* Result

reporting holds no ORE log grammar. =engine_error_log.cpp=, its header's two
readers and the six-case suite are deleted, and the header is now
=engine_log_error.hpp= holding the row type alone. The test fixture of the
engine's JSON lines went with them.

Both paths record the run's errors from the canonical rows:

- =post_process_results= records the log the node wrote for each result, which is
  where a run that completed gets its account;
- the failure path in =collect_results= records the failed result's log before it
  refuses, which is where a run that did not complete gets its account.

The collect step no longer parses the archive at all: it keeps the output as the
run's output and leaves the account to the rows. The body it downloads is still
stored, so nothing is lost.

The rows keep the table's meaning. The canonical file holds every line the
engine wrote, so the recorder keeps the severities the screen shows -- =error=
and =warning= -- and drops the rest, with a case that says a notice is not a
problem. A run whose log says nothing went wrong returns before the write rather
than asking the table to take no rows.

The refusal paths the task asks about are the canonical reader's: a wrong
header, a short row, a wrong field count, a quote that never closes and an empty
file each have a case in =results_canonical_log_reader_tests.cpp=.
