* Goal

A surface belongs to a party and reads the party's own series, so the quotes it calibrates must be that party's too. Make the derived source ask CRM for the party's daily levels and keep only the statistics: returns, moments, smile, quotes. Delete ecb_fixing_item, ecb_legs_of, fixing_provider and the URI that names a publisher.

* Acceptance

- Each party derives its own fx_option quotes from its own triangulated history.
- The derived source contains no currency, publisher or leg selection; it asks CRM and does arithmetic.
- The series it writes record derivation_kind and the config id of the party's build configuration.

* Plan

**What is already on main**

The three pieces this needs exist and are tested: the provider rank
(PR #4757), the policy that reads a topology from the identity a source
states (PR #4761), the CRM building its topology from the party's series
(PR #4763), and the replay that turns a publisher's fixings into daily
levels (PR #4765).

**What the derived source has to stop doing**

=derived_fx_vol_adapter= names its publisher (=fixing_provider = "ecb"=),
builds the leg URI itself (=ecb_fixing_item=) and decides the legs
(=ecb_legs_of=). All three go. The pair's returns then come from the CRM
engine reading the fixings the store holds, whichever publisher ranks
first, not from a constant in the adapter.

**The plan was wrong in two places**

Found before any of it was built, so the slices below replace the first
draft rather than extend it.

1. *A fixing series cannot be read over the wire.* The first draft opened
   with a client method for =marketdata.v1.ops.list_series_identities=,
   so that the adapter could read the party's fixing identities. That
   list cannot carry a fixing: =series_identity_lister::list= keeps only
   the identities whose =identity_kind= is =series=
   (=series_identity_lister.cpp:131=), and a fixing series is the one
   whose =identity_kind= is =index= (=fixing_sources.cpp:43=). The two
   sets are disjoint, so the method would have returned nothing the
   adapter needs.
2. *One source for a party can never surface a pair only another publisher
   quotes.* =topology_from_sources= chooses one publisher for the whole
   party. The ECB ranks ahead of the IMF (20 against 21) and quotes no
   CLP and no COP, so on a party holding both, the choice lands on the
   ECB and USD/CLP stays underived however the adapter is written. The
   choice has to be made once per pair.

**The slices, in order**

1. *Take each pair from the source that quotes it.* =sources_for_pairs=
   chooses, for each pair, the lowest-ranked source whose star can
   express both of its currencies, and reports the pairs no source can
   express. This is done.
2. *Serve the party's rate history.* The adapter holds no marketdata
   table and reads no =oresmd_uri=, so the service that owns both the
   identity and the topology serves the pair's daily levels: one
   operation over =read_fixing_sources=, =sources_for_pairs=,
   =topology_builder= and =replay_fixings=.
3. *Hand the levels to the engine.* The adapter asks for the pair's
   levels instead of reading two ECB item windows, and differences them
   into returns. =derive_grid= is left as it is.
4. *Delete the constants* and their tests: =fixing_provider=,
   =ecb_fixing_item=, =ecb_legs_of=, and the ECB wording in the header
   and the adapter's own documentation.

**What this collides with**

The horizon branch, =feature/surface-every-pair-out-to-ten-years=,
rewrites =derived_fx_vol.cpp= and the adapter's neighbours to carry a
thirteen-expiry ladder and a ten-year read. Whichever lands second pays
the conflict; the arithmetic of the move is independent of the horizon,
so either order works, but the branch that lands second should expect to
resolve rather than re-apply.

* Result

*Slice 1 landed.* =sources_for_pairs= chooses the source each pair is read
from, so a pair that only a second publisher quotes is read from that one
instead of being left underived. This is what the arc was missing: with
one source for the whole party the ECB, which ranks 20 to the IMF's 21
and quotes neither CLP nor COP, decided every pair, so USD/CLP could not
reach a surface however the adapter was written. A rate still never mixes
two publishers, and a pair no source can express is reported rather than
dropped.

The rank order, the refusal of a source that states no base, and the set
of currencies a source can express are helpers shared with
=topology_from_sources=, so the two choices cannot drift apart. 11 new
cases cover the pair-level rule, the rank, both sides of a direct edge, an
unserved pair, and the same shape under names the code has never met.

Also fixed: =fixing_sources.hpp= included the definition of
=ores::database::context= to name it in one signature, which the
forward-declarable check reports as a new offender. It carries that check
red on =main= for any change that touches it, so the line is corrected
here rather than added to the baseline.

*What this does not do yet.* Nothing consumes =sources_for_pairs=.
=derived_fx_vol_adapter= still names =fixing_provider = "ecb"=, builds
its leg URIs with =ecb_fixing_item= and chooses its legs with
=ecb_legs_of=; the surfaces for USD/CLP and USD/COP stay missing until
slice 2 serves the pair's levels and slice 3 hands them to the engine.
