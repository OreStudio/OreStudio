* Goal

The badge stops being mapped to the value and becomes a property of the value.
A tenant status names the badge that paints it, its own name is the word inside
the pill, and the junction that mapped one to the other is not what the screen
reads.

* Acceptance

- A tenant status row names the badge that paints it, and no screen or route
  reads a mapping to find out which.
- The word inside the pill is the status row's own name, and the colours, the
  severity and nothing else come from the badge.
- A status without a badge, and a status whose badge has left the catalogue,
  keep their words and lose their colours.
- The read the roster uses answers the statuses and their badges in one call.
- The mapping the screen used before is gone from the web read path.
- Every new behaviour is proved by a test, and the pill was read in a browser
  against the running deployment, compared to the status rows themselves.

* Plan

1. *The column, on the value.* The badge is a reference the value holds, so the
   value's own model gains it and the codegen produces the layers. The model is
   the source: no generated file is edited by hand.
2. *The words stay the value's.* The badge supplies colours and severity. Its
   own name is its entry in the catalogue and never the label of somebody
   else's state, which is what the junction made possible and what made a
   suspended tenant read Frozen.
3. *The read follows the model.* The route reads the statuses and the catalogue
   and joins them on the reference the row carries, so the join is a lookup and
   not a mapping.
4. *The junction stays for the domains that have not moved.* Deleting it now
   would break twenty domains at once. It is read by nothing on this path and
   goes when the last domain moves.

* Result

The badge is a property of the value, and the words are the value's own.

- *The row names its badge.* =ores.iam.tenant_status= gained =badge_code=, a
  soft reference to the badge catalogue, and the four statuses name
  =tenant_bootstrapping=, =active=, =frozen= and =archived=. The model is the
  source: the SQL, the C++ and the browser types were regenerated from it, so
  there is no hand-edited generated file to drift.

- *The words stay the deployment's.* The pill shows the status row's own name:
  a suspended tenant reads **Suspended**, painted in the badge's colour, with the
  status row's own description behind it. That is the whole point of moving the
  reference: the junction let a generic catalogue label replace the word the
  deployment chose, which is what made a suspended tenant read **Frozen**.

- *The read is a lookup, not a mapping.* =GET /api/tenant-statuses= answers the
  statuses with the badge each one names. Nothing on that path reads a mapping,
  and a status that names no badge, or names one the catalogue has lost, keeps
  its words and loses its colours.

Proved live: the harness reads the statuses, then reads the pill the browser
drew and compares them. It asserts the split directly — a status reads
=Suspended= while the badge painting it is named =Frozen=.

What this task deliberately does not do.

- *The junction stays.* =badge_mapping= still holds 154 rows across some twenty
  code domains, and its admin screens and recipes still work. Deleting it now
  would take those domains' colours with it. It is read by nothing on this path,
  and it goes when the last domain carries its own reference.

- *The other domains have not moved.* =party_status=, =book_status=,
  =calendar_type= and the rest still paint through the junction. The shape is
  now proved on one domain; the sweep is its own work.

- *Tenant status is not yet a state machine.* It is a lookup that names its
  badge, which is what this screen needed. Whether the lifecycle should be an
  FSM with its states carrying the badge, as =trade_status= is, is a modelling
  question this task leaves where it found it.

- *A status is still English server data.* The label is the status row's name,
  so a translated interface shows the deployment's English. Same gap as before,
  in a better place: the words are now data the deployment owns and could
  translate, rather than a catalogue's label.
