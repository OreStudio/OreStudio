Close the gap between what the component persists and what its models
describe. This is item group M. Three things are missing: entities with
a table and no model, entities with a model and no profile binding, and
types the model declares in a shape the database should not hold.

The last of these is the sixteen-defect investigation
=doc/agile/versions/v0/sprint_25/ore_trade_generator_trade_populations/trade_model_defects.org=,
whose model-shape defects belong here. Defect 11 and defect 12 belong
to the reference-data work and are out of scope, per decision D5.

** 0. What is done

M09's model half is done and this branch carries it.

- The twenty-five models that named the generator facet in the singular
  now name it in the plural, which is the loader's default and the only
  value the facet has. The correction collapses the second generator tree:
  the fifty files under =api/.../generator/= (the singular facet's output)
  are deleted, and their replacements are emitted under
  =api/.../generators/=. The api source list is regenerated.
- The five models that carried the Qt-era presentation properties --
  =trade=, =lifecycle_event=, =party_role_type=, =trade_id_type= and
  =trade_type= -- no longer name a retired message type. The eleven
  properties the refdata clean-up removed are the set; here nine of them
  were present, forty-five lines in all. The properties the generator
  still reads (=key_field=, =collection_name=, =domain_include=,
  =domain_class=, =protocol_include=, =has_pagination=,
  =has_uuid_primary_key=, =save_request_item_field=) stay, because
  core.py reads =key_field= from the presentation namespace and the
  canonical trade key depends on it.

What the collapse dragged in:

- A hand-written consumer, =api/tests/generators_tests.cpp=, included the
  singular path for one generator. It is migrated.
- The trade model's =handler_includes= block named
  =ores.dq.api/messaging/fsm_protocol.hpp=, a header dq deleted when it
  modelled the FSM pair (=dd131c388b=). No trading source reads a dq FSM
  symbol, so the include is removed rather than repointed, and the prose
  above it no longer claims the save path reads transitions from it.
- The regenerated trade eventing test seeds =status_id= from the dq
  catalogue, so =ores.trading.core.tests= now links =ores.dq.api.lib= and
  =ores.dq.core.lib=. The build graph could not make that change itself,
  which is why the generated test and the hand-written tests CMakeLists
  move together.

One thing this branch cannot finish. =ores.workflow= is red on main:
=core/src/service/fsm_state_map.cpp= still consumes the deleted dq
protocol (=get_fsm_states_request=, =get_fsm_states_response= with
=.success= and =.states=), which dq's modelling replaced. That consumer
migration is the workflow component's, not trading's, so the whole-tree
build stays blocked until it lands. Trading itself is verified below.

Two findings from doing it:

1. The in-place regeneration and the dry run disagree about one generated
   test. =trade_eventing_integration_tests.cpp= gains soft-FK parent
   seeding for =status_id= (an =ores.dq.fsm_state= row) when the component
   is regenerated in place, and the dry run does not render it. The
   seeding depends on another component's regenerated state, which the
   dry run, rendering trading alone into a temporary root, does not
   produce. This is the cross-component blind spot the backlog capture
   =drift_gate_misses_cross_component_outputs.org= records, seen from the
   trading side. The change is kept, and the dry run then agrees.
2. The model's presentation block is not itself the defect: other
   components keep theirs. What M09 forbids is a property that names a
   retired message type, which is what the refdata precedent
   (=6bb3577a55=) removed.

** 1. Bound or recorded: the M02 survey

Thirty-one of the component's sixty-five org files bind a profile today
(twenty-six trading-instrument, three simple-lookup, one
workspace-scoped-lookup and one trading-record). The remaining
thirty-four are the six field-group models, the module, the component
overview, and twenty-six entity models. Every one of the twenty-six is
recorded as a no-match, with the features that decide it and the reason:
=evidence/pr3_m02_no_match_survey.txt=.

The bindings were tested against every profile's own assignment table
rather than against a name:

- No profile declares a composite natural key, and fourteen of the
  twenty-six key on two or more columns (for example
  =instrument_id + leg_role + leg_number=).
- =uuid-identified-lookup= fixes =has_change_reason_cache= and
  =has_pagination= true, which every one of these entities resolves
  false, and =has_workspace_id= false, which two of them contradict.
- =trading-instrument= fixes =has_workspace_id= and
  =party_id_from_session=, neither of which the bond family sets. It is
  the closest profile and still the wrong one, which is why the task
  forbids a forced bind.
- =fk-scoped-child= fixes =has_workspace_id=, =has_explorer_api= and a
  parent, and only two of the twenty-six are workspace-scoped.
- =tenant-scoped-junction= fixes only =has_tenant_id=, but it is anchored
  to the junction metatype, and M07 already records that this component
  has no junction metatype. =trade_party_role= is the entity that would
  open when one is introduced.
- =readonly-timeseries= describes a TimescaleDB hypertable, and every one
  of the twenty-six is an ordinary versioned table.

None of this is recorded as a model property, because the loader does not
know the names the spec's =RecordNoMatch= rule uses and an unknown
property is silently inert. The record is the survey, which is what the
standard's M02 method names and what the components that have already
closed M02 did: =clean-compute= records its workflow batch link as a
no-match with no profile, and =clean-iam= records two entities as genuine
no-matches with their feature values.

* Plan

** 1. Bind the unbound entities

Choose a profile or record a no-match for each of the 26. The bond
family is the large group: =bond_issue= and its children are shared
static data rather than per-trade records, so a profile built for a
per-trade instrument is the wrong bind, and a forced nearest bind is not
allowed. Where no profile fits, record the entity's actual feature
values and the reason, as item M02 requires.

** 2. Author the nine missing models

Eight tables have a table, a repository, a service, a handler and SQL, and
no model at all: =activity_types=, =fpml_event_types=, =commodity_instruments=,
=composite_instruments= with =composite_legs=, =credit_instruments=,
=scripted_instruments=, and the shared =swap_legs= table. =product_type=
is the ninth, and its current shape is a database enum on the trades table
rather than an entity, which is defect 10.

Use the established entity org format. The bond family from the sprint
25 pilot is the worked example. =swap_legs= is decided: D10 on the story
fixes one model over the shared table, not one per family.

** 3. Classify the unmodelled hand-written domain types

Twenty-four hand-written domain types have no model:
=activity_type=, =fpml_event_type=, =commodity_instrument=,
=composite_instrument=, =composite_leg=, =credit_instrument=,
=scripted_instrument=, =swap_leg=, =product_type=,
=rates_instrument_variant=, =equity_instrument_variant=,
=fx_instrument_variant=, =instrument=, =instrument_identity=,
=instrument_payload=, =trade_instrument=, =trade_audit=,
=trade_classification=, =trade_envelope_data=, =trade_identity=,
=trade_lifecycle=, =trade_parties=, =bond_instrument_data= and
=bond_schedule_data=.

Some become models in step 2. Some are messages, and item M05 says a
joined or denormalised shape is a message rather than an entity: the
instrument variants, the payload and the container are the candidates.
The rest are infrastructure with a recorded reason. No type is left
unclassified, and none is deleted from this PR.

** 4. Clear the legacy fragments

#+begin_src sh
grep -rn "Presentation" projects/ores.trading/modeling/
grep -rn "generator_facet_name" projects/ores.trading/modeling/
#+end_src

Five models carry a presentation drawer: =trade=, =lifecycle_event=,
=party_role_type=, =trade_id_type= and =trade_type=. Twenty-five models
name the generator facet in the singular. Fix both in the models and
regenerate; do not edit the generated output.

** 5. Close the type defects

Work them in the order the investigation gives, because each makes the
next smaller. Defects 2, 3, 4 and 6 are item M08: SQL type spellings
must be canonical, flags must be booleans, and one concept must have one
name. Defect 5 is a =_code= suffix with no reference table behind it,
so either the table is created or the suffix is dropped. Defect 1 is a
collection held as JSON text; where the collection is a keyed child row
under the relational rule, model it as one. Defect 8 moves twenty-seven
enumeration checks out of trigger functions and into the schema.
Defects 14, 15 and 16 need a shape the grammar may not express today:
declared coverage, a qualified underlying rather than a free-text name,
and an observation schedule rather than two scalar dates. If the
grammar cannot express one, record it as a generator defect with a
failing regression test rather than forcing the tree.

** 6. Regenerate and prove

Regenerate the component and re-run the dry run twice. Every new
entity must leave the tree byte-identical. Then run the codegen suite.
