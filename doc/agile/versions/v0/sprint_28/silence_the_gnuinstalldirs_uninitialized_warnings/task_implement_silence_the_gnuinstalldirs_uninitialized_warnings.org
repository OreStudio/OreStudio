* Acceptance

- build/cpack/CMakeLists.txt suppresses CMD_UNINITIALIZED around include(GNUInstallDirs).
- The configure step still completes and still populates the CMAKE_INSTALL_* variables.

* Plan

Wrap =include(GNUInstallDirs)= in the guard that the same file already applies
to =include(InstallRequiredSystemLibraries)= and =include(CPack)=: push the
diagnostic state, set =CMD_UNINITIALIZED= to =IGNORE=, include, pop. Keep the
guard behind the =CMAKE_VERSION VERSION_GREATER_EQUAL "4.4"= test, because
=cmake_diagnostic= does not exist before 4.4.

Reproduce the warnings with cmake 4.4.4 before and after, because the local
cmake is 4.3.4 and does not report them at all.

* Notes

The probe includes the repository's real build/cpack/CMakeLists.txt, first at
origin/main and then on this branch, from a scratch project that supplies the
variables the file reads before it reaches the include. It does not copy CMake's
module, because the point is to test the module as CMake ships it.

=warnings.uninitialized= on its own prints nothing for these variables. The
probe passes =-Wuninitialized --check-system-vars=, which are the command-line
equivalents of both preset settings.

* Result

build/cpack/CMakeLists.txt suppresses =CMD_UNINITIALIZED= around
=include(GNUInstallDirs)=, in the same shape as the two includes below it.

The probe goes from 10 warnings to 0 and still configures with exit code 0. The
three =CMAKE_INSTALL_*= values it prints are identical before and after, so the
guard does not change what the module computes.
