* Result

** Outcome

The adapter and supplier catalogues ship as DQ datasets, =marketdata.adapters=
and =marketdata.suppliers=, members of the =system_core= bundle. Their publish
functions write the system tenant's rows from =dq_adapters_artefact_tbl= and
=dq_suppliers_artefact_tbl=; the old final-table populate scripts are gone. The
datasets stage the two modules the release actually has: =frankfurter= and
=synthetic=, with Frankfurter and the simulator as their suppliers.

Both entities are =:client_read_only:=: a client reads them and every write verb
is absent from the protocol, the service, the shell and the web twins. The SQL
publish functions remain the writers.

An adapter's announce carries =adapter_code= and =module_version=. The service
refuses a module the catalogue does not define, and the announce is what marks
the module installed on this installation, so an installation that never runs a
module never claims it. The runtime adapter menu is =adapter-status=, which
leaves the =adapters= name to the catalogue and ends the menu collision.
