That the engine runs the archive moved on 2026-10-04 to [[id:3064DDA0-67AD-43B0-B57D-5AC5926E4C4E][Write the portfolio and market data files into the engine input]], since it needs the portfolio and market files too.

* Plan

[[id:0170DEC3-FA2E-410E-99BF-7B4029FC9478][Import a run's configuration from an ORE input directory]] built the export: a
report definition's run document and the documents it binds, rebuilt as files.
This task puts that export into the package step, so the archive the compute
wrapper unpacks carries the run's input.

1. =prepare_ore_package_request= carries the report definition id, which the
   workflow already holds in its start request.
2. The ORE service's package handler exports the definition under the run's
   tenant and writes the files into the archive with =archive_layout=.
3. =export_run= narrows itself to the definition's party when the session has
   none, since a workflow step runs with the tenant alone and would otherwise
   read every party's conventions.

Decisions:

- The engine is started on =Input/ore.xml=, so the run document goes there;
  every other file goes under the run's =inputPath=, as ORE reads them. The
  corpus sets =inputPath= to =Input= or a folder under it in every run
  document.
- The trades and market data stay the msgpack blobs the earlier steps write.
  Turning them into the portfolio and market files the run document names is
  separate work, so the engine cannot run the archive yet.

* Notes

**Today's market: how a run reaches its document, and an open question.**
Recorded in the PR #2500 review. A run names its today's market file in
=report_run_setup.market_config_file= (from =marketConfigFile= in =ore.xml=),
and binds each analytic stage to a configuration id in =report_market_binding=
(from the =Markets= block). =todays_market_config.configuration_id= links the
document to its =reporting.configurations= header, which is what joins the run to
the rows.

Inside the document, every reference is text. A
=todays_market_configuration_binding.reference= of =inccy= for
=DiscountingCurves= means the =DiscountingCurves= collection whose
=collection_id= is =inccy=. Nothing checks it. This task is the first code
that resolves the chain, so it decides whether the binding should carry a
=todays_market_collection_id= foreign key, or whether name resolution at
export time is enough.

The export resolves the chain by name, as ORE does, and nothing checks it at
write time. The decision moved to its own task on 2026-10-04: [[id:A766897B-B26A-44DA-AEA0-749A594A6B68][Link today's market
bindings to their collections]].
