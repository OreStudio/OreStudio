* Plan

The routes fall into two groups, each a reviewable unit:

- The bootstrap and setup reads: =/api/bootstrap=, =/api/bootstrap/administrator=,
  =/api/bootstrap/complete=, =/api/tenant-setup= and =/api/registration-policy=.
  The first two run with no session and the BFF rate limits the policy read,
  which the C++ server cannot do yet.
- The reads inside a tenant: =/api/tenants/{code}/parties=, =people=,
  =accounts/{username}/sign-ins= and =images/{id}=. Each enters the tenant for
  the read alone. The parties read reuses =party_page_routes::read_page= with a
  request that carries the tenant's token.

The bootstrap read states whether the browser holds a session, so it may
wait for [[id:D4275B6D-BF22-4A77-9F00-018D776966CB][Serve the browser's session routes, sign-up and password]].
