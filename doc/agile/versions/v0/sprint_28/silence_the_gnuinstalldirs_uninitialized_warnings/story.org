#+title: Story: Silence the GNUInstallDirs uninitialized warnings
#+description: CMake 4.4 prints ten (uninitialized) warnings on the Linux configure step, one for each CMAKE_INSTALL_<dir> variable. They come from CMake's own Modules/GNUInstallDirs.cmake, which dereferences each cache entry at line 306 before it creates it, and the repository's warnings.uninitialized and warnings.systemVars preset settings make CMake report that dereference. The module is not ours to patch, and the same file already silences this diagnostic around Modules/InstallRequiredSystemLibraries.cmake and Modules/CPack.cmake for the same reason.

* Decisions

- *Silence the diagnostic; do not change the module and do not drop the
  preset settings.* The dereference is inside CMake's own
  =Modules/GNUInstallDirs.cmake=, which reads each =CMAKE_INSTALL_<dir>= cache
  entry at line 306 before it creates the entry. build/cpack/CMakeLists.txt
  already suppresses =CMD_UNINITIALIZED= around
  =Modules/InstallRequiredSystemLibraries.cmake= and =Modules/CPack.cmake= for
  the same class of problem, so the third include follows the same pattern.
- *Keep the =warnings.systemVars= setting.* Turning it off would silence these
  ten warnings, but it would also stop CMake reporting every other uninitialized
  variable with a =CMAKE_= prefix, which is the check that found these.

* Out of scope

- The uninitialized warnings that come from CMake's own compiler-detection
  modules. Those do not appear in the repository's configure output.
