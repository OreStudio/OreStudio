* Decisions

** The trade activity is a stamp, and a process run is not

Taken 2026-10-07 with the owner. Two records that had been read as one
are separate. A *trade activity* is stamped on a trade amendment to say
what the amendment was about, so risk buckets by amendment type; it
stands alone and names no other trade. A *process run* records one
execution of a process over a set of trades, with its inputs, its
outputs and the time point it read them at, so the process can be
undone or repeated. Where a process generates an amendment it stamps
its own activity, and that match is incidental: nothing requires a
stamp to point at a run, and most stamps have no run behind them.

The process run is its own subject and its own story:
[[id:C0D511A9-E15F-4863-890D-5B20EA0628C7][Trace a process run and the trade groups it creates]].
The three tasks that hung process structure off the activity moved
there, and the story waits on one process with a real client.

- [[id:C0D511A9-E15F-4863-890D-5B20EA0628C7][Trace a process run and the trade groups it creates]] — the run, its state machine and the trade groups, waiting on a pilot process.
- [[id:A7381409-AFD0-4F0E-BAB4-61CD35341AA8][Trace a process run over a set of trades]] — the capture the run model is written down in.
- [[id:61590415-C7E0-4BB9-8845-8BB794896EE0][Implement the processes that act on sets of trades]] — the capture for building the processes themselves, one pilot at a time.
- [[id:2AF58405-4F3D-4B74-AAD0-6A97E7DA215F][Trade sets and trade groups]] — the primitive, the trade group a run creates, and the roles the process fixes.
- [[id:116164D0-A54A-4872-8BA6-1FE36583C8C4][Trade set]] — the set a run reads and writes, and how its membership is resolved.

** The create aggregators stay hand-written, and a check guards them

Taken 2026-10-08 with the owner. A component's `*_create.sql` names its
table files in the order psql must run them, and a new entity means a new
line in it. Nothing generates that file: all 22 aggregators are
hand-written, no template emits one, and neither `compass add` nor
`codegen regenerate` writes an include.

It is hand-written because the order is the content, and the order is not
something a model states. An alphabetical include set cannot build the
schema at all: in `create/trading/`, `trading_trade_identifiers_create.sql`
and `trading_trade_links_create.sql` both sort before
`trading_trades_create.sql` and both carry a foreign key to it. Nor is the
order purely foreign keys: the product type discriminator enum must precede
the tables whose columns use the type, and no key records that edge.

The cost showed itself in this story. Two link tables had create files
that matched their models and that no aggregator named, so no database
ever created them, and every other check passed. A check now walks the
include directives from the schema entry points and fails on any create
file nothing reaches. Generating the order topologically was considered
and rejected: it would mean touching all 22 files and modelling the
ordering edges that today live in comments, to save one line per entity.
