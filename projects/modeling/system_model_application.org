This page is part of the [[id:D773166D-0C91-8CB4-3323-42166BC07687][System Model]]. Application is where the system surfaces
— the layer that composes everything below it into user-facing executables. The
shell REPL is a client of the same domain services over [[id:C9C24C99-F16C-45BE-A262-1C0F4502765E][ores.nats]];
the compute engine is a long-running service. To generate component diagrams,
use the [[id:D6D86317-4961-6754-A6DB-9C12B5FAC997][PlantUML Class Modeler]] skill.

* Detail

** ores.http

Boost.Beast/Asio async HTTP server exposing a REST API for domain services.
ores.http.api defines the route handler contract; ores.http.core provides the
async infrastructure; ores.http.server wires all handlers and runs the event
loop.

** ores.compute

Distributed compute grid for ORE Engine risk runs. ores.compute.core
manages the cluster: it keeps the app and app-version registry, assigns
batch jobs to registered hosts, tracks execution state, and collects
results. ores.compute.service is the NATS entrypoint for that
orchestrator; ores.compute.wrapper executes each assigned run as a
child process on a worker node; ores.compute.client uploads engine
packages with hash verification for the shell.

** ores.shell

Interactive REPL for connecting to ORE Studio over NATS. It parses command-line
arguments and a configuration file, auto-connects and auto-logs-in from that
configuration, and exposes commands for querying and provisioning a running
system from a terminal. It is the surface the system tests drive, and the
Emacs dashboard launches it.

** ores.lisp

Emacs Lisp developer tooling — per-checkout dashboard (transient menu), database
browser, shell integration, and org-roam export pipeline. Not part of the
production system; it automates the developer workflow inside Emacs.
