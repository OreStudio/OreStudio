* Acceptance

- Each defect is recorded with the command or recipe that shows it, and with the file and line of its cause.
- Each fix changes a template, a loader or a script, and not the generated output.
- Each fix carries a regression test that fails before the fix and passes after it.
- The affected components are regenerated, and the drift gate passes with each of them listed.

* Plan

Work the defects in the order the clean-up passes find them. Each one is one
unit: record it in the register below with the evidence that shows it, fix it
at the source, add the regression test, regenerate the affected components,
run the drift gate, and commit.

The branch accumulates the fixes and is rebased onto main as needed. Nothing
merges until every component is clean, so a fix that would change generated
output across components does not have to land early to be correct.

* Notes

*Finding.* The two malformed comments are not a generator bug. They are two of
**46** umbrella headers that the generator stopped owning when the archetype
moved into the disabled scaffold facet. Nothing regenerates them, nothing
gates them, and none of the 46 is =#include=d by any =.cpp=, =.hpp= or =.h= in
the tree: they survive only as entries in a generated =component_files.cmake=
list and as namespace prose. 78 of the 124 components have none.

*Why regeneration is off.* Moving the umbrella into =ores.cpp.component= would
put it back under regular codegen and the drift gate, but it would emit one for
every component of kind =flat=, =api=, =core= or =service= -- about 84 of the
124 -- recreating =ores.nats.hpp= and some 37 that do not have one. That is
precisely what the scaffold-is-opt-in story stopped, and it is why the facet is
disabled.

*The inconsistency.* The scaffold facet's own lifecycle says every artefact in
it is deleted as the component's first real model lands. 46 were never
deleted, so the tree holds a file that is in neither state: not scaffolding
any more, and not a generated artefact either.

*Options.*

- Delete the 46, which finishes the opt-in decision and removes the malformed
  comments with the files. The generated CMake file lists drop their entries.
- Move the archetype back to =ores.cpp.component=, making the umbrella a
  permanent generated artefact for every eligible component, and accept the
  ~38 new headers and the reversal of the opt-in decision.
- Leave them and keep the register entry as the only record.
