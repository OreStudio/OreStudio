#+title: A stale publish tree runs code the source no longer has
#+description: ores.http.server failed to start asking for a JWT secret. The source stopped asking for one a day earlier and .env correctly has none. The published library predated the change, so the service ran an option the tree had deleted.
#+type: capture
#+level: cross
#+filetags: :compass:build:services:http:defect:
#+created: 2026-09-27
#+updated: 2026-09-27

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

=ores.http.server= refused to start, once per restart, with:

#+begin_src text
Usage error: JWT secret is required. Set --jwt-secret or ORES_HTTP_SERVER_JWT_SECRET.
#+end_src

The variable is not in =.env=, and that is correct. Commit =75789b79fb=
("[http] Verify session tokens with IAM's key alone") removed it on
2026-09-27 13:09, along with the option, the parser requirement and the
symmetric verifier behind them, because a second trust root meant anyone
holding that secret could mint a token the gateway believed. The task that
made the change says so explicitly: "Removing the variable matters as much
as removing the option: CLI11 maps it onto the option name, so leaving it
in =.env= fails the parse at startup."

The service still asked for it because the *published* library was older
than the source:

| Artefact | Timestamp |
|----------+-----------|
| =build/output/.../publish/lib/libores.http.server.so.0.0.25= | 2026-09-26 22:55 |
| The commit that removed the option | 2026-09-27 13:09 |

The string is in the library and nowhere in the source. =parser.cpp= and
=options.cpp= contain no occurrence of =jwt= at all.

So this is not an environment defect. It is the publish tree disagreeing
with the tree it was built from, and the failure it produces is a message
the source cannot produce.

* Why

Found on 2026-09-27 while bringing the fleet up after =compass db recreate=,
when =ores.http.server= was the one unit of twenty-five that would not
start. The first reading — that the environment was missing a variable it
should have generated — was wrong, and acting on it would have made things
worse in two ways: it would have papered over a stale build, and it would
have left a variable in =.env= that breaks the parse once the library is
rebuilt.

The general shape is worth recording, because nothing warns about it.
=compass services start= runs whatever is in =build/output/<preset>/publish/=,
and that directory is only as current as the last build. A source change
that removes an option, a variable or a requirement will not reach a
running service until somebody rebuilds it, and until then the service
fails in a way that reads like a configuration mistake.

Two things would make that harder to hit. The deploy could compare each
unit's binary against the sources it is built from and refuse to start a
stale one, the way the codegen gates refuse a stale tree. Or the build
could stamp the artefact with the commit it came from, and the failure
message could carry it, so a reader sees the age before reading the error.
