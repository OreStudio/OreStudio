* Goal

A repository whose entity has a write observer cannot build without seeing
that observer. Found in #3978: only one file included the trade write
observer, so 32 repositories saw it only when a unity batch happened to put
them after that file, and otherwise never observed their writes. The fix
there was an include paste in each model; nothing stops a new observed model
from forgetting it.

* Acceptance

- A model whose entity is observed but whose repository does not see the
  observer fails codegen or the build, with a message that names the model.

* Plan

- Treat the specialisations as the record of which entities are observed: a
  component observes an entity by specialising =entity_write_observer= for its
  entity type, in a header of its own.
- Have codegen read those specialisations from the component's headers and,
  when it prepares an entity's or a junction's model, refuse a model whose
  observed entity's repository does not include the header, naming the model
  and the include it needs.
- The drift gate runs codegen over every model, so the refusal reaches CI.

* Notes

** Where the check lives

The acceptance allows the refusal in codegen or in the build. Codegen is the
earlier place and the one that can name the model: the build sees only a
repository translation unit, and the unity batching that hid the bug also
decides what a build-time check would see. The check reads every header under
the component's include trees once per component and caches the result.

Only ores.trading observes writes today, through
=trade_write_observation.hpp=; every observed trading model includes it.
