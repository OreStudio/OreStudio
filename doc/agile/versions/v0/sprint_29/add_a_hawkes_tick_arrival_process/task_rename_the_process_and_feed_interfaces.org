* Plan

This task changes names only. It adds no behaviour and no build target, and it
moves no file: the three headers are already =i_yield_curve_process.hpp=,
=i_stochastic_process.hpp= and =i_feed.hpp=. The symbols inside them are not.

1. Rename the three class names, and only the class names:

   | Old                  | New                    |
   |----------------------+------------------------|
   | =IStochasticProcess= | =i_stochastic_process= |
   | =IYieldCurveProcess= | =i_yield_curve_process= |
   | =IFeed=              | =i_feed=               |

2. Drive the rename with one scripted pass that a reviewer can rerun. The
   script owns the file list and the substitutions, so the diff reads as one
   shape and the old spelling cannot survive in a corner of the tree.
3. Follow the dependency order inside the tree: =ores.analytics.quant= first,
   then =ores.marketdata.api=, then the synthetic feeds, the service and the
   clients that consume both.
4. Leave the past agile records alone. A sprint org file from an earlier sprint
   is a record of what was true then. It keeps the old spelling. This point
   overrules point 2 for =doc/agile/=.
5. Rewrite the eight current documents that name an interface. Regenerate the
   codegen output of the three model files under
   =projects/ores.synthetic/modeling/=. One exception: the four component class
   diagrams under =projects/*/modeling/*.puml= are renamed in place, because a
   full regeneration would add about 140 unrelated lines from the parser gap
   recorded in
   =doc/agile/product_backlog/inbox/diagram_parser_drops_wrapped_declarations.org=.
6. Build and run the affected suites. The acceptance is no behaviour change, so
   a green build and green tests are the proof. A =git diff --stat= that touches
   no test expectation is the second proof.

* Notes

** The pass

=scripts/rename_interfaces_to_snake_case.py= carries the three substitutions.
It edits hand-written text and leaves output to its generator.

Its =--check= mode is the acceptance test. It exits non-zero when a hand-written
file or a generated file still names an old interface, and non-zero when it
cannot read a file. It names the files it allows and prints their counts, so the
gate never hides a match. It refuses to run outside the repository root, because
a run from elsewhere would find nothing and pass.

** The generated addresses

Three model files changed, so their output was regenerated rather than edited:

| Model | Addresses regenerated |
|-------+-----------------------|
| =ores.synthetic.ir_curve_generation_config= | =ores.cpp.domain=, =ores.cpp.protocol=, =ores.ts.domain=, =ores.ts.protocol=, =ores.sql.schema= |
| =ores.synthetic.yield_curve_process_type= | the same five |
| =ores.synthetic.ir_curve_operations= | =ores.cpp.protocol=, =ores.ts.protocol= |

The eye-check after each run: the diff held the rename and the line rewrap that
follows from it, and nothing else.

The ER diagrams came from =projects/ores.codegen/plantuml_er_generate.sh=: two
=puml= files and the two SVGs drawn from them.

The drift gate agrees: =check_component_drift.py --sweep= reports "Sweep clean:
no file this branch touched would change". The plain =--all= mode is
destructive, so only =--sweep= ran.

** The component class diagrams are the exception

The four component =.puml= files are generated by
=build/scripts/generate_component_puml.py=. A full regeneration here would add
about 140 unrelated lines, because the parser drops three declaration shapes
(the capture is =doc/agile/product_backlog/inbox/diagram_parser_drops_wrapped_declarations.org=).
So the class labels and the relations were renamed in place. The diagrams keep
their shape, and a later full regeneration converges.

** The SVG churn**

The two SVGs were drawn with the installed PlantUML and Java build, which seeds
different internal ids and prints a different Java version than the build that
drew the committed files. Expect id churn beyond the rename in those two files.

** The past records

30 files under =doc/agile/= name an old interface. They are records of what was
true then and keep the old spelling. The script itself names all three as well,
because it must, so it is the 31st. =--check= prints each one, with its count, so
the allowance is visible and nobody mistakes it for a clean tree.

* Result

The three interfaces are now =i_stochastic_process=, =i_yield_curve_process=
and =i_feed=. No class, file or document outside the agile record names an old
spelling.

The rename is mechanical. The branch changes 68 files; the rename commit changes
64 of them: 52 hand-edited files, 11 regenerated files, and the script. The
remaining four are this page, its parent story, the backlog index and the new
capture.

Per file, the rename is all that changed except in five places, each with its own
reason:

| File or group | What else changed, and why |
|---------------+----------------------------|
| The two redrawn SVGs | PlantUML id and renderer-version churn from the machine that drew them |
| =simulator_adapter_tests.cpp= | clang-format rewraps at two hunks; the file was unformatted before this branch and the format gate fails on any changed file |
| Four component =.puml= | Renamed in place, because a full regeneration brings about 140 unrelated lines |
| The backlog index and the capture | The capture records a race this branch found; the index gains its row |

The evidence:

- =scripts/rename_interfaces_to_snake_case.py --check= exits zero, and names
  the 31 records it allows, the script included.
- The 12 changed translation units pass =clang++ -fsyntax-only=.
- =check_component_drift.py --sweep= is clean.
- =clang-format --dry-run --Werror= is clean on the changed files, now including
  =simulator_adapter_tests.cpp=, which was formatted for that reason.
- The full build passes, and =compass test run= passes all four affected
  suites.

One caveat on that last line. =ores.synthetic.service.tests= passes only while
=ores.marketdata.service= is not running: the live adapter supervisor answers
the announce inside the 300 ms window that the test reserves for silence. The
failure predates this branch and is captured as its own item.
