* Goal

The storage upload reads the whole object into =req.body= and writes it in one call,
and the download builds the whole object in a response string. Both cost the object's
size in memory. Move them onto the chunk channel and the file on disk.

* Acceptance

- The upload writes each chunk to a temporary file beside the object and renames it
  when the body ends, so a reader never sees a partial object.
- A request that fails, disconnects, or is refused leaves no file behind.
- The upload's stated limit and the ceiling are unchanged, and the answer carries
  the digest and the byte count of what was stored.
- Tests cover an upload of several chunks, an aborted upload, and a key that cannot
  name an object.
- The download is served from the file by [[id:9A622B67-34FA-4426-9526-508CFB7A690C][Serve the download from the file]], because it needs the
  response streaming that increment B1 owns.

* Plan

1. Write to =<root>/<bucket>/<key>.part= from the channel, then rename on the last
   chunk.
2. Delete the part file when the channel stops early, from the same scope that owns it.
3. Test the sink on its own: the part file, the rename, the digest, and the abort
   that leaves nothing.
4. Leave the download to its own task, which waits on B1.

* Notes

- The upload's digest is taken from the part file once the last chunk arrives, so
  the response still carries the same =sha256= the buffered write did, without the
  bytes ever being in memory.
- The part-file protocol lives in =local_store=: =begin_put= names a part that no
  other caller shares, =commit_put= publishes it, =abandon_put= removes it. Two
  uploads of one key therefore never write one file, and neither can publish or
  remove the other's bytes. =put= is now the same protocol with one write in it.
- =list= skips a part file, so an object being written is not reported as an
  object.
- A factory that refuses the request throws =invalid_argument= and the session
  answers 400; any other failure is a 500. That is why the body has to be read
  after the route is resolved and before the handler runs.
