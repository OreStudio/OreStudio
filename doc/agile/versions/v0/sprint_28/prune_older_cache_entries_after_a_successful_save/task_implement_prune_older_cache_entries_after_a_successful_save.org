* Notes

** The accumulation is the price of the earlier fix

Saving under a run-unique key is what stopped a failed save destroying the
cache, because the delete-then-save pair had a window with nothing in it.
The price is that every run adds an entry rather than replacing one: two
clang-debug runs already hold 5 GB of a 10 GB repository cap, and the
repository sits at 9.55 GB.

** What that has cost

The gcc compiler cache has been evicted entirely, so the Nightly Build's
gcc jobs, including the gcc release job restored earlier, run cold. vcpkg
entries survive only because they are small.

** The delete moves after the save

This step deletes older entries of the same variant once the new one is
stored. The ordering is the whole point: the delete can no longer run
before a save that might fail, so it cannot destroy the cache. A variant
ends a successful run holding exactly one entry.

** The filter was dry-run first

The jq expression was run against the live cache with the delete replaced
by an echo. It selected the older clang-debug entry and not the current
one, which is the behaviour the step depends on.
