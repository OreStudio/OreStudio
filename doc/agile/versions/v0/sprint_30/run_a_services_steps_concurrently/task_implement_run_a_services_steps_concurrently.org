* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)


The provisioning run of the conventions story stopped at attach_photos: the
IAM service ran its steps one at a time on the delivery thread of its step
subscription, generate_trades took about 25 minutes, and attach_photos,
set_staff_passwords and schedule_reports waited behind it until the workflow
failed attach_photos as unclaimed after twenty minutes.

1. Audit the step handlers of the fourteen services that serve steps for
   state a call changes. Their members are references, database contexts,
   configuration, and caches that lock or read wait-free, with one
   exception: the service token provider caches its token with no lock, and
   handlers on several subscriptions already call it at once.
2. Add =step_workers=, a fixed set of threads that waits for a free worker
   rather than queueing, so a command not yet taken stays with the server.
3. Give =serve_step_commands= a number of workers, one by default, and run
   the IAM provisioning steps on four. Steps that hold a database connection
   for long, such as the data quality publishes, stay on one: more workers
   than the pool's two connections would starve the service's other handlers.
4. Lock the service token provider.
