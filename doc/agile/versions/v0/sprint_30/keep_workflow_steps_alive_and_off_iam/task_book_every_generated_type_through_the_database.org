* Notes

- The check lives in =ores.synthetic.core.tests=, which already links the
  trading core service, so it draws each class's population with the planner
  and books it through =trade_operations_service=. It asks the planner for a
  population of each class's own code count, so every code the class cycles
  appears exactly once.
- Two defects so far, found before the check ever passed:
  - the fixture's first attempt wrote a portfolio whose currency was a random
    code, which the currency validator refuses. The fixture now writes the
    currency it uses, because the conventions the population draws on name
    indices in EUR.
  - =book_trade= of a generated bond crashes with a segmentation fault before
    it answers, so the store's refusal is never reached. The check reports the
    class and the type it was booking, which is how the crash was named.
