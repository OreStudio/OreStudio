* Acceptance

- A business unit states a set with the same two-state flag as the party and the book, and a business unit that states none permits everything its party permits.
- The chain is enforced on both links: a desk may not permit a type its party does not, a book may not carry a type its desk does not, and neither parent may drop a type a child carries.
- The resolution answers the set a book may carry by reading the chain from the book upwards, and never reads the product type catalogue.
- The book's owner business unit is the link the chain follows, and a book with none inherits its party's set.

* Plan

The desk is the middle of three levels, so every piece of it has a twin one
level up or down, and the work is to copy the twin and then prove the chain as
one thing:

1. *The model.* A =business_units= flag with the same two states as the party's
   and the book's, and a junction of the desk's permitted types, written as its
   own literate model so the table, the notify trigger, the row-level security,
   the C++ stack, the wire protocol and the shell recipes all come from
   generation rather than from hand.
2. *The rules.* Extend the hand-written approvals file so a resolution reads
   the chain upwards — a book states a set, else its desk does, else its party
   does — and six triggers hold both links, each with the two refusals its
   parent link already had.
3. *The proofs.* A pgTAP file of its own, because the party file is about two
   levels: the desk's resolution in all four of its states, the refusals on
   both links, and the replacement that is not a drop.
4. *The wiring.* Compose the two generated registrars and the shell command
   unit in the three files that compose them, or nothing registers the junction
   and the commands never reach the REPL.

Two things about the tree, rather than about the desk, stopped the work and are
part of it: a junction's domain header did not include the uuid type it names,
which no test caught until the shell compiled it alone, and the party's
approval table had no party isolation policy, so a session could read another
party's approvals.

* Result

The chain now has its middle level, and every link of it is either permitted or
refused by the database rather than by the caller.

*The model.* =business_units.restricts_product_types= carries the same two
states as the party's flag and the book's: false permits everything its party
permits, true permits exactly the rows of the new
=ores_refdata_business_unit_product_types_tbl=. The junction is generated from
its own model, so it arrives with its notify trigger, its row-level security,
its C++ domain type, codec, repository, service, history provider, event
registrar, HTTPS routes and shell recipes: 42 files, none of them written by
hand.

*The rules.* =refdata_product_approvals_create.sql= resolves a set along the
chain and never reads the product type catalogue: a book's own set where it
states one, else its desk's, else its party's, and a book with no desk inherits
its party's. Six triggers hold the two links — a desk may not permit a type its
party does not, a book may not carry a type its desk does not, a parent may not
drop a type a child carries, and neither may start restricting while a child
carries something outside the set — and a seventh refuses a book that names a
desk of another party, because that chain would resolve a set the book's party
never approved.

*Two holes the proofs found.* A version replacement closes a row and re-creates
it for the same type, which is not a drop, and the close guards refused it
whenever a child carried the type: they now act only on a row the delete rule
closed, marked by =closed_by=. And a session could read another party's
approvals, because the party's junction had no party isolation policy: it now
carries the restrictive, select-only policy the party currencies carry. The desk
junction needs none, because it names no party.

*A defect in the tree, fixed beside it.* A junction's domain header named
=boost::uuids::uuid= and included nothing that states the type, so it compiled
only where another header brought the uuid header in first. =ores.shell.refdata=
is the first unit that includes it alone and it did not compile; the template
now gates the include on =has_uuid_left_or_right=, as the junction entity header
already did.

*The review round.* Two holes the first proofs could not see, because they flipped
the flag with an =UPDATE= and the product writes by =INSERT=. A party or a desk is
version-inserted: the write closes the live row and inserts the next version, so
a level that started restricting never met a guard that listened only to
=UPDATE=. Both guards now read the live row on =INSERT= and are attached to both
statements, and the proofs flip through a version insert, as the repository does.
A book moved to another desk kept types that desk never approved; the move now
refuses a book whose set the new desk does not hold and allows it where it does.
The refusals are pinned by their message because the error code alone cannot tell
these guards from the status and ancestry ones, and the isolation the new party
policy adds is proved by two assertions of its own. The parent dispatch the book's
resolution and the book's guard both made is now one function.

*Not done here.* Four wide-type counts grew with the flag — =party= 20 against a
recorded 19, =party_entity= 21 against 20, =business_unit= 16 where fifteen is
the ceiling and the type joins no row, =business_unit_entity= 17 against 16 — and
the rule keeps a listed type shrinking but never growing, so no ceiling rose. The
fix is to group the flag into a type of its own, which the task
[[id:6EF48536-68CE-43B7-B629-7EC4D679C602][Group the approval state of a party and a desk]]
holds.
