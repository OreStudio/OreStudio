* Notes

** The provisioning step arguments are untyped

A seed profile states each step as a =step_kind= and an =arguments_json=
=jsonb= column, written in =iam_seed_profiles_populate.sql=. The provisioning
command carries the string on the wire, and =provision_step_arguments.hpp=
reads it as =rfl::Generic=, picking members out by name, or for trade
generation with reflect-cpp's =DefaultIfMissing=. Each kind has its own shape,
and nothing checks it until the step runs. Replacing the generic read is a
design choice, so this task leaves =provision_step_arguments.hpp=,
=tenant_provisioning_handler.hpp= and =provision_tenant_workflow.hpp= on
reflect-cpp and raises it.

** The credential's secrets stay wrapped

The generated codec leaves the =:no_wire:= columns out of its field list, so it
never writes a secret. reflect-cpp writes every member that is not an
=rfl::Skip=, and =account_credential_routes.cpp= in ores.http and
=account_credential_commands.cpp= in ores.shell still write the credential
responses with it. Making the secrets plain members would put them in that
output, empty today because the server codec never sends them, and would move
the protection from the type to every caller. The PR #4368 review found this,
so the wrapper stays and =account_credential.hpp= keeps =rfl::Skip=. A codec
case checks that no secret reaches the codec's encodings or reflect-cpp's. The
capture =drop-rfl-skip-once-nothing-reflects-a-credential= owns the plain
member once those writers move.

The credential is the one type whose MessagePack bytes differ from
reflect-cpp's. reflect-cpp keeps the three skipped members' names in its
MessagePack map with nil values, while its JSON drops them; the codec drops
them in both. A reader skips names it does not take, so each form reads to the
same value, and the codec case proves the codec reads reflect-cpp's bytes.

** Security's storage grant

=storage_grant= in =jwt_claims.hpp= is held by the storage capability messages,
so it states its wire fields beside the struct. The header now names the codec,
so =ores.security= links =ores.utility= publicly, in its hand-written CMake file
and in its model.

** Writing a message that holds another type

=json::write= builds the encoder in the caller's unit, so it needs the wire
fields of every nested type. The account party and account handlers write
responses that hold an account party and a result, so they call the generated
=wire_traits<T>::write_json= instead, as ore's package handler does. The
capture =let-json-write-reach-a-generated-codec= owns making =json::write= find
the generated codec by itself.

** A unity collision from main

=check_unity_collisions.py= reports =the_run= in two marketdata test files that
arrived with #4364. This branch does not touch them.

grant states its fields.
