* Goal

Every screen that sets something up draws the same chrome. The rail comes from =JourneyPage= and the splash header from =JourneyHeader=, and the setup journeys, the registration door and the sign-in dialog all use them unchanged. The setup screen already leads with the project's artwork; the sign-in dialog does not, and the registration door the Entry story adds must. A screen that draws its own rail, or its own banner, is the defect this task exists to prevent.

* Acceptance

- The registration door renders on =JourneyPage='s rail, unchanged: the same entry classes, the same three states, the same circled mark with a tick behind the person, and the same footer.
- The splash is the header =JourneyPage= is given, and it stands on every step rather than only the first.
- The splash keeps its own 964:323 ratio: the element states its width and height, and nothing crops it or states a height that is not the ratio's, because that is what cut the top and the foot off the wordmark before.
- The sign-in dialog carries the same banner element above its form.
- The banner does not crowd the party picker, the forced password change panel, or the refusal notices: it stands above the work, and the work still reads.
- A test asserts both the rail and the banner render on the screens that carry them, so a future layout change cannot drop either silently.

* Plan

1. Decide where the banner belongs. The setup screen draws it per screen; a shell that draws it for every visitor is the smaller change and the one that makes "every dialog" true by construction, so try the shell first and fall back to the page if the shell cannot tell a door from a form.
2. Put it on the sign-in dialog, above the credentials form and above the party picker, because the picker replaces the form rather than following it.
3. Put it on the registration door's rail, above the step, so it stays put while the step changes.
4. Assert it in the shell's or the page's test, whichever ends up owning it.

* Notes

- The artwork is =heroSplash= in =projects/ores.web/packages/web/src/assets/brand.ts=, which the site publishes at =/OreStudio/projects/ores.web/packages/web/src/assets/ore-studio-splash.png=; the prototype uses that URL so what a reviewer sees is the real banner and not a drawing of one.
- The rule the setup screen follows, and this task carries: the image states width 964 and height 323, the class is =h-auto w-full rounded-md border border-line=, and no height is declared anywhere. =JourneyHeader= renders it as the step header, which =JourneyPage= wraps in =mb-5 border-b border-line pb-5=.
- =PublicShell= already draws the header mark and the application name for a visitor. The splash is the larger artwork above the work, so it is a second element rather than a replacement for the header.
- The prototype needed both corrections and both are now in it. It drew a rail of its own, and it cropped the splash with =max-height= and =object-fit: cover= — the exact failure the setup screen's comment records. The prototype now borrows the application's tokens from =styles.css= as well, because a prototype in a palette of its own answers the wrong question.
