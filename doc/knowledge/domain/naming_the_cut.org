#+title: Naming the cut
#+description: The naming decision for the cuts cluster: what the prior art calls the fixed body of a valuation, why the word cut is kept for the general concept, what each component is called, and what a change of term would cost.
#+type: knowledge
#+level: cross
#+filetags: :knowledge:domain:cut:naming:
#+created: 2026-10-30
#+updated: 2026-10-30

* Summary

The cluster keeps the word *cut* for the general concept and qualifies it for
everything narrower. The recommendation is a *cut* for the label, the timepoint
and the body together, a *market data cut* for the market data component, a
*trade cut* for the deal component, and a *cut code*, always with the second word,
for the option-expiry sense. The candidate *snapshot* is rejected because this
repository already uses it for two other things, both of which are reads rather
than fixed bodies. The prior art, which is surveyed below, names the market data
component and leaves the whole body unnamed, so the choice is ours and rests on
the collision argument rather than on precedent.

* The prior art

** OpenGamma Strata

Strata models the fixed set of market data a calculation reads as a first-class
type and calls it *market data*. The package description states the subject:

#+begin_quote
Market data is used to capture the current market, such as quotes, FX rates,
discount curves, forward curves and volatilities.
#+end_quote

and names the type:

#+begin_quote
The main market data interface is MarketData which is keyed by MarketDataId.
#+end_quote

The implementation is described in the same package as "An immutable set of
market data", and an observable carries the source it came from, which the
package lists as `ObservableSource`
([[https://strata.opengamma.io/apidocs/com/opengamma/strata/data/package-summary.html][Strata
package com.opengamma.strata.data]]).

Three facts follow. Strata names the component rather than the whole body: there
is no type for the deals, the settings and the engine version taken together.
The name of the component is *market data*, which is the phrase this cluster uses
for its component. And the word *snapshot* does not appear in the package at all,
which means a snapshot is a term this repository introduced rather than a term
the prior art supplies.

** Murex

Murex publishes the architecture of MX.3 and lists a *market data server* among
the orchestration services, beside position, limits, collateral, XVA and
simulation servers. The same page reports "real-time and end-of-day value at risk
calculations"
([[https://www.murex.com/en/solutions/technology/mx3-architecture][Murex, MX.3
architecture]]).

The vocabulary is instructive for what it omits. The vendor names a server that
serves market data, and names *end of day* as a time at which computation
happens. No public page of that material names the fixed body of a valuation as
an object with a name of its own.

** Calypso

No public Calypso page that I could read names the concept. The searches returned
recruitment material and third-party summaries rather than vendor documentation,
and I did not use them. The finding is therefore a gap in the record and not
evidence either way.

** Regulators and industry sources

The public sources this cluster already cites name processes and instants, and
they do not name the fixed body. A prudential standard names the independent
price verification process and its admissible sources; a central bank publishes
one reference rate per day, at a stated time; a settlement system publishes the
start and end of its business day. Each of these supplies a time, a source or a
process. None supplies a term for the body a valuation reads.

* Both senses in the industry

The same word carries an expiry sense and a valuation sense in dealing practice.
An FX option expires at a time of day that the market names, and the cut code is
that name; a valuation day ends at a cut, and the cut fixes the day's data. Our
own cut code page records that we hold no public source which fixes the expiry
times, so the expiry sense is reported here as practice rather than as a cited
fact.

The systems surveyed above resolve the collision by never using the bare word for
the expiry sense. They speak of the market data a calculation reads, and of the
end of the day as a time. The collision in our cluster is therefore a collision
of our own making, and it has a grammatical remedy.

* The decision

| Object                        | Term             |
|-------------------------------+------------------|
| The general concept           | cut              |
| The market data component     | market data cut  |
| The deal component            | trade cut        |
| The option-expiry sense       | cut code         |

The rule that keeps the words apart is that the bare *cut* names the general
concept, and every narrower object carries a qualifier. *Cut code* is the only
use in which the word names a time rather than a body, and the qualifier marks
it.

* Why not snapshot

*Snapshot* is the strongest candidate and the one to reject, for a reason internal
to this repository. The word already names two things here, and neither is a cut.
[[id:CEC7844C-B3AE-4858-BF67-71F511007F82][Market Data Snapshot]] names the
resolution-side concept, a set of identifiers resolved into values.
[[id:4EE26B23-003B-4DF1-AA83-1196CC6810C3][Snapshots and cuts]] names the
stored-data reads, and its subject is what a read returns from rows that already
exist. Adopting *snapshot* for the general concept would give the repository three
meanings for one word, and the two existing meanings are exactly the things the
cluster's hub distinguishes the cut from.

A second argument is semantic. A snapshot is a capture of state at a moment. The
body of a cut includes the engine version, the code revision and the settings,
which are inputs to the computation rather than state that a market moved through.
A word that describes a capture of state therefore under-describes the object the
hub argues for.

* The other candidates

- *Market data snapshot* names the component, and this cluster calls that the
  market data cut. It also carries the collision above.
- *Valuation snapshot* is close to the concept, and it retains the snapshot
  collision and adds nothing that *cut* lacks.
- *EOD snapshot* and *close-of-business snapshot* name a kind. They exclude the
  flash cut, the start of day cut and the instant a process names, so neither can
  stand for the concept.
- *As-of snapshot* names the read, and this repository uses as-of for the stored
  data read rather than for a fixed body.
- *Valuation point* names the instant and not the body. In fund regulation the
  phrase names the moment at which the value of the scheme property is
  determined, which is a time, and adopting it would import that narrower meaning
  into a term that must cover the body, the label and the authorisation.

* What a change of term would cost

A change of term would rename five pages and rewrite twelve links, and the cost
is bounded, which is not the reason to keep the word.
