* Result

Done. The reference data part answers all three curve-configuration routes at the
BFF's paths, member names and status codes.

** The three routes

- =GET /api/refdata/curve-configurations= answers a party's configurations in
  name order, each with the count of curves it holds and the sections those curves
  name.
- =GET /api/refdata/curve-configurations/{id}= answers the document a reporting
  configuration is filled by, drawn as the sections the ORE schema declares: each
  section with its entries, every entry's leaves joined to the words the ORE
  parameter contract gives them and the values the value sets accept, the child
  elements the entry states, and the segments it holds with their kind and their
  quotes. A configuration no document fills is a 404.
- =PUT /api/refdata/curve-configurations/{id}= reads the stored document, checks
  each change against the contract and the value sets, writes the columns it names
  into the rows they belong to, and saves only the tables it touched. A version
  that moved on is a 409; a value outside its set is a 400.

** What the branch adds

- The curve section wiring as a C++ table, from the same generator that writes the
  BFF's TypeScript: one read of the projection, two surfaces, and the drift check
  compares the pair.
- The document flattened into the cells the wiring names. The document arrives
  typed, so its rows become cells by their own fields, and a column a row does not
  carry stays absent rather than empty text.
- The value set tables read in =ores.http.core=, beside the reader, so the
  reporting part and the reference data part hand it the same four tables; and the
  JSON shape helper moved to the gateway's own part for the same reason.
- The page drawn from the wiring and the contract, and the amendment that writes
  one column of one row in the row's own type.

** Two departures from the BFF, both stated at their site

- The BFF read a pattern off the ORE parameter contract, which has no such column,
  so a regex value set was never enforced. The route enforces the set's own
  pattern, which is the rule the data states.
- A value set the data states in a way this build cannot read is a 500 with the
  sentence, as the reporting part already answers one, rather than a page drawn
  with half its controls unchecked.

** What is not proved

The routes are proved against a client that is not connected, so their refusals
are covered and their happy paths are not exercised against a live estate. The
view and the amendment are proved against documents the tests build, which is
where their joins and counts are checked.
