#+title: The shell aggregator opts out silently on a missing overview or a misspelt flag
#+description: shell_command_surface finds the overview by a fixed directory depth and returns no surface when it is absent or its flag value is not recognised.

* What

=core.py='s =shell_command_surface= reads a component's shell opt-in from
the shell part's =modeling/component_overview.org=. The caller finds the
projects directory as =Path(templates_dir).resolve().parents[2]=, so it
depends on the depth of the templates directory. When the overview is
absent, the function returns =(False, ())=. The flag
=#+shell_command_aggregator:= accepts only =true=, =t=, =yes= and =1=, and
any other value also opts out. Make both cases fail loudly: a component
with opted-in entities and no overview is an error, and an unknown flag
value is an error.

* Why

The review of [[https://github.com/OreStudio/OreStudio/pull/2496][PR #2496]] found this. When the opt-out is silent, the
component-scoped registrar does not generate, and the shell has no menu for
that component. The cause is not visible from the generator output.
