* Goal

Every existing foreign key gets its removal behaviour, and the seeded data is
checked for the orphans that exist today. For each =cascade= child, decide
whether it also bumps its parent's version, so the model treats it as part of
the parent for versioning and for removal alike. The identity shape and its
entries go first, as the case that found the gap.

* Notes

- 642 links is too many to decide one at a time by hand. Write the first pass
  as a script that proposes a behaviour from the link (a =:parent_entity:=
  child with =:bump_parent_version:= is likely =cascade=; a reference from a
  trade is likely =refuse=), and review the proposal by component.
- The 36 links with =:bump_parent_version:= already behave as owned children:
  23 carry =:parent_entity:= and 13 do not. Propose =cascade= for all 36.
- The rows the writer skips today, such as an orphan shape entry, may hide
  orphans in the seed; the query finds them.
