* Goal

Every equity, FX and commodity script in ORE's library that has no element of its own is booked as a generic ScriptedTrade through the scripted builder, from a recipe stated as data, and ORE reads and builds it.

* Acceptance

- each such script has a recipe: a value rule per input, held as data, not as code per script
- the generated population holds one trade of each such script
- the ORE engine test reads and builds each, with no error of the trade kind
- a test fails when a library script is neither generated nor named as a script with an element of its own

* Plan

A script with no element of its own has no native trade to take its terms
from. Decided on 2026-11-21: a native type the generator already books carries
it. The catalogue's =Script-only recipes= table states, for a carrier type and a
script, where each input comes from in the carrier's rows, in the twin recipes'
grammar, so the evaluator, the transforms, the builder and the generator's
checks are the twins' own. An input the carrier states no term for takes a
literal.

- The generator reads both recipe tables and checks them alike. The compiled
  rows state whether each is the carrier's twin.
- The runtime books every scripted form of a native trade: its twin, then each
  script it carries, with an id =carried_id_for= draws by name, and an internal
  identifier =<native>-scripted-<script>=.
- The =Library scripts= table states how each library script is held: =both
  forms=, =element only=, =script only= or =not yet=. The generator fails when a
  script of the seed is missing, listed twice, or held otherwise than the recipe
  tables state; this is the acceptance's test of a script neither generated nor
  named.
- One trade of each script, carried by an equity type.

The families, a PR each:

1. The single-name variance family on EquityBasketVarianceSwap: VarianceOption,
   KIKOVarianceSwap, CorridorVarianceSwap, KIKOCorridorVarianceSwap,
   ConditionalVarianceSwap01 and 02, GammaSwap.
2. The rainbow call spreads and the worst-performance rainbows on
   EquityBasketOption.
3. The dispersion swaps and the correlation swap.
4. The forward-starting options, VolatilityBarrierOption, DualEuroBinaryOption
   and LadderLockInOption.

* Notes

** Barrier levels no underlying reaches

No carrier states a level near its underlying's price: the basket variance swap
states a variance strike, and its underlyings range from DHER.DE near 27 to
.NDX near 21,000. A barrier is therefore one the underlying never reaches: a
knock-in at zero, the User Guide's form of no barrier, a knock-out at one, and a
corridor from zero to ten million. ORE values KIKOVarianceSwap,
CorridorVarianceSwap and both ConditionalVarianceSwaps carried by the same
basket at the same value, -2995483.84 and -34388.52 EUR for the two recorded
carriers, which is the plain single-name variance swap each becomes. A carrier
that states a level relative to its underlying would let the barriers bite; that
is a follow-up, not this task.

** Scripts with an element of their own and no scripted form

Classifying the library showed scripts whose product a type of ours holds, with
no scripted form booked: Accumulator01 and 02 (the accumulators), TaRF,
OutperformanceOption, MinRainbowOption, the AssetOrCash rainbows, and the
Asian, average strike and lookback basket options. The =Scripted forms= table
does not name them, so the both-forms task did not twin them. The =Library
scripts= table holds them as =element only=, with the types that hold them.

* Result

First PR: the machinery and the single-name variance family. A native type the
generator books carries each script with no element of its own: the catalogue's
=Script-only recipes= table states where each input comes from in the carrier's
rows, in the twin recipes' grammar, and the generator checks it as it checks the
twins. EquityBasketVarianceSwap carries VarianceOption, KIKOVarianceSwap,
CorridorVarianceSwap, KIKOCorridorVarianceSwap, ConditionalVarianceSwap01 and
02, and GammaSwap; ORE reads, builds and values each. The =Library scripts=
table states how each of the library's 54 scripts is held, and the generator
fails when one is missing or held otherwise than the recipes state. The rainbow,
dispersion and option families follow.

Abandoned on 2026-11-21, superseded by the design of this story: a script-only product is booked against a schema of its own, not from a carrier native type's rows. The task moved here from [[id:0CAC2F0E-69EC-4497-8587-4E0A6593BC7D][Hold every product type the engine supports]] when scripted trades became a story of their own. The first PR, #4948, is on main and stays until the new story replaces it.
