* What

A service started against a database built from other SQL prints its schema-mismatch warning and
then dies with =free(): invalid pointer=, exit code 139. Every service that took that path exited
the same way on pauli on 2026-11-18, so a deploy that should have run with a warning ran nothing.

The warning is designed to let the product start: "The service starts anyway: a query against a
table that moved will fail and the rest of the product is unaffected." The crash defeats it.

* Why

The mismatch itself was expected — the images were built before a merge brought new SQL into the
checkout, and the database was recreated from the newer SQL. What was not expected is that the
diagnosis path corrupts memory: a person who reads "the service starts anyway" gets containers
that exited instead, and nothing in the message says the process is about to die.

Whatever the mismatch path allocates and frees, it does so wrongly. The fix belongs there, and a
test should start a service against a database whose recorded fingerprint differs and expect the
warning plus a running process.
