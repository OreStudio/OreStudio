#+title: Store a callable bond's call terms
#+description: The store keeps a callable bond's call dates but not each call's style, price, price type or accrual, so the ORE writer states fixed stand-ins.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Give each call date of a callable bond its own style, price, price type and
whether it includes accrual, as ORE's =CallData= states them. Today
=bond_issue_call_date= keeps only the date.

* Why

The ORE writer must state those four lists, so it writes the same stand-ins
for every call: Bermudan, at par, clean, with accrual. A callable bond imported
from a document whose calls differ, such as an American call or a call above
par, therefore exports with different terms than it was read with, and values
differently. The stand-ins were an empty style and a price of zero until the
bond builders task, which ORE refused.
