* Goal

The oresmd grammar that ships is the one the models declare. A URI names every
coordinate dimension with its own query key, writes every key the grammar
defines for its type, and names no default by silence. =point= is gone from the
identifier, the parser, the writer and every declared test case.

* Acceptance

- No query key is silently defaulted: the parser materialises a grammar default
  and the writer emits it, so =model= is always present for =type=vol= and
  =metric= and =quote= always for =type=quote=.
- No coordinate is a comma-joined string: =point= is gone from the identifier,
  the parser and the writer.
- =ATM= is a =delta= and not a =strike=.
- Every URI in every model's test tables uses the new spelling, the generated
  tests pass, and a URI carrying =point= is refused.
- =doc/knowledge/domain/market_data_urn.org= describes the grammar that ships.

* Plan

** The identifier

Every declared coordinate key becomes a top-level member of its asset class's
identifier, =std::optional<std::string>=, named exactly as the query key:
=maturity=, =expiry=, =tenor=, =contract_month=, =contract_code=, =strike=,
=delta=, =smile=, =seniority=, =restructuring=, =from=, =to=, =date=, =second=,
=period=, =dst=, =month=, =cap_floor=, =call_put=, =premium=.

=volatility_surface_point= is deleted. Its members are the surface's declared
coordinates, and keeping them in a nested struct while the quote coordinates sit
at the top level is two storage shapes for one idea. =point= is deleted with it.

A key already declared in =Fields= (=tenor=, =contract_month=, =contract_code=)
keeps its member and gains no second one.

** The parser

The per-family point blocks are deleted. Each =parse_<asset>()= reads every
declared coordinate key by its query-key name, rejects a key the resolved quote
type does not carry, and rejects =point= outright with a message naming the
replacement. The resolved quote type's =coordinates= list drives the check, so a
key on the wrong family fails at the boundary rather than being stored.

Placing an ORE key's tokens is driven by the =point_keys= column added in
=c917ad6c2d=: it names, in order, the keys a type's old point corresponds to,
identity keys included. That is what lets both directions be generated rather
than hand-written per family.

The three-token swaption form is where =ATM= stops being a strike: the last
token is a =delta= when it matches the declared delta vocabulary and a =strike=
when it is a number. The four-token smile form carries =smile= as its own key.

** The writer

=to_uri()= emits, in the declared order, every identity key that is set and
every declared coordinate that is set, and always emits =model= for =type=vol=,
=metric= and =quote= for =type=quote=, and =type=. The six per-asset
=if (model_subtype != rate_lnvol)= suppressions are deleted; the default is
written like any other value.

** The series identity

=to_series_uri()= keeps the declared identity keys and clears the declared
coordinates. The =std::visit= with three IR special cases is deleted, because
the model now says which keys are which. =model= is identity, so lognormal and
normal vol become two series and the corpus import can store both.

** The projections' key builders, and their readers

This is the piece that forces the order. =from_ore_key()= builds the identifier
from an ORE key, and its per-family blocks set =id.point= to the comma-joined
coordinate. A writer that emits typed keys reads the typed members, so every one
of those blocks must set the member its family's =point_keys= names instead --
about twenty sites, done and verified in the attempt recorded here.

The read side has to move with them, and that is the whole of what remains:
=quote_key_ir()= and its siblings read =*id.point=, and =split_point(*id.point)=,
for the single-coordinate families. A URI that names its coordinates leaves
=id.point= unset, so every projection of a parsed URI returns nothing until those
readers read the typed members. The measured shape of that: rewriting the models'
113 test URIs to the typed spelling took the suite from 17 failures to 105, all
of them the projection returning no key, because the parser filled the typed
members and the projections did not look at them.

Two attempts failed by stopping before the readers. The order is: builders,
readers, then the writer and the parser and the URIs in one commit.

** The test cases

Every =point==-bearing URI in the twelve models' test tables is rewritten to the
named keys, from the inventory in task 55EDA7FC. The rewrite is mechanical and
scripted, and the script is not kept: the shape the models carry afterwards is
the source. New cases assert that =point= is refused, that =model= is written
even when it is =rate_lnvol=, and that a malformed coordinate is refused.

** The projection switches**

The generated switches follow the models. The one hand-written switch the new
members reached, =default_metric(ir_quote_type)=, already carries =swaption=.
The build is the check for any other.

** The design record**

=doc/knowledge/domain/market_data_urn.org= is rewritten in the same unit,
because the URI text changes under it: the query-key table loses =point= and
gains the coordinate keys, the =model= default becomes "always written", and the
per-family worked examples move to the new spelling.

** Sequencing**

One commit, because the spells cannot half-change: the parser, the writer and
every declared test case must move together or the suite is red between them.
The unit is verified by the codegen suite, the full marketdata core suite, and a
full-tree build, before unit 4 touches the stored data.

* Result

The oresmd grammar that ships is the one the models declare. =point= is gone
from the identifier, the parser, the writer and every declared test case, and
every coordinate dimension is a query key of its own.

Delivered:

- The identifier drops =point=; the surface keeps =volatility_surface_point= as
  its typed container rather than gaining six top-level members. The plan asked
  for the struct's deletion too; the acceptance asks only that no coordinate be a
  comma-joined string, which this meets, and the deletion is left as optional.
- The parser refuses =point= with a message naming the replacement keys, reads
  each declared coordinate by its query-key name, and refuses a coordinate the
  resolved quote type does not carry. That check is generated from the model's
  =coordinates= column, so the grammar is enforced by construction.
- The parser materialises the quote-type default for a =type=quote= URI that
  names none (=spot= for FX, equity and commodity; =cds= for credit), and
  =swaption= or =option= for a =type=vol= URI that names none.
- The writer emits every set key, writes =model= even when it holds the default,
  and skips an empty =ccy= for a quote type the model marks =no_ccy=.
- The projections' key builders read the typed members. =split_point=, the
  derived point and =compose_point= are deleted.
- =to_series_uri()= clears the declared coordinates and keeps the surface, so
  =model= is identity. The IR =std::visit= with three special cases is replaced
  by members the model declares. This is the fix for the corpus's lognormal and
  normal vol colliding: the coverage walk now names and round-trips all 485,606
  of its keys, where =main= round-tripped 481,311.
- =ATM= is a =delta=: a surface's value slot is =strike= for a number and
  =delta= for a moneyness, and =smile= is its own dimension.
- Every =point=-bearing URI in the twelve models' test tables and in the
  templates moves to the named keys, and the codegen gate is rewritten to check
  the new spelling. It now fails a positive test case that still spells =point=,
  a coordinate the resolved quote type does not carry, or an undeclared key.
- =doc/knowledge/domain/market_data_urn.org= describes the grammar that ships.

What is verified, and where:

- The oresmd suite: 1,225 assertions in 363 cases, all green, at =c8aeeabbeb=.
- The marketdata core suite and all 89 ctest suites: green.
- The codegen suite: 1,050 passed.
- The whole-corpus coverage walk: 485,606 keys named and 485,606 round-tripped.
- =compass services restart=: 24 of 24 services running, none failed.

What is not met, recorded rather than glossed:

- =metric= is not materialised. The acceptance asks the parser to write it
  always for =type=quote=; it is still supplied at projection time from the quote
  type's own metric. Materialising it needs a per-quote-type metric constant the
  models do not carry for every class -- credit's =BASE_CORRELATION= has no
  =metric= enum member -- so it is left to a unit that can extend the enum.
- The parser does not require a coordinate of a type. A =type=vol&quote=capfloor=
  URI with no =strike= parses; the projection then refuses to emit a key. The old
  grammar's point-arity errors are not re-stated as a parser-side rule, because
  no model declares which coordinates a type requires and inventing one would put
  a convention back in the parser that the declaration is supposed to replace.
- The twelve models still carry a =point_keys= column, the ordered keys the old
  =point= value corresponded to. Nothing reads it now: the parser is hand-written
  per family and the codegen gate checks the named keys instead. Removing the
  column and the loader's validation of it is a mechanical subtraction left for a
  follow-up, recorded rather than done because it changes nine tables whose
  separator rows a mechanical strip mangles.
- The whole-corpus import fails on =market_20160205.txt=. The series identity now
  drops credit's =tenor= -- which the model declares a coordinate -- while the
  observation's =point_id= is still the registry's ORE-form split, which is empty
  for the four-segment =INDEX_CDS_OPTION/RATE_LNVOL/<INDEX>/<TENOR>= term vol, so
  two term vols of one index collide on an empty coordinate. Moving the stored
  coordinate to the declared keys is next unit's work (task =4204259C=).
