#+title: Removing a refdata code is not refused while records use it
#+description: A lookup delete closes the row without checking who refers to it; a record that still uses the code then fails its next save.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

A delete on a refdata lookup (rounding types, monetary natures, party types and the rest) is a rule that closes the current row. Nothing checks whether a currency, book, party or other record still names the code. Because each record's insert validates its codes, such a record cannot be saved again until someone changes the code it uses. Refuse a delete while records use the code, and say which.

* Why

The classification screen warns before every removal because the server cannot say whether the code is in use. The warning should become a refusal with the names of the records that still use it.
