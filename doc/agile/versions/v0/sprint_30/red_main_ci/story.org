* Decisions

- The GCC failure is a name collision, not a GCC bug: member =root::entry=
  shadowed struct =entry=. Renaming the member to =entries= fixes it and reads
  correctly, because the field is a repeated child element.
- The Windows failure is a runtime gap, not a code error: clang-cl defines
  =_MSC_VER= but links no =__divti3=. Every MSVC-family target now uses
  =boost::multiprecision::int128_t=, which needs no runtime helper. The type is
  arithmetic-equivalent for the two expressions =billing.cpp= uses.
- The =ores.web.tests= failure is a stale fixture: the step schema gained
  =progress=, =progress_done= and =progress_total= with defaults, and the
  fixture still listed the old shape. The defaults are deliberate, so the
  fixture moved to the shape a browser receives.
