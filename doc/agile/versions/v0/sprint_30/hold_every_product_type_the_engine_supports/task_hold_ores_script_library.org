* Goal

Every script in ORE's library is a row with its code, its NPV and results, and one row per input stating its name, its type, scalar or array, and the rule a valid value follows; a scripted trade's variables are checked against its script's inputs.

* Acceptance

- every script in external/ore/examples/Products/Input/scriptlibrary.xml is seeded as a script row with its code, product tag, NPV and results
- each script states its inputs as rows: name, type (Number, Event, Index, Currency, DayCounter), scalar or array, and a value rule; the inputs are mined by a script from the script's free variables and the library's comment blocks, not typed by hand
- the run's scriptlibrary.xml is written from the rows, and ORE reads it
- a scripted trade whose variables miss an input of its script, or state one of the wrong type, is refused with the input's name
- a check fails when a later ORE library adds, removes or changes a script's inputs

* Plan

1. Model the library column by column as seven trading entities: the script, each variant's code and NPV variable, its results, its calibrations and their strikes, its coarsenings, and the script's inputs. The rows are the system tenant's reference data.
2. Mine the rows from ORE's library with a script, the inputs from the code rather than the comments: an input is a variable a variant reads and does not assign or declare; its type is what the code does with it; it is an array when the code indexes it or asks its size; its rule is the script's REQUIRE statement about it.
3. Measure the miner against every scripted trade of ORE's examples, and register its --check as a local check.
4. Write scriptlibrary.xml from the rows, and have the engine run read it.
5. Refuse a booking whose scripted trade does not state its library script's inputs as the script reads them.

* Notes

** What the mining found

- The comment blocks are stale in places: the window barrier option's lists =ObservationDates=, while its code reads =StartDate= and =EndDate=. The inputs come from the code; a comment only adds a description.
- An input is the union over the variants: =BermudanSwaption= reads =ExerciseSettlement= only in its AMC variant, and a trade states what every variant it may run reads.
- A variable the code assigns is the script's output, not an input, even when it is not declared; one it only reads is an input even when it is also reported as a result (=PayCcy= is reported as =notionalCurrency=).
- ORE spells the day counter type =Daycounter=, which the column keeps.
- Four example trades state a variable their script never reads, which ORE ignores; the comparison counts them apart from misses.
- A trade that carries its own code, or names a script the library does not hold, is not checked against the library.

* Result

ORE's script library is reference data: 54 scripts, column by column, seeded by a script that mines the library, with each script's 750 inputs taken from its code. The run's scriptlibrary.xml is written from the rows, and the ORE engine prices every generated scripted trade on it. A generic scripted trade that leaves out an input of its script, or states one as another type or shape, is refused with the input's name.

- The run's scriptlibrary.xml is written from the rows, and ORE reads it: met; the engine test writes it from the store.
- A scripted trade that misses an input or states the wrong type is refused with the input's name: met; three service tests.
