#+title: Nothing ends a session, so every session is an open one
#+description: ores_iam_sessions_tbl carries end_time text not null default '', and an empty end_time is what makes a session active. Nothing ever writes it: after signing out through POST /api/session and DELETE /api/session the row still has an empty end time, and a live read of the fleet's sessions found 17 rows and not one with an end time. The consequences for the credentials work are that iam.v1.sessions.active answers every session the deployment has ever created rather than the open ones, the audit screen cannot show a session that has ended or a sign-out at all, and iam.v1.sessions.end - the operation the audit and rescue screens both want, to end another account's session - has no counterpart writer behind it either. Found while implementing the active sessions read (PR #2468).
