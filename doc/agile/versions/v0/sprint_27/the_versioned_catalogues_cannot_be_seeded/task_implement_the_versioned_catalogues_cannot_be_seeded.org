* Notes

Three defects follow from one commit. =a2dcf034fa= made the three closed
trading vocabularies regular, versioned tables. It changed their shape but not
the three writers that depend on it.

- The generated insert trigger validated =change_reason_code= through the
  ={{^domain_entity.has_tenant_id}}= branch, which called
  =ores_dq_validate_change_reason_fn= with one argument. The function takes
  =(p_tenant_id uuid, p_change_reason_code text)=, so the branch emitted SQL
  that no database accepts. The branch had never run: before =a2dcf034fa= a
  tenantless entity carried no audit columns, so it never reached the
  =has_audit_columns= guard above it. Giving these three tables an audit tail
  made the dead branch live.
- The seeds kept =on conflict (code)=, which matched no unique constraint once
  the key became =(code, valid_from, valid_to)=.
- The seeds supplied neither the audit columns nor =version=, all of them
  =not null= in the new shape.

The table stays versioned. #2889 records that whether these tables keep the
versioning =a2dcf034fa= gave them is an open design question, and this task does
not answer it: it makes the shape that is committed work. A decision to make
them immutable again would delete the audit tail and restore the simple seed,
and is a separate change.

The models' prose still describes the tables as immutable, and the predicates
in =ores.trading.trade.org= still call the lookup "a database foreign key" where
the generator now emits a soft check. That prose belongs to the design
question, so it is left alone here.
