* Plan

Survey program, in order:

1. *Inventory the six unwired engines* (=black_karasinski_process=,
   =black_derman_toy_process=, =affine_term_structure_process=,
   =heath_jarrow_morton_process=, =libor_market_model_process=,
   =quadratic_gaussian_process=). Record what each needs to reach the
   system: factory method, seed rows, parameter structs, child
   tables, config domain/repository work, Qt form.

2. *Extract the G2 wiring precedent* (task
   [[id:8B09FCC2-0D30-4AF2-A205-01FC0A41ED3D][Wire G2 into the system]],
   DONE): the reusable step list per engine — strongly-typed parameter
   struct, =process_factory= method, seed row, child table + migration,
   config extension, =IrCurveGenerationConfigDetailDialog= form,
   controller mapping.

3. *QuantLib reference*: inventory =/home/marco/Development/ORE/Engine/QuantLib=
   — the test-suite reference vectors for short-rate and forward-rate
   models, and any jump-process references for the FX side. Note which
   of our engines have direct QuantLib counterparts and which do not
   (QG is the most original).

4. *New IR models*: two-factor Hull-White (likely thin — the affine
   engine already reproduces HW2/G2 exactly), shifted log-normal /
   displaced diffusion, normal (Bachelier). Decide per model whether it
   is a new engine or a parameterisation of an existing one, and name
   the QuantLib class + test to port.

5. *FX jump/Poisson process* (capture
   [[id:84635A47-0E1A-4B67-A775-15F256D54A2D][Implement jump/Poisson
   stochastic process component]]): =IStochasticProcess= in
   ores.marketdata.api, a =process_factory::make_process()= branch in
   ores.synthetic, and =FxSpotRateEditor= UI exposure (placeholder
   exists). Survey jump-size distribution options and QuantLib
   references.

6. *UI surfaces*: =IrCurveGenerationConfigDetailDialog= parameter
   forms, =FxSpotRateEditor= Component Tools panel, catalogue seed
   data and combos. Assess whether the form-switching machinery
   generalises beyond the G2 one-off.

7. *Deliverable*: the task breakdown — one task per engine wiring, per
   new IR model, and for the FX jump process — with effort estimates,
   ordering, and QuantLib references. Populate the story's Tasks
   table.
