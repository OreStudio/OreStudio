* Acceptance

- each of the three types names an instrument table, with the barrier levels and the observation schedule in rows
- the projection reads and writes each element, value for value
- each type has a builder, and the catalogue routes all three
- the generator books one trade of each type through its builder, and the recorded trades hold it
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: no list, basket or schedule is held as text

* Plan

The three types route to the scripted instrument table through the class-read
path, as the catalogue's scripted form says. Native rows would need new columns
on the equity barrier row for the settlement terms, the kiko type and the
barrier window.

- The class-read path reads and writes a =BarrierData= member, and a member
  that holds barriers (=Barriers=, =TransatlanticBarrier=). A holder's barriers
  land in the shared barrier rows under the roles every family uses (=barrier=,
  =transatlantic=), its schedule under =barrier_schedule=, and its own leaves as
  parameters named for the holder and the leaf, such as =Barriers.KikoType=.
  The writer states them in the schema's order, because =Barriers= is a
  sequence.
- The scripted carrier gains barrier and barrier level rows.
- An element that states one =Underlying= or a list writes the form its rows
  hold.
- Builders: =window_barrier_option_builder= (equity and FX) and
  =equity_generic_barrier_option_builder=.

* Result

EquityWindowBarrierOption, FxWindowBarrierOption and EquityGenericBarrierOption
are held in the scripted instrument table. The barrier levels are barrier level
rows, the monitoring schedule is a schedule row, and the kiko type is a
parameter. The round-trip test reads ORE's FX window example and the user
guide's generic barrier, with two barriers, rebates, a kiko type and a
transatlantic barrier, and writes them back. Each type has a builder, the
catalogue routes all three, and the generator books one trade of each. The ORE
engine builds the recorded trades with no error, and the recorded FX window
trades state every path ORE's example states.

The first engine run refused a generic barrier whose expiry fell on a Sunday:
ORE rolled the expiry past a settlement on the same day. The generator now
settles five days after the expiry.
