** The jobs build cold

The measured sccache hit rate is 17.96 % on the one job that passed,
3.21 % on the Linux clang job, and 0.00 % on the macOS debug job. A
cold build executes 5539 to 9515 compile requests. That work, not a
compiler or test defect, is what fills the six hours.

** The workflow facts behind the cold builds

- =.github/workflows/continuous-linux.yml= has a =Free disk space= step
  (lines 103-142). =.github/workflows/continuous-macos.yml= has no such
  step.
- The macOS workflow deliberately does not persist sccache across runs,
  because GitHub's =actions/cache= is capped at 10 GB per repository
  and shared by every variant (comment at
  =.github/workflows/continuous-macos.yml= lines 125-132). The macOS
  cache is empty at the start of every run.
- The Linux clang jobs install LLVM 19 before the build. That adds wall
  clock and does not raise the hit rate.
- The Linux debug jobs add =code_coverage=1=, which makes the build
  larger. The macOS debug job does not.
- The macOS workflow sets =CMAKE_BUILD_PARALLEL_LEVEL=2=.

** An existing capture already diagnoses the cache

[[id:86E3CEA4-B44D-498A-90EB-88CBCE440C70][sccache's cache is on
GitHub's built-in actions/cache, capped at a fixed 10 GB]] names the
shared quota and the cross-variant eviction, and recommends an external
sccache backend. This task shows that the same cause now pushes the
jobs past the runner time limit.

* Result

No compiler and no test defect caused these failures. The jobs build
almost entirely from cold, and a cold build no longer fits in the
runner's six-hour budget or on the macOS runner's disk.

| Job | Root cause | Change that clears it |
|-----+------------+-----------------------|
| =linux-clang-debug-ninja=, =linux-clang-release-ninja= | Cold rebuild. The sccache hit rate is 3.21 %, so the job compiles 7932 requests and reaches the 6h0m0s limit. | Move sccache to an external backend, so eviction by the shared 10 GB quota stops discarding the clang cache. |
| =linux-gcc-debug-ninja= | The runner sent a shutdown signal and the job exited 143. The log holds no build or test error. | None. This is infrastructure. Re-run the job. |
| =linux-gcc-release-ninja= | Not a cause of failure. It passed in 4h05m53s at a 17.96 % hit rate. | Keep it. It is the closest job to the limit that still passes. |
| =macos-clang-debug-ninja= | Disk exhaustion. A 0.00 % hit rate forces all 5539 requests to compile, and the runner fills before the link of =libores.shell.refdata.a=. | Add the Linux =Free disk space= step to the macOS workflow. Persist or externalise the macOS sccache. |
| =macos-clang-release-ninja= | The 6h0m0s job limit, from the same cold build. | The same changes as the debug job. |

Recommended order:

1.  Add the =Free disk space= step to
    =.github/workflows/continuous-macos.yml=. This is cheap and clears
    the disk failure on its own.
2.  Move sccache to an external backend, per capture
    [[id:86E3CEA4-B44D-498A-90EB-88CBCE440C70][86E3CEA4]]. This is the
    root fix, because it keeps the caches warm on every platform.
3.  Revisit the macOS decision not to persist sccache, now that a cold
    macOS build exceeds the job limit.

The fix itself is out of scope for this story. It belongs in its own
story, with the external cache backend as its first candidate.
