* Goal

Extend the parameter definition with a label, a help line, a full description, a default, a format, the release that introduced the parameter and the release that removed it. Seed the 15 Setup parameters of the engine settings with the text of the prototype, and link each engine settings column to its definition, so the screens, the importer and the checks read one source.

* Acceptance

- The parameter definition holds label, help, description, default, format, introduced_in and removed_in, and the model, the generated SQL and the C++ carry them.
- The 15 engine settings are rows of the definition in the Setup scope, each with the full description, default, format and release range of the prototype.
- Each engine settings column names its parameter definition, and a test fails when a column has none.
- The analytic parameters keep working while the new fields are empty. The analytics task later filled the fields and made them required.

* Plan

1. Add seven nullable columns to the model =ores.reporting.parameter_definition=: =label=, =help=, =description=, =default_text=, =format=, =introduced_in= and =removed_in=. Regenerate the SQL, C++ and TypeScript. A null =removed_in= means the parameter still exists.
2. Keep the 15 texts in one Python module in =projects/ores.sql/utility=, as =file_type_descriptions.py= does for the file types. The words come from the prototype =see-the-engine-settings-a-party-holds=. A generator writes =reporting_setup_parameter_definitions_populate.sql= and has a =--check= mode. The existing seed has no generator and covers only analytic parameters, so the new script owns the Setup scope only.
3. The link between a column and its definition is the name. The column =n_threads= matches the Setup parameter =nThreads=. A pgTAP test fails when a value column of an engine settings part has no definition, or when a definition has no column.
4. The importer keeps its =engine_binding= table. Reading it from the definitions is a later change.
5. Keep the prototype and the seed in step: a check compares the texts of both.

* Notes

- The link between an engine settings column and its definition is the name. The column =n_threads= is the Setup parameter =nThreads=. A pgTAP test checks both directions. A foreign key would need a column on each part table for no gain.
- The texts are those of the prototype =see-the-engine-settings-a-party-holds=. Most describe the effect and when to change the setting. Only =log_mask= and =observation_model= give worked values. The owner may ask for examples on the others.
- =introduced_in= holds the text a screen shows, for example =1.8.0.7 or earlier=, so a bound the project could not measure stays visible.
- The seed of the analytic parameters had no generator. The task that documents the analytic parameters added one.
