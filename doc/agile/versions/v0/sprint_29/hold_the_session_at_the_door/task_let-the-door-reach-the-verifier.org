* Goal

A door that is opened before the lock is fitted still works once the lock is in place. The door asks for the verifier at each sign-in instead of keeping the one it was handed at construction, and refuses to ask IAM for a token it could not check.

* Acceptance

- The door takes a way to find the verifier, not a verifier, so a verifier installed after the door is built is the one it uses.
- A sign-in refuses before it asks IAM when no verifier is configured, because a token it cannot check is not a session.
- A case proves the door refuses while no verifier is configured and stops refusing once one is installed.
- A running deployment signs in a browser user and sets the session cookie.

* Plan

- The door takes a =std::function<shared_ptr<jwt_authenticator>()>= instead of the
  verifier. One caller exists, the application, and it passes a lambda over the
  server, so the door reads whatever the runner installed.
- The verifier check moves to the top of =sign_in=, before IAM is asked. A token
  that cannot be checked is not a session, and asking for one spends a request to
  answer a refusal that reads like the caller's fault.
- The cases that build the door with no verifier use one named finder, so the
  meaning of =nullptr= in those three places becomes a name.
- A new case installs a verifier after construction and proves the door stops
  refusing. It cannot reach IAM, so what it asserts is that the refusal is gone.

* Result

The door no longer keeps a verifier it was handed before there was one. It takes
a way to find the verifier and asks on every sign-in, so the one the service
runner installs is the one that checks the token. The application passes a lambda
over the server, which is where the runner puts it.

The check also moved ahead of the request to IAM. A gateway that cannot check a
token no longer spends a round trip to fetch one, and a misconfigured deployment
answers the same refusal whether or not IAM is up.

Proven on the deployment once main compiled again: a sign-in over HTTP answers
=200= with the principal and a session cookie, where it answered
=Authentication is not configured= before.
