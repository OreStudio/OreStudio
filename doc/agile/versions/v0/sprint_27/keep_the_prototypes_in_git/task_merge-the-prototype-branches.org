* Goal

Main carries every prototype. The three chain tips merge, so all seven
prototype branches become ancestors of main; the =/prototype= hub answers
every prototype route, and the onboarding screens, which their branch wired
onto the application's own routes, are re-homed under the hub. The web
package stays green: it typechecks, its tests pass, and the site check is
clean on the changed pages.

* Acceptance

- The three chain tips merge into main and the seven prototype branches are
  their ancestors, so git reports each of them merged.
- The hub answers every prototype route: credentials, operations and
  onboarding; no prototype route collides with an application route.
- The web package typechecks and its tests pass with the prototypes on main,
  and the site check is clean on the changed pages.
- The journey records and the prototype task docs state main as the
  prototype's home, so no document calls the prototypes unmerged.
- The story's inventory lists every prototype branch, backed by a sweep of
  every remote branch.

* Plan

1. Sweep every remote branch for prototype paths, so the inventory cannot
   miss one.
2. Merge the three chain tips in acceptance order, oldest first:
   =prototype/new-party-journey= (onboarding), =prototype/audit-sign-ins=
   (credentials), =prototype/operations-journeys= (operations). Each merge
   keeps a merge commit, so the branches stay merged in git's own record.
3. Resolve conflicts toward main for every shared file a prototype branch
   drafted earlier (the sprint 25 documents, the i18n locales, the password
   field and policy, the sign-in page, the dev stack script): main carries
   the merged successor of that same work. Keep the prototype screens as
   accepted.
4. Author the hub once, after the last merge: the credentials and operations
   route tables unite, the shell props follow the screen's audience, and the
   onboarding screens gain hub routes under =PublicShell=, because their old
   routes belong to the application now.
5. Verify: the web package typechecks and its tests pass; the site check
   passes on the changed pages; the drift checks that cover =projects/= run.
6. Update the records: each journey's Prototype section, the prototype task
   docs, and the story inventory.
7. Close the task, raise the PR, and merge it at the operator's word.
