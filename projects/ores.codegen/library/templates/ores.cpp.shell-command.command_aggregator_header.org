The class the shell host calls once to install a component's command
surface. One unit owns one submenu, so the registrar is the list the host
does not have to know: it declares one =register_commands= and nothing
else.

The file lands in the shell's =application= part, because the registrar is
the host's wiring rather than the component's own units. Those units stay
in the component's adapter part, =projects/ores.shell/{component}/=, and
the aggregate header includes them across the two parts, under the shared
=ores.shell/= include prefix the parts already use.

The registrar takes the root menu and the session, which is the whole
context a unit reads: the generated =list= verb spells paging as
=--offset= and =--limit= flags rather than through the shell's pagination
state, so no unit asks for more and the registrar carries nothing it does
not pass on.

The list itself is not in the model. The generator injects it at render
time from the component's opted-in entity models plus the component's
declared local units, the same way =ores.cmake.component.files_*= receives
a directory scan. The archetype therefore holds the shape of the list and
its call, and the component's declaration supplies the entries.
