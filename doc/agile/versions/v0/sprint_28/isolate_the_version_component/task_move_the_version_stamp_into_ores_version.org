* Result

The commit is out of every binary and in a manifest read at runtime, so a
commit changes no compiled file.

=version.cpp= no longer contains the commit, so =copy_if_different= leaves it
alone and nothing recompiles or relinks when a commit lands. The commit,
branch and dirty flag are written to =version.manifest= beside the binaries
by the same generator, and =build_info()= reads the first manifest that
carries =build_info=, caching it in a function-local static. The manifest is
not a BYPRODUCT or a dependency of anything, because a build input that
changes every commit is what relinks the tree.

No =ores.version= component was created. With nothing embedded the cascade
disappears on its own, so a separate shared library would have bought a
codegen ceremony for one translation unit and no benefit.

Measured:

| Build | Compiles | Links |
|-------+----------+-------|
| A commit lands, nothing compiled changed | 0 | 0 |
| A genuine change to =version.cpp= | 1 | 177 |

The first row is the case that used to recompile =version.cpp= and relink
all 179 targets. The second is the mechanism working as designed: a real
content change still costs a real relink, and the stamp is no longer what
drives it.

Staging was the part the design first got wrong. Neither stager copies
=publish/= wholesale, so both had to carry the manifest explicitly:
=docker/stage-runtime.sh= into its flat =bin/=, and
=library_partition.stage_for_build()= beside each service in
=services/<svc>/bin/=. Copying it into the flat =bin/= before the =ldd= walk
is a trap: =ldd= fails on a non-binary and that script runs under
=set -euo pipefail=, so the staging aborted in silence and produced an image
carrying no libraries at all. The walk is now tolerant and the copy happens
after it.
