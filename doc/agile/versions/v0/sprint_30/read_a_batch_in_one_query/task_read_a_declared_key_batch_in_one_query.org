* Goal

A bulk request to a service whose declared key is not the storage key reads its rows with one query per batch, as every other generated service does.

* Acceptance

- The repository template declares a batch read by the declared key, with the same party rule as the single read, wherever it generates the single read.
- The service helper reads a declared-key batch with that read; a model that states its own single read keeps working.
- The regenerated services and repositories build, their suites pass, and the drift gate on both addresses is clean.

* Plan

- 70 services read a batch one key at a time, because their declared key is
  not the storage key. Every finder they call takes one text value, and 68 of
  the 70 are generated: a tenant filter, one column equality and the window,
  and for 36 the session's party filter.
- Each generated finder by the declared key gains a batch overload over a
  vector of values, with the same tenant, window and party rules, an =IN= over
  the column, and the 1,000-key chunks of the batch =read_latest=. The finder
  is marked =is_declared_key_finder= in the codegen model.
- The service helper reads a declared-key batch with that overload and joins
  each row back by the declared key's text form (=declared_row_text=), the
  same conversion =declared_key_text= states for the key.
- A model that states its own finder keeps reading per key unless it states
  the batch form too. iam's role finder was a hand-written copy of the
  generated one, so its paste block goes. iam's account finder reads only the
  session's tenant, by design, so its model states the batch form beside it.

* Result

A service whose declared key is not the storage key reads a batch with one
query. No generated service reads a batch one key at a time any more.

- Acceptance 1 holds: each generated finder by the declared key has a batch
  form with the same tenant, window and party rules and 1,000-key chunks.
- Acceptance 2 holds: the service helper reads a declared-key batch with it.
  iam's role now uses the generated finder; iam's account states the batch
  form of its own finder, keeping its tenant-only rule.
- Acceptance 3 holds: 13 of the 14 touched core suites pass, with dq at 126
  test cases including the two new batch tests; synthetic fails only the case
  main fails too. A join that drops every row fails both new tests. The codegen
  unit tests pass, 1,787 of 1,787.
