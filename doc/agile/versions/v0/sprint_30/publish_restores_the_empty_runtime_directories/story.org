runtime directories the staging leaves empty, so the base image finds every

* Acceptance

- A nightly run whose clang-release leg staged the tree publishes every image to ghcr under the release tag and `main`.
- The publish job does not depend on an empty directory surviving an artifact upload.

* Decisions

- *The job recreates the paths, not the staging.* Write a placeholder file into the staging and the image ships it; creating the directories in the job that downloads the artifact leaves the images unchanged.

* Out of scope

- Uploading `build/docker-stage/bin`, which the library partition has already consumed.

* Result

The publish job recreates the three runtime directories the staging leaves empty, so the base image
finds every path its Dockerfile copies and the hierarchy behind it can be built. The failure it
removes was the whole job: nothing was published while the first COPY could not resolve.
