* Goal

A junction write that claims no row exists is refused when a live row exists, and every writer that means to replace a link says so.

* Acceptance

- The junction insert trigger refuses version 0 on a live row with already_exists, unless the transaction allows a replace.
- Every writer that relies on replacing a live link either states its claim or sets the replace signal.
- A repository test proves a duplicate junction create is refused and writes nothing.

* Plan

- Mirror the entity trigger in the junction trigger template: a version of zero
  on a live link raises =already_exists= unless
  =ores_utility_version_replace_allowed_fn()= is on. Regenerate the 27 junction
  tables.
- List the writers of the junction tables. The SQL publish functions already
  state the replace signal; the seed scripts run on an empty database. The C++
  tenant provisioner states =any=.
- Prove it by observation rather than by reading every writer: recreate the
  database, which runs every seed script, and provision Acme, which runs every
  provisioning writer. A writer that relied on the old replace fails there.
