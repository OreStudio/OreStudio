* Goal

The bond family's document shape is generated from the model, not hand-written
in C++. =bond_instrument_data= and the 22 document types beside it stop being
hand-written headers and become =field_group= models, and the export batch can
then carry the bond family as a generated type.

* Acceptance

- =bond_instrument_data= and the 22 document types beside it are declared as
  =field_group= models under =projects/ores.trading/modeling/=, and their C++
  headers and TypeScript interfaces are generated.
- The generated C++ structs declare the same members, in the same order, with
  the same types as the hand-written ones, so the bond mapper and the ORE
  import and export paths compile with no change to their member accesses.
- No non-generated behaviour is lost: =bond_leg_data::is_empty()= and the
  =stamp_ids(bond_instrument_data&)= overload move to a hand-written ops header.
- =bond_schedule_data.hpp= and =bond_instrument_data.hpp= carry the generated
  banner; no document struct is declared in a hand-written header.
- The trading drift gate is clean and the ORE import/export round trip is
  unchanged.

* Plan

1. Field groups already generate a C++ domain header (=ores.cpp.field-group=)
   and a TypeScript interface (=ores.ts.domain=), so the container needs no new
   model type. The one codegen gap is that a field group's TypeScript interface
   emits no imports for the types its members reference, which the existing
   group TS files never needed because their members are scalars. Add that
   derivation.
2. Declare each document struct as its own =field_group= model, one file each,
   transcribing members, order, types and defaults from the hand-written
   headers.
3. Move the behaviour that is not data — =bond_leg_data::is_empty()= and the
   =stamp_ids= overload for the carrier — into a hand-written
   =bond_document_ops.hpp=, and point the call sites at the free functions.
4. Delete the hand-written declarations and let the generated headers take
   their paths.
5. Verify: regenerate the component, build, and run the ORE mapper round-trip
   suite.

* Notes

- The generated headers carry the same structs as before, so nothing in the
  bond mapper, the ORE importer or the exporter changed beyond the include of
  =bond_document_ops.hpp= and the two =is_empty= call sites.
- The C++ field-group template writes one =@brief= line per member, so a
  member's long explanation belongs in the model body rather than in its field
  description. The struct-level prose carries the fidelity notes.
- The generated TypeScript interface for a group imports the types it names.
  Before this change no group needed an import, because every existing group
  declares scalars only.
- The =bond_leg_data= field descriptions are new one-line texts: the
  hand-written struct described its members in one block comment, and the
  template needs a line per member.
- =ores.trading.api.puml= is hand-maintained; the =is_empty= method was
  removed from it. The PNG is rendered by the =generate_ores.trading.api_diagram=
  target and was not re-rendered here.

482159 assertions, the trading drift gate is clean, and the scaffold defect
