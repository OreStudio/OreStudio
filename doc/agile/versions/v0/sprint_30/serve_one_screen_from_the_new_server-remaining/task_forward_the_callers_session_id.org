* Goal

Send the caller's session id with every request the gateway forwards, as the BFF does, so a service that keys on the session, such as IAM's party switch, sees the same caller through either server.

* Acceptance

- Every forwarded request carries the caller's session id when the token states one.
- A party switch through the C++ server succeeds where the BFF's does, proved live.
- A test proves the session id travels with a forwarded request.

* Plan

Found while proving the trade reads live on Acme. A tenant administrator who
signs in lands on the tenant's System Party, which holds no trades, and must
switch to an operating party. The BFF's switch succeeds. The C++ server's
answers 401 "Your session has ended": IAM logs "party ... not in account's
party list (account has 0 parties)" for it, and logs a session_id for the
BFF's request and none for the C++ server's. The BFF sends its session id on
every authenticated call; the gateway forwarded the caller's token alone.

Decisions:

- =forward_on= forwards on =caller_client=: the caller's token as a
  delegation, and the session id the token's claims state as
  =Nats-Session-Id=, through the NATS client's own =with_session_id=. Every
  forwarded request goes through =forward_on=, so every service sees the
  caller's session, as it does from the BFF.
- The session id is read from the token's claims, so no route states it, and a
  token that states none forwards as before.
- =nats_client= keeps no accessor for the id, and adding one would rebuild every
  component on =ores.nats=, so the test proves =caller_session_id= and the live
  switch proves the header reaches IAM.
