* Goal

Write the document back from the same tables. The write direction need not
mirror the read direction; it has to be valid, cheap and lossless. Three rules
carry it: schema order, present fields only, and a decimal form that never
exponentiates.

* Plan

*The direction is a walk of the table, not a replay of the reading.* The
emitter takes the same /document_type/ the binder takes and walks the record
in table order, which the generator emits in schema order. Nothing about the
document that was read survives, so a record built by any other route writes
the same way.

*Three rules carry it.*

- *Present fields only.* A field whose presence bit is clear writes nothing.
  A required field whose bit is clear is an error, not a silent omission: the
  writing would not validate, so it is not made.
- *A decimal is plain text.* The writer calls the decimal's own canonical
  rendering, which never exponentiates and never invents a column scale. A
  continuous quantity uses the shortest text that reads back to the same
  double, and may exponentiate because =xs:float= accepts it.
- *Escape in one scan.* A text node escapes =&=, =<= and =>=; an attribute also
  escapes ="= and the whitespace a parser would normalize away. A value that
  needs none of them is copied whole.

*The table grew one thing: a repeated member's operations.* A repeated member
is a =std::vector= whose element type only the generated code knows, so
=field= now carries a =vector_ops= of three functions -- append, count, at.
The reader appends; the writer measures and indexes. Before this, the row
carried only =append=, which is why the reading existed and the writing did
not.

*The writing found three defects in the generator.* None of them was visible
from the reading, because the reading tests counted documents rather than
comparing values:

- *A repeated compositor repeats its members.* =conventions.xsd= states the
  root as =xs:choice minOccurs="0" maxOccurs="unbounded"=, so every member
  may appear any number of times. The generator read each member's own
  =maxOccurs= and modelled Deposits as one optional record, so a document with
  twelve Deposits bound twelve values into one record and the writer emitted a
  single =<Deposit>= with the values concatenated. The compositor's repetition
  now reaches its members.
- *A repeated leaf carries its element's own kind.* Every repeated leaf row
  said =scalar_kind::text= regardless of the element, so a repeated
  =xs:integer= wrote =std::string= values into a =std::vector<std::int64_t>=.
  It was silent heap corruption rather than a wrong answer, and the netting
  family's =Currencies= is the case: =vector<std::int16_t>= over an
  enumeration, read as strings.
- *An enumeration index needs its spellings.* A repeated enumerated element
  now has =scalar_kind::enumeration=: the reader validates the spelling and
  stores the index, the writer renders the spelling back.

*A generated record states its own zeros.* An =int16_t= member with no
initializer is indeterminate in a default-initialized record, so a record
built by hand carried garbage into a writing and failed on an enumeration
index that was never set. Every numeric member now states = 0=. The decimal
already defaulted to zero.

* Result

fields whose row says they appeared. Its fourth acceptance criterion, that a
reading of the output yields the same values, is proved by the round-trip
task rather than here, because that is where the harness lives.
