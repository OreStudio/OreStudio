* Goal

The Sign-ins screen reads as the rest of the application does. A username
opens that person's profile. The lock state is a badge painted from the badge
catalogue, in the catalogue's colours. The failed attempts tab has a knob that
hides accounts that never signed in, so the tab shows the accounts that an
attacker or a forgotten password could be locking out.

* Acceptance

- A username on Sign-ins and Rescue access opens =/people/<username>=.
- The lock state on Sign-ins and Rescue access is a badge from the catalogue
  (=account_locked= red, =account_unlocked= green), with no hand-picked tone.
- The failed attempts tab has a checkbox that hides accounts that never signed
  in. It is off by default.
- The web tests, the type check and Prettier pass. The en, fr and pt catalogues
  keep the same keys.

* Decisions

- The Operations area, its menu entry and its cards come from main's menu
  structure (=doc/knowledge/ui/menu_structure.org=). Sign-ins is a card in
  Operations. This story no longer moves it.
- The badge is a small component, =AccountLockBadge=, that reads the catalogue.
  The shared component for every badge is the story
  [[id:A75A9B98-46BD-46CE-8ED1-BA15A1881385][Paint every web badge from the catalogue]].

* Out of scope

- The real client address of a sign-in. The login handler records the loopback
  address, so a NAT lookup and a country flag need a backend change first.
  This stays in the backlog capture "Retrieve NAT'ed IP address from local IP".
- The shared badge component for the whole codebase.
- Recording the size of NATS messages per server.
