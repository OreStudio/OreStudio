This page gives the data of compass-ng's =conventions_coverage= codec, which
ORE Studio runs over its conventions dataset. The =* Definition= names the
codec; each table below is data the codec reads, and the prose says what it is
for. The tables were =INDEX_FIELDS= and =BDC= in
=projects/ores.seeder/datasets/conventions/propose.py=, which compass-ng used to
parse.

* Rule

The conventions dataset (=projects/ores.seeder/datasets/conventions/conventions.tsv=)
holds every convention ORE's examples hold, and states each one's terms as ORE
does, or =propose_decisions.tsv= says why not. Each row names its source, each
(kind, id) is one row, and each index a convention names is defined by an
index convention of the dataset.

* Why

The dataset is ORE Studio's curated copy of the conventions ORE ships. A
convention ORE adds or changes in its examples has to reach the dataset, or be
declined with a reason, so the dataset never silently falls behind the engine.

* Index fields

The fields of a convention whose value names an index, as the dataset's
generator reads them. compass resolves each such value against the index
conventions of the dataset, and reports one no index convention defines.

| field |
|-------|
| Index |
| BMAIndex |
| FlatIndex |
| SpreadIndex |
| IndexName |
| PayIndex |
| ReceiveIndex |
| LongIndex |
| ShortIndex |

* Business day conventions

The spellings ORE's examples use for a business day convention, which the
engine states in full: compass rewrites the engine's name to the example's
code before it compares an index's terms with the dataset's.

| convention | code |
|------------+------|
| Following | F |
| ModifiedFollowing | MF |
| HalfMonthModifiedFollowing | HMMF |
