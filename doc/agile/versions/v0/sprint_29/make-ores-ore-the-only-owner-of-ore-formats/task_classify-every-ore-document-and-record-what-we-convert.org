* Acceptance

- Every family the generator emits has a document_kind, and the kind is answered from the root element.
- The coverage table names, for each family, the read direction, the write direction and the surface that reaches it, or says that none does.
- A test fails when external/ore/xsd gains a schema the codec does not classify.

* Plan

The thirteen families the generator emits become the thirteen values of
=document_kind=, and one table says for each of them what the tree does with it:
the root element that names it, whether the codec reads it, whether it writes
it, and the surface that reaches it, or nothing when none does. The detector
answers from the table, so a family is described in one row and nowhere else.

| Family | Read | Write | Surface |
|--------+------+-------+---------|
| portfolio | yes | yes | portfolio import and export |
| currency config, calendar adjustments, credit simulation | yes | yes | the round trip |
| conventions, curve configuration, today's market, pricing engines | yes | yes | run configuration import and export |
| run document | yes | yes | the run document projection |
| counterparty information, IBOR fallback config, netting set definitions, stress testing | no | no | none |

The round trip now asks the table: a family it does not convert reports itself as
unsupported rather than throwing, because a family the codec can name is no
longer an unknown document.

Four cases state the table: every generated family has a row whose root element
is the one its own source writes, every kind has exactly one row, a family
nothing converts says so, and every schema in =external/ore/xsd= is recorded as
the schema of a family or as one holding no document of ours.

* Result

Every family the generator emits is classified, and the tree says in one table
what it does with each: which root element names it, whether the codec reads it,
whether it writes it, and which surface reaches it.

Six kinds became thirteen. The seven that were unnamed — curve configuration,
today's market, counterparty information, IBOR fallback config, netting set
definitions, stress testing and the run document — are named from their root
elements, which the generated sources state.

Four of them have no conversion at all, and the table says so rather than
leaving them absent. The round trip now asks the table before converting: a
family it does not convert is reported as unsupported, where it used to be
indistinguishable from a file the codec had never heard of.

The schema test is the gate: every file in =external/ore/xsd= is recorded as the
schema a family comes from, or as one that holds no document of ours. A new
schema fails the case until someone says which it is.
