* Summary

One template projecting the catalogue's /mapping/ onto C++: the function
that reads a resolved oresmd identifier and answers which refdata class it
belongs to. The classifier calls it for an =index_name= rule, so a fixing
takes its class from the index name it is written under rather than from one
literal all fixings share.

The template writes into =ores.marketdata.api= because its subject is the
oresmd identifier type, which lives there; the catalogue model owns the
mapping wherever its outputs land.

* The ores.cpp.asset_class facet

Driven by the /asset-class catalogue/ model's =namespace= list — each entry
an oresmd authority and the refdata class it maps onto — rather than by an
entity.
