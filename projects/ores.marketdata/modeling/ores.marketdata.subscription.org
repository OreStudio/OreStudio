A subscription is the entitlement of one party to the feeds of one provider. It carries the
three rights the vendor licences name: =display=, =non_display= and =derived=. A demand checks
that the subscription holds the right the use needs. The source that serves the party is not
here. A route names it.

A subscription holds at least one right. A party administrator reads and changes only the
subscriptions of the party, and the history of every change is kept.

*** read_latest_all_tenants
:PROPERTIES:
:ID: 8E4B1D26-3A7C-4F59-B0D2-6C9A5E1F7B43
:END:

Reads the latest subscriptions across all tenants. The service computes the demand of an
adapter from the parties of every tenant, so it cannot filter on one. Queries only on
=valid_to == max=.

#+begin_src cpp :name implementation :implements F2EB1914-5E94-42CA-9C77-46BDB364BF9E
std::vector<domain::subscription>
subscription_repository::read_latest_all_tenants(context ctx) {
    static constexpr auto max = db_timestamp::max();
    const auto query = query_builder::read<std::vector<subscription_entity>> |
                       query_builder::where("valid_to"_c == max) |
                       query_builder::order_by("id"_c);

    return query_builder::execute_read_query<subscription_entity, domain::subscription>(
        ctx,
        query,
        [](const auto& entities) { return subscription_mapper::map(entities); },
        lg(),
        "Reading latest subscriptions across all tenants");
}
