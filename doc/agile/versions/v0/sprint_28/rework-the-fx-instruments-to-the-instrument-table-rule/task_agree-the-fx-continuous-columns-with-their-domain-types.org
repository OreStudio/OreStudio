Make every FX continuous quantity agree with its column. A variance strike is
volatility, which is continuous, so the domain type =double= is right and the
=numeric(38, 12)= column is wrong. A value that is exact at rest and lossy in
the domain is the shape the exact-numbers rule exists to end.

* Result

=fx_variance_swap_instrument.strike= is =double precision= at rest, matching the
=double= the domain and the entity already carried. A variance strike is a
volatility, so rounding it to twelve decimal places stated a precision the
quantity does not have.

The sweep found one other FX continuous column and no other disagreement. It
walked every column of the seven FX models whose SQL type or C++ type is
numeric, which is the population that can disagree:

#+begin_src python
import re, pathlib
for path in sorted(pathlib.Path("projects/ores.trading/modeling").glob("ores.trading.fx_*.org")):
    text = path.read_text()
    for m in re.finditer(r"^\*\* (\w+)\n:PROPERTIES:\n(.*?):END:", text, re.S | re.M):
        name, block = m.group(1), m.group(2)
        t = re.search(r"^:type:\s*(\S+)", block, re.M)
        c = re.search(r"^:cpp_type:\s*(.+)$", block, re.M)
        if t and c and ("double" in c.group(1) or "decimal" in c.group(1)):
            print(path.stem, name, t.group(1), c.group(1).strip())
#+end_src

The sweep found twenty-two numeric columns. Twenty-one are money: an amount, a
notional, a level or a price, each =numeric(38, 12)= in the column and exact
decimal in the domain, so each already agreed. The twenty-second was the
variance strike. =range_bound.leverage= is the family's other continuous
quantity, and it agreed when it landed: =double precision= with a =double=.

Nothing that is money moved to a float. The SQL regenerated from the model, the
generated C++ did not change because the entity and the mapper already read a
=double=, and =check_model_sql_types.py= passes.

* Decisions

- *A variance strike is continuous, not money.* It is a volatility, the same
  kind of quantity as a basket weight, so the exact-numbers rule puts it in the
  binary double direction. The money direction is for amounts, notionals and
  price levels, which is what the other twenty-one columns hold.
