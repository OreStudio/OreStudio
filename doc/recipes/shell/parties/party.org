#+title: How do I run the parties commands from the shell?
#+description: Every command the parties submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:parties:

This file documents the parties resource at the shell, one section per command. Every command is a subcommand of =parties=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: AEFEC2B1-1E43-58F2-806C-184579B715D3
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
parties list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.parties.list=.

#+name: parties-list
#+begin_src ores-shell :tangle parties-list.ores :exports none
parties list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 7F9D5687-AB51-59F3-AFE6-E5D6FC779F3D
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
parties get <id>
#+end_example

It is addressed at =refdata.v1.parties.get=.

#+name: parties-get
#+begin_src ores-shell :tangle parties-get.ores :exports none
parties get 00000000-0000-0000-0000-000000000000
#+end_src

** =add=
:PROPERTIES:
:ID: 72EA7C06-1B47-5CE9-978B-441AC67DBF84
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example

#+end_example

It is addressed at =refdata.v1.parties.put=.

** =set=
:PROPERTIES:
:ID: B863248C-0AB6-5E98-B924-629699C2D95E
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
parties set <id> <short_code> <full_name> <codename> <transliterated_name> <party_category> <party_type> <parent_party_id> <business_center_code> <status> <image_id> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.parties.put=.
