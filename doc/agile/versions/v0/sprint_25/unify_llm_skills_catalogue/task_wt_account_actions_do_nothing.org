* Goal

Three account operations in the Wt web UI ask the user to confirm and
then do not perform the operation.

=confirm_delete_account=, =confirm_lock_account= and
=confirm_unlock_account= in =ores.wt.service/src/app/ore_application.cpp=
each build a message box, and on =StandardButton::Yes= call
=load_accounts()= and nothing else. The account id each is given is
never used. A user who confirms a delete sees the list refresh and the
account still there.

Found by =-Wunused-parameter= once the warnings were enabled. The
parameter was hidden until then because each lambda captured =id=
without reading it, so the capture consumed the reference and the
compiler saw a use. Removing the dead capture exposed the parameter,
and the parameter exposed the missing implementation.

That chain is the argument for the warnings: nothing else in the build,
the tests or the review had reported three operations that silently do
nothing.

* Acceptance

- Each of the three confirmations performs its operation against the account it was given.
- A failure is reported to the user rather than swallowed, and the list refresh happens after the operation rather than instead of it.
- Each has a test that fails if the handler reloads without acting.
- The =[[maybe_unused]]= markers left on the three id parameters are removed, because the parameters are used.

* Notes

The three id parameters currently carry =[[maybe_unused]]= so the build
stays clean under =-Werror=. That marker is a placeholder for this task
and should not survive it: a parameter the implementation needs is not
maybe-unused, it is unimplemented.

Whether the same shape exists on other entities in the Wt UI is worth
checking while here. These three were found together because they sit
together; nothing suggests they are the only ones.
