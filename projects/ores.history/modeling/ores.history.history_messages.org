The generic entity-history protocol, per [[id:85892C17-BB81-4724-9B84-20E21D41C499][History Diff Architecture]].

One request, shared by every entity, carrying the entity's type and its key as
strings. No typed domain payload crosses the wire for history: the fields arrive
rendered, and the diff arrives computed, because the comparison is entity-agnostic
once both sides are strings and belongs on the server where it is done once.

** get_entity_history_request
:PROPERTIES:
:subject: {component}.v1.history.get
:response: get_entity_history_response
:END:

#+begin_src cpp :name comment
/**
 * @brief The one generic history request every entity shares.
 *
 * entity_type is the dispatch key (e.g. "ores.refdata.currency"); entity_id
 * is the entity's own primary key rendered as a string, since key shapes vary
 * across entities.
 *
 * The subject names the component that OWNS the entity, which this model
 * cannot know: the same request reaches iam.v1.history.get for an IAM entity
 * and refdata.v1.history.get for a refdata one. So the segment is left open
 * and history_subject_for() derives it -- one rule, read by the service that
 * subscribes and by every client that sends.
 */
#+end_src
