* Result

=trade_link= joins two trades under a type from =trade_link_type=, with
both ends enforced, the type validated against the seeded catalogue, and
the activity that made it recorded. The link holds no amount, no state and
no cash flow, and the tree still carries no successor trade id.

Three defects surfaced only when the database was rebuilt, and none of
them was visible from the C++. The two link tables had generated create
files that no aggregator listed, so the tables had never existed. The link
copied its party from the from trade and pinned it to nothing, so the copy
could drift from its source. And the link had no party isolation policy,
so a session restricted to a set of parties read every link in its tenant.
All three are fixed here.

The tables are wired into the schema, the party is pinned to the from
trade's key, the party isolation policy matches the sibling trade tables,
and a link may not join a trade to itself.
