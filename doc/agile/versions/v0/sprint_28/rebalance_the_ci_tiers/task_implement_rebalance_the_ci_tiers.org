* Notes

** Why linux-clang is the continuous pair

The two clang jobs are the only ones that finished well inside the six
hour limit: 2h46m and 2h54m. The gcc jobs ran 4h08m to 4h17m, and the
macOS jobs 4h40m to 5h40m. Neither pair can run every three hours
without queueing. Both already have a nightly home: the Nightly Build
covers gcc, and this change gives macOS its own nightly.

** The cadence

Continuous Linux runs every three hours. The slower clang job ran in
2h54m, so three hours is the tightest interval that does not queue a
run behind its predecessor. The relevance-guard skips a run when no
non-doc code changed, so three hours is a ceiling rather than a promise.

** Why this also fixes the cache

Two sccache variants hold roughly 5 GB, which fits inside GitHub's 10 GB
repository cap alongside the vcpkg and get-cmake entries. A run can now
finish and reach its =Save sccache= step, which the four-variant matrix
could not. The cold-build loop closes.

** The macOS runner

The macOS workflow moves to =macos-15= in the same change. GitHub
retires =macos-14= on 2026-11-02 and browns it out on October 16, 19, 23,
26, 29 and 30.

** Not done here

- Coverage and packaging still run on the continuous clang jobs.
- Windows has no measured run time. Its last run reported success with
  the build matrix skipped, so the 5-8h figure in its comment is
  inherited, not measured.
