* Acceptance

- each of the two types names an instrument table carrying its basket or its option terms in rows
- the projection reads and writes each element, value for value
- each type has a builder, and the catalogue routes both
- the generator books one trade of each type through its builder, and the recorded trades hold it
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: no list, basket or schedule is held as text

* Plan

- *CreditDefaultSwapOption*, natively in the credit family. The trade's CDS is
  a credit default swap fact row held as the carrier's =wrapped_swap=, as an
  index option holds its =wrapped_index_swap=; its premium leg is a leg row.
  The option's own terms (=KnockOut=, =Term=, =StrikeType=) share the index
  CDS option fact row, whose columns are those terms; the strike is a strike
  row and the option block the option rows. The batch mapper looks for the
  option fact before a plain swap.
- *CBO*, on the class-read path. A trade states its =CBOInvestment= (tranche,
  notional, structure id) and names a structure the reference data holds, as
  ORE's own example does. The path reads a block of leaves only as parameters
  named for the block and the leaf.
- Builders: =credit_default_swap_option_builder= and =cbo_builder=.

* Result

CreditDefaultSwapOption is held natively: the header row, the wrapped CDS
fact, the premium leg, the option terms, the strike and the option block. CBO
is held in the scripted instrument table as its investment. The round-trip test
reads ORE's CDS option example, with a strike, strike type, knock out and term
added, and ORE's CBO example, and writes them back. Each type has a builder,
the catalogue routes both, and the generator books one trade of each.

The ORE engine raises no error of the trade kind. A CDS option on an entity
whose credit curve the test market lacks raises market data, as a callable bond
on it does. A CBO's structure lives in reference data, which the engine test
does not stage; ORE then lists every structure element as missing, and the
test classes that one message as market data. A message missing only some
elements stays the trade's.

The builder does not state a CBO structure inline (bond basket, tranches,
fees); a trade read from ORE with one keeps only its investment.
