* Plan

Five independent defects sit on main. Fix each one at its source.

1. Warning C4244 in =environment_mapper_factory.cpp=. The lambda
   declares =-> char= and returns =std::tolower(c)=, which is an
   =int=. The MSVC build promotes the warning to an error through
   =/WX=.
2. Missing link of =libfort::fort= in =ores.ore/api/src/CMakeLists.txt=.
   =series_key_shape_table.cpp= calls the libfort C API. Linux accepts
   undefined symbols in a shared library. The Windows linkers do not.
3. Unknown component prefix =ores_ore_= in the SQL validator. Register
   the prefix in =COMPONENT_PREFIXES=.
4. Missing select grant on the ore tables for the marketdata service.
   Add the prefix to the service registry and regenerate the grants.
5. No binding from a checkout label to a declared ores.web environment
   id. Emit =ORES_WEB_ENV= from =compass env configure=.

* Notes

Root cause and fix of each defect.

- =environment_mapper_factory.cpp:36=, both MSVC configs:
  =warning C4244: 'return': conversion from 'int' to 'char', possible
  loss of data=, promoted to =error C2220= by =/WX=. The build stops at
  edge 24 of 4453. Fixed with =static_cast<char>= and an explicit
  =<cctype>= include.
- =ores.ore.api.dll=, both Clang configs: the link fails on undefined
  =ft_create_table=, =FT_BASIC_STYLE=, =ft_set_border_style=,
  =ft_set_cell_prop=, =ft_ln=, =ft_destroy_table=, =ft_nwrite= and
  =ft_to_string=. Commit e069e792f1 turned ores.ore.api from an
  interface library into a real library, and left out its libfort link.
  Fixed by adding =libfort::fort= to the private link list.
- SQL validation, all four Linux jobs and the Nightly Build:
  =NAMING_010= and =NAMING_002= on =ores_ore_series_key_shapes_tbl=,
  because =COMPONENT_PREFIXES= has no =ores_ore_= entry. Fixed by
  registering the prefix.
- =ores.marketdata.service= dies at startup with =ERROR: permission
  denied for table ores_ore_series_key_shapes_tbl=. The service reads
  that table to classify series (=feed_ingest_loop.cpp=,
  =import_service.cpp=), but the per-service grants give it only
  =ores_marketdata_= DML and =ores_refdata_= select. Fixed by adding
  =ores_ore_= to the marketdata service's select prefixes in
  =projects/modeling/service_registry.org= and regenerating
  =iam_service_db_grants_create.sql= from the
  =ores.sql.service.db_grants= archetype.
- =ores.web.service= fails with =ConfigurationError: No environment
  'swift_curie'=. The BFF resolves its site configuration from
  =ORES_WEB_ENV=, else =ORES_ENV_NAME= -- the checkout label, which is
  not necessarily a declared id. This checkout reports =swift_curie=
  while =config/environments.json= declares =swift_curie_local= for it,
  and =compass env configure= wrote no binding. Fixed by emitting
  =ORES_WEB_ENV=, selecting the declared entry whose NATS port and
  subject prefix match the ones compass assigned.

Verification runs on the checkout's clang debug preset. The MSVC
warning itself needs the Windows jobs, which are only observable on the
next scheduled run.
