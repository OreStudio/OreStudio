This page documents a [[id:31C868B9-306E-4282-BA8C-07E647021B34][task]] in the [[id:FA10EE76-EC92-444C-B4F2-2BFFAD9C4AE4][Replace GLOB_RECURSE with explicit source lists across the build]] story. It captures the goal, current status, acceptance, and any notes or results.

* Goal

Eliminate every =file(GLOB_RECURSE ...)= source-discovery call from the
build (165 CMakeLists.txt files across ~96 components at task start),
replacing it with an explicit, checked-in list of files -- the
idiomatic CMake approach per Kitware's own guidance, rather than
mitigating the stale-configure problem with =CONFIGURE_DEPENDS= (already
landed separately, and explicitly out of scope for this story to redo).

Since these CMakeLists.txt files are themselves codegen-templated
boilerplate rather than hand-maintained one-offs, hand-editing 165
files is both impractical and error-prone. Instead: write a small,
idempotent generator script that computes the explicit list from the
filesystem and rewrites the =file(GLOB_RECURSE ...)= block in place,
run it across every component (one commit per component so each is
independently reviewable and revertable), and update the codegen
archetype templates so newly scaffolded components start with
explicit lists rather than regressing back to GLOB.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

1. Write =regenerate_cmake_sources.py=: regex-match each
   =file(GLOB_RECURSE ...)= call (with its optional seeding
   =set(<var> "")=), resolve its base directory (either
   =${CMAKE_CURRENT_SOURCE_DIR}= itself, or a component-root variable
   of the form =set(VAR ${CMAKE_CURRENT_SOURCE_DIR}/..)= found earlier
   in the same file -- the only two shapes this codebase uses), walk
   the filesystem for matching files, and replace the call with an
   explicit, sorted =set(<var> ...)= block. =--check= mode reports drift
   without writing, for CI.
2. Validate on two representative components first (a plain library,
   =ores.diff=, and a Qt AUTOMOC component with both =.cpp= and =.hpp=
   globs, =ores.qt/synthetic=) -- build both targets to confirm the
   explicit lists behave identically to the GLOB they replace.
3. Run the script across every remaining component, one component
   (=src= + =tests= CMakeLists.txt together) per commit.
4. Update the codegen archetype =.org= templates
   (=ores.cmake.component.*.org=) to stop emitting GLOB.
5. Add a recipe documenting the new convention.
6. Full =compass build= + =ctest= at the end; fix any straggler.

** Design pivot: codegen-driven generated file, not in-place regex

Steps 1-3 above were implemented and landed a first batch (96
components, one commit each) using a regex-based script that
rewrote the =file(GLOB_RECURSE ...)= block in place inside each
=CMakeLists.txt=. Splicing generated content into an otherwise
hand-maintained file via regex is fragile long-term (parsing an
evolving hand-edited file to find the "generated" region), so the
approach was replaced before closing the task:

- A new =ores.cmake.component.files_{src,tests}= archetype pair,
  registered in the =ores.cmake.component= facet like every other
  CMake archetype, renders =src/component_files.cmake= /
  =tests/component_files.cmake= -- a small, wholly-generated file
  =CMakeLists.txt= =include()=s, rather than an inline block.
- The file list (and, for Qt AUTOMOC components, the header list) is
  injected into the render context as a directory scan at generation
  time (=core.py='s =_COMPONENT_FILES_TEMPLATES= branch) -- the one
  piece of context a source-file archetype can't get from the model
  itself.
- =regenerate_cmake_component_files.py= renders only these two
  archetypes via the same =generate_from_model()= the rest of codegen
  uses -- deliberately not =compass codegen regenerate=, which would
  regenerate every archetype in the facet (=CMakeLists.txt= included)
  and clobber hand-added =target_link_libraries=.
- =wire_component_files_include.py= was the one-off helper that
  replaced the first batch's inline blocks with the =include()= line;
  not meant to be re-run.
- Per "codegen the file list for every component, no exceptions" (a
  mid-task instruction), the 10 remaining components that had no
  =modeling/component_overview.org= (=ores.eventing/{api,core}=,
  =ores.marketdata/client=, =ores.qt/{dq,marketdata,synthetic}=,
  =ores.refdata/client=, =ores.workspace/{api,core,service}=) got one
  scaffolded via =compass add component=, bringing every C++ component
  onto the same codegen-driven mechanism -- zero components left on
  the earlier regex-script's inline-block approach.
- That scaffold surfaced (and this task fixed) a pre-existing
  =#+type: component= bug in both the scaffold template
  (=ores.doc.knowledge.component.org=) and =ores.qt.headless='s own
  model -- should be =ores.codegen.component=; both silently failed
  =load_model()=.

occurrences across 96 components at task start) and replaced it with
a codegen-generated =component_files.cmake= per =src=/=tests= dir,
=include()=d from =CMakeLists.txt=. See =* Plan= §"Design pivot" above
for why the initial in-place-regex approach was replaced with a
