* Goal

The download builds the whole object in one response string, so a large object
costs its own size in memory to serve. Serving it from the file needs the server
to write a response in chunks, which increment B1 owns: this task takes the
download over once that exists.

* Acceptance

- The download writes the file through a fixed buffer, so its memory does not grow
  with the object.
- A download larger than one buffer arrives whole and unchanged.
- A client that stops reading is closed on the same deadline the upload uses.
