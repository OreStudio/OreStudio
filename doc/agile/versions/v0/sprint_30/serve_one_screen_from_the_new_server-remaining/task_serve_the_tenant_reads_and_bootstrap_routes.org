* Plan

The routes fall into two groups, each a reviewable unit:

- The bootstrap and setup reads: =/api/bootstrap=, =/api/bootstrap/administrator=,
  =/api/bootstrap/complete=, =/api/tenant-setup= and =/api/registration-policy=.
  The first two run with no session and the BFF rate limits the policy read,
  which the C++ server cannot do yet.
- The reads inside a tenant: =/api/tenants/{code}/parties=, =people=,
  =accounts/{username}/sign-ins= and =images/{id}=. Each enters the tenant for
  the read alone. The parties read reuses =party_page_routes::read_page= with a
  request that carries the tenant's token.

The bootstrap read states whether the browser holds a session, so it may
wait for [[id:E57938AF-06F7-4330-B992-F7BE5296D8A3][Serve the browser's session routes]].

On 2026-11-11 the task served the reads inside a tenant, and the bootstrap
and setup routes moved to [[id:1BFF30C8-F1D4-4917-99B1-F6F6F3069D02][Serve the bootstrap and setup routes]].

- =tenant_inside_routes= is a new unit in the IAM part. =read_inside= checks
  the deployment read, finds the tenant by its code, and reads as the caller
  when the tenant is the caller's own. Otherwise it enters the tenant, reads
  with a copy of the request that carries the tenant's token, and leaves,
  logging an exit that cannot be recorded. Only a refused entry is a refusal,
  forbidden; a read that fails inside fails as itself.
- The reads reuse what the caller's own screens use: the refdata part's party
  page (the IAM part now links =ores.http.refdata=), the account page writer,
  the sign-in history reader (extracted as =sign_in_routes::sign_ins_json=), and
  =image_answer=.
- The BFF kept a cache of a tenant's images, filled when a page named them.
  The C++ route reads each image inside the tenant when the browser asks, which
  the browser caches for five minutes.
- A test helper, =route_answer=, runs one registered route on a client that is
  not connected. The provisioning and inside-tenant tests share it.

* Result

The C++ server answers a tenant's parties, people, one account's sign-ins and
its images, read inside the tenant, at the BFF's addresses and in its shapes,
and the inventory pairs each. Tests prove the tenant token replaces only the
caller's, the page refusals come before entering, and each accepted read
forwards. The bootstrap and setup routes moved to their own task.
