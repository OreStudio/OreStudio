* Result

The BFF serves three routes behind the session check: =GET /api/oresmd/schema=, =POST /api/oresmd/parse= and =POST /api/oresmd/compose=. Each forwards the structure to the server's subject and returns the answer. The BFF holds no grammar: it checks only the size of a request, a URI of at most 2048 characters and at most 64 fields, which are the server's own limits, and it leaves the kind, the instrument and the quote as text for the codec to judge. The server checks the permission, and a refusal of the call, such as a missing permission, is a 403 as for any other read.

A URI the codec refuses is an answer and not a fault. Parse and compose return it with =success= false and the codec's words, with status 200, so the editor can show them beside the field. The schema is the codec's table and changes with a release, so the route lets a browser keep it for five minutes.

The contracts package has the shapes, in =oresmd.ts=, and the BFF checks them against the generated twin with =satisfies=, so a change to the model that the contracts do not follow fails the typecheck. I broke one field on purpose and the typecheck failed, then I restored it. Nine route tests pass. They cover the session, the three forwards, a refusal as an answer, the bodies that are refused without asking the server, a missing permission and an unsuccessful schema read.

Not done: I did not call a running server, because the C++ services are not rebuilt and started here. The routes meet the real operations when the services run with the merged tasks 1 and 2.
