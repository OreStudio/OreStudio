* Decisions

- Remove the unused parameter name rather than log the exception. The handler
  already logs and throws a message specific to the circular dependency, and
  =not_a_dag::what()= says only "The graph must be a DAG."
- No checker is added. A scan of =projects/= for catch parameters that its own
  handler never mentions finds this one occurrence, and the compiler already
  fails the build on it wherever /W4 /WX is on.
- No Linux job can catch this class: GCC has no warning for an unused exception
  parameter, and clang emits =unused-exception-parameter= only when asked. The
  Linux builds run =-Wall -Wextra -Werror=, so MSVC's C4101 under /W4 /WX is the
  only gate that sees it.

* Result

=publish_service.cpp:196= no longer names the =boost::not_a_dag= exception
object, so the MSVC jobs clear the translation unit that stopped the Windows
build at 512 of 6393. Landed with PR #2710. The full Windows build was not run
here, so any later /W4 /WX failure in the remaining translation units is still
unknown.
