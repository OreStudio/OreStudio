* Goal

Finish the list contract the protocol specification already states, in the
code generator, so every entity gets it from its model:

1. *Order.* Columns declare =:sortable: true= and the entity a
   =:default_order:=. The repository builds the order from that allow-list,
   with the key as the last tie-break, and the service accepts a declared field
   and refuses any other with =order_not_supported=.
2. *Filter.* The repository applies each set member of the filter record the
   generator already derives, as a condition on its column.
3. *Search.* A model may declare =:searchable:= columns, which add one typed
   =search= member to the filter record: a case-insensitive substring match over
   those columns. This amends the specification, which forbids a query
   language; a typed member is not one.
4. *One of.* Key and relation columns may take a list-typed member, so a screen
   can read the rows for the keys on its current page in one call.
   The parties screen needs it too: a party's parent is named only when it is
   on the same page, because party =get= and =get_many= key by short code and
   nothing reads a party by its id.

Then move the hand-written reads onto the contract: =iam.v1.tenants.search=
becomes =iam.v1.tenants.list= with a filter, its SQL function
=ores_iam_tenants_search_fn= is removed, and the roster's provisioning run read
uses a one-of member in place of a single read capped at 1000.

* Decisions

1. *The model owns the order allow-list.* A column declares =:sortable: true=
   and the entity =:default_order:=. An undeclared field is refused with
   =order_not_supported=, never ignored. The key, ascending, breaks every tie.
2. *Three filter members, all typed.* Equals for the filterable columns,
   =<column>_one_of= for the primary key and relation columns, and one
   =search= member over =:searchable:= columns. Set members must all hold.
3. *One-of has the key-set bound.* At most 1000 values, like =get_many=; an
   empty list matches no row; the page still applies.
4. *Search is literal.* A case-insensitive substring match; =%= and =_= are
   not wildcards; an empty string sets no condition.
5. *A column the model reads by is filterable, and so is one that says so.*
   =:list_filter_column:= and the scoped-read relation columns are filterable
   with no flag. A column that is neither declares =:filterable: true= and
   gets the same equals and one-of members. The roster's type and status are
   such columns: the first version of this decision had no flag, and the
   roster could not be moved without one.
6. *Query parameter names are reserved.* =offset=, =limit=, =order=,
   =descending=, =search=, =scope=, =as_of= and =keys=; the generator refuses a
   filter member with one of them.

** Why

The specification makes every list paged, with a stated order and a filter
record. The generated service refuses any stated order and any filter, and the
repository can only sort by id. That gap pushed the tenant roster into a
hand-written search read and a capped run read. Every list must page, with no
fixed cap.
