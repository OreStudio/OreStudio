* Result

* Result

The step now names PowerShell where Windows keeps it rather than trusting the
bash PATH, which does not reach it, and falls back to Python's zipfile module
when that interpreter is absent. Both runners paths fail loudly, naming the
archive, instead of dying with a bare exit 127.

The 27 November run proves the previous attempt reached the extraction and
failed there: the checksum passed and the step exited 127, which is a command
that is not on the PATH.

Verified locally: the step body passes =bash -n=, the workflow parses as YAML,
and a stub run of the resolution yields the interpreter's path under
=/c/Windows/System32/WindowsPowerShell/v1.0/=.

Not verified locally: the step on a Windows runner. The next nightly is the
check.
