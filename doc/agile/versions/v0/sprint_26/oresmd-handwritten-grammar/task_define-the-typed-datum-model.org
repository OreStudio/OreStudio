* Goal

One hand-written value type, =market_datum=, describes every ORE market datum:
the instrument type, the quote type and a short list of typed fields. A
=constexpr= schema table states, per instrument type, which fields exist, in
which order, and which are coordinates.

* Acceptance

- =instrument_type= enumerates all 45 ORE instrument types and =quote_type= all 16 ORE quote types.
- =field= enumerates every field any ORE key carries, and a traits map gives each field one value type.
- The value variant has no more than about six alternatives: string, ORE period, ORE date, decimal, strike and enum code. A strike is a variant of absolute, ATM with its ATM type, moneyness and delta.
- The schema table has one row per instrument type, listing its fields in key order, each field's role, and the fields that may hold =none=.
- The only constructor refuses a datum that does not match its row: a missing field, an extra field, or a value of the wrong type.
- No field is absent where its absence would mean a default; an optional ORE token holds an explicit =none=.
- Free-text names keep the case they arrived in.
- =series_of(datum)= removes exactly the coordinate fields.
- No =std::variant= over instrument types exists, and the header that holds the enums and the table includes no codec.
- Unit tests cover the constructor's refusals, equality, =series_of=, and every value type's text form.

* Plan

1. Derive each schema row from the reference catalogue, not from the current
   models.
2. Write the value types, then the =field= enum and its traits, then the
   schema table and the constructor, then =series_of=.
