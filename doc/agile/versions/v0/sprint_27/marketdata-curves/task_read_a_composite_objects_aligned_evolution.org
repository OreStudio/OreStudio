* Acceptance

- The read returns a matrix of instants by nodes, not arrays of objects.
- Every node is marked added, dropped or persistent against the declared shape.
- The fixed five-bucket window is replaced.
- A node the shape declares and no instant carries is distinguishable from a
  node the object does not have.

* Plan

The aligned evolution read is the slice read's sibling. It returns the whole
object rather than one component, and it states the change each node shows
against the shape. The fixed five-bucket window goes, and the subject that
carried it goes with it.

1. A new operation in =ores.marketdata.operations=,
   =get_series_evolution_request= and =get_series_evolution_response=, with the
   two messages it carries: one node with its coordinate labels and its status,
   and one instant with a value per node.
2. The request states the object as the typed identity the resolver takes, and
   either a range or a set of instants. A set the caller states replaces the
   range.
3. The response is the matrix: the axis names once, the declared grid's nodes
   once with their labels and their status, and one row per instant whose values
   are index for index with the nodes. It is parallel arrays, not arrays of
   objects.
4. The node status is the change the node shows over the range: =persistent=
   when every instant carries it, =added= when the last carries it and the first
   does not, =dropped= when the first carries it and the last does not,
   =intermittent= when an instant between them does, and =never_quoted= when the
   shape declares it and no instant carries it.
5. =read_as_of_instants= grows a stated set of instants. A range draws its
   boundaries from the data; a stated set uses the caller's.
6. The fixed five-bucket window is removed: its request, its response, the
   handler method and the registration. The repository's own =read_as_of_buckets=
   stays, because a backlog story names it as the reference implementation of the
   as-of-bucket pattern that story exists to generalize.
7. The shape reader both reads share moves to its own service, so the slice read
   and the evolution read cannot disagree about what an axis is.

** The grid is the shape's product, so a hole is a cell and not a missing node

The nodes are every combination of the declared values of the object's axes, in
the order the shape stores the axes and with the last axis varying fastest. That
is what makes a declared node distinguishable from a node the object does not
have: the first is a cell of the matrix, marked =never_quoted= when no instant
carries it, and the second is not in the matrix at all.

** The status is a summary of the range, not of one step

A node that is dropped and then added again is reported =added=, because the
range's last instant carries it and its first does not. A caller that wants the
change step by step reads two consecutive rows, which the matrix already carries.
One word per node is what makes the answer readable at a glance, which is what
the journey asks for.
