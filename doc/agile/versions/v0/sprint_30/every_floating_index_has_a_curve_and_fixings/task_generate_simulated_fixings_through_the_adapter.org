* Goal

Implement A simulated fixing source is a publisher the simulator serves. Install a publisher and a simulated source for each administrator of a simulated source, with vendor instruments and mappings for its fixing items, and route the system party to it. Add a fixing generator kind that backfills a history on start and fixes its item at each fixing time from the run's market board, and publishes durable fixing ticks through the adapter. Remove the synthetic service's fixing writer and the curve feed's fixing plan.

* Acceptance

- The simulator writes nothing to the store; every simulated fixing arrives through the adapter.
- A fixing of EUR/USD at the New York cut equals the run's EUR/USD spot at that instant.
- On a fresh acme_demo provision, every FX and IR fixing address a trade names has a series with values, under the system party.

* Plan

A fixing reaches the store as an ordinary adapter tick: the market data service
stores it as durable because its vendor id maps to a =type=fixing= address, and
it stores it for each party routed to the source that sent it. So a simulated
fixing needs a vendor id, a mapping, a route of the system party, and a
generator that sends the tick.

1. *Name a fixing in a notation.* Add =fixing_quote= to the vendor quote
   descriptions: the fixing's oresmd address. A simulated fixing notation writes
   its id as the ORE index name the ORE index codec writes, such as =USD-SOFR=
   or =FX-WMR1000NYC-EUR-USD=, with the field =value=, and reads it back. One
   provider per administrator of a simulated source uses it. Check: notation
   round trip tests.
2. *Install the simulated publishers.* For each administrator of a fixing source
   whose fixings the run simulates, a provider, a publisher and a
   =synthetic-local= source; a vendor instrument and a mapping for each fixing
   item, written by =tools/vendor_catalogue=; a route of each tenant's system
   party to the source. Check: a recreated database holds the rows, and the
   party demand of the system party names the fixing items.
3. *Generate the fixings.* A fixing generator kind that the simulator offers one
   generator per fixing id. On start it sends the history the direct writer
   wrote, from the same =derive_fixing_history=; then at each fixing time it
   fixes the item from the run's market board: an IR index from the curve's
   rate, an FX fixing from the pair's spot at the cut instant. Check: unit tests
   of the history and of the FX value at the cut.
4. *Remove the direct writer.* =fixing_history_writer= and the curve feed's
   fixing plan go. Check: the synthetic service writes nothing to the store.
5. *Prove it end to end.* A fresh acme_demo provision; the fixing gap query for
   IR and FX under the system party.
