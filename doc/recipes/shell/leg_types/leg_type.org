#+title: How do I run the leg_types commands from the shell?
#+description: Every command the leg_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:leg_types:

This file documents the leg_types resource at the shell, one section per command. Every command is a subcommand of =leg_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 4083103C-3A60-5A3B-91A8-E389AA42022C
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
leg_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.leg_types.list=.

#+name: leg_types-list
#+begin_src ores-shell :tangle leg_types-list.ores :exports none
leg_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 42E392C8-84B8-5012-BA65-D2A156E82DE6
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
leg_types get <code>
#+end_example

It is addressed at =refdata.v1.leg_types.get=.

#+name: leg_types-get
#+begin_src ores-shell :tangle leg_types-get.ores :exports none
leg_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 5B8BE900-0B2A-55CF-A581-9A2D6A77CB96
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
leg_types add <code> <description> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.leg_types.put=.

#+name: leg_types-add
#+begin_src ores-shell :tangle leg_types-add.ores :exports none
leg_types add __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: C45DC6C2-FF4E-58C8-8B56-B71011595FC8
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
leg_types set <code> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.leg_types.put=.

#+name: leg_types-set
#+begin_src ores-shell :tangle leg_types-set.ores :exports none
leg_types set __none__ __none__ system.new_record generated_script
#+end_src
