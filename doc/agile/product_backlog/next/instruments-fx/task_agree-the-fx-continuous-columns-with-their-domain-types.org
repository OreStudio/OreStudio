* Goal

Make every FX continuous quantity agree with its column. A variance strike is
volatility, which is continuous, so the domain type =double= is right and the
=numeric(38, 12)= column is wrong. A value that is exact at rest and lossy in
the domain is the shape the exact-numbers rule exists to end.

* Acceptance

- =fx_variance_swap_instrument.strike= is =double precision= in every column declaration.
- Every other FX column that holds a continuous quantity agrees with its domain type. Record the sweep, including the columns that already agree.
- Nothing that is money moves to a float in this unit.
- The models, the generated SQL and the generated C++ regenerate together, and =check_model_sql_types.py= passes.

* Plan

1. List every FX column whose name reads as continuous, and its domain type.
2. Move =strike= with the mirror mode of =scripts/convert_money_column_to_decimal.py=.
3. Regenerate the SQL and the C++, and recreate the database.
4. Run the trading suite and the ORE round-trip tests.
