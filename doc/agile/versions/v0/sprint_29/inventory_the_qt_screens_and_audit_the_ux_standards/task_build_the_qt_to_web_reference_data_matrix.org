* Goal

One table answers, for each of the 61 Qt reference data entities, which web screen covers it (a dedicated record screen, the classification screen, the convention screen or none), which fields and child records the web lacks, and which Qt behaviours the web dropped on purpose. The name match of the first pass is replaced by a reading of the Qt sources.

* Acceptance

- Every Qt reference data entity has a row that names its Qt parts and the web screen that covers it or states that none does.
- Each row lists the fields, child records and actions the web lacks, read from the Qt .ui and .cpp sources and the web field tables, not inferred from names.
- The matrix lives as a knowledge page under doc/knowledge/ui and the UX hub links it.
- A Qt behaviour the web drops on purpose is marked as such with the standard section that drops it.

* Plan

Build the lever, not the table. A script beside this task,
=evidence/qt_web_matrix.py=, reads the Qt sources and the web registries and
writes the matrix, so a reviewer reruns it instead of trusting a hand copy.

1. Qt side. An entity exists where a window, a dialog or a client model exists.
   The fields of a dialog are the entity struct members the dialog source reads
   and writes, because the widget names are not the wire names and some combos
   are built in code. The columns are what the model returns for the display
   role. The actions are the toolbar actions the window adds.
2. Web side. The record registry, the classification lists and the convention
   kinds, matched by entity type, plus the =FieldSpec[]= table beside each
   record screen. An entity the registries do not name is matched by hand in
   the script, with the surface that covers it.
3. Judgement. The provenance fields, the parent keys and the party scope are
   not gaps, and the script names the standard section for each. The rest of
   the judgement, the gaps and what was dropped on purpose, is prose on the
   knowledge page.
4. The page. =doc/knowledge/ui/qt_web_reference_data_matrix.org=, with the two
   generated tables spliced between markers, linked from the UX hub.

* Result

The knowledge page [[id:C82ED7AD-7E13-46FA-B7E9-C4E66E823478][Qt to web reference data matrix]] holds one row per Qt
entity with its parts, the web surface that covers it, the field counts and
the fields only one side has. It also holds the windows that went beyond the
standard toolbar, what the web added, the gaps judged, and what was dropped on
purpose with the standard section that drops it. The UX hub links it. The
script beside this task produces both generated tables and a reviewer reruns it.

The first pass matched Qt widget names to web field names and reported false
gaps on business units and parties. The dialog source, which reads and writes
the entity struct, replaced it as the source of Qt fields.
