* Summary

=ores.http.dq= is the adapter part that projects the data-quality domain onto
the HTTP server's REST surface. It holds the generated route units for the DQ
models that opt in, and each unit owns one route per derived verb.

The models opt in through the =:ores.cpp.http-route.enabled:= property in their
own drawer, so a model that needs no route leaves the facet off. The units speak
the canonical DQ protocol over NATS and hold no service, repository or database
context: the DQ service stays the only place that decides, and the caller's own
token travels with every forwarded request.

The part declares =#+component_kind: adapter=. Its =CMakeLists.txt= files are
hand-authored, because the link libraries belong to the HTTP surface rather than
to the domain, and codegen writes only the two =component_files.cmake= lists.

* Inputs

- HTTP requests on the =/api/v1/dq/...= paths the units register.
- The caller's bearer token, forwarded to the service on every NATS request.
- The connected NATS client the hand-written aggregator passes to
  =register_routes=.
- The DQ models under =projects/ores.dq/modeling/= whose drawers opt in.

* Outputs

- One route unit per opted-in model, at =src/routes/dq/<unit>_routes.cpp= and
  =include/ores.http/routes/dq/<unit>_routes.hpp=.
- The routes and their OpenAPI schemas, registered on the router and the
  endpoint registry.
- NATS request messages to the DQ service, one per route.

* Entry points

- =include/ores.http/routes/dq/= -- the generated unit headers.
- =src/routes/dq/= -- the generated unit implementations.
- =dq_routes= -- the aggregate the host calls to install every DQ unit.

* Dependencies

- =ores.http.api= -- the router, the route builder and the OpenAPI registry.
- =ores.http.nats= -- the gateway's one forwarding step to the services.
- =ores.nats= -- NATS transport for service calls.
- =ores.dq.api= -- the canonical protocol messages the units send.
- =ores.utility= -- the codecs and the wire support types.
- =ores.logging= -- logger factory.
