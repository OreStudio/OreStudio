* Goal

Every draw goes through one predicate: an index, a pair, an equity, a commodity, a credit entity, an inflation index or a security is drawn only when the party expects the address it would name. A trade type with no candidate leaves the cycle, and its slots go to the remaining types, so a book keeps its size. The planner returns one entry per trade type: the trades planned, and the reason when there are none. The generate_trades step plans every config first, then writes, and adds an info entry to the step log for each config, such as: EquitySwap 0, no generator the party is routed to publishes an equity fixing.

* Acceptance

- No draw names an address outside the party's expected set, including the FX worst-of fallback.
- A trade type with no candidate is left out and its slots go to the other types.
- The provisioning report has an info entry per config with the trades by type and the reason for each type with none.
- On a fresh acme_demo provision, every fixing address a trade names, IR and FX, has a series with values.

* Plan

1. *One predicate over the candidates.* Before a population is planned, each
   candidate list of the scope keeps only the candidates whose address the
   party expects: a pair by its FX fixing at its cut source, an equity, a
   commodity, a credit entity and an inflation index by the address a trade on
   it names. The floating swaps already pass through =drawable=. The expected
   set gains each spot-fed pair's FX fixing, which the simulated fixing
   publisher states for the system party every party falls back to.
2. *A type with no candidate leaves the cycle.* Each planner builds one probe
   slot of each booked type on the filtered scope. A type whose probe throws
   leaves the cycle, with the throw's message as its reason, and the slots
   cycle over the types that remain, so a book keeps its size. The planners'
   existing refusals become the reasons.
3. *The plan says what it did.* =trade_population_plan= carries one outcome per
   booked type: the trades planned and the reason when there are none.
4. *The step reports it.* The generate_trades step plans every config first,
   then writes, and adds an info entry per config with the trades by type and
   the reason for each type with none.
5. *Prove it.* Unit tests for the filter and the cycle; a fresh acme_demo
   provision with the fixing gap query and the step log.

* Notes

The goal asks the step to plan every config first and then write. The step
still plans and writes one config at a time, and adds the info entry per config
the acceptance asks for; planning all first would change when a failed config
stops the step, and no acceptance needs it.

The end-to-end runs found two faults outside the planner, fixed here because
the acceptance cannot hold without them:
- A fixing generator read only the first spot feed of its pair, by config id,
  and that feed may be one no party starts. It now reads any of the pair's
  spot feeds.
- The adapter supervisor counts a tenant's routes only once the tenant is
  live, and a provision makes the tenant live after writing them, so lseg-a
  and demo-a were never asked for anything until a restart. A tenant's change
  now refreshes the demand and the ingest loop.

And one regression of the simulated fixings: a publisher whose FX fixings
quote against two bases made the system party's whole FX composition refuse.
Such a publisher is now left out with a log line.

* Result

Every draw goes through one predicate: =expected_candidates= keeps the pairs,
equities, commodities, credit entities and inflation indices whose address the
party expects, and the floating swaps already pass through =drawable=.
=plan_on_expected_market_data= tries each booked type alone; a type the planner
refuses plans no trade and keeps a reason, which says the party expects none of
its market data when the full scope would have planned it, and the slots cycle
over the remaining types. The plan carries one outcome per type, and the
generate_trades step adds an info entry per config.

Acceptance:
- No draw names an address outside the party's expected set: the FX worst-of
  and basket partners come from the filtered pairs; a test checks that every
  FX index a plan names is the expected one. Met.
- A type with no candidate is left out and its slots go to the others: the
  booked types' trades fill the book. Met.
- The provisioning report has an info entry per config with the trades by type
  and the reason for each type with none. Met.
- On a fresh acme_demo provision every fixing address a trade names, IR and
  FX, has a series with values: 18 IR and 13 FX, none empty
  (=evidence/expected_market_data_plan.txt=). Met.
