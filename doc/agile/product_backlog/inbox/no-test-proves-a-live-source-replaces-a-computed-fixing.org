#+title: No test proves a live source of a computed item replaces the simulated one
#+description: A computed fixing is stated by the administrator's simulated source; a live source of the same item should win by the route resolution the store already applies, and nothing proves it for a computed item.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

The three term indices the run computes are stated by the administrator's
*simulated* source: =cme-a= for Term SOFR 1M, =banrep-a= for IBR 3M, =gpw-a= for
WIBOR 6M. A live source of the same item, when one arrives, should replace the
simulated one by the route resolution: the store keeps one active source for each
(party, provider), and a vendor ranked above another replaces it by precedence.

Nothing proves that for a computed fixing. The route resolution is exercised for
quotes, and the fixing sources are ranked in =fixing_sources.cpp= for the FX
cross matrix, but no test adds a live source of an item whose value the run
computed and shows it winning.

* Why

The rank rule is the whole argument for filing a computed value under the
administrator whose item it is: the administrator's own live feed, or a vendor
whose precedence is higher, replaces what the run computes without changing where
the item lives. If that does not hold, the file-under-the-owner decision buys
nothing but a truer name.

The task
[[id:0B9995FC-96D1-4785-AEBD-512397ECA7D5][Annotate a derived value instead of naming a derived provider]]
asked for the test and did not write it, and its Result says so.
