* Acceptance

- Windows (MSVC + Clang) CI goes green on all 12 affected translation units
- Linux (Clang/GCC) build remains green
- All affected test suites pass on Linux

* Plan

Root cause: =setenv=/=unsetenv= are POSIX-only functions (<cstdlib>).
On Windows (both MSVC and Clang), they are undeclared — the platform
uses =_putenv_s= instead. The 12 test files (1 nats, 11 service
config_parser) call =setenv=/=unsetenv= directly instead of using the
portable =ores::platform::environment= wrapper.

Fix: replace all raw calls with =environment::set_value= /
=environment::unset_value= from ores.platform, which already has
=#ifdef _WIN32= guards using =_putenv_s=. Drop =<cstdlib>= — no other
stdlib symbols are used in these files.
