* Goal

The body is read with the rest of the message, so the limit has to be decided
before the route is known and therefore is the same for every route. Reading the
headers on their own makes the route resolvable first, which is what lets the
limit fit the route and, later, lets the body be streamed.

* Acceptance

- The request is read in two steps, and the limit in force is the route's.
- A route with no stated limit gets the server default; one that states a limit
  gets that, capped by the server ceiling.
- The existing suites stay green.

* Plan

1. =http_session::run()= reads the headers with =http::async_read_header=, then
   reads the body with =http::async_read= on the same parser.
2. =body_limit_for()= strips the query, matches the route, and returns the route's
   =max_body_size= or the server default, capped by the server ceiling.
3. =http_server_options= gains =default_max_body_size= (1 MiB); =max_body_size=
   becomes the ceiling rather than the limit every route gets.
4. =domain::route= gains =max_body_size= and the builder gains =max_body()=.
