* Result

The sweep is a SQL function the scheduler can fire as an =execute_sql= job, as it
already does for the metrics scrape. It reads the enabled policies and, for a
chunk drop, does the drop itself: the action runs on either edition, which is the
gap a licence-guarded retention policy leaves open.

Each policy it considers writes one row to =ores_scheduler_retention_runs_tbl=
with the action, the target, what was removed and the outcome, with the reason in
=detail= when it did not apply.

Verified on the environment database, not in a fresh one: the policy table and
the sweep were applied, a one-day policy over the ticks table was inserted, and
the sweep reported =applied= with no chunks past that period, writing its run row.
