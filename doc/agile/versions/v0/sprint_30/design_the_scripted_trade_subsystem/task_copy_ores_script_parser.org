* Acceptance

- the sub-component sits below ores.trading.api and depends only on ores.utility, ores.platform and Boost Spirit; the component catalogue lists it
- every copied file keeps ORE's copyright header and names the ORE commit it was copied from, and a script diffs the copy against ORE's files at that commit
- parse returns ORE's error with its line and column, and every script of the library parses
- inputs_of agrees with the library's stored inputs for every script, and each difference is explained
- parse and check report their findings as diagnostics: an error or a warning, a stable code such as SCR1001, the one-based line, the column where it can be determined, the end of the range where known, and a message naming the construct, input or variable concerned
- the diagnostics are ordered by location and numbered by position, and the codes are held as data with their severity, title and explanation; a test reports each code at least once
- check reports every input, value and usage finding of a parsed script together, and parse reports the first syntax error with its position, as ORE's grammar does

* Plan

Two PRs.

1. The sub-component and the copy. =ores.trading.scripting= is a part of
   =ores.trading=, first in its =#+parts:=, generated from its component overview.
   ORE's grammar, syntax tree, parser, printer, converter back to text and random
   tree generator are copied by =utility/import_ore_scripting.py=, which reads
   ORE's files at a recorded commit through git, applies a fixed set of
   transforms (namespace, include paths and guards, QuantLib names to the
   standard library through =ore_compat.hpp=, and one stated patch), and
   clang-formats the result; =--check= fails when the committed copy differs. The
   copied identifiers stay ORE's, so the diff against ORE stays small; a façade in
   ORE Studio's style parses a script and reports a syntax error as a diagnostic,
   located in code points. The tests parse every code block of every script
   library ORE's examples ship.
2. =inputs_of= and =check=: the free variables of a parsed script with their
   types, multiplicities and rules, compared with the stored inputs of every
   library script, and the input, value and usage diagnostics.

* Notes

** What the first PR found

- ORE's identifiers, whitespace and keywords are ASCII and its grammar has no
  comments, so the text before a syntax error is ASCII. A syntax error's column
  differs from Spirit's only through tabs, which Spirit widens to four columns;
  the conversion to code points still counts multi-byte characters for the
  findings of later checks.
- ORE's own run reported the WorstOfBasketSwap error as =expected
  <InstructionSequence> in L17:30=; the diagnostic states the same line, column
  and message.
- The copied code carries no export macros, so the component builds with default
  visibility, as adding macros to ORE's declarations would hurt the diff.
- ORE's =ScriptGrammar= holds its 25 rules as fields, over compass-ng's
  =wide_types= ceiling of 15; the warning is left for the user to excuse, since an
  exception names its approver.

The form of validation findings, numbered errors and warnings with line and column, is [[id:ECA442BB-48D7-47CB-9BAA-97FD1C0BBA9A][Diagnostic Reporting in Script Validation]].
