* Result

The umbrella header is a permanent artefact of =ores.cpp.component=, and every
component that owns a namespace now regenerates one.

The reason it never did was discovery, not the template.
=manifest.discover_models= globbed a component's =modeling_dir= one level deep,
so a composite's parts -- =ores.refdata/api=, =ores.http/server= -- were never
enumerated. Their =export.hpp=, =tests/main.cpp= and umbrella headers had no
model in any pass and went stale with nothing reporting it: at =ores.iam/api=
those files were last written 2026-06-05 while their templates changed
2026-08-02.

Discovery now walks the parts by the same disk rule that
=_hosted_subcomponents()= validates the model against, and two regression tests
pin it. The parts' presence files were then regenerated, their 39 missing
=#+brief:= values authored, and the component file lists refreshed.

Two guards keep the graph off what main hand-maintains. A part's CMake is
hand-authored -- =ores.history/api= is a header-only =INTERFACE= library, and 93
of the 94 =src/CMakeLists.txt= diverge from the template baseline -- so the
graph skips every =ores.cmake.*= facet for a sub-component project.
=component_files.cmake= is owned by =regenerate_cmake_component_files.py=
alone, which its own archetype already claimed.

A service that outgrows the stub now keeps its code in its model.
=ores.storage/service= is the only component of kind =service=, so it is the
only one the service-app facet renders, and its =application.cpp=,
=options.hpp= and =parser.cpp= were hand-written inside generated files.
Component models carry paste blocks now, and six paste points cover the extra
includes, the namespace preamble, the body of =run()=, the option's member, its
declaration and its assignment. Regeneration reproduces the file it had, byte
for byte.
