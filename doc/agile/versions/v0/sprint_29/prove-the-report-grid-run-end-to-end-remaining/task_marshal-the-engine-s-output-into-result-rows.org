* Goal

The node turns the engine's own output into one file of canonical rows before it
uploads, so the service reads one shape and never the engine's files.

* Acceptance

- The projection lives in =ores.ore.core/results=, because the engine's headings are an ORE format.
- It reads the engine's headings by name: =TradeId=, =NPV=, =NpvCurrency=, =NPV(Base)=, =Notional=, =NotionalCurrency= and =CounterParty=.
- It writes one row per measure: =npv= and =npv_base= with their currency, and =notional= with its own currency when the file states one.
- It refuses a file with no =TradeId= and no =NPV= heading, a row with no trade id, a figure it cannot read and a currency-bearing measure with no currency. Any refusal uploads nothing.
- The wrapper gzips the canonical rows and uploads them as the result's rows, because storage holds blobs compressed.
- The canonical header is =subject_type,subject_id,measure,currency,counterparty_id,figure,source=.

* Plan

The projection renames the engine's headings onto the canonical columns rather
than interpreting the file. The wrapper marshals =npv.csv= after the engine
finishes, writes =results.csv.gz= beside the log file and uploads it to the
result's rows location.

* Result

The node writes the canonical rows from the engine's =npv.csv= before it uploads.
The projection is a rename of the engine's headings onto the canonical columns,
so a file whose headings are not the engine's is refused rather than guessed at,
and the refusal names the headings it saw. Three measures come from one file:
=npv=, =npv_base= and =notional=, each with the currency the engine stated beside
it, and the counterparty the file names travels on every row. The rows are
gzipped, because storage holds blobs compressed, and the service decompresses
them on read.

The projection reads only =npv.csv=. Every other analytic's file has no
projection yet, so a run of one of those analytics uploads no rows.
