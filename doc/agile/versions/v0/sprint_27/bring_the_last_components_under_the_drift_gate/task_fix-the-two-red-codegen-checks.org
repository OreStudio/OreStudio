* Result

Seven cases failed for three reasons, none of them a codegen defect.

Five were fixtures that predate =d16b253c21=, which made
=validate_rls_isolation= refuse tenant isolation without =has_tenant_id=
and party isolation without a =party_id= column. The fixtures now declare
both where their flags read them; no assertion changed. The same column
went into the name-base fixture, whose party policy is the subject of the
truncation case.

The seventh named =ores_trading_trades_tbl= as immutable, and
=a2dcf034fa= made every trading entity a regular versioned table, so the
target is temporal and the check correctly emits the current-version
filter. No soft FK left in the tree points at an immutable entity -- the
one model that declares =:immutable:= has its only soft FK enforced, so
it renders no trigger check -- so the case points the table-to-org lookup
at that model and keeps its claim.

=er-diagram= was stale by =output_storage_key : text=, added by
=fd06ab945a= and never regenerated. The =.puml= now carries it. The PNG
is left as committed: PlantUML cannot paint this diagram here, failing in
=EmptyImageBuilder= with =NegativeArraySizeException= and writing
different bytes on each run, and the check reads the =.puml= alone.

Story's =* Decisions= is not touched: the task settles stale fixtures, not
a design question.
