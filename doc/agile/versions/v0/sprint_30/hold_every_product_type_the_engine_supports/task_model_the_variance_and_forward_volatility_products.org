* Acceptance

- each of the six types names an instrument table, with the basket or the pair in relationship rows
- the projection reads and writes each element, value for value
- each type has a builder, and the catalogue routes all six
- the generator books one trade of each type through its builder, and the recorded trades hold it
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: no list, basket or schedule is held as text

* Plan

All six elements are flat: scalar terms, one Underlying or a list of them,
lists of values, and schedules. They route to the scripted instrument table
through the class-read path. The two pairwise variance swaps are native ORE
products, but their element is as flat as the others, so the same table holds
them.

- The class-read path reads and writes a free style scalar, an element whose
  value is its own text with an optional type attribute. The pairwise variance
  swap states every term this way. Its declared type is the attribute, or the
  schema type's name less =stFreeStyle=.
- A list of indices (=stFreeStyleIndexVector=) is an =Index= list: held as
  addresses, written in ORE's spelling.
- A rules schedule a builder states carries its term convention, as ORE's FX
  basket variance swap example does.
- Builders: =basket_variance_swap_builder=, =pairwise_variance_swap_builder=
  and =forward_volatility_agreement_builder=, each for equity and FX.

* Result

The six types are held in the scripted instrument table. The basket members
and their weights are underlying rows, the pairwise legs are three lists of
parameter values, and the valuation schedules are schedule rows. The round-trip
test reads ORE's FX basket variance swap example, the user guide's equity
pairwise variance swap and its FX forward volatility agreement, and writes them
back. Each type has a builder, the catalogue routes all six, and the generator
books one trade of each.

The ORE engine builds every recorded trade with no error of the trade kind. The
two pairwise variance swaps raise an engine configuration error: ORE's Products
example configuration names no engine for them. The known list holds both, and
pricing engine configuration is out of this story's scope.
