The real-data counterpart to the [[id:B0A8E259-5B88-40AE-BA27-BBC3679186E7][Acme Corp (synthetic) provision]]: same
three-stage shell flow, but =provision tenant= is called with

* Question

How do I provision a fresh system from the shell with the Acme Bank
holding-group data?

* Answer

Bootstrap =super_admin=, install an =Acme Bank= tenant, then provision
it with =--source acme=, which server-side orchestrates importing the
Acme LEI hierarchy (all four legal entities) and publishing each
party's business units/portfolios/books plus the group-wide accounts
dataset — no repeated per-party logins, no client-side orchestration.

Expectations: the services are up (=compass services start=) and the
database is fresh (=compass db recreate -y -k= → bootstrap mode).
=connect= takes the endpoint from =$ORES_NATS_URL= and inherits the
subject prefix and TLS context the shell was started with.

#+name: acme-bank-system-provision
#+begin_src ores-shell :exports none
connect $ORES_NATS_URL

provision system super_admin Secure-Password-123 super_admin@localhost.com --tenant-admin-password Secure-Password-123 --tenant-code acmebank --tenant-name "Acme Bank" --tenant-hostname acmebank
logout

login tenant_admin@acmebank Secure-Password-123
provision tenant --source acme
logout

exit
#+end_src

#+begin_src sh :noweb yes :results output :wrap example
./ores.shell ${log_args} ${connect_args} << 'EOF'
<<acme-bank-system-provision>>
EOF
#+end_src
