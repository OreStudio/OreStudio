* Result

Closed on branch =hotfix/clear-the-new-nightly-failures=, rebased onto main at
0e2470c87e.

The nightly failed on three test-only causes: the analytics tests used
=std::accumulate= without =<numeric>= (Windows) and compared
=std::partial_ordering= with the literal zero inside Catch's matcher (clang-cl);
the tick scheduler case slept a fixed span and took two readings where it
expected three; and the synthetic golden was stale. The golden and the scripted
Strike were already fixed on main by the time this branch was rebased, so those
changes were dropped.

The full GCC build then found no =-Wchanges-meaning= anywhere, so the reporting
route's =unread= rename was the last one, and reported 18 warnings in three
families, all cleared here: =-Wsubobject-linkage= on the synthetic application's
fleet, the marketdata official application's BCCH closure and the host runner
tests' local types; =-Wmaybe-uninitialized= on the file-types request's
defaulted order member; and =-Wmaybe-uninitialized= on =http_request::method=,
which the route tests read from a default-constructed request.

The site build's unresolved link to a superseded task now points at the task
that replaced it.

Out of scope: the Windows =C2220=/=C4244= narrowing inside =std::optional<int>=,
which needs an MSVC build to pin down.
