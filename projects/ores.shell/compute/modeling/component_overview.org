* Summary

=ores.shell.compute= is the adapter part that projects the compute domain
onto the shell's REPL menu. It holds the generated command units for the
compute models that opt in, and each unit owns one submenu.

An entity unit owns that entity's verbs: the paged list, the read by key,
the write, the delete, the scoped reads and the version reads, each
rendered from the entity's derived protocol. A junction unit owns the
junction's own verbs. The part declares =#+component_kind: adapter=, so
its command units are static and link into =ores.shell.exe=.

The generated units cover the entity verbs, from the same models the
service serves, so a verb the model gains appears as a command without an
edit. The grid verbs no single entity owns — publish a package, dispatch a
batch, watch the grid, and download a job's input or a result's output —
stay in the hand-written =compute= menu in =ores.shell.application=,
because each orchestrates several entities rather than one.

* Inputs

- The compute entity and junction models under =projects/ores.compute/modeling/=.
- A shell session, for the NATS client every command addresses.

* Outputs

- One command unit per compute model, each registering its own submenu.

* Entry points

- =ores::shell::app::commands::app_commands::register_commands= and its
  siblings, one per model.

* Dependencies

- =ores.shell.api= for the menu and the request helpers.
- =ores.compute.api= for the generated protocol types.
- =ores.nats=, =ores.logging=, =ores.platform=, =ores.utility= and =cli=.
