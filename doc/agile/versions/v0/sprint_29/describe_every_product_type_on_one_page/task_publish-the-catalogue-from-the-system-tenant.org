* Acceptance

- One current row exists per product type code in the whole database.
- A tenant provisioned from scratch reads the system rows and can book against them.
- The trade check reads the system rows, and no reader names a tenant copy.
- The migration removes the per-tenant copies from an existing database and runs twice without effect.
- compass db recreate ends in the same state.

* Plan

The catalogue is already seeded into the system tenant, and the trade check
already reads those rows by naming the system tenant. What is missing is the
read and the copy.

- Give the three tables the own-or-system-tenant policy, so a session reads its
  own rows and the system tenant's and writes stay its own. This is the shape the
  meta model calls =:rls_own_or_system_tenant_rows:=, not the system-tenant
  widening, which is for a session that must see every tenant.
- Mark the three entities =:system_tenant_visible:= in their repository drawer.
  Without it the generated read filters on the session's tenant alone and a
  tenant reads nothing, because the policy admits rows the query has already
  excluded.
- Stop the provisioner copying the catalogue into each tenant.
- Delete the copies an existing database holds, in a script that runs with the
  seed and does nothing on a second run.
- Prove it: a session of a provisioned tenant reads the catalogue, and the
  database holds no copy.

* Notes

** 2026-11-02 — the catalogue is one copy

The provisioner's copy was a bridge. The previous task replaced the trade type
table, and the tables were tenant-isolated, so a tenant that booked a trade saw
no product types unless the catalogue was copied to it. That copy is gone, and
the isolation it made necessary with it.

The two halves have to move together. The policy on its own is not enough,
because the generated read names the session's tenant: a tenant would ask for
its own rows, the policy would not matter, and it would read nothing. The
repository flag on its own is not enough either, because the policy would refuse
the rows the query asked for. Both are stated, and the suite proves the read.

Provisioning a tenant end to end runs and generates its trades, so the trade
check reads the one catalogue while the writes land in the tenant.
