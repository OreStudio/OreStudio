* Decisions

- *A shared registry carries no ports.* =service_registry.org= is deployed by
  every environment, so a literal port in it is wrong however right the port is
  for one checkout. The telemetry monitor URL references the environment's own
  variable.
- *Fix the omission, do not model around it.* Storage is a compiled service like
  its siblings, and every sibling publishes a heartbeat. It gets one rather than
  the roster learning to treat it specially.
- *The web service is left as it is.* It cannot publish a heartbeat, and whether
  the roster should list a service that cannot report belongs to the roster.

* Out of scope

- Whether the roster should list a service that has no heartbeat, such as
  =ores.web.service=. It still reads as =missing=.
- The =AUTO-GENERATED FILE= header on the service =application.cpp= files, whose
  template is a stub that cannot produce them.

* Result

Both defects are fixed and the screens read correctly against a running fleet.

The message bus screen was permanently empty: the telemetry poller was pointed
at a literal =localhost:8221= from the shared registry while this environment's
NATS monitor is =20406=. It now reads its own environment's variable, and the
screen shows server samples and all five JetStream streams.

The services screen reported a running service as =missing=: =ores.storage= was
the only compiled service with no heartbeat publisher. It has one now, pending a
build.
