* Goal

The fixed elements of these products are held on tables of their own, with
their terms as columns, beside the generic ScriptedTrade form the scripted
table holds.

* Acceptance

- each of the five types routes to a table of its own (one table may serve an equity
  and an fx pair that state the same element), whose columns hold every scalar term the
  element states; lists, baskets and schedules are rows of child tables or of
  the shared rows (options, barriers, underlyings, schedules)
- the projection reads and writes the element from those rows, value for value,
  and a round-trip test reads ORE's or the user guide's example and writes it back
- the builder states the rows, and the generator books the element form
- the class-read entry for the type is removed: the scripted instrument table
  holds no element form of it, only the generic ScriptedTrade form where ORE's
  library carries one
- the catalogue names both forms of the type where ORE carries both
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: nothing is held as text

* Plan

Two PRs, decided with the user on 2026-11-19.

1. FxWorstOfBasketSwap. FX has no general swap table, so it gets a table of its
   own for the element's scalars, as EquityWorstOfBasketSwap is held on
   =equity_swap_instrument= with its constituents and periods. The members with
   their initial prices, the per-period knock-out and fixed trigger levels and
   the eight schedules are rows: FX constituent rows (or underlying rows), the
   shared =basket_swap_period= rows and schedule rows.
2. Autocallable_01, DoubleDigitalOption, EuropeanOptionBarrier and
   PerformanceOption_01 have no home market: their underlyings may be equity,
   FX or commodity, and one trade may mix them (a DoubleDigitalOption states up
   to four underlyings, a EuropeanOptionBarrier one for the option and one for
   the barrier). Routing is per type and every table so far sits in a family
   carrier, so these four get a new multi-asset family: its own carrier, one
   table per product, the shared underlying and schedule rows (each underlying
   row keeps its own type), and child tables for the value lists
   (StrikePrices, AccumulationFactors). The product type asset class junction
   records equity, FX and commodity for each, with no home market. The user
   chose this over an element row on the scripted carrier and over deferring
   the four.

class-read path, as parameter rows. That held every value but gave the element
no table of its own, against the story's rule that a product ORE carries in
both forms is held in both, and that the forms can be compared.
