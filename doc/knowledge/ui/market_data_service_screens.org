* Summary

The *Market data* menu holds four areas. The catalogue shows what providers
offer. Subscriptions and routes show what a party takes and from which source.
Usage and cost show what a party used and what it costs. The simulator holds the
authoring tools. The first three are the same for live and simulated sources.

* Detail

| Area | Shows | Who |
|------+-------+-----|
| Catalogue | Providers, their sources with kind badges, vendor instruments, mappings, minted ids | Everyone reads. The system administrator writes. |
| Subscriptions | A party's subscriptions, rights, and the route of each | Party administrator |
| Usage and cost | Demand, delivery, bills and shadow bills, by provider and period | Party administrator reads own. System reads all. |
| Simulator | Collections, folders, generators, preview, fault injection | Simulator author |

** Rules for the screens

- A source's kind is a badge and a filter, and it changes no other behaviour. See
  [[id:F64DB34E-084D-4437-B536-392AA26D8B77][No code path may behave differently because a source is simulated]].
- A source screen shows the adapter state, the demand set and the rejected ids.
  See [[id:B4729C76-4D88-4F3C-B3D3-5FC7BD62D158][The adapter lifecycle]].
- A route change goes through a dialog that asks for a reason.
- The simulator area is the only one with authoring controls.

** Standards

All screens follow the record screen standard and the feed screen standard. The
simulator screens are described in [[id:5779B40E-1C82-478D-951E-C81C13F7DFEA][The market simulator screens]].
