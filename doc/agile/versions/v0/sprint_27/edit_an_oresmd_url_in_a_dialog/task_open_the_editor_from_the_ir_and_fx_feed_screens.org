* Result

PR 3152 is merged, and the IR curve feed and the FX feed share one set of screens through =FeedKind=. Both kinds draw their market data URI as a row of the Details tab through =extraDetails=. That row is now =OresmdUrl=: the URI as text with an *Open in the editor* button that opens the editor over the screen, loaded with that URI. =extraDetails= now returns a node and not only text, so a kind can draw a button.

The editor opens read-only on these screens. A feed's URI follows from its currencies and its curve, so the feed owns no URI to change, and the story's open question about Apply is answered for the feeds: no Apply. =OresmdEditorDialog= takes =onApply= as optional, and without it the editor offers Copy and Cancel and no Apply. A screen that does store a URI passes =onApply= and gets the edited URI back.

Tests: the two feed screens draw the button, =OresmdUrl= draws the URL, draws nothing for an empty URL and keeps the editor closed, and the dialog without =onApply= has no Apply. The full web suites pass (web 1332). I drove =OresmdUrl= in headless Chrome against a mock of the routes: the URL shows as text, the dialog is closed at first, the button opens the editor field by field with Copy and Cancel and no Apply, and Cancel closes it. I did not open the full feed pages in a browser, because they need a signed-in session and the records of a running server, and the feed tests that draw them as markup show the button. The routes were mocked, so the grammar and the wire shapes are not checked against the real services.

With this task the five tasks of the story are done. What is left of the story is the open questions: modal against inline, encoding of the path, a value outside the catalogue, the catalogues that have no reader yet, and a run against the real services.
