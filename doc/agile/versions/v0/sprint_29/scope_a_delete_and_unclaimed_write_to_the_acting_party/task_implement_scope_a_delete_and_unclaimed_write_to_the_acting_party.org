* Goal

A write or a delete from a session that sees several parties acts on the acting party's row of the key, and only on that row. The repository makes the choice where it reads, so the service needs no filter after the read.

* Acceptance

- read_latest by key prefers the acting party's rows, with the rule of_acting_party() has today: keep only the acting party's rows when one exists, otherwise keep the rows as read.
- remove checks the version of the acting party's row and closes only that row: the delete names the party of the row it checked.
- A write with no precondition states the version of the acting party's row.
- The service template drops of_acting_party(); the helper and its tests go if nothing else uses them.
- A test proves from a parent party that a delete and an unclaimed write of a convention key touch only the acting party's row.
