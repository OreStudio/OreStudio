#+description: Read build/output/local_checks/report.md, re-run the one failing check with compass check --only, read its log, fix, and re-run the whole gate.

This is one branch of the [[id:F6E88DCC-9240-4632-A9A3-9F36F79C9262][PR monitoring loop]]. The other branch is
[[id:26C1DC06-82D2-46C4-94D6-DF9231BA171B][addressing review comments]].

* Question

A check failed. How do I find what it was, fix it, and prove the fix?

* Answer

1. /Read the report/. =compass check= writes
   =build/output/local_checks/report.md=. Its *Fix these first* section
   names each failing check, the command that reproduces it, the command
   that fixes it, and the tail of the check's own log:

   #+begin_src sh :results verbatim
   ./compass.sh check
   sed -n '/## Fix these first/,/## Every check/p' build/output/local_checks/report.md
   #+end_src

2. /Re-run just the failing check/. Every check has an id, printed in the
   report's *Every check* table:

   #+begin_src sh :results verbatim
   ./compass.sh check --only component-drift
   #+end_src

3. /Read the full log/ when the tail is not enough. Each check writes one
   file, named after its id:

   #+begin_src sh :results verbatim
   less build/output/local_checks/logs/component-drift.log
   #+end_src

4. /Diagnose by category/:

   - /Drift/ (=component-drift=, =model-drift=, =tangle-*=) → regenerate
     the artefacts the check names, then commit them.
   - /Compilation/ → fix the source file.
   - /Test failure/ → fix or update the failing test, then run
     =./compass.sh test run -R <name>= for a single suite.
   - /Formatting/ → =clang-format -i= on the files the report names.
   - /Documentation/ → fix the page or the link; =site-page= names the page.
   - /Cross-platform/ (=enum-attributes=, =exported-types=) → the defect is
     one only MSVC reports; fix the header, no Windows build needed.

5. /Re-run the whole gate/ and confirm it is green:

   #+begin_src sh :results verbatim
   ./compass.sh check
   #+end_src

6. /If the failure is on main instead/. The twelve retired pull-request
   workflows kept their =push= to =main= trigger, so a defect that escaped
   the runner shows there. Find the run and read the failing step:

   #+begin_src sh :results verbatim
   gh run list --branch main
   gh run view <run-id> --log-failed
   #+end_src

   The fix is the same, and the local check then reproduces it:
   =./compass.sh check --only <id>=.

* Script

=compass check= and the report it writes. The GitHub fallback is the bare
=gh= CLI.

* Tested by

The runner's own suite, =projects/ores.codegen/tests/test_local_checks.py=,
pins the decision tree: a documentation change must not reach the compiler,
a header change must, and a path nobody classified must ask for everything.
