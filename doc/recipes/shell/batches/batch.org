#+title: How do I run the batches commands from the shell?
#+description: Every command the batches submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:batches:

This file documents the batches resource at the shell, one section per command. Every command is a subcommand of =batches=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 4C0B7852-5EA3-5224-95A0-565547B96F7F
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
batches list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =compute.v1.batches.list=.

#+name: batches-list
#+begin_src ores-shell :tangle batches-list.ores :exports none
batches list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 20FB1889-D384-5081-AECF-33BE896AF230
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
batches get <external_ref>
#+end_example

It is addressed at =compute.v1.batches.get=.

#+name: batches-get
#+begin_src ores-shell :tangle batches-get.ores :exports none
batches get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: B3011C7C-72FA-50A5-889F-D0760C2ECEA4
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
batches add <id> <external_ref> <status> <reason> <commentary>
#+end_example

It is addressed at =compute.v1.batches.put=.

#+name: batches-add
#+begin_src ores-shell :tangle batches-add.ores :exports none
batches add 00000000-0000-0000-0000-000000000000 __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 7E3046C2-16F6-5C04-8CBA-EA7A558E46A4
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
batches set <id> <external_ref> <status> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =compute.v1.batches.put=.

#+name: batches-set
#+begin_src ores-shell :tangle batches-set.ores :exports none
batches set 00000000-0000-0000-0000-000000000000 __none__ __none__ system.new_record generated_script
#+end_src
