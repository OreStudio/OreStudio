The detail row of one =marketdata.curve_publish= approval request: the subject
the request authorises, and the record of the act once the subject is published.

A request is a header. What it is about lives here, keyed by the request's own
id, exactly as a proposed book change lives in =ores.refdata.book_change= and is
keyed by its request. The subject is three facts and no more: the curve
configuration whose output is published, the as-of instant the bootstrap reads
the market at, and the party the configuration belongs to (=party_id=). The curve
is named by its configuration because that is what the publish call names. The
series the output is written to (=output_series_id=) is carried beside it because
the reader that serves a published curve starts from a series and not from a
configuration.

=published_at= and =published_by= are the publication record. Both are empty
while the request waits, and both are written in one act when the approved
subject is published: the timestamp is the instant the published set moved, and
the username is the account that applied it. The row is bitemporal, so the
applied version is a new version of the same row and the history holds the
unapplied subject beside it. =request_id= is the natural key, so a request
authorises one publish and no second apply can find a row to write.

A set ends once, and the end is two more facts on the same row rather than a
second entity. =withdrawn_at=, =withdrawn_by=, =withdrawn_reason_code= and
=withdrawal_request_id= are the withdrawal: the instant, the account, the reason
and the request that authorised it, written as a new version of this row. The
withdrawal is not a deletion: the published facts stay, so the set a desk priced
from is still readable afterwards. =superseded_at=,
=superseded_by_request_id= and =superseded_as_of= are the supersession: a later
publish replaced this set, and the link names the successor's request and the
as-of it was built at. A supersession is a publish and not a second act, so the
successor's own apply writes it on this row.

The state a reader sees is a function of these facts and is stored nowhere:
withdrawn when =withdrawn_at= holds an instant, superseded when =superseded_at=
does, published when =published_at= does, and a candidate otherwise.

The row is not a client's to write: the raise writes it, the gate reads it, and
the apply stamps it. A client reads it to decide a request or to audit a curve.

** Flags
:PROPERTIES:
:tablename:            ores_marketdata_curve_publishes_tbl
:rls_tenant_isolation: true
:END:

The record is tenant-scoped and not party-scoped: the decider of a publish is a
tenant function -- Market Risk of the tenant -- so hiding the subject behind the
party a decider does not work in would hide the request's own subject from the
person who decides it. The subject names its party instead, so a reader always
knows whose curve it is.

** Checks

| expression                                                    |
|---------------------------------------------------------------|
| ("published_at" is null) = ("published_by" = '')              |
| "as_of" > '1970-01-01 00:00:00+00'::timestamp with time zone   |
| ("withdrawn_at" is null) = ("withdrawn_by" = '')              |
| ("withdrawn_at" is null) = ("withdrawn_reason_code" = '')     |
| "withdrawn_at" is null or "withdrawn_at" >= "published_at"    |
| ("superseded_at" is null) = ("superseded_by_request_id" is null) |
| ("superseded_at" is null) = ("superseded_as_of" is null)      |
| ("withdrawn_at" is null) or ("superseded_at" is null)         |

A set ends once, either because it was taken out of use or because a later set
took its place. The last check states that, so the three end facts a reader
finds are the three the state names.

** Indexes

| name                              | columns                            | unique | current_only |
|-----------------------------------+------------------------------------+--------+--------------|
| curve_publishes_series_published  | tenant_id, output_series_id, published_at desc | false  | true         |

The second index is the single-use rule of a withdrawal: a decision authorises
one act, so two sets cannot name the same withdrawal request. A set that ended
without a request holds null there, and the store treats nulls as distinct, so
every set a person ended alone is its own index entry.

std::optional<domain::curve_publish>
curve_publish_repository::read_latest_published_for_series(
    context ctx, const boost::uuids::uuid& series_id) {
    BOOST_LOG_SEV(lg(), debug) << "Reading the published set of series: " << series_id;
    static constexpr auto max = db_timestamp::max();
    const auto tid = ctx.tenant_id().to_string();
    const auto sid = boost::uuids::to_string(series_id);
    const auto query = query_builder::read<std::vector<curve_publish_entity>> |
                       query_builder::where("tenant_id"_c == tid && "output_series_id"_c == sid &&
                             "valid_to"_c == max);

    auto rows = query_builder::execute_read_query<curve_publish_entity, domain::curve_publish>(
        ctx,
        query,
        [](const auto& entities) { return curve_publish_mapper::map(entities); },
        lg(),
        "Reading the published set of a series.");

    // The newest applied version wins. A record that holds no instant is a
    // request that still waits, and a waiting request publishes nothing.
    rows.erase(std::remove_if(rows.begin(),
                              rows.end(),
                              [](const auto& r) { return !r.published_at.has_value(); }),
               rows.end());
    if (rows.empty())
        return std::nullopt;
    const auto newest =
        std::max_element(rows.begin(), rows.end(), [](const auto& a, const auto& b) {
            return *a.published_at < *b.published_at;
        });
    return *newest;
}

Reads every record of one series that was published and has not ended, newest
first. The publish gate asks here before it stamps the successor: one live set is
what a reader is promised, so a series that holds more than one is a set that
never ended, and the apply ends them all.

#+begin_src cpp :name implementation :implements F2EB1914-5E94-42CA-9C77-46BDB364BF9E
std::vector<domain::curve_publish>
curve_publish_repository::read_live_for_series(context ctx,
                                               const boost::uuids::uuid& series_id) {
    BOOST_LOG_SEV(lg(), debug) << "Reading the live sets of series: " << series_id;
    static constexpr auto max = db_timestamp::max();
    const auto tid = ctx.tenant_id().to_string();
    const auto sid = boost::uuids::to_string(series_id);
    const auto query = query_builder::read<std::vector<curve_publish_entity>> |
                       query_builder::where("tenant_id"_c == tid && "output_series_id"_c == sid &&
                             "valid_to"_c == max);

    auto rows = query_builder::execute_read_query<curve_publish_entity, domain::curve_publish>(
        ctx,
        query,
        [](const auto& entities) { return curve_publish_mapper::map(entities); },
        lg(),
        "Reading the live sets of a series.");

    // A set is live when it was published and nothing ended it: a record with no
    // instant is a request that still waits, and one that carries an end is a set
    // a reader no longer prices from.
    rows.erase(std::remove_if(rows.begin(),
                              rows.end(),
                              [](const auto& r) {
                                  return !r.published_at.has_value() ||
                                         r.withdrawn_at.has_value() ||
                                         r.superseded_at.has_value();
                              }),
               rows.end());
    std::sort(rows.begin(), rows.end(), [](const auto& a, const auto& b) {
        return *a.published_at > *b.published_at;
    });
    return rows;
}
