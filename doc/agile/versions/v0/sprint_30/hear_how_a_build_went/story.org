* Goal

A build reports itself to a person who is not watching it. A local build runs
for minutes to an hour and is usually started and then left; the log answers
what happened only to someone who goes looking. The build plays the desktop's
own freedesktop sounds instead: information when it starts, complete when it
ends green, error when it ends red, so the vocabulary is the machine's and not
one this project invents. CI pays nothing: the sounds are local, and a machine
with no player or no theme builds in silence.

* Acceptance

- Starting a build plays one sound, and a finished build plays another that
  says whether it succeeded.
- The sounds are the desktop's own theme, so they are recognisable and do not
  ship audio in the repository.
- A build never waits on a sound, and a machine with no player or no theme
  builds in silence.

* Decisions

- *The desktop's sounds, not this project's.* =dialog-information= when a build
  starts, =complete= when it ends green, =dialog-error= when it ends red, from
  the freedesktop theme every desktop already installs. A person learns nothing
  new to read the outcome, and the repository carries no audio.
- *The sound never costs the build anything.* The player is spawned detached
  with its output dropped. A missing player, a missing theme file or a dead
  sound server leaves the build exactly as it was, which is why the sounds need
  no failure path and cannot fail a build.

* Out of scope

- Desktop notifications (=notify-send=). The sound answers "is it done"; a
  notification would answer "what did it say", and the log already does.
- A sound for the build lock's wait, or for tests and other long commands.
