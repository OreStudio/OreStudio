* Goal

A builder can look up the conventions an oresmd identifier needs, and the exporter and importer can project an identifier to ORE and back under a market configuration, both in the marketdata API. The names follow the market data requirements pages: resolution is a requirement mapped to an identifier, which this task does not do.

* Acceptance

- =convention_lookup= answers by identifier: an index's convention, the swap convention that uses it, a CDS convention, an equity or commodity underlying; an unknown address is a stated error. An in-memory implementation serves tests, the generator and the shell.
- =ore_projection= writes an identifier as its ORE name, and reads an ORE name back where the codecs can, under one market configuration: fixed for indices through =ore_index_codec=, configuration-bound for curves.
- =reference_curve_names= and =reference_curve_names_of= are replaced by =ore_projection= and deleted, with the bond export unchanged in the recorded trades.
