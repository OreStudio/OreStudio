* Acceptance

- The shared options types (logging, nats, database, telemetry, http_server) state their shapes through codegen.
- No hand-written wire_fields remains for an options type.

* Plan

One archetype in the field-group facet, =options_header=, writes an options
struct where its library keeps it, from a field group model that names its
header. A converter read each hand-written header into its model, and a
comparison requires the generated header to hold the same code as main's.
Components outside the drift registry join it with their component model
excluded, so only the options models regenerate.

* Notes

=context_factory::configuration= in ores.database keeps its hand-written
shape. It is a struct nested in a class, the configuration a context is made
from, and no options type: moving it out of the class would change every
caller for no gain in what the wire carries.

* Result

All ten options types state their shapes through codegen: logging, nats,
database, telemetry and the HTTP server's, and the options of the compute
wrapper, the HTTP server, the official market data adapter and the shell's
two. The new =options_header= archetype writes each from a field group model,
with =:secret:= keeping a value out of the shape, an optional printer and a
paste point for declarations such as =to_connection_options=. logging, nats
and database joined the drift registry with their component models excluded.
The generated headers hold the same code as main's.
