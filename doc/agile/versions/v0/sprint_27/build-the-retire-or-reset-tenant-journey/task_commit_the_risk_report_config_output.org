* Result

check_component_drift --all exits 0 over every component and reports no drift.

The task began as its opposite. ores.dq.risk_report_config.org was an invalid
scaffold that aborted the gate at dq, and the first branch removed it. While
that sat open, 97051b9fd0 completed the model on main, so deleting it would
have destroyed finished work and the removal was abandoned.

What was left is the second half of that commit: it added the model and
committed the model, but not everything the model generates. The dq TypeScript
domain and protocol twins were untracked, and the marketdata identity SQL and
the reporting operations protocol moved with it. component-drift names
untracked files explicitly, because git diff cannot see them, so the gate kept
failing on a tree that looked complete.

The lesson is not about this model. A model and its generated output are one
change, and committing the first without the second leaves the gate red in a
way that reads as drift rather than as an omission.
