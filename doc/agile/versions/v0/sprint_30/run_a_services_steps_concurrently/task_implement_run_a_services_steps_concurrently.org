* Acceptance

- =serve_step_commands= takes a worker count, one by default, so every other
  service is unchanged.
- =step_workers= waits for a free worker rather than queueing, and its
  destructor joins the running steps.
- A delivery moves to its worker, which settles it; a step that throws on a
  worker is logged and its delivery rolls back.
- The IAM provisioning steps run on four workers, and the service token
  provider takes a lock.
- A fresh environment provisions the system and Acme to completion with no
  service crash.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)


The provisioning run of the conventions story stopped at attach_photos: the
IAM service ran its steps one at a time on the delivery thread of its step
subscription, generate_trades took about 25 minutes, and attach_photos,
set_staff_passwords and schedule_reports waited behind it until the workflow
failed attach_photos as unclaimed after twenty minutes.

1. Audit the step handlers of the fourteen services that serve steps for
   state a call changes. Their members are references, database contexts,
   configuration, and caches that lock or read wait-free, with one
   exception: the service token provider caches its token with no lock, and
   handlers on several subscriptions already call it at once.
2. Add =step_workers=, a fixed set of threads that waits for a free worker
   rather than queueing, so a command not yet taken stays with the server.
3. Give =serve_step_commands= a number of workers, one by default, and run
   the IAM provisioning steps on four. Steps that hold a database connection
   for long, such as the data quality publishes, stay on one: more workers
   than the pool's two connections would starve the service's other handlers.
4. Lock the service token provider.

* Result

=serve_step_commands= runs a service's steps on the number of workers it is
given, and IAM runs its provisioning steps on four. The branch was rebased on
/Own each durable NATS delivery with one RAII transaction/: a step's delivery
moves to its worker, so the double free that crashed IAM when this branch
first ran cannot happen. =step_workers::run= takes a
=std::move_only_function=, because a delivery cannot be copied.

All acceptance points are met. =ores.service.tests= (63 cases, including the
four =step_workers= cases), =ores.nats.tests= (65), =ores.iam.service.tests=
(13) and =ores.iam.core.tests= (341) pass.

A fresh environment provisioned the system (3 of 3 steps) and Acme (17 of 17)
to completion with this branch merged with the hotfix /Publish one curated
convention set and provision to completion/, with no failed unit and no
crash in the journal. The steps now run side by side, which exposed two
defects in the derived FX vol source that the hotfix fixes. Without the
hotfix, provisioning stops at =generate_trades= on the convention defect it
names.
