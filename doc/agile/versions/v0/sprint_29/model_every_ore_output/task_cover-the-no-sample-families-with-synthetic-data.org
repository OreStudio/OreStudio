* Acceptance

- Every output the seed names is a family with a sample, real or synthetic, or is stated out of scope with a reason, and the generator refuses one that is neither.
- A synthetic fixture's columns come from the writer that produces it at ORE v1.8.17.0, and each fixture names its writer.
- The catalogue marks a family whose only fixture is synthetic, so a reader can tell a sample ORE shipped from one we wrote.
- The corpus gate reads a synthetic fixture exactly as it reads a sample, and fails when a family has neither.

* Plan

The seed names 44 output files; 27 had no family. The writers at ORE v1.8.17.0
(3d75a6908, the version the project vendors) sort them:

- *Real samples outside the suites.* =runtimes= and =scenariodump= are in the
  notebook examples, =timeaveragedexposure= in the legacy ones, and
  =pricingstats= is captured from a run here. Each source is read for the named
  families only, because the notebooks and legacy examples repeat the suites.
- *Synthetic.* =crif=, =capital_crif=, =sacva_sensitivity=, =jacobi= and
  =jacobi_inverse= have a writer and no sample; each fixture states its writer's
  columns in order, with two rows, and the catalogue marks it synthetic.
- *Other names.* A report the run configuration does not name is written under
  the engine's report name: =cashflow.csv= is flows and =saccrdetail.csv= is
  saccr_detail, which a run here wrote and the catalogue missed. The seed names
  the initial margin files =.txt=. A family now carries alias patterns.
- *Stems.* =pca.csv= and =meanReversion.csv= are written per currency, as the pca
  and mean-reversion families already match.
- *No writer.* crossgamma, productclass_mapping, creditcurves, parsensi, the
  aggregation scenario dump and the xvaSensitivity jacobi names are parameters no
  code reads at v1.8.17.0.
- *Not a report.* The =.dat= files are binary data the engine reads back; the
  =.csv.gz= cubes are compressed copies of what rawcube and netcube state as text.
- *Text-valued.* additional_results, marketObjects, riskFactors and the calibrated
  model's XML have no figure, so no reader here holds them. They are a new task,
  Store the text-valued outputs.

The generator states each out-of-scope file with its reason and refuses a seed
output that is neither a family nor stated, so the list cannot drift.
