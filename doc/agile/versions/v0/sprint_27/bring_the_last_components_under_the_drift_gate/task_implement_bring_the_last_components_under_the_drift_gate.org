* Result

ores.inbox is regenerated and named in COMPONENTS_UNDER_TEST, so
check_component_drift --all now covers it. The component was never dirty:
nothing in it was hand-edited or wrong. Its output had simply stopped being
regenerated when the registrar template's include lists moved on, and 95
files had drifted while the gate reported a clean tree. Regenerating it
produces no inbox drift, which is the answer to whether these components are
clean -- they are, but unguarded generated output rots.

The branch's check run is red on codegen-tests, from a trunk defect it does
not touch: trading::trade_link_types:{delete,read,write} are checked in the
handler but never seeded. Recorded for its own task.
