* Acceptance

- The Product website workflow runs on a two-hourly schedule and on manual dispatch, and no longer on push to main.
- Deploy to GitHub Pages still runs on the scheduled and manual runs.

* Plan

=build-site.yml= built and deployed on every push to main. The site build and
the Doxygen deploy take longer than the gap between pushes on a busy day, and
=site-cdash.yml= sets =cancel-in-progress: true= per ref, so a later push
cancelled the earlier run. Five runs on 2026-10-06 were cancelled in a row.

Replace the =push= trigger with a two-hourly =schedule= at =30 */2 * * *=, offset
from Continuous Linux's =0 */2 * * *= so the two do not start together, and
keep =workflow_dispatch=. The deploy job has no push-only condition, so the
scheduled runs deploy.

The 17:12 run was cancelled by the 18:05 push. The schedule removes that race:
one run per two-hour window, and a manual dispatch can still force one.
