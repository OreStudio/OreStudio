#+title: How do I run the books commands from the shell?
#+description: Every command the books submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:books:

This file documents the books resource at the shell, one section per command. Every command is a subcommand of =books=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: A569318A-E78C-5EAB-B917-953A9D6F001E
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
books list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.books.list=.

#+name: books-list
#+begin_src ores-shell :tangle books-list.ores :exports none
books list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: E032009A-6D6D-5BAF-A90E-DB81F2788C25
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
books get <id>
#+end_example

It is addressed at =refdata.v1.books.get=.

#+name: books-get
#+begin_src ores-shell :tangle books-get.ores :exports none
books get 00000000-0000-0000-0000-000000000000
#+end_src

** =add=
:PROPERTIES:
:ID: 7E59DB28-7047-5A39-B814-73FF63418AB2
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
books add <id> <name> <description> <parent_portfolio_id> <owner_unit_id> <functional_currency> <gl_account_ref> <cost_center> <book_status> <regulatory_book_type> <is_sweepable> <rates_centre_code> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.books.put=.

#+name: books-add
#+begin_src ores-shell :tangle books-add.ores :exports none
books add 00000000-0000-0000-0000-000000000000 __none__ __none__ 00000000-0000-0000-0000-000000000000 __none__ __none__ __none__ __none__ __none__ __none__ false __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 92EB1F47-818C-563B-A432-8A848FD7DE2D
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
books set <id> <name> <description> <parent_portfolio_id> <owner_unit_id> <functional_currency> <gl_account_ref> <cost_center> <book_status> <regulatory_book_type> <is_sweepable> <rates_centre_code> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.books.put=.
