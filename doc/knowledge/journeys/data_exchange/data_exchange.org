* Summary

A person imports data so a party, an environment or a single dataset can be
built, repaired, promoted or reproduced. A person exports data so it can be
shared with support, archived, or moved to another installation. The journeys
here name what the person is trying to do, what the shell and the web UI offer
today, and what they leave undone.

The entry points are the =ore= command family, =marketdata import= and
=marketdata export= in the shell, and the workflow instance screens in the web
UI. There is no import or export screen in the web UI.

* Detail

The journeys read together as three questions. The first is scope: a whole
environment, one party, one dataset, or the data of one party versus the tenant.
The second is ownership: conventions belong to refdata, trades to trading, quotes
to marketdata, and a run binds documents from three services. The third is the
aftermath: what the person can read after a failure, and what the server can undo.

No current entry point offers all three. The =ore= verbs move one component at a
time. The run import is the one that carries several configuration documents, and
its undo covers the curves, the market data, the pricing engines and the run
document but not the conventions. The conventions document itself is still one
message with 27 typed arrays.
