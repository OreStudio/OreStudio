After running compass bearings, load the doc-review-ste100 skill at the start of every session, before producing any user-facing prose output. This ensures all human-readable communication follows ASD-STE100 Simplified Technical English conventions. Do not apply STE100 to structured output: JSON, diffs, code, commit messages, or command output.

*Why:* STE100 reduces ambiguity in inter-agent and human-agent communication, following the same discipline that makes aircraft maintenance instructions safe for non-native readers.

*How to apply:* At session start, after running compass bearings, invoke the doc-review-ste100 skill via the Skill tool before producing any user-facing output. All subsequent agent output must follow STE100 rules: one meaning per word, active voice, simple tense, one instruction per sentence, ≤25 words per sentence.
