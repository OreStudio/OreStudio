* Goal

A response may name a body source that has to wait for its next piece without stopping the
connection's thread, so the change stream of increment B3 has a form to arrive in.

* Acceptance

- [X] A response may name an awaitable body source, and the session writes it.
- [X] A source that states its length is answered with =Content-Length=; one that does not is chunked.
- [X] A waiting source does not stop another connection being served on the same thread.
- [X] A source that fails mid-body closes the connection rather than short-changing the client.

* Plan

Two sources, one write loop. The synchronous =body_source= stays as it is, because a file
always has more to give and the extra suspension would buy nothing. =awaitable_body_source=
is the same contract with a =co_await= on the read. The loop takes the next piece from
whichever one the response names, so the framing, the drain and the failure handling are
written once.

The alternative was a second write loop for the awaitable case. It reads as the simpler diff
and is the worse code: two copies of the chunked framing, the need_buffer handling and the
short-body rule, one of which a change would forget.

* Notes

- The isolation case runs the server with one worker thread and holds one response open for
  400 ms. A synchronous read would have held that thread and the prompt request would have
  waited; it answers in tens of milliseconds instead. That is the whole claim, and it is why
  the case fixes the thread count rather than trusting a default.
- The first version of the case measured nothing, because the waiting source returned its
  piece before waiting and a fixed =Content-Length= let the client finish early. The source
  now waits before every piece, which is also the truthful shape for an event stream.
- The failure case asserts on the client's side only. The session cannot send a status once
  the headers are out, so what a case can prove is that the client does not receive the
  length the headers promised.

* Result

=awaitable_body_source= exists, the write loop serves it beside the synchronous one, and four
cases pin the behaviour that matters: the length, the chunked framing, the thread that is not
held, and the connection that closes instead of lying about its length.
