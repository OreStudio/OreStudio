{{! ============================================================
    Template : cpp_field_group.hpp.mustache
    Purpose  : Generates a plain C++ struct for a named group of
               related fields.

    WHEN TO USE
    -----------
    Use this template when you need a named block of related fields
    that is its own type: no new DB table, no repository layer, and no
    change to the wire format.

    The first use case is a column block composed into an entity. The
    group is its own struct with a literal of its own names, so a reader
    states what belongs together, and the entity's mapper names every
    column through the member that carries it.

    C1202 has two paths, and a group meets only the first. A plain
    nested member costs the parent one name, so a group declared as a
    plain member lowers the parent's literal: that is the remedy for one
    literal that is too wide on its own. rfl::Flatten instead hoists the
    group's names into the parent's literal, recursively, so it keeps a
    shape and lowers nothing. Neither touches the second path,
    accumulation across a unit, which is decided by how many types the
    unit reflects and not by how they are declared. See the
    decomposition section of
    doc/knowledge/architecture/data_oriented_design.org.

    The wire is a separate question. The generated JSON writer is a
    bare rfl::json::write, so a plain nested member appears as a nested
    object on the wire. That is a known defect against the atomised
    shape, not something a group sets out to do.

    The second use case is a document-only struct: a shape the ORE
    schema states and no table holds, such as a bond's option block.
    It is not flattened into a parent.  It crosses the wire as its
    own JSON object, and the container above it holds it whole so
    that export re-emits what the document held.  A document-only
    struct has no DB table either, so the same rules apply: one
    model, one header, no repository.

    WHAT IS GENERATED
    -----------------
    One header file (.hpp) containing a single plain struct inside
    the declared C++ namespace.  No .cpp, no primary key, no audit
    columns (version / modified_by / recorded_at), no DB entity,
    no mapper, no SQL schema.

    MODEL TYPE
    ----------
    field_group  (org #+type: field_group)

    ADDRESS
    -------
    ores.cpp.field-group  — use via:
      codegen.sh generate --model path/to/foo_field_group.org \
             --address ores.cpp.field-group

    WHAT NOT TO USE IT FOR
    ----------------------
    * Do NOT use for structs that have their own DB table — use
      domain_entity instead.
    * Do NOT compose a group with rfl::Flatten when the group crosses
      the wire as its own object: flattening it would change the wire
      shape.  A group that is part of a document is written whole, as
      the bond container writes its parts.
    * Do NOT use for enums — use the enum model type.
    * Do NOT add a primary_key, natural_keys, or audit columns
      to the field_group model — they have no meaning here.

    PARENT STRUCT
    -------------
    The composing parent struct (e.g. trade) is hand-crafted; it
    is not generated.  It should:
      #include the generated sub-struct headers
      declare one member per group
      itself be marked final if appropriate
    ============================================================ }}
