* What

The test case "tick_clock hands the body the gap it waited"
(=projects/ores.analytics/quant/tests/tick_clock_tests.cpp:179=) fails on
main. It expects the first gap to be one full period, 0.001 s. Commit
=7484ed7f97= gave periodic arrival a random phase, drawn from a default seed,
so the first gap is 0.001 × 0.5928 = 0.00059284461651668. The unity build and
the non-unity build fail with the same value, so the build mode is not the
cause.

Fix the test or the design, not the tolerance. Either the test seeds the
process and expects the phased first gap, or the phase becomes explicit state
that the test sets to zero. The second fits the tick arrival analysis sent to
the tick arrival work: a stationary start is state that the caller gives, and
no default seed hides it.

* Why

=ores.analytics.quant.tests= is red on main, so the local check gate cannot go
green on any branch that builds C++. Each branch must document the failure
by hand until it is fixed.
