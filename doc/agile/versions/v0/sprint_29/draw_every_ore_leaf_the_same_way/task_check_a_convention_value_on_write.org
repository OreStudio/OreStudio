* Goal

Refuse a convention value that lies outside the value set of the term it holds, in the database, so the shell, the screens and a data quality publish all get the same answer, and a value set means the same thing for a convention term as for a pricing parameter.

* Acceptance

- A convention write whose value is outside its term's set is refused, and the refusal names the value, the term and the set.
- The rule a value meets is one function, which the pricing parameter trigger and the convention trigger both call.
- Every seeded convention meets its sets, measured before the trigger is on, so the seed still loads and a tenant still provisions.
- The triggers are generated from the same terms as the term seed, so a term added to the map is checked without an edit.

* Plan

The owner chose the database on 2026-10-26, as pricing does, over the BFF the engine run settings use.

1. Measure every seeded convention against its term's set with the rule pricing uses, before any trigger exists.
2. Fix what fails in the data, not in the rule.
3. Move pricing's rule, unchanged, into =ores_reporting_value_in_set_fn=, and call it from pricing's trigger.
4. Generate a trigger on every convention entity that holds a term, beside the term seed.
5. Test the trigger in pgTAP, and provision a tenant through it.

* Notes

- *Two ISO 4217 fund codes were missing from the currencies.* MXV, the Mexican unidad de inversion, and CLF, the Chilean unidad de fomento, are ISO codes the seeded conventions use; they are added to the ISO currency seed as synthetic emerging currencies, with the minor units ISO states.
- *The business day convention catalogue holds the full names only.* The ORE parser also reads MF or F, but the mapper stores the full name, so every seeded value meets the catalogue; a write of MF is refused.
- *The calendar and the index stay text*, as the value set task recorded, so the trigger admits any calendar.

* Result

- A trigger on each of the 28 convention entities refuses a value outside its term's set. The message names the value, the term and the set: =Invalid value Fortnightly for Swap.FixedFrequency: the value is not in set ...=.
- =ores_reporting_value_in_set_fn= holds the rule. The pricing parameter trigger and the convention trigger both call it.
- =generate_convention_kind_terms.py= writes the triggers and their drop from the same terms as the term seed. Its gate compares all three files.
- The ISO currency seed now holds MXV and CLF, so every seeded convention meets its sets. The gate provisioned acme_corporation through the trigger without an error.
- The pgTAP test =refdata_convention_terms_validate_test.sql= accepts a good swap and refuses a bad frequency, a bad business day convention and a bad day counter.
- The gate failed on ticks-smoke: the Bloomberg adapter rejected 20 of 86 demanded IDs. This branch changes no market data. Commit =b56a374918= on main added about 60 Bloomberg curve instruments the simulated adapter does not serve.
