#+title: The shell history command needs a clear error for a stale key
#+description: Ten entities now read their generic history by the row's own id: party and counterparty contacts, party, counterparty and netting set identifiers, business units, portfolios, portfolio rights, CSA eligible currencies and run grants. A caller that passes the old declared key, such as the shell history command with a contact type, gets the dispatcher's failure text, bad lexical cast, which names neither the entity nor the key it expected. The provider should refuse a value that is not a uuid with a message that names the entity and says the history is read by the row id, and the shell command should say which id to pass.
