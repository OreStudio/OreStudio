Fix at root cause the defects the ores.iam component clean-up recorded and deliberately left open: the assets publish-from-DQ function selecting columns its table does not have, the workflow engine attributing records to its service account instead of the caller behind the bearer token, and the tenant provisioning command that cannot answer inside the client's request timeout. * Acceptance

- The assets publish-from-DQ function reads the columns ores_assets_images_tbl has, and a live publish inserts instead of aborting
- The workflow engine records the caller's username from the bearer token on the instance and its steps, and falls back to the service account only when no caller is present

* Plan

The three defects are independent, so they are fixed smallest first, each
verified against the real artefact before the next starts.

1. *assets.* The function names columns its table does not have. Read the
   table, correct the names, and call the function against the live schema --
   once to insert and once to update -- because the second call is what
   exercises the upsert the function claims to implement.
2. *The request timeout.* Stated in the operation model, not the client: how
   long an operation takes is a fact about the operation. The codegen facet
   gains `:request_timeout_seconds:`, refused unless it is a positive whole
   number of seconds on a message that requires a session, and the profile
   operation declares 1800 seconds -- above the handler's own 1500-second
   wait on the base bundle.
3. *Attribution.* The rule that reads the actor out of a message belongs
   neither to the engine (which needs a database and a connection to exist)
   nor to each publisher. It moves to `actor_from_message()` in the workflow
   core, the nats layer gains one reading and one forwarding helper, the
   engine takes the verifier the service runner already builds, and every
   publisher of a start request forwards its caller.
4. *Captures.* The five whose defects have closed are deleted and the
   backlog index regenerated, because a capture that describes finished work
   is work a reader would otherwise start.
5. *Gates.* Build, the full suite, component drift, lint and the doc check,
   then the verification runs on a live fleet.
