* Goal

The series page asks for the latest 500 observations. A synthetic tick every two seconds fills that in about seventeen minutes, so the chart shows a narrow slice. The observation list filter has no date range today. Add an observed-since filter to the server, send it from the BFF, and offer a window on the page, such as an hour, a day, a month, a year and all, with the count cap kept as the limit on size.

* Plan

The window is a name in the browser and an instant on the wire. Three pieces,
one decision each.

** The server

=observation_datetime= is marked =:filterable: true= in the observation model,
which the repository facet reads to give the filter record an =equals=, a
=one_of=, a =_from= and a =_to= member, and to build the condition that
narrows the read. The =_from= bound is the observed-since time the task asks
for. The condition is built by the template from the same member list the
protocol record is built from, so no second list can disagree. Nothing is
hand-written: the five generated files under =ores.marketdata= are the whole
change on this side. This is the shape =trade_bookings_filter= already carries
for =execution_timestamp=.

** The BFF

The route takes a =window= name, one of =hour=, =day=, =month=, =year= and
=all=, and turns it into the earliest instant the read takes. The rule is a
pure function in =series-window.ts=, tested on its own, and the clock it counts
back from is the deployment's, not the browser's: the observations were stamped
against that clock. =all= names no instant, and an all-null filter record reads
as no condition, so one request shape covers both cases. The count cap is
untouched: a window wider than the cap returns that window's newest
observations.

** The page

The window is held in the address as =window=, beside =uri= and =series=, so a
link reopens the same view. A bar of five pressed buttons offers the windows,
the sentence beside it says which window is shown, and an empty answer inside a
window says so rather than claiming the series holds nothing. The count the page
reads stays =DEFAULT_OBSERVATIONS=.

** The tests

One C++ test writes observations an hour apart and asserts that the filter
keeps the ones at or after the bound and that the count agrees. A second asserts
that a bound the server cannot read is refused. The BFF test asserts the
observed-since instant the route sends for a named window, and that =all= sends
none. The page's own rules, the window an address names and the window bar's
list, are pure and tested beside the page.

* Notes

** 2026-10-18 — the filter member the task asks for is a model flag

=observation_datetime= now carries =:filterable: true=. The model's filter
facet then gives the record an =equals=, a =one_of=, a =_from= and a =_to=
member and builds the condition that narrows the read, so no C++ is
hand-written for the task. The cost of the flag is three members the page does
not use: the relation's =one_of= members the read already carried take the same
shape, and trading's =execution_timestamp_from= is the same member for the same
reason.

** 2026-10-18 — the window is a name in the browser and an instant on the wire

The page sends =?window=hour=, the route turns it into the earliest instant the
read takes, and the server compares =observation_datetime_from= against it. The
rule lives in =series-window.ts= beside the route, tested on its own, because
the deployment's clock is the one the observations were stamped against: the
audit, logs and grid series windows are computed in the BFF for that reason.
=all= sends no bound at all, and the route sends the filter record with every
member null in that case, so one request shape covers both.

** 2026-10-18 — the count stays the cap

The page still reads =DEFAULT_OBSERVATIONS= (500), and the window only narrows
what those 500 are drawn from. A window wider than the cap therefore returns
that window's newest observations, and the sentence beside the bar says which
window is drawn while the count sentence says how many of how many.

** 2026-10-18 — two corrections to the first draft of the observed-since test

The first bound sat ninety minutes past the first of three rows an hour apart,
so only one row qualified and the assertion failed. The second draft compared
each returned instant against the instant the test wrote, which fails on a
fraction of a second: the column keeps microseconds and =system_clock::now=
does not. The test now asserts the values the filter keeps, in no order.
