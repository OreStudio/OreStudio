* Notes

Survey, 2026-09-25, at trunk `5de59e3fb8`, by an agent that did not write
the component.

- Keep the component. The retirement hypothesis fails, because the call
  site is live. `ores.http` builds the service at `application.cpp:86` and
  calls `lookup` at `iam_routes.cpp:502` inside the login handler, and
  `ores.http.server` is enabled in the service registry. That is the only
  production call site, reached through two includes.
- The use is inert. The geo table is written only by the dq ip2country
  publish path over NATS. The standalone import script omits the `NOT NULL`
  `tenant_id`, so it cannot succeed as written. A database recreated from
  scratch therefore returns `address_not_found` for every lookup and
  `country_code` is always empty.
- Scale. 5 production C++ files in 4 headers and 1 source, with 2 files
  under `tests/`. 5 test cases and 5 assertions. The suite passes, but see
  V02.

Work items, in the order they land.

1. Rewrite the overview. Replace the MaxMind, city and coordinate claims
   with ip2country and `ores_geo_ip2country_tbl`, state that the service is
   country-only, and name `ores.http` as the consumer rather than
   `ores.iam`.
2. Fix the other stale ground truth. `projects/modeling/system_model_foundation.org`
   and `ores.utility.hpp` both repeat the stale claims. The audit's step 4
   applies: the documents lead, so a discrepancy in them is a document bug.
3. Drop the unused PUBLIC `ores.geo.lib` link from
   `projects/ores.iam/core/src/CMakeLists.txt`. That component contains no
   geo symbol.
4. Fill `See also` with id links.
5. Rewrite the tests so they can fail. Seed a known range in
   `ores_geo_ip2country_tbl`, assert a literal country code for a public
   address, add an `invalid_address` case, and drop the two cases that
   assert on a plain struct.
6. Decide the data path. Either wire the dq publish function into the
   recreate flow, beside the fpml and iso equivalents, or record the
   emptiness as accepted in the overview and in the service. Leaving it
   undocumented is the worst option.
7. Hygiene. Drop the unused `<optional>` include, drop or use
   `database_not_available`, and correct the script name in the header
   comment.
8. Decide the two umbrella headers that nobody includes. Keep them with
   corrected text, or delete them.
