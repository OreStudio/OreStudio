* Goal

Ticket type: grilling (human in the loop).

The booking screen captures the NPV at the time of booking. No pricing layer
exists, so the number has to come from somewhere else. The candidate is a
valuation run dispatched from the screen, whose result carries the NPV and
the market data snapshot it was struck against.

Decide the request path, what the booker sees while the run is out, what
happens when it fails or the result goes stale, and what provenance is
stored beside the number.

The user left this one open: they were not sure of the best route, and
suggested the user might ask for the valuation.
