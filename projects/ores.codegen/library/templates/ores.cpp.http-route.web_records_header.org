The header of one resource's record routes. The screens name a reference data
resource by a key in the address, such as =/api/refdata/currency-memberships=,
and read it in the shapes the BFF answered with. This unit answers those
addresses on the C++ server, so the screens keep working when the BFF goes.

The unit renders only for a model that states =#+web_resource:=. The output
path names ={web_entity}=, which resolves only for such a model, so every
other entity renders nothing here.

* Mustache incantations

The template reads ={{web_records}}=, which =entity_web_records_plan= builds
from the model. ={{unit}}= is the class stem, =<entity>_web=. ={{base}}= is the
resource's address, and ={{single_key}}= and ={{list_by}}= say whether the
resource is read by one key and by a parent, so the header declares only the
handlers the unit has. A resource whose key read is hand-written has no key
handler here, and its by handler reads a list-by request or a parent filter.
