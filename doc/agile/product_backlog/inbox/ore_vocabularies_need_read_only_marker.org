#+title: The ORE vocabularies need a read-only marker
#+description: Day counters, calendar names, floating index types, leg types and business day conventions hold spellings ORE must read exactly, but nothing marks them read-only.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Calendars mark the rows ORE defines with =is_editable=. The five code lists of ORE spellings have no such marker, so the server accepts a change or a removal that would make an ORE document invalid. The web screen keeps a list of the five and refuses to edit them itself. Model the marker on these lists, enforce it on write, and let the screen read it instead of keeping its own list.

* Why

A rule that lives only in one client is a rule every other writer ignores.
