#+title: How do I run the trade_types commands from the shell?
#+description: Every command the trade_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:trade_types:

This file documents the trade_types resource at the shell, one section per command. Every command is a subcommand of =trade_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: D2200EE7-2AB8-5FF2-BEFD-4FF1FA180AAB
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
trade_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =trading.v1.trade_types.list=.

#+name: trade_types-list
#+begin_src ores-shell :tangle trade_types-list.ores :exports none
trade_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 5FA2DADE-9155-57F4-8A74-B759B4677058
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
trade_types get <code>
#+end_example

It is addressed at =trading.v1.trade_types.get=.

#+name: trade_types-get
#+begin_src ores-shell :tangle trade_types-get.ores :exports none
trade_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 59F2C0C5-0DE7-562B-AD58-657E5B8CD056
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
trade_types add <code> <description> <product_type> <has_options> <has_extension> <reason> <commentary>
#+end_example

It is addressed at =trading.v1.trade_types.put=.

#+name: trade_types-add
#+begin_src ores-shell :tangle trade_types-add.ores :exports none
trade_types add __none__ __none__ __none__ false false system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 427A1211-8CB5-5B76-972D-0F3A34DD6E20
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
trade_types set <code> <description> <product_type> <has_options> <has_extension> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =trading.v1.trade_types.put=.

#+name: trade_types-set
#+begin_src ores-shell :tangle trade_types-set.ores :exports none
trade_types set __none__ __none__ __none__ false false system.new_record generated_script
#+end_src
