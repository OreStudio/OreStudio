* Acceptance

- additional_results.csv is read into rows keyed by result, file and line, with the trade, the result name, its type, its text and its figure when it is a number.
- marketObjects.csv and riskFactors.csv are read into rows, one for each object or factor the portfolio depends on.
- calibration.csv, the calibrated cross-asset model as one XML document, is stored as a row that names the model, and the decision on parsing it further is recorded.
- The generator's out-of-scope list no longer names these four.

* Plan

Six outputs state a name and a text rather than a figure: additional_results,
marketObjects, riskFactors, swap_indices, underlying_indices and the calibrated
model. One reader serves them from a table of the headings each states its
subject, name, type and value under, and one reporting table holds them, keyed
like every other run row by result, file and line. The calibrated model is the
whole body after its heading, because the engine writes the XML unquoted.
counterparties, netting_sets and trade_types, the other portfolio details,
state a count and read as metrics. A run whose output states only text values
completes, which resolves the capture that a report pricing nothing fails.

The calibrated model is stored as its XML, one row. Parsing it into the
project's model configuration is a model-import concern, not a run result.

* Result

The outputs that state text rather than figures are read and stored in
=ores_reporting_report_text_values_tbl=: additional results, the portfolio
details lists and the calibrated model as its XML. The other portfolio details
lists state counts and are stored as metrics. A portfolio details run, which
failed for stating no figure, now completes and stores what it found; the capture
that recorded the failure is removed. The generator's out-of-scope list no longer
names these outputs. Building it exposed a codegen defect, a codec header missing
for a member named domain::x, which is fixed with a test.
