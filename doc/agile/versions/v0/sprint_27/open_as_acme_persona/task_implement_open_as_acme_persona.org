* Acceptance

- compass open-as with a person's name opens an isolated Chrome on the web login with that user's credentials filled in.
- compass open-as can also choose a person by job title and location, or by role and location, with London as the default location.
- The command leaves the developer's own Chrome profiles untouched and is documented as a recipe.

* Plan

1. Add =compass open-as= as a compass pillar in =compass_open_as.py=, with three ways to choose a person: =name=, =title= and =role=. Title and role take an office, London by default.
2. Hard code what Acme fixes: the tenant hostname, the shared password, the office aliases, the roles and the job titles. Read the staff from the seeder's =accounts.json=.
3. Give each person a Chrome data directory under the cache folder, so the developer's own profiles never change.
4. Fill the sign-in form through the DevTools protocol with a small standard-library socket client, so compass gains no dependency.
5. Unit-test the choice and the frame encoding. Check the fill and the sign-in end to end in headless Chrome against the running web service.
6. Write a recipe and link it from the ops index.
