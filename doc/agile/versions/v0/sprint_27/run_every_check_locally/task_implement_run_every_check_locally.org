* Goal

One local command replaces the GitHub pull-request wait. The command classifies the change against a documented decision tree, runs only the checks that class needs, and writes one report that names each failing check and the fix. A docs-only change runs no C++ build and no C++ test.

* Acceptance

- One command classifies the change and runs every check the change needs.
- The report names each failing check, the evidence, and the command that fixes it.
- The decision tree maps each change class to its checks and lives in the repo.
- A documents-only change runs no C++ build and no C++ test.

* Plan

=build/scripts/local_checks.py= holds four things: the *catalogue* of checks
(id, title, argv, classes, optional path narrowing, phase, fix hint, working
directory, timeout); the *decision tree*, a table of change class to path
globs; =classify=/=select_checks=, both pure functions of the changed paths;
and the *executor*, which runs the writers first, then the fast reads in
parallel, then the heavy tier, and writes =build/output/local_checks/report.md=.
=compass check= hands its arguments to the script, so the catalogue is
reachable with or without compass.

Decisions:

- *The tree is data, not a chain of conditionals.* =--list= prints it and the
  suite pins it, so a check cannot be added without a class and a phase.
- *A path no rule claims selects every check.* A change the table cannot
  classify is one it cannot vouch for.
- *A model or template change does not by itself force a build.* The
  regeneration writes the generated C++ into the tree, so that file appears in
  the diff and the =cpp= class does the build. A missing regeneration fails
  =component-drift= first, which is the cheaper and more precise verdict.
- *The change is measured from the merge base with =origin/main=*, including
  uncommitted and untracked files. Another author's merge onto trunk must not
  read as this branch's change, and the runner has to be useful mid-work.
- *The tangle checks carry the CI path filters*, so a tangle runs only when a
  file it tangles from changed, not on every model edit.
- *The retired half of the gate is deleted, not kept.* The twelve
  =pull_request= triggers went first, on their own task; the orphaned
  classifier at =projects/ores.codegen/src/codegen/change_classification.py=
  (no caller since =pr.yml= was deleted) goes with this one, superseded by the
  new tree.
- *=compass pr checks= treats "no checks reported" as green.* With no workflow
  triggering on a pull request, the old guard would have refused every merge.

* Notes

* Result

=compass check= is the pull-request gate. It classifies the branch diff
against the decision tree in =build/scripts/local_checks.py=, runs the checks
the matching classes need, and writes =build/output/local_checks/report.md=:
a verdict, a *Fix these first* section naming each failure with the command
that reproduces it, the command that fixes it and the tail of its log, then
the full table and the reason each class was selected. The catalogue holds 38
checks over 10 classes and 3 phases.

Verified on this branch at =c35caff642=: 38 of 38 checks passed in 3920s,
with a clean tree afterwards, so the regenerating checks left nothing behind.
The gate is the first thing that ran the new =no-pr-triggers= guard, the
=format= check and the =component-drift= family in one pass.

Three defects surfaced by running it, all fixed here:

- *A workflow grew the =pull_request= trigger back.* =entity-writes.yml= on
  =feature/book-trade-through-repositories= declares it, and nothing read the
  workflow files. =build/scripts/check_no_pr_triggers.py= now fails on the
  plain trigger, ignores the =pull_request_review= events the =@claude= review
  uses, and runs under the =ci= class.
- *The drift checks write what the parallel checks read.* =component-drift
  --all= regenerates every artefact in place, and it was rewriting generated
  C++ while =format= read it, so =format= reported unformatted headers on a
  branch that touches no C++. The regenerating and comparing checks now run in
  the serial prepare phase.
- *The tangles write outside the trees their checks verified.* =tangle-http=
  emits ten =.hurl= files under =projects/ores.http/scripts/library= that main
  never committed, and the check only looked at =doc/recipes/http=. Both tangle
  checks now verify every tree they write, untracked files included.

The gate also found three pre-existing drifts on main, and cleared them in its
own commit: the =ores.synthetic= CMake file list stale since #2708, the
physical-space inventories stale since the recent template edits, and the
missing =.hurl= files.

Out of scope, recorded for the next pass: the workflow files are still 12
near-identical copies of the same drift gates, and nothing checks that every
check in the catalogue has a counterpart in the retired workflow set.
