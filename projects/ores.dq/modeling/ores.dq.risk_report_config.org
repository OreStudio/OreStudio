* Notes

Bound to [[id:5D3A6D13-73E0-41A5-9E08-0C8C11BD609E][Artefact staging only]] (alongside its shape profile): this
artefact type's own row in =ores_dq_artefact_types_tbl=
(=risk_report_configs=) publishes to =target_table:
reporting_risk_report_configs_tbl= -- the authoritative production table is
owned by =ores.reporting=, not =ores.dq=. This model exists to describe the
DQ import/staging shape only; an =ores.dq=-owned main table would be a
wrongly-owned duplicate.

The report's own scope is not a column here. A seeded configuration is always
scoped to the target party's root portfolio, the one whose parent is null,
and the publication resolves it. A report that has no root portfolio to
scope to is skipped by the publication rather than given an invented one.

No UI: this is a DQ-side staging view onto data that isn't authoritative
here (see above) -- an editable window in =ores.dq= would be a second,
confusing, edit-capable copy of import data whose real home is
=ores.reporting=.
