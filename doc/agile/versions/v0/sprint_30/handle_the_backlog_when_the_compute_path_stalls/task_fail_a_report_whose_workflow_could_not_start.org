* Result

The trigger wraps the dispatch of a run's workflow. A dispatch that throws now
marks the instance failed with the reason it carries, and answers the caller
with that reason, so a run that never began cannot keep holding its
definition's in-flight slot. The instance is still recorded and its id still
returned, so a caller learns which run it asked for.

The review found the first version of this writing a change reason that is not
seeded, which the instance trigger rejects: the save would have thrown, been
swallowed, and left the run pending exactly as before. The seed now carries
=system.dispatch_failed=, the handler names it, and an answer that could not
mark the run failed says so instead of implying the run is finished.

PR #4891. =compass check --exclude-heavy=: 35/35 passed and
=ores.reporting.core.lib= builds clean. No test drives a failed dispatch.

Left open: nothing retries a run whose dispatch failed, and the run's failure
is only visible to the caller and in the log, not on the run's card.
