* Plan

The topic already has its journey: Keep a holiday calendar right, written on
2026-10-04 in the existing form, with the calendar, its rules, exceptions,
events and business days, and the calendar type and diary entry type pickers.
So the task is not to write a journey but to judge the one that exists, step by
step, against the standard the second story settled and the screen the web
draws today: which steps the standard record screen with parts already covers,
which are a kind's own action, which are a view the standard has no rule for,
and whether any step keeps state across a reply and so needs a workflow. The
judgement goes on the journey page, where the prototype reads it, with the
missing Prototype section the document contract requires and a link from each
gap in What is missing to the capture that carries it. The classification
lists the pickers offer are another journey already, in the Classifications
group, and the group page says so.

* Result

The calendars topic has one journey of its own, Keep a holiday calendar right,
and shares Maintain a classification list for its two pickers. Each of its
twelve steps is judged on the journey page: nine are the standard record
screen with parts, two are a kind's own actions (Derive a calendar and Rebuild
business days), one is a missing server operation (the ORE export), and none
keeps state across a reply, so no workflow is needed and the Workflows menu
stays empty for calendars. The Business days tab is a derived view no rule of
the standard draws yet; the prototype defines it and the standard gains the
rule. Each gap in What is missing links to its capture, with an eighth added
for the unenforced read-only calendar. The journey page gained the Prototype
section the contract requires, pointing at the prototype task. The owner's
sign off of the journey is the gate before the prototype starts.
