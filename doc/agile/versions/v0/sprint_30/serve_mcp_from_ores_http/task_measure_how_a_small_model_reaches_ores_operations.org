* Goal

Write a set of real requests a person would give an agent, each with the operation that answers it. Run each with a small local model through browsing and through search, and record how often it reaches the right operation and in how many steps. The result decides whether the catalogue's areas, entities and summaries need work, and is compared with what ores.agent's evaluations measured.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

- Twenty requests a person would give, each answered by one operation a
  read-only grant reaches, in =projects/ores.http/evals/catalogue_reach/requests.json=;
  every expected operation was checked reachable through =call_operation=
  before the run.
- =run.py= drives the model through the running =/mcp= with a read-only agent
  grant it creates and revokes. Each request runs browsing (=list_areas=,
  =list_entities=, =list_operations=) and searching (=find_operations=), each
  beside =call_operation=, at most eight steps. A request is reached when the
  model calls the expected operation.
- The model is ores.agent's pinned LFM3-1.7B Q4_0 on llama.cpp b12172 with
  CUDA on an RTX 2080 Ti, at temperature 0; ores.agent serves it at 0.1.

* Result

The request set and its runner are in the repository and rerun against any
served model. LFM3-1.7B reached 10 of 20 operations by browsing, in 4.7 steps
when it did, and 13 of 20 by search, in 2.0 steps; counting a duplicate read
that also answers the request, 12 and 14. Every miss is named in the evidence
file. Browsing failed most by answering after =list_areas= without walking on,
by wandering among entities a screen route splits, and by areas whose purpose
misled; search failed by dropping a word of the request. The result says the
catalogue's entities and purposes need work, which
[[id:75C3EE23-A43D-4621-80F6-36B25C9D2CDE][Make ORE's catalogue easier for a small model to walk]] takes up. ores.agent's
live evaluation passed 26 of 36 cases, but through tools written per
capability, so it measures a different task and is not compared here.

Checking the expected operations found =list_images= failing for every caller;
see [[id:E4FA5F3A-AEF6-4DAD-95C8-52739440CAB9][List images without exceeding the NATS payload]].
