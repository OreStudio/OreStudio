This page documents a [[id:F44766FA-1E9C-416F-849A-E131101B2ECA][user journey]]: A person watches the quotes each vendor sends as they tick, for any asset class, on the feeds their party may watch for display; the system tenant watches every vendor.

A user journey describes what one person is trying to do, before anything is
built. It is a design document that outlives any sprint, so it names the
screens, the entity fields each screen shows, and the operations and messages
each step needs.

* Goal

"I want to see what each vendor is quoting right now, as it ticks, whatever the
asset class." The journey is done when the person has seen the quotes they came
for and leaves the screen. Nothing is changed and nothing is decided.

* Actor and trigger

The actor is anyone who watches the market: a trader, a quant, sales, or
operations checking that a feed is alive. In the system tenant the actor is the
person who runs the installation. The trigger is a question about the market as
the vendors send it: is this feed ticking, what does Bloomberg quote for this
series, how fast is it moving. The journey starts on the quotes screen and ends
when the person leaves it.

The view is the market as the vendors quote it, not the data a party publishes.
It shows raw vendor quotes, and so it shows the same thing to every party that
may watch a feed: two parties with the same routes and subscriptions see the
same rows. A party sees only the vendors it subscribes to with the display right,
through the feed its route picks, because vendor streams are paid for. The system
tenant sees every feed of the catalogue, routed or not.

The view is not specific to an asset class. Every quote is a series, a point in
it and a value, so FX spot, IR pillars and volatility quotes are rows of one
table. A layout made for one class, such as the FX montage, is a later lens over
the same rows.

* Steps

1. *Open the quotes.* The person opens *Market data*, then *Quotes*. The system
   asks which feeds the session may watch for display, and lists them as the
   sources on the left: each vendor once, with a dot and the age of its last
   tick, and /All vendors/ at the top. A party with no subscription sees an empty
   list and a line that says why.
2. *Choose a source.* The person picks one vendor, or /All vendors/. The system
   watches the live ticks of the chosen feeds and fills the table: for one
   vendor, one row for each datum it quotes, with the value, the change from the
   previous tick, the time and the age; for all vendors, one row for each
   vendor's quote of each datum, with a vendor column, so the vendors' GBP/USD
   sit together. A cell updates in place when it ticks again, and briefly marks
   the change.
3. *Lay it out.* The person switches between two layouts of the same rows:
   every datum, or grouped by series, a series opening into its points.
4. *Narrow it.* The person narrows by asset class, from the asset class codes
   table, or by instrument type within it, or types part of a series to find it.
   The screen filters the rows it holds, with no call. Narrowing to one series is
   the exception: the system then asks the broker for that series alone.
5. *Compare the vendors on one datum.* The person picks a row. The /All quotes/
   panel lists every vendor the session may watch that quotes the datum: its
   value, its distance to the mid, the change, the time and the age, then the mid
   and the spread. Below, each vendor's last hour is drawn: one history read for
   each vendor, extended with each live tick. The rows above keep ticking.
6. *Notice a silent feed.* A source whose last tick grows old turns its dot
   amber in the list, once it has ticked, and its rows fade. The person sees that
   a vendor stopped without leaving the screen.
7. *Pause.* The person pauses the view to read it. The screen stops updating the
   values and keeps counting the ages, and resumes from the newest values. No
   call is made.

When a route or a subscription of the party changes while the screen is open, the
system asks again which feeds the session may watch: a vendor that is no longer
allowed leaves the list and its rows go, and a new one appears.

The journey carries no server state. Every step is a read or a watch.

The instrument type, the series and the point of a row come from the tick's
oresmd URI, read by the codec; the schema the client needs to split it is
=describe_oresmd_schema=.

* Operations and messages

#+ATTR_HTML: :class hug-leading
| Step | Operation | Subject | Status |
|------+-----------+---------+--------|
| Open the quotes | Ask which feeds the session may watch | =marketdata.v1.ops.list_watchable_feeds= | exists |
| Open the quotes | Read the feeds' names | =marketdata.v1.feeds.list= | exists |
| Choose a source | Watch a feed's ticks | =marketdata.v1.ops.market_tick.<provider>.<feed>.>= | exists |
| Choose a source | Carry the watched ticks to the browser | none | missing |
| Choose a source | Split a URI into its type, series and point | =marketdata.v1.ops.describe_oresmd_schema= | exists |
| Narrow it | Watch one series | =marketdata.v1.ops.market_tick.<provider>.<feed>.<type>.<series>.*= | exists |
| Compare the vendors on one datum | Read its recent ticks, for each vendor | =marketdata.v1.ops.get_provider_ticks= | exists |
| A route or subscription changes | Learn of the change | =marketdata.v1.events.routes.>=, =marketdata.v1.events.subscriptions.>= | exists |

Switching the layout, narrowing by class or text and pausing are done on the
screen and need no operation. The asset class of a row is the code the asset
class catalogue maps its oresmd namespace onto (=ir= to =interest_rates=), and the
filter lists the asset class codes table (=refdata.v1.asset_class_codes.list=). The live subject and the two operations are in
[[id:4DB1ED0C-4BEA-4164-9129-5731AE559AE9][A source tick is published once and entitled when it is watched]].

* What is missing

- *A stream from the web server to the browser.* The broker checks no subject, so
  the browser never reaches it: the web server asks =list_watchable_feeds= for the
  session, watches those feed subjects, and streams the ticks to the page. No route
  does this today. The feed pages read a display tap that only the simulator
  publishes, and the task that builds the quotes view adds the route; the tap then
  goes.
- *A feed's age.* No read says when a feed last ticked. The screen measures it from
  the ticks it receives, so a feed that was silent before the screen opened shows
  no age until its first tick.
