* Acceptance

- Each table is generated from its owning model and its hand-written create and drop scripts are gone.
- The datasets that stage into them publish as before.

* Plan

1. Find each table's owning model. Five have one: =crm_topology_config=,
   =market_observation=, =gmm_component=, =ir_curve_generation_config= and
   =ir_curve_template_entry=. Two do not: =ip2country= publishes into a geo
   store that has no model, and =lei_bic= is GLEIF data whose owner the
   DQ-only task decides. Move those two to the tasks that own the question.
2. Write an =* Artefact columns= section on each owner from the current table,
   with its key and extra indexes, so the columns do not change.
3. The CRM table has six check constraints, and the artefact template had no
   way to state one. Add an expression table to the section, render it in
   the template, and refuse it on the junction and lookup archetypes, whose
   templates would drop it.
4. Regenerate, diff each table against the old one, and follow the table
   names through the hand-written SQL.
5. Recreate the database, run pgTAP, and provision Acme.

* Result

Five hand-written staging tables now come from their owning models: the CRM
topology (=ores_dq_crm_topology_configs_artefact_tbl=), the market data
observations (=ores_dq_market_observations_artefact_tbl=) and the three
synthetic feed tables (=ores_dq_gmm_components_artefact_tbl=,
=ores_dq_ir_curve_generation_configs_artefact_tbl= and
=ores_dq_ir_curve_template_entries_artefact_tbl=). Each owning model carries
an =* Artefact columns= section that states the staging shape, and the tables
keep their columns. The populates, publish functions, artefact types and drop
scripts follow the new names. The hand-written create scripts are gone; the
drop scripts stay hand-written, as for every artefact table.

The artefact template now renders check constraints from an expression table
in the section, so the CRM table keeps its six checks.

Two tables moved out of the task. =ip2country= needs a model of its geo store
first, which [[id:AE03BD95-AD8B-4FA9-9D56-230F4D26A7F2][Model the geo ip2country store]]
covers. =lei_bic= is GLEIF data like =lei_entities= and =lei_relationships=,
so [[id:6632B4F0-7005-4A55-BB69-96161952C2EF][Settle the owner of the DQ-only models]]
decides its owner with theirs.

Acceptance: the five tables are generated, and an Acme provision publishes
every dataset that stages into them with no failed step.
