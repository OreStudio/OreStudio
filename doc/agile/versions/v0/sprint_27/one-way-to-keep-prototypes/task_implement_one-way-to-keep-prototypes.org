* Acceptance

- Every prototype is a static page under =doc/prototypes/= and is listed in =doc/prototypes/index.org=.
- =doc/prototypes/index.org= states the one way to add a prototype.
- No prototype route or prototype source remains in =ores.web=.
- The site build publishes every prototype.
- =build/scripts/check_prototype_inventory.py= passes.

* Plan

1. Port the eleven React journey prototypes to self-contained static pages
   under =doc/prototypes/<name>/=. Plain HTML, CSS and JavaScript, mock data,
   variants and states carried on query parameters, as the existing
   prototypes do.
2. Make =doc/prototypes/index.org= the only inventory, listing all
   prototypes, and state the one way to add one there.
3. Point the journeys hub, =doc/knowledge/journeys/journeys.org=, at that
   inventory instead of describing a second way.
4. Publish each prototype with one =ores-deploy-web-app= call in
   =ores-build-site.el=.
5. Delete the React prototype tree and the =/prototype= route.
6. Add =build/scripts/check_prototype_inventory.py= and run it in the doc-lint
   workflow.

* Notes

Root cause: two prototype mechanisms grew and both were documented. The
static one was plain files under =doc/prototypes/=, listed in =index.org=. The
React one was routes in =ores.web=, listed only by the =/prototype= hub. The
React form needed the application's shell, build and types, so a prototype
could not open without the app and could not deploy with the documentation.

Fix: static pages are the one way. The eleven journey prototypes are ported to
self-contained pages under =doc/prototypes/=, =index.org= is the only
inventory, =ores-build-site.el= publishes each one, the React tree and route
are gone, and =check_prototype_inventory.py= fails CI when a prototype is
missing from the inventory or when a React prototype tree returns.

A verification agent wrote a Chromium profile and screenshots into a prototype
folder while checking its output. All such scratch was removed before the
commit, and no prototype folder carries a file whose name starts with =_=.
