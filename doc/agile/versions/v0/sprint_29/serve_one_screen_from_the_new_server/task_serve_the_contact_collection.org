* Notes

- The first attempt opted =auth_event= into the route facet and the build refused it: its
  derived protocol does not exist, because an operation model beside it owns the
  protocol. The facet now reads the same ownership rule the protocol facet reads, so it
  renders nothing for such an entity instead of a unit that includes a header nobody
  writes. The operation model's own route unit already answers the reads.
- The access and auth areas needed family rules for the generated collections beyond the
  four each served first. The rules exclude the four by name so the specific rules keep
  their precedence.
