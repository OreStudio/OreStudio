* What

=local_checks --exclude-heavy= failed three checks on =origin/main=, and none of
the three came from the branch that found it. Each was reproduced in a clean
worktree of =origin/main=. Two are fixed; the third is open.

1. =codegen-tests=: =projects/ores.codegen/tests/test_junction_events.py:50=
   asserts =subject_prefix = "testcomp.v1.test_links_events"= and the rendered
   =cpp_nats_changed_event.hpp.mustache= states none. It passed before #4447
   landed, and it fails on a clean =origin/main= worktree.
2. =component-drift=: the dry render would remove =find_package(msgpack-c)= and
   the =msgpack-c= link from
   =projects/ores.storage/service/src/CMakeLists.txt=. Commit a337e95529 added
   them by hand, "Link the MessagePack carrier the codec headers need", and
   =projects/ores.storage/modeling/= states no such dependency, so the tree does
   not match its models.
3. =er-diagram=: =projects/ores.sql/modeling/ores_schema.dq_staging.puml= is one
   line short. =ores_dq_report_definitions_artefact_tbl= gained =cut_kind_code=
   with the intraday reports (#4425), and the diagram was not redrawn.

* Why

A branch that touches a codegen template inherits the first two, and any branch
at all inherits the third, so a green gate is indistinguishable from a change
that broke a template or a diagram: the red lines are permanent until main is
fixed.

* How to check

#+begin_src text
$ python3 build/scripts/local_checks.py --exclude-heavy --only codegen-tests --only component-drift
$ projects/ores.codegen/venv/bin/python -m pytest projects/ores.codegen/tests/test_junction_events.py -q
#+end_src

* What to decide

The first is a template and a test that disagree; whichever of the two is right,
the other changes, and the events story owns both. The second is a model that
does not state a dependency its code needs: either the storage model gains it, so
the generator emits the lines, or the hand edit is removed and the build breaks,
so the model is the place to fix it. The third is a regeneration with its
diagram committed, and the reports story owns it.

* What is fixed, and what remains (2026-11-04)

Two of the three are fixed in #4444, because the branch could not go green until
they were:

- =codegen-tests=: the test now states the prefix the template emits.
  =event_prefix= became ={component}.v1.events.{plural}= when the events
  namespace landed in #4447, and =test_entity_events.py= was updated with it;
  =test_junction_events.py= still asserted the old =test_links_events= suffix. The
  test was the stale half.
- =er-diagram=: =ores_schema.dq_staging.puml= is regenerated, which adds
  =cut_kind_code= to =ores_dq_report_definitions_artefact_tbl=. Only the =.puml=
  is committed: the generator also redraws the =SVG= files, and on this machine
  the installed PlantUML is not the version that drew the committed ones, so a
  redraw changes every diagram's layout for no reason. The =.svg= files stay as
  they were until someone redraws the set with one version.

The storage model's missing =msgpack-c= dependency remains. It needs its owner:
either the model states the dependency so the generator emits the lines, or the
hand edit goes and the build breaks.
