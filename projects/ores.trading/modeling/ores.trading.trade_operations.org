A trade is an immutable [[id:4304A441-E532-45FB-837A-378F13693CAE][anchor]] with a [[id:40B71C6F-6E04-4679-BF7E-A2CE936C2515][booking]] and a [[id:85F71403-ACE4-4032-B3D4-EA5A61DC6812][state]], each in its own
table. Booking a trade writes all three, and a trade with an anchor but no
booking or state is not a trade anyone can read. So booking is one operation
rather than three entity writes: the three rows are written in one
transaction, and a failure in any of them writes none.

The anchor is written once. A second booking of the same trade id is
answered with a conflict, because the trade it names already exists, rather
than surfacing as a database key violation.

The handler stays hand-written beside this model, because an operation model
generates no service handler.
