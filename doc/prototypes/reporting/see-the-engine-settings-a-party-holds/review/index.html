See the engine settings a party holds prototype — Gemini reviews

Gemini drew one engine settings configuration again, as one page with a sidebar of categories, filter chips and a table of settings, each row with an inline control and a drawer for its documentation. It is kept beside the prototype as an alternative reading, not as the agreed design. Every value on it is mock data, and some of the settings on it do not exist in ORE. This is the actual generated file, kept as it was produced. It loads Tailwind, Lucide and Chart.js from public CDNs, so it needs the network to render, and it is a record rather than something to drive. The analysis of what to take from it, and what it leaves out, lives in the design note.

  • One configuration, as a table with drawers

    Five settings of the Fixings and cash flows group in a table. Each row has its control, its default and a drawer with the documentation and a schema panel: the ORE XML path, the release that introduced the setting, the release that removed it and the format. A Simple and Advanced switch hides the XML column, and two chips filter the rows.
