* Plan

Two components before this task -- inbox and synthetic -- were each found by its
own investigation, one full regeneration run apart. A third, scheduler, followed
the same way. Each discovery paid for a sweep of every component to find one
defect.

This task takes a census first. The census asks three questions of every
modeling directory:

- Does it declare itself a component in its =component_overview.org=?
- Does it carry a row in =component_catalogue.org=?
- Is its name in =COMPONENTS_UNDER_TEST=?

The answers separate three failure modes. A component can be registered but
stale, clean but unregistered, or unaddressable. The third mode is invisible to
every existing tool: the manifest reads components from the catalogue table, so
a component without a row cannot be regenerated even by name.

One change follows the census: add the missing row and registration, regenerate
the component, and let the gate confirm it. The census also settles the story's
acceptance criterion, so it needs no further task.

* Result

The census is done, and the gate is closed over the last three components.

The census found no fourth gap. Every modeling directory that carries entity,
operation or junction models either has a gate entry or is one of three aliases:
=trade= points at the trading modeling directory, =dq-cpp= at =dq=, and
=iam-cpp= at =iam=. Those directories are already covered under another name, so
a second entry would render the same tree twice. Every other directory without a
catalogue row carries no model of those kinds, so it generates nothing. Only
=ores.diff= was reachable no other way.

Three components now sit in =COMPONENTS_UNDER_TEST=, which takes the list from
18 to 21. =ores.diff= gained the catalogue row that makes it addressable, and
its six committed generated files had drifted. =ores.storage= and =ores.history=
regenerated byte-identical, so neither had drifted yet.

The gate also found two defects that arrived with main. The branch repairs both,
because the gate cannot be green without them:

- =component-drift=: the iam work that served the auth events, the geo lookup,
  the session statistics and the signouts regenerated the C++ and the TypeScript
  but committed a recipe for none of the six new operations. It also left
  =session_operations= one endpoint behind.
- =tangle-shell= and =tangle-http=: a market data link made a convention field
  optional, which moved its sentinel from =__none__= to =-=. The recipes were
  regenerated and the scripts were not, so 115 committed scripts carried the old
  sentinel and the =rate_instruments= recipes had no script at all.

Neither defect is this task's deliverable. Both went unseen because the chain
from model to recipe to tangle to inventory has no single command that walks it,
and because the per-component pass a pull request runs does not see the rest of
the tree.

The full suite, heavy tier included, reported 4 of 53 red. All four were on
trunk. Two were already repaired on main by PR 2924 (=er-diagram= and
=codegen-tests=) and one by PR 2916 (=ctest='s iam access read). The fourth,
=pgtap=, is still red: the trading structure suites write rows without the audit
columns the generated table requires, and one ownership-marks case finds no
primary contact. Its fixtures are unchanged on main, so that repair belongs to a
trading task, not to this one.
