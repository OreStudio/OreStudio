* Acceptance

- Six-field and four-field expressions are refused, with the count in the
  error.
- =next_occurrence("0 9 1 * 1")= after Tuesday 2026-10-06 is Monday
  2026-10-12 at 09:00 local time.
- =ores.scheduler.api.tests= passes.

* Plan

- In =croncpp.h= of the 2026-08-12 port, =make_cron= accepts six fields,
  or seven when the traits declare a year range, and
  =cron_standard_traits= declares one (lines 1445 to 1452). The parser
  sends ="0 " + expr=, so =* * * * * *= becomes seven fields and passes.
- Add =count_fields= beside =to_croncpp_expr= and refuse any count but
  five before calling croncpp.
- Tests: two more invalid inputs (a Quartz-style six-field expression and
  a four-field one), a check that the error names the count, and a
  =next_occurrence= case that restricts both day fields. The old port's
  loop (=croncpp.h= 711 to 712) required both fields to match, so that
  case also detects a return to the old rule.
