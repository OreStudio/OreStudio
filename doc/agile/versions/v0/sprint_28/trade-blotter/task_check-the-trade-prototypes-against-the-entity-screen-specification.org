** Trade page review, 2026-10-19

Read at =6b0451ee62=: =doc/prototypes/trades/trade-page/prototype.js= and
=common.js= against [[id:BD492939-118E-4B55-AE5B-300F7A1C3B41][Entity screen specification]], the record standard, the menu
structure and the NATS entity protocol. The code was read, not run. =common.js=
is the same in four prototypes, so a fix there goes to all four.

What already matches: tabs in the specified order and held in the address; the
card layout, the dash for an empty value and the fixed-field reason; the Edit
pattern with the kind of change first, the effect notice, the version precondition
and the conflict notice; Refresh gold with the pulse and the loaded-at line; the
Workflows menu rules; the system-activity toggle; the author photo, link and
note line in the history.

Gaps in the specification, to settle before the blotter:

- Which permission shows each trade tab. Every tab is drawn for every role today.
- Whether a trade history entry offers Revert. The rail says it does. Trade Versioning says to undo with the mirror event.
- Whether the title of a trade page is its code or its trade type. The breadcrumb ends in the code and the title is the type, so two swaps read the same.

section "Booking a trade" of the specification and the general rules. The code was
