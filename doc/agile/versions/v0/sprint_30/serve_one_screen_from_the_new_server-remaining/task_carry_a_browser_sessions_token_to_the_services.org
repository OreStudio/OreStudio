* Plan

Found on 2026-11-11 while reading the session path for the bootstrap read.
=auth_session_routes= keeps the token a sign-in returns in the session record,
and the session path in =http_session= took the claims from that record and
nothing else. Every route forwards the token =get_bearer_token= reads from the
=Authorization= header, so a browser request forwarded an empty token, and every
route ported in this story would have failed for ores.web, which signs in with
the cookie.

The session path now sets the request's =Authorization= header from the token
the session keeps, once the cookie proves the session. The header is set on
the request only and never on the answer.
