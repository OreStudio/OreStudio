* Plan

The suites fail for three different reasons, and the reasons hide each other. A
suite whose fixture cannot write its first row reports zero tests run, so its
assertions are never reached and whatever is wrong behind them stays invisible
until the fixture is repaired. The order is therefore: make every suite run,
then repair what each one says once it does.

Reproduce first. Recreate the database before believing any failure, so the
verdict comes from the tree and not from what the last run left in the
database. =compass db recreate --yes= wants no service up and no other
argument.

Then take a census instead of chasing failures one at a time. Hold every
insert's column list against the columns the generated DDL declares, and every
fixture's session context against the policies its table carries. A census
finds a whole class at once, which matters when the only feedback is a
fourteen-second suite run.

        if unknown:
            print(p.name, text[:m.start()].count('\n') + 1, tbl, unknown)

* Result

Every pgTAP suite passes. Ten failed and six of those ran no test at all,
because a fixture that cannot write its first row takes the rest of the suite
with it. The suites now reach 298 tests, against 226.

Three defects sat behind the failures, and each one hid the next:

- Twenty-one inserts into trades, trade activities, structures and their
  children named no audit columns. The tables require four, so every insert
  died on the not-null constraint and the suite reported nothing.
- Thirteen inserts named =party_id= or =counterparty_id= on a child of the
  trade. Those columns went when a child stopped copying the party and started
  reading it through the trade.
- =ores_refdata_publish_lei_counterparties_from_dq_fn= created its centre-map
  temp table without dropping it first, so a second call in one transaction
  failed. The uuid map beside it has the drop and the comment that explains
  why; the centre map was added later without either.

Repairing the fixtures then exposed twenty-two cases that were stale rather
than broken. No trading entity has been immutable since the model became
versioned, and the children stopped copying the party; the suites were never
revisited. Each case now proves what the schema does, and a versioned write or
delete replaces the immutability it lost.

One case was withdrawn rather than rewritten. Nothing refuses a report into
another party's portfolio any more: the check and its message are gone from the
generated SQL. That is a missing guarantee rather than a stale test, so it is
filed on its own story instead of asserted away. The same refactor left the
purge switch inert for trading, and the structures self-parent check
unreachable behind the parent lookup; both are recorded on that story.

The rates-family header left the ER diagram stale, so the diagram and the SVGs
are regenerated here.
