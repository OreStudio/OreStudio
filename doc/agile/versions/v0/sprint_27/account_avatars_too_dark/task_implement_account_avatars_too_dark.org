* Result

The 27 avatars in =external/avatars= were filled =#212121=, which is the
dark theme's background rather than its ink, so a service account, tenant
administrator or super administrator drew an avatar that read as disabled.
Every source image is recoloured to =#e3e3e6=, the theme's ink, and the seed
is regenerated with =images_generate_sql.py --config system_avatars=, so a
provision from now on publishes the legible colour. The running environment's
images were updated in place so the fix shows without a re-provision, and the
BFF image cache, which holds bytes forever, was cleared by restarting
=ores.web.service=.

Verified in the browser: the Accounts list under System administration draws
the service-account avatars in the theme's ink against the dark surface
(=evidence/accounts_avatars_after.png=).
