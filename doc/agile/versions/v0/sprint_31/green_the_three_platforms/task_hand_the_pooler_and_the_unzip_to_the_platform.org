* Result

- =start_ci_pooler.sh= hands PgBouncer to =postgres= when it starts as root,
  because PgBouncer exits on =FATAL PgBouncer should not run as root=. The
  runtime directory goes to that account first, since the pooler writes its log
  and pid file there and reads its credential file from there. =runuser= is
  preferred and =setpriv= is the fallback, so an image carrying either one
  works. Proved twice: once against the real binary as an ordinary user, where
  the pooler still listens and stops, and once as root with =id=, =chown=,
  =runuser= and =pgbouncer= stubbed, where the recorded calls are
  =chown -R postgres <runtime dir>= and
  =runuser -u postgres -- <pgbouncer> -d <ini>=.
- =nightly-windows.yml= extracts the release with =tar -xf=, whose libarchive
  backend reads a zip. The runner carries no =unzip=, which is why the step
  reached its checksum, printed =OK=, and then exited 127.
- The two schema diagrams are regenerated. =compass generate= reported them as
  already stale at the base commit, so they travel in their own commit.
