* Acceptance

- One command runs Playwright against the environment web, reading host, port and credentials from .env.
- The test signs in as a seeded Acme user chosen by role and opens a record list and a record page.
- The run leaves a trace or screenshot on failure in a stated place.
- A recipe states how to run it.

* Plan

Reuse what the repository already knows rather than invent it: the web port
from the checkout's .env, as compass open-as reads it; the seeded people and the
shared Acme password, as compass_open_as.py holds them; the two autocomplete
fields the sign-in page marks, as the open-as script fills them. Put the harness
in a workspace package of its own so npm test does not run it, because it needs
a started environment, and pin @playwright/test to the CLI version the owner
installed. Make the first spec touch a list, a server search and a record page,
naming the rule identifiers it checks, so the harness proves the chain before
the conformance checks are written.

* Result

=projects/ores.web/packages/harness= drives the environment's web in Chromium.
=npm run harness= in the web component signs in as the tenant administrator,
opens the currencies list, searches a code on the server and opens its record
page, naming RS-LIST-03, RS-LIST-04, RS-LIST-10 and RS-PAGE-01. The config
reads the port from the checkout's .env, the fixture signs in through the two
autocomplete fields, and a failing test leaves a screenshot, a snapshot and a
trace under =.runtime/harness=. The recipe How do I run the browser harness
against the environment says how, and the local gate's web class is green.
