* Goal

Two refdata entries still hold a block that exists for one value of the entry,
which [[id:51839336-1AF9-4EFD-84E0-0CB983DC385B][the re-inventory]] found after
the first splits:

- =swaption_volatility_config= carries =smile_option_tenors=,
  =smile_swap_tenors= and =smile_spreads=. They mean something only when
  =dimension= is =Smile=, and they are one block. This is the reading the FX
  split made for =fx_volatility_smile=, so the swaption smile becomes a part the
  same way.
- =inflation_curve_config= carries =has_seasonality= with
  =seasonality_base_date= and =seasonality_frequency=. ORE's =seasonalityType=
  requires =BaseDate=, =Frequency= and =Factors= together, and the factors are
  already the rows of =inflation_seasonality_factor=. The flag and its two
  columns become a part, and the part's presence replaces the flag.

* Acceptance

- A swaption entry has a smile part only when it states a smile grid, and the
  import and the export agree on that.
- An inflation curve has a seasonality part with a required base date and
  frequency, or none. =has_seasonality= is gone.
- The model, SQL, C++, TypeScript twins and fixtures move in one change, and the
  wire change is stated.
- The ORE round trip and the database round trip hold for both, with a refused
  case for each.

* Plan

** The two parts

| Part | Key | Holds | Present when |
|------+-----+-------+--------------|
| =swaption_volatility_smile= | =swaption_volatility_config_id= | =smile_option_tenors=, =smile_swap_tenors=, =smile_spreads= | the entry states any smile list, whatever its dimension |
| =inflation_seasonality= | =curve_definition_id=, as the factors are keyed | =base_date=, =frequency=, both required | the curve states a =Seasonality=; the schema makes it state =Factors= |

The corpus decides the rules. Of 138 =SwaptionVolatility= entries, 33 are
=Smile= and state all three lists, 100 are =ATM= and state none, 3 are =ATM= and
state all three, and 2 state no dimension and no smile. The three are in
=InitialMargin/Input/Dim2=, where the dimension was switched from =Smile= in a
comment and the grid kept. ORE ignores that grid, but the document states it, so
the part exists wherever a grid is stated and the dimension decides nothing. An
earlier count read the commented =Dimension= and claimed no =ATM= entry had a
grid; the import refused the =Dim2= document on that rule, and the corpus test
caught it.

Of 133 =InflationCurve= entries, 71 state a seasonality, and every one has its
base date, frequency and factors. The XML reader already refuses a
=Seasonality= with no =Factors= element, because the schema requires it. The
element may hold no =Factor=, so a seasonality with no factor rows is legal and
the export writes an empty =Factors=. The export refuses factor rows with no
seasonality, which a document built in the store can hold. The code review
caught the first version of this, which also refused a seasonality with no
factors and so would not have written a document the import had accepted.

** Where each rule is enforced

The parts' presence is a statement of the projection, through the
=document_part= index the curve entry split introduced, so a duplicate or an
orphan is refused as for every other part. Neither owner has a construction
column a trigger could read, so there is no insert trigger, as for the
commodity parts.

** The DQ path

Both parts get an artefact table and a place in the publish list. Without one,
the columns would leave the parents' artefacts and a staged dataset would
lose the block. The FX smile and the two proxy parts have that gap today;
it is captured.

* Result

Two parts replace a block each that the re-inventory found.
=swaption_volatility_smile= holds the three smile lists, keyed by the swaption
entry. =inflation_seasonality= holds the base date and frequency, both
required, keyed by the curve definition as the factors are. =has_seasonality=
is gone. The swaption entry goes from 21 members to 18, and the inflation curve
from 20 to 17.

The import fills each part where the document states the block. The export
takes it from the part index, so a duplicate or an orphan is refused. The export
also refuses factor rows with no seasonality. Both
parts have a DQ artefact table and a place in the publish list, so a staged
document keeps them.

The wire change: the curve configuration document gains
=swaption_volatility_smiles= and =inflation_seasonalities=, and the
=swaption_volatility_config= and =inflation_curve_config= messages lose the
moved fields.

The corpus changed one rule. The first plan refused a smile on an entry that is
not =Smile=, from a count that read a commented =Dimension=. Three =ATM=
entries in the ORE examples keep a grid, and the corpus test refused their
document. The part now exists wherever a grid is stated, as the FX smile does.
