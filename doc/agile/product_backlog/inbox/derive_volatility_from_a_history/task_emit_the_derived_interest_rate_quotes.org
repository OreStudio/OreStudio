meter counts them.

* Acceptance

- The adapter reads each currency's term histories, calls the batch derivation once over all of them, and writes one quote per pillar and per strike of the ladder, so the strike axis is emitted and the cube has a producer.
- Every series it writes states the method and the version that computed it, and every value names the series, the window and the model it read, so a stored value says how it was made without reading the code.
- The quotes are internal: a non-system party cannot read one, and no meter counts one. The refusal and the read are both stated in the task, not left to the entitlement layer to imply.
- A currency or term with no history is refused by name, with the series it lacks, and the rest of the run continues.
- The run is idempotent: a second run over the same histories writes the same series and the same observations, and a day already written is not written again.

* Notes

- The emitter is the interest rate counterpart of =derived_fx_vol_adapter= and its feed, and it is built on the descriptor of the pattern task and the batch of the pass task, so it names no asset class.
- The producer is =orestudio=, the producer of the platform's own arithmetic, and it replaces the mechanism-named =derived= for this class. The catalogue row for =derived= is FX-named and is renamed when that class moves.
- Internal standing is the story's decision: stored, versioned, visible to the system tenant and the debugger, never entitled to a non-system party, never metered. If the entitlement layer cannot express it yet, the task states what it does instead and records the gap rather than widening a read.
