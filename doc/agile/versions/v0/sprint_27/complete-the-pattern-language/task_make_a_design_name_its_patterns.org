* Goal

A page that designs how services work together names the service architecture
patterns it applies, and a check keeps the pattern and the page linked both
ways.

* Acceptance

- A memory states the rule: a design names its patterns from the hub, and a
  mechanism with no pattern becomes a pattern page first.
- The knowledge template has an optional =* Patterns used= section, and the
  workflow template a required one; both contracts state it.
- =build/scripts/check_pattern_uses.py= fails when a pattern's use does not link
  back, when a used pattern does not list the page, or when a Patterns used
  entry is not a pattern. Plans, external pages and agile records are exempt.
- The doc lint workflow and the PR-raise skill run the check.
- The existing design pages and the three workflow pages pass it.

* Plan

Write the check first, because it defines the rule, then make the templates,
the contracts and the pages satisfy it. Keep the section optional for knowledge
pages, which are mostly not about services, and required for workflow pages,
which always coordinate services. Name a pattern whose page is not yet written
in plain text, so the coordination group can link it later.

* Result

The rule is in place in four forms. The memory
[[id:470D4571-47A4-4AEF-9A93-2B4DE0279C1E][A design names its service
architecture patterns]] states it. The knowledge template carries an optional
=* Patterns used= section and the workflow template a required one, and both
contracts say so. =build/scripts/check_pattern_uses.py= enforces the links both
ways, with nine tests; its first run found that the reporting design did not
link Grant Management, which lists it as a use. The doc lint workflow and the
PR-raise skill run the check.

The reporting design, the IAM run grants page and the three workflow pages now
carry the section. The workflow pages name Process Manager, Saga and Idempotent
Receiver in plain text until the coordination group is written.
