* Acceptance

- A committed file pins the compass-ng release ORE Studio needs.
- bearings reports a missing compass-ng, or one older than the pin, with the command that fixes it.
- A recipe covers the first full check in a new worktree, compass gc, and the fallback to Python when the binary is missing or crashes.
- compass gc runs on a schedule or from a documented command; the pilot store reached 12 GB before a gc.
- The recipe checks the store's file count (find <git common dir>/compass | wc -l) as well as its size: after one day of the pilot it held 188,697 files, 858 MB of data and 1.5 GB on disk, and compass gc removed nothing. compass-ng keeps one file per cached result until its D8 fix packs them.
- The fleet broadcast names the change and the date the Python gates stop.

* Result

- build/scripts/compass_ng.pin names the build ORE Studio needs, 21ae16d,
  with its commit time. bearings runs compass-ng --version and prints a NEXT
  ACTION when compass-ng is missing or was committed before the pin; commit
  times order the builds without the compass history. Tests cover a missing,
  an older, the pinned and a newer build.
- How do I install and update compass-ng? covers the install, the full check
  that builds a new worktree's record, compass-ng gc, and the fallback to the
  Python gates; the compass recipe index links it.
- The store is no longer a growth risk: compass-ng d2c6595 packs it, and on
  this machine it went from 323,894 files and 2.9 GB to 4 files and 591 MB;
  gc is an occasional command, not a schedule.
- The fleet hears of it through bearings, which every session runs first:
  there is no broadcast channel beyond it. The pull that brings this change
  also brings the PostToolUse hook and the switch-over, so a session that
  pulls main sees the instruction before it runs a gate.
