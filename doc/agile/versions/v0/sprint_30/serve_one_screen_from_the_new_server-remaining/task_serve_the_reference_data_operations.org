* Plan

The inventory lists 33 unpaired reference data routes in five groups. Each group
is one pull request, so each review covers one screen's routes.

| Group | Routes | BFF source |
|-------+--------+------------|
| Counterparties | 6 | =counterparties.ts= |
| Conventions | 5 | =conventions.ts= |
| Curve configurations | 3 | =curve-configuration.ts= |
| Tenors | 9 | =tenors.ts= |
| Generic records, calendars and ORE currency documents | 10 | =records.ts= |

Each route keeps the BFF's address and answer shape, as the earlier ports did.

Decisions made in the counterparty group:

- The router sends a path to the most specific pattern that matches it. A
  literal segment beats a parameter at the first segment where two patterns
  differ, as the BFF's framework did. Before this, the first pattern added won,
  so =/api/counterparties/{id}= could take =/api/counterparties/children=.
- The identifier check moves into =record_routes= as =rr::is_uuid=. The IAM and
  assets copies are deleted, so the refdata routes use the same check.
- A write answers the service's =result= with 200, whatever its outcome, as
  the BFF did. A read that the service refuses answers with the status the
  outcome names, through =rr::require_ok=.

Decisions made in the conventions group:

- The two routes that draw a convention's terms, the document read and the
  terms write, wait for the reporting part. They read the ORE parameter and
  value set tables, which the reporting service owns, through the BFF's
  =readValueSets=. The curve configuration routes read the same tables. The
  value set reader belongs in the reporting part that
  [[id:504FD469-B1A1-4480-9694-34724AD2F2A5][Stand up the reporting part and serve its resources]]
  creates, so those routes are ported after that part exists. The three routes
  that need no value set (the families, one family's page and the family write)
  are ported now.
- The families are a table of typed units: each names its list request and the
  reply member that holds its rows, so the compiler checks every name. A test
  compares the table with the convention registry, so a family added to the
  model fails the test until it is added here.
- The tenor and currency pair conventions answer their rows. The BFF read their
  rows from =tenor_conventions= and =currency_pair_conventions=, but the reply
  names them =conventions=, so the BFF answered no rows for either family.
- The screens' intent and the paged whole read move to shared units, as
  =rr::stated_intent= with =rr::intent_of=, and =forwarding::forward_all=. The
  counterparty unit's copies are deleted.

Decisions made in the tenors group:

- =GET /api/tenors/catalogue= is a composed view with a cache policy, so
  [[id:068865A5-2C31-4735-873E-2CB04A134EF2][Serve the tenor catalogue composed view]]
  serves it. This group serves the other eight tenor routes.
- A one-row write as a screen states it is =rr::versioned_write=, sent through
  =forwarding::put_at_version=, and answered by =rr::result_with=. The
  conventions family write uses the same three.
- A resolution and a write answer 200 with the service's result whatever its
  outcome, as the BFF did: a declined rule is an answer.
- The membership write takes its convention and tenor codes from the address,
  as the BFF did, so the body may leave them out.

Decisions made in the records group:

- The generic =/api/refdata/:resource= routes are answered by the generated
  unit of each resource, at the address the BFF matched. =route_pairing.py=
  states them as families: each names the BFF registry, the C++ address with
  ={resource}= in it, and which resources must answer it (every resource, those
  read by one key, those read by a parent, or the writable ones). The inventory
  reads the registry and fails when a resource lacks its address. The 26
  resources of =REFDATA_RECORDS= all answer.
- The ORE currency routes link =ores.ore.api= into the refdata part. The
  inventory files a route by the screen that calls it, and these are the
  currency screen's import and export.
- =GET /api/change-reasons= was missing from the plan's count; it is reference
  data and is ported here, in =ores.http.core= beside the history route, because
  every screen's reason picker reads it.
- A failed calendar days read or rebuild answers 409 with the service's words,
  as the BFF's =OperationFailedError= did.

* Result

The C++ server answers 23 of the reference data area's BFF routes in hand-written
units, over four pull requests. The generated units answer the five generic
record routes, which the inventory now pairs as families and checks against the
BFF's registry. Each
new route has a test of its refusals and of its forward step. Six routes leave
this task: the conventions document and terms routes and the three curve
configuration routes read the ORE value sets, so
[[id:504FD469-B1A1-4480-9694-34724AD2F2A5][Stand up the reporting part and serve its resources]]
serves them with the value set reader; the tenor catalogue is a composed view,
so [[id:068865A5-2C31-4735-873E-2CB04A134EF2][Serve the tenor catalogue composed view]]
serves it.
