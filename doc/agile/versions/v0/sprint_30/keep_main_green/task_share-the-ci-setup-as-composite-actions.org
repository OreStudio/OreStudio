* Acceptance

- The pinned compass release is installed by one action that unpacks a tar.gz on Linux and macOS and a zip on Windows.
- The Postgres, environment, NATS, database, compiler-cache and guard steps each have one definition.
- The four build jobs keep their steps and their order.
- actionlint reports nothing new.

* Plan

One composite action per step group, and one reusable workflow per repeated
job. The caller keeps what is its own — trigger, guard, matrix, runner,
container, permissions — and the operating-system branch lives inside the
action, so a platform fix is one file.

The guard stays a composite rather than becoming a called workflow: it asks the
API for the last successful run of =GITHUB_WORKFLOW_REF=, and a called workflow
would answer for itself, so every caller would compare against a history that is
not its own.

Verification without a runner: expand every call into the steps it holds, and
diff the resulting list of run bodies against the previous revision, so a
dropped or reordered step shows as a diff line. Then lint the YAML with
actionlint, and add the check that reads it for the two rules the platform
enforces only at run time.

* Result

The four build workflows lost 822 lines and the tree gained nine composite
actions and one called workflow. Every step that ran before runs now, in the
same order: expanding the calls and diffing each build job against the previous
revision gives the same sequence of run bodies, and the three intended
differences are the guard annotation reaching Continuous Linux, the version
check running on every platform, and the compiler-cache save warning rather
than reddening a job when sccache is absent.

Two things the census did not have became clear while implementing. The guard
cannot be a called workflow, because the API query is about the caller. And the
reference password, the server and the database cannot share one composite,
because the environment is written between them and has to be: the password and
the server come first, the database after =env configure= has named it.

The platform does not check either of the mistakes a composite introduces, so
=build/scripts/check_ci_actions.py= reads the YAML for them and
=./compass.sh check= runs it on any change under =.github=.

What this does not prove: no step of the change ran on a runner before it
merged. The first statement about a real leg comes from the continuous run on
main, and from tonight's two nightlies for macOS and Windows.
