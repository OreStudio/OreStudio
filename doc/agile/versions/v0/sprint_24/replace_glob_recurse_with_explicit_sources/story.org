* Goal

Eliminate GLOB-based source discovery across the codebase so that a target's source list is always exactly what's checked in, with zero risk of a build silently using a stale file set after a rebase or new-file add -- the idiomatic CMake approach, as opposed to the CONFIGURE_DEPENDS mitigation already landed.

* Acceptance

- Every CMakeLists.txt currently using file(GLOB_RECURSE ...) (180 files as of this story's creation) is converted to an explicit, checked-in list of source/header files.
- compass build (all presets in regular use) and ctest remain fully green after the migration.
- A recipe or short doc note explains the new convention for adding a source file (must be added to the target's CMakeLists.txt explicitly, no auto-discovery) so contributors aren't surprised.

* Decisions

** Explicit source list lives in its own codegen-generated file, not spliced into CMakeLists.txt

Considered rewriting =file(GLOB_RECURSE ...)= in place inside each
hand-maintained =CMakeLists.txt= (a regex-based script, landed as a
first batch of 96 commits) versus generating the list as its own
file, =include()=d by =CMakeLists.txt=. Chose the latter and redid the
migration: parsing an evolving, hand-edited file to find "the
generated region" is exactly the kind of fragility this story was
trying to remove in the first place, whereas a dedicated generated
file is a safe full-overwrite every time. Implemented as a proper
codegen archetype pair
([[id:0C35DF87-6CBE-41E7-A4FC-B6828EAEE1A8][ores.cmake.component.files_src]]/
[[id:16520415-5CFB-4D46-844C-25688B6425BC][files_tests]]) in the existing =ores.cmake.component= facet, following
the same address system as every other CMake archetype, rather than
a bespoke standalone tool.

** No exceptions: every C++ component goes through codegen for its source list

Ten components had no =modeling/component_overview.org= at task
start and so couldn't be regenerated via the model-driven pipeline.
Rather than leave them on the earlier regex-script's inline-list
approach, scaffolded a =component_overview.org= for each so every C++
component -- no exceptions -- uses the same generated-file mechanism.

* Out of scope

- The CONFIGURE_DEPENDS mitigation itself (already landed sideloaded on the --entity filter PR) -- this story is the follow-on full replacement, not a redo of that fix.
