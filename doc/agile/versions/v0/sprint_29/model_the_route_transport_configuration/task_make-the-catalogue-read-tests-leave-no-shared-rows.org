Make the catalogue read tests order independent: the supplier and adapter cases write into the run's own tenant, and no test leaves a row in the shared system catalogue.

* Acceptance

- The supplier and adapter catalogue read cases write and read in the test tenant, not the system tenant
- The marketdata suite passes in any test order, with no row left in the shared system catalogue

* Plan

The two cases that need a row of their own -- supplier and adapter, because the
populate scripts leave those two catalogues empty -- wrote it into the system
tenant, which is shared reference data and outlives the test. The supplier case
also switched on the session insert guard: that guard validates a supplier only
while the system tenant holds an active one, so the row one case left behind
rejected the supplier the session eventing case states.

Both cases now write and read in the run's own tenant, which the read path
already covers: a read returns the caller's rows and the system tenant's. The
fixture states why, so the next author does not reintroduce the write.
