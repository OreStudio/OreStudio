* Goal

The shared runner in =ores.service= holds a waiting state after phase 1. It
probes each declared dependency until it answers, sends systemd
=STATUS=waiting for <service>= and =EXTEND_TIMEOUT_USEC== while it waits, and
sends =READY=1= only when each answers and the first run of its reconcilers
has started. A service that waits longer than a stated limit logs which
dependency it waits for.

* Notes

- The probe should be cheap and answered by every service; a ping subject the
  runner registers in phase 1 serves, or the dependency's heartbeat.
- A service answers some subjects before it has subscribed the rest. On
  2026-11-21 the market data service answered =marketdata.v1.feeds.list=
  while =marketdata.v1.market_series.list= still had no responder, and the
  synthetic service's fixing writer failed on the second. So a probe of one
  subject is not proof the service is ready: the probe should be a subject
  the runner subscribes after phase 1 is complete.
- This changes what =READY= means for the task Ready the market data service
  before its usage sync: its usage sync becomes a reconciler of task 4.
