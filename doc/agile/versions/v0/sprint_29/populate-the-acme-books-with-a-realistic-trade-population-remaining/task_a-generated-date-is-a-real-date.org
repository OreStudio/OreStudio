* Acceptance

- The planner's month and year arithmetic states the last day of the target month when the anchor's day does not exist in it.
- A date that is not a real date is refused where it is written rather than travelling as the absent date.
- The fx family's variance swap books a real window in a provisioned tenant, and no date column in that tenant holds the sentinel date.

* Plan

Proven by the run that died on the fx family. The first booking it refused was
the variance swap, because that is the first instrument whose two dates the
store compares: =check1= states =end_date > start_date=, and the row carried
the absent date at both ends.

The chain, each link measured rather than reasoned:

1. The planner anchors the population on the day it runs, and draws each slot's
   start as =add_months(as_of_date, -(slot % 6))=. On 2026-10-31, slots 1 and 4
   state =2026-09-31= and =2026-06-31=. Both are =!ok()=: =year_month_day +
   months= keeps the day of the month and does not clamp it, so the arithmetic
   invents a day the month does not have.
2. The wire's =year_month_day= reflector writes the empty string for any date
   that is =!ok()=, because the default date is also =!ok()= and the empty
   string is the sentinel the domain uses for absent. An invented date therefore
   arrives as the absent date, and the run loses it without a word.
3. The store encodes a =year_month_day= as whole days since 2000 through
   =sys_days=, and the default value lands on =0002-11-30 BC=. That is a real
   Postgres date, so the row was accepted and stored.
4. The variance swap compares its two ends and refuses, which is why the run
   stops where it does and not one table earlier. The =FxSwap= row already
   stored in the tenant states its =value_date= as =0002-11-30 BC=: the same
   fault, silent because no check compares that date to anything.

So the fix is three layers, and each layer is a guard that would have caught
the one beneath it:

- *The arithmetic.* =add_months= and =add_years= state the last day of the
  target month when the anchor's day does not exist in it. A month added to the
  31st of May is the 30th of June; a year taken from the 29th of February is
  the 28th.
- *The boundary.* The reflector refuses a date that is neither real nor the
  default sentinel, so an invented date fails where it is written instead of
  travelling as an absent one. The default keeps travelling as the empty
  string, because absent is a value the domain states on purpose.
- *The domain.* A product constructor refuses a date that is not a real date.
  =require_date= states that a date is present; it must also state that the
  date exists, because a caller can hand it =2026-09-31=.

Measured evidence:

- =/tmp/ymd_probe= printed the six anchor offsets for 2026-10-31:
  =back=1 start=2026-9-31 ok=0= and =back=4 start=2026-6-31 ok=0=, with the
  other four real dates.
- =select value_date from ores_trading_fx_forward_instruments_tbl= states
  =0002-11-30 BC= for the =FxSwap= row and =2028-10-31= for the =FxForward=.

* Result

The population now draws dates that exist, and a date that does not exist cannot
travel: it is refused at the reflector instead of arriving as the absent date.

What that bought, on a fresh tenant:

- The fx family booked all sixteen trades, the variance swap among them, and the
  swap states =2026-09-30= to =2028-09-30=. The slot that drew it is the one
  whose anchor month holds no 31st, so the day it asked for was held to the
  month's last.
- No date column in the tenant holds the sentinel =0002-11-30 BC= any more. The
  =FxSwap= row that carried it now states a real value date.
- The run no longer stops in fx. It stops in the bond family on =Bond issue
  … is stored with other terms=, which is the security-naming defect and not
  this one: a callable bond and a plain bond were named by the same security id
  because the id left the product out. The fix for that is written on
  =chore/seed-an-inflation-curve= and lands as its own change, so a full
  provisioning run writes the whole population there.

Two decisions worth keeping:

- The arithmetic clamps the day rather than shifting the date: the 31st of May
  less a month is the 30th of April, not the 1st of May. A window that ends a
  day later than the product means would be a silent change of terms.
- The reflector keeps writing the empty string for the default date. Absent is
  a value the domain states on purpose, and the wire needs one spelling for it;
  the guard is only against a date that is neither absent nor real.
