The test file for the messages of one protocol header. Each message gets one
case, which calls =ores::testing::check_wire_roundtrip=. That helper fills the
message with =ores::utility::codec::sample=, writes it, reads it back, and
requires the value it read to equal the value it wrote, in JSON and in
MessagePack, for the sample and for the default value. It also requires the
message's =wire_fields= to name every member, because the sample fills only the
members the list names.

See the [[id:C4E8A91F-3B7D-4F2E-85A6-1D9C7E3B2F4A][Template variable reference]] for the complete list of available
variables and their semantics.

* Mustache incantations

The sections, includes and type names follow the
[[id:6A583145-C60B-4EDC-A17E-03226578C168][protocol codec unit]], because
the tests call the functions that unit defines. The sampler must see the
=wire_fields= of each domain type a message holds, so the test includes the same
codec headers the unit includes, and the envelope shapes in
=ores.utility/domain/protocol_codec.hpp=. It renders only where =ores.cpp.protocol=
renders, because a model with no protocol has no header to include.

One case per message, not one per format and value: a component has about
twenty messages in each protocol header, and the helper's checks state which
format failed and which value. The checks live in the helper, so the generated
file declares no names of its own, and the files of a component can build as one
unity unit. The case name is the message's qualified type name, which is unique
in the test binary because it is unique in the program.
