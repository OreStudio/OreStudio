* Goal

One component, ores.inbox, holds the approval requests and the notifications as designed: a relational schema generated from codegen models, the approval rules enforced in the database and the service, notifications raised by any component, and the role request built as the first kind with its screens.

* Acceptance

- ores.inbox is a standard codegen component: overviews, generated CMake, C++, SQL, protocol and web types.
- The approval and notification tables match the accepted schema, with keys and foreign keys and no JSON.
- A member asks for a role, an administrator answers from the queue, and both are told through in-application notifications.
