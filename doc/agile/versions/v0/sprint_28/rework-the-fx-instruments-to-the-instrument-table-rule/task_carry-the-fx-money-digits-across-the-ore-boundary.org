* Goal

Make every FX money value keep the digits the ORE document wrote. Today each
FX money leaf is a plain =float= in the binding, so the XML parse discards the
text and the mapper's =exact_decimal= call takes the =from_double= overload.
The stored decimal is therefore the binary float's spelling, not the document's
number.

This unit comes first because it moves the goldens.

* Acceptance

- Every FX money leaf in the binding is a lexical leaf, and each one is patched by =scripts/reapply_ore_lexical_form.py=, never by hand.
- The script handles a required plain =float= member, or it refuses the shape with a stated reason. Today it handles =xsd::optional<float>= only, and most FX money members are required.
- Every FX money field that has a continuous sibling stays a binary float. A variance strike, a ratio and a quantity are not money.
- The forward mapping reads each money leaf with the =xsd::base<T>= overload of =exact_decimal=, and the reverse mapping writes each one with =set_exact=.
- A mapper test holds the digits of each money member: a value with more significant digits than a float carries survives the round trip.
- No golden that changes has a non-numeric change.

* Plan

1. Classify every FX binding member as money or continuous, with the exact-money rule of the data-oriented design page.
2. Extend =scripts/reapply_ore_lexical_form.py= to a required member, with a self-test for the new shape.
3. Add the FX money members to the script's table and run it. Check the diff by hand: the struct, the getter, the element info and the serializer of each member.
4. Replace the reverse casts with =set_exact=.
5. Add the digit tests, then regenerate the goldens and read every changed line.
6. Run the ORE core and trading core suites, and the codegen tests.
