* Before you start

- The database must be freshly provisioned with the Acme Corporation
  holding-group tenant — confirm via =compass db status=, recreating
  only if stale: =compass db recreate -y -k=, =compass services
  start=, then =compass shell -f
  projects/ores.shell/scripts/library/provisioning/how_do_i_provision_the_system_with_acme_corporation_holding_group.ores=.
  Confirm the run completes with no failed steps before starting.
- Login credentials for this scenario: =tenant_admin@acme_corporation=
  / =Secure-Password-123= (from the provisioning script's own
  =login= line — re-check that script if credentials appear to have
  changed).
- The vendored ORE package for =x64-linux= is already built into
  =publish/vendor-packages/= (populated by the =vendor_compute_packages=
  CMake target) — its raw source lives at
  =external/ore/packages/ore-1.8.16.0-3-g3b62ba248-x64-linux.tar.gz=.
  This scenario re-uses that same file for the =arm64-osx= and
  =x64-windows= uploads too (there is no real macOS/Windows build to
  hand); the platform code, not the file's actual contents, is what's
  under test here.

** Publish first platform via shell CLI

- In a terminal, open an interactive shell: =compass shell=, then log
  in with the same credentials as above (=login
  tenant_admin@acme_corporation Secure-Password-123=).
- Run:
  #+begin_src text
  compute publish-package TEST_ENGINE 1.0.0 x64-linux --file external/ore/packages/ore-1.8.16.0-3-g3b62ba248-x64-linux.tar.gz
  #+end_src
- Confirms: output shows =Uploaded: packages/TEST_ENGINE/1.0.0/TEST_ENGINE-1.0.0-x64-linux.tar.gz (sha256=...)=
  followed by =Published TEST_ENGINE 1.0.0 (x64-linux) successfully.=
  with no errors.

** Verify both platforms preserved after merge

- In the Qt client, open Compute Console (menu: Compute) > Apps tab.
- Double-click the =TEST_ENGINE= row, then its =1.0.0= version row to
  open =AppVersionDetailDialog=.
- Confirms: the platforms list shows *both* =x64-linux= and
  =arm64-osx= with distinct =package_uri=/=sha256= values — this is
  the regression check for the bug where a second =publish-package=
  call used to wipe out the first platform's row (=save_app_version_request=
  replaces every platform row for the version wholesale; the fix
  fetches and merges existing platforms before saving).

** Create app via wizard, two platforms

- In Compute Console's Apps tab, click the "App" toolbar action to
  open =AppProvisionerWizard=.
- Application page: name =WIZARD_ENGINE=.
- Version page: check "Register a version now", wrapper version
  =1.0.0=, engine version =2.0.0=, min RAM =512=.
- Platforms page: move both =x64-linux= and =x64-windows= to
  "Selected".
- Package page: for *each* platform row, click "Browse…" and select
  =external/ore/packages/ore-1.8.16.0-3-g3b62ba248-x64-linux.tar.gz=,
  then click "Upload All".
- Confirms: both rows' Status column reads "Uploaded"; "Next" becomes
  enabled only once both platforms have uploaded.
