* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

The screen is the calibration screen with the interest rates class beside
fx, not a new screen: a person reads one place for "which currencies are
covered". A row is one supported currency and states its source, the IR
calibration policy it is read under, its bootstrap config and its latest
published curve with its as-of; a gap states which of the four is missing
and the recorded reason.

1. Assemble the rows in the BFF, where the class is already a parameter
   (=/api/synthetic/calibration/:assetClass=). A row joins three existing
   reads: the class's synthetic feeds (source and calibration outcome), the
   IR curve bootstrap configs (the config and its output series), and the
   published sets of each output series (the latest publish and its as-of).
   The universe is the union of the feeds and the configs, so a currency
   that has one and not the other is a row with a gap.
2. State the gap and its reason per row, in the order a person needs them:
   no public source, no bootstrap config, no published curve, and a publish
   older than the feed's cadence. The reason is the one the system records,
   not a new sentence.
3. Render the interest rates class on the calibration screen as a coverage
   table, following =doc/knowledge/ui/feed_screen_standard.org= and the
   colour rules in =doc/knowledge/ui/ux_language.org=; a gap carries the
   missing badge the language fixes, not a bespoke colour.
4. Prove it: a BFF test for the join and each gap reason, and a web test
   that a row renders its four facts and a gap.

Out of scope: the per-curve inspector. The AUD-AONIA prototype that Gemini
produced is the right vocabulary for a row's drill-in, but it is a single
curve's pillars, chart and conventions, with no server contract yet. It is
captured for a later task, and this task links it.

* Result

Shipped. The calibration screen has an interest rates class beside fx. For
that class it draws one row per supported currency: the currency, the
synthetic feed's source name and provider, the class policy's window in days,
the bootstrap config's name, the latest published set's as-of, and a state.
The state is "Published" when nothing is missing, and otherwise the first gap
with the reason the system recorded: no feed, no public source, no bootstrap
config, no publish, or a publish older than the hour the republish job keeps.

The rows are assembled in the BFF from three reads the system already answers:
the IR generation configs (source and currency), the class calibration's
resolved feeds (whether the feed starts from a fixing, the provider and its
note), the IR curve bootstrap configs (the curve and its output series), and
each output series' newest published set. The currency universe is the union
of the feeds and the configs, so a currency with one and not the other is a
visible gap. The fx response keeps its shape and makes no extra read.

Acceptance:

- The calibration screen lists each supported currency with its source,
  policy, bootstrap config and latest published curve with its as-of. Met.
- A currency with a gap shows the gap and its recorded reason. Met: five gap
  states, each with the system's own note where one exists.

Limitations:

- A currency with several feed configs shows the first that starts from a
  fixing, then the first by source name. The other configs (a term index, a
  LIBOR feed) are not rows of their own.
- A currency with several bootstrap configs across tenants shows the first the
  tenant-scoped list returns.
- No manual QA scenario was written; the browser and BFF suites cover the
  screen's data and states.
- The currency universe is the union of the class's synthetic configs and its
  bootstrap configs, so a currency with neither is not a row. A currency with
  several configs shows the one whose publish is newest.
- Four of the five gap reasons are the screen's own words: the system records
  one only for a feed that keeps a fixed level. The other states have no
  recorded reason to repeat.
- The interest rates class replaces the fx feed panels with this table,
  because those panels assume a currency pair. The class's run actions stay on
  the run tab.
- The per-curve inspector the AUD-AONIA prototype sketches is captured in the
  inbox as a later drill-in, not built here.
