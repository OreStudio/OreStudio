* Acceptance

- Maintain a classification list, Add or correct a currency, Set up a currency pair, Group currencies for the desk and Keep a holiday calendar right each run in ores.web against the real server.
- Every screen uses the journey runtime and the generic history request; none adds a per-entity list, detail or history primitive.
- Every gap a journey document records is either closed or stated on the screen as the document says.

* Plan

1. Wire: register the 28 lists' list, put, put_many and delete operations, and
   the generic history request, in the wire package's operations.
2. BFF: a route per verb over an allow-list of the 28 lists, keyed by list
   name, plus a generic history route; reuse =/api/change-reasons=.
3. Web: the Classifications page, the topic list, the row table, the edit form
   with the change reason, and the shared history panel.
4. Menu: add *Classifications* to the tenant administration menu.
