* What

=GET /api/marketdata/public-rates/coverage= answers ={"series":{}}= on ores.http
where the BFF answers 142 series, each with its first and last date and its
count. The gateway's route reads the durable fixings table
(=ores_marketdata_market_fixings_tbl=, empty in this deployment) and the BFF
reads the public rates' own series, so the two are reading different stores and
answering different screens.

* Why

Found by the answer-shape sweep on 2026-11-25, comparing every paired route's
answer with the shape the BFF gave: every other difference the sweep found is
either fixed or excused, and this one is a member the screen reads answered
empty. The availability tab reads this route to say how far back a publisher's
data goes, so an empty answer reads as "no data" while the BFF said 142 series
hold it.

The market fixings table holds no rows here at all, so the read is not wrong:
the question is which store the coverage belongs to, and the sweep cannot answer
it. Either the durable fixings are the source and the deployment must fill them,
or the route should read the public rates' series the BFF read.
