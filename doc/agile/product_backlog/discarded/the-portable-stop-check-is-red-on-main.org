* What

=projects/ores.synthetic/service/src/app/application.cpp= line 57 includes
the =stop_token= header, and nothing in the file uses it. The file already names
=ores::platform::concurrency::stop_token= in two places -- the worker's signature and the
run loop -- so the include is a leftover from the port that introduced the platform type.

=check_portable_stop_types.py= scans *includes*, not uses, so it reports the file and
=compass check= fails the =portable-stop= check for everyone. Deleting the one include
clears it.

* Why

Every branch's gate is red on a file it did not touch, which is the state that makes people
stop reading the gate. A one-line removal fixes it, and it is nobody's task: it belongs to
whoever finally removes the last C++20 stop type from the tree, and until then it costs
every environment a failed check.

Verified on =origin/main= =6dfbd3a3fb=: the include is still there. This branch's diff does
not touch the file.

stop type is named outside ores.platform", and =compass check= no longer reports it.
