* Goal

The checked-in generated code and the generator disagree, and nothing
reports it.

Found while fixing a compiler warning: the table renderers are generated
from =cpp_domain_type_table.cpp.mustache=, so a one-line template change
was the right fix. Regenerating =marketdata= produced exactly that one
line in five files. Regenerating =analytics-cpp=, =refdata= and
=scheduler-cpp= produced 116 changed files with 1112 insertions and 756
deletions, and created 24 files that had never been committed —
registrars, protocol headers, presentation and generator directories,
eventing integration tests.

None of that was the template change. It is the accumulated difference
between what was committed at some point in the past and what the
generator emits today, and it sat invisible because nothing regenerates
those components in CI.

The danger is specific rather than theoretical. Anyone making a
legitimate template change to these components has to choose between
shipping a 1100-line diff they did not author and not making the change
at all. That is what happened here: the drift was reverted and the task
it surfaced in shipped without it.

=trade= is a fourth component with the same disagreement, and it is the
one that shows what the drift costs. Its committed
=trade_generator.cpp= declares a =counter= that nothing reads. The
model gives =trade= a uuid primary key, no natural keys and no
=:unique:= column, so all three disjuncts of =needs_counter= are false
and the current generator emits no counter at all. The declaration is a
leftover from a generator the model no longer describes.

The compiler found it once =-Wall= was on, and the warnings task
silenced it with =[[maybe_unused]]= rather than by regeneration,
because regenerating =trade= is not a one-line diff: the emitted code
is flat where the committed code uses field groups, and it lands in
namespace =generators= where the committed code uses =generator=. It
would not compile against the domain type as it stands. That
=[[maybe_unused]]= should come back out when this task regenerates the
component; it marks drift rather than an intentional declaration.

* Acceptance

- Regenerating =analytics-cpp=, =refdata= and =scheduler-cpp= leaves the tree unchanged.
- The 24 uncommitted generated files are either committed or the generator stops emitting them, and which it is, is stated per file.
- Each substantive difference is understood before it is accepted: a diff taken because the generator is right is recorded as such, and one taken because the checked-in file was hand-edited is recorded as the hand-edit it overwrites.
- The three components join the drift gate's registry, so the next divergence fails rather than accumulates.
- The gate runs in CI, not only on request.

Scope warning for whoever picks this up: 1112 insertions is not a
mechanical accept. Some of it will be the generator having improved, and
some will be hand-edits to generated files that regeneration is about to
destroy. The second kind is why this is a task rather than a command,

kept it current is the one the other three need.
