* Goal

The story claims a 256 MiB upload costs less than 1 MiB of resident memory. Nothing
measures it, so nothing would notice if streaming regressed to buffering.

* Acceptance

- A test uploads 256 MiB and reads the gateway process's peak resident memory across
  the request.
- The peak moves by less than 1 MiB.
- The grid wrapper's transfer tests pass against the streamed routes. Moved to
  [[id:9A1C38AC-48B2-4F25-905E-A3104FE461F2][Prove the transfer through the wrapper]], which needs a fleet and a tree that builds.
- The measurement names the commit it ran at.

* Plan

1. Read =VmRSS= from =/proc/self/status= every 5 ms while the upload runs and keep
   the peak. =VmHWM= would also count everything the process did before the test, so
   it cannot answer "what did this upload cost".
2. Upload 256 MiB in chunked frames written from one 64 KiB buffer, so the client does
   not hold the object either, and warm the buffers with a small upload first.
3. Assert the delta, and fail with both numbers so the regression is legible.
4. Run the wrapper's transfer tests and record them.

* Notes

- The session's byte counter now has a test that a streamed body's bytes reach it:
  a capability token carries a session, the gateway records what it reports, and
  the count is asserted against a 2 MiB upload. Counting the request body instead
  reports zero there, which the case catches.

- The measurement is the test process's own =VmRSS=, read from =/proc/self/status=
  every 5 ms while the upload runs, and the peak is kept. A peak file counter
  (=VmHWM=) would also count everything the process did before the test.
- A first, small upload warms the buffers before the baseline is taken, so the
  one-off allocations are not credited to the large body.
- The client generates its frames into one 64 KiB buffer, so the test does not
  hold the body on the sending side either.
- The wrapper's transfer tests are the only acceptance left. They need a fleet and
  a tree that builds, and neither is available: =ores.trading='s generated batch
  header is missing the members =ores.synthetic= writes.

* Result
A 256 MiB upload moves the process's resident memory by 136 to 464 kB, against the
megabyte the story allows, and the same test with a sink that keeps the body costs
461 MB. The test measures the process, not the gateway alone, and it guards the
session's read loop rather than the storage route: the wrapper run is what closes
the second gap.
