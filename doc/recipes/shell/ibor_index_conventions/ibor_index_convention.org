#+title: How do I run the ibor_index_conventions commands from the shell?
#+description: Every command the ibor_index_conventions submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:ibor_index_conventions:

This file documents the ibor_index_conventions resource at the shell, one section per command. Every command is a subcommand of =ibor_index_conventions=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 5AC3157E-5205-50B6-A3A4-FBD8BED77041
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
ibor_index_conventions list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.ibor_index_conventions.list=.

#+name: ibor_index_conventions-list
#+begin_src ores-shell :tangle ibor_index_conventions-list.ores :exports none
ibor_index_conventions list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 2843BDDE-1FC4-5E29-8298-5F36CAB77313
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
ibor_index_conventions get <id>
#+end_example

It is addressed at =refdata.v1.ibor_index_conventions.get=.

#+name: ibor_index_conventions-get
#+begin_src ores-shell :tangle ibor_index_conventions-get.ores :exports none
ibor_index_conventions get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 10215B1C-8909-59FA-8823-243CCED78B87
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
ibor_index_conventions add <id> <fixing_calendar> <day_count_fraction> <settlement_days> <business_day_convention> <end_of_month> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.ibor_index_conventions.put=.

#+name: ibor_index_conventions-add
#+begin_src ores-shell :tangle ibor_index_conventions-add.ores :exports none
ibor_index_conventions add __none__ __none__ __none__ 0 __none__ false system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 9A0E78AA-D3CA-5D83-BDFD-0431A381F04F
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
ibor_index_conventions set <id> <fixing_calendar> <day_count_fraction> <settlement_days> <business_day_convention> <end_of_month> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.ibor_index_conventions.put=.

#+name: ibor_index_conventions-set
#+begin_src ores-shell :tangle ibor_index_conventions-set.ores :exports none
ibor_index_conventions set __none__ __none__ __none__ 0 __none__ false system.new_record generated_script
#+end_src
