#+title: How do I run the zero_conventions commands from the shell?
#+description: Every command the zero_conventions submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:zero_conventions:

This file documents the zero_conventions resource at the shell, one section per command. Every command is a subcommand of =zero_conventions=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 040146FD-8664-5667-BB35-EB9C0E9E29F8
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
zero_conventions list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.zero_conventions.list=.

#+name: zero_conventions-list
#+begin_src ores-shell :tangle zero_conventions-list.ores :exports none
zero_conventions list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 6EDD021D-DA4B-5B05-B0F4-343E54E73E55
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
zero_conventions get <id>
#+end_example

It is addressed at =refdata.v1.zero_conventions.get=.

#+name: zero_conventions-get
#+begin_src ores-shell :tangle zero_conventions-get.ores :exports none
zero_conventions get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 26EBEF20-5A83-5510-A5B6-BF8B968F324C
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
zero_conventions add <id> <tenor_based> <day_count_fraction> <compounding> <compounding_frequency> <tenor_calendar> <spot_lag> <spot_calendar> <roll_convention> <end_of_month> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.zero_conventions.put=.

#+name: zero_conventions-add
#+begin_src ores-shell :tangle zero_conventions-add.ores :exports none
zero_conventions add __none__ false __none__ __none__ __none__ __none__ __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 85905ABC-79AB-539A-B4A0-B825AFA14CC0
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
zero_conventions set <id> <tenor_based> <day_count_fraction> <compounding> <compounding_frequency> <tenor_calendar> <spot_lag> <spot_calendar> <roll_convention> <end_of_month> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.zero_conventions.put=.

#+name: zero_conventions-set
#+begin_src ores-shell :tangle zero_conventions-set.ores :exports none
zero_conventions set __none__ false __none__ __none__ __none__ __none__ __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src
