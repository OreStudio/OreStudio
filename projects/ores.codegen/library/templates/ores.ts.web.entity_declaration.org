One entity's declaration, as a TypeScript data module: the component and
entity identifiers the registry knows it by, the route its screens live
at, the API path the BFF serves it on, the parameter that carries its
natural key, the four capabilities, and the fields its list searches
across. It imports its own metadata from the sibling =ui= module, so the
declaration and the columns are two projections of one model and cannot
disagree about a field.

The module holds values and one type-only import. There is no function in
it, which is what makes it safe to generate: nothing here is behaviour
that a template would have to be taught to reproduce.

The values arrive pre-rendered where Mustache cannot express them. The
search fields are a block for the same reason the columns are: every
element but the last carries a trailing comma, and Mustache offers a
comma or a leading comma, never "a comma unless last".

The capabilities are derived rather than declared. An entity can be
created, amended and deleted unless its model says it is read-only, and
it has history when the service has a history provider for it. A
capability is a property of the model and the service, never a preference
of the screen.

Field grouping is deliberately absent for now: the entity meta-model can
resolve a field group, but no entity model binds one yet, so there is
nothing to emit. It arrives with the field-group grammar work rather than
being invented here. Until then the shared detail form shows the entity's
fields in one group, which is what "no grouping declared" means.
