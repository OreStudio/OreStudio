* Result

The three chain tips merged into main as merge commits, so the seven
prototype branches are ancestors of main and git reports each of them merged.
The merges resolved toward main for every shared file a branch had drafted
earlier, because main carries the merged successor of that work.

What changed beyond the merges, and why:

- The hub is one route table, =PrototypeApp.tsx=, that answers eleven
  journey routes and an index grouped by onboarding, credentials and
  operations. Each route states its actor's shell: the member and the tenant
  administrator in Acme, the system administrator on the system tenant, and
  the public shell for onboarding. The credentials routes link the accepted
  variant B.
- The onboarding screens moved from the application's routes (=/setup=,
  =/iam/tenant/onboard=, =/refdata/party/new=) to =/prototype/setup=,
  =/prototype/tenant= and =/prototype/party=, because the application owns
  those routes now.
- Both prototype sets brought a =fixtures.ts=. Their exports never overlapped,
  so they split into =credentialsFixtures.ts= and =operationsFixtures.ts=.
- Main's password field now takes the policy as a prop. The onboarding stub
  gained a policy fixture in the shape the server returns.
- The "throwaway, delete with the branch" comments now state the code is the
  kept record.
- The journey pages name =main= as each prototype's source; the credentials
  journeys gained the Prototype section they lacked. A project memory, [[id:708C2462-C1F8-455B-B091-9D9690FEEAAB][Keep
  journey prototypes on main]], records the convention.

Not run: the C++ build and ctest, because no C++ changed; and
=misspell-fixer=, which this session may not run.
