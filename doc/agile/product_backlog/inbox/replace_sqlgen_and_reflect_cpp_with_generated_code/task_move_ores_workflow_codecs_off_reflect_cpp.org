* Acceptance

- ores.workflow's generated types use the generated codecs.
- ores.workflow's hand-written JSON uses the generated codecs or yyjson.
- Nothing in ores.workflow includes reflect-cpp.
- ores.workflow's suites pass, and its wire bytes match the bytes before the move.

* Plan

- Opt the four workflow entities and the workflow messages model into the
  wire codec and regenerate.
- Give the hand-written identity workflow and step claim messages wire fields;
  the claim messages cross NATS, so they take =shaped_wire_traits=.
- Move the identity step handler, the query handler and the engine's step log
  onto the codec, and drop the include-only reflect-cpp uses.
- Prove the domain types, every workflow message, a filled step event with its
  log, the claim messages and the identity requests against reflect-cpp.

* Notes

** What keeps reflect-cpp

- =workflow_vocabulary.hpp= keeps the reflectors of the step outcome and log
  level enumerations. Components that have not moved still encode those enums
  through reflect-cpp, so the reflectors go with
  [[id:7A1D09B8-B3F2-4E02-9669-3C2F6CC2C6EC][Remove reflect-cpp]].
- The workflow messages model still lists =ores.utility/rfl/reflectors.hpp= in
  its includes, so the generated =workflow_protocol.hpp= keeps it. Most of the
  tree includes that header, and a unit that has not moved may get the
  reflectors only through it, so dropping it waits for Remove reflect-cpp,
  which proves it with a full build.

* Result

ores.workflow encodes and decodes without reflect-cpp, apart from the enum
reflectors and one transitive include that Remove reflect-cpp owns. Its five
models use the generated codec, its hand-written identity and claim messages
state their wire fields, and its handlers and engine read and write through the
codec. The bytes match reflect-cpp's.
