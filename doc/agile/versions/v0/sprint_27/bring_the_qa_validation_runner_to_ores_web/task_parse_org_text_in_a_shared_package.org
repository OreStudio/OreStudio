* Result

The new package, @ores/org in projects/ores.web/packages/org, has two entries. The root entry parses org text into a line-indexed outline with no dependency. The render entry turns org text into sanitised HTML with unified and uniorg. The outline names the lines of every section, table and list item, so task 2 can replace one table and keep every other line. It follows the shape that compass creates: the file drawer, the keyword block, nested sections, field tables and src blocks. A src block is left alone, and a star line in one needs a comma, as org says.

The tests number 50. Two real scenario docs are fixtures, and one test parses every scenario doc in the repository. The renderer is tested against twelve hostile inputs, parsed back as a browser would. Removing the sanitiser fails four of those tests, and removing the line guard fails the stress test. The uniorg parser overflows its stack on a few thousand nested markers and slows sharply on an emphasis-heavy line, so a line with more than 300 markers shows as fixed-width text, and any error falls back to an escaped block. ores.org-js is untouched. It leaves the site in story 2.
