This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

=ores_compute_hosts_tbl= carries =last_rpc_time=, described as the time of the
last heartbeat received from the node. Nothing writes it any more. The
heartbeat handler used to load the host row, set the column, and save, which on
a bitemporal table adds a version: with five nodes heartbeating every thirty
seconds the table grew by about fourteen thousand rows a day, all of them
differing only in that timestamp. The write is removed, and the grid summary's
online count now comes from the node samples instead.

The column itself is still there, in the model, the table, the generated
entity and mapper, the wire protocol, the browser types and the hand-written
host domain tests. Its name promises a value that nothing maintains, so a
reader has no way to tell that it stopped meaning anything.

* Why

A dead column that reads like a live one is the same defect as a dead
environment variable or a stale gap statement: it costs whoever reads it next
the time to work out that it is not what it says. It is also in the way of the
work that replaces it, because liveness is becoming a series.

Removing it is not a one-line change. It means editing the model, regenerating
the compute addresses so the generated entity, mapper, table and JSON I/O, the
protocol and the browser types all lose the field, updating the hand-written
domain tests that set it, migrating the existing table, and rebuilding. That is
why it did not travel with the change that stopped writing it.

It belongs with the time-series work that gives the grid its charts
([[id:84345A75-CCE4-4C6B-80EA-A5857E01730B][Account for the grid's usage]] and
the node-sample series), because that is the work that owns liveness and will
decide what the host row still needs to state.
