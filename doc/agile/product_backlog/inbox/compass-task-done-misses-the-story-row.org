#+description: compass task done does not flip the task's row in the story's * Tasks table whenever the story's * Status block names that task as Next. The row updater _update_task_row_in_story (projects/ores.compass/src/compass.py:4002) walks the story line by line and acts on the FIRST line that links to the task, which is the Status table's Next row. That row splits into four cells, fewer than the six a task row has, so the function returns False and the real row, further down and correctly shaped, is never reached. The command prints no error: it simply omits its 'story * Tasks row -> DONE' line. Closing a task is exactly when the Status block tends to name it, so the failure is the common case, and the drift it leaves (task DONE, story row BACKLOG) is the silent inconsistency the runbook warns about. The candidate fix is for the loop to skip a match whose cell count is not the task table's and continue to the next match, rather than returning False on the first one, plus a unit test over a story text whose Status block names the task. Found while closing the bundle write, where the row was corrected by hand.
