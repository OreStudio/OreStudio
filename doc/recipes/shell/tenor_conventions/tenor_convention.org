#+title: How do I run the tenor_conventions commands from the shell?
#+description: Every command the tenor_conventions submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tenor_conventions:

This file documents the tenor_conventions resource at the shell, one section per command. Every command is a subcommand of =tenor_conventions=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 7D9D1D45-7940-52D9-9EE7-9289A4D1D283
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tenor_conventions list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.tenor_conventions.list=.

#+name: tenor_conventions-list
#+begin_src ores-shell :tangle tenor_conventions-list.ores :exports none
tenor_conventions list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 718B8B77-DC5D-5B28-A0C7-C5C5B559287D
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
tenor_conventions get <code>
#+end_example

It is addressed at =refdata.v1.tenor_conventions.get=.

#+name: tenor_conventions-get
#+begin_src ores-shell :tangle tenor_conventions-get.ores :exports none
tenor_conventions get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: D1336552-B4AD-5C86-AB96-380C521302B3
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tenor_conventions add <code> <description> <measured_from> <resolution_algorithm> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.tenor_conventions.put=.

#+name: tenor_conventions-add
#+begin_src ores-shell :tangle tenor_conventions-add.ores :exports none
tenor_conventions add __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 3D713558-6C07-5982-97A7-66EA87D7268E
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
tenor_conventions set <code> <description> <measured_from> <resolution_algorithm> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.tenor_conventions.put=.

#+name: tenor_conventions-set
#+begin_src ores-shell :tangle tenor_conventions-set.ores :exports none
tenor_conventions set __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src
