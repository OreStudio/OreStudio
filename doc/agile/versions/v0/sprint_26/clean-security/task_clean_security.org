* Notes

Survey, 2026-09-25, at trunk `5de59e3fb8`, by an agent that did not write
the component. Cryptographic code, so an untested path here carries more
weight than an untested path elsewhere.

- Scale. 16 production C++ files in 11 headers and 5 sources, with 6 files
  under `tests/`. 55 test cases, 127 assertions, and 448 files outside the
  component include it. Consumers include
  `ores.iam`'s account and signup services and its auth handler.
- Suites pass. `ores.security.tests` runs green, 127 assertions in 55 test
  cases.
- Keep the component. It is the repo's only home for hashing, encryption,
  JWTs and the OWASP validators.

Work items, in the order they land.

1. Decide `crypto/encryption.cpp`. It has no consumer at all. Only its own
   test includes it, and it holds three public statics in 194 lines with no
   failure-path test. Either name a consumer and test it properly, or
   delete it with its test. This decision comes first, because several of
   the gaps below go with it.
2. Delete the two `base64_encode` and `base64_decode` declarations in
   `password_hasher.hpp`. They are never defined and never called.
3. Remove `jwt_error::missing_claims`, or add the claim-presence check that
   produces it. Nothing returns it today.
4. Forbid a downgraded scrypt cost at verify. `password_hasher.cpp:117`
   accepts any `ln` from 1 to 31, and `ln=1` is 8192 times weaker than the
   production factor. Add the test that rejects it.
5. Pin the stored hash format and the cost parameter. No test asserts the
   `$scrypt$ln=14,r=8,p=1$` shape, `get_n_parameter()` is untested, and
   `CMakeLists.txt:137` sets `ORES_TEST_PASSWORD_FAST=1`, so the suite only
   ever runs the test factor.
6. Test `validate_allow_expired`. It carries a 100-year leeway, has no test
   in the component, and `ores.iam`'s refresh path depends on it. Prove it
   still rejects a bad signature.
7. Add the failure-path tests for `decrypt`. Tampered ciphertext, tampered
   tag, truncation and non-base64 input are all unverified, and the wrong
   password is the only case covered.
8. Add the JWT cases. Algorithm confusion, wrong issuer, wrong audience and
   `nbf`.
9. Decide the empty-input behaviour of `verify_password`, which returns
   true today, and pin it either way.
10. Hygiene. Drop the narration comments in `crypto/encryption.cpp` and the
    end-of-line comment, and align the overview with the umbrella header.
