* Result

Agreed with the user on 2026-09-22.

1. *Engine*: every bootstrap workflow is an =ores.workflow= definition.
   A request returns an instance id straight away. Clients follow
   progress through =workflow_instance_changed= events. Steps call the
   real handlers through internal actor impersonation, never through
   SQL shortcuts.
2. *Workflows*: /System bootstrap/ creates the system admin only.
   /Provision tenant/ creates every tenant, the first one included.
   /Provision party/ (activate, onboard, membership, party bundles) is
   its own workflow. Provision tenant runs it once per party, and an
   admin can run it alone.
3. *Seed profile*: registered data (rows, like DQ bundles) that orders
   *step kinds* from a fixed catalogue in code: =publish_bundle=,
   =import_lei_hierarchy=, =provision_party=, =load_staff=,
   =attach_photos=, =start_market_feeds=. A new profile is data. A new
   step kind is code. Keep it inflexible.
   - /Empty operational/: =base=, a counterparty size, GLEIF root LEI
     parties, =party_essentials= per party. No test data.
   - /ACME demo/: a fully usable, realistic system with no parameters.
     All test data lives here.
4. *Parameters*: each profile declares a small schema (name, type,
   default, required). The web builds its form from it. The shell takes
   =--param key=value=.
5. *New bundle*: =party_essentials= holds =ore.report_definitions= and
   =crm_topology=. =risk_management= loses report definitions and
   becomes ACME-only.
6. *Failure*: steps are idempotent. A failed step stops the instance.
   The tenant stays /provisioning/ and can be retried from that step.
   /Discard tenant/ is a separate system-admin action.
7. *Who runs what*: system bootstrap, anyone while in bootstrap mode.
   Provision and discard tenant, the system admin. Provision party, the
   tenant admin.
8. *Clients*: ores.web and ores.shell are thin callers. The shell's
   client-side orchestration is deleted. ores.qt is frozen as
   reference.
9. *Dropped*: the /Synthetic/ profile. The generator stays a shell
   tool outside provisioning.
