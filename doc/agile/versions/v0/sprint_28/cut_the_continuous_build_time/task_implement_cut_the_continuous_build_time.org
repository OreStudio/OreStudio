* Acceptance

- A measured A/B build shows what a unity build, or precompiled headers, changes in compile work.
- The lever that pays is adopted behind an option, or every lever is measured out and recorded.
- The continuous clang jobs complete inside the six-hour limit.

* Plan

Measure before changing anything. The linker is already measured out.
Trial a whole-tree unity build against a non-unity baseline. If unity is
blocked, trial precompiled headers instead. Adopt the lever that pays,
behind an option, or record every lever as measured out.

* Notes

** There is no hotspot to split

The largest gap between two step completions in the failing run is 36.9 s
and the median is 1.96 s. The time is spread across all 5422 steps, with a
long tail of 20 to 30 s translation units in =ores.shell/refdata=,
=ores.ore/core=, =ores.reporting/core= and =ores.trading/core=. Splitting
one oversized translation unit therefore buys little.

** The linker is measured out

The build has 53 link steps out of 7187. Link time cannot be a
significant share of a six-hour build, so a faster linker is not the lever.

** The unity build is blocked on symbol hygiene

Merging translation units fails immediately. Four files in
=ores.analytics.quant= each define a file-local =small_kappa_threshold= at
namespace scope, so one unity translation unit redefines it:

=black_karasinski_process.cpp:33=, =ornstein_uhlenbeck_process.cpp:30=,
=quadratic_gaussian_process.cpp:37=, =two_factor_gaussian_process.cpp:29=.

The build stops in 19 s. A unity build therefore needs a sweep first:
every file-local constant and helper becomes =static= or moves into an
anonymous namespace. The sweep's size is unknown, because the build stops
at the first collision.

** What is left

Precompiled headers, which do not change translation-unit boundaries and
so carry no collision risk, and the sweep that would unblock unity. The
non-unity baseline build runs in =build/output/nounity-trial= for the
comparison.
