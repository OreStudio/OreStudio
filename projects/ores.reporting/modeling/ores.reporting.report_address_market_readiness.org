One row per oresmd address the run needs, written before the engine sees any
work, whether or not the market answers it.

This is the grain that answers why the market is short. A party that has to buy
the data needs to know whether it is missing a series or missing a point in one
it holds, and those are different purchases, so the row names the series that
answers the address when there is one and the cause when there is not.

An address several trades name is one row, because the question is about the
address and not about the trade that asked for it.

The series that answers the address, absent when nothing holds it. It is
written as the commit points out the series, not the address alone, because a
provider may hold two series under one address and only one of them is the one
the run read.

** gap_cause
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:nullable:     false
:END:

Why the market did not answer the address, empty when it did. The codes are
=no_series=, when nothing holds the address, and =no_point=, when a series
holds it but carries no point at or before the run's as-of. A cause no read can
state is not invented here; the list grows when a read can state more.
