* Goal

Provisioning a system offers to populate its entities with trades, at a chosen
size. Four sizes, each serving a purpose the others cannot.

Tiny exists so an integration test can assert against a book small enough to
read. Extra large exists so volume and query performance can be measured against
something the size of a real institution's book. Medium and large sit between,
for demonstrations and for work that needs breadth without the cost.

Every size is realistic *at its own scale*. A tiny population is a small firm's
book, not a large firm's book with most of the rows deleted. That distinction is
the substance of this story: the sizes differ in what a plausible entity of that
size would actually trade, not only in row count.

* Acceptance

- Provisioning takes a size and populates trades without a manual step. No
  hand-written XML, no separately run generator, no hand-imported file.
- Four sizes exist, each with its purpose stated and its row order recorded.
  Tiny is small enough for an integration test to assert against; extra large is
  of the order of 400,000 trades.
- Realism is defined per size and is checkable. A tiny population is realistic
  as a small book rather than as a sample of a large one, and the analysis
  states what differs beyond count: how many asset classes, how many
  counterparties, what maturity spread a firm of that size plausibly has.
- The sizes are datasets, following the pattern already established under
  =projects/ores.seeder/datasets/=.
- The load path is bulk SQL, generated as the rest of a dataset already is, and
  its cost is measured at the largest size rather than estimated.
- Coverage is measured against the =ores.trading= instruments: which the
  generator can populate, which it cannot, and which asset classes a realistic
  book needs that neither side carries.
- Trades land in portfolios by a rule reflecting each portfolio's owner unit and
  aggregation currency, not by round-robin.
- What ORE's TradeGenerator knows is extracted and written down: which fields a
  valid trade needs, which come from the convention, which from the curve
  config, and which the caller must supply. Whether we depend on it or
  reimplement it is a conclusion of the analysis, not its premise.
