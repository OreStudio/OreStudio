One =Parameter= element inside one =Analytic= of a run document: the value, and
the definition that says what it means. The corpus writes eighteen hundred and
seventy-four analytics whose parameters barely overlap -- xva takes around
seventy, simulation sixty, sensitivity thirty, and several types one flag -- so
the parameters cannot be columns on the analytic.

They are held the way the reporting registry already holds a configuration's
parameters: a row per value, keyed to a definition in =parameter_definition=
whose =scope= is the analytic and whose =subtype= is the analytic type code,
and whose value domain supplies the type. Adding a parameter is a lookup row,
never a column, and no analytic type needs a table of its own. That is the
decision this entity records, and it replaces the plan's table-per-type with the
registry's own pattern, which was built for this shape.

Each row belongs to exactly one analytic and has many parameters, in the order
the document wrote them.
