* Goal

Five journeys document how a system administrator sees a running installation: See the running services, Watch the compute grid, Watch the message bus, Read the telemetry logs, and Check the versions and the database. Each follows the [[id:AFE1E3F9-F687-4CA7-AA6D-C9AAF727D00D][User Journey Extraction Standard]], and a clickable prototype on a throwaway branch proves the screens.

* Notes

*The handler checks changed four claims.* Reading the code behind the
operations, not only the protocol pages, moved four statements: the heartbeat
states a release and not a build, the services list keeps only the last five
minutes, the grid read drops the failure counts the ingest stores, and the
NATS counters are cumulative since the server started. Each became a gap the
journey records.

*The database fingerprint is the one genuinely missing read.* The row exists,
and exactly one reader touches it: each service at its own startup. No
subject serves it to a person, so the versions journey states the panel as
unknown until the read exists.

*The legacy inventory lives on the hub.* The standard asks for it, and the
story put it in the group hub's =* Where the legacy screens went=, next to the
journeys that carry the screens.
