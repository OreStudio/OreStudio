#+title: Trade set

* Summary

A trade set is a set of trades. Something always defines it, and this
page calls that something the set's /context/. The context is a book, a
counterparty, a portfolio, a netting set, a structure, a strategy, a
recorded selection, or an operation. The context's entity is the set's
identity, and one trade belongs to many sets at once.

* Detail

** The primitive

A trade set asks nothing of its members beyond membership in it. Every
other construct in this cluster is a trade set with something added: a
purpose, an operation, or a product.

The set is not the trades. It is the reading of which trades are in it,
and a reading needs a standpoint. That standpoint is the context.

** The context's entity is the set's identity

Where the business names a collection, an entity carries the name. The
book is the identity of its trade set, and the netting set is the
identity of its own. The set needs no key of its own, because the
context supplies one.

An empty set is therefore meaningful. A book with no trades is a book,
and a netting set with no trades still has an agreement behind it. A
collection with no identity could not be empty, because nothing would
record that it exists.

** Membership

A context resolves membership in one of two ways: by derivation from the
trades' own attributes, or from a list recorded when the set is created.
The choice decides where membership is stored and whether the set changes
underneath its reader.
[[id:55269F2C-18DD-4A33-B1CE-770EF5F56BB5][Trade set membership]] states it.

** Nesting

Some sets contain others. The portfolio tree and the structure tree are
of this kind, and there membership is part of the trade's identity.
[[id:80760020-5896-4C1C-805D-87B93982F0C0][Nested trade sets]] states the test that
separates them from the rest.

** What is not a set

A [[id:886AAFB5-62F3-4AA3-B325-386665AFF926][position]] aggregates trades and has no identity. The
system computes it from the trades in scope rather than recording it, so
nothing refers to it by key and it is not a set.

[[id:44C9D99B-979B-43AB-90BC-AF7E7D8BDE7C][Dynamic books]], trade blotters and live filters are
queries. A query becomes a set when someone records the membership it
returned. Until then it is a question asked again each time it is read.

** What follows for the model

- A derived set is a key on the trade's booking and needs no table.
- A recorded set is a table with a key, and a membership table beside it.
- The context's entity supplies the set's key wherever one exists.
- A set whose context has no entity carries a key of its own.
