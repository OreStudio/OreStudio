* Acceptance

- the type names an instrument table, and each batch is a row with its option
  terms, name, currency, strike, strike currency and quantity
- the hedging volatility, drift rate, observation start and payment date are
  columns
- the projection reads and writes the element, value for value
- the type has a builder, and the catalogue routes it
- the generator books one trade of it through its builder, and the recorded
  trades hold it
- the ORE engine test reads and builds it, with no error of the trade kind

* Plan

The option rows hold one block a trade, and this product states one a batch,
so the batches need rows of their own. The equity position option underlyings
already hold an option position's entries, the same shape less a few terms,
so both product kinds share them.

- =equity_position_instrument= gains =volatility=, =drift_rate=,
  =observation_start_date= and =payment_date=, all optional.
- =equity_position_option_underlying= gains =currency=, =strike_currency=,
  =quantity=, =premium_amount=, =premium_currency= and =premium_pay_date=, all
  optional. ORE requires exactly one premium a batch.
- The codegen regenerates both entities across SQL, domain, mappers,
  repositories, services, shell commands and wire types.
- The projection reads a batch's premium from =Premiums= or from the legacy
  =PremiumAmount= form, and writes =Premiums=.
- =equity_auto_delta_hedged_option_builder=; the equity planner books a call
  and a put at the level on the slot's equity.

* Result

EquityAutoDeltaHedgedOption is held natively: the hedge's terms on the equity
position row, each batch a row with its option terms, name, currency, strike,
strike currency, quantity and premium. The round-trip test reads the user
guide's example, with both premium forms and an optional strike currency, and
writes it back. The type has a builder, the catalogue routes it, and the
generator books one trade of it. The ORE engine builds the recorded trades with
no error of the trade kind; it raises an engine configuration error, because
ORE's Products example configuration names no engine for it, which the known
list holds and the valuation story owns.

The first engine run refused the trades for want of a premium a batch, which
the premium columns answer.
