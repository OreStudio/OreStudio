* Result

Accepted by the user on 2026-09-22. Snapshot: branch
=prototype/new-party-journey=; the route is =/refdata/party/new=.

- *Same journey page* as the tenant journeys: Find the legal entity →
  Describe the party → Review → Provisioning → Next steps.
- *Find*: search GLEIF by name or LEI; results show country, LEI and
  parent; "It has no LEI: add it by name" is the manual path.
- *Describe*: a short name (from the legal name) and the *accounts
  that work in it* -- the account-party association, now in the IAM
  glossary. The tenant admin is ticked by default.
- *No data choice*: counterparties are tenant-wide; a party's bundles
  come from the tenant's seed profile. The Qt wizard's dataset-size
  question is gone.
- *Provisioning*: create, activate, publish essential data, link
  accounts, complete; resume on failure as in the tenant journeys.
- *Next steps*: switch to it, set up its books, add another party.

Onboarding (first sign-in) is covered by the first run journey.
