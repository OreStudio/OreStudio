#+brief: A key that a product carries so the sensitivity configuration can set its own shifts.
#+entity_singular: sensitivity_template

#+entity_title: Sensitivity Template
#+created: 2026-10-21
#+updated: 2026-10-27

A sensitivity template is a key. The pricing engine configuration puts it on a product with the setting SensitivityTemplate. The sensitivity configuration gives shift sizes and shift schemes to the products that carry the key. The key names an asset class and a method, for example IR_FD, and the row states both of them in the two forms ORE uses: the token a key carries, and the words a person reads.

The key's spelling is the tenant's. ORE resolves a template key by looking up the key the sensitivity configuration states, and a configuration may state a key that ORE's own list does not hold, so a tenant can add a key of its own. The table therefore holds every row to the metadata it states and does not hold the key to a shape built out of it.

** method_code
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:nullable:     false
:END:

The method as ORE spells it in a template key: Analytical, Semianalytical,
FD, MC or Trade. The generated key encodes it, as in =IR_FD=, and so does the
key a tenant writes. It says which shift scheme ORE applies, so a screen can
read it without reading the English of =method=.

#+begin_src cpp :name generator
[&r]{
    if (r.method == "Finite difference")
        return std::string("FD");
    if (r.method == "Monte Carlo")
        return std::string("MC");
    if (r.method == "Trade level")
        return std::string("Trade");
    return r.method;
}()
#+end_src

** Checks

Domain constraints beyond the standard temporal, natural-key and nil-uuid
checks the template emits on its own. A text key column already rejects the
empty string, so the template emits the code's own check and no row here
repeats it.

The pair of =method= and =method_code= is checked, and nothing else is: the
key is not held to =asset_class || '_' || method_code=. ORE resolves a
template key by looking up the key the sensitivity configuration states, so a
tenant may register a key ORE's own examples do not hold. What must be valid
is the metadata each row states, not the spelling of a key a tenant chose.

| expression |
|------------|
| "asset_class" in ('IR', 'FX', 'EQ', 'COMM', 'CR', 'ALL') |
| "method_code" in ('Analytical', 'Semianalytical', 'FD', 'MC', 'Trade') |
| (method, method_code) in (('Analytical', 'Analytical'), ('Semianalytical', 'Semianalytical'), ('Finite difference', 'FD'), ('Monte Carlo', 'MC'), ('Trade level', 'Trade')) |
