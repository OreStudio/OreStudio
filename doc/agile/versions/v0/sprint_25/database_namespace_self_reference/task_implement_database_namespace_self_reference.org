* Acceptance

- ores.database compiles on Windows MSVC with /WX and no C4515 warning.
- The codegen templates omit the self-referential using-directive for the database component and leave all other components byte-identical.

* Plan

The two failing files are generated from the =database= codegen component,
so fix the root cause in the templates and correct the two generated files
by hand, because the stale =database_info= model cannot regenerate them.

1. Guard the four template sites that emit
   =using namespace ores::database::repository;= with
   ={{^component_is_database}}=.
2. Expose =component_is_database= on the entity models in
   =projects/ores.codegen/src/codegen/core.py=.
3. Re-tangle the two =.mustache= files from their =.org= sources.
4. Remove the redundant using-directive from the two generated =.cpp= files.

* Notes

Root cause: both files open =namespace ores::database::repository= and then
pull in that same namespace with =using namespace ores::database::repository;=.
MSVC reports C4515 ("namespace uses itself") and =/WX= promotes the warning to
the error C2220. The directive is redundant, so removing it changes no
behaviour.

Only these two files are affected. The other generated repository and mapper
files use a different enclosing namespace, e.g. =ores::refdata::repository=,
so the same directive there is not self-referential.

The templates keep the directive for every component except =database=, so
all other components keep byte-identical output. Verified by regenerating
=ores.refdata.asset_class_code= (no diff) and by rendering the guarded
template with a =database= component (directive omitted).

The =database_info= model fails current validation (missing =:subcomponent:=
and no =:primary_key:= column), so codegen cannot regenerate the two files.
The hand edit matches exactly what the guarded template now emits.

Build check: =compass build ores.database.lib= is green on the local preset.
