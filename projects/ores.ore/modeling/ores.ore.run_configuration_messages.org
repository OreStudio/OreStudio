#+title: ores.ore.run_configuration_messages
#+description: Codegen operation model for importing a run's configuration into a report definition and exporting it back: the files of an ORE input directory travel inline, and the service stores them through the run store under the caller's session.
#+type: ores.codegen.operation
#+component: ore
#+subcomponent: api
#+entity_singular: run_configuration
#+namespace: ores::ore::messaging
#+brief: Import and export a report definition's ORE run configuration.
#+filetags: :model:operation:ore:
#+created: 2026-10-04
#+updated: 2026-10-04

A report definition's configuration is an ORE input directory: the run document
and the configuration documents it names. These messages carry that directory's
files inline, since configuration documents are small.

The import is a workflow saga. The client request starts it; the execute step
maps the files and stores each document through the component that owns it,
under the caller's delegated session, so the party is the caller's; on failure
it deletes what it stored. The export reads the documents back through the same
owners and returns the files. The ORE service never touches another component's
tables.

* Physical space

The shell commands are switched off for the same reason as the ORE import's: the
component has no part under =projects/ores.shell=. The hand-written =ore= menu
reaches them through its =import-run= and =export-run= verbs.
