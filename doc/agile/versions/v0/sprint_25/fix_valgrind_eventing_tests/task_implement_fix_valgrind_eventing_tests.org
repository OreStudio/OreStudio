* Plan

1. Classify the CDash dynamic analysis failures: all 54 records (21
   per component) are still-reachable blocks from the NATS C library's
   one-time global init (nats_openLib: dispatcher pool, mutexes,
   conditions, thread structs), reached via
   =ores::nats::service::client::connect()=. Not a leak: the library
   holds live pointers and frees them only in =nats_library_cleanup=,
   which the client layer must not call (global teardown is unsafe
   while other subsystems may still use NATS). CDash flags them only
   because CTest.cmake passes =--show-reachable=yes=.
2. Add one suppression per allocation site to
   =build/valgrind/custom.supp=, =match-leak-kinds: reachable=,
   anchored on =fun:nats_openLib= so any real leak through another
   call path still surfaces. Intermediate frames use =...= (the local
   run showed three stack shapes: allocator direct under
   =nats_openLib=, allocator via =nats_initDispatcherPool=, and pool
   growth via =_growPool=).
3. Create the =How do I fix valgrind errors?= recipe with compass add,
   listing the suppression file path and the triage procedure.
4. Verify locally: run the three failing eventing test cases under
   valgrind with the nightly's exact options and the suppression file,
   NATS server running (port 20605); confirm zero remaining records.
