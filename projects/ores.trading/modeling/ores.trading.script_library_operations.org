#+title: ores.trading.script_library_operations
#+description: Codegen operation model for reading the versions of the script library that a run's trades name.
#+type: ores.codegen.operation
#+component: trading
#+subcomponent: api
#+entity_singular: script_library_operation
#+namespace: ores::trading::messaging
#+brief: Reads stated versions of the script library.
#+filetags: :model:operation:trading:
#+created: 2026-11-22
#+updated: 2026-11-22

A scripted trade records the version of the library script it was booked on:
the tenant that holds the script, its name and its version. A run writes the
library the engine reads from those versions, and only trading can read them,
because the script tables are trading's. So the packaging step states the
versions its trades name and trading returns their rows.

A version is the script's row at that version together with every row beneath
the script that carries it as its script version. A stated version the store
does not hold is returned as missing rather than refused, so that the caller
can name each one in the failure of its run.

The handler stays hand-written beside this model, because an operation model
generates no service handler.
