* Goal

compass-ng generates the code and runs the build-free gates for every environment, for CI and for external developers. ores.codegen regeneration and the ported Python gates are removed only after the two tools give the same verdicts on the same commit.

* Acceptance

- A recorded comparison lists every disagreement between compass check and local_checks.py on one commit, with its cause and which side is right.
- compass check reports nothing on main: the real drift is regenerated, and each baseline entry is an inline exception.
- ./compass.sh check runs compass check for the ported gates, and runs Python only for the gates compass does not cover.
- compass generate replaces regenerate --all and the ores.codegen regeneration verbs.
- CI runs compass check --ratchet from a pinned compass release, and the ported Python CI workflows are removed.
- Every environment and every external developer installs a pinned compass release with one documented command, and bearings reports a missing or out-of-date binary.
- The Python gates and generators that compass replaces are deleted, together with their baseline files.

* Decisions

- Replace one area at a time, and only after the two tools agree on the same commit; keep the Python gate for any rule where they differ.
- compass-ng bugs go to the compass repository; ORE Studio does not work around them.
- CI and external developers install a released, pinned compass-ng; nobody builds it from source to use it.

* Out of scope

- HTML site export: compass-ng does not export HTML yet; the Emacs site export and site-page stay.
- The document verbs of the Python compass (bearings, where, search, story, task, journal, env, db, services, pr): compass-ng has no replacement yet; the compass repository's Retire legacy tooling story tracks them.
- Building and publishing compass-ng binaries and its CDash dashboard: compass repository stories Publish installable binaries and Report builds and tests to CDash.
