* Goal

The system administrator's home answers "is the installation healthy" in one
place. Its *System health* panel counts tenants alone today: in service, on
evaluation, setting up, and those that need attention (the =home.system= keys
in =ores.web=). The panel splits into sections, one per kind of thing that can
be unhealthy: *Tenants*, as now, and *Services*, from the services roster. The
services section states how many expected instances are running, and names
the ones that are lost or missing, with a link to the services screen. Further
sections, such as the compute grid or the message bus, can join the same shape
later.

* Acceptance

- *System health* on the system administrator's home has a *Tenants* section
  and a *Services* section, each with its own summary line and its own
  attention list.
- The services section reads =telemetry.v1.services.roster= through a BFF
  route, states running instances against expected ones (for example
  /20 of 21 running/), and lists each lost or missing service by its display
  name, with a link to the services screen.
- When the roster cannot be read, the section says so, and the tenants
  section still renders.
- Every new string is in each locale the web client carries, and the home
  page tests cover both sections, including an unreadable roster.
