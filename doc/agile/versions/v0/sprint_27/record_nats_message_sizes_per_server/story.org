* Goal

The Session activity tab has no series to draw: ores_iam_session_samples_tbl exists with bytes_sent, bytes_received and latency_ms per session and sample time, and nothing writes a row to it. This story measures the size of every NATS message that a server receives and sends, keeps running totals in memory for each server, and writes them to the database at a fixed interval. The write must not slow the message path, and a failed write must not refuse a message. Open question for the first task: 'per server' may mean each service process that connects to NATS, or the NATS server itself. The answer decides whether the totals key on the session, the service instance, or both, and whether the existing sample table is enough or a second table is needed. The first task settles that and records the choice in Decisions.

* Acceptance

- The size of every NATS message a server receives and sends is counted, with no message missed or counted twice.
- The totals reach the database at a fixed interval, and the interval is a setting.
- A failed or slow write never delays or refuses a message.
- The Session activity tab draws the series from the samples, and states no series only when none exist.
- The answer to what 'per server' means is recorded in Decisions.
