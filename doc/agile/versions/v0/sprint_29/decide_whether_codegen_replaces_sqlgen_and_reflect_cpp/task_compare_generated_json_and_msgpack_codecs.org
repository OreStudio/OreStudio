* Acceptance

- A generated codec for one real response type encodes JSON and MessagePack
  byte-identical to reflect-cpp, and decodes reflect-cpp's output to the same
  value.
- Each operation has a time per message and an allocation count, for a small
  and a large message.
- Each codec's translation unit has a compile time and a peak memory.
- The time each codec spends is split between the codec and the per-field
  conversions both share.

* Plan

The type is =ores::dq::messaging::list_change_reason_categories_response=: a
=result= with its =field_failure= list, a vector of =change_reason_category=,
and a total. It holds every wire shape the control plane uses: strings,
integers, an enum by name, a =tenant_id= and a =time_point= as strings, nested
objects and arrays. The benchmark is in =evidence/codec_bench/=.

- =reflected_codec.cpp= calls =rfl::json= and =rfl::msgpack= with the project's
  reflectors, as =ores::nats::wire_codec= does.
- =generated_codec.cpp= is the code the generator would emit: one function a
  type and a format, in the field order of the struct, over yyjson and
  msgpack-c. It makes the same library calls as reflect-cpp, so the bytes
  match, and it refuses a message that lacks a required field.
- =main.cpp= proves the identity on a list of 1 and a list of 100. The text
  holds a quote, a backslash, a tab and non-ASCII letters, so the check covers
  escaping. Then it times each operation, median of 7 runs, and counts C++
  allocations.
- =conversions.cpp= times the per-field conversions both codecs share.
- =build.py= compiles each codec as its own unit with the release flags.

* Notes

** Where the time goes

Both codecs convert each =time_point= and each =tenant_id= through the same
functions. For a list of 100, those conversions cost about 77.5 µs to encode
and about 101 µs to decode: 82–91% of the generated codec's time, and 55–82% of
reflect-cpp's. With that shared cost taken out, the codec work alone compares
as below. These figures are a subtraction of medians on a loaded machine, so
they are estimates.

| Codec work for a list of 100 | reflect-cpp | generated | Ratio |
|------------------------------+-------------+-----------+-------|
| JSON encode                  | 16.5 µs     | 7.6 µs    | 2.2×  |
| MessagePack encode           | 44.2 µs     | 12.6 µs   | 3.5×  |
| JSON decode                  | 73 µs       | 44 µs     | 1.7×  |
| MessagePack decode           | 78 µs       | 27 µs     | 2.9×  |

So a generated codec is 2–3.5 times faster than reflect-cpp at its own work,
but a message that carries timestamps sees only 1.1–1.9 times, because the
timestamp conversion is most of its cost. A timestamp takes 760–960 ns to
format or parse; a fixed-format ISO 8601 writer and reader would take tens of
nanoseconds. That is the larger lever for message speed, and it helps both
codecs. It is outside this story, so it goes to the backlog.

** Allocations

The generated decoder allocates about 9% less: 1,104 against 1,214 for a list
of 100. Most allocations in both are the strings of the decoded value, which
neither codec can avoid while the domain types hold =std::string=.

** Compile cost

The reflect-cpp unit takes three times as long to compile as the generated
unit, and 2.2 times as much memory. This repeats the result of the
translation-unit task: the build-time gain of generated codecs is larger than
their run-time gain.

- MessagePack has no schema language: the entity models are the schema, and the
  generator writes msgpack-c packer and unpacker calls for each type in its own
  =.cpp=. No intermediate schema is generated or compiled.
- reflect-cpp packs a struct as a map keyed by field name, and the TypeScript
  side (=@msgpack/msgpack= 3.1.3 in =wire-protocol=) decodes those maps into
  objects. Keeping maps keeps the wire byte-compatible; arrays by position are
  smaller and faster but break compatibility and tie readers to field order.
  Measure both, and let the decision task settle it.

* Result

A generated codec over yyjson and msgpack-c can reproduce today's wire format
byte for byte, for both formats and in both directions, so a move needs no
protocol change and no version bump. It does the codec work 2–3.5 times faster
than reflect-cpp, but messages with timestamps gain only 1.1–1.9 times, because
=datetime='s ISO 8601 conversion is 80–90% of their cost. Its translation unit
compiles three times faster in half the memory. The case for generated codecs
is build time first and run time second. A faster timestamp conversion is a
separate win for both codecs.
