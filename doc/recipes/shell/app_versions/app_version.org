#+title: How do I run the app_versions commands from the shell?
#+description: Every command the app_versions submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:app_versions:

This file documents the app_versions resource at the shell, one section per command. Every command is a subcommand of =app_versions=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: C657ABCC-7B6B-502F-921B-52DD5928041B
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
app_versions list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =compute.v1.app_versions.list=.

#+name: app_versions-list
#+begin_src ores-shell :tangle app_versions-list.ores :exports none
app_versions list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 0ADE5281-E1D8-5D9C-901E-2831DC59B32F
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
app_versions get <wrapper_version>
#+end_example

It is addressed at =compute.v1.app_versions.get=.

#+name: app_versions-get
#+begin_src ores-shell :tangle app_versions-get.ores :exports none
app_versions get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 28D1C612-F5F2-550C-81D4-949DC7A95C79
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
app_versions add <id> <app_id> <wrapper_version> <engine_version> <min_ram_mb> <reason> <commentary>
#+end_example

It is addressed at =compute.v1.app_versions.put=.

#+name: app_versions-add
#+begin_src ores-shell :tangle app_versions-add.ores :exports none
app_versions add 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: A8F14548-A8B6-5874-BF30-2ED4FE65C2BB
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
app_versions set <id> <app_id> <wrapper_version> <engine_version> <min_ram_mb> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =compute.v1.app_versions.put=.

#+name: app_versions-set
#+begin_src ores-shell :tangle app_versions-set.ores :exports none
app_versions set 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 __none__ __none__ 0 system.new_record generated_script
#+end_src
