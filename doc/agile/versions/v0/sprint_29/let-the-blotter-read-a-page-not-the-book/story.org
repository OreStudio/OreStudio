* Goal

A desk opens the blotter and has its rows in well under a second, at any size the tenant has written, and its rail states how many rows sit at each node without reading the book to find out.

The screen asks two questions, and they are different questions: give me one page of rows, and give me a count at each node. Both have their operation on main, and both still read the union view, so a page pays for each row's laterals and sorts the book to take the first hundred rows. That is what the tasks below take away.

- *The contract comes first, the store behind it.* Two new operations carry the screen: one page of rows, keyed by the sort key and the row id, and one rail of counts. They are implemented over the summary view first, so the screen's answers are correct and measurable at the size we have, and the store behind them changes when the model does. Deciding the contract before the store keeps the store replaceable.
- *The rail is counted by the store.* A count at each node is one grouped read; the client never counts rows it retrieved to draw a page.
- *A package is a trade, so there is no projection.* [[id:FC31FC9C-7A6E-4EFD-8A62-6DE4137F7160][Trade Structures and Deal Composition]] states that a structure is one deal whose legs are themselves trades, and that this tree's =CompositeTrade= is the structure. The blotter row is therefore a trade, with its own booking and state, and the union it was computed from is the defect. The projection table, its rebuild and its alarm are closed: see [[id:7C1F0E52-9A44-4B31-8E6D-2F5C7A1B9D03][The blotter lists trades]].
- *Search* is left as the summary states it today: the identifiers and the references, concatenated into one column. A trigram index waits until a search is measured to need one.
- *Flat mode* is a filter on the same rows, not a second model: the composite carries its legs and the top list filters them out.
- *The order is an index.* A page is ordered by a column of a table, compared in the column's own type, so a keyset page is a scan from the key and not a sort of the book.
- *The refactor runs before the screen is measured again.* Four tasks make a package a trade, and one makes the order indexable. The plan is [[id:7C1F0E52-9A44-4B31-8E6D-2F5C7A1B9D03][The blotter lists trades]].
- *History*: the blotter reads the current state only, as the summary view already states. As-of would make the projection bitemporal; nothing asks for it.
