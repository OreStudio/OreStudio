* Acceptance

- Every screen draws its signed-off prototype: the same rows, the same columns, the same order, in the shell's chrome.
- Each screen reads its facts from the marketdata service through the BFF; the browser derives no instrument identity, no axis order and no staleness verdict.
- Each screen states the party it reads for and what it does when the read refuses or answers nothing.
- Every screen is reachable from the market data part of the application, in the three languages the shell carries.
- Each screen has tests that assert what it shows for a stated answer, in the manner of the existing market-data screens.

* Plan

The four reads already answer from the marketdata service, so this task is
presentation: one BFF route per read, one client method per route, and one
screen per prototype.

The routes forward the typed request and return the answer as the server wrote
it; a refusal travels as the server's words. The client parses each answer into
a shape the screen can rely on, defaulting nothing the server did not send. The
screens hold their state in the address, as the existing market-data screens
do, so a row or a currency can be linked to.

What the screens add is display arithmetic only: the ladder's best quote and
its distance in basis points from the consensus, and the montage's ordering by
move. Every identity, maturity date, year fraction and staleness verdict is the
server's.

* Notes

- The generated TypeScript protocol types had drifted from the org models, so
  the four reads had no client types to call. They are regenerated rather than
  written by hand, and the same generation wrote the surface read's new
  metadata fields.
- The curve selector reads =ir-curve-bootstrap-configs=, because the analytics
  read names a bootstrap configuration and not a market instrument. The
  catalogue's instruments are the series a person reads; the two are different
  identities and the screen says which it is choosing.
- The curve analytics prototype's T-1 columns are not drawn: the read carries no
  prior close, so the screen says so instead of deriving a change.
- The ladder holds one column per provider that quotes any rung, and a dash where
  a provider does not quote one. The answer does not name the providers a party
  holds, so a column is drawn only for a provider the market shows, and the
  absent ones cannot be named.
- The ladder's window is the prototype's own control (short dates, the whole
  curve, 1Y to 10Y) applied to the year fraction the server dates each rung with.
- The finder's Enter destinations follow the published journey: a pair opens the
  FX montage of its base, a curve the curve inspector, a ladder the rate ladder,
  a fixing its observations. A surface has no page yet.
