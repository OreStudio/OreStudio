* Acceptance

- The booking records the counterparty and netting set identifiers the import resolved, pinned to the trade's counterparty and netting set.
- The export envelope's CounterParty and NettingSetId come from those identifiers, falling back to the entity's ORE alias, and AdditionalFields from trade_additional_field in order.
- Example_63, whose CP and CPTY name one bank, round trips with no in-scope loss.
- Build, ctest, pgTAP and the local check set pass.

* Plan

A lossless export needs the names the document used, not only the entities
they resolved to: =CP= and =CPTY= both resolve to JPMorgan Chase, and a trade
imported as =CP= must come back as =CP=.

- The booking gains =counterparty_identifier_id= and
  =netting_set_identifier_id=: the identifier rows the import resolved, pinned
  to the trade's counterparty and the booking's netting set. The names stay
  resolved entities, not document text.
- =ores_trading_trade_envelope_names_fn= derives each booked trade's
  CounterParty and NettingSetId: the recorded identifier, else the entity's
  first ORE alias, else its code. It runs as the owner, because the names live
  in refdata tables the trading service does not read, and holds every row to
  the caller's tenant.
- The envelope reader builds a booked trade's envelope from that function and
  =trade_additional_field=; a trade with no anchor keeps the envelope tables'
  envelope, and every trade still takes its PortfolioIds from them.
- The import stops writing the counterparty, netting set and additional fields
  to the envelope tables, so the round trip proves the new path.
- An empty =<AdditionalFields/>= or =<NettingSetId/>= needs no flag: the round
  trip classifier treats an empty element as absent, as ORE does.

* Result

An ORE export now regenerates a booked trade's CounterParty, NettingSetId and
AdditionalFields from the anchor's booking and the trade's additional fields.
The booking records which identifier the document used, so two aliases of one
counterparty each come back as the trade named them. A 16-trade portfolio
mixing CP and CPTY on NS round trips with no in-scope loss, with the envelope
tables no longer holding those fields. PortfolioIds still come from the
envelope tables until their own task.
