* Acceptance

- An ORE sample import creates its portfolios as roots of the party's sample sandbox, and its books as virtual books in them.
- The official portfolio tree of the party is unchanged after an import.
- Importing the samples into two parties lands each in its own sandbox.

* Plan

1. Add a =sandbox_id= choice to the import. The planner puts every portfolio it
   creates in that sandbox and makes every book a virtual book.
2. Run a sample import into a party's sandbox. Fix what blocks it.
3. Check the official tree is unchanged.

* Notes

*What the proof found, 2026-10-11.* The first imports failed in three places. Each
was a real defect, and each was fixed:

- *The key lookups ignored the party.* Netting sets, portfolios, books and the
  rest belong to a party, and their names are unique per party. The generated
  key finders read by tenant only. A tenant administrator sees every party, so
  the import resolved the sample netting set =NS= to another party's set, and
  the trade booking refused it. The repository template now keeps the rows of
  the session's party when it has one. 32 repositories were regenerated.
- *The import ran in the session's party, whatever =--party-id= said.* Writes
  take the party from the validated session. The shell now refuses a party that
  differs from the session's.
- *A virtual book holds only drafts, tests and hypotheticals.* The importer booked
  every trade as actual. A sandbox import now books them as =test=.

A stale =ores.shell= binary also dropped the new choice: only a full build avoids
that.

* Result

An ORE sample import with a =sandbox_id= lands in the party's sample sandbox.
Verified on a clean provision of the final code: Plc's import created its portfolios and one
virtual book in the sandbox and saved two test trades against Plc's own sample
netting set. Plc's official tree did not change (20 portfolios, 22 books).

*Not met.*

- Importing into two parties was not run. The lookups now take the session's
  party, so another party needs a session in that party. The shell has no
  command to choose one, and the staff accounts' passwords were not tried.
- No wizard or web default: the sandbox is chosen through the choices file
  (=sandbox_id=). A caller that gives none still imports into the official tree.
- The key-finder change has no dedicated unit test; the import is its test.
- Six refdata and one marketdata test fail on the provisioned database. They fail
  on INSERT validation and on leftover rows; the change does not touch either.
  Not shown to fail on main.
