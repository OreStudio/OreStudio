* Effect

The repository gains =insert(ctx, v)= and =insert(ctx, vector)=. Both write the
rows as they are, in one statement, without the claim =write= states for each
row. A claim reads the current row to stamp its version, which is one query per
row; an append-only series never edits a row in place, so it has no row to
claim, and a bulk load of a hundred thousand rows becomes one write instead of a
hundred thousand reads. =write= stays, with its claims, for the rare edit.

The value is read from the model's =* SQL ** Flags= drawer. It cannot be set
together with [[id:54EC48CE-B2B1-4A86-BFA1-7B2EB32BBDC3][current_state]]: a
current-state table replaces its rows rather than appending them, and codegen
refuses the model.

* Structural consequence

None in the table. The repository class gains the two =insert= members.

* Used by

No profile sets it. =ores.marketdata.market_observation= and
=ores.marketdata.market_fixing= set it in their models: the import and the feed
ingest loop append observations and fixings in bulk.
