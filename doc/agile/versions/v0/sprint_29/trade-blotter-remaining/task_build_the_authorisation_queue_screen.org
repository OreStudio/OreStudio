* Acceptance

- The queue groups deals by class and by state.
- A hold and a denial need a comment.
- A new version of a deal notifies the operator and does not lock it.

* Plan

The task asks for a prototype first, so this unit is the prototype:
[[proj:doc/prototypes/operations/operational-authorisation-queue.org][Work the authorisation queue]].
It draws the queue two ways — class and state as a rail, or as tabs over a
full-width table with the deal in a drawer — and it settles nothing about the
build until one variant is chosen.

The screen itself comes after that: an Operations screen over the approval
request of kind =trading.operational_authorisation=, the trade it names, and the
states the knowledge page sets. It reuses the inbox's request parts rather than
a second authorisation model, because a second one would be a second answer to
the same question.
