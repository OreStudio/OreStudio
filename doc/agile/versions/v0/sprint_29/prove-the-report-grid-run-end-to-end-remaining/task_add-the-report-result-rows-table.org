* Acceptance

- The table holds one row per tenant, party, run, priced date, subject, measure and currency, with the figure and the file it came from, and the counterparty when the engine stated one.
- The table is a TimescaleDB hypertable on =as_of=, in 30-day chunks.
- Tenant isolation and party isolation are policies on the table rather than checks in the service.
- A natural key index and an =as_of= index serve the run read and a subject's history.
- The DDL is generated from =ores.reporting.report_result_row=, and =projects/ores.sql/create/reporting/reporting_create.sql= includes it, so a database built from nothing has the table.
- The table declares no retention interval; that is recorded as an open capture rather than claimed here.

* Result

The result rows table exists and is a hypertable on =as_of=, in 30-day chunks. It
holds one row per tenant, party, run, priced date, subject, measure and currency,
with the figure, its currency, the counterparty the engine stated and the file
the row came from. Two policies confine a reader to its tenant and its party, so
the service applies no rule of its own. The natural key index and the =as_of=
index serve the run read and a subject's history.

The model emits the create and drop scripts and the reporting schema includes
them, so a database built from nothing has the table. The table keeps its rows
indefinitely: it declares no retention interval, and this environment runs no
Timescale retention job.
