* Acceptance

- The initial administrator carries the full name Super Admin, and the administrator a provisioning run creates carries Tenant Admin.
- The home greeting shows the full name when the account holds one and the username otherwise.
- One helper computes the name a surface shows, and the shell, the greeting and the people lists use it, so they agree.
- No surface shows an empty name.

* Plan

The name rule lived in fifteen places, so it went into one helper and
every surface was migrated to it. The decisions in the order they were
made:

- One helper, =displayName= in
  =projects/ores.web/packages/web/src/access/names.ts=, computes the
  name a surface shows. Its account parameter is structural
  (={ readonly fullName: string } | null | undefined=), so the identity
  form can pass its own draft without the helper knowing about drafts.
- The greeting takes =self=, the signed-in person's own account, as a
  =HomePage= prop, wired in =AppRoutes= from the shell's own read, so the
  fallback is testable on the greeting's own surface rather than only
  through the shell.
- The initial admin function gains =p_full_name text default 'Super
  Admin'= as the fifth parameter, after the already-defaulted actor. The
  bootstrap handler's four-argument call keeps working through the
  default and no caller changes. The drop file drops both the
  four-argument and the five-argument signature, because =create or
  replace= with a new signature leaves the old overload in place and
  PostgreSQL prefers the exact-arity match.
- =create_account= gains =full_name= appended after the defaulted
  =change_commentary=, so the one five-argument caller rebinds nothing.
  An empty string is what the mapper writes as NULL, which is also the
  state the fallback covers.
- Provisioning passes =tenant_admin_name=, a constant beside
  =tenant_admin_role=, with the commentary "Provision tenant: create the
  administrator", matching the call beside it.

* Notes

Where the name is missing and where it is already wanted:

- The greeting: =projects/ores.web/packages/web/src/pages/HomePage.tsx=
  passes =username= to =home.welcome= ("Welcome, {name}"), in the system
  and tenant homes. The locales are under
  =projects/ores.web/packages/web/src/i18n/locales/= (en, fr, pt).
- The shell already prefers the name:
  =projects/ores.web/packages/web/src/components/AppShell.tsx= uses
  =self.fullName !== '' ? self.fullName : username=.
- No creation path records a name:
  =ores_iam_create_initial_admin_fn= in
  =projects/ores.sql/create/iam/iam_system_provisioner_create.sql=, and
  the tenant provisioning service
  (=projects/ores.iam/core/include/ores.iam.core/service/tenant_provisioning_service.hpp=)
  both create the account without =full_name=.
- The lists compute the name in place — =TenantPeople= in
  =projects/ores.web/packages/web/src/pages/TenantPage.tsx= and
  =projects/ores.web/packages/web/src/access/PeoplePage.tsx=.
- The first-run form keeps its fields:
  =projects/ores.web/packages/web/src/journeys/FirstRunJourney.tsx=
  (principal, email, password; default principal =super_admin=).

* Result

Delivered in =54a98fdf56= and =9c21e4e36f=. The deployment's first
administrator is created with the full name Super Admin: the initial
admin function inserts =full_name= and defaults it, so the bootstrap
handler's four-argument call is unchanged. A provisioned tenant's
administrator is created with =tenant_admin_name= ('Tenant Admin'),
beside the role constant it already grants. On the screens, one helper,
=displayName=, computes the name a surface shows, and the shell, the home
greeting, the people lists, the role holders, the rescue finder and the
identity form call it, so they agree.
