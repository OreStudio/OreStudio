* Goal

A reviewer or a check can point at a rule by its identifier, and the rule has one answer. The standards no longer disagree on where Edit stands, how the dialog is titled or when Save is enabled. The form layout is specified: how fields group, which widget each field kind uses, where the buttons go, how history is laid out and how refresh behaves. The behaviour of a record screen is an Allium specification beside the prose.

* Acceptance

- Every contradiction the audit found has a decision, recorded on the page that now rules, and the losing page points at it.
- The record screen standard states the form layout rules: field grouping and order, the widget per field kind, button placement, the history layout and the refresh behaviour.
- Every rule in the record screen standard and the entity screen specification carries a stable identifier, and the Screen review checklist is keyed by those identifiers.
- An Allium specification under doc/llm/specs states the record screen behaviour: the stale and Refresh rule, the edit in progress conflict, the stale version refusal, revert as a new version, and the create and delete flows.
- The UX hub reading order reflects the settled pages.
