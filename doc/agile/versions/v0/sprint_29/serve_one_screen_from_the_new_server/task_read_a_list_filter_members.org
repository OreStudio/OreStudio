* Acceptance

- A list whose filter record states a single-valued member reads ?f.<member>= and hands the parsed value to the filter.
- A member that takes a list or a pair of bounds states no single-valued parameter.
- The parameter is documented on the route that reads it and on no other route of the unit.
- A list with no filter record reads no filter parameter.

* Notes

- The parameter is =f.<column>=, which is the BFF's own spelling, so a moved screen
  sends the request it already sends.
- Only the members the filter record models as a single value are read. A one-of member
  takes a list and a range takes two bounds, and neither is a single query value; the
  route states nothing for them rather than guessing an encoding, and the parity note
  records the gap.
- The parameter is documented inside the paged route only, because that is the handler
  that reads it; a versions read or a key read states no filter it would ignore.
- A nullable member's record wraps it twice, so the reader parses the type inside both
  wrappers; that is why the member list now states the type a parameter parses into.
