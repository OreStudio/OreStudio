* Before you start

Done before the scenario reaches you, so Step 1 can assume it:

- The branch =feature/verify-the-stored-outputs-end-to-end= is built and the
  services run on that build. It carries the fix for the orphan commodity future
  part, without which every report run fails before it stores anything.
- The database was recreated from this branch's schema and the Acme Corporation
  holding group provisioned with
  =projects/ores.shell/scripts/library/provisioning/how_do_i_provision_the_system_with_acme_corporation_holding_group.ores=.
- Group Consolidated Exposure for Acme Corporation Plc skips no family.

The checks that read stored rows use =compass sql= from the root of this
worktree, =/home/marco/Development/OreStudio/ores_dev_swift_curie=. Each command
below reads the latest run of Group Consolidated Exposure for Acme Corporation Plc,
so it needs no id copied from the screen.

story says, keyed by file and line. The NPV and SA-CCR figures and the run

in marketdata's market input table. A family the report is set to skip stores no
rows, and an unknown family name is refused.

** Check the figures by file and line

- In a terminal, at the worktree root, run:
  #+begin_src sh
  ./compass.sh sql -- -c "with latest as (select i.id from ores_reporting_report_instances_tbl i join ores_reporting_report_definitions_tbl d on d.id = i.definition_id and d.valid_to > now() join ores_refdata_parties_tbl p on p.id = d.party_id and p.valid_to > now() where d.name = 'Group Consolidated Exposure' and p.short_code = 'ACMCOR' order by i.valid_from desc limit 1) select source, family, count(*) as figures, min(line), max(line) from ores_reporting_report_metrics_tbl where report_instance_id = (select id from latest) group by 1, 2 order by 1;"
  #+end_src
- Pass: four rows.
  - =npv.csv=, family =npv=: 36 figures, lines 2 to 10.
  - =saccr.csv=, family =saccr=: 2 figures, line 2.
  - =pricingstats.csv=, family =pricingstats=: about 219 figures.
  - =runtimes.csv=, family =runtimes=: a few figures.
