Document the terms of ORE's conventions document in the one ORE parameter contract, so a convention screen reads a term's label, help, description, default and format from data, as product pricing and engine run settings do. * Acceptance

- Every term the ORE conventions parser reads is extracted with the element it belongs to, whether it is required, the type its value is parsed to, and the source line of each fact.
- Every term with a text, from the guide or from curation, is a row of =ore.parameters= keyed by =conventions.xsd= and its XPath, and no existing row changes its id.
- A term with no text is not given an invented one: the generator names it, and the gap is recorded.
- The seed gate runs when a convention source changes.

* Plan

1. Read the structure from the ORE source, not the guide: each convention class's =fromXML= names its element with =checkNode=, and each read says the term and whether it is mandatory. A read inside a branch is mandatory only there, so it is recorded as conditional. =build= names the parse function of a term, which gives its type.
2. Read the prose from the guide: each section names its element and lists "Name [Optional]: text".
3. Write the rows in a fifth row module beside the setup, block, analytic and pricing modules, with =conventions.xsd= as the schema.
4. Let a row name its schema. The default stays =ore.xsd=, so every existing row keeps its id.
5. Curate only the text the guide does not give, with a reason, a source, a source reference, a curator and a date per entry.

* Notes

- *The schema was never per row.* =ore_parameter_seed.py= wrote every row with =ore.xsd=, including the pricing rows whose XPath starts at =/PricingEngines=, so the documented key, the schema and the XPath, was not the stored key. A row may now name its schema; the pricing rows still carry =ore.xsd=, because changing them moves their ids in every tenant. That correction belongs to the pricing work.
- *The service key is the name.* =ore_parameter_service= reads a parameter by its name, which pricing already repeats across product types, and convention terms such as =Calendar= repeat it again. Nothing in the screens reads by name today; a read by schema and XPath is the fix when one does.
- *Defaults are generic.* The guide states a default for few terms. A term the guide gives none says "Not given: ORE applies its own rule." or that the convention must give it; the rule ORE applies, such as the fixed calendar falling back to the index's calendar, is in =build= and not extracted.
- *Releases are not measured.* Every convention row takes the floor the pricing rows use, =1.8.0.7 or earlier=.
- *ORE's own spelling stays.* The parser reads =OvernightLockouDays= for the BMA basis swap, so that is the element name the contract keys.

* Result

The contract now documents the conventions document. 238 of the 296 terms the ORE conventions parser reads, across 27 conventions, are rows of =ore.parameters= keyed by =conventions.xsd= and their XPath, and the seed grew from 1782 to 2020 parameters with no existing row changed.

- =extract_convention_terms.py= reads the structure from the ORE source and the prose from the guide, at ORE commit =3d75a6908=, and records the source line of every fact in =convention_terms.json=.
- =convention_parameter_rows.py= writes the rows; =convention_term_curation.json= holds the one curated text, the =Id= of every convention, with its reason, source and curator.
- 58 terms have no text. They are not written, the generator names them, and [[file:evidence/undocumented_convention_terms.org][evidence/undocumented_convention_terms.org]] lists each with the line that reads it.
- A row may name its own schema now; the =ore-parameters-seed= gate runs when a convention source changes.

The local gate passes the seed, the build, the database and the ticks smoke test. Four checks fail on what this change does not touch, as the PR records: the pgTAP XPath test, on 108 pricing code settings with no product type; the pgTAP trading suites, on the origin rule; =ores.analytics.core.tests=, on the value set trigger; and =er-diagram=, on seven warnings of the strict validator. The value sets are the next task.
