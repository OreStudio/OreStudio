* Goal

Every existing junction entity in this codebase (currency_calendar,
currency_pair_convention_calendar, currency_country, ...) has zero Qt
files: the established pattern for a many-to-many *relationship*
junction is a hand-written widget embedded as a tab in the owning
entity's own detail dialog (e.g. Currency's =CalendarAssignmentWidget=
tab), not a standalone list window. That pattern is correct for small,
user-assigned relationships and is not what this task changes.

=calendar_dates=
([[id:875E96F6-3FC7-4E0B-8E3C-2AC0F8BD488F][ores.refdata.calendar_dates]]) doesn't fit that mould: it is a large
(potentially thousands of rows per calendar, spanning a decade-plus),
read-only, server-paginated materialised fact table, not a relationship
a user assigns. Its shape is closer to the existing History dialog
facet (read-only, scoped/filtered by a parent key) than to the
assignment-widget pattern -- except History dialogs load everything at
once (a version history is small), while this shape genuinely needs
server-side pagination.

This task adds that missing shape to =ores.codegen='s Qt facet: a
client model + list dialog for a junction-backed, read-only,
paginated, parent-scoped dataset -- no detail dialog, since there is
nothing to edit. Generated for =calendar_dates= as the first consumer,
but written generically so any future entity in this shape (junction
or otherwise) can opt into it.

* Acceptance

- [ ] A new Qt codegen knob/shape exists for a read-only,
  server-paginated, parent-scoped list (client model + list dialog),
  distinct from the existing full-CRUD domain_entity shape and from
  the read-only-but-unpaginated History dialog shape.
- [ ] Generating it for =calendar_dates=, scoped by =calendar_code=,
  produces a working paginated list (offset/limit sent to the server,
  accurate total count -- respecting the fix from
  [[id:914B206F-CDB2-4CDC-80BF-0285839E514D][Fix silent 100-row list truncation on entities missing has_pagination]]) with no
  add/edit/delete affordances anywhere in the generated UI.
- [ ] Documented in the Qt facet's meta-model page
  (=entity_meta_model_cpp_qt.org=) alongside the existing knobs, so
  the next entity in this shape doesn't have to rediscover it.
