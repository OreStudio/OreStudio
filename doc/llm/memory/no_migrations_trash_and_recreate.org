Do not write migration scripts or any backwards compatibility code for schema changes. The database is trashed and recreated with compass db recreate, so a change to tables only edits the create scripts, and nothing keeps legacy names, columns or handling around.

*Why:* The operator said so on 2026-10-03, during the curve configuration table rename: do not worry about backwards compatibility, do not create migration scripts, trash and recreate, keep it clean.

*How to apply:* When a change alters tables, change the create, drop, RLS and populate scripts only, and verify with compass db recreate. Do not add files under projects/ores.sql/migration, and do not add compatibility shims, column aliases or old permission codes.
