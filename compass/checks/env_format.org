#+description: The versions and variables of the generated .env; compass env generate writes the file from these tables and compass check holds every new variable to a new version.
#+type: check

This page gives the data of compass-ng's =env_format= codec and of
=compass env=, which write and version ORE Studio's uncommitted =.env=. It
replaces =doc/knowledge/architecture/env_format_version_log.org= and the
template =env_init.py= wrote: each table below is data compass reads, and the
prose says what it is for.

* Rule

Every variable of the =.env= has a row of the Variables table, and the row
names the version that added it; that version, in the Versions table, says it
adds it. A version after the baseline adds or removes a variable, or is
marked format only.

* Why

=.env= is generated and never committed, so a variable written into it
without a new version leaves every environment's file looking current while
it lacks the variable. Nothing committed can show that file, so the table
that generates it is the only place a variable comes from: a variable added
to the table without a new version, or with an old one, is a finding of
=compass check=, and =compass env status= tells an environment whose file
is older than the table, or lacks a variable the table and the service
registry give it, to generate it again.

Record a version with
=compass env version new "<description>" --adds A,B --removes C=, which
appends the row and sets the added and removed versions of those rows. A
version that changes only values or layout, or adds a service to the
registry, which adds that service's per-service variables without a new row,
takes =--format-only=.

* Definition

* Settings

=file= is the generated file; =version_variable= the variable that carries
the version; =service_registry= the document whose entries the per-service
rows expand over; =regenerate= the command =compass env status= tells a
stale environment to run; =baseline= the version up to which versions need
not declare their variables, which is version 1: the variables the old log
never recorded are said to be added in it.

| setting          | value                                      |
|------------------+--------------------------------------------|
| file             | .env                                       |
| version_variable | ORES_ENV_VERSION                           |
| service_registry | projects/modeling/service_registry.org     |
| regenerate       | compass env configure --preset <preset> -y |
| baseline         | 1                                          |

* Inputs

What =env_init.py= decides and passes to =compass env generate= as
=--input name=value=: the choices about the machine and the checkout that
stay in ORE Studio's Python. compass also gives =checkout=, =home= and =now=.

| input               | purpose                                                                                                                                |
|---------------------+----------------------------------------------------------------------------------------------------------------------------------------|
| env_name            | The environment's name: ORES_ENV_NAME of the existing file, else the label of the checkout directory.                                  |
| label               | The name in the underscored form every database role and path uses.                                                                    |
| base_port           | The environment's base port: ORES_BASE_PORT of the existing file, else the first free slot env_init finds among the sibling checkouts. |
| http_port_offset    | 1 for a release preset, else 0.                                                                                                        |
| preset              | The build preset; empty in CI, which writes no ORES_PRESET.                                                                            |
| env_activity        | The activity number a fresh file starts at: the latest of the activity log for a new file, else 0.                                     |
| nats_subject_prefix | ores.dev. and the environment's name with each hyphen a dot, for a file that has no prefix yet.                                        |
| nats_tls_ca         | The NATS CA certificate's path, or empty when compass nats certs made none.                                                            |
| nats_tls_cert       | The shell's NATS certificate's path, or empty.                                                                                         |
| nats_tls_key        | The shell's NATS key's path, or empty.                                                                                                 |
| web_env             | The id of the ores.web environment this checkout serves, resolved from projects/ores.web/config/environments.json, or empty.           |
| db_port             | ORES_DB_PORT of an old file, the PGPORT a file had before it was named so; usually empty.                                              |

* Variables

One row per variable, in the order of the file. =kind= says how its value is
made: =value= is the argument, a template of inputs and earlier variables;
=offset= the sum of the argument's terms; =secret= a random alphanumeric
secret made once and then kept; =kept= the existing file's value, else the
argument; =inherited= the file's, else the process environment's, else the
argument; =environment= the process environment's, else the argument;
=version= the current version; =file= a file's lines on one quoted line;
=carried= every variable of the existing file whose name matches the
argument. A name holding ={service.<field>}= is written once per registry
entry that has the fields it uses, and =services= narrows it to the entries
named, or with =!= away from them. =section= and =comment= name blocks of
the Comments table, written before the row. =when= is a condition: a
template, which holds when it is not empty, or two templates joined by
" = " or " != ", which hold when they expand alike or not; the row is
written only when it holds. A variable may have several rows whose
conditions exclude each other, and the one that holds is written in its
place. A row with =removed= is no longer written.
