#+title: ores.marketdata.feed_scope
#+description: Codegen entity model for feed scopes: the items a feed fetches, per asset class, with no item in two feeds of one publisher.
#+type: ores.codegen.entity

#+entity_title: Feed Scope
#+brief: One item a feed fetches, with its asset class and the vendor instrument that carries it.
#+created: 2026-10-30
#+updated: 2026-10-30

A feed scope states what a feed fetches. Each row names the feed, the asset
class and the item, and may name the vendor instrument the supplier uses for it.
The scope is the set of rows a feed holds; a read of a feed's scope is the rows
that name it.

No item belongs to two feeds of one publisher. A publisher may have an
=end_of_day= feed and a =real_time= feed, but an item arrives through one of
them, so a party reading the item reads one feed's values and never a mixture.

** feed_id
:PROPERTIES:
:table:             ores_marketdata_feeds_tbl
:target_column:     id
:use_system_tenant: true
:nullable:          false
:skip_check:        true
:error_message:     Invalid feed: %. No active feed found in the system tenant's catalogue with this id.
:END:

The scope reads a feed from the catalogue the system tenant holds, so the
parent resolves there whatever tenant owns the scope. The invariants trigger
already refuses a scope whose feed is not in that catalogue, and it states a
better sentence than a plain existence check, so the check is not repeated
here (=:skip_check:=); the declaration is what tells the generator that a test
seeds this parent by reading the catalogue.
