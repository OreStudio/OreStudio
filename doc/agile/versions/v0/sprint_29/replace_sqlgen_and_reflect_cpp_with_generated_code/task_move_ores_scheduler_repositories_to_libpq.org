* Notes

** Hand-written code

The read_all_active paste in the job_definition model now uses the query builder. The hand-written job_instance_repository runs raw SQL through the shared helpers of ores::database::repository and includes no sqlgen; those helpers move to libpq in one place with the removal of sqlgen, so it is left on them rather than split across two backends.

** What else

The pq template opened ores::database::query_builder at namespace scope, and in a unity batch that reached job_instance_repository, whose raw helpers then were ambiguous. The template now keeps only the alias and the literals and names the builder in full.
