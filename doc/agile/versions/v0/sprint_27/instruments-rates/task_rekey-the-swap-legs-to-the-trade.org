* Goal

=ores_trading_swap_legs_tbl= is keyed by the trade and the leg's ordinal,
=(trade_id, leg_number)=, with no surrogate. A leg's identity is the trade it
belongs to plus its position on that trade, and nothing ever supplied the
surrogate meaningfully. The compound-key codegen defect that blocked the
re-key is fixed, so a generated eventing test for a key with an integer
column compiles.

* Acceptance

- =swap_leg= declares no surrogate =id=, and the generated primary key is
  =(tenant_id, trade_id, leg_number, valid_from, valid_to)=.
- A generated eventing integration test for a compound key with a non-uuid

  the column's text form.
- The import no longer mints a leg id, and the shell surface addresses a leg
  by =trade_id= and =leg_number=.

  =ores.trading.core.tests= passes.

* Plan

1. Fix the codegen defect first, because the re-key cannot generate a
   compilable test without it. =core.py= already prepares the text form of
   every key column through =_key_as_text=; it now also publishes the form
   read from a domain value, one per key column, alongside the joined form it
   already published. The eventing template uses it for the row's key, for the
   key parts it matches a notification against, and for every key argument it
   passes to the service — the last three were broken the same way and the
   capture did not record them.
2. Leave the single-column emission byte-identical. The row's key conversion
   is stated in its own branch, as it was, and the new form is emitted only
   under =is_compound=. There are 266 eventing integration tests in the tree
   and all but the compound-key ones would otherwise be regenerated for a
   comment, so the fix regenerates only the entities whose key is compound.
3. Remove the surrogate =id= from the =swap_leg= model and from its identity
   field group, and mark =trade_id= and =leg_number= as the primary key. The
   columns stay in the identity group, as they were, so the domain class keeps
   its nesting and the mapper is untouched.
4. Drop the import's leg-id mint, which is the only hand-written use of the
   surrogate.
5. Regenerate, then build and run the suites.

* Notes

- The defect was wider than the capture recorded. It named the notification
  key parts; the four key arguments the test passes to the service
  (=delete=, =get= and two =get_*_history=) were broken the same way, and the
  fix covers them because the text form is now the single source for all of
  them.
- The fix is confined to compound keys. All 266 eventing integration tests in
  the tree would otherwise regenerate for a comment, so the single-column
  emission keeps its own branch and its bytes. Four entities have a compound
  key: =swap_leg=, =ores.dq.subject_area=, =ores.inbox.notification_preference=
  and =ores.marketdata.series_classification_rule=. The other three are
  text-keyed, so their generated code was already correct and their diff is
  the comment alone.
- The notify trigger, the shell surface, the protocol key record, the list
  filter, the repository key parameters and the recipe all follow the re-key
  from the model; only the import's leg-id mint was hand-written.
- =ores.marketdata.core.tests= reported one failure on its first run, in
  =read_as_of_records_carries_the_row_record_time=: a two-second tolerance
  spanning the two inserts, which the load on the box exceeded. It passes on
  re-run, alone and as a suite. It is a timing-sensitive assertion, not a
  regression, and it does not touch any generated file.
- =swap_leg= keeps its hand-written policy in =trading_rls_policies_create.sql=
  and adds no =rls_tenant_isolation= flag, so the re-key does not duplicate it.
- The branch needed =compass env configure= first: the working copy's =.env=
  was format version 27 where the newer trunk requires 29, and every database
  command refused until it was regenerated.
