* Steps

Each step is its own heading — the title should be five to seven
words so it fits on one line in the QA Validation Runner's step list
without wrapping or truncating (e.g. "Edit and save the record", not
a full sentence describing the whole operation). The body below the
title is a bullet-point checklist, not a prose paragraph: give the
tester every piece of context needed to execute that one step without
looking anything up elsewhere — what UI state must already exist,
exactly what to click or type, and exactly what confirms the step
passed. The panel writes each step's PASS/FAIL/PENDING outcome and
notes back as a =*** Result= child heading directly under it.

** Connect to tenant Barclays Plc

Log in as =tenant_admin@barclays_plc= / =Secure-Password-123= and
select *BARCLAYS PLC*.

** Open IR Curve Generation Configs

- Menu: Market Data > Synthetic > Configuration > IR Curve Generation
  Configs.
- Confirm a list window opens showing the configs seeded by
  provisioning (=price_source= = fixed, since these came through the
  DQ-publish path).

** Add a fixed-price-source config

- Click *Add* to open =IrCurveGenerationConfigDetailDialog=.
- Fill currency/index/process type as usual; set *Price Source* to
  =fixed=, leave *Vintage Source*/*Vintage Date* blank, set an
  arbitrary *Initial Rate* (e.g. 0.03).
- Save.
- Confirm the row appears in the list and the detail dialog reopens
  with the saved =fixed= price source and the exact initial rate
  entered — nothing is resolved from a real observation for this
  config.

** Add a vintage-price-source config

- Click *Add* again.
- Set *Currency* = =USD=, *Index* = =USD-LIBOR-3M=, *Process Type* =
  =VASICEK= (mirrors the seeded =synthetic.ir_curve_configs.ore_samples_2016=
  USD-LIBOR-3M config, whose real DEPOSIT-tenor observation is seeded
  by the =marketdata.ir_deposit_rates= dataset).
- Set *Price Source* to =vintage=, *Vintage Source* to
  =ore.samples.2016-02-05=, *Vintage Date* to =2016-02-05=. Leave
  *Initial Rate* as any placeholder value (e.g. 0.05) — it is not used
  when =price_source= is =vintage=.
- Save. Confirm the row appears in the list with =price_source= =
  =vintage=.

** Start the vintage-mode feed and verify resolution

- Select the vintage config row and start its feed (auto-start toggle,
  or the feed control action used for on-demand start — whichever the
  UI exposes).
- Confirm the feed starts successfully and its resolved =initial_rate=
  is *0.007961* (0.7961%, the real 3-month USD LIBOR rate on
  2016-02-05 from ORE's own bundled Legacy/Example_56 sample data) —
  not the placeholder value entered in the dialog. Check the feed's
  status/detail view or the service log for the resolved starting
  rate.

** Start a vintage config with a missing observation

- Add (or edit) a config with *Price Source* = =vintage= but a
  *Vintage Source*/*Vintage Date* combination that has no matching
  imported observation (e.g. a currency/index not in the seeded
  dataset, or a nonsense date).
- Attempt to start its feed.
- Confirm the start fails with a =vintage_data_missing_error= (or its
  surfaced error message) that names the missing
  currency/index/source/date, rather than silently falling back to a
  default rate or crashing.
