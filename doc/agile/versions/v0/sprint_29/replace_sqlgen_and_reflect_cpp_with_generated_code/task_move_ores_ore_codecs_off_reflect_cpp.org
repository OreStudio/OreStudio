* Notes

** The conventions path carries untyped data

Questioning =run_configuration_operations.cpp= before replacing its
=rfl::Generic= use showed that the conventions code drifted from its design.
The stage message carries each row as a JSON string, the export reads each
family untyped with a hand-built request and a party filter in ores.ore, and
the package inside ores.ore holds rows as JSON strings. The bundle docs say a
bundle's rows never sit in a message field. Four tasks on
[[id:60EDB576-96B3-433A-9CDA-9FA70CEE20ED][Import and export conventions without a document aggregate]]
make each part typed, so this task leaves =run_configuration_operations.cpp=,
=conventions_family_pack.hpp=, =conventions_diff.cpp= and
=conventions_family_cross_currency_fix_float.cpp= on reflect-cpp.

** What else keeps reflect-cpp

- =report_package_handler.cpp= reads =prepare_ore_package_request= and writes
  =prepare_ore_package_result=, which belong to reporting and have no codec
  until reporting's own task.
- =nats_call.hpp= keeps the reflectors, because it calls analytics and
  reporting, whose types still fall back to reflect-cpp.

** The import choices travel as a JSON string

=ore_import_request= and =ore_import_execute_request= carry the choices as
=import_choices_json=. The capture
=carry-the-ore-import-choices-as-a-typed-member= owns making the member typed.
The choices now have a codec, so that change needs no new one.

** The api part was header-only

=ores.ore.api= was an INTERFACE library, so the generated protocol codecs were
never compiled and the first build failed to link. Its model no longer
declares it header-only.

* Result

ores.ore's messages encode and decode without reflect-cpp. Its five models use
the generated codec, its workflows and handlers read and write through it, and
the import choices have their own codec. The bytes match reflect-cpp's. The
acceptance that nothing in ores.ore includes reflect-cpp is met only in part:
the conventions path waits on the conventions redesign, the reporting package
messages on reporting's task, and =nats_call.hpp= on the components it calls.
