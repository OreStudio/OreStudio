* Acceptance

- The tree builds and every suite passes.

* Plan

The router published a schema with =rfl::json::to_schema=, so a route's schema
and the bytes it reads were two statements of one shape. The shape the codec
walks is =wire_fields=, so the schema is generated from it: a member's type says
whether it is a string, a number, a truth, a list, a map or a nested object, an
optional member is not required, and an enumeration names the text each of its
values has.

* Notes

**Two statements, one shape.** The schema generator walks the same
=wire_fields= the encoder does, so a member cannot appear in the schema and be
absent from the bytes. A member that is not optional is required, because the
reader refuses a document that leaves it out.

**Why the protocol headers moved.** A message's own shape is stated in its
protocol header, but the shapes of the rows it holds live in their codec
headers, and the header named only the plain domain header. The template now
includes the codec header where the message has a generated wire codec, which is
what lets the schema describe a list of rows rather than a list of objects.

**What a schema cannot yet state.** A type whose shape header is not in view
where the message is named renders as an object with no members: valid, and
less than the truth. Every component's protocol headers were regenerated, and
the one that a component's regeneration lagged behind is stated as an object
until its own regeneration catches up. The generator's comment says so.

* Result

No file calls =rfl::json::to_schema=. The router's request and response schemas
are generated from the wire shapes: each member's type, the members the reader
requires, and the text an enumeration carries.

The whole tree builds, and the seven http suites pass, which is what exercises
the router's schemas. The utility suite carries the generator's own cases: a
member per kind, an enumeration's text, and the required list that leaves an
optional member out.

The task page keeps one limitation: a type whose shape header is not visible
where the message is named renders as an object with no members rather than as
a schema that would be wrong. The template change that names the codec headers
closes it for the components that regenerate, and the fallback keeps the rest
valid until they do.
