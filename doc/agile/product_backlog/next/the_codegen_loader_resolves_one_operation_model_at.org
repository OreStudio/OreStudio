#+title: An operation model cannot reference a sibling model's message in TypeScript
#+description: The codegen loader resolves one operation model at a time, so a message declared in one operation model cannot be referenced from a second model in the same component. The C++ side compiles only because the model's Includes block names the sibling header by hand; the TypeScript projection has no equivalent and emits the bare PascalCase name, so tsc fails with TS2304 'Cannot find name'. Hit while modelling the ORE import protocol as a client-facing and an engine-facing model that shared ore_import_item_error; resolved by merging them into one model, which is also the better shape since they share a payload. The general fix is a component-wide message registry so the TS template can emit 'import type { X } from "./sibling_protocol.js"', and a check that every generated .ts resolves every referenced interface.
