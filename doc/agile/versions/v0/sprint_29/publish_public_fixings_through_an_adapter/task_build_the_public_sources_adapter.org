* Acceptance

- The adapter announces each public source, answers its demand set and sends a heartbeat.
- The Frankfurter fetcher asks for one provider at a time and never for the blended rate, and is tested on stored responses, a missing day and an empty range included.
- On start it backfills the window for each demanded item oldest first, then polls each provider once a day after its publication time.
- The Frankfurter address is a setting.
- A run against the hosted API stores fixings for several providers of one pair. (Moved on 2026-10-28 to the catalogue task, which supplies the sources and mappings a live run needs.)

* Notes

- The part is =ores.marketdata.official=, not =public=: =public= is a C++ keyword, and
  codegen generated =namespace ores::marketdata::public=, which does not compile.
- The adapter reads no catalogue. It announces what each publisher quotes, and the
  service's demand set says what to send.
- A rate is written as the shortest text that reads back to the published number,
  because Frankfurter sends JSON numbers. That keeps the published digits except a
  trailing zero.

* Result

=ores.marketdata.official= is a new part of the marketdata composite: a process with
no database that speaks the adapter contract for official rates. Each hosted source,
given as =<source>:<provider>:<Frankfurter key>=, reads its universe from
=/v2/providers=, announces it, answers its demand set from it, sends a heartbeat,
backfills a window of rates on a new demand, oldest first, and then polls; each rate
becomes a fixing tick stamped at midday UTC of its date. It asks Frankfurter for one
provider at a time and never for the blend. A demand is answered on the bus's thread
from the universe alone, and one source at most reads Frankfurter per pass, so a long
backfill never delays a reply or another source's heartbeat.

Evidence: =ores.marketdata.official.tests= passes 6 of 6 on responses captured from
Frankfurter on 2026-10-28: the parsing of rates and providers, a refused malformed
response, a fetch that names one provider, a source that sends its demanded currencies
once and then only what is new, and its announce. The process starts and prints its
options. A live run needs the catalogue of the next task.
