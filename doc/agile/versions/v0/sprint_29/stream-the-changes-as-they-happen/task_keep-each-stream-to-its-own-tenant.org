* Goal

A stream shows a caller its own tenant's changes and the system tenant's, and nothing else. A client that disconnects leaves nothing behind. The hub has no timer it could cancel after the fact.

* Acceptance

- A frame for another tenant is never written to a stream, and a frame for the system tenant is written to every stream.
- A stream whose source is destroyed leaves the hub, so its queue and its copy of every frame do not outlive the client.
- The waker holds the timer it cancels by shared ownership, so a cancel after the read ended is a no-op and not a dangling call.
- A case proves each of the three without a broker, and the stream's own cases still pass.

* Plan

- A subscription states the tenant it was opened for. The hub holds the system
  tenant, and a publish gives the frame to a stream when the frame's tenant is
  the stream's own or the system tenant's. Filtering happens before anything is
  queued, so another tenant's frame never enters a queue at all.
- The route reads the caller's tenant from =authenticated_user= and passes it to
  =subscribe=. A caller with no tenant in its claims hears only the system tenant,
  which is the safe default rather than a wildcard.
- The stream source closes its subscription in its destructor. The hub keeps its
  own reference, so without this a stream that ended stayed in the hub for the
  life of the process and kept receiving frames.
- The keep-alive timer is held by =shared_ptr= and the waker captures that, so a
  cancel that lands after the read ended touches a live object and does nothing.
- The feed is a =shared_ptr= and the registrar's handler captures it by value,
  because the handler outlives the frame that built it.
