* Acceptance

- The compass suite passes with a read-only home directory.
- The IAM pgTAP suites pass on a freshly rebuilt database, with nothing
  provisioned beforehand.

* What was actually wrong

** The compass suite wrote outside its working directory. The persona cache
was rooted at =Path.home() / ".cache" / "ores-personas"=, so
=prepare_profile= chmod'd the user's home. A sandbox makes that read-only, and
two tests died on the chmod. A tool that writes outside its working directory
cannot run in a sandbox at all, so the cache now lives under the checkout.

** Four pgTAP suites needed a tenant that nobody provisioned. They searched
for "a tenant that people set up" and found none, because provisioning is a
runtime act and the gate only rebuilds the database. The failure then
cascaded in a way worth recording: with nothing found, =t_other= was empty,
=set_config('app.current_tenant_id', ...)= set a NULL tenant, and row-level
security stopped restricting. That is why the seed profile suite appeared to
show a tenant deleting every seed profile, and why the counts were zero. The
suites were failing on their missing fixture, not on the policies they test.

Note that the gate's own comment claimed the corpus was self-sufficient --
"every suite writes the reference data it reads and rolls it back" -- and that
was true of 48 suites and false of these four.

* Decisions

- The persona cache moves rather than the tests being patched. Pointing each
  test at a temporary directory would have hidden the real defect: a tool that
  writes to the user's home cannot run in a sandbox.
- The pgTAP suites provision their own tenant instead of the gate provisioning
  one. Provisioning through the application needs a running fleet, which a
  database check must not require.

* Out of scope

- The other paths that leave the checkout are deliberate and stay:
  =~/.config/systemd/user= holds the user units =compass services= installs,
  =~/.claude= receives deployed skills, and =/tmp/ores-build.lock.*= is
  host-wide on purpose so two worktrees cannot build at once.

* Result

Both checks pass, and they pass for reasons that hold anywhere.

The persona suite runs as the gate runs it, with no writable-home workaround:
398 passed, 1 skipped. Previously two tests failed on a read-only home.

The pgTAP corpus is green on a freshly rebuilt database with nothing
provisioned: 52 files, 512 tests. The count rises from 510 because the actor
suite had been aborting after two of its four planned tests.

Neither fix needed the other, and neither needed ACME.
