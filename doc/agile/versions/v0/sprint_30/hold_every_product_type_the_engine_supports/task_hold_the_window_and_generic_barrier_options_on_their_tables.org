* Acceptance

- each of the three types routes to a table of its own (one table may serve an equity
  and an fx pair that state the same element), whose columns hold every scalar term the
  element states; lists, baskets and schedules are rows of child tables or of
  the shared rows (options, barriers, underlyings, schedules)
- the projection reads and writes the element from those rows, value for value,
  and a round-trip test reads ORE's or the user guide's example and writes it back
- the builder states the rows, and the generator books the element form
- the class-read entry for the type is removed: the scripted instrument table
  holds no element form of it, only the generic ScriptedTrade form where ORE's
  library carries one
- the catalogue names both forms of the type where ORE carries both
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: nothing is held as text

* Plan

Three tables. ORE states the window barrier in one shape for both families
(=windowBarrierOptionData2=), and only the equity generic barrier is in scope:
=FxGenericBarrierOption= is already held on =fx_barrier_option_instrument=.
=equity_barrier_option_instrument= has no column for a generic barrier's
quantity, amount, settlement or kiko type, so the equity generic barrier gets a
table of its own. One header, =barrier_product_projection.hpp=, reads and
writes the scalars.

- Window barrier: currency, fixing amount, strike, an optional strike currency
  (the =StrikeData= form) and the window dates are columns. The OptionData
  block is an option row with its exercise dates, the BarrierData an
  =barrier= row, and the underlying an underlying row, all through the families'
  shared holders. The equity table is named =equity_window_barrier_options= to fit
  the identifier budget.
- Equity generic barrier: pay currency, quantity (a double), strike, amount, the
  settlement date or lag, calendar and convention, the barrier start and end dates
  and the kiko type are columns, all optional as the schema states. The barriers
  under =Barriers= and =TransatlanticBarrier= are barrier rows; the barrier
  =ScheduleData= is a schedule row under =barrier_schedule=, as the FX generic
  barrier holds it.
- The builders move to =barrier_product_builders= and return the family's rows;
  the generator books the element form. The class-read entries are removed.
- The catalogue names =WindowBarrierOption= and =GenericBarrierOption= as the
  scripted forms, including the FX generic barrier's.

* Result

The three types are held natively: =equity_window_barrier_options=,
=fx_window_barrier_option_instruments= and =equity_generic_barrier_options=.
The scalars are columns, with the strike's currency when the document states a
=StrikeData=. The OptionData block, the barriers under =BarrierData=, =Barriers=
and =TransatlanticBarrier=, the barrier schedule and the underlying are the
families' shared rows. The round-trip test covers the FX window and the equity
generic examples, plus an equity window with a =StrikeData= strike and an
equity generic that states its settlement lag, amount and barrier window, and
checks every column and the exercise date before and after a rebuild. The
builders return the family's rows and the generator books them; the recorded
trades are unchanged. The class-read entries are removed, and the catalogue
names =WindowBarrierOption= and =GenericBarrierOption= as the scripted forms.

The first run showed that the families wrote a product's exercise dates from
the rows only for the baskets. These products keep their expiry only as an
exercise date row, so the families now write it for them too; the round trip
now checks the exercise date, which it did not before.
