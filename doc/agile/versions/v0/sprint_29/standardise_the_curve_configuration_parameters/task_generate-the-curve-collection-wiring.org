* Acceptance

- The generator emits, for each section, the collections its entries hold: the element, the table, the vector, the join column and the kind column.
- It emits, for each kind, the leaves that kind reads, with the ORE element each column holds.
- The BFF and the page read those rules instead of holding a table, and no hand-written map of a segment's leaves remains.
- A check fails when the generated rules and the projection disagree.

* Plan

#+begin_src text
1. Read the collection from the projection's own readers:
   =import_context::segment= names the row, the vector, the key back to the entry
   and the kind column; =import_quotes= names the column a quote joins by; the
   section's call to =import_segments= names the block.
2. Read the leaves each kind reads from =import_segments= and
   =common_settings=, in the order the projection reads them, so the screen
   offers a kind's leaves and not the row's columns.
3. Delete the BFF's table, its column blacklist and its column-name guess, and
   read the generated rules instead.
4. Fail the generator when a section holds a =Segments= block that its call
   pattern does not read, and when a kind reads no leaves.
#+end_src

* Notes

The three browser failures are =src/shell/cards.test.ts=, which reports
=synthetic: "Simulator" but the screen says "Synthetic"= in all three languages.
They fail on main without this change, which a stash confirmed; the fix is a
product decision, so it is recorded rather than taken here.

The leaves a kind reads are not the leaves the row has columns for. A =Simple=
segment reads =Conventions=, =PillarChoice=, =Priority=, =MinDistance= and
=ProjectionCurve=; a =FittedBond= one reads no conventions at all. Reading the
kind's leaves is what stops the screen offering a leaf of another kind, which the
QA walk recorded as a snag.

* Result

The collection wiring is the projection's. The generator reads the segment row,
the vector, the join, the kind column, the quote join and the block from the
projection's readers, and the leaves each kind reads from the projection's own
dispatch. The BFF holds no table: it reads the generated wiring, and the column
blacklist and the column-name guess that stood in for the kind's leaves are gone.

A section that holds a =Segments= block the call pattern does not read, and a kind
the parser finds no leaves for, both fail the generator instead of reaching a
screen with no rows.
