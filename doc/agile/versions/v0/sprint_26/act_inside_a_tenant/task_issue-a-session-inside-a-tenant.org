* Result

=iam.v1.ops.enter_tenant= and =iam.v1.ops.leave_tenant= are generated from the
operation model =ores.iam.tenant_session_messages= and served by
=tenant_session_handler= through =tenant_session_service=. Entering refuses a
caller outside the system tenant, a caller already inside, a caller without
=iam::tenants:impersonate= (read from the database), an unreadable id, the
system tenant, an unknown tenant and a tenant with no read permission to
carry. The token acts as the tenant's system party with every party visible,
carries only the read permissions the administrator holds, and names the
tenant it acts from in the new =acting_from_tenant_id= claim. Refresh refuses
such a token. Both events go to the tenant's own audit trail as
=tenant_entered= and =tenant_left=. No shell command is generated, because a
command would print a bearer token.

Tests: four service tests against the database (entry, read-only filter,
every refusal, exit) and a claim round trip in the security suite. The full
build is clean. The full ctest passed 86 of 89; the 3 failures were a database
older than main, and they pass on a recreated one. Live, entering Acme,
reading, leaving and the refusals passed 15 of 15, and the trail holds the
entry and the exit.
