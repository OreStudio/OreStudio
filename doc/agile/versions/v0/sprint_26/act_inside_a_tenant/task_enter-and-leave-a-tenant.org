* Result

=OresClient= enters and leaves a tenant, holding the entered tenant and the
token it entered from in one field; a lapsed tenant session returns to that
token without asking the server and throws =TenantSessionEndedError=. The BFF
serves =POST= and =DELETE= on =/api/session/tenant=, reads the session's
tenant, party and mode from the client, answers a lapse with 409
=tenant-session-ended=, and refuses every change while inside before the route
runs, except leaving, signing out and watching for changes. The tenant's screen
offers *Act in this tenant*; every screen inside carries a banner naming the
tenant and the administrator, saying it is read only, with *Leave the tenant*,
which returns to the tenant's screen. The home screen offers no change to a
read-only session.

Tests: four client cases (enter, refused entry, leave, lapse), six BFF route
cases with a stub proof of the guard, and banner, button and home screen
cases in the web suite. Live, the run in Issue a session inside a tenant
covers these routes, 15 of 15.
