* Goal

A single typedef in make_logger.hpp pulls Boost.Log's sources into 565 objects. This task holds the logger behind a small handle so the typedef stops being the reason a header parses Boost.Log, and the call sites keep using the macro they already use.

* Plan

make_logger.hpp is fifteen lines, and almost all of its cost is the three
Boost.Log includes it needs to name its one type: 1.93 s per probe against
1.10 s for the handle that replaces it, in one run at load 5.8. 604 objects
reach the header because every component's source calls =make_logger= to make
its own static logger.

(An earlier probe of the old header read 6.40 s. It was taken while the machine
was at load 48; the same-run pair above is what this task's record stands on.)

The handle:

- =ores.logging/logger.hpp= holds what a call site needs and nothing else: the
  severity constants, a =logger= class whose backend is an opaque
  =std::shared_ptr<detail::logger_core>=, the =make_logger= factory declared
  here and defined in the =.cpp=, and a =log_record= that streams with =<<= and
  writes when it goes out of scope. The same probe costs 0.67 s.
- =ORES_LOG_SEV(logger, severity)= replaces =BOOST_LOG_SEV=. The severity is a
  =severity_level= constant in =ores::logging=, so a call site's =debug= and
  =ores::logging::debug= both resolve as they did.
- =ores.logging/src/logger.cpp= keeps the backend: the Boost.Log logger, the
  channel and the one =BOOST_LOG_SEV= left in the tree.
- =boost_severity= moves into =ores::logging::detail=. Its enumerators spelled
  the same five words as the new constants, and two sets of those cannot share
  a namespace. Its users are the logging internals and the telemetry sinks,
  which extract the severity attribute from a record.

The sweep is mechanical and is kept as a script in the task's evidence: 55199
call sites across 4073 files, 4764 includes of the header, 2152
=severity_feature.hpp= includes and 2155 =boost_severity.hpp= includes. The
codegen templates carry 264 sites in 40 files and 20 model archetypes carry 99
more, so the generated tree is regenerated rather than edited.

One behaviour changes. A =log_record= formats its text into an
=std::ostringstream= whether or not a sink keeps it, because the header cannot
name Boost's record type and so cannot defer the formatting. A filtered record
therefore costs a string build where it used to cost a record that was never
formatted. That is the price of the 5.7 s, and it is written here rather than
left to be discovered.

* Notes

The sweep is the task. =ORES_LOG_SEV= and =ORES_LOG_SCOPED_TAG= replace the two
Boost macros at 57911 call sites across 7669 files, =ores.logging/logger.hpp=
replaces =make_logger.hpp= in 5000 files, and the two backend includes leave the
2263 and 2266 files that carried them only for the macro's benefit. The script
that does it is idempotent and lives in =evidence/split_logger.py=; it rewrites
the codegen templates and the model archetypes too, so a regeneration does not
bring the old spelling back.

Four things the build found that the script could not:

- Boost's scoped logger tag calls =add_attribute= and =remove_attribute= on the
  logger object. The handle has neither, so =ores.logging= gained its own
  =scoped_tag=, and the six test sites that tag a run's records use it.
- The handle's namespace was =detail=, which a file that opens its own =detail=
  and does =using namespace ores::logging= cannot then name: the
  change_stream test proved it. It is =backend= now.
- Moving =boost_severity= into =backend= moved the stream operator out of the
  argument's namespace, and argument-dependent lookup does not look upwards, so
  a record printed the enumerator's value. The operator sits beside the enum.
- The site routes mapped a level string to Boost's severity and handed it to the
  macro; they map to the domain severity now. The local store names =<atomic>,
  which it had been taking from the Boost.Log headers.

* Result

The logger is a handle of its own. =ores.logging/logger.hpp= costs 1.10 s to
parse where the Boost.Log headers cost 1.93 s, the call sites are unchanged
apart from the macro's name, and Boost.Log's logger header is reached by one
object in the whole tree instead of 604.

The log output is what it was. The 24 services start and write 19767 records
with the timestamp, the severity word, the channel and the message in the
places they were, and the generator's =[ERROR]= lines, the market data store's
=[WARN]= lines and the test listener's =Tag= attribute all behave as before. The
one line without a timestamp is the =Replica index= record, which the lifecycle
manager writes before it adds the =TimeStamp= attribute; that is not new.

The price is written down: a record is formatted whether or not a sink keeps it,
because the header cannot name Boost's record type and so cannot defer the
formatting. A filtered record therefore costs a string build where it used to
cost a record that was never formatted.
