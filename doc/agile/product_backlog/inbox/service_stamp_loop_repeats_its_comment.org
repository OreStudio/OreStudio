#+title: The service template repeats its stamp comment and reason expression once per member

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

In =cpp_service.cpp.mustache=, the =stamp_members= section of
=prepare_change= puts its comment inside the loop. A grouped entity gets
the same three-line comment once for each stamped member, five times in
=trade_service.cpp=. The loop also repeats the full reason-code expression
for each member. The comment about the version above the loop
("The version is the repository's to state") has no code below it. Move
the comment above the loop, compute the reason once into a local, and
delete or re-place the orphaned comment. Then regenerate every component
with grouped entities, using the pinned =clang-format= that CI uses.

* Why

The G04 review of ores.trading found this. G04 asks that generated code
reads like the component's best hand-written code, and that a finding is
fixed in the template. The fix changes the output of every grouped entity
in every component, so it needs a full regeneration with the pinned
=clang-format=. A newer local =clang-format= changes the wrapping of
unrelated lines, so a regeneration on such a machine is not safe.
