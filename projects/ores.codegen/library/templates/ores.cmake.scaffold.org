This page is the node for the =ores.cmake.scaffold= facet of the codegen
template library, part of the [[id:CA666722-1F34-4591-BC54-BC161BE45EB2][ores.cmake]] [[id:E7B74138-9ADA-4B4B-A983-23B3FDB55F44][technical space]]. Each archetype
below is documented, and holds its =mustache= source, in its own
linked page — this page is the facet-level summary and the routing
table to them.

* Summary

The build files a component needs to exist at all: its root =CMakeLists.txt=,
the =src/= and =tests/= targets, the =modeling/= directory's own file list,
and the two =component_files.cmake= lists the targets read.

They cannot be re-rendered over a mature component. The template states a
first-generation target, and a component's build files move past it as the
component grows: =ores.http.server='s =src/CMakeLists.txt= filters =main.cpp=
out of the library and links libraries the template does not name, and
=ores.analytics='s two parts link =sqlgen= and =ores.platform= that the
profile cannot know about. Re-rendering either discards the difference, so
they belong behind the same opt-in as the C++ stubs.

The one exception is a composite's own root, which stays in
[[id:4A3D3B2C-B4EC-46D7-BFF1-816A41896199][ores.cmake.component]]: a composite
holds no code, so its root is a fixed list of parts and does not grow.

=component_files.cmake= is maintained for every component, opt-in or not, by
=projects/ores.codegen/scripts/regenerate_cmake_component_files.py=, which
renders the two file-list archetypes here directly. Nothing else regenerates
them.

* The ores.cmake.scaffold facet

This facet is =#+default: disabled=, so a normal regeneration of a
component emits nothing from it. A component opts in, once, by adding one
line to its overview's =:PROPERTIES:= drawer:

#+begin_example
:ores.cmake.scaffold.enabled: true
#+end_example

The line is scaffolding, not configuration: it is removed together with the
files, once the component's build files have moved past the template. The
component scaffold writes it beside =:ores.cpp.scaffold.enabled: true=, so a
new component gets both.
