* Acceptance

- The codegen reads both declarations.
- A field added later is economic or not by declaration, not by default.

* Plan

The name rule lived in =ores.trading.api/domain/economic_digest.hpp=: a fixed
list of identity and audit names, an =_id= suffix rule, and a small allow-list
of =*_id= names that are external identifiers. That rule lived in code, so it
was the thing this task replaces. Two things it could not do: tell a money
field from a continuous one that shares a name shape, and tell an external
identifier from a foreign key when neither was in the allow-list.

What the task built, in order:

1. A =:economic: true= or =:economic: false= property on a column, in entity
   models and field-group models. Codegen requires a struct to declare all of
   its members or none, and refuses a value that is not a boolean.
2. Codegen writes =economic_fields_of(std::type_identity<T>)= beside each
   declared struct. It takes the type, so the digest asks it at compile time
   and a member that is not economic is never rendered.
3. =economic_digest= reads the declaration. The name list, the =_id= rule and
   the allow-list are deleted. A type with no declaration fails the build.
4. =scripts/declare_economic_fields.py= wrote the declaration once, from the old
   rule, over 51 models and 479 columns. The declaration matched the old rule on
   the 35 types the digest read at that point, before the rule was deleted, and
   on all 51 declared types afterwards.
5. The trade-type catalogue gained a =* Digest= section. =Instrument
   components= lists the rows that make up each routed instrument's shape, and
   =Shared components= lists the rows every instrument shares, with their
   readers. A new archetype, =ores.cpp.trade_type.digest=, generates
   =instrument_economic_shape.hpp= from it, and =read_instrument_digests= calls
   the generated readers instead of 22 hand-written cases.

Design choices, and what they replaced:

| Choice | Alternative | Why |
|--------+-------------+-----|
| A property on each column | A list of names per entity | The column is where a person adds a field, so the declaration is in front of them |
| All members or none | A default for the undeclared | A default is the name rule again under another name |
| An overload on the type | A trait specialisation in a shared header | The generated header is self-contained, and ADL finds it |
| The overload takes the type | Taking a value | A value forces the digest to render every member, including types such as =tenant_id= that have no canonical form |
| Shape in the catalogue | A =:shape:= property on each entity | The catalogue already owns the routing, and the shape is a property of the routing |

Found while declaring the shape: the option's exercise prices are an economic
table that the digest has never read. They are not listed, because listing them
changes what the digest covers. That is a capture, not part of this task.
