#+title: How do I run the calendar_events commands from the shell?
#+description: Every command the calendar_events submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:calendar_events:

This file documents the calendar_events resource at the shell, one section per command. Every command is a subcommand of =calendar_events=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: B2DC9F10-E0F2-5254-B7BE-AF820DDE77BD
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
calendar_events list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.calendar_events.list=.

#+name: calendar_events-list
#+begin_src ores-shell :tangle calendar_events-list.ores :exports none
calendar_events list --limit 1
#+end_src

:PROPERTIES:
:ID: 569181DF-32DF-51FB-9947-9A38CB2EBF44

** =add=
:PROPERTIES:
:ID: B81D7383-5807-5096-AFA7-E08569DD566B
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
calendar_events add <id> <calendar_code> <event_date> <diary_entry_type> <name> <description> <source> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.calendar_events.put=.

** =set=
:PROPERTIES:
:ID: 67EF5B9E-FED5-5A06-B1D7-198C403192A3
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
