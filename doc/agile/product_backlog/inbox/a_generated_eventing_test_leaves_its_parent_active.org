#+title: A generated eventing integration test leaves the parent row it seeds active
#+description: The codegen template that writes the eventing integration tests seeds a soft-FK parent row and closes only the row under test. Because a generated entity's code restarts its sequence every run, the parent left active makes a second run against the same database fail on the duplicate code. Fixing it regenerates 53 files across five components.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

=projects/ores.codegen/library/templates/cpp_nats_integration_test.cpp.mustache=
writes the =*_eventing_integration_tests.cpp= suites, and the body it writes
seeds a soft-FK parent row before the row under test. It closes the row under
test at the end and leaves the parent it seeded active.

* Why

A generated entity's code is named from a sequence that restarts in every
process, so two runs against one database produce the same codes. The parent
left active therefore makes the second run's parent write fail on the unique
code, and the suite fails on a database it has already run against once:

#+begin_example
../../../../../../../projects/ores.iam/core/tests/seed_profile_step_eventing_integration_tests.cpp:122:
failed: unexpected exception with message: 'Repository error: Executing INSERT
failed: ERROR:  duplicate key value violates unique constraint
"seed_profiles_code_uniq_idx"
DETAIL:  Key (code)=(CD_profile-2) already exists.
#+end_example

53 generated files across five components carry the seeded parent, so the fix
is one template change and a regeneration of all of them. =ores.iam.core.tests=
is where it was found: the seed profile parameter and step suites both seed a
parent profile. Closing the leftover rows by hand makes the suite pass once
more, which is the workaround, not the fix.
