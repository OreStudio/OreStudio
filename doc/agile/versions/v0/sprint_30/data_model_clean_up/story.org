* Goal

One data-oriented, consistent model of the system's persisted data. A document an external system defines, such as ORE XML, FpML or a CSV or JSON payload, crosses the boundary through a mapping and is never the shape of a table. A column holds one value, never a list or a serialised object. One thing has one model. A row names another thing by key or by oresmd identity, never by a string some other system spells.

* Acceptance

- The data-oriented design rules leave no way to persist a document tree, a list or a serialised payload as an entity model.
- The market configuration (curves, FX volatility surfaces, today's market) has one native model, and ORE XML is projected from it at the export boundary.
- Every other stored document image found on the way has a task of its own in this story.
