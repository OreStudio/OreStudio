* Result

* Result

The bond, commodity and interest rate planners state the envelope of a slot
once. =common_slot= sets the book, the counterparty, the trader, the two
identifiers, the trade date and the netting set, and =slot_count= states how
many slots a scope holds, so each planner now says only what its family adds:
the trade type, the notional and the terms. The netting set scan exists once
instead of three times, and the planner file is twenty-five lines shorter.

The extraction is known to be inert by measurement. A digest of a bond plan's
envelope, hashed, was recorded from the planner as it stood before the change;
the refactored planner produces the same value and a case asserts it. That case
also pins the determinism the interface promises, so a later edit that moves a
slot field fails a test rather than quietly changing a population.

What this does not do: the dispatch on =trade_type_code= still appears in the
planner, in the writer and in the routing table. Collapsing it needs the payload
to state the product, which touches both sides of the rate family, so it stays
its own change.
