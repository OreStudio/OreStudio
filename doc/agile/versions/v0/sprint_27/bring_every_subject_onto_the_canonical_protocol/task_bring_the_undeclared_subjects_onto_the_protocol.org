* Result

Ten subjects that no model declares are on the protocol. Each was written
where the conformance gate cannot read it, so it survived the migration:

| Was | Now | Where it is written |
|-----+-----+---------------------|
| =synthetic.v1.feed_configs.start= | =synthetic.v1.ops.start_feed= | =feed_config_protocol.hpp= |
| =synthetic.v1.feed_configs.stop= | =synthetic.v1.ops.stop_feed= | =feed_config_protocol.hpp= |
| =synthetic.v1.fx_spot.simulate= | =synthetic.v1.ops.simulate_fx_spot_paths= | =simulate_fx_spot_paths_protocol.hpp= |
| =synthetic.v1.ir_curve.preview_shape= | =synthetic.v1.ops.preview_ir_curve_shape= | =preview_ir_curve_shape_protocol.hpp= |
| =synthetic.v1.ir_curve.simulate_paths= | =synthetic.v1.ops.simulate_ir_curve_paths= | =simulate_ir_curve_paths_protocol.hpp= |
| =reporting.v1.report-definition-templates.list= | =reporting.v1.report_definition_templates.list= | =report_definition_template_handler.hpp= |
| =synthetic.v1.tick.= | =synthetic.v1.ops.tick.= | =tick_subjects.hpp= |
| =synthetic.v1.sandbox.tick.= | =synthetic.v1.ops.sandbox_tick.= | =tick_subjects.hpp= |
| =scheduler.v1.job-instance-events= | =scheduler.v1.job_instance_events.updated= | =scheduler_loop.hpp= |
| =iam.v1.ops.provision_tenant-step= | =iam.v1.ops.provision_tenant_step= | =provision_tenant_workflow.hpp= |

The five synthetic operation subjects take the reserved =ops= namespace, named
for the request message each protocol header already declares. The two tick
prefixes keep their broadcast shape -- the source name is appended at run time
-- and take =ops= for the same reason =marketdata.v1.ops.market_tick= did. The
scheduler's is a state-change announcement, so it becomes an event with the
action the grammar allows. The provision-tenant step command was already in
=ops= and only carried a hyphen.

79 occurrences across 39 files, the protocol headers, the registrars, the
tests, the protocol tables, the diagrams and the journeys. Verified at the
build, the six affected suites, and a recreated database plus the ACME
bring-up, which completes all eight steps -- =start_market_feeds= being the
step the synthetic tick subjects feed.

Out of scope, and the point of the goal: the gate still reads only a model's
=:subject:=. Widening it needs the scan to know *where* a subject is written,
so that a SQL =job_name= such as =compute.v1.reap.stale_results= and an event
base such as =trading.v1.trades_events= are not read as subjects.
