* Acceptance

- A scheduled job bootstraps and publishes each curve on its cadence, and each publish supersedes the previous one.
- The log names each curve, its as-of and its duration, and a failed bootstrap leaves the previous curve published.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

The cadence is one scheduler job for every published system curve. The
task's "config or policy states" becomes "the job states", because the
curves share one market and one cadence; a per-curve interval is a later
change if a curve ever needs a different one.

A publish is the pair provisioning already uses: =compute_curve=, then
=publish_curve= at the same as-of. The =republish_curve= operation is
not used: it writes observations but no publish record, so nothing is
superseded.

1. Add =marketdata.v1.ops.publish_due_curves=: an empty request and a
   per-curve response. The handler lists the system tenant's IR curve
   bootstrap configs and, for each one at a single =now=, sends
   =compute_curve= and then =publish_curve= as a delegated request with
   the caller's own token. It measures each curve, logs its name, as-of,
   duration and outcome, and names a failure in the response. A curve
   whose compute or publish fails keeps its previous publish.
2. Let the scheduler send an authenticated request. As built, this is a new
   =nats_request= action rather than a flag on =nats_publish=: that action
   already shapes a report trigger from its payload, and mixing an empty
   request into it would make one kind guess another's body. The request is
   the no-member body, encoded in the process wire format.
3. Grant =SchedulerService= the curve compute and publish permissions in
   the IAM role seed, so the scheduler's token passes the handlers.
4. Seed one job, =ores.marketdata.curve_republish=, every 15 minutes,
   action =nats_request=, subject =marketdata.v1.ops.publish_due_curves=.
   The job row states the cadence.
5. Prove it: tests for the sweep (publishes and supersedes, keeps the
   previous publish on a failed compute, names the failure), for the
   scheduler payload, and for the permission refusal; then fire the job
   on the provisioned environment and read the new publish, its
   supersession and the log lines.

Out of scope: per-party curves, which the story excludes; a per-curve
cadence; the market-day roll, which is captured in the backlog.

* Notes

- The first live firing, at 00:45, reached the scheduler and was refused
  =bad_request=: the =nats_request= action sent the payload's raw ={}= text,
  which the callee decodes in the process wire format. The action now sends a
  codec-encoded request from a no-member body type.
- The provisioning runs on 2026-11-13 failed with SIGSEGV in the workflow
  service, then in the shell, both around =get_workflow_steps_response=. The
  cause was stale binaries: the worktree had been rebuilt only in parts after
  the branch moved onto the workflow change, so a process built against one
  shape of =workflow_step_summary= talked to a library built against another.
  A rebuilt workflow service stopped crashing; a rebuilt shell ended it, and
  the provisioning runs have been clean since.

* Result

Shipped. A scheduler job fires =marketdata.v1.ops.publish_due_curves= every
15 minutes through a new =nats_request= action, which sends the request with
the scheduler's own service account. The sweep lists the system tenant's IR
curve bootstrap configs and publishes each one at one instant through the same
approval-gated path a person's publish takes, so each publish supersedes the
previous one. The log names every curve with its as-of and duration, and a
curve whose bootstrap fails keeps its previous publish and is named in the
response.

Acceptance:

- A scheduled job bootstraps and publishes each curve on its cadence, and each
  publish supersedes the previous one. Met: the 14:15 firing published 20 of
  20 curves and left 40 earlier set records superseded.
- The log names each curve, its as-of and its duration, and a failed bootstrap
  leaves the previous curve published. Met in part: each line carries the
  name, the as-of and the duration, and the service test names the curve whose
  bootstrap fails. That the failure leaves the previous publish in place is the
  gate's write order, not covered by a test.

The cadence is the job row's, not a per-curve column: the curves share one
market, and a per-curve interval is a later change.

Limitations:

- The sweep acts in the caller's tenant, because the repository reads through
  the request context. The seeded job's caller is the scheduler service
  account, which works in the system tenant, so a firing publishes the
  installation's curves. The system tenant auto-approves the publish; any other
  tenant raises a request and waits for a decider, and the response says so.
- The full local gate did not reach green: the =web= check fails on trunk
  because the BFF workflow-progress fixture lacks the progress members that
  #4660 added. That failure is covered elsewhere.
- The live proof ran on the rebased main, whose =acme_demo= profile no longer
  orders the surface steps. Provisioning completed cleanly there.
