* Plan

The routes fall into four groups, each a reviewable unit:

- The bootstrap and setup reads: =/api/bootstrap=, =/api/bootstrap/administrator=,
  =/api/bootstrap/complete=, =/api/tenant-setup= and =/api/registration-policy=.
  The first two run with no session and the BFF rate limits the policy read,
  which the C++ server cannot do yet.
- The roster: =/api/tenants=, =/api/tenants/{code}= (read and remove) and
  =/api/overview=. Each needs the deployment read and joins the provisioning runs.
- The reads inside a tenant: =/api/tenants/{code}/parties=, =people=,
  =accounts/{username}/sign-ins= and =images/{id}=. Each enters the tenant for
  the read alone. The parties read reuses =party_page_routes::read_page= with a
  request that carries the tenant's token.
- Provisioning: =/api/seed-profiles=, =/api/provision-party= and
  =/api/provision-tenant=.

On 2026-11-11 the task served the provisioning group first, and the other
three groups moved to [[id:6A5E392C-464E-4B9F-9E09-4ADF336D075A][Serve the tenant roster and the bootstrap routes]].

- =provisioning_routes= is a new unit in the IAM part. =GET /api/seed-profiles=
  joins each starting point with its steps and its parameters, reads the JSON
  list columns as lists, and orders the cards by their declared order and then
  by code, as the BFF did.
- =POST /api/provision-tenant= reads the body into the provision command. Each
  parameter becomes one =name=value= entry. The codec reads the parameters as a
  map, so the entries are in name order rather than the order the browser sent;
  the service reads them by name.
- =POST /api/provision-party= reads every party of the tenant to find its root,
  writes the new party under it with a random id, inactive, operational and in
  =WRLD=, and then starts the party stage. A refused write or stage is an
  answer with success false, as the BFF sent it.
- The IAM part takes =ores.refdata.api=, for the party reads and the write.

* Result

The C++ server answers =GET /api/seed-profiles=, =POST /api/provision-tenant=
and =POST /api/provision-party= at the BFF's addresses and in its shapes, and
the inventory pairs each. Tests compare the card shape exactly, read the list
columns, the tenant body and the root party, and prove the refusals come before
a forward. The other thirteen routes moved to their own task.
