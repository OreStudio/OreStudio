* Acceptance

- A decision is recorded on a result that never started. Today a late assignment ends as a client error, and the validator counts any done result toward the redundancy target, so the workunit completes with that failure as its canonical result. The decision is either that such a result does not count and returns to the queue for another attempt, or that it counts.
- A result with attempts left returns to unsent when its lease ends, and one without ends as no reply with a message that names the lease.
- A dispatch past the tenant's limit is refused and says how many jobs wait.

* Plan

- Decision on a result that never started: such a result does not count toward the redundancy target. A late submit for a result that is not in progress changes nothing (done in the earlier task), and a claim marks the result in progress, so a node that never claimed a job cannot produce a result for it.
- The reaper is a service coroutine that sweeps the ledger every 15 seconds. One statement returns every expired claim with attempts left to the queue. The entry keeps its queue time.
- A re-claim finds the result still in progress, as the lost node left it. The claim accepts that state when the entry has been claimed before.
- A claim with no attempts left (three) ends its result as Done with outcome 4, NoReply, and the message "The lease ended with no reply after 3 attempts." The entry is then removed, only if its lease still has ended, so a late heartbeat keeps it.
- The reaper rings the doorbell when it returns jobs, so idle nodes ask at once.
- The bound is a limit of 3600 waiting jobs for each tenant, checked in the dispatcher. A dispatch past it is refused and the service log states how many jobs wait. The dispatch runs after the commit of the workunit, so the refusal reaches the log and not the reply to the shell.
- Fair choice between tenants was already in the claim (fewest claimed entries first).

* Result

An expired lease now returns its job to the queue while it has attempts left, and ends it as no reply with a visible message when it has none. A tenant with 3600 jobs waiting cannot dispatch more, and the service log says how many wait. Verified on the dev grid with two claims that lost their leases.
