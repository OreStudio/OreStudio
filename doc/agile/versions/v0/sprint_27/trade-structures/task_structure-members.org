* Result

=structure_member= is keyed on the trade and is temporal, so a trade sits in at
most one structure at a time and unlinking closes the row rather than deleting
it. Its party and counterparty are copied from the structure and pinned to it,
which needed two unique keys on the structure table that this task adds.

The insert trigger holds a leg to the roles its template allows and to the
number of legs the template states for that role, with a maximum of zero
meaning no upper bound. A package rests on no template and is constrained by
nothing.

Validation was static only: four checks pass, including sql-reachability,
which is what confirms both the create and the drop aggregators name the new
files. No build, no ctest and no database run happened, so the six pgTAP cases
have never been executed and the trigger's behaviour is read, not observed.
