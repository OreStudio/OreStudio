* Result

Every pricing parameter now carries the one contract: a label, a help line, the
description from the ORE user guide, the value the examples use, the format, the
release it entered and the XPath of the leaf. 646 setting rows cover every
(type, scope, name) the guide describes, and 17 global rows cover the guide's
global section and the pseudo-currency block the ORE source reads. The release
each parameter entered is measured from the ORE release tags and kept in
=pricing_parameter_releases.json=.

The vocabulary joins the rows by (scope, product type, name), so the Product
pricing screen reads one field shape: 834 of 834 settings on the live API carry
their documentation, and the Global parameters tab reads the globals array.

One acceptance item remains: the vocabulary tables still carry the wording in
their =note= column, which the authoring journey reads. Drop it once the journey
reads the contract.
