* Result

The Install Clang step now asks for LLVM 22 instead of 20. The runner image's
MSVC 14.52 standard library refuses anything older (error STL1000 from
=yvals_core.h=), so the leg was failing on toolchain drift before it compiled
a line of our code. The workflow says why the version follows the image rather
than being a preference.

PR #4970. Workflow YAML parses and =compass check --exclude-heavy= is 10/10.

Unverified by construction: whether =install-llvm-action@v2= can fetch LLVM 22
for Windows. If it cannot, the leg fails at install rather than at compile,
which is at least a truthful failure. Pinning the runner image instead would
stop the drift recurring and is a separate decision.
