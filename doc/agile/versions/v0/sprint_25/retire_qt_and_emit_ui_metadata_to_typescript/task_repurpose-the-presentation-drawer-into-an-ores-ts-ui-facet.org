* Plan

Three commits on one branch, in this order.

** Rename the drawer

The level-2 heading =** Qt= becomes =** Presentation= in every entity
model; =*** Columns (Qt model)= becomes =*** Columns= and
=*** Icon columns (Qt model)= becomes =*** Icon columns=. The rename is
mechanical: the org parser keys off heading level, so the level-3
=*** Columns= does not collide with the level-1 =* Columns= section
that holds the SQL schema, and both are read by different functions.
The four models carrying =:ores.cpp.qt.*.enabled:= properties drop them,
because the facet they gate is gone. =org_loader.py= renames
=_parse_qt_drawer= and its helpers and moves the twelve variability
features from the =qt= namespace to =presentation=; =core.py= renames
its local =qt= bindings.

** Delete the Qt templates

=ores.cpp.qt.org=, its nine archetype orgs, and the nine tangled
=.mustache= files go, with the facet's row in =ores.cpp.org= and the Qt
scaffolding in =generate.py=. The tangle derives its file list from the
directory, so it needs no edit. =physical_space.py='s worked example
repoints at a facet that survives.

** Add the facet

=ores.ts.ui= is a facet over =domain_entity junction=, with one
archetype =ores.ts.ui.ui_meta= that writes
=projects/ores.typescript/src/{component}/ui/{entity}_ui.ts=.
=load_graph= finds it by scanning =library/templates/ores.*.org=, so
nothing else registers it. The contract
=projects/ores.typescript/src/ui-contract.ts= is hand-written from the
request's §3.3; it is the only hand-written TypeScript in the change.

The projection is =ui_meta_projection= in =core.py=. Every member comes
from the drawer's tables or the model's own tables; a member the request
does not name is not emitted, and a member with no model source is
omitted rather than invented. =generate.py= withholds the facets for a
domain entity or junction whose drawer has no =*** Columns= table.

** The derivations that are not mechanical

- =style= follows the request's §3.5 table, re-derived from the model's
  flags rather than read from the drawer's =column_style= cell.
- =lookup.collection= resolves one hop, from the =combo_domain_type= to
  the target entity's own =collection_name=.
- =displayField= is the first of =name=, =<entity_singular>_name=,
  =key_field= that the columns carry. The request does not state this
  derivation; it is inferred from its worked example.

* Notes

- =ores.presentation= names two different things: the drawer on the
  entity model, and the variability namespace the twelve presentation
  features live in. Neither is =ores.cpp.presentation=, the unrelated
  codegen facet for server-side rendering.
- The generated =style= and the C++ projection disagree on UUID and
  timestamp columns: =core.py='s C++ derivation falls through to
  =text_left= while §3.5 asks for =mono_left=. Followed §3.5, as the
  request is explicit that the generator follows it.
- =numeric_code= emits =text_left=. The request's worked example shows
  =mono_left= for that one row although it types the column =string= and
  its own §3.5 table maps a string to =text_left=. The other seven rows
  agree with the table, so the row reads as a slip.
- The request's example emits =maxLength: 2= for =alpha2_code=. No length
  exists anywhere in the models, so nothing is emitted.
- Keys are emitted, not translated: =<entityCamel>.fld<Pascal(field)>=,
  =<entityCamel>.col<Pascal(enum_name)>=, =<entityCamel>.<camel(field)>Ph=,
  =<entityCamel>.type.<value>=. The English, Portuguese and French
  catalogues live in Volga.

* Result

PR 1 of the story, on =feature/codegen-ts-ui-metadata=. The drawer is
renamed, the Qt templates are gone, and =ores.ts.ui= emits the metadata.

- All 109 entity models name their drawer =** Presentation=, and no
  =(Qt model)= heading survives in the models or in =library/templates/=
  — only in the agile backlog and history, which the change does not
  touch. The nine tangled =cpp_qt_*.mustache= files are gone with their
  facet.
- The rename did not reach the prose that cites the retired address: ten
  =** Qt: …= subsections in five entity models, the codegen pages that
  describe the facet, and three model files that name =ores.cpp.qt= in
  passing. PR 2 removes them with the trees.
- =ores.ts.ui= emits 90 =*_ui.ts= modules: refdata 63, synthetic 7,
  compute 6, iam 5, analytics 4, reporting 4, marketdata 1. A model whose
  drawer carries no column table emits nothing.
- =projects/ores.typescript/src/ui-contract.ts= holds the emitted shape,
  hand-written from the request's §3.3.
