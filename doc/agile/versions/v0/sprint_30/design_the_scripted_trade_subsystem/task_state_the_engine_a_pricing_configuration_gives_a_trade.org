* Notes

Moved here from [[id:6E4060D6-DF49-44C9-97E3-6CDB8F6954C3][Describe every product by its schema]], whose acceptance asked each form to
state "the engine its product tag prices with". Measured on 2026-11-23, that is
not a fact of a product:

- ORE chooses a native trade's engine builder from the trade's terms. A
  Swaption looks up =EuropeanSwaption= or =BermudanSwaption= by its exercise
  type (ORE 3d75a6908 =OREData/ored/portfolio/swaption.cpp=, the exercise branch
  before the builder lookup). Even where the choice does not depend on terms, the
  engine type need not be the trade type: an =FxSwap= is priced by the
  =FxForward= builder (=fxswap.cpp:62=), so its engine type is =FxForward=.
- A scripted trade is priced by the =ScriptedTrade= builder, which resolves the
  script's product tag by putting the trade's asset class in place of
  ={AssetClass}= and looks up the resolved tag
  (=builders/scriptedtrade.cpp:120=), so =SingleAssetOption({AssetClass})= is
  =SingleAssetOption(EQ)= for an equity trade.
- Of the 120 catalogued trade types other than the container, 51 share a code
  with a pricing engine type in the store; none of the 54 library scripts' product
  tags is a pricing engine type code.

So the engine is stated for a booked trade under a pricing configuration,
from the trade's terms, and the rule ORE's builders follow must be held as data
first: which engine type each trade type looks up, and on which term it depends.
The analytics service's =pricing_model_product= then gives the model and engine
of that engine type in a configuration.
