A value set governs a leaf, and a leaf is carried by a column of a table the
projection writes. The map names the leaf; this table names the columns that
carry it, so a guard can start from the row it is about to write and reach the
rule without knowing either the document's path or the parameter contract.

The row exists because the same leaf is carried by many columns: =DayCounter= is
a column of every curve family table. One map row, many columns, one rule.

The =xpath= stays here because it is the leaf's address in the document, which is
what the import and the convention screens show. The entity, the table and the
column are what the guard needs, because a trigger sees a row of one table.

** code
:PROPERTIES:

:END:

The column's code, which names the map row and the column it carries, for
example =curveconfig.xsd|DayCounter|base_correlation_config|day_counter=.

** element_map_code
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:nullable:     false
:END:

The map row this column carries. Soft foreign key to
=ores_reporting_ore_parameter_vocabularies_tbl=, whose key is
=(schema_name, element_name)= spelled as one code.

** entity_name
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:nullable:     false
:END:

The projection family the column belongs to, which is what the guard's trigger
names, for example =base_correlation_config=.

** table_name
:PROPERTIES:
:type:         text
:cpp_type:     std::string

:END:

** column_name
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:nullable:     false
:END:

** xpath
:PROPERTIES:
:type:         text

:END:

The leaf's address in the document, for example
=/CurveConfiguration/BaseCorrelations/BaseCorrelation/DayCounter=.

** position
:PROPERTIES:
:type:         integer
:cpp_type:     int
:nullable:     false
:END:

Where the column sits among the columns of its map row, counting from zero, so
the seed and a reader see the same order every time.
