This page documents a [[id:31C868B9-306E-4282-BA8C-07E647021B34][task]] in the [[id:5FFB587D-D85A-4B51-8C80-0F8D485754A7][Migrate remaining ~100 entity models from JSON to org]] story. It captures the goal, current status, acceptance, and any notes or results.

* Goal

Add the ores.sql.populate archetypes that crypto, flags, ip2country and
FPML need, plus the generator changes those archetypes require, so the
four datasets can move onto the org dataset pipeline.

The nine generic archetypes from [[id:7917CA28-A69D-4FA5-A95B-B0346C73272A][Decommission the legacy ores.codegen
bash scripts]] cover the six-file metadata core of every dataset:
catalog, dataset, dataset_dependency, tag, methodology and the
batch-execute master include. They do not cover the artefacts. Three
archetype families are missing:

1. *Image artefacts* — crypto icons and country flag SVGs. The current
   output comes from =images_generate_sql.py=, which inlines a whole
   SVG document per row.
2. *The ip2country artefact plus its TSV import* — IP geolocation
   ranges loaded from a tab-separated source file.
3. *FPML per-entity refdata* — 22 entities, a dataset plus an artefact
   each, plus the coding schemes they reference.

The archetypes also need a generator change: the payload each dataset
carries comes from =manifest.json=, whose field names do not match what
the archetypes read (=subject_area= vs =subject_area_name=, =catalog=
vs =catalog_name=, =coding_scheme= vs =coding_scheme_code=,
=source_system= vs =source_system_id=, =license= vs =license_info=,
=artefact_type= vs =asset_type=).

This task stops at the archetypes and the generator. Moving the four
datasets themselves is [[id:44B275EC-DC37-4961-80EF-9D79D4C186FB][Migrate FPML, crypto, flags and ip2country onto
the org dataset pipeline]].

* Acceptance

- An image-artefact archetype generates the crypto-icon and
  flag-image SQL that =images_generate_sql.py= produces today.
- An ip2country archetype generates the artefact SQL plus its TSV
  import.
- An FPML archetype generates the per-entity dataset and artefact SQL
  for all 22 entities, plus the coding schemes, byte-identical to the
  committed output.
- The generator reads =manifest.json= directly, or the four datasets
  carry a translated payload; either way no hand-written translation
  step remains.
- Each new archetype is an org node in the template library with an
  =#+model_types:=, an =#+output:= pattern, and a tangled mustache.
- =compass build --direct tangle_codegen_templates= produces no drift.
- The codegen test suite passes, with a test per new archetype.

* Plan

1. Read the committed crypto, flags, ip2country and FPML populate SQL
   to fix the exact output each archetype must produce.
2. Write each new archetype as an org node with its mustache source,
   following the shape of the nine generic archetypes.
3. Extend the generator to read =manifest.json=, or add the payload
   translation, and decide which on the evidence.
4. Re-tangle, then diff the generated output against the committed SQL
   until it is byte-identical.
5. Add a test per archetype, following =test_data_scope.py=.
