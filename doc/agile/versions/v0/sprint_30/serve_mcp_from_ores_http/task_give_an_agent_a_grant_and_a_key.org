* Goal

A person signed in to ores.web creates a grant for one agent: its name, read only or read and write, and an expiry. The grant gives a key, shown once and stored hashed. The agent sends the key as a bearer token, and ores.http exchanges it for a short session whose token names the person as sub and the agent as act. The person lists their grants and revokes one, which ends the agent's access at once.

* Acceptance

- A grant is created, listed and revoked in ores.web, and its key is shown once and stored only as a hash.
- A request with a valid key acts as the person, with the agent named as act in its token; an expired or revoked key is refused with 401.
- A read-only grant cannot write, whatever the person may do.
- The grant model admits a second way to create a grant, so OAuth can be added without changing what comes after the grant.
