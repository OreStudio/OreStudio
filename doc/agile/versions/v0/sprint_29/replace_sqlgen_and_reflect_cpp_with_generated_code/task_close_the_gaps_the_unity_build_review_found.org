* Acceptance

- =check_unity_collisions.py= groups sources by target, not by directory, so
  two files of one target in different directories are checked together.
- The exclusion the collision check picks for a group stays the same when a
  new file sorts before the others.
- =--record= reads relative paths in a compiler log as well as absolute ones.
- =check_unique_type_names.py= reads every namespace of a header, nested and
  sibling, and covers the test headers (=tests/*.hpp=).
- Both scripts have a unit test fixture.
- =cmake_minimum_required= is 3.18 or newer, or the exclusions say why not.
- =compass lint= lints every file when git is not available, instead of
  crashing.
- The own-or-system RLS template comment reads: every session reads its own
  rows and the system tenant's rows.

* Plan

1. Rewrite the type-name check around one function, =defined_types=, which
   walks the header's braces with a scope stack. A type counts when every
   enclosing scope is a named namespace, so nested and sibling namespaces
   qualify it in full and a type in a class, a function or an anonymous
   namespace does not count. Comments, literals and directives are blanked
   first.
2. Read test headers too, and say which binary each header can reach: a
   public header any binary, a test header only its own test target.
3. Group the collision scan by =target_dir=, not by directory.
4. Keep a committed file in the unity build before a new one when =--write=
   picks the exclusion of a group.
5. Read a relative compiler log path from its =projects/= part on.
6. Give lint a fallback that lints every file when git is missing.
7. Reword the RLS comment in the two org template sources and regenerate.
8. Pin each point with a test in =projects/ores.codegen/tests/test_unity_checks.py=.

* Notes

The CMake point needed no change: the tree already requires 3.28, and
=SKIP_UNITY_BUILD_INCLUSION= read through =DIRECTORY= needs 3.18.

The collision scan still reads declarations one line at a time, so a helper
declared on the same line as =namespace {= is not seen. The tree never writes
one that way, and the compiler-driven =--record= catches what the scan
misses, so the scan was left line-based.

* Result

Both unity build checks now see what a unity batch sees. The collision check
groups sources by target, keeps committed files in the build before new
ones, and reads relative paths in a compiler log. The type-name check reads
every named namespace, nested and sibling, and covers test headers within
their own test target. Twelve tests pin these points. Lint lints every file
when git is missing, and the own-or-system RLS comment is reworded in the
templates and the generated SQL. CMake already required 3.28, so that point
needed no change.
