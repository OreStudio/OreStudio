* Goal

A member can no longer read another account's contact information, which
account works in which party, or who asked for which role, through the
entity's reads or through its history. A person still reads their own contact
record, through a self read.

* Notes

The profile page reads the caller's own contact record through
=iam.v1.account_contact_informations.list_by_account_id=, passing the session's
account id (=readContactInformation= in =wire-protocol/src/profile-operations.ts=).
The server cannot tell that call from a read of a colleague's record, so
guarding the read would break the profile. Add a self read,
=iam.v1.account_contact_informations.mine=, beside the existing =update-self=,
move the profile onto it, and only then guard the list. The self read is in
the planned table of [[id:804C7048-DBBF-4B39-8737-BFB4949884C4][Authorised reads]].

Permission wildcards are =*= and =component::*= only
(=ores::security::authorization::grants=); there is no read-only wildcard such
as =iam::*:read=.

* Result

Contact information and both role request tables guard their reads; the
hand-written account party reads check =iam::accounts:read=, as their writes
check =iam::accounts:update=. A person reads their own contact record through
=iam.v1.account_contact_informations.mine=, which names no account, and the
profile route moved onto it. The contact information codes are seeded; the
handler checked them before, but nothing defined them.

The history subject was a second way in: =<component>.v1.history.get= served
every version of any entity after authenticating the caller. A history
provider now registers its entity's read code and the dispatcher refuses a
caller without it.

A junction ignored =:guard_reads:=, because codegen did not pass the flag for
junctions; fixed, with a test that fails without the fix.

Live, on a fresh database: =ashley.moore= (Member and Viewer) reads her own
contact record and is refused colleagues' contact information, account parties
and role requests, and a colleague's contact history; =tenant_admin= reads
them all (=evidence/reads_as_member.ores=, =reads_as_administrator.ores=,
=history_reads.ores=).
