* Result

* Result

=iam.v1.ops.get_session_statistics= answers one row per day and account,
newest day first, scoped to the caller's tenant.

The journey's premise was wrong and the model records the correction: the
three =ores_iam_session_stats_*_vw= continuous aggregates are created only
under the =timescale= licence, and this database reports =apache=, so they do
not exist. Rather than depend on a licensed feature, the read aggregates
=ores_iam_sessions_tbl= itself, so it answers in either edition.
