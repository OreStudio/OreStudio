* Goal

One hand-written value type, =market_datum=, describes every ORE market datum:
the instrument type, the quote type and a short list of typed fields. A
=constexpr= schema table states, per instrument type, which fields exist, in
which order, and which are coordinates.

* Acceptance

- =instrument_type= enumerates all 45 ORE instrument types and =quote_type= all 16 ORE quote types.
- =field= enumerates every field any ORE key carries, and a traits map gives each field one value type.
- The value variant has no more than about six alternatives: string, ORE period, ORE date, decimal, strike and enum code. A strike is a variant of absolute, ATM with its ATM type, moneyness and delta.
- The schema table has one row per instrument type, listing its fields in key order, each field's role, and the fields that may hold =none=.
- The only constructor refuses a datum that does not match its row: a missing field, an extra field, or a value of the wrong type.
- No field is absent where its absence would mean a default; an optional ORE token holds an explicit =none=.
- Free-text names keep the case they arrived in.
- =series_of(datum)= removes exactly the coordinate fields.
- No =std::variant= over instrument types exists, and the header that holds the enums and the table includes no codec.
- Unit tests cover the constructor's refusals, equality, =series_of=, and every value type's text form.

* Plan

* Notes

Choices made while writing the model, each inside the agreed design:

- *Fields take ORE's meanings and names*, from the inspectors the catalogue
  records, in snake case: =fwd_start= where the old grammar said =settle=,
  =atm= and =relative= where it said =shift= and =strip=, =quote_tag= where it
  read an index.
- *Tokens ORE drops are fields all the same.* ORE ignores the curve name of a
  ZERO or DISCOUNT key and the seventh segment of a basis swap; the datum keeps
  them as =curve_id= and =identifier=, because a key must read back as written.
- *One =term= type, with a kind.* ORE lets one slot hold a period or a date, and
  a forward's also ON, TN, SN or a continuation =c1=. Separate period and date
  types would need a field that holds either, so the value kinds are none,
  text, term, decimal, strike and code.
- *Numbers keep their text and are checked by the platform.* =decimal::parse=
  validates through =ores::platform::numeric::parse_double=, the estate's one
  locale-free number grammar, which exists because libc++ deletes the
  floating-point =std::from_chars=. It is stricter than ORE's =std::stod=, which
  accepts trailing text, =inf= and hexadecimal; the catalogue's keys carry none.
- *A code is used only where ORE checks a vocabulary*: cap/floor, call/put,
  payer/receiver, the swaption dimension, ORE's booleans, protection side, time
  unit and DST. ORE accepts any seasonality type, so that field is text. ORE
  upper-cases a time unit, so only that code compares without case.
- *The equity ATM and ATMF shorthand is part of the strike*, flagged, so =ATMF=
  and =ATM/AtmFwd= stay two keys although ORE reads them alike.
- *The fields are a =std::vector=*, not a small vector; a datum holds at most
  eight fields, and the choice can change behind the class.

* Result

=ores::marketdata::datum= holds the model: ORE's two enums, the value types,
the 45-row schema with its compile-time checks, and =market_datum= with its two
checked constructors, typed reads and =series_of=. It replaces nothing yet; the
key codec is the next task.
