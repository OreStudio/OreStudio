model, and codegen renders it to C++, TypeScript and the shell. No protocol of

* Why this task exists

The clean-up task found this work and closed without it. Its M06 and P04 rows
say the workflow's operation messages need an operation model; P01 and P03 are
"pending the operation model"; and its P04 detail records a decision (option 2:
each commissioner owns its workflow's payload) and a change set "awaiting the
go-ahead". Its Result lists none of these under what did not land, and no
follow-up was filed. A hand-written TypeScript mirror of the instances list then
broke the tenant roster on =feature/return-to-a-journey-in-progress=.

* Acceptance

- One operation model declares every message of the workflow conversation, with
  today's subjects and field names. The six hand-written headers
  (=step_log_types=, =steps_query_protocol=, =workflow_events=,
  =workflow_protocol=, =workflow_query_protocol=, =workflow_retry_protocol=) are
  gone, and every consumer includes the generated header.
- What a model cannot state stays hand-written in one place: the two enums
  with their reflectors, and the NATS header names. The enums are registered as
  custom types, so they cross to TypeScript as =string=.
- The =provision_parties= payload and its handler live in =ores.refdata=, and
  =ores.workflow= declares no domain payload.
- The shell's workflow verbs are generated from the model. Only =workflow wait=,
  which polls and is no message, stays hand-written.
- =ores.web= uses the generated types and subjects for every workflow call, and
  a test proves that a request the client encodes decodes in C++.
- The Protocol rows of the clean-up task and the false P04 statement in
  =ores.service='s clean-up task are corrected.
- Build, ctest, codegen drift, the sweep, shell-script drift and the web suites
  pass, and the roster and run page work against the running deployment.

   point every includer at the generated header, and build.
4. *Payload move.* Model =provision_parties= in =ores.refdata= as an operation,
   move =workflow_handler= into refdata's aggregate registrar, and delete
   =workflow_protocol.hpp= and =workflow_handler.{hpp,cpp}= from the engine.
5. *Shell.* Register the generated workflow operations unit. Reduce the
   hand-written unit to =wait= and the =wait_for_instance= helper its callers

6. *ores.web.* Replace the mirrors in =tenants.ts= and =operations.ts= with

** What

Bring =ores.workflow='s protocols under codegen, as
[[id:5E4C1A90-3B27-4E6D-9F01-7A2C8D4B6E15][Protocol types are generated from the C++ codegen model]]
requires:

1. Add =projects/ores.workflow/modeling/ores.workflow.workflow_query_messages.org=
   as an =ores.codegen.operation= model. It holds the instances list
   (=list_workflow_instance_summaries_request= / =_response=,
   =workflow_instance_summary=), the steps read (=get_workflow_steps_request= /
   =_response=, =workflow_step_summary=, =step_log_entry=) and the retry
   request and response. Field names and subjects stay exactly as they are.
   =step_log_entry= goes in the same model, because an operation model cannot
   reference a sibling model's message in TypeScript (capture C80EC09A).
2. Generate. The output replaces the hand-written =workflow_query_protocol.hpp=,
   =steps_query_protocol.hpp= and =workflow_retry_protocol.hpp=.
3. In =ores.web=, delete the hand mirrors: =listWorkflowInstancesRequestSchema=
   and the summary schema in =wire-protocol/src/tenants.ts=, and the
   =workflowInstanceSteps= and =retryWorkflowInstance= subjects and schemas in
   =operations.ts=. Add mappers typed against the generated interfaces, and take
   the subjects from the generated =subjects=.
4. Commit the =workflow_instance= entity's generated TypeScript, which
   =codegen entity show workflow_instance= reports as missing.
5. Add a boundary test: a request the client encodes is decoded by the C++
   handler.

Do this as part of the work to bring =ores.workflow= to the component clean
standard.

** Why

The roster's run read was written by hand on
=feature/return-to-a-journey-in-progress=. It left out the unused optional
filters. The C++ decoder requires every field, so every request failed with
"Invalid request payload", and the Setup column stayed empty. The BFF tests use
a fake client, so they did not see it. A generated interface renders a
=std::optional= field as a required =T | null=, and tsc then refuses a request
that leaves it out.
