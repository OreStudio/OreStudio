* Plan

Each of the 28 code lists is a generated unit, from one model declaration:
=#+web_classification:= names the key, =#+web_classification_topic:= the topic,
and =#+web_classification_read_only: true= marks the five lists of ORE
spellings. A list's shape follows from its write record: =named= with a name,
=ordered= with only a display order, =plain= with neither.

What is the same for every list lives once. The bodies, the row the screen
reads, the write a row becomes and the intent are in
=ores.http.api/net/classification_routes.hpp=. The label read and write, which
differ only by the list's code domain, are in the refdata part's hand-written
=classification_routes=, which also answers the catalogue of lists with their
counts and the label catalogue.

* Result

The C++ server answers the classification screen's six routes for each of its 28
code lists, the catalogue of lists with their row counts, and the label
catalogue. Each list is a generated unit; what every list shares lives once in
=ores.http.api= and in the refdata part's =classification_routes=. The
generated tests check each list's refusals, its read-only state and its
catalogue entry. All nine =ores.http= suites pass.
