* Acceptance

- each of the two types names an instrument table, with its own terms in the rates family's fact rows
- the projection reads and writes each element, value for value
- each type has a builder, and the catalogue routes both
- the generator books one trade of each type through its builder, and the recorded trades hold it
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: no list, basket or schedule is held as text

* Plan

- =SwaptionStraddleData= is the same schema type as =SwaptionData=, so the
  straddle routes to the rates header row with the swaption fact, natively.
  The swaption reader and writer take the trade type, and
  =swaption_straddle_builder= wraps the swaption builder.
- =RateDigitalOptionData= is flat: an option block, the index, the strike, the
  payoff and two dates. It routes to the scripted instrument table through the
  class-read path; the index is stated by ORE's name, which the planner takes
  from the index's subject.
- The rates planner books the straddle as it does a swaption, and the digital
  as a scripted batch fixing a year out.

* Result

SwaptionStraddle is held natively in the rates header row with the swaption
fact, the option block and the legs. RateDigitalOption is held in the scripted
instrument table. The round-trip test reads a straddle and the user guide's
rate digital option and writes them back. Each type has a builder, the
catalogue routes both, and the generator books one trade of each. The ORE
engine builds the recorded straddles with no error; the digital raises an
engine configuration error, which the known list holds and the valuation story
owns.
