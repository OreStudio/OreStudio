* Acceptance

- No test file in ores.ore.core.tests opens a database session, a repository or a transaction, except the configuration type seed check, which the third bullet keeps.
- The document-to-rows roundtrips run in a suite that owns a database and the components they exercise.
- The configuration type seed check stays, because it guards ORE format coverage, and it says so.

* Plan

Each roundtrip goes to the suite of the component whose tables it writes:

| Test | Suite |
|------+-------|
| credit simulation, pricing engine, today's market | ores.analytics.core.tests |
| conventions per party, curve configuration | ores.refdata.core.tests |
| run document, pooled session | ores.reporting.core.tests |

The configuration type seed check stays, because it guards the codec's format
coverage and not a component's rows, and a comment says so.

The fixtures they shared move to =ores.testing=, where the suites that now use
them can reach them: the two parties and their contexts, the conventions rows,
and the two ORE corpus helpers. The helper that seeds the system analytic
parameters leaves the party fixture, because only the run document needs it and
the analytics suite must not be made to link reporting for it.

* Result

The codec's suite proves the codec. Seven test files left it for the suite of the
component whose tables they write, and the one file that still opens a session
says why: the configuration type seed guards the ORE format coverage, so it
belongs where the codec is.

The fixtures they shared moved to =ores.testing=: the two parties and their
contexts, the conventions rows, and the ORE corpus helpers. Nothing is copied,
so the suites cannot drift from each other.

Moving them found a fault that had been invisible: three of the moved cases wrote
a reporting configuration without the audit fields the schema requires, so they
failed with "modified_by cannot be null or empty". The codec's suite had not run
them in a state where that showed. They now state their actor, and run.
