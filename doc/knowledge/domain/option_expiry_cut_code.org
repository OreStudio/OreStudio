#+title: The option-expiry cut code
#+description: A cut code names the time of day at which an option expires: what the label is, why the time of day matters, its relation to the cut time and timezone, what it does not fix, and where ORE Studio stands.

This page is the expiry sense of a
[[id:B5214F3A-A72E-421E-82BC-79338B2E95CB][cut]]: the same shape, a label for a
timepoint, applied to the moment an option expires. The
[[id:B5214F3A-A72E-421E-82BC-79338B2E95CB][Cuts]] structure note gathers it with
the market data and deal components.

* Summary

A cut code is a *label* for the *time of day* at which an FX option expires on
its expiry date. An option has an expiry date and an expiry time, and the date
alone does not price it. The code names the time, the timezone says which clock
it is read on, and the pair decides which code applies by default. It fixes an
instant for one contract and not a population, which is what tells it apart from
the market data and deal components of a cut.

* What the label is

An FX option expires at a stated time on its expiry date, and the market names
that time rather than writes it out per trade. A cut code is that name. It is
chosen per currency pair, applies to every option on the pair unless a trade
overrides it, and carries the timezone the time is read on.

Two things follow. The same code on two pairs can mean two instants, because
each pair's default differs. And a trade that carries an override is not priced
on the same clock as its pair's other trades, so the override is worth showing
to whoever reads the trade.

* Why the time of day matters

- *Time value*. The remaining life of the option is measured to the instant, not
  to the date. Near expiry, the hours between one cut and another are a
  material part of the premium.
- *The strike and the barrier*. An option that expires at one cut and a barrier
  that is monitored to another are observed at different moments, and a spot
  move between them changes whether the option ends in the money.
- *The surface*. Volatility is quoted at tenors measured to the expiry instant,
  so the code and the surface have to agree. A surface quoted to one cut prices a
  contract expiring at another with a small, systematic error.

We hold no public source that fixes these times. The times in circulation are
market convention, they differ by centre and by pair, and a firm's own list is
the only authority on what it trades. This page therefore records the shape of
the label and no table of times.

* The label and the cut time

The label and the time are two facts. The *cut code* is the name, and the *cut
time* is the time of day it resolves to, with its timezone. A reference table
holds the name beside the time and the timezone, so a reader can see what a code
means without asking a person.

This is the same shape the hub describes: a label, a timepoint, and an object.
Here the object is one contract's expiry instant.

* What it does not fix

A cut code does not fix a population. It says nothing about which deals or which
market data a valuation reads, and nothing about which centre's close the day
runs to. A cut code on a trade and a market data cut on a book answer two
different questions, and one does not imply the other.

* Where ORE Studio stands

We have the code as designed reference data, and not as a field. The design is a
lookup entity holding code, name, description, cut time and timezone, referenced
by =currency_pair.default_cut_code= and by anything else that needs a cut time,
in
[[id:4B4ED152-1670-4E81-895A-24D747382D4C][Model market data cuts as proper ORE Studio reference data]].
The same story records that no entity, table or foreign key target exists today,
and that the field was dropped from the currency pair rather than kept as free
text until something could be referenced.

The model agrees. [[id:E1EE950D-FC22-4DAB-A93F-8B2A15196031][ores.refdata.currency_pair]]
carries the pair's identity, its classification and its conventions, and no cut
field.

The field list that describes what the pair should carry, and why an override is
worth flagging, is on
[[id:CC6D86D8-33FC-41D6-AC27-F35FA942F436][Currency pair and currency entity fields]].

* What the sources establish

Nothing on this page rests on an external source. The time of day is market
convention and we say so, the definitions are ours, and the statements about our
system link the model and the story that show them.
