* Result

The blotter opens the trade a run failed on, at the version the run read.

The trades route gained =GET /api/trades/:id/versions/:version=, which asks the
trading service for the versioned trade rather than filtering a list the screen
already holds. The server answers a version the trade never had as a missing
answer, so the screen can say so instead of showing a read failure.

The trades page reads =trade= and =version= from its address and, when both are
there, shows the trade above the blotter with its type, state and trade date,
and the words saying that the blotter shows the current version. A version that
is not there is said in words. The error screen links a trade only when the run
recorded its version; otherwise it names the trade, because a link that lands on
an unfiltered blotter is worse than a name.

Proven in a browser: /trades?trade=26b4ff60-…&version=5 showed the panel with
"Version 5", and version 99 said there is no such version.
