The corpus-derived seed states an address on its ten IborIndex rows, and every
one carries a tenor (e.g. AED-EIBOR-3M -> ...&name=EIBOR&tenor=3M). A defining
convention states the family address, so the lookup drops the tenor and matches
nothing: 0 of 10 are reachable by index_definition_of.

Seeded ids that differ from ORE's own spelling for the same index:
  EUR-ESTR     vs ORE EUR-ESTER
  JPY-TONA     vs ORE JPY-TONAR

Seeded rows with no counterpart in ORE's built-in table (the synthetic feeds name
families ORE has no index for): SEK-SWESTR, KRW-KOFR, NZD-NZONIA, INR-MIBOR
(ORE has INR-MIBOROIS, a different index).

where the physical fields live: each built-in maps to a QuantLib or QuantExt class
whose constructor states them, e.g. QuantLib/ql/indexes/ibor/sofr.cpp:
  OvernightIndex("SOFR", 0, USDCurrency(), UnitedStates(UnitedStates::SOFR), Actual360(), h)
so settlement days, currency, fixing calendar and day counter are minable from the
same checkout, and the calendar and day counter need a mapping to refdata's codes.
