* Goal

Each step service obtains a run token through one shared cache in
=ores.service=, keyed by grant id and run id. The cache exchanges again when a
token is close to its expiry, so a run of hours lives through many tokens, and
it lets a caller that an owner refused as =token_expired= exchange once and
retry the same request.

[[id:78B82824-0BBB-4442-A9FA-E1F265DF57BD][Run grants and run tokens]] states
the cache rules this task implements.

* Acceptance

- A step service obtains a run token through one cache keyed by grant id and
  run id.
- The cache answers the held token while more than 20 percent of its life
  remains, and exchanges again after that. Concurrent misses for one key share
  one exchange.
- An exchange the minter cannot make holds nothing and answers no token.
- A caller that an owner refused as =token_expired= exchanges once and retries
  the same request.
- The end of a step, and the end of a run, drop the run's entries.
- The cache is bounded, so a missed event costs memory for at most one token
  lifetime. It never writes to disk, a database, a message or a log.
- A restart or a second replica starts with an empty cache.

* Plan

The cache is one header-only class in =ores.service=, and one small adapter in
=ores.iam.client=.

1. *The cache.* =run_token_cache= in
   =ores.service/include/ores.service/service/cache/run_token_cache.hpp=. It
   holds one entry per =run_token_key= of grant id and run id. The key is a
   value, so the cache never parses a joined string. The cache is bounded and
   drops the least recently used entry when full, and it can drop every entry of
   one run. The clock and the exchange are injected, so a test moves time and
   answers the exchange itself instead of calling IAM.
2. *The exchange.* =run_token_minter= in =ores.iam.client= wraps a NATS client
   and the service's own token provider, calls =iam.v1.run_grants.exchange= and
   answers the token and the instant it expires. =ores.service= does not link
   =ores.iam.api=, so the adapter lives where that dependency already is, and
   the cache stays free of it.
3. *The retry.* The cache offers =invalidate=, so a caller whose request an
   owner refused as =token_expired= exchanges once and repeats the request. The
   repeat stays with the caller, because only it knows how to make the request
   again.
4. *Wiring each step service* is the story's live test, not this task. This task
   builds the cache and the exchange adapter the wiring calls.

* Notes

- The hold is satisfied. Clever dijkstra's story landed as PR #2679, which added
  =partitioned_cache= and =partition_token_cache= in =ores.eventing=, and the
  exchange task added the =act=, =grant_id= and =run_id= claims and the issue
  log. Neither generic cache fits a run token. =partitioned_cache= mirrors
  another service's entity per tenant, and =partition_token_cache= is keyed by
  one string, has no bound and cannot drop one run. This task builds the bounded
  cache the run token needs, and leaves both generic caches alone.

- The reporting service is wired first. Its =gather_trades= and
  =gather_market_data= steps call their owner with a run token from the cache,
  and an owner that answers =token_expired= costs one exchange and one repeat of
  the request. The grant id is read from the report instance's =run_grant_id=.
  The trigger handler records that field at admission, copied from the
  definition, so the run keeps the grant it was admitted under even if the
  definition is later re-scheduled or unscheduled. An earlier cut read the
  definition's =run_grant_id= at step time and shared the definition's current
  consent across every run; the instance field removes that.
- Two of the owners the design names are not wired yet. =ores.ore= reads the
  configuration documents through its own steps, and =ores.compute= obtains the
  run token to create its batch. Those follow the same shape.
- Eviction is wired for the reporting steps. A step-scoped guard drops the run's
  entries when the step ends, on every return, and the terminal handlers drop
  them again when the run completes or fails. The bounded LRU remains the
  backstop for an event nobody sees.
