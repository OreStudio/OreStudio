* Acceptance

- Both Windows legs reach the build; the install step unpacks the zip with PowerShell.
- The step refuses loudly when the release holds no compass.exe.

* Plan

Replace the archive tool with PowerShell's =Expand-Archive=, which every
Windows runner carries, and stop the step when the archive holds no
=compass.exe= rather than leaving the shim and the PATH entry pointing at a
directory without it.

* Result

* Result

The install step unpacks the pinned release with PowerShell, and the two
failed attempts are gone: =unzip=, which Windows does not carry, and =tar=,
which Git Bash shadows with GNU tar, which cannot read a zip.

- =Expand-Archive= expands the archive into =compass-ng= under =RUNNER_TEMP=.
- The step fails when the expanded tree holds no =compass.exe=, naming the
  archive, instead of writing a shim and a PATH entry for a directory that
  holds no binary.

Verified locally: the workflow parses as YAML, the step body passes =bash -n=,
the expansion line hands PowerShell one well-formed =-Command= argument, and
=compass-ng check --ratchet= reports no new diagnostics on this branch.

Not verified locally: the step itself, which needs a Windows runner. Tonight's
nightly is the check.
