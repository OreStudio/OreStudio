#+title: Roll the response-shape and recipe fixes out to the components outside COMPONENTS_UNDER_TEST
#+description: The refdata clean-standard pass found and fixed four generator defects: the protocol-dependency gate asked its question of the address-narrowed facet set, so the ores.doc.shell-recipe family was regenerated by nothing and rotted; a put response and a version response carried their row by value, so a missing row serialized a zero date the client refused; and a batch removal of nothing rendered an empty IN (). The fixes reach the components in COMPONENTS_UNDER_TEST only, because that is the set every regeneration walks. The other components still carry the old shapes until they are regenerated: as of this capture, dq's put and version responses are by value, and its shell recipes are un-regenerated.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *next* bucket of the product backlog — triaged, not yet pulled into a sprint as a story.

* What

Regenerate every component outside =COMPONENTS_UNDER_TEST= against the four
generator fixes the refdata pass landed, so the tree carries one response shape
and one recipe family rather than two of each.

* Why

=check_component_drift.py --all= regenerates exactly the components in
=COMPONENTS_UNDER_TEST=, so a shared-template change reaches those and no
others. Three of the four fixes are shared templates or shared protocol
derivation:

- The protocol-dependency gate now asks whether the *model* has a protocol
  rather than whether the address under regeneration selected one. Before it,
  any per-space run -- and the drift check regenerates one space at a time --
  dropped =ores.doc.shell-recipe=, so every component's checked-in recipes are
  frozen at whatever the last working generator produced. Regenerating a
  component refreshes its recipes and, from then on, the gate keeps them honest.
- A put response and a single-version response now carry their row in a
  =std::optional=. A component that has not been regenerated still serializes a
  default row when there is no row: a client refuses the whole response with
  =Invalid date value: 0000-00-00= before it can read the outcome. Measured on
  =ores.dq=, whose =get_lei_entity_version_response= and =put_lei_entity_response=
  still state their row by value.
- A batch removal of an empty key list now answers instead of rendering an empty
  =IN (=, which the server refuses as a syntax error.

The components outside the set are =dq=, =trading=, =reporting=, =marketdata=,
=storage=, =http=, =scheduler=, =synthetic= and =workspace=. Each needs the
regeneration its own clean-standard pass will run; this capture exists so that
the work is not silently assumed done.
