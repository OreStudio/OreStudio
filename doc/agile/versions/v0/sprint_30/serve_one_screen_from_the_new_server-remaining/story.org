#+title: Story: Serve what the BFF serves, then retire it — the remaining work
#+description: The C++ server answers a fraction of what the BFF answers, and the browser calls none of it. Retiring the BFF is a later set of pull requests, once the coverage is complete.

* Goal

Every route the BFF answers has an equivalent on the C++ server, merged and proved as
it lands, and the browser keeps calling the BFF until the last one does.

* Acceptance

- [ ] Every resource route the BFF answers has a C++ equivalent, area by area, merged as
      it lands.
- [ ] Every composed view is answered by the server that owns it, with its name, its
      schema, its owner, its computation and its cache policy.
- [ ] A generated list route carries what the BFF's lists carry: the page, the order,
      the search and the filter's own members.
- [ ] The C++ server answers every route ores.web calls, including the routes the
      inventory classifies as not an API.
- [ ] The coverage is counted from the route inventory, not claimed.
- [ ] ores.web passes its test after the switch, and a rollback to the BFF is one
      switch.
- [ ] The local gate is green on every pull request.

* Decisions


- Split from [[id:35649881-C6FE-4FC6-97D7-DA18A05A0355][Serve what the BFF serves, then retire it]] on 2026-11-08 at sprint 29 close. The acceptance above is copied from that story; its done tasks are recorded there.
- Reviewed on 2026-11-08 at sprint 30 start. The goal is still open and the story has no tasks. It needs one task per area of the route inventory.
- Decided on 2026-11-09: the C++ server answers every route ores.web needs to function, including the routes the inventory classifies as not an API.
- Decided on 2026-11-09: when the work is done, move the one switch and test ores.web. If ores.web breaks, keep using the BFF until the fault is fixed. The design's section 12.4 states this rule.
- Found on 2026-11-11: a pair in =route_pairing.py= records the C++ route that does the same thing, not one ores.web can call unchanged. Of 54 pairs, 39 differ in method, path or shape, such as =GET /api/accounts/:accountId/access= against =POST /api/v1/iam/ops/get_account_roles=. The switch is one switch, so each area task serves the BFF's own path and shape for every route ores.web calls, paired or not, as the pick list, site and change stream routes do.
