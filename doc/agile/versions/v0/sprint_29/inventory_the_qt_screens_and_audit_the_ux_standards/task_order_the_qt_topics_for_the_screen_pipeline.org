* Goal

The pipeline has a queue. Each topic names its entities, the journeys it needs, whether a standard record screen is enough or a workflow is needed, the server side work it implies, and its place in the order. The first topic is chosen and the reason is recorded.

* Acceptance

- Every entity of the matrix belongs to exactly one topic.
- Each topic is judged as standard CRUD or as needing a workflow, with the reason.
- The topics are ordered and the first topic is named with its reason, and the fourth story's description is updated to name it.
- Topics after the first are filed as captures in the next bucket, one per topic, so each becomes a story when its turn comes.

* Plan

Group the 63 entities of the matrix into topics by the records a person keeps
together, name the journeys that already exist for each from the journey
catalogue, judge each topic's shape from the record and entity standards, and
order them: the owner's choice first, then the shapes the standards must prove
in order, then by the size of the gap. Write the order as a knowledge page, file
a capture per later topic tagged pipeline, name calendars in the fourth story and
record the decision on the first.
