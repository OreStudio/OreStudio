* Acceptance

- The engine re-runs a completed_with_warnings step that is not essential, of a finished run, under a new idempotency key, and records the new outcome; other steps and running runs are refused with their reason.
- setup-rerun STEP in the shell and a Re-run button on /setup-report start it and show its outcome.
- Each of the nine steps that are not essential, re-run on a provisioned Acme tenant, adds nothing that was already there.

* Plan

- *The retry carries the re-run.* A retry that names a step of a completed run, where the step
  is not essential and ended with warnings, runs it again. The message, its permission, the
  shell's =workflow retry= and the web client already exist, so nothing new is added to the
  protocol.
- *A new attempt, the same step.* The step keeps its id, which is how the run names it and how
  a service finds it; a service answers a step id from its record only while the step is
  settled, and a re-run puts it back to work first. The attempt gets a new idempotency key,
  and commands now send that key as =Nats-Msg-Id=, so the stream does not drop a re-run inside
  its duplicate window. A dispatch, retry or recovery sends the same value as before, because
  there the key is the step id.
- *The run reopens.* The run goes back to in progress while the step runs, and the step's
  answer completes it again, so its completion time and the login summary follow the re-run.
- *Proof by snapshot.* The count of current rows in every bitemporal table is taken before and
  after; any growth is attributed to its writer and time.
- *Nine became eight.* publish_system_curves belongs to the system's provisioning run, not the
  tenant setup, so setup-rerun cannot reach it; it publishes through the same helper as the
  party curves.

* Result

A tenant administrator re-runs a setup step that ended with warnings from the setup report: the
=Run again= button on =/setup-report=, or =setup-rerun STEP= in the shell, which reports only that
step. The engine sends the step again as a new attempt under a new idempotency key, reopens the
run, and completes it again when the step answers; it refuses a clean step, an essential one, an
unknown one and an unnamed one, with the reason. The person checked the button in the browser.

All eight tenant setup steps that are not essential were re-run on a provisioned Acme tenant and
added nothing that was already there (see the Measurements). The ninth, publish_system_curves,
belongs to the system's run and cannot be reached from the setup report; it publishes through the
helper the party curves step uses, whose re-run published nothing.
