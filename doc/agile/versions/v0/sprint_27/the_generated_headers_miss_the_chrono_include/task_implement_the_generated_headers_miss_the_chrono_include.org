* Acceptance

- No generated domain header uses std::chrono without including <chrono>.
- The codegen suite fails when one does.

* Plan

The domain class template emits =std::chrono::system_clock::time_point
recorded_at= for every entity with audit columns, and supplies no header with
it. Commit =06936a44da= settled what that means: "The fix is in the templates.
An include every file of a template needs is unconditional. One that some files
need sits behind a context flag core.py computes from the template branches that
spell its symbol." =core.py= computes =has_audit_columns= already, at the branch
that emits the member, so the gate goes next to the other template includes.

Two variants emit the member. The =domain_entity= one emits it under
={{#has_audit_columns}}=, so the include is gated on the same flag. The
=junction= one emits it unconditionally, so its include is unconditional.

=** Domain includes= was standing in for that gate: 244 models declared
=<chrono>= by hand, and the 126 that did not are the ones whose headers named
=std::chrono= without it. Those declarations are now redundant, and 237 of them
are deleted -- the template owns the include.

Not every model can lean on the gate. An entity with no audit columns that
declares a =std::chrono= column of its own is outside it, so four models keep or
gain the declaration: =grid_sample=, =node_sample=, =workflow_batch_link=, which
have no =** Domain includes= block at all, and =session=, which is a
current-state entity.

=tests/test_domain_includes.py= gains the rule in the other direction: a header
that names a standard type must declare the header for it. The rule it already
had, declared but unused, was red on =main= -- =structure.org= declared
=<optional>= and uses none -- so that line goes too.

* Notes

The model's =** Domain includes= block feeds more than the domain header: the
operation template reads its own model's block to build a protocol header. A
first pass stripped =<chrono>= from every model with an =includes= block and
took it out of ten operation models and one knowledge doc that use theirs for
their own reasons. Both sets are restored, and the strip is restricted to
=ores.codegen.entity= and =ores.codegen.junction=.

The protocol headers' lack of a direct =<chrono>= is not part of this: 354 of
the 360 that name =std::chrono= on =main= already had no include for it, and
they reach it through the domain header they include.
