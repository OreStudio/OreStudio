* Plan

The task began with eight routes. The five that hold the browser's session --
sign-in, the session read, sign-out, the party choice and the party switch --
need the session record to hold what the BFF's session held, so on 2026-11-11
they moved to [[id:E57938AF-06F7-4330-B992-F7BE5296D8A3][Serve the browser's session routes]].

- =account_door_routes= is a new unit in the IAM part. =POST /api/signup= runs
  under the credential policy, so it shares the sign-in budget as the BFF's
  did, takes the tenant from the request's host as the bootstrap routes do, and
  maps each refusal code to the BFF's status and code. =GET /api/password-policy=
  needs no session. =POST /api/account/password= forwards the change and refuses
  a failed one as the BFF refused a failed operation.
- The BFF cleared its session's password-reset flag after a change. The C++
  session record holds no such flag yet; the session task adds it and clears it.
- The BFF read the body before it spent the budget; the C++ policy runs before
  the body is read, so a malformed registration also spends an attempt.
- The pairing table's =IAM_OPS= prefix has no user left and is removed.
