#+title: Story: Run a full report: scheduling, reporting and compute in two modes
#+description: Integrate scheduling, reporting and compute so that one report definition runs end to end. The pipeline is designed in two modes: demo, which collects a tarball that already holds the deal and market data, and full, which selects the trades, resolves the market data, converts ORE Studio data into ORE XML, packages, submits, retrieves and converts the results back into the database. A single knob on the definition selects the stages, so demo mode exercises the real machinery rather than a stub. Full mode is designed here and implemented later.

* Decisions

1. *The mode is the definition's own state.* A column, resolved when the
   instance is created and carried into the workflow start message, so a run
   is reproducible from the database and works with no operator present.
2. *The mode is not the report type.* The type axis stays a category of
   report; the mode axis is separate, so a full run and a demo run of one
   definition differ in one field.
3. *Stages hand each other storage URIs, never structures.* Both modes
   therefore produce the same object at the seam, which is what lets the grid
   stay mode-blind and demo mode stay a real test.
4. *Step results are addressed by role, not by index.* Positional access is
   already fragile with one chain and becomes a defect generator with two, so
   it changes before the second mode lands.
5. *The engine package is a prerequisite.* Registering the ORE build is
   seeded per engine build, not a stage of a run.
6. *The reporting to compute handoff stays with the ACME smoke-test story.*
   That story already owns the three defects that stop the tail being driven
   from reporting, and this story waits on it rather than duplicating it.
7. *Full mode is designed now and built later.* No stage that demo mode
   proves may need to change to admit it.

* Out of scope

- Implementing full mode. It is designed and tasked, not built.
- Parsing ORE results beyond writing them into the database; no analytics on
  them.
