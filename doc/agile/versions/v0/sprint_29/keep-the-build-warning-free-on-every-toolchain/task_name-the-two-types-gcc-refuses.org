* Acceptance

- The latch the client holds is a named type
- The jwks retry attempt is a named type rather than a lambda in the coroutine's frame
- The nats unity translation unit compiles with gcc 16 and the project's warning flags

* Plan

Reproduce the gcc error without a gcc build tree: the compiler sees the same
sources the clang build's unity file includes, so compiling that one file with
g++ and the project's warning flags is the same test, in seconds rather than an
hour of vcpkg and configure.

Then give each type a name that has linkage: the latch goes at namespace scope
beside =client::impl=, and the jwks attempt becomes a functor with the client,
the timeout and the result string as members.

* Result

ores.nats.lib compiles clean under gcc 16.2 and clang 21 with -Werror, so the
gcc nightly no longer stops on this library.

The two other failures in the same nightly are not this task's: the web build
reads a generated marketdata module that the source-to-feed rename deleted, and
the MSVC unity build runs out of template context on a generated entity. Each is
recorded on the parent story.
