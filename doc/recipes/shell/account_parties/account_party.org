#+title: Account Parties shell commands
#+description: Every command the account_parties submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:account_parties:

This file documents the account_parties resource at the shell, one section per command. Every command is a subcommand of =account_parties=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: DC3B170F-DCF9-5C84-8F19-917AEF20E96A
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
account_parties list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =iam.v1.account_parties.list=.

#+name: account_parties-list
#+begin_src ores-shell :tangle account_parties-list.ores :exports none
account_parties list --limit 1
#+end_src

:PROPERTIES:
:ID: 26B081E5-7882-546E-BE6F-29F41635442F

** =add=
:PROPERTIES:
:ID: EC2CA896-1B95-531A-A6A3-9AED537D018E
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
account_parties add <account_id> <party_id> <reason> <commentary>
#+end_example

It is addressed at =iam.v1.account_parties.put=.

#+begin_src ores-shell :tangle account_parties-add.ores :exports none

#+end_src

** =set=
:PROPERTIES:
:ID: 270E0D5B-9DD1-5B53-8F24-680359FBA515
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
account_parties set <account_id> <party_id> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =iam.v1.account_parties.put=.
