added to the table first, so it draws those without a new icon. The standards
need those rows. This task does not edit the standards.

The list prototype meets every line of the checklist except those below. Each
line not named here Meets.

| Line | Mark | What changed or why it stands |
|------+------+-------------------------------|
| Page, size, search, filter and order live in the address | Fixed | The prototype writes them to the address as it draws. |
| States: loading again with dimmed rows | Fixed | =?state=reloading= dims the rows. |
| A refused read is stated in words | Fixed | =?state=refused= says what the person cannot read and whom to ask. |
| Rows that changed after a reload are marked | Fixed | After a Refresh that follows a change, the row carries a gold mark for a few seconds. The strip for a change off the page is not drawn. |
| Tabs: a tab that does not apply is not drawn | Fixed | The Requests tab shows only while a request waits. |
| A person is drawn with a photo and a link | Fixed, in part | An avatar and the name. The name is plain text, because no person page exists in the prototype. |
| A value shows as a name | Fixed | A change reason shows its name and not its code. |
| The screen does not explain what is absent | Fixed | The "None yet" and "terms not drawn" sentences are gone. |
| Edit is on the card, and the header has none | Fixed | Edit stands on the Terms card. The record screen standard puts Edit in the header. The checklist says to follow the entity screen specification. |
| Save waits until a field differs | Fixed | Propose waits. "No change in substance" is never offered, because nothing can be saved without a change. |
| A commentary is required when the reason needs one | Fixed | Market practice changed needs a commentary. |
