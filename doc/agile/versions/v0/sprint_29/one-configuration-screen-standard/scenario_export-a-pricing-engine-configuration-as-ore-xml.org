** Save the file the server names

- Press *Export* in the dialog.
- The browser saves a file named *pricingengine.xml*; the name comes from the response, not from the dialog.
- No XML is shown in a text field and the page does not parse it.

*** Result

| Field  | Value |
|--------+-------|
| Status | PENDING |

** Read the file as ORE reads it

- Run =xmllint --noout pricingengine.xml=. It reports no error.
- The root element is =PricingEngines=.
- It holds five =Product= elements, in this order: Swap, CrossCurrencySwap, FxForward, CreditDefaultSwap, Bond.
- Each product states a =Model=, a =ModelParameters=, an =Engine= and an =EngineParameters=.
- =GlobalParameters= follows the products and holds =ContinueOnCalibrationError= true.
- The engine parameters carry ORE's own names, such as =Training.Sequence=.

** Get the same bytes from the shell

- In the shell, =pricing_engines export <configuration id> --file from_shell.xml=, with the id the record page shows.
- The command reports the file it wrote as *pricingengine.xml*.
- =cmp from_shell.xml pricingengine.xml= reports no difference.

* Notes

- The name comes from =ores_reporting_file_types_tbl=: the row for =pricing_engines= whose kind is =input_document= and whose direction is =input=, with =is_default= winning when a kind has several. A table with no such row refuses the export rather than inventing a name.
- The dialog's sentence uses a constant for the name today, so a tenant that renames the row would see the old name before the press while the saved file still takes the server's name. That is the one known gap; the test checks the saved file, not the pre-press sentence.
