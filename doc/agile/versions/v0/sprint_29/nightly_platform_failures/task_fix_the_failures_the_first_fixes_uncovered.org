* Result

The first fixes worked: Windows set up its database, macOS compiled and ran its
suites, the memcheck run completed and submitted to CDash, and the codegen and
include hygiene checks are green. Each nightly then failed further on:

| Failure | Run | Cause | Fix |
|---------+-----+-------+-----|
| Valgrind: 172 uses of uninitialised values | CDash 4468864 | =report_cashflow::value= had no initializer and the generator never set it, so the codec test wrote an uninitialised double. | The model gives it a default and a generator. The codec test runs clean under valgrind. |
| MSVC: test mains | 42181208341 | =BOOST_SCOPE_EXIT= declares a local that hides a global of =boost/scope_exit.hpp=: C4459, an error. | A named guard in every test main, the digest suite, the shell and the template. |
| clang-cl: hostname test | 42181208341 | The test included =unistd.h=. | It reads the host name portably, through =COMPUTERNAME= on Windows. |
| MSVC: =std::getenv= | latent | The CRT deprecates it, and the build treats that as an error; five tests called it. | They read the environment through =ores::platform::environment=. |
| gcc: redundant move | 42166109767 | A const condition made =std::move= a copy. | The condition is not const. |
| Memcheck: marketdata core timeout | 42166109767 | The whole-corpus walk outgrows the suite's own 3600 s budget under valgrind. | It skips under valgrind; the sampled case takes the same path. |
| Memcheck: feed loop deadline | 42166109767 | A test must store ticks within 60 s. | It skips under valgrind. |
| macOS: nats memory test | 42191098938 | It reads =/proc=. | It skips off Linux. |
| macOS: next fire unavailable | 42191098938 | Unknown: the read answers =internal_error=, and the log does not carry the message. | The test reports the message. |
| macOS: http client hang | 42191098938 | Unknown: the log does not name the case. | The suite registers the timeout listener. |
| macOS: linker warnings | 42191098938 | CMake repeats static libraries on purpose, and Apple's linker warns on each. | =-no_warn_duplicate_libraries= where the linker accepts it. |

Two causes are still open and wait on the next macOS nightly to name them. A
Windows build stops at its first error, so more may follow these.
