#+title: ores.marketdata.published_curves_operations
#+description: Codegen operation model for the published curve screens: the list of a tenant's published sets and candidates, one curve's last sets with the points they hold, and the act that takes a set out of use.
#+type: ores.codegen.operation
#+component: marketdata
#+subcomponent: api
#+entity_singular: published_curves_operations
#+namespace: ores::marketdata::messaging
#+brief: The reads of published curves, and the act that ends a set.
#+filetags: :model:operation:marketdata:
#+created: 2026-10-27
+#+updated: 2026-10-27

A published set is the =curve_publish= detail row of the request that
authorised it, and a screen reads three things about it that no existing read
answers together:

1. every set the tenant holds, with the curve, the party, the publisher and the
   state, because a reader finds one set for one series today and never the
   tenant's sets together;
2. the last sets of one curve and party with the points each holds, because the
   points tab draws them overlaid and the comparison draws two of them;
3. the act that takes a set out of use, because a set that ended is a state a
   reader must reach.

The first two are reads over the publish records joined to the series they
published and the observations the published set holds. The third is a write,
and it is an operation rather than a second half of the publish gate: the
publish gate's single-use rule is that one request publishes once, and a
withdrawal does not use a publish request at all. A supersession is not here,
because a supersession is a publish: the successor's own apply writes the link
on the set it replaced.

The points travel with the set rather than in a second read of their own. The
curve snapshot read states the values a series holds now, and it reads the
market at the caller's clock, so it cannot serve a set built at an earlier
as-of; the set's points are the observations the publish wrote at its own
as-of, and they are read beside it.

** published_curve_point

One pillar of a published set: where the point stands, the value the set holds
there, and the instant the value was observed.

#+begin_src cpp :name comment
/**
 * @brief One pillar of a published set.
 *
 * The pillar is the coordinate the datum stands at -- the term of an interest
 * rate curve -- and the value is the text the publish wrote, exact. The kind
 * says what the value denotes, so a reader that shows a rate and the discount
 * factor it implies knows which of the two it was given.
 */
#+end_src

** published_curve_set

One publish record as a reader draws it: the subject, the act that published
it, the state it is in now, and the points it holds.

#+begin_src cpp :name comment
/**
 * @brief One published set, or the candidate that waits to become one.
 *
 * The state is a function of the record's own facts and is stated here rather
 * than stored: `withdrawn` when the set was taken out of use, `superseded` when
 * a later set replaced it, `published` when a person applied a request and the
 * set is in use, and `candidate` when the request still waits. A candidate
 * holds no publisher and no published instant, so a reader cannot mistake it
 * for the set a desk prices from.
 *
 * A set read from the list carries its point count and no points; a set read
 * for one curve carries its points, because the screen draws them.
 */
#+end_src

#+begin_src cpp :name comment
/**
 * @brief The published sets of the tenant, newest first, and the candidates.
 *
 * A reader sees the sets in use by default. A candidate is a set nobody has
 * approved and an ended set is one that was in use and is not any more, so
 * neither is drawn unless the caller asks for it: a candidate read as the set
 * a desk prices from would be a lie, and an ended set is reached on purpose.
 *
 * The total is the size of the whole filtered set and not of the page, so a
 * screen can page without a second read.
 */
#+end_src

** withdraw_curve_request
:PROPERTIES:
:subject:  marketdata.v1.ops.withdraw_curve
:response: withdraw_curve_response
:END:

The act that takes a published set out of use, with the reason kept against
it.

#+begin_src cpp :name comment
/**
 * @brief Takes a published set out of use, as a new version of its record.
 *
 * The set is not deleted and its values are not cleared: the record keeps the
 * publisher, the published instant and the set's points, and gains the account
 * that ended it, the instant and the reason. A set that already ended cannot be
 * ended again, and a set that was never published cannot be withdrawn, because
 * a candidate is not in use.
 *
 * A withdrawal names no request when the tenant lets a trader act alone, and
 * names one when a decision stands behind the act. A request authorises one
 * withdrawal, so a request that already ended a set ends nothing else.
 */
#+end_src
