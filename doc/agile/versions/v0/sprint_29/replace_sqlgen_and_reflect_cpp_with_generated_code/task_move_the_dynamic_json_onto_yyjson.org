* Plan

The dynamic JSON is what a message whose members a client learns at run time
carries: the OpenAPI spec a person posts, a provisioning step's arguments, the
rows a conventions export pages through. Two things were missing, so the work is
the value and then the callers:

1. A document a program walks and builds with no shape, over the yyjson the
   codec already uses, and its MessagePack bridge. json_codec.hpp turns a stated
   type into JSON; this is the other half, and it states the wire traits a
   message needs so the NATS codec can encode it in either format.
2. Each caller reads and builds that document instead of rfl::Generic. The
   arguments of a step keep their lenient read; the OpenAPI registry keeps its
   $ref inlining, its cycle fallback and the examples it carries.

* Notes

**The document owns the tree; the value is a view.** A parsed document that a
reader rewrites is the common case -- the registry serves the spec it was
handed -- so one type owns the yyjson document and hands out views, and a view
lives no longer than the document it came from. That rule is what lets the
registry build a new tree from an old one: a value copied across documents is
deep copied by the API, not aliased.

**The wire needed a second bridge.** The conventions export pages a family whose
row type it learns at run time, so the request and the response cross NATS as a
document. The codec's format is chosen at startup, so the document states both:
JSON is its own text, and MessagePack bridges through the msgpack C API. A null
survives the round trip because a list request states =filter= and =as_of= as
null and the service reads a request strictly.

* Result

No file in the tree names =rfl::Generic= or =rfl::Object=: 79 uses in seven
files are gone. The dynamic JSON is a document, in both wire formats, and each
caller reads and builds it: the provisioning step's arguments, the conventions
export's paged family reads, and the OpenAPI registry's spec rewriting.

The whole tree builds, and 97 of 98 suites pass. The one failure is
=ores.marketdata.service.tests=, whose two ingest-loop cases time out only under
parallel load; it passes alone, it is not a codec path, and it is captured as its
own problem.
