* Decisions

- *Qualify the definition; do not add the alias.* The sibling class in the
  directory declares =using context = ores::database::context;= and uses it in
  both places, which is why its definitions compile. Adding the alias here would
  work too, but the header is the interface and it already states the type in
  full; the one-token qualification makes the definition agree with it.
- *Leave the rest of the commit alone.* Its other hand-written change is four
  lines in =curve_republish_service.cpp=, whose class already has the alias.
  Every other file it touched is codegen output, which the drift gate reports in
  step with its models.

* Out of scope

- A gate for this. A bare =context= in a definition is correct inside
  =ores.database= and in any file that carries a =using=, so a scan cannot tell
  the defect from the convention without knowing the scope of every file.
