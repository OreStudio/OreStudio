An IPv4 address range and the country code it resolves to, one row per range
per tenant. The ranges are found by containment -- =ip_range @> address= -- so
the range is the key and the index over it is a GiST index; a btree cannot
answer a containment test.

The store holds no history. A publish truncates it and loads the ranges the
dataset carries, because ip2country reissues its whole table rather than
amending rows.

* Columns

** ip_range
:PROPERTIES:
:type:         int8range
:primary_key:  true
:END:

The addresses this row covers, as the integers IPv4 addresses are counted in.

The range is half-open: it covers its lower bound and not its upper, so the
publish function makes it from the first address and the last address plus
one. Ranges that touch share a boundary rather than overlapping.

** country_code
:PROPERTIES:
:type: text
:END:

The ISO 3166-1 alpha-2 country the addresses in this range belong to.

* Artefact columns
:PROPERTIES:
:key: range_start
:END:

The dataset states a range by its first and last address rather than by the
range itself, so the staging row carries the two ends and the publish function
makes the range.

=ores.geo= keeps its headers at its own include root, so there is no directory

component rather than the surface.

* Notes

Bound to [[id:5B0A3DD1-A705-439B-9FA8-E5FEB9C1B267][SQL-only store]] (alongside its shape profile): the only reader of this table is =ores_geo_ip2country_lookup_fn=, which answers in SQL, so the model generates the schema and no client surface. Its key is an =int8range=, which no C++ type maps, so a domain class could not be generated for it in any case.

The range index is one of the few indexes in the tree that is not a btree.
