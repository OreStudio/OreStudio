* Summary

=ores.refdata= provides the reference-data foundation for ORE Studio —
currencies, counterparties, books, business units, party relationships, and
associated conventions. Every other domain component reads its codes and
conventions through it, and the UI drop-downs and validation rules are drawn
from it. It is a composite component with four sub-components and has no code
of its own: every generated and hand-written artefact lives under one of the
sub-components below, never directly under this directory.

* Inputs

- NATS requests from the shell, the HTTP server and peer services, addressed
  to the reference-data subjects the api module declares.
- PostgreSQL connections to the =ores_refdata_*= tables.
- Data-quality population events, which bulk-load reference data from
  =ores.dq=.
- The operator's session: tenant, party and workspace, resolved per request.

* Outputs

- Reference-data records with full temporal history, persisted to the
  =ores_refdata= tables.
- NATS responses and the =*_changed_event= announcements other components
  subscribe to.
- Currency-pair rate formatting and the convention cache the client module
  offers its consumers.
- The generated shell command units and their recipes.
