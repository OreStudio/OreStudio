- ores.http gains a dq part that answers the reads the coverage screen needs: datasets, dataset bundles, bundle members by bundle code, and artefact types.

* Result

* Notes

The C++ server has HTTP parts for analytics, assets, compute, core, iam,
marketdata, refdata, reporting, synthetic, trading and workflow, and none for
dq — the reads the screens need are served by nobody. The BFF has no DQ route
either: its seed-profile and workflow tests mention publishing, and no path
answers a DQ list.

A screen names its module, not its page, in =VITE_ORE_CPP_SCREENS= — the switch
is =baseFor(screen)= in =api/servers.ts=, and =api/quotes.ts= is the worked
example. One module per screen family is what keeps the flag honest.
