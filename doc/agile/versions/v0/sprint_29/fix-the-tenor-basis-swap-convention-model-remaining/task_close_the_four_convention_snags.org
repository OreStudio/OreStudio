* Result

** One live row per convention

Both parts now mark =convention_id= as a natural key that is unique, so the
generated table adds a partial index:

#+begin_example
create unique index ... tenor_basis_swap_pay_receives_convention_id_uniq_idx
on "ores_refdata_tenor_basis_swap_pay_receives_tbl" (tenant_id, convention_id)
where valid_to = ores_utility_infinity_timestamp_fn();
#+end_example

A convention can hold one live row of each leg form and never two, and the
partial predicate leaves the value-log history alone. The refdata suite is 467
cases and 5610 assertions, and the ORE suite 401 cases and 475592 assertions,
both against a database rebuilt from this branch.

** The five long and short leaves

=LongIndex=, =LongPayTenor=, =ShortIndex=, =ShortPayTenor= and =SpreadOnShort=
each have a curated label and description in =convention_term_curation.json=,
so the seeded contract grows by five rows and the value-set seed by five links.
The text is authored from the field the ORE parser reads, because the guide
documents the paying and receiving form and not this one; each entry records
that reason and the source line. The undocumented-terms evidence file drops
from 53 to 48.

** The bundle redesign, filed

[[file:doc/agile/product_backlog/inbox/carry-a-documents-families-as-a-bundle.org][Carry a document's families as a bundle, not as one struct of typed arrays]]
is in the inbox, with the anti-pattern, the package shape, the precedent not to
copy and the nightly failure it removes. The redesign is a story as well:
[[id:62370F84-69A5-4980-9774-28F49EF0C61C][Refactor conventions onto families and bundles -- the remaining work]], whose
task [[id:6E7E20DA-D08B-410B-B1B8-A571C40F83CF][Apply the same shape to the curve configuration document]] names the curve
document as the first candidate.

** The browser smoke, run on a live fleet

The fleet was stopped and the database recreated when this task closed, so the
page could not be opened; the check was carried to the inbox as
[[file:doc/agile/product_backlog/inbox/smoke-the-convention-record-page.org][Smoke the convention record page on a live fleet]].

It has since been run on a provisioned tenant, and it failed. The page had not
been seen since the parts were grouped, and three things were wrong: the list
answered 500 because the central row is grouped too and the BFF read =id= off
the top level, the record page matched a party the same way and reported the
convention missing, and it drew both forms' terms on a one-form convention --
with two of those terms named the same on both forms, so they drew twice.

All three are fixed, and the check now runs as
=projects/ores.web/packages/harness/tests/convention-record.spec.ts= against a
live fleet: both forms, each term documented, the five curated terms carrying
their new text, and a one-form convention told nothing about the other. See
PR #3960.
