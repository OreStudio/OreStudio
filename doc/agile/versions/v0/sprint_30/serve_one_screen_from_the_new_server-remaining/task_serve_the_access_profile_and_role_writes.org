* Acceptance

- Each of the 20 routes names its same-address C++ route in the inventory.
- A test proves each route against the answer the BFF gives.
- The local gate is green.

* Plan

Serve the access screens' role and lock writes at the BFF's addresses, in a
hand-written unit, =role_write_routes=: a role given to an account or taken
away, an account locked or unlocked, the tenant's roles with what each grants,
the permission catalogue, a role made, edited or removed, and the permissions a
role grants written whole or changed by what to add and remove. Each body is
read within the BFF's limits and refused with its message before the forward,
and a refused write answers as the BFF did: a role write as a conflict, a lock
as an invalid request.

The helpers the access units share, a refusal, a guarded forward and the length
of a text in characters, move into one header, =access_screen_answers=, rather
than one copy per unit.

The last nine routes move to [[id:0BD277CC-A6E2-4C34-BECD-8A81E8FD672C][Serve the access profiles, contacts and reporting tree]].

* Result

The C++ server answers 11 access writes and catalogues at the addresses ores.web
calls, each paired with its BFF route in the inventory. The tests prove each
body's limits, the refusals before forwarding, how changes apply to what a role
grants, and the shape of each catalogue.
