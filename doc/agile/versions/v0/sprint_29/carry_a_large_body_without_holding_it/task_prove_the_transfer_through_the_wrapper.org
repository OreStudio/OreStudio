* Goal

The grid wrapper moves every package, input, output and log through the storage
routes, and the upload now writes a part file and renames it. Nothing has run the
wrapper against it: the measurement proves the session's cost, and the sink's tests
prove the file protocol, but the path a real transfer takes is unproven.

* Result
Three cases run against a real =http_server= with the real storage routes, a real
RS256 capability token and the real =storage_transfer= client, which is what the
wrapper's =package_publisher= calls:

- 8 MiB uploaded, present at its key, digest equal to the file sent, the route's
  answer naming that digest, and no part file left behind.
- 3 MiB uploaded and downloaded again, byte for byte.
- An upload whose token names another bucket is refused, and nothing is written.

The grid wrapper process itself was not run: it needs an assignment from the compute
service, and the transfer path it depends on is what these cover.
