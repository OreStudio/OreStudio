#+title: How do I discover the physical-space catalogue?
#+description: Read the technical-space and facet pages in the codegen template library; each facet page lists its archetypes, templates and admitted model types.
#+type: recipe
#+level: cross
#+filetags: :codegen:compass:entity:archetypes:recipe:
#+created: 2026-07-19
#+updated: 2026-11-22

The physical space is the graph of =ores.*= technical-space/facet/archetype
nodes under [[proj:projects/ores.codegen/library/templates][=projects/ores.codegen/library/templates/=]] that
[[id:08FBD248-257A-A474-DD43-DB08949978F1][ores.codegen]] generates from — the successor to the retired
=facet_catalogue.org= profile system. See the [[id:B3CBBDED-7CD9-423B-94D8-F5C4C0488CEA][component catalogue]] for how
entities are discovered, separate from which addresses they can generate.

* Question

How do I see every valid =ores.*= address, or which archetypes a specific
entity will generate and why others are excluded?

* Answer

The catalogue is the set of pages in
[[proj:projects/ores.codegen/library/templates][=projects/ores.codegen/library/templates=]]. Each technical space
(=ores.cpp.org=, =ores.sql.org=, =ores.cmake.org= and the rest) and each facet
(=ores.cpp.domain.org=, =ores.cpp.repository.org= and so on) has its own page.
A facet page names the model types it admits (=#+model_types:=), its default,
and each archetype with its template. List the facets:

#+begin_src sh
git grep -l '^#+type: facet' -- projects/ores.codegen/library/templates
#+end_src

A model turns a facet or archetype off with an =:ores.*.enabled: false=
property, the most specific key winning. To see what a model actually feeds,
run =./compass.sh diff --scope <model>=: it reports the count of outputs.

* Script

The pages are data that compass-ng's =codegen= codec reads; nothing else
renders the catalogue.

* Tested by

Run the =git grep= and verify that it lists the facet pages, among them
=ores.cpp.domain.org=.
