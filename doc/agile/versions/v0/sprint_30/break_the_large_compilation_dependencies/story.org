* Goal

A change to one header rebuilds only the code that uses what the header defines. Today a few headers sit under most of the build, so a small change to one of them recompiles most of the tree. The database context is the case that started this story: =ores.database/domain/context.hpp= is included by most repositories and services, and through it every one of them parses =libpq-fe.h=, the pool, =<mutex>= and =<condition_variable>=, although most of them only pass a context along and never look inside it.

The story first analyses the include graph to find which headers couple the build and what to do with each type in them. It then fixes the database context, the known case, and applies the analysis to the other headers it names.

A developer sees the result as shorter rebuilds after a change to a shared header. The next engineer inherits headers that state what they need, with forward declarations where a type is only named, and a check that keeps it so.

* Acceptance

- An analysis of the include graph names the headers that most of the build depends on, and, for each type in them, records one decision: forward-declare, move to a smaller header, split, or keep. The analysis and its method are kept with the story, so it reruns.
- The database context is passed as =const context&= wherever it is only read or passed along, is forward-declared in every header that only names it, and =context.hpp= no longer includes libpq or the pool.
- Every other header the analysis names is changed per its decision.
- Each change states its measured effect: the objects that depend on the header, and the rebuild time after the header is touched, before and after, at named commits.
- The codegen templates emit the new form, so regenerated code keeps it.
- A check stops a header that only names a forward-declarable type from including its full definition again.
- No behaviour changes. Every test suite passes.

* Decisions

- The include graph, the cost of each header and the decision for each type are
  in [[id:AF6C4DA7-903E-4848-8807-73EA4E49E9CA][Investigation: The headers that couple the build]]. Its two
  instruments live beside it in =evidence/=, and both rerun on any commit.
- The cost is carried by three shapes: the codec chain rooted in =text_form.hpp=
  and =decimal.hpp=, the clock habit of =<chrono>= that =datetime.hpp= and
  =boost/uuid/uuid.hpp= carry into most objects, and the logging chain opened by
  =make_logger.hpp=. The work goes in that order, not in order of the database
  context.
- Rebuild radius and parse cost are separate measures, and this story is about
  the first. Forward declarations reach only the types held by pointer or
  reference.
- A header family is not uniform, and only a compile says so. The repository
  archetype emits two headers, and the junction one carries a =context ctx_=
  member in 29 generated files, so it keeps the definition while its 539
  siblings take the declaration. The check that guards the rule can see a header
  that includes too much and cannot see one that includes too little.
- The copies are real and come from codegen: 21874 by-value =context=
  parameters, 11141 of them emitted by the =repository= and =service=
  archetypes. Changing them to =const&= is worth doing for run time and for the
  one synchronous reference capture in =feed_kind_registry.cpp:492=, but it does
  not shorten rebuilds.
- =context.hpp='s radius is structural: cutting the include from all 1738
  repository headers saves one object, and cutting every header in the tree
  still leaves 179 of 365 objects reading it. The only lever on the radius is
  splitting the type, which needs its own task.
- The rebuild saving is inside =context.hpp=, not in its users. Four files
  include =pq/pool.hpp= and 365 objects rebuild when it changes, because
  =context.hpp= is the door. Cutting that edge takes 147 objects off
  =pq/pool.hpp= and =pq/transaction.hpp= each. =pq/connection.hpp= moves only
  with =pq/pool.hpp= and =pq/statement.hpp=, because each of those reaches it.
- =libpq-fe.h= costs 0.04 s to parse and still sits under 375 objects. It is a
  blast-radius problem, not a parse-time problem.
- The rest of the header cost is parse time, in three shapes: the codec chain,
  =<chrono>=, and Boost.Log. It is real and it is a different task's leverage.
