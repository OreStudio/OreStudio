* Goal

The ORE codec holds no database session and calls no other component's repository. Its only remaining knowledge of a run is where each file sits inside an ORE input directory.

* Acceptance

- store::import_run and store::export_run are gone, and nothing calls them.
- The package helpers — the run document's name, where each file sits in the archive, and the paths the run document declares — stay and are covered by tests.
- ores.ore.core links no ores.database, ores.analytics.core or ores.reporting.core library, and none of its public headers includes their headers.
- The codec suite passes with the run store's database tests deleted.

* Plan

The store held two things that do not belong together: the database import and
export, and the layout of an ORE input directory. The layout stays and moves to
=xml/run_package.hpp=, because an ORE package is an ORE artefact; the import and
export go, because the live import is the service's, over NATS, and nothing but
the store's own tests called them.

=report_package_handler= is the one caller, and it used only the layout. Its
three call sites move to the new namespace. The component's dependency block
drops =ores.database=, =ores.analytics.core= and =ores.reporting.core=, and the
drift check and the ore suites prove the result.

* Result

Merged as #3990. The codec holds no database session: the database import and
export are gone, and the layout of an ORE input directory lives in
=xml/run_package.hpp=, where the rest of the ORE package knowledge is.

The declared libraries fall from 22 to 19: =reporting.core=, =analytics.core=
and =scheduler.api= are no longer loaded. =ores.database= is no longer a direct
link; it still arrives through =ores.refdata.core=, until the conventions bundle
moves, and through the profile's =nats= and =service=, which the story's Notes
count as a finding of their own.

Proven: the ore suites pass, no header or source includes the three removed
libraries, and the component regenerates to exactly what is committed.
