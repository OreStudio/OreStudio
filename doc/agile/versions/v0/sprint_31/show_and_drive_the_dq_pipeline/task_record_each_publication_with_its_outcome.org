* Goal

=ores_dq_dataset_publications_tbl= gains a writer and the columns a reader needs:
one row for each dataset a publish dispatches, carrying the outcome, the messages
the run produced, and what it wrote. A dataset's page then says when it was last
published, whether that run worked, and why it did not.

* Acceptance

- The bundle and dataset publish verbs append one row per dataset they dispatch,
  and the row is written whatever the outcome.
- The row carries an outcome — published, published with warnings, or failed — and
  the messages that go with it, each with a severity, so an operator reads why a
  run wrote nothing.
- A row and the workflow step it came from agree on the reason: the step already
  states its error, and the log row states the same one.
- A test publishes a dataset that fails and reads the row back with its outcome and
  its message.
- The dataset page's Publications tab draws from it with no mock data.

* Notes

This was captured before it was pulled into the sprint:
[[id:5C20BEF9-13CA-48B5-8221-E83C1D6345DD][The publication run log has no writer]].
Read it first; it records what =record_publication= was, why =publish()= has no
caller, and the two coherent answers, one of which this task takes.

The outcome and the message are part of the same task and not a second one,
because a row that exists and cannot say why it failed is a row the screen cannot
use: the design in
[[id:5344ADC1-E729-4846-BE07-C6BC2169C4C9][Is my reference data complete?]] draws
the message beside the counts, and the coverage prototype draws it in the
Publications tab.
