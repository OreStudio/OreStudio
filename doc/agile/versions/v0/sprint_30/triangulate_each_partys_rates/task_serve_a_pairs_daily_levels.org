* Acceptance

- One operation answers a pair's daily levels for a party over a date range.
- The source is chosen per pair by sources_for_pairs, and a pair no source can express is refused by name.
- The levels come from replay_fixings over the party's own fixings; nothing new composes a rate.

* Plan

Slice 2 of the move onto the CRM, as [[id:C330DD6F-258B-4D41-930D-AE00FC60BF2E][the derive task]] laid it out: one operation over
=read_fixing_sources=, =sources_for_pairs=, =topology_builder= and =replay_fixings=.

- *Wire.* =marketdata.v1.ops.get_pair_levels= joins the fixing read model: a party, a pair, a
  last date and a day count in; the provider, the pivot and parallel =dates= and =levels= out.
- *Composition.* =compose_pair_levels= is a pure function of the party's sources, the request
  and a window reader, so its rules are tested without a database. It chooses the source per
  pair, reads each side that is not the pivot, replays only the days every side was fixed on,
  and keeps the fresh levels.
- *Entitlement.* The handler lends the composition =fixing_reader::window=, so each leg is read
  under exactly the entitlement a fixing window already has.
- *Leg lookup.* =read_fixing_sources= already read each fixing series' URI and dropped it; it
  now keeps it by provider and currency, so nothing builds a URI from a publisher's name.

* Result

A consumer asks for a pair and a window and gets the pair's daily levels, composed from the
party's own fixings through the source that quotes both sides. No consumer names a publisher,
a leg or a pivot any more to read a history: the service chooses them from data.

- *Acceptance.* The operation answers a party's pair over a range. The source is chosen per
  pair by =sources_for_pairs=, and a pair no source expresses is refused with =pair_unserved=
  and the pair's name. The levels come from =replay_fixings=; nothing new composes a rate.
- *Tests.* Seven cases state the rules: a cross through the pivot each day, a pair against the
  pivot read either way round, a day only one side was fixed on having no level, a pair only a
  later-ranked source quotes being read from it, an unserved pair refused by name, a refusal of
  the fixing read passed through as the pair's refusal, and a pair of one currency refused.
  Two of them use invented currency codes, so nothing depends on a name the code knows.
- *Found on the way.* =fixing_reader.hpp= named its protocol as =messaging::=, which inside
  =ores::marketdata::service= resolves to the service library's own =messaging= namespace in a
  unity batch that sees it. It compiled only because no service file included it. Both readers
  now name the protocol from the root.

*What this does not do.* Nothing calls the operation yet. The derived source still reads two ECB
windows; the next task, "Derive the volatility quotes from the pair's levels", moves it onto this operation and deletes the ECB constants, and its
provisioning run is the end-to-end proof of this handler.
