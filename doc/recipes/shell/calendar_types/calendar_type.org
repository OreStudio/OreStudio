#+title: How do I run the calendar_types commands from the shell?
#+description: Every command the calendar_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:calendar_types:

This file documents the calendar_types resource at the shell, one section per command. Every command is a subcommand of =calendar_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 3C227EC9-2B1A-5BF2-A757-1DA35B87F9A9
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
calendar_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.calendar_types.list=.

#+name: calendar_types-list
#+begin_src ores-shell :tangle calendar_types-list.ores :exports none
calendar_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: D1671AE8-D910-5C7A-AB48-25AEA8B6227B
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
calendar_types get <code>
#+end_example

It is addressed at =refdata.v1.calendar_types.get=.

#+name: calendar_types-get
#+begin_src ores-shell :tangle calendar_types-get.ores :exports none
calendar_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: F7056CE5-B638-56F1-AAAB-25E7B86A2990
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
calendar_types add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.calendar_types.put=.

#+name: calendar_types-add
#+begin_src ores-shell :tangle calendar_types-add.ores :exports none
calendar_types add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 8E11B202-F58E-51A4-AB42-22FC7CA0945A
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
calendar_types set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.calendar_types.put=.

#+name: calendar_types-set
#+begin_src ores-shell :tangle calendar_types-set.ores :exports none
calendar_types set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
