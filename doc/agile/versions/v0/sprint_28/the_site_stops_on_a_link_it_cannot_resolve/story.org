* Goal

The documentation site builds. A full export stops when org cannot resolve an
=id:= link, and this page's id disagreed with the links that name it. The page
defined it in lower case while two of the five links spelled it in upper case,
and org resolves ids by exact string:

#+begin_example
Build failed: Org export aborted.  Unable to resolve link:
"465CA244-C488-4C69-ACA3-C694D104A42A"
#+end_example

=doc/meta/document_types.org= settles which spelling is right: every =:ID:= and
every =[[id:UUID]]= link is uppercase hex, and a hand-edited or copy-pasted
UUID follows the same rule. So the definition was the deviant one, and the fix
uppercases it and the five links, not the other way round.

* Acceptance

- The page's =:ID:= is uppercase, and every link that names it matches exactly.
- The six pages that carry the id publish without a resolution failure.
- A full site build succeeds.
- =site-page=, =lint=, =org-links= and =backlog-indexes= pass.

* Decisions

- Uppercase the definition rather than lowercase the links. The rule is
  documented; conforming to the deviant side would have made the tree agree with
  its own exception.
- Leave the rest of the tree's lowercase ids alone. About 7,956 documents carry
  a lower-case =:ID:=, so widening this hotfix would turn it into a migration.

* Out of scope

- The 7,956 lower-case =:ID:= properties elsewhere in =doc/= and
  =projects/*/modeling/=. They violate the same rule and are a migration, not a
  hotfix.
- The regenerated backlog index. Another environment added a capture without
  regenerating the indexes, which reds =backlog-indexes= on every branch cut
  after it; the row is carried here because it was in the way, and it is
  generator output rather than part of this story.

* Result

PR #3551. The page's id and the five links that name it are uppercase, which is
the form =doc/meta/document_types.org= requires, and the full site export
succeeds: 12,585 nodes and 52,094 links.

The reviews were right about the direction: the first version lowered the
conforming links to the deviant id, and the rule says the definition was the
outlier. They were also right that the task's gate claims were wrong. =site-page=
would have caught the broken link, because the links landed in commits that
changed their own pages; the gap that let it through is that the full build is
=deploy_site=, which =compass check= never runs, and that =lint= uppercases both
sides before comparing ids, so a case disagreement cannot reach it.
