* Goal

Every place a trade's status is drawn paints it as the badge the system holds
for that status, so two screens cannot state one deal differently.

A trade's status is a coded value like a book's or a party's, and the badge
catalogue paints those. It paints no trade status, because no =trade_status=
domain exists in it: the values a trade holds are the ones the trading status
lookup seeds, and nothing in the catalogue names them. So the screens fall back
to words -- the queue draws the status as a muted tag and the trade page as its
own tag -- and each screen is free to state the same deal in different words.

The gap surfaced building the Operations authorisation queue, where a deal's
status sits beside its authorisation state and the two are read together.

* Acceptance

- The badge catalogue holds a trade-status domain, with one badge for each code
  the trading status lookup seeds, and the mapping is complete: a code the
  lookup holds is a code the domain paints.
- A trade screen draws the status through that badge: the queue's page, the
  trade page and the blotter's rows say the same thing about one deal.
- A status code the domain does not paint is drawn as plain text rather than
  hidden, and the test says so.

* What the work will have to settle

- Which catalogue the domain belongs to. The badge catalogue holds the codes the
  system paints, and the trading status lookup holds the codes a trade may hold;
  the two must agree, and the domain is the place they agree.
- Whether the badge's words are the status's own words or a shorter form. The
  house rule is that a badge states the value it paints, so the status's name
  wins.
- Whether the colours are new or reused. Book and party statuses already hold a
  set of neutral pairs; a trade status whose meaning is the same should reuse
  them rather than add a fourth vocabulary.
