* Goal

Make it impossible for a =TEST_CASE= to sit inside a conditional compilation
block, so that no green suite can hide a case the compiler never received.

The task is a gate plus the tree change the gate demands. The gate is a static
rule and needs no build, so it runs on every pull request.

* Acceptance

- A gate fails on a =TEST_CASE= inside any =#if=, =#ifdef=, =#ifndef= or
  =#elif= region, and passes on the tree as it stands once the six cases that
  use the construct are restructured.
- The gate runs in the =codegen-drift= workflow, beside the other gates, with no
  build, no formatter and no dependency beyond the Python standard library.
- The six cases in the three files that use the construct register
  unconditionally and report as skipped where they cannot run, so the case count
  a suite reports always matches the number of cases its sources declare.
- A test in the codegen suite fails when the gate stops finding anything, so the
  gate cannot pass every tree by finding nothing.

* Plan

*Which sub-case the rule must catch.* Every way a case can fail to reach the
compiler runs through the preprocessor. The measured instance was a guard on
=BOOST_ASIO_HAS_LOCAL_SOCKETS= placed above every boost::asio include, so the
macro was undefined when the guard was read and the file compiled to nothing.
The same shape covers =#if 0=, a guard on a macro that no longer exists, a guard
whose defining include was moved inside it, and a platform guard that is wrong
for the target. One rule covers all five: a test case declaration may not sit
inside a conditional block.

*Why the rule is static.* The promoted capture below proposed preprocessing each
test source with its own flags from =compile_commands.json= and comparing the
declared cases against the preprocessed output. That is exact, and it cannot
gate a pull request: =codegen-drift.yml= has no C++ build, and
=continuous-linux.yml=, which has one, runs on a schedule and on tags. A static
rule needs neither, and it makes the class impossible rather than reporting it.

*What the gate reads.* The scan strips comments and string literals, tracks the
conditional nesting depth, and reports every =TEST_CASE= whose depth is not zero
together with the directive that opened the region. Stripping matters: a =#if=
inside a comment or a raw string is not a directive, and a =TEST_CASE= named
inside one is not a case.

*What the tree change costs.* Six cases in three files, all legitimate platform
guards: the three readiness cases in =ores.service=, two in
=ores.platform/tests/net_network_info_tests.cpp= under =__linux__=, and one in
=ores.platform/tests/environment_environment_tests.cpp= under =_WIN32=. Each
moves its guard from around the declaration into the body, with =SKIP(...)= in
the branch that cannot run. The case then registers everywhere, reports as
skipped where it cannot run, and the suite's case count is stable. That is
strictly more visible than the construct it replaces.

* Result

* Promoted from capture

Captured 2026-09-26 in the product backlog; promoted preserving the UUID.

Two claims in this capture were superseded by the plan above: the check does not
preprocess with =compile_commands.json=, because no pull-request job can, and the
tree held 722 test sources rather than 684 when the work started. The capture's
own wording is kept as the record of what was known when it was filed.

** What

Add a check that fails when a =TEST_CASE= in a test source never reaches the
compiler. For each =*_tests.cpp=, count the cases the file declares, preprocess
it with its own flags from =build/output/<preset>/compile_commands.json=, and
fail when a declared case does not appear in the preprocessed output. It writes
nothing and needs no test run, so it can sit beside the other codegen gates and
run in the same CI job.

** Why

The hazard is silent in the strongest sense. The translation unit compiles, the
link succeeds, ctest runs the suite and reports green, and the only evidence is a
case count that nothing compares against the sources.

The measured instance is the =ores.service= readiness suite. Its three
=TEST_CASE=s sat inside =#if defined(BOOST_ASIO_HAS_LOCAL_SOCKETS)=, and the
guard was placed above every boost::asio include, so the macro was never defined
when the guard was read and the file compiled to nothing. ctest reported 39 cases
where the sources held 42, and the three missing names were exactly the readiness
tests. A clean-standard record then cited that suite as the coverage for
=systemd_notify.cpp= under V08, so the record claimed verification it did not
have. An independent verifier found it by preprocessing the file with its own
flags and counting what reached the compiler.

The same shape covers =#if 0=, a guard on a macro that no longer exists, a guard
whose defining include was moved inside it, and a platform guard that is wrong
for the target.

The class is small enough to sweep today. There are 684 test sources in the tree
and three carry a preprocessor conditional at all, two in =ores.platform= and
both correct.
