* Result

A derived point's provenance now names the recipe that built it. =point_provenance=
carries =derivation_config_id=, =derivation_config_version= and =source_as_of=, read
from the annex row the snapshot already fetches. A quoted point, a manual point and a
hole carry an empty id, version zero and the epoch. The snapshot asks for no extra
read, and still asks for provenance only when the caller sets =include_provenance=.

A test writes a derived annex row and checks that the snapshot returns its config id,
version and source as-of, and that every other node carries none. Without the reader
change the three fields stay empty, so the test fails.

The evolution read keeps no provenance. The story records the reason: the watch
journey reads the lineage of one selected point, so no step needs a matrix over the
range. This closes the second acceptance bullet by its second branch.

The acceptance audit's bullet 8 now has its recipe. Whether the lineage read for a
point in the past needs a key by observation stays a gap of that read, named in the
journey, and not of this task.
