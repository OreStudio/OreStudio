* Acceptance

- the known ORE error list states a kind on every line: market data or engine configuration; no line is a parse error and no build error names a field of the trade
- the kind of an error is decided by a fixed rule, not by hand: the test
  classifies each message against a table of ORE's message patterns (a missing
  curve, quote, index or reference data is market data; a missing pricing engine
  or engine builder is engine configuration), and a message no pattern matches is
  of the trade kind
- the DoubleDigitalOption parse error, the ScriptedTrade index named .SPX, the CallableBond empty handle and the BondOption volatility curve id are each fixed or proven to be market data, with the evidence in the task
- BalanceGuaranteedSwap runs in the ORE engine test, or its crash is shown to come from the engine configuration, with ORE's message
- every line of the known missing-paths list is filled by the generator, or names the reason the generator leaves it out
- a test fails when a new line of the trade kind appears

* Notes

** The state of the scripted index on main

The recorded =ScriptedTrade= states its index as =.SPX=, which ORE refuses
("Could not build index info for '.SPX'"). Since =cf010d9c18= the export writes
=EQ-.SPX=, which is the name ORE reads, but it also drops the =Strike= Number
variable, and the recorded files were not re-recorded, so =the generated trades
are the ones recorded= fails on main for two trades. The fix keeps =EQ-= names,
restores =Strike= (and the full variable set =AsianBasketOption= reads), and
re-records the files in the same commit.
