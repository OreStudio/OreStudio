  files outside tests, 0 of them generated (0%). 0 messaging headers, 0 of
  them hand-written.
- Consumer census. The only reference in the tree was
  =projects/CMakeLists.txt= line 124, =add_subdirectory(.../ores.connections)=.
  =#include <ores.connections/...>= appears nowhere outside the component.
  A grep for =ores.connections=, =ores.connections/= and =connection_manager=
  across every =.cpp=, =.hpp=, =CMakeLists.txt=, =*.cmake=, =*.ts= and =*.py=
  outside the component returns nothing.
- The component is not a codegen component. It has no row in
  =projects/ores.codegen/library/component_catalogue.org=, and the codegen
  has no SQLite target. The generated entity, domain and repository
  templates hard-code the PostgreSQL shape: =schema = "public"=, tenant,
  version and audit columns, and =sqlgen::session= on a connection pool.
  This component uses =sqlgen::sqlite= with a file path. So 63 of its files
  are generatable only after new generator capability, which a component
  with no consumer does not earn.
- 7 files are transitively dead inside the component as well:
  =domain/recent_party.hpp= and =repository/recent_party_{entity,mapper,repository}.{hpp,cpp}=.
  The only caller of that family, =connection_manager::get_recent_parties=,
  has no caller of its own. =get_child_folders= and =resolve_connection=
  are unreachable in the same way.

  =projects/ores.security/modeling/component_overview.org=,
