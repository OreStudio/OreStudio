This page gives the data of compass-ng's =ore_value_sets= and
=parameter_value_sets= codecs, which ORE Studio runs over its parameter value
sets. The =* Definition= names both codecs, because the generator and the gate
resolve one model from the same curation; each table below is data they read,
and the prose says what it is for. The tables were module-level literals of
six modules under =projects/ores.sql/utility/=: =convention_value_sets.py=,
=curve_value_sets.py=, =ore_aliases.py=, =ore_schema_types.py=,
=generate_ore_element_map.py= and =generate_convention_kind_terms.py=, which
compass-ng used to parse. The regular expressions and functions of those
modules are compass code.

* Rule

Every parameter a screen draws names a value set by a curated link, every set
is named and states only a rule its kind can hold, and no source restates
another's set. =ore_value_sets= writes the value set seed, the ORE element map
and its columns, and the convention kind terms with their validation triggers,
from one resolution of the curation; =parameter_value_sets= reports every rule
the same resolution breaks, and writes nothing.

* Why

A value set is the rule the store applies to a parameter's value: the values
an enumeration lists, the catalogue it names, or the pattern or bounds it
states. ORE's reader, parsers and schema are the authority for each rule, and
the tables below say where the extraction of that authority needs a person:
which reader converts a value, which kind a leaf really has, and what a reader
of the element map is told about it. Stating them once, beside the prose that
explains them, means the generator and the gate read the same curation.

* Catalogues

The catalogues of reference data a value may name, with the relation that holds
their codes. A term whose kind the =Catalogue kinds= table names, and a curve
setting whose declaration names a catalogue, takes a set that names one of
these instead of copying its values. This was =CATALOGUES=, which
=convention_value_sets.py= and =curve_value_sets.py= each stated, alike.

| code               | name       | relation                            | description                          |
|--------------------+------------+-------------------------------------+--------------------------------------|
| =refdata.currency= | Currencies | =ores_refdata_currency_catalogue_v= | The currencies reference data holds. |

* Catalogue kinds

=convention_value_sets.py='s =CATALOGUE_OF=.

|------------+--------------------|
| =currency= | =refdata.currency= |

* Rendered kinds

The convention term kinds ORE's reader converts before the store sees a value,
and the family of =ore_renderings.json= that states which renderings mean one
fact. The set states every rendering, so a document may write any of them, and
a configuration holds the one form the set names. This was
=convention_value_sets.py='s =RENDERED_OF=.

| kind                      | renderings                 |
|---------------------------+----------------------------|
| =business_day_convention= | =business_day_conventions= |
| =day_counter=             | =day_counters=             |

* Kinds without a list

would otherwise leave the term free text with no one told. This was
=convention_value_sets.py='s =WITHOUT_LIST=.

|------------+--------|
| =calendar= | =text= |
| =index=    | =text= |
| =text=     | =text= |

* Convention own sets

The sets the convention family defines itself, rather than drawing from a
parser, the schema or a catalogue. =pattern= is the pattern a value must match,
where the set states one; =is_ordered= is =yes= when the order of the values
means something. This was =convention_value_sets.py='s =OWN_SETS=.

| code                 | name         | description                                                             | source_kind | pattern                      | is_ordered |
|----------------------+--------------+-------------------------------------------------------------------------+-------------+------------------------------+------------|
| =convention.integer= | Whole number | A whole number the ORE code parses as an integer.                       | =integer=   |                              | no         |
| =convention.period=  | Period       | A period such as 2D, 3M or 1Y6M, which the ORE code parses as a period. | =regex=     | =^[+-]?([0-9]+[DdWwMmYy])+$= | no         |

* Type overrides

Convention leaves whose extracted type is wrong, the kind that holds instead,
and why. A row with no =element= holds of the term under every convention; a row
with one holds of that convention's term only, and a row for every convention
wins over it. This was =convention_value_sets.py='s =TYPE_OVERRIDE=, whose key
was (term, None) for every convention and (element, term) for one.

| element            | term                    | kind                      | reason                                                                                                                                                                                                |
|--------------------+-------------------------+---------------------------+-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
|                    | =SettlementDays=        | =integer=                 | The ORE schema declares SettlementDays xs:integer, and the extractor typed it text because no parser reaches it.                                                                                      |
|                    | =FixingDays=            | =integer=                 | The ORE schema declares FixingDays xs:integer, and the extractor typed it text because no parser reaches it.                                                                                          |
| =CommodityForward= | =SpotDays=              | =integer=                 | The ORE schema declares the commodity forward's SpotDays xs:integer, and the extractor typed it text because no parser reaches it.                                                                    |
| =IborIndex=        | =DayCounter=            | =day_counter=             | ORE stores this day counter as a string and never parses it, so a typo is silent in the engine; it means the vocabulary every other convention states, so the catalogue refuses the typo.             |
| =IborIndex=        | =BusinessDayConvention= | =business_day_convention= | ORE stores this business day convention as a string and never parses it, so a typo is silent in the engine; it means the vocabulary every other convention states, so the catalogue refuses the typo. |
| =OvernightIndex=   | =DayCounter=            | =day_counter=             | ORE stores this day counter as a string and never parses it, so a typo is silent in the engine; it means the vocabulary every other convention states, so the catalogue refuses the typo.             |

* Parser tables

The ORE parser whose list names one family of renderings of
=ore_renderings.json=. ORE's reader states each rendering once, in the table
that converts it, and the parser that accepts it states the word it means; the
two must agree, and a rendering only one of them names is a problem the codecs
report. This was =ore_aliases.py='s =PARSER_TABLE=.

|------------------------------+----------------------------|
| =parseBusinessDayConvention= | =business_day_conventions= |
| =parseDayCounter=            | =day_counters=             |
| =parseFrequency=             | =frequencies=              |
| =parseCompounding=           | =compoundings=             |
| =parseDateGenerationRule=    | =date_rules=               |
