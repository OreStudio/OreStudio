* Goal

A prototype is the design record its journey cites, and this story keeps it
readable after the sprint that built it closes. Every prototype branch merges
into main: the =/prototype= hub answers the credentials, operations and
onboarding screens, and each journey's Prototype section names the path on
main rather than a branch that may disappear.

* Decisions

- The operator set the convention on 2026-10-05: prototypes stay in git for
  future reference, like the operations prototype a later task re-read as its
  design record. The merges are kept as merge commits, so each prototype
  branch becomes an ancestor of main and git itself reports it merged.
- The hub answers every route under =/prototype=. The credentials and
  operations screens arrive as their branches wired them; the onboarding
  screens, which their branch wired onto the application's own routes
  (=/setup=, =/iam/tenant/onboard=, =/refdata/party/new=), are re-homed under
  the hub, because those routes now belong to the application.
- Conflicts resolve toward main for every shared file a prototype branch had
  drafted earlier (the sprint 25 documents, the i18n locales, the password
  field and policy, the sign-in page), because main carries the merged
  successor of that same work. The prototype screens themselves are kept as
  accepted.

* Out of scope

- Cleaning the prototypes up (tests, typing, wiring them into the
  application's real routes) stays out; they are the record as accepted.
- The static prototypes under =doc/prototypes= stay where they are.
