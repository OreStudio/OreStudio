(One paragraph: the idea.)

* Why

=cpp_service_config_options.hpp.mustache= renders a config member's type and never its
=:default:=, so a model that states a default gets a struct member with no initialiser.
=ores.marketdata.service/config/options.hpp= is the live example: the model declares
=:default: 0= on =stale_seconds_ir= and =stale_seconds_fx=, the generated header carries
=std::int64_t stale_seconds_ir = 0;= because someone added it by hand, and regenerating the
component deletes the initialiser. The two members are read in =application.cpp= behind
=> 0=, so an uninitialised read is undefined behaviour.

The drift also hides a second hand edit in the same component: a four-argument
=market_fixing_repository::read_latest_for_series(ctx, tenant, party, series_ids)= that no
caller uses. Regenerating deletes it, which is the right outcome for dead code but not one
to land by accident while fixing something else.

Found while a branch that touches the marketdata models made =component-drift= render that
component; the check had been quiet because it only renders the components a branch changes.

* Acceptance

- The options template emits a member's =:default:=, and the marketdata options header
  generates its two initialisers rather than carrying them by hand.
- =component-drift= passes for the marketdata component with no hand-edited generated file.
- The dead fixing-repository overload is removed, and the change says so.
