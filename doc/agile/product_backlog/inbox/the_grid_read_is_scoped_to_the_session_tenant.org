#+description: The grid belongs to the installation: every tenant's work runs on the same hosts. * What

The grid belongs to the installation: one set of hosts runs every tenant's
work, and the samples describe the fleet, not a tenant's slice of it
([[id:7B820710-161C-4926-B5AA-5EF2772A3652][Watch the compute grid]]). The
reads filter by tenant anyway. =latest_node_samples= selects
=DISTINCT ON (host_id) ... WHERE tenant_id = $1=, and the grid summary read
follows the session's tenant; the node sample carries a =tenant_id=, so the
filter has something to bite on and quietly returns one tenant's rows.

The accepted design says the grid is read whole. The fix is to drop the
tenant filter from the grid reads — the stored =tenant_id= stays on the
sample as attribution — and to guard the read with the permission the
journey records, so *the whole grid* and *who may see it* stay two separate
decisions.

* Why

Silent and wrong: the person whose job is to see all the nodes reads a
shorter table and cannot tell it is short. The samples are already
installation-wide; only the read narrows them. This is a defect under the
read, not a missing feature.
