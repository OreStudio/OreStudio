* Result

The rail is answered by one grouped read. =count_blotter_rail= groups
=ores_trading_trade_summaries_vw= by the dimension the request names, under the
same filter the page takes, and =trading.v1.blotter.rail= returns one node per
group with its count. The portfolios a book sits under are rolled up from the
grouped rows, not from the trades.

Merged on main in #4403 at =b903acb4=. The six =[rail]= cases in
=trading/core/tests/blotter_rail_tests.cpp= cover the book counts, the portfolio
subtree, the filter the page honours, a list of values, a search, and the
refusal of a dimension the rail does not have.

The store behind the rail is still the union view. This task gave the rail the
right shape; making it cheap is [[id:A0AE98E4-DF2E-4D75-9099-FF3E2555B5B1][List a
package as the trade it is]] and
[[id:2A42890A-63B5-4076-B934-E98685795CF0][Order the page by an indexed key]].
