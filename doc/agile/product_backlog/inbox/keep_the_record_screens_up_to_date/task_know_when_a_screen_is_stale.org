* Goal

One hook, useEntityChanges, tells a list or a record page that what it shows is older than what exists, by comparing the change time with the time it loaded. It never reloads the screen itself.

* Acceptance

- A change after the load makes the screen stale; a change before it does not.
- A change that arrives while a load is in flight makes the screen stale, so no change is missed.
- Lists, relationship views and record pages use the hook through tasks 4 and 7.

* Result

=useEntityChanges(watches, load)= takes the entities a screen shows and the query state (=dataUpdatedAt=, =isFetching=) and returns =stale= and =changedAt=. A screen is stale when a change reached the browser after the load that produced its data began. The comparison uses the browser's clock at both ends because the server's clock and the browser's differ; the server's time is kept only for the tooltip. The page Change notification said to compare the server's change time with the load time, and task 8 corrects that.
