* Acceptance

- The book and portfolio generator comments state the real rule: X-0 is a sentinel the fixtures seed, and no fixed code is valid on its own.
- The eventing-test template seeds the currency a generated parent portfolio's trigger validates, and the book eventing test carries that seed before the parent write.
- ores.refdata.core.tests passes and the full ctest suite passes.

* Plan

The fix belongs in codegen, not in the generated files. Three edits, no
hand edits to generator or test output:

1. =core.py=: carry the parent entity's =seed_currency= flag through
   =_parent_entity_info=, stamp it on each FK as =parent_seed_currency=,
   and aggregate it onto the domain entity as =seed_parent_currency=.
   This mirrors the =seed_country_sentinel= / =parent_seed_country_sentinel=
   pair that already handles the same shape of problem for calendar.
2. =ores.cpp.eventing-integration-test.nats_integration_test.org=: add
   the matching include, =using= and seed blocks. The seed writes a
   synthetic currency stamped =iso_code = "X-0"= before the parent
   portfolio write.
3. Regenerate: =compass build --direct codegen_templates= to tangle the
   org to =cpp_nats_integration_test.cpp.mustache=, then
   =compass codegen entity generate book= and =portfolio=.

The generator comments in =ores.refdata.book.org= and
=ores.refdata.portfolio.org= also claimed that every test tenant's active
set already holds X-0. The observed failure contradicts that, so both
comments now state the real rule.
