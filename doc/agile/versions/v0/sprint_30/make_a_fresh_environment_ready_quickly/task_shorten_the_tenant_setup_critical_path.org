The tenant setup workflow of 2026-11-20 on a fresh database, from the step
state lines of =ores.workflow.service.0.log= (start offset, duration):

| Start (s) | Took (s) | Step |
|-----------+----------+------|
| 0 | 95 | publish_bundle |
| 99 | 90 | provision_party |
| 189 | 94 | load_staff |
| 191 | 600 | give_party_surface_blueprints (failed, see the sibling task) |
| 191 | 719 | publish_party_curves (12 curves deferred) |
| 283 | 243 | generate_trades |
| 910 | 47 | publish_party_forwards |
| 956 | 115 | publish_party_surfaces |
| 1072 | 0 | complete_provisioning |

The critical path is publish_bundle, provision_party, publish_party_curves,
publish_party_forwards and publish_party_surfaces: 1072 s. While the curve and
blueprint steps ran, the market data service missed every adapter's heartbeat
and its repository reads were logged as slow (5710 mappings, 2557 fixings),
which points at the service being saturated rather than at one slow query; a
measurement is the first job. The ticks smoke check provisions a tenant the
same way, and its slowest step was publish_party_surfaces (see the capture
[[id:C8714C54-91DF-4941-932D-303BFBB3DD0B][Speed up the ticks smoke gate]]).
