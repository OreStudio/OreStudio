* Result

=read_series_shape= now returns a term axis in order of length through the new =in_term_order=. The snapshot, slice and evolution reads take their nodes from that one function, so none of them changed. The shape tables keep the order the source stated.

Acceptance met:
- Terms stored as 2M, 10Y, 30Y, 5Y, 3M are read as 2M, 3M, 5Y, 10Y, 30Y. A unit test and an import-to-snapshot test cover it.
- A value that is no term follows the terms in its stated order. Tested.
- A second source needs no work, because the sort runs on every read.
- An axis that is not a term is not touched. The code checks the axis kind. No test covers this case.

Checked live: the EUR/CHF surface, stored in the order of the demo file, is read as 1W, 1M, 2M, 3M, 6M, 9M, 1Y, 18M, 2Y, 3Y, 4Y, 5Y, 7Y, 10Y, 30Y, with no re-import. The marketdata core suite passes, with six new cases.

Decision: the sort is at read time and not at declare time. See the story.
