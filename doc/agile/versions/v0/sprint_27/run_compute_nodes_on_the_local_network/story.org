* Goal

Three machines on the local network, goedel (192.168.1.199), newton (192.168.1.22) and 192.168.1.11, run compute nodes (ores.compute.wrapper) that join an existing environment's grid over NATS. Each host is reachable over SSH, and not every host is up at any one time, so the deploy must report a host that is down and carry on with the rest. The story builds on the work done for the WSL host: the compass env deploy command with the compute role, proven live on Newton in sprint 25, and the backlog items on the vendored ORE engine package and on compute tenancy. The story records, per host, the operating system, the container tooling found, and the packages the host still needs, so that nothing is installed without review.

The grid shows 26 running wrappers. Podman was present on the laptop and

Each wrapper registers itself in the host table on its first heartbeat. Its
host id is the UUID v5 of =hostname:replica=, as for the local wrappers, so
goedel:1 keeps the id it had.

** What ran

Eight batches of the TA002 interest rate swap (18, 90, 300, 120, 120, 60, 120
and 120 jobs) were dispatched from the shell. The first batch finished 18 of
18 with outcome Success. Later batches were counted from the node logs, not
from the result table, and only the ones that matter are recorded here.

- Batch 4 failed on every remote host. See "Download of the engine package".
- After the fix, the node logs of batch 5 show goedel with 18 jobs done, the
  laptop with 31 and newton with 48, and no failure after the redeploy. Two
  earlier connection resets on goedel came from containers replaced during the
  deploy.

The batches were not all counted to the end, so no total is claimed.

** The deploy

=compass env deploy all= deploys every profile that has compute settings. It
probes each host over ssh first and checks for podman on the remote before it
transfers the image, so a host that is down or lacks podman is reported and
the others carry on. A run that skipped a host exits with status 1.

** Defects found and fixed

- The remote run script passed =--log-directory= without =--log-filename=.
  The logging options validator has refused that since sprint 25, so a node
  exited at start. The script now passes a file name and logs to the console.
  The runtime role's loop had the same line and is fixed the same way. The
  runtime role was not deployed here, so that half is untested.
- The services roster capped the compute wrappers at the five replicas in the
  registry. Wrappers past the fifth showed as missing while their heartbeat was
  current. The roster now gives each host its own slot and drops an older
  instance on the same host as a restart's leftover.
- The idle heartbeat did not tell the stats reporter, so "since heartbeat"
  counted from the last heartbeat sent during a job and grew while a node sat
  idle. It now counts from the last heartbeat of any kind.
- ORE sends six memory-use lines per run through its WARNING channel. All 2670
  stored ORE warnings were those lines, so the Logs screen showed nothing else
  as a warning. The parser stores a WARNING line that ends with the memory
  report suffix as debug. Every other WARNING stays a warning. The stored rows
  were corrected.
- ORE writes its log lines in the local time of the machine, and the parser
  reads them as UTC. The five wrappers on the serving machine stored their
  lines an hour late. The wrapper now starts the engine with =TZ=UTC=. The
  147294 rows of 362 earlier local jobs were moved back one hour. Rows of jobs
  whose directory was already cleaned up could not be identified and were left.
- Giving each wrapper its own work directory left it with no engine package, so
  21 remote wrappers downloaded the package at once, the HTTP server timed the
  transfers out and every job failed with a partial message. See below.

** Download of the engine package

The wrappers on a host share one package cache, set with the new
=--package-dir= option. A lock file per package lets one wrapper download while
the others wait. A failed transfer is retried up to four times, with a pause
that grows by five seconds each time, and the partial file is removed between
attempts. A SHA256 mismatch still fails at once.

Tested on goedel (3 wrappers) and newton (11 wrappers) with the shared cache
moved aside. Each host created one lock file and one archive of 58946608 bytes,
finished within about 15 seconds of the first request, and then ran jobs with
no failure and no retry. The download count was not measured directly, because
the wrapper logs the download at debug level. A host with no cache is still
the case that decides this, and the laptop was not tested empty.

** Nodes that survive a crash and a reboot

Each wrapper runs as a systemd user service built from a Quadlet file, with
=Restart=always=, and starts at boot while the user has lingering on. The
deploy replaces the units and the containers of an earlier deploy, and fails
with a message when the user manager is down or podman is older than 4.4.

Tested on goedel. A =podman kill= of one wrapper was followed by a restart
within 20 seconds. After =sudo reboot= the three containers were running when
the machine had been up for 0 minutes, healthy a minute later, and their node
samples were arriving. The laptop and newton still run the plain containers
from the earlier deploy and move to units on their next deploy.

* Decisions

- The nodes join the system tenant and register themselves on their first
  heartbeat, as the sprint 25 proof did. No host row is created by hand. The
  host id of a wrapper is the UUID v5 of =hostname:replica=, which is how the
  local wrappers get theirs.
- A host runs one wrapper per core but one, so it stays responsive.
  =ORES_COMPUTE_REPLICAS= in the host profile overrides the count.
  =ORES_COMPUTE_HOST_ID= is gone.
- =compass env deploy all= probes each host with a 5 second ssh timeout before it
  deploys, and it checks for podman on the remote before it transfers the
  image. A host that fails either check is reported and the run carries on.
- Nothing was installed on any host by this story. The packages the laptop
  needed were a list in this story for review.
- The grid screen decides that a computer is up when one of its nodes is
  running, which is the runner state the nodes table already shows. No other
  threshold was added.
- A node sample carries the machine name rather than the screen guessing it from
  the host name. A node that reports none is shown under "Unnamed machine".
- The engine runs with =TZ=UTC= on every node, so the parser's assumption that
  ORE writes UTC becomes true. The alternative, reading local time in the
  parser, would be wrong for the UTC containers.
