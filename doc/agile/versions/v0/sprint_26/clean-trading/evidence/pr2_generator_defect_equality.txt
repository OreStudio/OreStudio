The note that names the cause:
  projects/ores.trading/api/include/ores.trading.api/domain/balance_guaranteed_swap_instrument.hpp:43:25: note: defaulted 'operator==' is implicitly deleted because there is no viable 'operator==' for member 'identity'

Cause
-----
projects/ores.codegen/library/templates/cpp_domain_type_class.hpp.mustache:161 emits
    friend bool operator==(const <entity>&, const <entity>&) = default;
for every generated domain class.
projects/ores.codegen/library/templates/cpp_field_group.hpp.mustache emits no
comparison operator for the field-group struct, so a domain class whose member is a
field group has its defaulted comparison implicitly deleted, and the build treats
that as an error under -Werror.

At 39f99acef3 neither file had a comparison operator, so the committed tree
compiled. The current templates add one to the domain class only.

The fix is at the source, in the field-group template, with a regression test in the
codegen suite, and then a regeneration. The other field-group models live in ores.dq
(one) and ores.codegen (one, a worked example); ores.dq is not in
COMPONENTS_UNDER_TEST, so no registered component is affected, but its generated
output would change and that is recorded.
