* Summary

The library of payoff scripts is reference data of the system tenant: each
script, each variant of it (a purpose such as =FD= or =AMC=), its inputs, its
results and calibrations are rows ([[id:833F8F79-7FF0-42B0-8C52-E3ED6596843E][ores.trading.script]], [[id:A2BE6361-0489-4A63-A1B7-6B07BB3F6000][ores.trading.script_variant]],
[[id:F08D458F-B694-4B2F-A945-E22544A9222F][ores.trading.script_input]]). Every change is a version, whether ORE ships a new
library, ORE Studio corrects a script ORE ships, or a person publishes a script
of their own. A trade states the version it was booked on
([[id:358CC548-3892-45A1-A916-DF4A48ADED03][A scripted trade names a library script or states its own]]), so a change never reprices a booked trade silently.

* Detail

** Where scripts come from

- *ORE's library.* The seed states every script of ORE's =scriptlibrary.xml= as
  ORE ships it, generated by compass-ng's =script_library_seed= codec; the seed
  is never edited by hand.
- *Corrections.* Where ORE ships a script ORE itself cannot run, a correction
  writes a new version of the one variant after the seed:
  =trading_script_library_corrections_populate.sql=. It applies when its text
  occurs once, does nothing once the code holds its replacement, and fails the
  load otherwise, so a library that changes the script is reviewed. Today it
  corrects =WorstOfBasketSwap='s missing semicolon and the =FD= variant of
  =GenericBarrierOption=, which rolled its values back only to the first
  monitoring date.
- *A person's own script.* Publishing a script is a change to reference data
  like any other, and parses before it is stored
  ([[id:8FD7BD95-AAEC-4CF9-A9F4-D609A9DEFBD8][ORE's grammar is the one authority on whether a script parses]]).

** What publishing does

A script is parsed when it is published, not when ORE first runs it: a script
that does not parse is refused at the load or the publish, with the line and
column ORE's grammar reports. Its inputs are derived from its text
([[id:92449D70-09E2-4391-B716-A1001F22B271][A script's free variables are its inputs]]) and stored with it.

** How it reaches a run

The run writes the library from the rows, so a script the rows lose fails the
run that needs it, and the engine reads what the store holds, not the copy ORE
ships ([[id:708554F7-FA3A-49E1-8A11-4AE968C76758][The engine is given a script's text]]).

** Where today's code differs

The inputs are mined into the seed by a text script, not derived by a parser,
and nothing parses a script before ORE does: =WorstOfBasketSwap='s syntax error
was found by an ORE run. A trade states no library version.
