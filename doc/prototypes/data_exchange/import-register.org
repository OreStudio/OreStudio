* Summary

Four journeys need a question no per-import screen can answer: what has
happened in this party? A failed family is found here, a retry is told from a
first attempt here, a promotion records its hops here, and a party-scoped user
is kept out of another party's rows here. The register is its own screen even
though no journey names it as its destination.

It is throwaway. Open [[file:import-register/][the register]].

* Detail

** What it argues

- A row is an attempt, not a file. A retry keeps the source and still gets its
  own row, which is the one thing the shell cannot do.
- The promotion record is a view of the register, not a second screen. Each hop
  is an import from files, and the row carries the source environment, the
  target, the manifest and the actor.
- The party boundary is the screen's structure. The operations user has no
  party selector and sees one party; the tenant administrator switches party
  and then reads that party and no other. Another party is refused, not empty.
- "May retry" is inferred, and the screen says how thin that is: the maker and
  the decider may retry, because no import permission exists to grant.
- A first attempt is never hidden. The failed row stays beside its retry, with
  both counts, so the person can see the difference.

** Variants and states

=?variant=list|promotion|compare|failed|refused=,
=?actor=admin|ops=, =?party=acme-trading|acme-capital-markets=. The party
selector appears only for the tenant administrator.

** What is real and what is not

The attempt shapes, the promotion hops, the party scoping rule and the retry
duplication are taken from the journeys. The request ids, manifest ids, times,
counts and people are invented. There is no import history, no promotion
record and no party-scoped import read today; that absence is the screen's
subject.

** The workflow behind a row

A row is a workflow instance. The register reads
=workflow.v1.instances.list= scoped to the party's imports — =target_kind= and
=target_id= name what each run acts on — and
=workflow.v1.ops.get_workflow_steps= answers one row's rail on the
[[file:one-import-run.org][Run]] screen. The state a row shows is the
instance's, and a retry of it keeps the same instance id.

** The verdict

Not signed off. The screen survives though no journey names it, because four
journeys need it as a secondary surface. The owner must decide whether it is an
import register, a workflow history, or both — and whether it is the place the
promotion record lives.
