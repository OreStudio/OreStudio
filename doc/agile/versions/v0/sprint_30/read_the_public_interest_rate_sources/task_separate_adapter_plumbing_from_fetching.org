* Goal

Each public source has its own adapter, because each publisher has its own API, its own format and its own terms. The code that does not depend on the publisher is in one library: the announce, the demand set, the backfill from the latest stored fixing, the refresh and the publish of ticks. An adapter supplies a fetcher and a parser for its publisher, its adapter code and its settings, and nothing more. The Frankfurter adapter is the first user of the library, and its behaviour does not change.

- The library holds the code that does not depend on the publisher, and the Frankfurter adapter links it.

- The tests of the Frankfurter adapter pass with no change to what they assert, and a fresh environment stores the same count of FX fixings as before.
- A new adapter supplies its fetcher, its parser, its adapter code and its settings, and nothing else.

* Notes

Today the adapter knows only Frankfurter. =source_feed= takes a =frankfurter_fetcher=, =hosted_source= has a =frankfurter_key=, and =official_adapter.cpp= sets the adapter code to ="frankfurter"=. The synthetic simulator and the derived FX volatility source in =ores.synthetic= are adapters too; read how they are hosted before the plan names where the library lives.

Two publishers share one adapter only when their API and format are the same, as the Frankfurter providers are. Otherwise each publisher has its own adapter.
