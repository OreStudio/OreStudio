* Notes

- The mechanism, reproduced minimally. In a table cell, the probe
  command of two bracketed classes delimited with tildes exports; the
  same command delimited with equals signs aborts with the same
  =:space:= error. The equals sign inside the command closes the span, so
  the character class that follows is parsed as a link. Tilde delimiters
  cannot be closed by an equals sign, and an inline source block is not
  protected inside a table cell, which is why the fix is the delimiters
  rather than the form.
- The check is exact rather than heuristic. No org link type begins with a
  colon, so a parsed link whose target does is always a mistake; the
  check reports the file, the line and the target, and it does not need
  the id map, so it is cheap enough for the doc-lint job.
- Two defects of this family have now reached main: the =file:= link with
  a line-number search into a Python file, fixed in PR #2262, and this
  one. The check this task adds catches the second shape; a general
  "every link resolves" check would need a full parse of the corpus,
  which the site build already does on every push to main.
- A second, unrelated finding, carried here because it surfaced while this
  task ran the generators. =doc/recipes/http/currencies/currency.org= is
  generated output (it carries the =#+generated:= marker and the
  =http_recipe.org.mustache= template) that the tree did not contain: the
  other HTTP resources' pages are committed, this one was not. Nothing
  reported it, because the codegen drift check reports drift with =git
  diff= and an untracked generated file is invisible to it. The page is
  committed on this branch; the gate hole it exposes -- a generated file
  the tree never received -- is the same class as the unrun CMake file
  list check captured separately.
