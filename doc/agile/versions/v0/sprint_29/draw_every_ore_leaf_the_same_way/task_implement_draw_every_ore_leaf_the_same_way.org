* Goal

One standard says how every screen draws a leaf of an ORE document and the element type it belongs to, with the exact words, and an Allium specification carries its state rules so tests can follow them. Conventions are the first application: a convention's terms read exactly as a product's parameters and the engine run settings do, with their documentation in the one contract and their metadata in data. Product pricing and engine run settings follow through the gaps the standard records.

* Acceptance

- One knowledge page states the leaf and element type rules with identifiers and the exact words, and the UX hub, the knowledge index and the screen review checklist point to it.
- An Allium specification states the switch, the documentation, the value in force, the control, the edit marks, the filters and the gaps.
- The standard records conformance for engine run settings, product pricing and conventions, rule by rule.
- A convention's terms are drawn with the shared parts and the one word namespace: documentation entries for conventions.xsd, the kind metadata in data, and the controls from value sets.
- The owner decides the open words: the convention noun, the section button, the switch's name and the seed tag.
