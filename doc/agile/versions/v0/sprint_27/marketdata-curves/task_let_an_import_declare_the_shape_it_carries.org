* Goal

A curve declares its shape when a build publishes it, so the point check has something to enforce. An observed or imported structure declares nothing, so every point of it is accepted and its shape is inferred from whatever arrived, which is the state the shape tables exist to end. Let an import declare the shape of each series it carries, from what the file states, and settle the layering first: the shape writer sits in ores.marketdata.service because it reads the reference tenors, and the import sits in ores.marketdata.core, so the writer has to move down or the tenor check has to move into the store.

* Acceptance

- An import declares the shape of every series it creates, from what the file it reads states rather than from whatever points it happened to write.
- A series the import does not name keeps the shape it had.
- The reference-tenor check applies to an imported shape as it does to a built one, or the task says which path is not checked and why.
- The layering is stated in the task result: where the writer lives and why, and what the tenor check costs the component that cannot reach the reference data.
- Re-importing the same file declares the same shape and writes no duplicate axis or value rows.

* Plan

1. /Settle the layering./ The writer moves from =ores.marketdata.service= down to
   =ores.marketdata.core=, beside the import that now calls it, and the core
   library links =ores.refdata.core= for the reference tenor read. The goal's
   premise was that core cannot reach the reference data. It can: =ores.ore.core=
   and =ores.synthetic.core= already link that library, and the import already
   reaches =ores.refdata= over NATS for the currency pairs. One code path for the
   check is better than a second source of the same reference data.
2. /Make the check a policy of the call./ =declare= takes a =term_check=. A build
   passes =against_reference_tenors=, because its pillars come from the tenant's
   own curve configuration and a pillar the table does not hold is a mistake. An
   import passes =as_stated=, because the terms it records are the file's. The ORE
   example corpus writes =13Y= and =1Y6M=, which the 46-code reference table does
   not hold, so checking an imported shape would refuse valid market data.
3. /Declare before the points./ The import collects, for each series the file
   carries, the datums the file names for that series, and declares every shape
   before =market_observation_repository::insert=, because the write-time check
   refuses a point whose axis the series does not declare.
4. /Declare for every series the file carries, not only the ones it creates./ The
   goal says each series the import carries, and acceptance two says a series the
   import does not name keeps the shape it had. Declaring only for series the file
   creates does not survive contact with the corpus: one series is named by
   several files with different grids, so the first file's shape would refuse
   every later file's points and =every_line_of_the_whole_corpus_reaches_the_database=
   would fail. A later file therefore appends its terms to the stored shape.
5. /Leave an optional coordinate out when nothing states it./ The swaption and
   other types declare =strike_level= and =expiry= as coordinates a key may leave
   out. A file of ATM-only quotes states no strike, so the axis constrains nothing
   and is not written. A required coordinate that no point carries is still
   refused.
6. /Append rather than renumber./ A second file for one series writes only the
   values the series does not already hold, and each new value takes the place
   after the values already there, so the order the shape stores survives.
