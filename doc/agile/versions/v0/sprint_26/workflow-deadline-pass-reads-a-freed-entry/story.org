* Goal

A step that outlives its deadline stops its run on every platform. On macOS the
run was never stopped: =workflow_engine::expire_overdue_steps()= failed the
step, then read the run's id through a reference into a map entry it had just
erased. Two =ores.workflow.core.tests= cases have failed on both macOS CI jobs
since the deadline landed.

* Decisions

* Out of scope

- A test that fails on Linux without the fix. The fault is a read of freed
  memory, which only an allocator that reuses the block, or valgrind, makes
  visible; the two existing macOS cases are the regression check.

* Result

The pass now erases a step's awaiting entry after it has read and stopped the
run, and the exception handler still erases it once if anything throws. Valgrind
reported one invalid read on the deadline case before the change and none
after; the workflow suite passes.
