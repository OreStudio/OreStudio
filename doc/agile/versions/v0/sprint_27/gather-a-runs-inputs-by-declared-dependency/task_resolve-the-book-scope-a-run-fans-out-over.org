* Goal

The run resolves its scope once, inside =gather_trades=, and treats it as one
bag of books: the handler asks the risk report configuration for its books and
hands the whole list to one export. A report covers hundreds to thousands of
books, and each needs its own trades archive, its own market data and its own
portfolio XML.

Resolve the scope up front, record it against the run, and let the run fan out
one gather per book.

* Acceptance

- The book scope a run covers is resolved once and recorded against the run.
- A run over N books dispatches N gathers, each naming one book, and a book's
  artifacts are addressable on their own.
- The package step runs only when all N have produced what the run declared.
- A single book failing fails the run, and the failure names the book.

* Plan

The scope already has an owner: the definition's risk report configuration
holds the books, and =gather_trades= reads them today. What changes is that the
list stops being an argument to one export and becomes the fan-out width.

The load has to be bounded. Hundreds to thousands of concurrent NATS requests
and the same number of archives is not a burst to hand to a single connection;
the fan-out wants a worker pool whose width is configured, with the run
waiting on the set rather than on each request in turn. The number belongs in
the story's measurements when the shape is chosen.

This task is where the graph task earns its keep: without a declared artifact
set and a fan-in completion condition, N producers have no defined "all done".
