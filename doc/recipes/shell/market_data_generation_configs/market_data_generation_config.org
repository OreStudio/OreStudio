#+title: How do I run the market_data_generation_configs commands from the shell?
#+description: Every command the market_data_generation_configs submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:market_data_generation_configs:

This file documents the market_data_generation_configs resource at the shell, one section per command. Every command is a subcommand of =market_data_generation_configs=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 1303E4C8-68E8-5446-9271-75A52396E088
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
market_data_generation_configs list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =synthetic.v1.market_data_generation_configs.list=.

#+name: market_data_generation_configs-list
#+begin_src ores-shell :tangle market_data_generation_configs-list.ores :exports none
market_data_generation_configs list --limit 1
#+end_src

** =add=
:PROPERTIES:
:ID: B7801E11-4D47-5069-8A41-1381E6E79178
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example

** =set=
:PROPERTIES:
:ID: B72B5AB6-2106-5659-89D0-024F0F1698EF
