* Notes

Root causes:

- Shell suites: cli 2.3.0 returns the bare verb from completion. =ores.shell= uses =CliFileSession=, so no tab completion is reachable. The tests and their templates now expect the bare verb.
- GCC: a =const= local made a =std::move= redundant in the trade summary repository.
- Valgrind MPK: the NATS C library holds one per-thread error slot for its async callback thread. The suppression covers this reachable block.
- Valgrind UMR: the =cpp_nats_integration_test= template read =*party_ctx.party_id()= for party-isolated parents. In two tests =party_ctx= is the plain =h.context()=, so the optional is empty and the read is undefined behaviour. The row got uninitialised bytes as its =party_id=. The template now reads the session party only when writes are party-scoped. TLS hid the origin. =PGSSLMODE=disable= and a field probe located it.
- Windows: the cron tests called =localtime_r=. They now call =localtime_safe=.
- macOS change stream: two epochs could match on a coarse clock. =make_epoch= now increases strictly within a process.
- macOS next-fire: the exception missed its catch clause. =nats_connect_error= now has a key function in the library, which anchors its type info. This is the likely cause, and only the macOS nightly can confirm it.
- macOS HTTP client timeout: cause not found. The tests now print each name at start, so the next hang names the test.

Neither macOS nor Windows ran locally. The nightly run is the final proof for those platforms.
