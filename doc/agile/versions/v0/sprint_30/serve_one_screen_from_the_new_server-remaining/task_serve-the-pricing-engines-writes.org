* Goal

Serve the pricing engines' three writes. A write takes the whole document, as a
read answers it, and the analytics service saves it across the header, its
products and its parameters. A write that omits a product or a parameter that
the earlier version held removes it, which is how the document save of that
service behaves.

* Acceptance

- The C++ server answers =POST /api/reporting/pricing-engines=,
  =PUT /api/reporting/pricing-engines/:id= and
  =DELETE /api/reporting/pricing-engines/:id= at the BFF's member names and
  status codes: 201 on a create and 204 on a removal.
- A create writes the reporting configuration header first and the document
  second, and removes the header when the document write fails.
- A write removes the products and the parameters that the document no longer
  names.
- A removal removes the document through the service, and a service that says it
  did not is a refusal that carries its sentence.
- A body that names a member the route does not know is refused, as in the
  earlier families.
- A test proves each refusal; the happy paths need a live estate and this task
  does not prove them.
- Each route in scope names its C++ equivalent in the inventory.
- The local gate is green.

* Plan

Branch =feature/serve-the-pricing-engines-writes=.

The save builds on the document unit that the reads task adds. It writes up to
five hundred products and five thousand parameters, and the limits are the BFF's
so a document the screen accepts is a document the gateway accepts.

The reason a write carries travels with it. The analytics service's document
save has no field for one, so the gateway states it as the BFF does and the rows
carry it.
