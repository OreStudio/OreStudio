* Notes

Found on 2026-10-04 during the comment pass of
[[id:E773291A-0E73-4AAA-86AD-E94E16D691AF][Clean the marketdata code]]. That
pass removed the closer comments from marketdata's hand-written code. The owner
chose a task of its own for the templates, because the change reaches every
component.

The 14 template sources, each tangled into a =.mustache= file:

- =ores.cpp.history-provider-registrar=: header and implementation;
- =ores.cpp.http-route=: route and operation implementations;
- =ores.cpp.nats-event-cache=: cache header and registrar wiring;
- =ores.cpp.nats-event-registrar=: header and implementation;
- =ores.cpp.nats-handler=: header;
- =ores.cpp.nats-sub-registrar=: header and implementation;
- =ores.cpp.service=: implementation;
- =ores.cpp.shell-command=: command and operation implementations.

On 2026-10-04, =git grep= found 3,175 C++ files with a commented closer; the
=Template:= header of 2,873 of them names one of these templates. The other 302
are hand-written and stay with their own components.

The lever: =sed -E 's#^\}\s*// namespace.*$#}#'= over the template sources and
over the files their =Template:= header selects. Applying it to the generated
files, rather than regenerating them, keeps other components' unrelated drift
out of the PR; the drift checks then prove the edited files match a render.

** How the change was verified

A full rebuild reached 19% in two hours on the shared build lock, so it would
have held the lock for about ten hours more. Decided with the owner on
2026-10-05: verify by tokens and by one component instead. Every removed line is
=} // namespace ...= with no trailing backslash, so no line splice joins it to
the next and the compiler sees the same tokens in all 2,972 files. The
marketdata targets and everything they depend on are built and tested end to
end, and the nightly build compiles the rest.

** The ten files left alone

The first sweep failed on ten generated services in =ores.scheduler= and
=ores.synthetic=. Their closer comments were gone, but each already differs from
its template for other reasons: =job_definition_service.cpp=, for one, was
generated before its template learned ordering and filters. Touching a file
makes the sweep hold the change responsible for all of its drift, so the ten
were restored from main and listed in the script's =EXCLUDED=. Neither component
is in =COMPONENTS_UNDER_TEST=; sprint 27's =clean-scheduler= and
=clean-synthetic= stories regenerate them, and since the templates no longer
write the comment, it leaves them then.
