This page documents a [[id:F44766FA-1E9C-416F-849A-E131101B2ECA][user journey]]: A trader corrects a candidate curve or surface by hand where the market is wrong or thin, with a manual point or a spread overlay, and each correction carries a reason.

A user journey describes what one person is trying to do, before anything is
built. It is a design document that outlives any sprint, so it names the
screens, the entity fields each screen shows, and the operations and messages
each step needs.

* Goal

"I want to override the parts of this candidate the market got wrong or never
gave me, and I want the hand value to stay put while the feeds keep ticking."
The journey is done when every correction the trader intended is on the
candidate, each carries a reason, and the candidate still reads as a candidate:
nothing has been published.

The trader keys a point for three reasons. The market is wrong, so the hand
value corrects it. The market is thin or absent, so the hand value stands in
for it. The trader wants a what-if, so the hand value is a candidate only.

* Actor and trigger

The actor is the trader, acting as maker: the person who holds the market-data
management role for this party and owns the candidate. An approver owns the
decision to publish, in a different journey. The trigger is a bad print, a
stale or missing quote, a thin tenor, a broken pillar, or a request from
pricing to mark a point by hand. The journey starts at a candidate curve or
surface and ends when the trader leaves it, still a candidate.

A manual point is a candidate correction. It stays a candidate until it is
approved and published, and the rule that keeps it against a later feed write is
[[id:C1C37A35-7DE8-4FD2-8A2F-E7E2CF08EED4][Manual correction of a derived market data set]].
The one act this journey asks for that does not exist is the spread overlay.

* Steps

1. *Open the candidate.* The person opens *Curves and surfaces* and selects
   the candidate curve or surface. The system reads the =market_series= row
   and lists its points with =marketdata.v1.market_observations.list_by_series_id=.
2. *Read the points.* The system shows one row per =oresmd_uri= with its
   value, its =source= tag and its =observation_datetime=. A point keyed by hand
   carries the source =manual.operator=, so the screen marks it as a correction
   and never as a feed value.
3. *Key a curve point.* The person chooses *Set manual point*, picks a tenor,
   types a value and states a reason, and confirms. For a curve the coordinate
   is the tenor. The service checks the coordinate against the shape the series
   declares and writes the point with an annex that names the author.
4. *Key a surface point.* For a surface the coordinate is an expiry and a
   strike. The person picks both, types a value and states a reason. The shape
   declares both axes, so the point is addressed by the two labels the grid is
   indexed by, and a label the shape does not hold is refused.
5. *Clear a manual point.* The person selects a manual point and chooses
   *Clear manual point*. The service closes the point's annex row, so the feed
   value shows again, and the closed row stays in the annex's history.
6. *Apply a spread overlay.* The person chooses *Apply spread overlay*, picks a
   parallel shift or a twist, picks a node or a segment to apply it over, types
   the shift and states a reason, and confirms. The system has no shift
   operation, so the button names the subject it needs and changes nothing.
   See /What is missing/.
7. *Read the corrected candidate.* The system redraws the curve or surface
   with the manual points applied and marks each correction with its reason; the
   automatic values stay beneath, so the person reads what the market sent and
   what the desk replaced.
8. *Confirm the hand value survives a feed update.* The person waits for, or
   forces, a feed update. The hand value stays until it is cleared: the guard
   drops an automatic write to a coordinate an operator owns at the manual
   point's own instant, leaves the manual row in place at later instants, and
   the read prefers the manual point
   ([[id:C1C37A35-7DE8-4FD2-8A2F-E7E2CF08EED4][Manual correction of a derived market data set]]).
9. *Leave unpublished.* The person chooses *Leave unpublished* and returns to
   the list. The corrected candidate is still a candidate.

Writing a correction, if it existed, would be immediate: the reply would carry
the corrected candidate, so the journey carries no state of its own. The only
state it would leave is the row on the candidate, which stays until it is
cleared.

A manual point is not a separate entity today: the screen reads and would
write =market_observation= rows. Because those rows carry no actor and no
hand-written marker, the correction has no entity of its own; see /What is
missing/.

The operation is shape-driven: one subject serves a curve and a surface, because
the coordinate is one value per axis the shape declares. The observation row says
=manual.operator=, the annex row keeps the author, the reason code and the
commentary, and the annex registers a history provider, so the trail of a
correction is readable through =marketdata.v1.history.get=. Clearing closes the
annex row and keeps it in the history.

* What is missing

One act is missing.

1. *There is no spread overlay operation.* A mark moves one point by hand. A
   shift moves many by one decision: a parallel shift or a twist, over a node or
   a segment, with its own reason. The subjects =marketdata.v1.curve.shift= and
   =marketdata.v1.surface.shift= would each name the kind of shift, the node or
   segment it applies over, the shift and the reason. An overlay is not a loop
   of manual points, because it applies to whatever the automatic values are at
   the time the read happens, and a mark fixes one value forever. Until it
   exists, *Apply spread overlay* names the step and stays inert.

The precedence rule has one limit, and it is a limit and not a gap: the guard
reads the annex and the insert is a separate statement, so a manual point
committed between them, by another transaction, can still be replaced by an
automatic write at its own instant. Closing the window needs the check inside the
insert statement. The rule and its limit are stated in
[[id:C1C37A35-7DE8-4FD2-8A2F-E7E2CF08EED4][Manual correction of a derived market data set]].
