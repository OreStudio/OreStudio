* Goal

The bindings screen is built by the tasks of the story: the server reads, the BFF record kind, the list and record page, the dialogs, the history and the menu entry. This task checks it as a whole against the signed-off prototype on the running server, as step 8 of the record screen standard asks: list, page, search, open, add, edit with a stale version, delete, history and revert, and the empty, error and no-permission states. It checks the synthetic scenario to the end and the vendor binding, which is read only and deletable. It records what differs from the prototype.

It also checks the window control on the series page, because no component test reads that markup: the five buttons, the sentence that names the window drawn, and the sentence a window with no observation prints.
