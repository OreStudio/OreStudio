#+title: Story: Gather a run's inputs by declared dependency
#+description: A run's inputs are gathered today by a fixed linear chain that exports each owner's rows as one opaque blob and never waits for more than one of anything. A report has hundreds to thousands of books, each needing its own trades archive, its own market data resolution and its own configuration at a stated as-of. Declare the inputs a run needs, let the engine hold them as a graph, fan the gathering out per book, and assemble the package only when every declared input is present.

* Goal

A report run must name up front what inputs it needs, and the engine must know which are present, which are still being produced, and which failed. Gathering fans out per book; the package is assembled only when nothing is missing.

* Acceptance

- A step declares the artifacts it consumes and produces, and the engine refuses to dispatch it until its inputs exist.
- A run whose gathering fans out over N books dispatches N gathers and assembles its package only when all N are present.
- The dependency graph is persisted with the run and reconstructed for dispatch, rather than living only in the code that built the chain.
- Every gathered artifact is reproducible for a stated as-of date.

* Dependencies between the tasks

The two foundations gate the rest:

#+begin_example
declare what a step consumes and produces
  └─ hold a workflow as a dependency graph
       ├─ resolve the book scope a run fans out over
       └─ assemble the package once every input is present

export a book's trades as an archive at an as-of
  └─ map a book's archive into the ORE portfolio

resolve a book's market data requirements
  └─ export the market data a book requires

hand each configuration to its owner by id at an as-of   (independent)
#+end_example

The four producers are independent of each other and of the foundations, so
they can be built in any order once the declaration's vocabulary exists. What
they cannot do is *wait* for each other: only the graph can say whether a run
is still gathering.

* Decisions

*Open, to settle inside the tasks.* Each is recorded with the task that owns
it, and none is closed:

- *The archive's shape.* One archive per book, with a member per instrument
  type plus a manifest; not one archive per book per type. Owned by
  [[id:8BC0E84C-9B4B-4A12-8E3F-E86EF2A8A807][Export a book's trades as an archive at an as-of]].
- *Where the oresmd requirement grammar lives.* It is C++ codecs today, so
  "resolve it in the database" means moving the grammar or splitting the
  resolution. Owned by [[id:7D9C535D-ED63-43A6-AD1D-54E6E73CF2CF][Resolve a book's market data requirements]].
- *How the graph's edges are persisted.* An edge table keeps a step's
  producers open-ended; a depends-on column keeps the read simple. Owned by
  [[id:E3988B3F-BB78-4E9C-850A-78CA4CEAF72D][Hold a workflow as a dependency graph]].
- *What carries a configuration document to storage.* One transport shape for
  every kind, or a message type per kind. Owned by
  [[id:75159083-58A4-4266-A64B-4FDC94EF0426][Hand each configuration to its owner by id at an as-of]].

*The as-of is cross-cutting.* Every market and trade table is bitemporal, so an
as-of read is a =valid_at= read and needs no new machinery — but the run
document's =asofDate= is currently passed to nothing, and every producer has to
be handed it for the same run to be reproducible. The story's acceptance says
every gathered artifact is reproducible for a stated as-of; that is the test.

*What this story does not do.* It does not change the compute side. The package
the run assembles, the assignment that carries it and the node that runs it
keep the shape the storage-capability work gave them.
