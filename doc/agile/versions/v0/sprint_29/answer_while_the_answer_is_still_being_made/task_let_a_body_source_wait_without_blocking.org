* Goal

A response body is read with a plain =read=, on the connection's thread. That is
right for a file, which is in the page cache and answers in microseconds. It is
wrong for a stream: a source whose next event has not arrived would hold the thread
that serves every other connection on that thread, which is the defect A1 removed
from the handlers.

Increment B3 builds the change stream on this mechanism, so the awaitable form has
to exist before it starts.

* Acceptance

- A source may be awaited rather than called, and the session writes each piece as
  it arrives.
- A source that has nothing to write yields the thread instead of holding it: a
  test shows another connection answered while one source waits.
- A file keeps the synchronous form, so the common case pays nothing for it.
