#+title: How do I run the tenor_anchors commands from the shell?
#+description: Every command the tenor_anchors submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tenor_anchors:

This file documents the tenor_anchors resource at the shell, one section per command. Every command is a subcommand of =tenor_anchors=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 6B7417D0-B6AE-513E-89FF-59998B6BB249
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tenor_anchors list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.tenor_anchors.list=.

#+name: tenor_anchors-list
#+begin_src ores-shell :tangle tenor_anchors-list.ores :exports none
tenor_anchors list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: D04ACC73-E9F1-5B10-A1A7-F9B6A05EE26B
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
tenor_anchors get <code>
#+end_example

It is addressed at =refdata.v1.tenor_anchors.get=.

#+name: tenor_anchors-get
#+begin_src ores-shell :tangle tenor_anchors-get.ores :exports none
tenor_anchors get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 52785901-F632-58F2-9547-82C814EA2159
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tenor_anchors add <code> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.tenor_anchors.put=.

#+name: tenor_anchors-add
#+begin_src ores-shell :tangle tenor_anchors-add.ores :exports none
tenor_anchors add __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: E152C17E-99B0-5568-B8FB-AB1863D0B1AD
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
tenor_anchors set <code> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.tenor_anchors.put=.

#+name: tenor_anchors-set
#+begin_src ores-shell :tangle tenor_anchors-set.ores :exports none
tenor_anchors set __none__ __none__ 0 system.new_record generated_script
#+end_src
