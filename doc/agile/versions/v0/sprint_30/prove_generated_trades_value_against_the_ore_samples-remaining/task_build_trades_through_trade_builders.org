* Acceptance

- The builder API takes =TradeGenerator= as its inspiration, extended to every trade type as the review states: a caller gives the economic terms, and conventions supply the rest.
- Each builder requires the terms the [[id:45DFB9BE-495C-4BE5-954B-D06673BB178F][review]] lists as mandatory for its type.
- =required<T>=, =build_error{term, message}= and the registry: each builder states its trade type, and a test fails when the builders and the trade type catalogue differ.
- The fixed and floating leg sub-builders derive frequency, day count, calendar, adjustment and fixing days from the swap and index conventions found through =convention_lookup=, and emit each leg's schedule row.
- A vanilla swap built on EUR-EURIBOR-6M from ORE's example conventions writes the same XML as ORE's own sample, up to the economic terms.

* Result

The trade builder API exists in =ores.trading.api=: =required<T>=, =build_error{term, message}=, a registry, and =vanilla_swap_builder=.

- The builder takes the economic terms and derives each leg from the swap and index conventions.
- A vanilla swap on EUR-EURIBOR-6M writes the same =SwapData= as ORE's =Example_1= sample. The test sets one override, because the sample rolls its fixed leg =F= and its convention states =MF=.
- Stored conventions state a frequency (=Annual=) and a schedule needs a tenor (=1Y=). The builder maps one to the other and names the term when it cannot.
- The registry test reads the trade type catalogue. It has 121 types, 1 built and 120 listed in =trade_types_awaiting_builders.txt=, which task 4 empties.

This task builds the vanilla swap only. Other swap shapes and all other families are task 4.
