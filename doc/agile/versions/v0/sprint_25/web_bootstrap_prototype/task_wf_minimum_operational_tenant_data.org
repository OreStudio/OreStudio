* Result

Answer: an operational tenant needs the mandatory members of the =base=
bundle, one counterparty dataset, and its own parties. The current party
bundle plan is *not* a minimum. It seeds test data and synthetic market
data, so an operational profile cannot reuse it unchanged.

** Required: the =base= bundle (tenant-wide)

Source: =projects/ores.sql/populate/dq/dq_dataset_bundle_member_populate.sql=
lines 38-100.

- Geography and currency: =assets.country_flags=, =geo.ip2country=,
  =iso.countries=, =iso.currencies=, =refdata.currency_pairs= and
  conventions, calendars, currency calendars, currency countries.
- FpML code lists: 21 =fpml.*= datasets, including
  =fpml.business_center=. Party import needs that list (see the Acme
  handler, step 1 comment).
- GLEIF: =gleif.lei_entities.small= and =gleif.lei_relationships.small=.
- Badges: =ore.badge_severities=, =ore.badge_definitions=,
  =ore.code_domains=, =ore.badge_mappings=.

** Required choice: counterparties (optional members of =base=)

=gleif.lei_counterparties.small= or =.large= and =gleif.lei_parties.small= or
=.large= are marked optional (=true=). They load only through
=opted_in_datasets=. The shell and Acme both opt in to
=lei_counterparties.small= (about 13k rows). Party provisioning offers
=--dataset-size small|large=. This is the "essential published data"
the destination keeps in scope.

** Required: the tenant's own parties

At least one active, onboarded party the tenant admin belongs to. The
parties come from the source: a GLEIF root LEI hierarchy, synthetic
generation, or the Acme LEI import. Per party: activate
(=save_party=), =complete_party_onboarding=, account-party membership.
If a step is missed, the party is inactive or the onboarding wizard
opens again on every login (Acme story: task "Fix remaining --source
acme provisioning gaps").

** Not minimal: the party bundle plan

Source: =projects/ores.dq/api/include/ores.dq.api/messaging/party_provisioning_plan.hpp:65=.

| Bundle | Content | Operational? |
|--------+---------+--------------|
| =risk_management= | =testdata.business_units=, =testdata.portfolios=, =testdata.books=, =ore.report_definitions= | No: test data. Only report definitions are general. |
| =synthetic_realistic_2026= | Synthetic market data config | Demo only |
| =synthetic_ore_samples_2016= | Synthetic market data config | Demo only |
| =marketdata.reference_vintage_2026_05_05= | FX driver rates | Demo only (fixed vintage) |
| =crm_topology= | CRM Cross-Rates Matrix topology | Probably general. Confirm in the contract ticket. |

** Consequence for the seed profile contract

- *Empty operational*: =base= + chosen counterparty size + GLEIF root
  LEI parties + per-party activation/onboarding/membership. Per-party
  bundles: only the general ones (report definitions, CRM topology),
  which need a new non-test bundle.
- *Synthetic* and *ACME demo*: add the current party bundle plan and
  the profile extras.
- The bundle plan becomes profile data, not one hard-coded list.

Open for the contract ticket: split =ore.report_definitions= out of
=risk_management=, and decide if =crm_topology= belongs to every
profile.
