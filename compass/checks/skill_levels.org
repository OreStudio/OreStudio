#+title: Check: skill levels
#+description: The cybernetic level of every skill, the order of the levels and which one binds, which compass-ng's skill_levels codec stamps on each SKILL.org and counts into the levels page.
#+type: check
#+level: cross
#+filetags: :compass:check:skills:levels:generator:
#+created: 2026-11-22
#+updated: 2026-11-22
#+options: prop:t

This page gives the data of compass-ng's =skill_levels= codec, which stamps the
=#+level:= line of every skill under =doc/llm/skills= and writes the inventory
and the slices of the levels page. The =* Definition= names the codec; each
table below is data the codec reads, and the prose says what it is for. The
tables were =LEVELS=, =ORDER= and =READ_ONLY_VERBS= of
=build/scripts/apply_skill_levels.py=, read from it with Python's =ast= rather
than retyped, and the binding and cross levels its =in_scope= named.

* Rule

Every skill has a row in the table =Levels=, and every row names a skill.
=compass generate= writes each row's level as the skill's =#+level:= line: it
replaces the line the skill has, or puts it after the scaffold's
=#+export_exclude_tags: noexport= line. =compass check= reports a skill whose
level differs from its row as drift, and a skill with no row
(=skill_levels/skill_without_level=) or a row with no skill
(=skill_levels/level_without_skill=) as a finding.

* Why

The level turns the cybernetic systems into a variety attenuator: a session
declares its System, and the level selects the slice of the catalogue in
scope by default. A regulator swamped by variety it cannot use stops
regulating, and an agent shown every skill at once is exactly that.

The level is a judgement about which System the skill serves, so it is a
reviewed table rather than a rule over names. The table =Levels= is that table:
every skill appears, and the value is defensible from what the skill acts
on. A skill missing from it is an error, not a default.

Attenuation is advisory at S1, S2, S3, S4 and S5 and binding at S3*, the
audit channel, which sees read-only actions only. Read-only is derived from
the verb register rather than tagged, which is one of the reasons that
register exists: =show= and =find= promise to change nothing.

The table =Systems= states the levels in order. A level whose attenuation is
=binding= sees the read-only skills and nothing else: those whose verb, the
third segment of the name, the table =Read-only verbs= lists. A level whose
attenuation is =advisory= (=s1=, =s2=, =s3=, =s4=, =s5=) sees its own skills and the
skills of the =cross= level, and may reach outside them on request. The level
whose attenuation is =cross= is no System: its skills are in every advisory
slice.

Pruning the deployed tree to a level, which makes the attenuation binding for
whatever is spawned next, acts on an agent's runtime rather than checking the
checkout, so it stays ORE Studio's: =build/scripts/prune_deployed_skills.py=
reads the slices compass writes into the levels page.

* Systems

The levels in order, the System each serves and its horizon, and what a
session at the level sees by default. This was =ORDER=; the Systems and
horizons are those of the levels page.

| level    | system           | horizon    | attenuation |
|----------+------------------+------------+-------------|
| =s1=     | Agent            | Hours      | advisory    |
| =s2=     | Orchestrator     | Days       | advisory    |
| =s3=     | Sprint Planner   | Weeks      | advisory    |
| =s3star= | Auditor          | Continuous | binding     |
| =s4=     | Version Planner  | Months     | advisory    |
| =s5=     | Identity Steward | Indefinite | advisory    |
| =cross=  |                  |            | cross       |
