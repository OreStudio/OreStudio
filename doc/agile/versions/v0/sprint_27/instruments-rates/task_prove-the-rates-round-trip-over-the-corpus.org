* Acceptance

- The ORE round trip runs over the family's corpus at the new shape and every document comes back equivalent.
- A migration script moves the rows of the legacy rates tables into the header and the fact tables, and a database holding rates rows survives the move.
- The eventing integration test for the rates instruments is generated, and the family's repository and service coverage exists where it had none.
- The migration's row counts and the round trip's documents are recorded as measurements with their commands.

* Plan

1. *The migration script.* One hand-written artefact: read each legacy table
   and write the header row and the fact row, keyed by the trade, with the
   header written first because the facts and children join it by that key.
   The legacy tables are the nine the design's mapping table lists.
2. *The corpus round trip.* Run the family's corpus at the new shape and
   record the document count with the command that produced it.
3. *The eventing test.* Generate the rates instruments' eventing integration
   test as the other entities' are generated.
4. *The coverage gap.* Add the repository and service cases the family has
   none of, guided by what the round trip and the migration exercise.
5. *Measurements.* The migration's row counts and the corpus size go in this
   page's Measurements table with their commands, as the header task's did.
