* Goal

Make the wire codec name the active alternative of every variant it
writes, so a variant decodes back to the alternative that was written,
whatever the order the alternatives are declared in. No instrument may
be lost in silence.

* Acceptance

- The four reflect-cpp calls in =ores.nats::wire_codec= encode and
  decode with =rfl::AddTagsToVariants=, for both json and msgpack.
- The one direct reflect-cpp call on the trading storage path writes
  with the same processor.
- A unit case round-trips a variant whose first alternative is
  =std::monostate=, in both formats, and checks the index of each
  alternative rather than only that decoding succeeded.
- The full round trip test reads zero lost pairs under the bond
  products and the trade envelope.

* Plan

=ores.trading.domain.trade_instrument= is a =std::variant= that lists
=std::monostate= first. reflect-cpp 0.25.0 wrote every variant untagged,
naming no alternative, and read a variant back by trying the
alternatives in declaration order and taking the first that parsed.
=std::monostate= parses from any payload, so it always won, and every
instrument decoded as monostate.

The fix is one processor applied at every reflect-cpp call site that
carries a variant: the four in =wire_codec=, plus the storage blob in
=trade_handler.hpp=, which is written directly and does not go through
the codec. Measured with a standalone reflect-cpp probe before touching
the tree, then by the full round trip.

* Notes

- The defect was silent in two stages. The decode produced a monostate
  instrument, and the exporter logged =Skipping unmapped trade= at
  =debug=, which the service never prints. A 653-byte export with no
  product block was the only visible sign.
- Sweep of the tree for other bypasses: exactly one direct msgpack
  write exists (=market_series_handler.hpp=), and =market_series= has
  no variant members. Three direct json message handlers read payloads
  outside the codec, and all three message types are flat. The codec is
  the only variant-carrying path today.
- The generated =api/src/domain/*_json_io.cpp= helpers still call bare
  =rfl::json::write=. They are logging helpers and carry no variant
  today, but they would degrade a variant the same way if one were ever
  added.
- No test anywhere round-tripped a protocol type through the codec.
  That gap is why a codec-level defect reached a live round trip.
- The tag changes the wire shape, so the two directions are not
  symmetric across versions. Measured with a standalone probe:
  an untagged blob read by this code fails loudly (=Could not parse
  rfl::Variant, could not match field named 'currency'=), which is a
  visible failure and not a loss. A tagged blob read by the old code
  still decodes as =monostate= in silence. A deployment that mixes
  versions across the change loses data on the new-to-old direction, so
  the services must be restarted together. Blobs already in storage
  from before the change must be re-imported.

* Result

=reflect-cpp 0.25.0 writes a std::variant untagged=, and reads it back
by trying the alternatives in declaration order. =std::monostate= is the
first alternative of =ores.trading.domain.trade_instrument= and parses
from any payload, so every instrument decoded as monostate and was
dropped, on both the NATS wire and the storage blob. The exporter then
logged =Skipping unmapped trade= at debug and emitted a =Trade= element
with no product block.

=wire_codec::encode= and =wire_codec::decode= now pass
=rfl::AddTagsToVariants= on all four rfl calls, and =trade_handler.hpp=
passes it on the storage blob, which is written directly rather than
through the codec. The tag names the alternative, so any declaration
order decodes unambiguously.

Verification, in order:

1. A standalone reflect-cpp probe reproduced the loss and then the fix
   before the tree was touched.
2. =ores.nats.tests= carries a new case that round-trips a variant whose
   first alternative is =std::monostate=, in json and msgpack, asserting
   the index of each alternative. It passes (0.95 sec).
3. Two live full round trips, each on a fresh database with its own
   provisioning, both reading zero lost and zero unexplained.

The only remaining differences are element order, which the classifier
is order-blind to, and two numerics collapsing to =xs:float= precision
(=28371509.989758= to =28371510=, =0.0178= to =0.0177999996=), both
classified =numeric=.

The second document was chosen to exercise a different product family:
the option block, the strike group and the exercise dates. Two of two
clean, so the result is not specific to the BondRepo plus Bond pair.
