* Acceptance

- The DQ publish copies arrival_mode, branching_ratio, decay, sensitivity, variance_model, garch_alpha, garch_gamma, garch_beta and garch_window_days from the artefact row to the live config.
- Every seeded FX spot artefact row, in the starter, provider and uniform demo datasets, names variance_model gjr_garch.
- After a database recreate and an Acme provision, every live FX spot config has variance_model gjr_garch.
- A pgTAP test publishes a feed whose arrival and GARCH columns differ from every default, and fails if the publish drops any of them.

* Plan

Every FX spot feed is a system feed in the root tenant, which Acme reads, so the
change is to the system feed datasets. The publish function dropped nine
artefact columns, so a seed naming =gjr_garch= published as =constant=; fix the
publish first, then set =variance_model= in every seed. The authored parameters
keep the column defaults; a feed that starts from fixings fits its own.

* Result

The DQ publish now copies the four arrival columns and the five variance columns
from an FX spot artefact row; before, it dropped them, so every published feed ran
on the defaults. Every shipped FX spot seed, the Bloomberg, LSEG and uniform demo
feeds and the unshipped starter set, names =gjr_garch=.

Measured at e5ceae4f33 on a recreated database with Acme provisioned: the 51 live FX
spot configs all have =variance_model= =gjr_garch= (40 from fixings, 11 fixed). The
new =synthetic_fx_spot_regimes_publish_test.sql= passes, and fails 3 of 4 against
main's publish function; the two provider feed tests pass with their GJR-GARCH
assertions.

The starter dataset cannot publish, because it names a provider that does not
exist; that is filed as a capture. Four marketdata pgTAP files fail on main
already, because their counts predate the derived source; the derived source task
fixes them.
