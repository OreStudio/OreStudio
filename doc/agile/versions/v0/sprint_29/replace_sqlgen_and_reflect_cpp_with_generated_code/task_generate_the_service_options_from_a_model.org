* Plan

Two PRs, in order.

1. Service options. Each service model states its own options in an
   =* Options= section, one heading per member: =:cpp_type:=, =:default:=,
   =:help:=, the flag in =:option:= where it differs from the member name, a
   header initialiser in =:initial:=, and =:secret: t= for a value that must
   never be written out. The body is the member's comment. From that one list
   the service-app templates write the member, its wire field, the
   program_options declaration and the assignment. A secret stays out of the
   wire shape, as the database password does, so the startup dump cannot print
   it, and the completeness guard counts it. The seventeen services that turn
   =ores.cpp.service-app= off turn on its five config addresses only, so their
   hand-written application and host stay. The model's =#+brief= is the first
   line of =--help=, so the four briefs that differ take the text the parser
   prints today. A check the list cannot state, synthetic's positive market
   speed, stays in the assignment paste point.
2. Shared options types. logging, nats, database, telemetry and http_server
   state their shapes through codegen. Split into its own task when this PR
   was ready to merge, so each task lands in one PR.

* Result

Each service's own options are one list in its model. Codegen writes the
member, its wire field, its program_options declaration and its assignment
from it, with =:secret:= keeping a value out of the wire shape and
=:positive:= checking a number. All seventeen services generate their config
from the five config addresses of =ores.cpp.service-app=, and keep their
hand-written application. The resolver now keeps a disabled facet when a model
turns one of its archetypes on. A comparison with main finds no service whose
members, flags, defaults, help text, assignments or =--help= title moved. The
build passes, and the binaries print the same help.
