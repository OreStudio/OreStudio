* Acceptance

- latest(item, on_or_before) and window(item, to, days) read the durable table, checked against the reader's entitlement.
- Each answer names the provider, the vendor id, the vendor time and the time received.
- A window skips missing days and says how many values it used.
- Tests cover a gap, a date before the first fixing and two providers of one pair.

* Plan

The consumer is the calibration of the synthetic feeds (T7), which runs in another
service, so the reader is a NATS read of the marketdata service, as the series
ticks read is.

1. Two operations in a new model, =ores.marketdata.fixing_read_operations.org=:
   - =marketdata.v1.ops.get_fixing= takes the item, the fixing's oresmd URI, and a
     date, and answers the latest fixing on or before it.
   - =marketdata.v1.ops.get_fixing_window= takes the item, an end date and a number
     of days, and answers every fixing in those calendar days, oldest first, with
     the number of days asked and the number of values found.
   Each answer names the provider, the vendor id behind the item, and for each
   value its date, its source and the time the service stored it. Values stay
   decimal text, as they are stored.
2. A reader, =service::fixing_reader=, follows =series_tick_reader=: a session
   with no party is refused, the item names one series among the parties the
   session sees or the read is refused as ambiguous, and a window over a ceiling
   is refused.
3. A hand-written repository, =fixing_reads=, reads the current rows of one
   series on or before a date or between two dates with their =valid_from=,
   which the generated domain type does not carry, and the vendor id of the
   item through the mapping.
4. A handler checks =marketdata::market_fixings:read= and replies; the registrar
   subscribes it.
5. Tests: the reader against the database (a gap, a date before the first
   fixing, two providers of one pair, a window over the ceiling), and the
   handler over NATS (the permission).

Deviation from the acceptance: a daily publisher states a date and not a time,
and the adapter stamps midday UTC only to make a tick. So the vendor time of a
fixing is its date, and no column holds a made-up time. The time received is the
row's =valid_from=.

Found while building:

- An ORE index names the fixing's source, not the provider that delivered it: the
  ECB rate is =FX-ECB-EUR-USD= from the ECB adapter and from the ORE sample data
  alike. One party holds one series of an index (=market_series_identity_fixing_identity_idx=),
  so two providers of one item meet across the parties a session sees. A request
  may name the provider; without one, such an item is refused as ambiguous.
- The read has no shell command. The shell generator has no token form for a
  date, and adding one is a change to the generator, not to this task.

* Result

The marketdata service answers two reads of the durable fixings over NATS:
=marketdata.v1.ops.get_fixing=, the latest fixing of an item on or before a date,
and =marketdata.v1.ops.get_fixing_window=, every fixing in a number of calendar
days, which skips the days with none and says how many it used. Each answer names
the provider and the vendor id behind the item, and each value its date, source
and the time the service stored it. The read checks =marketdata::market_fixings:read=
and refuses a session with no party, an item that names more than one series
unless the request names the provider, and a window over ten years. Tests cover a
gap, a date before the first fixing, a window with missing days, two providers of
one item, the refusals, and the permission over NATS.
