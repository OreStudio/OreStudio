* Acceptance

- A session in the system party reads the batches, workunits, results and grid samples of every party of its tenant.
- A session in any other party reads only its own parties' rows.

* Plan

A tenant administrator who signed in as the system party saw the fleet and no jobs, and a person who signed in as Acme Corporation Plc saw the jobs. The party rule hid the other parties' rows from a session in the system party, which is a separate root with no children. The owner's rule is that the system party sees every party of the tenant and each other party sees only its own.

- Add =ores_compute_session_is_system_party_fn()=, which is true when the session's party is the tenant's system party.
- Add it to the four party policies of the compute tables: batches, workunits, results and grid samples.
- The rule stays inside one tenant. The security page records it.

* Result

A session in the tenant's system party now reads the compute work of every party of the tenant, and any other party reads only its own and the parties below it. The change is in the policy and no code. I applied it to the development database by hand, so a new database gets it from the create script. I checked it with the session settings of both parties and in a repository test. I have not checked it in a browser.
