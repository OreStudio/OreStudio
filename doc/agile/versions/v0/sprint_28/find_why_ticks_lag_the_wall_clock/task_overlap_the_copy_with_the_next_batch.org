* Goal

The drain of a burst through NATS passes 100,000 rows per second with margin on one connection, because the COPY of one batch runs while the worker prepares the next.

* Acceptance

- A second thread owns the tick writer connection and copies a batch while the worker plans and numbers the next, and one connection is still the only one the copy uses.
- A tick is republished after the copy of its batch, in the order of the batches, and a failed copy still republishes without a store, with the same backoff as today.
- The burst tests give a median above 110,000 rows per second through NATS over ten runs, and the raw output is in the evidence folder.
- A test shows that no tick is lost or stored twice when a copy fails while the next batch waits.
