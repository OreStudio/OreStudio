* Acceptance

- The screen is reachable from the signed-in shell and reads the sessions, the
  active sessions and the login records through the BFF routes that already
  serve them.
- The account filter is drawn and disabled, with the reason: =iam.v1.sessions.list=
  takes no account filter, so the server cannot apply one.
- The session activity panel says its data is not available. Nothing serves
  =iam.v1.sessions.samples= on either transport, so no empty chart and no
  fabricated sample rows are drawn.
- The authentication events are a gap line, not an empty log. No subject carries
  them on any surface.
- The failure count and the lock state travel together, and Refresh is the only
  action: no version, diff or revert control appears.
- The screen says that nothing writes a session's end time, so an old session
  cannot be told from a live one in the session list.

* Plan

1. Read the accepted variant B on =prototype/audit-sign-ins= and the three reads
   the group landed.
2. Build =/audit= behind the signed-in shell, composing =AppShell= with the
   shared primitives.
3. State every gap the prototype records: the account filter, the samples, the
   auth events and the missing end time.
4. Drive the screen against the running fleet, then land it.

* Notes

*No new server work.* All three reads this screen needs are landed; the two
handler gaps the inventory records are =sessions.active=, which is implemented,
and =sessions.samples=, which cannot be implemented because nothing writes
=ores_iam_session_samples_tbl=. The samples panel therefore states the gap
instead of waiting on a task.

*The end-time gap is the screen's honesty problem.* Nothing writes a session's
=end_time=, so every session row looks open and the "ended" state has no
producer. The screen states this beside the list rather than inventing an ended
state.

*The account filter is a scope gap, not a route gap.* Widening
=iam.v1.sessions.list= with an account filter is its own task, and the
prototype already draws the control as unavailable.
