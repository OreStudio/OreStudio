The synthetic feeds and the ingest: what the live system did before the fix
==========================================================================

Environment: eager_maxwell, database recreated 2026-10-29 20:34 from
e0b42ec674-dirty (schema fingerprint 8d7947c687844a3e, in sync), every
service started from the same build, the Acme Corporation tenant
provisioned by
projects/ores.shell/scripts/library/provisioning/how_do_i_provision_the_system_with_acme_corporation_holding_group.ores.

1. What the feeds published, and where
--------------------------------------
The synthetic service's log names the feed's own source name on every batch:

  $ journalctl --user -u ores.synthetic.service-eager_maxwell.service -o cat \
      | grep 'SYNTHETIC CURVE PUBLISH'
  SYNTHETIC CURVE PUBLISH: subject='synthetic.v1.ops.tick.synthetic.bloomberg.sgdsora' \
      source='synthetic.bloomberg.sgdsora' batch=1 points=12
  SYNTHETIC CURVE PUBLISH: subject='synthetic.v1.ops.tick.synthetic.demo.cnyshibor' \
      source='synthetic.demo.cnyshibor' batch=1 points=3

The same service's FX feeds logged the ingress subject they really used:

  SYNTHETIC PUBLISH: subject='marketdata.v1.ingress.bloomberg-a.USDJPY%20Curncy' ...

The curve line was the same batch whether the pillar served an adapter or not:
the feed logged its producer subject on every batch, and used it only for a
pillar with no adapter target. The log did not say which subject the tick went
out on, so a reader could not tell a stored tick from a dropped one.

4. What follows
---------------
Two defects, both through the adapter contract:

- The system party had no route to the synthetic source, so the ladder series
  the seeded blueprint reads held no point. The seed now writes the subscription
  and the route, in marketdata_market_series_ir_curve_populate.sql.
- A feed a person starts by hand was built with no adapter target, so it
  published a market tick on its producer subject, which no source or route
  names: the ingest drops it as an unbound source. The build input now names the
  provider's default simulated source, so the feed publishes as that adapter.
