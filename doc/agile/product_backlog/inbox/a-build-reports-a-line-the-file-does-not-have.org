#+title: compass build can report errors for source content that is n…
#+description: compass build can report errors for source content that is no longer on disk, and the same build directory compiles cleanly under ninja.

Seen on feature/model-the-basket-constituents after a rebase. A helper called json_escape and another called parse_range_bounds had been deleted from projects/ores.ore/core/src/domain/equity_instrument_projection.cpp, and grep found no trace of either string in the file. compass build failed four times with 'unused function json_escape' at line 214 and quoted the deleted signature with a caret. Line 214 of the file was blank and md5sum of the file was stable. The same target built under ninja in build/output/linux-clang-release-ninja, ran, and passed.

Three things were tried and none changed the result: deleting the unity object and its dependency file, touching the source, and CCACHE_DISABLE=1. The failing object was projects/ores.ore/core/src/CMakeFiles/ores.ore.core.lib.dir/Unity/unity_2_cxx.cxx.o, and the unity file included the correct absolute path.

The consequence is that a red compass build cannot be trusted as evidence that the tree is broken, and a green ninja build is not the documented path. This cost an hour and it is the second time in this work that a build result disagreed with the source.

The requirement: compass build should fail in a way a reader can check, and when it reports an error in a file, the file should contain the line it quotes.
