* Acceptance

- A preview operation returns every line outcome and the parts, and writes nothing.
- A raise operation returns the request or the refusals.
- The handler refuses a caller who may not write books, and a delete line needs the permission to delete them.
- The operations are registered in the refdata service, beside the entity handlers.
- The operations are modelled in an operations model and generated, as the approval operations are.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

- Model the two operations in =ores.refdata.book_proposal_operations=. The generator writes the C++ protocol and the TypeScript wire types.
- The response names the raised request by its id. The TypeScript generator imports a type from the same component only, and the inbox operations already read the request.
- Write the handler in =ores.refdata.service=, beside the proposal service, and register it from the service application. =ores.refdata.core= cannot link the inbox.
- Keep the permission rule and the wire mapping in plain functions so they have tests. The handler only proves the request, checks the permission and calls the service.
- The BFF routes belong to the review panel work, which is the first caller.

* Result

A caller outside the process can preview and raise changes to books.

- =ores.refdata.book_proposal_operations= models =preview_book_changes= and =raise_book_changes=. The generated C++ protocol and TypeScript wire types carry the lines, each line's outcome and the parts.
- =book_proposal_handler= proves the request, checks =refdata::books:write= for a put line and =refdata::books:delete= for a delete line, and calls the proposal service. It is registered by =book_proposal_registrar= from the refdata service application.
- The preview answers each line's refusal and the parts. The raise answers the request id, or an invalid result with a code.

Evidence: five new mapping cases and the thirteen proposal cases pass (48 assertions). The refdata service and test targets build. The wire-protocol package typechecks. The cmake source, handler permission, test case reachability, pasted block symbol, populate reference and derived-model checks pass.

The component-drift check failed on main for =book_change_eventing_integration_tests.cpp=. The generator changed in PR #3073 after the file was generated, so the file is regenerated here. The regenerated test passes.

Not done here: the BFF routes and the screens, an end-to-end NATS test of the handler, and the apply.
