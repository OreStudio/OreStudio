* Notes

- =SwapIndex= is modelled: three fields, and it appears in forty-seven files.
  Its case asserts 1451 times over that corpus.
- =CrossCurrencyBasis= is modelled: twenty-five fields across forty-nine files,
  the largest category in the document, and it clears three files. Every field
  is a text, an integer, a boolean or a business day convention, so it needed no
  new kind of mapping; the size was the only thing that made it look expensive.
  It went in before smaller categories because the clearing measurement named it
  as the second-best win, and because leaving the largest one until last is how
  a plan runs out of room.
- =AverageOIS= is modelled: eleven fields across thirty-six files. It went in
  before the cheaper categories because it is the one that clears files: seven of
  the thirteen files with exactly one unmodelled category name it, so modelling
  it took the count of files that round trip outright from twelve to nineteen.
  The corpus makes three of its fields required and never sets its frequency, so
  the mapper reads the three unconditionally and the frequency only when present.
- =FxOption= is modelled: nine text fields across thirty-six files.
- =Future= is modelled: six fields, and it appears in thirty-nine files. Three of
  those carried no other unmodelled category, so the count of files that round
  trip outright went from nine to twelve. Its two enumerations are stored in
  ORE's own spelling, because they are closed enumerations with no aliases and
  the token is what an export has to write back.
- =TenorBasisTwoSwap= is modelled: eleven fields across forty-six files, the
  largest single category left when it went in. It is the first convention whose
  legs differ from each other rather than from one quoted leg, so each leg
  carries its own frequency, convention, day count and index and the mapper
  normalises three enumerations per leg. Twelve files carried it and nothing
  else unmodelled, more than the rest of the corpus put together, which is why
  it took the round-trip count from twenty-two to thirty-four in one category.
- =TenorBasisSwap= is modelled: fifteen fields across twenty-nine files, and the
  only convention the corpus writes in two alternative forms. The paying and
  receiving form names =PayIndex= and =ReceiveIndex=; the long and short form
  names =LongIndex= and =ShortIndex=. The forms share no field, so the table
  carries both sets and each row fills one. The periods stay in ORE's spelling
  because they are tenors rather than frequency enumerations, and =12M= and =1Y=
  are distinct tokens an export has to write back exactly.
- =ZeroInflationIndex= is modelled: seven fields across six files, and the first
  category whose ORE type carries a field the table cannot hold. =RebasingEvents=
  is a list of doubles and the refdata schema has no array column, so the mapper
  counts each element that carries one into =unmodelled= under
  =ZeroInflationIndex.RebasingEvents=. No shipped file sets one, and a case
  builds that document by hand to assert the count, because the corpus walk
  cannot reach it. That is the rule the story settled on: a skip that is counted
  keeps the file out of the round-trip set, and a skip that is silent loses
  content.
- =BMABasisSwap= is modelled: twelve fields across sixteen files. Three are
  required and the corpus exercises the optional half lightly, so most of the
  mapping is read-when-present rather than normalised. It is the first category
  of the second half of the task, which continues on a new branch because the
  first eight merged with [[https://github.com/OreStudio/OreStudio/pull/2357][#2357]].
- =InflationSwap= is modelled: thirteen fields across twenty-two files, ten of
  them required. It is the second category with a field no column can hold:
  =PublicationSchedule= is a schedule of rules, dates and derived groups, and two
  shipped files set it. The mapper counts it into =unmodelled= under
  =InflationSwap.PublicationSchedule=, and the category's case asserts both the
  count over the corpus and that a file carrying a schedule names it.
- =CrossCurrencyFixFloat= is modelled: eighteen fields, nine required and nine
  optional, across eighteen files. The corpus sets none of the optional ones, so
  a case builds the element and sets all nine, including a zero-valued fixing
  days and a false resettable flag -- the two a mapper that tested the value
  rather than the presence would drop.
- =CmsSpreadOption= is modelled: eight required fields across twelve files. The
  twelve elements are otherwise identical, so it is one convention shared by
  twelve files, and eleven of them round trip the moment it lands -- the largest
  single win after =TenorBasisTwoSwap=.
- =CommodityFuture= is modelled: thirty-four fields across five files, thirty of
  them as forty columns. It is the first category whose entity flattens nested
  structs instead of counting them: =AnchorDay= becomes seven columns and the
  corpus uses all six of its variants, so flattening is what lets a commodity
  future round trip at all. Four list-bearing fields -- =ProhibitedExpiries=,
  =FutureContinuationMappings=, =OptionContinuationMappings= and =AveragingData=
  -- are counted rather than modelled, and reaching seventy-two of seventy-two
  will mean modelling them.
- =CommodityForward= and =BondYield= are modelled together: eight and seven
  fields, all but one optional each, across two files and one file. Neither
  clears a file, because the three files still unmodelled each need several
  items, so the round-trip count holds at sixty-nine and the remaining gap is
  now known exactly. The bond yield's two floats travel through double precision
  columns, because the refdata schema has no float type and a float widens and
  narrows back with no loss.
- The commodity future's four list-bearing fields are modelled rather than
  counted. =AveragingData= became eight columns and the other three one text
  column each, holding comma-separated dates and =from:to= pairs. A text column
  is a weaker home than a table and it is the one that keeps the field in the
  element's round trip; the alternative was to exclude the file.
- The gap left in the conventions kind is two items, and the measurement names
  both: =InflationSwap.PublicationSchedule=, which two files set, and
  =IntradayPowerLoad=, which one file carries. Two files need only the schedule
  and one needs only the load, so the kind reaches seventy-two of seventy-two
  when both land. Each is a list of structs nested two deep -- a schedule of
  rule blocks and date blocks, a load profile of dated entries each with its own
  load factors -- so each needs either a child table or a stated text form.

* Result

Eight of the sixteen categories landed, in one pull request: SwapIndex, Future,
FxOption, AverageOIS, CrossCurrencyBasis, TenorBasisTwoSwap, TenorBasisSwap and
ZeroInflationIndex. They took the count of files that round trip outright from
nine to forty-four and the count carrying an unmodelled category from sixty-three
to twenty-eight.

The acceptance is not met, so the task stays STARTED. Eight categories remain
unmodelled -- BMABasisSwap, CrossCurrencyFixFloat, InflationSwap,
CmsSpreadOption, CommodityForward, CommodityFuture, BondYield and
IntradayPowerLoad -- so the mapper's count of what it skips is eight rather than
zero, and twenty-eight of the seventy-two files still carry one. The work
continues on a new branch, because this branch's pull request is merged and the
acceptance asks for all sixteen.

Two decisions the work settled, for whoever picks up the rest:

- A category lands one at a time, and the next is chosen by how many files it
  clears alone rather than by how few fields it has. The hidden case
  =conventions_files_cleared_by_each_category= ranks the candidates, and the
  Measurements table records the ranking each round. The next two are
  =BMABasisSwap= and =InflationSwap=, at three files each.
- A field the refdata schema cannot hold is counted, not dropped.
  =ZeroInflationIndex.RebasingEvents= is the first: a list of doubles with no
  array column to hold it, counted into =unmodelled= under that name, so a file
  that ever sets one leaves the round-trip set and is named in the measurement.
