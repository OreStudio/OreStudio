* Goal

=ores.shell= holds its sources and its build in one target. A domain adapter
therefore cannot link the shell plumbing without the REPL host, and codegen
has no part to write a generated command unit into. Move the sources into an
=api= part holding the shared plumbing and an =application= part holding the
runnable host and the executable, then declare the component a codegen
composite so its root =CMakeLists.txt= is generated like every other
composite root.

* Acceptance

- =projects/ores.shell/api= and =projects/ores.shell/application= exist, each
  with its own =CMakeLists.txt= and its own CMake target.
- =libores.shell.api.a= and =libores.shell.application.a= build, and
  =ores.shell.exe= is still produced.
- The root =CMakeLists.txt= is codegen output, and regenerating it is a no-op.
- Both part test suites pass.
- Consumers of the old single target and the old header paths are fixed.

* Plan

1. Move the plumbing headers and sources into =api/=, and the host, the
   config parser, the REPL loop, the script runner and the command units
   into =application/=.
2. Replace the single =CMakeLists.txt= with one per part, plus a composite
   root that adds them.
3. Declare =#+component_kind: composite= and
   =#+parts: api application modeling= in the modeling org, then generate the
   root.
4. Regenerate =component_files.cmake= for both parts.
5. Fix the consumers: =ores.qt='s application target, a prose path in
   =ores.service=, and the System Model application page.

* Notes

- The gcc build of one =application= translation unit holds 6.76 GiB RSS, and
  this worktree's build slice caps =memory.high= at 8 GiB. The kernel
  therefore throttles the compiler into uninterruptible sleep, and no job
  count avoids it, because a single unit crosses the cap by itself. clang
  stays under the cap, so clang is the preset the green build and the sweep
  used. The measured peak is recorded in the slice drop-in; the values are
  unchanged, and re-deriving them is a separate decision.
- =scripts/= stays at the component root. Moving it under =application= is
  recorded as an open question in the component overview.

generated root. Both part libraries build, =ores.shell.exe= is still

codegen registry entry, which left the generated root with no regeneration
path, and the duplicate test module name. Two are deferred with their reasons:
the part-generation trap, whose fix belongs to the command codegen wave, and
stale paths in live backlog items, which are a grooming decision. The
=* Review= table above carries the decision and the evidence for each.
