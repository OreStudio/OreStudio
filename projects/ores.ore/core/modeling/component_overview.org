* Summary

=ores.ore.core= is the engine that moves ORE documents in and out of the
ORES domain model. It holds the codec that reads and writes ORE's XML
vocabulary, the projections and mappers between the codec's records and the
=ores.trading=, =ores.refdata= and =ores.analytics= domain types, the importer, the exporter
and the directory round trip, readers for ORE's market data text formats,
the import planner and directory scanner, and the generated series key
shape entity with its repository.

The record tables are generated from the vendored schemas by
=projects/ores.ore/scripts/regenerate_xml_bindings.sh=, and a drift check
fails when the committed tables differ from what the schemas produce.

* Inputs

- ORE XML documents read from disk: portfolios, currency configurations,
  calendar adjustments and conventions.
- ORE market data text files (=-market*.txt=, =fixings*.txt=) and the
  =oresmd= series keys they carry.
- ORES trading and reference data objects to serialise back to ORE XML.

* Outputs

- Trading domain objects: trades with their instruments and envelopes,
  plus mapped conventions and FX conventions.
- Reference data objects: currencies, calendar adjustments, portfolios
  and books.
- Regenerated ORE XML documents, mirrored by the round trip.

* Entry points

- =include/ores.ore.core/domain/= — the projections and the mappers.
- =include/ores.ore.core/xml/= — the importer, the exporter and the round trip.
- =include/ores.ore.core/market/= — the ORE market data readers and the FX
  quote convention checker.
- =include/ores.ore.core/scanner/= — the directory walk that classifies ORE
  files by root element.
- =include/ores.ore.core/planner/= — the import plan and its choices.
- =include/ores.ore.core/hierarchy/= — the portfolio and book node builder.
- =include/ores.ore.core/log/= — the ORE engine log line parser.
- =include/ores.ore.core/xml/run_package.hpp= — where an ORE input directory's
  files sit in the directory the engine reads.

* Dependencies

- =ores.ore.api= — the shared contract, linked publicly.
- =ores.refdata.api=, =ores.trading.api=, =ores.analytics.api= and
  =ores.reporting.api= — the domain types the mappers and projections target,
  linked publicly.
- =ores.dq.api=, =ores.logging=, =ores.platform=, =ores.utility= and Boost — linked
  privately.

The component holds no database session. It converts documents and returns
types; the store that once wrote reporting, refdata and analytics rows lived
here and was removed, because a format codec that opens a session is a codec
that writes another component's tables.

XML parsing is the generated binding code. The component links =pugixml=
for the documents it writes and does not link =nats.c=.

* CMake

The generated record tables and the larger projections are big translation
units, and MSVC needs /bigobj for them. The flag predates the codec and stays
until a Windows build shows it is not needed.

#+begin_src cmake :name cmake_finalize :implements FDEE629F-F8BA-4940-AA1B-6671AF332D82
if(MSVC)
    target_compile_options(${lib_target_name} PUBLIC /bigobj)
endif()
#+end_src
