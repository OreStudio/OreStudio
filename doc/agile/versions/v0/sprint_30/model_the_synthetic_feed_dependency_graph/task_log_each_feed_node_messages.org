* Goal

A person diagnosing a quiet surface reads its own log: the state changes with who stopped what and why, and the surface's market and calibration messages, such as no market: curve:USD, without opening a service log. The graph read shows the surface failing, with that diagnostic as its reason, and its views starved on it.

* Acceptance

- A telemetry log entry carries the node's name in its tag, and the log read filters on it: the check the design asked for.
- A latent surface that refuses a tick raises its reason once, when it changes, and clears it when it publishes again; the service publishes both to telemetry, tagged with the surface's name.
- A node with a diagnostic is failing, with the diagnostic as its reason, and the nodes below it are starved on it.
- A stop or start publishes, to each node whose state it changes, a message with the new state and its reason.
- Live: stopping a curve a surface reads puts a no market message in the surface's log and its views' starve messages in theirs, read through GET /api/operations/logs with the node's name as the tag.

* Plan

One PR. It applies choice 4 of the [[id:2376A086-4C3C-4D61-92E5-29B122DB6A41][synthetic feed graph]] design: a node's
messages are telemetry log entries tagged with its name.

1. *The check.* A telemetry log entry has a =tag=, the log read filters on it,
   and both the BFF and =ores.http= serve that read as
   =GET /api/operations/logs?tag==. The publish verb,
   =telemetry.v1.ops.publish_log_entries=, stores a batch under one tag with no
   session, as the compute wrapper already uses it. So a node's messages are
   batches tagged with its name, and no new store or route is needed. The
   database sink uses the tag for a trace id, but no service runs that sink.
2. *Diagnostics.* A =node_diagnostics= interface in the API, carried by the
   feed build context, optional. A latent surface raises its refusal when it
   changes and clears it when it publishes again: the two points where it
   already logs once.
3. *The journal.* The service's journal keeps each node's current diagnostic
   and publishes every raise and clear to telemetry, tagged with the node's
   name. The graph's rule gains =failing=: a node that is not stopped, whose
   inputs run, and that holds a diagnostic, with the diagnostic as its reason;
   a failing input starves the nodes below it. A stop or start derives the
   states before and after, and publishes to each node whose state changed.
   Check: graph cases for failing and its precedence, and a journal case.
4. *Proof.* Live: stop a curve a surface reads, and read the surface's and a
   view's messages through the log route by their names.
