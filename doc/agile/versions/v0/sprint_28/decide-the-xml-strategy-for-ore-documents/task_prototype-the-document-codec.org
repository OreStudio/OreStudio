* Goal

Answer three questions with measurements so the story can choose a route.

- How fast can a scanner we own read the ORE corpus?
- How few allocations can one document cost when no document tree is built?
- Can a table generated from the XSD carry the mapping in both directions?

* Acceptance

- A scanner reads a real ORE document with no allocation per event.
- A generated table maps one real ORE document family into records.
- The records agree, field for field, with the production path.
- The same table writes the document back and the reread records agree.
- Time and allocation counts for both paths are recorded with the command
  that produced them.

* Plan

Build the smallest thing that answers the three questions, on one document
family. =CurrencyConfig= was chosen because it is real, it is small, and its
=currencyDefinition= is an =xs:all=, so the mapping must key on the element
name rather than on position.

Four variants share one switch so the alternatives are compared on the same
document in the same process: the current path, pugixml with the same table,
the codec with owned strings, and the codec with borrowed views. All of them
end in the same descriptor table, so a difference between them is the
document model and the record layout, not the mapping.

* Notes

- The baseline for =portfolio.xml= is missing. The built library in this
  worktree predates the checkout's =domain.hpp=, so the executable and the
  library disagree about the generated =trade= layout and loading a portfolio
  aborts. The other four documents take the number.
- The owned-string layout allocates more bytes than pugixml's DOM on the same
  document, 156 KB against 36 KB. That is because every record is built
  eagerly at its full width while pugixml allocates per node as it goes. It is
  the reason the borrowed layout matters: it removes the per-value copy
  entirely rather than making it cheaper.

* Result

Route C works. The scanner is about 500 lines with no dependency, reads
530-660 MB/s, and allocates nothing per event. The table carries the mapping
in both directions from the XSD alone. The borrowed layout costs two
allocations for a whole document.

The design's weakness is also measured: the pull-event interface makes the
full codec marginally slower than pugixml on the same table. That is a local
cost with an obvious fix, and it does not change the architectural argument,
which rests on allocation and on the document tree not existing.
