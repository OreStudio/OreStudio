* Acceptance

- A party holds, or is given, the fixings of each index its trades use, under the party isolation the export applies.
- The baseline run's fixings file holds the public overnight fixings of the indices the population uses.
- A test fails when a party's export leaves out a public fixing of an index the party uses.

* Plan

The capture [[id:A77947D9-FB2E-4518-A26B-21680DB0E1E1][World data versus party configuration]] classes market quotes as world
data, and states the rule for a party's own copy: take the party's row first
and the world's otherwise. Fixings are the clearest case: the public sources
store them once, under the system tenant, and every party's trades fix
against the same published rate.

1. State the rule as a pure function, =series_to_export=: a party's run
   writes the party's series, and each fixing series of the system tenant
   whose address the party holds no fixing series of, the first one only.
2. Read the fixings of the chosen series once for each tenant and party that
   holds them, keyed as the table's indexes are, and not once per series.
3. Run the ACCOUK NPV report and measure the fixings file, the export time,
   and ORE's load time and missing fixings.

* Decisions

- *The export reads the world, rather than copying it to each party.* A copy
  under each party, the way raw quotes reach a party through its
  subscriptions, would store 301,675 fixings again for every party of every
  tenant, and would need a job to keep each copy current. A fixing is the same
  fact for every party, so the export reads it where it is stored.
- *A party's own fixing series wins.* A party that keeps its own series of an
  index overrides the world's, as the capture's override rule states.
- *A session with no party writes its own tenant's series.* Before, it wrote
  every series it could read, but read data only from its own tenant, so the
  world series came out empty; the rule now says so plainly.
- *All world fixings, for now.* The run carries every public fixing, 1.5 MB
  compressed, and ORE spends about 3 s loading them. Narrowing to the indices
  the trades name is the export narrowing task's.

* Notes

- Main's trade generator refused the provision of 2026-11-17 12:01: the
  population of 1000 trades gives bonds 40 trades and its configs need 44, so
  no trade was booked. The measurements below therefore run ORE on the package
  of the earlier run =e5d89166= with this run's fixings file.
- The 8 overnight SONIA fixings ORE still misses are for 2026-11-16, the
  business day before the run; the newest stored GBP-SONIA fixing is
  2026-11-13. SONIA publishes the next business day, so this is the

* Result

A party's run now writes the public fixings the system tenant stores, unless
the party holds its own series of the index. ACCOUK's fixings file went from
empty to 301,675 fixings, the overnight SONIA history resolves, and the
export reads the fixings in one query per tenant and party.
