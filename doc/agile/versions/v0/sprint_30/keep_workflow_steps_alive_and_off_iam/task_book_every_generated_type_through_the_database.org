* Notes

- The check lives in =ores.synthetic.core.tests=, which already links the
  trading core service, so it draws each class's population with the planner
  and books it through =trade_operations_service=. It asks the planner for a
  population of each class's own code count, so every code the class cycles
  appears exactly once.
- Four defects, in the order they appeared. The check found the last three.
  - The fixture's first attempt wrote a portfolio whose currency was a random
    code, which the currency validator refuses. The fixture now writes the
    currency it uses, because the conventions the population draws on name
    indices in EUR.
  - The check built the service from a temporary port:
    =trade_operations_service books(f.ctx, open_books{})=. The service holds the
    port it asks, so the temporary died at the end of that statement and the
    first booking read it. That is the segmentation fault a backtrace put inside
    =book_trade=: the port is the first thing a booking reads once it has
    checked the instrument rows. The check now names the port, and the service
    deletes the rvalue overload, so a port that only the constructing statement
    owns is a compile error and not a crash.
  - The store holds a trade's counterparty to =ores_refdata_counterparties_tbl=
    and not to the parties table. The fixture writes a generated counterparty,
    and the population states that row as its counterparty and its issuer.
  - The check drew all eight classes from one config, so the second class booked
    trade ids the first had already written, and every one answered
    =already_exists=. A config states one asset class, and the planner names a
    trade from its config, so each class is now drawn from its own config, built
    with =config_id_for= the way a provisioner builds one.

* Result

The check books one trade of every generated type of all eight asset classes
through the real tables, 103 assertions, one population per class. Each of the
three defects it found is fixed at its cause: the service no longer accepts a
port it would outlive, the fixture writes the counterparty the store holds the
trade to, and each class is drawn from a config of its own.

The crash it found was in the check and not in the store. The service let the
mistake through, though, which is why the constructor refuses it now.
