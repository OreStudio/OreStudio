* Plan

- The generator moves, not the callers: =entity_event_prefix= states
  <component>.v1.events.<collection>, and the junction prefix with it, so every
  event header, protocol header and TypeScript twin follows from one rule.
- The feed subscribes =*.v1.events.>= and reads five segments from the right.
  The old four-segment spelling is refused rather than tolerated, so a publisher
  left behind is named by the check instead of going quiet.
- The checker learns the event grammar and refuses the old form. The
  specification, the messaging references and the codegen tests state it too.
- Two subjects are written by hand and move with it: the scheduler's
  job-instance announcement and the shell's watch of it.

* Result

An event is now =<component>.v1.events.<collection>.<action>=. The namespace is a
token of its own, so =*.v1.events.>= hears the events of every component and
nothing else: the feed no longer subscribes to every versioned request in the
fleet and discards all but the events.

The generator states the rule once, and the catalogue is regenerated from it:
481 event headers before the merge, and every protocol header and committed twin
with them. The feed parses five segments from the right and refuses the old
spelling; the conformance checker accepts the new grammar and refuses the old
form; the specification says five segments for an event. The BFF's
=eventSubject= and its twelve assertions follow, and so do the scheduler's
hand-written announcement and the shell's watch.

Verified: the conformance check reads 406 declarations with none new, 64 codegen
tests pass, and the core and eventing suites pass. Not verified: the scheduler's
integration cases, which need a broker this worktree does not have running, and
the web suite beyond formatting. The deployment runs the old spelling until it is
rebuilt.
