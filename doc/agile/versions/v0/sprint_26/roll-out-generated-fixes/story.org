* Goal

Every component outside =COMPONENTS_UNDER_TEST= carries the four generator
fixes the refdata clean-standard pass landed: a put response and a
single-version response carry their row in a =std::optional=; a batch removal
of an empty key list answers instead of rendering an empty =IN (=; the
protocol-dependency gate keeps the =ores.doc.shell-recipe= family alive, so
each component's recipes regenerate; and each response shape's TypeScript twin
matches its header. The work is captured in the next bucket as
=shell-recipes-no-longer-run=.

* Acceptance

- =history=, =scheduler=, =storage=, =marketdata= and =synthetic= are regenerated
  against the current templates, one commit per component, and
  =check_component_drift.py --all= reports no drift.
- Every hand-written caller the new response shapes break is migrated, with the
  break named in the commit that fixes it.
- A full =compass build= exits 0, =compass db recreate -y -k= exits 0, the
  fleet comes up 25 of 25, and the full =ctest= suite passes.
- The two components that stay outside — =trading= and =workspace-cpp= — are
  recorded with the reason each is out, so the remainder is not assumed done.

* Decisions

- =trading= is deliberately not regenerated. Its model holds 64 entities, and
  the regeneration rewrites the whole component rather than refreshing a stale
  corner of it.
- =workspace-cpp= is deferred rather than out. Its regeneration is structural:
  it materialises 30 files, 10 of them new eventing, history-provider,
  registrar, handler and presentation files the component does not carry.

* Out of scope

- =trading= and =workspace-cpp=, for the reasons above. Both stay in
  =shell-recipes-no-longer-run= so the next pass picks them up.
