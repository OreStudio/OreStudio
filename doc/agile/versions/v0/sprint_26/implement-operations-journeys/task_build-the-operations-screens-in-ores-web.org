* Goal

The five operations journeys run in =ores.web= against the real server, as
the accepted prototype draws them: the services roster, the whole grid with
its node table and wrapper panel, the bus vitals and streams, the logs filter
bar, and the versions panels with the footer. The screens ride the journey
runtime the Setup group landed, with a hand-written BFF route per screen, and
Operations is an area with "Back to operations" navigation rather than tabs.
Where the data-model linkages are not yet closed, the screen states the gap
as the prototype does rather than showing a guess.

* Acceptance

- The five screens run against the real server on the journey runtime, and no
  journey entity is added.
- Each screen carries its Related journeys links, and the versions panel reads
  the database from the login answer with no request of its own.
- The Operations area offers the five screens with "Back to operations"
  navigation, and every screen carries the footer with both builds.
- Every gap the five journeys record is either closed or stated on the
  screen, and the statement is recorded.
