#+title: How do I open the web as an Acme user?
#+description: Open an isolated Chrome with the sign-in form filled for a seeded Acme user, chosen by name, job title or role, without adding profiles to your own Chrome.
#+type: recipe
#+level: cross
#+filetags: :ops:web:acme:compass:
#+created: 2026-10-10
#+updated: 2026-10-10

Acme is a fixed seeded tenant, so compass open-as knows its users, their shared password and its three offices. Each user gets a separate Chrome data directory under the cache folder, so your own Chrome profiles never change.

* Question

How do I test the web as a particular Acme user, or as a user of a given job title or role in a given office?

* Answer

Choose the person by name, by job title, or by role. Title and role take an office: london (the default), new york or hong kong. Aliases uk, ny, us and hk work too. When several people match, the first opens. Add --pick N to open another, or --list to see them all.

#+begin_src sh :results verbatim
./compass.sh open-as name "adrian vance"
./compass.sh open-as title "senior trader" --location hk
./compass.sh open-as role trading --location hk --pick 3
./compass.sh open-as tenant_admin
./compass.sh open-as super_admin
#+end_src

The two administrators have their own words: tenant_admin opens as tenant_admin@acme_corporation, and super_admin opens as the system administrator. Neither takes more text.

The browser opens on the web sign-in page with the username (for example adrian.vance@acme_corporation) and the password filled in. Press Sign in. A near miss in a name, such as "adrian vince", still finds the closest person. The Chrome profile carries the person's name. Chrome gives a profile that is not signed in to Google no way to show a photo, so the photo is not set. The command finds the Wayland or X display itself, so it also runs from a shell that was not started on the desktop. Add --workspace N to open the window on workspace N, where 1 is the first. GNOME on Wayland cannot move a native window from outside, so this runs Chrome under X11 and moves the window with wmctrl. Each person keeps their own Chrome data, and each workspace keeps its own copy, so the same person on two workspaces keeps different pages. Close Chrome in the normal way and the pages left open, and the sign-in, come back the next time you open that person on that workspace. Use --fresh to discard a persona's browser data, and --no-fill to leave the form empty.

* Script

projects/ores.compass/src/compass_open_as.py, run through compass open-as. The staff come from projects/ores.seeder/datasets/acme_corporation/accounts.json.

* Tested by

projects/ores.compass/tests/test_compass_open_as.py checks the choice by name, title and role, the office aliases and the DevTools frame encoding. The sign-in fill was checked against a running web service in headless Chrome.
