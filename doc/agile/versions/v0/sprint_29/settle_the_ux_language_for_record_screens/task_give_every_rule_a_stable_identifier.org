* Goal

A rule is named by an identifier that survives a section move. The checklist cites identifiers, not section titles, and a check in the harness reports the same identifier.

* Acceptance

- Every normative rule in the two pages carries an identifier in a stated scheme, and the scheme is documented on the UX hub.
- The Screen review checklist cites each line by identifier.
- A check in the repository refuses a rule without an identifier and a checklist line that cites an unknown identifier.

* Plan

Build the lever first: =build/scripts/check_rule_identifiers.py= names the
keyed pages and a code for each section whose bullets are rules, gives a bullet
without an identifier the next free one of its section with =--assign=, and
refuses a rule without one, a duplicate, and a checklist line that cites an
unknown one. A rule the page keeps as prose or as a table's lead gets a
placeholder by hand, =*RS-LIST-??*=, and the script numbers it. The checklist is
rekeyed in two passes: a script proposes the identifiers each line cites from
the sections it names and the words it shares with the rules there, and the
lines it cannot place are cited by hand. The check joins the docs class of the
local gate and the Doc Lint workflow, and the UX hub states the scheme.

* Result

Every rule in the record screen standard and the entity screen specification
carries a stable identifier at the start of its bullet or paragraph, 98 and
204 of them. The Screen review checklist cites identifiers on every line that
names a keyed page, 90 of 110; the rest cite UX Language, UI design
principles or the configuration standard, which are not keyed yet. The check
=build/scripts/check_rule_identifiers.py= refuses a rule without an identifier,
a duplicate, and a checklist line that cites an unknown one, and runs in the
docs class of the local gate and in the Doc Lint workflow. The UX hub states the
scheme and its permanence rule.
