* Steps

** Log in as the tenant administrator

- Start the shell against the running environment: =compass shell=.
- Log in with the provisioned tenant administrator account and its password,
  and confirm the shell reports the login succeeded before continuing.

*** Result

** Import a curve whose pillars are staggered

- Run =marketdata import --file external/ore/examples/Legacy/Example_56/Input/market.txt --source ore.reference=.
- Confirm the import reports the series and observation counts it read and
  no hard failure.
- The import gives every observation the instant it was read at. To get a
  stitched curve, backdate one pillar with
  =compass sql -- -c "update ores_marketdata_market_observations_tbl set observation_datetime = observation_datetime - interval '3 days' where oresmd_uri = '<one pillar of the imported curve>' and valid_to = '9999-12-31 23:59:59'"=,
  and confirm one row was updated.

*** Result

** Read the snapshot and check the ages

- Ask the read for that series, over the shell command that sends
  =marketdata.v1.curve_snapshot.get=, or over =compass shell= with the raw
  subject.
- Confirm the reply states =as_of=, the instant the read is relative to.
- Confirm =recorded_at= has exactly as many entries as =observations=, so
  each point has a record time and none is missing or extra.
- Confirm =oldest_age_seconds= equals the read's instant minus the oldest
  point's =observation_datetime=, and that the backdated pillar is the oldest
  one.
- Confirm =spread_seconds= equals the difference between the oldest and the
  newest age, and that it is at least three days minus the range the import
  covered.
- Confirm =warning= is true: with one pillar three days behind the rest, the
  curve is stitched and must not be drawn silently.

*** Result

** Read a snapshot whose points share one instant

- Choose a series whose observations were all imported in one run and were
  not backdated, and ask the same read for it.
- Confirm =spread_seconds= is zero and =warning= is false, however old the
  points are: the age of a curve is not the warning, the mixing is.

*** Result

** Confirm the old read is unchanged

- Ask for the same snapshot through any caller that used =read_as_of= before
  this change — the curve bootstrap and the republish path are the two in the
  tree — and confirm the points come back exactly as they did, with no record
  time added and no field removed.
