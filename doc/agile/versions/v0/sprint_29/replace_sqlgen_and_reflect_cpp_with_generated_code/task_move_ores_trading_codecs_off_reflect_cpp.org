* Acceptance

- Every ores.trading model that names an entity, a junction or a field group
  uses the generated codecs.
- ores.trading's hand-written JSON uses the generated codecs or yyjson, except
  the files listed under "What is left", each of which names its owning task.
- No file in ores.trading includes reflect-cpp unless a task in this story owns
  its removal.
- ores.trading's suites pass, and its wire bytes match the bytes before the move.

The first draft of this list asked for no reflect-cpp at all. Five files cannot
meet that inside one component: each waits on a generator or shared-type change
that the whole estate needs. Those changes now have their own tasks, so the
criteria name the boundary instead of hiding it. The fourth criterion is met by
=message_codec_tests.cpp=, which compares the generated bytes with the
reflector's bytes for a trade and a trade type in JSON and MessagePack.

* Notes

**The sweep, and the facet it forgot.** 148 models were opted in and the
wire-codec, protocol, nats-eventing and domain facets regenerated, which took the
component's production C++ files naming reflect-cpp from 254 to 7. The eighth error
then named =text_form<instrument_identity>= though the type had a shape, because
a field group states its shape under its own facet, and that facet was never
regenerated. Regenerating =ores.cpp.field-group= wrote all 26 of them from the
template, and the three shapes that had been hand-written were deleted: the
generator states them, so a hand copy is drift.

**An enumerator was spelled in two places.** The codec's =text_form= names an
enum through =magic_enum=, and the repository mapper and the presentation history
mapper named it again through =rfl::enums=. Both templates use the codec now, so
one statement remains, and no =cpp= file in the tree calls =rfl::enum_to_string=
or =rfl::string_to_enum=. Six generated units move estate-wide: four in this
component and two in ores.inbox. A shared template cannot honour one component
per task, so the boundary is stated rather than hidden, and the estate build is
the evidence it is safe.

Where a type states its own text form the mapper's spelling can differ from
rfl's. =product_type= spells =unknown= as the empty string, which is what its own
header documents and what the wire already wrote; the mapper was the odd one out.
=codec_product_type_tests.cpp= compares the codec against =rfl::json::write= for
three of the nine enumerators, including =unknown=, which is the one that states
its own form, so the two agree by test and not by argument.
=message_codec_tests.cpp= does the same for a trade and a trade type in both
formats: the generated codec is asserted to write the reflector's bytes, which is
what the trade's acceptance criterion asks for.

**Five refdata mappers the regeneration surfaces.** Regenerating the repository
facet is what the enum change requires, and it rewrote five refdata mappers
because their models state =:store_transform:= and the tree had stopped applying
it: =[marketdata] Finish the connectivity and public rates screens (#4262)=
removed the calls without removing the property. The removal was partial and so
is this repair: eleven refdata models state a store transform, and main applied
it in six mappers. The model is authoritative in this story, so the tree follows
it. It is another component's unit and is stated here rather than buried.

**draft_reason arrived after the sweep.** Main added the =draft_reason= entity
after the 148 models were opted in, so its event and protocol encoded through
reflect-cpp. It is opted in now, which makes 149. Main also never listed its C++
files in the CMake component lists, so the =cmake-sources= gate failed on main;
the regenerated lists fix that here.

**A member main added was dropped on the wire.** Main also added
=draft_reason_code= to the trade after the sweep. The shapes the sweep wrote did
not name it, so the generated codec dropped the member. The byte comparison test
in =ores.trading.core.tests= failed on it, and the =component-drift= check named
the two stale headers. Regenerating the trade's wire-codec and protocol facets
fixed both. A branch that carries generated shapes must regenerate after each
rebase, and the drift check is the gate that says so.

**What is left, and which task owns each one.**
- =economic_digest.hpp= walks a value's members to hash the ones its model marks
  economic. It decides with =if constexpr=, so the member's name has to be a
  constant expression. Owner: [[id:9994C1B0-0071-4ACA-AA15-B2885D9235C7][State a type's wire shape by its type]].
- =trade_operations_service.cpp= walks a bond row the same way to name the parts
  it cannot write yet. Owner: the same task.
- =trade_operations_handler.hpp= stores an export blob with =rfl::msgpack=. Its
  messages come from an operation model, and no operation model has a generated
  codec: 0 of 73. Owner: [[id:5891DD57-4FDE-4C99-9009-8299E4479AA1][Generate codecs for the operation messages]].
- =options.cpp= prints the service's configuration, which holds logging, NATS
  and database options types that have no shape. Owner:
  [[id:BE89C669-2CBF-477D-B87B-1C6996187585][Print every options type through the codec]].
- =product_type.hpp= carries a legacy =rfl::Reflector= that the codec tests
  compare against. Owner: [[id:7A1D09B8-B3F2-4E02-9669-3C2F6CC2C6EC][Remove reflect-cpp]].

The reflectors include in =bus_book_status.cpp= and =application.cpp= is gone.
Neither file named a reflector, and the full build passes without it.

* Result

ores.trading's generated types encode through the generated codecs. 149 models
opt in, and the field groups are regenerated from the template. Production files
that name reflect-cpp went from 254 to 5, and each of the five has an owning
task in this story. The enum text form now has one spelling, through
=text_form=, and a refused value names the allowed values. A byte comparison
test proves the generated codec writes the reflector's bytes for a trade and a
trade type. Three new tasks own the estate-wide blockers: shape by type,
operation codecs and options printing.
