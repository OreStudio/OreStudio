* Goal

Every report definition ACME carries resolves a report configuration, each scoped to the ACME root portfolio and shaped after the matching external/ore example, and a SQL function returns every book under a root portfolio for the run to read.

* Acceptance

- Every report definition provisioned to ACME resolves a configuration, so no run fails with 'risk_report_config not found'.
- Each configuration is scoped to a root portfolio, or records why the root portfolio does not apply.
- The configuration values follow the matching external/ore example under external/ore/examples.
- A SQL function returns every book under a given root portfolio, and the report run reads the population from it.

* Plan

The inventory first, because the numbers decide the shape.

- The seed profile =acme_demo= publishes the =risk_management= and
  =party_essentials= bundles, and =ore.report_definitions= rides both. The
  dataset carries 31 definitions, not the 30 its own docstring claims. The
  publish runs per party, and provisioning publishes to the system party and
  to each ACME company, which is where the 155 comes from.
- Every definition is report type =risk=, and that type requires four
  configuration types: =pricing_engines=, =todays_market=,
  =curve_configuration= and =conventions=.
- The run resolves a =risk_report_config= by definition id. No seed writes
  =ores_reporting_report_configurations_tbl=, the risk config or its scope,
  so every seeded definition is unrunnable.
- The root portfolios are =Group Treasury Portfolio=, =Global Portfolio=,
  =Regulatory Capital=, =ACME Corporation US Inc Global Markets= and
  =ACME Corporation HK Ltd Global Markets=.
- The SQL method that returns the books under a root already exists:
  =ores_trading_get_book_ids_by_portfolio_fn= walks the portfolio subtree,
  and =ores_reporting_resolve_book_ids_for_config_fn= already calls it for a
  config scoped by portfolio. This task reuses both rather than adding a
  third.

Work, in order. Fold each step into the provisioning path so a recreated
database reproduces it.

1. Add the seed that creates, for every active definition of a party, its
   risk report config and the configuration row that binds the two, shaped
   from the =MinimalSetup= and =MarketRisk= run documents.
2. Scope each config to the party's root portfolio.
3. Bind the four configuration documents the type requires, using the
   =MinimalSetup= and =Input= examples.
4. Extend =ores_iam_reset_tenant_fn= to wipe the configuration tables, so a
   reset leaves a tenant in the seeded state rather than with orphaned
   configurations.
