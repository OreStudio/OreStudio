** What H01 cost

The four part diagrams had gone stale and their manual sections were empty. The
automated pass, =build/scripts/generate_component_puml.py=, was run with its
diff read before the refresh, per G07. It exposed two parser defects, both
fixed at source with the regression test
=test_plantuml_component_parse_nested_type.py=:

- A type declared inside a class on one line was read as a data member named
  after the type, so a repository box gained =+remove_status : enum class=. The
  pass draws types at namespace scope only, so the nested declaration is
  skipped and left to the manual section.
- A two-level brace initialiser at namespace scope opened two braces but the
  parser counted one, so the enclosing namespace never closed and the next
  sibling was nested inside it: =ores::marketdata::datum::detail::detail=.

The manual pass below each sentinel adds the derived edges and notes the free
functions, the nested types and the declarations the parser cannot read; each
rendered image was read. The composite root owns no code, so the automated pass
has nothing to contribute to it: the root is a hand-authored component diagram,
and its oresmd data-model diagram is kept as =ores.marketdata.data_model.puml=.
The root's missing sentinel is recorded as an accepted exception for H01 in
=projects/ores.codegen/scripts/component_registry.py=, with the reason every
listed composite gives.
