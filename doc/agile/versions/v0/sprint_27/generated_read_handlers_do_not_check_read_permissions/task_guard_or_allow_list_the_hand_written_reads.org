* Result

Twelve hand-written reads checked nothing; each now checks its resource's
read code, and three resources had their codes seeded. =suggest-commands=
answered anybody with an account's id and its tenant's hostname for any
username in any tenant; it now needs a session and =iam::roles:assign=, and
another tenant needs =iam::tenants:read=. The four reads made before a
session exists are allow-listed, and the rule names that reason. A rescan
finds no hand-written read without a check except the allow-listed ones, the
history dispatcher and the access read whose service checks it.

A local review found two more: the =composite_as_of= methods the party and
counterparty models inject into their generated handlers. The party method
checked nothing, so any signed-in member read any party with its contact
information; both now check their resource's read code.
