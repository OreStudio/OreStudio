* Goal

A tenant may see the generator, as a firm may read a vendor's methodology, but nothing a party
builds, calibrates or prices reads the generator's data: a party works only from the quotes it
receives by subscription, so replacing the generator with a real vendor changes data, not code.
What a tenant sees of the generator stays only if it adds something for the tenant.

* Acceptance

- No tenant-side process (provisioning, bootstrapping, calibration, forwards, pricing, reports)
  reads a synthetic table; a check fails the gate if one starts to.
- No tenant session can write the system tenant's generator rows: the row policies apply to
  every command, so a tenant administrator's write is to be shown refused, or made so.
- What a tenant session shows of the generator is either removed or kept with the reason it
  helps the tenant.
