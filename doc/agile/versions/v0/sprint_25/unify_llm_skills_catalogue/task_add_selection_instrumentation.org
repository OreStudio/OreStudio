* Goal

We know skill mis-selection is a real problem because it has been corrected by hand repeatedly over months. What is missing is not the knowledge but the quantification and the reporting. The council asked for a retrospective study of thirty past tasks as a gate on the whole migration; we reject the gate, because half this work is new capability and you cannot measure the failure rate of something not yet built. What we accept is the honest half: we have no instrument. Build one that records selection events forward, so the measurement accrues while the work proceeds and keeps working after the migration lands, which a one-off scoring exercise would not. Record for each session the skills offered, the skill chosen, whether it was corrected, and the correction reason. Report on it.

* Acceptance

- Every skill invocation records the skills that were visible, the one chosen, and whether the user or the agent corrected it.
- A correction records a one-word cause: description, catalogue-size, level, or none.
- A compass command reports selection quality over a window, including the correction rate and the causes ranked.
- The instrument runs without the agent having to remember to use it.
- The report distinguishes sessions run under the attenuated catalogue from sessions run without it, so the level axis can be judged on evidence.
- First report is produced and reviewed before the sequencing function lands.
