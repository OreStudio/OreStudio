* What

Two changes, smallest first.

1. Require every measured number in a task record to name the command that
   produced it and the commit it was measured at. The task template's Evidence
   column says "kept on the task" today, which is not the same claim.
2. Optional, and only if it earns its place: a =compass task verify <task>= that
   re-runs the commands a record declares and reports any that no longer produce
   the number beside them.

* Why

A clean-standard record is a claim about a tree, and its numbers are the part a
reviewer checks least and a verifier re-runs first. When trunk moves under a
branch, a count of consumers, a gate's component count and a suite's size all
change without any code changing, and the record goes quietly wrong.

The measured case is the =ores.service= task. Trunk advanced four times while the
branch waited, and the record was failed twice by independent verifiers for
exactly this. Five of ten census counts, the codegen suite count, the
handler-permission component count, the refdata drift count and the Notes' suite
size had all been taken on an earlier head. Both rounds confirmed the code was
sound and failed the record, which cost two extra verification rounds on work
that was already correct.

Naming the commit turns that from a discovery into a visible statement. A reader
sees "measured at 1a2b3c4" and knows whether the base has moved since. The
verifier command would close the loop, but the template change is what makes the
answer checkable.
