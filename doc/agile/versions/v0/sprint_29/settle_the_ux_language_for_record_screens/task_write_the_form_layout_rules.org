* Acceptance

- The standard states field grouping and order, including how a form of many fields splits into sections.
- The standard names one widget per field kind, including picker, badge select, date, long text and image.
- The standard states button placement in the dialog and on the record page, and the history layout.
- The refresh behaviour on a form, including the gold Refresh and the edit in progress warning, is stated once and linked from Change notification.
- Each rule names the shared component that carries it.

* Plan

Take the eleven open questions of the audit's form layout section. For each,
read what the shared dialog, the field input and the details grid do today, and
write that as the rule where it is right. Where the code has no answer, write the
smallest rule that settles the question: one dialog with titled groups and no
tabs, the field table's order with the key first, and a kind the field kinds
table lacks added before a screen uses it. Put the rules in one new section of
the record screen standard, add the two field kinds the table lacked, and give
the checklist a line per rule. Apply every edit by one script whose
replacements must match exactly once.

* Result

The record screen standard has a section The form's layout: one dialog with no
tabs and titled groups for a kind with many fields, the field table's order with
the key first, two columns from the small breakpoint, the help or meaning under a
control, nothing marking a required field, Cancel then the primary button at the
right, Escape through the guard and Enter never saving, and the refresh rules
pointed at the entity specification. The record page's details grid is stated
too. The field kinds table gains cron and longtext, and a kind it lacks is added
before a screen uses it. The checklist has a line per rule. Every rule names
the part that carries it, and the longtext control is the capture Add a long
text field kind.
