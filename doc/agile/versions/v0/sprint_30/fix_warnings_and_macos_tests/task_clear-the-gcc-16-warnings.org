* Result

Closed on branch =hotfix/clear-the-gcc-16-warnings=, code commit a3409670ca.

The nightly's 138 warning rows come from six causes. Three were our code and are
fixed here: =-Wsubobject-linkage= on the range type that =handle_get()='s
coroutine frame held, =-Wmaybe-uninitialized= on the four rate builders that
copied a value-initialised =swap_instrument_data= into their =expected=, and
=-Wmaybe-uninitialized= on the anonymous temporary the NATS request's =as_tuple=
adapter left in its frame. One was already fixed on main by eb04abd593, which
renamed the curve route's =identity= struct, so the =-Wchanges-meaning= errors
that failed the build are gone without a change here.

The remaining two are =-Warray-bounds=, and both are inside code this tree does
not own: libstdc++'s =make_shared= control block and Boost 1.92's exception and
beast internals. =-Warray-bounds= is off for GCC in =projects/CMakeLists.txt=,
with the trade-off stated there.

The nightly that reported these rows ran GCC 16.0.1. On GCC 16.2.0-3 the NATS and
iam.client warnings no longer reproduce, so those changes are precautionary for
the nightly and necessary only while it stays on 16.0.1.
