* Goal

Give ores.platform a stop state with an interruptible wait, so that the retry of the feed restore and the deadline watch of the workflow engine do not poll. A platform whose library has the C++20 stop types uses them, and Apple's libc++ uses a portable subset with the same names, so the wrapper can be deleted when Apple catches up. A check keeps the C++20 stop types out of code outside ores.platform.

* Acceptance

- stop_source has wait_for(span), which returns early on a stop and answers whether a stop was requested.
- Where the library has them, the names are the standard types, and elsewhere they are a portable subset with the same spelling, so dropping the wrapper is a replacement of the namespace.
- The portable types compile on every platform, and the unit tests run them on Linux beside the selected types.
- A unit test shows that a stop wakes a wait at once, and it fails when the wake-up is removed.
- The feed restore retry and the deadline watch call wait_for and do not poll.
- A check fails on std::jthread, std::stop_token and std::stop_source outside ores.platform, and it runs in CI.

* Plan

1. Name =jthread=, =stop_token=, =stop_source= and =wait_for= in =ores::platform::concurrency=. Select the standard types when =__cpp_lib_jthread= is defined. Otherwise select the portable subset, which has a mutex and a condition variable that a stop wakes.
2. Move the feed restore retry and the deadline watch of the workflow engine onto =wait_for=, and delete their polling loops.
3. Test the wait on Linux, and check that the tests fail without the wake-up.
4. Add a check that fails on the C++20 stop types outside =ores.platform=, and run it in CI and in the local gate.

Decision. The first version of the change used the portable subset on every platform, so that the code macOS runs was the code Linux tests. The owner asked for the standard library on Linux, with the wrapper only as a fallback to delete once Apple's libc++ catches up. The portable subset is therefore always compiled, and the tests run it beside the selected types, which keeps the coverage. The names are the standard names, so the later removal is a replacement of the namespace.

* Notes

- The feed restore retry (#3633) polled in spans of 100 ms, and the deadline watch polled in spans of 250 ms. Both now wait on the stop state and wake at once.
- The portable types follow the standard ones where the tests can see a difference: a token with no state is never stopped, and a moved-from source does nothing.
- Defining =ORES_PLATFORM_PORTABLE_STOP= selects the portable types on any library. A probe of the callers' code compiled and ran with it on clang and gcc.
- The standard =wait_for= makes a mutex and a condition variable on each call. Its callers wait for 2 s to 30 s between calls, so the cost does not matter.
- The check is in its own workflow, =portable-stop-types.yml=, because the drift workflow runs only when models, tests or templates change, and a new use of a stop type is a change to a C++ source.
- The macOS nightly build is the first run of this code on Apple's library. The tests run on Linux.
