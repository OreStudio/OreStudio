#+title: How do I run the ir_curve_bootstrap_pillars commands from the shell?
#+description: Every command the ir_curve_bootstrap_pillars submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:ir_curve_bootstrap_pillars:

This file documents the ir_curve_bootstrap_pillars resource at the shell, one section per command. Every command is a subcommand of =ir_curve_bootstrap_pillars=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: D939B2DD-1C3F-5179-85C0-5866B0BF02A7
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
ir_curve_bootstrap_pillars list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.ir_curve_bootstrap_pillars.list=.

#+name: ir_curve_bootstrap_pillars-list
#+begin_src ores-shell :tangle ir_curve_bootstrap_pillars-list.ores :exports none
ir_curve_bootstrap_pillars list --limit 1
#+end_src

** =add=
:PROPERTIES:
:ID: 454542E2-2D0B-5264-BAD4-DF455DE0424E
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
ir_curve_bootstrap_pillars add <party_id> <bootstrap_config_id> <sequence_index> <start_tenor_code> <end_tenor_code> <curve_role_code> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.ir_curve_bootstrap_pillars.put=.

** =set=
:PROPERTIES:
:ID: FD1200CA-244E-53E0-B3F1-00132335F086
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:
