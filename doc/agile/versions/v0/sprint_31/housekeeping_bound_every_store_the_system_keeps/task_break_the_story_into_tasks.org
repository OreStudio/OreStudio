* Result

The story carries eight tasks, in the order the investigation ranks them by what
bounding each would save. Each states a goal and checkable acceptance, and none
carries a branch: the branch is created when the task is started, so one branch
is in flight at a time.

| Task | What it removes | Order |
|------+-----------------+-------|
| Carry the delivery counts forward | 1270 MB of versioned rows behind 23 counters | 1 |
| Bound the report run outputs by age | 1777 MB, growing about 7 MB a run | 2 |
| Share one package cache across a host's nodes | 266 MB per node per engine version | 3 |
| Give object storage a lifecycle | every key family, none of which expires | 4 |
| Decide whether calendar dates are stored or computed | 612 MB, copied per tenant | 5 |
| Model the retention policy | the mechanism the rest depend on | 6 |
| Build the housekeeping sweep | applies the policy, with the licence fallback | 7 |
| Give housekeeping a screen | makes a policy visible and changeable | 8 |

The first two are transforms and retention on the stores that hold the most. The
third and fourth bound artefacts rather than rows. The last three build the
mechanism that keeps the others from returning.

Two tasks already existed and are not repeated: releasing a job's folder once its
output is uploaded, which sits on its own branch, and the umbrella implement
task, which these displace once the mechanism is picked up.

The measurement table is not repeated here; every figure in the order column is
stated with its command in
