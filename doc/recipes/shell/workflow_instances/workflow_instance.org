#+title: How do I run the workflow_instances commands from the shell?
#+description: Every command the workflow_instances submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:workflow_instances:

This file documents the workflow_instances resource at the shell, one section per command. Every command is a subcommand of =workflow_instances=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 6964009A-C345-587F-A150-ADF4E0166D0B
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
workflow_instances list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =workflow.v1.workflow_instances.list=.

#+name: workflow_instances-list
#+begin_src ores-shell :tangle workflow_instances-list.ores :exports none
workflow_instances list --limit 1
#+end_src

** =add=
:PROPERTIES:
:ID: BEA67046-EAA0-5657-9B49-33B528609D58
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
workflow_instances add <type> <state_id> <request_json> <result_json> <error> <correlation_id> <created_by> <current_step_index> <step_count> <materialised_steps_json> <completed_at> <last_event_at> <reason> <commentary>
#+end_example

It is addressed at =workflow.v1.workflow_instances.put=.

** =set=
:PROPERTIES:
:ID: 36E11EFD-7E24-5756-BE17-140DD7FFE92F
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.
