* Goal

ORE becomes an OAuth 2.1 authorization server for its own API, for every client
and not for MCP alone. A client such as Claude Desktop or claude.ai connects to
/mcp, is sent to ORE's own sign-in and consent pages, and the person signs in,
possibly with an external identity, and approves the client, which creates the
same agent grant an API key does. ores.http publishes protected resource
metadata, answers 401 with WWW-Authenticate, and serves authorization server
metadata, an authorize endpoint whose sign-in is the one the previous tasks
built, and a token endpoint with PKCE S256, rotating refresh tokens and tokens
bound to ORE by resource indicator, as MCP's authorization specification asks.
MCP is the first client of this server; any other client that follows the same
specification is served by the same endpoints.

* Notes

* What the libraries give, and what they do not

Probed on 2026-11-25 against =microsoft/vcpkg@master=. No port provides OAuth
2.x or OpenID Connect: =ports/oauth2=, =ports/openid=, =ports/oidc=,
=ports/liboauth2=, =ports/libjwt=, =ports/keycloak=, =ports/hydra= and
=ports/dex= are all absent, and =cpprestsdk=, the only port tagged =oauth2=, has
been removed from vcpkg and was a client-side helper in any case. What is
available is the parts:

| Port | What it gives |
|------+---------------|
| jwt-cpp | JWT signing and verification, already in the manifest and used by ores.security |
| openssl | The crypto behind it, HMAC and RSA |
| boost-json | Parsing the metadata, the JSON Web Key Set and the request bodies |
| libsodium | Ed25519 and secretbox, if a future revision needs them |
| cppcodec | Base64url, for the key set's members |

So the cryptography and the token format are not work this task does. The
protocol, the client registry, the consent and the binding to the agent grant
are, and no library in vcpkg would give them.

The alternative worth weighing is not a library but a service: run an
authorization server of the fleet's own (Keycloak, Dex or Hydra), point MCP's
protected resource metadata at it, and validate what it issues with jwt-cpp.
That removes the protocol from ORE and moves consent, its screen and its record
out of ORE with it. The decision task settles which way this task goes.
