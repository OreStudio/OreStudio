* Result

The Linux nightly now uploads its valgrind logs when it fails:
=Testing/Temporary/MemoryChecker.*.log= and =LastTest.log=, kept for seven
days and named for the matrix variant. A memcheck failure reports a count and
nothing else, and the stacks it counts lived in the build tree, which the
runner discards; that is what made the four defects on
=ores.http.marketdata.tests= untraceable.

PR #4976. Workflow YAML parses; =compass check --exclude-heavy= passed every
check it ran (the web check hit its own 900 second timeout on a loaded box,
unrelated to a workflow edit).

No suppression was added, and that is the substance of what this pair of tasks
found. Built in a debug tree and run with the CI's own valgrind options, the
suite reports no invalid reads, writes or uninitialised uses; the harness
thread TLS record it does carry is already covered by "Pthread TLS Allocation
via std::thread" in =build/valgrind/custom.supp=, so with the suppressions
applied the run leaves only a libc =atexit= block, which is reachable rather
than lost. The four defects the CI leg counts therefore come from something
this box does not reproduce, and the next red run now brings its own evidence.
