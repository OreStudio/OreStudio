* Acceptance

- The marketdata service tests compile under -Werror with the discarded raise result marked as deliberate.
- Both raise functions are nodiscard, so a discarded result fails the build in either of them rather than in one.

* Plan

The failing line is in =app_published_surface_tests.cpp=, in the case that
checks a set naming one surface twice is refused. The call sits in a =try=
only because the refusal is the assertion, so its result is unused on
purpose, and the compiler cannot tell that from a mistake.

The same shape exists in =app_curve_publish_gate_tests.cpp= for the curve
set, and it compiles today for one reason: =raise_publish_request_set= is
not =nodiscard= while =raise_surface_publish_set= is. The asymmetry is the
cause, so the fix is to remove it rather than to copy the =[[nodiscard]]=
across silently.

The change is three lines:

- =app_published_surface_tests.cpp= casts the raise to =void= and states
  why in a comment, because this set must throw.
- =curve_publish_gate.hpp= marks =raise_publish_request_set= =nodiscard=,
  as its sibling in the surface service already is.
- =app_curve_publish_gate_tests.cpp= casts its own deliberately unused
  raise to =void=, which the new attribute makes necessary.

Every remaining caller reads the result: the provisioning step handler in
two places, the surface publish service, and the curve gate's own
single-subject wrapper returns it.

* Notes

brave_hopper reported this: a full build of =origin/main= stopped after 358
of 475 targets, in =ores.marketdata.service.tests=, and it blocked the build
their own branch needed. The break came in with PR #4913, commit
=44e27d91ef=, which added the case that raises a set naming one surface
twice.

The report also said it was the only site. That was true of the surface
raise and false of its sibling: the curve raise is discarded in the same
way in its own test, and only escapes because that function carries no
=[[nodiscard]]=. Marking it turns the escape hatch into a compile error,
which is the point.
