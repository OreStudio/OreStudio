* Goal

The FX forward ladder shows what the session's party published and explains it. The read returns the party's published set at or before the as-of, and the screen shows its provenance: the spot, both funding curves, the convention, the method, who raised it and how it was approved. The compute-on-read path is removed once the screen reads published sets. Vol surface calibration takes its forwards from a published set.

* Acceptance

- The ladder shows only the session party's published sets, and a pair with none says so.
- Every input in the provenance panel links to its own record.
- A set closed by auto-approval says so, and names the rule and who turned it on.
- No code path computes a forward for display.
- The user manual and the journey describe the published ladder.
- The pair list offers USD pairs and the crosses with a convention, and no refusal says a pair lacks a USD leg.

* Plan

The screen keeps its shape and changes its source. The BFF route serves =marketdata.v1.ops.get_published_fx_forward= for the session's party, and the client parses the published set into the ladder the page already draws, so the chart, the table, the start and the forward-forward are unchanged.

- The published read gains what the screen needs: the spot lag, the pip and the decimals from the convention, and the approval from the inbox (who raised, its state, the auto-approval rule, who decided and the decision's comment, which names who turned the rule on).
- The page adds the spot legs, the convention version, the method and a *How it was approved* panel. Each input links to its own record: the curve to *Published curves*, a spot and the convention to the pair's page, the request to its own page.
- The pair list is every pair with a convention, crosses included.
- =get_fx_forward_ladder= goes: its messages, its handler, its subscription and its shell command. The compute stays internal to the publish, behind its own input and output types.

* Result

The FX forward ladder now shows the session party's published set of a pair, USD pair or cross, and explains it: every input with a link to its record, and how its request was decided. A set closed by auto-approval says so, names the rule and, in the decision's comment, who turned it on. No code path computes a forward for display: the compute-on-read operation is gone.

The page was checked by rendering it in tests and by reading the live BFF route, not in a browser. The manual gained a section under currency pairs, with a screenshot placeholder for the screenshot workflow.

Vol surface calibration reads its forwards from a published set in the calibration task.
