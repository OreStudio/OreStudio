* Result

Ten constructors, one per routed bond code, and a single append that crosses a
whole product into the instrument batch. Each constructor states only what its
product has, and each refuses what its product cannot be: an option with no
type, a forward with no settlement date, a future with no contract, a repo with
neither rate nor index, a total return swap with neither return nor funding leg,
a callable bond with no call date, a convertible with no target.

The batch the constructors fill is generated from the trade type catalogue's
`* Batch/Children` list, and the bond rows were missing from it: the issue and
its legs, amounts, rates and schedules had been added to the generated header by
hand, and a regeneration by another environment deleted them, leaving main
referring to arrays it no longer declared. The catalogue now states the bond
children, so a regeneration keeps them, and this task repairs the break as well
as adding the nine constructors.

Tests: thirteen cases in `domain_bond_instruments_tests.cpp`, asserting each
product's own row, the refusals above, and that a product crosses the batch in
one append. `ores.trading.api.tests "[bond]"` passes with 51 assertions.

The full tree was building when this was written and the build broke elsewhere;
the whole-tree run is owed once that is fixed.
