* Goal

CDash shows every Catch2 case again. One Test.xml with all 36,355 cases is about 54 MB, and CDash dropped it while processing it, so CI builds since 20 Nov show no tests. The expansion writes small case entries and one Test.xml per component, and the final submit sends those.

* Acceptance

- Each case entry carries its name, the suite path once, a short command
  line, its time, status, failure text and labels, and nothing repeated.
- =expand_catch2_cases.py --split <dir>= writes one Test.xml per CDash
  subproject, each with the Site header and its own Subproject element,
  and a =files.txt= that lists them. Tests with no subproject label go to
  =Test-unassigned.xml=.
- =CTest.cmake= submits those files and then the remaining parts without
  Test. Without the split files, the submit is as before.
- A real submission to my.cdash.org shows every case under its component.

* Notes

- Why CI showed no tests: the build and configure parts reached CDash, and
  the 54 MB Test.xml uploaded, but CDash kept none of its tests. Reports
  of CDash running out of memory on Test.xml files with about 15,000 tests
  go back to 2008; my.cdash.org's settings cannot be changed from here.
- One file per component keeps each file under 6 MB. ores.refdata.api is
  the largest component, with 6945 cases. If a component grows past what
  CDash takes, split it further.
- Another site, ip-10-0-134-92, also submits linux-clang builds to the
  project, with one entry per suite. It is not ORE's CI.
- The local proof build split-test-linux-clang-release-ninja stays in the
  Experimental group.

* Result

Case entries are about 840 bytes instead of about 1500, and CI sends one
Test.xml per component instead of one with every case. A local submission
of three suites, 12563 cases with the largest file at 5.8 MB, appeared on
CDash in full under its three components. The script's 11 tests pass,
two of them new for the split.
