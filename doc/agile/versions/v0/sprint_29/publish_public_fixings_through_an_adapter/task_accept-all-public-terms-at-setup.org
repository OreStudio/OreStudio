* Goal

A new system fetches public fixings as soon as it is set up: the administrator accepts every public source's terms in one step in the first run, and the shell's bootstrap setup accepts them by default.

* Acceptance

- marketdata.v1.ops accepts a list of provider codes with the versions read and answers, per provider, accepted or refused with the reason; each acceptance records the digest, the session's account and the server's time, as the single accept does.
- The first-run public sources step has an accept-all tick box that accepts every listed provider at the version shown; a provider can still be declined on its own card.
- bootstrap setup accepts every public provider's terms after it signs in as the administrator and prints one line per provider; --no-accept-terms skips it.
- A shell command accepts all public terms on a system already set up.
- No seed or profile step writes an acceptance.

* Plan

Data shape first. A =provider_terms_choice= is a provider code and the version
read, zero for the terms as they stand. A =provider_terms_outcome= is the code,
whether it was accepted, why not, and who and when. The new
=accept_many_provider_terms_request= on =marketdata.v1.ops.accept_many_provider_terms=
carries the choices; its response carries one outcome a choice and =success=
when every one was accepted.

1. Server: the model gains the two structs and the request and response; the
   protocol is regenerated for C++ and TypeScript. The handler's single accept
   becomes =accept_one=, and the list accept calls it for each choice, so one
   rule records an acceptance. Same permission, =marketdata::providers:accept_terms=.
2. Shell: =bootstrap setup= lists the providers after it signs in as the
   administrator, accepts every one that states terms at version zero, and
   prints one line a provider; =--no-accept-terms= skips it. A command accepts
   all public terms on a system already set up.
3. BFF and web: =POST /api/marketdata/public-rates/accept-terms= takes the list;
   the first-run step gains an accept-all tick box that sends every listed
   provider at the version shown.

* Notes

- Why: the adapter fetches no public provider until its terms are accepted
  (since 10-28). Nothing in setup accepts them, so after a database recreate
  every feed kept its fixed level until someone accepted the terms on the
  Public rates page. The earlier tests had accepted them by hand.
- The acceptance stays with the signed-in system administrator rather than a
  tenant provisioning step: terms belong to the system, and the record must
  name a real account.

* Result

A new system now fetches public fixings with no manual step. =bootstrap setup=
accepts every public source's terms after it signs in as the administrator, and
on a fresh database the four sources were accepted, the adapter backfilled their
fixings within seconds, and 28 FX feeds calibrated from them. The acceptance goes
through the service's one accept, so it is recorded under the administrator's
account and the server's time; =--no-accept-terms= leaves it to the person.

The service gained a list accept, which the first run's new tick box and the
shell's =provider_terms_operations accept-all= both use, and an accept of terms
already accepted writes nothing, so a setup that runs again leaves each
provider's history as it was.

The FX calibration list read about 5 s on the fresh system, against 3.4 s
measured on the calibration branch; this task does not touch that path.
