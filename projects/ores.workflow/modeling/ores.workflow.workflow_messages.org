#+title: ores.workflow.workflow_messages
#+description: Codegen operation model for the workflow engine's own conversation: starting a run, reporting a step, and reading runs, steps and definitions.
#+type: ores.codegen.operation
#+component: workflow
#+subcomponent: api
#+entity_singular: workflow
#+namespace: ores::workflow::messaging
#+brief: The workflow engine's operation messages.
#+filetags: :model:operation:workflow:
#+created: 2026-10-01
#+updated: 2026-10-01

These are the messages of the workflow engine that are not entity verbs. A
component that commissions a workflow starts a run with
=start_workflow_message=, and the service that executes a step reports it with
=step_completed_event=. A person or a client reads runs, their steps and the
registered definitions, asks for one step's result, and retries a stopped run.
The two entities' own verbs are generated from their entity models.

They were hand-written headers until this model, and the TypeScript client
mirrored some of them by hand. They are one model so that no message refers to
a message in a sibling model, which the TypeScript projection cannot resolve.

What a model cannot state stays in =workflow_vocabulary.hpp=: the step outcome
and log level enumerations with their reflectors, and the names of the NATS
headers a step command carries. Both enumerations are registered custom types,
so they cross to TypeScript as strings.

** get_step_result_request

:END:

#+begin_src cpp :name comment
/**
 * @brief Queries the workflow engine for a previously-completed step result.
 *
 * Domain service handlers send this before executing a workflow step command.
 * If the step already completed (e.g. the command was re-dispatched after a
 * restart), the handler can replay the cached result without re-executing.
 *
 * No authentication required: the step ID is an opaque idempotency key and the
 * reply is confined to the tenant the request names. The engine hands the
 * caller that tenant in the X-Tenant-Id header of the command it dispatched,
 * and the caller echoes it back, so the query stays inside the tenant the step
 * belongs to. A request that names no tenant is answered with found = false,
 * because there is no tenant whose data it could be entitled to.
 */
#+end_src
