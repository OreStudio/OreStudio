* Notes

=history get <entity_type> <entity_id> [--diff] [--version <n>]= is the shell's
history surface for every entity, not for this component's own records. It sends
=get_entity_history_request= and renders the answer through the diff renderer,
which computes a unified diff between two versions.

That is why it stays and why the operation renders no unit. A generated unit
would send the same request and print the reply as JSON, so it would be a second
command for one read and the diff would be lost. The reason is the same shape as
dq's =bundles publish=: the hand-written verb does something the reply does not
carry.

No hand-written command reads the component's own tables, because the generic
read is what a client uses.
