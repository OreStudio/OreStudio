* Summary

[[id:E140C8C6-4532-48D9-ABDF-7B81A21C9EE3][Import a portfolio from ORE]] and [[id:65B02BD9-4633-490C-B8A3-F5680067054B][Export a portfolio to ORE]] are workflows: each has several steps and a write that a person must understand before it happens. The prototype draws both. =?mode=export= switches to the export.

* Detail

** Import

Five steps: directory, choices, preview, confirm, result. The first step finds every portfolio file in the directory and below it, lists them, and lets the person choose which to bring in. Folders named in the skip list are not searched, and the step says how many files that skipped. Each file shows the book it becomes, because the import builds portfolios and books from the folders and the person no longer picks one book.

The real import has no choice of files. It brings in every file the scan finds, and takes only the folders to skip, the parent portfolio, the re-import mode and the trade defaults. The file list is the change this prototype argues for. The journey lists it as missing, with the missing operation that lists the files.

The preview is the plan. It lists every trade of the chosen files, says which counterparty names match no alias and which trade types have no instrument table, and offers a default counterparty as the way out. The result says what was refused and why, and offers the rollback. A rollback removes the trades the import created, and the prototype keeps them in the browser so that they appear on the trade list.

** Export

The person chooses a book or the trades chosen in the list, and chooses a file or storage for a run. The check names the trades the file cannot hold (a draft, a cancelled trade, a trade type with no instrument table) before it is made. The result shows the beginning of the file.

** What is fake

The file never leaves the browser. The upload path of a browser is not defined: the journey names it as missing.
