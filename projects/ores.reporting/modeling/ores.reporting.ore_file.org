#+title: ores.reporting.ore_file
#+description: Codegen entity model for the reporting ore_file table. A file of an ORE run, as the ORE user guide identifies it.
#+type: ores.codegen.entity

#+brief: A file of an ORE run, as the ORE user guide identifies it.
#+entity_singular: ore_file
#+entity_plural: ore_files
#+entity_title: ORE File
#+created: 2026-11-02
#+updated: 2026-11-02

Reference data naming the files an ORE run reads and writes, one row for each
file as the ORE user guide identifies it: the market data, the fixing history, the
NPV report, the NPV cube. The code is the guide's name for the file, so it says
what the file is and not what a run happened to call it.

A file is not a parameter. Several parameters may name the same file: the NPV
cube is written by the cubeFile of simulation and read by the cubeFile of xva and
pfe. Each of those is a file type, and each file type names its file by this
code. A file no parameter names, such as the master input ore.xml or the log, is
still a file.

The table recognises a file by its name. The typical name is the name ORE gives
the file when nothing says otherwise, and the name ORE Studio writes when a run
has one file of the kind. The regular expression matches every name a run may
give it, so a file a run wrote can be told apart without knowing which parameter
named it.

The table describes files. It does not hold the content of a file.

** guide_section
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

The label of the section of the ORE user guide that describes the file, for
example sec:market_data. Nothing when the guide has no section for it.

** origin
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:END:

Where the file comes from in a run: supplied when the run is given it, produced
when ORE writes it, packaged when ORE Studio makes it to carry a run to the engine
and back. A file one analytic produces and another reads is produced; the file
types of the two parameters say which reads and which writes.

#+begin_src cpp :name generator
std::string("supplied")
#+end_src

** format
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:END:

The format of the file: xml, csv, csv_gz for a compressed csv, txt, dat for a
binary file, json, json_gz for a compressed json, tar_gz for a compressed
archive of other files, or xsd for an XML schema. An xml file is validated
against the schema schema_ore_file_code names.

#+begin_src cpp :name generator
std::string("csv")
#+end_src

** schema_ore_file_code
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

For an xml file, the ORE file of the XSD that declares its root element, for
example conventions_schema for the conventions. The schema is itself an ORE file,
so its contents can be read for each engine version. Nothing for a file that is
not xml, or an xml file that ORE publishes no schema for.

** typical_filename
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:END:

The name ORE gives the file when nothing names it otherwise, and the name ORE
Studio writes when a run has one file of the kind: npv.csv, cube.csv.gz. For a
file a run writes once for each trade or netting set, an example of such a name.

#+begin_src cpp :name generator
std::string(faker::word::noun()) + ".csv"
#+end_src

** filename_regex
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:END:

The regular expression every name a run gives the file matches, anchored at both
ends: ^npv\.csv$, ^exposure_trade_.+\.csv$. No name a run writes matches two files.

#+begin_src cpp :name generator
std::string("^.+\\.csv$")
#+end_src

:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:END:

What the file holds and what a run does with it, for a reader who has never seen
an ORE run.

** display_order
:PROPERTIES:

:nullable: false

The order the file appears in a list.

Domain constraints beyond the standard temporal, natural-key and nil-uuid
checks the template emits on its own.

| "format" in ('xml', 'xsd', 'csv', 'csv_gz', 'txt', 'dat', 'json', 'json_gz', 'tar_gz') |

| "typical_filename" ~ '^[A-Za-z0-9_.-]+$' |
| "filename_regex" ~ '^\^.*\$$' |
| "typical_filename" ~ "filename_regex" |
