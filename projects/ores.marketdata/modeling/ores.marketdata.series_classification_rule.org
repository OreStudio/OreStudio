#+title: ores.marketdata.series_classification_rule
#+description: The taxonomy rule for one oresmd identity -- a datum keyed by instrument and quote, or an index keyed by family -- and the asset classes and series subclass it maps onto.
#+type: ores.codegen.entity
#+component: marketdata
#+filetags: :model:entity:marketdata:
#+entity_singular: series_classification_rule
#+entity_plural: series_classification_rules
#+entity_title: Series Classification Rule
#+brief: How one oresmd identity maps onto the refdata asset class and series subclass codes.
#+created: 2026-09-18
#+updated: 2026-10-29

The taxonomy rule for a market series, one row per identity the runtime
classifies. The runtime reads the whole table once, builds a classifier from it,
and asks that classifier for the asset classes and the series subclass of every
series it creates.

The table replaces a compiled C++ map, so the taxonomy is managed like every
other catalogue: an instrument a corpus adds later, or one a user brings, is an
inserted row rather than a rebuild. This matters because an ingest that cannot
classify a series it must create aborts on it, so a compiled table makes every
new instrument a code change.

The key is the oresmd identity and not an ORE key. Two kinds of identity reach
this table, and =key_kind= says which a row is keyed by:

- =datum=, keyed by =instrument= -- the text the URI writes under
  =instrument=, such as =ir_swap= or =discount= -- and by =quote=, the text it
  writes under =quote=, or the empty string for a rule that applies to every
  quote of its instrument. Most instruments classify the same way whatever their
  quote carries, so their row holds the empty string; a lookup tries the exact
  quote first and falls back to the empty one.
- =index=, keyed by =instrument= too, which for this kind holds the index
  family's oresmd name or the empty string for every family. A fixing series is
  an index and not a datum, so it is keyed by the index's own vocabulary.

=asset_class_source= says where a row's classes come from:

- =literal= names its class in =asset_class_code=.
- =correlation_operands= reads the classes from the two operand fields of a
  correlation datum, because a pairwise correlation belongs to the two classes
  it relates and to no class of its own.
- =index_authority= reads the class from the index family's schema row, whose
  asset authority names the market-data namespace the index is written in, and
  =ores.refdata.asset_class_catalogue= maps that authority onto a refdata class.
  One row serves every index family, and a family the catalogue maps to no class
  leaves the class list empty rather than mis-classing the series.

The class codes name rows in =refdata.asset_class_code= and the subclass codes
name rows in =refdata.series_subclass_code=, and the insert trigger checks both
against those catalogues.

The reader rejects an empty table, because an empty table aborts the first
ingest that reads it and the message should name the table rather than the first
series it met.

* Columns

** instrument
:PROPERTIES:
:type:              text
:cpp_type:          std::string
:primary_key:       true
:skip_empty_check:  true
:END:

The identity's instrument, as the URI writes it under =instrument=, in lower
case: =ir_swap=, =discount=, =correlation= for a datum; the index family's name
such as =ibor= for an index, or the empty string for a rule that speaks for
every family. An empty instrument is the one honest "any" this table states, and
only an =index= row uses it: a datum's identity always names its instrument.

#+begin_src cpp :name generator
std::string("ir_swap")
#+end_src

** quote
:PROPERTIES:
:type:              text
:cpp_type:          std::string
:primary_key:       true
:default:           ''
:skip_empty_check:  true
:END:

The identity's quote, as the URI writes it under =quote=, in lower case, or the
empty string for a rule that applies to every quote of its instrument. An index
has no quote and holds the empty string.

A lookup tries the exact quote first and falls back to the empty one.

#+begin_src cpp :name generator
std::string("rate")
#+end_src

** key_kind
:PROPERTIES:
:type:        text
:cpp_type:    std::string
:primary_key: true
:END:

Which kind of oresmd identity this rule is keyed by: =datum= for a market datum
and =index= for a market index, which is what a fixing series is.

Examples: 'datum', 'index'.

#+begin_src cpp :name generator
std::string("datum")
#+end_src

** asset_class_source
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:default:  'literal'
:END:

How this rule obtains its asset classes: =literal=, =correlation_operands=
or =index_authority=.

A literal rule names its class in =asset_class_code=. A correlation rule reads
the classes from the two operand fields of the datum, because a pairwise
correlation belongs to the two classes it relates and to no class of its own.
An =index_authority= rule reads the class from the index family's own schema
row: one =index= row serves every family, and the class cannot be a literal
because the corpus carries rates, equity, commodity, power, inflation, security
and generic fixings alike.

#+begin_src cpp :name generator
std::string("literal")
#+end_src

** asset_class_code
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

Code of the asset class this type measures, from
=refdata.asset_class_code=.

Null on a correlation rule, which names no class of its own, and on a
rule whose classes come from the key. The column is nullable rather
than empty because null is the honest "no class here", and the insert
trigger validates a code only where one is set.

#+begin_src cpp :name generator
[idx]{
    constexpr auto count = sizeof(domain::asset_class_codes) /
                           sizeof(domain::asset_class_codes[0]);
    return std::string(domain::asset_class_codes[static_cast<std::size_t>(idx) % count]);
}()
#+end_src

** series_subclass_code
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:END:

Code of the series subclass this type belongs to, from
=refdata.series_subclass_code=.

Example: 'spot' for FX, 'index_fixing' for FIXING, 'correlation' for
CORRELATION.

#+begin_src cpp :name generator
[idx]{
    static constexpr std::string_view subclasses[] = {
        "spot",    "forward", "volatility", "yield",       "basis",
        "fra",     "xccy",    "spread",     "index_credit", "recovery",
        "swap",    "capfloor", "seasonality", "price",     "correlation",
        "prepayment", "transition_probability", "index_fixing"};
    return std::string(subclasses[static_cast<std::size_t>(idx) % std::size(subclasses)]);
}()
#+end_src

** description
:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: false
:END:

Why the identity carries this taxonomy, and the evidence behind it.

Example: 'The two operands of a correlation datum name the classes it
relates; the subclass is the correlation itself.'
