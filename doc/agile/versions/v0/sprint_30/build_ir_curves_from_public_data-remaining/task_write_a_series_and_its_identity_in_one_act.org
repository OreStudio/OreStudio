* Goal

A series write the identity shape refuses stores nothing at all: the projection is taken first and written once the series is in, so a reader never meets a series whose identity is missing.

* Acceptance

- The repository template pastes a block before the generated write, and the market series model states the projection there.
- A write the shape refuses leaves the series row count unchanged.
- A write that is not refused stores the series and its identity in that order, and a batch does the same.

* Plan

The projection hook in =cpp_domain_type_repository.cpp.mustache= pastes at the end of
the generated write, after the row is stored, so a projection that refuses the row has
already written the series. A run of the core suite that refused eight fixtures left
sixteen series with no identity row: readable by the series repository, invisible to
every identity reader.

The template already pastes before-write blocks for =insert= and none for =write=, so
the seam has to be added: two paste points, one before the single-value write and one
before the batch write, registered in the entity meta model and the paste-block table.
The market series model then states the projection in the new block, =rows_of= builds
the rows and refuses them before anything is stored, and the existing after-write
block writes them.

Writers that hold a =unit_of_work= today already lose the series when the projection
throws, because the throw unwinds the transaction. The ingest path and the tests do
not, which is where the residue came from.

* Notes

The single write applied the claim twice in the template, once in each
=current_state= branch, with the same statement. It is now applied once above
the branches, which the new paste point needs: the block reads =t= whichever
branch follows. =compass diff= confirms no other generated repository changes.

=project= no longer writes and no longer counts the URIs neither codec reads: no
caller read that count. The rows it returns are written by =write= once the
series is stored.

A caller without a transaction can still store a series whose identity write
then fails for a database reason, such as a lost connection. The task closes the
refusal path, which the acceptance names. The database path needs the caller's
transaction and is not changed here.

The red-first run of the two refusal cases on the old code was not taken: the
machine was overloaded and the build that would have produced it was stopped.
The old code stored the series before it projected, and the write commits on its
own without a transaction, so both cases would see a stored series.

The ER diagrams =ores_schema.iam.puml= and =ores_schema.dq_datasets.puml= were
regenerated after the rebase. Main changed the dq bundle notes and did not
regenerate them.

* Result

A series write the identity shape refuses now stores nothing, with or without a
transaction. The repository template pastes a block after the claim is applied
and before the row is written, in the single and the batch write. The market
series model takes the projection there and writes the identity rows after the
series. =market_series_identity_projector= splits into =project=, which checks
and writes nothing, and =write=.

All three acceptance points are met. Three repository cases prove them: a refused
series stores nothing, a batch with a refused series stores none of its series,
and an accepted batch stores each series and its identity. The market data core
suite passes: 396 cases with the services stopped, and the 60 cases that need
NATS with the services started.
