#+title: Task: Add a generic shared-domain fallback tier to environment_mapper_factory
#+description: Extend environment_mapper_factory so that, after the per-app ORES_APP_* prefix check fails, it also matches against a set of registered "shared domain" prefixes (e.g. NATS) -- generically, by prefix-strip-and-kebab-case, the same transform already used for the per-app tier -- not a fixed list of specific variable names. A config module (e.g. nats_configuration) declares itself a shared domain once; every option it registers, present or future, then reaches every service via .env alone, with zero argv threading. NATS is the first domain to register; the mechanism must not name NATS anywhere in environment_mapper_factory itself, so the next shared domain (telemetry, logging, ...) is a one-line registration, not new mapper code.

* Goal

A generic shared-domain fallback tier in environment_mapper_factory, with NATS
registered as its first shared domain: every service picks up a new fleet-wide
ORES_NATS_* knob straight from .env, without any CLI argv threading -- and
registering a second shared domain later requires no changes to
environment_mapper_factory itself.

* Acceptance

- A new ores.utility component, shared_domain_registry, exposes register_domain(prefix) and domains() (Meyer's-singleton-backed, no static-init-order dependency -- registration happens via an explicit bootstrap call at each service's parser setup, not global static construction).
- environment_mapper_factory::make_mapper's fallback tier consults shared_domain_registry::domains() generically (prefix-strip-and-kebab-case, the same transform as the per-app tier) -- no per-variable-name logic and no mention of NATS anywhere in environment_mapper_factory or shared_domain_registry.
- nats_configuration exposes register_shared_domain() (calls shared_domain_registry::register_domain("NATS")); every service's parser.cpp calls it once before parsing, covering nats-url, nats-subject-prefix, nats-wire-format, nats-tls-ca (nats-tls-cert/nats-tls-key stay excluded/per-service -- genuinely per-service file paths, not shared values).
- Unit tests cover: shared_domain_registry registers/lists domains idempotently; environment_mapper_factory's per-app prefix still wins when both tiers match; shared-domain fallback resolves any ORES_<DOMAIN>_* option generically for a registered domain; an ORES_<DOMAIN>_* var for an unregistered domain still returns empty; a second, hypothetical shared domain can be registered and resolved without touching environment_mapper_factory's implementation.

* Plan

- Added ores::utility::program_options::shared_domain_registry (new
  ores.utility component): register_domain(prefix) / domains(), backed by
  a function-local static set (Meyer's singleton) -- no static-init-order
  dependency, since registration happens via an explicit call, not a
  global constructor.
- Extended environment_mapper_factory::make_mapper's returned lambda: try
  the per-app ORES_<APP>_* prefix first (unchanged behaviour, still wins);
  if that fails, loop over shared_domain_registry::domains() and try
  ORES_<DOMAIN>_* generically, using the same prefix-strip-and-kebab-case
  transform. No domain name (NATS or otherwise) appears in this file.
- Added nats_configuration::register_shared_domain(), which calls
  shared_domain_registry::register_domain("NATS"). Wired a call to it
  into all 20 parser.cpp files that build a nats_configuration options
  block (17 near-identical domain-service parsers via a scripted edit,
  plus ores.wt.service, ores.http.server, and ores.shell handled
  individually due to their differently-named local variables), right
  next to where each already calls
  nats_configuration::make_options_description().
- Added two new unit test files under ores.utility/tests: one exercising
  environment_mapper_factory's two-tier resolution (app prefix wins,
  shared-domain fallback resolves generically, unregistered domains stay
  empty, a second hypothetical domain works with zero mapper changes),
  one exercising shared_domain_registry's idempotent registration.
- Regenerated component_files.cmake everywhere via
  regenerate_cmake_component_files.py --all (also picked up unrelated
  pre-existing drift across the tree).
- Verified: `ores.utility.tests` full suite green (471 assertions/139
  cases); a full `compass build` (all targets, including every touched
  service) completes at 100% with no errors.
- Noted while implementing: this leaves ORES_NATS_WIRE_FORMAT genuinely
  redundant in .env going forward for services that don't need a
  per-service override -- task 3 (strip redundant CLI-arg threading) is
  the follow-on that actually removes the now-unnecessary argv threading
  this task makes possible.

registration, precedence, generic fallback resolution, and a

=ores.utility.tests= green (471/139). Any new =ORES_NATS_*= knob now
reaches every service via =.env= alone -- task 3 will remove the argv
