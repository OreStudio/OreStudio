* Goal

An operator who holds the write permission can set a node of a curve or surface by hand from the evolution screen, with a reason, and clear it again. The screen marks the node as manual, and a later feed write does not undo it.

* Acceptance

- A server operation keys a manual point on a node of a named object, checks the coordinates against the declared shape, and stores the value with the actor, the reason and the commentary.
- A second operation clears the manual point on a node, and the feed value shows again.
- Both operations check =marketdata::market_observations:write=, and a caller who lacks it is refused.
- The BFF routes both for a session, and a refusal reaches the browser as the server's reason.
- The evolution screen offers set and clear on a node for a person who may write, shows a manual node as manual with who set it, and shows the correction at once.

* Decisions

- The node is named by its coordinates in the order the shape declares its axes, the order the reads return them in. The server composes the URI through the codec, so no caller builds one.
- A key is stamped when the server receives it. A node can hold several manual points over time, and clear releases all of them.
- Clear closes the keyed observation row as well as the annex, in one transaction. Releasing the annex alone left the keyed value as the newest row, so it read as quoted until the next feed write.
- Only the series' own party can write to it, because the observation takes the context's party.
- The screen offers the controls from the write permission and always reads the source for such a person, so manual nodes are marked. The server checks the write again.
- Not checked: the handler's permission check has no test, the adjust form has no interaction test, and nothing ran against the live stack. The services could not restart because =.env= is out of date.

* Out of scope

- The spread overlay, a parallel shift or a twist over a segment. It needs its own operation and its own journey step.
- The history of a manual point beyond what the annex already records.
- Approval of a manual correction. That belongs with the publication and approval chain.

* Result

An operator who holds the observation write permission can set a node of a curve or surface by hand from the evolution screen, with a reason and a commentary, and clear it again. Two server operations, two BFF routes and the screen controls ship together, with the repository fix that makes a clear show the feed value again. The marketdata core suite, the BFF curve tests and the web market, access and language tests pass. The live stack was not used. See the decisions for what was not checked.
