#+title: How do I run the instrument_codes commands from the shell?
#+description: Every command the instrument_codes submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:instrument_codes:

This file documents the instrument_codes resource at the shell, one section per command. Every command is a subcommand of =instrument_codes=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 19A8737A-EC0D-559C-9214-636AEF1FA0EB
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
instrument_codes list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.instrument_codes.list=.

#+name: instrument_codes-list
#+begin_src ores-shell :tangle instrument_codes-list.ores :exports none
instrument_codes list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 9C2CDE0E-38AE-59E6-938C-6D09348DADFE
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
instrument_codes get <code>
#+end_example

It is addressed at =refdata.v1.instrument_codes.get=.

#+name: instrument_codes-get
#+begin_src ores-shell :tangle instrument_codes-get.ores :exports none
instrument_codes get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 75CF37F0-076B-5954-8D83-5006E50794D3
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
instrument_codes add <code> <name> <description> <asset_class> <ore_trade_type> <display_order> <curve_role> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.instrument_codes.put=.

#+name: instrument_codes-add
#+begin_src ores-shell :tangle instrument_codes-add.ores :exports none
instrument_codes add __none__ __none__ __none__ __none__ __none__ 0 __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 6CF07CE2-8BC6-57C3-9BD7-41E360DD231B
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
instrument_codes set <code> <name> <description> <asset_class> <ore_trade_type> <display_order> <curve_role> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.instrument_codes.put=.

#+name: instrument_codes-set
#+begin_src ores-shell :tangle instrument_codes-set.ores :exports none
instrument_codes set __none__ __none__ __none__ __none__ __none__ 0 __none__ system.new_record generated_script
#+end_src
