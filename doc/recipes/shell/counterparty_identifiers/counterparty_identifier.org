#+title: How do I run the counterparty_identifiers commands from the shell?
#+description: Every command the counterparty_identifiers submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:counterparty_identifiers:

This file documents the counterparty_identifiers resource at the shell, one section per command. Every command is a subcommand of =counterparty_identifiers=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: E0281D7A-03E1-5A2C-8CB4-73E0B50E6741
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
counterparty_identifiers list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.counterparty_identifiers.list=.

#+name: counterparty_identifiers-list
#+begin_src ores-shell :tangle counterparty_identifiers-list.ores :exports none
counterparty_identifiers list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 16FF5437-C909-5AF3-BDC3-4385C6AC96C6
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
counterparty_identifiers get <id>
#+end_example

It is addressed at =refdata.v1.counterparty_identifiers.get=.

#+name: counterparty_identifiers-get
#+begin_src ores-shell :tangle counterparty_identifiers-get.ores :exports none
counterparty_identifiers get 00000000-0000-0000-0000-000000000000
#+end_src

** =add=
:PROPERTIES:
:ID: 12E04E79-1ECB-57AE-A49A-D2D17A55B8D1
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
counterparty_identifiers add <id> <counterparty_id> <id_scheme> <id_value> <description> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.counterparty_identifiers.put=.

#+name: counterparty_identifiers-add
#+begin_src ores-shell :tangle counterparty_identifiers-add.ores :exports none
counterparty_identifiers add 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 6CC50E85-D7CF-5BA0-AB3D-771778C4EA17
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
counterparty_identifiers set <id> <counterparty_id> <id_scheme> <id_value> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.counterparty_identifiers.put=.
