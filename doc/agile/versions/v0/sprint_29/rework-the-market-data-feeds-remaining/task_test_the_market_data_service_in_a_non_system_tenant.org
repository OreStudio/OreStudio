* Goal

A test that uses the system tenant for its rows cannot hide a tenant visibility defect. The demand and ingest tests create a tenant, give its party a subscription and a route, and read through the policies a service uses.

* Acceptance

- The demand test and the ingest test create their rows in a new tenant.
- A test reads the routes as the marketdata service role and fails if the policy hides them.

* Plan

1. Make the ingest fixture state, and assert, that its tenant is not the
   system tenant.
2. Add a core test that writes a route in the test tenant and reads it from a
   system-tenant session, which must see nothing, and from the owning tenant,
   which must see it.
3. Keep the service-role policy check in the route visibility pgTAP file,
   which already names the role and refuses a system session of another role.

* Result

The tests no longer rely on the system tenant. The ingest fixture asserts its
tenant is not the system tenant before it writes anything, so a test that falls
back to the system tenant fails instead of hiding a visibility defect. A new
core test writes a route in the test tenant and reads it from a system-tenant
session, which returns nothing, and from the owning tenant, which returns it.
The service-role read stays covered by the route visibility pgTAP file, which
names the role and refuses a system session of another role.
