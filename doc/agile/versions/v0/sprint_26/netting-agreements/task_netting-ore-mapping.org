* Acceptance

- A mapper turns a nettingsetdefinitions document into netting sets, CSAs and eligible currencies, and back.
- Every netting set document in ORE's examples round-trips through the entities unchanged.
- A netting set carries ORE's call type and initial margin type through the round trip.

* Plan

- A =netting_set_mapper= in =ores.ore.core=, following the credit
  simulation mapper: =map= returns one list per table (sets, CSAs,
  eligible currencies) and =reverse= rebuilds the document.
- ORE names a set by id alone, so an imported set has no agreement and no
  parties. NettingSetDetails with an agreement type or a legal entity is
  refused, since both must resolve to entities and the mapper has no store;
  no ORE example uses either.
- A set exports as NettingSetDetails when it has a call type or an
  initial margin type, and as a plain NettingSetId otherwise.
- The round trip is checked by serialising the original and the rebuilt
  document with the same binding and comparing the text.

* Result

- =netting_set_mapper= maps a NettingSetDefinitions document to netting
  sets, CSAs and eligible currencies, and back.
- All 99 netting set documents in ORE's examples, holding 191 netting
  sets, round-trip through the entities to the same serialised document.
  The binding keeps the whitespace between CSADetails' elements as mixed
  text; the test checks that it is whitespace before setting it aside.
- NettingSetDetails carries a set's call type and initial margin type
  through the round trip; details naming a legal entity are refused.
- An inactive CSA keeps its terms through the mapping.
- After review: export refuses a half-stated independent amount or margining
  frequency rather than inventing the missing value, and reverse indexes
  CSAs and currencies by key.
- ctest: 89 of 89 binaries passed, =ores.ore.core.tests= with the four
  new cases.
