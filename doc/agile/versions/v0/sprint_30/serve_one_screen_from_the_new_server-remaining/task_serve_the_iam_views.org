* Plan

ores.http already answers the three views at the BFF's addresses, from the
access and tenancy tasks, as hand-assembled answers with no cache policy. This
task meets the four obligations on each, as the synthetic views did.

| View | Address | Computation | Cache policy |
|------+---------+-------------+--------------|
| The bootstrap status | =GET /api/bootstrap= | the IAM answer and two settings a failed read leaves false | =ETag=, revalidated at each read |
| The deployment overview | =GET /api/overview= | a counted list read per status, the first page, the setup runs read once | =ETag=, revalidated at each read |
| The principal's ways to hold | =GET /api/me/ways-to-hold= | the caller's roles and the catalogue | =ETag=, revalidated at each read |

Decisions:

- *Schema.* Each answer is a model type with =wire_fields=, published through
  =response<T>()= and written by the codec. The answer keeps the BFF's bytes but
  one: a tenant with no setup run states no =setup=, where the BFF stated null,
  as the codec leaves out an empty optional. The web schema already reads a
  missing setup as null.
- *Cache policy.* The web client fetches with the browser's default cache, so a
  =max-age= lets the browser skip the server after the caller's own write: the
  setup screen would see bootstrap mode after creating the administrator, and
  the access screen the old ways after a grant. =view_cache_policy= now names
  three modes: not stored, revalidated at each read (=private, no-cache= with
  the =ETag=, so an unchanged view answers 304), and fresh for a while. These
  three views are revalidated, and so is the synthetic folder tree, which a
  folder write changes; the inventory's cache policy for each says so. Only the
  market trace, which no write of the caller changes, stays fresh for 10 s.
- The ways to hold answers no ways when a read fails, as the BFF did, so a test
  drives that route without a service and proves its =ETag= and 304 end to end.
