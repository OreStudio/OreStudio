#+title: How do I run the tenant_statuses commands from the shell?
#+description: Every command the tenant_statuses submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tenant_statuses:

This file documents the tenant_statuses resource at the shell, one section per command. Every command is a subcommand of =tenant_statuses=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 30111FA9-B197-5C1D-8A9E-94A90D4DFD35
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tenant_statuses list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =iam.v1.tenant_statuses.list=.

#+name: tenant_statuses-list
#+begin_src ores-shell :tangle tenant_statuses-list.ores :exports none
tenant_statuses list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 01EDCC1D-56F8-50A6-908F-EE91FC0DAB2C
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
tenant_statuses get <status>
#+end_example

It is addressed at =iam.v1.tenant_statuses.get=.

#+name: tenant_statuses-get
#+begin_src ores-shell :tangle tenant_statuses-get.ores :exports none
tenant_statuses get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: FDB5D6D7-79BF-51E1-ABBC-5D02C0A0800B
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tenant_statuses add <status> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =iam.v1.tenant_statuses.put=.

#+name: tenant_statuses-add
#+begin_src ores-shell :tangle tenant_statuses-add.ores :exports none
tenant_statuses add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 14E0FAF2-55D1-5180-A4DE-630CCCE266BD
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
tenant_statuses set <status> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =iam.v1.tenant_statuses.put=.

#+name: tenant_statuses-set
#+begin_src ores-shell :tangle tenant_statuses-set.ores :exports none
tenant_statuses set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
