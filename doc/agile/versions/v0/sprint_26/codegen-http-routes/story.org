* Result

The gateway's routes generate from the models. A codegen facet,
=ores.cpp.http-route=, projects an entity or an operation model onto a
route unit with a header, an implementation and a test. Three components
are landed, each in its own part beside the hand-written aggregator, and
each with its hand-written route file deleted rather than kept in
parallel: =ores.http.assets= (image, tag, image_tag), =ores.http.refdata=
(currency) and =ores.http.iam= (account, role, permission, session,
login_info, and nineteen operations). Ninety-two routes generate in
total, and the gateway serves 99 endpoints: those 92, the 5 storage and
1 variability routes that stay hand-written, and the server's own
=/api/v1/info=.

The gateway is a protocol gateway. A generated route builds the canonical
request, sends it over NATS and maps the reply to an HTTP response, so it
depends on the target's wire protocol and not on its service library. The
server stopped linking three component libraries.

Security is one declaration and one enforcement point. The route forwards
the caller's bearer token by delegation, so the service's own permission
check governs the real caller, and it states its authentication position
from the model. A route that states neither position cannot be built or
registered, and a gate fails the build if any registered route is silent.
The storage routes were public by omission and are now authenticated.

* Acceptance

- A codegen facet generates a route unit per entity, with a header, an implementation and a test, from the entity's model.
- The generated route speaks the canonical NATS protocol and carries the caller's session, so the service's own permission check governs access.
- Every route that needs a session is behind one by construction, declared in the model rather than by hand at the call site.
- The hand-written route file for ores.assets is deleted, and its endpoints still answer.

* Decisions

| # | Decision | Why |
|---+----------+-----|
| 1 | A generated route reaches its component over NATS, not in process. | It mirrors the shell, so one generator serves both surfaces from the same models, and the gateway stops linking every component's core library. |
| 2 | Security is declared once in the model and enforced once, in the service. | The gateway forwards the caller's bearer token by delegation, so the service's own permission check governs the real caller. Shell and HTTP answer to one check, not two, and the gateway does not re-implement authorization. |
| 3 | A route must state its authentication position, and silence is refused. | =route::requires_auth= defaulted to false, so a route that forgot the call was silently public. Three storage routes were public by omission. =build()= and =add_route()= now throw, naming the method and the pattern. |
| 4 | An operation states =:http_route: true= to become a route; absence means it is not exposed. | Whole-model opt-in exposed the model's entire declared surface, including two public endpoints that never existed: =bootstrap/provision-tenant= and =auth/service-login=. Refusal is the right default for a gateway. |
| 5 | Generated paths are namespaced by component, and the resulting URL changes are accepted. | The models state a NATS subject, not an HTTP path. Measured before deciding: no in-repo client calls the iam or refdata REST paths, because the web UI reaches the backend over NATS. |

* Out of scope

Recorded rather than done, each with its reason:

- =storage= keeps its five routes hand-written. Four are file operations
  on ={bucket}/{key}= and the fifth lists a bucket, so there is no entity
  to generate from.
- =variability= keeps its one route hand-written. It has no models, so it
  has nothing for the facet to read.
- The whole tree build, at the time. It failed on a pre-existing break in
  other components: =ores.trading.core= and =ores.workflow.core= included
  =ores.dq.api/messaging/fsm_protocol.hpp=, which =dd131c388b= split into
  two headers and did not migrate the including sites. Both components
  had active owners, so the repair belonged there, and main has since
  repaired it. No CI job builds the tree, which is how main broke without
  a check noticing.
- The trade and market series export handlers carry the reporting service's token, not the end user's, because the reporting service calls them without delegation. Authorization there is service-level; propagating the caller needs a reporting-side change.
- The compute wrapper has its own HTTP client and holds no JWT, so its storage transfers still receive 401. No credential exists to give it.
- A trailing ={key}= GET shadows the versions path beneath it, so =/roles/{name}= hides =/roles/{name}/versions=. Assets has the same shape with images. Pre-existing and worth its own fix.
- =journey_sign_up.org= still names =POST /api/v1/auth/signup=, which now answers 404. It is a journey document, not a client.
