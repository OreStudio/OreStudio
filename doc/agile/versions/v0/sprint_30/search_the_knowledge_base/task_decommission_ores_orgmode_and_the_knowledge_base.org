* Goal

ORE Studio removes its own org support. Org documents belong to compass, which
every project that uses compass shares; how ORE Studio reads them from compass
is the separate story [[id:7764434E-173B-4006-8A44-8AC453AAC14B][Read the documents from compass]], which waits for compass to release that
support. This task only removes.

What goes is the =ores.orgmode= stack and the knowledge base pipeline this
story built on it (PRs #4998 and #5010): the parser, which predates the story,
the api, core and service parts, the shell commands on them, and everything
from the generated pages file to the index. =@ores/org= in ores.web stays:
the agile browser and the scenario runner use it, and they move to compass in
[[id:7764434E-173B-4006-8A44-8AC453AAC14B][Read the documents from compass]].

* Acceptance

- No C++ in ORE Studio parses org: =ores.orgmode= is gone, group and parts,
  and no target links an =ores.orgmode= library.
- The knowledge base pipeline is gone end to end: the generated pages file, the
  DQ dataset and artefact type, the pages, artefact and index tables, the
  publish and replace functions, the permissions and role, the service, its
  account and its place in the fleet, and the shell commands.
- A database recreate, the fleet start and the full gate pass with none of it.

** Order

1. Remove the models, regenerate, and delete the components and the shell
   part, so the build and the generated files agree.
2. Remove the SQL, the seeds, the page generation and the recreate variable;
   recreate the database.
3. Remove the service from the registry and the fleet; fix the counts.
4. Update the docs, the ER diagram and the logging doc's example.
5. Run the gate.
