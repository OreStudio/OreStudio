* Goal

Every DQ artefact table is generated from the model of the entity it stages, through the domain_entity_artefact_create flag, with an Artefact columns section where the staging shape differs. No ores.dq model duplicates a domain model, no artefact table is hand-written SQL, and a guide states the one way to add a DQ artefact so a new one never starts a second pattern. Junction artefact tables are out of scope.

* Acceptance

- A knowledge page states the one way to add a DQ artefact, the full pipeline from model to published row, and a checklist.
- No ores.dq model duplicates a domain model that exists in another component; the duplicates' DQ C++, shell and TypeScript stacks are deleted.
- No DQ artefact table is hand-written SQL.
- No DQ artefact table comes from the older lookup template.
- Each remaining ores.dq artefact model has a recorded owner decision.

* Decisions

- *A moved table keeps its shape.* The owning model states the old staging
  columns in an =* Artefact columns= section, so a move changes no populate
  or publish function. A table takes the name its owning model gives it, as
  the provider table did.
- *The staging shim gate stays.* No dq shim copies another component's
  entity now, but codegen still drops the shell unit of one that would, and a
  fixture tests it.
