* Result

The tiles draw from the reference, there is one icon set, and the home screen
carries the two labelled runs the review drew.

The glyphs came from the review's set first, and that was wrong. The
application already has an icon system with a written rule — a concept goes
into =ui/Icon.tsx= and into the icon reference before a screen uses it — and
importing a second set quietly broke it. The correction cost less than the
mistake: every concept the tiles needed already had an asset and a reference
entry, so nothing was added and one dependency came out.

The footer arrow the review drew is not carried over. There is no right arrow
in the reference, and the guidelines say an icon that loses no meaning when
removed should be removed: the whole tile is the link, and the hover already
says so.

The two runs are separated by the rule the review used, so a screen with tiles
above and below it reads as two runs and not as one grid with a stray line
through it.
