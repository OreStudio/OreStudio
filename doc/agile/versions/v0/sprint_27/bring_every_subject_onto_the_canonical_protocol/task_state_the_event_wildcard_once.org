* Acceptance

- entity_event_traits offers the wildcard subject beside event_subject(action).
- The integration-test template uses it and no generated file appends a wildcard by hand.

* Plan

=entity_event_traits='s own docstring already says "a subscriber that wants all
three subscribes to the prefix's wildcard", but only =event_subject(action)=
exists, so every caller spells the wildcard itself. Add the sibling the
docstring promises and point the template at it:

1. =event_subject_wildcard<Event>()= returns the prefix with =".>"=.
2. =cpp_nats_integration_test.cpp.mustache= and its archetype page use it
   instead of the concatenation.
3. Regenerate, which rewrites one line in each of the 263 committed
   integration tests.

* Notes

The first =check_component_drift.py --all= regenerated 247 of the 263 and left
16 in =ores.inbox=, =ores.synthetic= and =ores.scheduler=. Those three are not
in =COMPONENTS_UNDER_TEST=, so the drift gate never regenerates them: a template
change reaches every component under test and silently misses every other one
that still generates C++. They were regenerated by hand with =compass codegen
regenerate --component inbox-cpp --address ores.cpp=, and the same for
=synthetic= and =scheduler-cpp=.

That hand regeneration swept 195 unrelated files whose committed output had
drifted from the current templates while no gate was looking. They are reverted
here, because this task is the wildcard and not that backlog. The gate gap is
the real finding: three components generate C++ that nothing checks.

The run also found two more trunk artefacts, both fixed here because they were
blocking this branch and neither is a judgement call:

- =cmake-sources= was red: a rename left =component_files.cmake= listing
  =approval_expiry_sweeper.cpp= after the file became
  =approval_expiry_schedule.cpp=.
- =site-page= was red: the rates design page cites
  =ores.refdata.asset_class_catalogue='s org id in upper case, and the note
  declares it lower case, so the HTML exporter could not resolve the link and
  aborted the page.

* Result

=entity_event_traits= now states the wildcard beside the action, and the
integration-test template uses it. The 263 committed tests that template
generates were rewritten, and no file in the tree appends a wildcard to a
subject prefix by hand any more.

Two things the task exposed, neither of them the wildcard:

- Three components that generate C++ -- =inbox=, =synthetic= and =scheduler= --
  are outside =COMPONENTS_UNDER_TEST=, so the drift gate never regenerates
  them. A template change reaches every component under test and silently
  misses the rest. That is a hole in the gate, not in this change.
- Regenerating those three by hand surfaced 195 files whose committed output
  had drifted from the templates while nothing was checking. They are recorded
  here and left for their own task.

And three things the run found on trunk, all fixed here because they blocked
the branch: a stale cmake file list, an upper-case org id the exporter could
not resolve, and -- in the run before this one -- a stale ER diagram.

That is five trunk artefacts found by two runs of the local gate, none of them
by a person looking. The gate works; the gap is that nothing runs it.
