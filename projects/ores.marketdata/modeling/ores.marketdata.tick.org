#+brief: The value of a coordinate of a stream at an instant; TimescaleDB hypertable partitioned by ts.
#+created: 2026-10-25
#+updated: 2026-10-25

A tick is a value of a coordinate of a stream at an instant. The stream is one
series of one provider, and its id is derived from the provider code and the
series URI, so the ingest writes the ticks of a source once and every party
reads the same rows. The ingest and the history read compute the id with
=datum::stream_id=.

The table has no trigger, no valid_to and one index on the stream, the
coordinate and the time. A correction is a new row, and the reader takes the
latest. There is no notification trigger: the live path publishes the tick, and
the table is the history.

The table belongs to no tenant and no party. Market data is an observation
about a source, so the row carries no owner and no row-level security policy
filters it. The history read checks the party's subscription to the provider of
the series before it reads a row, and that check is the only door to the ticks.
The tables are created by the schema owner and written by the ingest role.

The marketdata tick writer role has INSERT only. It does not own the table and
has no SELECT.

Retention drops whole chunks, so the store holds seven days of ticks. The table
is not compressed. See doc/knowledge/architecture/tick_ingest_pipeline.org.

* Columns

** stream_id
:PROPERTIES:
:type:     uuid
:cpp_type: boost::uuids::uuid
:END:

The stream this tick belongs to, derived from the provider code and the series
URI of the datum. The coordinate table and the index of this table both start
from it.

** source_id
:PROPERTIES:
:type:     uuid
:cpp_type: boost::uuids::uuid
:END:

Reference to =ores_marketdata_market_data_sources_tbl(id)= -- the source that
produced this tick.

** ts
:PROPERTIES:
:type:     timestamp with time zone
:cpp_type: std::chrono::system_clock::time_point
:END:

The instant of the tick, in UTC. Also the hypertable partition column.

** coord
:PROPERTIES:
:type:     smallint
:cpp_type: std::int16_t
:END:

The datum's coordinate: the number the coordinate table gives one datum URI of
this stream.

** value
:PROPERTIES:
:type:     double precision
:cpp_type: double
:END:

The value of the datum at the instant.

The table is not compressed. Retention drops whole chunks, so the store holds
seven days of ticks.

The table carries no row-level security, so it has no policies. A role that the
store grants INSERT writes with COPY, and the service role reads through the
grants the schema gives every marketdata table.

** Indexes

| name               | columns                  | unique | current_only | where_extra |
|--------------------+--------------------------+--------+--------------+-------------|
| stream_coord_ts    | stream_id, coord, ts desc | false  | false        |             |

One index serves the reader that takes the ticks of one stream in a span of
time, a coordinate at a time. The table is not keyed, so the index is the only
structure over it.

* Physical space

No facet beyond the SQL schema renders: the model states =:sql_only: true=.

The table sends no notification. The live tick stream carries each new value, and
a notification for each row would take a database-wide lock at every commit and
tell a client to reload a series that changes faster than the client can read it.
