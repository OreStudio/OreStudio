* What

The system administrator has no screen for the market data feeds. The journey
[[id:986CED57-341F-49DE-8F5D-F186771F10D8][Keep the market data feeds running]]
lists the feed bindings, says whether each source runs, and starts or stops a
feed. The web client has no page and no BFF route for it. The system home shows
it as an upcoming card.

* Why

The subjects the screen needs mostly exist: =marketdata.v1.feed_bindings.list=,
=.get= and =.put=, =synthetic.v1.feed_configs.list= for the running set, and
=synthetic.v1.ops.start_feed=, =.stop_feed=, =marketdata.v1.ops.start_feeds_under_folder=
and =.stop_feeds_under_folder=. The journey records what is missing: no read for
the last tick, no stored source-to-series mapping, no list for the IR generation
configs, and no permission that gates start and stop. Start and stop are
reachable from the shell only.

The first slice is the read-only roster: the bindings joined to the running set.
It needs one BFF route in =operations.ts= and one page under the operations area.
Start, stop and the last tick wait on the server changes the journey names.
