* Result

The shell asks a run's health, and the answer is the service's own.

=report_operations get-run-health <report_instance_id>= is a generated verb. The
operation is declared in =ores.reporting.operations.org= with subject
=reporting.v1.ops.get_run_health=, and the protocol, the shell command unit, its
tests and the shell recipe are generated from it.

The service side is hand-written but asks nothing new. It calls
=report_instance_service::get_report_instance_health=, the read the web already
makes, with the one id, and projects the row onto the one-run answer. A read
that answers no row is a run that does not exist or is not the session's, and
the answer is =missing= rather than an empty word a caller would read as a
state.

Proven from the shell against a triggered package run. Instance =c0922bbf=:
=state_name= completed, =health= completed clean. An id that does not exist
answers =missing= with "The report instance does not exist."
