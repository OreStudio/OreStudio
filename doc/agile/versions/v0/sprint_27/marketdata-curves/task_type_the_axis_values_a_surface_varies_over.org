* Goal

A composite object's axis values carry a typed, validated code rather than free text, so ATM, 25RR and 25BF name one component each however a file spells them, and the components of a surface can be listed by querying the shape.

* Acceptance

- An axis value that is a strike label is stored as a canonical code.
- Two spellings of one component resolve to one value.
- The components of a surface can be listed from the shape, without scanning
  observations.
- The vocabulary and the quoting convention are stated where the codec reads
  them, not repeated at each call site.

* Plan

The axis value vocabulary becomes a typed value on the codec. It does not
become a table.

1. A new value type, =datum::strike_label=, joins =value.hpp=. It holds the
   label's form (ATM, a delta call, a delta put, a risk reversal, a butterfly or
   a level) and its number. =parse= reads the grammar, and it returns the
   canonical spelling of the label.
2. =value_kind::strike_label= joins the kind enum. =kind_of=, =kind_type=,
   =holds_kind=, =parse_value= and =text_of= all handle it. The kind has no
   closed token list, so =codes_of= stays empty for it and the existing
   invariant holds unchanged.
3. =field::strike_label= moves from =value_kind::text= to the new kind. The
   schema then states that the codec checks the field.
4. The two key readers that fill the field, =read_fx= and the correlation
   reader, parse the token through the new type. They no longer store free
   text.
5. The tests cover the parse, the canonical spelling, a refused label, and the
   components of an FX option surface read from the declared shape.
6. No table, no refdata code list, and no shape change.

The decision that this is a codec type and not a table is recorded below,
because the journey that owns the surface framework proposes the other answer.

** The grammar is ORE's allow-list for an FX option quote

=parseStrike= in ORE accepts more forms than an FX option quote may hold.
=FXOptionQuote= refuses any strike whose type is not =DeltaCall=, =DeltaPut=,
=ATM=, =BF=, =RR= or =Absolute= (=marketdatum.hpp:1247-1257=). The new type
accepts exactly that set, so the codec refuses what ORE refuses. =ATMF= and
=25D= are therefore refused: ORE's strike grammar reads them, and its FX option
quote then throws.

** The canonical spelling, and what it does not rewrite

The canonical label fixes the case of the suffix and drops a leading =+=. A
fraction of zeros is dropped, so =25.0RR= and =25RR= are one component. The
digits are otherwise kept as the key wrote them, because rewriting a number is
a change of value and not a change of spelling.

The stored =oresmd_uri= therefore carries the canonical label, and two files
that spell one component differently declare one axis value. Every label in the
seed and in the ORE example corpus is already canonical, so no stored value
moves.

** Why not a reference-data code list

The surface journey proposes one: "No code list or table names =ATM=, =25RR=
or =25BF= ... The candidate is a reference-data strike or delta label list"
(=journey_author-a-surfaces-framework.org:157-160=). Three facts argue against
it here.

- The delta number is open. ORE accepts any number before =RR= and =BF=, so a
  closed list refuses valid market data. That is the defect the import path
  already met with tenors, which is why =series_shape_writer::declare= takes its
  term check as an argument.
- The vocabulary belongs to the grammar ORE's parser runs, which is what
  =codes_of= already holds for every other checked field. A table would be a
  second vocabulary that could disagree with the parser.
- The journey that owns the surface framework, journey 2, is deferred to its
  own story (story.org:912). A table here would pull that story forward.

The quoting convention a label implies, the ATM type and the delta type, is
stated once beside the parser. A per-surface convention is journey 2's work.

* Notes

- The field is shared. =fx_option= and =correlation= both carry
  =strike_label=, and the schema states the kind per field, not per type, so a
  correlation strike is checked by the same grammar. Every correlation point in
  the ORE example corpus writes =ATM=.
- The grammar is narrower than ORE's =parseStrike= and exactly as narrow as
  =FXOptionQuote=. ORE's strike grammar reads =ATMF=, =25D= and =ATM+0.5=, and
  its FX option quote then throws on each. The codec refuses them at the key.
- The seed and the corpus already spell every label canonically, so the change
  writes no stored value differently. The corpus carries five distinct labels:
  =ATM=, =25RR=, =25BF=, =10RR= and =10BF=.
- No table, no refdata code list and no migration. The shape tables and the
  point check are unchanged.
