#+title: How do I run the currency_pair_classifications commands from the shell?
#+description: Every command the currency_pair_classifications submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:currency_pair_classifications:

This file documents the currency_pair_classifications resource at the shell, one section per command. Every command is a subcommand of =currency_pair_classifications=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 2AE0C23D-5F94-5BB8-B311-5D2190ACDFFC
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
currency_pair_classifications list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.currency_pair_classifications.list=.

#+name: currency_pair_classifications-list
#+begin_src ores-shell :tangle currency_pair_classifications-list.ores :exports none
currency_pair_classifications list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: F4CB597E-897A-5D8C-A6DA-E8BFB03B6A1A
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

It is addressed at =refdata.v1.currency_pair_classifications.get=.

#+name: currency_pair_classifications-get
#+begin_src ores-shell :tangle currency_pair_classifications-get.ores :exports none
currency_pair_classifications get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: FE57FDE8-A3B3-505A-803F-A2B07A8C231F
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
currency_pair_classifications add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.currency_pair_classifications.put=.

#+name: currency_pair_classifications-add
#+begin_src ores-shell :tangle currency_pair_classifications-add.ores :exports none
currency_pair_classifications add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: A3B6C906-76A3-5F00-85BD-DC61E2FCD45D
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
currency_pair_classifications set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.currency_pair_classifications.put=.

#+name: currency_pair_classifications-set
#+begin_src ores-shell :tangle currency_pair_classifications-set.ores :exports none

#+end_src
