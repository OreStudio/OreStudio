#+title: How do I run the tags commands from the shell?
#+description: Every command the tags submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tags:

This file documents the tags resource at the shell, one section per command. Every command is a subcommand of =tags=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: ACAEA6BB-EBE4-5EEA-ABA3-B764243B9F13
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tags list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =assets.v1.tags.list=.

#+name: tags-list
#+begin_src ores-shell :tangle tags-list.ores :exports none
tags list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 8800F32B-BF6D-5F80-8E1A-C17FD15BCE72
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
tags get <name>
#+end_example

It is addressed at =assets.v1.tags.get=.

#+name: tags-get
#+begin_src ores-shell :tangle tags-get.ores :exports none
tags get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: A1454DA4-6D77-5188-9BBF-34D3A9B2E58B
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tags add <id> <name> <description> <reason> <commentary>
#+end_example

It is addressed at =assets.v1.tags.put=.

#+name: tags-add
#+begin_src ores-shell :tangle tags-add.ores :exports none
tags add 00000000-0000-0000-0000-000000000000 __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: F37E8037-1BF0-56BF-8A35-E1193D6E7F10
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
tags set <id> <name> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =assets.v1.tags.put=.

#+name: tags-set
#+begin_src ores-shell :tangle tags-set.ores :exports none
tags set 00000000-0000-0000-0000-000000000000 __none__ __none__ system.new_record generated_script
#+end_src
