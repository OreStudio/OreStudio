#+title: Column-list chains exhaust MSVC's template budget in a unity unit
#+description: windows-msvc-release-ninja fails C1202 in 11 ores.trading.core unity units, not only at trade_entity.hpp:95. In one translation unit MSVC fails at the first column-list operator| call past the 1,025th whose result has 18 or more bindings. Generating columns() as one variadic make_columns call never fails in the probes, so one codegen change fixes all 11.

* What

The nightly of 2026-11-19 (run 44485188155, head =e866b76f3e=) failed in
=windows-msvc-release-ninja= with =fatal error C1202: recursive type or
function dependency context too complex= at =trade_entity.hpp:95=, the
trade entity's =columns()= chain, in =ores.trading.core= unity unit 55.
The MSVC job built units 66 down to 55 and stopped there; only the clang
job compiled the lower units.

compass's MSVC probes (run 44607561767; MSVC 14.51 with ORE's release
flags) fit one rule, the only fit, which predicts all 337 chain probes
exactly, including ORE's own entity headers:

- In one translation unit, count every column-list =operator|= call,
  across every entity's =columns()= chain, in include order.
- The 1,026th call and every call after it are past the budget.
- MSVC fails with C1202 at the first call past the budget whose result
  has 18 or more bindings.
- Chains of 17 or fewer bindings never fail, however late they come,
  and field lists (=wire_fields=) never fail.

At =e866b76f3e= the rule predicts 11 failing =ores.trading.core= units:

| Unit | Entity it fails on |
|------+--------------------|
| 55 | =trade_entity=, at binding 18 after 1,197 calls |
| 53 | =fx_strike_resettable_option_instrument_entity= |
| 50 | =fx_variance_swap_instrument_entity= |
| 48 | =fx_variance_swap_instrument_entity= |
| 46 | =fx_window_barrier_option_instrument_entity= |
| 44 | =instrument_barrier_entity= |
| 43 | =index_credit_default_swap_instrument_entity= |
| 38 | =equity_outperformance_option_instrument_entity= |
| 36 | =equity_cliquet_option_instrument_entity= |
| 34 | =credit_default_swap_instrument_entity= |
| 29 | =fx_window_barrier_option_instrument_entity= |

Other components' units are not computed yet; the compass check being
built will compute them.

The fix is confirmed. With column lists built in one variadic call,
=make_columns<e>(key(...), bind(...)...)= returning
=column_list<Bindings...>{{{bindings}...}}=, no probe failed: units 53
and 55 as they are, 120 or 480 entities of width 20, 60 of width 75 and
240 of width 40. The change is to the codegen template that emits
=columns()=, plus =make_columns= in =columns.hpp=. compass's version is
=build/probes/msvc_c1202/flat_columns.hpp=. Smaller unity batches would
only move the failures.

* Why

The failure is on MSVC release alone; the Linux and Windows clang legs
compile the same tree. No MSVC Windows artefact can be built while it
stands, and every entity a model adds spends more of each unit's budget.
