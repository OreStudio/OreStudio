* Acceptance

- The grid screen shows the depth and the oldest wait.
- The over-capacity warning uses the oldest wait.

* Plan

- The usage read already counts the waiting results of each group. It now also returns the wait of the oldest one, in seconds, counted from the time the result was queued (=oldest_unsent_seconds=).
- The read keeps its scope. A tenant administrator gets one row for each party. An operator gets one row for each tenant, read by entering the tenant, and a tenant's wait is the longest wait of its parties.
- The Usage tab shows the wait as a column, and warns from the age. The warning is a caution at half the limit that a job can wait (30 minutes) and an error at the limit (60 minutes), because a storage token of a job lives one hour.
- A result that the reaper returned to the queue stays in progress in the results, so the count of waiting results does not include it until its next claim. The ledger holds it, and the tenant cannot read the ledger.
- The warning on the Load tab stays an estimate from the rate. The usage read enters every tenant and the server records each entry, so the Load tab does not poll it.
