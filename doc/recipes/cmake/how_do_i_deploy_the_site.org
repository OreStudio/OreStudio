#+title: How do I deploy the site?
#+description: Build the ORE Studio website locally: `compass site page` to rebuild the pages you have just edited in about a second, and `compass build --direct site` for a full publish.

#+level: cross
#+filetags: :cmake:build:site:website:emacs:compass:recipe:

For the build script that does the work ([[proj:projects/ores.lisp/src/ores-build-site.el][=projects/ores.lisp/src/ores-build-site.el=]]) and the
output location, see [[id:5AAE6900-8488-4E22-9F31-A1B9D5320EFB][CMake setup]].

* Question

How do I build the ORE Studio website locally?

* Answer

There are two commands, and which you want depends on whether you are
editing documents or preparing to commit.

** While editing: rebuild what you changed

=compass site page= publishes every page whose source is newer than its
published HTML, in about a second each:

#+begin_src sh :results verbatim
./compass.sh site page
#+end_src

Name files to rebuild them whether or not they have changed, which is
what you want when the rendering rather than the source has moved:

#+begin_src sh :results verbatim
./compass.sh site page doc/llm/skills/skill_architecture.org
#+end_src

This reuses the publish cache the last full build wrote, which is where
the speed comes from. It rebuilds the identifier map first, so a page
linking to a document added since the last full build still resolves.
That scan takes about three seconds; skip it with =--no-index= when
nothing has been added, renamed or deleted:

#+begin_src sh :results verbatim
./compass.sh site page --no-index
#+end_src

** Before committing: publish everything

#+begin_src sh :results verbatim
./compass.sh build --direct site
#+end_src

=--direct= mode calls Emacs directly, with no cmake and no vcpkg, so it
works in a light environment. It invokes
[[proj:projects/ores.lisp/src/ores-build-site.el][=projects/ores.lisp/src/ores-build-site.el=]], which rebuilds the
identifier map, syncs the org-roam database, and publishes every =.org=
file in the repository (excluding =.packages=, =vcpkg=, =build=) to
HTML. Output lands at =build/output/site/=.

This is the run that proves the published site holds together, since it
is the only one that reads every file. It takes minutes rather than
seconds, which is why the fast path above exists.

In a full environment the equivalent =deploy_site= CMake target runs the
same script; for the raw CMake build (presets, targets, =cmake --build=
directly) see [[id:F176FCA1-68D5-420D-B076-75A65FEE5EBB][How do I build the system?]].

** Previewing locally

The site uses absolute =/OreStudio/= paths (matching GitHub Pages).
Use compass to preview with the correct URL structure:

#+begin_src sh :results verbatim
./compass.sh site serve
#+end_src

Then open =http://localhost:<ORES_SITE_PORT>/OreStudio/= in a browser (port from =.env=; default =51004= for local1).

To rebuild and serve in one step:

#+begin_src sh :results verbatim
./compass.sh site serve --compile
#+end_src

Use =--port N= to override the port.

** Prerequisites

- Emacs on PATH. The script uses =org-publish=, =org-id=, and =oc-bibtex=
  from a default Emacs install with =org-mode= shipped.
- =--direct= needs no preset or build directory. (The full-environment
  =compass build site= / =deploy_site= cmake path does: a =.env= with
  =ORES_PRESET= set, configured automatically on first build.)

** When to run which

Run the full build before committing, and whenever a change affects how
other pages render rather than only their own content. =compass site
page= now rebuilds the identifier map itself, so a new =.org= file or a
changed =:ID:= no longer forces a full build.

*** Rebuilding the identifier map on its own

=.org-id-locations-file= maps each =:ID:= to the file holding it, and is
what turns an =[[id:UUID]]= link into a path at publish time. Both site
commands rebuild it, as do the manual, help, skills and plan builds. To
rebuild it alone:

#+begin_src sh :results verbatim
./compass.sh index --org-ids
#+end_src

It is distinct from =compass index=, which builds the search index, and
from =compass index --org-roam-db-sync=, which syncs =.org-roam.db=.

*** Deleted pages are not removed

Neither command deletes a published page whose source has gone. A
renamed or retired document keeps serving its old content from the
previous build until the file is removed by hand, as in:

#+begin_src sh :results verbatim
rm build/output/site/OreStudio/doc/llm/skills/skill_planes.html
#+end_src

This matters more than an ordinary stale file, because a reader
following an old link reaches a page describing a state that no longer
exists. A sweep that removes built output with no source is tracked as
a backlog capture.

* Script

[[proj:projects/ores.lisp/src/ores-build-site.el][=projects/ores.lisp/src/ores-build-site.el=]] is the Emacs script that =compass build --direct
site= runs. [[proj:projects/ores.lisp/src/ores-build-page.el][=projects/ores.lisp/src/ores-build-page.el=]] is the script behind
=compass site page=: it loads the site script's configuration, stops before its
work, and publishes only the files it is given.
[[proj:projects/ores.lisp/src/ores-org-ids.el][=projects/ores.lisp/src/ores-org-ids.el=]] holds the identifier scan and the
directories it excludes, shared by every build that resolves an =id:= link. The equivalent =deploy_site= CMake target definition lives in
=CMakeLists.txt= near =add_custom_target(deploy_site ...)= and invokes the
same script.

* Tested by

The =build-site.yml= GitHub Action publishes the site on every push to
=main=. The action's success is the integration test for this recipe.
