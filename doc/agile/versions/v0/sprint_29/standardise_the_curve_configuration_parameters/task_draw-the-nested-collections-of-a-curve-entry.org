* Acceptance

- A curve that holds segments draws one card per segment, naming the kind the row states, with the leaves the contract documents for that kind.
- A segment leaf the contract does not document shows its ORE name and is marked as a gap, as the standard requires of an entry's leaf.
- A leaf's path carries the kind the row states, because the contract keys the same column under a different kind's element.
- A row that belongs to another curve is not drawn with this one.
- The block badge row no longer names a block the page draws rows of, so nothing is said twice.
- Reading a collection holds no table that names a segment's leaves: the contract is the only source of them.

* Plan

The limit that shaped this. The generated section wiring covers an entry's own
table, where a column sits at a fixed path. A segment does not: the same column
is =Segments/Simple/ProjectionCurve= for a simple segment and
=Segments/AverageOIS/ProjectionCurve= for an average OIS one, so the path depends
on the kind the row states, and the wiring cannot express it. This task therefore
states the collection rules in the BFF — the element, the table, the vector, the
column that joins a row to its entry and the column that names its kind — and
resolves each leaf's path from the kind. Making the generator derive those rules
from the projection is the follow-up that removes the last hand-written table.

1. *Read the rows.* The document already carries its segments; the BFF filters
   them to the entry's and orders them as the document writes them.
2. *Name each leaf.* The column is the projection's member, and the projection
   names each element as the member's words in camel case, so the leaf's ORE name
   follows from the column and its path from the kind. A column the contract has
   no row for keeps its name on screen and shows as a gap, because a gap in the
   data must be visible.
3. *Draw them.* One card per segment under the parameters, its leaves in the same
   row as an entry's, with the same documentation under them. The block badge row
   drops a block the cards draw, so the page does not say it twice.

Editing stays out. The standard changes a collection in a dialog per row, and the
save path already takes the entity, the row and the column a dialog would send.

* Notes

- *A collection's path is not an entry's path.* That is the whole reason the
  wiring stops at the entry: a leaf's xpath depends on the kind the row states.
  The rules live in the BFF until the generator can read them out of
  =import_segments=, which reads each kind in its own loop.
- *Quotes are not leaves of the same shape.* A quote's value is the =Quote=
  element's own text, not a named child element, and its list element varies by
  segment kind. Drawing them wants its own decision, so they stay badges for now.
- *The gap rule holds.* =PillarChoice= is a segment leaf with no contract row, and
  it draws with its ORE name and counts as a gap, as an entry's leaf does.

* Result

* Result

A curve that holds segments draws them. Each segment is a card under the curve's
parameters, naming the kind the row states, with the leaves the contract
documents for that kind in the same row, at the same documentation depth, as the
curve's own leaves. The badge row no longer repeats a block the cards draw.

What the work turned on: a segment's leaves do not sit at a fixed path. The same
column is one leaf for a simple segment and another for an average OIS one, so
the path follows the kind the row states, which the generated wiring cannot
express. The BFF states the collection rules and resolves each leaf under its
kind; a leaf the contract does not hold keeps its name and counts as a gap.

Verified by the suites, not by the browser: 1144 BFF tests and 2331 browser
tests pass, and both packages typecheck. The environment runs the published
build, so seeing the cards needs a rebuild, which this change does not do.

The rest of the collection work is three slices, recorded in the review: generate
the rules from the projection, draw a segment's quotes, and draw its role curves.
