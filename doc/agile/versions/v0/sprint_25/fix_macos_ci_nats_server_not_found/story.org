#+title: Story: Hotfix: macOS CI fails to start NATS server, nats-server not installed
#+description: Continuous MacOS CI aborts at the Start NATS server step: the nats-server binary is only installed inside the Run CTest workflow step (brew install autoconf automake libtool autoconf-archive nats-server), which runs after the step that launches it, so the launch emits command not found and the 30s readiness poll fails. Linux CI installs it via compass env install-packages and Windows CI downloads a GitHub release (v2.10.24) -- three platforms, three sources, three versions. Introduced by commit 41a07950e which added the Start NATS server step to all four workflows. Fix: every CI workflow gets an identical Setup NATS server step running the shared build/scripts/setup_nats_server.sh (PowerShell equivalent setup_nats_server.ps1 on Windows), which unpacks the vendored nats-server v2.14.3 release (external/nats/packages) and puts it on PATH -- one pinned binary on every platform instead of apt/brew/GitHub-download.

* Goal

Every CI platform (Linux, macOS, Windows) must launch NATS from the same pinned nats-server binary -- the vendored v2.14.3 release under external/nats/packages -- installed by an identical Setup NATS server step before the Start NATS server step, so the macOS command-not-found failure is fixed and every platform exercises the same version.

* Acceptance

- Every CI workflow (continuous-linux, continuous-macos, continuous-windows, nightly-linux) has a Setup NATS server step before the Start NATS server step
- The step unpacks the vendored nats-server v2.14.3 release for the platform and puts it on PATH (setup_nats_server.sh; setup_nats_server.ps1 on Windows)
- The platform-specific NATS installs are gone: nats-server removed from the macOS CTest step brew list, the GitHub-release download removed from Windows CI
- The Start NATS server step resolves the binary without command not found
