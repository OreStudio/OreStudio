* Goal

A reader of a run's errors can tell where each one came from: the run's own preprocessing, the engine, or the postprocessing of its results.

* Acceptance

- A recorded error states its phase alongside its scope, and the phase is one of preprocessing, engine or postprocessing.
- Every writer of an error states its phase: the workflow steps, the engine error reader and the results ingester.
- A read groups a run's errors by phase and answers the count of each.

* Plan

- The phase is data, not an enum in code: a lookup table with the three rows
  the story names, seeded, as the error scope already is. A phase the run
  cannot state is then a row nobody seeds rather than a value nobody compiled.
- =report_error_event= gains =phase_code= beside =scope_code=, and the model
  states why the scope stays the engine's own group name: the two answer
  different questions, and folding one into the other would make the engine's
  words mean something the engine never said.
- One recorder writes every error a run holds, so it is the one place that
  states the phase. Each caller names it: the engine log reader states engine,
  the results ingester states postprocessing, and a workflow step that refuses
  its work states preprocessing.
- The compensation that fails the report is dispatched by the failing step, so
  the phase travels with that command rather than being guessed at the far end.
- A read answers a run's count of errors per phase, so a screen can open the
  errors of one phase without reading them all.

* Measurements

Every number this task claims about a tree, with the command that produced it
and the commit it was measured at. A number without both is not a measurement,
because a clean-up record describes a tree and trunk moves under a branch: a
consumer count, a gate's component count and a suite's size all change with no
code changing, and the reader of a bare number cannot tell which tree it came
from. Where the raw output matters, put it in an =evidence/= file beside the
task and name that file in the Command column.
