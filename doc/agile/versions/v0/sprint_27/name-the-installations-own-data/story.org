* Goal

The installation owns a class of data the schema does not name: the facts about the deployment itself. This story names it, gives it the policy shape it wants, and moves the Operations reads onto it, so a read of the fleet is honest rather than a workaround. It adds no security exception and no tenant parameter.

* Acceptance

- The codegen can express installation-scoped data, so a model declares its owner instead of hand-writing a policy.
- The samples, the roster, the logs, the bus and the versions carry the installation's policy shape and are read whole by a session the permission admits.
- The Operations grid reads the fleet whole under compute::grid_samples:read, and every claim it makes about the work counts is true.
- Installation-wide work totals are either built on the audit's token exchange or stated on the screen as out of reach, with the capture that records it.
