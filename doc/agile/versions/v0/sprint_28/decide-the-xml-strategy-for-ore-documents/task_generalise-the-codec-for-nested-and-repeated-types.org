* Goal

Teach the table engine the shapes the corpus actually holds. The probe maps one
flat record family; ORE nests complex types, repeats children, puts attributes
on leaf elements and allows =xs:any=. Each of those needs a decision written in
the table rather than in the engine.

* Acceptance

- A type may hold another type, to the corpus's full nesting depth.
- A repeated child fills a contiguous run, not one heap object per element.
- An attribute on a leaf element is a field like any other.
- Content the schema does not name is captured and written back, not skipped.
- The engine fills a record as the document streams past it. It does not build
  the tape first: the tape costs 4.5 times the first-level cache misses of
  scanning on the portfolio and 10.6 times on the 6.3 MB file, and the entity
  path needs none of it.

* Result

The engine is in =ores.ore.core/xml/binding=. It holds a stack of at most 32
frames, each a type and the record being filled, and it writes into the record
as the scanner walks past. Nothing is retained after a frame closes, so the
document is never materialised. That is the decision the benchmark drove.

What it handles, exercised by a hand-written table for CalendarAdjustments:
three levels of nesting, a repeated child of a complex type, a repeated leaf,
a required attribute, optional children, and requiredness checked at the end of
each element. Verified against the corpus: the five calendar adjustment
documents in =external/ore= bind, 45 calendars in all, and the whole
=ore xml= suite is green at 514 cases and 63,540 assertions.

Two positions are worth recording because they are choices, not defaults.

- *A required attribute is checked like a required child.* Both are content
  the schema requires. Skipping attributes was a bug the test caught.
- *Content the schema does not name is refused, not dropped.* For a projection
  that is the right failure: a document carrying an element the model cannot
  represent should stop, not lose it. The tape keeps the fidelity case, where
  the whole document is preserved and written back.

Still open in this task: the three =xs:any= sites, and repeated children of a
simple type that is not text. Both are needed before every family can bind.
