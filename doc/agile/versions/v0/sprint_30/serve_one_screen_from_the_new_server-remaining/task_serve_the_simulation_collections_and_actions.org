* Plan

The inventory lists 25 unpaired simulation resource routes in five groups. Each
group is one pull request, so each review covers one screen's routes.

| Group | Routes | BFF source |
|-------+--------+------------|
| Feed and folder operations | 7 | =synthetic.ts= |
| Feed ticks and the raster | 2 | =synthetic.ts=, =market-regime.ts=, =feed-ticks.ts= |
| Simulation and conversion | 6 | =synthetic.ts= |
| Calibration | 6 | =calibration.ts= |
| Market regime | 4 | =market-regime.ts= |

The feed ticks and the raster read buffers the BFF fills by listening to each
running feed's tick subject, so they need a tick buffer in the gateway, which
is its own pull request.

The three composed views of the area (=GET /api/synthetic/calibration/:assetClass=,
=GET /api/synthetic/feed-folders= and =GET /api/synthetic/market-trace=) belong
to [[id:BE5A7BF2-B680-42BF-AB49-E9801C307742][Serve the synthetic composed views]].

The first pull request also pairs the five generic =/api/synthetic/:resource=
routes as families, as the reference data task paired its own. The generated
units already answer the 16 resources of the BFF's =SYNTHETIC_RECORDS=. That
registry states a resource in another form, so the inventory's registry reader
learns it: one =keyField=, a =parentField= for a read by parent, and
=readOnlyBecause= for a resource no screen writes.

Each route keeps the BFF's address and answer shape, as the earlier ports did.

Decisions made in the feed and folder operations group:

- The folder start and stop call the market data service, so the synthetic part
  links =ores.marketdata.api=, a service's wire protocol. The inventory files a
  route by the screen that calls it, and these are the feed screen's.
- A refused start or stop answers 409, a refused page or selection 400, and an
  unread running set 502, as the BFF answered them.
- The feed page refuses a query parameter it does not know, as the BFF's strict
  schema did. A selection body ignores a member it does not know, because the
  codec reads the members it names; the BFF refused one.
- The registry reader learns the synthetic form, and reads the three reference
  data lookups that the synthetic registry spreads into its array with the
  members a trailing map adds.

Decisions made in the feed ticks group:

- =feed_tick_buffers= keeps the newest 500 ticks of each source a read names,
  as the BFF's =FeedTickBuffers= did, and is shared by every session. It listens
  on =synthetic.v1.ops.feed_tick.<source>= through the client's transport and
  reads each =market_tick= with the process's wire codec.
- Each source's ticks have a lock of their own, which a tick handler takes and
  nothing else holds while it does. The handler owns the run it fills, so a tick
  that arrives while a source is dropped writes to a buffer no one reads. A
  dropped subscription stops outside the buffers' lock, because stopping waits
  for its handlers.
- The buffers live in the route handlers, which the router owns. The server
  declares the NATS client before the HTTP server, so the subscriptions stop
  before the client goes.
- The subscriber is a function the buffers are given, so a test hands ticks in
  without a transport.
- A tick's time is written as UTC to the millisecond, the form the browser
  parses; the BFF passed the text its decoder gave.

Decisions made in the simulation and conversion group:

- Five of the six bodies read as the service's own request, so the codec checks
  their shape and the route checks the bounds the BFF checked. The simple-view
  conversion reads a body of its own, because the BFF defaulted the side of
  the conversion the screen leaves out.
- A preview the service refuses answers 400 with its words, as the BFF did.
- An IR conversion's parameters arrive as a name-to-value object and go to the
  service as two aligned lists; its answer is the object again. The members of
  that object come back in name order, which a JSON object does not promise
  anyway.

Decisions made in the calibration group:

- The six routes are one unit, =calibration_routes=, because one screen calls
  them and they share the asset class, the intent and the system tenant check.
  The class's composed read stays with the composed views task.
- A policy and a review are refused 403 outside the system tenant before the
  body is read, as the BFF refused them. A pin is any tenant's, because a feed
  belongs to its tenant.
- A policy row is found by reading every policy, as the BFF did, because the
  list filter names no asset class. A save keeps the variance window and the
  approval rules as stored, or as the domain's defaults for a new row, which
  are the column defaults the BFF stated.
- A write the service refuses answers with the status its outcome names, so a
  stale version is a 409. The BFF answered every refusal but a denial, a
  missing row and an outage as 400.
- The run and the review refuse a body member they do not name, as the BFF's
  strict schemas did. The policy and the pin ignore one, as the BFF's did.

Decisions made in the market regime group:

- The four routes are one unit, =market_regime_routes=, because the regime
  screen calls them. The market trace stays with the composed views task.
- A read or a switch the service does not answer is a 502 with its words, and
  settings it refuses are a 400 with its words, as the BFF answered them.
- A sample's and a slot's time is written by the JSON codec, the form the
  service's own wire gives, which the BFF passed on.
- The strict reads of a query and of a body moved into =record_routes= as
  =refuse_unknown_params= and =refuse_unknown_members=, and the calibration and
  feed tick routes call them instead of their own copies.
