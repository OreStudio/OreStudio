* Goal

* Acceptance

- Every one of the 108 pricing engine types appears in the mapping with a product type code or a stated reason for having none.
- The 57 types with no trade type are classified: a finer variant of a product type, a building block, or a gap for a product the catalogue lacks, with the evidence for each and every row listed.
- The join shape is decided and written down: a junction keyed by both codes where one product type takes several engines, a column where it takes only one, with the rejected shape and its reason.
- The hand-written prose of the 108 is given one home, and the investigation says which.

* Plan

The task is an analysis, so the deliverable is the record rather than code.

1. Query the 108 rows and the column that could already carry the join, to see
   how far it reaches.
2. Read the seeder curation and its generator, to find where a new field would
   live.
3. Classify all 108 against the 121 catalogue codes: which name a product, which
   are finer, which are building blocks, which name a product the catalogue
   lacks.
4. Validate the classification mechanically: every row decided, every target a
   real code, nothing invented.
5. Decide the join shape: a column where each pricing type names at most one
   product, a junction where one pricing type serves several.
6. Decide where the instrument prose lives, since the product type now owns the
   instrument description.
7. Record the mapping's consequences on the tasks that consume it.

* Result

The mapping and the join are settled in
[[id:23F5286D-2B19-45BE-B63F-E8FD541AA917][How the pricing engine types join the product type]].

- All 108 are classified: 51 name a product type by an identical code, 32 are
  finer than one, 15 are building blocks and 10 name a product the catalogue
  lacks. The four kinds replace the three the acceptance expected: the data has
  a fourth, the product the catalogue cannot name.
- The join is a column, not a junction. No pricing engine type names more than
  one product type, so a junction would only permit a state that cannot happen.
  The column replaces =instrument_type_code=, which was filled on 32 rows and
  pointed at a catalogue the story retires.
- A =kind= of =product= or =block= tells a row that names no product type
  whether it is a gap or a building block.
- The instrument prose moves to the product type. A pricing engine type whose
  code is a product type code carries none of its own; a variant keeps one
  sentence saying how it differs; a block and a gap keep theirs.
- The 65 product types no pricing engine type names are a fact of the ORE
  guide's list, not evidence that the product cannot be priced. The page states
  it that way.
