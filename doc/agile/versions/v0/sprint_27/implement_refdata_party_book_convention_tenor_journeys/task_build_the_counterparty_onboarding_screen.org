* Notes

Started, not built. The reconnaissance above is recorded so the build begins
from a map; the screen itself is a 9-step front-end composition that needs the
prototype and the shared parts read in full, and it is left for a session with
the room to do that and verify the result.

Everything it was waiting on is done and merged. The story's eleven server-side
tasks are all =DONE=, including the four that unblocked this screen: the typed
refusal, the authoritative-identifier and primary-contact flags, the
counterparty business centres, and the composite write. =Operations= now holds
the permissions the screen needs, so a person who is not a tenant administrator
can run it. The one gap journey 5 still carries is the composite read of the
agreements and collateral terms, and the screen works without it by reading them
one subject at a time, which the journey's own step text describes.

Two traps worth naming before the build. Journey 5's prototype names
=refdata.v1.counterparties.composite_as_of= and a child-carrying list reply; the
tree carries =refdata.v1.ops.get_counterparty_composite_as_of= instead, and the
landing list reads its children with =counterparty_id_one_of= rather than one
reply. Both corrections are in the journey's coverage table, so read that table
and not the prototype's subject strings.
