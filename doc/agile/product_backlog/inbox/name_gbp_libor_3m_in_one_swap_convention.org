#+title: Name GBP LIBOR 3M in one swap convention
#+description: Acme provisioning fails at generate_trades: the Swap builder refuses GBP LIBOR 3M because both GBP-3M-SWAP and GBP-3M-SWAP-CONVENTIONS name it.
#+type: capture
#+level: cross
#+filetags: :trading:refdata:provisioning:
#+created: 2026-11-11
#+updated: 2026-11-11

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Make exactly one swap convention name the index =oresmd://ir/GBP?type=fixing&index=ibor&name=LIBOR&tenor=3M=, or give the Swap builder a rule that picks one, so the =generate_trades= step of provisioning builds its GBP swaps.

* Why

On 2026-11-11 a fresh Acme provisioning on a tree based on =319deea465= completed every step but the last, which failed:

#+begin_example
[13/13] generate_trades: failed - The Swap builder refuses the drawn index: oresmd://ir/GBP?type=fixing&index=ibor&name=LIBOR&tenor=3M: more than one swap convention names it: GBP-3M-SWAP and GBP-3M-SWAP-CONVENTIONS
#+end_example

The seed =refdata_conventions_seed_populate.sql= has carried both conventions since 2f26e8cbcc (2026-10-09). The refusal arrived with 6cc82f7356, "[trading] Build rates trades through their builders" (2026-11-10). The tree that showed it changed neither trading nor the conventions.
