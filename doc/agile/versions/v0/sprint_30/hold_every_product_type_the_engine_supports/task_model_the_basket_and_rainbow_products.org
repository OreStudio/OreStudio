* Acceptance

- each of the four types names an instrument table, and the tables carry the constituents and the terms the products state
- the projection reads the element into rows and writes it back, value for value
- each type has a builder, and a term a builder is not given does not compile
- the catalogue routes all four, and a test asserts the routing
- the generator books one trade of each type through its builder, and the recorded trades hold it
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: no list, basket or schedule is held as text

* Plan

ORE reads the four types as scripted trades over fixed elements
(=basketOptionData=, =rainbowOptionData=). The four types route to the
scripted instrument table through the class-read path, which already holds
=PerformanceOption_01= and the other class-read products. The FX tables cannot
hold a basket, so new equity and FX tables were not added.

- The scripted carrier holds option rows (option, premiums, exercise fees,
  payment dates, exercise prices), as the other families do.
- The class-read projection reads an =optionData= member through the option
  block, and a =scheduleData= member (=ObservationDates=) as a product schedule.
  It writes both back. Task B8BF800F can use the same path for
  EuropeanOptionBarrier and FxWorstOfBasketSwap.
- The scalar terms (Currency, Notional, Strike, Settlement) are parameter rows.
  The members are underlying rows with a weight and an optional currency.
- One builder, =basket_option_builder<basket_product>=, builds all four types.
- The equity planner books both on two equities in one currency. The FX planner
  books both on the slot's pair and a second pair with the same quote currency.

* Result

EquityBasketOption, FxBasketOption, EquityRainbowOption and FxRainbowOption
are held in the scripted instrument table. Each fact of the element is a
parameter, underlying, option or schedule row. No fact is held as text. The
round-trip test reads the user guide's Asian basket and best-of rainbow and
writes them back. Each type has a builder and the generator books one trade of
each. The ORE engine builds the four recorded trades with no error.

Two defects came up and are fixed:

- The FX basket planner chose its second pair by an offset from the slot. The
  slot's pair comes from the pairs that hold the book currency, so the offset
  could find the same pair. The planner now searches all pairs.
- The FX average forward ended its observations on the payment date, rolled
  forward. A payment date on a holiday put the last observation after the
  payment, and ORE refused the trade. The schedule now rolls its end date back
  (=TermConvention= P).
