* Goal

The import path formats a full JSON record for every entity it maps, at a
level that is not enabled. It is the largest single cost in the importer today
and it has nothing to do with XML, so it stands on its own.

* Notes

The investigation blamed the hand-written mappers for the cost. Those mappers
went with the codec moves. On main at =7515c50292=, a search of
=projects/ores.ore/core/src= and =projects/ores.ore/service/src= finds no log
line that serialises a record. The remaining per-record trace lines in the
conventions files stream a single id, inside the logging macro. That is a
reading of the code, not a measurement. The first step is a profile of
=import_portfolio_with_context= and the conventions import at default log
level.

* Result

The cost this task named is gone. It came from the hand-written mappers, and the
codec moves deleted them. The conventions and portfolio imports run with no
logging work at default level. The acceptance lines hold by removal: a trace
line that is off builds nothing, the importer has no per-record formatting to
remove, and no log line changed at an enabled level.

The profile binary was built from PR #3565. PR #3566 then moved conventions
functions between files. This record did
not re-measure on that tree.
