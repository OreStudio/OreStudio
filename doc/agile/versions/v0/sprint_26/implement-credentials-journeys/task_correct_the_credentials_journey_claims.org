Make the three [[id:8C1DC5DE-F480-49F4-AA63-77A397D0BC03][Credentials]]
journey documents true against the tree. Three of their claims are wrong: the
change-password handler does verify the current password, the

the wrong surface or the wrong behaviour misleads the build, so the corrections

* Notes

- The BFF's 23 routes include three for the caller's own session
  (=POST /api/session=, =GET /api/session=, =DELETE /api/session=). None of them
  lists a session, an account or a login record.
- =ores.http= forwards each IAM route to the matching subject, so a route that
  exists there proves the subject answers, not that it answers with rows:
  =POST /api/v1/iam/sessions/active= forwards to a handler that returns no
  sessions.
- The programme already decided that "the BFF is the browser's only HTTP
  surface". These corrections record what that decision costs the credentials
  group: a BFF route per read and per write, on top of the subjects that exist.
