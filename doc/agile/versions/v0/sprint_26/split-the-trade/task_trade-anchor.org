* Acceptance

- trade_anchor is immutable and keyed by (tenant_id, id); its party, counterparty and trade type are checked, and its three closed classifications are C++ enums with enforced foreign keys to immutable lookup tables.
- The generated write inserts and never replaces, so the key refuses a second write of the same trade id. The booking operation, which task 2 adds, maps that refusal to a domain error.
- A tenant purge removes anchors through a sanctioned session switch; any other update, delete or truncate is refused.
- Build, ctest, pgTAP and the local check set pass.

* Plan

- Three lookup entities, =entry_channel_type=, =counterparty_scope_type= and
  =booking_nature_type=: =read-only-current-state= profile, =:immutable:=, no
  tenant, seeded by populate scripts. The codes are the enumerators of three
  hand-written C++ enums, in the manner of =binding_mode=; enum generation was
  retired in sprint 20, so there is no generator to extend.
- The anchor, =trade_anchor=: =read-only-current-state=, =:immutable:=,
  tenant-scoped, so its key is =(tenant_id, id)=. Party, counterparty and trade
  type are trigger checks, because their tables are temporal. The three
  classifications are enforced foreign keys with =:use_no_tenant:=. A check
  requires a counterparty unless the scope is =intra_entity=.
- Generator: the immutable guard lets a =DELETE= through while the
  transaction-local purge switch is on (=ores_utility_allow_immutable_purge_fn=).
  The notify trigger states a null tenant for a table with no tenant.
- Hand wiring: the trading create and drop masters, the populate master, the
  message registrar, the anchor event mapping, the anchor RLS policies, the
  tenant purger, the custom type registry and the CMake source lists.
