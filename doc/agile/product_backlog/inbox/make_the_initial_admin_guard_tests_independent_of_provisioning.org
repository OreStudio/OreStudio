#+title: Make the first administrator guard tests independent of provisioning
#+description: The guard tests pass on a fresh database and fail on one that holds a provisioned tenant, because the trigger rejects their actor test.
#+type: capture
#+level: cross
#+filetags: :iam:testing:isolation:

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Make the first administrator guard tests in =ores.iam.core.tests= pass whatever the database holds: on a fresh database and on one where a tenant has been provisioned.

* Why

On 2026-11-12 the guard tests passed on a freshly recreated database. After an Acme provisioning on the same database, three of them failed before they reached their checks:

#+begin_example
messaging_initial_admin_guard_tests.cpp:104: FAILED:
due to unexpected exception with message:
  statement: ERROR:  Invalid modified_by: test. Must be a valid account
  username or service role.
#+end_example

The tests write as the actor =test=, which the username check accepts only while no account exists. A suite whose result depends on what an earlier run left in the database tells a reader nothing about the code. The three tests are =initial_admin_create_runs_once_in_bootstrap_mode=, =initial_admin_create_refuses_outside_bootstrap_mode= and =initial_admin_create_refuses_an_empty_principal=.
