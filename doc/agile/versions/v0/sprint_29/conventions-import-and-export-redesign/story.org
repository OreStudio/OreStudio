* Decisions

- Pull requests merged in sprint 28 for this work, with no task to record them: #3462, #3465, #3467, #3469, #3474, #3475, #3481, #3482 and #3485. They stage a conventions import in two tables, apply it in one transaction, move the ORE path onto it, and rename the staging to bundle import. The story was carried with no task. The next owner should write the tasks and close the ones these PRs finished.

- 2026-11-02: the code drifted from [[file:design.org][the design]] into untyped data in three places. The stage message carries a family name and the row as a JSON string, where the design asks for one typed stage per family. The export reads each family through =rfl::Generic=, with a hand-built request, the first array of the reply and a party filter in ores.ore, and a null =as_of=. Inside ores.ore the package holds rows as JSON strings. The cause is that the registry is a table of strings, so only refdata's generated apply could dispatch on it. A typed view of the registry is the first task, and the other three build on it. A typed transient package inside ores.ore is allowed; one struct with a typed array per kind on the wire is not.
