* Goal

A reader of the catalogue sees the whole of what ORE carries, and nothing on how
a trade is represented is left to do: every type is held, built and generated in
each form ORE reads it in, ORE reads and builds every generated trade, and a
check fails when a type is added, removed or re-routed without its model, its
builder and its generator.

* Acceptance

- Every other task of the story is done.
- Every catalogue type ORE supports names an instrument table, a builder and a
  generator; every type it does not support is tagged unsupported with its reason.
- Every remaining =construct_*= function and =*_terms= struct is deleted.
- The recorded trades' known lists hold only lines of the market data or engine
  configuration kind, each with its reason; the roundtrip differences list is
  empty.
- A run of the Acme reports after provisioning records no Trade errors, only
  market data errors.
- The coverage note states every type, its form or forms, its table and the task
  that closed it.
- A check compares the catalogue with the ORE source it was reconciled against,
  and fails on a type the engine gained or lost.
- Tests catch the FxOption style and FxSwap far leg defects that the first Acme
  run found.
- The review points of PR #4474 below are done.

* Notes

** From the review of PR #4474

Points the review raised on the recorded-trades test and the writer, left
for this task because it edits both:

- =state_reason= in the writer skips a row with none of the three audit
  shapes without a word; end it with a =static_assert= so a new row type
  that fits none fails to compile.
- =known_refusals()= mixes writer refusals with the three bond types the
  in-memory path cannot join; split the test-only ones into a list of their
  own, so the case's name says what it asserts.
- =sample_requirements()= should =REQUIRE= the corpus directory, for a
  clear failure when =external/ore= is missing.
- The recorded files compare as exact text; check line endings
  (=.gitattributes= for =tests/data=) and number formatting on the Windows
  build.
