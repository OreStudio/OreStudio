* Acceptance

- A service operation imports an ORE input directory's files against a report definition under the caller's session, and returns what was stored and what was not.
- A shell command imports a directory and exports a definition to a directory.
- The handler's permission is seeded.
- The import runs as a workflow saga over the owning services: a failure in any step compensates the steps before it, so no partial run stays behind, and two imports into one report definition cannot both store a run document (raised in the review of PR #2624).

* Result

A run's configuration now imports and exports through the owning services,
from the shell or any NATS client, without the ORE service touching another
component's tables.

- =ores.ore.run_configuration_messages=: the client import, which starts
  =run_configuration_import_workflow= and answers with its instance; the
  workflow's execute and rollback messages; and a synchronous export.
- The execute step parses and maps every file first, saves the run document
  through reporting, then binds a configuration through reporting and saves
  each document through its owner, as the caller. A failure part way deletes
  what the step stored; the rollback, which the engine sends as compensation,
  does the same from the step's result. The export reads the run through
  reporting and each document through its owner, and rebuilds the files.
- =nats_call= moved to a shared header, so the trade import and the run import
  call the owners the same way.
- The live run exposed that the document services stamped only the party: a
  live tenant refuses a row with no modified_by, while the test tenants, which
  have no user accounts, accept one. =stamp_document= in =ores.service= stamps
  every row of a document with the session's party and audit fields, and every
  document service uses it.
- The shell's =ore import-run= waits for the workflow; =ore export-run= writes
  the files. The recipe records the live run.

Live, against Acme Corporation: ORE-Python Example_1 imported into Acme
Corporation Plc's NPV definition and exported back; pricing engines, today's
market and the run document matched, the curve configuration differed only in
how two tolerances print, and the conventions held all but the FX convention,
which has no store yet. ctest 90/90 after a database recreate.
