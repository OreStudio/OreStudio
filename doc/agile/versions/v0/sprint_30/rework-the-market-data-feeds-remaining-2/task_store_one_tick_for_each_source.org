* Plan

The decision is in [[id:D71F9446-C62E-48A6-A87B-136EF598A59E][One shared
tick or one copy for each party]]. The slices, each verified before the next:

1a. Bring the tick table under codegen. The generator already emits the
   hypertable (partition column, chunk interval, retention). It lacks three
   traits the tick table needs, and the model needs a fourth capability:
   - =:rls_policy_style:= (default or hot_path). =hot_path= emits FORCE row
     level security, the tenant policy in the scalar-subquery form, and the
     restrictive select-only party policy without the null passthrough. One
     typed style, not three booleans that must agree.
   - =:writer_role:= (a psql variable). Emits =grant insert on <table> to
     :<role>=, for a role that carries BYPASSRLS.
   - =:sql_only:= at the model level. The model emits the SQL facet alone.
     Without it, modelling the tick store also generates a domain type,
     repository and service that duplicate the hand-written batch writer.
   - =:no_primary_key:= at the model level. The tick table has no primary
     key, and the template always emits one. The capability is needed to
     reproduce it, with a validation that a hypertable may omit the key.
   The four hypertable knobs are undocumented and unvalidated. Document them,
   and refuse a hypertable that names no partition column, because the
   template otherwise emits a broken key and create_hypertable call.
   Model the tick table with =:no_audit_columns:=, the hypertable knobs and the
   new traits, and prove the generated SQL matches the hand-written choices.
   Delivered in PR #3769 with a baseline repair for the arrival change that
   main left stale. The store reshape (1b) follows in its own PR.
1b. Model the shared point store: a tick belongs to a source and a datum, not a
   party, and every row sits under the system tenant. The per-party series
   keeps its classification and gains the key that finds the shared stream.
2. The ingest writes one row for each tick and stops reading the routes for
   the store. The delivery fan-out still needs to know who consumes the
   source, so it moves to the demand snapshot the supervisor already builds,
   or the ingest keeps a routes read for delivery only; the slice decides
   which and records it.
3. The history read resolves the party's series to the shared stream and
   checks the subscription and its rights before it returns a tick.
4. The ingest loop and quote series pages describe the decided shape, and the
   provisioning smoke proves the path end to end.

The table was hand-written because it led the generator on row-level security,
not because the generator cannot make a hypertable. Modelling it is part of
this task, so the shared store is reviewable through the model and the
policy-form knob is available to every hypertable after it.

* Result

The tick store holds one row for each tick of a stream. The stream id is a
name UUID of the provider code and the series URI. The tick row and the
coordinate dictionary carry no tenant and no party. A unique key on stream,
coordinate and time keeps one value for each point, and the writer skips a
key that it already stored, so the first value wins. Reads check the party's
subscription. A raw read needs display or non-display. A compute read also
accepts derived. A party with no right reads its own observation rows and no
tick.

Acceptance:

- One row for each tick, with no routes read for the store: met. The ingest
  test of two consumers of one source stores one row.
- A routed party reads the shared stream, and the tick read tests pass: met.
  On a recreated database the marketdata suites pass: api 943 test cases,
  core 381, service 208.
- A provisioned tenant ticks end to end, proved by the smoke check: met. The
  ticks-smoke check of compass check provisioned a tenant on a fresh database,
  and the tenant's routed feeds stored 16742 ticks. See Measurements.
- The pages describe the shared store: met by
  [[id:D71F9446-C62E-48A6-A87B-136EF598A59E][A source tick is stored once and entitled when it is read]]
  and [[id:E4736D88-03B2-4A40-B7F4-01B06B9B9FD7][A quote series is keyed by item, provider and party]].

Open: the entitled-stream wrapper type and its coverage test (review item 1).
A party with a derived right alone cannot read a snapshot of its own
published curve. The write cost of the staged insert is not measured.
