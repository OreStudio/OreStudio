* What

=import_service::import= finds each series by its oresmd URI with one
=read_latest_by_uri= query per distinct series in the file. The series cache
lives for one call, so every file looks its series up again. Each query costs
about 18 ms here, most of it fixed overhead: the pool sets the service and
tenant context on every call and logs "there is no transaction in progress".
Fetch the file's series in one query (the URIs =IN= a list), and create only
the ones that query does not return.

* Why

Measured on 2026-10-02 with debug test logging over the whole-corpus walk,
after its verification was fixed: 15,047 queries take 278 of the walk's 327
seconds, and 10,365 of them are the by-URI series lookup. The walk is the
default regression check for the import, and it shares the 600-second ctest
limit with the rest of =ores.marketdata.core.tests=. A real import of a large
file pays the same cost: a file with 1,000 series spends about 18 seconds on
lookups.
