This page defines one [[id:A7FCC423-1CA3-4345-BF5B-18D54207B00B][report]]:
Headline Position (EOD). It shows the most important Greeks across a trade set
at the close, so the market risk function signs off on figures that stay
authoritative for the day. It runs on the schedule at 18:00 on weekdays and on
demand, and it selects the end of day cut. It leaves the engine's own output
archive and records the cut its run selected; the result store that would
ingest the archive is not built yet.

* Purpose

It answers what a book's or a portfolio's headline Greeks were at the close, on
the market data that the day is booked against. The decision it feeds is the
sign-off: the market risk function accepts the day's risk position, or it sends
the desk back for a correction before the numbers stand.

The report exists beside its [[id:500AC7E3-E87C-4EC8-88A2-B46FB310F865][intraday sibling]]
because the two answer different questions. The intraday definition says what
risk looks like now, on an indicative body, and a later run replaces it. This
definition says what the risk was at the close, on the authorised body, and no
later run of the intraday definition replaces it. A reader who wants a figure to
quote or to hedge against reads the intraday one. A reader who wants the figure
that stands reads this one.

* Frequency

Cycle =eod=. Frequency =scheduled= and =on-demand=. The definition is seeded with
the expression =0 18 * * 1-5=, which fires it at 18:00 London time on weekdays,
and a person may ask for one at any time. It is not a member of the ten-report
Market Risk EOD set, so nothing orders it after the market data cut.

The concurrency policy is =skip=: a firing that arrives while a run of the same
definition is in flight is dropped, because a second close report of the same
day answers nothing the first one did not.

* Inputs

- Trades selected by scope. The scope shape is =book= or =portfolio=, and the
  seeded definition reads the entity's =Global Portfolio=.
- Market data for the close. The run selects the end of day cut, and it values
  the portfolio at the weekday before the run date.
- The risk report configuration the definition binds, =Valuation and
  sensitivities (EOD) - Global Portfolio=. It states the market data type =eod=
  and the base currency of the entity.
- The pricing engine the definition binds, =EOD Official=, which is the set of
  engines whose numbers are booked.

* Outputs

The run produces the engine's own output archive, which holds the report's CSV
artefacts, and it records where that archive landed against the run instance. It
also records the cut the run selected, with the cut's identity, label, kind and
instant.

The archive is the only shape the figures take today. The rows a reader would
query are a later phase, designed on
[[file:../architecture/report_post_processing.org][Report post-processing]] and
not built.

* Measures

The set is the configuration's. The measures below are the ones the business
catalogue states this report carries; their definitions are on
[[file:../domain/risk_reporting.org][Risk reporting]] and are not repeated here.

#+ATTR_HTML: :class hug-leading
| Measure    | Meaning                                                        |
|------------+----------------------------------------------------------------|
| PV         | Present value of the scope at the close.                       |
| Daily P&L  | The change in NPV since the previous business day.             |
| MTD P&L    | NPV minus the previous month-end NPV.                          |
| YTD P&L    | NPV minus the previous year-end NPV.                           |
| Delta P&L  | The P&L the report attributes to directional risk.             |

The engine aggregates by book, by portfolio, by currency pair, by Greek and by
unit hedge. The aggregation is the producing engine's, not the reader's.

The =npv= analytic states the base currency and the file it writes. The
=sensitivity= analytic states the two documents it reads and the three

<Analytic type="npv">
  <Parameter name="active">Y</Parameter>
  <Parameter name="baseCurrency">GBP</Parameter>
  <Parameter name="outputFileName">npv.csv</Parameter>
</Analytic>
<Analytic type="sensitivity">
  <Parameter name="active">Y</Parameter>
  <Parameter name="marketConfigFile">simulation.xml</Parameter>
  <Parameter name="sensitivityConfigFile">sensitivity.xml</Parameter>
  <Parameter name="scenarioOutputFile">scenario.csv</Parameter>
  <Parameter name="sensitivityOutputFile">sensitivity.csv</Parameter>
  <Parameter name="outputSensitivityThreshold">0.000001</Parameter>
  <Parameter name="recalibrateModels">Y</Parameter>
  <Parameter name="parSensitivity">Y</Parameter>
</Analytic>

The run document that carries this fragment is generated, not stored. The
service builds it from the risk report configuration, the analytics and the
engine settings the definition binds. The run settings row states the market
data type =eod=, so the document's =asofDate= is the weekday before the run
date.

* A worked read

A person reads this report once a day, after the desk has closed.

1. Open the run of =Headline Position (EOD)= for the entity and the day. Read
   the run instance first. It names the cut it selected, and the cut's label and
   instant say which body the figures came from.
2. Take =npv.csv= and select the rows whose =NettingSet= is the book under
   review. Sum =NPV(Base)= over those rows. That total is the present value of
   the book at the close, and it is the figure the P&L measures are taken
   against.
3. Compare that total with the same total from the previous day's run of the
   same definition. The difference is the daily P&L. Compare with the month end
   and the year end totals for the MTD and YTD figures.
4. Take =sensitivity.csv= and group by =Factor_1=. Sum =Delta= within each
   factor. Read the result as money per shift of that factor, and note that the
   shift size is stated in =ShiftSize_1= and is already inside the number.
5. Sort the factor groups by absolute total. The largest groups are the risks the
   sign-off is really about, and they say which deeper report a reader opens
   next: a curve ladder, a vol ladder or a spot ladder.
6. Where a figure looks wrong, take the matching row from =scenario.csv= and
   check =Difference= against the =Delta= of the same trade and factor. The two
   agree to the printed precision when the run is sound.
7. Sign off, or send the book back. The run instance holds the figures that were
   signed off, and a later run of the intraday definition never replaces it.

* What is not built

The report states what its definition and its configuration state. Four limits
follow, and a reader must know them.

- The cut is reproducible and the body behind it is not. The run records the cut
  and its instant, and the market data body that the cut fixes is not
  materialised. So a rerun tomorrow selects a different cut and returns
  different figures. The record says which body was signed off, and it cannot
  hand the body back.
- The dataset holds curve quotes only, and no volatility market data. A volatility factor therefore has nothing to
  shift, and no volatility sensitivity can be computed until the store holds that
  data. This is a fact
  about the data and not about the report.
- The result store is not built, so the figures live in the archive. Nothing
  queries them, and a reader opens the CSVs by hand.
- The seeded definition runs on =EOD Official= engines. A bump report on
  analytic sensitivities ideally binds an engine set whose numbers are built for
  bumping; the ACME dataset carries such a set for London alone, named =Risk
  Sensitivities=. This definition does not bind it.

* Test coverage

No substitute is defined for this report, so a test run of it executes every
phase: it gathers trades and market data and assembles its own bundle. The
report is exercised by the full-pipeline proof, not by a smoke test. The cut
resolution it relies on is exercised by
[[id:EA59C7E0-CFDF-4BBE-815C-8AF53BFC16E1][Light the intraday reports on the LIVE cut]],
which proves the same chain for the live selection.
