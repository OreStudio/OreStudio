#+description: A trader or an operations user needs a journey to authorise a live trade. Operations releases a new or amended live trade, and can withdraw the release with a reason. The state machine and the trade versioning note define it as operational authorisation, which moves neither version. The trade journeys written in sprint 27 cover booking, amending, reviewing, importing, exporting, lifecycle events and structures, and none covers authorisation or the authorisation queue. The trade page prototype draws an Authorise button so that the state machine reads whole. Write the journey, and decide with the four-eyes framework story how the queue and the escalation of some reasons to a head of desk are drawn.
