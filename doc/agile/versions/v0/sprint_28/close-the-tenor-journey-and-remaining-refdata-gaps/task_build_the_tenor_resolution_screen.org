* Acceptance

- A tenant administrator lists tenors and opens one. *Met.*
- The screen shows the tenor's convention and the tenors that convention resolves. *Met.*
- The screen shows the schedule axes a convention may roll on, and which axis a
  tenor in the set uses. *Met.* Expanding an axis into its dated rolls is *not
  met*, for the same reason as the resolved dates below.
- The screen states the refusal when a write fails, names the step that refused,
  and says which calls had already been written. *Met.*
- The screen shows the tenor's history. *Met.*
- The screen shows the resolved dates. *Not met*, and it cannot be: the server
  serves no operation that resolves a tenor to a date. That view belongs to the
  sibling task [[id:CFE1A720-6BB6-4D94-AA26-28FBC1A2978D][Resolve a tenor over the wire, with the refusal it carries]].

* Plan

The work is split between the wire layer and the screen.

The branch =feature/build-the-tenor-resolution-screen= carries the first half,
written 2026-10-10 and parked while the book prototypes were signed off:

- =bff/src/tenors.ts= with =tenors.test.ts= — the catalogue, the pick lists, one
  convention's set, and the writes of a tenor, a convention and a membership row.
  No route resolves a tenor to a date, because the server serves no such operation.
- =web/src/api/tenors.ts= — the typed client.
- =web/src/journeys/tenorsServer.ts= — the server half of the journey.
- =web/src/journeys/tenorsState.ts= — the journey state.

The screen half is not written. Every peer journey in this package carries five
files — =<x>State.ts=, =<x>State.test.ts=, =<x>Steps.tsx=, =<x>Steps.test.tsx=
and =<X>Journey.tsx= — so its state machine and its screen are proved by tests.
The tenor journey has the state file alone. The remaining work is:

1. =web/src/journeys/tenorsState.test.ts= — prove the state machine.
2. =web/src/journeys/tenorsSteps.tsx= and =tenorsSteps.test.tsx= — the steps.
3. =web/src/journeys/TenorJourney.tsx= — the screen, against
   =doc/prototypes/tenors/define-how-tenors-resolve/=.
4. Wire the journey into its route, then run the package suites.

The journeys it draws from are the list, the tenor, its convention, the
schedule, the resolved dates, the review, the refusal and the history.

* Built, 2026-10-15

All four steps above are done. The screen is a six-step rail — choose, tenor,
convention, review, outcome, history — and the convention is the second half of
the same rail rather than a journey of its own, because a tenor and the rule
that resolves it are read together and the review draws one difference list over
both.

Two decisions worth carrying to the story:

- The screen is reached from its own card, =Define how tenors resolve=, at
  =/refdata/tenors=, beside the instrument-convention card. Tenors are their own
  reference-data job, not a step inside the convention journey.
- The resolved-dates view is not drawn. The server serves no operation that
  resolves a tenor to a date; the BFF says so in =tenors.ts= and the state
  machine says so in =tenorsState.ts=. That view belongs to the sibling task
  =Resolve a tenor over the wire, with the refusal it carries=.

* Review round one, 2026-10-15

The local review raised findings on both axes. What it changed:

- Every word the journey draws now comes from the catalogue. The state module
  named its changes and its problems in English; it now names them by key, and
  the screen renders them. A member's before and after are a named set state
  rather than the sentence "in the set". (TS-C04.)
- The schedule step is drawn. It was missing: the prototype's rail carries seven
  steps and the screen carried six. The step names each schedule axis, its source
  and its calendar, and marks the axis a tenor in the set uses. Expanding an axis
  into dated rolls needs the same operation the resolved-dates view waits on, so
  it is not drawn here either.
- The refusal notice now names the step that refused, in the rail's own words.
  It previously named only the protocol subject, so the step was reachable but
  never stated.
- Two return types declared on the client's write calls. (TS-T13.)
- A dead catalogue key removed. (TS-H02.)

Tests: 20 on the state machine, 9 on the steps, 1 on the page.

* Result

Complete. Journey 9 is built in =ores.web=: a seven-step rail — choose, tenor,
convention, schedule, review, outcome, history — reached from its own card,
=Define how tenors resolve=, at =/refdata/tenors=.

The confirm is a sequence of writes. It writes the tenor, then the convention,
then each membership link and unlink, and a refusal names the step that refused
and the calls already written, so a person can see what landed.

Two parts of the prototype are not met, for one reason: the server serves no
operation that resolves a tenor to a date, so neither the resolved dates nor a
schedule axis expanded into dated rolls can be drawn. Both belong to
[[id:CFE1A720-6BB6-4D94-AA26-28FBC1A2978D][Resolve a tenor over the wire, with the refusal it carries]].

The gate is green: 1550 web tests and 771 BFF tests pass, and =./compass.sh
check= is 7 of 7 on the release-ninja preset.
