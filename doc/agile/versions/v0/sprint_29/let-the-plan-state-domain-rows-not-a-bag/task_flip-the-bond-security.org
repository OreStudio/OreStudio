* What moves, measured

=ensure_issue= writes a =put_bond_issue_composite_request=: one =bond_issue= row
(issue id, security id, issuer, face value, issue date, settlement days,
calendar, sub type, price type, curve) plus one leg, one notional amount and one
fixed rate. It runs before the trade is booked, because the instrument points at
an issue that must already exist.

So this slice moves about sixty lines from the writer to the planner and gives
the batch the rows the request already holds. It is not a rename: the leg, the
amount and the rate are part of the security, and the planner has to state them
with the issue's own identifiers.

* Why it is its own task

The instrument flip kept =terms= precisely because this coupling exists, and the
planner's tests caught it. Moving the security is the step that lets
=bond_terms= leave the plan, so it is the step that starts deleting the bag.
