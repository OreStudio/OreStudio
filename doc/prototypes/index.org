* Summary

A prototype answers a question about layout or behaviour that a document
argues badly. It is kept after the argument is settled, as the design record
of what was agreed. A prototype is throwaway in spirit and plain in form:
static files, mock data, no framework and no backend.

* Adding a prototype

There is one way, and it is this.

1. Create =doc/prototypes/<name>/= with an =index.html=, and a
   =prototype.css= and =prototype.js= when the prototype needs them.
   Plain HTML, CSS and JavaScript: no framework, no build step, no
   backend. Switch variants and states with query parameters, as every
   prototype here does.
2. Copy the design tokens from
   =projects/ores.web/packages/web/src/styles.css= so the prototype reads
   in the application's own colours.
3. Describe what it argues on the journey's page, or on a knowledge page
   beside this one.
4. Add a row to the table above.
5. Publish it with one =ores-deploy-web-app= call inside
   =ores-deploy-web-apps=, in =projects/ores.lisp/src/ores-build-site.el=.

A prototype is never a route in =ores.web=. React is for the product, and a
prototype must open without a build, a server or a session.

=build/scripts/check_prototype_inventory.py --check= enforces this: it fails
when a =doc/prototypes/<name>/index.html= is missing from the table above.
