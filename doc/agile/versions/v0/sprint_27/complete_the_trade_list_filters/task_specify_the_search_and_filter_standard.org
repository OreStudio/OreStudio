* Acceptance

- The entity protocol specification states when an entity is a read model over several entities, and that a screen filters through it, not through joins in the client.
- The specification defines the enum filter member, the _from and _to range members with the end-of-day rule, and the by-parent read.
- The specification states which instant a read model answers when its parts version on their own timelines.
- The specification states when a scoped read states =as_of=. Only 9 of 78 scoped reads declare =list_by_as_of: true= today, so the rule needs a decision and an example.
- The specification states that a foreign key declares =list_by= on its own section of the model, and that a filterable enum column compares the text of its =to_string=.
- The entity screen specification and the modeling standard point to it, and each rule has an example from the trade list.

* Result

The NATS entity protocol specification now states the standard for finding rows:

- the enum filter member, with the enum stored as its text;
- the inclusive =_from= and =_to= range members and the end-of-day rule;
- the read model: =list= and =get= only, the standard filter record over columns of every part, one instant for all parts, its own key and permission, and no event of its own;
- the declaration of a scoped read on the foreign key, and when it states =as_of=;
- a table, "Finding an entity", that names the mechanism for each need, with the limit of 1000 keys for a scope sent as a one-of member.

The entity screen specification points to the table and no longer claims a book subtree is a scoped read. The decision that a read model emits no event is new, and the summary task confirms it against the events of the parts. No separate modeling standard lists filter properties, so the protocol specification is the only place.
