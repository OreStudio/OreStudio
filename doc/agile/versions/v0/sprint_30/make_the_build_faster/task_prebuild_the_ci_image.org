* Acceptance

- A versioned image holds the toolchain, dev packages, PostgreSQL and the vcpkg binary packages.
- continuous-linux.yml runs in that image and its setup steps take at most 2 min.
- A vcpkg.json change rebuilds the image.

* Plan

The step times below show where the 7 to 10 min of setup go. Two findings
change the premise of the task:

- The vcpkg cache is warm. CTest restores 123 packages in 1.1 s, so an image
  that holds the vcpkg packages saves almost no time. It helps only after a
  =vcpkg.json= change, when the cache misses.
- The runner disk is now 145 GB, with 86 GB free before cleanup. The debug
  job grows the disk by about 47 GB, so it peaks at about 106 GB without the
  cleanup. "Free disk space" (82 to 260 s) is the largest setup step, and the
  build no longer needs it.

The work is in two phases. Each phase ends in a measured run.

1. Remove the setup that the build does not need, with no image:
   - Remove "Free disk space". Keep a =df= report before the build.
   - Install clang 19 from apt.llvm.org with =build/scripts/install_llvm.sh=
     instead of the 1 GB LLVM release download. Both give 19.1.7; the
     Ubuntu archive has only 19.1.1.
   - Move "Validate SQL Schema" (40 to 95 s) to the relevance-guard job,
     where it runs in parallel with nothing on the critical path.
   Expected setup: about 4 min. The compiler binary changes, so the first
   run after the change misses sccache once.
2. Put clang, the dev packages and PostgreSQL with TimescaleDB in an image on
   GHCR, built from =build/docker/ci/Dockerfile= by a workflow that runs when
   the Dockerfile or the scripts it copies change. Run the build job in that
   image. The Dockerfile is in the repository from phase 1, so the image can
   be built again at any time.

* Notes

- Phase 1 keeps clang 19.1.7 but takes the binary from apt.llvm.org, not
  from the LLVM release tarball. sccache keys hash the compiler binary, so the
  first run of each variant after the merge compiles cold.
- The image holds no vcpkg packages, contrary to the first acceptance item.
  The actions cache restores all 123 packages in 1.1 s, so the image would
  save nothing, and an image without them does not go stale when
  =vcpkg.json= changes. The third acceptance item then does not apply.
- The CTest step already prints =df -h= before and after the build, so the
  removal of "Free disk space" keeps a record of the disk headroom.
- CTest runs no Python, so the build job does not need the =pystache= install
  that the SQL validation step did.
- All versions live in =build/docker/ci/versions.env=. The Dockerfile has no
  defaults, =build.sh= passes the file as build arguments and checks each tool
  against it, and continuous-linux.yml reads =LLVM_MAJOR= from it. A new
  compiler is a one-line change there.
- nightly-linux.yml has the same setup steps. It changes after phase 1 is
  measured on continuous-linux.yml.
