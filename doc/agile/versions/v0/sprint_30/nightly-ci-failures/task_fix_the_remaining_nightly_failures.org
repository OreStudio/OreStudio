* Result

- Windows: the http client tests take the process id from =current_pid=. A
  new =ores::platform::process::peak_resident_bytes= takes the place of
  =getrusage= in the reporting benchmark. It also corrects the macOS unit,
  which =getrusage= gives in bytes.
- macOS: the cases that refuse a certificate hung for 600 s. The test server
  ran accept, handshake and read with no deadline. It now runs every step
  asynchronously, and its destructor stops its context. The cause of the hang
  is not proven. If the next nightly still hangs, the cause is in the client.
- The ORE engine test runs only on Linux, where the engine is built.
- Drift: the three FX forward publish read permissions are seeded for
  Trading and Operations. The two new provisioning steps have translations.
  The synthetic tests' model declares =Boost::process=. The
  =fx_forward_operation= shell recipe is generated.

No Windows or macOS build ran locally. The next nightly runs are the proof.
