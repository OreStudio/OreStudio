#+title: How do I run the tenor_schedules commands from the shell?
#+description: Every command the tenor_schedules submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tenor_schedules:

This file documents the tenor_schedules resource at the shell, one section per command. Every command is a subcommand of =tenor_schedules=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 58DE1C34-4552-5742-B122-0243181AA33B
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tenor_schedules list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.tenor_schedules.list=.

#+name: tenor_schedules-list
#+begin_src ores-shell :tangle tenor_schedules-list.ores :exports none
tenor_schedules list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 2164BCD6-B4B4-5C3A-9D05-CFDE41980A05
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
tenor_schedules get <code>
#+end_example

It is addressed at =refdata.v1.tenor_schedules.get=.

#+name: tenor_schedules-get
#+begin_src ores-shell :tangle tenor_schedules-get.ores :exports none
tenor_schedules get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 074BC41B-0941-5758-A594-F55AC416C1BC
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tenor_schedules add <code> <name> <description> <display_order> <schedule_source> <calendar_code> <diary_entry_type> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.tenor_schedules.put=.

#+name: tenor_schedules-add
#+begin_src ores-shell :tangle tenor_schedules-add.ores :exports none
tenor_schedules add __none__ __none__ __none__ 0 __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 67CDAD70-4690-5645-810E-12F06B05203E
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
tenor_schedules set <code> <name> <description> <display_order> <schedule_source> <calendar_code> <diary_entry_type> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.tenor_schedules.put=.

#+name: tenor_schedules-set
#+begin_src ores-shell :tangle tenor_schedules-set.ores :exports none
tenor_schedules set __none__ __none__ __none__ 0 __none__ __none__ __none__ system.new_record generated_script
#+end_src
