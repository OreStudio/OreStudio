* Acceptance

**Documentation first.** No implementation starts until these documents answer
every question below.

- One knowledge page paints the whole publishing architecture in one picture:
  every level, every artefact table, every dataset, every bundle, and what
  publishes what into which tenant. It replaces the four partial answers, and
  the pages it supersedes link to it rather than restating it.
- The page carries UML for the parts a table cannot show, as =*.puml= beside it
  in =doc/knowledge/=:
  - a component diagram of the publish path from request to published row;
  - a diagram of the levels, showing which tables each level writes and which
    readers look at each;
  - a sequence diagram for one bundle publish, including the dependency order.
- The page states, in their own sections:
  - *Provenance* — for a published row, the dataset and artefact row it came
    from, and how a person finds that chain.
  - *Methodology* — how a dataset is staged, declared, bundled and published,
    as the canonical sequence an author follows.
  - *Reproducibility* — what a blank database produces, what a recreate
    reproduces, what depends on the outside world, and how an operator proves a
    database matches its datasets.
- Every question the investigation left open is answered on the page:
  1. Which levels exist, what each is named, and what each holds?
  2. Which bundle publishes which datasets, into which tenant, once or per
     tenant?
  3. How does a reader see world data without a second copy, given row-level
     security?
  4. Where do the coded vocabularies and catalogues live, and who owns them?
  5. What is the single canonical way to add a dataset, end to end?
  6. What is legacy, and what retires it?
  7. What does a recreated database contain, and what must an operator run?
- The page is reviewed and signed off before task 2 starts.
