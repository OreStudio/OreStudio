* Result

The diagram is drawn one file per package, from the grouping the model
already carried, and =ores_schema.puml= is the index over them. Every one
of the 22 renders; the largest, =dq_staging=, is 226.6M pixels, against
the single 463-table diagram that overflowed a 32-bit pixel count at
about 2.68e9.

*The policy for a key that leaves its package.* A group draws its own
tables and the keys with both ends inside it. A key that leaves is not
drawn, because its other end is in another file; the group's note names
those tables and the group each belongs to, so the reader knows where to
go next. The note is emitted from both sides, so =alpha= names =c_tbl
(beta)= and =beta= names =b_tbl (alpha)=.

*The index.* It names every group, the file that group is drawn in and
the tables it holds, and draws no columns and no keys, so it stays the
starting point without being another picture to read.

The generator writes the group files beside =--output= and the index to
=--output= itself, so the shell script, the CMake target and the check
needed only the new =--index-template=. =--check= now walks every file
and reports each stale or missing one rather than the first.
