its credit simulation, stress test and today's market configurations: through a

* Result

The pricing model configuration carries a nullable =configuration_id= to the
reporting configuration it is registered as, with the same insert-trigger check
as credit simulation, stress test and today's market. All four per-report
configuration roots now reach their report the same way.

A database created before the change gains the column through
=analytics_pricing_model_configs_add_configuration_id_migration.sql=. It also
re-runs the generated create script, which creates nothing that exists and
replaces the insert trigger, so an existing database checks the link too.
Adding the column alone would have left the old trigger, which never checks it.

**Component audit.** The task touched =ores.analytics= through one model and
its regenerated surfaces. =validate_docs.sh= passes for all 41 components, and
no folder, type or component changed.
