* Goal

The route is the only consumer record. The ingest reads the routes, and the feed binding is gone from the model, the code, the tables, the screen, the permissions and the widening guard. No migration and no compatibility layer is added: the database is recreated.

* Acceptance

- The ingest reads the consumers from the routes only, and the marketdata service and core tests pass.
- No file under projects/ores.marketdata, projects/ores.shell or projects/ores.web names a feed binding, and the build, the web typecheck and the web tests pass.
- The binding tables, triggers, policies, event mapping, permissions, menu card and generated artefacts are gone from the create and drop scripts, and the widening guard no longer lists a binding policy.
- A recreated database provisions a tenant and still produces ticks from its routes.

* Plan

1. Give the ingest loop its own consumer record, built from the route, and
   delete the binding read, the activity record and the binding event
   subscription.
2. Delete the binding model and regenerate the component. Delete the generated
   domain type, table, protocol, event, generator, repository, entity, mapper,
   service, handler, history provider and presentation.
3. Delete the shell commands, the client methods and the permission.
4. Delete the two binding tables, their triggers and policies, the schema
   diagrams, and the guard exception.
5. Delete the web surface: the list and record pages, the API, the BFF read,
   the contracts, the generated wire protocol, the routes, the menu card and
   the i18n keys.
6. Rebuild, run the marketdata suites, the web checks and the guard, recreate
   the database and prove that a provisioned tenant ticks from its routes.
