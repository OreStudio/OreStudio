* Result

Closed on branch =hotfix/clear-the-valgrind-and-gcc-failures=, based on
5ce3cd7e6c.

The 30 Valgrind defects are one bug: =config::options= left =stale_seconds_ir=
and =stale_seconds_fx= without an initialiser, and the config test streams a
default-constructed options through the JSON codec into yyjson, which reads both
integers. They now default to zero, the value that means the deployment's
threshold answers for the kind.

The GCC build's foured =-Wchanges-meaning= rows are two declarations:
=bond_trade_rows::bond_option= and =::ascot= share their type's name. Their
types are qualified, which is how the generated protocol headers already spell
the same shape.

Still open: the Windows nightly's 23 unresolved externals, led by
=ores::synthetic::service::read_calibration_policy=. The free functions declared
in =feed_kind_registry.hpp= carry no =ORES_SYNTHETIC_SERVICE_EXPORT=, so the
tests' header-inline code cannot import them from the DLL. That is a separate
change, and the full symbol list is not on CDash yet.
