* Goal

Two guarantees went out with the immutable profiles, and nothing replaced them:

- A trade is no longer refused when it is reported into another party's
  portfolio. The check and its message are gone from the generated SQL, so
  the report is accepted.
- A raw update rewrites every version of a trading row in place. The history
  a versioned table exists to keep can be written over.

* Notes

Two smaller consequences of the same refactor, found while repairing the pgTAP
suites. Neither is worth a task of its own yet:

- =ores_utility_allow_immutable_purge_fn()= is inert for trading. Nothing in a
  trading table consults it any more, so a delete closes the current version
  with the switch on or off. The pgTAP case that used to purge now asserts that
  the switch changes nothing.
- The structures insert trigger checks that a structure is not its own parent
  after it checks that the parent exists, so a self-parent write is refused as
  a missing parent and the self-parent branch never runs. The check is
  unreachable rather than wrong.
