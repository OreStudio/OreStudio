* Plan

** What a refdata row is made of, measured first

A census of the member types of the component's generated structs, over its 688
domain headers, is 24 distinct types. Twenty-two of them already have a carrier:
the strings, the integers, the truth values, the uuids, the instants, the dates,
the tenant ids and the decimals, and the optionals of each. So the component is
much closer to the move than dq was, and the census says exactly what is
missing:

- =double=, in three structs directly and in thirteen as an optional. That is
  what a rate or a weight is, and it had no carrier.
- The component's *field-group* structs -- =convention_identity=,
  =convention_payload= and the =tenor_basis_swap_*= parts -- which are members of
  other types and are rendered by the field-group templates.
- =ores::dq::domain::audit_record=, a field group another component owns, which
  is reached as a member of three refdata types.

There are no enums among them: a coded value in this component travels as its
code, a string, which the carrier already covers.

** The order that follows

A carrier first, because nothing else compiles without it -- and the doubles'
proof is the same one every other carrier carries, a byte comparison against the
reflector. Then a shape for the field groups, which is the same move the
protocol header got: state =wire_fields= where the struct is declared, from the
iteration that writes its members. Then the models opt in, one entity at a time,
and the suites say what the move changed.

* Notes

The doubles' carrier landed first, because the census put it at the root of
everything else: an integer and a truth value had been added for dq, a real had
not. The proof is the one every carrier carries -- the bytes are reflect-cpp's
for the same value -- and it held for =0.1=, for a negative and for =1e300=,
which is the answer to the question the shortest-round-trip spelling could have
made awkward.

The whole-component sweep was tried and it stops on one shape. Every entity
opted in at once, regenerated and built, and the build refuses on
=tenor_basis_swap_pay_receive=: a *grouped* entity, whose members sit in an
=identity= or an =audit= group rather than flat. The codec header states no shape
for such a type -- the review of the previous task gated the shape on the three
group flags, because the flat member list the first version stated would have
been wrong for them -- so a type that *holds* one has nothing to recurse into.

So the sweep waits on the grouped shape, which is a template change of its own
kind rather than another opt-in: a grouped entity's shape is one field per group
member (=identity=, =audit=, or the =domain_groups= the entity names), and
recursing into those groups is what the field-group work above just made
possible. The 158 opt-ins are reverted until then; =currency= stays, because its
row is flat.

A second sweep followed the grouped shape, and it stops on two more boundaries,
both worth stating because they are not about carriers:

- **A generated codec unit does not include the codec headers of the types its
  members hold.** This one is now derived, from the columns and the groups a row
  is made of, and it carries a row's recursion to its end. It does not carry a
  *composite message*: =put_counterparty_composite_request= holds
  =csa_eligible_currency=, which no column of the counterparty row names, so the
  message's own field types are the second source the include set needs, and
  they are wired in now. What the sweep still needs is the *path* of a junction
  named from another row: the include came out as =refdata.api/...= rather than
  =ores.refdata.api/...=, so the last step is the junction's component include,
  not another source of types. A junction holding a =csa= recurses into =wire_fields(csa)=,
  which is declared in another header the unit never includes, so the compile
  fails as though the type had no shape. The include has to be derived from the
  member types, which is a template change and not an opt-in.
- **Seven of the component's domain headers are hand-written** --
  =tenor_resolution=, =tenor_basis_swap_long_short_legs=,
  =tenor_basis_swap_pay_receive_legs= and four smaller ones -- so nothing
  generates their shapes; each needs the hand-written treatment
  =dataset_dependency= got in dq.

The grouped shape itself is in the template and unexercised until the sweep can
run: a grouped entity states one field per group member, which is what the
reflector writes for them.

The field groups followed. =cpp_field_group.hpp.mustache= states each group's
shape beside the struct now, from the same iteration that writes its members, and
the group models of both components opt in. Two things about that are worth
keeping:

- The gate leaked the blank line in front of it on the first cut, and rewrote
  twenty-six of trading's headers. That is the same defect the protocol header
  had, in the same place: a mustache section emits no text but the newlines
  around its tags are not inside it. The check is a drift run, not an argument.
- A group is a member and never a message, so it needs the shape and not a codec
  specialisation. The dq suite compares one group's bytes with the reflector's,
  which proves the recursion a convention will rely on.

** The whole component, on the generated path (2026-10-31)

All 178 models opted in: 159 entities, 10 junctions, 9 field groups. That is 501
new files -- a codec header and two codec units per entity, and the protocol
codecs -- plus the component's file list, which is generated from the tree and
had to be regenerated or the new units would not compile at all.

The sweep stopped five times before the component built, and every stop was the
same rule learned once more: the include that makes a member's shape visible.
The last two stops were worth the trip:

- The junction root was spelled without the product prefix. The templates write
  =ores.{{component_include}}/...= and the helpers did not, so the compiler was
  sent to =refdata.api/domain/book_change_codec.hpp=.
- A member named qualified resolved to its plain header while the same member
  named bare resolved to its codec header. Only one of the two spellings carried
  the shape, so a composite request holding =std::vector<domain::csa>= compiled
  as a type with no shape at all.

Both live in one function now, with a test: the two callers had drifted because
they were copies. The name classification reads the model's =#+type:= line
rather than its filename, because a junction called
=ores.refdata.calendar_date.org= has no suffix to go by.

Verified, in this order: =ores.refdata.api.lib= builds with no errors, then
=ores.refdata.api.tests= 83 cases / 598 assertions, then the component's four
suites through ctest, with a database rebuilt for this checkout.

One suite is red and it is not this branch's: =ores.refdata.core='s
curve-configuration round trip loses a =BusinessDayConvention= spelling. The same
case fails on origin/main-based worktrees that hold none of these changes
(prime_origin fails the same two; festive_dijkstra one; merry_newton none), so
the witness is the estate, not an argument.

** The curve-configuration round trip, investigated (2026-10-31)

=ores.refdata.core='s round trip is red on this branch, and it is not this
branch's. The investigation found two defects in the test's own expectation,
both carried in with =bc083d5498= ("Keep one code for a business day convention in
the store"), and neither of them involves a codec.

- =as_stored= assigns the canonicalising helper's =std::string= result into an
  =std::optional<std::string>= member. For a row that states no convention the
  helper answers ="",= so the expectation gains an empty convention where the
  document states none, and the store rightly returns none: "BusinessDayConvention
  was lost". Proved by rebuilding the test with the empty optional preserved --
  the Example_63 case passes and the suite drops to one failure.
- The expectation canonicalises a spelling the store never canonicalises. The
  document says =MF=; =as_stored= maps it to =ModifiedFollowing=; the database
  held =MF=. The defect is in production, not the test:
  =stored_business_day_convention= has exactly one caller in the tree, and it is
  the test. The invariant its own comment states -- "the mapping layer converts
  the stated spelling to the code before a row is written" -- is not implemented,
  and the SQL value guard only refuses a value, it never rewrites one.

So the test asserts behaviour that nothing implements. The remedy belongs to the
story that introduced it: either the mapping layer canonicalises, which is what
its commit says it does, or the test stops expecting it.
