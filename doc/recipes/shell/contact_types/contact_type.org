#+title: How do I run the contact_types commands from the shell?
#+description: Every command the contact_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:contact_types:

This file documents the contact_types resource at the shell, one section per command. Every command is a subcommand of =contact_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 24D553BD-BF92-53CF-B2F1-7E2EBCB579D2
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
contact_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.contact_types.list=.

#+name: contact_types-list
#+begin_src ores-shell :tangle contact_types-list.ores :exports none
contact_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 9A4C9E72-CD41-5B31-AAC1-562B997EEB15
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
contact_types get <code>
#+end_example

It is addressed at =refdata.v1.contact_types.get=.

#+name: contact_types-get
#+begin_src ores-shell :tangle contact_types-get.ores :exports none
contact_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 0DD5E344-1AA6-5EFB-B377-53A105D12ECD
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
contact_types add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.contact_types.put=.

#+name: contact_types-add
#+begin_src ores-shell :tangle contact_types-add.ores :exports none
contact_types add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 00D66F5D-22B3-5902-9BF4-5B58FCC5A2F4
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
contact_types set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.contact_types.put=.

#+name: contact_types-set
#+begin_src ores-shell :tangle contact_types-set.ores :exports none
contact_types set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
