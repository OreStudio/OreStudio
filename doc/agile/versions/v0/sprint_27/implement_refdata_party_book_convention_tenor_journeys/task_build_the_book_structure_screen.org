** What is not done

1. *The rights step is read only.* The server addresses a portfolio right by its code alone (=PortfolioRightKey= holds =right_code=, and the service reads =read_latest_by_right_code=). A grant of a code another account holds would collide, and a removal would reach whichever account's row it found first. The new task "Address a portfolio right by account, portfolio and code" fixes the key.
2. *A history revert is not offered.* The book has no composite-as-of read, and the history panel's field values are display labels, not the book's fields.
3. *Closing a book is not checked against open activity.* The journey document records this as unenforceable until a cross-component read exists. The classification step says so.
4. The tree reads every portfolio and every book on each load.
5. The confirm is two calls when the walk creates a portfolio. A refusal of the book leaves the portfolio written, and the refusal lists it.
