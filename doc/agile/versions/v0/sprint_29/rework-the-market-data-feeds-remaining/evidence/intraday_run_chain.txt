5. Where the chain stops, and why
---------------------------------

The package step asks the reference data service for every family of the
conventions document. The running reference data service does not answer
refdata.v1.commodity_future_conventions.list, so the request times out after
thirty seconds and the run records the timeout on itself.

The checkout's convention family registry names no such family. It names
commodity_future_averaging_terms, commodity_future_contract_terms,
commodity_future_expiry_anchor, commodity_future_off_peak_index and
commodity_future_option_expiry, each with a subject stem of its own. The running
services were built before this branch, so the exporter that runs and the
registry in the tree disagree about the family names.

The engine is therefore not reached in this environment, and the refusal is a
fact about the environment's service versions, not about the report. Nothing in
this branch changed the package step, the workflow, the engine invocation or the
way a run records an engine error.


6. The environment's administrator could not act in a party
-----------------------------------------------------------

The first attempts were refused at the run grant, with

  "The definition's runs act in its own party, and this session is in another."

The cause was a membership of the administrator account in a System Party row
that the parties dataset superseded when it republished the parties earlier the
same day (c52017ac-454a-4bb8-8322-fd2bccbdd6ca, a row no active party matches).
The membership is removed with

  account_parties delete 01a1a19c-e341-79cd-bc13-8b929bccddc6 \
      c52017ac-454a-4bb8-8322-fd2bccbdd6ca system.new_record "<reason>"

and the account then offers the real parties at login, so a run can be triggered
for the entity a definition belongs to. The change is a correction of one
membership row and nothing else.
