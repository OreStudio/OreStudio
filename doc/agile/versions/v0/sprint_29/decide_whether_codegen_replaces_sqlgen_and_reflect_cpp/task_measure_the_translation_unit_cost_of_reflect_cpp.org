* Goal

Numbers for the translation-unit cost of reflect-cpp and sqlgen, and how much of it a generated codec, or a reflect-cpp instantiation confined to one .cpp, removes.

* Acceptance

The measure of success is the total build time of the whole system.

- Baseline: total compile CPU and wall time of a full build without ccache, at the
  build slot's job count, and the peak memory of each file.
- reflect-cpp's share of the total, extrapolated from the time traces of a random
  sample of files, with the sampling error stated.
- The total build time and peak memory after each option: one-time codecs for the
  common types (=decimal=, =tenant_id=, UUID, =audit_record=, time points),
  generated codecs in the per-concern layout, and reflect-cpp confined by =extern
  template=.
- For each option, the job count its peak memory allows within the build slot, and
  the wall time at that job count.

* Notes

- Entities already have one =_json_io.cpp= each (466), so their generated codecs
  add no translation units. Messages have 516 protocol headers and no =.cpp=;
  their encoding is instantiated in each of the 424 files that call the wire
  codec. Generated message codecs add files (about 516 for one each, about 40 for
  one for each component) but remove the repeated instantiation, so the total
  compile CPU of a full build is the number that decides, not the file count.
- In =report_package_handler.cpp= reflect-cpp's time is spread across small types
  used everywhere: =decimal= 6.0 s, =audit_record= 3.3 s, =tenant_id= 3.2 s, and
  7.7 s in reflect-cpp's own templates, against 2.6 s for the largest instrument.
  Those types are instantiated again in almost every file, so a one-time codec for
  them is the cheapest lever on total build time.
- Peak memory per file (up to 3.72 GiB) is what holds the build slot to three
  jobs on eight cores, so lower peak memory shortens wall time beyond the CPU it
  saves.
- reflect-cpp is about a fifth of the total build CPU. Repeated header parsing is
  about a third of a typical file and the backend nearly half, so precompiled
  headers or unity builds, and the optimisation level of tests and generated
  code, are levers on total build time at least as large as the codecs, and they
  stack with them.
- Layout to prototype and measure: one file pair for each concern of each type.
  The type's header holds the plain struct. =_json_io.hpp=, =_msgpack.hpp= and the
  repository's header only declare; their =.cpp= files define the codec or the
  statements and include only their own library (yyjson, msgpack-c, libpq or
  libpqxx). A caller compiles a function call, never a template, and no codec is
  defined in a header. If the file count costs too much, CMake's unity build
  batches the small generated files at build time without merging the sources.
- reflect-cpp's cost sits inside our own wrappers, such as the wire codec's
  =encode<T>=, so attribution by outermost instantiation hides it. The figures
  above are exclusive times: each instantiation less its nested children, and
  the backend's per-function events by the function they name. Module-wide
  optimisation is not attributed, so the shares are lower bounds.
