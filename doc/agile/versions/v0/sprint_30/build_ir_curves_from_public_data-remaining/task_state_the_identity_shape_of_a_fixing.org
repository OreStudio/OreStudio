* Goal

Every family the market data ingest writes states the fields its identity requires and forbids, so a fixing that leaves its index name empty is refused at the writer instead of failing later as a curve that cannot find the series it names.

* Acceptance

- The projection refuses a series whose identity contradicts its stated family, naming the class, the subdivision and the field.
- The IBOR, swap and FX fixing families state the fields they key on, and one seed states each one.
- A provisioned tenant reads the same shapes as the system tenant, holds no copy of them, and reads one rule for the index keys.
- The identities already written contradict no shape they are held to.

* Plan

The shape of an identity is data, one row per field per family, in a table beside
the series classification rules, because the family that a series belongs to is
already data there and a second place to state it would drift from the first. The
key carries the index family as well as the class and the subclass, because
=ir/index_fixing= is an IBOR fixing when the index is =ibor= and a swap fixing
when it is =swap=, and the two are named by different fields: an IBOR fixing
carries an index name, a swap fixing a tenor.

The writer that projects an identity row from an oresmd URI enforces the shape,
because that is the boundary where external data meets the model and the only
point that sees the whole row before it is stored. It fails closed and names the
family and the field, so the message says which series was refused and why. The
backfill, which is a repair, counts the rows it refuses instead of aborting on the
first legacy one, so the rest are projected and the refused ones are named.

A family no row states is projected unguarded and counted. Refusing every family
nobody has declared yet would stop an ingest over a gap in the catalogue, so the
seed states the families the curve and fixing work already creates, and the rest
wait for the family's own task.

A tenant holds no copy of the shapes. It reads the system tenant's rows beside its
own, as it reads the classification rules, so a tenant cannot drift from the system
tenant and a provisioning run has nothing to copy.

A party's curve output is the party's own computation from its own subscriptions,
so it is labelled =IR_CURVE_BOOTSTRAP= and names the party's copy of the config
that computes it, at version 1; it is never =OBSERVED=.

* Notes

The 73 fixing series the classification calls something other than =index_fixing=
are fixtures: every one of them was written by the test DML user with the reason
=system.test=, and all 162 real fixing series classify as =index_fixing=. There is
no classifier defect to fix.

Those fixtures are not served. Each test suite provisions a tenant of its own, named
after the suite and the run, writes its fixtures there, and terminates that tenant at
the end of the run; a terminated tenant admits nobody, because the login reads the
tenant's status before it reads the password. Row-level security answers for one
tenant per session, so no other session reads the rows either.

They were still wrong, and the reason they were wrong is worth keeping: a fixture
wrote a fixing URI and kept the generated series subclass, and the shape guard could
not see the lie, because the shape is keyed on that very subclass. The projector now
refuses an index identity whose series subclass is not =index_fixing= before it looks
a family up, and the fixtures that did this state the subclass their URI implies: one
that writes an FX fixing, one that writes an IBOR fixing, and an FX montage fixture
that called an FX spot series =yield=.

A provisioned party's curve could not be labelled by copying the system's row. The
seed writes every curve output =OBSERVED=, and the curve republish stamps it
=IR_CURVE_BOOTSTRAP= only on its first run, so on 2026-11-16 four LIBOR projection
curves were still observed when Acme was provisioned. The planner now states the
label the republish would stamp: a bootstrap of the party's own config copy, at
version 1. The series table refuses version 0 for a derived series.

The second rebase, on 2026-11-16, brought main's shared-reference read: a tenant
reads the system tenant's catalogues and the provisioner no longer copies them.
The shape copy that this branch added to the provisioner went with the rest. The
shape model now declares the same two flags as the classification rules, so a
tenant reads the system's shapes, and the projector reads them with no change.

* Result

Shipped:

- =series_identity_shapes=, a catalogue of the fields each series family requires
  and forbids, keyed by asset class, series subclass and index family, seeded with
  29 rows over 7 families: FX spot, forward, volatility and fixing, IR yield, and
  the IBOR and swap fixings.
- The identity projector refuses a row that misses a required field or carries a
  forbidden one, and names the family and the field. It also refuses an index
  identity whose series subclass is not =index_fixing=. The backfill counts the
  rows it refuses instead of stopping.
- The shapes are a shared catalogue: a tenant reads the system tenant's rows and
  holds no copy. Shape changes raise events, and the shell has the
  =series_identity_shapes= commands.
- A party's curve output is labelled =IR_CURVE_BOOTSTRAP= at config version 1, so
  Acme provisions its curves.
