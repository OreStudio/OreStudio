* Notes

The premise of the task was wrong. The market file is not empty. Three
other things fail the run, and each one becomes work in the story.

1. *The market configuration names only OIS, overnight indices and FX.*
   ACCOUK's =todaysmarket.xml= holds four collections: discount curves,
   17 overnight index forwarding curves, FX spots and FX volatilities. It
   comes from a hand-authored seed
   (=acme_uk_todays_market_artefact_populate.sql=, written by
   =generate_configuration_data.py=). So ORE answers "did not find object"
   for every IBOR index, equity, commodity, inflation index and credit
   curve. This is 352 of the 416 failures, whatever quotes exist.
2. *The quotes cover FX and IR only.* No equity, commodity, inflation or
   credit series exists under any party, so naming those objects in the
   configuration is not enough on its own.
3. *The fixings file is empty.* Every fixing in the tenant sits under
   =system_party=, and the export writes only the reporting party's
   series. ACME parties receive the system's raw quotes through
   subscriptions, but no fixings.

Smaller causes, each under 30 trades: the credit index products need
basket reference data; seven scripted trades find no script library; five
EquityOutperformanceOption trades have no pricing engine; 14 KnockOutSwap
trades report the GBP OIS convention as not found, although
=conventions.xml= holds it; two commodity strips need a future convention.

70 of the 148 index failures name a ceased LIBOR index (=GBP-LIBOR-3M=,
=GBP-LIBOR-1W=, =USD-LIBOR-3M=). The generator books them. A market cannot
forward a ceased index, so the trades need either a live index or an
ORE IBOR fallback configuration.

One defect was in the export, and this task fixes it. The export reported
every series the session can read as the series it wrote, so the run
logged "Gathered 1280 market data series" for a party that holds 265.
That count is what made an incomplete market look full.

The script's =select-party= line answers "Invalid or expired token",
because the script's =connect= reconnects without the session. The
trigger still runs the definition as its own party, so the run is valid.

* Result

The market file was not empty. ACCOUK's run carried 3,313 FX and IR data
points and no fixings, and 416 of its 460 trades failed. The main cause is
the market configuration: it names only OIS curves, overnight indices and
FX, so ORE cannot find any other object. The export also reported the
tenant's 1,280 series as the party's. That count is fixed, and a test
asserts that a party's export counts only its own series. The story gains
two tasks from these findings: name every object the trades use in the
market configuration, and give each party the fixings of the indices it
trades.
