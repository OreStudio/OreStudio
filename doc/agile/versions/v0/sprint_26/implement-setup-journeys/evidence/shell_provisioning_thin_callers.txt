carries a defect this branch found and did not fix: the seed profile
parameter and step eventing suites inside it had left generated parent
profile rows active, so a second run against the same database failed on a
duplicate code. Their bodies are generated by
cpp_nats_integration_test.cpp.mustache, which seeds a soft-FK parent and
closes only the row under test; the generator names codes from a sequence
that restarts every run, so the leak is what makes the second run fail. The
fix belongs in that template and regenerates 53 files across five
components, so it is captured as its own work rather than carried here. The
run above is against a database whose leftover rows were closed:

mode, so running them needs a fresh database -- 'compass db recreate -y -k'
-- and this environment holds a working deployment the product owner set up.
That run is the story's own last plan step as well as this task's last one,
and it waits on the product owner.
