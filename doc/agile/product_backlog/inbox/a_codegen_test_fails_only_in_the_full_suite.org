passes when it runs alone and fails when the whole suite runs:

Observed on 2026-10-10 in a clean worktree at =origin/main= =629573080a=
with =projects/ores.codegen/venv/bin/python -m pytest projects/ores.codegen/tests -q=:
1 failed, 1314 passed. The same file alone: 8 passed. So an earlier test
leaves state behind, probably in the model index that maps a table to the
model declaring it, and this test reads the stale entry.

* Why

The =codegen-tests= local check is red on every branch, so a real codegen
failure hides behind it, and every pull request has to explain it away.
