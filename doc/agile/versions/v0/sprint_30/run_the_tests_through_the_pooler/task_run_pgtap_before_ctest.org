* Goal

The local gate never runs the =pgtap= check and the =ctest= check at the same
time. Both run =after=("db",)= in =build/scripts/local_checks.py= today, so
they share the fresh database at once, and =iam_tenant_purge_test= deadlocks.

The order to use is =db=, then =pgtap=, then =ctest=: the =ctest= check gets
=after=("db", "pgtap")=. Running pgTAP after ctest instead would put it beside
=ticks-smoke=, which runs after ctest and recreates the database with
=--fresh=. The ordering code ignores a dependency that is not selected
(=all(d not in ids or d in placed ...)=), so a change without the sql class
still runs ctest straight after =db=.

* Notes

- pgTAP rolls back what it writes, so the database ctest gets is the one =db=
  built.
- The pgtap check takes much less time than ctest, so the wall time of a full
  gate grows by about the pgTAP run time. Measure it before and after.
- If the deadlock remains with the checks apart, the cause is in the test
  itself; open a bug-fix task for it.
