* Acceptance

- The ACME provisioning surface states the population's total size and a percentage per asset class, with the seeded values as the defaults.
- The percentages are validated: a mix that does not sum to one hundred is refused, and a class whose count falls under its routed-code floor is reported before the run starts rather than after it fails.
- A provisioning run started from the surface writes a population whose measured mix matches the percentages the operator stated, within the tolerance the weights page sets.
- The knobs reach the generation configs the run creates, so the surface states the mix and the generator still draws it.

* Plan

The surface states a total and a mix; the configs it creates carry them.

A generation config already states =trades_per_book=, which is the count per
book, so the arithmetic between a percentage and a config is the surface's: a
class's trades are spread over the books its configs name, and every config must
still state at least one trade per routed code or the family loses codes it
routes. So the surface computes a count per class from the total and the
percentage, checks it against the class's code count, and states what it did.

Three rules the surface must state rather than discover:

- A mix that does not sum to one hundred is refused before the run starts.
- A class whose count falls under its routed-code floor is reported with the
  smallest total that would fit it, because the alternative is a population that
  silently loses a code — which is the defect the family tasks fixed.
- The tolerance is the weights page's own: a class carries every product it
  routes, so a small class at a small total cannot hit its percentage. The
  surface says so in the numbers it shows rather than refusing the run.

Where it lands is the part this task has to decide by looking: the provisioning
surface is a shell flow today, and the demo's screens read a tenant's books after
the fact. The knob belongs wherever a run is started, so the task starts at the
shell's provisioning commands and the profile's step arguments, and takes the
shortest path that keeps one source for the arithmetic rather than duplicating it
in a screen.
