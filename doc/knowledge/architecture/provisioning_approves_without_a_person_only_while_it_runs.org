#+title: Provisioning approves without a person only while it runs
#+description: Provisioning turns the tenant's auto-approval on for its own publishes and turns it off when the run ends, whether the run completes, fails or is abandoned.
#+type: knowledge
#+level: cross
#+filetags: :architecture:approval:auto_approval:provisioning:
#+created: 2026-11-11
#+updated: 2026-11-11

* Summary

Provisioning publishes a tenant's own sets, such as each party's curves, before the tenant has the people who decide them. So it turns the tenant's approvals mode to =auto_approved= when it starts its publishing steps, and turns it back to =enforced= when the run ends, whether the run completes, fails or is abandoned. A tenant is never left approving without a person because a run stopped.

* Detail

** The window

The provisioning profile's first step that needs a decision turns the mode on, with the reason that provisioning runs without waiting on approvals ([[id:6014CFE1-D978-4ABA-BBA9-D87040FE44BA][The acme_demo profile is ten ordered steps, and the steps are data]]). The run's end turns it off. The end is the last step of a completed run and the failure or abandonment of any other: the workflow that runs the profile turns the mode off as part of closing the run, as it closes every other state the run holds open.

** What it covers

Every request the run raises closes under the =tenant= rule ([[id:71146F3F-B884-4E61-BA8B-A8A0731703C6][A request closes without a person only under a stated rule]]) and names it. A request a person raises in the tenant during the window closes the same way, which is why every screen shows the mode while it is on.

** After the run

From the end of the run, a person decides every request, unless the tenant's administrator states otherwise with a reason.
