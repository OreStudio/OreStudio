#+title: Story: Silence the configure warnings on the site and macOS builds
#+description: The doc-only site configure prints six unused-cli warnings, because the linux-doc-only preset inherits vcpkg and compiler variables that a configure with ORES_VCPKG_ENABLED=OFF never reads: without the toolchain there is no dependency discovery, and without the C++ build configuration there are no compile rules. Two further warnings come from vcpkg's own ports and are out of scope.

* Decisions

- *A doc-only configure must not inherit the compiler variables.* CMake reports
  a variable as unused when nothing reads it. With =ORES_VCPKG_ENABLED=OFF= the
  toolchain file is never loaded (CMakeLists.txt:29) and the C++ build
  configuration is skipped entirely (CMakeLists.txt:308), so the four vcpkg and
  find-path entries have no reader, and with no compile rules the generator has
  no use for =CMAKE_EXPORT_COMPILE_COMMANDS=. The five move to a hidden
  =compiler-configuration= mixin that the eighteen compiling presets inherit.
- *The doc-only preset also drops the make mixin.* =CMAKE_COLOR_DIAGNOSTICS= is
  read only when diagnostics are emitted, so a configure that compiles nothing
  reports it as unused too. The preset names its generator directly instead, so
  the make mixin keeps its colour settings for the presets that compile.
- *The plist variable names were simply wrong.* =Info.plist.in= read
  =PROJECT_MAJOR_VERSION=, =PROJECT_MINOR_VERSION= and =PROJECT_PATCH_VERSION=.
  CMake sets =PROJECT_VERSION_MAJOR= and its siblings from
  =project(OreStudio VERSION 0.0.28 ...)=. Nothing set the names the template
  used, so both version fields in the macOS bundle plist rendered as =..=.

* Out of scope

- The vcpkg port warnings: boost-system's build-path length warning on Windows
  and libarchive's unused =CMAKE_REQUIRE_FIND_PACKAGE_MbedTLS= on macOS. Both
  are emitted by ports inside the pinned vcpkg submodule.
