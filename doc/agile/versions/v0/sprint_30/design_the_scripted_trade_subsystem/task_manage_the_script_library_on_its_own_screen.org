* Goal

A person browses the script library on a screen of its own: each script with its variants, inputs, results and code, each version of it and which trades are booked on it; and a tenant's administrator publishes the tenant's own script there, seeing the parser's diagnostics and the warning on a name the world library holds.

* Acceptance

- ores.http serves the scripts, the version history of a script, the state of any version and a tenant's publish, as JSON routes over the trading service's operations
- the BFF serves the same under /api/trading/scripts, with unit tests of each route
- the screen lists the scripts of the world library and of the tenant, marks a tenant script that shadows a world script of the same name, and shows a script's variants, inputs, results and code read-only
- the screen shows a script's versions and the rows of any version, and the trades booked on each
- a publish shows the diagnostics located by line and column, and refuses a script with an error
- a publish names the version it edited, and a publish over a newer version is refused as a conflict rather than writing
