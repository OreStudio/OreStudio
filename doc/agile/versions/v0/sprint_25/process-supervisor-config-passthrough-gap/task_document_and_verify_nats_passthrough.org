A future engineer adding a new shared NATS knob only has to touch .env and the mapper's fixed prefix list -- never five other files.

* Acceptance

- Knowledge doc reflects the new architecture; a new test_scenario or automated test demonstrates a passthrough knob reaching a service via .env only.

* Plan

Audit what the fallback tier already shipped on main (the mapper
fallback-tier task, the parser consolidation, the systemd/shell
threading strips) against what the task's two deliverables still need:

1. *Doc*: =nats_wire_format.org= mentioned =ORES_NATS_WIRE_FORMAT=
   only in passing; no doc described the config-flow at all. The old
   five-layer threading (controller-launch argv, C++
   =default_args_template=, SQL =args_template= rows, Qt client launch,
   shell =flag_for= + .env mirror) lived only in the story. Add a
   "Config flow" section describing the single-source-of-truth design:
   shared knobs set once in .env, two edits to add a knob (env_init.py
   emission + register_shared_domain suffix), the allowed-suffix
   contract, the deliberate exclusions (TLS trio, shell mirror,
   app-prefix precedence), and where the regression tests live.
2. *Regression test*: the mechanism-level tests already exist
   (config_nats_configuration_tests.cpp: shared-var resolution + TLS_CA
   exclusion) and service parser tests only proved the blanking
   direction (defaults with env stripped). Add the missing positive
   proof at the real service-parser level: a shared =ORES_NATS_URL=
   set in env reaches =ores.iam.service='s parser with empty argv.

No code changes to process_supervisor, SQL args_template rows, or
systemd_generate.py — verification confirmed they need none.

* Result

Shipped in the feature/document-and-verify-nats-passthrough branch
(commit range ff33b0595..HEAD, PR to follow):

- =doc/knowledge/architecture/nats_wire_format.org=: new "Config flow:
  shared NATS knobs reach every service from .env alone" section
  documenting the single-source-of-truth design — the collapsed
  five-layer passthrough, the two-edit contract for adding a shared
  knob, the =environment_mapper_factory= shared-domain fallback
  mechanism, the allowed-suffix scope, the deliberate exclusions (TLS
  trio CLI-supplied, shell's own ORES_SHELL_NATS_* mirror, app-prefix
  precedence), and pointers to the regression tests.
- =ores.iam/service/tests/config_parser_tests.cpp=: new
  =shared_nats_env_var_reaches_service_without_argv= test — a shared
  =ORES_NATS_URL= set in the environment reaches the real service
  parser's =nats.url= with zero argv, proving the passthrough contract
  end to end through =standard_service_options::parse()=.

Acceptance met: the knowledge doc reflects the new architecture, and
