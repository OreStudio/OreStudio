#+title: How do I run the pricing_model_configs commands from the shell?
#+description: Every command the pricing_model_configs submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:pricing_model_configs:

This file documents the pricing_model_configs resource at the shell, one section per command. Every command is a subcommand of =pricing_model_configs=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: D51AE36E-9BE0-57BA-8F41-BEF600C17096
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
pricing_model_configs list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =analytics.v1.pricing_model_configs.list=.

#+name: pricing_model_configs-list
#+begin_src ores-shell :tangle pricing_model_configs-list.ores :exports none
pricing_model_configs list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: F06D5E3D-9FC2-51B3-BDBA-0BBAAA59DCE8
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

It is addressed at =analytics.v1.pricing_model_configs.get=.

#+name: pricing_model_configs-get
#+begin_src ores-shell :tangle pricing_model_configs-get.ores :exports none

#+end_src

** =add=
:PROPERTIES:
:ID: 02337CA7-A9C0-5D2B-8F4E-FC23DBACCA2C
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
pricing_model_configs add <id> <name> <description> <config_variant> <reason> <commentary>
#+end_example

It is addressed at =analytics.v1.pricing_model_configs.put=.

#+end_src

** =set=
:PROPERTIES:
:ID: 7E750329-3FBB-5B70-8379-09BF970923F2
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
pricing_model_configs set <id> <name> <description> <config_variant> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =analytics.v1.pricing_model_configs.put=.
