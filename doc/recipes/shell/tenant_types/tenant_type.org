#+title: Tenant Types shell commands
#+description: Every command the tenant_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tenant_types:

This file documents the tenant_types resource at the shell, one section per command. Every command is a subcommand of =tenant_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: CACC757A-3820-5692-A7FB-20B9CCB1842C
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tenant_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =iam.v1.tenant_types.list=.

#+name: tenant_types-list
#+begin_src ores-shell :tangle tenant_types-list.ores :exports none
tenant_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 1DE72809-4F71-5292-866B-B3B5182BEB55
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

#+end_example

It is addressed at =iam.v1.tenant_types.get=.

#+name: tenant_types-get
#+begin_src ores-shell :tangle tenant_types-get.ores :exports none
tenant_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: C7454CE6-7586-5DB0-A264-139937449C37
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tenant_types add <type> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =iam.v1.tenant_types.put=.

#+name: tenant_types-add
#+begin_src ores-shell :tangle tenant_types-add.ores :exports none
tenant_types add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 6780E2FF-B89B-5247-81CA-C40367F289EE
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
tenant_types set <type> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =iam.v1.tenant_types.put=.

#+name: tenant_types-set
#+begin_src ores-shell :tangle tenant_types-set.ores :exports none
tenant_types set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
