* Plan

An ORE PortfolioId is a portfolio's name, and a portfolio's natural key is its
party and name, so the import resolves each id by name among the importing
party's portfolios and rejects a trade whose id names none, as it does a
counterparty or netting set that resolves to none.

- =trade_portfolio= (trade, ordinal, portfolio) is a trade component keyed by
  the anchor with a database foreign key, its party pinned to the anchor and
  to the portfolio, so a trade is reported only in its own party's portfolios.
- The ORE sample portfolios PF1 and PF2 are the dataset =ore.sample_portfolios=
  with its own methodology, published by the artefact type =named_portfolios=.
  It reuses the portfolio staging table, but its publish adds top-level
  portfolios by name to a party that already has portfolios, which the
  portfolio tree publish refuses to do. The bundle =ore_sample_netting= becomes
  =ore_samples= and carries it.
- The import resolves PortfolioIds before it books, writes =trade_portfolio=
  rows after, and writes no envelope rows at all.
- The export reads a booked trade's PortfolioIds through
  =ores_trading_trade_portfolio_names_fn=, which runs as the owner for the same
  reason as the envelope names function.
