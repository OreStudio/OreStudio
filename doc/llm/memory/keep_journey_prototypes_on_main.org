#+title: Keep journey prototypes on main
#+description: An accepted prototype stays on main as the design record, as plain static files under doc/prototypes/; React is for the product, never for a prototype.
#+type: memory
#+memory_subtype: feedback
#+level: cross
#+filetags: :web:prototype:journeys:memory:feedback:
#+created: 2026-10-05
#+updated: 2026-10-06

An accepted prototype merges into main and stays there as the design record.
It is plain HTML, CSS and JavaScript under =doc/prototypes/<name>/=, it is
listed in =doc/prototypes/index.org=, and the site build publishes it. React is
for the product.

*Why:* Two mechanisms grew. The first was static pages under =doc/prototypes/=.
The second was React routes in =ores.web=, added on 2026-10-06. The React form
needed the application's shell, its build and its types, so a prototype could
not open without running the app, could not deploy with the documentation,
drifted with the product, and left two inventories that disagreed. The
operator's words: "we want it to be quick".

*How to apply:* Add a prototype as plain files under =doc/prototypes/<name>/=,
copy the design tokens from
=projects/ores.web/packages/web/src/styles.css=, add a row to
=doc/prototypes/index.org=, and wire one =ores-deploy-web-app= call in
=projects/ores.lisp/src/ores-build-site.el=. Do not add a prototype route to
=ores.web=: React is for the product. =build/scripts/check_prototype_inventory.py
--check= fails when a prototype is missing from the inventory. The empirical
apparatus of compass-method-prototype is still thrown away.
