* Plan

Every reader of a stored quote URI must move in the same change as every writer:
a URI the new codec writes is one the old parser cannot read, and the seeds hold
URIs too. So the cut-over is two PRs, each one green on its own.

1. *Readers and writers move together.* The import, the export, the
   classifier's inputs, the feed ingest loop, the curve republish service, the
   curve pillar reader and the two synthetic feeds read and write quote URIs
   through =ore_key_codec= and =oresmd_uri_codec=. The SQL seeds that hold
   quote URIs (the FOMC series, the FX driver rates, the deposit rates and the
   synthetic curve configs' vintage series) are rewritten in the new form. The
   API gains one operation: a datum built from a series and its coordinate
   values, which the curve republish and the synthetic curve feed need where
   they used =with_point=. A reversed FX pair is reported and stored corrected.
   Fixings keep the old grammar, as the story's decision 9 allows: an index is
   not a quote.
2. *The raw key goes.* =market_observations.key= is dropped through the model
   and regenerated; the corpus tests compare values by key, read the =MD_*= and
   =FD_*= files, and share the production tokeniser.

Recreate the database and re-import; write no migration.

* Notes

See [[id:6D60C52C-26B9-416B-A453-478EE5CA33C5][the 2026-10-02 review]], section 2, "The ORE export echoes the input text" and "The corpus
import compares values without their keys".

** Part 1: the readers and writers

Done in the first PR. Each consumer now reads and writes quote identities
through the two codecs, and the SQL seeds hold the new form.

- *A row holds one identity.* The import stores the datum URI and the
  canonical key of that datum, never the file's own text. The export writes
  every key from the stored URI, so it no longer reads the =key= column at all.
- *A reversed FX pair.* The FX convention checker is applied to the datum's two
  currencies, for an FX spot rate only, as before. The row holds the corrected
  pair, and the import reports it.
- *Classification.* The rule table is keyed by the key's first token, its
  quote token and, for a correlation, its two indices. All three now come from
  the datum, so the shape table's decomposition is not read.
- *Fixings stay on the old grammar.* An index is not a quote, and the story's
  decision 9 keeps fixings and curves on the richer contract. The export tells
  the two apart: a series URI the datum codec reads is a quote series.
- *Series plus point.* The curve republish and the synthetic curve feed built
  a datum from a series and a pillar point through =with_point=. The API now
  has =datum_at= and =datum_at_point= for that, with no per-type code.

** Two behaviour changes

- *The spot pillar key.* =make_pillar_quote_key= wrote
  =IR_SWAP/RATE/USD/0D/1D/20260319= for a pillar that starts at spot: a
  period start with a date end. ORE refuses it ("Expect swap quote with
  start/end as either periods or dates", checked with the catalogue harness),
  and the strict codec does too; the old grammar accepted a key ORE cannot
  read. A spot pillar is now =0D= to the days its end lies after spot, such as
  =50D=, which ORE reads as the same swap. This keeps one spot series across
  days. Writing the spot date instead would be ORE-valid too, but would make a
  new series every day.
- *Currency case.* The old grammar upper-cased a currency, so
  =FX/RATE/gbp/jpy= became =GBP/JPY=. The datum model keeps every token as ORE
  wrote it, and ORE does not change it either, so the lower-case key is now its
  own series and no respelling is reported. An alias such as =FX_SPOT= is still
  respelled and reported.

** What part 2 holds

=market_observations.key= still exists and holds the canonical key; part 2
drops it through the model. The corpus tests already compare by canonical key;
part 2 adds the =MD_*= and =FD_*= files and the shared tokeniser. The import
still passes the shape registry to the tokeniser, which fills decomposition
fields nothing reads now; the retire task removes both.
