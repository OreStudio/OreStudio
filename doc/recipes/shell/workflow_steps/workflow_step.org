#+title: How do I run the workflow_steps commands from the shell?
#+description: Every command the workflow_steps submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:workflow_steps:

This file documents the workflow_steps resource at the shell, one section per command. Every command is a subcommand of =workflow_steps=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: E3C4FCB1-3577-5E60-A884-E83710192B6B
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
workflow_steps list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =workflow.v1.workflow_steps.list=.

#+name: workflow_steps-list
#+begin_src ores-shell :tangle workflow_steps-list.ores :exports none
workflow_steps list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 079FD459-E03F-56CF-8AD1-9DF33CAE5239

** =add=
:PROPERTIES:
:ID: 4303D366-1326-5A2F-A1AA-19AC147FCF18
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.

** =set=
:PROPERTIES:
:ID: F78F75E8-127D-5862-80A0-4A00336E3CDE
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.
