* Acceptance

- conventions_bundle, conventions_bundle_row and conventions_apply_result are declared in ores.refdata.api.
- ores.ore.core includes no ores.refdata.core header and links no ores.refdata.core library.
- Refdata's stage, commit and apply path and the ORE conventions import still pass their suites.

* Plan

The header held three payload structs and a service that needs a session. The
structs are the contract between a caller that reads an ORE document and the
service that applies the rows, so they move to
=ores.refdata.api/messaging/conventions_bundle.hpp=; the service stays where the
database is, and re-exports the names it works with.

The codec then includes the api header alone, and its family units name
=refdata::messaging::conventions_bundle= rather than the service namespace. The
dependency block drops =ores.refdata.core= and the story's Notes lose one of the
six.

The removal also exposed a test helper that read its stream through a
transitive include, which is now stated.

* Result

Merged as #3997. The three payload structs are in
=ores.refdata.api/messaging/conventions_bundle.hpp=, the service stays with the
database and re-exports the names, and the codec names the bundle through the
messaging namespace.

The codec now declares eighteen ORES libraries where it declared nineteen, and
=refdata.core= is gone: refdata appears only as its api. The four affected
suites pass, and both touched components regenerate to exactly what is
committed.

The removal also exposed a test helper that read through a transitive include,
which is now stated, and an environment whose database lacked the equity
underlying table and its grants; both were repaired, the second by applying the
create script and the grants the schema's setup would have given it.
