* Result

The shell reads a run's reasons and its whole job chain.

- `report_instances list` and `report_instances get <name>` state the run: its
  state, times, party, output message and output storage key.
- `report_error_events list` and `report_error_events
  by-report-instance-id <id>` return the run's reasons with scope, severity,
  subject, subject id, detail and time.
- `report_error_scopes list` returns the catalogue the reasons are grouped by.
- `batches`, `workunits by-batch-id <id>` and `results by-workunit-id <id>`
  carry the job chain, down to the result's outcome and error message.

Proven against a triggered Board Risk run. Instance =944fc6e3= recorded 33
errors; `by-report-instance-id` returned them (scope =Trade=, subject =trade=,
the missing mandatory id in the message, the exception type in the detail), and
the chain answered: instance to batch =89c05351=, batch to workunit
=1d4931f8=, workunit to result =cbc2a3e7= with outcome 3 and the engine's
message.

Two defects made this impossible before. Nothing registered the generated
=report_error_event= or =report_error_scope= command units, so every recipe for
a run's errors aborted with "Wrong command". The reporting service subscribed
only the counts read, so even a registered command reached no responder. Both
are fixed, and every reporting unit is registered now: 187 units across refdata
and reporting, with ores.reporting added to the composition check so an
unregistered unit fails the gate rather than a person's session.
