#+title: How do I run the counterparties commands from the shell?
#+description: Every command the counterparties submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:counterparties:

This file documents the counterparties resource at the shell, one section per command. Every command is a subcommand of =counterparties=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 9F8FE01A-2327-569E-8880-24E6F7030A2C
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
counterparties list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.counterparties.list=.

#+name: counterparties-list
#+begin_src ores-shell :tangle counterparties-list.ores :exports none
counterparties list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: FACCA85D-3955-5219-8D34-5BF2F87007FA
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

#+end_example

It is addressed at =refdata.v1.counterparties.get=.

#+name: counterparties-get
#+begin_src ores-shell :tangle counterparties-get.ores :exports none

#+end_src

** =add=
:PROPERTIES:
:ID: D686FDC0-D892-5D23-9203-EB988465E2D0
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
counterparties add <id> <short_code> <full_name> <transliterated_name> <party_type> <parent_counterparty_id> <business_center_code> <status> <image_id> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.counterparties.put=.

** =set=
:PROPERTIES:
:ID: 6C4699F9-AB27-53C7-8961-E21CB789776B
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
counterparties set <id> <short_code> <full_name> <transliterated_name> <party_type> <parent_counterparty_id> <business_center_code> <status> <image_id> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.counterparties.put=.
