This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

A party's fixings manager enters a fixing for one of the party's trades on a day
the platform never stated, with the reason for it. The screen lists the days of
each index the party's trades float on, marks the ones no series holds, and takes
the value, the reason code and the explanation. The entry joins the controls the
fixing process already states — authorise, override, unauthorise, undo — so an
entry a second person has not authorised does not fix a trade.

* Why

A derived term index publishes nothing while the currency's overnight curve feed
is stopped, and it makes up no day when the curve returns: repeating the last
value would claim something about a day nobody observed, and backfilling would
rewrite a history the provider has no right to rewrite. The hole is permanent in
the system's own series, and only the party can close it: its trades fix on what
its operations decide, with an explanation, under the party's own approvals.
Without this screen the hole reaches the risk run as a missing index and the
run stops.
