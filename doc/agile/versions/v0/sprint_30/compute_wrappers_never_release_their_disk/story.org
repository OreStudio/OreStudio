* Goal

Each compute wrapper keeps one unpacked copy of each engine version, and it
removes the folder of a job that is older than a configured age. A developer's
disk then stays bounded however often the database is recreated and however
many jobs run.

On 2026-11-20 the disk of the development machine filled to 0 bytes free.
Postgres and git both failed. The wrapper run folders of all worktrees held
about 320 GB. Two leaks cause this:

- The wrapper caches an engine under =packages/<app_version_id>/=. The seed
  =compute_ore_app_seed.sql= makes that ID with =gen_random_uuid()=, so each
  database recreate gives the same engine a new ID, and each wrapper downloads
  and unpacks it again. The wrapper also keeps the downloaded =.tar.gz=.
- The wrapper unpacks each job into =jobs/<result_id>/= and never removes it.

* Acceptance

- One engine version has the same app version ID after every database
  recreate, and a wrapper reuses its unpacked package after a recreate.
- A wrapper keeps no downloaded package archive after it unpacks it.
- A wrapper removes job folders older than a configured age, and the default
  age is stated.
- The size of the wrapper folders is measured before and after, on the same
  workload.
