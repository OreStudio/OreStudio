#+brief: One report trigger, on demand or scheduled, that admitted a report run.
#+created: 2026-10-14
#+updated: 2026-10-14

One row per report trigger. A trigger is how a run is admitted, and it is of two
types: a person asks for the run now, or a schedule asks for it later. The
scheduler does not write this table. Its job publishes a trigger event, and the
reporting service records the trigger here and admits the run, so both types
reach the same handler and differ only in the payload.

The rows are append-only, so the model states =:current_state:=: an event is a
fact about an instant, and the bi-temporal pair has no meaning on it. A
current-state immutable table has no audit tail, so the actor and the time are
columns of its own and there is no version and no validity window. The table is
plain, not a hypertable: =ores.iam.auth_event= is one because logins are high
volume, and triggers are a handful a day.

:PROPERTIES:

The scheduler job that fired, when the type is scheduled. The scheduler owns

uuid because the job definition's key is one, and because the same reference on
ores.reporting.report_definition is spelled scheduler_job_id and typed uuid.

Report trigger types are a system-wide lookup seeded for the system tenant only,
so the check reads that tenant whatever tenant owns the trigger.

** scheduler_job_id
:PROPERTIES:
:table:               ores_scheduler_job_definitions_tbl
:use_no_tenant:       true
:target_no_validity: true
:nullable:            true
:error_message:       Invalid scheduler_job_id: %. No scheduler job definition found with this id.
:END:

The scheduler owns its job definitions, so this is a soft foreign key validated
here rather than a database constraint. Its table is hand-written and carries no
validity window, so the check names its id alone. The key is a uuid, which is
what the scheduler declares its job definition's id to be.

** schedule_job_run_id

:nullable:            true

:END:

The scheduler owns its job instances, so this is a soft foreign key validated
here rather than a database constraint. Its table is hand-written and carries no
validity window, so the check names its id alone. The key is a bigint, which is
what the scheduler declares, so this reference is typed bigint and not uuid.
