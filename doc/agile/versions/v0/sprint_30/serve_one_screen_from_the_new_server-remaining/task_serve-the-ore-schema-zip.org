* Acceptance

- The C++ server answers =GET /api/reporting/ore-files/:code/schema?version== at
  the BFF's path, with the BFF's member names and status codes.
- The answer is a zip of the schema and every schema it includes, at the engine
  version asked for.
- A missing include is a 404 that names what is missing, and not a partial zip.
- The route states no cache: the schema is read from the store per request.
- A test proves the route against the answer the BFF gives.
- The route names its C++ equivalent in the inventory.
- The local gate is green.

* Plan

Branch =feature/serve-the-ore-schema-zip=.

The route joins two reads: the catalogue entry that is a schema with this code,
and its stored contents at the version asked for. The includes are read from the
contents and not guessed.

The route is a composed view in the inventory, and it keeps the obligation that
kind carries: the owner, the computation and the cache policy it states.
