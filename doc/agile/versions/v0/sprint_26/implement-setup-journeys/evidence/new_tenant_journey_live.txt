The New tenant journey, walked in a headless browser
====================================================

Walked on 2026-09-29 against the running deployment (fleet up, a tenant of its
own, signed in as super_admin through the BFF), with the web bundle built from
this branch and served by ores.web.service. The rail, the starting points, the
form and the review below are the page's own text, read out of the DOM after
each step; the screenshot beside this file is the first step.

The route
---------

  GET http://127.0.0.1:21402/tenants/new  ->  200

The shell renders it for a signed-in person, and the guard sends a visitor to
sign in rather than to it (covered by AppRoutes.test.tsx).

What this proves
----------------

The journey is a route of its own on the shared runtime: one flat rail of the
five tenant steps, the starting points read from the server, the form built
from the chosen profile's declared parameters, the shared password field
enforcing the deployment's policy, and the review summary before anything is
created.

What it does not prove
----------------------

The run itself was not walked to its end here: the walk stopped at the review,
because the tenant name, code and hostname are typed by hand for the
operational starting point and this driver did not fill them. Creating a tenant
runs the provisioning steps for minutes and is covered by the journey's own
tests -- the create action sends the request, and the hand-over signs out and
in -- and by the shell recipes the previous task ran from empty installations.
