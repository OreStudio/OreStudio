* Goal

Give every convention term the contract documents a value set, so a convention screen draws the control from data, as product pricing does. The set follows from the type the ORE parser gives the term, and a catalogue is used only where it holds the values the seeded conventions use.

* Acceptance

- Every convention term the contract documents is linked to one value set, and no term takes two.
- A business day convention, a day counter and a currency draw on the refdata catalogue of their kind; a value an ORE parser maps takes that parser's list, each string with the word it means; a flag, a whole number, a number and a period take their type's set.
- A catalogue is used only where the seeded conventions' values are in it, measured, and every exception is recorded.
- No pricing set, value or link changes, and a gate fails when the committed script differs from its sources.

* Plan

1. Read each parser's own map from =parsers.cpp=: the strings it accepts and the enumerator each one means.
2. Measure, across every convention table, how many distinct values of each kind a catalogue would refuse, before choosing a catalogue.
3. Write the convention sets and links in their own module, and merge them after the pricing links are resolved, so the name fallback in =resolve= never reaches them and pricing stays as it is.
4. Gate the populate script with =--check=.

* Notes

- *A calendar is text.* ORE reads a joint calendar such as =US,MWK= and a currency code such as =JPY= as a calendar, and the refdata calendar catalogue holds 28 of the 254 calendar values the seeded conventions use. A catalogue would mark good conventions as invalid. A calendar set needs ORE's calendar grammar, not a list.
- *Two currency fund codes are missing from refdata.* =MXV= and =CLF= are ISO 4217 codes that conventions use and the currency catalogue lacks, so a screen marks those values until refdata holds them.
- *The pricing type extractor misses these parsers.* =extract_parameter_types.py= looks for =const std::string&=, and =parsers.cpp= writes =const string&=, so it reads no map of =parseFrequency=, =parseCompounding= or the rest. The convention extractor reads both. The pricing extractor is unchanged, because a fix would change the pricing sets.
- *No write is checked yet.* The value check guards only the pricing parameters. Refusing a bad value in a convention needs the map from a refdata column to its term, which is [[id:F8CA3B52-F299-4A92-84A0-CF4F9A2694F0][Move the convention kind metadata into data]].
- *An index is text.* No catalogue holds ORE's index names.

* Result

Every convention term the contract documents now has a value set. 238 terms are linked to 16 sets, and the populate script grew from 520 to 846 rows with no pricing row changed.

- =convention_value_sets.py= chooses each set from the type the ORE parser gives the term: a business day convention, a day counter and a currency draw on refdata catalogues, which the conventions' values were measured against; a frequency, a compounding rule, a date generation rule, a month, a weekday and the option enums take the parser's own map, each string labelled with the word it means; a flag, a whole number, a number and a period take their type's set; a calendar, an index and any other term are text.
- The extractor now reads each parser's map and the enumerator each string means; the generator merges the convention sets after the pricing links are resolved, and refuses a code or a link that pricing holds.
- The new =ore-parameter-value-sets= gate fails when the committed script differs from its sources.

The calendar stays text because the refdata calendar catalogue holds 28 of the 254 calendar values the seeded conventions use. Two currency fund codes, MXV and CLF, are missing from refdata. No write is checked yet: that needs the column-to-term map of the next task.

The local gate passes both generator checks, the database recreate and the ticks smoke test. Four checks fail on what this change does not touch, as on the previous PR: =er-diagram=, on warnings of the strict validator; the build, where =messaging_trade_origin_handler_tests.cpp= calls a =trade_operations_handler= constructor that no longer exists; =ctest=, on that trading suite and on =ores.analytics.core.tests= and its value set refusal; and pgTAP, on the XPath test's 108 pricing code settings and the trading anchor tests.
