Why the direct command, and not `compass build`
------------------------------------------------

`./compass.sh build` was run first, and it failed before reaching the
compiler:

    systemd-run --user --scope -q --collect ... cmake --build --preset ...
    Failed to connect to user scope bus via local transport: No data available

The wrapper cannot run in this session. This session's commands execute inside a
bubblewrap sandbox with an unshared PID namespace -- /proc/1/comm inside it is
`bwrap`, and /proc/self/ns/pid is not the host namespace -- so systemd-run
cannot reach the user manager. The manager itself is present on the machine:
/run/user/1000/systemd exists and `busctl --user list` shows
org.freedesktop.systemd1. The two commands are the same command: compass runs
`cmake --build --preset linux-clang-debug-make -j 3`, and
build/output/linux-clang-debug-make is that preset's binary directory. The
direct run is recorded because it is the only form the environment allows, not
because it is a different check.
