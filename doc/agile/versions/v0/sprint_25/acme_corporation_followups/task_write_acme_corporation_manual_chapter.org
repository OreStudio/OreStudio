* Goal

Barclays Plc has served, until now, as ORE Studio's realistic
demo/test entity for manual walkthroughs and screenshots. Acme
Corporation -- a synthetic four-legal-entity holding group
(Group/UK/US/HK) -- is replacing it. Write a user-manual chapter that
introduces Acme Corporation as the system's reference entity: its
holding-group structure (parent plc plus three operating companies),
the business units, portfolios, and books seeded under each operating
company, its staff/accounts, and the demo logo attached to one of the
real GLEIF counterparties it trades with (see [[id:21C9CA52-3515-4D99-9B95-1F5BA8A05DCD][Attach a logo/image to a
counterparty]]). The chapter should let a new user provision Acme
Corporation (=provision tenant --source acme=) and understand what
they are looking at once it is up.

* Plan

Followed the =doc-add-entity-chapter= skill, adapted for a narrative
overview rather than a single codegen entity: same thesis structure
(Abstract, Overview, domain-concepts section, body sections, segued
throughout, Conclusion, See also), but the body sections cover the
holding-group structure, staff, and a worked counterparty example
instead of a list-window/detail-dialog/history/shell-CLI walkthrough.

Domain-knowledge sources (confirmed with the user before drafting,
per the recipe's step 0): the =Trading Structure= modelling note
(=projects/ores.refdata/core/modeling/trading_structure.org=) for the
organisational/portfolio hierarchy model, plus the =acme_corporation=
and =acme_corporation_structure_analysis= dataset_overview.org docs
for the actual shipped structure (four legal entities, business
units, 58 staff accounts, LEIs). Cross-checked the analysis doc's
proposed shape against the actual generated =companies.json=/
=business_units.json=/=accounts.json= data, since the analysis
predates and partially diverges from what shipped (e.g. entity
naming, UK entity's broader global-desk structure).

Scaffolded via =compass add manual=, wired into =user_manual.org=
(Getting Started part, after Provisioning from the Shell -- this
entity is what every later chapter's screenshots point at) and
=user_manual_site.org=. Six =[SCREENSHOT NEEDED]= placeholders
inserted: Parties window (4-entity hierarchy), Org Chart window
(staff reporting lines), CounterpartyDetailDialog (Barclays PLC demo
logo), and the tenant-wizard's Acme-vs-Manual choice step.

One id-link (to the Trading Structure note, outside doc/manual/)
broke the PDF export -- =compass add manual='s own warning about
this was right; switched it to a plain GitHub blob URL, matching how
the shell-provisioning recipe cross-reference is already handled.

Along the way, hit a pre-existing, unrelated
=validate_schemas.sh= warning (=TEMPORAL_004= on
=ores_compute_app_version_platforms_tbl=) while confirming a clean
build; added it to =validation_ignore.txt= under the existing
"lightweight junction tables" exception category (same pattern as
=ores_dq_dataset_dependencies_tbl=) rather than bolting on an unused
version column, per user instruction to fix it as part of this task.

** Screenshot capture and scope revision (round 2)

Ran the =doc-run-manual-screenshots= flow: DB recreate, Acme
Corporation provisioning, test scenario, QA Validation Runner. 2 of
4 planned screenshots captured cleanly (Parties window, Org Chart);
2 were dropped by user decision during the run rather than captured
-- see the scenario doc's =* Notes= and its steps 4/5 Results:

- The Barclays PLC counterparty logo screenshot -- and the whole
  chapter section describing it -- dropped. User: "lets not do the
  barclays logo."
- The tenant wizard's Acme-vs-Manual screenshot dropped: the QA
  Validation Runner cannot screenshot QWizard dialogs (not MDI
  windows). Kept the choice described in prose instead of working
  around the modality gap with a manual desktop capture.

User then asked for a substantially larger rework than the original
scope: drop all Barclays/historical framing from the chapter (present
Acme directly, not as "replacing" anything); add a detailed
Departments and segregation of duties section (front office, Middle
Office, Market Risk -- what each does, headcounts, and which seeded
RBAC role each department's accounts actually hold, grounded in
=accounts.json='s real =job_title=/=role= fields, not invented);
and separate the two provisioning use cases (Acme quick-start vs.
building your own organisation) across chapters. Scoped this with the
user via AskUserQuestion into: (1) update =chapter_initial_setup.org=
and =chapter_shell_provisioning.org= now, since both have real,
undocumented drift (the wizard's Welcome page already offers the
Acme/Manual choice; the shell chapter's worked example demoed an
unrelated, confusingly-similarly-named synthetic "Acme Corp" tenant);
(2) leave 5 other chapters with real Barclays UI screenshots
(Tenants, Accounts and Roles, Connecting, Parties, Counterparties)
untouched -- filed as capture [[id:56A3540C-26F8-4A2E-9DE1-616E8D402156][Re-shoot manual screenshots showing
Barclays as Acme Corporation]] rather than edited blind, since their
prose is tied to real screenshots that would need re-shooting too.

Important accuracy check made while writing the departments section:
ORE Studio's roles (=Trading=, =Operations=, =Viewer=) are seeded at
the tenant level, not scoped to an individual desk/business unit --
so the chapter is explicit that the organisational separation Acme
demonstrates is not yet an access-control boundary, rather than
overclaiming desk-level RBAC enforcement that doesn't exist (a real,
tracked gap -- see the structure-analysis dataset's Gaps section).

Discovered and worked around a real Qt-help caching gotcha while
verifying the rebuilt chapter renders in the client: HelpViewer only
re-registers a =.qch= if its namespace isn't already in the
co-located =.qhc= index, and the exe's POST_BUILD =copy_if_different=
deploy step only runs on an actual relink, so =deploy_help_qch= plus
a full rebuild can silently leave the client serving a stale manual.
Worked around by hand (copy the =.qch=, delete the =.qhc=); filed as
capture [[id:09CC7500-87FA-41BD-B98C-00AED080F9A1][Document the stale Qt help .qch/.qhc cache gotcha in the
screenshot recipe]] so the recipe covers it next time.
