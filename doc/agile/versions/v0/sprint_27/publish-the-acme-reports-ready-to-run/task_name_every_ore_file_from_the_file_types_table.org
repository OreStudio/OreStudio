* Goal

When the export writes an ORE file, or the run document names one, it looks the name up in the file types table by file type. A parameter that names an input document is resolved through the bindings of the definition: the parameter definition refers to a configuration type, and the export writes the bound document under the well known name of its file type. A parameter that names an output or an intermediate file takes the default of its file type, and a configuration stores a value only to override it. Two analytics that share a file read one name.

* Acceptance

- The parameter definition has a value domain for a reference to a document and a column for the configuration type it refers to. The 129 analytic parameters with File in their name are classified as input document, output file or intermediate file.
- The export and the run store name every file from the file types table. The names hard coded in the run document builder and in the run store are removed.
- Each parameter that names an input document is filled from the binding of the definition. A definition that binds no document of the type fails the readiness check with a message that names the type.
- The simulation and the analytic that reads its cube agree on the cube file name by construction.
- Every exported ACME run document validates against the ORE schema, and its input files all exist in the exported package.

* Plan

1. Classify every analytic parameter with File in its name as an input document, an output file or an intermediate file. Record the classification.
2. Add a value domain for a reference to a document, and a column on the parameter definition for the configuration type it refers to. Add a default value to the parameter definition for output and intermediate files.
3. Replace the file names hard coded in the run document builder and in the run store with a lookup in the file types table.
4. Resolve each input document parameter from the bindings of the definition at export. A definition without the bound document fails the readiness check with the missing type.
5. Make an intermediate file that two analytics share read one name.
6. Validate every exported package, and check that every file a run document names is in the package.

* Notes

The files are of three kinds. Input documents are dumps of domain entities: the export writes them from the database under a well known name, so no parameter needs to store the name. Analytic specific configuration documents, such as the simulation and the sensitivity configuration, are the same kind of thing and are bound as configuration types. Files the engine writes are not in the database, and the platform only needs their names to collect results.
