* Summary

Booking is the journey [[id:F7987581-7AED-499C-9EEA-000AFB1FA95A][Book a trade]]. It is one page in tabs, because a trader booking a deal knows the whole deal, and the [[id:BD492939-118E-4B55-AE5B-300F7A1C3B41][Entity screen specification]] allows a guided sequence only when it makes the task quicker. The trade type is a combo box. The Instrument tab has a tab for each part of the instrument. Booking is the Add of the trade list, so the list has a Book a trade button and the page has none of a step rail.

** What the prototype argues

- The trade type is a combo box grouped by product, not a grid of cards. It is one choice among 121, and a combo box is quicker to scan and to type into. The 28 types with no instrument table are listed and cannot be chosen, and the option says so.
- The trade type decides what the Instrument tab holds, because each type routes to one instrument table. A swap has terms and legs. An FX option has terms, a premium and exercise prices. The tabs follow the parts of the instrument, as the tabs of any record follow its parts.
- A term that has a set of values is a combo box, with the flag for a currency or a calendar. A date is a date input. An optional term has Clear. The Edit dialog of the trade page uses the same input.
- The Review tab asks for the reason and the commentary, as the Edit dialog does, and counts the refusals on its tab. Book is disabled while one stands, and its tooltip gives the first.
- A form with changes asks "You have unsaved changes. Close anyway?" before the person leaves.
- A failed request names its operation, status, code and the first eight characters of the request id.
- A part with rows is a table with Add a row and Remove. A part the economic digest does not read says so where it is edited.
- A virtual book holds only a draft, a test or a hypothetical. The Review tab refuses a live, real trade in a virtual book.
- The Review tab lists the writes. =book_trade= is a domain operation, and it does not write the instrument today, so the instrument is a second, standard =put=. The half-booked state shows the outcome.
- A trade can be a leg of a structure or a package. The Structure card on the Trade tab makes it the first leg of a new one, or a leg of an existing one. A structure holds trades of one counterparty, so choosing a structure fixes the counterparty. A template fixes the roles and how many legs each holds, and the card says which roles are open. A strategy has one product family. The booking and the membership are two writes, and the Review tab lists both. The result offers the next open role, and links to the structure and its price.
- A composite is one trade whose legs are other trades. It is not a structure.

** What is fake

Everything. A booked trade is kept in the browser so that it appears on the trade list.
