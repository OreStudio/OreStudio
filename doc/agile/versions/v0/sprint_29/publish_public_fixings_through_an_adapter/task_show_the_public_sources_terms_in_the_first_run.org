* Goal

A system administrator who sets up a new installation reads the terms of each public source the system loads quotes from, and accepts or declines each one, before any of its quotes are fetched.

* Acceptance

- The first-run journey has a step between the administrator and ready that lists each public provider of the catalogue: its name, what it gives, its terms page as a link, the credit it asks for and whether it allows storage.
- The administrator accepts or declines each provider. An acceptance records the terms version, the principal who accepted and when; a declined provider is not fetched.
- A provider whose terms change has a new version, and the system administrator is asked again before the adapter fetches it.
- The terms can be read and changed later from the provider's own screen, not only in the first run.
- Acceptance is set only by the accept operation, on the server: it computes the digest, takes the accepting account from the authenticated session and the time from the server clock. A provider write ignores acceptance fields that a client sends. (Added on 2026-10-28 from the review of #3992.)

* Plan

- The accept operation existed but failed on main: the store accepts only an
  account's name as the acceptor, and its handler test signed in as a name no
  account held. The test now seeds its reader account.
- A withdraw operation, =marketdata.v1.ops.withdraw_provider_terms=, clears
  the digest, the account and the time on the server, so a declined
  publisher is not fetched. =POST
  /api/marketdata/public-rates/{code}/withdraw-terms= serves it.
- The acceptance fields leave the provider's write record and the service
  carries them forward on an edit, so only the terms operations set them; the
  shell and the HTTP writes can no longer state an acceptance.
- The first run gains a *sources* step after the administrator: each
  publisher's name, what it gives, its terms link, its credit and its storage
  rule, with Accept and Decline. The person goes on once every publisher has
  a decision.
- The Public rates screen offers a withdrawal beside an acceptance, so the
  terms are changed later outside the first run.

* Result

The first run asks the system administrator to accept or decline each public
publisher before any of its quotes are fetched. An acceptance records the
terms digest, the accepting account and the server's time; a decline, or a
later change of mind on the Public rates screen, withdraws it on the server,
and a publisher without a current acceptance is not fetched. A change of
terms clears the acceptance through its digest, so the administrator accepts
again. Acceptance is set only by the terms operations: a provider write
carries no acceptance, and an edit keeps the one stored.
