* Goal

Every statement a service runs goes through the pool and a transaction, as [[id:CE41E828-18EB-4E88-BB02-6A4930E7B67C][The data path]] states. The seven raw helpers in =ores.database/src/repository/bitemporal_operations.cpp= (=execute_raw_string_query=, =execute_raw_grouped_query=, =execute_raw_multi_column_query=, =execute_raw_command=, =execute_parameterized_string_query=, =execute_parameterized_command=, =execute_parameterized_multi_column_query=) are retired: each caller moves to the transaction-aware =query_builder= API, and the helpers are deleted in the same change.

* Acceptance

- =query_builder= offers every shape a caller needs, on =transact=: rows, a string column, a command, with parameters or without.
- Every caller of a raw helper calls the =query_builder= API instead. The move is a scripted codemod, kept with the task, so it reruns.
- The raw helpers, and =execute_raw_grouped_query=, which has no caller, are deleted.
- No statement connects per call ([[id:729F746E-36DD-40A2-A592-6972239E31F0][A service holds a few long-lived connections and never connects per query]]), and none sets a session-level setting: the tenant, party and actor are transaction-local ([[id:3C334C3B-2760-4278-95B8-B71268E8FD18][A transaction sets its own tenant context, so any connection serves any tenant]]).
- A statement made with a context bound to a unit of work runs on its transaction ([[id:37D08E01-F99C-4D2D-8ACA-E19E252BBE3D][A repository works inside an open transaction and never holds credentials]]); the stopgap that routes the raw helpers onto a bound transaction goes with them.
- Every test suite passes.

* Plan

=query_builder= already has three of the shapes, with the same names and arguments as the raw helpers. It gains the other three: =execute_raw_string_query=, =execute_raw_command= and =execute_parameterized_command=. The move is then a change of namespace, which a script makes.

- Every shape runs one unnamed statement with text results inside =transact=. A context bound to a unit of work runs on its transaction; a free context takes a pooled connection. An unnamed statement is not cached, so SQL that joins literals into its text does not grow the prepared-statement cache, which the shared =prepared()= cache would.
- An unnamed statement is one statement. No caller sends two, sets a session setting or controls its transaction; a grep of the callers' SQL found none.
- A string query skips a NULL row, as both raw string helpers did. The eight callers already on =query_builder= read columns that are never NULL.
- A failure throws =repository_exception=, as the generated repositories' reads and writes do. It carries the SQLSTATE and its class from =pq::store_error=, so the first administrator create still answers fixed words by SQLSTATE.
- The script =retire_raw_query_helpers.py= beside this task rewrites every call to its =ores::database::query_builder= name, drops the using-declarations of the old names and adds the =query_builder= include where it is missing. The codegen templates already call =query_builder=.
- The raw helpers, the transaction stopgap and =execute_raw_grouped_query= are deleted from =bitemporal_operations=.

* Notes

Found while fixing auto-approval inside a unit of work: the inbox decided a request through =repository::execute_parameterized_multi_column_query=, which opened its own connection and could not see the request its caller's transaction had just written. The publish lifecycle task routes the raw helpers onto a bound transaction as a stopgap; this task removes them. At the stopgap's commit the seven helpers had about 195 call sites, a few of which already resolve to =query_builder=.

The stopgap ran its statements through the shared =prepared()= cache, which names one server-side statement per distinct SQL text and never frees it; hand-written SQL that joins literals into its text grows it without bound. The shapes here run unnamed, which removes that.

Every failure now throws =repository_exception=. The first administrator create read the SQLSTATE from =pq::store_error=, so =repository_exception= now carries the SQLSTATE and the handler catches it. The geolocation lookup caught =std::runtime_error= to answer =lookup_failed=; it now catches =repository_exception=. A caller further up that catches =std::runtime_error= around a repository call is not visible to a grep; the full suite exercises those paths.

The same change fixes the codegen drift the publish lifecycle's first PR left on main: the trading core links the inbox core publicly, and the market observation model carries the manual-point order, its comments and the all-series merge that the generated repository already had.

* Result

The raw helpers and =bitemporal_operations= are gone. Every hand-written statement runs through =query_builder= on the pool and the unit of work, as one unnamed statement, and a failure throws =repository_exception= with the server's SQLSTATE. The codemod =retire_raw_query_helpers.py= moved 98 files and reruns as a no-op. The full suite passes on a fresh database (88 suites); the stale =ores.trading.core.digest.tests= binary, which is not a build target, still segfaults as before. The change also clears the codegen drift on main.
