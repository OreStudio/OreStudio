* Summary

Passwords, sign-in state, and the audit of who signed in.

3 prototypes answer to this group. Each one is a static page under
=doc/prototypes/=, opens with no build and no session, and reads mock data
only. The table below opens each one and says what it argues. Where a
prototype carries a Gemini review, the last column opens it: a review is a
generated alternative kept beside the agreed design, never instead of it.

[[file:../index.org][Prototypes]] is the top page and the only inventory.

* Adding a prototype

Create =doc/prototypes/credentials/<name>/= with an =index.html=, and a
=prototype.css= and =prototype.js= when it needs them. Add a row to the
table above, with the design note beside the prototype when there is one.
Stop there: the site build finds every prototype under this tree, so no
build file names it.

A review goes at =doc/prototypes/credentials/<name>/review/=, with an
=index.html= that lists its screens, and the row names it.
[[file:../index.org][Prototypes]] states the whole method and the rules that hold
for every group.
