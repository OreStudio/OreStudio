#+created: 2026-10-08

One value an axis of a composite market series holds. The rows of one axis are
its ordered values, so a grid can be read as coordinates rather than as the set
of points that survived a build.

The =sequence= column holds the position of each value among its axis's values.
A value that the axis declares and no point uses is still a declared value, and
a reader can tell it apart from a value the build never saw.

The table is a current state, not a history: a rebuilt series writes its shape
again. A value is text because the codec keeps every value as the key spelled
it, and a projection that reinterpreted it would be a second spelling of the
same coordinate.

* Columns

** series_id
:PROPERTIES:
:type:        uuid
:cpp_type:    boost::uuids::uuid
:primary_key: true
:END:

The series this axis value belongs to. A soft reference: the series table is
temporal and its primary key carries the validity window, so no foreign key can
name a single current row of it.

** axis_field
:PROPERTIES:
:type:        text
:cpp_type:    std::string
:primary_key: true
:END:

The oresmd field code of the axis this value belongs to, matching the axis row
the series declared.

** value
:PROPERTIES:
:type:        text
:cpp_type:    std::string
:primary_key: true
:END:

The axis value as the coordinate spells it. The writer refuses a value the axis
field's vocabulary does not hold.

** party_id
:PROPERTIES:
:type:     uuid
:cpp_type: boost::uuids::uuid
:END:

The owning party, copied so a query filters without joining the series.

** sequence
:PROPERTIES:
:type:    integer
:cpp_type: int
:default: 0
:END:

The value's position among its axis's values. The order the writer found them in
is the order they are read.

The table is current state and carries no validity window. A rebuilt series
writes its values again, and a history here would be a second copy of a
coordinate the points already carry.

** Indexes

| name   | columns              | unique | current_only | where_extra |
|--------+----------------------+--------+--------------+-------------|
| series | tenant_id, series_id | false  | false        |             |

A read starts from the series, because every query names the object whose shape
it wants before it names an axis.

* Physical space

The table is a projection the service writes and a query joins. It reaches no
client as an entity of its own, so nothing but the data layer and the SQL schema
is generated.
