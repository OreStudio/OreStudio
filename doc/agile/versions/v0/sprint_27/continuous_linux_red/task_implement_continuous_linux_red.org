* Plan

The run reported =sccache: command not found=, but that is the last step of a
run that stopped early. The first failure is =Check every Boost header has a
vcpkg port behind it=:

#+begin_example
  boost/functional (projects/ores.utility/src/domain/hierarchy.cpp)
  -> add "boost-functional" to vcpkg.json
#+end_example

The check took the first directory of an include and named a port after it.
boost/functional/hash.hpp is not a Boost.Functional header: boostorg/container_hash
carries it, and vcpkg installs it as =boost-container-hash=. The wrong mapping
was hidden because =quantlib=, now absent from =vcpkg.json=, used to pull
=boost-functional= into the closure.

The fix maps a header to the port that ships it, through a small table for the
paths that do not follow the directory rule, and adds a test for that table. It
also gives the CTest step an id, so the cache delete, save and statistics steps
run only when a build actually happened: on this run the =if: always()=
statistics step found no sccache, and the delete step threw away a warm cache
that the failed run never replaced.

* Notes

Root cause: the check mapped a header's first directory to a port named after
it. =boost/functional/hash.hpp= belongs to =boost-container-hash=, so the check
demanded a port the header does not need and, on main, is not installed.
=quantlib= had pulled =boost-functional= in transitively, which hid the wrong
mapping until it left =vcpkg.json=.

Fix: =PORT_FOR_INCLUDE= names the ports for include paths that break the
directory rule, =port_for= resolves every include through it, and
=boost_headers_used= keys the result by port. The regression tests live in
=projects/ores.codegen/tests/test_check_boost_dependencies.py=.

The sccache steps now read the CTest step's outcome. =Show sccache statistics=
still runs on failure, so a build failure keeps its statistics, but it no
longer runs when no build started.

* Result

The Boost port check resolves an include to the port that ships it, so
boost/functional/hash.hpp no longer asks for boost-functional. The check passes
on main's tree at vcpkg pin 19780d9cd. Five tests in
=projects/ores.codegen/tests/test_check_boost_dependencies.py= pin the mapping,
and codegen-drift runs them when the check changes.

The sccache delete, save and statistics steps run only when the CTest step
started, so a failure before the build neither reddens the run a second time
nor deletes the saved cache.
