This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

=event_bus::publish= logs "Publishing event type ... to N subscriber(s)" at
INFO for every event (=ores.eventing.api/service/event_bus.hpp:222=). Under a
bulk write that is one log line per row: one corpus import put 566,867 such
lines in the marketdata service's journal in under half an hour. Per-event
lines belong at DEBUG or TRACE; INFO could report a count per batch.

* Why

At the default service log level of INFO the line is written for every
event, so the journal grows by hundreds of megabytes per import and the line
that matters in an incident is buried. Found while diagnosing the stalled
marketdata listener.
