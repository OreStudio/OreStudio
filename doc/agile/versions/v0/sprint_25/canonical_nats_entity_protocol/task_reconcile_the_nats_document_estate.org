**Conflicts to resolve.**

- *History subject, three ways.* =history.v1.get= with =entity_type= dispatch
  (=history_diff_architecture=); =<component>.v1.history.get=
  (=messaging.org=, which records the generic form as a fixed failure because
  it fanned out to every service's queue group and won the request/reply race);
  and =<component>.v1.<entity_plural>.history= (the codegen archetype and
  =entity_composed_registrars=).
- *Event subject prefix.* Events are =ores.{component}.{entity}_changed=
  while request/reply is ={component}.v1.<resource>.<verb>=.
- *Payload format, three claims.* A completed plan mandates MessagePack;
  =nats_wire_format= makes it a process-wide JSON-or-MessagePack choice; the
  =ores.nats= overview and =messaging.org= still say JSON.
- *Two error channels, no arbiter.* The transport =X-Error= header with an
  empty body versus =success=/=message= on every typed response. A third
  proposal, =next/improve_handling_of_error_responses.org=, describes a typed
  error message from the deleted binary protocol and is stale.
- *Response-shape outliers.* The NATS monitor returns =success= without
  =message=; =steps_query= uses =found=/=outcome=; the
  =history_diff_architecture= request struct wrongly carries =success= and
  =message=.
- *Verb naming.* =entity_commissioning_reference= lists =list= and =get= as
  distinct operations, while codegen names the paged read
  =get_<plural>_request= on a =.list= subject.
- *Queue groups.* One plan says the group is the service name; the registrars
  use opaque per-subject groups; =messaging.org= records that several queue
  groups on one subject fan out and break request/reply.
- *Audit fields on the wire.* =shared_audit_record= proposes one flat set of
  five; the junction =replace_by= request carries =modified_by= and
  =performed_by=; =secure-stamping= declares both server-owned.

**Under-specified, with no home document at all.** The standard verb set; the
error envelope and its code enumeration; the header registry; correlation id
naming and propagation; batch atomicity; the pagination and filtering
contract; delivery guarantees, retry and dead-letter policy; idempotency
outside the workflow engine; optimistic concurrency as a wire contract; the
security rules for writes and the server-owned field list; whether a request
may carry =tenant_id= at all; subject-prefix semantics; the =v1= versioning
rule; JetStream stream and consumer naming; the changed-event payload shape;
and compression, tracing and disconnect detection.
