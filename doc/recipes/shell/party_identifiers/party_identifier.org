#+title: How do I run the party_identifiers commands from the shell?
#+description: Every command the party_identifiers submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:party_identifiers:

This file documents the party_identifiers resource at the shell, one section per command. Every command is a subcommand of =party_identifiers=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 9FB66842-688A-54E0-A1BE-18FDFD9E5064
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
party_identifiers list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.party_identifiers.list=.

#+name: party_identifiers-list
#+begin_src ores-shell :tangle party_identifiers-list.ores :exports none
party_identifiers list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 9D2854F0-BA7B-5D8B-BDC0-3A98F066C516
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

It is addressed at =refdata.v1.party_identifiers.get=.

#+end_src

** =add=
:PROPERTIES:
:ID: 702D5DF5-DD3C-57B8-9235-3B5F0D45FF98
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
party_identifiers add <id> <id_scheme> <id_value> <description> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.party_identifiers.put=.

#+name: party_identifiers-add
#+begin_src ores-shell :tangle party_identifiers-add.ores :exports none
party_identifiers add 00000000-0000-0000-0000-000000000000 __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: AD27CA17-958F-5E29-8813-15CF2B12D442
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
party_identifiers set <id> <id_scheme> <id_value> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.party_identifiers.put=.
