This page gives the data of compass-ng's =ore_output_catalogue= codec, the
generator of ORE Studio's output catalogue. The =* Definition= names the codec;
each table below is data the codec reads, and the prose says what it is for.
The tables were module-level constants of
=projects/ores.ore/scripts/generate_output_catalogue.py= and the =FAMILY_DOCS=
of =projects/ores.ore/scripts/output_family_docs.py=, which compass-ng used to
parse. Every cell is read as written: a blank cell, or one that is only ==, is
the empty string.

The codec still reads the list of ORE's files from
=projects/ores.sql/utility/ore_files.py=, which ORE Studio's seed generator also
reads; that list is not data of this page.

* Rule

The output catalogue
(=projects/ores.ore/core/src/results/output_catalogue_data.cpp= and its header)
and the page =doc/knowledge/external/ore_output_formats.org= are what the codec
writes from the samples ORE ships under =external/ore/examples=, the samples
under =projects/ores.ore/data/samples=, the seed of ORE's output files and the
tables below. Each family the samples show is one ORE file, has a row in
=* Family documentation=, and each output file the seed names is a family, an
alias of one, or a row of =* Out of scope=.

* Why

ORE publishes no list of what its output files hold, so ORE Studio derives the
catalogue from the samples. The samples cannot say which analytic writes a file
no parameter names, which columns identify a row, which values mean no value,
or what a figure means; these tables say it, once, beside the reason for each.

* Definition
:PROPERTIES:
:CODEC: ore_output_catalogue
:END:

* Family roles

Families the codec treats apart. A =risk_factors= family's figures are the risk
factors the run simulated, so its columns come from the configuration even
where the samples hold one variant: its measures are open. A =notebook= family
has no sample in the suites and is read from the notebook examples
(=ORE-Python/Notebooks=); only these are read from there, because the notebooks
also hold copies of families the suites already state. A =legacy= family has a
sample only in the legacy examples (=Legacy=); only these are read from there,
because the legacy examples repeat the suites with older headers. A family may
hold more than one role.

* Nulls

The engine writes a value it has no figure for as its null string. It is not a
value of the column, so it is dropped before the kind is inferred. The row ==
is the empty string: an empty cell of a sample.

|-------|
| ==    |
| #N/A  |
| #NA   |
| N/A   |
| null  |
| NULL  |
| NaN   |
| -nan  |
