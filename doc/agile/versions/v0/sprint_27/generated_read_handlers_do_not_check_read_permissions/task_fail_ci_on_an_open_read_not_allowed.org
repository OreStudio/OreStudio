* Result

=check_open_reads.py= fails when a generated read handler checks no
permission and its subject is not allow-listed, when a generated history
registrar passes no read code, and when the allow-list names a subject no
protocol defines. It runs in the codegen drift workflow, which now also runs
when Authorised reads changes. On its first run it found a hand-written read
pasted into the composite instrument handler with no check, now guarded. A
local review then found that it classified a read by the method's name, so the
two injected =composite_as_of= reads escaped it; it now classifies by the
request a method decodes, whatever its name, and it failed on both before
their guard landed. It also counts each history registration against a literal
read code, and reports a missing allow-list section rather than aborting.
Seven tests cover it.
