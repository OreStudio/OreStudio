#+title: How do I run the calendars commands from the shell?
#+description: Every command the calendars submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:calendars:

This file documents the calendars resource at the shell, one section per command. Every command is a subcommand of =calendars=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 52AA7DC4-E6F0-5799-B0F4-379B9CB05F3E
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
calendars list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.calendars.list=.

#+name: calendars-list
#+begin_src ores-shell :tangle calendars-list.ores :exports none
calendars list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 48AF9568-88C4-5C67-B0E3-3E652271A688
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
calendars get <code>
#+end_example

It is addressed at =refdata.v1.calendars.get=.

#+name: calendars-get
#+begin_src ores-shell :tangle calendars-get.ores :exports none
calendars get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 9E88E843-8AC3-5DC6-9457-F61E5AB85911
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
calendars add <code> <name> <calendar_type> <country_code> <image_id> <source> <is_editable> <base_calendar_code> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.calendars.put=.

#+name: calendars-add
#+begin_src ores-shell :tangle calendars-add.ores :exports none
calendars add __none__ __none__ __none__ __none__ __none__ __none__ false __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: AF9F895A-20E0-5C8F-B1D1-039AB450CC50
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
calendars set <code> <name> <calendar_type> <country_code> <image_id> <source> <is_editable> <base_calendar_code> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.calendars.put=.

#+name: calendars-set
#+begin_src ores-shell :tangle calendars-set.ores :exports none
calendars set __none__ __none__ __none__ __none__ __none__ __none__ false __none__ system.new_record generated_script
#+end_src
