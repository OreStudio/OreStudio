* Acceptance

- Each node links to its page.
- A batch the shell dispatched shows no report, and the chart says so.
- The scheduled job node appears when the scheduled job read exists, and not before.

* Plan

Replace the lineage list with the chain of the prototype: one column of nodes, each with a dot on a line, from the scheduled job to this job. The report run page already reads the run with its definition, so the chart reads the run through it, and one read of the batch's jobs gives the sibling count. A node the model states is a solid dot. The batch is a dashed dot when a report made it, because its link to the run is the External Ref and not a checked relationship. This job is the highlighted node, with its results beneath it.

* Notes

The scheduled job node is drawn and says it is not shown yet, because the scheduler has no read of one job instance by id. The task Read a scheduled job by its id lifts that, and the node then names the job. A batch the shell dispatched has no report behind it, and the chart draws the batch and the job only and says so. A session that may not read the run, such as the operator, sees the run as a link and no definition.

I did not draw this chart when I built the job page. The prototype showed it and I built to the story's acceptance line instead. The comparison of the page with the prototype is in the task Lay out the job page as its prototype.
