#+title: How do I run the business_day_convention_types commands from the shell?
#+description: Every command the business_day_convention_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:business_day_convention_types:

This file documents the business_day_convention_types resource at the shell, one section per command. Every command is a subcommand of =business_day_convention_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

:PROPERTIES:
:ID: E862179C-A811-59C0-8E04-9FD98941F03D
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example

#+end_example

It is addressed at =refdata.v1.business_day_convention_types.list=.

#+begin_src ores-shell :tangle business_day_convention_types-list.ores :exports none

#+end_src

** =add=
:PROPERTIES:
:ID: 1DCC4283-D155-522C-AE75-440B0BC7710A
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.

** =set=
:PROPERTIES:
:ID: CB77B5AE-09CD-51EC-B194-75CFD7A34F2E
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses.
