* Result

All 54 request types a provisioning step makes were read handler by handler. The
five that read a catalogue and narrowed it in memory now ask the store for their
own rows. The inventory is
[[id:BCC7D01B-6BA9-40F0-8402-41C9DC249DE6][The work each provisioning request does, and what bounds it]].

What the five were, and what they read now:

- =calibrate_fx_vol_surface= read every FX volatility pillar and every pillar
  source the tenant holds, to build one blueprint's recipe. It reads that
  blueprint's pillars through =fx_vol_surface_pillars_filter=, and their sources
  by pillar id.
- =compute_curve= and =publish_curve= read every IR curve pillar, to build one
  config's curve. They read that config's pillars.
- =publish_fx_forward= read every IR curve config, to find one currency's
  funding curve. It reads that currency's funding curves.
- =publish_fx_vol_surface= read every surface publish, to find a second raise of
  the same calibration. It reads the blueprint's own raises.

Each repository already offered the filtered, paged read: the handlers were
simply not using it. Each read is paged, so a request cannot be made unbounded
again by a tenant that adds rows.

Two request types do not meet the first sentence of the acceptance, and both are
stated rather than implied:

- =regenerate_calendar_dates= writes a day per calendar in use, about 37,000 days
  each, and the request names no calendars because =in_use_only= is set. It is
  bounded by the years the service caps, and it runs as =build_calendars_step=
  with a 600 s deadline, so the acceptance's second clause covers it. Its read of
  the existing days loads each calendar into memory to subtract them, which is a
  memory cost and is named in the recommendations.
- =list_accounts= is the one read on this path that grows with the tenant's data:
  both the password and the picture step ask for its accounts with
  =limit = 10'000= and work one by one over the answer, dropping the rest past the
  ceiling without a word. It is captured as
  [[id:DC63BCCB-0967-4A2D-B978-2033DF7C943D][Provisioning asks for every account in one request, and drops what is past ten thousand]]
  for the step that moves to its owning service.

The =put_many_*= handlers are bounded by the rows they are handed, but pay 2N+1
queries for N rows, which the recommendations name.
