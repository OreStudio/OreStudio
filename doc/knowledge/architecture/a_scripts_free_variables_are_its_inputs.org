#+title: A script's free variables are its inputs
#+description: An input is a variable a script reads and never declares or assigns; its type follows from use, and the inputs of a script with no element of its own are that product's fields.
#+type: knowledge
#+level: cross

* Summary

An input of a script is a variable the script reads and never declares or
assigns: ORE takes its value from the trade. Its type follows from how the
script uses it, an index called with a date is an =Index=, a date argument of
=PAY= an =Event=, and it is an array when the script indexes it or asks its
=SIZE=. A script's inputs are the union over its variants, since a trade states
what every variant it may run reads. For a product with no element of its own,
the inputs are the product's fields ([[id:290A1069-A1EE-4DD1-8D23-1C60F76F8949][Every product has a schema of its fields and its forms]]).

* Detail

** Derived by the parser

The parser derives the inputs from the syntax tree ([[id:8FD7BD95-AAEC-4CF9-A9F4-D609A9DEFBD8][ORE's grammar is the one authority on whether a script parses]]): declared
and assigned names are the script's own, every other name it reads is an input,
and ORE's static analysis already classifies the indices and events a script
uses. The rule a value follows comes from the script's =REQUIRE= statements
about it, such as =REQUIRE PayoffType == 0 OR PayoffType == 1=. A library script's
inputs are derived when it is published and stored as rows of
[[id:F08D458F-B694-4B2F-A945-E22544A9222F][ores.trading.script_input]]; an inline script's are derived when it is validated.

** Checked against a trade

A trade's variables are checked against the inputs: one missing, one the script
never reads, or one of the wrong type is refused with the input's name, before
ORE sees the trade.

** What the comments are not

A library script's comment block may list its inputs, but comments go stale:
=WindowBarrierOption='s lists =ObservationDates= while its code reads
=StartDate= and =EndDate=. The code is the authority; a comment only adds a
description.

** Where today's code differs

The inputs are mined from the code by a text script into the seed, not by a
parser, so a person's own script has no way to state them.
