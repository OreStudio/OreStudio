* Acceptance

- compass codegen regenerate --all runs with no error for ores.http.
- check_component_drift.py --component http-cpp reports no drift.

* Plan

The part was written by hand in PR #4571 and modelled as an adapter, the kind
of a component's route module, which shares the composite's include root. It
owns its own root, =include/ores.http.nats/=, as =ores.http.core= does, so it is
a core part:

- =ores.http='s =#+parts:= lists =nats=.
- The part states the =core= kind and the name =http.nats=, the form the
  modelled parts use, so the profile's baseline links =ores.http.api.lib=.
- Codegen writes its CMake, its export header, its umbrella header and its
  test main. The model's own block keeps only =ores.logging.lib=, which the
  baseline lacks.

* Result

=ores.http.nats= is a modelled core part of =ores.http=, built as a shared
library like =ores.http.core= and =ores.http.api=. The drift check for
=ores.http= reports no drift, so =compass codegen regenerate= no longer refuses
the component. The server builds, and the nine =ores.http= suites pass.
