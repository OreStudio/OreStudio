* Goal

* Acceptance

- conventions_mapper.cpp holds only read, write and unmodelled
- Each family has a unit that defines map, reverse, pack and join for its own type
- The dispatch unit includes declarations only and a static_assert ties its table to the registry
- The translation unit budget gate no longer lists the mapper

* Plan

The refdata side already has the shape: one unit per family, a header of
declarations, and a dispatch table. The ORE side copies it.

- =conventions_mapper= keeps =read=, =write= and =unmodelled=. Its =map_<key>=
  methods stay public, and each gains a =reverse_<key>= beside it. Both are
  defined in the family's own unit. The reverse functions are no longer in an
  anonymous namespace, so no unit holds private functions that a unibuild could
  merge or collide.
- =conventions_fields.hpp= and =.cpp= hold the field helpers that two or more
  families share, in a named namespace, defined once. A helper that only one
  family uses lives in that family's unit, in the same namespace. The codemod
  decided which is which by reading who uses each helper.
- Each family has =conventions_family_<key>.cpp=. It defines =map=, =reverse=,
  =pack_<key>= and =join_<key>= for its own type. The pack and join templates
  are in =conventions_family_pack.hpp=, so reflecting a type happens in the unit
  that names it.
- =conventions_package.cpp= holds the table of =family_codecs=, =split_conventions=
  and =join_conventions=. It includes declarations only and reflects nothing.
  A =static_assert= requires one row for each registry family that is not a
  tenor basis swap family, so a new family stops the build until it has a unit.
- The tenor basis swap trio and the FX projection are not table rows. The trio
  is one document element, so it has one unit. The FX conventions are a
  projection that no family holds.
- =conventions_diff.cpp= shares the tenor kind and the tenor family test with
  the trio's unit, so the two cannot disagree.
- The budget gate counts a unit that includes =conventions_family_pack.hpp= as
  reflecting, because the templates in it reflect for the unit. Without that the
  gate would not see the new units at all.

* Result

The mapper no longer holds the families. =conventions_mapper.cpp= went from 2207 lines to 72 and keeps =read=, =write= and =unmodelled=. Each of the 23 document families has a unit of its own that defines =map=, =reverse=, =pack= and =join= for its own type. The tenor basis swap trio has one unit, because it is one document element. The FX projection has a unit too.

No anonymous namespace carries a per-family function. The reverse functions are public members beside the map functions. The shared field helpers are declared once in =conventions_fields.hpp= and defined once. A helper that only one family uses sits in that family's unit.

The table of families is in =conventions_package.cpp=, which includes declarations only. A =static_assert= requires one row for each registry family outside the tenor trio. A new family therefore stops the build until it has a unit.

All four acceptance points are met. The budget gate lost its mapper entry, and it now sees the new units. The ore core suite passes, including the XML round trips. The one open item is the tenor trio, which stays at a ceiling of 3 with the diff and the bundle service.
