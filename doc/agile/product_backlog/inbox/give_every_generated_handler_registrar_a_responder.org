This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

The =handler-registrars= check in =./compass.sh check= fails when a generated
handler registrar is never called and its subjects are not subscribed by hand.
It covers only the components that pass today: ores.assets, ores.compute,
ores.dq, ores.marketdata, ores.scheduler, ores.synthetic and ores.variability.
A census on 2026-11-01 found the rest:

| Component       | Registrars without a responder |
|-----------------+--------------------------------|
| ores.refdata    | 17                             |
| ores.analytics  | 16                             |
| ores.trading    | 10                             |
| ores.reporting  | 7                              |
| ores.workflow   | 2                              |
| ores.iam        | 1                              |
| ores.inbox      | 1                              |

For each, call the registrar from the component's =registrar.cpp=, or retire
it when the entity is not meant to be served. Then add the component to
=CHECKED_COMPONENTS=. Run the check script without the list to see the names.

* Why

The synthetic calibration policy, provider order and fallback were generated
but never called, so the calibration screen timed out reading its policy, and
neither the build nor a test noticed. A request on any of the 54 subjects above
times out the same way.
