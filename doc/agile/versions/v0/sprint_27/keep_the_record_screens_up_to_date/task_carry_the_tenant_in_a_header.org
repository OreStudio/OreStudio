* Goal

An entity event names the tenant of its row in the =X-Tenant-Id= header, so a subscriber that serves people can pass it on only to a reader of that tenant. The notification already holds the tenant. The typed event and the registrars drop it. The protocol specification (Events, Tenancy of an event) defines the header and keeps the subject grammar as it is.

* Result

Built. Not run against NATS yet.

- The protocol specification defines =X-Tenant-Id= and =X-Party-Id= (Events,
  Tenancy of an event, and the header registry).
- =entity_event_notification= gains =party_id=. =published_entity_event<Event>=
  carries the typed event with the tenant and party the store reported.
  =postgres_event_source= publishes it beside the typed event.
- =publish_entity_event= has an overload that sets the headers
  (=entity_event_headers=). The payload and the subject are unchanged.
- The registrar, cache registrar and integration test templates are changed and
  regenerated for every component (346 registrars, 270 integration tests).
- The cache registrar used to decode the tenant from the payload, which carries
  none, so it could never reload a partition. It reads the header now.
- Checked: =clang -fsyntax-only= on a registrar, an integration test, the cache
  registrar and the publisher tests; the codegen tests (114) and
  =check_subject_conformance.py= pass. The C++ tests need a build to run.
