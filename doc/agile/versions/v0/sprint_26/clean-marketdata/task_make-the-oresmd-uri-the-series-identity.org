* Goal

Every identity-bearing market-data row carries the oresmd_uri that its key or its index name projects to, so the series identity is the URI rather than the registry's (series_type, metric, qualifier) triple, and the import creates a series for every row ORE's own examples carry -- the fixing half included.

* Acceptance

- market_series and feed_binding carry oresmd_uri, and it is the natural key for a series and for a feed binding.
- import_service writes the URI for every market-data key and every fixing index name, and writes no row that has an identifier without one. from_index_name has production call sites at last.
- The corpus import round-trips: every fixing row in external/ore/examples creates a series, with the skipped-name warning count at zero and the de-duplication count unchanged.
- series_type, metric, qualifier, ore_key and the import classification table are deleted, and every consumer reads the URI.

* Scope, measured before the column

Read at =00c9cdd711= on the merged trunk. Nothing here is a claim about the
abandoned branch; the two write paths are the code as it stands.

**Neither import path stores an identity today.**

- *Market data.* =import_service.cpp='s =canonical_key()= already computes the
  identifier: it calls =from_ore_key()=, projects it back with =to_quote_key()=, and
  returns the canonical spelling and the registry's decomposition of it. The
  identifier itself is **discarded**. The series is found or created on
  =(series_type, metric, qualifier)=, and the observation keeps the file's own text
  in =obs.key=, because the rows above hold the canonical spelling rather than it.
- *Fixings.* The series is created as
  =find_or_create_series("FIXING", "RATE", f.qualifier)=, where the qualifier **is**
  the index name. =from_index_name()= has no production call site at all: zero
  outside the projections and their tests. A fixing series therefore has no
  identifier to store, and the index name is the whole of its identity.

**Both identity-bearing tables are known, and the blast radius is measured.**
=market_series= keys on the triple; =feed_binding= keys on =ore_key= and
=source_name=. 63 files across =ores.marketdata=, =ores.synthetic=, =ores.shell= and
=ores.ore= name =qualifier=, which is the set the deletion has to carry. The value
the new column needs is in hand on the market-data path and one call away on the
fixing path, so this task is the cutover and its consumers rather than a new
projection.

* What the deletion has to carry, counted

Counted at =ce3c6f32bd= on this branch, with member-access and column patterns
rather than the bare word, because =metric= alone matches 481 files and most of
them are somebody else's metric:

| What | Count | Pattern |
|------+-------+---------|
| C++ files reaching a series' =qualifier= | 21 | =\.qualifier\b= |
| C++ files reaching a series' =series_type= or =metric= | 32 | =\.(series_type\|metric)\b=, in the three components that hold series |
| SQL files naming the ="qualifier"= column | 2 | the market series create and populate scripts |
| SQL files naming the ="ore_key"= column | 2 | the feed binding create and populate scripts |
| Generated TypeScript carrying the field | 2 | the market series domain and protocol twins |
| Org documents naming =qualifier= | 80 | models, recipes and manuals |

The organs split by component: =ores.marketdata= 33, =ores.synthetic= 16,
=ores.ore= 12, then two in the shell and one each in =ores.trading= and
=ores.testing=. The deletion is therefore a cross-component change, which is why
the plan kept it as its own acceptance rather than folding it into the column's.

**=feed_binding='s column is deferred, and the reason is structural.** The plan
gives the binding an =oresmd_uri= beside its =ore_key=, and the column was added and
regenerated: =ores_marketdata_feed_bindings_tbl= took it and the entity's layers
followed. It was then taken back out, because nothing can write it today. The row is
assembled by the generated service -- =feed_binding_service.cpp= carries the
AUTO-GENERATED banner -- and the service template has no per-column derivation hook;
the =#+begin_src cpp :name generator= blocks a model can declare feed the test-data
generators under =api/src/generators/=, not a real write. Every other writer is a
generated shell command. So the binding's identity arrives with the unit that
replaces =ore_key=, where the same code that supplies the key today supplies the URI;
until then the column would be null in every row, which is worse than absent. The
natural key stays =ore_key= and =source_name= meanwhile.
