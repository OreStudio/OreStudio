* Goal

ores.ore converts between ORE formats and our domain types and does nothing else. Every ORE-defined format is read and written in one place, the component's dependencies are api contracts rather than other components' cores, and a build check stops the boundary from drifting again.

* Acceptance

- ores.ore.core links no other component's core or service library; its dependencies are api contracts, logging, platform, utility, pugixml and Boost.
- The codec performs no database work: it opens no session, calls no repository and writes no table.
- The setup parameter that names each ORE input file is declared in ores.ore and checked against external/ore/xsd, not read from a configuration table.
- One parser reads the engine's log, and it reads both log.txt and log_structured.json.
- A build check fails when a component's core library links another component's core or service library.
- The ORE document kinds the codec recognises, and the formats it converts in each direction, are recorded in one place and agree with external/ore/xsd.

* Notes

The audit that scoped the story measured six dependencies the codec does not
justify. The Status table claims the run store drops four of them, which is
the table below.

| # | Dependency | Kind | Why it is there | Dropped by |
|---+------------+------+-----------------+------------|
| 1 | =ores.database= | public | the run store's session context | the run store |
| 2 | =ores.analytics.core= | private | the run store's document services | the run store |
| 3 | =ores.reporting.core= | private | the run store's repositories | the run store |
| 4 | =ores.refdata.core= | public | the conventions bundle type, and the run store's curve service | the run store and the bundle move |
| 5 | =ores.nats= | public | nothing the codec uses; the generated core profile adds it | the profile, or a per-component override |
| 6 | =ores.dq.api= | private | four change-reason constants in the planner | the planner taking them as a parameter |

The api contracts the codec keeps are justified by the mapping it performs:
=ores.refdata.api=, =ores.trading.api= and =ores.analytics.api=. =ores.reporting.api=
stays for the run document projection, which is the conversion the component
exists to perform.

* Decisions

- 2026-10-27: The story is scoped from an audit of the codec's dependencies. The codec itself is clean: =xml/generated= is produced from =external/ore/xsd= by our own generator, and no XML parser exists outside the component. Every finding sits above the codec — the run store, two public headers, and one test suite.
- 2026-10-27: The run store's =import_run= and =export_run= are deleted rather than re-homed. The live import is =run_configuration_operations=, which reaches each owner over NATS with a delegated token. The database path has no production caller, and only its own tests keep it alive. The package helpers stay, because an ORE input directory and its layout are ORE artefacts.
- 2026-10-27: =reporting.api= stays a codec dependency. Mapping =ore.xml= into our run document is the conversion this component exists to perform, and the reporting contract is a leaf. What changes is the kind of edge that remains: no =core=, no =service=.
- 2026-10-27: The XML binding generator is not revisited. xsdcpp is removed and the generator is ours. Its missing drift check is recorded out of scope so that it is not lost.
- 2026-10-27: The state before the work is measured, not assumed. =libores.ore.core.so= declares 22 ORES libraries, including =reporting.core=, =analytics.core=, =refdata.core=, =service= and =database=. =ores.compute.wrapper= links the codec, so the compute node process loads the reporting service layer to parse a log and marshal a CSV.

* Out of scope

- A drift check for the XML binding generator. =regenerate_xml_bindings.sh= supports =XML_BINDINGS_OUT= for one, but no test and no CI job runs it, so the committed tables can disagree with =external/ore/xsd=. The component overview claims the check exists.
- The conventions import and export redesign, which has a story of its own.
- The =oresmd://= URI grammar, hand-built in =ores.ore.service=, =ores.iam.core=, =ores.synthetic.api= and the shell. It is our format, not ORE's.
