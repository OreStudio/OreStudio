* Goal

The shape tables say what a composite object comprises, but nothing enforces it: a point whose coordinate the shape does not list is still written, so the shape and the points can disagree and the disagreement is silent. Refuse such a point at write time, wherever a point is written, so the two cannot drift. The import declaring a shape is its own task: the shape writer sits in ores.marketdata.service because it reads the reference tenors, and the import sits in ores.marketdata.core, which cannot reach it.

* Acceptance

- A point whose coordinate is not a declared axis value of its series is refused, and the refusal names the series, the value and the axis that does not declare it.
- The refusal holds for every writer of a point, not only the one that was changed, or the task says which writer it does not cover and why.
- A point for a series that declares no shape is written as it is today, so no existing series stops accepting points.
- A point whose URI the codec cannot read is accepted, so a defect the identity projection already records does not stop a write.
- A series whose declared shape gains a value accepts points at that value without any further change.
- The check reads only the shapes of the series a batch names, so the ingest path pays for the series it is writing and not for every shape in the installation.

* Plan

Two pieces: a check in core, and a hook where a point is written.

The check is =series_shape_check=. It gathers the distinct series of the batch, reads those series' axes and values in two filtered statements, and refuses the first observation that carries a value one of its series' axes does not declare. A series with no axis row declares nothing, so nothing about it is refused, and a URI the codec cannot read is accepted and logged, because a URI the codec cannot read is a defect the identity projection already records rather than a point outside the shape.

The filtered reads are new: =read_latest_for_series= on each shape repository. The generated key read wants a series and an axis or a value per row, and a caller that checks points does not yet know which axes a series has, so the key read cannot serve. The new read filters by the series alone and the index on =(tenant_id, series_id)= carries it. Without it the check would read both shape tables whole on every observation insert, which is per tick on the ingest path.

The hook is two paste points in the repository template, at the top of the generated single and batch =insert=, before the row is written. Every writer of a point uses =market_observation_repository::insert=, so the refusal holds for the ingest loop, the curve republish and the import alike. A repository of another entity collapses both markers.

Out of this task, and recorded as the next one: the import declaring a shape from what it carries. The writer is in =ores.marketdata.service= because it reads the reference tenors, and the import is in =ores.marketdata.core=, so that task either moves the writer down or moves the tenor check into the store.
