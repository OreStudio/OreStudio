* Notes

** Part 3: the comment rules

The pass covered the 103 hand-written C++ files and the comments in the models.

- Namespace closers lose their end-of-line comment: =} // namespace= becomes
  =}=, as the project's own files write it.
- Ten other end-of-line comments moved to their own line above the code.
- Comments that narrated history, stories or tasks now state the behaviour:
  "no longer splits keys", "now the series' oresmd identity", "the CRM story's
  architecture decision", "the config-creation task's own doc comment" and
  "today's synchronous publish" among them.
- Comments that use "removed" or "added" to describe behaviour, such as "a
  field added to the enum and not here fails", stay.

The two review points PR 2597 deferred are in the same PR, as model edits
regenerated into the repositories:

- =read_latest_for_series= on observations and fixings reads the maximum
  timestamp once, as a static, as the other reads do.
- =read_as_of= and =read_as_of_buckets= throw on a row with too few columns, a
  bucket with no ordinal, or an ordinal outside the requested buckets, rather
  than dropping the row. A dropped row would make a curve snapshot silently
  short a pillar.


** Part 1: the two repositories

The generated =market_observation_repository= and =market_fixing_repository=
survive. Their =write= makes a version claim per row, one query each, which an
import of about 100,000 observations cannot afford, so the append the
hand-written classes did is =insert=. It is a codegen feature, not pasted code:
the =:append_insert:= flag in a model's SQL Flags drawer gives the repository
=insert(ctx, v)= and =insert(ctx, vector)=, so any append-only entity can use it.
Codegen refuses the flag together with =:current_state:=, and
=test_append_insert.py= covers it. The reads production
used, =read_latest_for_series=, =read_as_of= and =read_as_of_buckets=, moved as
custom methods too, declared in the models. The date-range read and
remove-by-series had only test callers, so they went with the hand-written
classes. The single-fixing test asserted only that nothing threw; it now reads
the fixing back.

[[id:8B193823-0382-4FE3-A95B-A34799B5972D][Correct the marketdata clean-standard record]] added the three namespace headers, so G08 already
passes, and made =subject_helpers.hpp= use the api constant
=marketdata_tick_subject_prefix=. What is left of P02 is declaring the subject in
a model and generating that constant.
