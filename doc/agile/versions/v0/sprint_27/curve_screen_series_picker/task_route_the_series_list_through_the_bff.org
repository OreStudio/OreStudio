* Acceptance

- A session-guarded route forwards to the new operation and returns the identities.
- A refused read reaches the browser as the server's reason, and a missing permission as forbidden.
- Tests drive the route through a canned client.

* Plan

Add =POST /api/curves/series-list= to =curves.ts=. The body is empty or names a party, which must be a
UUID. The route forwards it to the server's list operation and returns the series and the =truncated=
flag without the success and message fields. A refusal reaches the browser as a 422 with the server's
words, and a missing permission as 403, as for the other curve routes. Test the route against a canned
client, then read it against the running stack as two different parties.

* Result

The browser can ask which series its session can see. =POST /api/curves/series-list= returns each series
as the typed identity the other curve reads take, with the owning party stated and the axes the series
declares, and says when the list was cut. The route was read against the running stack, signed in as the
tenant administrator under two parties. As the System Party it returns the six imported volatility
surfaces with their axes. As Acme Corporation Plc it returns the thirteen FX spot series, which have no
axes because a spot rate has no grid. A party sees its own series and no other's.

*A gap this found.* The market data that provisioning seeds for the Acme parties has no rows in the
identity projection, so thirteen series for each of four parties, and fourteen of the System Party's
twenty, were invisible to the list and to the resolver. =marketdata backfill-identity --party= fixes it
for one party at a time, and it has to run in a session of that party. It was run here for Acme
Corporation Plc. Provisioning should project the identities it seeds. It is captured as a backlog item.
