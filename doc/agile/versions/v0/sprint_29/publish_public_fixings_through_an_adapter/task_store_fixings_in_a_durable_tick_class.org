* Goal

* Acceptance

- The class of a tick follows from its item: an index's tick is a durable fixing, and every quote keeps today's rules. (Amended on 2026-10-28: a policy table keyed by instrument type waits for a second durable class; see Notes.)
- A durable tick skips the age gate; a backfill sent oldest first for each vendor id passes the order rule.
- Fixings go to the fixings table, =market_fixing=, which has no retention policy, and never to the ticks table. (Amended on 2026-10-28: the durable table already existed.)
- A test sends a fixing a day old and a ten-day backfill through the ingest and reads them all back; a live quote of the same age is still dropped.
- A durable tick whose vendor id and vendor time are already stored is skipped, so a backfill that overlaps the store after a restart adds no row; a test shows it.

* Plan

1. Mark each adapter tick with its class. The translator holds the items of its
   mappings that are indices (=oresmd_uri_codec::read_index=), and a tick of one
   of them is a fixing. A fixing skips the age check; a quote keeps it.
2. Give the fixings their own path. A quote is age-checked twice, in the
   translator and in the worker that drains the quotes' queue, and that queue
   drops its oldest tick when full. A fixing never enters it: =fixing_ingest=
   holds a queue that never sheds and one thread that stores what it holds.
3. Store a fixing in =market_fixing=, which already is the durable table: a
   hypertable keyed by party, series and fixing date, with no retention. The
   series of an index is found or created for each consumer, through
   =create_feed_series=, which the quote path now shares.
4. Skip a fixing whose series already holds that value on that date, so an
   overlapping backfill adds nothing and a correction adds one version.

* Notes

- The tick pipeline is built around =market_datum=, which =oresmd_uri_codec::read= reads.
  A fixing's item is a =market_index=, which =read= refuses, so before this task a
  fixing tick was dropped as =unnameable_datum= before any age check.
- The class policy is keyed by what the item is (quote or index), not yet by a policy
  table per instrument type. A second durable class, such as a trade, would add that
  table.
- Two burst tests of the ingest loop fail while a live =ores.marketdata.service= runs,
  because it consumes the tests' NATS ticks too. They pass with the service stopped.

* Result

A fixing is now a class of its own in the ingest. The translator knows the items
of its mappings that are indices, and their ticks skip the age check. They never
enter the quotes' queue, which drops its oldest tick and ages ticks out a second
time: =fixing_ingest= holds a queue that never sheds and one thread that stores
into =market_fixing=, the existing fixings table, which keeps them for good. The
series of an index is created for each consumer through =create_feed_series=,
now shared with the quote path. A fixing whose series already holds that value on
that date is skipped, so an overlapping backfill adds nothing and a correction
adds one version.

Evidence: =ores.marketdata.service.tests= passes 191 of 191 (2111 assertions).
New cases: a fixing two days old is kept while a quote of that age is stale; a
ten-day backfill sent oldest first passes the order check; a backfill stored once,
sent again after a restart adds nothing, and a correction adds one row; and a
fixing of yesterday with a ten-day backfill, sent through the loop's adapter path,
reaches =market_fixing= with no stale drop. The live service runs the new build
and reports =fixings_stored=, =fixings_failed= and =fixings_pending= beside 8274
quote ticks stored.
