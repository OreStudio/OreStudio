* Acceptance

- A model that opts into the route facet and whose unit the aggregate never calls fails the gate, and the failure names both.
- A unit the aggregate registers twice fails the gate.
- The three components that answer routes today pass the check unchanged.
- The check runs in the local gate for a change to the adapter, the models or the check itself.

* Plan

The port has one silent failure. A resource is served in five steps, and the fourth,
adding its unit to the component's hand-written aggregate, is the one no generator
covers. Skip it and the unit compiles, links, passes its own registration cases and is
never called, so the gateway answers nothing for that collection and nothing anywhere
says so. The route inventory cannot see it either: it reads the unit's own router
calls, and they exist.

So the link gets a check, in the shape the repository already uses for the same trap in
the shell's command units. It reads the components under =projects/ores.http/=, takes
each model that opts into the route facet in the matching =projects/ores.<component>/modeling/=,
and asserts the aggregate calls that unit once. A unit registered twice is a second
problem, because the second registration claims routes the first stated.

The check reads the models rather than the generated files, so it holds for a model
whose unit has not been generated yet, which is the state a branch is in between the
opt-in and the regeneration.

* Notes

- The check names the aggregate, the unit and the model that opted in, because the
  three are what a person needs: where to add the call, what to add, and why it is
  expected.
- A unit the aggregate calls but which does not exist is a problem too, so a deleted
  unit cannot leave a stale registration behind.
- The aggregate itself is still hand-written. Generating it is the alternative, and it
  would remove the step rather than guard it; that is a larger change to the facet and
  is not what this task does.

* Result

A component's route units are reachable or the gate says which one is not. The check
reads the models for the opt-in and the aggregate for the call, so the silent step of
the five that the port takes is now the one that fails loudly.
