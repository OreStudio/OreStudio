* Plan

(Implementation strategy. Written when work starts; key decisions

The task is two pull requests, because the two halves fail for different reasons and a reviewer reads them
differently. The first changes behaviour. The second changes names only.

*Pull request 1: the adapter.*

1. Name the vendor id of a generator. An FX spot generator for the pair =EUR/USD= quotes the ORE key
   =FX/RATE/EUR/USD= with the field =value=, the notation the catalogue installs for the provider =ore=.
   Only FX has vendor rows today, so only FX generators are adapter generators. The rate curves keep to the
   old path until their rows exist.
2. Let a generator publish an adapter tick. The FX generator takes an optional adapter target: the vendor
   id and the ingress subject. With a target it publishes =adapter_tick= on
   =marketdata.v1.ingress.<adapter>.<id token>=. Without one it publishes the old =market_tick=.
3. Add the runner. It holds the generators that run, keyed by vendor id. It takes the full demand set and
   answers accepted and rejected ids. It starts the generators the set adds, stops the ones it drops, and
   refuses a second generator for one vendor instrument. It knows nothing of NATS or of the database, so a
   unit test drives it.
4. Add the adapter. It announces the id =ore-simulated= for the provider =ore= with the universe of the
   generators it can build, answers the demand request on =marketdata.v1.adapters.ore-simulated.demand=, and
   sends a heartbeat. The generator configs it builds from are the ones the system tenant owns.
5. Remove the run grant, the run token cache and the restore walk. The feed identity, the restore pass, its
   retry policy, the restore verb and the run grant column of the collection go. A generator that starts
   from a vintage price reads marketdata as the service, so a vintage price in a tenant collection no longer
   resolves. The next task makes the generators system-owned, which is the case that remains.
6. Test the runner and the tick translation without a server, and the whole path (announce, demand, tick,
   ingest) against the live NATS and the rebuilt database.

*Pull request 2: the name.* Move =projects/ores.synthetic= to =projects/ores.marketdata.synthetic= and change the
component name, the library names, the namespaces, the include paths and the generated files with it. The
change is a script that runs the move and the regeneration, so the reviewer reruns it.

* Notes

*Pull request 1 (the adapter).* The simulator serves the market data service as the adapter =ore-simulated=
of the provider =ore=. It announces the ORE keys of the FX generators that the system collections hold,
answers each demand set with a generator for every key it can quote, and sends a heartbeat every 5 seconds.
The announce repeats every 60 seconds, so a market data service that restarts learns the adapter again.
An FX generator with an adapter target publishes =adapter_tick= on =marketdata.v1.ingress.ore-simulated.<key>=.
The runner keeps one generator for each vendor instrument: of two configs that quote one pair, the config
with the lower id wins and the other is logged.

The run grant, the run token cache and the restore walk are gone from the simulator. The feed identity,
the restore pass, its retry policy, the =restore_feeds= verb, the provisioning call to it and the
=run_grant_id= column of the collection are removed, and the database was recreated without the column. A
generator that starts from a vintage price reads marketdata as the service, which belongs to the system
tenant. A vintage price in a tenant collection no longer resolves; the next task makes the generators
system-owned.

What this pull request does not do:

- The old control plane stays. =start_feed=, =stop_feed= and the folder verbs still start a generator by
  hand, and that generator still publishes =market_tick= on its binding subject. The screens task retires
  them with the bindings screen.
- Rate curve generators are not adapter generators. The catalogue has no vendor rows for the curve pillars,
  so a curve generator keeps the old path.
- The adapter was tested against a fake market data service and the real FX generator on live NATS. A run
  of the real market data service, the adapter and a database together was not made.
