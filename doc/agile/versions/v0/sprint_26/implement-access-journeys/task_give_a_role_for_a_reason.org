An administrator gives a role with a reason a person understands, the grant records it, and the server refuses taking a role away from oneself.

* Acceptance

- iam.v1.roles.assign carries a change reason code and commentary, and the grant row stores them.
- An access change-reason category offers new joiner, role change, cover for absence and access review.
- iam.v1.roles.revoke refuses a caller taking a role away from their own account.
- Tests cover the stored reason, a reason nobody defined, and the self refusal.

* Plan

- The grant row already has =change_reason_code= and =change_commentary=, and
  its insert trigger validates the code; only the request lacked the fields.
  Add both to =assign_role_request= in the message model and regenerate, so
  the protocol, the shell command, the HTTP route and the web types agree.
- No seeded reason fits a person's access: the ones that apply to a new record
  are =system.*=. Seed an =access= category with new joiner, role change,
  cover for absence and access review.
- An empty reason keeps =system.new_record=, so provisioning, sign-up and the
  other platform callers do not change.
- A revoke closes the grant row, which has no place for a closing reason, so
  revoke carries none; the gap is recorded on the journey.
- Refuse a revoke whose caller is the account, in one helper both revoke
  subjects call.

* Result

Giving a role carries a reason, and nobody takes a role away from themselves.

- =iam.v1.roles.assign= carries =change_reason_code= and =change_commentary=,
  stored on the grant; an empty reason records =system.new_record=. The shell's
  =assign-role= takes both, and its recipe passes =access.new_joiner=.
- The =access= change-reason category holds =access.new_joiner=,
  =access.role_change=, =access.cover_for_absence= and =access.access_review=.
- =iam.v1.roles.revoke= and =iam.v1.roles.revoke-by-name= refuse a caller
  taking a role away from their own account.

Tests, on a recreated database: iam core 208 cases (four new), shell iam 315,
HTTP iam 22 pass. Not done: a reason on a revoke, which needs somewhere to
store it.
