This page gives the data of compass-ng's =route_inventory= codec, which writes
ORE Studio's HTTP route inventory,
=doc/knowledge/architecture/http_route_inventory.org=. The =* Definition= names
the codec; each table below is data the codec reads, and the prose says what it
is for. The tables were =HEADER= of =build/scripts/route_inventory.py=, the
rules, exceptions and views of =build/scripts/route_classification.py= and the
pairs and families of =build/scripts/route_pairing.py=; the code that finds the
routes and applies the decisions is compass's.

The same tables publish the HTTP areas, so they are also the data of
compass-ng's =model_rules= codec, which the =* Definition= names too. An area
is published when a rule or exemption gives a route it, and every =#+http_area:=
a model declares must be a published area. They were =AREAS= and =NO_AREA=
of =build/scripts/route_classification.py=.

* Rule

Every route the BFF and ores.http register is a row of the inventory, decided by
the Exemptions and Rules tables, and every BFF route the Pairs or Families
tables pair is counted as covered. =compass check= reports an inventory that
differs from what the tables and the code generate, and =compass generate=
writes it.

* Why

The classification work needs a list that cannot be short, so the routes are
read from the code that registers them, never typed. What a route is cannot be
read from the code: the design's four-way rule decides it, and the decisions are
this page's tables, beside the reasons, so changing one is an edit here and a
regeneration.

* Settings

The kind and area the codec gives a meaning to, one row per setting. Every
setting has a row.

| setting | value |
|---------+-------|
| composed kind | composed view |
| no area | (none) |

- =composed kind= :: The kind of a composed view: the routes a rule or exemption
  decides as it make the composed views section, each owing the obligations of
  the Views table.
- =no area= :: The area of a route that publishes none, written last in the area
  map and the coverage; a BFF route nothing decides is counted under it. It is
  the one area of the =area= columns that is not published, so no model may
  declare it.

* Rules

The decisions over a route's method and path, in order. A route an exemption
does not decide is decided by the first rule whose =server= is empty or names
the route's server and whose =pattern= accepts =METHOD /path=, the method in
capitals: =exact= when the two are equal, =prefix= when the route starts with
it, and =regex= when the pattern is found in it. The order carries meaning: a
narrow judgement stands before the family rule it would otherwise be swallowed
by. A route no rule decides is unclassified, and its kind and area are empty.

The line between a resource and a composed view is the number of collections the
answer weaves. One collection with its keys resolved is a resource; two or more
independent collections woven into one answer are a view.

* Views

A composed view owes four things (design section 11.1): a name in domain
language, a published schema, an owner, and a stated computation and cache
policy. The name is the =name= of the rule or exemption that decides it; the
schema follows from K1; this table holds the rest. The owner is the component
that must answer the question after the port, which is not always the one that
answers it today. A composed view with no row here owes nothing yet, and its
cells in the inventory are empty.

* Families

A BFF route that serves many resources at one address, paired with the C++
address that has ={resource}= in place of the resource. The =registry= is the
TypeScript file whose =array= lists the resources, and =needs= says which of
them must answer: =every= resource, those read by =one_key=, those read by a
parent (=list_by=), or those the registry marks =writable=. The coverage counts
the resources that must answer.

| BFF method | BFF path | registry | array | C++ method | C++ path | needs |
