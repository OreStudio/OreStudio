* Acceptance

- The ORE examples are the provider ORE, and no collection is without a provider
- Both feed tables carry an asset class code, checked against the asset class table
- The feed page read returns the provider, asset class, underlying, engine, frequency and run state
- A start or stop request names a filter and ids, and the service resolves the feeds

* Plan

The shape is the [[id:17E6CB2C-E1C9-4911-81AC-591D88AC5B89][Browse the feed tree prototype]].

- A collection names its provider, and the column is required. The ORE examples are a provider of their own, ORE, of kind reference, and the Generic provider is gone. Each provider's description says what it simulates.
- Both feed tables carry =asset_class_code=, checked against the asset class table: =fx= for an FX spot, =interest_rates= for an IR curve.
- One filter value, =feed_filter=, builds the query that pages the feed table and the query that resolves a selection, so a start applies to what the table shows. A pick names its ids; a filter names the folder (with the folders under it), provider, asset class, state and words, less the ids left out. Every part is checked or escaped.
- The page read returns the provider, asset class, underlying, engine, frequency and run state of each feed. The folder read counts the enabled auto-start feeds that are not running.
- =start_selected_feeds= and =stop_selected_feeds= use the same start and stop as the folder verbs, now one function.

* Result

Every collection names a provider and every feed has an asset class. The ORE examples are the provider ORE. The feed table read pages and filters on the server by state, provider, asset class, folder and words, and returns what each row needs. One request starts or stops the feeds a filter or a list of ids names.

Checked: the synthetic api suite (77 cases, 12 of them new for the filter), the synthetic core suite (43), the service suite (58, two new for the selection verbs), the shell and DQ suites, four pgTAP tests (publish with the asset class, scope, visibility, providers), and, as the Acme tenant administrator on a fresh database, the reads by provider, asset class, state and words, a start of the feeds that should run (54 started, none skipped, none left), a stop of a pick and a stop of a filter less one, and a refusal of a bad id and a bad state.
