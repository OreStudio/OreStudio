* Goal

The ingest loop reads an adapter tick, maps it through the provider mapping, applies the quality checks, finds the parties routed to the source, stores one observation for each and delivers the party tick.

* Acceptance

- The loop drops a tick with the reasons unmapped, not_a_number, out_of_range, stale and out_of_order, and counts each reason for each adapter.
- The loop refreshes its mapping and route caches from change events.
- A test shows a live source and a simulated source take the same path and write the same rows apart from source_id.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

1. Build a translator that maps an adapter tick through the provider mapping and applies the five checks, with no database or NATS, so each reason can be tested.
2. Make a route a consumer of its source in the loop, by building the loop's consumer from the route, so the existing batch, series and store code is the one path.
3. Subscribe the loop to the ingress subjects of all adapters and queue the translated ticks.
4. Record the id of the source on each stored tick.
5. Refresh the loop when a route, a source, a vendor instrument or a mapping changes.

* Result

An adapter tick now goes through the provider mapping and five checks before it is stored. =adapter_tick_translator= finds the source by the adapter id, the vendor instrument by provider, scheme, id and field, and the mapping that holds now. It drops a tick as unmapped, not_a_number, out_of_range, stale or out_of_order, and counts each drop for each adapter and reason. The loop subscribes to the ingress subjects of all adapters, and a route makes its party a consumer of its source, in the same table as a binding, so the existing batch, series and store code is the one path. The tick table records the id of the source for each row. The loop refreshes when a route, a source, a vendor instrument or a mapping changes. Eleven translator tests pass, with the tick writer tests: a live and a simulated source take the same path and differ in the source id only. The build of the service and core test targets passes.

Left for later tasks:
- The stored rows of the live path were not read back in a test against a database or NATS, because the worktree =.env= is at version 32.
- Reads of a series from the tick table, and a manual point, still give a nil =source_id=. The tick table holds it, and the read projections do not carry it yet.
- The bounds of out_of_range are one absolute limit for every item. Item bounds need a model that does not exist yet.
- A default route is not created for a new subscription, so a party with no route receives nothing from an adapter.
- The legacy synthetic subjects and feed bindings stay until the simulator moves in a later task.
