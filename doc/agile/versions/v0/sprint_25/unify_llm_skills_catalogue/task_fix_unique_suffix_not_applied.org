* Notes

Found while enabling =-Wall=. The compiler reported an unused =counter=
in =trade_generator.cpp=. The warning is a symptom, not the defect.

=needs_counter= in =codegen/core.py= turns the process-static counter
on when any column carries =requires_unique_suffix=. =trade.external_id=
carries it, so the counter is declared. The generator then emits

: r.identity.external_id = std::string();

with no suffix and no read of the counter. The column is under a unique
index, so the second synthetic trade written in one process collides on
an empty string.

Eight generated files declared the counter without consuming it. Seven
of those consume it elsewhere in the same function; =trade_generator.cpp=
was the only one that did not, which is why only it failed the build.
The template now marks the declaration =[[maybe_unused]]=, so a future
instance of this defect no longer announces itself at compile time. That
is the reason to fix the generator rather than leave the suppression to
stand in for it.
