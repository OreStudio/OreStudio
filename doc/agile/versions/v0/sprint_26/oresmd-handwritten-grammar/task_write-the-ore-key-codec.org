* Goal

=ore_key_codec= reads ORE key text into =market_datum= and writes it back. It
follows the structure of ORE's =marketdatumparser.cpp= and chooses each field by
the token's value, so it assigns fields the way ORE does.

* Acceptance

- Every key in the reference catalogue reads into the fields ORE assigns.
- For every key ORE accepts, =write(read(k)) == k=, or the canonical spelling where =k= is an alias.
- Every key ORE rejects is rejected, with an error that names the form expected.
- Dispatch is a =switch= on =instrument_type=, and the build fails on a missing case (=-Werror=switch-enum= on GCC and Clang, C4062 as an error on MSVC). No class hierarchy and no visitor.
- The settlement segment, the case of free-text names and every optional token survive the round trip. No form uses a silent default.
- The CDS running-spread form, the swaption payer/receiver flag, the commodity =DEL= and =ATM/<type>/DEL= forms, the equity =MNY= form and the 4-segment index CDS option form read into the right fields.

* Plan

One reader and one writer per instrument type, each citing the ORE form it
handles, split into one translation unit per asset-class family. Dispatch is a
=switch= on =instrument_type=; typed access inside a reader uses a non-owning
view over the datum. Test-first against the catalogue.

* Notes

The current readers choose fields by segment count. [[id:6D60C52C-26B9-416B-A453-478EE5CA33C5][the 2026-10-02 review]] lists the mislabelled
forms in section 1.

** How the test compares fields

The catalogue prints ORE's datum through ORE's own inspectors. The test
translates each datum into the same text: ORE's field names, ORE's defaults for
a token the key leaves out, and ORE's printing of periods (=12M= prints as
=1Y=, =14D= as =2W=), reals (six significant digits) and derived dates (the
as-of date plus the period, moved off a weekend). Each field ORE prints must
have a translation. A field without one fails the test, so no field goes
unchecked.

** Keys ORE accepts that the codec refuses

ORE reads part of these keys and drops the rest. No datum can write such a key
back, so the codec refuses it.

- =INDEX_CDS_OPTION= with five tokens, where the last token starts with a
  number but is not a number, such as =CDXIG/5Y/1Y=. ORE's =tryParseReal= uses
  =std::stod=, which reads the =1= of =1Y=, so ORE takes =1Y= as a strike of 1.
  The documented "index term then expiry" form therefore works in ORE only for
  an expiry that does not start with a digit. The catalogue form is listed in
  the test's =deliberately_refused= table with this reason.
- The forms in the unit test =the_codec_refuses_tokens_it_could_not_write_back=:
  a cap/floor or swaption shift with a trailing flag, a base correlation tranche
  with an attachment point, and a shape profile with a sixth token other than
  =DST=.

** Missing switch cases

The project builds with =-Wall -Werror= on GCC and Clang. =-Wall= turns on
=-Wswitch=, which reports a switch on an enum that has no =default= and misses
an enumerator. The dispatch switch has no =default=, so a new
=instrument_type= without a case fails the build. The task acceptance named
=-Werror=switch-enum=; that flag also reports switches that have a =default=,
and the family readers keep a =default= that throws, so =-Wswitch= is the flag
that fits. MSVC's equivalent, C4062, is off by default; =ore_key_codec.cpp=
turns it into an error with a =#pragma warning= so it applies to that file
only. No MSVC build ran on this branch, so the MSVC side is unverified.

** Open point

QuantLib reads a signed period such as =-1Y=. The model's period does not. No
catalogue key has a signed period, so the codec refuses one.

* Result

=ore_key_codec= in =ores.marketdata.core= reads ORE key text into
=market_datum= and writes it back. It reads every documented form and every
corpus key as ORE's parser does, except one form where ORE drops part of a
token (see the notes). It writes every key it reads back to the same text,
with aliases in their canonical spelling. A missing dispatch case fails the
build on GCC and Clang. The MSVC side is set up but not built on this branch.
