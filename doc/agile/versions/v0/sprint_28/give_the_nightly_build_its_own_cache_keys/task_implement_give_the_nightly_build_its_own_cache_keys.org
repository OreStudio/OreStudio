* Acceptance

- The continuous and nightly cache keys are disjoint.
- Restore, save and prune all use the workflow-scoped key in both workflows.
- The sum of the ceilings fits the 10 GB repository cap.

* Plan

Prefix the cache key in each workflow with the workflow name. The Continuous
Linux key becomes =sccache-continuous-<family>-<buildtype>-...= and the Nightly
Build key becomes =sccache-nightly-<family>-<buildtype>-...=. Change the restore
key, the =restore-keys= prefix, the save key and the prune prefix together, so
that no step keeps an unscoped key.

Keep one transitional legacy prefix in the Continuous Linux workflow only. The
entries that exist in the cache today were built by the continuous jobs, so the
continuous job must keep restoring them. Remove that prefix after the first
warm continuous run.

Lower the Nightly Build ceiling from 2000M to 1000M, because four nightly
variants draw on the same 10 GB repository cap as two continuous variants.

* Result

All six keys are scoped. The continuous workflow uses
=sccache-continuous-${{matrix.family}}-...= on restore, restore-keys, save and
prune; the nightly workflow uses =sccache-nightly-${{matrix.family}}-...= on the
same four places. The only remaining unscoped prefix is the transitional legacy
=restore-keys= entry in the continuous workflow.

The sum of the ceilings is 8.8 GB, which leaves about 1.2 GB of the 10 GB
repository cap for the non-sccache entries.
