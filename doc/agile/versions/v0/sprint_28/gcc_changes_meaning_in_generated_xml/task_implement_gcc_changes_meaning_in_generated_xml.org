* Goal

Make the generated xml headers compile with gcc. The nightly gcc builds fail
with =-Wchanges-meaning= because a record names a member after its own type,
or after a type that an earlier member uses.

* Acceptance

- Every generated xml header compiles with gcc and with clang.
- The xml bindings drift check passes.

* Plan

The nightly gcc-release run of 2026-10-18 failed in =credit_simulation.hpp=
after commit 73c676be80 added the generated header. gcc 12 and later reject a
member whose name is also the name of a type the record uses. clang accepts
it. A reproduction with g++ 16 confirmed the error, and the =struct= keyword
before the type removes it under both compilers.

=shadowed_types= in =generate_xml_bindings.py= already spells a type with
=struct= when an earlier member hides it. Widen the rule to every member of
the record: the member itself, an earlier member and a later member. Then
regenerate the bindings.
