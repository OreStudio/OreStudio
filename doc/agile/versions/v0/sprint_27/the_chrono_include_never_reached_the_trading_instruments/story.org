* Decisions

- *Commit the generator's output, do not edit the models.* The models are
  current; the six headers are simply output the gate never regenerated. Nothing
  in a model needs to move for the gate to go green.
- *Leave the template alone.* Its include sits behind =has_audit_columns=, while
  the =std::chrono::= member it serves sits behind =has_audit_columns= and not
  =has_audit_group=. An entity that carries =audit_record audit= therefore gets
  the include without the member. That is the template's shape on main and these
  six are its only instances. Whether the template should exclude them is a
  separate question, and this hotfix does not reach it.

* Out of scope

- Whether the domain class header template should skip the include for an entity
  with an audit group. See the second decision.
- The broad trading model sweep in [[id:C203937E-BB91-48F4-995D-523D3866D60C][Fix trading entity model drift]], which
  is a different, larger piece of work.

* Result

Done. `check_component_drift.py --component trading-cpp` reports no drifted
trading file. The six instrument headers carry the `#include <chrono>` the
template emits.

No model changed: the drift was a regeneration the gate's own commit never ran
for this component.
