* Goal

Serve the OpenID Connect authorization code flow in ores.http, so a browser that chooses a provider comes back with an ORE session or a refusal it can read. The start reads the provider's registration and its discovery, sets a state, a nonce and a PKCE challenge, and redirects. The callback validates the ID token against the provider's published keys — the issuer, the audience, the expiry, the nonce and the signature — and issues the same session cookie a password sign-in issues. A wrong state, a replayed nonce, an expired token, a token from another issuer, or an address whose domain the tenant does not allow each answers a refusal the screen can show.

* Acceptance

- A browser that chooses a provider returns with a session in the tenant the host named, and the session cookie is the one a password sign-in sets.
- The callback validates the ID token against the provider's published keys and refuses a bad issuer, audience, nonce, expiry or signature.
- The provider's keys are fetched once and cached, with a refresh when the provider rotates them, and the fetch has a time budget.
- Each refusal has a distinct shape, and the screen shows which rule stopped it.
- The route declares its catalogue place and permission as every other ores.http route does, and the gate passes.
