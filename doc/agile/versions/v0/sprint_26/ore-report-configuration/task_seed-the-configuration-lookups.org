This task seeds the configuration types. The today's market collection kinds
and the stress shift kinds are tasks of their own, because a pull request can
only merge once its task is closed.

*Configuration types.* The kinds come from ORE's own schemas: every global
element of a configuration schema in =external/ore/xsd=, excluding the run
document (=ORE=, which a report owns directly through =report_definition_id=,
not through a configuration), trades and portfolios, instrument and shared-type
fragments, collateral balances (data, not configuration) and the script
library. Each kind records the root element it serialises to, the component
that owns its entities, and the run-document parameter that names its file.
A test ties the seed to the binding: for every kind the binding can save, an
empty document must start with the seeded root element.

* Result

The configuration types are seeded, so a reporting configuration can now be
registered, and through it a report can point at its configuration.

**What a configuration type holds.** Its code, name and order, and now the root
element of the ORE document it serialises to, the component that owns its
entities, and the run-document parameter that names its file. The mapping from
a kind to its document is data, not code.

**The seventeen kinds** are the global elements of ORE's configuration schemas,
derived as recorded in
[[file:evidence/configuration_types_derivation.md][the derivation]]. The run
document is not one: a report owns its run setup directly through
=report_definition_id=. Historical return and Basel traffic light have no
run-document parameter, because no shipped run document names one.

**How it is proven.** For each of the twelve kinds the binding can save, an
empty document must open with exactly the seeded root element; breaking one row
to a prefix of the real name makes the test fail. The five kinds without a
binding are listed, so one that gains a binding without joining the check fails.
A migration adds the columns and the rows to a database created before the
change.

**Moved out.** The today's market collection kinds and the stress shift kinds
became tasks of their own, so that each can close with its own pull request.
The other lookups the task named were already seeded (analytic types, value
domains, pricing engine types) or wait for work that does not exist yet (risk
classes, for SIMM calibration).

**Component audit.** The task touched =ores.reporting= through one model, and
added a seed, a migration and a test. =validate_docs.sh= passes for all 41
components, and no folder, type or component changed.
