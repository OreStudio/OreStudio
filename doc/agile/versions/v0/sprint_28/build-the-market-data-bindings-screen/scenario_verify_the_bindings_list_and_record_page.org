This page documents a test scenario verifying [[id:27E932EB-7079-49A6-B61B-7F2056882FBE][Build the bindings list and record page]] in [[id:0EF4BCEC-5D8B-4C83-A229-793962AEAFD2][Build the bindings screen and clear the oresmd snags]]. It is filled in with the target screen and checklist of steps before testing starts; record the outcome by hand in =* Results=.

* Before you start

- The services run. Confirm with =./compass.sh services status=: 24 services running and =nats: running=.
- The web app serves this work tree. It listens on =ORES_WEB_PORT=, which is 21402, so the site is at =http://127.0.0.1:21402=.
- The database holds the Acme Corporation tenant with a party that owns feed bindings. The bindings are created by the =start_market_feeds= seed step (dataset =synthetic.feeds.bloomberg=), which runs during provisioning:
  #+begin_src sh
  ./compass.sh shell -f projects/ores.shell/scripts/library/provisioning/how_do_i_provision_the_system_with_acme_corporation_holding_group.ores
  #+end_src
- The source names to expect are =synthetic.refinitiv.<pair>= for the FX spots, such as =synthetic.refinitiv.eurusd=, and =synthetic.ice.<index>= for the interest rate curves, such as =synthetic.ice.gbplibor3m=. All are synthetic sources, enabled, and set to auto start.
- The Market data menu has no *Bindings* card yet: the card is a separate task (*Put Bindings in the Market data menu*). Open the list by its address, not from the menu. This is expected and is not a failure of this scenario.
- *Known blocker, 2026-10-15.* Provisioning does not finish in this build. The tenant setup stops at =publish_bundle: refdata.currency_groups= with =JetStream publish failed: Timeout=. The workflow service cannot command the refdata service because =ores.refdata.service= never declares a JetStream stream for its =refdata.v1.ops.*= step subjects; only the iam, synthetic, marketdata and workflow services create streams. The Acme tenant stays =bootstrapping= and the list has no rows. Clear this before running the scenario, or the list states in steps 2 to 5 show only the empty state.

* Steps

** Open the Bindings list by address

- In a terminal in this work tree, run =./compass.sh open-as tenant_admin=. Chrome opens on the sign-in page with the form filled in as =tenant_admin@acme_corporation=.
- Press *Sign in*. The home page loads and shows the Acme Corporation tenant.
- In the address bar, go to =http://127.0.0.1:21402/market-data/bindings=.
- The page shows the title *Bindings* and the lead *The feeds that write market data for this party: which source each one names, the series it writes and whether it runs.*
- The trail above the title reads *Home* then *Market data* then *Bindings*.

** Check the list columns and its rows

- The list shows six columns, left to right: *Source name*, *Kind*, *Series*, *Enabled*, *Status*, *Last tick*.
- *Source name* is drawn in a monospace face and names a source, for example =synthetic.refinitiv.eurusd=.
- *Kind* reads *Synthetic* for these rows.
- *Series* draws the series title as a link, and not the whole oresmd URL. The URL stays on the record page.
- *Enabled* reads *Yes*, and *Status* shows a tag, one of *Running*, *Stopped*, *Disabled* or *Quiet*.
- *Last tick* shows a time relative to now, such as *2 minutes ago*. A source with no tick yet shows a dash.
- If the list is empty, the page says so instead of drawing the table. Record which state you saw.

** Search the list by source name

- In the *Search* box, type =refinitiv= and press Enter.
- The list narrows to the rows whose source name holds that text, and the total count follows the search.
- Clear the box and press Enter. Every row of the party comes back.
- Now search for =zzzz=. The list says *No bindings match the search.* and offers *Clear the search*. Press *Clear the search*: the full list returns.

** Filter the list by kind

- The kind filter sits beside the search box and reads *All kinds* to begin with.
- Choose *Synthetic*. Every row shows *Synthetic* in the *Kind* column.
- Choose *Vendor*. The list is empty in this environment, because the seed makes only synthetic sources. That is the expected result, not a failure.

** Open a binding record page

- Click a row, or press Enter on it. The address ends in =/market-data/bindings/= and the record's id.
- The record page opens on its *Details* tab and draws the record as the record screen standard draws it.
- The main rows read *Source name*, *Kind* and *Enabled*, with the values of the row you opened.
- Under them, the extra rows read *Status*, *Last tick*, *Feed*, *Folder*, *Ticks per hour* and *Series*.
- *Feed* is a link to the feed behind the source; press it and the feed page opens. Return to the binding with *Back*.
- *Series* draws the series title as a link and, under it, the oresmd URL as the product ships it.
- The hint under *Series* reads *The series this binding writes to, and the oresmd URL that names it.*
- The last line of the record says who changed the binding last, when, and why.
- The header carries the access mark only for a person who may change a synthetic binding. You are =tenant_admin=, so it shows.
