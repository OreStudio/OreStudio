#+title: The drift checks render every component on every branch

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Render only the components a branch touched, and render each component
once. =component-drift= regenerates all 21 registry components in place
(239.9s) and =drift-sweep= renders all 38 catalogue components into a
throw-away root (195.9s). Together they are 436s of the 785s non-heavy
total, on a branch that usually changes one component.

* Why

Measured with =./compass.sh check --all --exclude-heavy= at 770fc62e23;
the per-check table is in =build/output/local_checks/report.md=. The two
checks are the same script in two modes, and the registry's 21 components
are rendered twice between them. =_touched_files(base)= already exists in
=check_component_drift.py= for the sweep's comparison, so the same set can
scope the render, widening to the whole catalogue only when the change
touches the generator, the templates or =component_registry.py=.
=component-drift= also gates seven other Prepare checks through
=after=("component-drift",)=, so its cost delays all of them.
