* Goal

The ORE path stops handing refdata one value that holds every family. It maps a conventions file into per-family payloads, stages them, and commits them as a bundle. Export goes the other way, one family at a time, and the file it writes is the same file it read.

* Acceptance

- The importer maps a conventions file into per-family payloads and stages each one. No message it sends carries every family.
- The exporter reads each family on its own and rebuilds the ORE file from those reads.
- The ORE conventions file is a package at the boundary. No refdata type that holds every family reaches ores.ore.
- A conventions file imported and exported unchanged produces the file it started from.

* Notes

* Notes

- The ORE conventions import ran as one call carrying the whole document. That call is gone from the service. =projects/ores.ore/service/src/messaging/run_configuration_operations.cpp= now opens an import, stages one message per family, and commits, and the export asks for each family in turn.
- A second path still saves the whole document. =projects/ores.ore/core/src/store/run_store.cpp= calls =conventions_document_service= to store the conventions a run's input package carries, and calls it again to write them back out. That service is the last caller of the aggregate, and it is the one task 1 has to move before the type can be deleted.
- The FX convention has no family of its own. The export skips it and the boundary mapper derives it from the currency pair, which is why the commit reply names the families it skipped.
- The export currently asks with a null =as_of=, so the families it reads are not read at one instant. Task 7 owns that.
