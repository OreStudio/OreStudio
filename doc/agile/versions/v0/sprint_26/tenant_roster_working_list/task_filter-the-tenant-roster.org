* Goal

A system administrator narrows the roster to a type and a status, and sees only
real tenants unless they ask for the test ones. Tenants of type =automation= are
test infrastructure: the type table describes them so, and the tenant generator
and the test fixtures write them. A development deployment holds many of them,
and they hide the real tenants.

* Acceptance

- The roster filters by tenant type and by status, from the deployment's own
  type and status rows.
- =automation= tenants are hidden by default. A *Show test tenants* toggle shows
  them, and the count says how many are hidden.
- The type column renders as a badge from the badge catalogue, the way the
  status column does since
  [[id:0DD8A141-2D77-47A0-A0EC-B4662767CCF6][Paint the tenant status with the badge catalogue]].
  The tenant type row has no badge reference yet, so it gains one, as the
  status row did, and the words stay the type row's own.
- The search request can leave a type out, so the server answers "every type but
  automation" and its total counts the same rows the page shows.
- The See the tenants journey and its wireframe record the filters and the
  toggle.
- Every new behaviour is proved by a test, and the screen was read against the
  running deployment.

* Plan

1. *Badges.* Four badge definitions, one per tenant type, in both the
   artefact and the system badge populates; =automation= reads as test
   infrastructure.
2. *The type row names its badge.* =ores.iam.tenant_type= gains =badge_code=,
   a soft reference to the badge catalogue, as =tenant_status= did. Regenerate
   the entity, and seed the four types with their badges.
3. *The type read.* A =readTenantTypes= beside =readTenantStatuses=, and
   =GET /api/tenant-types= with each type's badge.
4. *Leaving a type out.* The search request gains =exclude_type_filter=, and
   =ores_iam_tenants_search_fn= a matching parameter, so the server answers
   "every type but automation" with a total that counts the same rows. Test it.
5. *The BFF.* =/api/tenants= takes =type=, =status= and =includeTest=. Without
   =includeTest= it leaves =automation= out, and answers how many tenants that
   hid.
6. *The screen.* A type select and a status select from the deployment's own
   rows, a *Show test tenants* toggle that states the hidden count, and the type
   column painted with its badge.
7. *Records.* The See the tenants journey and its wireframe gain the filters
   and the toggle.
