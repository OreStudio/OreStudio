* Plan

Serve =GET /api/tenors/catalogue= from ores.http, as the synthetic and IAM views
were served.

| View | Computation | Cache policy |
|------+-------------+--------------|
| The tenor catalogue | three whole list reads: tenors, conventions, schedules | =ETag=, revalidated at each read |

Decisions:

- *Owner and place.* The view lives in =tenor_screen_routes=, beside the tenors
  screen's operations in =ores.http.refdata=, because that screen calls it.
- *Schema.* =tenor_catalogue= is a model of the three domain lists, published
  as the route's response and written by the codec. The rows are the domain
  rows the BFF passed on from the service.
- *Order.* The service will not order a tenor list by its sort order, so the
  view sorts the tenors by it, stable, as the BFF did: O/N before T/N before 1M.
- *Cache policy.* The inventory stated "stale after 5 min". The tenors screen
  writes tenors and conventions and reads the catalogue again, and the web
  client fetches with the browser's cache, so a =max-age= would show the
  catalogue from before that write. It is revalidated at each read instead,
  as the IAM views and the folder tree are.

* Result

The tenor catalogue is served by ores.http at the BFF's address, a published
model of the three lists with the tenors in their own order and a revalidated
=ETag=. Tests prove the order, the answer's member names and that the route
reaches the service.

Proved live on a freshly provisioned Acme deployment: the catalogue answers
200 with 46 tenors in their own order, 4 conventions and 2 schedules, with
=private, no-cache=, the =Vary= and the =ETag=; the same tag answers 304 with
no body; no session answers 401. Against the BFF's answer it is equal member
for member once nulls are set aside: the BFF writes null for an empty optional,
as the msgpack wire does, where the JSON codec leaves the member out. That
difference holds for every C++ answer, not this view alone, and the tenors
screen reads a missing multiplier as the text undefined, so it is raised as its
own decision rather than worked around here.

Component audit: the task touched ores.http (the refdata part). The view lives
in the tenors screen's unit; =validate_docs.sh= is run before the pull request.
