* Goal

Make the JSON codec write null for an empty optional, as the msgpack codec writes nil, so every C++ HTTP answer carries the members the BFF's answers carry and ores.web reads them as it reads the BFF's.

* Acceptance

- An empty optional is written as null by the JSON codec, and a missing or null member still reads as empty.
- The tenor catalogue matches the BFF's answer byte for byte where they hold the same rows.
- Tests that expected an absent member expect null.
- The ores.web change that read a missing calibration version as null is kept or removed on purpose.

* Plan

The JSON codec's object writer skipped an empty optional member; the msgpack
writer packs every member and writes nil for an empty one. The BFF decodes the
msgpack wire and answers null, so ores.web's types say =T | null= and its
screens test for null. A C++ answer that leaves the member out reads as
undefined: the tenors screen shows a tenor with no multiplier as the text
undefined. Found by comparing the C++ tenor catalogue with the BFF's on a live
deployment: equal member for member once nulls were set aside.

Decisions:

- The object writer writes null for an empty optional, as msgpack writes nil.
  Reads are unchanged: a member left out or null reads as empty, so every
  reader of the old form still reads the new one.
- The schema marks an optional member =nullable=, the OpenAPI 3.0.3 form, and
  keeps it out of =required=, because a request body may still leave it out.
- Code that tests whether a member exists in codec-written JSON would now see
  it. The JSON documents read that way (=provision_step_arguments=, the run
  configuration) are authored, not written by the codec, and the ORE
  projections read XML; the full test run and a provisioning run are the
  check.
- The ores.web change that read a missing calibration version as null is
  removed, with its test: the C++ answer states null again, as the BFF's does,
  so the client schema stays strict.
- Two tests of the views expected the member left out; they expect null again.

* Result

The JSON codec writes null for an empty optional, as the msgpack wire writes
nil, so every C++ HTTP answer carries the members the BFF's answers carry.
Reads are unchanged. The schema marks an optional member nullable. The full
test run found three tests that expected a member left out (the codec's object
test, the site deployment's TLS members, the printed market data options); they
expect null. The ores.web workaround for the calibration version is removed.

Component audit: the task touched ores.utility (the codec and its schema), and
tests in ores.http and ores.marketdata. No component changed shape.
