* Goal

Every import path (shell, Qt wizard, web) lands in a sandbox unless the user picks an official target on purpose. Today only a choices file can name a sandbox.

* Acceptance

- An import with no choice never creates a portfolio or book in the official tree. It lands in the party's open sample sandbox, or it fails.
- The caller can choose the official tree on purpose.
- The import can be proven for a second party, with a way to choose the party for the session.
- The Qt wizard and the web import offer the party's sandboxes. This tree has neither screen, so this part moves to the task that adds them.

* Plan

The server decides, so every client gets the default: the import service picks the sandbox when the choices name none. A client that wants the official tree says so with =official=.

1. Add =official= to the import choices, optional so that older choices files still parse.
2. In the import handler, when the choices name no sandbox, no existing parent portfolio, no existing target book and not =official=, read the open sample sandboxes and keep the one whose anchor portfolio belongs to the importing party.
3. Fail the import with a clear message when the party has no such sandbox. Never fall back to the official tree.
4. Add =--official= to the shell =ore import=.
5. Prove it on a clean database for two parties.

* Result

An import that names no sandbox now lands in the importing party's open sample sandbox. If the party has none, the import fails with a message, and the official tree stays untouched. =official= in the choices, or =--official= in the shell, picks the official tree on purpose. An import that names an existing parent portfolio or target book also counts as an official choice.

Proven on a clean database for two parties (see Measurements). Not done: the Qt and web screens, which do not exist here; a unit test of the lookup, which needs a NATS stand-in; the =attach_photos= failure above.
