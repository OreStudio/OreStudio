#+title: The ORE key codec refuses a signed period
#+description: QuantLib reads a period with a sign, such as -1Y, and the typed datum model does not, so the ORE key codec refuses a key ORE would accept.
#+type: capture
#+level: cross

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

QuantLib's period parser reads an optional sign, so ORE accepts a key such as
=MM/RATE/EUR/-1D/1D=. The typed datum model's =term= reads only an unsigned
period, so =ore_key_codec= refuses that key. Decide whether a signed period is
a form the model should hold. If it is, =term= gains a sign that survives the
round trip. If it is not, record the refusal as deliberate, beside the other
keys the codec refuses on purpose.

* Why

The codec's contract is to accept what ORE accepts. No key in the reference
catalogue or the example corpus has a signed period, so the catalogue test
cannot see this gap. A feed that sends a negative forward start would fail on
import with no test that predicted it.
