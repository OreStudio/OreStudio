#+title: How do I run the data_domains commands from the shell?
#+description: Every command the data_domains submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:data_domains:

This file documents the data_domains resource at the shell, one section per command. Every command is a subcommand of =data_domains=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 44DBFF49-7CAE-5C57-81DE-547B50EAEE16
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
data_domains list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =dq.v1.data_domains.list=.

#+name: data_domains-list
#+begin_src ores-shell :tangle data_domains-list.ores :exports none
data_domains list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 51568922-A79E-55F8-940B-9C598701C719
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
data_domains get <name>
#+end_example

It is addressed at =dq.v1.data_domains.get=.

#+name: data_domains-get
#+begin_src ores-shell :tangle data_domains-get.ores :exports none
data_domains get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 8413DCA3-8E3A-5D32-BAF0-0E26F8E6A038
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
data_domains add <name> <description> <reason> <commentary>
#+end_example

It is addressed at =dq.v1.data_domains.put=.

#+name: data_domains-add
#+begin_src ores-shell :tangle data_domains-add.ores :exports none
data_domains add __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 42134A97-F20E-556B-8426-65A1A11811F6
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
data_domains set <name> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =dq.v1.data_domains.put=.

#+name: data_domains-set
#+begin_src ores-shell :tangle data_domains-set.ores :exports none
data_domains set __none__ __none__ system.new_record generated_script
#+end_src
