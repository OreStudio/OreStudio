* Goal

* Acceptance

- A service row opens a log overview without leaving the view.
- The overview shows the tail, and can switch to the last warnings and the last errors.
- The overview names the unit and says when the journal has nothing for it.
- The route that serves it requires the browser session cookie, as the other two do.

* Plan

The plugin gains a third host route and a panel in the view.

- The route is keyed by unit and takes the filter and the line count, so the
  log is fetched when a reader asks for it rather than on the two-second
  environment poll. It requires the browser session cookie, as the state and
  action routes do.
- The overview opens from a service row and stays inside the view. Three
  choices: the tail, the last warnings, the last errors. It names the unit, and
  when the journal holds nothing for it the panel says so, because an empty box
  and a silent service are different facts.
- The panel does not follow the log live. The route is one-shot, and a reader
  presses Refresh, which is the same honesty rule the action strip already
  follows.

* Result

A service row offers its journal. The panel opens inside the view, names the
unit, and switches between the tail, the last warnings and the last errors. An
empty result says which it is, the journal holding nothing for that unit or
nothing at that level, because both are different facts from a failed read.
The =nats-server= row carries the same affordance.

The log is a third route and a second payload shape, fetched on demand rather
than with the environment. Writing it exposed a smell in the browser half that
the general field guard caught: two different payloads were both called
=snapshot=, so the guard could not tell the environment model from the log
model. The log one is named apart now and the guard covers both.
