* When to use this skill

Exposing an existing entity through one of the user-facing surfaces: the CLI,
the HTTP API, the shell REPL, or the Wt web UI. The procedure is the same for
all four, so it is one skill and a table; only the file locations, the build
target and the phase contents differ.

Prerequisites, in order: the domain type exists
([[id:B1450696-8C51-4CC5-8910-84912A411AB6][code-add-domain-type]]), and its
repository and table I/O are implemented. See
[[id:608675E1-4284-4902-99AC-4DA565390AFB][Entity lifecycle]] for the full
layer ordering.

The Qt client is not in this table. It has a codegen profile and a
generate-first flow of its own, which is a different procedure rather than a
different surface: use
[[id:C6ADAC80-F4E6-44E8-9525-3760CB98C41D][codegen-add-qt-entity]].

* How to use this skill

1. /Pick the surface/ and read its row below. The row names the build target,
   the patterns document holding its file locations and class shapes, and the
   walkthrough recipe.

2. /Gather requirements/: the entity name, the surface's own name for it
   (a plural hyphenated command, a menu name, a route), the operations
   needed, the key field, and the required and optional parameters.

3. /Work the three phases/, one PR each. The phases differ per surface and
   the row names them. Each phase ends in a building, reviewable state.

4. /Build after every step/ through compass, so the host-wide build lock is
   taken and a concurrent build in another worktree cannot corrupt this one
   (see [[id:F176FCA1-68D5-420D-B076-75A65FEE5EBB][How do I build the system?]]).

5. /Raise each phase's PR/ with [[id:4DF9BFE8-DC28-4220-AFF0-68E0A7CD5D2B][pr-raise]],
   branching between phases with [[id:6EEA2ACE-BD40-4209-9CBE-6A86553AEEB7][code-start-branch]].

* Codegen gap

None of these four surfaces has a codegen profile, so the code in them is
written by hand. That is a gap to close rather than a standing arrangement:
generated structure is the target state for every surface
([[id:D8CB6EED-1F6A-4EE5-840B-2FE28DE17911][Generated artefacts]]).

When a surface is reached during entity work, raise a sprint story for its
profile, link it to the entity task, and reference
[[id:608675E1-4284-4902-99AC-4DA565390AFB][Entity lifecycle]]§"Codegen gaps"
for what the profile must cover. Once the profile lands, regenerate the
surface and discard the hand-written code.
