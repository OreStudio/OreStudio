* Goal

The shell has one owner per menu and per verb. A duplicate registration fails loudly at startup instead of being resolved silently by the order of the calls in repl.cpp, and the dead hand-written verbs are migrated or deleted.

* Decisions

** One owner per menu, enforced at startup, not by registration order

cli::Menu holds its children in a vector and answers a name by first match, so
the order of the calls in repl.cpp decided which unit answered. The root is now
a shell_root_menu that claims a name once and refuses a second claim, and every
unit inserts through a seam the codegen template declares, so a component that
gains a unit joins the rule with no edit.

** A second unit extends a menu instead of registering its own

The generated entity unit owns the menu named for its entity. The hand-written
unit beside it contributes the verbs the model cannot express through
extend_menu, and the root applies those once every unit has registered, so the
order the units register in cannot decide whether an extension lands. Merging
rather than renaming keeps every verb at the address callers and recipes
already use.

** The name is read through Menu::Prompt()

cli::Command keeps a command's name protected, so the root cannot read it back
directly. Prompt() is the same string because every shell menu is constructed
from its name alone, and check_shell_menu_collisions.py rejects a construction
that passes a separate prompt, which is what holds the two together.
