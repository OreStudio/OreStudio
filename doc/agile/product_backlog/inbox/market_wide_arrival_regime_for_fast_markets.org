#+title: A market-wide arrival regime, so the desk can panic together
#+description: The arrival processes built so far model one stream, so each config row clusters on its own events and nothing makes FX, IR and credit burst at the same time. A fast market or a panic is exactly that: every series' intensity rises together for a while. The approach note already lists Regime-switching as a tick mode (two-state active/quiet with a state-transition matrix, lambda_active, lambda_quiet) but no code implements it. Options, cheapest first: (1) one shared market-state machine per run, calm/active, scaling every feed's baseline by a per-asset sensitivity; (2) a common-factor intensity added to every baseline, a shared shock stream that decays; (3) full multivariate Hawkes with a kernel matrix, faithful but O(N^2) and needing multivariate thinning. Option 1 matches the note's vocabulary and gives observable panic windows for scenario and QA runs; option 3 is the only one where one series' events excite another's. All three need the per-row arrival parameters first, so they sit on top of the current task rather than inside it.
