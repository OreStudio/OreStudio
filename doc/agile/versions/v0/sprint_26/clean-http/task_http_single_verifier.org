#+title: Task: Verify session tokens at the gateway with IAM's key alone
#+description: The gateway authenticates HTTP sessions with a verifier that prefers IAM's published RS256 key and silently falls back to a symmetric HS256 secret it generates. The fallback is a second trust root, it authenticates nothing legitimate because the gateway never mints, and it masks a failed key fetch. Remove it, so the edge has one way of being believed, and document how the edge verifies on the security architecture page.

* Goal

The gateway verifies session tokens with IAM's published RS256 key alone, holds no signing credential of its own, and refuses requests when it has no verifier; the security architecture page states how the edge verifies.

* Acceptance

- The gateway verifies with one verifier: IAM's RS256 public key, fetched from its JWKS at startup.
- The HS256 path is gone: no option, no parser requirement, and no environment variable.
- A session with no verifier refuses every request, so a failed key fetch cannot fall back to anything weaker.
- The HTTP edge's verification is documented on the security architecture page.
