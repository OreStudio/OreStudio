* Result

The composite convention has a publish path. One artefact table per live
table stages the identity and the payload, never the uuid and never the
party, because the database assigns the key and the publish names the
party. The existing conventions publisher delegates to a composite one for
the atomised kind, so there is still one dataset, one artefact type and
one subject.

Identity resolves by party, kind and name, and each part's live rows are
made exactly the staged rows. That closure is what closes the old leg form
when a convention changes form, instead of leaving it carrying both forms
at once; the document path closes omitted forms too.

Exercised on a recreated database against the real ore.conventions
dataset: a first publish inserted the staged conventions, a republish
changed nothing and left every version untouched, and restaging one
convention in the other form inserted one part and closed the other.
pgTAP now covers this publisher; the flat one had no test at all.

Left deliberately: the publishers declare p_mode and never read it, while
the contract says it accepts upsert, insert-only and replace-all. The
contract and the code disagree, and one parameter cannot express both the
row conflict and the closure, so it needs its own decision.
