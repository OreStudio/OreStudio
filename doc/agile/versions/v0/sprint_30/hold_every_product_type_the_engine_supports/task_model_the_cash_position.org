* Acceptance

- the type names an instrument table carrying its currency, amount and dates
- the projection reads and writes the element, value for value
- the type has a builder, and the catalogue routes it
- the generator books one trade of each type through its builder, and the recorded trades hold it
- the ORE engine test reads and builds each, with no error of the trade kind
- every fact the element states is a column or a row: no list, basket or schedule is held as text

* Plan

=CashPositionData= states a currency and an amount, and no dates: ORE's schema
gives the element those two members only. It routes to the scripted
instrument table through the class-read path, which holds each as a parameter
row. =cash_position_builder= refuses an empty currency and a zero amount; a
negative amount is a short position. The equity planner books it, as the
catalogue's family says, in the book's currency.
