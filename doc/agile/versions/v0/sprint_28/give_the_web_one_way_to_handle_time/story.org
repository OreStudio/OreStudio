#+title: Story: Give the web one way to handle time and timestamps
#+description: ores.web has no single owner for time. The wire-protocol package validates only four timestamp fields with wireTimestampSchema; at least twelve timestamp-shaped fields are plain z.string(), including eventTime, three recordedAt, startTime, endTime, givenAt, assigned_at, occurred_at and two more recorded_at. Nothing checks those, so server drift reaches the browser silently. Worse, the server sometimes does not send the project's wire shape at all: auth_event.event_time is std::string in the operations protocol even though the domain holds a time_point, so it bypasses to_iso8601_utc and carries the database's textual rendering, '2026-10-17 15:27:23.511414+01' in a +01 session and '+00' in a UTC one. The same instant therefore serialises two ways depending on the reader's timezone. The accounts outage (GET /api/accounts 500, 'Not a wire timestamp' at every recorded_at) was this same class of drift caught loudly because that one field was validated; the unvalidated ones would have failed silently.

* Goal

A person working in ores.web should have exactly one place that knows how a timestamp is written, read and converted, and no way to hand-roll a second. The server should send every instant in the project's wire shape, independent of the process timezone, and the client should reject anything that is not that shape instead of trusting a bare string.

The web's convention must be the server's convention, not a second one written to agree with it. The server owns the definition - one serializer, one architecture page - and the web module mirrors it exactly: same separator, same optional fraction, same UTC marker, same timezone independence. Where the two disagree, the server is right and the web is the bug, and a disagreement must fail a test rather than be reconciled by loosening a pattern. A pattern that merely accepts whatever the server happens to emit today is not a shared convention; it is the same drift with a later alarm.

* Acceptance

- ores.web has one module that owns parsing a server wire timestamp (a space separator, a Z suffix and an optional one-to-six digit fraction), formatting one for the wire, and converting to and from a JS Date and a branded WireTimestamp; no other module reimplements any of them
- every time-valued field in the wire-protocol schemas is typed with that module's schema; none is a plain z.string(); absent values are modelled explicitly instead of passing an empty string that silently satisfies the type
- the server sends every instant in the project's wire shape: auth_event.event_time no longer travels as a database textual rendering, it is formatted by one named function at the boundary, and the emitted string is identical whatever timezone the reading session uses
- an endpoint test feeds a captured live payload through each schema, so server drift fails a test rather than a browser; and the shared module has unit tests for a fraction of six digits, one digit, no fraction, an absent value, a malformed value, an impossible calendar date, and timezone independence
- the work is ordered producer first, then field types, so a silent bug is not converted into a crash and each change can be attributed; the sweep names every endpoint it touched and every field it left alone with a reason
- doc/knowledge/architecture/time_architecture.org states the wire shape once, as the single source of truth, and the TypeScript and C++ references point at it rather than restating it
- the web's convention IS the server's convention, not a parallel one written to agree with it: the definition is owned by the server's serializer and the architecture page, the web module mirrors it field for field - separator, optional fraction, UTC marker, timezone independence - and where the two disagree the server is right and the web is the bug
- a golden payload captured from the live server is committed to the web package and asserted against the web parser byte for byte, so changing the server's serializer fails the web's tests and changing the web's parser fails against the captured server bytes; a test that only round-trips the web's own output does not satisfy this
- the wire pattern accepts exactly what the server writes and no more - an optional one-to-six digit fraction as parse_utc_timestamp reads it - and it is never widened to whatever happens to arrive, since a pattern that accepts everything is the drift with a later alarm
- the web module and the server serializer agree on one instant across a timezone change: a test runs the same instant through both with the process timezone set to UTC and to a non-UTC zone and requires identical bytes
