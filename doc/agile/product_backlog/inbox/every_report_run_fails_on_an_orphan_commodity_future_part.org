#+title: Every report run fails on an orphan commodity future part
#+description: Since the conventions split, building a run's input refuses with 'Commodity future part commodity_future_averaging_terms names no commodity future convention' on a freshly provisioned Acme tenant, so no report runs.
#+type: capture
#+level: cross

#+updated: 2026-11-02

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

On main at 2c52d7fdfd, after a database recreate and the Acme provisioning, a run
of Group Consolidated Exposure fails at version 3, while the run's input is
built, with: Commodity future part "commodity_future_averaging_terms" names no
commodity future convention. The refusal is =join_commodity_future= in
=projects/ores.ore/core/src/domain/conventions_family_commodity_future.cpp=, added
by f3714dad5e as part of PR #4369, which split the commodity future convention
into a central row and parts. The package the run builds therefore carries an
averaging-terms part whose central convention row is not in the same package.
Instance a2fbe367-6bd0-4cd2-93fc-7c4101875faa on 2026-11-02 shows it.

* Why

No report run completes, so nothing downstream of input preparation can be
exercised end to end. Either the package query omits the central commodity
future rows the parts name, or the seed provisions parts for a convention it does
not provision. Before the refusal existed, the part was silently dropped from the
export, which is the loss the refusal was added to catch.
