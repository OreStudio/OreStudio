* Goal

The checks exist before the screens change, so the first screen work proves the checks. A failing check names the rule identifier it breaks. The reviewer has one procedure to sign off a screen: run the harness, walk the lines the harness cannot check, and record the outcome on the task.

* Acceptance

- Playwright runs against the environment ores.web, signs in as a seeded Acme user and opens a record screen, from one command.
- The harness discovers the record kinds from the wire protocol registries (records, classifications, convention kinds) and runs the same checks over each.
- Each structural rule the settled standard marks as checkable has one check, and the check reports the rule identifier on failure.
- The harness runs over today's screens and the failures are recorded as the baseline, one capture or task per screen family.
- A recipe states how a reviewer signs off a screen: the harness, the manual lines, and where the outcome is recorded.
- The Allium specification propagates tests where it can, and the harness carries the rest.
