* Notes

** Run under test

The NPV report of ACME Corporation HK Ltd (party =2307069c-69ab-49b1-b0ba-6363916a75a7=).
It binds one risk configuration, "Valuation - Trading Book", that holds only the
NPV analytic. The party holds 8 bonds, and the database holds 32 trades, all of
type Bond. The trigger is =reporting.v1.ops.trigger_report_instance=, and the
chain is in [[id:28438C94-4AE6-4455-8786-4CF02286944B][Report execution]].

** The environment, rebuilt on 2026-10-21

The database was recreated (=compass db recreate -y -k=), the services started,
and ACME provisioned with the =acme_demo= script. Every id from before the
recreate is gone. The party that was =2307069c-...= (ACME Corporation HK Ltd) is
now =734e60cd-d806-4f9b-9cd1-f571387d0224=.

** How the bond population is made

Provisioning makes it. The =acme_demo= seed profile has a =generate_trades= step
with four trade generation configs, one for each party: asset class =bond=, a
named book, a tenor band of 1Y to 10Y, a notional band of 100,000 to 10,000,000,
and seed 42. The step stores the configs in
=ores_synthetic_trade_generation_configs_tbl= and runs each as the party it books
for. The same run can be repeated by hand with
=synthetic generate-trades --config <id> [--config <id>...]=. A second run writes
nothing.

After the rebuild the population is 32 bond trades (8 for each of 4 parties) over
18 bond issues, measured with =compass sql= on 2026-10-21.

** Result

The NPV report of ACME Corporation HK Ltd (definition =99c87db3-3b6f-478b-b5c5-d2afbbcee778=) ran from the trigger to a completed instance, with the portfolio widened by hand, as issue 7 first said.

- Instance =66f4a841-a8c9-42b3-a01b-aa08f87192a2=, started and completed at 2026-10-21 01:53, about ten seconds.
- All seven steps completed: gather_trades (8 trades from 7 books), gather_market_data, assemble_bundle, prepare_ore_package, submit_compute, collect_compute_results, finalise.
- The output archive is =reporting/runs/66f4a841-a8c9-42b3-a01b-aa08f87192a2/output.tar.gz= (676,864 bytes).
- =npv.csv= holds 8 bond rows, all in HKD, each NPV close to its notional. The engine log says "built 0 failed trades". Its warnings are the missing security specific recovery rate for 5 bonds, which fall back on the credit curve's rate.
- Four counterparties read as =UNKNWN..= codes in =npv.csv=. Issue 9 explains why.

** Second run, from a clean seed

After the fixes for issues 3, 7 and 9 the database was recreated and ACME
provisioned again, with no hand-made change. The HK NPV report (definition
=3d7c0b29-ef1d-4d8d-a46a-fc9a7c6fe1fc=) completed as instance

counterparty reads =UNKNWN=. The counterparties with no Latin name read as
