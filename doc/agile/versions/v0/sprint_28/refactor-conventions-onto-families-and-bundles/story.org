* Goal

A convention is declared once, in its own entity, and carries only its own fields. Nothing in the code holds every family at the same time, so a change to one family cannot break another family's build. An import applies the families it carries as one unit of work, and a failure names the family that failed. The ORE conventions file is a package the boundary maps, not a type the components share.

* Acceptance

- Each convention family has its own operation model, generated from its entity, and no reflected type in refdata carries every family.
- One generated list names the families, their scope, and their repository, and nothing hand-maintained duplicates it.
- An import applies its families in one unit of work and reports an outcome for each family. A failure rolls the whole import back and leaves it staging.
- The ORE conventions file crosses into and out of refdata as a package. No component shares a type that holds every family.
- The web reads the family list from the generated registry rather than a hand-written table.
- The configuration document protocol compiles on MSVC without a compiler flag that deepens constexpr evaluation.
- Every read an export takes is taken at one bitemporal instant.

* Decisions

- A bundle is the largest atomic unit. The import stages one row per family and applies them in one unit of work, so a reader sees either all of the bundle or none of it. Nothing smaller is atomic and nothing larger is offered.
- The family list is generated once and every consumer derives from it. A hand-maintained list beside it is a second source of truth and drifts.
- The registry cannot dispatch by itself. A table of strings cannot call a typed repository, so the same generation emits the per-family apply, and the service calls generated functions instead of listing families by hand.
- The ORE FX convention is a projection, not an entity. It is a currency pair, that pair's convention, a spot lag and the pair's advance calendars, all of which are entities, so =fx= stays out of the registry and the boundary mapper derives it.
- The tenor basis swap family registers as its central row plus its two part rows, because that is what the document carried. Collapsing it to one entry is a later decision.
- The MSVC failure is accumulated context in the handler translation unit, not one over-wide literal. The investigation in [[id:9738A907-2C19-4B89-9B69-9411FA257F54][Fix the tenor basis swap convention model and the document TU]] measured it, and task 8 follows that finding.
- The conventions import owns no state of its own beyond the staging rows. A retried begin names the import it already opened, and a commit on an import that is not staging is refused, so a crash mid-import leaves an import that can be read and either committed or abandoned.

* Out of scope

- Collapsing the tenor basis swap family into one registry entry.
- Changing the ORE XML model. The generated =conventions.hpp= stays as it is. This story changes what crosses a component boundary, not the file format.
