* Goal

The TypeScript render emits a tree that no formatter owns, so the format check named in package.json has never passed and never run: there is no prettier configuration in the repository at all. The C++ render already runs clang-format over its output as a second step, and the drift gate depends on that, so the generated C++ is byte-identical to clang-format output. The TypeScript facets need the same second step, a committed style, and a workflow that runs the check.

* Acceptance

- A prettier configuration is committed and states the house style: 4-space indentation, single quotes, 100 columns, with JSON, Markdown and CSS at 2 spaces because that is their convention.
- The TypeScript render runs prettier over its own output, as the C++ render runs clang-format, so the generator and the drift gate agree byte for byte and no generated file is hand-formatted.
- package-lock.json is excluded, because npm owns the file.
- The generated tree and the hand-written tree both pass prettier --check.
- The TypeScript workflow runs the format check, and the codegen-drift workflow installs the same pinned prettier the workspace declares, because the drift gate reads every generated file as drifted without it.
- The TypeScript Clean Standard records what changed against its first audit, with the numbers re-measured at the commit that lands this.

* Decisions

- *The house style is the C++ style.* Four spaces, single quotes and 100
  columns, matching =.clang-format= (=IndentWidth: 4=, =ColumnLimit: 100=), so
  one style governs both languages. JSON, Markdown and CSS stay at two spaces,
  because that is the convention for those formats, and the configuration says
  so in an override rather than leaving it to a default.
- *The generator formats its own output.* The alternative was to exclude
  =src/generated/= from prettier and leave the templates as they are. Running
  prettier inside the render is what
  [[id:CDE625E2-96AE-4644-9921-282339925F3E][the TypeScript Clean Standard]]'s
  TS-R02 prefers, and it keeps the drift gate meaningful: the gate compares
  rendered bytes, so the render and the check have to format identically. It is
  also why no generated file is ever hand-formatted — the next regeneration
  would undo it.
- *One pinned prettier.* The workspace declares =3.9.8=, and the drift job
  installs the same version. A different prettier would read every generated
  file as drifted, which is the failure the clang-format install in that
  workflow already warns about.
- *=package-lock.json= is excluded.* npm owns the file. Reformatting it would
  add noise to every dependency change and could be undone by the next =npm
  install=.

* Out of scope

- The lint gate (TS-V05), coverage, and the live-fleet check (TS-V07). Each is
  its own item in the standard, and this story only closes the formatting ones.
- The C++ tree, which clang-format and =nightly-format.yml= already own.
- The templates' own whitespace. The formatter normalises the output, so a
  template that emits ragged indentation stops meaning anything.

* Result

prettier is the second step of the TypeScript render, as clang-format is the
second step of the C++ render, and the format check is a gate on a pull
request.

The style is committed in =.prettierrc.yaml= and applies the C++ widths, so one
style governs both languages. The tree is formatted: 216 files, 148 of them
generated. The generator and the drift gate agree on formatted bytes by
construction, which is what lets the gate stay a byte comparison.

Four items of the [[id:CDE625E2-96AE-4644-9921-282339925F3E][TypeScript Clean
Standard]] move: TS-R02, TS-H01 and TS-V04 are met, and TS-V08 is closer but
still open. The standard's first audit is corrected where it was read too
narrowly, and its new section carries the numbers.

Two things found on the way are captures rather than work: the documented
regenerate-all command generates components that do not project, and refdata's
generated wire projection is drifted. The second is why refdata's protocol
directory is excluded from the check, by name and with its reason.
