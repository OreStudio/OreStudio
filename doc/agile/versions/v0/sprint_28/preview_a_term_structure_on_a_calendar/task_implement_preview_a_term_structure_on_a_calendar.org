* Acceptance

- One wire call resolves all the tenors of a convention on a calendar and a horizon date, and returns a date or a refusal for each.
- A tenor that cannot resolve returns its refusal in its own entry, and the other entries still carry their dates.
- A test pins the dates for one convention, including an IMM roll convention.

* Plan

** What exists

No wire call resolves many tenors. The engine does, and the service hides that.

- =tenor_resolution_engine::resolve_batch= takes a span of requests and answers each by index, one status per row. A bad row does not stop the others.
- =tenor_resolution_service::resolve= reads one tenor, one convention and one resolution row. It builds a one-row batch and returns one =resolve_tenor_response=.
- The wire has =refdata.v1.ops.resolve_tenor= (one tenor) and =refdata.v1.ops.preview_tenor_resolution= (one draft). The BFF route =POST /api/tenors/resolve= serves the first.

** Approach

Add a convention-level operation beside =resolve_tenor=. It answers every resolution row of one convention in one reply.

1. Model =resolve_convention_request= (convention, calendar, horizon, optional spot) and =resolve_convention_response= (one entry per tenor: the tenor code and the fields of =resolve_tenor_response=) in =ores.refdata.tenor.org=. Regenerate the header and the TypeScript twin.
2. In =tenor_resolution_service=, split the engine-request build out of =resolve_rows=. Add =resolve_convention=. It reads the calendar once and builds one engine request per row. It makes one =resolve_batch= call. Rows that name a schedule share one schedule read per schedule code.
3. Register the subject in =tenor_registrar.cpp= and the handler.
4. Add the BFF route and its zod schema in =tenors.ts=, with a test in =tenors.test.ts=.
5. Test the service: a period convention and the IMM roll convention (=CREDIT_CDS_IMM=), plus one row that refuses while the others resolve.

** Open points

- The engine takes one =schedule_index= per request. Several rows can name different schedules in one convention. Step 2 must assign the index per distinct schedule.
- The calendar must be materialised past the horizon plus the longest tenor. The existing refusal =calendar_not_materialised= covers an absent calendar only.
