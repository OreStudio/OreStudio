#+title: How do I delete a compute host from the shell?
#+description: Close a compute host row by external id; stop the host's wrapper first.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:compute:hosts:
#+created: 2026-08-11
#+updated: 2026-09-26

The compute entity verbs live in their own shell menus, one per entity
(=apps=, =app_versions=, =platforms=, =batches=, =hosts=, =workunits=,
=results=). They talk to the ~ores.compute~ service over NATS; the
domain shapes and table renderers come from ~ores.compute.api~.

* Question

How do I delete a compute host from the shell?

* Answer

Log in as the system super admin, then run =hosts delete= with the host
external id, an audit reason and a comment. Stop the host's wrapper
first: a wrapper registers the host row on its first heartbeat, so a row
deleted under a running wrapper stays deleted while the wrapper keeps
heartbeating for it.

#+name: delete-compute-host
#+begin_src ores-shell :exports none
connect $ORES_NATS_URL
login super_admin@localhost Secure-Password-123
hosts delete $HOST_EXTERNAL_ID system.new_record "decommissioned"
logout
exit
#+end_src

#+begin_src sh :noweb yes :results output :wrap example
./ores.shell ${log_args} ${connect_args} << 'EOF'
<<delete-compute-host>>
EOF
#+end_src

The row is closed temporally: the current version gets a =valid_to=
stamp instead of being removed, so the grid history stays intact. The
external id comes from =hosts list=; it is the wrapper's own id, not the
row's =id=.
