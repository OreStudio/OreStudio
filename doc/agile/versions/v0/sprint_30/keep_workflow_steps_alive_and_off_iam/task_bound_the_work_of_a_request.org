* Result

Every request a provisioning step makes now costs what the request names, or
runs as a step: 46 request types were read handler by handler, and the five that
read a catalogue and narrowed it in memory now ask the store for their own rows.
The inventory is
[[id:BCC7D01B-6BA9-40F0-8402-41C9DC249DE6][The work each provisioning request does, and what bounds it]].

What the five were, and what they read now:

- =calibrate_fx_vol_surface= read every FX volatility pillar and every pillar
  source the tenant holds, to build one blueprint's recipe. It reads that
  blueprint's pillars through =fx_vol_surface_pillars_filter=, and their sources
  by pillar id.
- =compute_curve= and =publish_curve= read every IR curve pillar, to build one
  config's curve. They read that config's pillars.
- =publish_fx_forward= read every IR curve config, to find one currency's
  funding curve. It reads that currency's funding curves.
- =publish_fx_vol_surface= read every surface publish, to find a second raise of
  the same calibration. It reads the blueprint's own raises.

Each repository already offered the filtered, paged read: the handlers were
simply not using it. Each read is paged, so a request cannot be made unbounded
again by a tenant that adds rows.

Two request types needed more than a filtered read, and neither is an unbounded
read any more:

- =regenerate_calendar_dates= is bounded by the year and the calendars the
  request names, which the service caps, and it runs as a step with a 600 s
  deadline, so the story's second clause covers it. Its read of the existing
  days loads a whole calendar into memory to subtract them, which is a memory
  cost and is named in the recommendations.
- =attach_account_pictures= is the one request on this path that nothing bounds:
  it attaches a picture to every account of the tenant that names one, read
  10,000 at a time, and drops the rest without a word. It is captured as
  [[id:7849DEEF-9C8A-40C2-BA80-20C90505AB75][Attaching account pictures does a whole tenant's work in one request]]
  for the step that moves to its owning service.

The =put_many_*= handlers are bounded by the rows they are handed, but pay 2N+1
queries for N rows, which the recommendations name.
