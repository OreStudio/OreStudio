* S01 entity decisions

Two of the 33 entities without the facet are headers a caller must be able
to create, and they are opted in:

| Entity | Why |
|--------+-----|
| =bond_issue= | The shared ISIN row every instrument of the family references. =bond_instrument add= takes an =issue_id=, and nothing over the shell creates one, so a bond cannot be booked from scratch today. |
| =commodity_instrument= | The commodity family's header. It has no shell surface at all, so the family is unreachable over the shell. |
| =equity_position_option_underlying= | A hand-written application-local unit exposes it today. The standard prefers the generated unit, so opting the entity in replaces it rather than keeping a hand-written duplicate. |

verb would let a caller mint an orphan. They get no commands, and this is

* Plan

** 1. Enable the shell facet and generate

Set =:ores.cpp.shell-command.enabled: true= on the entities that should
have commands, or record the reason an entity has none. Generate the
units and their tests, then delete the hand-written units the generation
replaces. If the facet still has no aggregator archetype, build it in
the codegen library with a regression test.

** 2. Generate the recipes

Generate one recipe per command, regenerate the inventory, and run every
recipe against the live fleet. Record the run.

** 3. Seed the permissions

Take the 98 codes the handlers check, find the 92 that no populate
script seeds, seed them, grant them to the roles that need them, and add
the component to the permissions gate's registry. Then run the gate.

** 4. Run the audits and the surveys

- The Component Architecture Audit, with its record.
- The two-pass diagrams, reading the rendered image.
- The B06 consumer census over every public symbol.
- The H03 comment pass.
- The V08 per-file coverage survey.
- The V07 stub test: stub the subject and require the test to fail.

** 5. Recreate, start and run live

#+begin_src sh
./compass.sh db recreate -y -k
./compass.sh services start
ctest --test-dir build/output/linux-clang-debug-make -R "ores.trading" --output-on-failure
#+end_src

Run every generated shell command against the fleet. Record any command
that cannot run.

** 6. Enter the registry

Add the component to =COMPONENTS_UNDER_TEST= in
=projects/ores.codegen/scripts/component_registry.py= and run
=check_component_drift.py --all=. This is the last step, and it turns
every vacuous green into a real one.

** 7. Record every item

Fill the story's checklist with the final result per item, the evidence
file, and the reason for each not-applicable.
