#+title: How do I run the hosts commands from the shell?
#+description: Every command the hosts submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:hosts:

This file documents the hosts resource at the shell, one section per command. Every command is a subcommand of =hosts=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 1EC3FDF0-1964-51F6-B58C-79FD980526DA
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
hosts list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =compute.v1.hosts.list=.

#+name: hosts-list
#+begin_src ores-shell :tangle hosts-list.ores :exports none
hosts list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 261D86DB-9CF0-5905-BA73-EA7C0EF7C237
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
hosts get <external_id>
#+end_example

It is addressed at =compute.v1.hosts.get=.

#+name: hosts-get
#+begin_src ores-shell :tangle hosts-get.ores :exports none
hosts get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 409BE8DF-32D6-5C2F-8E2E-5DB4E74A83FB
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
hosts add <id> <external_id> <location> <cpu_count> <ram_mb> <gpu_type> <display_name> <last_rpc_time> <credit_total> <reason> <commentary>
#+end_example

It is addressed at =compute.v1.hosts.put=.

#+name: hosts-add
#+begin_src ores-shell :tangle hosts-add.ores :exports none
hosts add 00000000-0000-0000-0000-000000000000 __none__ __none__ 0 0 __none__ __none__ 1970-01-01T00:00:00Z 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 961DD095-1D87-5C59-8676-5A727E50DAD5
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
hosts set <id> <external_id> <location> <cpu_count> <ram_mb> <gpu_type> <display_name> <last_rpc_time> <credit_total> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =compute.v1.hosts.put=.

#+name: hosts-set
#+begin_src ores-shell :tangle hosts-set.ores :exports none
hosts set 00000000-0000-0000-0000-000000000000 __none__ __none__ 0 0 __none__ __none__ 1970-01-01T00:00:00Z 0 system.new_record generated_script
#+end_src
