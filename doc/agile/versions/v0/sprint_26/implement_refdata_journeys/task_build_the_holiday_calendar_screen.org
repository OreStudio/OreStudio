* Plan

1. Registry: calendars writable; rules, exceptions and events read by
   =calendar_code= and keyed by =id=; the year read and the rebuild as two
   calls beside the generic ones.
2. BFF: write schemas that admit only user calendars; a days route that
   pages to the year; a rebuild route.
3. Screen: panels by calendar shape (QuantLib, derived, bespoke); a field
   table with conditional fields so the rule form follows the rule kind; one
   parts panel for rules, exceptions and events, each row with its history.
4. Days panel: one year by month, with the cause of each holiday, a second
   calendar beside it, and the rebuild.
5. Live check on the real server, then correct the journey where the build
   proved it wrong.

* Result

Shipped the holiday calendar screen at =/refdata/calendars=, linked from the
reference data area, which now shows all four journey screens and the
classifications.

- A QuantLib calendar is read only, explains that QuantLib holds its
  holidays, and offers *Derive a calendar*. A derived calendar shows its
  exceptions over its base. A bespoke calendar also has its rules, described
  in words (=3rd Monday of January=, =+1 days from Easter=), with a form that
  asks only for the fields the rule kind uses.
- Rules, exceptions and diary events each keep their own history and revert.
- The business days panel shows one year by month with the cause of each
  holiday, lays a second calendar beside it, and rebuilds up to a year.
- Checked live: a bespoke calendar built the right 2026 holidays; a stale rule
  correction answered 409; the BFF refused a QuantLib write with 400.

The build found two server defects, now stated on the screen and in the
journey, and captured: a rebuild never rewrites a built day
(=calendar_rebuild_never_rewrites_built_days=), and a QuantLib calendar
builds without its holidays (=quantlib_calendars_build_without_holidays=).
A third capture records that nothing enforces a QuantLib calendar is read
only (=calendar_editability_not_enforced=). The ORE export stays unoffered,
as the journey says.
