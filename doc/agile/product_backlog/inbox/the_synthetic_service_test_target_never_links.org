* What

=compass build= fails at =ores.synthetic.service.tests= with undefined
references to every =ores::synthetic::service::feed_kind_registry= member and to
=make_default_feed_kind_registry= and =run_simulate_paths=. The test includes
=projects/ores.synthetic/service/src/feed_kind_registry.hpp=, which lives in the
private =src/= tree and carries no export macro, while
=projects/ores.synthetic/service/CMakeLists.txt= line 51 builds the library with
=-fvisibility=hidden -fvisibility-inlines-hidden=. The library does define the
117 symbols — =nm -C --defined-only libores.synthetic.service.so.0.0.28= finds
them — but none of them reach the dynamic symbol table, so no test that includes
the header can link. =publish/bin/ores.synthetic.service.tests= has never
existed in this checkout.

* Why

The failure stops a full build at target 3783 of 3864, so every gate that builds
the tree fails for a reason that has nothing to do with the change under test.
It was found on =a1152ae6ee= while running the checks for a marketdata history
fix, and that fix shares no file with it.

Two ways out: give =feed_kind_registry= the export macro and move its header to
the component's public =include/= tree, or move the two test files onto a seam
that is public already. The first is smaller and matches how the rest of the
service library exposes what its tests use.
