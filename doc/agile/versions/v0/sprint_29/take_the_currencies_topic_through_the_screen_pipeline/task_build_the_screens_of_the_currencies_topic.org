* Notes

Found while building step 1:

- The harness's RS-WRITE-24 check typed into the first text input, which on
  the pair dialog is a number; a number field drops nothing, but the error
  it showed on blur pushed Cancel down between mousedown and mouseup, so
  the click was lost, for a person as much as for the script. A field's
  error now takes the hint's line, so a message never moves the form, and
  the check types into a field that takes words.
- The pair's classification shows its code, =major=, where the prototype
  shows the label; the pair classification list is a read-only
  classification and its labels need a look in the test step.
- The closing guard watched the write, not what was typed, so a half-typed
  value did not count as a change; it watches the typed values now.
- The convention's versions have no Revert of their own in the pair's story:
  a part is reverted through its parent, as RS-HIST-02 offers Revert on the
  record's versions, and the calendar's rules have none either. Intended.

Found while building step 2:

- The ORE currency configuration carries a currency's name, codes, symbols,
  rounding and ORE type and nothing else. The first import compared and wrote
  every field, so a round trip marked 120 currencies changed and emptied
  their format, market tier, spot days, day basis and base precedence on the
  development database. The preview now reads the difference on the
  document's fields alone, the import lays the document over the tenant's
  row, and step 3 names the fields the document has no element for. The
  database was recreated and Acme provisioned again, which the schema drift
  needed anyway.
- The document carries the numeric code as a number, so 036 came back as 36
  and fifteen currencies read as changed; the importer pads it to the three
  digits ISO 4217 gives, with a core test.
- The import's choices default as the standard says: Keep it for a row the
  file omits, Take the file's for a changed or new one.
