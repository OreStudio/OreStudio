#+title: The trader applies an approved publish, which supersedes the live set and tells its readers
#+description: The apply checks the approval and the candidate's version, then publishes, ends every live set of the series and writes the notice in one transaction.
#+type: knowledge
#+level: cross
#+filetags: :architecture:marketdata:publish:approval:
#+created: 2026-11-11

* Summary

The apply is the trader's act, run with the approved request's id, and it is the only way a set becomes published. It checks the request, the candidate and the candidate's inputs again, because each may have moved since the raise. Then, in one transaction, it publishes the set, supersedes every set of the series that this one replaces, and writes the notice. A request a person approved and nobody applied lapses after the kind's apply window, so it never blocks its subject.

* Detail

** What the apply checks

| Check | Refusal, which closes the request |
|-------+-----------------------------------|
| The request is of the kind's publish kind | A request of another kind authorises nothing here. |
| The subject and as-of are the ones the request names | A request authorises one subject at one as-of. |
| The request is approved and within its apply window | A waiting, held, refused or lapsed request publishes nothing. |
| The request has not published already | A request publishes once. The next publish is a new request. |
| The candidate is still the version the request names | A candidate computed again after the raise was not decided. |
| No input of the candidate was withdrawn | A set built from withdrawn data is not published. |
| The live set's as-of is not newer | Another publish was applied in between. |

A refusal tells the trader why and closes the request, so the subject is free for a new raise.

** The one transaction

The apply stamps the publisher and the instant on the publish record, marks every published, unwithdrawn set of the series at an as-of at or before its own superseded, naming the request and the as-of that replaced it, and writes the notice. Either all of it is written or none is.

** The notice

The notice is a row written in the apply's transaction, an outbox, and is delivered from there after the commit and retried until it is delivered. It names the series, the set published and the set it replaced, and every reader of the series receives it, as [[id:7FAF3C0D-1131-4C32-9C29-3D1EF6D1005D][Notification requirements]] states. A delivery that fails is retried and never undoes the publish.

** The apply window

A request a person approved waits for the trader for the kind's apply window. When the window passes, the request lapses: it closes, nothing is published, and a new raise is possible. A request closed under a stated rule is applied in its raise ([[id:BF14C932-D699-4224-98DA-0481E49FA394][A publish raise names one candidate version, in one transaction]]) and never waits.

** Why the trader applies it

The trader who raised the publish is the one who knows when the desk should move to the new set, so the apply is the trader's act and not a workflow that runs on the decision, as [[id:53F31919-86FA-4E35-8594-9E72197C4A3B][Publish the approved set]] describes.
