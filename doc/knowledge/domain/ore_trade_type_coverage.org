* Summary

This page states, for every trade type the catalogue declares, what ORE does
with it and what ORE Studio holds of it. ORE's side is mined from ORE itself: a
harness asks ORE's trade factory for every registered type and the class it
builds, and a script reads ORE's source, schema and script library for the rest.
ORE Studio's side comes from the trade type catalogue and the recorded generated
trades. The last column names the task of
[[id:0CAC2F0E-69EC-4497-8587-4E0A6593BC7D][Hold every product type the engine supports]] that closes a
type's gap, so the coverage work has one index.

* Detail

** Reading the table

- *ORE form* is what ORE's trade factory builds for the type: =scripted= when the
  class derives from =ScriptedTrade=, =native= otherwise, and =not registered=
  when ORE has no builder for the type.
- *Catalogue form* is the =construction= the catalogue states today. Where it
  disagrees with ORE's form, the catalogue is wrong.
- *Data element* is the element ORE's =fromXML= reads. It is the type with any
  underscore removed followed by =Data=, except where ORE's class reads another
  element. The miner looks for the element's name as a quoted string in the
  class's source and its base classes. This is a text search, not a parse, so a
  match shows the name is present, not that =fromXML= reads it. An element ORE
  reads that the vendored XSD does not declare is marked.
- *Table* is the instrument table that holds a trade of the type, empty when no
  table holds it yet. *Generated* says whether a recorded generated trade exists.
- *Library scripts* are the scripts in ORE's Products script library that carry
  the same product as a generic =ScriptedTrade=. *Match* compares a script's code
  with the code ORE's class embeds: =identical= when they are the same text,
  =near= when they differ in small edits (a similarity of 0.7 or more), and
  =named= when the library holds a script of the product's name whose code
  differs.
- *Closed by* is each task of the story that owns one of the type's gaps: the tag task for a type ORE does not register, the form task for a form the catalogue misstates, the both-forms task for a type with a library script, and any task whose description names the type.

** How the evidence is mined

=external/ore/tools/datum_catalogue/regenerate.sh= builds =trade_catalogue=
against a local ORE build, which prints every registered type with its class
and form, and runs =mine_trade_types.py=, which joins that with ORE's source,
the XSD, the Products script library, the curated
=trade_type_twins.txt= and =trade_type_elements.txt=, and the catalogue. The
result is =external/ore/catalogue/trade_types.tsv=, with the ORE commit in
=ore_version.txt=. This page is generated from that table by
=build/scripts/generate_trade_type_coverage.py=; its =--check= mode fails when
the page is stale.

** Findings

- ORE reads 39 trade types through a =ScriptedTrade= class: the accumulators,
  target redemption forwards, basket, rainbow, best-entry, strike-resettable,
  window and generic barrier options, the basket variance swaps, worst-of basket
  swaps, forward volatility agreements, =KnockOutSwap=, and the four classes
  named for their script. The catalogue states five of them as scripted.
- =CommodityPairwiseVarianceSwap= and the bare =ForwardVolatilityAgreement= have
  no ORE trade builder. ORE still carries both products as a generic
  =ScriptedTrade=, over the library scripts =PairwiseVarianceSwap= and
  =ForwardVolatilityAgreement=.
- ORE reads =CommodityWindowBarrierOptionData=, which the vendored XSD does not
  declare, so a writer that follows the XSD cannot write the type.
- Three types read an element other than the convention's: =BondPosition=
  reads =BondBasketData=, =CommoditySwap= reads =SwapData= and =SyntheticCDO=
  reads =CdoData=.
- The basket, rainbow and best-entry classes embed the library's own script
  text, so their two forms are the same payoff by construction. The accumulator,
  TaRF, window barrier and basket variance swap scripts are near copies. The
  generic barrier, worst-of basket swap, forward volatility, pairwise variance
  and outperformance scripts share only the product.
