* Goal

The story planned a table for every one of the twenty corpus root elements.
Counting the consumers first showed that eight of them have none: no product
code reads those documents, so there is no mapper to migrate and no feature
that a table would serve. Building eight tables, and their harness cases, would
prove a capability nothing uses. They are deleted instead, and a table is added
if a feature ever needs one.

* Acceptance

- Every corpus root element is classified as supported, migrating or unused,
  and a check fails when the tree stops agreeing with that.
- A family classified unused has no test that names it, so the deletion stays
  deleted rather than growing back as an unused test.
- The deleted families' mapper and its tests go together, so no dead code is
  left behind.
- What remains compiles and the XML suites pass.

* Plan

*Count consumers before mapping anything.* The boundary between "migrate" and
"delete" is whether product code reads the family, and that is a grep, not a
judgement: =domain.hpp= -- the generated binding -- is included by six product
files plus the mappers, so the families a mapper reaches are the ones that
matter.

*The census is a decision, and a check.* =build/scripts/check_xml_family_coverage.py=
names each family's state with its evidence and fails when the tree disagrees:
a supported family without a table, an unused family with a test, or a corpus
root nobody classified. The check is what stops "eight families to delete" from
becoming "eight families nobody got to".

*Provisionally supported, permanently deleted.* Counterparty information and
ibor fallback config already have tables, so they stay in the supported set even
though nothing reads them yet: the table costs nothing to keep and the harness
already proves it. The other eight are deleted -- their tests, and the one
mapper nothing called (=stress_test_mapper=, whose only users were the tests
being deleted; the analytics stress test domain is seeded from JSON, not from
ORE XML).

*What is not deleted here* is the xsdcpp-generated type surface for those
families. It is generated from =input.xsd= as one unit, so it leaves when
xsdcpp leaves, which is the last task.
