* Goal

Every shell command analytics answers is produced by a generated unit. Nine of the twelve analytics models already render one. The three stress-test entities (stress_test_library, stress_test_scenario, stress_test_shift) render nothing: each carries no :profile: and no drawer opt-in, so the facet never fires. The task gives each one a generated unit, or records why the shell is not the surface that should produce it.

* Acceptance

- Every analytics entity, junction or operation model is either covered by a generated shell unit or recorded on this task with the reason it is not.
- The three stress-test entities each have a stated outcome: a generated unit, or a recorded reason.
- No hand-written unit registers an analytics menu or verb, or each one that does is recorded with its reason.
- The analytics shell suite passes.

* Plan

Analytics needs no code change, so the task is a measurement and two negative
claims. First, map every analytics model to the unit it renders: nine of the
twelve do, and the three that do not are the stress-test entities another story
is still modelling. Second, prove that no hand-written unit registers an
analytics menu or verb, and that no hand-written unit extends a generated
analytics menu. Third, build and run the component's shell suite as the
evidence that the generated units compile and pass against the current trunk.

* Notes

The three stress-test entities are not a gap in this task. =stress_test_library=,
=stress_test_scenario= and =stress_test_shift= were added on 2026-09-29 by
[[id:EC3B6F30-2A64-4FAB-9E5A-71A5A5645C9B][Model the ORE report configuration as entities]],
which environment =bright_faraday= still holds. They carry no =:profile:= and no
facet opt-in at all, so the shell is not the only facet that is off for them.
Binding them to a profile is that story's decision. Enabling the shell facet on
its own would not work either: the facet is dropped when =ores.cpp.protocol= is
off, so a drawer entry with no profile renders nothing.

=analytics_commands.cpp= is hand-written and registers no command of its own. It
calls the nine generated units' =register_commands= in turn. The facet page
records the same gap and its fix: the aggregator needs a component-scoped
archetype and a render-time list of the component's opted-in entities, which is
a generator change and not a shell-cleanup one. It is recorded here because it is
the one hand-written file in the component's shell part.

* Result

Analytics closes with no code change, which is the finding: nine of its twelve
models already render a shell unit and nothing hand-written sits beside them.

The three that render nothing are the stress-test entities, and they belong to
[[id:EC3B6F30-2A64-4FAB-9E5A-71A5A5645C9B][Model the ORE report configuration as entities]]
rather than to this story. Their models carry no profile, so no facet is on for
them; the shell cannot be switched on in isolation because the facet is dropped
when the protocol is off. This task records that rather than reaching into
another environment's in-flight work.

The component's one hand-written file is the aggregator, which registers no
command. Its generation is a facet change recorded in the notes, not a shell
clean-up.
