This recipe covers all code generation profiles for a =domain_entity= model.
See [[id:FE693595-6693-459B-AD9B-EB7E3ABBBC88][ores.codegen architecture]] for the profile system and [[id:F556E446-EB91-4656-BEDC-15AE0F7B5ECD][Entity commissioning process reference]] for output location checks and drift classification.

* Question

How do I regenerate all the code for a domain entity?

* Answer

One scoped =generate= writes every layer of the entity, SQL and every C++
facet its model admits:

#+begin_src sh
./compass.sh diff --scope projects/ores.refdata/modeling/ores.refdata.rounding_type.org
./compass.sh generate --scope projects/ores.refdata/modeling/ores.refdata.rounding_type.org
#+end_src

Only the outputs whose content changed are written, so the resulting
=git diff= is the entity's change and nothing else. For a template change, or
any change that reaches more than one entity, run =./compass.sh diff= and then
=./compass.sh generate= over the whole tree.

*Before committing*, verify each generated file landed in the correct split project directory — not the stale monolith paths. See [[id:F556E446-EB91-4656-BEDC-15AE0F7B5ECD][Entity commissioning process reference]] § Codegen sync task acceptance criteria, output location check.

* Script

=./compass.sh generate= and =./compass.sh diff= forward to compass-ng through
=cmd_compass_ng= in [[proj:projects/ores.compass/src/compass.py][=compass.py=]]; its =codegen= codec renders the templates
of [[proj:projects/ores.codegen/library/templates][=projects/ores.codegen/library/templates=]].

* Tested by

Manual: run the scoped =generate= for a target entity, inspect the diff and
verify the output paths against the location table in [[id:F556E446-EB91-4656-BEDC-15AE0F7B5ECD][Entity commissioning process reference]].
