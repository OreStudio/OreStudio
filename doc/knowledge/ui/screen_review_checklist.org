#+title: Screen review checklist
#+description: One line per rule of the UX standards, to tick off when a record or entity screen is built or reviewed.

* Summary

This page turns the UX standards into one list of checks. Use it when you build
a screen and when you review one. Each line is one rule and names the page and
section that state it. The list adds no rule. If a line and its source differ,
the source is right and this page is wrong.

Mark each line /Meets/, /Gap/ or /N/A/. Write a gap in the story or task that
owns the screen, with the line it breaks. Where the two standards disagree, the
line says so. The [[id:BD492939-118E-4B55-AE5B-300F7A1C3B41][Entity screen specification]] rules for an entity. The [[id:2BF7F03F-6BF4-45FF-8E26-4D3B4E2D943D][Record screen standard]] rules
for one kind of record.

Source names: RSS is the Record screen standard, ESS is the Entity screen
specification, UXL is [[id:166B2D77-6D04-47D5-A651-5431E1F2E082][UX Language]], UDP is [[id:6743F6E3-578C-4E4B-9DD6-D5A0DF6734C8][UI design principles]],
CFG is the [[id:E69C008D-7092-4855-98EC-47A75F422F61][Configuration screen standard]].

* Detail

** The list

- [ ] The header has the breadcrumb, the plural title in sentence case and one sentence on what the records are. (RSS The list › Header)
- [ ] Refresh, then Workflows, then Add stand at the right. Add shows only for a person who may write. (RSS The list › Header)
- [ ] Search, sort, filter and page go to the server. The list never reads every row. (RSS Search and filter, Paging; ESS Paging)
- [ ] The pager shows the count first, then First, Previous, Next, Last and page size. The default is 15. (RSS Paging)
- [ ] Page, page size, search, filter and order live in the address. (RSS Paging)
- [ ] Every column sorts on the server, on the value and not on the text shown. (RSS The table)
- [ ] The first column is the display field or the key. A click or Enter opens the record page. (RSS The table)
- [ ] Audit columns are hidden by default. A tenant id and a UUID id never show. (RSS The table)
- [ ] The list shows these states: loading, loading again with dimmed rows, none yet, nothing matches with a way to clear, and an error in place with Retry. (RSS States)
- [ ] A party appears as a tag with its name, not its code. (ESS The list)
- [ ] Rows that changed after a reload are marked for a short time. (RSS Recency; ESS Rows and entries that changed)

** The record page

- [ ] The breadcrumb ends at the subject. The title is the display field. (RSS Header; ESS Header)
- [ ] Tabs live in the address. Details is first and History is last. A tab that does not apply is not drawn. (RSS Tabs; ESS Tabs)
- [ ] A label stands above each value, in sentence case, with no colon. (RSS Fields)
- [ ] An empty value is a muted dash. (RSS Fields)
- [ ] A code that names another record is a link to its page, with its flag or photo. (RSS Fields; ESS References are links)
- [ ] A link that cannot open is plain text. It is never a link that goes nowhere. (ESS References are links)
- [ ] A person is drawn with the photo and a link to the person. (ESS People are links)
- [ ] The details end with the last-changed line. (RSS Last changed)
- [ ] A value shows as a name, never as an identifier, where a name exists. (ESS Feedback, states and words)
- [ ] The page shows the access mark, Editable or Read only. It never shows a permission code. (UXL Access; RSS Access)
- [ ] An action the person may not take is not drawn. It is not drawn disabled. (RSS Access; ESS Changes the reader may not make)
- [ ] A record the server will not change shows no Edit and no Delete. One notice says why. (RSS Read-only records)
- [ ] The screen does not explain what is absent. A sentence that only explains an empty space is removed. (ESS Feedback, states and words)

** Edit

- [ ] Edit is one button with an icon and the word Edit. It is on the card it changes. (ESS The Edit pattern)
- [ ] The page header has no Edit. (ESS Header). RSS puts Edit in the header of a record page. Follow ESS for an entity.
- [ ] Edit opens a modal dialog over the page. The dialog has no address. (RSS Addresses)
- [ ] The dialog title is "Edit <key>" (RSS Amend) or names the card (ESS The Edit pattern). Pick one per screen.
- [ ] The dialog asks for the change reason and commentary. The page asks for neither. (ESS The Edit pattern)
- [ ] The reasons follow the change. "No change in substance" is offered only when nothing changed. (RSS Amend)
- [ ] Save stays disabled until a field differs from the record. (ESS The Edit pattern). RSS does not say this.
- [ ] A commentary is required when the chosen reason needs one. (RSS Amend)
- [ ] A wrong field shows its message under it when the person leaves it. Save waits until the form is complete. (RSS The form)
- [ ] The write claims the version that was read. A stale save is refused, and the dialog says so and offers to reload. (RSS Amend; ESS The Edit pattern)
- [ ] While the dialog is open it listens for a newer version. A warning shows who changed what and offers Keep my edit or Take the new values. (ESS An edit in progress)
- [ ] The dialog says under its title when the record was loaded. (ESS An edit in progress)
- [ ] Closing with changes asks "You have unsaved changes. Close anyway?" (RSS Amend)
- [ ] The server's own words show in the dialog. The dialog stays open. (RSS Feedback)
- [ ] After a save the dialog closes. Refresh turns gold and the person presses it. The page does not reload by itself. (ESS Refresh)
- [ ] An optional field has a Clear control. (ESS The Edit pattern)

** Fields in the form

- [ ] Each field uses the control for its kind: text, number, Yes and No, date, select, picker or image. (RSS The form)
- [ ] A field that names another record or a classification is a select. It is never free text. (RSS The form)
- [ ] A combo box offers only values that exist, as the server holds them. (ESS Combo boxes and filters)
- [ ] A screen that shows one value at a time has no "all" choice. (ESS Combo boxes and filters)
- [ ] The key is fixed after the record exists. So is a field that changes what the record is. (RSS The form)
- [ ] A fixed field says why in one line of small text under it. (ESS Cards)
- [ ] A field that another person owns says who. (ESS Cards)
- [ ] A field that follows from others is not asked for. The dialog fills it. (RSS The form)
- [ ] A rule across fields shows before the save. Save waits on it. (RSS The form)
- [ ] Long text uses a text area. (RSS The form)

** Create and delete

- [ ] Add is titled "Add <thing>" with the button Add. A new record uses the reason =system.new_record=, stated in a note. (RSS Create)
- [ ] A key that exists is refused, and the refusal names the key. (RSS Create)
- [ ] After a create the screen opens the new record page. (RSS Create)
- [ ] Delete always confirms, names the record and says what is lost. (RSS Delete; Safety)
- [ ] Delete asks for a reason. After it the screen returns to the list. (RSS Delete)
- [ ] A link is removed with Remove, not Delete. (RSS Links)
- [ ] Revert writes a new version and says so. (RSS History; Safety)

** History

- [ ] History is the versions of one record. A log of events is Audit and has Refresh only. (UXL History and Audit)
- [ ] The tab is named History, never Timeline. (ESS How the Staff screens conform today)
- [ ] The shared timeline draws it. Headers are one line, details open on demand. (ESS History and the timeline)
- [ ] The author's photo stands at the left of each entry. The note is on its own line. (ESS One line per entry)
- [ ] The newest version carries the current-version emblem and no Revert. (ESS One line per entry)
- [ ] A gap in the history is stated in words. It is never an empty list. (ESS Gaps)

** Refresh and live updates

- [ ] The header has the shared Refresh button, with the load time under it. (ESS Refresh, When the data was loaded)
- [ ] Refresh turns gold when the data changed on the server. Gold means that and nothing else. (ESS Refresh)
- [ ] Nothing reloads by itself. Nothing the person typed is lost. (ESS Updates and refresh)
- [ ] The screen names the entities it shows, so it hears only their changes. (ESS How a screen hears)

** Words, icons and colour

- [ ] The verbs are Add, Edit, Save, Delete, Remove, Revert, Refresh, Cancel and Propose. An own action is a verb and its object. (RSS Naming; ESS Feedback, states and words)
- [ ] Every action carries the icon of the icon table beside its word. (RSS Icons and cells)
- [ ] Each idea has one icon, and each icon has one idea. (RSS Icons and cells; [[id:46F465EE-7693-4852-B125-12C56290B695][Icon reference]])
- [ ] Words are in sentence case. (RSS Naming)
- [ ] Every string exists in English, French and Portuguese before the screen ships. (ESS Feedback, states and words)
- [ ] Every message says what happened and what to do. "Error" alone is not a message. (RSS Feedback)
- [ ] A time is relative, with the exact time on hover. A missing time is a phrase, not a date. (RSS Icons and cells; ESS Feedback, states and words)
- [ ] A code or number is monospace. A number is right-aligned with tabular figures. (RSS Icons and cells; UDP Monospace for Data)
- [ ] Grey means inactive and nothing else. Orange means a missing badge definition. (UXL Colour semantics)
- [ ] Red, amber and green carry a real status. They never mark a plain category. (UXL Colour semantics)
- [ ] Colour appears only when it means something. (UDP Color for Meaning Only)
- [ ] Spacing is on the 4 pixel grid, and padding is symmetrical. (UDP The 4px Grid, Symmetrical Padding)
- [ ] A control is not a native form element when it needs styling. (UDP Isolated Controls)

** Access and safety

- [ ] The screen needs a typed permission. The menu, the route guard and the button read it. (ESS What a screen or a form needs)
- [ ] A refused read is stated as a refusal in words. It is never shown as a failure. (ESS Feedback, states and words)
- [ ] Every write carries a change reason. There is no silent write. (RSS Safety)
- [ ] A save goes through the shared record dialog, remove dialog or revert dialog. A screen builds no dialog of its own. (RSS Writes)

** The configuration screen

- [ ] The kind is named as the standard names it: *Pricing engine configuration*, *Engine run settings*, and the rest of the table. No screen says *Pricing engines* or *Engine settings* alone. (CFG The name of each kind)
- [ ] The pricing page's parameter tab is *Parameters*. No configuration screen has a *Settings* tab. (CFG The name of each kind)
- [ ] Details is first, the section tabs follow in the declared order, and Used by and History are last. (CFG The record page)
- [ ] A group shows the value in force, and the default where the parameter is unset. (CFG Reading a group)
- [ ] A group is edited in place; a collection is edited in a dialog per row. (CFG Changing a group; Changing a collection)
- [ ] Every label, help, description, default, format and release comes from the documentation contract, not from the screen. (CFG The documentation contract)
- [ ] A setting with no documentation entry shows its ORE name and a note. (CFG Reading a group)
- [ ] Simple and Advanced are the shared switch, and Advanced adds the schema entry. (CFG Reading a group)
- [ ] The page says what the configuration decides and lists the related configurations the same report binds, with links both ways. (CFG What this configuration decides, and the related configurations)
- [ ] Used by lists the reports that bind the configuration and states the reach rule. (CFG Reach)
- [ ] History is the shared timeline, and a change names the section and moves the version of the whole. (CFG History)
- [ ] A change to a numbers-changing section of a bound configuration is a proposal: the version in force stays and the proposer cannot sign. (CFG The lifecycle)
- [ ] A change to an operational section writes directly, with a reason. (CFG The lifecycle)
- [ ] An import parses on the server, names every dropped value, lists removed rows first with *Keep it* as the default, and never makes a file official. (CFG Import)

** Exceptions

- [ ] A part the screen lacks is named in the standard's list of how screens conform, with the reason. (RSS How today's record screens conform)
- [ ] An exception changes which parts exist. It never changes how a part looks. (RSS Exceptions)

** Check on the running screen

- [ ] Try list, page, search, open, edit with a stale version, history, and the empty, error and no-permission states. (RSS Building a record screen)
- [ ] Try data of the real size, as a member and as an administrator. (ESS Building an entity screen, Verifying a rule)
