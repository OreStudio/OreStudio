* Goal

The system carries one hundred thousand feeds on one machine that runs ten
environments against one PostgreSQL instance. A service reaches the database
through a few long-lived connections and a unit of work, handlers run on a
bounded pool, ticks are stored once for each source by lanes writing in bulk
into a bounded, compressed store, the grid is woken rather than polled, and
every queue and session reports its own numbers. The target state is set out
in [[id:CE41E828-18EB-4E88-BB02-6A4930E7B67C][The data path]].

* Acceptance

- Every page of the data path cluster describes the system as it runs.
- No query opens a connection of its own, and a connection carries no tenant
  between transactions.
- The stored rows a second equal the source ticks a second, and the tick store
  stays within its window.
- An idle grid sends no claims.
- A load of 116,000 source ticks a second, an active market at one hundred
  thousand feeds, runs for ten minutes with bounded memory, no unplanned drops
  and the numbers of every queue and session published.

* Decisions

- *The target state is written first and reviewed before code.* The first pull
  request holds the scaffolding and the architecture notes only.
- *Two paths.* The control plane and the data plane reach the store by different
  paths ([[id:662D0C1B-319C-4F85-A118-42D830661B40][The data path serves a control plane and a data plane]]).
- *Tick points belong to the installation.* They carry no tenant and no
  row-level security, entitlement is checked when a party reads, and so closed
  chunks compress ([[id:D71F9446-C62E-48A6-A87B-136EF598A59E][A source tick is stored once and entitled when it is read]]).
- *TimescaleDB runs under the Timescale licence,* which the compression and the
  policy jobs need ([[id:A79C25FA-9F70-453B-A52E-780B4402ABAA][The tick store is bounded by compression, narrow chunks and retention policies]]).
