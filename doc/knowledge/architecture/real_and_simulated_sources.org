#+title: A live and a simulated source differ only inside the adapter

* Summary

The system handles real vendor data and synthetic data in the same way. The only
differences are inside the adapter, in the rate card of the source, and in the
kind label that a person can read. Everything in =ores.marketdata=, and
everything that consumes market data, is identical.

** What is the same

| Part | Live and simulated |
|------+--------------------|
| Provider and vendor ids | The same provider code, id schemes, ids and fields. |
| Mapping | One mapping for the provider. See [[id:BAE0F052-CCA6-43FB-A139-03518CE2D929][The mapping belongs to the provider and not to the source]]. |
| Adapter contract | The same four messages. See [[id:5DFA094B-4F9F-4190-8251-8D4D0B77A5C7][An adapter and the service meet at four messages]]. |
| Ingest, quality, storage | The same path. See [[id:00D63182-C7FF-4AC9-8A83-9A5D984B2876][The ingest loop and the one pipeline]] and [[id:98E49FCD-10E4-4DCE-9099-E728359B6D60][Quality checks run between mapping and storage and ignore the source kind]]. |
| Quote series key | (item, provider, party). See [[id:E4736D88-03B2-4A40-B7F4-01B06B9B9FD7][A quote series is keyed by item, provider and party]]. |
| Subscription and routing | The same entities and the same screens. See [[id:37B27CA8-9F44-4A61-9B02-3EAABD8C3818][A party routes to exactly one source for each provider]]. |
| Entitlement and metering | The same events. See [[id:3E51B0BD-D22B-4790-821F-E2FED44D152C][Usage is recorded as events and priced later]]. |
| Party stream | The same subject and the same tick. See [[id:1F609D0D-5C72-4A21-B988-6957F18D426F][The market tick]]. |

** What differs

| Part | Live adapter | Simulator |
|------+--------------+-----------|
| Where values come from | A vendor session | A generator run in the adapter |
| Credentials | Vendor credentials held by the adapter | None |
| Universe | What the vendor entitles | The universe the generators cover |
| Time | The vendor's clock | The simulator's clock, written as vendor time |
| Faults | Arrive from the network and the vendor | Injected on purpose, or absent |
| Authoring | None. The vendor defines the data. | Collections, folders, generators and preview |
| Source kind | =live= | =simulated= |
| Rate card | The real contract | A simulated rate card |
| The bill | The system pays the vendor | A shadow bill, with no payment |
| Component | One service for each provider | =ores.marketdata.synthetic= |

** Two sources of one provider can run together

=bloomberg-live= and =bloomberg-sim= are two sources of the provider Bloomberg.
Each has its own adapter. A development party routes to the simulated source,
and a prelive party routes to the live source, at the same time. Both read the
same ids and the same mapping. See [[id:37B27CA8-9F44-4A61-9B02-3EAABD8C3818][A party routes to exactly one source for each provider]].

** How a person finds out

A party can read the kind of any source it is routed to, on the source's screen
and on the series. The service hides nothing. The system simply never needs the
answer to behave correctly. See [[id:F64DB34E-084D-4437-B536-392AA26D8B77][No code path may behave differently because a source is simulated]].
