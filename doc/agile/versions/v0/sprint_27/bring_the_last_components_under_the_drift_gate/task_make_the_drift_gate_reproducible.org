* Result

The premise was wrong, and the task closes without a change.

--component synthetic and --all do not disagree. On a clean tree both exit 0
and write nothing. What I saw was --all regenerating ores.workflow as well --
two workflow_plan tests that had drifted when those models were added -- and I
attributed the extra files to synthetic because I was reading a total file
count rather than the paths.

That is --all behaving correctly: it regenerates every component under test,
and --component names one. They are meant to differ whenever a component other
than the named one has drifted. The check for the property that matters is
this: on a clean tree, neither path writes a byte.
