* Goal

Make the synthetic service refuse a write to a catalogue every tenant shares (providers, variance calibrations, their inputs and points, and process types) from a session that is not the system tenant's, so the gateway's check is not the only barrier.

* Acceptance

- The synthetic service refuses such a write with a denied outcome, with a test for each catalogue.
- The local checks that the change needs are green.

* Plan

The gap is wider than the five catalogues the BFF guarded. Every entity that
states =:system_tenant_validation:= has a generated handler that switches to the
system tenant's context before it calls the service, for writes as well as
reads. A session of any tenant that holds the write permission therefore wrote
the rows every tenant shares, and the store's tenant policy could not refuse
it, because the write arrived as the system tenant. Forty-one handlers in five
components had this shape.

- The outcome catalogue gains =system_tenant_required=, a =denied= outcome the
  service states before the store runs.
- The handler template denies each write operation of such an entity, after the
  permission check and before it reads the body, unless the session is the
  system tenant's. The junction block states the same gate, so a future
  system-owned junction is gated too.
- A new archetype, =ores.cpp.nats-handler.system_owned_tests=, renders one test
  per such entity a client may write. It drives each write over NATS with a
  body no wire format decodes. A session of the test tenant is denied; a
  session of the system tenant passes the gate and is refused at the decode
  step. No case writes a row.

The three variance calibration catalogues the task names do not state the
flag, and they need no gate. Their handlers write in the caller's own tenant,
their removals filter on that tenant, and their tenant policy refuses a row
under any other tenant. A tenant's write there makes a row of its own, which
the table's per tenant and party keys allow.

* Result

Every handler of an entity whose rows the system tenant owns now denies a
write from a session of any other tenant, with =denied= and
=system_tenant_required=. Forty-one handlers in synthetic, marketdata,
reporting, analytics and refdata take the gate from the template, and a
generated test per writable entity proves it over NATS for each write: 39
entities, 78 cases, all passing. The five catalogues the BFF guarded are
covered: providers and process types by the gate, and the three variance
calibration catalogues by their own tenant scoping, which already keeps a
tenant away from the system's rows.
