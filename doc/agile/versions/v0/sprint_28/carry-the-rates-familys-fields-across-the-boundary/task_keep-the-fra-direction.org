* Acceptance

- The import stores the direction the document states, not a constant.
- The export writes the stored direction back into the document.
- A test proves a Short forward rate agreement survives both directions, with the document's own value as its expectation.

* Plan

1. Write the failing test first: a Short document through =forward_fra= and back
   through =reverse_fra=, expecting Short both ways. The corpus states Long, so
   the test changes the one binding member rather than inventing a document.
2. Read the direction on import with =to_string=, and write it back with the
   mapper's own =parse_code=, which round-trips the generated =to_string= so the
   spelling has one source of truth.
3. Check the money path while the mapper is open, since the same function
   converts a notional and a strike. Add nothing: =mapper_fra_holds_the_digits_of_its_strike_and_notional=
   already asserts the lexical form and the serialised =<Strike>0.005</Strike>=.

  store agrees with itself and the document disagrees with both. The fix is

  only the mapper ignored them.

  than the ternary a neighbouring product uses. =parse_code= scans the generated

* Result

A short forward rate agreement now stores as Short and exports as Short. The
import reads =fra.LongShort= through the generated =to_string=, and the export
writes the stored code back through =parse_code=, so the column the review found
written from a constant is now the one source of truth for both directions.

Proved red first: =mapper_fra_keeps_the_document_direction= failed at
=xml_ir_mapper_roundtrip_tests.cpp:216= on =instr.long_short == "Short"= against
the constant, and passes after the change.

Money: the unit changes no conversion, and the FRA's four import and three
export sites were already exact. The family already proves it:
=mapper_fra_holds_the_digits_of_its_strike_and_notional= asserts the lexical
form and the serialised document text. This unit first added the same two
assertions to the reverse case as well; they were redundant, and they were
removed. The money check for this unit is therefore a negative result, recorded
because a fix that touches a money-carrying mapper should say so.

The gate ran in both fleet states: build, db, ctest, ore-xml-roundtrip and the
fourteen static checks with the fleet down, and =step-consumers= with it up.
