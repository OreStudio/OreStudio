* Notes

The regression: =login_info= and =session= are the only two =:current_state:
true= entities in =ores.iam=, and the only two whose generated notify trigger
scripts were never wired into =iam_create.sql= / =iam_drop.sql=. The other
nine IAM notify triggers are all correctly included. The trigger scripts
themselves are generated by =sql_schema_notify_trigger.mustache=; the
aggregators are checked-in files with no generator, so codegen emitted the
scripts and nothing added the includes.

=validate_schemas.sh= runs =plantuml_er_parse_sql.py --strict=, which exits 1
on any WIRE_001 warning. That is why Continuous Linux and the Nightly Build
have been red since at least 2026-09-21 04:28 across every run checked.

Only these four includes were missing; the validator reports no other
unreachable script.

Build check: =validate_schemas.sh= reports 0 warnings and Validation Passed.

* Result

Four =\ir= includes added — two per aggregator:

#+begin_src sql
-- create/iam/iam_create.sql
\ir ./iam_login_info_notify_trigger_create.sql
\ir ./iam_sessions_notify_trigger_create.sql

-- drop/iam/iam_drop.sql
\ir ./iam_sessions_notify_trigger_drop.sql
\ir ./iam_login_info_notify_trigger_drop.sql
#+end_src

The drop includes sit immediately after their own table's drop, so each notify
trigger is removed before the table it is attached to.
