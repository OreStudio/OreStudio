* Acceptance

- All 108 product types carry a hand-written description of the instrument.
- The description states what the product is, its cashflows and when it is used.
- No description mentions a model, an engine or a pair.
- A building block says it is a building block, not a standalone product.
- Each entry records =authored= as its source, the reference and the curator.

* Plan

1. Read the current description of each type and the trade type the guide
   records for it.
2. Write one paragraph for each of the 108 types, in product terms, from the
   standard definition of the instrument.
3. Put each paragraph in =curation/types.json= as =documentation=, with
   =authored= as the source, the reference and the curator.
4. Regenerate the ore parameter seed. The Types rows change and nothing else.
5. Re-provision the environment so the screens read the new rows.

The short description the combo boxes show is not touched: it is the label of
the type, and naming is the mapping task's work.

  The pair text stays on the model and engine cards, where it belongs.

  =CallableSwap=, =FlexiSwap= and =CPICapFloor=) are written from the same

- =CPICapFloor= keeps its note about the ORE code not naming the type.
