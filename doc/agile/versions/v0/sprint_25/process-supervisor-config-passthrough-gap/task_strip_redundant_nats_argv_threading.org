* Result

Abandoned in favour of a proper split, once implementation revealed the
real scope: the SQL-backed ores_controller_service_definitions_tbl this
task's args-template edits targeted is itself legacy infrastructure
(the controller/process_supervisor.cpp it served no longer exists in the
codebase) that should be decommissioned via a codegen-driven model, not
patched. Also found that service_registry.org (DB-grants) and a
newly-drafted "service_deployment_registry.org" would have described
overlapping sets of the same services from two separately-keyed files --
per direct feedback, these belong in one model with several aspects, not
two files. Split into four separately-reviewable tasks, in dependency
order: merge_service_registry_deployment_model (A),
wire_systemd_generate_to_codegen_model (B, carries this task's original
argv-threading goal), decommission_legacy_controller_schema (C),
rename_controller_named_env_vars (D). A backlog capture was filed for
future Windows/macOS service-install generators consuming the same
platform-agnostic model.
