* Result

The withdrawal journey now describes the act as the tree performs it. The four
columns that end a set are named, with the three that name its successor; the
operation is =marketdata.v1.ops.withdraw_curve=, which refuses a set that is
withdrawn, superseded or never published, and which accepts an approved
withdrawal request or none when the tenant's count lets the trader act alone. A
replacement is a publish, not a second operation, and the notice is
=marketdata.curve_withdrawn=.

The gaps the page now states are the real ones: the withdrawal exists for the
IR curve alone, no read maps a set to its consumers, and no single delta read
exists.

The two population scripts describe the rows they seed. The notification kinds
header names all three kinds and says why two kinds have no notice; the approval
kinds header names the three publish kinds, the curve withdrawal, and the two
raise permission codes they name.

The change to the two scripts is a change to their block comments alone: every
changed line begins with the comment marker, which a check of the diff confirms.
The rows are unchanged, so the database checks were excluded and the seeds were
not re-run.
