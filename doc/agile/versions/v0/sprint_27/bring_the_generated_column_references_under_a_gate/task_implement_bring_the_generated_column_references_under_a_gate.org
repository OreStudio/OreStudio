* Acceptance

- A generated table writer that streams a non-member fails the gate.
- A generated create script whose index names a non-column fails the gate.
- The gate is green on the tree it lands on.

* Plan

Two generated shapes can name a column that does not exist, and both come from
a free-text model section rather than from =* Columns=:

- =<entity>_table.cpp= streams one member per =** Table display= row, so a row
  left behind after a column is dropped becomes =pr.<gone>=.
- A create script carries one index per =** Indexes= row, so a row left behind
  becomes =create index ... (<gone>)=, which fails and takes the table with it.

Read both rules from the generated output rather than the model. The generated
domain class carries the flag-derived members (=version=, =tenant_id=,
=modified_by= and the rest) that =load_model= does not return in =columns=, so
the model alone cannot say whether =** Table display= is right.

Register the check in =build/scripts/local_checks.py= under the classes its
inputs belong to.

* Notes

The check is a detector, not a ratchet: there is no baseline, because the tree
it lands on is clean. It was proven both ways before it merged -- green on the
tree it lands on, and on =3d52a070ba= it reports the two references that broke
the build there.

It reads the generated output rather than the model on purpose. =load_model=
returns =columns= without the primary key and without the flag-derived members
(=version=, =tenant_id=, =modified_by=, the audit columns), and =** Table
display= names those, so a model-only rule would fail on correct entities.
