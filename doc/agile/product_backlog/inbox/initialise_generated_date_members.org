#+title: Initialise the generated domain types' date members
#+description: A generated domain type declares a required date with no initializer, so a default-constructed row holds an indeterminate date until a caller sets it.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Give every required =std::chrono::year_month_day= member a generated domain
type declares an initializer, =std::chrono::year_month_day {{column}}{};=, in
=cpp_domain_type_entity.hpp.mustache=, and regenerate the domain types.

* Why

A =year_month_day= has no default value: a row built with =T row;= holds an
indeterminate date until a caller sets one, and code that asks =.ok()= of it
reads uninitialised memory. The nightly valgrind run found this through the
ORE projection, whose readers built rows that way and whose writers ask
=.ok()= to tell a stated date from a missing one. The readers now
value-initialise their rows, which fixes that path but not the type: any other
default-constructed row is still exposed.
