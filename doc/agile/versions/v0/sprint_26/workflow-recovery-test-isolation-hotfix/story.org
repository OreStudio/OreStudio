* Goal

The recovery case fails on CI and passes on a quiet machine:

#+begin_src text
workflow_engine_tests.cpp:404: FAILED: after.size() == 2 for: 1 == 2
#+end_src

=recover_in_progress()= re-dispatches every in-progress instance the database
holds. The engine reads them with the system tenant because the generated
repository has no read by state, so the pass sees the workflows the other test
binaries ctest runs in parallel started in their tenants. The case subscribes
to the step subject with a ten-message buffer and waits five seconds, so a busy
deployment evicts the command it is waiting for and the pass grows past its
budget. The case tested a quiet machine, not the behaviour.

* Decisions

- The case is made to hold under load rather than the engine changed. The
  pass's breadth is deliberate: a restart must find every in-progress run. What
  it needs is a repository read by state, which is a change to the generated
  repository and a story of its own; the capture on the runs the tests leave
  behind already covers the residue that makes the breadth expensive.
- The buffer is not raised for every case: only the recovery case triggers a
  pass that re-dispatches other tenants' work.

* Out of scope

- The repository read by state, and the test residue, both filed already.
