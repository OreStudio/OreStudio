* Result

Every table keyed by a trade and one more column now has a by-trade read. A table of that shape is a collection: it has several rows for one trade. There are 24. Two had the read already: =swap_leg=, and the identifiers from the spike. This task added the other 22 by declaring =:list_by: true= on the =trade_id= foreign key. The generator emitted the protocol, handler, service, repository, TypeScript twin and, for four of them, the shell commands and recipes.

A table keyed by the trade alone has one row per trade. The state, the booking and each instrument are read by =get= with the trade id, and a page of them by =get_many=.

The repository tests read the additional fields and the party roles of one trade and none of another, in addition to the identifiers of the spike.

*Not done, and why.* =:list_by_as_of: true= is not declared. It generates a window read for composite history that nothing calls, and it puts no =as_of= on the wire. A scoped read that carries =as_of= is the new task "Carry as_of on a scoped read". The specification text was corrected to say so.

*Found.* The database was stale against the rebased code, which failed nine credit and swap-leg tests until it was recreated. Nothing in this change caused it.
