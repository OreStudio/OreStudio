* Result

Shipped the ores.inbox composite: api, core and service parts generated from
their component overviews, registered in projects/CMakeLists.txt and the codegen
catalogue, and an ores.shell.inbox adapter part wired into the shell. The
placeholder stubs were removed in the same change as the first models.

Building the first new component in a while exposed codegen defects, fixed in
the templates and generator rather than in the output:

- the api part template linked ores.eventing.lib, which no longer exists;
- the service stub test declared an unused variable, an error under -Werror;
- the junction mapper had no branch for optional timestamps;
- the test seeding planner seeded the parents of a system-tenant reference,
  which is only read from the catalogue, and seeded enforced enum lookups the
  populate scripts already hold.

The drift sweep shows none of these changes alters another component's output.
