#+brief: A key that a product carries so the sensitivity configuration can set its own shifts.
#+entity_singular: sensitivity_template
#+entity_plural: sensitivity_templates
#+entity_title: Sensitivity Template
#+created: 2026-10-21
#+updated: 2026-10-27

A sensitivity template is a key. The pricing engine configuration puts it on a
product with the setting SensitivityTemplate, and the sensitivity configuration
gives shift sizes and shift schemes to the products that carry the key. So the
row states the class of product the key belongs to and the method it is priced
by, and both are lookups: the class is the reference data's asset class, and the
method is one of the five ORE defines.

The class is the product's class and not a claim about which market keys the
shifts reach. A key may set shifts on keys outside its own class, which is the
sensitivity configuration's business and not this table's, so nothing here links
a template to the keys it reaches.

The method is the token a key spells -- =FD= in =IR_FD= -- and its name is the
words a person reads. Four of the five methods price a class of product and
state it; the trade-level method is the one ORE defines without a class, so a
template that states it states no class, and the table checks that.

The key's spelling is the tenant's. ORE resolves a template key by looking up the
key the sensitivity configuration states, and a configuration may state a key
that ORE's own list does not hold, so a tenant can add a key of its own. The
table therefore holds every row to the metadata it states and does not hold the
key to a shape built out of =asset_class_code= and =method_code=.

The method as ORE spells it in a template key: Analytical, Semianalytical,
FD, MC or Trade. It says which shift scheme ORE applies, and it is the row of
=ores_analytics_sensitivity_methods_tbl= whose =name= a screen reads beside it.

** asset_class_code
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:nullable:     true
:END:

The class of the products that carry the template, as the reference data spells
it: 'interest_rates', 'fx', 'equity', 'commodity' or 'credit'. It is the row of
=ores_analytics_sensitivity_asset_classes_tbl= whose =template_prefix= the key
spells and whose =name= a screen reads.

Null on a trade-level template, which is the one method ORE defines without a
class.

Soft FK to ores_refdata_asset_class_codes_tbl, through
=ores_analytics_validate_sensitivity_asset_class_code_fn=, which holds a null to
be no class and validates anything else against the reference data.

#+begin_src cpp :name generator
[&r] -> std::optional<std::string> {
    if (r.method_code == "Trade")
        return std::nullopt;
    static constexpr std::string_view method_codes[] = {
        "Analytical", "Semianalytical", "FD", "MC"};
    static constexpr std::string_view classes[] = {
        "interest_rates", "equity", "commodity", "credit"};
    for (std::size_t i = 0; i < std::size(method_codes); ++i)
        if (r.method_code == method_codes[i])
            return std::string(classes[i]);
    return std::string("interest_rates");
}()
#+end_src

** Checks

Domain constraints beyond the standard temporal, natural-key and nil-uuid
checks the template emits on its own. A text key column already rejects the
empty string, so the template emits the code's own check and no row here
repeats it.

The key is not held to =asset_class_code || '_' || method_code=. ORE resolves a
template key by looking up the key the sensitivity configuration states, so a
tenant may register a key ORE's own examples do not hold. What must be valid is
the metadata each row states, not the spelling of a key a tenant chose.

The one rule across two columns is the pair, and it states which methods have no
class. A template states a class exactly when its method needs one, and the
trade-level method is the one ORE defines without a class. The sentence names
=Trade= because a check cannot read another table; a screen asks
=ores_analytics_sensitivity_methods_tbl.needs_asset_class= rather than repeating
the exception, and a method added there with =needs_asset_class= false needs this
line widened before its templates are held to it.

Each column that names another table is checked by a function that says what a
bad value is, because both may be absent from the table that holds them while a
database is being built. The method must exist. The class may be null, which is
no class, and is otherwise checked against the reference data's catalogue.
