* What

Provisioning a tenant whose code already exists fails, and the page shows the
database's own text:

#+begin_example
Query execution failed: ERROR: duplicate key value violates unique constraint
"tenants_code_uniq_idx" DETAIL: Key (code)=(acme_corporation) already exists.
CONTEXT: ... PL/pgSQL function ores_iam_provision_tenant_fn(...) line 40
#+end_example

The refusal must be a sentence that names the code, for example "A tenant with
the code acme_corporation already exists". =ores.iam= checks the code before the
insert, or maps the unique violation to a named refusal. The journey shows the
refusal on the form, beside the code field.

* Why

Found on 2026-10-01 during a manual check of the new tenant journey: the Acme
starting point was chosen a second time. The same branch now greys out a
starting point whose fixed tenant code exists. A code typed by hand in the form
can still collide, so the server refusal must be readable. The text also
exposes table, index and function names to the browser.
