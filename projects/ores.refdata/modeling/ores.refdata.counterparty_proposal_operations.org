#+title: ores.refdata.counterparty_proposal_operations
#+description: Codegen operation model for proposing changes to counterparties -- a preview that runs the real writes and writes nothing, a raise that holds the lines in an approval request, and the reads a decider works from -- rendered to C++ and TypeScript from one source.
#+type: ores.codegen.operation
#+component: refdata
#+subcomponent: api
#+entity_singular: counterparty_proposal_operations
#+namespace: ores::refdata::messaging
#+brief: Propose and preview changes to counterparties.
#+filetags: :model:operation:refdata:
#+created: 2026-10-12
#+updated: 2026-10-12

The operations a person takes to propose a change to a counterparty instead of
writing it. A request holds lines of three kinds, each a typed pending row: the
counterparty itself, its identifiers, and the links that say which of the
tenant's parties may trade with it. A line is a put or a delete, and carries the
version the person read. The lines apply in the order of their kinds: the
counterparties first, then their identifiers, then the links, so a new
counterparty exists before the rows that name it.

The preview runs the real write for each line in a transaction it never commits
and answers each line's refusal and the parts the policy names. The raise
previews, then holds the lines in an approval request.

The handler is hand-written beside this model, because each operation applies
the rules of the four-eyes framework.
