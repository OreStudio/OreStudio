* Acceptance

- The harness has run over every record kind and the result is recorded with the commit it ran at.
- Each failure is filed per screen family, as a capture in the next bucket or a task on an open story.
- A failure that shows a wrong check, not a wrong screen, fixes the check and is recorded as such.

* Plan

Run the harness over every screen on the rebuilt environment, twice, so a
failure that moves between runs is timing and not the screen. Read each failing
check's screenshot and snapshot once per rule to say whether the screen or the
check is wrong; fix the check where it is, and record the screen where it is.
Fold the JSON report into the table by script, write the page around the table
with the judgement of each rule, and file one capture per rule in the next
bucket, so the topic that owns a screen picks the gap up with the measurement
behind it.

* Result

The record screen baseline page holds the run of 2026-10-25 at commit
b6698c1818 of the harness: 32 screens, 21 checks, 477 passed, 67 failed and 128
skipped with a stated reason, in a table a later run replaces. Every failure is
the screen's, in four rules, each judged on the page and filed as a capture in
the next bucket: the record and classification pages draw no Refresh with its
load time, no dialog says when its record was loaded, twelve dialogs are titled
by the key, and the five read-only classification lists open nothing on a
click. Two checks were wrong and were corrected before the baseline was taken.
