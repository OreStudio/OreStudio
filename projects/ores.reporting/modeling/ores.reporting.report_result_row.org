* Primary key
:PROPERTIES:
:column:   report_instance_id
:type:     uuid
:cpp_type: boost::uuids::uuid
:END:

The run, which owns the rows: a result row is written once, with the run, and
never edited. The table's identity is the run, the subject, the measure and the
currency together, so a repeated row is a fault the key refuses rather than a
correction.

* Natural keys

** report_result_row_key
:PROPERTIES:
:columns: report_instance_id, subject_type, subject_id, measure, currency
:END:

One row per subject, measure and currency within a run, which is the canonical
row's guarantee.

* Columns

** report_definition_id
:PROPERTIES:
:type:     uuid
:cpp_type: boost::uuids::uuid
:END:

The report the run came from, so a definition's runs are one query.

** as_of
:PROPERTIES:
:type:     timestamp with time zone
:cpp_type: std::chrono::system_clock::time_point
:END:

The run's priced date, and the time column of the series.

** subject_type
:PROPERTIES:
:type:     text
:cpp_type: std::string
:END:

The kind of record the figure is about: =trade=.

** subject_id
:PROPERTIES:
:type:     uuid
:cpp_type: boost::uuids::uuid
:END:

The engine's own identifier for the record.

** measure
:PROPERTIES:
:type:     text
:cpp_type: std::string
:END:

The engine's name for the figure: =npv=, =npv_base=, =notional=, =delta=,
=gamma=. Open, so a new analytic adds a value rather than a column.

** currency
:PROPERTIES:
:type:     text
:cpp_type: std::string
:END:

The currency the figure is stated in, empty when the measure has none.

** value
:PROPERTIES:
:type:     double precision
:cpp_type: double
:END:

The figure, as the engine stated it and never formatted.

** source
:PROPERTIES:
:type:     text
:cpp_type: std::string
:END:

The file and the row the marshal read, for provenance.
