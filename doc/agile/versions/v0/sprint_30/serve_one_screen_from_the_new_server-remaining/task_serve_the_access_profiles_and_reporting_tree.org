* Plan

Serve the profile and contact screens at the BFF's addresses in a hand-written
unit, =profile_routes=: a person's own profile and contact record, and an
administrator's view of one account's. The own routes name no account. A
profile write that states the version the screen read is refused as a moved
record when the account has changed since; the administrator's write reads the
account inside the request and keeps the fields the screen does not set. The
administrator's contact write reuses the account's current record identifier,
so a claim of no record finds the row the panel did not see and is refused.

A contact record is stated as the screens read it by =account_view=, beside the
account, and the bodies are read through =access_screen_shapes=.

The last four routes, the picture, the reporting line and tree and the ways to
hold, move to [[id:58A99F28-A560-4408-9D86-203A55CA2060][Serve the account picture, the reporting tree and the ways to hold]].

* Result

The C++ server answers six profile and contact routes at the addresses ores.web
calls, each paired with its BFF route in the inventory. The tests prove the
bodies, the moved-record check, the refusals before forwarding and the contact
record as the screens read it. The pairing kept two stale pairs for the
account's contact record on two lines, which a one-line match missed; they are
gone, and a check of the pairs finds no key twice.
