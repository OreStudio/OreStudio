* Goal

The feed graph the story describes gets one design, signed off before it is built: what a node is, how the edges between nodes are stored, how each node's state and its reason are held and passed down the edges, how a node is stopped and started, where each node's diagnostics are kept, and how the screens read the whole graph. Each choice states the options and a recommendation.

* Result

The design is written in [[id:2376A086-4C3C-4D61-92E5-29B122DB6A41][Synthetic feed graph]] and adopted. The graph
has four node kinds (upstream, latent, view, source), named by the signed-off
scheme, and four states (running, stopped, starved, failing), each with its
reason; a node runs when it is not stopped and every input runs. The owner
signed off the five choices on 2026-11-22, each as recommended: edges as typed
columns on the dependent node, the two curves among them; one stop table for
any node, keyed by name, which the stopped source table becomes; state derived
in the service, never stored; each node's messages as telemetry log entries
tagged with its name; and one read of the whole graph, with a filter by node,
served by the BFF and ores.http.
