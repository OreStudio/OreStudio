* Goal

A route handler forwards to the owning service with a synchronous request, and
today that request runs on the one io_context thread the server has. A single
blocked handler therefore stops every other connection, including =/health=, a
static file, or a second request that has nothing to do with the slow service.

This task moves the handler off the I/O thread. The handler runs on a fixed pool
of worker threads and the connection's coroutine is resumed with its result, so
the I/O thread only ever runs completions. The pool is bounded twice over: a
fixed thread count, and a cap on the requests it holds at once. Past the cap a
request is refused with 503 rather than queued without limit.

* Acceptance

- A handler runs on a pool thread, not on the connection's thread, proven by a
  test that reads the executing thread's id.
- A handler that blocks does not stop =/health= answering. Proven by an
  integration test that starts a server, blocks one handler, and reads =/health=
  under a 500 ms deadline; the same test hangs when the pool is removed.
- The pool is bounded: the thread count and the in-flight cap are configuration,
  and a request past the cap is refused with 503 immediately.
- The pool reports how many requests it holds, and that figure is in the log
  line that states a refusal.
- The existing suites stay green.

* Plan

1. A =worker_pool= in =ores.http.api/net/worker_pool.hpp=: an
   =asio::thread_pool=, an in-flight counter, a =saturated()= predicate, and a
   =run(Invoke)= that spawns the handler's awaitable on the pool with
   =asio::co_spawn(..., use_awaitable)= and resumes the caller with the result.
   The counter is released by a guard living in the coroutine frame, so a
   cancelled request releases its slot too.
2. =http_server_options= gains =worker_threads= and =max_inflight_requests=, with
   =--worker-threads= and =--max-inflight-requests= on the server command line.
3. =http_server= owns the pool and hands it to every session. Declared before the
   acceptor so it outlives the sessions that reference it.
4. =http_session::handle_request= refuses with 503 when the pool is saturated and
   otherwise runs the handler through it. A null pool keeps the old inline
   behaviour, which only a test wants.
5. =http_server::bound_port()= reports the port the acceptor actually bound, so a
   test can use port zero instead of guessing a free one.

The alternative — rewriting the 24 generated route units onto an asynchronous
NATS request — is the better end state and belongs to increment R1, where the
route table is rewritten anyway. This task buys the property with one call site.

* Notes

- The integration test is deliberately not vacuous. With the pool removed from
  =http_server='s constructor the same test never answers: the blocked handler
  holds the only I/O thread and the =/health= read runs out of time. That was
  confirmed before the pool was restored.
- =worker_threads = 0= selects eight, so the default deployment gets the fix
  without configuration.
- The pool is per process, not per core. Making it per core, and sizing it from
  the CPU count, belongs with the net layer in increment N1.
