* Goal

Add =compass db tenants= so that developers can discover tenant UUIDs
with a single compass command, without knowing the DB schema or having
to write SQL.

The command should:
1. Source =.env= for the shell's connect/login arguments (as the
   recipes in =doc/recipes/shell/tenants/= do).
2. Drive =./ores.shell= with a =tenants list= script.
3. Format and print a table of =code= / =name= / =tenant_id=.
4. Alongside each row print the copy-pasteable export line:
   =export ORES_TENANT=<tenant_id>=

Expected output:
#+begin_example
Provisioned tenants:

  code      name                    tenant_id
  --------  ----------------------  ------------------------------------
  barclays  Barclays Bank PLC       36d4c3c9-195c-46b5-a4d8-b36cb48c8f46
  acme      Acme Corporation        ...

To target a tenant, export its ID:
  export ORES_TENANT=36d4c3c9-195c-46b5-a4d8-b36cb48c8f46
#+end_example

* Acceptance

- =compass db tenants= lists all active tenants with =code=, =name=,
  and =tenant_id= (UUID).
- Each row is accompanied by a =export ORES_TENANT=<uuid>= hint.
- The command drives =./ores.shell= with a =tenants list= script,
  sourcing the shell's connect/login arguments from =.env=.
- A recipe =How do I list tenants?= (or =How do I set ORES_TENANT?=)
  documents the compass variant.
- The command is wired into =compass db --help= output.

* Plan

1. Add =tenants= subcommand to the =cmd_db()= handler in =compass.py=.
2. Source =.env=; drive =./ores.shell= with a =tenants list= script.
3. Parse the shell output and format as the table shown in Goal above.
4. Print the =export ORES_TENANT=<uuid>= hint for each row.
5. Add the recipe and update =compass db --help= epilog.

* Notes

Blocked on [[id:A2CD62D0-9CA2-49DF-8CEE-5D8D8809C0F0][Add shell tenants list command]]: the compass command
delegates to =ores.shell=; the shell's =tenants list= verb must be
confirmed before this task can proceed. (=ores.cli= was retired on
2026-09-23; the shell is the surviving path.)

Compass lives in =projects/ores.compass/src/compass.py=. The =db=
pillar is handled by =cmd_db(argv)=; add =tenants= as a new
subcommand there alongside =recreate=, =sql=, etc.

The shell connection/login sourcing pattern already used by the
recipes in =doc/recipes/shell/tenants/= (=./ores.shell ${log_args}
${connect_args} ${login_args}=) applies here; compass sources the same
arguments from =.env=.

The shell's =tenants list= table documented in
=doc/recipes/shell/tenants/= shows =code=, =name=, =type=, =hostname=,
=status=, =recorded by=, and =version= — it does not include a
=tenant_id= column. The wrapper must obtain each tenant's UUID (for
example via =tenants get <code>=) before it can print the
=export ORES_TENANT=<uuid>= hint.

Surfaced during the [[id:F0FC905B-6A70-486F-A23F-0064B6A3EE75][Commission: country]] story (sprint 21): the
=--tenant= flag requires a UUID but there was no way to discover it
without raw SQL. This command closes that gap.
