* Acceptance

- The scheduler does not keep a hand-written copy of the reporting trigger
  request. Either it sends the real type, or a test decodes the production type
  from the scheduler's payload rather than from a copy of the struct.
- A field added to the contract fails a test instead of being dropped at
  runtime.
- A trigger the reporting service refuses is visible as a failed firing. A
  refusal must not read as a firing that never came due.

* Notes

The scheduler carried a three-field copy of a contract that had grown a fourth
field. The codec is positional, so the whole decode failed, the handler answered
bad_request, and every scheduled firing was dropped for a day without anything
reporting it. A dropped firing and a firing that never happened look identical
from the outside, which is what kept it hidden.

The test added when this was fixed mirrors the scheduler's struct in the test
file. It pins the field order from the receiving end, but an edit to the
production struct that keeps its shape would slip past it. That is why this task
exists rather than being considered closed.

* Result

Guarded by a test that runs the scheduler's own publish handler and decodes the
bytes it actually published as the production request type. The old guard
restated the struct in the test file, so it passed whatever the contract said.
The scheduler's body now carries uuids rather than strings, which is why the old
guard was self-consistent and wrong.

Proved by mutation rather than assertion. Adding a field to the operations model
made the guard fail with "Field named 'probe_field' not found"; reverting left
the model and the generated header byte-identical.

Two things found on the way, both worth more than the guard. A business refusal
is a failed outcome in the answer body, not an X-Error, and the scheduler read
only the header, so every refusal was recorded as a succeeded firing with no
run. That is the actual reason this was invisible. And the live reporting service
queue-subscribes the production subject, so the refusal tests had been answered
by the service rather than by their own responder.

Still unguarded: the scheduler owns the field order, and the guard is a test
rather than the compiler. A new contract field carrying a codec default that
keeps the positional decode working would still slip through. Closing that needs
the scheduler to send the real type, which would add a scheduler to reporting
dependency to buy a compile-time check.
