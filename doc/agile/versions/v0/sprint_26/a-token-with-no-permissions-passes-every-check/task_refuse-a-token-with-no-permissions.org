* Result

=has_permission= refuses a token whose permission list is empty. The database
context's list became optional: a context built from a token carries the
token's list, and a context with no list, which only =context_factory= builds
for a service's own work, passes. =with_tenant= and =with_party= now keep the
list they narrow, so a request's context is never trusted for want of one.
=grants= in =ores.security= is the one matching rule, understanding a code, =*=
and =x::*=, and both =has_permission= and =authorization_service::check_permission=
use it; the database check no longer needs a sorted list and now honours
component wildcards. =make_request_context= refuses the =select_party_only=
audience by name, because no signer or verifier sets an audience.

Tests: five cases for =grants=; =has_permission= refusing an empty list,
passing the service's own context, and narrowed contexts keeping their list;
the request context refusing the party-choice token. The full build is clean
with no warnings. The full ctest failed 5 suites on a database built before
main added tables and columns (=sandbox_id=, =curve_configurations= and
others); all five pass on a recreated database (refdata 286, trading 127, ore
637, reporting 49, analytics 53), as do service 46, iam 192 and security 64
under ctest. Live, with the probes in =evidence/=: the party-choice token is
refused a parties read and refresh, the same session reads 5 parties after
choosing a party, and the tenant live check passes 15 of 15
(=evidence/refuse_task_live.out=).
