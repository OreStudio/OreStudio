* Goal

=codegen.sh regenerate --component <name> --address <addr>= always
generates every model discovered in that component. There is no way
to restrict a run to a named subset of entities (e.g. only
=rounding_type=, =monetary_nature=, =currency_market_tier= within
=refdata=) — every targeted run generates every other entity too,
which the caller must then manually discard.

Add an =--entity= (accepting a comma-separated list, e.g. =--entity
rounding_type,monetary_nature=) flag to =codegen.sh regenerate= in
=projects/ores.codegen/src/codegen/cli.py=/=generate.py=. When
present, =cmd_regenerate= restricts the discovered model files to
those whose entity name matches the list before generating — no
other entity's files are written to disk. Omitting the flag keeps
today's behaviour (every discovered model). An unknown name in the
list should be a clear error, not a silent no-op, so a typo doesn't
look like "nothing to generate."

* Acceptance

- =codegen.sh regenerate --component refdata --address ores.cpp.qt
  --entity rounding_type,monetary_nature,currency_market_tier=
  generates *only* files for those three entities; no other entity's
  files are written to disk (verified via =--dry-run= file-list diff
  against an unfiltered run).
- Omitting =--entity= is unaffected: every discovered model in the
  component is generated, identical to today's output.
- Naming an entity that doesn't exist in the component with
  =--entity= is a clear ERROR (non-zero exit), not a silent
  no-op/empty result.
- =--entity= is rejected (clear ERROR) when combined with a plain
  =codegen.sh generate --model <path>= single-model invocation, or
  documented as a no-op there if that's simpler — pick one and make
  =--help= say so.
- =codegen.sh --help= documents the new flag.
- CI passes; no production source files are changed by this task
  (only =ores.codegen= tooling).

* Plan

- Added =--entity NAME[,NAME...]= to both parsers that expose
  =regenerate= (=projects/ores.codegen/src/codegen/cli.py= and the
  =compass codegen regenerate= wrapper in
  =projects/ores.compass/src/compass.py=, which has its own duplicate
  argparse setup) — both delegate to the same
  =codegen.generate.cmd_regenerate()=.
- =cmd_regenerate()= parses =--entity= into a set, rejects it when
  combined with =--all= (ERROR, matches the story's "restrict a
  --component run" framing), then per component filters
  =discover_models()='s result down to models whose extracted entity
  name is in the set, tracking which names were actually matched.
  After the component loop, any requested name never matched is an
  ERROR — a typo doesn't read as "nothing to generate."
- Reused (rather than duplicated) entity-name extraction: moved
  =compass_codegen_entity.py='s existing
  =_entity_name_from_path()= into =codegen.manifest= as the public
  =entity_name_from_path()=, and updated
  =compass_codegen_entity.py= to import it from there — one
  filename→entity-name mapping instead of two copies that could
  drift.
- Verified live: =--entity rounding_type,monetary_nature,...=
  generates only those entities' files; an unknown name errors
  (exit 1); a mix of known+unknown still generates the known ones but
  still errors overall; =--entity= with =--all= errors; omitting
  =--entity= is byte-identical to before. Same behaviour confirmed
  through both the direct =codegen.sh regenerate= CLI and the
  =compass codegen regenerate= wrapper.
- 6 new unit tests (=test_regenerate_entity_filter.py=, isolating the
  filter logic from real generation via a monkeypatched
  =_generate_single= and a synthetic fixture component, per
  =test_manifest.py='s existing pattern). Full =ores.codegen= suite:
  83/83 passing.
