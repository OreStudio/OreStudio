Trade version 6 opens at 22:14:38.684248. Instrument version 1 closes at
22:14:38.684642, which is after that. Both instrument versions overlap the
trade's version 6 window, so the as-of read reports two.

The trigger bumps the parent before it closes the child's own row:

projects/ores.sql/create/trading/trading_bond_instruments_create.sql
  perform ores_trading_trades_touch_version_fn(...);   -- parent opens first
  ...
  update "ores_trading_bond_instruments_tbl"
  set valid_to = clock_timestamp()                     -- child closes after
  where ... valid_to = ores_utility_infinity_timestamp_fn();

The gap is the work between the two statements, about 394 microseconds
here. The test avoids it by widening each bound by a second
(repository_bond_composite_versioning_tests.cpp lines 242 to 246 say so).
A reader that feeds a parent window back verbatim, as the test's own
read_trade_versions comment invites, gets two child versions.
