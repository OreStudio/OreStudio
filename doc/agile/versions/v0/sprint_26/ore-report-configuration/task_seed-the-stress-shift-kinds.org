* Acceptance

- Seeded lookups hold the shift families and shift types =stress.xsd= defines,
  derived with the command recorded.
- =stress_test_shift.family= and =stress_test_shift.shift_type= refer to them,
  and an unknown value is refused on insert.
- The stress test corpus and database round trips still pass.

* Plan

- The families are the sixteen children of the =stresstest= type in
  =external/ore/xsd/stress.xsd=, apart from =Date=. They are exactly the sixteen
  strings the stress test mapper writes into =stress_test_shift.family=.
- The shift types are the =shiftType= enumeration in
  =external/ore/xsd/ore_types.xsd=: =Relative=, =Absolute=, =EqualTo=. The
  sensitivity configuration uses the same enumeration, so the lookup is named
  =shift_type=, not after stress.
- Both are analytics lookups seeded for the system tenant and readable by every
  tenant, as =pricing_engine_type= is, and the shift's foreign keys resolve
  under the system tenant.
- No stress database round trip existed, so this task adds one, over the corpus
  file that applies shifts in ten families and uses all three types, with a
  refusal case for each column and a test that pins both seeds to the schemas.
