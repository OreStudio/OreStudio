* Acceptance

- The import reads the CPI leg's index, base level and observation lag into the product's fact row.
- The export writes them back into the CPI leg, which currently leaves the leg with no payload at all.
- A test states the document's own values as its expectations and proves both directions.

* Plan

1. Write the failing case first, against the document's own values:
   =Inflation_CPI_Swap.xml= states =UKRPI=, =210= and =2M= on its CPI leg, so
   the case asserts those three and nothing the mapper invents.
2. Read them on import from the CPI leg, which is where the document states
   them. A swap states one such leg; a second would be another product.
3. Write them back on export onto the same leg, because the shared leg reverse
   states a cashflow, fixed or floating payload and nothing for a CPI leg.
4. Record the money limit rather than paper over it: =BaseCPI= is an =xs:float=
   in the schema and the generated binding has no lexical form.

* Result

An inflation swap is stored with the index, base level and lag its document
states, and exports them back. The import reads them from the CPI leg; the
export writes them onto the same leg, which the shared leg reverse leaves with
no payload at all.

Proved red first: against the merge base the case fails on an empty
=inflation_index_code= and an absent =base_cpi=; after the change it passes with
fifteen assertions, six of which name =UKRPI=, =210= and =2M= rather than quoting
the mapper.

Money: =BaseCPI= is an =xs:float= in the schema, and the generated binding is a
plain =float= with no lexical form, so the digits are the schema's own limit.
The column is =double=, which is wider than the leaf, so the store adds no loss
of its own. Giving the leaf a lexical form would be a codegen change of the
=moneyFloat= kind, which the FX rework already made; it is not this unit's.

A row imported before this unit could not be written at all, so there is nothing
to re-import: the affected trades failed and were left with a header and no
fact. Re-running the import after this change is the remedy for them.
