* Acceptance

- The 52 trading models that reference ores_trading_trades_tbl reference ores_trading_trade_anchors_tbl, generated from the models.
- The ORE import still saves its instruments, and the round trip stays lossless in scope.
- Build, ctest, pgTAP and the local check set pass.

* Plan

Retarget every instrument's trade reference with a script over the models,
regenerate, and fix what the generator assumed about the target.

- =retarget_trade_fk.py= points the =trade_id= foreign key of the 52 models
  that named =ores_trading_trades_tbl= at =ores_trading_trade_anchors_tbl=.
  The wide trade's own model is left as it is.
- The reference stays a trigger check rather than a database foreign key:
  the tenant purger deletes no instrument rows, so an enforced key would stop
  a tenant that holds instruments from being purged. The acceptance's purge
  order covers enforced keys only.
- The generator assumed every trigger-checked target is temporal and filtered
  on =valid_to=, which the immutable anchor has no column for. A target whose
  model is immutable now gets no current-version filter.
- The derived parent seeding in the generated tests assumed an audited,
  temporal parent with text lookups; the anchor is neither. A script adds the
  same =parent_seed= snippet the booking uses to each model, writing the
  trade's anchor at the column's group path.
- The hand-written instrument tests' shared seed writes an anchor instead of a
  wide trade.
