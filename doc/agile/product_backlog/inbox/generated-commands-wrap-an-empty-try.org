#+title: A generated shell command with no arguments wraps an empty try block
#+description: The shell operation command generator emits a try/catch around the block that populates a request from the parsed arguments. A request model with no fields produces no statements in that block, so the generated command contains 'try { } catch (const std::exception& e) { ... }' with nothing between the braces. It is harmless but it is noise in every no-argument command, and the first one is authorization_operations_commands::process_get_my_roles, generated from iam.v1.roles.mine. The candidate is for the command template to skip the block when the request declares no fields. The generator lives in projects/ores.codegen/library/templates/, so the fix is a template change plus a regeneration, not a hand edit of the generated file.
