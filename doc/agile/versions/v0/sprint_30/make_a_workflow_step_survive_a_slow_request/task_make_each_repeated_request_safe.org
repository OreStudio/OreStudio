* Goal

A retried request carries the same identity as the attempt it repeats, so a service that already did the work recognises it. A step reads the effect of an attempt that timed out before it asks again, and no repeat writes a second candidate or raises a second approval request.

* Acceptance

- A repeated calibration keeps its as-of, so its calibration id and its observations are the same rows as the first attempt.
- A step checks whether the work already happened before it asks again, and completes from the result it finds.
- A repeat raises no second approval request.
- A test proves a repeat of each retried request leaves the store unchanged.
