* Acceptance

- The catalogue names every family whose files appear under external/ore/examples/*/ExpectedOutput.
- Every output parameter the seed declares whose file the samples ship is one family's parameter, and the parameters the samples do not ship are named below rather than dropped.
- A family states the file parameter, its key dimensions, its columns and the header variants the samples show.
- A test fails when a checked-in expected output maps to no family, or a family has no file in the samples.

* Plan

The corpus is the authority for shape. =generate_output_catalogue.py= walks
every CSV under =external/ore/examples/*/ExpectedOutput=, groups the file names
into families, and states for each family the file pattern, the columns the
samples show, the keys among them and how many header variants there are. A
name the engine builds from the trade or the curve it belongs to
(=exposure_trade_*=) is a pattern, not a name.

The seed is the authority for the parameter. =reporting_file_types_populate.sql=
states the 55 output parameters and the file name each gives, so a family whose
pattern the seed states takes its parameter and analytic from there. The
generator's own table names the analytic of the families no parameter names,
which is most of them.

Column kinds are inferred from the values, dropping the engine's null string
first. A key column stays text unless its values are all dates or all times,
because a key identifies a record and is never summed.

The data is written into =output_catalogue_data.{hpp,cpp}= and parsed once by
=output_catalogue.cpp=. The generator's =--check= mode fails when the corpus and
the data disagree, and the local check =ore-output-catalogue= runs it.

* Notes

- The seed declares 55 output parameters and the samples ship the file of 17 of
  them. The other 38 name files the checked-in corpus does not carry: jacobi,
  jacobi_inverse and crossgamma, productclass_mapping, calibration with its pca
  and meanReversion outputs, creditcurves, crif, marketObjects and riskFactors,
  the scenario dumps and cubes of scenarioGeneration and simulation,
  timeaveragedexposure, dim_evolution, dim_regression, additionalResults and
  sacva's net sensitivity file. A family with no sample cannot state a shape
  from the corpus, so it is not in the catalogue, and the gap is filed as
  [[id:FC23D85D-2830-4D33-9239-7D268900A4DD][Read the outputs the samples do not ship]].
- The catalogue's authority is the sample, not the writer. The writers state
  their columns in C++ string literals, and a second authority would eventually
  disagree with the corpus a reader must accept. The writers were read for the
  one thing the corpus cannot say: which analytic writes a family no parameter
  names.
- A family's columns are a union over its header variants, because shape follows
  the configuration: =curves.csv= states one column for each curve the run built,
  in four variants. =header_variants= says how many there are, so a reader can
  tell one shape from several.
- A column whose samples are all the engine's null string reads as text. Nothing
  shows what it holds, so a reader carrying it as text is honest.
- The generator is the lever: regenerate to widen the catalogue, or =--check= to
  fail when the corpus and the data disagree. The local check
  =ore-output-catalogue= runs it.

* Result

The catalogue exists: 60 families, 1 584 columns, generated from the 473
expected outputs the repository ships. A family states its file pattern, the
parameter that names it where the seed gives one, the analytics that write it,
its keys, its header variants, a sample file and every column with a kind.

The measurement that matters is that every checked-in sample maps to a family,
and the suite walks all 473 to prove it. The second is that the data cannot
drift from the corpus: =--check= regenerates in memory and compares, and the
local check =ore-output-catalogue= runs it on every change to the corpus, the
generator or the data.

The catalogue states what the samples show, which is not every output ORE can
write. The seed declares 55 output parameters and the samples ship 17 of their
files; the other 38 are filed as a capture so the gap is visible.
