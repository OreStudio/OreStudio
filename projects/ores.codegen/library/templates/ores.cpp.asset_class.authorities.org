The C++ projection of the catalogue's mapping. =asset_class_for_authority=
takes the authority text; =asset_class_for_identifier= takes a resolved
identifier and applies the mapping to its alternative, so a caller that has
already parsed the index name does not turn it back into a string.

An authority the mapping leaves empty -- =correlation= and =generic= -- is
simply absent from both functions, so each answers =std::nullopt= for it.
=asset_class_codes= carries the taxonomy's own codes, in display order, so a
test-data generator that must emit a code the catalogue holds reads it rather
than restating the list.

The header is written into =ores.marketdata.api= rather than refdata's,
because the identifier type it names lives there. The build already links
=ores.refdata.api= into =ores.marketdata.core=, so the dependency direction
is unchanged.
