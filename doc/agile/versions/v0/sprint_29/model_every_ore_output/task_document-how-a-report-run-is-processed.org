* Goal

One page states the flow of a report run end to end, and what post-processing
does with the output, in enough detail that a person can follow a run without
reading the code.

It covers the phases the workflow invokes, what each hands the next, how the
engine's output becomes rows in the two stores, which component owns which
format, and why the shapes are what they are.

* Acceptance

- A knowledge page states the run's phases in order, with what each consumes,
  produces and hands on.
- It states what post-processing does: which readers run, which tables are
  written, how a family's shape decides between them, and what happens to a file
  no family covers.
- It states the ownership rule: the format belongs to ores.ore, the table to the
  component that stores it, and no screen learns a family.
- It states the cost shape: one object per file, blocks of rows in one
  transaction, and the market state as rows, with the measured cost.
- The existing pipeline page points at it, and the ORE output processing page
  links to it.

* Plan

The page lives under =doc/knowledge/architecture/= beside the pipeline page it
completes, and the pipeline page keeps the phase table while the new page keeps
the detail of what post-processing writes.

The page is updated as the three tasks that change the cost shape land, so it
never states a flow the code does not take.

* Measurements

Every number this task claims about a tree, with the command that produced it
and the commit it was measured at. A number without both is not a measurement,
because a clean-up record describes a tree and trunk moves under a branch: a
consumer count, a gate's component count and a suite's size all change with no
code changing, and the reader of a bare number cannot tell which tree it came
from. Where the raw output matters, put it in an =evidence/= file beside the
task and name that file in the Command column.

* Result

built, now that the tasks that changed the cost shape have landed: each result's
manifest, routing by family, the families a definition skips, one file fetched at
a time against its digest, rows written a block at a time in one transaction, the
six stores and their shared key, the readers, what a refusal rolls back, what the
node leaves behind and the measured cost. The market state is rows, not objects,
by the story's decision, and the acceptance says so. The diagram is redrawn, the
pipeline page no longer calls the output an archive, and the pipeline, output
processing and output formats pages link to it.
