* Goal

Some ORE files may be split so that a run reads part of the data, for example one portfolio file for each book. Use the name pattern of the file type, such as portfolio_{{BOOK_ID}}.xml, to write one file for each value of the key and to name each one in the run document. This is not a day one requirement. The task exists so that the file types table is built to allow it.

* Acceptance

- A file type with a pattern writes one file for each value of its key, and the run document names each file.
- The portfolio of a run that reads several books can be split by book, and the run produces the same results as the unsplit run.
- A pattern whose key the export cannot fill is refused with a message that names the key.

* Plan

1. Decide which files may be split and by which key. The portfolio by book is the first case.
2. Extend the file types table lookup to expand a pattern for a list of key values.
3. Write one file for each value and name each in the run document.
4. Compare the results of a split run with those of the unsplit run.
