* Notes

- The session record holds the token's claims rather than four loose fields, so a
  handler reads the same =jwt_claims= whichever proof reached it and cannot tell a
  cookie from a bearer token.
- The session path does not verify the token again. Its claims were taken when it
  signed in, and the store is the authority for it: the design calls this a different
  proof, not a cache, and re-verifying would make it the second.
- A cookie the server does not know is answered 401 with =Max-Age=0= on the same
  cookie, so a browser drops it and shows a sign-in instead of retrying forever.
- The =__Host-= prefix is chosen by the deployment's TLS flag and not by the request,
  because a browser rejects the prefix over a plain connection.
