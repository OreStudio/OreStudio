* Goal

The repositories' prepared statements are either kept, with a stated minimum
pooler version wherever a pooler is used, or sent unnamed, with the planning cost
measured and accepted. One of the two is decided on evidence, and the other is
recorded as rejected with the number that rejected it.

* Acceptance

- The cost of sending repository statements unnamed is measured: the same
  statement, the same rows, prepared once and sent unnamed, against a real
  database, with the numbers recorded on the task.
- If the measured cost is acceptable, =detail::prepared= stops naming statements
  and the pooler has no version floor; if it is not, the floor is stated as
  pgbouncer 1.21 or later with =max_prepared_statements=, and every environment
  that runs a pooler states its version in one place.
- The choice is proven through a transaction pooler in both directions: a named
  statement fails behind a pooler without support, and the chosen arrangement
  passes.
- The hand-written SQL path, which already sends unnamed statements, is unchanged
  by the decision.
- The decision is recorded in the story, and the number that decided it with it.

* Plan

Both halves need a running pooler, which the host cannot install (no root) and
which the development environment does not carry yet, so the measurement starts
from the container or unit that
[[id:3D23B905-359A-4DE0-9F35-1B047A54385B][Run a pooler beside a shared fleet]]
builds, or from the pauli image.

The two candidate measurements are a prepared statement executed N times against
an unnamed one on the same table, timed end to end from the client, and the total
statement time from =pg_stat_statements= for a provisioning run in each mode. The
first is cheap and answers the shape; the second is the one that decides, because
it weighs planning against the mix of statements a service really runs.

* Measurements

and the commit it was measured at. A number without both is not a measurement,
because a clean-up record describes a tree and trunk moves under a branch: a

code changing, and the reader of a bare number cannot tell which tree it came
from. Where the raw output matters, put it in an =evidence/= file beside the
