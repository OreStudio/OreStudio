* Result

The database now builds from the schema and the populate scripts, and every suite that the market data work touched passes against it. The first run found four defects, which the earlier PRs had missed because no database suite could run:
- The summary query at the end of the catalogue populate repeated its column aliases, and the database build stopped on it.
- The mapping dates =effective_from= and =effective_to= were typed =timestamp= without a time zone. They are instants, so they are now =timestamp with time zone=. The event payload of a mapping failed to parse without the zone.
- Observations record the id of their source, but the as-of reads and their positional row mapper did not carry it, so 44 reads failed with a bad lexical cast. The model's projections and the mapper now carry =source_id= after =source=.
- A test expected a tenant write for the system tenant to be refused. =ores_iam_validate_tenant_fn= reads the system tenant id as "use the session tenant", so the row lands in the tenant's own tenant and a tenant can never write a system row. The test now asserts that.

The database holds 6 providers, 4 sources, 78 vendor instruments and 78 mappings after the build. Against it: marketdata core 271 cases, marketdata service 161 (the ingest loop on live NATS), marketdata api 55, marketdata client 3, shell marketdata 315, refdata core 464, synthetic service 79, synthetic core 61, IAM core 304, and all 57 pgTAP files with 564 tests.

Left unrun: the web BFF tests, and an end to end run of the bill read, the supervisor with a real adapter and the usage recorder, which have unit tests only.
