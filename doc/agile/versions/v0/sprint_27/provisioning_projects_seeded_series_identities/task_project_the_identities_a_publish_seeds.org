* Plan

Move the "project the series that have no identity row" logic out of the backfill handler into the projector as
=project_missing=. Call it from the backfill handler and from the data quality publish handler, once the SQL
function has inserted or updated series, for the tenant the command names. Test it against series inserted by
raw SQL, which is how the publish inserts them. Prove it on the running stack with a real publish into a fresh
tenant.

* Result

A series a data quality publish creates now has its identity row as soon as the publish completes. The publish
handler calls =project_missing= for the tenant the command names, after the SQL function has inserted or
updated series and before the step reports complete. The picker and the resolver therefore see the seeded series
in a new environment, with no one running a backfill.

*Cause.* The publish is a SQL function that inserts series directly. The code there says SQL cannot run the
codec, and the identity projection is read through the codec, so the rows were never written. The backfill
command existed, kept its logic inline in the handler, and had to be run by hand for each party.

*The change.* =project_missing= finds the series with no identity row and projects them, for the whole tenant or
one party. The backfill command and the publish handler both call it. It is idempotent: a second call finds
nothing. A projection that fails fails the publish step, so a missing projection cannot go unseen. The SQL
function is unchanged, because the codec must stay the only reader of the URI grammar.

*On the running stack.* A real publish of the FX driver rates dataset into a fresh tenant produced 13 FX series
and 1 IR deposit series, and every one has its identity row. The Acme tenant, published before the change, had
13 of 65 and 0 of 1.

*A mistake the drift check caught.* I first edited =market_series_handler.hpp= by hand. It is generated from the
model, so the check regenerated it and restored the old code. The change now lives in the model's backfill handler
section and the header is regenerated from it. The check also regenerated six marketdata =*_service.cpp= files
that differ from main by one blank line, because main's generator templates changed and marketdata was not
regenerated. They are committed here so the drift check passes.

*Left alone.* One system-tenant series, seeded by a SQL populate script, still has no identity row. It belongs
to the system tenant and no screen lists it.
