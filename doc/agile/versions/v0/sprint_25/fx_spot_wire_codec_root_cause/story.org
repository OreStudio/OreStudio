* Decisions

- Root cause: fx_spot_subscription.cpp (projects/ores.marketdata/client/src/fx_spot_subscription.cpp)
  called rfl::json::read<fx_spot_tick> directly instead of
  default_wire_codec().decode<T>(), ignoring the tenant's negotiated
  wire codec entirely -- the one NATS-tick call site the original
  wire-format migration sweep missed, since it's a fire-and-forget
  subscription handler rather than a request_sync call the sweep
  grepped for. Fixed by commit 7fe8798452, PR #1809, under
  Task-ID 1FC899C9-48A9-416C-87D0-FF4BB54F0DB7 / Story-ID
  1A815B1E-904E-460C-A2FB-31D9E3B392E2 (the NATS wire-format story) --
  landed the same day this story's diagnostics task was authored, so
  by the time this story picked up, the fix was already on main.
  Verified live 2026-08-04: msgpack environment, FX Spot Monitor rows
  ticking, zero decode-failure warnings in the client log.
- While verifying the fix live, found a second, unrelated gap: CRM
  topology (majors/minors/exotics) is blank for freshly-provisioned
  tenants because the realistic_2026/base bundle used by
  'provision system'/'provision party' never publishes
  refdata.crm_topology_bundles -- only the older
  marketdata.reference_vintage_2016_02_05 bundle does. Rather than
  file a separate story, folded it into this one's scope as a new
  task, since it was found in the same verification pass against the
  same freshly-provisioned tenant.
