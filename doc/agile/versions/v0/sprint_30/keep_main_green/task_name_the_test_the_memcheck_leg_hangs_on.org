* Acceptance

- An exceeded timeout writes its test name to the run's output whatever buffering the streams use.
- The next failed memcheck run carries the log that holds the message.

* Plan

Write the timeout banner through C stdio, so it reaches the run's output
whatever the C++ streams did with their buffers, and upload every log CTest
keeps rather than two named files.

* Result

* Result

The watchdog now writes its banner through C stdio and flushes it, so a suite
it kills names the test in the run's output whatever buffering the C++ streams
chose. The nightly uploads every log under =Testing/Temporary=, so the file
that holds that output travels with the artifact on the next failure.

Found on the way: the 26 November clang debug run shows a 61 second gap
between its last printed case and the failure report, which is the watchdog's
first check past its 60 second limit. The case that hung is not named in the
run because the banner and the buffered output were lost, which is what this
change fixes.

Verified locally: the banner appears once, with the test name, when the output
goes through a pipe, and the suite exits 1 as before.
