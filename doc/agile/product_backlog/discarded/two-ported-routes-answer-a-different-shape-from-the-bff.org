#+description: Blame: answer_shapes reports two pairs where the gateway answers a different shape from the BFF corpus, on main.

Pairs, each reproduced alone on a started fleet and a database rebuilt by the gate:

  GET /api/reporting/reports at rows[].latestRun
    the BFF {'completedAt': ['string'], 'errors': ['number'], 'id': ['string'], 'startedAt': ['string'], 'warnings': ['number']}, the gateway ['null']
  GET /api/trades at rows[].structure_id
    the BFF ['null'], the gateway ['string']

A third pair, GET /api/marketdata/quotes/feeds at feeds[].last_at, fails in the gate and passes when the check runs alone, so it is a race over delivery data and not a shape difference; it should not be excused either, but it is not the same finding.

Attribution: neither route is touched by the branch that ran the check, and the corpus and exception file are unchanged, so the pairs came from whichever work last changed those answers on main. blame cannot name them because a shape mismatch is not a codec finding, and the git route needs the person who knows which of the two answers is correct: the BFF's, or the gateway's.

Disposition: hand back. Deciding which side is right is a contract decision, and recording an exception without it would hide the difference the check exists to show.

Reproduce: python3 build/scripts/check_answer_shapes.py .   # with the fleet up
