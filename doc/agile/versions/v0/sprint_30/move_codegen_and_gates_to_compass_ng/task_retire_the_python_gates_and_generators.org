* Acceptance

- Each deleted script has a compass codec that gave the same verdict on main for at least one week of merges.
- The baseline files and their readers are deleted.
- local_checks.py lists only the gates compass does not cover.
- The compass repository's Retire legacy tooling targets table is updated for each removal.
- Exception reasons that name a retired baseline file or script name what stays instead.
- Until this task lands, a new accepted violation goes both into a compass exception and into the baseline its Python gate reads, so the fallback agrees.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

compass-85 sorted the scripts into four tiers, from ORE main at 732fc2ee34:

1. Deletable now: no caller outside the set. This branch.
2. Called only by a GitHub workflow: switch or remove the workflow first.
3. Still called by other code (=check_clean_standard.sh=, the CMake unity
   exclusions, generators feeding generators): move the caller first.
4. The Python generator and its 140 tests: after the =compass codegen= verbs
   forward to compass-ng and =env_init.py= and =systemd_generate.py= stop
   importing it.

Each tier is checked against compass-ng itself before it goes: a full
=compass-ng check= and =compass-ng diff= on the branch, because some scripts
are inputs to compass-ng rather than gates.

* Notes

  running these so it's fine to delete, previous checks were so slow they
  were unusable." The gates have run through compass-ng locally since
  2026-11-18 and in CI since #4917.
- Tier 1 kept four files compass-85 listed:
  - =projects/ores.seeder/datasets/conventions/propose.py=: compass-ng's
    =conventions_coverage= codec runs it (=conventions_coverage.propose=).
  - =tools/ore_conventions/extract.py=: the documented data refresh runs it
    before =propose.py=, and =test_extract.py= tests it.
  - =projects/ores.sql/utility/generate_ore_element_map.py= and
    =generate_value_sets.py=: compass-ng's =parameter_value_sets= codec reads
    them as curation data. Deleting them gave
    =parameter_value_sets/unresolved= and =ore_value_sets/refused=.
- 2026-11-21, compass-ng v0.0.5: compass now reads its curated data from
  three check documents in =compass/checks/= (=conventions_coverage.org=,
  =value_sets.org=, =ore_output_catalogue.org=) instead of parsing ORE's
  Python, and adds =single_writer=, =xml_bindings= and =list_request_table=.
  That retires =propose.py=, the five value-set modules,
  =generate_ore_element_map.py=, =generate_value_sets.py=,
  =generate_convention_kind_terms.py=, =generate_output_catalogue.py= and
  its test, =output_family_docs.py=, =check_single_writer.py= and its test,
  =single-writer.yml=, =check_xml_bindings_drift.py= and
  =regenerate_list_request_descriptors.py=. The gates =xml-bindings-drift=,
  =convention-kind-terms=, =conventions-coverage= and =ore-output-catalogue=
  leave local_checks.py; compass-ng's own result fails on their findings.
  The pin moves to v0.0.5 in the same change, because an older compass-ng
  stops on a check document.
- 2026-11-21, tier 2 workflows: main was red on Compass check, Codegen
  drift and Codegen sweep. Compass check was route inventory drift on main,
  which this branch's regenerate fixes. Codegen drift and sweep failed because
  =check_component_drift.py= stages its dry run under the git directory and
  prettier 3.9.8 refuses any path inside =.git= ("No matching files", exit 2,
  reproduced with a probe file). A worktree, whose git directory is
  =ores.git=, never shows it. The product owner chose to delete the
  single-gate workflows compass-check.yml covers: codegen-drift (its unit
  suite kept as codegen-tests.yml), codegen-sweep, core-link-edges, doc-lint,
  entity-writes, event- and history-registrar-composition, header-hygiene,
  populate-reference-drift, portable-stop-types, rls-system-tenant-widenings,
  shell-command-composition, shell-recipe-provenance, shell-script-drift and
  template-drift. Their scripts are the tier 2 deletion. The staging bug
  stays in =check_component_drift.py= until tier 3 retires it.
- 2026-11-21, compass-ng v0.0.6: =compass/checks/xml_bindings.org= holds
  the family table compass had compiled in (Families, Exact decimals,
  Schema errata, Settings, Licence), so a money member is one Exact decimals
  row and =./compass.sh generate=. That retires =generate_xml_bindings.py=,
  =regenerate_xml_bindings.sh= and =test_generate_xml_bindings_derivation.py=.
  The regenerate rewrote only banner lines, plus a route inventory line
  number already stale on main. v0.0.6's =names_missing_file= rule also
  found four template sources naming =generator.py= (folded into the
  =codegen= package in 9d24a8ff52) and =setup_database.sh= (gone); their
  org sources now name compass's =codegen= codec and =compass db recreate=.
- Before v0.0.6: =generate_xml_bindings.py=, =regenerate_xml_bindings.sh= and
  =test_generate_xml_bindings_derivation.py= were dead as code: compass-ng's
  =xml_bindings= codec writes the 26 binding files byte for byte. They stay
  for now, because compass compiles the family table, the =--exact-decimal=
  money members among it, into =xml_bindings.cpp=. With the codec on, a
  member added to the shell script's list is drift that
  =./compass.sh generate= reverts, so until the table moves into an ORE
  check document (asked of compass-85), adding a money member or an XSD
  family needs a compass change.
- =projects/ores.codegen/scripts/regenerate_list_request_descriptors.py=
  stayed until compass-ng's =list_request_table= codec ships (compass PR
  #132). It is the only writer of
  =projects/ores.web/packages/wire-protocol/src/generated/list_requests.ts=;
  today =bff_list_requests= only reports the table as stale. After that
  release, enable =list_request_table= in =.compass.org=, run
  =./compass.sh generate=, and delete the script.
- =build/scripts/tests/test_unity_checks.py= also tested
  =check_unique_type_names.py=; those tests go, and the unity collision
  tests stay.
- The generated block of =doc/knowledge/domain/ore_trade_type_coverage.org=
  still says to run =generate_trade_type_coverage.py --write=. compass-ng's
  =trade_type_coverage= codec writes that line, so compass changes it.
