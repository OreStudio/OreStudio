* Plan

The work has four parts: generalise the pipeline, vendor the pictures,
stage them as a dataset, and attach them by code.

** Pipeline. The DQ image staging table carried the image as SVG text in
=svg_data=, so only SVG documents could stage. The table now carries the
live table's own shape, a =mime_type= beside base64 =data=, so one
pipeline takes flags, icons and PNGs alike. The reverse snapshot and the
publish function copy both columns unchanged.
=images_generate_sql.py= writes the media type from the file extension,
and the manifest-driven image archetype resolves each payload key across
the four known extensions and fails on a key with no file or with more
than one.

** Vendoring. The two pictures vendor as delivered, with no crop and no
re-encode. The keys are the filenames without extension under
=external/avatars/=, because the attach step looks the pictures up by
code.

** Staging. =assets.system_avatars= is a DQ dataset whose artefact rows
are the two pictures, generated by =images_generate_sql.py --config
system_avatars=. Its methodology, dataset and tag seeds mirror the flag
seeds. The dataset is a base-bundle member at order 3, so ACME, GLEIF and
every other bundle consumer publishes it, and the master include publishes
it to the system tenant at database build time, mirroring
=iso_populate.sql=, because the super administrator's account lives in the
system tenant.

** Attaching. The =attach_photos= step gains =attach_administrator_photos=,
which runs at the top of the step, before the parties loop:

- The tenant administrator is the account the run acts as
  (=command.admin_account_id=), read through =account_service=.
- The super administrators are the system tenant's SuperAdmin holders, the
  same rule =bootstrap_mode_service= uses. Each picture is written through a
  token minted for that account (=internal_impersonation_service=), so the
  write takes the real request pipeline with its tenant checks and audit.
- The picture codes are constants, not step arguments: these pictures are
  the product's own, while the parties and datasets stay the profile's
  data.
- =copy_template_image= finds the tenant's own published row by code, so
  both tenants bind rows the bundle publish already staged.

** Idempotence. =copy_template_image= returns the tenant's existing copy by
code, and =attach_account_photo= skips an account that already carries a
picture, so a second run changes nothing.

** Refactor. =attach_account_photo= carries the read-echo-write block the
staff photos used, and =resolve_step_actor= delegates to the new
=actor_of=, which the super administrator path reuses.
