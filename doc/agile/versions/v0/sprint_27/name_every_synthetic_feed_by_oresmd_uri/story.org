* Goal

Every synthetic feed states the datum or the series it produces as an oresmd URI, the same reference the market data store, the ticks, the feed bindings and the screens use. Today each feed kind has a key of its own:

- The FX spot feed stores an ORE key (=ore_key=, such as =FX/RATE/EUR/USD=) and converts it to a URI with =ore_key_codec= and =oresmd_uri_codec= at every use.
- The IR curve feed stores a currency, an index family and a tenor. =ir_curve_qualifier= joins them into a string such as =USD/SOFR= or =EUR/EURIBOR-6M=, and each pillar then gets its URI from =pillar_datum_uri=. Its =vintage_series_uri= is already an oresmd URI.
- The common =feed= interface states a =qualifier()= for every kind. The controllers compare it, with the role, to find two feeds that publish the same thing.

So a reader meets a different name for each kind, and none of them is the reference the rest of market data uses.

The oresmd URI already names every ORE datum: 45 instrument types in 11 asset classes (see [[id:C3E053CA-0D4B-480B-9119-E11530160EC1][oresmd: ORE Studio Market Data URI]]). The feed model must accept the URI of any supported datum, so a new feed kind needs no key of its own.

* Acceptance

- The =feed= interface states one oresmd reference for every kind, and the collision check compares it, with the role. =qualifier()= is gone.
- The FX spot feed model (=ores.synthetic.fx_spot_generation_config=) carries an oresmd quote URI where it carries =ore_key=. The generator derives it from the currency pair, for example =oresmd://fx/EUR?type=quote&instrument=fx_spot&quote=rate&ccy=USD=.
- The IR curve feed model (=ores.synthetic.ir_curve_generation_config=) carries an oresmd series URI for the curve it generates, with the =curve_role=. The currency, the index family and the tenor are read from that URI, or the URI is built from them in one place, and nothing builds the old qualifier string.
- A config is checked with the strict =oresmd_uri_codec::read=. A URI that is not the right type, or that names an instrument the feed kind cannot generate, is refused with a message that names the rule.
- A feed derives a series URI with =series_of=, and publishes ticks under the URI it stores. No code calls =ore_key_codec= to build a feed's identity.
- The unique-feed rule and the display name use the URI.
- The stored rows are migrated by a SQL step, and no row keeps the old ORE key or builds the old qualifier. The columns and the =publish_from_dq= function use the new name.
- The republish subject, today built from the ORE key, is decided and either moved or kept with a stated reason (see Decisions).
- The Qt and web screens, the docs and the tests use the new name.

* Decisions

- A feed stores the URI of what it generates: the quote URI for a feed of single quotes, such as FX spot, and the series URI for a feed of curves, such as IR. The series URI of a quote feed is derived with =series_of= and never stored.
- A curve is a series, as [[id:C3E053CA-0D4B-480B-9119-E11530160EC1][oresmd: ORE Studio Market Data URI]] now states. A feed reports the series it publishes into, as a list, and two feeds conflict when their lists share a series. The role is not part of a series, so a discount feed and a projection feed of one index conflict.
- An IR curve feed builds its pillar series from the currency, the start of the pillar and the tenor of its index, which is =1D= for an overnight index and for the FOMC variant. The bootstrap config states the same currency and index tenor (=index_tenor=), so the feed that writes a pillar and the bootstrap that reads it name one series.
- The IR config keeps its structured natural key (currency, index family, tenor). The reference is derived from it in one place, because the key is validated against the index conventions by a trigger.
- The FOMC config and the standard curve of one currency both start at spot, so they publish into one series and conflict.
- The feed screens are shared. =FeedKind= states what differs between asset classes, and =FeedsPage= and =FeedPage= draw the list, the page and the dialogs. The IR curve screens are the second kind.
- Open: =market_tick_subject(tenant, party, ore_key)= builds the per consumer subject from the datum's canonical ORE key. A quote that has no ORE key, such as one with the quote type =hazard_rate=, has a URI and no key, so it cannot be republished by that subject. Decide whether the subject takes the URI (percent-encoded into a token), or whether such quotes stay out of the feeds. This touches =ores.marketdata=, not only the feeds.

* Out of scope

- New feed kinds. This story changes the reference of the existing kinds and keeps the field general. It builds no new kind.
