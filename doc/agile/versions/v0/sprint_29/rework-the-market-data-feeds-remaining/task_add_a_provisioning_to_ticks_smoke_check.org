* Acceptance

- A compass verb runs the check and prints the evidence it used.
- The check fails on a build that has the route visibility defect of 2026-10-23.
- The local check gate runs it when the marketdata, synthetic or IAM provisioning code changes.

* Plan

1. Add a =smoke ticks= verb. With =--fresh= it stops the services, recreates
   the database, starts them and provisions a non-system tenant with the
   bootstrap recipe alone (no compute packages), then waits.
2. Wait for both a tick and a demand set that carries ids: a healthy system
   can tick a minute before the supervisor's next demand refresh.
3. Read the evidence from the service log file when it exists and from the
   journal otherwise, since a systemd launch logs to the journal.
4. Keep the verdict pure, so the 2026-10-23 defect (routes invisible, no
   demand sent) is an assertion rather than a live replay.
5. Add the check to the local gate after the suite, with =--fresh=, for the
   changes that can break the path.

* Result

=compass smoke ticks= runs the path nothing else runs: it stops the services,
recreates the database, starts them, provisions a non-system tenant, and waits
for a tick and for a demand set that carries ids. It prints the tenant, its
subscriptions and routes, the tick count and the first and last instant, each
adapter's accepted, rejected and demanded ids, and where the evidence came
from. It fails on the first reason in the order of the path:

- the tenant holds no subscription;
- the tenant has no route;
- no adapter got a demand set;
- every demand set was empty;
- the adapters accepted fewer ids than demanded;
- no tick arrived within the timeout;
- a tick is dated in the future.

The verdict is a pure function, so the 2026-10-23 defect is a unit test: with
the routes invisible the supervisor sends nothing, the check reports "no
adapter got a demand set" and fails. A live run also showed that failure
before the demand evidence was wired.

The local gate runs the check after the test suite, with =--fresh=, when the
cpp, services or sql classes change. A recipe documents the verb and the
compass recipe inventory lists it.

** Verified

Against a fresh database: 10 subscriptions, 10 routes, 5,460 ticks, the first
80s after the services started, and the simulated adapter accepting 26 of the
26 ids it was sent.
