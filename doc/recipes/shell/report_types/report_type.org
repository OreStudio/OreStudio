#+title: How do I run the report_types commands from the shell?
#+description: Every command the report_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:report_types:

This file documents the report_types resource at the shell, one section per command. Every command is a subcommand of =report_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 361DCEF1-20A6-5079-B61D-B14EFDE46605
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
report_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =reporting.v1.report_types.list=.

#+name: report_types-list
#+begin_src ores-shell :tangle report_types-list.ores :exports none
report_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: A045F53E-0FA4-5DE0-BED3-924E7246ADD7
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
report_types get <code>
#+end_example

It is addressed at =reporting.v1.report_types.get=.

#+name: report_types-get
#+begin_src ores-shell :tangle report_types-get.ores :exports none
report_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 1B8E5C90-8294-54D5-A888-4D5365172474
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
report_types add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =reporting.v1.report_types.put=.

#+name: report_types-add
#+begin_src ores-shell :tangle report_types-add.ores :exports none
report_types add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 89A94CF8-38FE-55BC-8CCF-97E2B834C145
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
report_types set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =reporting.v1.report_types.put=.

#+name: report_types-set
#+begin_src ores-shell :tangle report_types-set.ores :exports none
report_types set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
