* Acceptance

- The overlap between the two workflows is stated per variant.
- The reason a shared key namespace is harmful is stated.

* Decisions

- *A shared key namespace is harmful because the objects are not
  interchangeable.* Continuous Linux builds =linux-clang-debug= and
  =linux-clang-release=. The Nightly Build builds those same two variants and
  adds =linux-gcc-debug= and =linux-gcc-release=. Only the two clang variants
  overlap. For those, the Nightly debug job sets =code_coverage=1= and
  =with_memcheck=1=, which add =-fprofile-arcs -ftest-coverage= to the compile
  line. sccache hashes the compile line, so a nightly-produced object never
  matches a continuous request. With one shared prefix, =restore-keys= hands the
  continuous job the newest matching entry, which is then a nightly entry of no
  use to it, and the job warms from cold.
