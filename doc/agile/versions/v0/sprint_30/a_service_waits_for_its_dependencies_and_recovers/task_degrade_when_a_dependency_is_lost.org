* Goal

The runner watches the heartbeat of each declared dependency. When one is
lost it marks the service degraded: the handlers that need that dependency
refuse with an outcome that names it, the others answer as before, and the
service's reconcilers that need it pause. When the dependency's heartbeat
returns, the service is ready again.

* Acceptance

- Stop a dependency: its dependents stay active, log that they are degraded
  and why, and refuse only the requests that need it, with the stated outcome.
- Start it again: the dependents return to ready without a restart.
- The heartbeat and the degraded state are visible in the service samples
  telemetry keeps.
