* Goal

Every service prints its configuration with rfl::json::write, because its options hold a logging, a NATS and a database options type that state no shape. Each options type states its shape beside its struct, and the operator writes through the codec. One task covers every service, because the shared types are the obstacle and the service types follow them.

* Acceptance

- The logging, NATS, database and telemetry options state their shapes.
- No options.cpp in the tree names rfl.
- A test proves a service's printed options are unchanged.

* Plan

- State each options type's shape beside its struct with =wire_fields=,
  by a script over the headers, skipping the password members.
- Make the passwords plain strings: =rfl::Skip= existed only to keep
  reflect-cpp from printing them, and the shape now leaves them out.
- Print each options type with =json::write=, in the hand-written printers
  and in the service-app template.
- Give the codec the leaf forms the options hold and the messages did not:
  =std::filesystem::path= and =std::chrono::duration=, in reflect-cpp's bytes.
- Assert beside every hand-written shape that it names every member, since a
  hand-kept shape is not complete by construction.

* Notes

** Where a shape lives

A shape in its struct's header costs nothing measurable (see Measurements),
and a generated field group already states its shape that way. Only a
generated entity has a separate =_codec.hpp=, because that header also
declares =wire_traits=. So the options shapes stay beside their structs.
The cost that matters is the encoder header: =struct_codec.hpp= parses
slower than =rfl.hpp= did, almost all of it in =text_form.hpp=. That is
[[id:8856431C-F316-423C-B142-FAC42D87B1AC][Keep the codec headers light]].

** The password leak the tests caught

=context_factory::configuration= holds a =database_options= and still
printed through reflect-cpp. With =rfl::Skip= gone, reflect-cpp printed the
password, and =context_factory_configuration_streaming= failed on it. The
configuration now has a shape and prints through the codec. Every other
type that holds a =database_options= or a =login_options= prints through
the codec or is never printed.

** Why the options are hand-written

Twenty of the twenty-one service options headers predate the service-app
template, which has no input for a service's own members. Generating them
from a model is [[id:AECB213E-580A-43B7-8997-2C93E1EED9E2][Generate the service options from a model]]; until then the
member-count guard keeps a hand-kept shape complete.

** Found on the way

- The two refdata apply workflow headers ran the encoder inline, so their
  includers parsed =struct_codec.hpp=. The registrations moved to
  =ores.refdata.api=.
- =compass build status= started a build, =--status= tailed the wrong
  checkout's log, a backgrounded build printed nothing until it ended, and
  the skills deploy failed on symlinked skills. All four are fixed here,
  with tests.

* Result

Every options type states its wire shape and prints through the JSON codec:
the shared logging, NATS, database, telemetry and HTTP server options, all 21
service options, the shell's login options and the database context
configuration. No options printer names reflect-cpp, and the passwords are
plain strings that the shapes leave out. A marketdata test pins the printed
member order and the absence of both passwords, and the database test caught
the one printer that still leaked the password.

Each of the 32 hand-written shapes asserts that it names every member. The
codec gained the path and duration forms, proved against reflect-cpp's
bytes. The refdata apply workflows no longer run the encoder in their
headers.

Also fixed on the branch: four compass faults around the build lock's
status and output, and the order and fleet dependence of the marketdata core
tests, recorded in [[id:25A1EEA1-7804-4A1F-9BAF-603800868260][their own task]].
