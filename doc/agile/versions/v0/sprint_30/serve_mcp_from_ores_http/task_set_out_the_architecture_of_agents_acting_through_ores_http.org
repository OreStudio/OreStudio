* Goal

Before any of the story is built, the architecture is written as knowledge: how an agent acts for a person through ores.http, from the grant that lets it, through the token that names it, the MCP transport and catalogue it calls, to the record of what it did and the six eyes on what it changes. The notes build on what the ores.agent prototype taught and on the investigations already done, and link into the existing graph: the four-eyes framework, trade authorisation, IAM sessions and the actor claim. Each note holds one idea, follows the zettelkasten house style, and draws as UML what it describes as a structure or a process.

* Acceptance

- A structure note for agents acting through ores.http lists atomic knowledge notes, each one idea: the agent grant and its keys, the agent's identity in a token, recording what an agent did, six eyes on an agent's writes, the MCP transport in ores.http, and the catalogue an agent browses.
- The structure is drawn as UML: a component diagram of the parts, a class diagram of the grant, and sequence diagrams of a read, of a write held for approval, and of a trade booked by an agent through trade authorisation.
