* Goal

Every route reads its body into one string, so the storage upload holds the whole
object in memory. A route needs a way to say its body is a stream, and the session
needs a read loop that hands the chunks on instead of collecting them.

* Acceptance

- A route states that it takes its body in chunks, and the session reads it with a
  parser that holds one chunk at a time.
- The chunks reach the handler through a bounded channel, so the socket stays on the
  executor that owns it and the handler stays on its worker.
- The per-route limit and the ceiling apply unchanged, and a declared or chunked
  body past them is answered 413.
- A body that stops arriving is closed on a stall deadline and its worker returns.
- A buffered route behaves exactly as it does today.
- A test streams more bytes than the window holds and reads back the same bytes.

* Plan

1. Add a chunk channel: a bounded queue of fixed-size buffers with a producer side
   the session fills and a consumer side the handler drains, and a stop that either
   side can raise.
2. Add =route::streams_body= and a read loop in =http_session= that parses with
   =buffer_body=, fills the channel, and reuses the limit and refusal path already
   there.
3. Give the handler the consumer through =http_request=, so the existing handler
   signature and the generated route units are untouched.
4. Hold the channel depth and chunk size in =http_server_options=, and close on the
   stall deadline with the timer the session already owns.
5. Test the bytes, the limit, the stall and the window.
