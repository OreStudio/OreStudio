#+title: How do I run the workunits commands from the shell?
#+description: Every command the workunits submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:workunits:

This file documents the workunits resource at the shell, one section per command. Every command is a subcommand of =workunits=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: F8AA4A90-F39B-5862-9367-5427B8FFEAA3
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
workunits list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =compute.v1.workunits.list=.

#+name: workunits-list
#+begin_src ores-shell :tangle workunits-list.ores :exports none
workunits list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: A499E3A4-1596-58A8-BDB2-4F1609913DF3
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
workunits get <input_uri>
#+end_example

It is addressed at =compute.v1.workunits.get=.

#+name: workunits-get
#+begin_src ores-shell :tangle workunits-get.ores :exports none
workunits get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 13E0C753-FEBC-5C00-948C-70816602AEE7
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
workunits add <id> <batch_id> <app_version_id> <input_uri> <config_uri> <priority> <target_redundancy> <canonical_result_id> <reason> <commentary>
#+end_example

It is addressed at =compute.v1.workunits.put=.

#+name: workunits-add
#+begin_src ores-shell :tangle workunits-add.ores :exports none
workunits add 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 __none__ __none__ 0 0 00000000-0000-0000-0000-000000000000 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: D7CB0AC7-0C6E-5057-B32B-2278A4EF9661
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
workunits set <id> <batch_id> <app_version_id> <input_uri> <config_uri> <priority> <target_redundancy> <canonical_result_id> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =compute.v1.workunits.put=.

#+name: workunits-set
#+begin_src ores-shell :tangle workunits-set.ores :exports none
workunits set 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 __none__ __none__ 0 0 00000000-0000-0000-0000-000000000000 system.new_record generated_script
#+end_src

:PROPERTIES:
:ID: EB0AD984-C868-5C8B-A873-58D9AFABDA2C
