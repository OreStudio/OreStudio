* Goal

One CI job runs the marketdata service suite through a transaction pooler in
front of the test database, so a change that only works without a pooler fails on
the pull request rather than on a shared host.

* Acceptance

- The job starts a pooler in transaction mode against the test database, with the
  configuration the shared-fleet task states, and runs the affected suite through
  it.
- The job runs on every pull request that touches the database layer, the services
  or the test suite, and is not optional.
- It fails when the prepared-statement decision is violated: with named statements
  and a pooler below the floor, or with unnamed statements configured as named.
- The default path stays direct: a developer runs the suite with no pooler
  installed, and CI's ordinary job still does too.
- The job's own cost is recorded, because a check nobody waits for is a check
  nobody runs.

* Plan

The pooler is the container the pauli task builds, run by the CI job against the
same PostgreSQL service the other jobs use - no new service to install on the
runners, and the same image the deployment runs, so the job proves the artifact
and not a substitute.

Which suite is the first candidate: =ores.marketdata.service.tests=, because it
exercises the repositories, the transactions and the listener's neighbour paths,
and is the suite the connection work was measured against. The job widens to the
other suites once its cost is known.
