* Goal

A provisioned ACME states an initial approval matrix that is comprehensive across the trade type population and related to what each book is called: the cable book carries the FX option types, the CDS book the credit types, and together they cover every type the generator books, with no book carrying a type its party does not permit.

* Acceptance

- Each published ACME book states the product types its name and purpose imply, and no longer takes every code the catalogue holds.
- The party's set is stated by the provision and covers every one of its books' sets.
- The affinity is one list per book, read both by the book's set and by the generator's choice of types, so the two cannot drift apart.
- Every type the generator books into a book is permitted by that book's matrix, and a check fails when one is not.
- The union of the books' sets covers the trade type population the generator books, so no generated type is left without a book that may carry it.

* Plan

The gap is in the book population and not in the approval model.
=ores_refdata_publish_books_from_dq_fn= writes =restricts_product_types = true= on
every book and then takes *every* code the system catalogue holds, so the matrix
a provisioned tenant receives says nothing about the book; and no provision
states a party's set, so the party permits everything by its flag.

1. *The affinity is data, keyed by the book.* A curated table states, per book
   name or desk family, the product types a book of that name carries. The book
   population reads it to write the junction, and the generator reads the same
   rows to choose the types it books, so there is one list and not two.
2. *The publish writes the book's own set.* The DQ books artefact carries the
   affinity key, the publish resolves it to codes, and a book whose key states
   nothing is refused rather than published open.
3. *The party's set is the union of its books.* The provision states it after the
   books are published, so the subset rule holds from the first write and no
   book is ever outside a party that has not yet spoken.
4. *The population is checked against the matrix.* A published population states,
   per book, the trades booked and the types its matrix permits, and a check
   fails when a booked type is not permitted; the same check proves the union of
   the books covers the trade type population.
5. *The seed test changes with it.* =refdata_book_product_types_seed_test.sql=
   asserts today that a published book takes every code; it asserts the book's
   own set instead, and that the union across the group covers the population.
