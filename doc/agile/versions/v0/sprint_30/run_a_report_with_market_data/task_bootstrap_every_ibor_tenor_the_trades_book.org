* Acceptance

- The IBOR indices the generated trades name are listed from the requirements function, with the ones not bootstrapped today.
- Each listed index has a bootstrap config, the quotes it reads, and a published curve under each party.
- The ACCOUK NPV run reports no 'did not find object' of type ibor index for a listed index.
- An index left out is named with its reason, such as a GENERIC index of a currency ORE does not know.

* Plan

1. List the IBOR indices the generated trades name, from
   =ores_trading_market_references_fn=, against the bootstrap configs
   (=evidence/ibor_needed_query.txt=).
2. Add each new curve by cloning a curve the system already builds, in place,
   so the new rows follow the existing pattern exactly: GBP-LIBOR-3M for the
   GBP tenors, EUR-EURIBOR-6M for the EUR ones. Each clone sits right after
   its template, in the statement the template's row is in, and only its ids,
   its name and its index tenor change (=evidence/clone_ibor_curves_py.txt=).
   The ICE and Tradeweb feed rows go into the provider seed's own groups, and
   the template entries follow from them.
3. Regenerate the vendor catalogue with =ores.marketdata.vendor-catalogue=.
   Its documented input query needs a seeded database, and the seed refuses
   to load while a config has no vendor id, so the input was rebuilt from the
   seed's own generated blocks plus the new pillars
   (=evidence/vendor_catalogue_input_py.txt=). The diff is the 35 new ids and
   two count lines.
4. Recreate, provision, and run the ACCOUK NPV report.

* Decisions

- *Five curves, the LIBOR and EURIBOR tenors:* GBP-LIBOR 6M, 12M and 1W,
  EUR-EURIBOR 12M and 1W. They cover 63 trades of the population.
- *Left out:* the synthetic IR curve config admits a term tenor only for
  the LIBOR and EURIBOR families, so CZK-PRIBOR-6M, CNH-HIBOR-3M,
  HKD-HIBOR-1M, ILS-TELBOR-3M, JPY-EYTIBOR-6M, KRW-CD-91D, NOK-NIBOR-3M,
  SAR-SAIBOR-3M and SGD-SOR-3M need that check widened first, and CNH, ILS,
  NOK and SAR have no funding curve either. One trade each. The GENERIC
  indices of AOA, BHD, PKR and QAR name currencies ORE does not know.

* Result

The system now bootstraps and publishes GBP-LIBOR 6M, 12M and 1W and
EUR-EURIBOR 12M and 1W, cloned from the curves it already built, so each
party publishes 35 curves and the package step forwards them. On the ACCOUK
NPV run no trade fails on one of these indices; the index failures left are
the twelve single-trade indices whose families the synthetic config does not
yet admit. The record also corrects the earlier claim that the trades named
a ceased LIBOR index: the system generates LIBOR on purpose.
