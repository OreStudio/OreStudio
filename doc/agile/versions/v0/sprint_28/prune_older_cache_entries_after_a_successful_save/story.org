#+title: Story: Prune older cache entries after a successful save
#+description: Saves use a run-unique key so that a failed save can never destroy the cache, but the entries accumulate: two clang-debug runs already cost 5 GB of the 10 GB repository cap, the cache sits at 9.55 GB with 0.45 GB free, and the gcc cache has been evicted entirely, so the nightly gcc jobs run cold. Delete every older entry of the same variant once the new one is stored, which bounds each variant to one entry and frees roughly 5 GB.

* Decisions

- The delete returns, but only after a successful save. The earlier removal
  was about ordering, not about deleting: deleting first left a window in
  which a failed save destroyed the cache. Deleting afterwards cannot.
- One entry per variant is the target. It bounds the repository cache at
  roughly one cache per variant plus vcpkg, which fits the 10 GB cap and
  leaves room for the gcc jobs.
- The filter was dry-run against the live cache before it was committed, so
  the expression that selects the older entries is known to select the
  right ones.

* Out of scope

- Caching the macOS and Windows compilers. They still do not fit, and the
  Linux caches are the ones on the critical path.
