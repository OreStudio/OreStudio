* Acceptance

- Each of the twelve types has a JSON and a MessagePack encoder and decoder over yyjson and msgpack-c.
- A test for each type compares its bytes with reflect-cpp's, in both formats and both directions.

* Plan

** What the twelve are, and what makes each custom

Surveyed at =649b3072f0=. Eleven are =rfl::Reflector= specialisations and one is
a =rfl::parsing::Parser= specialisation, which is why the count reads twelve
rather than eleven:

| Type | Wire form | Where the reflector is |
|------|-----------|------------------------|
| =boost::uuids::uuid= | the lower-case canonical string | =ores.utility/rfl/reflectors.hpp= |
| =std::optional<boost::uuids::uuid>= | the string, or null | same |
| =utility::uuid::tenant_id= | the canonical string | same |
| =std::chrono::year_month_day= | ="YYYY-MM-DD"=, the empty string for the default-constructed value | same |
| =utility::decimal::decimal= | the decimal's own text | same |
| =boost::asio::ip::address= | the address's text | same |
| =utility::serialization::error_code= | the underlying integer, not its name | same |
| =trading::domain::product_type= | the enum's token | =ores.trading.api/domain/product_type.hpp= |
| =scheduler::domain::cron_expression= | the expression's text | =ores.scheduler.api/domain/cron_expression.hpp= |
| =workflow::messaging::step_log_level= | the enum's token | =ores.workflow.api/messaging/workflow_vocabulary.hpp= |
| =workflow::messaging::step_outcome= | the enum's token | same |
| =std::chrono::system_clock::time_point= | ISO 8601 UTC, six digits | =ores.utility/rfl/time_point_parser.hpp= |

Eleven of them are a *string* on the wire, and the custom part is the text form,
which the two formats carry as their own string primitive. The twelfth,
=error_code=, is the exception the survey found: its reflector names the
underlying integer, so the wire carries a number and the codec states a number.
That is what makes this task small and uniform rather than twelve unrelated
encoders, and it is why the survey mattered -- the plan read "twelve strings"
until the reflectors were read one by one.

The text forms of four types live in the components that own the types, beside
their reflectors, because =ores.utility= cannot see a product type or a workflow
outcome: =ores.trading.api=, =ores.scheduler.api= and =ores.workflow.api= each
state their own.

** Dependencies

=vcpkg.json= names =reflectcpp= and neither =yyjson= nor =msgpack-c=. Both are
added with this task and linked into =ores.utility=, beside the reflect-cpp they
are measured against.

** The surface the generated codecs will call

One header per format, in =ores.utility= beside =rfl/=, with a per-type
specialisation and a free function the generated code names:

#+begin_src cpp
namespace ores::utility::codec {

template <typename T>
struct json_codec;   // static void write(yyjson_mut_doc*, yyjson_mut_val*, const T&)
                     // static T read(yyjson_val*)

template <typename T>
struct msgpack_codec;  // static void write(msgpack_packer*, const T&)
                       // static T read(msgpack_unpacker*)

}
#+end_src

A container and the =std::optional= wrapper are generic over the element's
codec, as the database layer's =pq::codec= is; only the twelve need a
specialisation.

** How it is proved

The acceptance is byte equality with reflect-cpp, so the case per type encodes
the same value through both and compares the bytes, in both formats, and decodes
reflect-cpp's bytes with the new decoder and the new encoder's bytes with
reflect-cpp. A value chosen at the edge of the type's range is encoded as well as
a typical one, because the two disagree first at the edges: a nil uuid, the
default-constructed date, a negative decimal, a time point with a microsecond and
one before the epoch.

* Result

The twelve types have a JSON and a MessagePack encoder and decoder over yyjson
and msgpack-c. Eleven are strings on the wire and the twelfth is a number: the
survey of the reflectors, one by one, is what found that an error code is its
underlying integer and not its name, and the plan was corrected before any of
the code was written.

The custom part of every type is its text form, so the two formats cannot
disagree about a value -- only about how they frame it -- and one generic
carrier serves eleven of the twelve. `ores.utility` owns the types it can see;
the product type, the cron expression and the two workflow enums state their
text form in their own components, beside the reflector that already named it,
because the utility component cannot see them.

The acceptance is proved by byte equality with reflect-cpp, in both formats and
both directions, for each of the twelve: 102 assertions in 23 cases across the
four suites, and two defects in the test harness were found by those cases
before the code was believed -- a string built from two different temporaries,
and two test files colliding in the unity build.

Both libraries are declared in the manifest and linked into the component that
owns the codecs, rather than relied on as dependencies of reflect-cpp, so the
day reflect-cpp is removed the codecs keep their carriers.
