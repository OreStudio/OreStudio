* Summary

A trade set is a set of trades, and it is the primitive. A trade group is
a trade set created for a run of a process. A structure is a trade set
that is also a product, and a link is neither, because it holds no
container. This page is the way into the cluster: the test that tells
these apart, the taxonomy they form, and the order to read them in.

* Detail

** The words

| Word | What it is | Its identity | Detail |
|------+------------+--------------+--------|
| Trade set | A set of trades, defined by a context | The context's entity, or a key of its own | [[id:116164D0-A54A-4872-8BA6-1FE36583C8C4][Trade set]] |
| Trade group | A set created for a run of a process | Its own key, and a foreign key to the run | [[id:D6CF158A-69D1-4C1A-8FF3-0F1F4836B16B][Trade group]] |
| Structure | A set that is also a product | Its own key | [[id:FC31FC9C-7A6E-4EFD-8A62-6DE4137F7160][Trade Structures and Deal Composition]] |
| Link | A relation between trades that holds nothing | None | [[id:2AAC92EB-2320-4385-999E-947E9E8FE5C5][Trade links]] |

The words are not degrees of one thing. Every collection here is a
trade set. A trade group is the one an operation creates, a structure
is the one that is also a product, and a link is not a collection at
all.

** The test

#+begin_quote
Ask what defines the collection. If something in the business names
it, it is a trade set, and the context's entity supplies its identity.
If a process created it, it is a trade group, and the run supplies its
identity. If it relates particular trades for a reason and contains
nothing, it is a link.
#+end_quote

The test follows from the rule Data-Oriented Design states for persisted
data: relationships are keys, not ownership. A named collection cannot be
a by-product of the links between its members, because nothing would then
carry its name or record that it is empty.

The converse matters as much. A link is not a degenerate group. Recording
a hedge as a group of two would give it an identity the business never
refers to, and every reader would have to look through the group to reach
the relation.

* What this cluster does not cover

- *Batching and chunking.* How a set is partitioned for a report or for
  the compute grid, and the strategies that do it, belong with
  [[id:98B9FE2A-57FB-464F-A4E5-198461FE6987][Compute Engine]] and the report-execution pages. This
  cluster supplies the set they partition.
- *The run.* The identity of a run, the process enumeration, and the
  states a run moves through are their own subject. This cluster states
  the foreign key and stops.
- *Each process.* A funding roll, a sweep and a compression have pages of
  their own. [[id:D6CF158A-69D1-4C1A-8FF3-0F1F4836B16B][Trade group]] carries the catalogue and the
  role rules, and does not restate them.
- *Links.* [[id:2AAC92EB-2320-4385-999E-947E9E8FE5C5][Trade links]] and
  [[id:04F5EFF1-D4B5-4BD0-8CBC-4EF5DDF97921][Trade link types]] carry the relations that are not
  sets.
- *Positions and filters.* [[id:886AAFB5-62F3-4AA3-B325-386665AFF926][Positions]] and
  [[id:44C9D99B-979B-43AB-90BC-AF7E7D8BDE7C][Dynamic books]] are neither a set nor a link.
