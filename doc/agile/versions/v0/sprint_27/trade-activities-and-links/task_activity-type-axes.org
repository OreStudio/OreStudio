* Acceptance

- The activity type carries the economic, confirmable and real flags and a priority, seeded for every existing code.
- The seeds match the trade activity knowledge note; a pgTAP test checks a sample of codes.

* Plan

- The activity type already has =requires_confirmation=, which is the
  confirmable axis; add =is_economic=, =is_real= and =priority= beside it
  rather than a second confirmable flag.
- Priority ranks 1 to 8 follow the reason-for-update order in Trade
  versioning (book moves first, misbooking last); 9 is every other cause.
- Checks: the priority is a rank of that order, and a type that is not real
  is neither economic nor confirmable.
- One table in =scratchpad/seed_axes.py= rewrites every seed row with its
  axes and adds =null_amend=, the one type that is not real. Several
  confirmation flags change to agree with the activity mapping in the
  knowledge note (amendment, partial and full termination, assignment,
  increase, decrease, roll, compression, clearing, netting, rebook, split
  and merge are confirmable).
- The knowledge note gains a table of the seeded types generated from the
  populate script, so the two cannot disagree.

* Result

Each activity type states the confirmable (=requires_confirmation=),
economic and real axes and its priority in the reason-for-update order. The
schema refuses a priority outside ranks 1 to 9 and a type that is not real
but claims to be economic or confirmable. =null_amend= joins the seeds as
the one type that is not real, and the confirmation flags now agree with
the activity mapping in the trade activity note, which lists every seeded
type with its axes.
