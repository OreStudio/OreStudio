* Result

The task is delivered in two halves, and the second half is this commit.

The refdata vocabularies came first.

- The 34 refdata vocabulary tables the provisioner copied are no longer copied.
  Each one's model declares `:rls_own_or_system_tenant_rows:` and
  `:system_tenant_visible:`, so its policy admits the system tenant's rows and
  its repository reads them beside the caller's. The generated SQL, the C++ and
  the ER diagrams follow from the models.
- The validators already read the system tenant, so removing the copies changes
  no check: a tenant's party type is validated against the system catalogue
  whether or not the tenant holds a copy.
- =parties= and =business_centres= stay, and they are not copies: the provisioner
  creates the tenant's own system party and business centre with its own code
  and identifier.
- A recreate passed end to end with the policies and the shortened provisioner,
  and `compass db status` reports the schema in sync.

The catalogues and the bootstrap followed.

- Twenty more catalogue tables are read from the system tenant and copied into
  no tenant: the twelve DQ registries (artefact types, dataset bundles, data
  domains, subject areas, coding schemes and their authority types, the three
  dimensions, methodologies, change reasons and their categories), the six
  trading lookups (trade identifier types, trade link types, activity types,
  structure kinds, structure templates and their roles), the marketdata series
  classification rules, and =party_categories=. Path and row-level security
  follow the same rule as the vocabularies: a shared-reference read, and a write
  path only in the caller's own tenant.
- =party_categories= had no row-level security at all, so every session read
  every tenant's categories. It takes the shared-reference policy now, stated by
  hand in the refdata policies file because the table has no codegen model. Its
  validator reads the platform's copy, so removing the tenant copy loses no
  check.
- A new tenant is seeded by =ores_dq_tenant_bootstrap_fn(uuid)=, the second
  caller of the publish function. It names its bundles in one place, publishes
  them into the tenant being created, and the provisioner holds no list of its
  own. Today the list is =tenant_defaults=: 144 badge definitions, 187 badge
  mappings, 6 badge severities and 49 code domains, every row carrying the
  provenance of the dataset that produced it.
- The bootstrap reads the dataset from the system tenant rather than from the
  target. That is what removes the last reason a tenant needed a dataset row of
  its own, and it is the same rule the page states: the staged artefacts and the
  row that describes them are held in one copy.
- The four IAM copies stay, because those rows are the tenant's own: its
  members are granted its roles. The function's header says so, so the copy is
  declared rather than implicit.
- =test/dq_tenant_bootstrap_test.sql= asserts the seeded row counts, the
  provenance, the absence of every copied catalogue, the reads that replace them
  and a second bootstrap that inserts nothing. A recreate passed end to end and
  the whole SQL suite passes, 882 tests in 93 files.

Three tests that this branch's earlier commits invalidated were repaired here:
the currency groups test still named the =base= bundle, the conventions test
asserted that the system tenant holds no convention, which the bring-up now
publishes, and three trading fixtures wrote a business centre the published
catalogue already holds. The conventions test now asserts provenance instead of
absence, which is the property that distinguishes a published row from a seeded
one.

What remains is not this task's.

- The IAM roles a tenant starts with are a copy of the system tenant's. Whether a
  tenant's roles should be shared rows rather than copies is an IAM question, and
  the copy is declared until it is answered.
- =party_categories= still has no model, so its policy is stated by hand.
- The publish functions rewrite their rows, so a second run reports =updated=
  rather than =skipped=. The bootstrap leans on this being harmless, and
  [[id:16127025-230A-4723-A04E-02906ED26CCC][Make the publish guarantees real]] owns the fix.
- The badges are written both by a populate script, into the system tenant, and
  by this bootstrap, into a tenant: the system tenant holds 138 badge definitions
  and a tenant is seeded with the 144 the artefacts state.
  [[id:A611C520-54AA-4562-9BA6-768278E5DDEE][Collapse the tables written both ways]] owns that.
