* Goal

Two prototype mechanisms exist. Seven static pages live under
=doc/prototypes/= and follow one documented way. Eleven journey prototypes
live as React routes in =ores.web= and follow a second way. The React form
needs the application's shell, build and types, so a prototype cannot open
without running the app, cannot deploy with the documentation, drifts with
the product, and leaves a second inventory that disagrees with the first.

This story retires React for prototypes. It ports the journey prototypes to
static pages under =doc/prototypes/=, makes =index.org= the only inventory
and the only documented way, publishes every prototype through the site
build, and guards the rule so a second way cannot grow back.

* Decisions

- React is for the product; a prototype is static HTML, CSS and JavaScript.
  React buys fidelity to the real shell, but it costs the application's
  build, dependencies and types, and a prototype is throwaway. Quick to
  author, quick to open and quick to delete wins.
- Every prototype is listed in =doc/prototypes/index.org= and published by
  one =ores-deploy-web-app= call. The inventory is the only register.
- A guard enforces the rule: it fails on a prototype missing from the
  inventory, on a row with no prototype, on a prototype the site build does
  not publish, and on any React prototype tree.
- The journey documents keep the accepted design and its commit. The
  clickable prototype is the argument; the document is the record.

* Out of scope

- The application's own React components. Only the prototype tree is removed.

* Result

Shipped in PR #2696. Every prototype is a static page under
=doc/prototypes/=, listed in one inventory, published by the site build and
guarded in CI, and no prototype is a React route.
