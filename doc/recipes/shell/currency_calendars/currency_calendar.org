#+title: How do I run the currency_calendars commands from the shell?
#+description: Every command the currency_calendars submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:currency_calendars:

This file documents the currency_calendars resource at the shell, one section per command. Every command is a subcommand of =currency_calendars=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 8B3F6234-CBD6-5C43-9CC3-93A6C6E5A86A
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
currency_calendars list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.currency_calendars.list=.

#+name: currency_calendars-list
#+begin_src ores-shell :tangle currency_calendars-list.ores :exports none
currency_calendars list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: B688ECCD-699C-586E-9F4B-DB977C1B4DDB
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
currency_calendars get <currency_iso_code> <calendar_code>
#+end_example

It is addressed at =refdata.v1.currency_calendars.get=.

#+name: currency_calendars-get
#+begin_src ores-shell :tangle currency_calendars-get.ores :exports none
currency_calendars get __none__ __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 44F54CFB-0732-51EA-8F7B-82DF799FF88B
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
currency_calendars add <currency_iso_code> <calendar_code> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.currency_calendars.put=.

#+name: currency_calendars-add
#+begin_src ores-shell :tangle currency_calendars-add.ores :exports none
currency_calendars add __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 30DF150C-0AA3-5E04-A66E-4727AC6A4958
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
currency_calendars set <currency_iso_code> <calendar_code> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.currency_calendars.put=.

#+name: currency_calendars-set
#+begin_src ores-shell :tangle currency_calendars-set.ores :exports none
currency_calendars set __none__ __none__ system.new_record generated_script
#+end_src

** =by-currency-iso-code=
:PROPERTIES:
:ID: E4C0EDF9-46BC-5E9C-83F4-F95BCB96962C
:END:

Reads one page of the rows that share a relation value. The relation is part of the address rather than a filter applied after the read.


The command is shaped like this:

#+begin_example
