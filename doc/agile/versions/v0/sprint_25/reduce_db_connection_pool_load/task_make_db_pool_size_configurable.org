* Plan

Two-tier design (Option B) was chosen over the capture's original
plan: a fleet-wide default falling back per-service. This task scopes
*only* the per-service tier — the fleet-wide default tier is deferred
until bright_faraday's PR adding "global options common to all
services" lands, since that PR will provide the natural home for it.

Per-service tier, following the existing =db-host=/=db-port= pattern
in =database_configuration=:

1. Add =int pool_size = 4;= to =database_options=.
2. Add a =--db-pool-size= CLI option (default =4=) to
   =database_configuration::make_options_description=.
3. Read it into =database_options::pool_size= in
   =database_configuration::read_options=. The =ORES_<APP>_DB_*= env
   var mapping is generic (prefix-based), so
   =ORES_<APP>_DB_POOL_SIZE= falls out for free once the CLI option
   exists — no separate env var wiring needed.
4. Update the =component-service= codegen archetype
   (=ores.cpp.service-app.application_impl.org= /
   =cpp_service_app_application.cpp.mustache=) so generated
   =application.cpp= emits =.pool_size = db_opts.pool_size= instead of
   the =4= literal.
5. Re-tangle codegen templates, regenerate all 17 domain services,
   rebuild.
6. Defaults are unchanged (still =4= everywhere) — this task only adds
   the knob, it does not lower the default (that's the sibling task).

** What

Add =pool_size= (and possibly =num_attempts=/=wait_time_in_seconds=)
to =ores::database::database_options= and
=database_configuration::read_options=
(=projects/ores.database/src/config/database_configuration.cpp=),
sourced from a new =--db-pool-size= CLI flag and/or
=ORES_<APP>_DB_POOL_SIZE= env var, following the existing
=ORES_<APP>_DB_*= convention (see =database_user_arg=,
=database_password_arg= etc in that file), defaulting to =4=. Update
the =component-service= codegen archetype
(=projects/ores.codegen/library/templates/ores.cpp.service-app.application_impl.org=)
so generated =application.cpp= emits =.pool_size = db_opts.pool_size=
instead of a literal, then re-tangle and regenerate all 17 domain
services.

** Why

=pool_size= is currently a compile-time literal duplicated identically
across all 17 generated =application.cpp= files, so tuning it requires
a template edit, full codegen regeneration, and rebuild of every
service. Making it configurable lets pool size be dialed per
environment without a rebuild — small pools for hosts running many
concurrent dev environments (fleet observed with ~10 worktrees), large
pools for a single perf-testing environment — and is the durable fix
behind the quicker mitigation of just lowering the template default.
