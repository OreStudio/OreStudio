* Goal

The web client reads the batches, workunits and results that the session may see, one page at a time, through BFF routes on the journey runtime.

* Acceptance

- A route returns a page of batches, newest first, with the total count.
- A route returns a page of the workunits of one batch, and a page of the results of one workunit.
- A route returns one batch, one workunit or one result by id.
- Each route checks the entity's read code, and the row-level policy narrows a party member to their own party.

* Plan

One module in =wire-protocol= holds the reads, and one module in the BFF holds
the routes, as the grid usage read does.

- =grid-jobs.ts= in =wire-protocol= declares the request and reply schemas of
  the generated batch, workunit and result reads, the readers, and the views a
  screen reads. A view states an unset value as =null=.
- =grid-jobs.ts= in the BFF registers six routes under
  =/api/operations/grid/jobs/=: the batches, the workunits of a batch, the
  results of a workunit, and one batch, workunit or result by id.
- Every route is one generated read on the session's own client. The route
  states no tenant and no party.

* Notes

- The batch list first ordered by its key only. A live check on 2026-10-22
  showed that the key is a random identifier, not a time-ordered one. Six
  batches were created in turn, and the key order read b, d, e, a, f, c. The
  task Order the job lists by when they were recorded made the recording time
  sortable and the default order of the batch list. The routes send no order,
  so they take that default, and a live check read the six batches newest
  first. The routes needed no code change for it.
- The generated batch read is keyed by the external reference, not the id. The
  by-id route reads through the list read's =id_one_of= filter.
- The service states an unset id as the nil uuid, unset text as an empty
  string and an unset instant as the epoch. The views state =null= for each.
- Until the task Decide who sees a node's name is done, the result views state
  the node to an operator only. Other sessions get =host_hidden= set.
- A route reads the jobs of the tenant the session is inside. An operator in
  the system tenant does not read another tenant's jobs without entering it.
- A live check on 2026-10-22, as each role, showed the following.
  - An operator reads the jobs of the system tenant only. The batch of an
    Acme tenant answers 404, so tenant ownership holds.
  - An operator sees the host of a result. A tenant administrator gets
    =host_hidden= set.
  - A party member of the batches' own party reads all six batches. A member
    of another party reads none, with a total of 0.
  - Both party members are refused the workunit and result reads with 403.
    The Member role does not hold those read codes. The task Let a party
    member read workunits and results adds them.
  - A failed run keeps its output address. The prototype showed none for a
    failed run, and the screens must not assume it.
- Not checked: a tenant administrator who reads the batches of several
  parties. Every check batch belongs to one party.
