#+title: How do I run the purpose_types commands from the shell?
#+description: Every command the purpose_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:purpose_types:

This file documents the purpose_types resource at the shell, one section per command. Every command is a subcommand of =purpose_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 5B561167-B267-5867-929E-5D0CF4AFE657
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
purpose_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.purpose_types.list=.

#+name: purpose_types-list
#+begin_src ores-shell :tangle purpose_types-list.ores :exports none
purpose_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: F4E62925-2C26-592F-ADB0-731D334CAF35
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
purpose_types get <code>
#+end_example

It is addressed at =refdata.v1.purpose_types.get=.

#+name: purpose_types-get
#+begin_src ores-shell :tangle purpose_types-get.ores :exports none
purpose_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: D2118EC8-64F0-5BDF-BA60-94D13A4024B3
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
purpose_types add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.purpose_types.put=.

#+name: purpose_types-add
#+begin_src ores-shell :tangle purpose_types-add.ores :exports none
purpose_types add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: B52D8F24-1E4F-5527-920C-A158A2A5683C
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
purpose_types set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.purpose_types.put=.

#+name: purpose_types-set
#+begin_src ores-shell :tangle purpose_types-set.ores :exports none
purpose_types set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
