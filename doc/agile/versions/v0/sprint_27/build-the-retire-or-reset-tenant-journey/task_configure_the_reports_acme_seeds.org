* Goal

Every report definition ACME carries resolves a report configuration, each scoped to the ACME root portfolio and shaped after the matching external/ore example, and a SQL function returns every book under a root portfolio for the run to read.

* Acceptance

- Every report definition provisioned to ACME resolves a configuration, so no run fails with 'risk_report_config not found'.
- Each configuration is scoped to a root portfolio, or records why the root portfolio does not apply.
- The configuration values follow the matching external/ore example under external/ore/examples.
- A SQL function returns every book under a given root portfolio, and the report run reads the population from it.

* Plan

The inventory first, because the numbers decide the shape.

- The seed profile =acme_demo= publishes the =risk_management= and
  =party_essentials= bundles, and =ore.report_definitions= rides both. The
  dataset carries 31 definitions, not the 30 its own docstring claims. The
  publish runs per party, and provisioning publishes to the system party and
  to each ACME company, which is where the 155 comes from.
- Every definition is report type =risk=, and that type requires four
  configuration types: =pricing_engines=, =todays_market=,
  =curve_configuration= and =conventions=.
- The run resolves a =risk_report_config= by definition id. No seed writes
  =ores_reporting_report_configurations_tbl=, the risk config or its scope,
  so every seeded definition is unrunnable.
- The root portfolios are =Group Treasury Portfolio=, =Global Portfolio=,
  =Regulatory Capital=, =ACME Corporation US Inc Global Markets= and
  =ACME Corporation HK Ltd Global Markets=.
- The SQL method that returns the books under a root already exists:
  =ores_trading_get_book_ids_by_portfolio_fn= walks the portfolio subtree,
  and =ores_reporting_resolve_book_ids_for_config_fn= already calls it for a
  config scoped by portfolio. This task reuses both rather than adding a
  third.

Work, in order. The configuration is a standard dataset, so it arrives the
way every other ACME datum does.

1. Done in PR #2845, but in the wrong shape. =ores_reporting_seed_report_configurations_fn=
   creates the risk report config and the root portfolio scope, and
   =ores_reporting_analytic_flags_fn= maps each seeded report name to the
   analytics it turns on. Both stay, but the seeder becomes the dataset's
   publish function rather than something a caller invokes by hand.
2. Outstanding. The artefact table. The scaffold
   =projects/ores.dq/modeling/ores.dq.risk_report_config.org= exists and
   needs its columns, its flags and its physical spaces, modelled on
   =ores.dq.report_definition.org=. Regenerate to produce
   =dq_risk_report_configs_artefact_tbl= and its C++ staging entity.
3. Outstanding. Register the artefact type row in
   =dq_artefact_types_populate.sql=, mirroring =report_definitions=:
   artefact table =dq_risk_report_configs_artefact_tbl=, target table
   =reporting_risk_report_configs_tbl=, target subject
   =reporting.v1.ops.publish_risk_report_configs_from_dq=.
4. Outstanding. Register the dataset and its dependencies. The dataset
   carries the artefact type above; it depends on =ore.report_definitions=
   for the definitions it configures, on the ORE run configuration for the
   four documents it binds, and on the organisation datasets for the root
   portfolio it scopes to. Declare each with a role, the way
   =acme_dataset_dependency_populate.sql= does.
5. Outstanding. Reshape the publish function to read the artefact table,
   resolve each row's report definition by name for the target party, and
   write the risk config and its scope.
6. Outstanding. Seed the artefact rows for the 27 available reports and add
   the dataset to the bundles.
7. Outstanding. Extend =ores_iam_reset_tenant_fn= to wipe the configuration
   tables, so a reset leaves a tenant in the seeded state rather than with
   orphaned configurations.

The split matters. =ores.ore= owns the run document and the four
configuration documents, through =ore import-run=. =ores.reporting= owns the
risk report config, the analytics and the scope, and =ores.dq= stages the
rows that become them. An earlier draft of the seeder also wrote the
bindings, which would have duplicated what the import already writes.

* Result

The report configurations now arrive as a standard dataset. PR #2863 lands
the artefact table's staging entity, the =risk_report_configs= artefact type,
the =ore.risk_report_configs= dataset with its three dependencies, the
=ores_reporting_publish_risk_report_configs_from_dq_fn= publish function, the
27 artefact rows, the =risk_management= bundle membership, the reporting
service's subscription to the new subject, and the reset's wipe of the
reporting configuration chain.

Seven of the plan's steps landed: the flags map stays and the hand-run seeder
is gone; the artefact table and staging entity exist; the artefact type row,
the dataset row, its dependencies and the bundle member exist; the publish
function reads the artefact table and writes the config and its root
portfolio scope; and =ores_iam_reset_tenant_fn= wipes the configuration
chain.

The book population needs no new function:
=ores_reporting_resolve_book_ids_for_config_fn= already expands the config's
portfolio scope through =ores_trading_get_book_ids_by_portfolio_fn=.

Four of the 31 seeded definitions stay out: Board Risk Dashboard, Stressed
VaR and Intraday Risk Monitor need =historical_return=, and P&L Attribution
needs =basel_traffic_light=. Neither type has an ORE saver, so their artefact
rows are absent rather than wrong. The per-report analysis is
[[id:07FC58A2-A6AB-4444-8F96-ADCA9B2985C6][What each ACME report needs to run]].

=compass db recreate -y -k= exits 0, and the loaded database holds one dataset
row, one artefact type row, 27 artefact rows, three dependencies and one
bundle member.
