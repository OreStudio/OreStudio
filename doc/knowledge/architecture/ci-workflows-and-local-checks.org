#+title: CI workflows and local checks
#+description: GitHub runs no check on a pull request. Every check that used to gate one runs locally through compass check, which classifies the change against the decision tree in build/scripts/local_checks.py and writes one report. The workflows that never touched a pull request still run on GitHub.
#+type: knowledge
#+level: cross
#+filetags: :ci:devops:pr:velocity:checks:
#+created: 2026-08-11
#+updated: 2026-10-06

* Summary

GitHub runs *no check on a pull request*. The twelve workflows that used to
carry a =pull_request= trigger lost it on 2026-10-06, and =entity-writes.yml=
lost it when it was caught growing the trigger back hours later; the earlier
=pr.yml= gate and the automatic review were already gone. The local check
runner replaced the whole pull-request gate:

#+begin_src sh :results verbatim
./compass.sh check
#+end_src

=compass check= reads the branch diff against =origin/main=, classifies every
changed path against the decision tree in =build/scripts/local_checks.py=,
runs the checks that class needs, and writes
=build/output/local_checks/report.md= — one table of every check with its
result and time, and a *Fix these first* section naming each failure, the
command that reproduces it, the command that fixes it, and the tail of its
log. The exit code is 0 when every selected check passed.

The runner is the gate for two reasons. GitHub checks arrived minutes after a
push, so a broken change waited behind a queue for a verdict a workstation
reaches in seconds. And a workflow could only fire on the paths it named; a
change matching no workflow saw no check at all, while the runner's
catch-all sends an unclassified path through everything.

* The decision tree

One table, in =build/scripts/local_checks.py=, maps a changed path to a
change class. A check runs when its class matched the change *and*, when the
check declares its own path patterns, one of them matched too.

| Class | Paths | What it covers |
|-------+-------+----------------|
| docs | =doc/*=, =assets/*=, =.claude/*=, =*.md=, =*.org=, =LICENSE*= | the site corpus and the agile record |
| modeling | =projects/*/modeling/*= | a component model, which is what codegen reads |
| codegen | =projects/ores.codegen/*=, =projects/ores.http/*= | the generator, its templates and its tests |
| sql | =projects/ores.sql/*=, =projects/ores.seeder/*=, =*.sql= | the schema, its populate scripts and the migrations |
| cpp | =*.cpp=, =*.hpp=, =*.h=, =*.ipp=, =*.c=, =*.cc=, =*.cxx=, =*.cmake=, =CMakeLists.txt=, =CMakePresets.json=, =vcpkg*.json= | compiled sources, headers and the build description |
| services | =projects/*/service/*=, =projects/ores.service/*=, =build/config/*=, =docker/*=, =compose*.yml= | a service, its launcher and what starts it |
| web | =projects/ores.web/*=, =*.ts=, =*.tsx=, =package.json=, =pnpm-lock.yaml=, =.prettierrc.yaml= | the ores.web client and its packages |
| plugins | =projects/ores.dsh_environment/*=, =projects/ores.dsh_kanban/*= | the DSH profile plugins |
| tooling | =projects/ores.compass/*=, =build/scripts/*= | the project's own tools and their checks |
| ci | =.github/*=, =projects/ores.codegen/library/templates/*= | the check configuration itself |

Three rules follow from the table:

1. *A mixed change takes the union.* A model edit that also regenerates
   headers is a =docs= and =modeling= and =cpp= change, and runs the checks of
   all three.
2. *A path no rule claims asks for everything.* A change this table cannot
   classify is a change it cannot vouch for, and the cost of the extra run is
   smaller than the cost of the break it hides.
3. *A model or template change does not by itself compile the tree.* The
   regeneration writes the generated C++ into the tree, so that file appears
   in the diff and the =cpp= class does the build. A model change whose
   regeneration is missing fails =component-drift= first, which is the point.

The classes and the heavy tier:

| Tier | Checks |
|------+--------|
| always | the class's fast checks: =compass lint=, the drift gates, the codegen and compass suites, the per-language checks |
| heavy (=cpp=, =sql=, =services=, unclassified) | =build=, then =db recreate=, then =ctest= |
| sql only, after =db recreate= | =pgtap= |

=pgtap= runs =projects/ores.sql/test/run_tests.sh= over the database the
check above it rebuilt. It stays in the =sql= class alone and stays after
=db=, because it reads the schema that check recreates. Every suite writes
the reference data it reads and rolls it back, so the corpus passes on a
database that carries no tenant data beyond the seed.

A documentation-only change therefore runs =compass site page= and the doc
corpus checks and never reaches the compiler.

* Running it

| Command | What it does |
|---------+--------------|
| =./compass.sh check= | classify the branch diff and run what it needs |
| =./compass.sh check --plan= | print the classes, the checks and the reason for each, without running |
| =./compass.sh check --list= | print the decision tree and the whole catalogue |
| =./compass.sh check --only <id>= | run one check (repeatable) |
| =./compass.sh check --class cpp= | force a class, skipping classification |
| =./compass.sh check --all= | run every check |
| =./compass.sh check --exclude-heavy= | never run build, database or ctest |
| =./compass.sh check --include-heavy= | add the heavy tier to a change that does not need it |
| =./compass.sh check --json= | also write =build/output/local_checks/report.json= |
| =./compass.sh check --base <ref>= | measure against another ref (default =origin/main=) |

Three details matter when reading the report. The change is measured from the
*merge base* with =origin/main=, including uncommitted and untracked files, so
the runner is useful mid-work as well as before a raise, and another author's
merge onto main never reads as this branch's change. The tangle checks
(=tangle-templates=, =tangle-shell=, =tangle-http=) re-run the tangle and then
ask git whether the tree moved: they fail when the committed output is stale,
which is the same contract the retired workflows had. And the drift family
(=component-drift=, =model-drift=, the tangles) compares the regenerated tree
against =HEAD=, so it needs a committed tree — an uncommitted edit to any file
reads as drift. Commit before running the modeling or codegen classes.

* What still runs on GitHub

Nothing on a pull request. Eleven workflows keep their own triggers:

| Workflow | When | Why it stays |
|----------+------+--------------|
| =continuous-linux.yml=, =continuous-macos.yml=, =continuous-windows.yml= | every 2, 3 and 12 hours, and on a tag | the only multi-platform build, and the only Windows and macOS coverage; submits to CDash |
| =nightly-linux.yml= | daily | full build and =ctest= with coverage and memcheck, to CDash |
| =nightly-format.yml= | daily | rewrites formatting drift and opens a fix PR |
| =nightly-includes.yml= | daily | =misc-include-cleaner= fix PR |
| =build-site.yml= and =site-cdash.yml= | every 2 hours and manual | the published site, Doxygen and the CDash site build |
| =codeql-analysis.yml= | manual | security scan, currently disabled |
| =stale.yml= | daily | closes stale issues and pull requests |
| =claude.yml= | an =@claude= comment | the on-demand review |

The thirteen retired triggers were =codegen-drift=, =codegen-sweep=,
=doc-lint=, =dsh-environment=, =dsh-kanban=,
=entity-writes=, =event-registrar-composition=, =header-hygiene=,
=populate-reference-drift=, =rls-system-tenant-widenings=,
=shell-script-drift=, =template-drift= and =typescript=. Each keeps its
=push= to =main= trigger, so a defect that escapes the runner still shows on
main the moment it lands.

=entity-writes= is the cautionary case. It was merged with the trigger the
same evening the other twelve lost theirs, and nothing failed: the workflow
files are read by nothing but GitHub. A guard now fails on the plain trigger,
=build/scripts/check_no_pr_triggers.py=, and the runner runs it under the =ci=
class, so the next one fails locally before it reaches main.
