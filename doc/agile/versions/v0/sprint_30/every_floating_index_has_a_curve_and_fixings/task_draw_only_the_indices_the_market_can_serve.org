* Goal

The planner draws a floating index only from a list of the indices the
market can serve: an index with a curve, or one a stated rule derives. The
list is data, built from the curve configs and the derivation rules, so it
grows when a curve is added and never by hand. A check refuses a population
config that can draw an index outside the list, before a provision does.

* Acceptance

- A cross-currency swap's foreign leg, and every other drawn index, comes
  from the servable list. AOA, BWP, IDR, MYR, OMR, SAR and THB, which have no
  curve, leave the draw.
- The check fails on a population config that can draw an index the list
  does not hold, and names the config and the index.
- The ACCOUK and ACCOUS rates configs book, or each refusal is a named gap.
- On a fresh acme_demo provision, no cross-currency foreign leg names an
  empty fixing address.

* Result

The planner draws an interest rate index only when a curve serves its fixing
address (#4996). The cross-currency foreign legs on AOA, BWP, IDR, MYR, OMR,
SAR and THB left the draw, the ACCOUK and ACCOUS rates configs each book 154
trades, and a fresh acme_demo provision has 0 of 18 IR fixing addresses empty
(=evidence/draw_only_served_indices.txt=).

The second deliverable, the check that refuses a config before provision, is
not built here. Tracing the market data flow showed that the served set is the
wrong base: it covers IR fixings only and every curve in the system, whatever
the party subscribes to. The check moves to [[id:3A2A66B0-C8C1-4EB7-99ED-A3503D79DD66][Plan trades on the expected market data and report them]],
which plans on the market data the party expects and reports each trade type in
the provisioning report instead of refusing.
