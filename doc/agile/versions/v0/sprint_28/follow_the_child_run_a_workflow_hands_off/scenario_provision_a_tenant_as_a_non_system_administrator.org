It is filled in with the target screen and checklist of steps before testing starts; record the outcome by hand in =* Results=.

* Before you start

- The database holds a tenant whose administrator can sign in. The
  cheapest way is a recreated database brought up by =bootstrap setup=,
  which leaves =acme_corporation= and =tenant_admin= in place.
- Select a tenant code not already used in this environment, for example
  =review_scenario=. The command creates the tenant, so a code that
  exists fails before any run starts.
- The shell binary must be the one built from this branch, because the
  behaviour under test lives in the shell.

* Steps

** Log in as the existing tenant's administrator

- Start the shell against this environment and sign in as
  =tenant_admin@acme_corporation= / =Secure-Password-123=.
- The banner must name a tenant other than =Root Tenant=; the system
  tenant is the one case where the child run is readable, so a system
  session does not exercise this scenario.

** Run provision tenant for a new code

- Run =provision tenant --tenant-code review_scenario --tenant-name
  "Review Scenario" --tenant-hostname review_scenario
  --tenant-admin-password Secure-Password-123 --profile
  empty_operational --timeout 900=.
- The progress must show both steps of =provision_tenant_workflow=,
  =system_provision= then =start_tenant_setup=, and only then
  =✓ All 2 step(s) completed.= A command that returns after one step
  has not waited for the run.

** Check the handoff is reported, not followed

- The command must print =The run handed its work to instance <id>,
  which belongs to tenant <uuid>.= followed by a line saying that run
  continues in that tenant and this session cannot read its steps.
- The command must not print a poll failure or abort. The child run is
  healthy; it is simply outside this session's tenant.

** Check the closing message does not claim the tenant is ready

- The closing lines must read =✓ Tenant 'Review Scenario' created; its
  setup continues.= and the sign-in hint must point at the run to
  follow.
- =the tenant is ready to work in= must not appear, because the
  tenant's setup is still running.

** Confirm the child run finishes in its own tenant

- Follow the instance id the command printed, signed in as
  =super_admin= (or as the new tenant's administrator).
- =workflow wait <id>= must reach =✓ All 4 step(s) completed.= The work
  the parent handed on really does finish, so the report is truthful.
