Service wiring: config → dependencies → run loop. =component-service= profile.

A service starts as the stub below, which logs that it is not yet implemented.
A service that has been implemented keeps its code in its own model rather
than in the generated file, through three paste points. Provide each as a
=#+begin_src cpp :name <name> :implements <kind>= block on the service's
=component_overview.org=. A kind that no model implements collapses to
nothing, so the stub still renders for a service that supplies none.

- =<<paste:2A6D90B3-5EA2-48FA-BAC2-472EB4388B6C>>= — extra includes, emitted
  after the standard ones. Block name =service_app_includes=.
- =<<paste:729726C6-96A1-438C-8663-2CF919C72941>>= — namespace-scope
  preamble, emitted after =using namespace ores::logging=. Block name
  =service_app_preamble=.
- =<<paste:2CD994C9-83FF-4C41-8909-5AD2BF3DECCC>>= — the body of =run()=.
  Block name =service_app_run_body=. Supplying it suppresses the stub, so a
  stub and a real body never appear together.

=ores.storage/service= uses all three.

    using ores::database::context_factory;
