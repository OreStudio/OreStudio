* Plan

Five prototypes were drawn in parallel, one per journey, each from the
journey's own entities and their generated protocol headers. They were
then normalised so a reviewer meets the same affordances in all five:
the refusal is the parameter =?fail=<kind>=, =?fail=1= selects the first
kind, and =refused= is a state reachable from the foot bar.

** Gaps the prototypes found

Every one is drawn on the screen and marked as a gap. They are the
material for the implementation tasks.

- Journey 5. No authoritative-identifier flag exists; a counterparty
  carries one business centre rather than the centres it deals through;
  no counterparty-protocol call reads the party-counterparty junction
  from the counterparty side; the confirming act spans eight subjects
  with no composite write and no rollback; and no reply carries a
  field-level diff.
- Journey 6. =party_contact_information= has no primary flag, so "one
  contact is primary" is a client convention; the membership junctions
  have no versions read, so a closed membership leaves no record of when
  or by whom it closed; and a refusal arrives as the trigger's text
  rather than a typed refusal naming the field and the rule.
- Journey 7. The book model and =refdata.v1.books.put= carry neither
  =book_purpose_type= nor =ledger_feed_type=, though both lookup tables
  exist; nothing refuses closing a book with open activity, and no
  status transition rule exists beyond "the code is known".
- Journey 8. The convention list filters by =id_one_of= only, so it
  cannot be searched by a term; history has no draft version, so the
  history step shows a version the server does not hold; and only the
  swap and deposit terms steps are drawn in full, the other 23 families
  naming their entity and stating that their terms step is not drawn.
- Journey 9. No operation resolves a tenor over the wire, so the
  =resolve= step draws the reply it would need; =tenor_convention= has
  no roll-rule column, and the =business_day_convention_type= lookup has
  nothing pointing at it; =tenor_convention_resolutions= is read-only;
  and the refusal is a thrown exception with no message on the wire.

* Result

The five journeys are drawn and written.

Each prototype is a directory of =index.html=, =prototype.css= and
=prototype.js= under =doc/prototypes/=, plain HTML, CSS and JavaScript
with no framework and no backend, driven from the query string and
walkable from the foot bar. Each renders from =file://= with no uncaught

with a field diff. They are listed in =doc/prototypes/index.org=,
published by =projects/ores.lisp/src/ores-build-site.el=, and
=build/scripts/check_prototype_inventory.py= passes.

Each journey is a document under =doc/knowledge/journeys/=, following
the =user_journey= contract: goal, actor and trigger, steps, screens and
wireframes, prototype, entities composed, operations and messages, what
is missing, related journeys, related knowledge. Each has a PlantUML
salt wireframe rendered to PNG beside it and embedded with a caption,
and each carries a coverage table whose subjects were checked against
the generated protocol headers.
