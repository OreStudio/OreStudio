#+title: Story: Fix the deprecated getenv in the build stamp
#+description: The build-stamp change reads ORES_VERSION_MANIFEST with std::getenv. The MSVC STL deprecates it in favour of _dupenv_s, so every Windows job fails under -Werror=deprecated-declarations and all four Nightly Windows configurations are red. The codebase provides an environment provider that wraps this for exactly that reason; use it, and keep the utility component free of raw std::getenv.

* Decisions

- The fix goes through the existing environment provider rather than
  defining =_CRT_SECURE_NO_WARNINGS=. The provider exists for this reason
  and says so in its own header, so suppressing the warning here would
  leave the next caller to trip over it.
- The manifest variable is read as an =optional<string>=, so the emptiness
  check moves with the type.
- The project has hit this exact deprecation before, in the compute
  commands, so the rule is not new: read the environment through the
  provider, never with =std::getenv=.
