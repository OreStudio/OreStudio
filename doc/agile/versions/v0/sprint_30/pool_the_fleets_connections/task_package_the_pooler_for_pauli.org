* Goal

pauli runs the pooler as a podman container beside the fleet, pulled from the
same registry as the services, and every service on pauli reaches PostgreSQL
through it. A deploy of pauli starts the pooler before the services that need it
and reports it like any other container.

* Acceptance

- A =pgbouncer= image is built from a Dockerfile in =docker/=, on the smallest
  base that carries it (Alpine, whose package is 1.24 or later and past the
  prepared-statement floor), and published to the registry under the same tagging
  scheme as the service images: =0.0.30-<commit>= and =main=.
- Its configuration is generated from the environment, the same file the unit
  would use, mounted read-only into the container.
- =compass env deploy pauli= deploys the pooler with the fleet, ordered before the
  services, and its report names it as it names nats and the services.
- The services on pauli connect to the pooler; the listener and the
  administrative paths do not.
- pauli's =pg_stat_activity= shows the fleet arriving from the pooler, and the
  count of server connections settling to the cap.
- A deploy that finds the pooler image missing stops before it stops anything, as
  the service images already do.
- The deployment recipe records the pooler beside nats, so a person bringing up a
  host knows it exists and why.

* Plan

=env_deploy.py= already deploys three kinds of container - the fleet's
service-runtime images, =localhost/ores-nats=, and the compute and web images -
and marks them (=IMAGE_NATS= at line 68, the NATS configuration staged from
=build/config/nats-<label>.conf=, the ordering at lines 378-393). The pooler is a
fourth: an =IMAGE_PGBOUNCER=, its configuration staged beside NATS's, and the same
start ordering and missing-image guard.

The image follows =docker/nats.Dockerfile= in intent and not in base: NATS is a
static Go binary and gets =scratch=, while =pgbouncer= links libevent, OpenSSL and
c-ares, so the smallest honest base is =alpine:3.22= with =apk add
--no-install-recommends pgbouncer=, about 410 KiB installed. Nothing of ours is
linked into it, so musl is safe.

The recipe to update is the deployment runbook for the remote host
(=doc/recipes/compass/how-do-i-deploy-the-service-runtime-to-a-remote-wsl-host.org=),
which lists what a deploy starts.
