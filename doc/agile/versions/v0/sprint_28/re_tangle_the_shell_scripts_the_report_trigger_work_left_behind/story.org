* Decisions

- *Regenerate, do not hand-edit.* The three stale scripts carry the generated
  header, so the repair is the tangle that the header names, and nothing else.
  Only thirteen files changed content: three of the 3740 regenerated scripts,
  plus ten new ones.
- *The regenerated placeholder is the correct one.* The stale scripts wrote =0=
  for =trigger_id=, and the model types that column as a uuid
  (projects/ores.reporting/modeling/ores.reporting.report_instance.org line 356,
  and =boost::uuids::uuid trigger_id= in the generated domain header). Every
  other uuid parameter in the same scripts already rendered as the empty uuid,
  so the committed =0= was the outlier.

* Out of scope

- The recipe and the model themselves. This story only re-syncs the tangled
  output with the recipes that main already carries.
