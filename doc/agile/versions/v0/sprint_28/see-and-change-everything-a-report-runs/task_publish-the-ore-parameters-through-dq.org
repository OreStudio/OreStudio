* Result

The ORE parameters (610 rows) and their value domains (5 rows) are two DQ datasets. One generator writes them. Two publish functions write them into the system tenant through system_core and into each tenant through base. The four direct populate scripts are gone. After a provisioning of Acme, the system tenant and the Acme tenant each hold 610 parameters, and the engine settings screens read the documentation of all 15 settings.

The tests that need an ore parameter seed five of their own and no longer read the real data. The double bundle membership is a stopgap, and the capture "One source for reference data that the system and each tenant read" tracks the choice of one source.
