* Goal

A class is a descriptor and a module behind it, so the emitter, the batch runner and the page are
written once. A second class is a descriptor, a module and its note, and nothing else changes.

* Acceptance

- A derivation kind is a descriptor and a module. The descriptor states the method and its version, the transform, the coordinates a quote is named by, the smile model, the projection and the method note.
- The emitter, the batch runner and the page take the descriptor and never branch on the asset class. A class with no descriptor cannot be derived, and the refusal names the piece it lacks.
- The FX derivation and the interest rate derivation both register a descriptor, and neither is special-cased in the runner, the emitter or the page.
- Adding a class is a descriptor and a module, and the task measures the pattern with two numbers: the files outside the class's own module that name it, and the places that branch on it. Both are counted before and after, and neither grows with the class.
- The pattern does not pretend the methodology is shared: each module keeps its own projection and its own smile, and the descriptor only says which they are.

* Plan

The pattern is cut as data first, because the parts that differ by class are stated, not computed:
the code and version a stored value carries, the method identifier, the asset class, the transform,
the datum fields that name a quote, and the smile model. =vol_derivation_kind= in
=ores.analytics.quant= holds that row and the table of the kinds the platform derives, and nothing
else: no arithmetic, no store, no feed. A caller that reads a stored value asks the table what made
it, which is the branch the pattern removes.

The two modules keep their own maths. FX measures a pair's spot on its logarithm and fits a smile in
delta; interest rates measure a term's rate on its change and fit a smile in strike. The descriptor
says which of those a kind states, and the modules are unchanged by the declaration.

The FX derived source carried its own copy of its code and its version, and a method identifier as a
literal. It now reads all three from the descriptor, and the identifier is unchanged, so the series
it has already stamped stay readable.

* Notes

- The method identifier is fixed for the life of a kind. Changing it would make an old value
  unreadable, so it is stated rather than computed, and a test pins the FX one to the value the
  stored series already carry.
- The table is a plain array and its lookup is a walk over two rows. It is read at start and at a
  publish, not in a loop, so a map would be a cost with no reader.
- The remainders: SQL stamps the method on a published series and carries its own copy of the FX
  identity (=marketdata_surface_series_create.sql=), so the pattern reaches C++ and not yet SQL. The
  emitter, the batch runner and the page do not exist yet; each takes the descriptor when it is
  written, and the task that writes them is where the pattern is proven.
- The count of places that name a class outside its module is now one C++ file. The two SQL copies
  are the gap, and they belong to the task that writes the publisher.

- The lift merged as =f306a1152c= cut the engine where the class stops being named, with three parameters: the transform, the coordinates and the smile model. This task makes those three a declared shape rather than a convention each caller keeps.
- The stored method and version already exist as an identity for a series; the descriptor is where the emitter reads them, so the two cannot disagree.
- The FX derivation is the first descriptor to write, because it exists and its tests pin its numbers. A pattern with one implementation behind it is a guess, so the interest rate descriptor is written in the same task and the pattern is stated only when both fit.

* Result

Committed at =3f69ea0496=. A derivation kind is one row, both classes declare one, a kind is found by
the code a stored value states, and the FX source reads its identity from the declaration instead of
keeping a copy.

What the pattern still owes, and to which task: the emitter and the batch runner take the descriptor
when they are written, and SQL's copy of the FX identity is removed when the publisher is reworked.
The pattern is not declared proven until a second class reaches a stored quote through it.
