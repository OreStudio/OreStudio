* Goal

An entity that sets :has_as_of_lookup: answers a list request carrying as_of with the rows whose validity window holds that instant, paged and counted on the same predicate, and with the current rows when as_of is absent.

* Acceptance

- The generated handler, service and repository carry the list request's as_of through to the query.
- With as_of, the list and its total use valid_from <= as_of < valid_to; without it, the current rows as today.
- The four refdata entities that set the flag honour it, and a test proves a past instant returns the old version of a row.
- Every entity with a validity window offers the read by default; scheduler and synthetic, whose generated files drift too far to merge, get it when their clean-up regenerates them.
- Codegen drift is clean for every component the change regenerates.

* Plan

Decided with the owner on 2026-10-06: every entity offers the point-in-time
read, not only those that ask, and the change must not drag any component's
unrelated drift along.

1. =ores.database/repository/valid_at.hpp=: the run-time window condition. With
   an instant, =valid_from <= t AND valid_to > t=; without one,
   =valid_to = infinity=. It is its own header, so only the repositories that
   use it recompile.
2. Codegen: =:has_as_of_lookup:= defaults to on, turned off only by a model that
   says so, and by the existing guard for a current-state table. The paged read
   and the count of such an entity leave the window out of their typed
   =where()= and take =valid_at(as_of)=, narrowed by the filter, as their
   run-time condition. The generated service parses =as_of= and refuses one that
   is not a UTC timestamp with =as_of_invalid=.
3. Apply the change to the generated files by a three-way merge, with the
   render before the change as the base: =evidence/apply_codegen_change_by_merge.py=.
   A file that drifts keeps its drift and gains only the change.
4. The web clients state =as_of= on the list requests they build, since the
   TypeScript twin types it as a required string or null.

* Notes

** Why a merge rather than a regeneration

79 generated files outside the registry already drift from their templates.
Regenerating them would bring that drift along: one scheduler service would
call repository functions its header does not declare yet. The merge script
renders the catalogue twice, before and after the change, and applies only the
difference to each checked-in file. All 40 conflicts were in =ores.scheduler=
and =ores.synthetic=, the two components whose generated files predate the
ordering and filter templates, so both are left out; their sprint 27 clean-up
stories regenerate them, and the default gives them =as_of= then.

** The rounding the test run found

The first full test run failed the new currency case: a list at an instant
between two versions returned nothing. The service had rewritten =as_of=
through =to_iso8601_utc=, which writes whole seconds, so an instant at 08.6s
became 08.0s, before the first version began. The test only caught it because
the two versions lived about 100 ms apart; it now writes its instants to the
microsecond. =parse_as_of= in =valid_at.hpp= checks the text against the UTC
timestamp form, a fraction allowed, proves the date and time exist, and returns
the text as the caller wrote it. Text after the time, which the platform parser
silently ignored, is refused.

The same run failed =ores.scheduler.api.tests=. Nothing in this change reaches
scheduler; main's =vcpkg= update of 2026-10-05 lets =croncpp= accept the
expression the test expects refused, recorded as
[[id:C92DB57D-B4CC-4D50-8BC1-4AE3B630792E][Cron expression accepts six fields after the vcpkg update]].

** The web side

The TypeScript twin types =as_of= as a required =string | null=, so thirteen
hand-built list requests and request schemas in =wire-protocol=, and one in the
BFF, now state it as =null=, the current rows, as the four refdata entities'
callers already did. The per-resource =asOf= flags in =records.ts= and
=classifications.ts= still decide whether the generic list sends the field; a
list without it is answered with the current rows, so they are not wrong, but
every resource could now set them.

* Result

Every entity with a validity window offers the point-in-time read: its list
request takes =as_of=, and the list and its total answer with the rows valid
then, or the current rows without it. A malformed instant is refused, and a
fraction of a second is kept. The change reached 1,624 generated files by a
three-way merge, so no component's other drift came with it; scheduler and
synthetic get it when their clean-up regenerates them.
