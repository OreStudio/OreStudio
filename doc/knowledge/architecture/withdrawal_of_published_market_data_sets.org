#+title: Withdrawal of published market data sets
#+description: Taking a published set out of use is a four-eyes act with its own approval kind, applied by the trader, recorded with its reason and told to readers.
#+type: knowledge
#+level: cross
#+filetags: :architecture:marketdata:publish:approval:
#+created: 2026-11-11

* Summary

A published set that is wrong is taken out of use by a withdrawal: a request of the kind's withdrawal kind, raised with a reason, decided under four-eyes, and applied by the trader. Any published set that is not withdrawn can be withdrawn, live or superseded. The apply marks the set withdrawn, keeps the reason against it, and writes the notice. From then on no read by as-of takes it, and the series' live set is the newest published set that remains.

** The act

The withdrawal follows the publish's shape. The trader raises it naming the published set and a reason. It is refused if the set is already withdrawn or a withdrawal of it is open. A person decides it, or a stated rule closes it ([[id:71146F3F-B884-4E61-BA8B-A8A0731703C6][Rules for the automatic approval of requests]]), in which case the apply runs in the raise's transaction. Otherwise the trader applies it within the kind's apply window: the apply checks that the request is approved and the set not yet withdrawn, then marks it withdrawn and writes the notice in one transaction.

** What a read takes afterwards

A read by as-of skips a withdrawn set and takes the newest remaining published set at or before the as-of ([[id:86158AAD-423A-421A-8BE2-CC5123109297][As-of resolution of published market data sets]]). Withdrawing the live set therefore makes the set it had superseded the series' live set again; withdrawing a superseded set changes the reads of the as-ofs it covered. If no published set remains, a read refuses.

** What it leaves behind

A run that bound the set before the withdrawal names it by its publish record ([[id:FB8F701C-E56A-49A9-AA90-1B6BD0B02092][Binding reports to published curves]]), so a repeat of that run reads the same set and shows that it was withdrawn since. A cut that holds the set keeps it, for the same reason ([[id:DD59B04C-DAD2-458C-B35E-3F6B0B3D6DC6][Market data cut]]). Sets derived from a withdrawn set, such as a forward set built from a withdrawn curve, are not changed; their reads show the state of every input ([[id:AB7A0BE5-7EB8-5B44-B98D-05E0CD58E51D][Derivation of FX forwards from published curves]]). A candidate computed from it cannot be published ([[id:24950B8E-7FC4-4F0A-8AA4-9603B344F970][Candidate computation and storage before publication]]).

** Withdraw or replace

A correction is a new publish at the same or a newer as-of, which supersedes the wrong set ([[id:86D8986F-5247-4138-85C7-F8899C029F24][The trader applies an approved publish, which supersedes the live set and tells its readers]]). A withdrawal is for a set that must not be used at all. The two are distinct acts with distinct approval kinds, as [[id:B05A31CC-FA22-4534-848E-601A30822992][Withdraw or replace a published curve]] describes.

** What a kind must supply

A withdrawal is part of a kind's declaration and not a capability the lifecycle
adds by itself ([[id:186B44DD-51EA-45AA-971E-0C2D4D21A6DD][The publication lifecycle of derived market objects]]). A kind
that may be withdrawn supplies three things: the approval kind, with its raise
permission, its decide permission, its auto-approval code and its count; the
columns on the publish record that say who withdrew the set, when and why; and
the notice kind its readers are told with
([[id:B3F03DBB-EBD1-4649-94E5-6C5C1B67A084][Notification of a change to a published market data set]]).

A kind without those three parts has no withdrawal, whatever the lifecycle
permits in principle. Of the three kinds in the tree, only the IR curve supplies
all three today.
