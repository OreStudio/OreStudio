* Goal

Make =compass_claude._has_user_systemd()= answer whether =systemd-run= can
start a scope, so =compass build= and =compass claude= fall back to running
unscoped when the busctl transport is the only way to reach the manager.

* Acceptance

- =_has_user_systemd()= returns False when =systemctl_bus.use_busctl()= is
  True, whatever the probe would have answered.
- =compass build= prints =cmake --build --preset ... --target ...= with no
  =systemd-run= prefix under =ORES_USE_BUSCTL=1=.
- =test_compass_transport.py= covers the busctl case, a reachable manager,
  an unreachable manager and a missing =systemd-run= binary.

* Plan

Diagnosis. =compass build= (=compass.py:7141=) and =compass claude= wrap
their command in =systemd-run --user --scope= when
=compass_claude._has_user_systemd()= is true. That function probes through
=systemctl_bus.run(["show-environment"])=, which honours =ORES_USE_BUSCTL=1=
and goes over the D-Bus session bus. Inside a sandbox the probe succeeds,
but =systemd-run= opens the manager's private socket and is refused at
authentication, so the wrapped command cannot start. Measured here:
=use_busctl()= True, =_has_user_systemd()= True, =systemd-run= "Failed to
connect to user scope bus".

Fix. Return False from =_has_user_systemd()= when the busctl transport is
selected, before the probe. The transport is selected precisely because the
sd-bus client path is refused, and =systemd-run= is an sd-bus client, so no
scope can start. Both callers already have an unscoped fallback.

* Notes

- Measured before the fix: =use_busctl()= True, =_has_user_systemd()= True,
  and =systemd-run --user --scope ... true= failed with "Failed to connect
  to user scope bus via local transport: No data available".
- The probe in =_has_user_systemd()= uses =systemctl_bus.run= and so honours
  the transport; =systemd-run= does not, which is the whole defect.
- A real =compass build ores.nats.lib= after the fix printed the bare cmake
  command and exited 0, while the fleet stayed at 25/25 running.

* Result

The scope probe answers for =systemd-run=, the tool the callers run. Under
the busctl transport it reports no scope, so a sandboxed =compass build= and
=compass claude= take their existing unscoped path. The transport tests pin
all four cases.
