* Summary

The reports a party runs, what each produced, what went wrong, and when the next
one starts. Seven journeys describe that work, and there is no reporting surface
in the application at all today, so nothing here has prior art to copy.

16 prototypes answer to this group: one per journey, one that two of them hand
the analytics to, one that reads a report with its scope, analytics, conventions and history on tabs, and five for the pricing engines. Each is a static page under =doc/prototypes/=, opens with
no build and no session, and reads mock data only. The table below opens each one
and says what it argues. Where a prototype carries a Gemini review, the last
column opens it.

The conventions have no prototype of their own. They are named convention sets,
and the report chooses one: Create a report and Change what a report runs each
carry that choice on one page. Authoring a set is its own UX, addressed outside
this work, and the prototype that used to argue a per-kind interaction inside the
reporting group has been retired.

[[file:../index.org][Prototypes]] is the top page and the only inventory.

* One decision, an axis for each journey

The journeys are not a screen plan. Reading them one to one would give nine
screens for one job, and nobody would build it that way.

The decision this set exists to inform is what the reporting surface is, and how
many screens own it. Each prototype offers three structural variants of its own
journey, and each turns on the question that journey actually poses rather than
one frame forced onto all nine. Forcing a single axis was tried first and it
broke down: the question a catalogue asks is not the question a result asks.

What is shared is the method. Three variants, one switcher, the same chrome, and
the same rule that the variants disagree about structure and not colour.

#+ATTR_HTML: :class hug-leading
| Prototype | The axis its three variants turn on |
|-----------+-------------------------------------|
| See the reports a party runs | What the front door is: the catalogue of reports, a ledger of runs, or only what needs a human. |
| Run a report and watch it finish | Where waiting happens: a strip that reports itself while you work, a dedicated view you stay in, or a queue you watch together. |
| Read what a run produced | What the result is: the numbers and the trade rows under them, the archive of files, or a sentence about the numbers. |
| See a report's results by counterparty | How a result is read by counterparty: a ranked list of names, a tree through the group each one nests under, or a map of how concentrated the run is. |
| Find out why a run went wrong | Whether errors are a place you go, a panel beside the run, or a ledger across runs. |
| Choose when a report runs | Where scheduling lives: on the report, in a schedule list, or on a calendar. |

The prototypes are not meant to be read as one design with nine parts. They are
nine answers to nine different questions, drawn in one voice so that the
answers can be compared.

* What none of them settle

Whether the seven journeys become one area, one screen, or two. That is the
decision this set exists to inform, and it is taken after the review rather than
here. Each prototype argues one journey; the area they share is drawn only far
enough to judge the journey inside it.

Two things are settled. Analytic management has one screen: Create a report and
Change what a report runs used to draw the same switchboard, the same parameters
and the same incompatibility state, in two vocabularies for the same three
states — on, off, and a type with no row. Both now read the set and link to
Manage the analytics, which owns it.

And the conventions are chosen, not assembled. A convention set carries a name, a
purpose and a description, a system holds few of them, and a report binds one by
choosing it. Authoring a set is its own UX, deferred to its own work, so no
prototype here draws a per-kind table, an alternative per kind, a provenance card
or a migration state.

* Adding a prototype

Follow [[file:../index.org][Prototypes]], which has the one way. A prototype here
is a static page, never a route in =ores.web=, and it carries a design note at
=doc/prototypes/reporting/<name>.org= that this page links.
