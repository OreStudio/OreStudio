This page defines the [[id:68FAC606-569C-4B9B-932B-3B3A0181AC8B][service architecture pattern]]
Database per Service in the [[id:EA249899-6611-407F-A43A-B37019EBD1A7][pattern language]].
Each service owns its data, and other services reach it only through the owner's
operations. In ORE Studio components share one PostgreSQL instance, and still no
service reads or writes another component's tables.

* Also known as

- /Private data per service/.

* Context

Services are deployed separately and owned separately. The deployment happens to
put their tables in one database.

* Problem

Where does a service's data live, and how does another service read it?

* Forces

- A direct read is one query and no round trip.
- A direct read skips the owner's authorisation and couples two schemas.
- Owners must be free to change their tables.
- Some reads span owners.

* Solution

Each service owns its tables and serves them through operations on the bus. Any
other service reads and writes them only through those operations, with the
identity the call needs, and RLS applies as for any caller. A read that spans
owners calls each owner, or a composer calls them and joins the answers.

* Failure handling

#+ATTR_HTML: :class hug-leading
| Concern | What the pattern does |
|---------+-----------------------|
| Errors | An owner's refusal reaches the caller as an error, not as missing rows. |
| Timeouts | Each owner call has its own timeout. |
| Retries | Reads are safe to retry. |
| Idempotency | Writes across owners need a [[id:E8DAA8F6-9A41-44A7-A79C-58F7FDB5ADB2][Saga]]. |
| Observability | Each owner logs the read it served. |

* Pitfalls

- *A shortcut through a shared connection.* It compiles and returns rows, with no authorisation and no contract.
- *An owner linked as a library.* Linking another component's core library is the same shortcut in code.
- *Many small calls.* A per-row read across owners is slow; owners offer bulk reads.

* Security

The owner's handler authorises every read, and RLS applies with the caller's
tenant and party. A direct read would bypass both.

* Resulting context

- Benefits :: Owners change their tables freely, and access control applies everywhere.
- Liabilities :: Round trips, and cross-owner reads need composition.
