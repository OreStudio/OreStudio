* Summary

ores.shell has commands for scripted trades in its trading part. The commands
that only read a script's text, parse it, print its inputs, print it normalised,
link the parser ([[id:8FD7BD95-AAEC-4CF9-A9F4-D609A9DEFBD8][ORE's grammar is the one authority on whether a script parses]]) and run in the shell with no session, so a
person can check a script before they log in or with no server running. The
commands that read the store, describe a product, validate against a library
version, book, go to the trading service like every other command and need a
login.

* Detail

| Command | Needs a login | Does |
|---------+---------------+------|
| =script parse <file>= | no | parses with ORE's grammar; prints the error with its line and column |
| =script inputs <file>= | no | prints the free variables with type, array and rule ([[id:92449D70-09E2-4391-B716-A1001F22B271][A script's free variables are its inputs]]) |
| =script print <file>= | no | prints the script normalised |
| =script validate <file> <variables>= | yes | runs the server's validation against the store ([[id:C2A45123-A9B3-49BA-BEFD-07E1703F7B84][A scripted trade is validated in three layers]]) |
| =product describe <code>= | yes | prints the product's schema ([[id:290A1069-A1EE-4DD1-8D23-1C60F76F8949][Every product has a schema of its fields and its forms]]) |
| =trade book ...= | yes | books through the booking API ([[id:3085E65E-413B-4E7A-B60A-5844A124C999][One booking API books a product in either form]]) |

The commands live in =ores.shell.trading=, the part that projects
=ores.trading= ([[id:D0876A24-69BA-F484-ED9B-71CD3AA8710C][ores.shell]]).

** Where today's code differs

ores.shell has no command for scripts or products, and every command needs a
session.
