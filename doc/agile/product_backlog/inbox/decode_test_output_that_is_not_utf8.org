#+title: compass test run crashes on test output that is not UTF-8
#+description: compass test run reads the test process's output as UTF-8 in _run_logged and stops with UnicodeDecodeError ('utf-8' codec can't decode byte 0xa1) when a Catch2 failure expands a uuid as raw bytes. The run's results XML is written, but the summary and the failure detail are lost. Seen on 2026-11-03 with a failing uuid comparison in ores.ore.core.tests. Decoding with errors='replace' would keep the run readable.

* What

=compass test run= reads the test process's output as UTF-8 in =_run_logged=,
at =projects/ores.compass/src/compass.py= line 7286. When a Catch2 failure
expands a =boost::uuids::uuid=, the expansion holds raw bytes, and the read stops
with =UnicodeDecodeError: 'utf-8' codec can't decode byte 0xa1=.

* Why

The test binary still writes its results XML, so nothing is lost on disk. But
the command exits with a Python traceback and not with the test summary, and the
reader has to go to the XML to find out which assertion failed. The crash happens
exactly when a test fails, which is when the output matters. Decoding with
=errors='replace'= keeps the run readable.
