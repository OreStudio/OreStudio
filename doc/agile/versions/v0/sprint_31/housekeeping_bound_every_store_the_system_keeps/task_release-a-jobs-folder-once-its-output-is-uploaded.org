* Goal

A compute node deletes a job's working folder as soon as its output and log are uploaded, so the node keeps only the folders of jobs that failed before upload.

* Acceptance

- The job folder is removed on the success path, after the output and the log have been uploaded
- A job that fails before its upload keeps its folder, which is then the only evidence of the failure
- The removal is recorded in the log, so a later reader can tell that it happened and why the folder is gone
- A measured run shows a node's job directory stops growing with the number of completed jobs

* Result
- Measured after provisioning Acme and letting its reports run for an hour: the
  five nodes hold 565 job folders and 1903 MB, 3.4 MB per completed job. Only 39
  of those folders name a result the store still holds, because the database was
  recreated under the older 526, so a folder also outlives the result it belongs
  to. Releasing the folder on the success path bounds the first number; the age
  policy has to bound the second.
A compute node releases a job's folder once the job's result is submitted, and
the log states what it freed. A job that failed keeps its folder.

- The wrapper removes =<work-dir>/jobs/<result-id>= after =submit_result=, and
  only when the run succeeded: a failed run's folder is the only account on
  that node of why it stopped, and the story's decision leaves those to the age
  policy.
- =app/job_scratch.hpp= does the removal and states the bytes it freed, so the
  decision is one call and the number is the log's, not a guess. A folder that
  is already gone is the end state asked for, and a folder that cannot be
  removed is reported as staying.
- Measured on the live fleet after a fresh provisioning: three completed jobs
  released 3.8 MB each, with the log line
  =Released the folder of job <id>, 3842446 byte(s), once its output was
  uploaded=, and the folder count under the five wrappers stayed at 675 while
  the workunits went from 149 to 152. Before the change the same fleet added
  110 folders in an hour.

What the change does not do: the folders already on disk stay, including 526
the earlier runs left behind (1,903 MB in all). Removing those is the age
policy the story already decided on, and it needs the sweep to learn a
directory target; deleting them blind would delete the evidence of the runs a
person is still reading.
