* Goal

Move the checks in the web's =check()= to the write path, so a client cannot
save what the dialog refuses and every client gets the same answer. The errors
move; the warnings and information findings stay on the screen and do not block
a save.

* Acceptance

- The analytics handler refuses a pricing engines document that breaks a rule,
  before it writes a row, and reports every problem it found.
- Each problem carries a code from ={name_missing, no_products, model_missing,
  engine_missing, parameter_repeated, parameter_value_missing}=, the product id
  when it is about a product, the setting's scope and name when it is about a
  parameter, and a short message.
- The save response carries the problems beside =success= and =message=, and
  the message counts them.
- The BFF answers a refused save with 400 and the problems in the body. A
  version conflict stays 409 and a permission refusal stays 403.
- The web dialog names the problems in a person's words, one line each.
- The warnings and information findings of =check()= stay on the screen.

* Plan

The protocol is generated from
[[proj:projects/ores.analytics/modeling/ores.analytics.configuration_document_messages.org][the operation model]], so the problem struct and the field on the save response
were added there and the C++ and TypeScript protocols regenerated.

The rules live in one pure function,
=ores::analytics::validation::problems_of=, which the pricing engines save
calls before it hands the document to the service. The handler also serves
today's market documents, and each kind has its own subject and its own save,
so only the pricing engines save is validated.

The BFF turns the problems into =invalidRequest= details, and the web turns
them back into the findings =check()= produces, so one set of translated words
says the same problem whichever side found it.

* Result

A document with a product that names no model is refused through the BFF with
400 and ={"code":"invalid-request","message":"The document has 1 problem.","problems":[{"code":"model_missing","productId":"...","message":"The Swap product has no model."}]}=.
A document whose product states the same setting twice and leaves its value
empty is refused with 400 and two problems, =parameter_repeated= and
=parameter_value_missing=, each naming the product, the scope and the setting.
A valid document creates with 201 and amends with 200. A refused save writes no
configuration header and no pricing row.
