* What

An =ores.shell= command, =marketdata flow --by series --at <time>=, that counts
the stored ticks of one window by source, party and series from
=ores_marketdata_ticks_tbl=, with =time_bucket=. It answers the follow-up
question once the funnel shows a stage that is off: which series.

TimescaleDB runs the Apache edition here, which has no continuous aggregates,
so each query scans raw rows. The command therefore reads one bounded window
and is not the per-minute view; the funnel samples are.

* Why

On 2026-10-26 the machine went down overnight. Two defects together caused it: the shared Hawkes heat ran the synthetic feeds at about 300 times their configured rate, and the NATS client kept every message it received. Finding both took ad hoc sampling of systemd and /proc, parsing marketdata's once-a-minute INGEST STATUS log line, NATS monitoring endpoints, Postgres row counts and a core dump. The stored table is the ground truth for what was written, and it
already carries the tenant, the party, the series and the source of each row.
At the runaway rate it took about 41 million rows an hour, so a query must be
narrow.
