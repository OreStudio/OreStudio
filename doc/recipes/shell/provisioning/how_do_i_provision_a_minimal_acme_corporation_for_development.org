#+title: How do I provision a minimal Acme Corporation for development?

The =acme_minimal= starting point is a smaller form of the demonstration
in [[id:45B89A49-B2B8-4C1C-9BB7-09EB27E4D50C][How do I provision the system with Acme Corporation (holding group)?]].
It makes the same tenant and the same tenant administrator, so the scripts
that log in as =tenant_admin@acme_corporation= work against both.

* Question

How do I provision only the Acme Corporation data that an ORE import and
export needs, so a development loop does not wait for the full
demonstration?

* Answer

Bootstrap =super_admin= and install the =Acme Corporation= tenant from the
=acme_minimal= starting point. Its steps publish the base bundle and the
ORE counterparty aliases, import the Acme LEI hierarchy, provision the
party, and load the group party's bundle, which holds its portfolios and
books, together with the ORE sample counterparties.

It does not load the subsidiaries' staff, set the staff passwords, attach
photographs, subscribe to market data, schedule reports or generate the
synthetic trade population. It does not publish the ORE engine packages,
so a compute job cannot run against this tenant. Use the full
demonstration for that.

Expectations: the services are up (=compass services start=) and the
database is fresh (=compass db recreate -y -k=, which leaves it in
bootstrap mode).

#+name: acme-corporation-minimal-provision
#+begin_src ores-shell :exports none
connect $ORES_NATS_URL

bootstrap setup super_admin Secure-Password-123 super_admin@localhost.com --tenant-admin-password Secure-Password-123 --tenant-code acme_corporation --tenant-name "Acme Corporation" --tenant-hostname acme_corporation --profile acme_minimal
logout

exit
#+end_src

#+begin_src sh :noweb yes :results output :wrap example
./ores.shell ${log_args} ${connect_args} << 'EOF'
<<acme-corporation-minimal-provision>>
EOF
#+end_src
