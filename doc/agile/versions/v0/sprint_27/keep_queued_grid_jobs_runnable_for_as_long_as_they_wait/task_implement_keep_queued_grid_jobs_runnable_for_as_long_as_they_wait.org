* Goal

A job that waits in the grid queue for any length of time still runs when a node takes it, and the queue is bounded and visible, so a burst of work slows the grid and never fails it.

* Acceptance

- A job that waited longer than the storage token lifetime runs to success when a node takes it.
- The queue has a stated bound and a stated rule for what happens to a job that waits past it.
- A person sees how long the oldest job has waited and how many wait, per tenant for the operator.
- A restart or a recreate of the database does not leave assignments that fail on replay.

* Plan

The six tasks of the story did the work. This task records that each acceptance point holds and closes the story.

| Acceptance point | Where it holds |
|------------------+----------------|
| A job that waited longer than the token lifetime runs | The claim mints the storage token when a node takes the job, so the token is fresh. A node also skips an assignment whose token has ended. |
| The queue has a bound and a rule for a job past it | 3600 waiting jobs for each tenant, checked at dispatch. A job that loses its lease three times ends as no reply with a message. |
| A person sees the oldest wait and the count | The Usage tab shows the waiting count and the oldest wait for each tenant (operator) or party (tenant administrator), and warns from the age. |
| A restart or a recreate leaves no failing assignments | No assignment exists. The queue is a table, and the claim reads it. The stream is not created. |

* Result

The story is complete. A job now waits in a table, a free node claims it and gets a fresh storage token, a lost node loses its lease and the job goes back, and a person sees how long the oldest job has waited. The PRs that carry the evidence: #3184 for the late assignment, #3198 for the ledger and the claim, #3199 for the wrapper, #3201 for the lease reaper and the bound, #3202 for the oldest wait, and #3203 for the stream removal. The follow-ups are the stale-host reaper and its scheduled job (an inbox capture), a generated table for an installation-owned current state (an inbox capture), naming the waiting group in the age warning, making the tenant limit an option, and redeploying Newton and the laptop with the new wrapper image. A node that still runs the old wrapper takes no work after the cut-over, because nothing publishes to the stream it reads. It stays idle and fails no job.
