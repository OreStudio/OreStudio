* Notes

- *A run that reaches its end did not save.* A tester walked the scenario to the
  last step and pressed Save and nothing reached the doc: the server log showed
  the step screenshots arriving and no `PUT .../run` at all. Whether the click was
  missed or the button was disabled at that moment, the design was the defect: a
  run of nine steps is nine steps of work, and it was kept only if somebody
  pressed one button at the end.
- *The fix is that a run saves as it goes.* Marking a step, or skipping it, owes a
  save; the save waits 800 ms after the last move, so a quick walk sends one save
  at the end rather than nine, and a mark is never dropped while the save of the
  step before it is in flight. An image still uploading holds it back further,
  because the file's link reaches its step when the upload ends. The Save button
  stays, for a note written without moving on, and its help says what it now does.
- *Proven in a browser with nothing pressed at the end.* The run was walked from a
  pending scenario with a screenshot attached and no click on Save: the log shows
  one `PUT .../run` after the last mark, and the doc came away with nine PASS
  steps, an overall PASSED and the image link in step 1's note.
- *What the run does not do.* It does not save the note as it is typed, so a note
  written on the step on show is kept when the tester moves on or presses Save.


- *The elements a curve can also hold were one confusing line.* The tester's note on
  step 5 of the scenario, verbatim: "'Held as its own element:; Report; not stated;
  BootstrapConfig; not recorded here' this is extremely confusing to users." Three
  things were wrong with it: the label spoke about elements in the abstract, the
  words *not stated* and *not recorded here* named two different facts in one run,
  and a tag beside a word is read as a fragment rather than a sentence. It is now a
  card, *Other elements it can hold*, one element to a line, each with its own
  state on the right: *set*, *not set*, and *this screen cannot read it yet* for a
  column the projection does not read.

* The snags the first browser walk left

The walk that produced the evidence on
[[id:2543D83D-C11E-46F8-954D-F8B88E29BC45][Draw the quotes a curve segment holds]]
was taken with a script, not by hand, and it met these:

- *A segment leaf prints its ORE name.* =Conventions= drew with no label and
  counted as a gap because the contract held no =Segments/\{Kind\}/Conventions=
  row. The cause was exact: the leaf is read by =YieldCurveSegment::fromXML=, the
  segment base class, and the extractor kept a class's base only when the class
  was declared in the file it was defined in. Six shared leaves were lost for all
  twelve kinds. Fixed by [[id:3D1208F2-1D51-4733-81FB-01B19D36E8EE][Record the leaves a segment inherits]]:
  the walk on 2026-10-30 reads =Conventions= with its value and the page counts
  *238 of 238 parameters carry documentation*.
- *The curve's header counts only the curve's own parameters.* =GBP1D= reads *10
  parameters* while the page reads *238 of 238*: the segment's leaves are in the
  page's count and not in the curve's tag. A person reading the tag alone sees a
  smaller curve than the page holds. Still open.
- *The instant a row was recorded was drawn as a leaf.* Found and fixed on the
  quotes branch; the scenario confirms it is gone.
- *Two 401s appear in the console* while the shell settles before the party is
  chosen. They are the shell probing an endpoint it may not read yet, not a
  screen failing, and the walk continues. Recorded so the next person does not
  chase them.

What the walk could not judge, and the scenario asks a person to: whether a
segment's card reads as one element rather than a bag of settings, whether the
quote list is scannable at twelve rows and at three hundred, and whether the
documentation under a segment leaf is as easy to open as under a curve's own.

* Result

The curve screens were walked in a browser, and the walk left a scenario a person
can repeat plus the defects it found. The scenario walks the segments and quotes
of a curve, the blocks the page does not draw, and the Details, Used by and
History tabs, with a result table per step.

The walk found four snags. The instant a row was recorded drew as a leaf, fixed on
the quotes branch. A segment's conventions draw as a gap because the contract has
no row for them, filed as task 3D1208F2. The elements a curve can otherwise hold
were one line a tester called extremely confusing to users, now a line per element
with its own state. And a run that reached its last step never reached the doc:
the runner now saves as the tester moves on, which a browser walk from a pending
scenario confirmed with nothing pressed at the end.

Two fixes to the tooling came with it: the runner's save-on-move, and `compass add`
stating the environment on a doc the scaffold writes, which had left every
scenario's field empty.

What the scenario asks of a person that a script cannot judge: whether a segment's
card reads as one element, whether a long quote list stays scannable, and whether
a segment leaf's documentation opens as easily as a curve's own.
