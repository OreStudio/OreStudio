* Goal

IAM stores run grants: a person's consent that runs of one resource act in one
tenant and one party with one role. Grants are read like any entity and written
only through IAM's create and revoke operations, which make the checks.

* Acceptance

- =ores.iam.run_grant= exists as a codegen entity: tenant-scoped, party-isolated,
  bitemporal, with the fields of
  [[id:78B82824-0BBB-4442-A9FA-E1F265DF57BD][Run grants and run tokens]].
- Its reads are on the wire, HTTP and the shell; it has no generic write verbs.
- =iam.v1.run_grants.create= creates a grant on behalf of the person, refuses a
  role the person does not fully hold in the party, and returns the active
  grant for the same resource and grantor.
- =iam.v1.run_grants.revoke= ends a grant and is idempotent.
- Handler tests cover each check; the build and the test suite pass.

* Plan

1. Codegen: allow =:client_read_only:= on a domain entity, so the repository is
   writable and the wire carries reads only. The junction loader already
   computes =wire_write_enabled= from it; the domain entity loader rejects it
   today because it does not read it. A generated =put= would let a caller
   store a grant with none of the checks.
2. Model =ores.iam.run_grant= on =ores.analytics.pricing_model_config=: the
   UUID-identified lookup profile, =party_id=, and party isolation. Regenerate
   every layer, seed =iam::run_grants:read=, build and test through compass.
3. An operation model for create and revoke, with a hand-written handler that
   checks the grantor and the role.
4. A recipe, and the IAM page's record of what is built.
