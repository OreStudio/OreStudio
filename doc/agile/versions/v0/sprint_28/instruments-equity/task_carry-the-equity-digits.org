* Result

* Result

The variance strike is now money at rest: decimal in the domain and
numeric(38, 12) in the column, the same shape as the notional. It was the
only money column in the family still held as a float. Changed in the model
and regenerated, so the column, domain type, entity, protocol, history
mapper and repository mapper all follow from one declaration.

Scope, as the operator set it: this unit fixes the data model. It does not
teach the XML mappers to carry the document's digits. The equity binding's
money members are bare floats, which carry no lexical form at all, and the
XML boundary is being replaced by the xsdcpp removal, so digit-carrying
belongs to that work. The mappers changed only where the new type stopped
them compiling, and two sites in the synthetic generator and its repository
test followed the type.

Verification: full build clean, and the suite passes 95 of 96. The one
failure is ores.workflow.core.tests, which fails only under parallel load
and passes in isolation with 431 assertions in 55 cases; it is the same
flake seen before this change and does not touch ores.ore or ores.trading.
ores.ore.core.tests passes with 483664 assertions in 719 cases.

Not done, and named: the money members that are bare floats still lose
their digits at the XML boundary. That is now explicitly the xsdcpp
refactor's work rather than this unit's.
