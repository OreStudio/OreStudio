#+description: The shared-reference read tables carry no shared flag, which the owner block of doc/knowledge/security/data_read_across_tenants.org requires of a table that holds both tenant rows and shared rows. The flag exists so the system tenant can keep a row that no tenant reads; without it, every system-tenant row of those tables is readable by every tenant. Today that is the intent for the 54 catalogues: each publishes all its system rows for tenants to read, and the per-command policy split means a tenant still cannot write one. The deviation matters the day one of those tables needs a platform-private row, and the closing move is to add the column, have the seed set it, admit a row by owner and flag, and regenerate the 54 tables' policies. The read-across page states the flag, so a reviewer will find the gap.
