* Acceptance

- The ores.qt and ores.wt.service trees are gone.
- A full build configures and passes with no Qt present.
- CI installs no Qt and every job passes.
- compass env init writes no ores.qt.client certificate.
- Regenerating every model produces no drift.
- No Qt vocabulary survives in the modelling pages, the recipes or the skills.

* Plan

The cut lands on =feature/remove-qt-and-wt=, cut off main after the merge
of PR #2105. PR #2105 renamed the =** Qt= drawer to
=** Presentation= and added the =ores.ts.ui= facet, so the models already
read as presentation data before this cut starts.

The cut runs in this order:

1. *Trees.* =git rm -r projects/ores.qt projects/ores.wt.service=.
2. *Build.* Drop the Qt6 package, the Qt plugin output directory, the
   =deploy_help_qch= target and the =WITH_WT= option. Drop the matching
   =add_subdirectory= calls and the CPack executable entry.
3. *CI.* Remove the =install-qt-action= step from the four workflows that
   carry it, plus the macOS Qt pin comment and the =nightly-includes= note.
4. *Compass.* Drop the =client= service group, the =ores.qt*.pid= helpers,
   the two NATS certificate names, the =ORES_NATS_TLS_*= lines that point
   at them, and the =--with-qt= package list.
5. *Docs, recipes, skills.* Delete the Qt and Wt recipes, the Qt
   knowledge pages, the two Qt codegen skills, and the three
   =projects/modeling= Qt and Wt facet pages. Reword the passing mentions
   in the pages that survive.
6. *Templates.* Reword the Qt prose in the codegen template orgs, then
   re-tangle. Three =.mustache= files change.
7. *Elisp.* Delete the Qt and Wt service blocks, tags and helpers from
   =ores-prodigy.el=, =ores-dashboard.el= and =ores-build-recipe-scripts.el=.
8. *Regenerate.* Regenerate the one affected SQL output, then commit.

Deliberate keeps are listed under =* Notes=.

* Notes

*Scale.* The cut deletes 2171 files: 2120 under =projects/ores.qt/=,
39 under =projects/ores.wt.service/=, and 12 stragglers — =generate_help_qch.py=,
two Qt knowledge pages, two skills, four recipes, and the three
=projects/modeling= facet pages.

*What replaced the Qt reader.* The drawer keeps every knob it had. The
=ores.ts.ui= facet reads the =** Presentation= drawer, so the tables this
cut stopped feeding still feed the TypeScript metadata. Only the Qt
archetypes that consumed them are gone.

*Regeneration path for the service registry.* The =service_registry= model
lives at =projects/modeling/service_registry.org=, outside every component
directory, so =codegen regenerate --all= never reaches it. Generate it
directly:

#+begin_src shell
./compass.sh codegen generate --model projects/modeling/service_registry.org \
    --address ores.sql.service
#+end_src

That command writes four files. Only
=projects/ores.sql/populate/iam/iam_service_accounts_populate.sql= changed;
the other three regenerated byte-identical to their committed state.

*Deliberate keeps.* These Qt references stay on purpose:

- =ores-build-help.el= keeps one past-tense mention. It records why the
  help stylesheet holds to a CSS 2.1 subset. The reason outlives the viewer.
- =entity_meta_model_cpp_qt.uvl= and its =.svg= keep their filenames. The
  page is the drawer's meta-model and reads as presentation now; the file
  names are a separate rename.
- =projects/ores.workspace/core/modeling/multi_workspace.org= keeps its
  =*Removed with the Qt client.*= archive note. The note records a removal.
- =doc/agile/versions/**=, =doc/plans/=, =doc/analysis/= and
  =doc/investigations/= keep their Qt references. They are history.

*Deferred follow-ups.* Filed here rather than swept in this PR:

- *The =wt_user= database role is still provisioned.* With the Wt service
  gone, nothing connects as =wt_user=. The role lives in hand-written SQL:
  =setup_user.sql=, =recreate_database.sql=, =drop_roles.sql=,
  =teardown_all.sql= and =iam_infrastructure_accounts_populate.sql=, plus
  =database_lifecycle.org=. =env_init.py= also keeps a =WT= entry in its
  =client_apps= list, which writes five =ORES_WT_DB_*= variables that no
  binary reads. The entry goes with the role. Removing the role changes
  how environments are
  created, so it needs its own task and its own migration note.
- *=ores.connections= has no consumer left.* =projects/CMakeLists.txt= still
  builds it, but no component links the library. Three loose ends follow
  from that:
  - =doc/manual/user_guide/chapter_connecting.org= still describes the
    =connections.db= store and gives =ores.qt= paths for it.
  - =env_init.py= still emits the =connections.db= master-password variable.
  - =doc/knowledge/ui/icon_guidelines.org= still links 124 icon files that
    this PR deletes. Those links were already broken — they omit the
    =application/= path segment — and the page itself is a design guide
    worth keeping once the paths are repointed.
- *Two components sit outside the drift gate.* =trade= and =dq= are not in
  =KNOWN_DRIFT_FREE=, so no gate regenerates them. Their committed trees
  predate the generated-file marker template, and regenerating them today
  adds that marker to hundreds of files in each case. This PR
  regenerates the two =dq= files its own prose change touches — one of
  which takes the marker with it — and leaves the rest for the task that
  clears that backlog.
- *Qt vocabulary in prose and comments.* Roughly 30 comments in
  =core.py=, ~40 source-file comments, and the domain prose in the QA
  runner pages still name Qt classes. Almost all of them describe a
  derived value the generator still emits, so they need judgement, not a
  find-and-replace.
- *=CTestCustom.cmake= keeps inert Qt coverage-exclude patterns.* They match
  nothing now and cost nothing.
- *Two knowledge pages treat the Qt plugin as live.*
  =fx_spot_synthetic_poc_architecture.org= and
  =ores_marketdata_infrastructure_inventory.org= name =ores.qt.mktdata=,
  its windows and its charting in the present tense, 27 and 16 times
  respectively. Both are dated design records whose subject *is* that
  plugin, so each needs a rewrite or a superseded banner, not a
  find-and-replace.
- *=icon_guidelines.org= carries 124 broken links.* Pre-existing, unrelated
  to this cut, found while sweeping.

* Result

The cut lands as four commits: the scaffold, the removal, the
bookkeeping, and the fixes the local review found.

The =ores.qt= and =ores.wt.service= trees are gone, with the 12
straggler files above. The build, CI, the compass client and the
certificate list carry no Qt. The codegen templates drop their Qt
prose, and the one generated file they feed is regenerated.

394 of the deleted files are images, including the FluentUI icon set
under =projects/ores.qt/application/resources/icons/=. The only page
that links them is =icon_guidelines.org=, whose links were already
broken. No surviving page loses a working image.

A full build configures and passes, and ctest reports 100%: 70 of 70
tests, in 1499 seconds. vcpkg removes five packages that nothing uses
now: =boost-compute=, =boost-interval=, =boost-ublas=, =libpng= and
=wt=. The configure step takes 2.6 seconds and the build log names Qt
zero times.

The certificate generator writes 42 files into an empty root: the CA
pair, the NATS server pair and 19 client pairs. No file name carries
Qt or Wt.

Validators run against the committed tree, all clean:

- =check_component_drift.py --all= — no drift.
- =check_model_drift.py --summary= — no drift beyond the two recorded
  exceptions.
- =check_populate_references.py= — every referenced name is defined.
- =regenerate_cmake_component_files.py --all --check= — no drift.
- The codegen template tangle and the shell recipe tangle produce no
  diff.
- The codegen test suite: 254 passed.
- The compass test suite: 166 passed, 1 skipped.
- =compass lint=: exit 0.
- The domain roundtrip check: exit 0.
