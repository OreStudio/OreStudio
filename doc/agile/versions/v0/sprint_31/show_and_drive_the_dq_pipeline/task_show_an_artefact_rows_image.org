* Goal

A row whose point is a picture shows the picture. Six artefact tables hold an
=image_id=, the store keeps 687 images — SVG flags and JPEG photographs — and a
contents row prints the uuid today, so a reader learns nothing about it.

Two halves, and neither is served: the contents read states an image column's kind
and answers the image's code, and a route serves the stored image at its own content
type so the browser caches it. The prototype draws the result: the Contents table
shows four flags where it showed four uuids.

* Acceptance

- The contents read states each column's kind as well as its name, and an image
  column's kind is =image=.
- A row's image column answers the image's code, not the uuid the artefact table
  holds, so the screen never resolves a reference.
- A route serves a stored image's bytes at the image's own content type, so an
  =<img>= reads it, the browser caches it, and no JSON carries a byte array.
- The Contents tab draws an image column as a small picture with its code as the
  alternative text, and prints no uuid.
- An image the store does not hold, or one the caller may not read, is drawn as a
  muted dash rather than a broken picture.
- A test asserts a seeded country row's image code and that the route answers
  =image/svg+xml= for it.


* Plan

The prototype is
[[file:doc/prototypes/dq/reference-data-coverage.org][the coverage prototype note]],
whose Contents tab draws the four flags of the countries mock from real stored SVGs.

1. The read. =ores_dq_dataset_rows_fn= joins =ores_assets_images_tbl= for a column
   named =image_id=, states the column's kind as =image= in =columns=, and answers
   the image's code in place of the id. The join is per page, so it costs what the
   page costs.
2. The route. =GET /api/v1/assets/images/by-code/{code}/content= answers the bytes
   with the stored =mime_type=, so the screen sets =src= and the browser caches it.
   The existing JSON route stays for the images screen, which needs the metadata.
3. The screen. A column whose kind is =image= is drawn as a 40 by 28 thumbnail, its
   code as the alternative text and the title. A missing or forbidden image is a
   muted dash.
4. Tests: a pgTAP assertion for the kind and the code, a route test for the content
   type and the bytes, and the dataset page's test for the image cell.

* Notes

An image is stored as base64 text in =ores_assets_images_tbl.data= with its
=mime_type= beside it, and the JSON route decodes it into a byte array. That is the
wrong shape for a picture in a table: a 30 KB SVG costs 94 KB of JSON, the screen
must decode it, and every page re-reads every byte. A route that answers the bytes
at the stored type lets the browser do what it already does for an image.

The read answers the image's code rather than its id for the same reason the read
answers a family's table names: the screen is given something it can draw with, and
a reference it would have to resolve is not that. The id stays in the store; the
code is what a route and a person both use.

Only =image_id= is treated this way. A =party_id= or an =index_id= is a reference to
another record and is drawn as its code by the screen that knows that record's kind;
guessing from the name would draw a flag wherever a uuid happened to look like one.

Asked for on 2026-11-28, on review of the Contents work: the mock rows showed
uuids, and the flags the store holds were invisible.
