#+description: Codegen entity model for the refdata =convention= table. The central row every convention kind shares: its key, the party that owns it, the kind it is, and the name it carries in the source document.

#+brief: The central row every convention kind shares.
#+created: 2026-10-14
#+updated: 2026-10-14

The central row of the atomised convention. Every convention kind -- a swap, a
deposit, a tenor basis swap -- is one row here plus the parts its family names.
The row carries the key, the party that owns the row, the kind the row is, and
the name it carries in the source document.

The name is the identifier the source document gives the convention, the =<Id>=
element of that document. It is kept so a round trip through the ORE XML is
lossless, and it is part of the convention's identity: the party, the kind and
the name together are what make a convention the one a caller means. Two kinds
may hold the same name, because the kind is part of that identity.

A convention's kind-specific fields live in that kind's parts, reached from
this row by its key. The central row carries no kind-specific column.

The party that owns this convention. Set from the session that writes the
document, and enforced by row level security, so a party sees only its own
configuration.

It is part of the convention's identity, so two parties may each hold a
convention of one kind under one name.

** kind_code
:PROPERTIES:
:type:                text
:cpp_type:            std::string
:nullable:            false
:natural_key:         true
:filterable:          true
:no_generator_suffix: true
:END:

The kind of convention this row is, a code from the =convention_kind= lookup.
It selects the family whose parts the row carries.

It is part of the convention's identity.

It is filterable, because a screen that reads one family's conventions lists
the central rows by this column; the parts are aligned with the page the list
returns, so the screen zips the family read onto it rather than joining two
result sets in the client.

#+end_src

** oresmd_uri
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

The oresmd URI of the market data this convention needs, when the kind names
one index. The column holds the address as a value, so refdata depends on the
oresmd format as a contract only and never on the marketdata library or its
tables.

Nullable, because no convention is required to state its address yet.

* Artefact columns
:PROPERTIES:
:key: name
:END:

A convention stages without its uuid and without its party. The uuid is made by
the database when the publish inserts the row, and the party is the one the
publish names, so neither is known when the dataset is seeded. The staged row
carries the identity the source document gives instead: the kind and the name.
A part reaches the central staging row by exactly that pair.
