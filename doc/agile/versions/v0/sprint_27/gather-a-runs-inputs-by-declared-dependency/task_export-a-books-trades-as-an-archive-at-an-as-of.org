* Goal

=trading.v1.ops.export_trades_to_storage= takes book ids and no date, pages
=trade_export_service::export_books=, writes one =rfl::msgpack= blob of
=trade_export_item= rows for all of them, and uploads it. That blob is
trading's own transport encoding: an instrument is carried as an opaque
=instrument_payload=, because reflect-cpp cannot name the active alternative
of the instrument variant.

The ORE mapper cannot be driven from that. Export one book at a time, at a
stated as-of, and source everything the portfolio needs — trade headers,
instruments and envelopes — into a zip whose shape is declared.

* Acceptance

- The request names one book and one as-of date.
- The archive holds everything the ORE portfolio mapper needs: the trade's
  anchor, its instrument as something the mapper can walk, and its envelope
  (counterparty, netting set, portfolios, additional fields).
- The archive's shape is declared — the set of members, their names, their
  encodings, and a manifest to check them against — so a reader validates
  before it maps.
- The same book exported at two as-of dates yields archives that answer the
  two dates.

* Plan

*One archive per book, with members split by instrument type.* The book is the
unit the run fans out over and the unit the package counts, so the archive is
per book. Inside it, a manifest plus one member per instrument type (and one
for the headers and envelopes) is the shape that lets the mapper stream type
by type, lets a new instrument family arrive without touching the others, and
localises a mapping failure to a type rather than to a book.

The alternative — a separate archive per book per instrument type — multiplies
the object count by the number of types and makes the fan-in set's size vary
with each book's contents, which is the thing the waiting logic least wants.
This is a decision to confirm when the shape is drawn: it is recorded here
because it is the question, not because it is closed.

*Where the as-of comes from.* Every market and trade table is bitemporal, so
an as-of read is a =valid_at= read rather than new machinery. The run already
holds a date — the run document's =asofDate= — and it is currently passed to
nothing.

*What the encoding is.* The members stay in an encoding this tree can read
without a new parser; the point of the change is the shape and the completeness
of the data, not the container's format. The manifest is what makes the shape
declared rather than inferred.
