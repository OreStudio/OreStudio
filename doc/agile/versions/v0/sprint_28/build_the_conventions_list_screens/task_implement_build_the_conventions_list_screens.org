* Notes

The BFF page route takes an offset and a limit and nothing else. It sends an empty
filter and no order. The list of documents therefore offers no search and no
sort. The list of kinds reads all 26 kinds in one call, so it searches and sorts
in the browser, which is a complete read and not a page of one.

The page route has no read of one document by its key and no delete. The rows of
the list do not open, because no record page exists yet. The Edit, Add, Delete
and History parts are later tasks. They need the approval kind that the capture
=approve-convention-changes-with-a-request-kind= describes.

The environment's =node_modules= lacked =cronstrue=, so no web test that reaches
=CronField= could load. =npm install= in =projects/ores.web= fixed the local
copy. The lock file was restored afterwards.

* Result

Two screens and one move.

- *The list of kinds* at =/refdata/conventions=. Two tabs: Party conventions (22)
  and Shared conventions (4), the second with a warning that every party reads
  it. The kinds sit under their asset class: interest rates, FX, inflation,
  credit, commodity and bond. A search, an asset class filter and a sort by
  column live in the address. A row opens the kind.
- *The documents of one kind* at =/refdata/conventions/<kind>=. It draws through
  =RecordList=, so the page, the page size and the states come with it, and the
  server pages the rows. A shared kind carries the warning above the table.
- *Define instrument conventions* is now a workflow in the Workflows menu of both
  lists, at =/refdata/conventions/define=. The journey ends at the list.

Checklist, for the lines a list has. Each line not named Meets.

| Line | Mark | Why |
|------+------+-----|
| Search, sort and filter go to the server | Gap, server | The page route sends an empty filter and no order. The list of documents has no search and no sort. |
| Every column sorts on the server | Gap, server | The same gap. The list of kinds sorts in the browser. |
| Add shows for a person who may write | Gap | No Add. The write needs the approval kind. |
| A click or Enter opens the record page | Gap | No record page exists, so a row is plain and not a dead link. |
| The pager is on every list | Exception | The list of kinds has none. It is complete in one read and grouped. |
| A named permission guards the menu, the route and the button | Gap | The card carries no permission. The server refuses a read the person lacks. |
| Rows that changed are marked | Gap, in part | The list hears changes to the kind. A row key for a convention event is unknown, so the list says only that something changed. |
| The record page, Edit, History, Delete lines | N/A | No record page yet. |

Not done here: the record page, Add, Edit, Delete, History, and any run against
