* Goal

ORE becomes an OAuth 2.1 authorization server for its own API, for every client
and not for MCP alone. A client such as Claude Desktop or claude.ai connects to
/mcp, is sent to ORE's own sign-in and consent pages, and the person signs in,
possibly with an external identity, and approves the client, which creates the
same agent grant an API key does. ores.http publishes protected resource
metadata, answers 401 with WWW-Authenticate, and serves authorization server
metadata, an authorize endpoint whose sign-in is the one the previous tasks
built, and a token endpoint with PKCE S256, rotating refresh tokens and tokens
bound to ORE by resource indicator, as MCP's authorization specification asks.
MCP is the first client of this server; any other client that follows the same
specification is served by the same endpoints.

* Acceptance

- Claude Desktop connects to /mcp through ORE's sign-in page without a header or a bridge.
- The authorisation server publishes its metadata, and a client that follows the specification is served by the same endpoints as MCP's.
- The token endpoint requires PKCE S256, rotates refresh tokens, and binds a token to ORE by resource indicator.
- The consent creates an agent grant the person sees and revokes like any other.
- The server passes the MCP conformance runner's authorization checks for what it implements.
