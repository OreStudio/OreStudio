* Goal

Every valid oresmd quote reaches its consumers. Today plan_tick writes the ORE key of the tick's datum and drops the tick when there is none, before it is stored or republished. The subject takes its key from the URI instead, encoded into safe subject tokens, and the shell stream command, the web tick buffer and the feed binding page follow.

* Acceptance

- The subject needs no ORE key: it is made from the URI alone.
- A quote with an oresmd URI and no ORE key, such as one with the quote type hazard_rate, is stored and republished. This needs the oresmd URI codec to read such a quote, which it refuses today; see Notes.
- The subject is built from the URI by one encoder with a round trip test, and no subject part holds a character NATS refuses.
- The shell stream command, the market tick and feed binding pages, and every subscriber use the new subject.

* Plan

The subject takes its last token from the datum's canonical oresmd URI, written
by the codec, so every spelling of a datum has one subject. One encoder in
=tick_subjects.hpp= makes the token (=subject_token=) and a second reads it back
(=subject_token_text=). The ingest loop's plan, the shell stream command and the
tests use it. The party's whole tree is =market_tick_subject_all=.

The web has no reader of this subject: the BFF tick buffer reads the producer
subject, and its rows already carry the URI.

* Notes

- The drop of a quote with no ORE key is in the oresmd URI codec, not in
  =plan_tick=. =oresmd_uri_codec::read= and =write= refuse a quote that
  =ore_key_codec= cannot name (the test =a_quote_type_no_ore_key_can_name_is_refused=
  holds that). So this task makes the subject independent of the ORE key, and
  a hazard rate still cannot flow until the codec accepts it. The capture Let the
  oresmd URI name quotes that ORE cannot name tracks it. It is a design decision, because import, export and the curve republish all assume an ORE
  key for a quote.
- The capture about the feed binding's claim is out of date. A binding has no
  ORE key; its natural key is the party and the source, the claim is read by
  the row's id, and a read by source keeps the session party's row.
