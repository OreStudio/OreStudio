* Acceptance

- The pgTAP scan joins the shapes the way the projector reads them, so a violation in any tenant's identity fails the suite; the injection that proves it is part of the suite.
- The backfill response carries how many rows the shape refused and how many series fall in a family no shape states.
- The counts are asserted in a test, so a guard that refuses silently cannot return.

* Plan

Two gaps, both measured against the tree at =67803175ce=.

The pgTAP suite holds the stored identities to the shapes, but it joins the shape
row on the identity's own tenant:

#+begin_src sql
  join ores_marketdata_series_identity_shapes_tbl st
    on st.tenant_id = i.tenant_id
#+end_src

That was right while every tenant held a copy. The catalogue is shared now, and the
only shape rows are the system tenant's, so the join reaches the 330 identities the
system tenant holds and none of the 3,473 any other tenant holds. The projector
reads the shapes the session can see -- =tenant_id == tid || tenant_id == sys= in
the generated =read_latest= -- so the test must join the same way:
=st.tenant_id in (i.tenant_id, ores_utility_system_tenant_id_fn())=. A violation
injected into a non-system identity, inside the transaction and rolled back, is the
case that fails with the fixed join and passes with the current one.

The projector counts what it refuses (=backfill_result::refused=) and how many series
fall in a family no shape states (=unstated=), and the backfill response carries
neither: it reports projected, already projected and unreadable. A refusal and an
unguarded family are what an operator most needs to see, and today neither leaves the
process. The response gains =refused_count= and =unstated_count= from the model, and
a test asserts them.
