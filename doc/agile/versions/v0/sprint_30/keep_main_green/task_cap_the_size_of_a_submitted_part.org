* Acceptance

- No submitted part holds more than the bounded number of cases, and every part is listed.

* Plan

Write each subproject's cases in parts of at most =MAX_CASES_PER_FILE=, named
=Test-<component>-<n>.xml= only when there is more than one part, so a
component that fits keeps the name it has.

* Result

* Result

A submitted part now holds at most two thousand cases, and a component that
needs more is written as =Test-<component>-1.xml=, =-2.xml= and so on. A
component that fits in one part keeps the name it had.

The evidence that this matters: the two continuous legs expand the same 38,073
cases, and CDash holds all of them for the debug build, while the release build
is missing =ores.trading.api= (5,690 cases) and =ores.workflow.core= (70). The
parts it did accept were up to 5.8 MB.

Verified locally: the script's tests pass, including two new ones for the parts
and for the name a component keeps; a synthetic component of 30,000 cases is
written as fifteen parts whose largest is 1.05 MB.
