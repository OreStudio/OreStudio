This page is the node for the =ores.ts.protocol= facet of the codegen
template library, part of the [[id:1E93BE86-58BF-40FB-BB93-132D639BDC87][ores.ts]] [[id:E7B74138-9ADA-4B4B-A983-23B3FDB55F44][technical space]]. Each archetype
below is documented, and holds its =mustache= source, in its own
linked page — this page is the facet-level summary and the routing
table to them.

* Summary

One template: a TypeScript module per protocol, holding one exported
interface per message and one =subjects= constant naming the NATS
subjects. Only =operation= models render here — an operation model *is*
a protocol, and it carries the subjects and the message shapes.

The facet is narrower than its C++ sibling on purpose. An operation
whose fields reference a type with no TypeScript counterpart cannot
render a complete interface, so it declares
=:ores.ts.protocol.enabled: nil= in its own drawer and
=org_loader.load_org_operation_model= refuses to load it otherwise. A
field that vanishes from an interface is a run-time failure in a UI that
reads it, and no later check would see it.

* The ores.ts.protocol facet

The UI-facing end of the messaging fabric. Sibling to
[[id:E9A47FBA-7799-4D6B-AD1A-144B2F740F0F][ores.cpp.protocol.protocol_header]], which renders the same messages as C++
structs; the two templates read one model, so the wire shape is stated
once.
