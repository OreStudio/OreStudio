* Goal

Extend =credit_market_data_identifier= with a =credit_quote_type= enum
covering all 6 ORE credit quote TYPEs: single-name CDS, hazard rate,
recovery rate, index/tranche base correlation, and rating transition
probability — each projecting to its documented ORE quote key format via
the new =quote= query parameter.

* Acceptance

- [X] =credit_quote_type= enum added with 6 values (=cds=, =hazard_rate=,
  =recovery_rate=, =cds_index=, =index_cds_tranche=, =rating=).
- [X] =quote= query parameter generalised from IR-only to IR+credit;
  still rejected for FX, equity, commodity.
- [X] =quote_key_credit= handles all 6 formats: =cds= (existing
  seniority+tenor shape), =hazard_rate= (tenor only, no seniority),
  =recovery_rate= (seniority only, no tenor), =cds_index=/
  =index_cds_tranche= (series+tenor), =rating= (ccy only, no entity or
  point).
- [X] Backward-compatible: =quote= absent defaults to =cds=, matching the
  pre-existing worked-example behaviour exactly.
- [X] Round-trip parse→to_uri tests for all new types.

* Plan

Added =credit_quote_type= enum to =oresmd_enums.hpp= and =quote_type=
field to both =credit_market_data_identifier= and
=credit_market_data_requirement=. Refactored =validate_no_ir_only_keys=
to split out =validate_ir_or_credit_only_keys= so =quote= is allowed on
IR and credit but rejected on FX/equity/commodity. Extended
=quote_key_credit= with per-type format dispatch: =cds= uses
=ENTITY/SENIORITY/CCY/TENOR=, =hazard_rate= uses =ENTITY/CCY/TENOR=,
=recovery_rate= uses =ENTITY/SENIORITY/CCY=, =cds_index=/=index_cds_tranche=
use =INDEX/SERIES/CCY/TENOR=, =rating= uses just =CCY= with no point
requirement. Wired =quote= through resolver and parser =to_uri=.
