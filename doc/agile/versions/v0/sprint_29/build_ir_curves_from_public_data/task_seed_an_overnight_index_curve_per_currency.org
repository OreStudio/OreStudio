* Goal

The system tenant holds a bootstrap config for the overnight-index curve of each supported currency: AONIA, CORRA, SARON, ESTR, SONIA, TONA, NZONIA and SOFR first, then the other twenty currencies' indices. Each config names the series its pillars read, its interpolation, its day count and its tenor convention, and writes to its own output series. Today only USD has one.

* Acceptance

- Each of the eight currencies of the derived FX pairs has a config, pillars over the tenors its synthetic feed publishes, and an output series.

- The other twenty currencies have a config, or the reason they do not is recorded.

* Plan

1. Confirm the inputs: the synthetic Bloomberg feed's spot-starting overnight-index swap series of each currency, and the terms it quotes.
2. Seed each currency's ladder series, output series, config and pillars as the USD seed does, generated by one script so every currency has the same shape.
3. Take each day count from the currency's row in the overnight index conventions, and leave out a currency whose index or day count the engine cannot use.
4. Bootstrap every config on a recreated, provisioned environment through =/api/curves/compute=.
5. Hold the seed to its shape with a pgTAP suite.

* Notes

** Why some currencies have no config

| Currency | Reason |
|----------+--------|
| BRL | The CDI convention states BUS/252, which the bootstrap engine does not implement. |
| NOK | The NOWA convention states ACT/ACT.ISMA, which the bootstrap engine does not implement. |
| CNY | No overnight index convention exists for the feed's SHIBOR. |
| TWD | No overnight index convention exists for the feed's TAIBOR, a term rate. |
| ILS | The feed quotes TELBOR, which ceased after 30 June 2025. |
| CNH | The feed quotes HIBOR, a term rate. |
| HUF | The feed quotes the BUBOR overnight quote rather than HUFONIA. |
| PLN | The feed's index is unresolved. |

The last four wait for [[id:4B5701D6-16C6-445B-BDD4-C60050FED95C][Replace the synthetic feeds of ceased or misnamed indices]]; seeding a curve named after a ceased index would only be renamed there.

** Where the quotes are

The synthetic IR ticks are stored in =ores_marketdata_ticks_tbl=, not in =ores_marketdata_market_observations_tbl=, and the table forces row security for its owner, so a read must set =app.current_tenant_id= and =app.visible_party_ids=. Read without them, every ladder looks empty.

** The seed runs on a fresh database only

The insert triggers refuse a row that already exists before =on conflict do nothing= applies, so the seed, like the USD seed, is applied by recreating the database.

* Result

The system tenant holds an overnight-index curve config for nineteen currencies besides USD, and each bootstraps from its synthetic Bloomberg quotes through the existing compute operation.

- =marketdata_market_series_overnight_curves_populate.sql= seeds each currency's ladder series and output series; =refdata_ir_curve_overnight_configs_populate.sql= seeds its config and seven pillars, as the USD seed does.
- The seven other currencies of the derived FX pairs come first: EUR-ESTR, GBP-SONIA, JPY-TONA, CHF-SARON, AUD-AONIA, CAD-CORRA and NZD-NZONIA. Twelve more follow: CLP, COP, CZK, DKK, HKD, INR, KRW, MXN, SEK, SGD, TRY and ZAR.
- Each config is named after its index's overnight convention and takes that row's day count.
- The eight currencies without a config are listed with their reasons in Notes.
- =refdata_overnight_curve_configs_test.sql= checks that every config names a convention and its day count, ladders the seven pillars, reads its currency's Bloomberg ladder and writes its own discount series.

No curve is published yet: publishing is the next task.
