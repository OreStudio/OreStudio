#+title: sqlgen overlay port
#+description: How to build sqlgen with the cursor-transaction patch instead of the registry port.
#+filetags: :build:vcpkg:sqlgen:

* Why

sqlgen's postgres iterator wraps every read in its own transaction. It runs
=BEGIN= when it opens and =END= when it closes, and PostgreSQL reads =END= as
=COMMIT=. A read made inside a transaction therefore commits that transaction.
=ores.database= repository writes read before they write, so a unit of work
that writes several rows commits the first row when the second write reads.

=tests/unit_of_work_tests.cpp= records the behaviour in the case named "a read
inside a unit of work commits the transaction". The booking service avoids it
by stating claims that read nothing.

* What the patch changes

=fix-iterator-transaction.patch= makes the iterator ask
=PQtransactionStatus= whether it is already inside a transaction. An iterator
that joins one runs no =BEGIN= and no =END=; an iterator that opens its own,
outside a transaction, keeps the current behaviour.

* How to enable

The repository has no =vcpkg-configuration.json=, so the overlay is inert.
Add one at the repository root:

#+begin_src json
{
  "overlay-ports": ["./vcpkg-overlays"]
}
#+end_src

Then reconfigure. vcpkg replaces the registry =sqlgen= port with this one,
rebuilds sqlgen from the commit below, and reinstalls its dependents.

* Version note

The registry port is =0.8.0#1=, built from =getml/sqlgen@47e5711=. Upstream's
last tag is =v0.6.0=; =0.8.0= exists only as a commit on =main=. The port pins
the commit the registry already uses, so the only change is the patch.

* When to remove

Once the patch is upstream and the registry port carries it, delete this
directory, its wiring, the read-free claims in
=trade_operations_service.cpp=, and invert the unit-of-work case named above.
