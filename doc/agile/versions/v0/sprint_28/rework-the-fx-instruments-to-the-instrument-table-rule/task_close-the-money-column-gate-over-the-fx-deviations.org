* Result

The gate now sees all three shapes the review named, and each is asserted.

The first shape, a continuous quantity whose name reads as money, is decided by
the entity that states it: =CONTINUOUS_COLUMNS= names the column and its
reason, so =fx_variance_swap_instrument.strike= is checked in the continuous
direction rather than hidden. The exclusion list no longer carries it. The
second shape, money typed text, was already reported; the money baseline
records the five that remain, all in other components. The third, a money value
read through a binary float, is the =numeric= column with a =double= in the
domain, and it is reported.

Both baselines carry a header that states the format and what an empty list
means. The continuous baseline holds only its header, so the direction records
no debt and the next offender fails the check. The money baseline holds the
five text columns.

The exact-numbers page does not restate either baseline: it names the two files
as the authoritative inventory and forbids a prose copy. It needed no change,
and the claim that it still counts ten columns was stale when the task was
written.

* Decisions

- *The check stays on the models.* It does not read the ORE binding. A money
  value is lost at the binding only when a leaf is not a =moneyFloat=, and the
  digit tests and the goldens cover that seam directly; teaching this check a
  second input language would duplicate the binding's own drift guard.
- *An empty baseline is a statement, not an absence.* The header says so, and a
  test holds the reader to it, so the next offender in a clean direction fails
  rather than being absorbed.
- *The exclusion list stays for columns the name rule cannot classify.* It is
  not the mechanism for a continuous quantity any more; it remains for a money
  word that names a code or a quote, and each entry still needs its reason in
  the model prose.
