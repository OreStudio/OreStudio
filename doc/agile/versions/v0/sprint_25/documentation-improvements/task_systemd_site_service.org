* Goal

`compass site serve` currently only runs as an ad hoc foreground/background
shell process (manually backgrounded, killed via `pkill`), unlike every
other ORE Studio service which is managed through systemd (see
`systemd_generate.py` and `compass services start/stop/status`). Give the
site preview server the same treatment: a generated systemd unit and
`compass site start`/`compass site stop`/`compass site status` commands
(or equivalent), so it starts/stops/reports cleanly and doesn't leave
orphaned python http.server processes behind.

* Acceptance

- A systemd unit for the site-preview server is generated per
  environment, following the same convention as the other ORE Studio
  services (`systemd_generate.py`, per-environment scoping/cgroups).
- `compass site start`/`compass site stop` (or equivalent under the
  existing `compass site` subcommand group) start/stop the unit
  instead of a manually backgrounded process.
- `compass services status` (or `compass site status`) reports the
  site server's state alongside the other services.
- No orphaned `python3 -m http.server`/emacs processes left behind
  after stop.
