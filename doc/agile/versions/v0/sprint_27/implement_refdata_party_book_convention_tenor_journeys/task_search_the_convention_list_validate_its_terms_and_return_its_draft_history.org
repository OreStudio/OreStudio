* Result

One of the five units is built. The other four are filed as
[[id:ABEC57F4-A85F-4D0E-83F6-1FC9C7C891AB][Serve the convention family
mapping, its term filter and term rules]], each with the reconnaissance it needs
rather than a guess.

*What landed.*

- *The sub-periods coupon type is a list the server serves.*
  =refdata.v1.sub_periods_coupon_types.list= and its neighbours now exist, in the
  shape every other convention term list has: a =simple-lookup= entity, versioned,
  with a history provider, a shell command set and a TypeScript twin. It is seeded
  with the two values the =swap_convention= and =tenor_basis_swap_convention=
  models' own =sub_periods_coupon_type= column descriptions name -- =Compounding=
  and =Averaging= -- so the pick the journey draws offers them instead of free
  text. The table is wired into the create and drop aggregators, the seed is wired
  into the foundation populate, and the three =refdata::sub_periods_coupon_types=
  permissions are seeded. Journey 8's row for it reads =exists=.

*Why the other four are filed rather than built.*

They are not one unit with the first; they are four different kinds of change,
and two of them change every convention rather than adding to the tree.

- *The term filter* needs a codegen decision first. A generated =list= derives
  =id_one_of=, and a =list_by_<column>= only for a column the model marked
  =:list_by:= or =:list_by_uuid:=. The journey wants a convention reachable by an
  index, a calendar or a day count, and those are unmarked text columns. Whether
  the answer is a per-column opt-in of the existing kind or one free-text term
  filter decides the protocol of all 29 conventions, so it is a decision before
  it is an edit.
- *The term validation* is feasible as a codemod -- the sibling task records the
  name-to-validator census -- but the mappings must be verified column by column,
  because a validator that reads the wrong lookup would be worse than none. Only
  three of the 29 conventions carry a =* Validations= table today, so the codemod
  adds the section as well as the rows.
- *The family mapping* is a new entity, and the journey already writes out all 28
  of its rows in the table under /Choose the instrument/. What is missing is the
  entity, and the question of whether the family is its own concept or derivable.
- *The draft history version* rests on a premise that does not hold as stated.
  =build_entity_history_versions= builds one entry per row the repository returns,
  and the repository reads newest-first, so the reply already carries the record
  as it stands. If the journey's *now* row is the record, the server provides it;
  if it is the unsaved form state, no server can. The sibling task records that the
  prototype must be read before this one is written, and that it may be dropped.

*Verification.*

The new entity's subject matches the one journey 8 names, exactly. Ten checks that
a new entity must satisfy were run and all ten pass: subject-conformance,
handler-permissions, open-reads, sql-reachability, populate-refs, protocol-twins,
generated-column-refs, sql-hygiene, format and reachability. =sql-reachability=
caught the one real omission on the way -- the two generated drop files were not
wired into the drop aggregator -- and the fix is in.

Journey 8's table went from one =missing= row to none, and its /What is missing/
drops the unit this change built while keeping the four that remain.

The branch builds green. The first attempt failed, and not on this change: the
branch point could not build the web client, because PR #2987's merge left
=projects/ores.web/packages/web/src/api/client.ts= importing =ReportingLineWrite=
from the =browser= entry while that entry did not export it. Trunk gained the fix
as =6edc28defd= ("[web] Export the reporting line write from the browser entry"),
and the branch was merged up to it before the build was rerun.

*What is not verified.* No database test exercises the new entity: the box shares
one PostgreSQL across eleven worktrees, so =compass db recreate= would disrupt the
others, and the local =.env= is at format version 27 against a required 29. The
entity is verified by its generated subject, its regression through the ten
checks, and the shape it
copies from 25 siblings.
