This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

Re-key =ores_trading_swap_legs_tbl= from its surrogate =id= to
=(trade_id, leg_number)=, as =bond_legs= is keyed by
=(trade_id, leg_role, leg_number)=, once the codegen defect below is fixed.

* Why

The instrument table rule says a shared child is keyed by the trade, an
ordinal and a role code. =swap_leg= keeps a surrogate =id= that nothing
supplies meaningfully: the import would have to mint one per leg, and the
trade plus the ordinal already identify the row.

* The blocker

The compound-key path cannot generate a compilable eventing integration
test. =cpp_nats_integration_test.cpp.mustache= builds =key_parts= by
inserting each extra key column's raw domain value, while the generated
service takes every key part as =const std::string&=. For =leg_number=, an
=int=, the generated test emits
=const std::vector<std::string> key_parts = {id_str, v.identity.leg_number};=
and does not compile.

=core.py= already prepares a text form per key column through
=_key_as_text= (=key_text=, =removal_key_text=, =row_text=), and each
enriched column carries =is_int= and =cpp_type=, so the fix is to expose
the =v.=-scoped text form and use it in the template.

=bond_leg= has the same compound shape but no generated eventing test, so
the defect has never been exercised.

Fixing the template regenerates every component under test, so it belongs
with the codegen work rather than with a family rework.
