* Goal

The exposure, SA-CCR and XVA analytics read documents that the platform holds as entities or holds nowhere: the counterparty information and the netting set definitions come from the counterparties, netting sets and CSAs that ACME already publishes, and the collateral balances have no home. The calendar adjustment, currency configuration, reference data and IBOR fallback documents are optional inputs. Decide for each whether it is a configuration document that a definition binds or a file the export derives from existing data, store what needs storing, and add the DQ support.

* Acceptance

- For each of the seven documents the task records whether it is bound as a configuration or derived from existing entities, with the reason.
- Each document the export needs has its content stored or derivable, and a mapper that round trips the ORE samples.
- The collateral balances have an entity, a store and DQ staging, and ACME publishes balances for the CSAs it holds.
- The reports that read these documents export them, and the exported documents validate against the ORE schema.

* Plan

1. For the counterparty information and the netting set definitions, check whether the counterparties, netting sets and CSAs that ACME publishes can produce the documents. If so, derive them at export and record that they need no configuration.
2. Model the collateral balances, which have no home, with a store and DQ staging, and publish balances for the CSAs.
3. Decide the calendar adjustment, currency configuration, reference data and IBOR fallback documents. Each is optional, so store one only when a report needs it.
4. Add mappers that round trip the ORE samples for each document stored.
5. Validate the exported documents against the ORE schema.
