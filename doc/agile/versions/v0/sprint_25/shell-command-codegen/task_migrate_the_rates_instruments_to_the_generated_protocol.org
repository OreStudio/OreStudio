* Goal

The nine rates instruments share one hand-written protocol header that differs from the generated contract in three ways. Its list payload member is the generic =instruments=, its history request key is =id=, and its save request carries no =from()= factory while adding a =swap_leg legs= member. A generated shell command unit against that header fails to compile, with 20 errors of the form =no member named 'balance_guaranteed_swap_instruments' in get_balance_guaranteed_swap_instruments_response=. Two mechanisms were tried and reverted: a generated per-entity protocol creates two definitions of the same fully-qualified names, and a second dialect in the template would bake a hand-written header's quirks into the facet. The shared header, the aggregate =rates_instrument_handler.hpp= and =registrar_rates.cpp= must migrate to the generated contract first.

* Notes

The three dialect differences were measured against the generated contract on
the =task_generate-the-trading-command-units= branch. The shared header is
=projects/ores.trading/api/include/ores.trading.api/messaging/instrument_protocol.hpp=:

| Difference | Shared header | Generated contract |
|------------+---------------+--------------------|
| List payload member | =instruments= (for example line 61) | ={{entity_plural_short}}= |
| Save request factory | none | =static save_<entity>_request from(...)= |
| History request key | =std::string id= (for example line 93) | the primary-key column name |
| Save request extras | =std::vector<ores::trading::domain::swap_leg> legs= (line 339) | none |

Opting =ores.trading.balance_guaranteed_swap_instrument= in and generating
produced 20 clang errors of the form =no member named
'balance_guaranteed_swap_instruments' in
get_balance_guaranteed_swap_instruments_response=, then =too many errors
emitted, stopping now [-ferror-limit]=. The generated files were deleted after
the probe.

The header is wider than the rates family. It serves 13 entities, which are
the nine rates instruments plus the four modelless instruments
(=commodity=, =composite=, =credit= and =scripted=, which have no model to
generate from). It also has these consumers, so the migration reaches past the
rates aggregate handler and registrar:

| Consumer | Files |
|----------+-------|
| =ores.trading.core= handlers | =commodity_instrument_handler.hpp=, =composite_instrument_handler.hpp=, =credit_instrument_handler.hpp=, =rates_instrument_handler.hpp=, =scripted_instrument_handler.hpp= |
| =ores.shell.application= units | the 13 hand-written trading units that stay |
| =ores.qt.trading= | 16 files, including =ImportTradeDialog.cpp=, =OreImporter.cpp= and =SwapInstrumentForm.cpp= |
| =ores.ore= service | =ore_import_execute_handler.cpp= |
| =ores.trading.api= | =trade_protocol.hpp= includes it |

Two mechanisms were tried and reverted. A generated per-entity protocol
creates two definitions of the same fully-qualified names. A second dialect in
the template would bake a hand-written header's quirks into the facet.

=trades history --diff= is broken independently of this task. The unit calls
=render_history_diff= for entity type =ores.trading.trade= and no provider is
registered under that name.
