* Result

No removal. The branch that carried one is abandoned, and this is the record.

ores.dq.risk_report_config.org was invalid when this started: placeholder
prose, a TODO for its natural keys, no Columns section, and a validation
failure that aborted component-drift at dq, which left every component after it
unregenerated. Deleting it made the gate complete, and the deletion was raised.

While it sat open, 97051b9fd0 completed the model on main: real profiles, a
Columns section, a primary key. Deleting it then would have destroyed finished
work, so the deletion is dropped and only this record lands.

The defect it was going to fix is still there, one model further on.
component-drift aborts at the first model that fails validation, so a single
bad file turns a tree-wide check into a partial one and the report names drift
rather than the model. Collecting every invalid model before failing is the
fix, and it needs its own task.

What the model change did need landed separately: 97051b9fd0 committed the
model without everything it generates, so the dq TypeScript twins were
untracked and two other components' output moved with it. That was fixed by
committing the regenerated output.
