* Goal

Every tenant's partition of a generated event cache loads inside that tenant, with a token for that tenant obtained by Token Exchange, so no cache needs a policy that lets the system tenant read every tenant; the parties policy and read are strict again and the root tenant sees only its own parties.

* Acceptance

- The generated event caches take a token provider per partition, keep one token per tenant, renew it before expiry and re-exchange once on token_expired.
- IAM mints each partition token in-process: tenant, the tenant's system party, IAM as the actor, read on parties only, a short lifetime, and every issue logged.
- The parties policy scopes to the current tenant alone, the party read uses the default tenant scope, and a database test shows the root tenant lists only its own parties.
- The sign-in party chooser still shows party names, and the root tenant's Parties tab shows only its own parties.
- The Cache-Aside pattern page states the use, including the per-partition identity rule.
