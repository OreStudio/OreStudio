* Goal

No build has reached CDash since 2026-11-18. The nightlies and the continuous
runs stop in =Init environment=: =compass env configure= writes =.env= with
=compass-ng=, and neither workflow puts the release the pin names on PATH, so
the step dies before the build and nothing is ever submitted.

* Acceptance

- The nightly and the continuous workflow both install the pinned compass before
  they configure an environment, and their YAML parses.
- A run reaches the build, and =ctest --script CTest.cmake,build_group=Nightly=
  submits to my.cdash.org.

* Plan

The pin already exists and =compass-check.yml= already installs it, so the fix
is to do the same in the jobs that build: a step that reads
=build/scripts/compass_ng.pin=, downloads that release for Linux, checks its
sha256, unpacks it and puts its =bin= on =PATH=, placed before =Init environment=
in =nightly-linux.yml= and =continuous-linux.yml=.

The macOS and Windows nightlies take the same step with the asset of their own
platform; they are left for their own change because the asset names differ and
this task can only be checked against the Linux runners.

* Notes

The step is copied from =compass-check.yml=, which has installed this release
since the CI gate was added; the workflows that build were never given it. That
is why the gate stayed green while the nightlies stopped: the two paths grew
apart, one of them keeping the knowledge of how to install the tool.

The macOS and Windows nightlies configure their environments the same way and
will fail the same way. Their assets are named for their own platforms, and this
change cannot check those names from here.
