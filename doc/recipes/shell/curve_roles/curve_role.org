#+title: How do I run the curve_roles commands from the shell?
#+description: Every command the curve_roles submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:curve_roles:

This file documents the curve_roles resource at the shell, one section per command. Every command is a subcommand of =curve_roles=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: C6FF2AF1-3168-59FE-8FE0-FA7D3D96BE00
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
curve_roles list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.curve_roles.list=.

#+name: curve_roles-list
#+begin_src ores-shell :tangle curve_roles-list.ores :exports none
curve_roles list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: A4BF3C72-4103-52AA-96B6-BAA1CBE9F56D
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
curve_roles get <code>
#+end_example

It is addressed at =refdata.v1.curve_roles.get=.

#+name: curve_roles-get
#+begin_src ores-shell :tangle curve_roles-get.ores :exports none
curve_roles get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 37D4CE80-180A-597E-B360-3808101084B0
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
curve_roles add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.curve_roles.put=.

#+name: curve_roles-add
#+begin_src ores-shell :tangle curve_roles-add.ores :exports none
curve_roles add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: FDE34FC4-E451-502C-8C6A-C625DB727585
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
curve_roles set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.curve_roles.put=.

#+name: curve_roles-set
#+begin_src ores-shell :tangle curve_roles-set.ores :exports none
curve_roles set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
