* Goal

A person with the review permission approves or rejects a proposed calibration and states why. Approving supersedes the pair's earlier approved calibration in the same change, so one approval is current. Each decision is a new version of the calibration, so its history shows who decided what, when and why.

* Acceptance

- synthetic.v1 operations approve_variance_calibration and reject_variance_calibration, each requiring a reason and a review permission distinct from the write permission.
- Only a proposed calibration can be approved or rejected; approving supersedes the earlier approval atomically.
- Tests cover approve, reject, a second approval superseding the first, and a refusal to review a calibration that is not proposed.

* Result

=synthetic.v1.ops.review_variance_calibration= approves or rejects a proposed
calibration with the reviewer's reason, for the system tenant and the permission
=synthetic::variance_calibrations:review=, which Trading holds; the BFF route is
=POST /api/synthetic/calibration/variance/:id/review=. Each write claims the
version it read; approving supersedes the pair's approval, then approves, then
names the calibration on the pair's GJR-GARCH feeds. A calibration that is not
proposed is refused. The change reason =system.review= records each decision.

Measured live on a recreated database with Acme provisioned: approving the
EUR/USD fit superseded the authored approval and re-pointed the demo and
Bloomberg EUR/USD feeds; a second approval was refused; rejecting the GBP/USD fit
moved no feed. The BFF tests cover the system-tenant gate, the request, the
refusal and an empty reason.
