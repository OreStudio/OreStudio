* Acceptance

- The component model or the codegen check states which library kinds a core may link.
- The check names the component, its kind and the offending dependency, and exits non-zero.
- The check runs in CI, and a deliberate violation is shown failing before it is removed.
- ores.ore.core passes it.

* Plan

The rule lives in one table in the check, because the check is what enforces it:

| Kind a core links | Allowed |
|-------------------+---------|
| another component's =core= | no |
| another component's =service= | no |
| an =api= contract, or its own libraries | yes |
| anything that is not a component library | yes |

The check reads the =target_link_libraries= calls of every component's core
file, so it needs no configure step and no toolchain. It is a ratchet, like the
entity-write gate: the 37 edges that predate the rule are accepted in a baseline,
a new edge fails, and a baseline entry that no longer links also fails, so the
list can only shrink.

The codec must pass it, and did not: its core still declared
=ores.history.core.lib=, which no source used. The declaration was stale, and it
leaves the model rather than the generated file.

dependency that names a variable the templates do not use, and a core file that
states no name, are both failures rather than silence. Today every core is
scanned and every dependency is literal.

* Result

A build fails, and names the edge, when a component's core links another
component's core or service. The gate is
=projects/ores.codegen/scripts/check_core_link_edges.py=, its ratchet is
=core_link_edges_baseline.json=, and =.github/workflows/core-link-edges.yml= runs
it on every change to a component's CMakeLists, to the check, or to its
baseline.

It reads the CMake tree rather than the build, so it costs a fraction of a second
and needs no toolchain: the =target_link_libraries= calls are the declaration of
what a library links.

37 edges predate the rule and are accepted. The codec is not one of them: its
core still declared =ores.history.core.lib=, which nothing in its sources used.
That declaration left the component model, and the check now passes for
=ores.ore.core=.

The deliberate violation the acceptance asks for:

#+begin_example
ores.ore.core.lib: links ores.reporting.core.lib, which is reporting's core library.
A core may link another component's api contract, not its core.
1 core link edge(s) failed the check.
#+end_example

The gate's suite states what the parser must find and what it must not: another
component's core, another component's service, an api contract or its own
libraries, the shared =ores.service.lib= (which is not a component), a link named
only in a comment, a new edge, an accepted edge, a baseline entry whose edge is
gone, and an edge whose dependency names a variable the check cannot resolve.
The message names the component the dependency belongs to, not the one that
links it, and a case pins that too.
