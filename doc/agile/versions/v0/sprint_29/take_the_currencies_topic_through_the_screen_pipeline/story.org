* Goal

The second topic of [[id:C0D1A833-3E57-489A-A4D3-8C44266D3D6D][Screen pipeline topics]], currencies and pairs, goes through the
[[id:61C6B0A5-03A5-4424-8EA3-EE7E587629FD][screen pipeline runbook]]: the currency, the desk group, the currency pair and
the currency pair convention, with the classifications their pickers offer. The
currencies screen is the richest the web has, so the topic proves the runbook on
a screen that already conforms in most lines, and closes the gaps the
[[id:10ECDD95-0C8C-4BFF-A94A-FCBFAAC8F25A][record screen baseline]] and the currencies sign off sheet found on it. The Qt
import and export of currencies became, in the journeys step, the standard
Import and Export pair of the record screen standard, which this topic builds
first.

* Decisions

- The three journeys of the topic were judged on 2026-10-25 as CRUD
  variations of the standard record screen with links, a pair dialog with two
  groups and a derived key, and a members panel; no workflow. Signed off by
  the owner the same day.
- Every kind that ORE reads as one document exchanges it through one standard
  pair, /Import/ and /Export/, two buttons that call the server's three
  operations per document in the ORE component's namespace,
  =ore.v1.ops.export_<document>=, =preview_<document>_import= and
  =import_<document>=; no XML in the browser, bare verbs, Export where the
  document's scope is. Recorded as the Import and Export section of the
  record screen standard. Currencies prove the pair first (owner, 2026-10-25:
  "import and export sounds good, keep it simple").
- The earlier proposal to drop the import of one currency file is superseded
  by the pair.
