* Acceptance

- A seeded lookup holds the twenty-four collection kinds, each with its ORE
  element name and its key attribute or attributes, derived from
  =todaysmarket.xsd= with the command recorded.
- =todays_market_collection.collection= and
  =todays_market_configuration_binding.collection= refer to it, and an unknown
  kind is refused on insert.
- =todays_market_entry.key_attribute= is gone, and the today's market corpus and
  database round trips still pass.

* Plan

- The kinds are the children of the =todaysmarket= type in
  =external/ore/xsd/todaysmarket.xsd=, apart from =Configuration=: twenty-four.
  Each kind's entry element and key attributes come from the same file; two
  kinds, =SwaptionVolatilities= and =CapFloorVolatilities=, identify an entry by
  =key= and =currency=.
- =todays_market_collection_kind= is an analytics lookup seeded for the system
  tenant and readable by every tenant, as =pricing_engine_type= is. Both
  =collection= columns resolve against it under the system tenant.
- =key_attribute= only ever repeated the kind's attribute, and the export never
  read it, so it leaves the entry table and the mapper.
- The mapper keeps one branch per kind, because the binding gives each kind its
  own member. A test checks the mapper's twenty-four names against the schema,
  and the seed test checks the lookup against the same schema, so the two
  cannot drift apart.

* Notes

**Moved from [[id:1D039664-0DA4-40D5-BF7C-510BD11711F3][Seed the configuration lookups]].** Decided in the PR #2500
review. A today's market document has twenty-four collection kinds
(=YieldCurves=, =DiscountingCurves= and the rest). Today
=todays_market_collection.collection= and
=todays_market_configuration_binding.collection= hold the kind as free text,
and every =todays_market_entry= row repeats the kind's key attribute in
=key_attribute=. A seeded kind lookup would hold the kind code, its ORE element
name and its key attribute, or attributes for the two kinds keyed twice. Both
=collection= columns would then refer to it, and the database would refuse an
unknown kind. =key_attribute= could then leave the entry table.

One limit for this document: the binding gives each kind its own typed member,
so the mapper keeps one branch per kind whatever the lookup holds. The
acceptance line "no lookup value appears as a literal in mapper code" cannot be
met for today's market. The mapper can check its branches against the lookup
instead.
