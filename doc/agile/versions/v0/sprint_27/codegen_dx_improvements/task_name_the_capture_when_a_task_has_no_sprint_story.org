* Result

* Result

Delivered. =compass pr create= no longer refuses with the bare "No story.org
next to <task>". It now states that a task belongs in a sprint story, that a
backlog capture takes no task and no PR until it is promoted, and it names the
capture and the command:

#+begin_example
❌ doc/agile/product_backlog/next/task_record_where_the_arrival_process_plugs_in.org
   has no story.org beside it, so its story is not in a sprint.
   A task belongs in a sprint story: a backlog capture takes no task and no PR
   until it is promoted.
   Its story is the backlog capture 'stochastic-tick-arrival-times'. Promote it
   into the sprint first:
     compass capture promote stochastic-tick-arrival-times --to story
   then open the PR from the promoted story.
#+end_example

Resolving the capture needs two steps, because a capture is named after itself
rather than =story.org=, which is the whole reason the lookup failed. The
parent story is read from the task's =Parent story= row, falling back to its
first foreign id link =_parent_story_id=; the slug is then found by scanning
the backlog buckets for the file whose =:ID:= matches
=_backlog_capture_slug=.

Measured. The compass suite passes 13 tests, of which three are new: the
=Parent story= row, the fallback to the first foreign link, and the slug
lookup including the two negative cases (no id, and an id no capture carries).
The message above is the actual output of the command that previously gave the
bare refusal.
