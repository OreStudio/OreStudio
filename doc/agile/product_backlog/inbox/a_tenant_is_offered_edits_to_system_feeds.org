#+title: A tenant is offered edits to system feeds it cannot make
#+description: A tenant administrator sees Edit, Start, Stop and Delete on a system feed's page, and an editable Arrivals tab, but a save fails with a database error: the feed and its collection belong to the system tenant. The screens should offer a tenant what it may do on a system feed, which is to read it.

* What

Signed in as the Acme Corporation tenant administrator, the page of a system
feed (for example =synthetic.bloomberg.audaonia=) offers Edit, Start, Stop and
Delete, and its Arrivals tab is editable. Saving a change there fails with:
"Repository error: Executing INSERT failed: ERROR: Invalid config_id … No active
market_data_generation_config found with this id", raised by
=ores_synthetic_ir_curve_generation_configs_insert_fn()=. The same save as the
system administrator succeeds. Observed on 2026-10-28 while fixing the Arrivals
tab; the cause is inferred, not traced: the write runs under the tenant, and the
collection it names belongs to the system tenant.

* Why

System feeds belong to the system tenant, and the market switch and settings
already offer a tenant a read-only view. The feed pages do not: they compute
=mayWrite= from the tenant's permissions alone, so a tenant is shown controls
that the server then refuses, and refuses with a database message rather than
a permission. The fix is the same rule the market uses: a tenant reads a system
feed, and the page says so, while the server answers a tenant's write with a
forbidden rather than a trigger error.
