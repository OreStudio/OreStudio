The icon vocabulary for this interface, and the process for adding to it.

An icon set drifts when each screen picks its own. Two screens then use different
marks for one idea, and a third invents a fourth. This document exists so that
does not happen: the table below is the whole vocabulary, and adding to it is a
process with a checklist rather than a decision made at a call site.

The artwork is the 68 SVG files in
=projects/ores.web/packages/web/src/assets/icons/=. Every icon named below has a
file there. The [[id:6EF42145-CEE7-4035-806A-A4200A3E003A][Icon Guidelines]]
page carries the same set grouped for design use, and is the source of truth for
the artwork itself. The two specifications that once used it are superseded:
=entity_specification.org= describes entity screens that are deleted, and
=component_specification.org= now specifies the browser shell and the transport.

* 1. The system

One icon set: /Microsoft Fluent UI System Icons/. The Qt client also carried a
Solar set as an alternate theme; this interface does not, because supporting two
sets doubles the vocabulary for no gain. Fluent only.

/Naming./ Icons are =ic_fluent_{concept}_{size}_{variant}.svg=. Sizes are 16,
20, 32 and 48. The live set uses 16, 20 and 48, and carries the =regular=
variant only.

/Sizes./

| Size | Where |
|---+---|
| 16px | Inline with text, dense tables |
| 20px | Buttons, navigation, the standard action size |
| 32px | Headers, emphasis |
| 48px | Feature icons, onboarding, empty states |

/Variants./ Regular is the outline style, for passive states and secondary
actions. A filled variant would be solid, for active states, emphasis and
primary actions. The live set has no filled file.

/Colour./ Icons are monochrome and recoloured at use, not shipped in colour.

* 2. How the Qt client declared them

Historical reference. The Qt client is deleted from the tree, so nothing here
runs today.

An =Icon= enum in =IconUtils.hpp= listed every concept, alphabetically. A
=getIconDef()= function in =IconUtils.cpp= mapped each enum member to a
definition:

#+begin_src cpp
case Icon::Publish: return {"ic_fluent_arrow_upload_20", "upload-square.svg"};
#+end_src

The first string was the Fluent base name without the variant suffix; the second
was the Solar counterpart, which this interface does not use. In the port, one
table in the icon module replaced both. Commit =e47043269f= deleted that module
with the generated entity screens, so the set is a flat directory of SVG files
today.

* 4. Adding an icon

/In the Qt client (historical):/

1. Find a semantically appropriate icon in both sets, both variants.
2. Copy it into the Fluent directories, both variants. (In the Qt client,
   also the Solar directories; this interface uses Fluent only.)
3. Add it to =resources.qrc=.
4. Add an entry to the =Icon= enum, alphabetically.
5. Add the mapping in =getIconDef()=.
6. Use it through =createRecoloredIcon=.
7. Document it in the icon guidelines, in the right category.

/Here:/

1. Find the icon in the Fluent UI System Icons set, and confirm it is not
   already in the table under another name.
2. Copy the =regular= SVG file into
   =projects/ores.web/packages/web/src/assets/icons/=.
3. Add it to the table in this document, in the right category, with what it is
   for.

The artwork and the table are updated together. An icon added to the set but not
to the table is one the next person will not find, and will re-add under a
different concept.
