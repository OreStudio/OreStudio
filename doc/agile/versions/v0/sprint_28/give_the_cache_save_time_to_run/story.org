* Decisions

- The build step is capped rather than the job. A job-level timeout is
  already 360 minutes and cannot be raised, so the only way to keep room
  for the cache steps is to stop the build before the job limit is near.
- The cap is 320 minutes. Setup takes about eight and the cache work a
  few more, which leaves roughly thirty minutes of slack.
- The saving is deliberately given up on a run that is nowhere near the
  cache: the guard below it still refuses to replace a good entry with a
  small one.

* Out of scope

- The same cap for the nightly workflows. Their jobs have the same limit
  and the same shape, but they are not the ones blocking continuous.
