* Acceptance

- The nightly Windows matrix has the release buildtype only.
- =ci_health.py= does not expect a Windows debug cache.

* Plan

All five nightly Windows runs since 2026-10-15 failed, and every failure is
a compile error:

- msvc debug and release: C1202 in =rfl/internal/no_duplicate_field_names.hpp=,
  from =configuration_document_handler.cpp=.
- clang-cl debug: =-Winvalid-offsetof= treated as an error in the generated xml
  tables of =ores.ore=. The cause is a guess: the debug standard library
  probably makes those records non-standard-layout.
- clang-cl release, 2026-10-18 only: a dllexport redeclaration in a header
  that no longer exists.

The Windows legs have no compiler cache, so the four legs take 5 to 8 hours.
Dropping the debug legs halves the matrix and removes the offsetof error with
them, if the guess about the debug library is right. The release legs still
have to pass on their own.
