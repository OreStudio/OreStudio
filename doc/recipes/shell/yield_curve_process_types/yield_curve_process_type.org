#+title: How do I run the yield_curve_process_types commands from the shell?
#+description: Every command the yield_curve_process_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:yield_curve_process_types:

This file documents the yield_curve_process_types resource at the shell, one section per command. Every command is a subcommand of =yield_curve_process_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: B2591FCE-9B04-5752-B93D-827F11D4BAA0
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
yield_curve_process_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =synthetic.v1.yield_curve_process_types.list=.

#+name: yield_curve_process_types-list
#+begin_src ores-shell :tangle yield_curve_process_types-list.ores :exports none
yield_curve_process_types list --limit 1
#+end_src

** =add=
:PROPERTIES:
:ID: 6F643C13-8E4C-5D89-ACD2-E7257B026F35
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
yield_curve_process_types add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =synthetic.v1.yield_curve_process_types.put=.

#+name: yield_curve_process_types-add
#+begin_src ores-shell :tangle yield_curve_process_types-add.ores :exports none

#+end_src

** =set=
:PROPERTIES:
:ID: EF19E8EE-5CAA-54A3-BD24-0F9B48AE0CD0
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
