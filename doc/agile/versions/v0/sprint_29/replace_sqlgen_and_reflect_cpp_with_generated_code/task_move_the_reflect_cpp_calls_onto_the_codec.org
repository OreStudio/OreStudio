* Goal

Step 2 of 7 of the removal, and the second of its three codec steps. Every
hand-written read and write of a type with a stated shape goes through
=ores::utility::codec=, so no hand-written call encodes or decodes such a type
through reflect-cpp. The dynamic JSON, the JSON schemas and the =wire_traits=
fallback stay for steps 3, 4 and 5, and Notes names each one with the file
that owns it.

* Acceptance

- Every =rfl::json= or =rfl::msgpack= call in hand-written production code that
  encodes or decodes a type with a stated shape goes through
  =ores::utility::codec=. A test keeps reflect-cpp as the reference the codec
  has to agree with, until step 5 deletes it.
- A read that reported reflect-cpp's error reports the codec's, or hands the
  caller the reason where the caller reports one.
- The calls the removal's plan keeps for steps 3 to 5 are named in Notes, each
  with the file and the step that owns it.
- The tree builds and every suite passes.

* Plan

The templates move first, because every generated file follows them: the
domain JSON, shell command and operation, HTTP route and convention family
templates write and read through =ores::utility::codec=, and a route reads its
body and writes its response through =wire_traits= whatever its model states.

Then each hand-written call moves, component by component. A read becomes
=codec::json::read= where the caller wants the value or an exception, and
=read_expected= where the caller reports the reason it could not decode. A
document a person writes by hand keeps the defaults of the members it leaves
out through =read_lenient=.

A template cannot see the shape of every type it encodes, so a unit that
encodes one includes its =*_codec.hpp=: that header is what states the shape.
A struct hand-written code encodes states its own =wire_fields=, with a static
assert that fails when a member gains no name.

**The calls that stay, and the step that owns each.** The plan of

dynamic JSON onto yyjson, step 4 generates the schemas, step 5 deletes the
reflect-cpp primary of =wire_traits=.

The router's two calls generate a route's JSON schema; the examples the same
routes state are written by =wire_traits= now, so the schema is all that is
left there.

**The goal was written before the plan divided the work.** This task was
scaffolded with one line, "No hand-written code calls rfl::json or
rfl::msgpack", and the plan then gave the dynamic JSON to step 3, the schemas
to step 4 and the fallback to step 5. The goal above states the boundary the
plan draws instead of a line the plan makes unreachable here, and the table
above is the whole of what crosses it.

**A recipe a person writes keeps its defaults.** =trade_generation_step_arguments=
is read from a document a profile holds, which states only the members it
cares about. reflect-cpp read it with =rfl::DefaultIfMissing=; the codec
refuses a missing member, because a message that omits a field is a mistake
the wire should report. =read_lenient= is the exception: for the length of that one read, every member
the text leaves out keeps its default at any depth, which is what a
hand-written document's silence means.
=messaging_provision_step_arguments_tests.cpp= keeps its case that omits
=description=, =structures_per_book= and =trade_type_codes=, and
=codec_json_tests.cpp= pins the strict read that still refuses them, before and
after a lenient one.

**Five models state the facet here, and not in step 1.** Step 1 gave a shape
to every type a hand-written call encodes. This step finds five more that only
the codec reaches: the four refdata convention families and the trading
junction, whose rows the family packer now writes and reads through
=json::write= and =json::try_read=. The packer has no shape to write without
the facet, so the facets are turned on here and their protocols, codecs and
roundtrip tests follow. That is most of the two thousand generated lines this
diff adds that are not a mechanical replacement.

**The unit budget entry for =conventions_diff.cpp= goes.** The entry existed
because that unit reflected the convention families. It writes and reads their
rows through the codec now, so =check_translation_unit_budget.py= no longer
needs the allowance, and the guard is smaller by one entry.

**One vector printer, two ways to write an element.** =std::vector='s
=operator<<= exists so a test framework can print an expected value it does
not match. It writes a JSON array through the codec when the element has a
stated shape, and otherwise writes each element through its own
=operator<<=. The second branch is load-bearing: a framework that prints its
own range gives a better message than a compile error, and the constraint
keeps that fallback for an element that neither the codec writes nor prints
itself.

**The reference stays until the dependency goes.** The codec tests compare the
generated bytes with =rfl= in both formats, which is what the story's "the wire
format does not change" criterion rests on. They keep reflect-cpp until step 5,
together with the =wire_traits= primary, so the comparison has a reference.

**Three tests the rebase put back.** The vector printer's constraints were
written when the marketdata datum codecs lived in =ores.marketdata.core=, so the
replayed commit restored that include path in three tests after main had moved
the codecs to =ores.marketdata.api=. The three files are main's again, and the
branch changes nothing in =ores.marketdata= except the corpus import test.

* Result

The hand-written reflect-cpp calls are on the codec. 83 call sites in 32
production files become 14 in 6, and each of the 14 is the site a later step
owns, listed above. The five protocol codecs and the two domain codecs the move
needs are generated from their models with their roundtrip tests.

The gate ran at the tip the review was answered on: the build succeeded, 97 of
98 suites passed, and =ores.marketdata.service.tests= was the one failure — it
passes when run alone, so it is a timing fault in the suite. Five checks failed,
and every file they name is byte-identical to main: =component-drift= (7
files), =unity-collisions= (=ores.synthetic= tests), =er-diagram=,
=money-decimal-columns= and =bff-list-requests= (=instrument_underlying='s list
requests). The gate's =ticks-smoke= step also failed, and deterministically: it
books a bond whose =bond_issue_call_date= the run already stored, because the
planner in =ores.synthetic= books two rows for one issue, and this branch
changes no file in that component.

The branch then rebased onto =f9efe3b6e2=, where main had moved the HTTP layer
and two of the templates this task touches. The build succeeds there, all 97
suites that finished passed, and =ores.marketdata.service.tests= — the one
still running when the run was stopped — passes when run alone. Every suite is
green on the rebased tree, and =tangle-templates=, =cmake-sources=, =format= and
=component-drift= were re-run there: the first three pass, and the fourth names
only files that are byte-identical to main.
