* Goal

A step that gives up reports the party and the item it was working on, the request it made, the number of attempts and the reason. The transport's own words stay, as the reason. A person reading the run, in either client, can tell what failed without reading a service log.

* Acceptance

- A step that gives up names the party and the item it was working on.
- The report states the request and the number of attempts it took.
- The transport's own words stay, as the reason.
- A test asserts the message for a refused request and for one that timed out.

* Plan

- The retry helper already composes the report as
  ="<work> failed after N attempts: <reason>"=. This task states what each step
  passes as the work, so the report names the party and the item, and proves
  the composition.
- The reason is the transport's own words: a timeout names the subject and the
  deadline it waited, and a refusal names the subject and the code the server
  returned. Neither is replaced.
- A test asserts the composed message for a timeout, with the party, the item,
  the attempts and the subject, and for a refusal, with the server's reason.
- The aggregate failure path, where a step fails with a list of the items it
  could not finish, already names the party and the item on each line.

* Result

* Result

A step that gives up now reads as a report, not as a transport string. The
retry helper composes it, and each step states the work in a person's words:

| Step | What the report names |
|------+-----------------------|
| Surface calibration | =ACME: EUR/USD surface calibration failed after 3 attempts: ...= |
| Surface publish | =ACME: EUR/USD surface publish failed after 2 attempts: ...= |
| Forward set | =ACME: EUR/USD forward set failed after 3 attempts: ...= |
| Curve bootstrap or publish | =publish_party_curves ACME: EUR-1D curve bootstrap failed after 3 attempts: ...= |
| Holiday calendars | =the holiday calendars failed after 2 attempts: ...= |

The reason is the transport's own words and is not rewritten:

- A timeout reads =NATS request timed out: no reply from '<subject>' within
  <n> ms=, so the request is named.
- A refusal reads =Request to <subject> rejected by server: <code>=, so the
  server's reason is named.

The aggregate path, where a step lists the items it could not finish, already
names the party and the item on each line.

Two cases pin the composition: "A step's failure names the party, the item and
the attempts" asserts the party, the item, the attempt count and the subject;
"A refusal is thrown at once, with the server's reason" asserts the server's
code and the single attempt.
