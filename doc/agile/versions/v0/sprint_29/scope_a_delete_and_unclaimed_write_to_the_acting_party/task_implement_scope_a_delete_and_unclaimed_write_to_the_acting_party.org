* Goal

A write or a delete from a session that sees several parties acts on the acting party's row of the key, and only on that row. The repository makes the choice where it reads, so the service needs no filter after the read.

* Acceptance

- read_latest by key prefers the acting party's rows, with the rule of_acting_party() has today: keep only the acting party's rows when one exists, otherwise keep the rows as read.
- remove checks the version of the acting party's row and closes only that row: the delete names the party of the row it checked.
- A write with no precondition states the version of the acting party's row.
- The service template drops of_acting_party(); the helper and its tests go if nothing else uses them.
- A test proves from a parent party that a delete and an unclaimed write of a convention key touch only the acting party's row.

* Plan

The 27 entities whose =party_id= is a =:sql_key:= column hold one row per id and party, but the repository takes the id alone. Codegen justified that with "row level security already confines a session to its own rows", which is false: a parent party sees its subsidiaries' rows.

1. Codegen derives =primary_key.party_sql_key= and =primary_key.party_member= (the party's path, =identity.party_id= on a grouped row).
2. The repository's =read_latest(ctx, key)= keeps the acting party's rows when one exists, and otherwise the rows as read, so another party's row can still be found by its key. =replace_claim= and the unclaimed write read through it.
3. =remove= deletes by the party of the row it checked, and its read-back looks for that party's row only. The table's delete rule closes =OLD.party_id='s row, so the party filter is enough.
4. The service template drops =of_acting_party()=; the helper and its tests go. The services are again byte-identical to main before the hotfix.

* Result

A parent party's session reads, writes and removes its own row of a convention key. The repository template, through =primary_key.party_sql_key=, prefers the acting party's row in the key read and closes only the checked party's row in a removal. That covers the 24 refdata conventions and the 3 engine settings tables. The service template and services are back to their form before the hotfix, and =of_acting_party()= is gone.

Proof: =ores.refdata.core.tests "[acting_party]"= passes 6 of 6. Against main's repository, 4 of them fail: a false version conflict on an unclaimed write, two removals that report conflicting, and a key read that returns 2 rows. =test_sql_key_column.py= passes 6 of 6.
