* Goal

A screen that breaks the UX language fails a test that names the rule identifier. The harness discovers the screens from the registries, so a new record kind is checked without a new test.

* Acceptance

- The harness discovers the record kinds from REFDATA_RECORDS, the classification catalogue and the convention kinds.
- Each checkable rule has one check, and a failure reports the rule identifier and the screen.
- The tests the Allium specification propagates are included or the gap is stated.
- The harness runs in CI against a started environment, or the reason it cannot yet is recorded.

* Plan

Discover the screens from the registries the BFF reads, REFDATA_RECORDS and
CLASSIFICATION_LISTS, through the wire-protocol package, with a hand table of
routes that refuses a kind it does not place, so a new kind is checked or
stopped and never skipped in silence. Sign in once in a setup project and reuse
the session, because a sign-in per check would cost more than the checks. Write
one test per structural rule the audit named as machine checkable, over the
list, the record page and the Edit dialog, titled by the rule identifier with
the screen in the describe, so a failure names both. Where a row opens no page,
skip the record checks with the reason and let the list check report it. Add a
JSON report and a script that folds a run into the table of rule against
screen, so the baseline task reads the run and not the log.

* Result

The harness checks every record screen the registries name: 32 screens, 21
checks each over the list, the record page and the Edit dialog, each test
titled by the rule identifier it asserts. A full run takes 19.9 minutes with
four workers and reports 477 passed, 67 failed and 128 skipped. The
failures are the screens' and not the checks': record pages and classification
lists draw no Refresh and no load time, every dialog lacks its loaded-at time,
dialogs are titled by the key and not the display field, classification row
pages have no lead line, and five read-only lists open no row page. The JSON
report feeds =scripts/harness_baseline.py=, which the baseline task uses. The
harness does not run in CI yet: it needs a started environment with Acme
provisioned, and no workflow starts one; the baseline task records that gap.
