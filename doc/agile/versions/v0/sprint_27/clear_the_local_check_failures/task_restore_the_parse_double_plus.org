* Acceptance

- The marketdata api and core suites pass.

* Plan

Find who reads a plus before changing the parser. =value.cpp= calls
=decimal= "the estate's one definition of a number", and
=strike_label::parse= reads =+25RR= through it, so the parser is right to
take a plus and the gate that refuses one is the exception. Put the strict
rule where the contract lives, not in the shared grammar: =is_number= is a
spelling gate for text stored as stated, and it can say so in one line.
Correct the shim's documentation, which claimed =from_chars=' contract
while the estate's grammar is broader.
