* Acceptance

- =marketdata= is in =REGISTRY= in =check_handler_permissions.py=, and the gate passes.
- All 17 codes the handlers check are seeded. Codes no handler checks are removed or given a handler.
- Each role that calls a marketdata handler holds the code it needs, without the =marketdata::*= wildcard. =SyntheticService= is checked against what it calls.

* Plan

Decide one spelling per code (the handlers use =market_series=, the seeds use
=series=), then seed and grant.

The handlers' spelling wins, because the generated handlers write it from the
entity's plural and every other component's codes follow the same rule. So:

1. Add =marketdata= to =REGISTRY= in =check_handler_permissions.py= and let the
   gate list what is missing.
2. Seed each code a handler checks, and remove each seeded code no handler
   checks.
3. Map every caller outside the component to the handler it calls, and grant
   each service role the codes those handlers check.

** Decisions

- =MarketdataService= keeps =marketdata::*=. Every service role holds its own
  component's wildcard, and the service is the handler, not a caller of it.
- =marketdata::observations:read= stays under its old name. It is the one code
  the ORE export checks, and it reads every series, observation and fixing; the
  seed's description now says so.
- The six seeded codes no handler checked are removed, and so are
  =SyntheticService='s four grants of them.

** Found here, not fixed here

The handler for =marketdata.v1.series.export-to-storage=, in
=market_series_handler.hpp=, checks no code: any authenticated caller can write
every series, observation and fixing of its tenant to object storage. It is the
class of gap capture =CCB1D9D1= describes, an operation handler the gate cannot
see checking nothing, and it is recorded there.
