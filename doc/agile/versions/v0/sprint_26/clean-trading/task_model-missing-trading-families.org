* Plan

** 1. Bind the unbound entities

Choose a profile or record a no-match for each of the 26. The bond
family is the large group: =bond_issue= and its children are shared
static data rather than per-trade records, so a profile built for a
per-trade instrument is the wrong bind, and a forced nearest bind is not
allowed. Where no profile fits, record the entity's actual feature
values and the reason, as item M02 requires.

** 2. Author the nine missing models

Eight tables have a table, a repository, a service, a handler and SQL, and
no model at all: =activity_types=, =fpml_event_types=, =commodity_instruments=,
=composite_instruments= with =composite_legs=, =credit_instruments=,
=scripted_instruments=, and the shared =swap_legs= table. =product_type=
is the ninth, and its current shape is a database enum on the trades table
rather than an entity, which is defect 10.

Use the established entity org format. The bond family from the sprint
25 pilot is the worked example. =swap_legs= is decided: D10 on the story
fixes one model over the shared table, not one per family.

** 2a. The profiles the nine new models bind

The nine are new entities, so M02 applies to them too. The decision per
group, taken from the table's own columns and the profile's assignment
table:

- =commodity_instruments=, =composite_instruments=, =credit_instruments=
  and =scripted_instruments= bind =trading-instrument=. Each is an
  instrument sub-type with the same scope as the nine already modelled:
  tenant, workspace and =party_id=, no presentation tier.
- =composite_legs= and =swap_legs= bind =trading-instrument= as well.
  They carry the same tenant, workspace and =party_id= scope; a profile
  fixes variability, never structure, so a leg child over the same scope
  takes the same bind. D10 fixes their shape as one model each.
- =activity_types= and =fpml_event_types= bind =simple-lookup=. Both key
  on a text =code=, are tenant-scoped, carry no workspace, and have a
  shell surface, which is exactly the profile =country= anchors and what
  =trade_type=, =party_role_type=, =lifecycle_event= and =trade_id_type=
  already bind in this component.
- =product_type= is deferred to the defect 10 analysis. It is not a table
  today: it is an enumeration on the trades table, so authoring it as an
  entity is a schema change with a data migration, not a transcription.

** 2b. The commodity port, and the environment blocker

The commodity family is ported end to end in the tree: the model (450

** 2c. How the model was authored

One focused pass. The model comes from four sources: the create script
=projects/ores.sql/create/trading/trading_commodity_instruments_create.sql=
for its columns, indexes and checks; =equity_position_instrument.org= for
the format, since it is an instrument sub-type of the same kind; the
hand-written domain type for the field groups and the C++ type behind
each column; and the loader for any property whose spelling was in doubt.
It binds =:profile: trading-instrument=, like its nine modelled siblings.

The regeneration changes twenty-one existing files and creates thirteen.
The twenty-one are the hand-written stack, which becomes generated: the
domain type, JSON I/O, table and table I/O, the entity, mapper,
repository and service, the handler and the event registrar, the create
and notify-trigger scripts and the drop script.

The domain type is the significant change. It was decomposed into
=commodity_terms=, =commodity_option=, =commodity_pricing= and
=commodity_exotic= sub-structs, reached as =v.terms.= and so on. The
model converges it to the canonical shape its nine modelled siblings
have: =instrument_identity= plus flat optional blocks. Four files read
the nested shape and move with the model:

- =projects/ores.ore/service/src/messaging/ore_import_execute_handler.cpp=
- =projects/ores.ore/core/src/domain/commodity_instrument_mapper.cpp=
- =projects/ores.ore/core/tests/xml_commodity_mapper_roundtrip_tests.cpp=
- =projects/ores.shell/application/src/app/commands/trading/commodity_instrument_commands.cpp=

Nothing else in the tree names the nested types, and no other file reads
=.terms=, =.pricing= or =.exotic= in a commodity context.

What this means for the seven that remain: =composite_instruments=,
=credit_instruments= and =scripted_instruments= are instrument sub-types
and take the same model, regeneration and consumer migration.
=composite_legs= and =swap_legs= are children over the same scope, and
=activity_types= and =fpml_event_types= bind =simple-lookup= instead.
Authoring the model is the cheap part, one pass from sources already in
the tree; migrating the consumers and proving the regeneration is the
work, and each family carries its own two to four consumers.

** 5c. What the date unit found on the way

Two generator defects and two shared root causes, each fixed at its
source with a test rather than worked around:

- The generator knew dates only as keys and timestamps. A plain date
  column put the domain type into the sqlgen entity, which its parser
  rejects with a static assert, and the history field mapper dropped the
  field. The projection and its regression test are committed.
- A grouped column's write record is text while its domain member is
  typed, so the generated service emitted an assignment between them and
  did not compile. The conversion and its regression test are committed.
- =from_iso8601_date= rejected the ISO 8601 basic form. The ORE corpus
  states 32 dates that way, and the six ORE mappers and the planner threw
  on them. The parser now accepts both forms.
- The =year_month_day= reflector wrote the default-constructed sentinel as
  =0000-00-00=, which its own parser rejected, so a default date could not
  survive a JSON round trip. That is what failed the instrument payload
  variants and the bond future export, and it is why the earlier attempt
  at this defect looked like a type regression. The sentinel is now the
  empty string.

** 5d. What the decimal unit found

- =numeric(28, 10)= holds at most eighteen integer digits. The type holds
  a wider value exactly, and the store refuses it with
  =numeric field overflow=; the repository test pins that refusal rather
  than hiding it. Every money column is =numeric(28, 10)= or
  =numeric(18, 10)=, so the ceiling is the schema's, not the type's.
- =bond_leg_amount.value= carries all six amount roles, so its =rate= rows
  move to the decimal with its =notional= rows. "Rates stay double" is a
  statement about a column's role, not about a column, and this table
  cannot honour it without normalisation. The model records the finding,
  and D12 and D13 own the shape that would fix it.

** The child that landed: =equity_position_option_underlying=

The ORE schema states an equity option position's members in
=equityOptionPositionData=: a required =Quantity= and an unbounded
=Underlying= list of =equityOptionUnderlyingData=, each of which is a
shared =underlying=, an =optionData= and a =Strike=. The column claimed to
hold that list as serialised text and nothing ever wrote it: the mapper
had no dispatch for =EquityPosition= or =EquityOptionPosition= at all, and
the corpus path is a =TotalReturnSwap= whose =UnderlyingData/SubTrade= is
an =EquityOptionPosition=. The producer is now wired, so the payload's
shape comes from the document rather than from the column's own
description.

| Decision      | Value |
|---------------+-------|
| Table         | =ores_trading_equity_position_option_underlyings_tbl= |
| Key           | =(tenant_id, instrument_id, sequence_number, valid_from, valid_to)= — the parent id plus the entry's ordinal, the shape the two children above use |
| Parent        | =instrument_id= references the equity position instrument. The component declares no SQL foreign key yet (defect 7), so the reference is the column and its prose, as in =bond_leg= |
| Scope         | =has_tenant_id: true= only. The child rides the instrument's tenant, workspace and party, so no workspace column rides it |
| Natural key   | none; the ordinal is the identity |
| Audit/validity| the template's audit columns and the bitemporal =valid_from=/=valid_to= pair with the exclusion constraint |
| Quantity      | stays on the parent: it is a property of the position, not of one entry |
| Columns       | =sequence_number integer not null=, =underlying_name text not null=, =strike numeric(28, 10) not null=, =weight numeric(28, 10) null=, =long_short text not null=, =option_type text null=, =exercise_type text null=, =settlement_type text null= |
| Strike type   | =ores::utility::decimal::decimal= — a strike is money-role (D11), and the ORE element is a float |
| Weight type   | =std::optional<ores::utility::decimal::decimal>= — a weight is money-role (D11) and the shared =underlying= type makes =Weight= optional, so an absent weight stays null |
| Option terms  | the corpus entry carries =LongShort=, =OptionType=, =Style= and =Settlement=, so each has a column; the names follow =equity_option_instrument= |
| Checks        | ="sequence_number" > 0=, ="underlying_name" <> ''=, and the generated nil-uuid check |

The one value this child does not carry is the entry's exercise date
list. The corpus states =OptionData/ExerciseDates/ExerciseDate= as a
list, so a single date column would silently drop the rest of it. The
list is a collection of its own, and defect 16 (no observation schedule)
owns the shape that models it. The omission is recorded rather than
papered over with a truncated scalar.

The producer is =equity_instrument_mapper::forward_equity_option_position=,
dispatched from =trade_mapper::map_equity_instrument=. A
=TotalReturnSwap= (or =ContractForDifference=) whose underlying sub-trade
type is =EquityPosition= or =EquityOptionPosition= is dispatched to the
same family, so the nested corpus path reaches the producer. The forward
mapper reads every =Underlying= entry in document order and emits one row
per entry. The reverse,
=equity_instrument_mapper::reverse_equity_option_position=, rebuilds
=EquityOptionPositionData= from the rows and wraps it back inside the
=TotalReturnSwap= it came from. =EquityPosition= (the plain position, no
option terms) is dispatched too, and produces the parent row with no
children: its entries carry no strike or option data, so they cannot be
rows of this table. That gap is defect 15's multi-underlying shape.

The corpus does exercise the producer.
=xml_equity_mapper_roundtrip_tests.cpp= loads
=Hybrid_GenericTRS_with_EquityOptionPosition.xml=, maps it, asserts both
entries' names, strikes, ordinal, weight and option terms, then reverses
and asserts the same values in the rebuilt document.

** Judgement calls

- D12 is followed literally: a child entity per collection. The defect
  page's shared schedule table is recorded as the later generalisation.
- A column with no producer gets no invented child. The task requires the
  payload's shape to come from the real data.
- =basket_json= on =equity_swap_instrument= waits for defect 9 so that
  its removal cannot weaken the XOR assertion.
- =knock_out_dates_json= gets no child because the ORE schema states no
  knock-out date list; the finding is recorded instead of invented.
- The commodity producer is written for =CommodityBasketOption=, the
  first basket product dispatched. The other two basket products are
  recorded as remaining rather than half-wired.
- =commodity_instrument_data= is a new carrier struct rather than a reuse
  of =with_legs<>=, because a constituent's parent reference is a direct
  =instrument_id= column (the callable child's shape) and not a grouped
  =identity.instrument_id=, so =with_legs='s =stamp_ids= does not apply.
- The equity position carrier wraps the whole =equity_instrument_variant=
  rather than one leaf, because nine equity leaves share the family and
  only the position leaf states entries. The wire shape is then per-leaf,
  as the rates family does for its legs and call dates.
- The equity position producer reads the nested =UnderlyingData/SubTrade=
  shape a total return swap uses, not only the top-level
  =EquityOptionPositionData= element. =ContractForDifference= keeps the
  composite dispatch it had: its reverse rebuilds a different data member,
  and intercepting it made =Hybrid_CFD.xml= unreadable on export.
- The equity entries verb is hand-written in =ores.shell/application=
  rather than a template hook. A hook would change a template every
  component's shell unit is rendered from, for one family's child; the
  hand-written verb mirrors the commodity basket precedent and is one
  file pair.
- A plain =EquityPosition= sub-trade is dispatched, so its parent row is
  produced, but it gets no child rows: =equityPositionData.Underlying= is
  a bare =underlying= list with no strike and no option data, which this
  table's not-null columns cannot hold. That multi-underlying gap stays
  defect 15's.
- The entry's exercise date list is not modelled, and no single-date
  column is invented. The round trip asserts the entry values the mapper
  used to drop; the dates are the one value it still does not carry, and
  defect 16 owns the observation schedule that would.
