This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

The desktop client wrote =currencyconfig.xml= itself, with the ORE exporter linked into its binary. A browser cannot. =refdata.v1.calendar_adjustments.export= returns the adjustments and leaves the caller to write the =CalendarAdjustments= document. Add operations that return the documents, so a screen can offer the export.

Decided 2026-10-25, in the currencies topic of the screen pipeline: the operations live in the ORE component's namespace, one triple per ORE document, =ore.v1.ops.export_<document>=, =preview_<document>_import= and =import_<document>=, in the shape of =ore.v1.ops.export_run_configuration=; the screens draw them as the standard Import and Export pair of the [[id:2BF7F03F-6BF4-45FF-8E26-4D3B4E2D943D][Record screen standard]]. The build task of [[id:F211A600-B482-4C76-B4EF-2FFE1FDEB8EB][Take the currencies topic through the screen pipeline]] added the currency configuration triple on 2026-10-25; the calendar adjustments and the other documents follow it, each declaring its document to the shared =OreExchange=.

* Why

The currency and calendar journeys both offer an ORE exchange that the web screens cannot provide yet.
