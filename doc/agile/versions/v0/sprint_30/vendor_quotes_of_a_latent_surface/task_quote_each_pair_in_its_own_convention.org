* Acceptance

- The feed reads each pair's ATM type, delta type, risk-reversal favour and butterfly style from its FX option convention.
- A pair whose convention switches delta type at a tenor quotes each expiry in that expiry's type.

* Plan

The feed quoted every pair in spot delta, delta-neutral ATM and smile
butterflies. The stored conventions of all 14 surface pairs quote broker
butterflies, ten quote premium-adjusted deltas, and most switch delta type at
2Y (USDINR at 7Y). A party calibrating in its pair's convention therefore read
the vendor quotes with the wrong meaning.

- The data shape: the feed's build input carries the pair's
  =fx_option_convention= row, not one quoting convention. The emitter holds one
  quoting convention per expiry, which the generator already quotes each slice
  in.
- The mapping is reference data's =to_quote_convention=, the one the
  calibration plan and the derived source use, so the three cannot disagree.
- The registry reads the row named =BASE-QUOTE-FXOPTION=, as the derived source
  does, and skips a surface whose pair has none, naming it.
- The proof is the round trip: a row that switches from Spot to PaFwd inside
  the surface, with broker butterflies, and a calibration that reads each
  expiry's convention from the same row. A mutant that quotes every expiry in
  the first convention must fail it.

* Result

Each latent surface now quotes each expiry in the convention its pair's stored
FX option convention states for that tenor: its ATM type, delta type, switch
tenor, risk-reversal favour and butterfly style. The mapping is reference data's
=to_quote_convention=, the one the calibration reads, so a party reads a vendor
quote with the meaning the vendor quoted it in. A pair with no stored convention
is refused and named. All 14 surface pairs tick on the fleet with their own
conventions.
