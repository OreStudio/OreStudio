#+title: Find why ninja's state is truncated after every build
#+description: Each compass build in brave_hopper starts with ninja's premature end of file warning and rebuilds from scratch, so every build costs a full compile.

This page is a [[id:671F18E4-E09C-4B3B-BD24-D33DF8AE38A6][capture]] in the *inbox* bucket of the product backlog — a pre-sprint idea, not yet pulled into a sprint as a story.

* What

On 2026-11-02, every =./compass.sh build -j5 -k 0= in brave_hopper started with
=ninja: warning: premature end of file; recovering= and then rebuilt all 1111
steps. The warning means =.ninja_log= or =.ninja_deps= ended mid-record, so ninja
lost the record of what it had built. One log ended at =[1110/1111]= with no
final step and no "build stopped" line, which suggests ninja stopped before it
finished writing its state. Find what stops it, and fix that.

Leads, none confirmed:

- compass runs =cmake --build= in a systemd scope under
  =app-build-brave_hopper.slice=, with MemoryHigh 8 GiB and MemoryMax 12 GiB.
  A kill at the cap, or the scope ending before ninja exits, would truncate
  the state. The user journal for the afternoon shows no OOM line.
- Raw =cmake --build= runs from an agent session, outside the compass lock,
  could overlap a compass build in the same directory. This explains one
  truncation, not every one.

* Why

A truncated state turns every incremental build into a full one. Since #4392,
precompiled headers skip the compiler cache, so the dependent objects also
miss it, and a full rebuild is a real full compile.

* References

- PR #4392: precompiled headers outside the compiler cache.
- =build/output/<preset>/.ninja_log= and =.ninja_deps=.
