A byte range within a rendered value. It is never stored: it is a member of a
diff entry and reaches a client inside a history response.

This model does not yet replace the hand-written
=projects/ores.diff/include/ores.diff/domain/diff_span.hpp=, and generating it
overwrites that file. Two things stand in the way, both recorded on the
[[id:60D7964C-49DB-485B-B4FF-D0DA68B2E7FA][Table-less record]] profile: an audit
=recorded_at= member that no profile feature suppresses, and a profile that
cannot reach =:no_audit_columns:= at all. Fix those before adopting this model as
the real declaration of the type.

* Flags
:PROPERTIES:
:schema:          public
:product:         ores
:component:       diff
:no_primary_key:  true
:profile:         table-less-record
:END:

=No primary key=: a byte range identifies nothing. Saying so is what tells the
loader this is a record that is carried rather than stored.

* C++

** Flags
:PROPERTIES:
:no_subcomponent: true
:END:

=No sub-component=: =ores.diff= keeps its headers at its own include root, so
there is no directory between the component and =domain/= for this model to
name. The flag stands where =:subcomponent:= would, because it says the same
thing by negation.
