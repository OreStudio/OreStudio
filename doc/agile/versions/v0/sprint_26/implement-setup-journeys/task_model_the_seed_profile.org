* Notes

- *Binding.* The three models bind =uuid-identified-lookup=, the profile
  =ores.iam.tenant= binds, plus =:system_scope: true=. =uuid-surrogate-lookup=
  fixes =system_scope= to false, which platform-owned registered data cannot
  be, and the model-drift gate refuses the contradiction.
- *Whole-table ownership.* =:system_scope:= leaves =tenant_id= out of the
  primary key, which is =(id, valid_from, valid_to)=, so the profile's unique
  index is on =code= alone and the insert trigger forces the system tenant. The
  children's composite index still carries =tenant_id=, because the template
  adds it for a natural key even when the tenant is out of the primary key.
- *Pre-existing failures met on the way.* Both are captures in the inbox:
  the =entity_org= scaffold writes a =* Primary key= heading the entity loader
  does not read, and the generated shell =get=, =delete=, =versions= and
  =version= never read a minted UUID key.
- *Live-database grants.* The three tables were applied to the live database by
  hand, ahead of the create aggregator, so the rw role and the iam service user
  needed the grants re-applied by hand before the writes and reads answered. A
  =compass db recreate= covers both through the schema's default privileges and
  the prefix-matching service grant script; nothing in the repository needed
  changing for it.
- *Orphan rows from the generated tests.* Each child's generated eventing test
  writes its parent profile and does not delete it. The two synthetic profiles
  the tests left active were soft-deleted from the live database after the run.

profiles are rows. =projects/ores.iam/modeling= gained
=ores.iam.seed_profile=, =ores.iam.seed_profile_step= and
=ores.iam.seed_profile_parameter=, bound to =uuid-identified-lookup= with
=:system_scope: true= so every row belongs to the system tenant.

=projects/ores.sql/populate/iam/iam_seed_profiles_populate.sql= seeds
*Empty operational* (three steps: =publish_bundle= of =base=,
=import_lei_hierarchy=, =provision_party= of =party_essentials=; two
parameters: the counterparty count and the GLEIF root LEI; no prefilled tenant
details) and *ACME demo* (all six step kinds, the root LEI
=9695ACMEGROUP0000030= in the import's arguments, =base= together with
=risk_management=, the tenant details and the tenant administrator's identity
prefilled, and no parameters). The script is idempotent: a second run inserts
nothing.

shell's IAM aggregator carries the three command units, so the SQL, C++,
TypeScript, shell and CMake surfaces all exist and all build.

The read subjects answer. Measured in one authenticated shell session against
the live service, which is the whole chain: NATS subject, handler, service,
repository, database.
