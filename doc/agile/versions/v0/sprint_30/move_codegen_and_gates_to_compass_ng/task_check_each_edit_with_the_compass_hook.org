* Acceptance

- The hook is in the tangled settings, not hand-edited JSON.
- It is turned on only after the baselines are inline exceptions; before that it reports findings that were in the file before the edit.
- A memory or recipe says to run a full compass check after a pull or a rebase, because the hook trusts the last check's record.
- Hook time is recorded on a loaded machine: 0.5 to 0.6 s at load 34 in the pilot.

* Result

- claude_code_settings.org adds a PostToolUse hook on Edit, Write and
  MultiEdit that runs compass-ng hook, behind a guard that exits 0 on a machine
  without compass-ng; the settings tangle to it.
- The wait on the baselines is gone: compass-ng d2c6595 and later report only
  findings the last check did not record. On main, an edit to
  publish_service.cpp, which carries a recorded entity-writer finding, adds
  context and does not block (0.61 s); an edit that plants a duplicate index
  in refdata_currencies_create.sql blocks with the two findings it caused,
  sql_hygiene/duplicate_index and codegen/drift (1.17 s), with the machine
  otherwise idle.
- The settings section tells the reader to run ./compass.sh check after a pull
  or a rebase, because the hook trusts the last check's record.
