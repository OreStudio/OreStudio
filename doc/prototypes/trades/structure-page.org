* Summary

A structure is an entity: an immutable identity and legs that are trades. A package is not a second entity. The composition ladder in [[id:FC31FC9C-7A6E-4EFD-8A62-6DE4137F7160][Trade Structures and Deal Composition]] ends in the untyped structure, which the note calls a package, and the model holds it as a structure of kind Package: the same table, the same anchor, the same members. So the prototype has one screen, and its words follow the kind. A package page says package, and a strategy page says structure. It also draws the workflow [[id:3899F17C-232B-408C-B667-FA5C630BB71B][Group trades into a structure]].

* Detail

** Structure and package

They are different rungs of the composition ladder, one entity with a kind, and the page treats the kinds differently. The test is how the customer holds the trades. See [[id:FC31FC9C-7A6E-4EFD-8A62-6DE4137F7160][Trade Structures and Deal Composition]].

#+ATTR_HTML: :class hug-leading
| | Strategy, typed, dynamic | Package |
|-+--------------------------+---------|
| The customer holds | One deal | Each trade under its own terms |
| Confirmation | One document for the deal | Each leg confirms on its own |
| Pricing | As a whole | Leg by leg: the price is the sum of the parts |
| External version | Of the deal | Of each trade |
| Template and roles | A template fixes them (strategy, typed). Dynamic reads them from data | None. Any role is allowed |
| Product family | A strategy has one. Typed and dynamic may mix | Any mix |
| Unlinking a leg | Changes the deal. A partial close-out is a lifecycle event | The other legs are unaffected |

PKG-0004 is a package of a swap and a cap. STR-0007 is a risk reversal, a strategy. The page shows the chips, the card "How it confirms and prices", and the members table differently for each. The Members tab of a package shows each leg's external version, because the customer quotes the one for the trade they hold. The trade page says which kind a trade's structure is, and the amend dialog says whose confirmation a change reaches.

A composite trade is neither. It is one trade with its own legs, and it is not in a structure in these prototypes.

** What the prototype argues

- The version is read from the legs and is never stored beside them. The rule is the one the [[id:7B737119-099C-451D-9319-1D6BEE73A063][Trade Entry Prototype]] shows: a change to any component moves the structure, and authorisation does not.
- The kind is chosen at grouping, with its consequences stated beside each choice, because it decides what the customer receives. Package is one of the four kinds, so there is one workflow, Group trades.
- The client states the rules the database enforces: every leg shares the party and the counterparty, a structure nests one level at most, and a strategy has one product family. The person sees the check before the server refuses it.
- A trade moves from one structure to another without being rewritten.
- Pricing and composition stay in the Trade Entry Prototype. The Workflows menu links to both.

** What is fake

The structures. Grouping stores the new structure in the browser.
