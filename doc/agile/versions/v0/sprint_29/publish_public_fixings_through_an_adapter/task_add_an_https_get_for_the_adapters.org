* Acceptance

- A new library component, =ores.http.client=, scaffolded through codegen and registered in the build.
- Its first function is a GET over TLS, on the Boost.Beast and OpenSSL the build already links, with certificate and host name checks, a timeout and a limit on the body size. It returns the status, the headers it needs and the body.
- An interface lets a caller's test hand back stored responses, so no test needs a network.
- No secret is logged or kept in a URL that is logged or stored.
- Unit tests cover a refused certificate, a timeout and a body over the limit against a local server, with no outside network.

* Plan

1. Scaffold =ores.http.client= as a part of the =ores.http= composite, through codegen,
   with its OpenSSL and Boost.URL links declared in its overview.
2. Write =transport=, the interface a caller holds, and =beast_transport=, a GET over
   http or https on Boost.Beast, with certificate and host name checks, one deadline
   for the whole request and a body limit.
3. Test against a server in the test process, with a certificate made by OpenSSL at
   test time, so no test needs the network; and once, hidden, against the hosted
   Frankfurter.

* Result

=ores.http.client= is a new part of the =ores.http= composite, the way the system reads
an outside HTTP API. =transport= is the interface a caller holds; =beast_transport= is a
GET over http or https on Boost.Beast and Boost.Asio, with OpenSSL for TLS. Over https
it trusts the system's authorities, or a PEM file given, and checks the host name. One
deadline bounds the whole request, and a body limit bounds the answer. A failure says
whether the address was bad, the network or TLS failed, the deadline passed or the body
was too large, and names the address with any key in its query masked; =redacted= masks
a URL for a log or a store.

Evidence: =ores.http.client.tests= passes 9 of 9 against a server in the test process,
with a certificate made at test time: a plain GET, a body over the limit, a timeout
within the deadline, a trusted certificate, an untrusted one refused, a trusted one for
another host refused, bad addresses, and masked secrets in the query and in a failure.
A hidden live test read =https://api.frankfurter.dev/v2/providers= over the system's
trust store and found the ECB.
