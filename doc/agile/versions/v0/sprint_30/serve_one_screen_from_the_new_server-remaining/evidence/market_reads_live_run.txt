The run signs in to each server on its own and asks both the same body at the
same address. All four answers are identical, byte for byte: the same members,
the same values. The two payload reads are the instrument catalogue, 30
instruments of which the first five come back with the answer truncated, and the
EUR FX montage with its one pair; the two refusals are the rate ladder and the
curve analytics, which the service answers as a 422 with its own words and the
gateway passes on unchanged.

What this database cannot show is a ladder's rungs and a curve's pillars. It
holds no rate quote at any currency, instrument type or instant tried, and no
curve bootstrap configuration at all, so both reads answer the service's
refusal. The payload path of those two is the same forwarding and the same
answer as the two reads that came back whole.

A body the screen would not send is a 400 at both servers, and each names what
was wrong: an unknown member, a currency that is not three letters, an instant
that is not one, an id that is not one.
