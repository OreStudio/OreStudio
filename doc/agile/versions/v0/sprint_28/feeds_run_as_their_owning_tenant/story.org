* Goal

A feed acts for its owning tenant with the narrowest authority, whoever or whatever started it. The same feed behaves the same at boot, after a restart and on a button press.

* Acceptance

- A vintage-priced ACME feed starts at boot and after a restart.
- The Start command checks the caller's permission, and nothing else about the caller reaches the feed.
- A bound feed's binding is created with the collection's run token, with or without a person.
- A Start on a collection with no run grant gives the consent. IAM refuses a grantor who lacks a permission of the role.
- The knowledge notes state this model, with the sequence and state diagrams.

* Decisions

- The model is the Scheduled Work Acting as a Tenant pattern, which reporting
  already uses. IAM gets no new operation. The model is stated in
  [[id:A7D1927B-CB42-49A9-94EF-DBB40225274C][The identity a feed runs as]].
- The consent is one run grant per collection of feeds, stored in the
  collection's =run_grant_id=. The first Start by a person gives it.
- The role is =SyntheticFeedRun=: marketdata series and observations read, and
  feed bindings read and write. The audience is =ores.synthetic.service=.
- A feed that reads no marketdata needs no token.
- A running feed publishes under the service's identity. A lapsed grant stops
  the next start, not the running feed.

* Out of scope

- A screen that shows whether a collection holds a grant.
- Revoking a grant when a collection's party changes. A collection has no party change.
