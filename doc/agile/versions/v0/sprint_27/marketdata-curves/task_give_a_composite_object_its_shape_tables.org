* Goal

A term structure is drawn today from whatever pillars happen to be stored, so a caller cannot say what the object's shape is, what a missing point is missing from, or which points were added and dropped between two instants. Record the object's axes and their ordered values, so the shape is data rather than an inference from the points. Write it from the recipe's pillars when a build produces the series, and from the declaration when an import carries one. Validate every axis value against the reference tenor codes, and refuse at write time a point whose coordinate is not one the object's shape declares.

* Acceptance

- A composite object carries its axes and the ordered values of each, so its shape is readable without reading its points.
- A build writes the shape from the pillars it produced, and an import writes it from the declaration it carried.
- Every axis value that is a tenor is a code the reference tenor table holds, and a value that is not is refused.
- A point whose coordinate is not a declared axis value of its object is refused at write time.
- The existing series and points are unaffected: a series with no shape declared still reads, and the task says what it reports for them.
