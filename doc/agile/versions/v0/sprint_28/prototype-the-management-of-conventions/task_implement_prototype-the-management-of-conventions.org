* Notes

** Draft journey catalogue (J08: not yet agreed)

The five journeys that exist cover: onboard a party, publish from data quality,
see what a party uses, change one convention, and author one convention for a
kind. The checks below were made against those five and the story "Name the
convention sets a report chooses".

Three acts already appear in the five journeys, and none of them is a journey
of its own:

- /Search a kind by a term/ is a step and a named gap in three journeys.
- /Retire a document/ is a coverage row in "Change the convention"; that
  journey sends no delete.
- /A second person approves a change/ is a gap in "Change" and "Author"; the
  existing prototype draws it, and no journey states it.

| # | Candidate journey | Actor | Goal | Starts | Ends | Overlap with the five |
|---+-------------------+-------+------+--------+------+-----------------------|
| N1 | Name a convention set | Market risk owner | Group the kinds into one set with a name, a purpose and a description, so a report can choose it. | The person finds no set that fits (the link out from a report). | The set exists and its name, purpose and kinds read back. | None. This is the authoring UX that the story defers. "Author a convention for a kind" writes one document of one kind. |
| N2 | Retire a convention a run should stop reading | Operations, tenant administrator | Stop a run from reading a document that is wrong or unused, and know what it affects first. | The person finds the document in a kind's list. | The document is closed and the history shows who closed it and why. | "Change" lists the delete as `exists` and does not send it. |
| N3 | Decide on a requested convention change | Market risk approver (not the requester) | Approve or decline a change that another person asked for, with the old and new terms side by side. | A request waits for the person. | The request is decided and the requester can read the decision. | "Change" and "Author" record the missing four-eyes control as a gap. The existing prototype draws the screen. No journey states the approver's goal. |
| N4 | Find the convention that states these terms | Market risk, trading desk | Find out whether a document with these terms exists, before authoring a duplicate or choosing one. | The person holds a set of terms. | The person has the matching document, or knows none exists. | Three journeys carry this as a step and a gap. |

** Recommendation

- Write N1, N2 and N3. Each one has one person and one goal, and none repeats a
  journey that exists.
- Do not write N4 as a journey. It is a step in "Change" and "Author", and a
  filter on the term columns is the fix. Record it as a prototype feature of N1
  to N3 and as a server gap.
- Draw one prototype for each journey, in =doc/prototypes/conventions/=. N1
  also replaces the deferred link out from the two report prototypes.
