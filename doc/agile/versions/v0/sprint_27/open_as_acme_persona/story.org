* Acceptance

- compass open-as with a person's name opens an isolated Chrome on the web login with that user's credentials filled in.
- compass open-as can also choose a person by job title and location, or by role and location, with London as the default location.
- The command leaves the developer's own Chrome profiles untouched and is documented as a recipe.

* Decisions

- Each persona gets its own Chrome =--user-data-dir= under =~/.cache/ores-personas=, not a Chrome profile. A separate data directory never shows in the developer's profile picker and never syncs.
- The sign-in form is filled through the DevTools protocol with a standard-library socket client, so compass gains no dependency. The password is never stored in the browser.
- Acme's tenant, password, offices, roles and titles are hard coded, because the tenant is fixed. The staff come from the seeder's =accounts.json=.
