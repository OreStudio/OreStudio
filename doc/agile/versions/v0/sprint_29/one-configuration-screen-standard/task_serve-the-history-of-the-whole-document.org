* Goal

The History tab of a pricing engine configuration shows every version of the
whole document: the configuration, its products and its parameters, in the
shared timeline the other record pages use.

* Acceptance

- The tab draws versions of the configuration, its products and its parameters.
- Each event names the entity it came from.
- The tab uses the shared timeline, not the legacy history panel.
- An event states who changed it, when and why, and the fields that moved.
- A change to a setting appears without a change to the configuration row.

* Plan

1. Read the document, so the entity ids are known.
2. Read the generic history of the configuration, each product and each
   parameter. The reads travel in batches of 32, because a large configuration
   holds hundreds of parameters.
3. Answer the versions as one list, each carrying its entity, its name and its
   changes.
4. Draw the list with the shared timeline. The mapping lives in =model.ts=, so it
   is a pure function with a test.

* Notes

- The history read is the generic one, so a new entity type needs no new read.
- A configuration with hundreds of parameters reads one history per parameter.
  The batch keeps the requests bounded; a single read for the whole document is
  the server-side alternative if it ever gets slow.
