* Acceptance

- rawcube and netcube are read into a cube hypertable in ores.reporting with the columns result, trade or netting set, date index, date, sample, depth and value.
- scenariostatistics, stress_scenarios and the scenario dumps are read into a factor hypertable in ores.marketdata with the columns result, date, scenario, factor and value, one row for each value.
- todaysmarketcalibration is read into a calibration table in ores.marketdata with one row for each result key.
- scenario.csv is catalogued as a run result and lands in the metric table.
- The market_state_payloads table, the payload index and the base64 writer are removed.
- A test reads each checked-in sample of these families and lands every value.

* Plan

The metric reader already reads six of the seven families, because each one
states keys, qualifiers and figures: the cubes are keyed by netting set, date
and sample with one =Value=, the sensitivity scenarios by trade and factor, and
the two scenario files by date and scenario with one figure for each factor
column. Only =todaysmarketcalibration= needs its own reader, because its values
are text as often as numbers.

1. Give each metric an identity that holds at volume. The metric table's unique
   index is party, run, family, subject, date and measure, so two factors of one
   trade, two samples of one cube or two results of one run collide. A figure is
   identified by its result, the file it came from and the line it was read
   from. Prove it with a sensitivity of two factors for one trade, red first.
2. Make the cubes and the sensitivity scenarios run results, so the
   post-processor stores them as metrics with no new reader.
3. Give marketdata a figure hypertable for =stress_scenarios= and
   =scenariostatistics=, and a calibration table, each fed by a reader.
4. Remove the payload table, the payload index and the base64 writer.
