* Notes

** Two failures in one run, only one of them a build problem

The gcc job's exit 143 is a runner shutdown after 3h13m of a 6h limit, so it
is infrastructure rather than a timeout, and no disk error appears in it.
The clang job is different: it reached 6h0m0s to the second and was killed.

** Why this is the job that overruns

It is the heaviest configuration the repository builds -- linux-clang debug
with both code coverage and memcheck, the two things every other job drops.

** The same cap, for the same reason

The earlier change added 320 minutes to =continuous-linux.yml= because an
uncapped step runs to the 360-minute job limit and the job is then torn
down about thirty seconds later, which cannot upload a compiler cache.
=nightly-linux.yml= never got that cap.

* Result

The Run CTest workflow step in nightly-linux.yml is capped at 320 minutes,
so a run whose compile overruns stops with roughly thirty minutes of job
left for the cache guard and save.

The gate passes 7 of 7 (classes =ci=, =docs=).

Not verified here: no Nightly Build run has been cut by the new cap yet.
The next run that overruns is the proof, and its compiler cache growing is
the signal. The gcc job's runner shutdown in the same run is left alone:
that is infrastructure, and no cap addresses it.
