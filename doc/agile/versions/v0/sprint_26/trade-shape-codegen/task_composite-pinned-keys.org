* Acceptance

- A model can declare named unique keys over several columns.
- A foreign key can name several columns and the target columns they match.
- A test shows a row rejected when its copied value disagrees with the target's.

* Plan

- Named unique keys already exist: a row of the SQL =** Indexes= table
  with =unique= true and no predicate is a key PostgreSQL accepts as a
  foreign key target. No new declaration is needed.
- Composite keys go in a new =** Pinned keys= table under =* SQL=, not in
  =* Foreign keys=. Each =* Foreign keys= entry is keyed by one column and
  feeds C++ consumers (test seeding, list-by queries, group prefixes); a pin
  is a SQL-only rule.
- The source decides the check: a constraint for an immutable source, a
  trigger check on the current row for a temporal one.

* Result

- A =** Pinned keys= table under =* SQL= declares a pin: name, copied
  columns, source table, source columns and error message.
- Against an immutable source the pin renders a constraint,
  =<table>_<name>_pin=, that includes =tenant_id= when the row is
  tenant-scoped. The generator refuses the pin unless the source declares
  the referenced columns as its primary key or as a unique index with no
  predicate.
- Against a temporal source the insert trigger checks the source's current
  row. The check holds at insert only, so a pin copies only facts the
  source never changes.
- The generator refuses an unknown source, column lists of different
  lengths, columns either model does not declare, repeated pin names, a
  message without exactly one =%=, tenant scopes that differ, a mutable
  current-state source and a constraint name over 63 characters.
- Nine tests in =projects/ores.codegen/tests/test_pinned_key.py=.
- In Postgres, in transactions that rolled back, a copy whose kind differed
  from its source was refused with 23503: by
  =ores_testcomp_copier_records_source_pin= against an immutable source,
  and by the pin's own trigger message against a temporal source. A
  matching copy was accepted in both.
- The SQL meta-model page documents pinned keys, and the variability index
  lists =pinned_keys=.
