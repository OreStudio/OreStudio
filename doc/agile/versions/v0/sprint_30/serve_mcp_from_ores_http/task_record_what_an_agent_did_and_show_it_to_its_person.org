* Goal

Every write made with an agent's token records the agent beside the person, in a new audit field, so performed_by keeps meaning the service account. A person opens a view in ores.web of everything their agents did, by agent and by time, with the grant each used, and a record's history shows when an agent changed it.

* Acceptance

- A write made with an agent's token records the agent; a write made by the person directly records none.
- ores.web lists a person's agent activity by agent and by time, with the grant used.
- A record's history shows which changes an agent made, and for whom.
- The sessions window shows an agent's sessions apart from its person's, with the agent's name, and links each to its grant and its activity.

* Plan

The design page put the acting agent on every entity as a codegen field. A
field on every C++ domain type would break the width ceilings of most of them
(532 flat types; the ceilings only come down), so the agent is kept at rest and
read where it is needed:

1. At rest: =app.current_agent= joins the session settings every transaction
   sets, from the token's =act= when it names an agent, and the three SQL table
   templates and two hand-written tables gain an =acting_agent= column stamped
   by the insert trigger beside =performed_by=. The DQ publish functions that
   copy every live column from staging leave it out.
2. In history: =entity_history_version= gains =acting_agent=, and every
   generated history provider marks its versions through one helper in
   =ores.history.core=, which reads the record's stamps by its key and joins
   them on =valid_from=, the version's =recorded_at=.
3. The log: a hypertable =ores_iam_agent_calls_tbl=, written by ores.http after
   it answers a call made with an exchanged key, through a generic recorder on
   the gateway's credential path; read by =list_own_agent_activity=.
4. ores.web: the person's activity panel, a history tag, and links between
   sessions, grants and activity.

* Result

A write made with an agent's token stamps =acting_agent= with =agent:= and the
grant's id on the row it writes; a person's own write and a service's stamp
nothing. A record's history tags the versions an agent made, beside the person
it made them for. ores.http logs every call an agent makes, reads and writes,
by route pattern, method, status and duration, never its content, and a person
reads their agents' calls, newest first and by agent, on their Security page.
Their own sessions link an agent's session to its activity, and an
administrator's sessions window links it to its grant.

The history of a junction is not marked yet, and an administrator has no view of
another person's agents' calls; both are left for when they are needed.
