#+title: ores.vault.consumer
#+description: Codegen entity model for the vault consumers table: the identity a token presents and the public key the vault seals to.
#+type: ores.codegen.entity
#+component: vault
#+filetags: :model:entity:vault:consumers:
#+entity_singular: consumer
#+entity_plural: consumers
#+entity_title: Consumer
#+brief: A service the vault seals its answers to.
#+created: 2026-11-26
#+updated: 2026-11-26

A consumer of the vault: the identity a service's token carries, and the public
half of the key pair that service holds. The vault never takes a key from a
request. It reads the subject out of the verified token, finds the row that
names it, and seals the answer to the public key held here.

The private half is never in this table, never in the database and never in the
tree. It is a system credential of the consumer's unit, provisioned with the
deployment, so a copy of this table discloses nothing that can open an answer.

Two invariants decide the shape. A consumer registers once by its =name=, the
subject its token presents, which is the natural key: two rows for one subject
would give one service two keys, and the vault would have to choose. And a row
with no public key cannot be sealed to, so a consumer that has not been
provisioned is a consumer that receives nothing.

** name
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:natural_key:  true
:sortable:     true
:searchable:   true
:END:

The subject the consumer's token presents, such as =ores.http=, unique within
the tenant. It is the identity the service runner authenticates, and the only
thing the vault uses to find the key an answer is sealed to.

#+begin_src cpp :name generator
std::string("ores.http")
#+end_src

** public_key
:PROPERTIES:
:type:     text
:cpp_type: std::string
:END:

The Base64 of the consumer's 32-byte X25519 public key. It is not a secret: it
is the half the vault needs in order to seal, and it is useless without the
private half held by the consumer's unit.

#+begin_src cpp :name generator
std::string("tw+/9+zJr9z55w001kE3JIKMVsxyInWcHcPlyHtFmyBG=")
#+end_src

** is_enabled
:PROPERTIES:
:type:     boolean
:cpp_type: bool
:nullable: false
:default:  true
:END:

Whether the vault seals to this consumer at all. A disabled row keeps its key
and its history and refuses every resolve, which is how a consumer is withdrawn
without deleting what it asked for.

#+begin_src cpp :name generator
true
#+end_src

** actor
:PROPERTIES:
:type:     text
:cpp_type: std::string
:searchable: true
:END:

The account the consumer runs as, in the form the audit columns take, such as
=powershell@system.ores:9000=. A secret names its owner by this value, so the
vault compares an owner with a consumer whether the caller proved itself with a
token or with the key it holds: the token path reads the actor from the context,
and the bootstrap path reads it from this row.

#+begin_src cpp :name generator
std::string("vault@system.ores")
#+end_src

:PROPERTIES:
:type:     text
:cpp_type: std::string
:nullable: true
:END:

What the consumer is, in a person's words, such as =The gateway=. Nothing reads
it but a person.
