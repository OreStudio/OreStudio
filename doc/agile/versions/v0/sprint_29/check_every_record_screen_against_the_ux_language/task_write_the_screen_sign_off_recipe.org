* Acceptance

- A recipe states the steps, the command, the manual lines and where the outcome is recorded.
- The screen review checklist points at the recipe.
- The recipe is used once on an existing screen and the outcome is recorded as the worked example.

* Plan

The checklist has 104 identifiers and the harness asserts 20, so the sign off
cannot be the harness alone and cannot be a person alone: a script folds one
screen's run into a sheet of every checklist line, with the harness's mark where
it has a check and a blank for the person where it does not, so the same sheet
serves every screen and names what a person still owes. Write the recipe around
the sheet, point the checklist at it, and use it once on the currencies screen
so the worked example is real: run the harness on the screen alone, walk the
lines as the administrator and as a member, and record the verdict beside the
task. Add the deferred check that the harness's copy of the Acme password
matches the provisioning script, so a drift names itself instead of failing
every check as a sign-in error.

* Result

The recipe How do I sign off a screen? states the one procedure: run the
harness on the screen alone, fold the run into the sheet with
=projects/ores.web/scripts/screen_sign_off.py=, walk the lines marked walk as
the administrator and as a member, write the verdict, and record the sheet on
the task. The screen review checklist points at the recipe, and the ops
inventory lists it. The sheet of the currencies screen in =evidence/= is the
worked example: the harness marks 18 of 110 lines, 3 with the baseline's
failures, and the walk found 17 gaps, met 31 lines, set 24 aside and could not
check 26, so currencies is not signed off and the gaps go to its topic. One
finding became a capture: adrian.vance, whom the harness calls a reader, is
editable on currencies. The harness setup now checks that its copy of the Acme
password and hostname match the provisioning script. The fixture test for
=harness_baseline.py= was not written: no runner picks up Python tests under
=projects/ores.web/scripts=, and the sheet script is exercised by the worked
example.
