* Notes

- The CDash pages saved under =tmp/= are truncated at about a megabyte, so
  the analytics page listed 64 of the 214 defects and the first fix left 146
  behind in a second entity. The complete set came from re-running each
  binary locally, which is also what proves the fix.
- The uninitialised values are all created by a stack frame in the test or
  the generated generator, and read in a write path: sqlgen stringifies every
  entity member to build the INSERT, so an entity built by a generated
  generator that skips a column is read whole.
- =bond_trs::funding_rate= and =bond_repo::repo_rate= are =nullable: true=
  with a bare =double=, so the generated entity wraps them in
  =std::optional= and the generated mapper maps zero to =nullopt=. The
  declared default of =0.0= is that convention, not a value the domain
  intends.
- The full suite passes on a recreated database, and only on a recreated
  database: =ores.iam.core.tests= is not idempotent. Its first run leaves
  three seed profiles open, and the second run fails three cases on
  =seed_profiles_code_uniq_idx=. That is a pre-existing defect of the tests
  rather than of this change, and it is filed as
  [[id:96828FAA-1F22-4F18-AB56-81C0C8EBE33E][The iam seed-profile eventing tests only pass once per database]]. It also
  cost this task two verification runs: the residue was misread at first as
  damage the valgrind runs had done.
- The gate refuses the nullable shape rather than synthesising a default,
  because the value that means "absent" is the model's to state. For the
  non-nullable shape the same choice is open and is filed as a capture; this
  task declares the defaults the reported instances needed and records the
  census, so the decision is taken with the size known.
