* Plan

The inventory paired =GET /api/events= with =/api/v1/changes=, but the two did
not speak the same contract. ores.web listens for =connected= and
=entity-changed= events and drops a change whose data has no =at=; the C++
stream named each event after its collection, sent no =at= and no opening
message. Switching the browser to it would have stopped every live update.

- The C++ frame is now the browser's: =event: entity-changed=, with the
  component, the entity and the instant it was published, and the tenant and
  the party beside them. A stream opens with =event: connected=. Nothing else
  read the old frame.
- =GET /api/events= is the same stream, carrying only the collections the
  session watches. =/api/v1/changes= keeps carrying every collection the caller
  may see.
- =POST /api/events/watch= replaces the session's watch set, with the BFF's
  limits: at most 50 watches, each named in lower case. A session's set lives as
  long as its stream.
- The hub filters by the watch set before it queues a frame, on a live publish
  and on a replay alike.

The BFF also named the changed records in =keys=. The coalescer keeps
collections, not records, so the C++ stream names none, and ores.web refreshes
the whole collection, which its parser allows.
