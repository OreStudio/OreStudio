* Goal

The grid belongs to the installation: one set of hosts runs every tenant's
work, and the samples describe the fleet, not a tenant's slice of it. The
reads filter by the session's tenant anyway — =latest_node_samples= selects
=DISTINCT ON (host_id) ... WHERE tenant_id = $1=, and the grid summary read
follows the session — so an administrator reads a shorter table and cannot
tell it is short
([[id:3621E2BC-2670-4E59-8721-32F86B640F24][The grid read is scoped to the session tenant]]).
This task drops the tenant filter from the grid reads and guards them with
the permission the journey records; the stored =tenant_id= stays on the
sample as attribution, so *the whole grid* and *who may see it* stay two
separate decisions.

* Result

The read is whole and the record is closed.

=latest_node_samples= states no tenant predicate, and both sample models state
=:tenant_read_scope: shared= with =:rls_own_or_system_tenant_rows:=, the codegen
feature that emits the installation's policy shape: a session reads its own
tenant's rows plus the system tenant's, and writes stay confined to its own
tenant. The newest grid sample loses its predicate through the same shared
scope.

The fleet comes back because the installation's own samples are the system
tenant's, not because the read was widened to everything. The test states that
honestly: it proves a permitted session reads every node the installation
reports, and proves a third tenant's rows stay invisible. It would fail if the
predicate came back, which is the property a test for this change needs.

Two of the four acceptance items needed no work here. The read already checks
=compute::grid_samples:read= on =origin/main=, and the shell's =compute
grid-stats= command already sends =get_grid_stats_request=, so it reaches the
same read. Both are recorded rather than re-implemented.

The work counts are not this task's and never were, once the design settled:
they are the installation's own ledger, which
[[id:84345A75-CCE4-4C6B-80EA-A5857E01730B][Account for the grid's usage]]
builds. The acceptance now says so, and the capture moves out of the inbox with
this evidence.

pytest suite 1288 passed with 2 pre-existing failures that are main's; the RLS
guard unchanged at 10 widenings, all listed; and no component drift. The ER
