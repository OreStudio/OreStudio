* Notes

- *Where the leaves are lost.* =YieldCurveSegment::fromXML= reads =Type=,
  =Conventions=, =PillarChoice=, =DuplicatePillarPolicy=, =Priority= and
  =MinDistance=, and every segment class calls it first. The extractor's =BASE=
  pattern reads `class X : public Y` from *one file*, so a class declared in
  =yieldcurveconfig.hpp= and defined in =yieldcurveconfig.cpp= keeps no base and
  its inherited reads never reach the term. Both halves are in the tree; only the
  lookup is per file.
- *What the screen shows today.* A segment draws =Conventions= as a gap while the
  guide documents it, because the contract has no
  =Segments/<Kind>/Conventions= row. Measured on the UK curve configuration: two
  leaves per segment, one documented.
- *The fix is one map.* Collect the base of every class across all files the
  extractor reads, before building the entries, and look it up from that map.
