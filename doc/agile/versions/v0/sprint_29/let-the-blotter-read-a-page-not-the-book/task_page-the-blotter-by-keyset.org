* Result

The page is a keyset read. =read_blotter_page= reads one page after a key the
service itself wrote: the sort value and the row id, joined by a separator no
value holds. The default order is the trade date, newest first, then the id. A
page with no key is the first page. =trading.v1.blotter.page= carries the key
back to the screen, and =is_sortable= refuses a field the order cannot state, so
the page and the list cannot disagree about what an order means.

Merged on main in #4403 at =b903acb4=. The four =[page]= cases in
=trading/core/tests/blotter_rail_tests.cpp= cover a page of five read in twos, a
page after a key, the page's agreement with its rail, and every sortable field
stating a key.

Two costs remain, and they are not this task's: the key is compared as text, so
no index serves the order, and the page reads the union view, so it pays for
each row's laterals. [[id:A0AE98E4-DF2E-4D75-9099-FF3E2555B5B1][List a package as
the trade it is]] and
[[id:2A42890A-63B5-4076-B934-E98685795CF0][Order the page by an indexed key]]
carry them.
