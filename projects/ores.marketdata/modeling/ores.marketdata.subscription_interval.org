A subscription interval is a fact about usage. It records that a party held a subscription to a provider
with given rights and was routed to a source, from one time to another. It holds no price. A rating
step applies the rate card of the source to the interval later, so a new contract can price old facts.

The service opens an interval when a route and its subscription come to hold together and closes it
when either changes or ends. A change of the source or of the rights closes one interval and opens the
next. A party administrator reads the intervals of the party and the system tenant reads all of them.

Reads the latest subscription intervals across all tenants. The service that meters usage reads the intervals
that are open for every party, so it cannot filter on one tenant. Queries only on
=valid_to == max=.

std::vector<domain::subscription_interval>
subscription_interval_repository::read_latest_all_tenants(context ctx) {
    static const auto max(make_timestamp(MAX_TIMESTAMP, lg()));
    const auto query = query_builder::read<std::vector<subscription_interval_entity>> |
                       query_builder::where("valid_to"_c == max.value()) |
                       query_builder::order_by("id"_c);

    return query_builder::execute_read_query<subscription_interval_entity, domain::subscription_interval>(
        ctx,
        query,
        [](const auto& entities) { return subscription_interval_mapper::map(entities); },
        lg(),
        "Reading latest subscription intervals across all tenants");
}
