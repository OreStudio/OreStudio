The same rows as the sibling =dq_system_populate= archetype, written into the
three staging tables the publish pipeline copies into another tenant. Each
insert looks its dataset up by code rather than reusing a =psql= variable,
because the three artefact seeds that precede it each overwrite the same one.
The delete is scoped to this taxonomy's own rows -- the mirror seeds delete a
whole dataset before their insert, so an unscoped delete here would take every
other domain's rows with it -- which also makes re-running the fragment
replace only its own.

See the [[id:C4E8A91F-3B7D-4F2E-85A6-1D9C7E3B2F4A][Template variable reference]] for the complete list of available
variables and their semantics.
