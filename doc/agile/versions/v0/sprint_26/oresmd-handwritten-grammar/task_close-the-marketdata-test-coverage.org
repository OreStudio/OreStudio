The review of PR 2607 found no test for =feed_ingest_loop::on_tick=. Cover these
behaviours: a tick from an unbound source is dropped, a tick whose URI names no
datum is dropped, a tick whose value is not a number is dropped, and a tick from

needs it split out first.

** What the task added

- Generated eventing integration tests for =market_series=, =feed_binding= and
  =observation_lineage=, joining =series_classification_rule='s. The template
  sets audit columns that =market_fixing= and =market_observation= do not have,
  so their test does not compile; it is the fifth finding in the capture
  below. Turning it on also needs the core tests to link refdata, for the
  entities that take their party from the session.
- =repository_entity_repository_tests.cpp=: read back by key and remove for
  =feed_binding= (by id and by source), =observation_lineage= and
  =series_classification_rule=; and the junction's paged list by series, with
  its total and its order.
- =as_of_rows=: the as-of row mapping, moved out of the model's two reads so a
  test reaches it. =repository_as_of_rows_tests.cpp= covers a good row, a short
  row, a missing ordinal, an ordinal that is not a number (=two=, =2x=) and an
  ordinal outside the buckets.
- =tick_plan=: =on_tick='s decision, moved out of the loop. =app_tick_plan_tests.cpp=
  covers an unbound source, a URI that names no datum, a value that is not a
  number, and a source with two bindings, which gets two targets with their own
  republish subjects. The loop keeps the store, the stats, the CRM bridge and
  the republish, which need NATS and a database.
- =config_parser_tests.cpp=: the service's defaults, its =--http-base-url=,
  NATS and database options, and =--help=.
- The =observation_lineage= generator wrote =source_series_ids= as =[]=, which
  the table's check refuses, so no generated lineage row could be stored. The
  model's generator block now writes a one-element array, and the repository
  and eventing tests store generated rows.

** G04: the generated code review

Read on 2026-10-05: the junction's generated service, handler, repository and
protocol, which this story generated first, against the entities that had them
already, and the eventing tests generated for the other entities. The code
reads like the component's hand-written code. Six findings, all in shared
templates:

- Namespace closers carry an end-of-line comment, which H03 forbids. Task
  [[id:D0883E40-B0F8-49B5-8AEA-DFBB5F19834D][Remove the namespace closer comments from the templates]].
- A claim lost between the service's check and its write reports as
  =internal_error=, not =conflict=: every handler catches any repository
  exception the same way.
- =put_many= reads each written row back with its own query.
- No template generates a test for the =table=, =table_io= or
  =history_field_mapper= output.
- Generators fill foreign keys with random UUIDs, so their rows fail the
  foreign-key checks.
- The eventing integration test sets audit columns, so it does not compile for
  the time-series entities.

The last five are capture
[[id:DB762ADC-37BA-4234-9AF8-0515798F63C0][Defects in the generated C++ templates]].
