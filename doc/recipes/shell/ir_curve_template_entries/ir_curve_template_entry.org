#+title: How do I run the ir_curve_template_entries commands from the shell?
#+description: Every command the ir_curve_template_entries submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:ir_curve_template_entries:

This file documents the ir_curve_template_entries resource at the shell, one section per command. Every command is a subcommand of =ir_curve_template_entries=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: C2C2AA17-6B7D-58EA-A70D-3ADF77024065
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
ir_curve_template_entries list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =synthetic.v1.ir_curve_template_entries.list=.

#+name: ir_curve_template_entries-list
#+begin_src ores-shell :tangle ir_curve_template_entries-list.ores :exports none
ir_curve_template_entries list --limit 1
#+end_src

** =add=
:PROPERTIES:
:ID: 520729D9-6BDD-5D34-979E-1695665D77AF
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
ir_curve_template_entries add <id> <ir_curve_config_id> <sequence_index> <start_tenor_code> <end_tenor_code> <instrument_code> <reason> <commentary>
#+end_example

It is addressed at =synthetic.v1.ir_curve_template_entries.put=.

** =set=
:PROPERTIES:
:ID: 18A514B4-BA85-529B-BF29-FDB12E2FD73A
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:
