* Acceptance

- A gated book change raises a request and shows it waiting.
- A change with no policy row is written directly.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

- Ask the policy at the confirm, not at the screen's load: the confirm previews the book, and the preview names the parts. No part means the book is written as before, with its own refusal. A part means the confirm raises one request that holds the book.
- Show the same answer on the review step, so the person reads who will decide before they confirm. The review step draws the shared changes view and keeps the journey's own confirm.
- Split the review panel into the changes and the actions. The journey owns its confirm and draws only the changes. A screen with no journey of its own uses the whole panel.
- Record a raised request on the walk beside a written book. The outcome says the change is waiting for the named functions and links to the request page.

* Notes

- A new portfolio is written before the book, as it was. The portfolio is not gated yet, because only the book's model is marked gated, so the walk writes it and then raises the request for the book. If the book is refused after that, the refusal names the portfolio write that already happened.
- A refusal from the preview, when the policy names a part, stops the confirm with the write's own words. A change with no part goes to the write, whose refusal still carries its code and fields.
- The request's reason is the commentary the person wrote, or the description of the change reason they chose when they wrote none.
- The review step previews only when the book is complete and no new portfolio is waiting to be written, because the preview reads the portfolio the book sits in.
- The first screen onto the panel shows the pattern the other four follow: preview at the confirm, write or raise, and a waiting outcome that links to the request.
- Not done: a run in a browser against the running services. The ORE import and the shell still meet the gate and are not moved.

* Result

The book structure screen raises a request for a gated change and writes the rest directly.

- The confirm asks the policy by previewing the book. With no part it writes as before. With a part it raises one request that holds the book and records it on the walk.
- The review step shows the change with the fields it touches and the functions that decide it, from the shared changes view.
- The outcome says the change is waiting for the named functions and opens the request page.
- The review panel is split into the changes and the actions, so a journey that owns its confirm draws only the changes.
