What the run shows. The two catalogues answer whole: 23 providers and 26 feeds,
and the connectivity answer with its publishers, suppliers, adapters, sessions,
feeds, scopes and routes, the two document columns read back as documents. An
item's fixing series answers 2,558 values from 2016-11-23 to 2026-11-20 with the
publisher and the feed that carried it, and a URI the store does not hold answers
a null series. The public publishers answer 15 publishers with their series, each
pair read by the codec. The coverage answers 142 series. The file answers a CSV
of 120 rows for a five-day range, named for the publisher and the range, with no
cache.

The run found one thing the port had to put right in the market data service:
its fixing list could not be ordered by fixing_date, so a series' first and last
value could only be had by reading every value. The model now marks the column
sortable, and the coverage reads two values for each series and the count the
service states, instead of 608,334 rows.
