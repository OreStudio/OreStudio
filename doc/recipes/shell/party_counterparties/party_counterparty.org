#+title: How do I run the party_counterparties commands from the shell?
#+description: Every command the party_counterparties submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:party_counterparties:

This file documents the party_counterparties resource at the shell, one section per command. Every command is a subcommand of =party_counterparties=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: E9EA53C9-AAFD-5777-B035-236ED90DC5F5
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
party_counterparties list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.party_counterparties.list=.

#+name: party_counterparties-list
#+begin_src ores-shell :tangle party_counterparties-list.ores :exports none
party_counterparties list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: C89BFB92-E8F4-5897-98FD-99C1AB3CA8EB
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

It is addressed at =refdata.v1.party_counterparties.get=.

** =add=
:PROPERTIES:
:ID: DE395AA2-363E-5A22-AFD8-A31685157FE5
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
party_counterparties add <party_id> <counterparty_id> <reason> <commentary>
#+end_example

It is addressed at =refdata.v1.party_counterparties.put=.

#+name: party_counterparties-add
#+begin_src ores-shell :tangle party_counterparties-add.ores :exports none
party_counterparties add 00000000-0000-0000-0000-000000000000 00000000-0000-0000-0000-000000000000 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 292EF650-E667-5DFF-A538-76E3FE94AC7B
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
party_counterparties set <party_id> <counterparty_id> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.party_counterparties.put=.

#+name: party_counterparties-set
#+begin_src ores-shell :tangle party_counterparties-set.ores :exports none

#+end_src
