* Summary

A scripted trade carries its payoff one of two ways: it names a script of the
library, by name, or it states the script's code inline. ORE accepts either
([[id:2F5B28D9-9AB7-401E-8EF3-612712F626C1][Generic Scripted Products]]). ORE Studio records, for a named script, the version of the
library script the trade was booked on, and for an inline script, its text and a
hash of it. Either way the trade can be revalued on the payoff it was booked
with, after the library changes.

* Detail

** A named script

The common case: a booking form or the twin of a native product books a
ScriptedTrade naming =VanillaBasketOption=. The trade states the script's name
and the library version current at booking. Revaluing it later sends that
version's text to the engine, whatever the library's newest version is
([[id:CCA8090C-26E0-4571-84BA-9115C110376C][The script library is versioned reference data]]).

** An inline script

A person writing a payoff no library script states books it in the free-form
editor. The trade holds the script's text and its hash. Its inputs are derived
from its text by the parser ([[id:92449D70-09E2-4391-B716-A1001F22B271][A script's free variables are its inputs]]), not looked up in the library, and
the booking is validated as any scripted trade is ([[id:C2A45123-A9B3-49BA-BEFD-07E1703F7B84][A scripted trade is validated in three layers]]). Who may book
an inline script is a permission of its own: an inline script is a model no one
has reviewed.

** What both carry

The variables the script reads, as rows of [[id:8D12E0ED-B6D9-4FDC-A98C-35AE84B8045F][ores.trading.scripted_parameter]] under the
trade's [[id:B3FBDD1A-8FC6-4702-9600-B75581FC6494][ores.trading.scripted_instrument]], each checked against the script's inputs by
name and type.

** Where today's code differs

A trade names a library script by name only, with no version, so a library
change reprices it on the new text. No path books an inline script.
