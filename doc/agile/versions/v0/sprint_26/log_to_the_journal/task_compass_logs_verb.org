* Goal

compass services logs prints a tail from the user journal for any unit in this environment, and can return only the last warnings or only the last errors. nats-server is reachable through the same verb even though no service selector resolves it today, so the fleet has one log interface rather than one per family.

* Acceptance

- compass services logs <selector> prints the tail of that unit from the journal.
- The verb accepts nats-server, which _resolve_service does not match.
- The verb filters to warnings and to errors.
- The verb emits one JSON object with the same ok discriminant and no ANSI codes, as env status does.
- It reads the journal rather than any file, and it reports how many lines it returned and whether it truncated.

* Plan

One verb over =journalctl --user=, shaped like =env status=: one JSON object
with an =ok= discriminant, no ANSI codes, and the same failure reasons.

- =compass services logs <selector> [-n N] [--warnings] [--errors] [--json]=.
  The tail is =journalctl --user -u <unit> --no-pager -n N -o cat=, the two
  filters add =-p warning= and =-p err=.
- The selector resolves through the registry as the other verbs do, and also
  accepts a full unit name and =nats-server=, which the registry does not
  carry. That is what makes the interface single rather than one per family.
- The object reports the unit, the number of lines, whether the journal was
  truncated to reach the limit, and the filter that was applied, so a caller
  can say which of those it is looking at rather than showing an empty box.
