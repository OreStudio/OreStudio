* Goal

Serve the four writes of the engine settings: the create, the update, the group
write and the removal. A write to a group makes the next version of the central
row in the service, so a part is written alone and the document is never saved
whole.

A group whose settings change the numbers a run computes, on a configuration
that a report binds, is a proposal and not a write. That decision is the
service's, and the route states the answer it gives.

* Acceptance

- The C++ server answers =POST /api/reporting/engine-settings=,
  =PUT /api/reporting/engine-settings/:id=,
  =PUT /api/reporting/engine-settings/:id/groups/:group= and
  =DELETE /api/reporting/engine-settings/:id= at the BFF's member names and
  status codes: 201 on a create, 202 on a proposal, 204 on a removal.
- A create writes the reporting configuration header first and the central row
  second, and removes the header when the central write fails.
- A group write that is a proposal writes no part, and the answer states the
  document as it stands and the id of the approval it raised.
- The service decides that a write is a proposal. The gateway asks for one and
  does not decide.
- A removal refuses with 409 when a report binds the configuration, and
  otherwise removes the parts, then the central row, then the header.
- A body that names a member the route does not know is refused, as in the
  earlier families.
- A test proves each refusal; the happy paths need a live estate and this task
  does not prove them.
- Each route in scope names its C++ equivalent in the inventory.
- The local gate is green.

* Plan

Branch =feature/serve-the-engine-settings-writes=.

The writes extend the =engine_settings_rows= unit that the reads task adds. The
proposal travels on the service's own operation, so the gateway carries the
group, the base version, the values as text and the reason, and states the
approval it gets back.

The compensation the BFF keeps is kept: a create that cannot write its central
row removes the header it wrote. The header is the reporting configuration that
binds the settings to a report, so a failed create must not leave one behind.

The gateway checks no permission before a write. The service applies the rule
and its sentence is the one the person needs, as the earlier families settled.
