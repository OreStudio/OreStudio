* Notes

Root cause of the login-failure FAIL, diagnosed 2026-07-30:
=account_service::login()= requires a row in
=ores_iam_login_info_tbl=, created for =super_admin=/=tenant_admin= by
=ores_iam_system_provisioner_create.sql=, but never created by the
accounts publish-from-dq SQL path used to bulk-create the ~59
generated Acme staff accounts -- so every curated staff connection
fails login with "Login tracking information missing". This blocks
the parent story's own RBAC-exercising acceptance criterion (not just
this scenario), so it's split out as its own task rather than fixed
here: [[id:60C58FA5-94C2-49A2-94F1-7620237FB296][Fix: generated Acme staff accounts have no login_info row, can't
log in]]. Everything else this scenario checks (description field,
curated connection set, Barclays/NatWest removal) passes.
