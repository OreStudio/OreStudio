* Goal

Port the DQ screens of the Qt client to ores.web, so a person can see every
dataset, what it holds, whether it is published, and run the publication.

The source to port is =/home/marco/Vault/Development/OreStudio/ores.qt/dq=: 88
translation units and 27 =*.ui= screens, of which 18 are entity detail dialogs
and 9 are history dialogs. Publishing is not a hidden action there: the area
carries a =DataLibrarianWindow=, a =PublishBundleWizard= and a
=PublishDatasetsDialog=, with dataset, dataset-bundle and dataset-dependency
models behind them.

* Acceptance

- The dataset, dataset bundle and dataset dependency lists are readable in
  ores.web.
- Each dataset states whether it is published, and for which tenant.
- Publishing runs from ores.web, for one dataset and for a bundle, and reports
  what it inserted, updated and skipped.
- The coded vocabularies the Qt area shows — code domains, coding schemes,
  natures, origins, treatments, methodologies, change reasons, badges — have
  their ores.web screens.
- Nothing in the port needs a Qt client to be running.

* Plan

1. Walk the Qt DQ area and list every screen and the model behind it.
2. Decide which screens are records (entity page plus history) and which are
   tools (librarian, wizards), because ores.web has a record-page standard for
   the first and none for the second.
3. Port the record screens first, through the screen pipeline, so the lists and
   detail pages exist before the tools do.
4. Port the librarian and the two publish dialogs last, against the model the
   publish task settles.
