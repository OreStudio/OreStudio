* Acceptance

- The scope and binding mode columns and their code are gone.
- The Bloomberg, ORE, Refinitiv, ICE and Tradeweb feeds are installed by the system bundle, and no party owns a generator.
- A fresh provision of the Acme demo gives a party a subscription and a route and no generator.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

1. Remove the =scope= and the =binding_mode= columns of the collection, the conflict trigger that reads them, and
   the code that reads them. A collection is the installation's, so the question "whose is it" has one answer.
2. Replace the hand-written row-level security of the generator tables. Every tenant reads a generator row, and
   only a session of the system tenant writes it. The two helper functions that ask whether a collection is a
   system one go, because every collection is.
3. Make the DQ publish write the system tenant only. It takes no party and no mode.
4. Move the Bloomberg, ORE samples and uniform demo datasets into the system bundle, so the system bundle
   installs every provider's feeds.
5. Offer a collection to an adapter only when the collection names the adapter's provider. The adapter of
   =ore-simulated= serves the collections of the provider =ore= and no other, because a Bloomberg collection
   quotes Bloomberg ids that this adapter does not publish.
6. Change the Acme profile. The tenant publishes no generator. A provisioning step gives each party a
   subscription to the provider =ore= and a route to the source =ore-simulated=, and the step that bound
   parties to generators and started them is removed.
7. Test with the pgTAP files that state the new policy, and with the suites on a rebuilt database.
