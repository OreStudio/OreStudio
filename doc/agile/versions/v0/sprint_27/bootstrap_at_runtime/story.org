* Goal

A freshly created database holds the schema and the staged DQ artefacts and
nothing else. The system is made usable at runtime, by running the ACME
provisioning through =ores.shell= (or ores.web's setup journeys), which
publishes the bundles in dependency order. A test that reads reference data
inserts or publishes it in its own setup.

* Acceptance

- =compass db recreate= publishes no reference data: refdata books, business
  units, asset classes and images hold no published rows.
- The DQ artefacts are still staged, so the runtime provisioning has
  everything it needs to publish.
- =ores.shell= (or ores.web) makes the system usable through the seed
  profiles; no build-time step is needed.
- The test suite is green, with the tests that need reference data
  publishing it through the shared =ores.testing= helper.
- The memory records that the system is made usable by the runtime ACME
  provisioning.

* Decisions

- *One publish path, and it is the runtime one.* The build-time bootstrap was
  added in PR #2034 because a fresh database had no published books and no
  trade could be booked. It duplicated the runtime publish and hand-ordered
  the calls, so it drifted from the dependency graph and published countries
  without the flag images their dependency declares. It goes.
- *Staging stays at build time; publication moves out.* The DQ artefacts are
  data the seeder generates and the build stages. Publishing them is a
  business operation the seed profiles drive, so it belongs to the runtime.
- *Tests publish what they need.* =ores.testing= gains =publish_dataset()= and
  =publish_refdata_dataset()=, which make the same call the publish service
  makes. A test no longer leans on a build-time bootstrap that is not there.

* Out of scope

- Attaching each service account's picture. It joins the published system
  avatars, which now happens at runtime, so
  =iam_service_account_pictures_populate.sql= is not wired at build time and is
  named in =validation_ignore.txt=. The runtime attach step is its own change.
- End-to-end verification that =ores.shell bootstrap setup= leaves a usable
  system. The seed profiles and the bundle publish are unchanged by this
  story; the check belongs with the shell work.
