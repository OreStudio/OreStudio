* Goal

Serve the four writes of the engine settings: the create, the update, the group
write and the removal. A write to a group makes the next version of the central
row in the service, so a part is written alone and the document is never saved
whole.

A group whose settings change the numbers a run computes, on a configuration
that a report binds, is a proposal and not a write. That decision is the
service's, and the route states the answer it gives.

* Plan

Branch =feature/serve-the-engine-settings-writes=.

The writes extend the =engine_settings_rows= unit that the reads task adds. The
proposal travels on the service's own operation, so the gateway carries the
group, the base version, the values as text and the reason, and states the
approval it gets back.

The compensation the BFF keeps is kept: a create that cannot write its central
row removes the header it wrote. The header is the reporting configuration that
binds the settings to a report, so a failed create must not leave one behind.

The gateway checks no permission before a write. The service applies the rule
and its sentence is the one the person needs, as the earlier families settled.

* Notes

** The value set's rule is not restated

The BFF validated every value of a group against the value set of its ORE
parameter before writing, with a copy of a rule the service applies to the same
four tables. The gateway does not: it checks that the body names exactly the
settings of the group, and that each value is of the form its column holds, and
leaves the rule to the service. A value a set refuses is the service's sentence.

** The party of a new configuration

The BFF took the party from its own session, which is the party the caller's
token states. The gateway reads the same claim, and still accepts a party the
body names, because the BFF's form allowed one.

** The removal reads the bindings strictly

The reads task states a binding that cannot be read as an unknown list, so a page
still answers. The removal does not: a configuration whose binding cannot be read
is refused rather than deleted, because deleting on an unknown binding is the one
mistake a person cannot undo. The BFF threw there too, as it did not catch.

** The owning-party check is not restated

As in the reads, the gateway does not compare the row's party with the caller's.
The service reads and writes under the caller's own party, and its refusal is the
one the person reads.

* Result

The gateway answers the engine settings' four writes at the BFF's paths, shapes
and statuses.

- A create writes the reporting configuration header first and the central row
  second, and removes the header when the central write fails.
- A group write that the service says is a proposal writes no part: the answer is
  a 202 carrying the document as it stands and the approval's id.
- A group whose settings change no numbers, or a configuration no report binds,
  is written in place, at the version the form read or as a new row.
- A removal refuses with 409 when a report binds the configuration, and otherwise
  removes the parts, then the central row, then the header.
- The value set's rule is the service's: the gateway checks the body's shape and
  the form of each value, and states the service's sentence for the rest.
- The suite is 61 cases and 531 assertions, nineteen of them for the engine
  settings routes.
- The gate is 44 of 45; the one failure is the reference data drift that main
  carries.
- The reporting area states 34 of 44 routes paired where it stated 30.
