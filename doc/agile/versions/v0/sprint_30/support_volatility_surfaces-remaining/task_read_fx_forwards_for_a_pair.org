* Acceptance

- A read operation answers one pair at one as-of, and names the published set of each currency and the spot observation it used.
- A published curve gains its reference date at a discount factor of one before the calculator reads it.
- Spot is the latest =fx_spot= observation at or before the as-of, and the result states its age.
- A pair's spot days are the larger of its two currencies.
- A missing spot, published funding curve or pair convention is refused, and the refusal names what is missing.
- A cross that is not a USD-hub pair is refused and named.

* Plan

Name the data shape first. =fx_forward_ladder_plan= holds the pure decisions: which set stands at an as-of, the pair's joint calendar and the ladder's dates. =fx_forward_ladder_service= reads the inputs and calls =calculate_fx_forwards=. A missing input is a =success= false reply and not an error.

The dates use =calendar_arithmetic::advance= over one calendar closed when any of the pair's calendars is closed. The tenor resolution service takes one calendar, so it cannot answer a pair.

* Result

=marketdata.v1.ops.get_fx_forward_ladder= answers a USD pair at an as-of and names the spot and the set of each curve it used. The acceptance items are covered by unit tests, with the cross and missing-convention refusals also run through the database.

Not proved: a successful reply against stored data. A =curve_publish= row needs a real approval request, so no test seeds one. The first successful reply needs a feed run and a publish of both curves, and the screen task carries that check. Calendars are read as materialised, so a date past a calendar's window is treated as open.
