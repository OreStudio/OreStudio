* Summary

An entity is one record the system keeps: a row, the C++ type that carries it,
the repository that reads and writes it, the protocol that moves it, and the
screen that shows it. One name runs through all of them.

This hub gathers the pages that describe those layers. Read
[[id:608675E1-4284-4902-99AC-4DA565390AFB][Entity Lifecycle]] first if you are
building one, and [[id:471815CD-A377-4101-A4F8-E6962CD8469D][Entity naming]] if
you are only choosing a name.

* Choosing the shape

An entity is authored as a model, not as code, and the shape must be chosen
before anything is written. The shape decides what the generator produces.

- [[id:2A2E8B6D-179D-452C-9169-04E6BB46CC07][Codegen input org-file schema reference]] — the syntax for every pattern.
- [[id:3A49A0B0-9FCF-466C-B097-ECF9A60C0F3D][Adding a flagged combo field to a codegen entity]] — a worked change to a model.
- [[id:B6C5D4E3-F2A1-4B0C-8D9E-0F1A2B3C4D5E][How do I create a new entity?]] — the end-to-end recipe.

A codegen pattern library — the page that says which shape to pick, and which
neighbouring shape it is mistaken for — is being written on another branch.
Link it here once it merges.
