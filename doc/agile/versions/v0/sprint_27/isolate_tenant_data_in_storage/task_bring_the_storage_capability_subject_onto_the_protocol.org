* Acceptance

* Plan

Two independent clauses, both landed on trunk without a check to stop them.

1. *The subject left the grammar.* =iam.v1.storage_capabilities.mint= is
   ={component}.v1.{resource}.{verb}= with =mint= outside the closed set of
   eight. The mint is an operation, not an entity verb, so it moves to the
   reserved ops namespace: =iam.v1.ops.mint_storage_capability=. The permission
   =iam::storage_capabilities:mint= keeps its own grammar and does not move.

2. *The model opted the TypeScript facet out.* =grants= is
   =std::vector<ores::security::jwt::storage_grant>=, a hand-written struct
   with no entity model, so the projection had nothing to render and the model
   silenced the facet. The facet's own escape hatch and the =protocol-twins=
   gate had opposite intentions, so the fix is to close the gap rather than
   loosen the gate: =ores::security::jwt::storage_grant= joins
   =_TS_UTILITY_DOMAIN_TYPES= with a hand-written =StorageGrant= interface in
   =security/payload.ts=, beside the trading and diff payload modules that
   exist for the same reason. Removing the opt-out then generates the twin.

* Result

The mint subject is =iam.v1.ops.mint_storage_capability=, the model carries no
TypeScript facet opt-out, and =storage_capability_operations_protocol.ts= is
generated with a =StorageGrant= import from =security/payload.ts=.
=subject-conformance=, =protocol-twins=, =codegen-tests= and =format= all pass,
so a clean trunk is no longer red.

The lesson for the local checks: the ratchet held the subject grammar to zero
violations, and the first thing merged after the PR gates came out broke it. A
gate that only runs when someone remembers to run it is a gate with a delay.
