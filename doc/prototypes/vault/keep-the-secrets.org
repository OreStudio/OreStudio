This page documents the [[file:keep-the-secrets/index.html][prototype]] beside it.
It is the design note the task requires: the
[[id:CF052805-2B7A-46B9-B14C-EF8BCF810C44][record screen standard]]'s rule
identifier for every part the screens use, the operation each screen would call,
and the list of what is invented.

The prototype answers the journey
[[id:B14B2A74-CA0D-4A83-9C0A-46CAB79F6E8B][Keep the installation's secrets]]. It
holds four screens and thirteen addresses: =?screen=secrets|secret|consumers|uses=
with =&state=empty|full|refused= (the secret's own states are
=masked|revealed|refused=), plus =?screen=states=, which lists them all.

* The parts, and the rule each answers to

#+ATTR_HTML: :class hug-leading
| Part | Rule | What the prototype draws |
|------+------+--------------------------|
| The breadcrumb and the plural title | *RS-LIST-01* | Home › Secrets, with =Secrets= as the title in sentence case |
| The sentence under the title | *RS-LIST-02* | One sentence saying what the records are |
| /Refresh/ and /Add/, in that order at the right | *RS-LIST-03* | Refresh always; Add only for a person who holds the write |
| The rows | *RS-LIST-15* | Name as a link, the owning consumer, the current version, the protecting key's version, and when it was last read |
| The version stream | *RS-HIST-01* | The secret's own versions, newest first, each with its reason |
| Add and Change | *RS-ADDR-01* | Dialogs over the page, and no address of their own; the prototype draws the entry point to each and leaves the dialog body to the build |
| A rule across fields | *RS-WRITE-08* | Named in the dialog before Save; the prototype does not decide which rule, only that one exists |
| An action the person may not take | *RS-FEEDBACK-01* | Not drawn at all in the refused states, never drawn disabled |
| Whether the person may change a record | *RS-FEEDBACK-02* | The read-only access mark in the refused states |

The uses screen answers to no rule. The prototype draws it as a proposal and says
so on the page; the gap is
[[id:AB30FE64-5790-4942-A1CB-30CB7AE17530][a capture]].

* The operations each screen would call

#+ATTR_HTML: :class hug-leading
| Screen | Operation | Door | Status |
|--------+-----------+------+--------|
| Secrets | list the secrets | =GET /api/v1/vault/secrets= | missing; [[id:050BEC49-2581-4D6E-A404-75186205EF09][the web task]] |
| Secrets | write a secret | =POST /api/v1/vault/secrets= | exists |
| Secret | one secret and its versions | =GET /api/v1/vault/secrets/{name}= | missing; the web task |
| Secret | reveal the value | =GET /api/v1/vault/secrets/{name}/value= | exists, and it records the ask |
| Secret | delete | =DELETE /api/v1/vault/secrets/{name}= | missing; the web task |
| Consumers | list and write | =GET= and =POST /api/v1/vault/consumers= | missing; the web task |
| Uses | list the resolves | — | missing; the capture |

No BFF sits between the person and the vault: the two doors that exist are
=ores.http='s own, and the rest are the same gateway's when they land.

* Every value that is fake

- The four secrets and their names, owners, versions, key versions and last-read
  times.
- The three versions of =db.marketdata_service.password=, with their authors
  (=vault provision= and =marco=) and reasons.
- The three consumers, their subjects, the shortened key fingerprints and their
  enabled state.
- The three uses: their times, secrets, consumers, actors and key versions.
- The revealed value =f3a9-tyJ_03fl7eLhAn8_fv3fHvRFzhm=, which is not a password
  and is not the shape of one this deployment issues.
- The date "27 Nov 2026" and the phrase "last rotated".

Nothing else is invented: the rules, the operations and their statuses are the
tree's.

* What the prototype settles

How a version list marks the current version (the row's version is the title of
the record, and the stream is newest first); the words for a secret no consumer
has read (*never*, in the last-read column, rather than a blank); where a refusal
sits (a card under the title, in the place the part would occupy); and what a
masked value says (one control, one line about the record the ask leaves).
