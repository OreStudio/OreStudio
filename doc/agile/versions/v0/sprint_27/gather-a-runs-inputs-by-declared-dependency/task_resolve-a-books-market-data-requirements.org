* Goal

=gather_market_data= exports every series the tenant holds, at whatever the
database contains at the moment it runs. Nothing can say which market data a
book's trades actually need, so nothing can narrow the export, and nothing ties
the data to the run's date.

Resolve it, for one book at one as-of: from the book to its trades, from the
trades to the market data requirements they imply, expressed as =oresmd=, and
from those requirements to the series, observations and fixings that answer
them.

* Acceptance

- The resolution answers, for one book and one date, which oresmd data a run
  of that book requires.
- A requirement that no series answers is reported as a gap, not skipped.
- The resolution is reproducible for an as-of date.
- Where the resolution lives is decided and recorded, with the reason.

* Plan

*The crux is where the requirement grammar lives.* A trade names its
instruments and those instruments name indices, currencies and tenors; the
definition's curve configurations name the quotes a curve needs. Both halves
already exist as rows. But an =oresmd= requirement is spelled by C++ codecs —
=oresmd_uri_codec= and =ore_key_codec= — so "all in the database" means either
restating that grammar in SQL or moving it into SQL and having C++ read it.
That is the decision this task exists to take, and the two honest shapes are:

- a SQL function that resolves book to series and returns the rows, with the
  oresmd spelling left to the caller that already knows the grammar; or
- the grammar expressed once in SQL and consumed from both sides.

A split — SQL for book to trades to instrument attributes, C++ for the
requirement spelling — is the third shape and probably the first one built,
because it needs no grammar to move and still removes the per-trade round
trip. It should be recorded as a starting point rather than a resting place if
the grammar then has two homes.

*What the requirements are derived from* is the other half. The candidates are
the trades' instruments and the curve configurations the run binds; both are
needed, because a portfolio's instruments need curves and the curves need
quotes. The investigation should state which entity answers an oresmd
requirement today, because if none does, that entity is part of this task.
