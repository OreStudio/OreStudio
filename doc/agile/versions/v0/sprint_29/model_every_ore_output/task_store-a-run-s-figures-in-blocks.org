* Goal

The post-processor's memory does not grow with the size of a run's output.

Today it reads a whole family into memory, builds every row, and inserts them in
one statement. A large run holds millions of rows before the first is written.
It should read a block of rows, write the block, and read the next.

* Acceptance

- The readers hand back rows a block at a time, or the post-processor asks for a
  block and gets one.
- Each block is inserted with one statement, so the round trips stay proportional
  to blocks and not to rows.
- Peak memory for a run is bounded by the block size and not by the family's row
  count, and the bound is stated.
- A refusal still stops the run before any block is written, or the write is one
  transaction so a partial load cannot be seen.
- The measured peak memory and the wall clock of a large synthetic run are
  recorded on the task.

* Plan

The unit is a block of rows, stated once, and both readers and writers use it.
The insert stays one statement per block, which is the same shape as today's one
statement per family but with a ceiling.

The run's figures are written in one transaction, so a refusal part way through
leaves nothing behind: a partial load reads as a complete one, which is the rule
this story already keeps everywhere else.
