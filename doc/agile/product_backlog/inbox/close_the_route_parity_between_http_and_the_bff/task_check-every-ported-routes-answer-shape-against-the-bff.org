* Goal

Two routes answered a bare array where the BFF answered an object with a member: a report's runs answered an array instead of {runs: [...]}, and the screen read the missing member as no rows. The inventory pairs addresses, and each port task proves a payload by hand, but nothing compares the shape a route answers with the shape the BFF answered, so a member the client reads can be absent and the screen reads it as empty.

* Acceptance

- A harness sends the same request to the gateway and to the BFF and compares the status and the payload shape: member names and their types, not values.
- It covers every route pair the inventory records, not a sample chosen by hand.
- Every difference is either fixed or written down with the reason it stays.
- The check runs in the gate, so a later port cannot drift without failing it.

** See also

-* The other half: the parameters a screen sends

A route also differs from the BFF in the query it takes. ores.http refuses a
parameter a read does not declare, which tells a person their query did nothing,
while the BFF ignored it. That is the better rule, and it breaks a screen whose
call states a parameter the port did not declare: a series' observations refused
the as_of a chosen day states, a report's runs refused a search, and each looked
like a fault in the screen. The sweep therefore compares both: the members an
answer states, and the parameters a route takes, against what the screens send.
