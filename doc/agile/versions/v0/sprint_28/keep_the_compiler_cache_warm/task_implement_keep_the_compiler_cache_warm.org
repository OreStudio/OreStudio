* Goal

A continuous run that is cancelled or times out still persists the compiler objects it produced, so the cache warms across runs instead of resetting.

* Acceptance

- The delete and save steps run when the CTest step ran, even if the job was cancelled.
- A run whose local cache is too small to help leaves the existing entry untouched.
- A normal completed run still replaces its entry as it does today.

* Plan

Persist the local sccache directory whenever the build produced enough of
it to be worth keeping, whether or not the job was cancelled, and leave
the existing entry alone otherwise.

* Notes

** The guard was the defect

Both steps ran only when the job was not cancelled. A job that hits the
six-hour limit is cancelled, so it saved nothing, and the next run
restored the same stale entry. The cache could never warm, and the job
could never finish. That is the whole of the failure.

** Why a floor

A run that fails before it compiles much must not replace a good entry,
because the save cannot overwrite a key and the delete comes first. Below
1000 MB the local cache is not worth that deletion, so the steps are
skipped and the existing entry survives.

** Trade-off

The floor compares an uncompressed local directory against a compressed
remote entry, so it is a proxy rather than a measurement. It only has to
hold until one run completes; after that runs save normally.

* Result

Continuous Linux now saves its compiler cache after any run whose local
cache grew past 1000 MB, whether or not the job was cancelled, and leaves
the existing entry alone otherwise. That is what lets the cache warm
across runs instead of resetting on every six-hour timeout.

The gate passes 7 of 7 (classes =ci=, =docs=).

Not verified here: no run has yet exercised the new guard. The first
scheduled run after this merges is the proof, and the hit rate of the run
after that is the number that matters.
