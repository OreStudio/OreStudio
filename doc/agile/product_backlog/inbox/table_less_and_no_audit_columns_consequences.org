* What

Regenerate =ores.marketdata= in the same commit that brings it over, and fix
the two hand-written tests that populate the member on the way.

=:no_audit_columns:= now drops =recorded_at= from the domain type as well as the
version column and the four audit columns. =marketdata= is to-do -- it is not in
=COMPONENTS_UNDER_TEST=, so no gate covers it and its checked-in generated
output is already behind the templates. When it is brought over, these change:

- =projects/ores.marketdata/modeling/ores.marketdata.market_fixing.org=
- =projects/ores.marketdata/modeling/ores.marketdata.market_observation.org=

Both state =:no_audit_columns:=, so their domain types lose the member. Two
hand-written tests set it on a constructed object and will stop compiling:

- =projects/ores.marketdata/api/tests/domain_market_fixing_tests.cpp= (three
  assignments)
- =projects/ores.marketdata/api/tests/domain_market_observation_tests.cpp= (two
  assignments)

Neither test asserts on the value -- they build a populated struct and then
exercise something else -- so the fix is to delete the assignments, not to
re-add the member.

* Why

Deleting is right because nothing reads the member. Its only consumer is
=build_entity_history_versions=, and the history-provider facet is withheld for
every =no_audit_columns= entity: =flat_history_version_source= requires a
version type carrying =modified_by= *and* =recorded_at=, and =no_audit_columns=
drops the actor. A lone timestamp cannot serve the one thing it is for.

The table keeps its transaction-time window either way. =valid_from=/=valid_to=
and the GIST exclusion are the table's, not the domain type's, and the insert
function still sets =NEW.valid_from = clock_timestamp()=.
