* Effect

Modifier on =:rls_tenant_isolation=: emits the shared-reference and
installation-scoped policy shape. The =using= clause admits a row when
its =tenant_id= equals the session's tenant or the system tenant, and
the =with check= clause confines every write to the session's tenant:

#+begin_src sql
for all using (
    tenant_id = ores_iam_current_tenant_id_fn()
    or tenant_id = ores_utility_system_tenant_id_fn()
)
with check (
    tenant_id = ores_iam_current_tenant_id_fn()
)
#+end_src

The name states the rows the policy admits and puts =tenant_id= on the
left of both comparisons. That is deliberate. The existing
=:rls_system_tenant_visible:= names the *session* and emits =current =
system=, which admits one tenant's rows to another and is the shape
=check_rls_system_tenant_widenings.py= flags. This feature admits only
the system tenant's own rows to everyone, so the guard does not flag
it. The two names never mean the same thing, and the two flags are
mutually exclusive, so a model cannot ask for both.

Requires =:rls_tenant_isolation:=; without it the model's policy block
is not emitted at all. The permission decides who may call the read,
exactly as =compute::grid_samples:read= does today.

* Structural consequence

None on the logical shape — only the generated policy body differs.

* Used by

=ores.compute.grid_sample= and =ores.compute.node_sample=, the
installation's fleet samples. Deliberately not fixed by any profile.
