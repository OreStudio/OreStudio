* Decisions

- An immutable entity keeps its generated C++ =remove= methods. The store
  refuses the delete, and =:read_only:= keeps delete verbs off the wire.
- An enforced foreign key is opt-in per key with =:enforce: true=. The
  generator refuses it for a temporal target, because a =REFERENCES=
  constraint would accept a closed version as current.
- Composite keys are pinned keys in their own SQL table rather than
  entries in =* Foreign keys=, which C++ consumers read one column at a
  time. Named unique keys reuse the =** Indexes= table.
- The C1202 guard was abandoned before it was built. A nine-member cap on
  generated structs would flag 220 models that compile and miss the
  struct that fails, a hand-written carrier written as a tagged variant.

* Result

The generator can now express the first trade shape tables. Three tasks
shipped and one was abandoned on evidence.

- A model can declare an immutable entity. The store refuses every
  update, delete and truncate, and the repository inserts rather than
  upserts (PR 2526).
- A foreign key into an immutable entity can be a real constraint,
  matching the row's tenant (PR 2529).
- A pinned key holds a copied fact to its source: a constraint against an
  immutable source, a trigger check against a temporal one (PR 2531).
- Each capability was tested against PostgreSQL in transactions that
  rolled back.
- The C1202 guard was abandoned. Its nine-member rule does not hold, and
  the measured rule is now in the Data-Oriented Design note. The Windows
  build that fails on main today is filed as a capture.
