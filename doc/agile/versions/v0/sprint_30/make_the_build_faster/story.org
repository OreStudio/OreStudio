* Goal

Builds get fast enough that integration moves more often and an advisory PR build becomes possible. Today a continuous Linux build takes 42 min (debug) to 90 min (release) on a 4-core runner, sccache hits 38% of compiles, one unity unit (ores.synthetic.core.tests unity_0) takes 24 min alone, and setup costs 7 to 10 min. Unity builds stay: they cut CI from 230-280 min to 60-130 min. No new hardware is available, so all experiments run on GitHub-hosted runners.

* Acceptance

- The unity batch size of each heavy target is chosen from a measured comparison of 16, 8, 4 and off.
- No single compile unit takes more than 5 min on the CI runner.
- CI setup before the build takes at most 2 min.
- A measured distribution of incremental PR build times decides whether an advisory PR build job is added.

* Decisions

- *Keep unity builds.* Unity (commit 7f2c4f037a, 2026-10-27) cut the continuous Linux build-and-test step from 230-280 min to 60-130 min. Without it a cold debug run is close to the 6-hour job limit. Tune the batch size per target instead of removing it.
- *Run every experiment on GitHub-hosted runners.* The repository is public, so the minutes are free, and the local machine already serves 10 worktrees with 2 concurrent builds.
- *A PR build, if any, is advisory.* It cannot reliably finish in 5 to 15 min on a 4-core runner, so it must not block a merge.
- *Evidence, run 42954775219 (2026-11-11).* Build 42 min (debug) and 90 min (release); tests 9 to 10 min; setup 7 to 10 min; sccache hit 347 of 914 compiles. Continuous runs since unity vary from 22 to 177 min on near-identical code, so a warm cache already gives a fast build.
