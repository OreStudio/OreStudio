* Goal

A compass check fails any C++ source that calls BOOST_LOG_SEV or BOOST_LOG_SCOPED_LOGGER_TAG outside ores.logging/src/logger.cpp, and names the ORES_ macro to use instead, so the 604-object Boost.Log reach the logger handle removed does not come back.

  =BOOST_LOG_SCOPED_LOGGER_TAG= in every C++ source except

* Notes

- compass-85 advised the form. =CPP_NAME= matches a macro invocation and skips
  comments and strings. =OUTSIDE= is the place for a permanent exemption,
  because =* Exceptions= rows expire, and it is set once per check, so the page
  is named for the concept (log through the ORE logger) and later rules share
  the exemption.
- Two calls to =BOOST_LOG_SEV= were left on main at 6ebe67a9ac, in
  =projects/ores.http/synthetic/tests/feed_tick_routes_tests.cpp= lines 158
  and 190. This task converts them.
- Not in this task: Boost.Log includes. Most are legitimate (=ores.logging=,
  the telemetry sinks, the test scoped attributes). Two look like leftovers:
  =ores.synthetic/service/src/market_regime_handler.hpp= includes
  =boost/log/trivial.hpp= but logs only through =ORES_LOG_SEV=, and
  =ores.http/reporting/src/routes/reporting/run_routes.cpp= includes
  =boost/log/sources/record_ostream.hpp=. A =CPP_INCLUDE= rule on
  =boost/log= would need a wider =OUTSIDE=.

* Result

=compass/checks/ores_logger.org= forbids both Boost.Log macros outside the
logger backend, and each finding names its ORES_ replacement. The two calls left
on main are converted. With compass-ng 459f4a3, =compass check --codec
ores_logger= gives 0 diagnostics and its four examples pass. One call put back
on line 158 gave =ores_logger/boost_log_sev= with the fix text, and exit 1.
