* Acceptance

- A book lists the product types it allows, and a role lists the product types it permits.
- An unrestricted book and a deliberately empty one are distinguishable, and the rule is stated.
- The booking path refuses a type the book does not allow, and says which rule refused it.
- The ACME seed covers all 121 types for the books and roles it creates.
- Both junctions reference the product type table and carry a test.

* Plan

Two junctions, and one column that decides which of them applies.

- =ores_refdata_book_product_types_tbl= holds the product types a book allows,
  and =ores_refdata_books_tbl.restricts_product_types= says whether the junction
  is the allowed set or whether the book allows everything. An unrestricted book
  keeps no rows, so the same absence of rows means "all" on one book and "none"
  on another, and the flag is what tells them apart.
- =ores_iam_role_product_types_tbl= holds the product types a role may book. A
  blank junction permits nothing, which is the safe reading for an authority and
  the opposite of a book.
- Both name the catalogue by code, a soft reference: the catalogue belongs to the
  trading component and a foreign key would point refdata and IAM at the trades.
- The booking path reads the book's flag first, then the junction, and refuses
  with the rule that refused it.
- ACME seeds every book and role with all 121 types, which is the unrestricted
  reading written as data so a later restriction has somewhere to start.

* Notes

** 2026-11-03 — the model decides the question the acceptance asks

A book with no rows and a role with no rows mean opposite things, and that is the
part worth stating rather than discovering: a book is a container a tenant
configures, so a blank set is "nothing was restricted"; a role is an authority a
tenant grants, so a blank set is "nothing was granted". The book carries a flag
to say which; the role does not need one, because its junction is the grant.

Both junctions name the catalogue by code rather than by a foreign key. The
catalogue is the trading component's and the junctions belong to refdata and IAM,
so a key would point the reference data at the trades; the same soft reference is
what the instrument tables already use for a product type.
