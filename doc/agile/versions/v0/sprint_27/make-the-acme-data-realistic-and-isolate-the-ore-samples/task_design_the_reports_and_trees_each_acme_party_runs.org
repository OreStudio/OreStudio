* Goal

Today every ACME party holds the same 31 report definitions. No party has a risk report config. The portfolio trees and currencies are not reviewed for realism. Design, per party, the reports that party would run, justify each choice in a document that a reviewer can read later, then seed the matching configuration, portfolio tree, root portfolio and currencies.

* Acceptance

- A design document states, for each of the four parties, which reports it runs and why, from its role, its jurisdiction and its place in the group. Each decision names its justification and the alternative rejected.
- Provisioning gives each party only the reports in the design. Each party publishes its own report definitions dataset, and the generic tiered set no longer reaches the Acme parties or the system party.
- Each party's report definitions carry the configuration they need, with a base currency that matches the party.
- Each party has a realistic portfolio tree, root portfolio and currencies, and each report scope names portfolios that exist for that party.
- The seeds carry no comment that states a count. Existing count comments in the files the task touches are removed.
- Trades are out of scope. The task proves the definitions, configs and trees on a clean provision, and records what it did not prove.

* Plan

3. Trades are ignored for now.
4. The portfolio tree, root portfolio and currencies must be realistic.

* Notes

Audit of the local database and the publish functions, 2026-10-11. The
database schema was stale against the checkout, so the functions were read from
the files.

- Every ACME party holds all the seeded definitions, including the
  holding-company reports and the UK-only, US-only and HK-only reports.
- The definition publish filters by =tiers= and =jurisdiction=. The party
  provisioning plan in =party_provisioning_plan.hpp= sets only =party_id=, so
  the filter never runs. Both fields exist in =publish_bundle_params= and no
  code sets them.
- No party has a risk report config. The config publish skips a definition
  that lacks four ORE bindings: pricing engines, today's market, curve
  configuration and conventions. Only synthetic definitions carry them.
- No seeded definition names a portfolio, book or netting set. An empty scope
  means everything the tenant can see.
- Every seeded risk config has base currency GBP, whatever the party. The
  publish uses the root portfolio's currency when it has one.
- Every party has a USD root portfolio, and two roots: Global Portfolio and
  Regulatory Capital. The publish takes the first by name.
- The official trees hold no trades. Trades are out of scope here.

Provisioning change, 2026-10-11.

- A profile's party stage published =party_essentials= to every party, and that
  bundle held the generic report definitions. The profile's first publish also
  named =risk_management=, which published the same definitions and the fixture
  portfolio tree to the system party. Both are why every party held the same
  reports.
- The fix is data only. The generic definitions and run settings moved to a new
  bundle, =party_reporting=. The two non-Acme profiles name it. The Acme demo
  profile does not, and no longer publishes =risk_management=.
- The tree finding changed with it. Before, every Acme party held the fixture
  tree. After, each party holds the tree its own bundle defines, which is the
  tree this task reworks next.
- The generator =generate_sql.py= produced differences in the books and staff
  photos scripts that this task did not cause. The committed scripts carry book
  purpose columns that the generator does not write. Another story fixes the
  book purpose, so those scripts were restored and left alone.
- The tenant setup still stops at the photo step, because of the account
  visibility defect. The report definitions and the trees publish before that
  step, so the proof above does not depend on the fix. The market feeds start
  after it, so the feeds are not proved.
- The entity-writes check reports five writers that this task did not touch.
