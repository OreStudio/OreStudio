* Result

The four approval gaps are closed.

- An opening book asks for the controller part. The policy model gained an
  operation value `create`, so an opening asks controller plus the field owners
  and an edit asks only the owners.
- A market data publish has a kind, a raiser and a decider. The trader asks
  through publish_curve, which raises marketdata.curve_publish for the market
  risk decider, and writes only with an approved request. republish_curve stays
  the ungated internal write and is named as the bypass.
- The tenant's Market Risk decides a tenant-wide convention change, never a
  party's, as a permission is held by an account in a tenant and the queue is
  tenant-scoped. The journeys and the demo note state it.
- A hold takes a code from a seeded lookup of ten reasons; a missing or unknown
  code is refused with the lookup's terms, and the shell and the decision panel
  offer the list.

Open by design: a publish request names no subject, so it authorises whatever
config the publisher passes; a curve has no published marker or publisher; the
Acme dataset has no curve config of its own; the shell needs a placeholder part
token for a request with no parts; only TenantAdmin holds refdata::books:write,
so a desk cannot raise a book change; and a put of a book id that no longer
exists counts as an opening.
