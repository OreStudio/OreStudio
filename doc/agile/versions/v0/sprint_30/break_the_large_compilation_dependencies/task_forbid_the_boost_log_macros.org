* Goal

A compass check fails any C++ source that calls BOOST_LOG_SEV or BOOST_LOG_SCOPED_LOGGER_TAG outside ores.logging/src/logger.cpp, and names the ORES_ macro to use instead, so the 604-object Boost.Log reach the logger handle removed does not come back.

* Acceptance

- =compass/checks/ores_logger.org= forbids =BOOST_LOG_SEV= and
  =BOOST_LOG_SCOPED_LOGGER_TAG= in every C++ source except
  =projects/ores.logging/src/logger.cpp=.
- It also forbids the Boost.Log headers only those macros need: the
  =boost/log/sources/= headers, =boost/log/trivial.hpp= and
  =boost/log/attributes/scoped_attribute.hpp=. The sink and attribute headers
  the telemetry sinks use stay allowed.
- Each finding names the ORES_ replacement, the header to include, and the
  Boost.Log include to remove.
- The page explains why, from this story, and carries examples that compass
  runs on every check.
- The tree has no finding: the two calls left on main are converted, and the
  four unused includes are removed.

* Notes

- compass-85 advised the form. =CPP_NAME= matches a macro invocation and skips
  comments and strings. =OUTSIDE= is the place for a permanent exemption,
  because =* Exceptions= rows expire, and it is set once per check, so the page
  is named for the concept (log through the ORE logger) and later rules share
  the exemption.
- Two calls to =BOOST_LOG_SEV= were left on main at 6ebe67a9ac, in
  =projects/ores.http/synthetic/tests/feed_tick_routes_tests.cpp= lines 158
  and 190. This task converts them.
- The product owner asked for the old includes too. The sweep left four files
  that included a Boost.Log header and used nothing from it:
  =ores.http/reporting/src/routes/reporting/run_routes.cpp=
  (=sources/record_ostream.hpp=),
  =ores.synthetic/service/src/market_regime_handler.hpp= (=trivial.hpp=), and
  =ores.testing/src/database_lifecycle_listener.cpp= and
  =test_database_manager.cpp= (=attributes/scoped_attribute.hpp=). This task
  removes them.
- The exemption widened from =logger.cpp= to =projects/ores.logging/src/**=,
  because =lifecycle_manager.cpp= includes =boost/log/sources/logger.hpp= to
  set up the sinks. The rule lists exact headers rather than all of
  =boost/log=, because the telemetry sinks need the sink and attribute
  headers.

* Result

=compass/checks/ores_logger.org= forbids both Boost.Log macros, and the
Boost.Log headers only they need, outside the logger backend. Each finding names
its ORES_ replacement and the include to remove. The two calls left on main are
converted and the four unused includes are removed. With compass-ng 459f4a3 and
with the v0.0.2 release, =compass check --codec ores_logger= gives 0
diagnostics and its six examples pass. One call put back on line 158 gave
=ores_logger/boost_log_sev=, and one include put back in
=market_regime_handler.hpp= gave =ores_logger/boost_log_source_headers=, each
with its fix text and exit 1.
