* Goal

A market series carries its identity only inside its oresmd_uri string. Add a projection table keyed by the series id with one column per identity field the codec schema declares, written from the same codec parse that writes the URI and in the same transaction as the series row. Then a query filters and joins on the identity fields, and the URI stays the only spelling the system writes.

* Acceptance

- A projection table exists, keyed by the series id, with one column per identity field the codec schema declares, plus the kind, the asset class, the instrument type, the quote type, the subject, the owning party and the tenant.
- A check compares the table's columns with the identity fields in the codec schema and fails when the two differ.
- The series write path projects the identity of every row it writes, in the same transaction, so a committed series carries its projection.
- A query that filters on a projected column, and one that joins it to another table, both run, and the plan shows an index is used.
- A URI neither codec reads is recorded with its kind and no field values, so it stays findable and is never mistaken for a series with empty fields.

* Plan

The column set is the union of the identity fields the codec schema declares, so one
column per =field= the schema marks =field_role::identity=, plus the columns that say
which kind of identity the row is. The list is not retyped: the entity model is written
from =schema.hpp= and a check fails when the two disagree.

The writer walks the codec's own parse. =oresmd_uri_codec::read= gives a =market_datum=
for a series URI and holds the subject field from the path like any other, so a writer
that iterates =datum.fields()= fills the right column for every instrument type with no
per-type code and no second reading of the grammar. A URI neither =read= nor
=read_index= admits is recorded with its kind and no field values, because refusing it
would fail the backfill and the generated test data, and because a row that records its
kind still says what it is.

The hook sits in =market_series_repository::write=, the one place a series row is
written, so the projection and the row commit together. The generated write body takes
one marker, which collapses to nothing for every other entity.

The index the acceptance names is over the columns a caller filters on first -- the
instrument type and the subject's own column -- because a filter that begins with the
asset class alone selects most of the table and the planner will not use it.
