* Acceptance

- After services stop/start, ACME's party-scope feeds run and ingest stores their observations.
- System feeds still start once.

* Plan

Cause, from the code and a repro in the brave_hopper environment: the boot walk
=auto_start_feeds= read the feed configs through the service's own database
context. That context belongs to the system tenant. Row-level security shows it
the system collections and nothing of any other tenant. A party-scope
collection is also hidden by the party policy unless the context has a visible
party set. So the 54 auto-start feeds of the ACME tenant were never seen.

Change, in =ores.synthetic.service/app/application.cpp=:

- The walk runs once for the system tenant, then once for each active tenant.
- A tenant's context is opened on its root party, so its whole party subtree is
  visible. A tenant has exactly one root party.
- A system feed starts only in the system pass, as =feed_run_control= already
  does for a start request.
- A failing tenant is logged and does not stop the others.
- The service links =ores.iam.core.lib= for the tenant list.

The bound-feed binding needs no token at boot. =bind_feed= skips on an empty
token, but =save_if_absent= ran when the feed first started, so the stored
binding survives the restart.

* Result

The boot walk now restores the auto-start feeds of every active tenant.

- Repro: fresh =db recreate=, ACME provisioning, then =compass services stop=
  and =start=. Before the fix the walk started 24 feeds and the observations
  stopped at the stop time.
- After the fix the walk starts 24 system feeds and 41 ACME feeds, and the
  observations table grows with =synthetic.bloomberg.*= sources again.
- Built with =compass build ores.synthetic.service=. No unit test covers the
  boot walk, and I did not add one.
- Not fixed: 13 vintage-priced ACME FX feeds (=price_source= vintage) still
  fail at boot with =marketdata.v1.market_series.list failed: forbidden=.
  Their start replays a vintage through the service's system-tenant token.
  That token lacks =marketdata::market_series:read=, and it would see no ACME
  series even with it. Those feeds start when a user starts them.
