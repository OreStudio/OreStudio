#+title: Start the fleet without systemd on macOS and Windows
#+description: compass services start/stop/status are systemd-only: they generate units and drive systemctl --user, and the controller/supervisor that used to exec and cascade-stop children was decommissioned when systemd took over. macOS and Windows runners have no systemd, so the nightly jobs cannot bring NATS up: the macOS run fails with 'nats-server did not become ready within 30s' and 'no systemd user unit nats-server-orestudio.service'. The CI suites need a non-systemd supervisor path: spawn nats-server and the ores binaries with a pid file per service, keep the existing log-based readiness gate (the loop already waits on port 20005), and cascade stop through the same pid files so the stop command stays complete.
