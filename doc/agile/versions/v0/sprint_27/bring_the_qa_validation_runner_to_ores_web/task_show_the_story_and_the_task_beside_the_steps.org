* Acceptance

- The Story and Task tabs show the rendered org doc of the scenario's story and task.
- An id link in either doc opens the doc it points to, and a link that does not resolve says so.
- A scenario with no story or task shows a plain message, not an error.
- Tests cover a resolving link, a dead link and a missing doc.

* Plan

The runner page gets three tabs through =useTabs=: Steps, Story and Task. The page needs no new BFF route, because task 3 serves a story, a task or a scenario by :ID: at =GET /api/qa/docs/:id=.

- =DocPanel= reads a doc by id and draws its title, its path and its text through =renderOrgHtml=. The renderer strips the file header, shows raw HTML as text and removes unsafe links. An id link in the text points at =/development/docs/:id=.
- =OrgText= follows an id link inside the app. A click on a link that carries =data-org-id= goes to the handler, so the app navigates without a page load. A click with a modifier key, or on any other link, behaves as the browser makes it.
- =DocPage= is the route an id link opens, so a link in the story reaches the task, and a link in the task reaches the story or any other doc.
- A doc the server cannot find answers not found, and the panel says that no story, task or scenario has the id and that the link may point at a doc the runner does not show. The server answers the same for an id no doc has and for a doc of a kind it does not serve, so the panel does not tell the two apart.
- A scenario that names no story or task shows a plain message on that tab. It is not an error.
- The runner stays mounted but hidden on the other tabs, so the marks and notes of a tester survive a look at the story.
