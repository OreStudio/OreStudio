* What

=ores_marketdata_ticks_tbl= declares a retention of seven days, but the create
script sets the policy only on the Timescale licence. This machine runs
TimescaleDB 2.30.2 under the Apache licence, which has no retention job, so the
script reports the interval and the table keeps every row. The table is not
compressed either, because row-level security does not work on compressed
chunks. Something must drop old chunks: a scheduled =drop_chunks= call from a
service or a cron job, since the extension will not.

* Why

At the runaway rate the table took about 41 million rows an hour. At the
fixed rate it takes about 140 thousand rows an hour per environment, and ten
environments share the instance.
