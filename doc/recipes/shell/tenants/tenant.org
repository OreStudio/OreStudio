#+title: How do I run the tenants commands from the shell?
#+description: Every command the tenants submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:tenants:

This file documents the tenants resource at the shell, one section per command. Every command is a subcommand of =tenants=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 88423337-07AB-5C82-8DCD-B0CB616EA00E
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
tenants list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =iam.v1.tenants.list=.

#+name: tenants-list
#+begin_src ores-shell :tangle tenants-list.ores :exports none
tenants list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 55E62677-D980-518C-89D5-CB16811CE3F8
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
tenants get <code>
#+end_example

It is addressed at =iam.v1.tenants.get=.

#+name: tenants-get
#+begin_src ores-shell :tangle tenants-get.ores :exports none
tenants get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 696A96E8-D9E4-59EF-B5C5-C87ACF36A3DD
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
tenants add <id> <code> <name> <type> <description> <hostname> <status> <reason> <commentary>
#+end_example

It is addressed at =iam.v1.tenants.put=.

#+name: tenants-add
#+begin_src ores-shell :tangle tenants-add.ores :exports none
tenants add 00000000-0000-0000-0000-000000000000 __none__ __none__ __none__ __none__ __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 45AE56DD-7E29-5115-A52C-E6B2BE6863E7
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
tenants set <id> <code> <name> <type> <description> <hostname> <status> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =iam.v1.tenants.put=.

#+name: tenants-set
#+begin_src ores-shell :tangle tenants-set.ores :exports none

#+end_src
