One underlying of a product, keyed to the trade, the list that states it and
the underlying's ordinal in that list.

ORE states an underlying as an =Underlying= block of its =underlying= type:
a type and a name, and optionally an identifier type, a currency, an
exchange, a weight, a price type and the commodity future terms. Twenty-four
places in ORE's schema state one, some once and some as a list. Every block
is a row here, so a product with one underlying holds one row and a basket
or a position holds one per member.

A product's fact row keeps the first underlying's name as its summary; the
rows keep everything the document states.

** Custom repository methods

The trade read path fetches the instrument underlyings of many instruments at
once, and no generated read covers that: the generated reads address one key
group at a time. The batch read below is one statement over the instrument
set.

*** read_by_instruments_batch
:PROPERTIES:
:ID: EA991EE0-0AFD-474B-903C-E52BAF895BDB
:END:

Reads every current instrument underlying of the given instruments, in one statement. An empty input
reads nothing.

#+begin_src cpp :name implementation :implements F2EB1914-5E94-42CA-9C77-46BDB364BF9E
std::vector<domain::instrument_underlying>
instrument_underlying_repository::read_by_instruments_batch(
    context ctx, const std::vector<std::string>& trade_ids) {
    if (trade_ids.empty())
        return {};
    static constexpr auto max = db_timestamp::max();
    const auto tid = ctx.tenant_id().to_string();
    const auto query = query_builder::read<std::vector<instrument_underlying_entity>> |
                       query_builder::where("tenant_id"_c == tid &&
                             "trade_id"_c.in(trade_ids) && "valid_to"_c == max) |
                       query_builder::order_by("trade_id"_c, "underlying_role"_c, "sequence_number"_c);
    return query_builder::execute_read_query<instrument_underlying_entity,
                                             domain::instrument_underlying>(
        ctx,
        query,
        [](const auto& entities) { return instrument_underlying_mapper::map(entities); },
        lg(),
        "Reading instrument underlyings for multiple instruments.");
}
