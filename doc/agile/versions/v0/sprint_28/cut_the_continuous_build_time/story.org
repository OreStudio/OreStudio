* Decisions

- *The build is not the constraint, so no compile-time lever was adopted.* The
  largest gap between build-step completions is 36.9 s and the median is 1.96 s,
  so the time is spread across all 7187 steps and there is no hotspot to split.
  Linking is 53 of those steps, so a faster linker cannot pay. A whole-tree unity
  build stops in 19 s, and precompiled headers were not reached because the
  measurement already showed there was nothing for them to recover.
- *The constraint was the compiler cache.* On 2026-10-03 the same job ran at an
  85.72 per cent hit rate and finished the whole build in about 49 minutes. A
  job that reached the six-hour limit was cancelled, and =Save sccache= was
  gated on =!cancelled()=, so the run threw away every object it had compiled.
  The cache could never warm and the job could never finish.
- *The fix belongs to the cache, and it landed as its own stories.* Keeping the
  save on a cancelled job, giving the save time to run, pruning older entries,
  scoping the keys per workflow, and restoring the gcc release job are separate
  stories in this sprint, because each is a defect in its own right rather than a
  build-time trial.

* Out of scope

- Precompiled headers. The hotspot measurement removed the reason to trial them,
  so this story closes without that trial rather than recording a result it
  never produced.
