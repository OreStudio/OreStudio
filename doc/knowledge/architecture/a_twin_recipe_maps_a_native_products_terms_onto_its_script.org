#+title: A twin recipe maps a native product's terms onto its script
#+description: How a product with both forms is booked as scripted: a recipe held as data names, for each script input, the native term that fills it.
#+type: knowledge
#+level: cross
#+filetags: :scripting:trading:architecture:
#+created: 2026-11-21
#+updated: 2026-11-21

* Summary

A product with both forms is booked as scripted by mapping its native terms
onto its script's inputs. The mapping is a recipe held as data, one row per
input naming the native term that fills it, in a small grammar of sources, and
not code per product. The same recipe serves the booking form's "book as
scripted", import of a native document as scripted, and the generator's twins.

* Detail

** The recipe

The =Scripted twin recipes= table of [[id:A8E9807F-1BC8-4DA5-9A66-720D2444DA1B][the trade type catalogue]] states, for each native
type and each input of its script, a source and an optional transform; the rows
are seeded into [[id:C0D2BFF8-3742-4FAE-92C0-3BD185147CCF][ores.trading.script_twin_input]]. A source reads the native trade's rows:

| Source | Reads |
|--------+-------|
| =product.COL= | a column of the native product row |
| =ROWS[ROLE].COL= | a column of the rows under a role |
| =COL[n]= | the n-th value |
| ='literal'= | a literal |
| =a or b= | =b= when =a= has no value |
| =a and b= | a list of =a='s values then =b='s, or an event's dates |
| =instrument_schedules[role]= | a whole schedule, by rules or by dates |
| =X shifted 1D on Calendar Convention= | an event derived from another input |

A transform turns a native word into the code a script reads, as the =Scripted
twin transforms= table states: =Long= to =1=, =UpAndOut= to =4=. A value the
transform does not list is refused, so a twin never carries a code its native
does not state.

** Where the recipe falls short

The recipe maps terms; it does not reconcile two implementations. Where ORE's
own class differs from its library script, the forms price differently, and
the ORE engine test lists the product with its reason and a bound: the FX
worst-of basket swap's library script reads one fixing per period where ORE's
class compounds.

** Where today's code differs

The recipe is evaluated in =ores.synthetic.core= for the generator only, so no
booking path books a product as scripted from its terms. The same evaluator
also books script-only products from a carrier type's rows, which
[[id:290A1069-A1EE-4DD1-8D23-1C60F76F8949][Every product has a schema of its fields and its forms]] replaces.
