#+title: Story: Close the IAM isolation gaps and review account visibility
#+description: Two IAM audit tables and three seed profile tables carry a tenant and have no isolation policy, so a session in one tenant can read another tenant's authentication events. The account visibility model built in PR 3124 widens what a tenant reads of the system tenant and what a service reads of a tenant, and was promised a review once its tests passed. This story closes the gaps and records the review as findings.

* Goal

No IAM table that carries a tenant is readable across the tenant boundary unless a model says why, and the account visibility model has been reviewed against a stated list of threats.

* Acceptance

- auth_events and run_token_issues enforce tenant isolation, and an event with no tenant is readable only by the system tenant.
- The seed profile tables state who may read them, in policy or in the ignore file with a reason that matches.
- Each threat in the account visibility review is a pgTAP or C++ test, or a recorded finding.
- validation_ignore.txt no longer states a reason that contradicts the table.
