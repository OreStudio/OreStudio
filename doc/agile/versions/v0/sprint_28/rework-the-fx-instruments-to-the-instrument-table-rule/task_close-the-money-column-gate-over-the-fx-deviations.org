* Result

The three shapes the review named were closed across two units, and this one
makes the gate say what it covers.

The continuous shape, a quantity whose name reads as money, was closed when the
variance strike landed (=a08b693bed=): =CONTINUOUS_COLUMNS= names the column
and its reason, so the entity that states it decides, and the exclusion list no
longer hides it. Money typed text was already reported; the money baseline
records the five that remain, all in other components. This unit closes the
remaining hole in the binary-float direction: the match read the literal word
=double=, so a money column typed =numeric= with a =float= in the domain passed.
It now matches either binary float, a field group's money member typed string
or float is reported too, and a missing baseline is an error rather than an
empty debt list.

Both baselines carry a header that states the format and what an empty list
means. The continuous baseline holds only its header, so the direction records
no debt and the next offender fails the check. The money baseline holds the
five text columns.

The exact-numbers page already forbids a prose copy of the baselines and points
at the check. It was corrected in =a07cbba44f=, before this unit, so it needed
no change here; the claim that it still counts ten columns was stale when the
task was written. The stale count did live in the codegen test's docstring, and
that is corrected.

* Decisions

- *The check stays on the models.* It does not read the ORE binding. A money
  value is lost at the binding only when a leaf is not a =moneyFloat=, and the
  digit tests and the goldens cover that seam directly; teaching this check a
  second input language would duplicate the binding's own drift guard.
- *An empty baseline is a statement, not an absence.* The header says so, and a
  test holds the reader to it, so the next offender in a clean direction fails
  rather than being absorbed.
- *The exclusion list stays for columns the name rule cannot classify.* It is
  not the mechanism for a continuous quantity any more; it remains for a money
  word that names a code or a quote, and each entry still needs its reason in
  the model prose.
