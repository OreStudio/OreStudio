#+title: How do I run the party_role_types commands from the shell?
#+description: Every command the party_role_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:party_role_types:

This file documents the party_role_types resource at the shell, one section per command. Every command is a subcommand of =party_role_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 16716F33-D0D1-5526-B1A9-947EA2F7562E
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
party_role_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =trading.v1.party_role_types.list=.

#+name: party_role_types-list
#+begin_src ores-shell :tangle party_role_types-list.ores :exports none
party_role_types list --limit 1
#+end_src

** =add=
:PROPERTIES:
:ID: C98C3D23-9832-5A59-B410-51250AC363E5
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
party_role_types add <code> <description> <reason> <commentary>
#+end_example

It is addressed at =trading.v1.party_role_types.put=.

#+name: party_role_types-add
#+begin_src ores-shell :tangle party_role_types-add.ores :exports none
party_role_types add __none__ __none__ system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 5810E0FF-446C-5F15-A381-538C2A583B86
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
party_role_types set <code> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =trading.v1.party_role_types.put=.

#+name: party_role_types-set
