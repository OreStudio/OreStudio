* Goal

Make it possible to watch a market data series live from the shell, with no UI and no code: marketdata stream takes an oresmd URI, subscribes to the republished tick stream the marketdata service already produces for the caller's tenant and party, and either prints each tick to the screen until the person presses Ctrl-C, or writes them to a CSV file. This is the fastest way to prove that a synthetic feed is ticking and that its ticks reach a consumer as themselves: a bound synthetic feed's observations are republished on marketdata.v1.tick.<tenant>.<party>.<ore_key>, so a stream command is the end-to-end test a person can run by hand.

* Acceptance

- marketdata stream <oresmd-uri> prints each tick as it arrives (observation time, the point oresmd URI, the value, the source) until Ctrl-C, and then prints a summary count.
- marketdata stream <oresmd-uri> --csv <path> writes one row per tick to the file, with a header, and still stops on Ctrl-C; the file is valid CSV for an empty run too.
- The command resolves the oresmd URI to the datum's canonical ORE key and subscribes to the republished subject for the caller's tenant and party; an unparseable URI is refused with the codec's own message, not a raw subject error.
- A series URI streams every point of that series, so a curve or surface can be watched without naming each point.
- Ctrl-C exits cleanly (no stack trace, exit code 0 or the conventional 130), and a stream that receives nothing says so rather than hanging silently.

* Plan

** Where it goes

A hand-written subcommand of the existing =marketdata= menu in
=projects/ores.shell/application/src/app/commands/marketdata_commands.cpp=,
beside the hand-written =import= and =export=. The per-entity menus are
generated; this one is not, and the file already carries the
=parse_args=-plus-=process_*= shape to follow.

** How it streams

- Resolve the argument with =oresmd_uri_codec= (the same codec the editor and
  the ingest use), then write the datum's canonical ORE key with
  =ore_key_codec::write=.
- Subscribe on the shell's existing NATS session to
  =market_tick_subject(tenant_id, party_id, ore_key)= from
  =ores.marketdata.api/domain/tick_subjects.hpp=: the republished consumer
  subject =marketdata.v1.tick.<tenant>.<party>.<key>=. The tenant and party
  come from the session, so the command needs no extra arguments for them.
  The subscribe-print-unsubscribe shape already exists in
  =ores.shell/application/src/app/commands/subscription_commands.cpp=.
- A series URI subscribes to the wildcard for that series' key prefix, so
  every point of the series streams.

** Screen and CSV

Default writes one line per tick to the stream the REPL prints to; =--csv
<path>= writes a header and one row per tick (=observation_time=,
=oresmd_uri=, =value=, =source=). Ctrl-C is a SIGINT handler that unsubscribes,
flushes and closes the file, prints the count and exits; the CSV is written
flush-per-row or on exit so a killed stream still leaves usable data.

** Testing

A command unit test with a stub session: a URI resolves to the expected
subject, the CSV has the header and the rows, and an unparseable URI is
refused with the codec's message. The end-to-end check is the manual scenario
in this task: start a synthetic feed, run the command and watch it tick.
