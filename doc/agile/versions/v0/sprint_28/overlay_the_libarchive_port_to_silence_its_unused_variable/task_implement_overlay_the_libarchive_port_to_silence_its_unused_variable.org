* Acceptance

- An overlay port for libarchive lists CMAKE_REQUIRE_FIND_PACKAGE_MbedTLS in MAYBE_UNUSED_VARIABLES.
- The overlay differs from the pinned port by that entry and a comment only.
- vcpkg selects the overlay and the port rebuilds.

* Plan

Copy the pinned port into =build/cmake/overlays/common/libarchive= and add
=CMAKE_REQUIRE_FIND_PACKAGE_MbedTLS= to =MAYBE_UNUSED_VARIABLES=. The overlay
directory is already on =VCPKG_OVERLAY_PORTS= (CMakeLists.txt:30), so nothing
else needs to point at it.

Copy rather than patch, because the change is to the portfile and the overlay
is the portfile. Keep the copy byte-identical apart from the one entry and a
comment, so that a reviewer can diff it against the submodule and a future bump
is a straight re-copy.

Verify by building, not by reading: diff the copy against the pinned port for
the first two acceptance items, then reconfigure so vcpkg installs from the
overlay and rebuilds the port.

* Result

The overlay is in place at =build/cmake/overlays/common/libarchive=, with =
CMAKE_REQUIRE_FIND_PACKAGE_MbedTLS= added to =MAYBE_UNUSED_VARIABLES=, which is
the remedy vcpkg's own message names.

It differs from the pinned port by fourteen added lines: thirteen of comment
explaining why it exists and when to drop it, and the one variable. The other
five files are byte identical to =vcpkg/ports/libarchive=.

Reconfiguring picks it up and rebuilds the port, so the overlay is both
selected and valid: vcpkg reports
=libarchive[bzip2,core,crypto,lz4,lzma,xar,zstd]:x64-linux@3.8.9 -- .../build/cmake/overlays/common/libarchive=,
logs =installing overlay port from here=, and the configure completes with the
project linking the rebuilt package.

The macOS warning itself is not reproduced here, because the variable is only
passed on OSX. What the Linux evidence establishes is that the overlay is used
and that the portfile runs; silencing the warning follows from the entry being
in the list the check consults.
