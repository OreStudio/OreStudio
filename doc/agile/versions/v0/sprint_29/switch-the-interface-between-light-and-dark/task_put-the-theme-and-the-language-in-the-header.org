* Acceptance

- A light palette states every role token the dark one does
- The theme toggle shows the palette it will switch to and survives a reload
- The language menu opens from the header and marks the language in use
- The account menu no longer carries a language select

* Plan

The palette is a second block of the same role tokens, selected on an attribute
of the document, so no screen learns that a second palette exists: every utility
already reads a role, and the block says what that role is in the light one.

The choice is kept in the module that owns it rather than in a React context.
The attribute on the document is the one place the palette is in force, and a
context would be a second copy that could disagree with it; a control subscribes
to the module with =useSyncExternalStore= instead, and a screen that never asks
for the palette pays nothing.

The language menu leaves the account menu for the header and reuses the
language label the header already carried. The document's =lang= attribute
follows the choice, so a screen reader and a browser's dictionary agree with the
menu.

* Result

The header carries the palette switch and the language menu beside the bell, and
the account menu keeps only the person's own pages. The palette survives a
reload, applies before the first paint, and the language sets the document's own
language with it.

The two icons are vendored from the Fluent set and recorded in the icon guide,
as the guide asks of a new icon.
