* Goal

The data-oriented design rules let a persisted model call itself "document-shaped" and so skip the table-shaped children check. That is how the curve configuration family came to store ORE's =curveconfig.xml= as 49 tables, with lists and ORE reference strings in its columns. The rules change so that no model can persist a document tree, a list or a serialised payload, whatever it calls itself.

* Acceptance

- [[id:BBD43BF2-9FEE-42B0-A667-9468AF759DC2][Data-Oriented Design in ORE Studio]] states that a document an external system defines (ORE XML, FpML, a CSV or JSON payload, an org file) is transient. It exists only at the boundary, where a mapping converts it to and from the core model, and it is never the shape of a table.
- The Regime 2 checklist adds the checks the clean-up applies: one value per column (no list, no JSON, no serialised object); references by key or oresmd identity, not by a string another system spells; one model for one thing; a tenor, a currency, a calendar or a convention is a validated key.
- The "not applicable" exemption for document-shaped types applies only to transient boundary types, never to an entity model.
- The =compass-code-review-data-model= skill reads the new checks.
