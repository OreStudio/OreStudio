* Goal

Two leftovers of the interface story are closed.

The first is the raw shell surface. The [[id:286B7167-9B8A-4937-BBA5-E9D285AFECE3][Object Storage]]
target state separates raw use from wrapped use, and promises that a caller
which only wants bytes somewhere can name a bucket, a key and a local path and
be done. The generated =objects= menu covers the NATS protocol, so the work is
the HTTP half: verbs that move files, and the client operations they need.

The second is the schema setup. A second =setup_schema.sql= run stopped, which
made the seed helpers' idempotency a matter of review rather than a thing
observed. The story closes that gap and gates the class, so the next statement
of the same kind cannot arrive unnoticed.

* Decisions

- *The raw surface speaks HTTP, not NATS.* A message bounds the value it
  carries, and the target state already says the bulk path is HTTP. So the new
  menu moves files and the generated =objects= menu keeps the command surface.
  Both interfaces stay exercisable by hand, which is what the interface story
  asked for.
- *The populate phase declares itself a reseed.* Its scripts state version zero,
  and the version gate refuses a create that meets a live row: 53 files stopped
  on the second run. Opening =ores_utility_allow_version_replace_fn()= for the
  populate transaction is the mechanism the gate documents for a reseeding
  generator, so one change closes all 53 without touching any of them. The cost
  is that a re-run re-asserts each seeded row at a new version instead of
  skipping it.
- *The class is gated, not the instance.* =check_sql_hygiene.py= now reports DDL
  a second run cannot repeat, so the next =create trigger= without =or replace=
  fails a check rather than a database recreation.
- *The two transports carry one listing document.* The HTTP listing and delete
  replies now carry the fields the protocol declares, so the shell parses either
  interface with the protocol's own type.

* Out of scope

- Fixing the reporting write path. The research this story commissioned found
  that =ores.reporting= writes its gathered blobs to the retired bucket
  =report-data= while =ores.ore= reads them from =ores=, so the writer and the
  reader of one object disagree. Reporting is another environment's live work, so
  the defect is captured rather than fixed here:

  a bucket ore does not read]].
- =HEAD= on the client. Existence stays a read, which is what the protocol
  declares.

* Result

Both leftovers are closed on PR
[[https://github.com/OreStudio/OreStudio/pull/2250][#2250]], with all nine
checks green.

*The raw surface.* The shell has a =storage= menu whose verbs are =put=, =get=,
=delete= and =list=, over HTTP, beside the generated =objects= menu that speaks
NATS. Both interfaces are therefore exercisable by hand, which is what the
interface story set out to do. The client grew the operations the surface
needed -- a body-returning GET and DELETE -- and the transfer helper and the URL
contract grew with it. The shell's two identical copies of the storage base URL
collapsed into one, and the routes now compose their patterns from the declared
prefix.

*The schema setup.* The create scripts needed one word: =create or replace
trigger= in a single hand-written file. The populate phase needed the reseed
declaration its own version gate documents, which closes 53 files at once.
=check_sql_hygiene.py= now reports DDL a second run cannot repeat, so the class
is gated rather than the instance.

*Cost paid, recorded.* A re-run re-asserts every seeded row at a new version
instead of skipping it, so the version history grows with each setup run. That
is the price of declaring the run a reseed, and it is the behaviour the gate's
own documentation asks for.

*Found, not fixed.* The research the story commissioned established what the
interface task's note about the trading and marketdata export handlers meant:
those handlers own no bucket, =ores.reporting= names one for them, and it names
=report-data= while =ores.ore= reads =ores=. The capture carries the finding and
the lines that prove it.
