* Goal

The projection exists and every write fills it, but series that predate it carry no row, and a caller still reads a single wide table. Seed the rows that are missing, and give each asset class a view over the columns its instrument types fill. Then a caller reads the view that matches the object it wants, joins it to the series and the observations, and finds every series the database holds rather than only the ones written since.

* Acceptance

- Every current series row has a projection row, including the rows written before the projection existed.
- Running the backfill again changes nothing and reports nothing left to do.
- An asset-class view exists for each asset class whose series carry an identity, and it exposes that class's identity fields and no others.
- A query reads a view, joins it to the series and to the observations, and returns a term structure or a surface for a scope the caller names.
- A series row whose URI the codec cannot read is reported by the backfill rather than silently skipped.

* Plan

Two halves, and the check holds both to the codec schema.

The views are one file of plain SQL, one view per asset class, written from
=schema.hpp= once and guarded afterwards. A view exposes the context columns every
view needs, then exactly the identity fields that class's instrument types fill,
and it filters on its own instrument type list rather than on the asset class,
because the instrument index is what the planner can use. Every view is
=security_invoker=, so the tenant policy on the table decides what the reading
session sees rather than the view owner.

The backfill is an operation on the series subject, because the rows it repairs
are ones the write path never saw: a database restored from a dump, or a series
written before the projection existed. It reads the projected series, inverts
that set, and projects only the rest, so a second call finds nothing and says so.
The projector returns how many series carried a URI neither codec reads, and the
backfill reports it, so an identity the database cannot state is visible rather
than quietly written as an empty row.

=check_marketdata_identity_columns.py= grows the view half: every class with a
series must have a view, a view must not carry a field its class does not give,
and a view must name every instrument type of its class. It also keeps the two
earlier assertions, the table's columns and the projector's field placement.

* Result

The projection is now complete and readable. A series the write path never saw
is repaired on demand, and a caller reads the identity columns its asset class
fills rather than the whole wide table.

What landed:

- Ten asset-class views, one per class the codec schema gives a series, each
  exposing its class's identity fields and naming its class's instrument types.
  Every view is =security_invoker=, so the tenant policy on the table decides
  what the reading session sees.
- The =backfill_series_identity= operation on the market series subject. It
  reads what is already projected, inverts that set, and projects only the rest,
  so a second call finds nothing to do. It is registered by hand in
  =registrar.cpp=, beside the export operation.
- =market_series_identity_projector::project= returns how many series carried a
  URI neither codec reads, and the backfill reports that count.
- =check_marketdata_identity_columns.py= now holds the views to the schema as
  well as the table and the projector.

Limitations:

- Nothing was compiled and no test was run. The build and the suites are swift
  curie's hourly validation.
- The change adds a NATS operation and a SQL file, so the schema fingerprint
  moves and =compass db recreate= must run before the test binaries will start.
- The index (fixing) grammar is still out of scope. Such a series gets a row
  that records its kind and the asset class and no field value, and the backfill
  counts it as unreadable rather than guessing.
- A series removed through the repository still leaves its identity row behind,
  because the generated remove path carries no hook. The backfill does not
  repair that either, since it only adds rows the projection lacks.
- =component-drift --all= reports drift in =ores.trading= alone, from another
  environment's in-flight work. No marketdata artefact drifts.
- The =web= local check fails on prettier formatting in ten files another
  environment is editing, none of them the generated protocol this change
  touches. The =er-diagram= check fails under the bare =python3= of this
  checkout, which has no =pystache=; the diagram is unchanged, because the
  parser does not read views.
