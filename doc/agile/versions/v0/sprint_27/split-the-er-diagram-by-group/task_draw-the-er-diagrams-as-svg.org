* Result

The drawing step emits SVG and every generated diagram is drawn, not only
the index: the script expands =ores_schema*.puml= and the CMake target
does the same through =bash -c=, because CMake cannot expand a glob in a
=COMMAND= and the file set has to follow the model rather than a list
kept in the build description. 22 diagrams draw in one pass, 4.5 MB in
total, and a pass writes no PNG and no cmapx.

=ores_schema.png= and =ores_schema.cmapx= are deleted from the index. The
SVGs that replace them are committed: they are what the documentation
site renders, through =proj:= links that export as image tags pointing at
the file in the repository, so an image outside the tree is a broken
page. The first cut of this task ignored them, which would have published
a schema page with no schema on it.

=ORES_JAVA_ARGS= is shared with the sixteen component diagrams that still
draw PNGs, so it keeps =PLANTUML_LIMIT_SIZE=; the ER target passes it
through and adds =-tsvg=. The script's own invocation drops the limit,
since a vector has no pixel count to overflow, and its java fallback does
the same.

The conventions doc names the drawn files, links the index and every
group image so the site shows them, and the memory note now counts the
SVGs among the addresses a model change has to regenerate.
