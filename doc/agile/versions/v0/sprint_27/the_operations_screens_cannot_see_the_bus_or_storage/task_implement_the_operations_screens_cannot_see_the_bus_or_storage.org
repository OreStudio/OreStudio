* Notes

=projects/modeling/service_registry.org= is the shared model every
environment deploys from, so it must not carry a port at all. The telemetry
entry carried =http://localhost:8221=, a leftover of the retired
=42221xxx/8221xxx= scheme =env_init.py= names in its own comment. The C++
default is =8222= and this environment's port is =20406=; none of the three
agreed.

=env_init.py= already emits =ORES_TELEMETRY_SERVICE_NATS_MONITOR_URL= per
environment, in the same block as the service's database credentials, for
exactly this argument. Nothing read it: the native unit passed the literal
instead, and the C++ parser takes =--nats-monitor-url= from the command line
only. The fix makes the argument reference that variable, so the registry
stays free of ports and both the native and container paths read one value.

The poller logged a refused connection every 30 seconds and the screen showed
an empty bus with no error, because the read succeeds and returns no rows. A
read that is silently empty is what made this survive.

* Result

Done. The unit takes =--nats-monitor-url ${ORES_TELEMETRY_SERVICE_NATS_MONITOR_URL}=,
the poller reports =Monitoring localhost:20406 every 30s=, and samples reach
both tables. The message bus screen reads them: two server samples and the five
JetStream streams, including =ores_dev_brave_hopper_marketdata_ticks= at 1.2M
messages.
