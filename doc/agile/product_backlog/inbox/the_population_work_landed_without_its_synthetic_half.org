* What

Two component builds fail on =origin/main=, and both are one commit's missing
other half.

=cb28cc941d= "[iam,synthetic,refdata] Let a run state the population it wants"
calls =ores::synthetic::service::routed_code_count(asset_class)= from
=ores.iam/core/include/ores.iam.core/messaging/tenant_provisioning_handler.hpp=.
No header declares that function, and the commit's own file list holds no
synthetic file at all, so the half that would declare it never landed. It is the
function that answers how many codes a class's planner cycles, which the knob
check needs to refuse a share too small to hold them.

=ores.synthetic= does not compile either:
=trade_population_planner.cpp:1255= pushes an inflation swap instrument into a
batch of balance guaranteed swap instruments, so the planner and the generated
instrument batch disagree about the arrays.

=ores.iam.core= and =ores.trading.core= both depend on synthetic, so the failure
stops every C++ suite under them. A trading service change merged on 2026-10-31
(#4284) carries six written and compiled cases that have never run.

* Why

A red main hides real failures: a branch cannot tell its own breakage from the
one it inherits, and every PR raised on top is red for a reason its author does
not own. The proof is in this capture's own origin, where two runs of the same
=trading= build failed on the two other components before reaching the branch's
code.
