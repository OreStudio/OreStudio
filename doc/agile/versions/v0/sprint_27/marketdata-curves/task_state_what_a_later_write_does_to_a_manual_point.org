* Acceptance

- The policy is stated, in the story's decisions or a document the code cites.
- A test covers a later automatic write against a manual point, and asserts the
  outcome the policy states.
- The rule holds on the write path the import and the feed share, not only on the
  manual path.

* Plan

The read side already prefers a manual point to a later automatic value. So the
first step is to try the write side, through the import, and see what happens.

1. Write a test that over-keys a point, then imports the same coordinate at the
   same instant and at a later one. It failed: the same-instant import replaced
   the manual row, so the point read as manual with the feed's value.
2. Drop an automatic write to a coordinate an operator owns, in the insert the
   feed, the import and the republish share. =manual_point_guard= holds the rule.
   It is wired through the two hook slots of the generated insert, from the
   market observation model, so the codegen drift check stays clean.
3. Let =write_manual_point= write past the guard, because that write is the
   operator's.
4. Add =read_manual_for_series= to the lineage model, which the guard reads.

Decision: see the story's "A manual point owns its coordinate until it is cleared".

* Result

A manual point now owns its coordinate until it is cleared, on the write side as
well as the read side.

The read side already held. An automatic write at a later instant leaves the
manual row alone, and the as-of read prefers the manual point. The test through the
import found the write side did not. An import at the same instant replaced the
manual row, and the annex still named the point manual, so a reader saw the feed's
number labelled as an operator's. That was a real defect, and it is fixed.

- =manual_point_guard= drops an automatic write to a coordinate an operator owns.
  The generated insert calls it through its two hook slots, in the market
  observation model, so the codegen drift check stays clean.
- The feed, the import and the republish all write through that insert, so one rule
  covers all three. =write_manual_point= writes past the guard, because that write
  is the operator's. Clearing the point releases the coordinate.
- =read_manual_for_series= is in the lineage model and reads the cold manual annex.
- The policy is in the story: "A manual point owns its coordinate until it is
  cleared".

Three tests cover it. An import at the same instant and at a later one leaves the
manual value and its provenance. A manual point re-keyed twice shows the second
value. An import lands again once the point is cleared.

Cost. The guard adds one narrow read of the manual annex per series in an insert
batch. That includes the feed's per-tick insert. I did not measure it. A series
nobody over-keyed returns no rows.

Not done here. The generic write and put paths are explicit operator writes and do
not pass through the guard. The evolution read states the rows each instant holds,
so a later instant still shows the fed value there.
