* Result

* Result

- =ores.platform= gains =zone_offset_at=, which reads the offset a zone keeps
  from the TZif file the system's database holds. It reads the 64-bit block,
  never changes process state, and refuses a name that climbs out of the
  database. A reader is needed because libc++ ships no std::chrono time zone
  database, so =locate_zone= does not compile on macOS with any header.
- The fixing feed asks the library's database where there is one and the
  system's otherwise, which is a choice the preprocessor makes once.
- Proved against the library: a throwaway harness compared 52,560 instants
  across twelve zones and three years, and found no difference. The suite's own
  case repeats a narrower version of that comparison on every platform whose
  library has a database, and states the offsets outright where it has none.
- The four fixing cases pass unchanged, so the arithmetic that reads the offset
  is the one that was there before.
