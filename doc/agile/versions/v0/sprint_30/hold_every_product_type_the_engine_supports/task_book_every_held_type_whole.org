* Goal

The ORE import books every family through =book_trade=, as the generator does, so no instrument write is copied field by field and every row carries its audit. A parent and its embedded trades are written as one unit, and the export-and-rebook round trip holds for every family.

* Acceptance

- =book_trade= writes every member of a bond row the export reads, and the import books a bond through it; the import's hand-built bond requests are gone
- each instrument row the import writes carries the caller's audit, and no request leaves a field of its write struct unset
- an ORE import writes a parent and its embedded trades as one unit, so a failure leaves none of them behind
- the export-and-rebook round trip holds for every family, comparing the whole row apart from keys, version and audit
- each named defect has a test that fails without its fix, or evidence that it was already fixed

* Notes

** Split from the held-type defects task

Split from [[id:87282F95-BA5B-40CF-8D41-D4996BEE27BC][Close the known defects in the held trade types]] on 2026-11-15, which kept the representation defects. A child array of the wrong family is already refused by name (=instrument_not_routed=, trade_operations_service.cpp), so that part of the booked-trade capture is done.

The generator books a bond as =put_bond_issue_composite= for the security plus the trade's flat rows through =book_trade=. The import still sends the nested =bond_instrument_data= and writes its remainder through about thirty hand-built requests (ore_import_execute_handler.cpp). Flattening the import's bond the way the generator does removes those requests.
