* Plan

Measure the tree before writing any task, so each task states a figure rather
than an impression. The measurements below were taken against the running
environment at =a44998824c=.

Then one task per question the review raised, each with the acceptance that
closes it:

- the database's size against the host's free space, on both homes;
- the telemetry tables, which declare a bound nothing applies;
- the size a party holds, as a pie on the tenant's screen;
- a tenant's own size over time;
- how many bytes a policy bounds, as distinct from how many stores;
- the largest tables, with a pie of the top N.

One thing is captured rather than tasked, because it is a discovery and not a
request: the catalogue names ten stores and the installation holds 846
relations, so the count the screen states describes a tenth of the bytes.

* Measurements

Every number this task claims about a tree, with the command that produced it
and the commit it was measured at. A number without both is not a measurement,
because a clean-up record describes a tree and trunk moves under a branch: a
consumer count, a gate's component count and a suite's size all change with no
code changing, and the reader of a bare number cannot tell which tree it came
from. Where the raw output matters, put it in an =evidence/= file beside the
task and name that file in the Command column.
