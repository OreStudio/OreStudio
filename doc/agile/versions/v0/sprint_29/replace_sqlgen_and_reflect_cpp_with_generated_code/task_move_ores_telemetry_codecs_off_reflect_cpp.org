* Notes

** The generator named the wrong root for a core-owned type

Telemetry's operation models generate into =ores.telemetry.core=, not
=ores.telemetry.api=. The codec source includes the headers of the enum
member types, and =_member_headers= put every type of the component under
=<component>.api=. It now puts a type of the model's own component under the
model's own root. A test covers a core-owned type.

** The member-count guard and anonymous namespaces

The poller's reply types live in an anonymous namespace. The guard's
=any_member= declares a conversion it never defines, and clang reports that
as =-Wundefined-internal= for a type with internal linkage; =-Werror= makes it
fatal. gcc does not report it. The conversion is only named in an unevaluated
requirement, so the warning is true and harmless; a clang pragma around
=any_member= silences it, and a utility test probes a type of that kind.

** The precompiled header stays

The telemetry libraries still link =ores.rfl.pch=. The codec precompiled header
that replaces it belongs to [[id:7A1D09B8-B3F2-4E02-9669-3C2F6CC2C6EC][Remove reflect-cpp]].

* Result

ores.telemetry encodes and decodes without reflect-cpp. The three operation
models use the generated codec, and the NATS monitoring replies read through
the codec with their shapes stated beside them. The wire bytes match
reflect-cpp's in both JSON and MessagePack. The generator now finds the header
of a type owned by a core-rooted model, and the member-count guard compiles on
clang for a type in an anonymous namespace.
