#+title: The generated shell recipes no longer run
#+description: V04 of the refdata clean-standard pass ran all 732 generated refdata shell scripts against the live fleet: 93 abort. Two causes, both in the ores.doc.shell-recipe family. The scripts omit the session-party positional the generated command requires, so an add or a set fails its own arity check by one; and they send __none__ where the shell needs its absent token -, so every optional uuid, date and numeric field is refused. The archetype is still registered (template shell_recipe.org.mustache, output doc/recipes/shell/{shell_menu}/{entity}.org) but renders nothing: an explicit --address ores.doc.shell-recipe run reports no file and no warning, so the family is frozen at whatever the last working generator produced and cannot be refreshed by the drift gate. This affects all 144 entity menus, not only refdata.
