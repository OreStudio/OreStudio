* Acceptance

- Generated code defines no file-local name that another generated file of its directory also
  defines, including the generated tests.
- A test target defines its logger name once, in =test_suite.hpp=, and no test file defines
  =test_suite=, =tags= or =valid_party_id= of its own.
- The top-level build sets a unity build of 16 for every target, behind =ORES_UNITY_BUILD=.
- The hand-written sources that collide are kept out of the unity build by
  =cmake/unity_exclusions.cmake=, which =build/scripts/check_unity_collisions.py= keeps from
  growing.
- The whole tree builds and every suite passes as a unity build.
- A full build without ccache, on a quiet machine, measured against the baseline of about 17.2 CPU hours, with the command and commit.

* Plan

1. Make the test targets unity-safe without renaming in bulk: one
   =test_suite.hpp= per target, the tag literal in each =TEST_CASE=, and
   =valid_party_id= in =ores.testing=. A script does the change on the test
   files and the test templates, and a second script pins it: every test
   case keeps its name and its tags.
2. Prefix the generated helpers the first pass missed, and fully qualify the
   service header's protocol types.
3. Turn the unity build on once, at the top level, and keep the hand-written
   sources that do not build in a merged unit out of it, recorded in
   =cmake/unity_exclusions.cmake=. The record comes from a scan of
   file-local names and from the compiler: a loop builds with =-k 0=, records
   the hand-written files the errors blame, and repeats until green. A
   generated file is never recorded; its template is fixed.
4. Fix, not record, what the merged units show to be defects.
5. Run every suite from the unity build.
6. Measure the full build on a quiet machine.

* Notes

** What the merged units found

A unity build puts a target's files into one unit, and that showed defects the
tree already had. Each one is fixed, not recorded:

- Two =ores::iam::messaging::list_role_permissions_request= types with
  different members. They shared reflect-cpp's instantiations at link time,
  so the shell encoded one with the other's layout once the linker kept the
  other copy. The operation's message is now
  =list_role_permissions_page_request=, and =check_unique_type_names.py=
  keeps a second such pair out.
- Two =ores::shell::app::commands::subscription_commands= classes, one
  hand-written and one generated. The hand-written one is now
  =event_channel_commands=.
- The UUID and tenant parsers read an error value through =->=. Their read
  path had never compiled.
- The health monitor logged with Boost.Log's trivial severities, and its
  severity aliases shadowed the project's in a merged unit. It now uses
  =ores.logging=.
- Six model fragments used the old unprefixed queue group, so the first
  template pass did not compile for those registrars; the earlier byte check
  proved the renames but not that they compiled.

** What is recorded, not fixed

The 206 recorded files fall into two groups: names the scan sees, such as
duplicated helpers in the ORE projections, and clashes only the compiler
sees, such as types in anonymous namespaces and namespace aliases. The task
[[id:B6121657-0FF2-4570-8CAF-EAF77E1AFDDF][Remove the unity build exclusions]] pays them down. The check refuses a new
collision outside the record and refuses to record a generated file.

** Test failures that are not this change's

- =a_small_batch_does_not_pass_the_batches_that_are_in_the_stages= failed in
  both full runs and passed five times out of five alone.
- Three tenant tests in =ores.iam.core.tests= pass on a fresh run and fail on
  a second run against the same database, on a duplicate tenant code.

Both are captured in the backlog inbox.
