* Goal

The prototype argues what the binding screen shows and does: the list of bindings, the source and the series behind each, the last tick, the enabled state, bind and rebind, and start and stop. It has a synthetic scenario, which a person can follow to the end, and a real data scenario, which shows how a vendor binding would look and says that real feeds are not supported, so the design holds both and no screen offers to connect a real feed.

* Result

Marco signed the prototype off on 2026-10-13. It draws the bindings screen as the record screen standard draws a record screen, with the history as the shared timeline and an oresmd URL as the product ships it, and it has no layout variants. It has a synthetic scenario that runs to an added binding, and a real data scenario in which a vendor binding is read only and deletable. Marco decided what the standards left open: the screen lives in Market data beside the Synthetic folder, Edit offers the source name, a vendor binding can be deleted, and an operator adds and edits while only the system administrator deletes. The menu structure and the record screen standard now say so. One point stays open: the lead line follows the shipped feed page and not the standard's wording. The task Build the market data binding screen can now be split into server and web tasks.
