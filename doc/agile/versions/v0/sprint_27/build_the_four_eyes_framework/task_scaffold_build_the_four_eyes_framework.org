* Result

Wrote =doc/knowledge/architecture/four_eyes_framework.org=, which reads the
inbox as built (the request, its kinds, states and decisions, four-eyes in the
schema, the decide function, the sweeps, the notifications, and the role request
as the one kind with its own detail and apply) against what the five prototypes
draw. Four things are missing for a gated refdata write: several deciding parts, a
held pending change, a gate in the write path, and one set of screens for every
kind. The note adds parts, a policy, lines, raise and preview, an apply as one
transaction with an =apply_failed= state, a gate, and a kind descriptor on the web.

Filed nine tasks: parts and policy; lines, raise, preview and apply; the gate; the
common screens; and one to move each of the five screens onto the review panel
(book structure, counterparty, party, convention, tenor).

*One decision is open and blocks the second task.* How a line holds its proposed
write: a typed shadow table per gated entity, or one lines table with the canonical
serialisation of the generated write record. The note recommends the lines table and
flags that it reverses the earlier decision that a kind keeps a typed table.
