The five operations the vault answers, and the one read that makes a write
possible.

A write arrives with the value sealed to the vault's transport key, because no
caller sends a plaintext across the bus. A resolve leaves with the value sealed
to the caller's registered key, which the vault looks up by the subject in the
verified token. =describe= is the one read that answers no value at all.

None of these messages carries a plaintext, and none carries a ciphertext that a
party other than the named recipient can open.

The tenant is never a field: it arrives in the request context, scoped by the
token, exactly as every other read and write in the tree scopes it.

 * @brief Stores a new version of one secret, sealed to the vault.
 *

#+begin_src cpp :name comment
/**
 * @brief Re-wraps every secret of the tenant under a new key version.
 *
 * One audited act: every stored value is opened under the version that sealed it
 * and sealed again under the new one, and no plaintext leaves the process. A run
 * that fails part way leaves the rows it has not reached under the old version,
 * which is why every row records its own version.
 */
#+end_src
