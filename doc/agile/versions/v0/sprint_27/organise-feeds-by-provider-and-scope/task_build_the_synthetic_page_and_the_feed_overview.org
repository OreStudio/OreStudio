* Acceptance

- Market data has a Synthetic folder card. The Synthetic page holds the feed overview and the FX and IR feed cards.
- The feed overview drills down by scope, provider and feed kind in columns, shows the feeds, the running roll-up and the ticks, and never lists a feed.
- A server read returns a folder's children with their counts and run state, so no screen reads all feeds.
- Start and stop of a provider or a kind use the existing folder routes and report what started, what was already running and what was skipped.

* Plan

The shape is the [[id:17E6CB2C-E1C9-4911-81AC-591D88AC5B89][Browse the feed tree prototype]] and the
[[id:339F0405-43AE-4049-B6B3-EB12E5A38CA4][Menu structure]] page.

- A service read, =synthetic.v1.ops.list_feed_folders=, returns the children of one folder
  with the FX and IR feeds under each and the running ones. The roll-up is a pure function
  of the API library, =children_with_counts=, unit tested without a database; the handler
  runs three queries (the folders with their collection, the feeds grouped by folder, and
  the running source names grouped by folder) and calls it.
- The BFF route =GET /api/synthetic/feed-folders?parent=<id>= relays it.
- A folder card inside an area is new to the shell. A card names its folder with =in=, the
  Synthetic folder card is drawn on the Market data page, and the folder's page draws its
  cards. The feed screens move to =/market-data/synthetic/fx-feeds= and =ir-feeds=, and
  the earlier addresses redirect. Their trails gain the Synthetic step.
- The overview derives its columns from the hierarchy as it is: a collection folder is a
  provider (or generic), and its asset class folders are the feed kinds. System feeds are
  the collections whose scope says system.
