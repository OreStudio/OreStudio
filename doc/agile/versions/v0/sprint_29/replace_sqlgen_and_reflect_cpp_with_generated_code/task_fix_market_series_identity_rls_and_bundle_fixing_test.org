* Notes

** What main had already fixed

- The series identity RLS refusal: every =repository_series_identity_backfill_tests=
  case passes on the rebased branch.
- The terms handler failures: =9958dbf651= seeded the reader account the store
  needs.

** The bundle fixing pgTAP test

Main's feed rename (=84605bcf70=) turned the feed's =provider_code= into
=publisher_code=, which the table validates as a provider, and line 100 of
=synthetic_system_bundle_fixing_test.sql= still read the old name. It now
reads =publisher_code=. An earlier note here said main had fixed this test;
it had rewritten other lines of it, not this one, and the check's pgTAP run
showed the error.

** What the terms fix broke

=9958dbf651= wrote its reader as a user account into the suite's tenant.
=ores_iam_validate_account_username_fn= lets a tenant with no user account
write an empty =modified_by= (it becomes =current_user=) and refuses one
after. The suite's import tests write with an empty actor, so each one that
ran after the terms test failed, and none failed alone. The reader is now a
service account: the store accepts any current account as the acceptor, and
the bootstrap check ignores service accounts.

** The export counts

The two export tests read every series and expected only their own. A tenant
reads the system tenant's rows as well, and the running fleet writes series
there, which is why the counts moved between runs (58, 56, then 4). The tests
now count their own tenant's series.

The tests still rely on bootstrap to write with an empty actor. A test
context that carried a real actor would remove that dependency; it is a
harness-wide change and not made here.
