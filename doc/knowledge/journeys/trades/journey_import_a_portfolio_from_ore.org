This page documents a [[id:F44766FA-1E9C-416F-849A-E131101B2ECA][user journey]]: An operations user brings the trades of an ORE portfolio file into a book, and can roll the import back.

A user journey describes what one person is trying to do, before anything is
built. It is a design document that outlives any sprint. These trade journeys are
use cases, so they name the operations and messages each step needs and leave the
screens to the UX standards.

* Goal

"I have an ORE portfolio file and I want its trades in the firm's books, exactly as the
file states them, and I want to undo the import if it is wrong." The journey is done when
the trades read in the chosen book, the ORE document still exports from them, and the
person has seen what was and was not imported.

* Actor and trigger

The actor is an operations user. The trigger is a new ORE portfolio, a migration, or a
test population. The journey starts with a directory and ends when the import is
confirmed, rolled back or refused.

* Steps

1. *Choose the directory.* The person chooses an ORE directory. The browser packs it and
   uploads it to storage. The person may name folders to skip, such as =Output=.
2. *Find the files.* The system searches the directory and every folder below it. It lists
   every portfolio file that matches, with the book each one becomes, its trade count and
   its size. It says how many files it searched and how many it skipped in excluded
   folders. The person chooses the files to bring in. All are chosen at first, and the
   person may choose all or none.
3. *Choose how to import.* The person names the parent portfolio, says what to do with
   portfolios and books that already exist, sets a default counterparty for a trade whose
   counterparty is unknown, and chooses the activity of the first booking.
4. *Read the plan.* The system lists the trades of the chosen files with the trade type of
   each. It names the trades it cannot read, and why. A counterparty name that matches no
   alias is refused unless a default counterparty is set. A netting set that does not exist
   is created.
5. *Confirm.* The person confirms. The system books each trade with its anchor, booking,
   state, ORE identifier, envelope fields and instrument, under the portfolios and books
   the folders give.
6. *Read the result.* The system reports how many trades it imported, how many it refused
   and why. A partial import is stated as partial.
7. *Roll back.* The person may roll the import back. The system removes what the import
   created.

* Screens

This journey is a use case. The workflow is the Import action in the Workflows menu of the
trade list, as the [[id:BD492939-118E-4B55-AE5B-300F7A1C3B41][Entity screen specification]] places workflows. It opens a dialog or a short sequence.
The result is the trade list filtered to the trades the import created.

The [[id:741FE353-C420-41C1-913D-EA99A73754CA][Trades prototypes]] draw it in =ore-portfolio=. No wireframe is drawn here. The prototype story draws the screens, from the
[[id:00BA1689-B060-4BD8-BC46-67034D663B7F][UX standards]] and from this use case.

* Entities composed

This journey adds no entity of its own. It reads and writes the trade and the records on its page.

* What is missing

- The server finds the portfolio files only inside the import, and the person cannot see them
  first. A step that lists every matching file of an uploaded directory is needed.
- =import_choices= has no list of files. Its choices are the folders to skip, the parent
  portfolio, the re-import mode and the trade defaults. The import brings in every file the
  scan finds. A list of chosen files is a change to the choices and to the scan.
- The default counterparty, the trade date and the activity are choices of the import
  (=trade_defaults=). Whether the plan can say beforehand which trades they rescue is not
  checked.
- The import creates portfolios and books from the folders. The old client asked for one
  book. The person no longer picks the book, so a screen must show the book each file
  becomes.
- =BondForward= has no standalone round trip test. Add one before the import is relied on
  for bond forwards.
- The old wizard also imported currencies. This journey covers trades only.
