* Acceptance

- DQ artefact types and publish functions for netting agreements, netting sets, CSAs (with eligible currencies) and netting set aliases; the publish resolves the party from the params, counterparties by LEI and sets by code.
- Four ORE datasets with a dedicated methodology, catalogue, subject area, synthetic nature, licence and dependencies, published by a party-scoped bundle in the party provisioning plan.
- After provisioning ACME, all 19 ORE netting set ids resolve to netting sets of the ACME party.
- Build, ctest, pgTAP and the local check set pass.

* Plan

Follow the counterparty alias pattern: stage in DQ, publish through the
generic publish-from-DQ handler, and deliver through a bundle.

- Four DQ staging models, each with the artefact staging only profile:
  =netting_agreement= (by number, counterparty by LEI), =netting_set= (by
  code, agreement by number), =csa= (by netting set code, eligible currencies
  as a comma separated list) and =netting_set_alias= (by name, set by code).
- Four publish functions. Agreements and sets are party-scoped: the party is
  the one the publish parameters name, else the tenant's root party, through a
  shared helper. A set opened under an agreement takes the agreement's
  counterparty, which the pinned key requires. Every publish only inserts and
  skips what the tenant holds or cannot resolve.
- The paperwork: the methodology =ORE Sample Netting Synthesis=, the subject
  area =Netting and Collateral=, the ORE catalogue, origin =Derived=, nature
  =Synthetic=, the Modified BSD License of the ORE examples, and the
  dependency chain GLEIF counterparties, agreements, sets, then CSAs (also on
  =iso.currencies=) and aliases.
- The bundle =ore_sample_netting= is party-scoped. Only the =acme_demo=
  profile's =provision_party= step names it, so production profiles get no
  demonstration data. The system tenant gets the same data in populate.
- The data: one agreement per bank (ISDA 2002, FBF for the French banks), one
  set per NettingSetId the sample trades use, ORE's most common CSA terms for
  each id ORE defines, and the NettingSetId as each set's ORE alias.
