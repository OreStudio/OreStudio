* Goal

A commodity trade names its commodity in free text, and nothing holds the set of commodities a tenant may use. Every commodity reference table is empty, and the conventions import stages 790 future conventions of which 756 name no index at all and none are published. A population therefore has to invent a commodity, which is the one thing its generator may not do. This task adds a commodity reference entity, seeds it with the names the engine resolves, and makes an unknown commodity a refusal rather than free text. It does not supply the forward curves a commodity needs to price; that belongs to the market data stories.

* Acceptance

- A refdata entity holds one commodity: the code as the engine spells it, a human name, the unit it is quoted in and the currency it is quoted in.
- The catalogue arrives through the DQ pipeline, as countries, currencies and calendar types do: an artefact table, a publish function and a dataset, with the rows staged rather than inserted.
- The publish is idempotent: a second publish changes no row, inserts nothing and reports it.
- The catalogue carries the index names ORE's own corpus uses, among them NYMEX:CL, NYMEX:NG, XLME:AH and PM:XAUUSD.
- Every seeded commodity states a unit and a quotation currency that match how that commodity is traded: barrels for WTI, MMBtu for gas, tonnes for LME aluminium, ounces for gold.
- A commodity code the catalogue does not hold is refused by name, rather than accepted as free text.
- The entity, the artefact table and the publish function are generated through codegen, and the component's drift check is clean afterwards.

* Notes

The catalogue arrives through DQ rather than a generated populate script,
and the tree says why. Both mechanisms are live, and they split by who
owns the list.

| Catalogue | Rows published | Staged artefact |
|---|---|---|
| =ores_refdata_asset_class_codes_tbl= | 21 | none: the table is absent |
| =ores_refdata_countries_tbl= | 293 | =ores_dq_countries_artefact_tbl= 250 |
| =ores_refdata_calendar_types_tbl= | 10 | =ores_dq_calendar_types_artefact_tbl= 5 |
| =ores_refdata_currencies_tbl= | 0 | =ores_dq_currencies_artefact_tbl= 12511 |

Asset class codes are the exception: twenty-one rows, installation-wide,
and also the source of the UI badges. The other three are market-standard
lists a tenant takes a subset of, and each arrives through an artefact and
a publish function.

A commodity list is the second kind. The exchange indices are the same the
world over, but a tenant holds the ones it trades, the list grows as
exchanges list contracts, and the rows want a reviewable vintage. The
conventions already arrive this way, and commodity conventions are among
them, so the catalogue lands beside its own siblings.

What the task does not do is publish the conventions. Those are staged and
unpublished, and 756 of the 790 future conventions name no index at all, so
publishing them would add rows that cannot name a commodity. Fixing that is
a separate piece of work.
