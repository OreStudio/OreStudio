* What

The tenant list reads its pages with a search and filters, but the roster
query has no order, so no tenant column sorts. The server serves no history
for a tenant, so the tenant page has Details, Parties and People but no
History tab. The party read takes only an offset and a limit, so the parties
list has no search and no column sorts. Add the order to the tenant roster,
the tenant to the history types, and search and order to the party read.

* Why

The record screen standard says every list searches and sorts on the server,
and every versioned record has a History tab. The tenant and party screens now
use the shared list and page, so these server gaps are the only reason they
differ; the conformance table in the standard names them.
