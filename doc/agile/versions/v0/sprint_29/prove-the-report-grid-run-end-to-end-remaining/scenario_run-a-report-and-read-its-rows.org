This page documents a test scenario verifying [[id:77CC92BD-4F9E-42A6-84F8-45265F2DAA91][Run a report from its page and read its rows]] in [[id:90A8E8FB-F103-42D1-9C57-517D7F0694B3][Prove the report grid run end to end — the remaining work]]. It is filled in with the target screen and checklist of steps before testing starts; record the outcome by hand in =* Results=.

* Before you start

- The database is the environment's own, provisioned with Acme Corporation
  holding group: =compass db status= answers, and the fleet is up with
  =compass services status= showing every unit running, including the five
  =ores.compute.wrapper= nodes.
- The report the scenario runs has market data for the date it prices at. A fresh
  environment carries no currency curve quotes, so seed them first with
  [[file:/home/marco/Development/OreStudio/ores_dev_swift_curie/doc/recipes/seed-currency-quotes-for-a-local-report-run.org][How do I seed currency quotes for a local report run?]].
  Without them the run reaches the grid and the engine refuses every curve.
- The result rows table answers the reporting service:
  =grant select, insert, update, delete, truncate on
  ores_reporting_report_result_rows_tbl to ores_swift_curie_reporting_service=
  is applied, which a freshly recreated database grants through its prefix grant
  function.
- Open =http://127.0.0.1:20202= and sign in as
  =tenant_admin@acme_corporation= / =Secure-Password-123=, then choose the party
  =ACME Corporation HK Ltd= in the party picker.

* Steps

** Log in as the tenant administrator

- Sign in at =http://127.0.0.1:20202= as =tenant_admin@acme_corporation= with
  the password =Secure-Password-123=.
- Choose the party =ACME Corporation HK Ltd= in the party picker at the top.
- Confirm the =Reporting= area appears in the main navigation.

*** Result

** Open the NPV report definition

- Go to =Reporting= then =Reports=.
- Open the report named =NPV=.
- Confirm the page states the definition first, with the tabs =Definition= and
  =Runs=, and that =Run= and =Refresh= sit at the top right.

*** Result

** Start the run from the definition

- Press =Run=.
- Confirm the page moves to a new run's page, with the tabs =Run= and
  =Results=.
- Confirm the run's state moves from =queued= or =running= without the page
  being reloaded by hand.

*** Result

** Follow the run to the grid

- On the run's =Run= tab, confirm the run names its compute batch and that the
  state moves through the pipeline rather than resting in one state.
- Open =Operations= then the compute area, and confirm the batch and its jobs
  are listed for this run, and that the jobs reach =Done=.
- Return to the run's page and confirm its state is =completed=.

*** Result

** Read the run's results

- Open the run's =Results= tab.
- Confirm the header states the number of trades and the priced date, and that
  one row per trade is drawn.
- Confirm the note says the rows are the ones the post-processor loaded, not the
  engine's file.
- Change =Aggregate by= to =Book= and confirm the books roll up under their
  portfolios, then to =Counterparty= and confirm the rows roll up by
  counterparty.

*** Result

** Check the rows in the store

- In a shell, run
  =compass sql -- -c "set row_security=off; select measure, count(*) from ores_reporting_report_result_rows_tbl group by 1;"=.
- Confirm the run's rows are there with the measures the report produced, and
  that the count matches the trades on the screen times the measures.
- Confirm =select count(*) from ores_reporting_report_result_rows_tbl= equals
  the rows the screens draw and not a row more.

*** Result
