** Connect to tenant Barclays Plc

Log in as =tenant_admin@barclays_plc= / =Secure-Password-123= and
select *BARCLAYS PLC*.

** Open Market Simulator

- Menu: Market Data > Synthetic > Market Simulator.
- Confirm the tree shows (at least) two theme collections: *2026
  Realistic* (auto-provisioned by default) and *2016 ORE Samples*
  (published separately for this scenario) — each with FX and IR
  Curves sibling nodes.

** Start the 2016 ORE Samples theme

- Select the *2016 ORE Samples* root node (or any item under it) and
  click *Start Feed* — if prompted "Starting everything at once...",
  choose *2016 ORE Samples*.
- Confirm every curve under it starts without error, including *Fixed
  Synthetic IR Curve (2016 ORE Samples): EUR/EUR-EURIBOR-3M* (a
  =price_source=fixed= config) and *Vintage Synthetic IR Curve (2016
  ORE Samples): USD/USD-LIBOR-3M* (a =price_source=vintage= config) —
  the naming prefix distinguishes them at a glance.

** Verify the vintage curve resolved its real rate

- Select *Vintage Synthetic IR Curve (2016 ORE Samples): USD/USD-LIBOR-3M*
  and open it (double-click, or *Edit*) in =IrCurveEditor=.
- On the *Instrument* tab, confirm *Price Source* = =From vintage data=,
  *Vintage Source* = =ore.samples.2016-02-05=, *Vintage Date* =
  =2016-02-05=.
- On the *Process* tab, confirm the running feed's resolved starting
  rate is *0.007961* (0.7961%, the real 3-month USD LIBOR rate on
  2016-02-05 from ORE's own bundled Legacy/Example_56 sample data) —
  check the feed's status/detail view or the service log for the
  resolved rate, since the Process tab's r0 control shows whatever was
  last typed there, not the server-resolved value.

** Verify a fixed curve used its typed rate

- Select *Fixed Synthetic IR Curve (2016 ORE Samples): EUR/EUR-EURIBOR-3M*
  and open it in =IrCurveEditor=.
- Confirm *Price Source* = =Fixed=, and the running feed's starting
  rate matches the *Initial rate r0* value shown on the *Process* tab
  exactly — no server-side resolution for this one.

** Add a new vintage config via the editor

- With a feed selected in the Simulator tree, click *New IR Curve*.
- Set *Currency* = =USD=, *Index name* = =USD-LIBOR-3M=.
- On the *Instrument* tab, select *From vintage data*; confirm the r0
  controls on the *Process* tab grey out. Click *Browse available…* —
  confirm it lists =ore.samples.2016-02-05 — 3M= (the seeded USD
  DEPOSIT observation) — select it and confirm *Vintage Source*/
  *Vintage Date* populate.
- Save. Confirm the new curve appears in the tree and starting it
  resolves to the same *0.007961* rate as the seeded exemplar.

** Add a vintage config with a missing observation

- Click *New IR Curve* again.
- Set *Currency*/*Index* to a pair with no imported observation (e.g.
  =GBP=/=GBP-LIBOR-6M= — the seeded =marketdata.ir_deposit_rates=
  dataset only covers USD). Select *From vintage data*, type an
  arbitrary *Vintage Source*/*Vintage Date* (e.g. =test.none= /
  =2020-01-01=) rather than using *Browse available…* (which would
  correctly show nothing to pick).
- Save, then attempt to start its feed.
- Confirm the start fails with a =vintage_data_missing_error= (or its
  surfaced error message) that names the missing
  currency/index/source/date, rather than silently falling back to a
  default rate or crashing.
