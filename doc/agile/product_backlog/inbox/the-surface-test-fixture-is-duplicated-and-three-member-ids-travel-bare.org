* What

Two findings from the review of the surface's tick tests that the branch recorded instead of
fixing, because neither changes what is asserted.

*Duplication.* =feeds_fx_vol_surface_tick_tests.cpp= and
=feeds_fx_vol_surface_round_trip_tests.cpp= carry the same board fixture line for line under
a prefix rename -- =tick_days_to= against =round_trip_days_to=, and the curve, the board and
the publish with it. Seventy lines that differ only in the name of their constants. One
=tests/fx_vol_board_fixture.hpp= of =inline= functions would carry it once; this project
already does that in =provider_seed.hpp= and =test_suite.hpp=, and the header has to avoid an
anonymous namespace, because a unity build merges the target's sources.

*The ids.* =fx_vol_board_inputs= takes three =market_board::member_id= arguments of the same
type in a row, and the feed holds three =optional= values of it. Passing the pair's base curve
where the quote belongs is not a type error, it is a silent read of the wrong curve -- and it
is exactly the mistake this pair of curves invites. One =fx_vol_member_ids= struct makes the
transposition unrepresentable.

* Why

Both were judged out of scope for the task that found them: the first is a change to how the
target's fixtures are built rather than to what any test asserts, and the second is a small
API change with a call site in the feed and two in tests. Recording them keeps the review's
findings from being lost without spending a task's worth of churn on either.
