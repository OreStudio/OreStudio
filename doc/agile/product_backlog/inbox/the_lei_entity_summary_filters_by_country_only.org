* What

Let the read filter by legal name, or by LEI, beside the country it already
filters by. The two SQL functions behind it take a country and a page window;
a text filter belongs there with them, because the filter has to be correct
over the whole set and a client can only ever see one page of it.

* Why

Found on 2026-09-29 while designing the starting point's root-LEI picker. A
person provisioning the *Operational* card must name a root legal entity, and
the deployment holds about two thousand of them, more than the read's default
page of a thousand. The read answers a country and nothing else, so a screen
that lets somebody type a name has two choices, and neither is right:

- page the whole set and filter in the browser, which is correct but moves
  every row to the client, and the page size is a deployment's decision rather
  than the screen's;
- filter the page it fetched, which is what the shell's
  =lei entities <country> --filter <text>= does today, and which silently
  misses every entity beyond that page.

The second is worse than it looks: a person searching for an entity that
exists is told it does not, because the row was on a page nobody fetched.

The picker that needs this is described in
[[id:68113CC3-55C1-4EDE-AEFF-CEE043A9431C][the first run journey's task]]; the
read itself is =dq.v1.lei-entities.summary=, whose model already says it
answers "the active root legal entities, optionally of one country".
