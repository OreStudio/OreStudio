* Acceptance

- A suite killed by SIGABRT or SIGSEGV writes a stack to standard error before it dies.
- A signal the harness does not handle still kills the process as it did.

* Plan

Install handlers for the fatal signals once per test process, from the
listener every suite registers. The handler writes the signal's name and the
unwound stack to standard error, then restores the default action and raises
the signal again, so the exit status stays the one the process would have had.

* Result

* Result

A suite that takes SIGABRT, SIGSEGV, SIGBUS, SIGFPE or SIGILL now writes the
signal's name and its stack to standard error before it dies, and still dies
from the signal: the exit status is unchanged, so CTest and the nightlies
report the failure as they did.

This is what the gcc double free needs. glibc reports a corrupted heap in one
line and no stack, the abort happens inside =free=, and the run says only which
suite died. The frames carry mangled names; =c++filt= reads them.

Verified locally: a suite sent SIGABRT writes =TEST FATAL SIGNAL: SIGABRT= and
sixty-four frames, and exits 134. The handler is installed on the first case
that starts, so it is in place for every case of every suite that registers the
listener.

Not verified locally: the handler under a double free, which needs the gcc run
that reports it. Tonight's nightly prints the stack.
