* Goal

The NATS service pattern library states how a service must address, subscribe, publish, request, fail and log on the bus. This story establishes whether the service code does that, and closes the gap. The audit is exhaustive over the four consumer variants and the publisher, requester and stream-provisioning call sites; it names each deviation, the pattern it breaks, and the change that fixes it. The fixes make a deviation unrepresentable where a codegen template generates the call site, and correct the hand-written ones directly. A deviation that is deliberate and correct stays, and the pattern page is amended to say so, so the library and the code agree at the end.

* Acceptance

- Every NATS call site in projects/ is classified against the pattern library, and the inventory is recorded on the story.
- Each deviation names the pattern it breaks, the file and line, and the fix; each non-deviation is recorded as deliberate with the pattern page that licenses it.
- The fixes are made: generated call sites through their codegen templates, hand-written ones directly, with no compatibility shim left behind.
- A pattern that the code proves wrong is amended, so the library and the code agree.
