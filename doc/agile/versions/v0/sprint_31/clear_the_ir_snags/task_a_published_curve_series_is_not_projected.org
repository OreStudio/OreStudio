* Goal

=ores_refdata_publish_curve_configuration_from_dq_fn= calls
=ores_marketdata_publish_curve_series_fn=, which inserts a =yield= series for
each published curve straight into =ores_marketdata_market_series_tbl=. SQL
cannot run the oresmd codec, so no identity row is written, and the refdata
service's publish handler runs no projection after it. The marketdata publish
handler does: it calls =project_missing= after its own SQL function, and that
call covers the whole tenant. So a curve's series is projected only when a later
marketdata publish happens to run, or when an operator runs
=marketdata backfill-identity=. Make the curve publish project what it writes,
for example by asking the marketdata service to backfill the party once the
refdata publish completes.

** Why

Until it is projected, the resolver and the series list cannot see the series,
and its identity shape is not checked. Measured on 2026-11-20 on a freshly
provisioned Acme tenant: 35 =ir.yield= curve series (=*1D= zero curves, one per
party and currency) had no identity row after provisioning. A backfill projected
all 35 and the shape refused none of them.
