#+title: How do I run the code_domains commands from the shell?
#+description: Every command the code_domains submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:code_domains:

This file documents the code_domains resource at the shell, one section per command. Every command is a subcommand of =code_domains=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 53A6D4C3-6574-551E-9F13-EA6610CFF2A3
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
code_domains list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =dq.v1.code_domains.list=.

#+name: code_domains-list
#+begin_src ores-shell :tangle code_domains-list.ores :exports none
code_domains list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: 733B131A-0698-5C75-B0BF-95AF101F1A2B
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
code_domains get <code>
#+end_example

It is addressed at =dq.v1.code_domains.get=.

#+name: code_domains-get
#+begin_src ores-shell :tangle code_domains-get.ores :exports none
code_domains get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: E571B219-3DDA-5207-9671-668E781E2635
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
code_domains add <code> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =dq.v1.code_domains.put=.

#+name: code_domains-add
#+begin_src ores-shell :tangle code_domains-add.ores :exports none
code_domains add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: B7230A7F-98DD-5CAC-9E46-A067A8FAA22B
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
code_domains set <code> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =dq.v1.code_domains.put=.

#+name: code_domains-set
#+begin_src ores-shell :tangle code_domains-set.ores :exports none
code_domains set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
