#+description: An archetype placed in a facet that every component renders makes the local check gate verify every component at every address, because check_component_drift.py --changed selects the components the branch touched. Adding the umbrella header to ores.cpp.component therefore drags 94 components into the gate at once, and any component whose generated files main hand-edited then fails it -- geo, ores.history/api and ores.storage/service all do. A change of this shape should land as the mechanism alone: the discovery fix, the guards and the template, touching no component file, so the changed set stays empty and the gate passes. Each component then regenerates, and reconciles its hand-edited files, inside its own clean-up task. The bulk flush of about 250 presence files is real work, but it belongs to those tasks, not to the enabling change.
