* Acceptance

- Each defect is recorded with the command or recipe that shows it, and with the file and line of its cause.
- Each fix changes a template, a loader or a script, and not the generated output.
- Each fix carries a regression test that fails before the fix and passes after it.
- The affected components are regenerated, and the drift gate passes with each of them listed.

* Plan

Work the defects in the order the clean-up passes find them. Each one is one
unit: record it in the register below with the evidence that shows it, fix it
at the source, add the regression test, regenerate the affected components,
run the drift gate, and commit.

The branch accumulates the fixes and is rebased onto main as needed. Nothing
merges until every component is clean, so a fix that would change generated
output across components does not have to land early to be correct.

* Notes

*Finding.* The two malformed comments are not a generator bug. They are two of
**46** umbrella headers that the generator stopped owning when the archetype
moved into the disabled scaffold facet. Nothing regenerates them, nothing
gates them, and none of the 46 is =#include=d by any =.cpp=, =.hpp= or =.h= in
the tree: they survive only as entries in a generated =component_files.cmake=
list and as namespace prose. 78 of the 124 components have none.

*The discovery gap, measured.* Making =discover_models= pick up the parts'
=component_overview.org= makes the gate reach them, and the check then reports
**381 files**: 336 gain the =AUTO-GENERATED= marker they never had, and 46 are
new umbrella headers. That part is right.

*Why it cannot be applied as-is.* The same render also fires the
first-generation CMake archetypes, which are not scaffolding in the current
tree and are not safe to re-render over a mature component.
=cmake_component_src.mustache= rewrote =projects/ores.http/server/src/CMakeLists.txt=
by dropping =list(FILTER lib_files EXCLUDE REGEX "main.cpp")= and rewriting its
=target_link_libraries=. Those archetypes only never fire today because the
gate sees composites, whose kind excludes them.

*Options.*

- Make the first-generation CMake archetypes opt-in, as the stub trio already
  is, then widen discovery. This is the consistent reading: a file that may not
  be re-rendered over an existing component belongs behind the scaffold opt-in.
- Give the parts a narrow path that renders only the component facet, so the
  umbrella regenerates and the CMake archetypes never fire. Narrower, but it is
  a second way of regenerating a component.
- Register the parts as components. Largest, and it changes the manifest that
  many other tools read.

*Scope of the regeneration.* =check_component_drift.py --all= covers the 12
components in =COMPONENTS_UNDER_TEST=, so the regeneration reached the parts of
those 12 and no others: 37 umbrella headers now carry the marker, and 31 parts
gained the header. The 22 own-root umbrellas still without a marker belong to
components that are not under test yet -- =trading=, =refdata=, =marketdata=,
=scheduler=, =synthetic=, =history=, =storage=, and the standalone =database=,
=diff=, =geo=, =logging=, =nats=, =orgmode=, =platform=, =security=, =service=,
=testing= and =utility=. They regenerate as each of those components is cleaned
and listed, which is the arrangement the branch exists for. Nothing is
outstanding against this task for them.

*Not checked by the include gate.* The scan covers the headers codegen still
owns. =dataset_dependency= is excluded because it has no model, which is the
point of entry 5: nothing regenerates it, so nothing can correct it either.
