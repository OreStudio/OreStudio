* Result

The run reads its conventions family by family through each family's list
subject, and keeps the rows of its party. It read =party_id= only at the top of
a row. The central convention groups its identity, so its =party_id= sits under
=identity= and the read dropped every central row, while the commodity future
parts state =party_id= at the top level and were kept. The commodity future
join then refused each part as naming no convention, and every report run
failed while its input was built. The data was sound: every part had its
central row, for the same party.

The read now takes the party from a row's =identity= group when the row has
one (=party_of_family_row=, in its own unit of =ores.ore.service= so a test can
reach it). The run of Group Consolidated Exposure that failed now completes.

The same filter also dropped the tenor basis and cross currency parts, whose
types group their identity like the central row. Their central rows were
dropped with them, so nothing was orphaned and nothing refused: runs before the
fix carried none of those conventions, silently. That is inferred from the code and the
types' shapes; this task did not measure a run's conventions before and after.

** Why

No report run completes, so nothing downstream of input preparation can be
exercised end to end. Either the package query omits the central commodity
future rows the parts name, or the seed provisions parts for a convention it does
not provision. Before the refusal existed, the part was silently dropped from the
export, which is the loss the refusal was added to catch.
