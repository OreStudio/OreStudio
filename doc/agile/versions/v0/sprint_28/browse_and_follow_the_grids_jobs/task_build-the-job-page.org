* Plan

Add the page =/operations/grid/jobs/:workunitId= as =GridJobPage.tsx=. It reads the
workunit, its batch, up to 50 runs of it and one page of the batch's workunits,
all through the six BFF routes, and draws the panels of the prototype that the
models can fill: the header, the runs, the bar for the first run, the jobs of the
batch, the files, the release and the lineage. The Follow this job link of the
Jobs tab and the App Version ID links lead here and to the app version page.

* Notes

- The state comes from the canonical result: a job with one is Done, and a job that
  ran and failed is Done too, so the outcome sits beside the state.
- The jobs of the batch panel states Done or Not done from the canonical result of
  each workunit. A bar per job needs the runs of every job, one read each, so the
  page draws no timeline for the siblings.
- The release panel shows the App Version ID as a link. The engine and wrapper
  versions need an app version read, which the app version page adds.
- The time bar of a run read 0 s on the check: the engine failed at once.

* Result

The job page states where a job is, what ran it and what it produced. It reads the
state from the canonical result, puts the outcome of the run beside it, and warns
that a closed batch is not a successful batch. A run in flight states that its node
and output are not yet known. The Jobs tab links to the page. The link to the
report run and the run statistics wait for their own tasks.
