* Goal

A product type says what a desk needs in one row, and no second classification is invented for it. The eight values of product_type_t map onto the axes with no loss, and each axis has one code set, one spelling and one owner.

* Acceptance

- The page records each axis, its code set, its spelling and the entity that owns it: the market junction against =asset_class_codes=, and =ores_refdata_product_family_codes_tbl= for the family.
- All eight product_type_t values map onto the axes, including composite and scripted, and the routing family the instrument table needs is named.
- rates, interest_rates, swap and InterestRate resolve to one spelling, and the mapping is recorded.
- has_options and has_extension keep a stated meaning, or are replaced by something that states it.

* Plan

The task is an analysis, so the deliverable is the record rather than code.

1. Read the enum and every consumer, to see what actually reads it.
2. Read the notes' identifier tables, to learn what class and shape the corpus
   already states.
3. Compare the three asset-class schemes and settle the spelling the row stores.
4. Decide the family: what the values are, and whether they are a lookup or an
   enum.
5. Decide the construction values, and what happens to the two flags.
6. Decide the routing, and state why no routing family survives.
7. Write the column list the model task implements, and map every enum value
   onto the axes.
8. Record the decisions on the story and the open items on the tasks that own
   them.

* Result

The axes are settled in [[id:E7095E28-EB36-427C-9C14-AB6AB0593B33][The axes a product type carries]].

- The row carries the shape (a reference to a new family lookup) and the
  construction (=native=, =scripted=, =container=). The shape reference is
  nullable, and null has a stated meaning.
- The market is a junction, because a type may reference two: six do today, two
  more would if the gap products were added, and two have none by construction.
  One row is marked as the market the catalogue groups the type under, and a type
  with no rows is decided per trade.
- The enum is dropped and no routing family replaces it: the instrument table on
  the row does the routing, and nothing reads the enum for anything else.
- The spelling the row stores is our taxonomy's: =interest_rates=, not =rates=,
  =swap= or =InterestRate=. The external schemes stay registered and mapped.
- The two flags are kept, with their meaning restated as facts about the trade
  the type produces.
- The eight enum values map onto the axes with no loss, and the distinctions the
  enum could not state come back with the family.
- The taxonomy's =scripted= value is not used by any product: renaming it or
  retiring it is left to the taxonomy work.
