#+title: Keep the system tenant's rows out of writes and removals
#+description: Repositories of models with system_tenant_visible read the system tenant's rows beside the caller's, and some write paths use those reads. The pair template (tenor_convention_resolution, app_version_platform_junction, product_type_asset_class_junction) builds batch claims from read_current and single claims from read_latest with shared rows, so a tenant's write of a key the system tenant holds is claimed against the system row and refused. The entity template's remove reads read_latest with shared rows, so removing a key only the system tenant holds reports conflicting rather than missing. The script entities' claim_rows filter is the pattern: a claim or a removal acts on the caller's own rows. About 100 models carry the flag. Found by the review of PR 4835.
