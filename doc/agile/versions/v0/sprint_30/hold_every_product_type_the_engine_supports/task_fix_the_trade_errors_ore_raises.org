* Goal

Every error ORE raises reading or building a recorded trade is either fixed, because the trade caused it, or tagged as market data or engine configuration, because the trade is correct and the run lacks what prices it.

* Acceptance

- the known ORE error list states a kind on every line: market data or engine configuration; no line is a parse error and no build error names a field of the trade
- the kind of an error is decided by a fixed rule, not by hand: the test
  classifies each message against a table of ORE's message patterns (a missing
  curve, quote, index or reference data is market data; a missing pricing engine
  or engine builder is engine configuration), and a message no pattern matches is
  of the trade kind
- the DoubleDigitalOption parse error, the ScriptedTrade index named .SPX, the CallableBond empty handle and the BondOption volatility curve id are each fixed or proven to be market data, with the evidence in the task
- BalanceGuaranteedSwap runs in the ORE engine test, or its crash is shown to come from the engine configuration, with ORE's message
- every line of the known missing-paths list is filled by the generator, or names the reason the generator leaves it out
- a test fails when a new line of the trade kind appears

* Plan

- The ORE engine test gives each error a kind from a fixed table of ORE's
  message patterns: =market_data= for a missing curve, quote, index or
  reference data; =engine_configuration= for a missing pricing engine or engine
  builder; =trade= for any other message. The known list gains the kind as its
  first column, and the test fails on any error of the =trade= kind.
- Trace each =trade= error to its cause in ORE's source, fix it in the
  generator, re-record the generated trades, and rewrite the known list from a
  fresh run.
- Give every known missing path a reason, from ORE's schema, and make the
  export test require one.

* Notes

** What caused each trade error

- /ScriptedTrade/: the generic trade named its index =.SPX= and stated three of
  the variables =AsianBasketOption= reads, with =PutCall= as =Call=. ORE's own
  example (=Example_Trades/Scripted_BasketOption.xml=) states =Expiry=,
  =Settlement=, an =ObservationDates= schedule, =PutCall= and =LongShort= as
  signs, =Notional=, =Strike=, =Underlyings= and =Weights= lists and =PayCcy=.
  The generator now states all of them; the export writes =EQ-= names since
  =cf010d9c18=. ORE now reports only the missing =.SPX= equity curve.
- /BondOption/: =BondOptionEngineBuilder= requires the bond's
  =VolatilityCurveId= (=OREData/ored/portfolio/builders/bondoption.hpp:68=), which
  ORE's examples take from reference data and our inline bond left empty. The
  issue of a bond option now names =BondOptionVols-<ccy>=; the trade prices.
- /CallableBond/: with no =CreditCurveId= the engine builder leaves the default
  curve, recovery and spread handles empty
  (=OREData/ored/portfolio/builders/callablebond.cpp:348-370=) and pricing
  dereferences them. The issue now names the credit curve a credit trade on
  the same entity names; ORE reports that curve missing, which is market data.
- /BalanceGuaranteedSwap/: ORE crashed with signal 11 in
  =BalanceGuaranteedSwap::build=. The builder reads =fixLeg[i]= at the floating
  coupon's index (=OREData/ored/portfolio/balanceguaranteedswap.cpp:191=), past
  the end of an annual fixed leg against a semi-annual floating one. ORE's own
  BGS example (both legs 6M) runs clean under the same configuration. Both legs
  now pay on the floating tenor; ORE reports the missing CPR, market data, and
  the test runs the type again.
- /DoubleDigitalOption/: the parse error no longer occurs on main; the trade
  now reaches the missing =.SPX= and =.STOXX50E= equity curves.

** Credit curves named by address

A generated credit curve is named by its oresmd address, so ORE reports
=did not find object 'oresmd://credit/...'=. The planner says so on purpose:
the market data work gives each entity its curve. The pattern table counts it
as market data.

** The state of the scripted index on main

The recorded =ScriptedTrade= states its index as =.SPX=, which ORE refuses
("Could not build index info for '.SPX'"). Since =cf010d9c18= the export writes
=EQ-.SPX=, which is the name ORE reads, but it also drops the =Strike= Number
variable, and the recorded files were not re-recorded, so =the generated trades
are the ones recorded= fails on main for two trades. The fix keeps =EQ-= names,
restores =Strike= (and the full variable set =AsianBasketOption= reads), and
re-records the files in the same commit.

* Result

Every error ORE raises on the recorded trades has a kind from a fixed table of
ORE's message patterns, and the known list states it: 44 market data and 3
engine configuration lines, none of the trade kind. The trade's own errors are
fixed in the generator: the generic ScriptedTrade states every variable its
library script reads, a bond option names its yield volatility, a callable bond
names its credit curve, and a balance guaranteed swap pays both legs on the
floating tenor, which stops ORE's builder crashing and lets the test run it
again. The ORE engine test fails on any new error of the trade kind. Every known
missing path names the reason the generator leaves it out, and the export test
fails on a line with none. The recorded trades are re-recorded, which also
clears the scripted trade failure main carried.
