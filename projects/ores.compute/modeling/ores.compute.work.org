The machine channel between wrapper nodes and the service: pull a unit of
work, announce a live node, requeue the work of a dead one, and hand back a
finished job.

These are operations rather than entity verbs. A pull assigns the next
unsent result, a heartbeat touches a host row, a reap moves results back to
the queue, and a submit closes a result and signs off its workunit. None of
them is a row a caller addresses by key, so none of them is derived from an
entity.

Three of the four carry no session. A wrapper node holds no user JWT, so
the heartbeat, the reap and the submit are trusted at the transport layer,
and their handlers read the service context directly. The pull is the
exception: its handler makes a request context and checks
=compute::batches:write=, so it states a session.

The handlers stay hand-written beside this model. An operation model
generates no service handler.
