#+title: How do I run the account_types commands from the shell?
#+description: Every command the account_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:account_types:

This file documents the account_types resource at the shell, one section per command. Every command is a subcommand of =account_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 98ACEFB2-0A78-5C5A-8B40-23636AFD79B5
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
account_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =iam.v1.account_types.list=.

#+name: account_types-list
#+begin_src ores-shell :tangle account_types-list.ores :exports none
account_types list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: DC23B26A-A6E1-5F70-90EF-BA8FF27389E7
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example
account_types get <type>
#+end_example

It is addressed at =iam.v1.account_types.get=.

#+name: account_types-get
#+begin_src ores-shell :tangle account_types-get.ores :exports none
account_types get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 46BAB3F5-E971-57C6-BBC8-BF1917D39496
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
account_types add <type> <name> <description> <display_order> <reason> <commentary>
#+end_example

It is addressed at =iam.v1.account_types.put=.

#+name: account_types-add
#+begin_src ores-shell :tangle account_types-add.ores :exports none
account_types add __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src

** =set=
:PROPERTIES:
:ID: 020119F1-0018-588D-BEDA-B9A3D8124213
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
account_types set <type> <name> <description> <display_order> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =iam.v1.account_types.put=.

#+name: account_types-set
#+begin_src ores-shell :tangle account_types-set.ores :exports none
account_types set __none__ __none__ __none__ 0 system.new_record generated_script
#+end_src
