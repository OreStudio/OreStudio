* Result

The gate reads a subject wherever a person writes one, not only where a model
declares it.

=WRITING_SITES= is a registry of the places a subject is written without a
model: a protocol header or hand-written constant (the
=std::string_view ..._subject[_prefix] = "..."= shape, wrapped or not), and the
=target_subject= a DQ artefact type seeds. Each site names its paths *and* the
shape the subject takes there, so adding a new way to write one is a deliberate
act rather than a silent blind spot.

Reading 212 subjects where it read 159, and still reporting none outside the
grammar. The precision is the point: the registry reads where a subject is
written rather than guessing from what it looks like, so a scheduler job name
(=compute.v1.reap.stale_results=) and an event base
(=trading.v1.trades_events=) are not read at all. Both are pinned by tests, so
a future widening that reintroduces them fails rather than being noticed in
review.

Four cases hold the widening: the sites are read and not empty, a job name is
not read, an event base is not read, and every written subject conforms. The
codegen suite is 1266 cases.

The capture that scoped this is deleted, and its false-positive analysis lives
on in the registry's comment and those cases.
