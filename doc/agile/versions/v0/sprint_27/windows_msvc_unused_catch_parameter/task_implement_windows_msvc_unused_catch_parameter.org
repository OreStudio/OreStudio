* Acceptance

- The boost::not_a_dag catch parameter is unnamed.
- No unused catch parameter remains in projects/.

* Plan

MSVC at /W4 /WX stops the build on the unused =e= in

#+begin_example
} catch (const boost::not_a_dag& e) {
#+end_example

at =publish_service.cpp:196=. The handler logs and throws its own circular
dependency message, so the exception object is dead weight. Drop the name:
=} catch (const boost::not_a_dag&) {=. The file keeps its one-line diff, and no
other file in =projects/= has a catch parameter its handler never mentions.

* Notes

Root cause: =boost/not_a_dag= arrives across a catch clause whose body never
reads it, and MSVC's C4101 "unreferenced local variable" is an error under the
project's /W4 /WX. The file has not changed since df60ea85fc (2026-09-27), so
the failure only appeared when the MSVC toolchain started flagging it.

The same warning class reproduces on Linux with clang's
=-Wunused-exception-parameter=, which is how the fix was verified without a
Windows runner.
