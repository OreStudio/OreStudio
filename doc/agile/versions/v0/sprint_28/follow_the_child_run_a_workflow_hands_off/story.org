* Goal

A person who provisions a tenant should not be told it is ready while its setup is still running. The provisioning run records the id of the run it creates, so the shell should follow that child run to completion before it reports success.

* Acceptance

- run_and_follow follows a non-empty child_instance_id from the last completed step's response, so provision tenant and bootstrap setup both wait for the tenant setup to finish
- the success message is only printed once the child run has completed, and a failing child run fails the command
- the transient 'Workflow instance not found' first-poll warning is not printed as a warning
- proven by provisioning a tenant on a recreated database and showing the command does not return until tenant_setup_workflow has completed with 0 step errors
