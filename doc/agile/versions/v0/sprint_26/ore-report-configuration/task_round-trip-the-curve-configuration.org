* Goal

Curves are referenced by name from five of the analytics documents, so a curve that does not round trip breaks every document that names it.

* Acceptance

- Every curveconfig.xml in the corpus imports, exports and matches.
- A curve resolves its conventions, calendar, day counter and index by foreign key, not by string.
- The segment types are a seeded lookup, so a new segment type is a row and not a struct.

* Plan

Measured on 2026-10-03 at fe244a3331 before any change:

- 89 corpus documents have the root =CurveConfiguration=, with 22 section kinds.
  An entry carries from 2 to 30 distinct child elements, by section. Yield
  curves are the largest: 1193 entries and 10 segment kinds in use.
- The binding already holds =curveconfiguration= with a loader and saver. No
  binding work is needed.
- The binding groups a yield curve's segments by kind, one vector per kind, so
  the order of segments across kinds is lost before a mapper runs. A mapper can
  keep only the order within a kind.
- The curve tables on main (=curve_definition=, =curve_section=,
  =curve_segment=, =curve_quote=) store each entry's common settings as text
  and the rest as a semicolon and pipe encoded =extras= column. Nothing reads,
  writes or seeds them. That shape fails this task's acceptance and the
  story's (no name and value pairs, references by foreign key).
- The day counters the corpus writes do not match the seeded day count codes:
  =Actual/365 (Fixed)=, =ACT=, =Actual/360=, =ActActISDA= and =30E/360E= have
  no row, 657 values in all. The schema's =dayCounter= enum lists every
  spelling ORE accepts, about seventy.
- Curve segments name 219 distinct convention ids. Conventions are one table
  per category, each keyed by its text id, with no shared identity table.

Shape:

- A curve entry is a header row, =curve_definition= (section, =CurveId=,
  description, position), which is the one identity other documents refer to,
  plus a detail row per section family with that family's settings as typed
  columns. Nested lists (segments, quotes, volatility configurations) are child
  rows with typed columns and a position within their kind.
- An ORE enumeration becomes a seeded lookup derived from the schema by a
  script, keyed by ORE's own spelling, so a column keeps the exact spelling
  and resolves by foreign key. A day counter spelling also names its canonical
  day count code.
- A convention reference is checked against every convention table by one
  validation function, because there is no shared convention identity. An
  index reference resolves against the floating index types.

Delivery, one PR per step, each with its own check:

1. Lookups. The curve sections, the segment kinds and types, and the ORE day
   counter spellings, seeded by a script that reads the schema. Check: the
   seed counts equal the schema's enumerations.
2. Yield curves. Replace the generic columns with the header and the yield
   curve detail, segments and quotes; the mapper for the =YieldCurves=
   section. Check: every =YieldCurves= section in the corpus round trips in
   memory and through the database.
3. The other curve sections (default, equity, inflation, commodity, securities,
   FX spots, intraday power). Same check per section.
4. The volatility and correlation sections and the report configuration. Check:
   every whole document in the corpus round trips.
