#+brief: The market state a run saw, as one compressed payload with an index of its dates, scenarios and factors.

#+entity_title: Market State Payload
#+created: 2026-10-31
#+updated: 2026-10-31

The market state an engine run priced against, kept as the file the engine
wrote. A cube states a column for every curve and tenor the run built — the
widest checked-in sample states 789 — so a row for each value would be millions
of rows per run, and a read that needs one factor would unpack all of them.

The payload is therefore stored once, compressed, with an index beside it: the
headings, the number of rows, and the distinct values of each key the catalogue
names, which are the dates, the scenarios, the factors or the market objects the
file covers. A reader that wants one slice asks the index first and unpacks only
what it must.

This is market state and not a run result: it says what the world looked like,
it is what the engine read, and it belongs beside the series and the fixings the
market data store already keeps.

** report_instance_id
:PROPERTIES:
:type:         uuid
:cpp_type:     boost::uuids::uuid
:natural_key:  true
:filterable:   true
:END:

The run whose engine read this state.

** report_definition_id
:PROPERTIES:
:type:         uuid
:cpp_type:     boost::uuids::uuid
:END:

The report the run came from, so a definition's states are one query.

** family
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:natural_key:  true
:filterable:   true
:END:

The family the file belongs to, as the catalogue names it: stress_scenarios,
scenariostatistics, rawcube, todaysmarketcalibration.

** file_name
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:natural_key:  true
:END:

The name the engine gave the file.

** as_of
:PROPERTIES:
:type:         timestamp with time zone
:cpp_type:     std::chrono::system_clock::time_point
:natural_key:  true
:END:

The date the run priced at, which is the state's observation date.

** row_count
:PROPERTIES:
:type:         integer
:cpp_type:     int
:END:

How many rows the file states, not counting the heading.

** column_count
:PROPERTIES:
:type:         integer
:cpp_type:     int
:END:

How many columns the file states. It is the size of the index's column list and
is carried beside it so a reader can size a read before parsing the list.

** column_names
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:END:

The headings the file states, in its order, as a JSON array. A reader finds the
columns it wants here rather than in the payload.

** key_values
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:END:

The distinct values of each key the catalogue names, as a JSON object of key
name to array, in the order the file states them. These are the dates, the
scenarios, the factors or the market objects the file covers.

** keys_truncated
:PROPERTIES:
:type:         boolean
:cpp_type:     bool
:END:

Whether a key stated more values than the index records. A reader that needs the
exact set of such a key reads the payload.

** payload
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:END:

The file as the engine wrote it, gzipped and held as base64 text, because the
store's columns are text and a binary column would be a second way to hold a
blob.

** payload_bytes
:PROPERTIES:
:type:         integer
:cpp_type:     int
:END:

The size of the compressed file, so a reader sizes its read from the row rather
than from the length of the text.

** content_sha256
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:END:

The digest of the file as the engine wrote it, so two runs of the same state are
one payload and a corrupted one is detected.

** source
:PROPERTIES:
:type:         text
:cpp_type:     std::string
:END:

The family the payload came from, for provenance.

** Bitemporal natural keys

A run's state is its own. The insert trigger closes the current row of the same
key, and the key names the run, so one run never closes another run's payload.
