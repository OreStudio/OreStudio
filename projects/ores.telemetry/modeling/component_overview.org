* Summary

=ores.telemetry= is the observability component for ORE Studio. It receives
log entries, service heartbeats, and NATS server and stream samples, persists
them, and answers queries over the stored data.

It is a composite of three parts. =ores.telemetry.core= is the logging and
tracing library that every component links against. =ores.telemetry.database=
is the PostgreSQL persistence layer. =ores.telemetry.service= is the NATS
service that serves the =telemetry.v1.>= namespace.

* Inputs

- Log entries published on =telemetry.v1.logs.publish= by other components'
  wrapper nodes. The compute wrapper is the only in-repo publisher, and it
  sends batches of up to 200 entries.
- Heartbeats published on =telemetry.v1.services.heartbeat= by every service
  that embeds the =ores.service= heartbeat publisher, including this
  component's own service.
- NATS server and stream samples that the service polls from the NATS HTTP
  monitoring API, at =/varz= and =/jsz?streams=true=.
- Queries for logs, service samples, and NATS samples, on the four request
  subjects of the namespace.
- Configuration: the NATS server URL and subject prefix, and the PostgreSQL
  connection string.
- Log events that other components emit through the Boost.Log sink that the
  core library installs.

* Outputs

- Rows in its own tables: =telemetry_logs=, =service_samples=,
  =nats_server_samples=, and =nats_stream_samples=, written through
  =ores.telemetry.database=.
- Replies to the query subjects. The log and service sample handlers read the
  repository; the two NATS sample handlers currently reply with an empty
  =samples= list and do not call the repository.
- JSON Lines log files written by the core library to its configured export
  path.

* Entry points

- =core/= — Boost.Log setup, trace and span correlation, the file and hybrid
  exporters, and the three protocol headers that declare the six subjects.
- =database/= — ORM entities, mappers, and repositories for the four
  telemetry tables.
- =service/src/main.cpp= — the service entry point that starts the NATS event
  loop.
- =service/src/messaging/registrar.cpp= — the one place that subscribes all
  six =telemetry.v1.>= subjects and binds their handlers.

* Dependencies

- =ores.nats= — the transport the service subscribes and replies through.
- =ores.service= — the service runner and heartbeat publisher; the telemetry
  service embeds it and publishes =telemetry.v1.services.heartbeat= on its
  behalf.
- =ores.logging= — the Boost.Log infrastructure the service runner uses.
- =ores.dq= — the ORM base classes the persistence layer builds on.
- External libraries: =Boost.Log=, =nats.c=, =soci=, and PostgreSQL.
