* Goal

Every route of ores.http declares a stable tool name, the area and entity it belongs to, and whether it writes, and every route that takes a body declares its schema through the route builder's typed body declaration. Routes the codegen generates take the area and entity from their model. A gate refuses a route that declares none of these, so the catalogue is complete by construction.

* Plan

Two pull requests. The first declares every route's tool, area, entity and
whether it writes: a =route_catalogue= on the route, grouping its
documentation so the route narrows from 17 fields to 15; one rule in
=ores.http.api= for generated routes, called from the four route templates; a
rerunnable codemod for the 321 hand-written routes, reading each area from the
route inventory; a router report the server refuses to start with; and the
OpenAPI fields. The six-eyes hold reads the declaration instead of guessing
from names. The typed bodies of the 116 hand-written routes that take one
moved to a task of their own, so this one closes on what it delivered.

* Result

Every ores.http route declares a stable tool name, its published area, its
entity and whether it writes, in a =route_catalogue= that also holds its
documentation, so the route narrows to 15 fields. Generated routes take theirs
from their model through one rule; the hand-written routes state theirs, those
of the web application with =web_= tools, so all 1145 tools are unique. The
server refuses to start while a route is undeclared, names an unpublished area,
shares a tool, or changes something by its method while declaring that it does
not write and is neither a bulk get nor an operation named for reading. The
OpenAPI document carries each declaration, and the six-eyes hold reads it. The
typed bodies are the task Declare a typed body on every hand-written route.
