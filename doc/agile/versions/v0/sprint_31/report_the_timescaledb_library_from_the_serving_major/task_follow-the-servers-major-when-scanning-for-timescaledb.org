* Goal

* Result

compass db status now resolves the timescaledb library directory from the
server that is running.

The defect was in the lookup, not in the scan. =pg_config= on PATH answers for
the client's default installation, which on this host is PostgreSQL 19, while
the server that serves every environment database is PostgreSQL 18 and holds
=timescaledb-2.32.0.so= in its own library directory. The scan therefore read
=/usr/lib/postgresql/19/lib=, found nothing, and told a database that records
the installed version that no library was on disk.

- =server_libdir()= takes the server's version number and maps it onto
  =/usr/lib/postgresql/<major>/lib=, returning None when no such tree exists.
- =timescaledb_state()= asks the server for =server_version_num= and uses that
  answer as the key. =pg_config= stays only as the fallback for a host whose
  server cannot be asked.
- Two regression tests cover the failure as observed: a tree holding both major
  18 and 19 must select 18, and a major with no tree must return None.
