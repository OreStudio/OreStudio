* What

=projects/ores.codegen/tests/test_handler_permissions.py= fails on a clean
=main= at =c70e30a652=: =test_every_handler_permission_is_seeded= and
=test_a_code_missing_from_the_seeds_is_reported=. The check finds 16 permission
codes that the reporting ORE parameter value set handlers check and that
=iam_permissions_populate.sql= does not seed, the first of them
=reporting::ore_parameter_setting_value_sets:delete= in
=ore_parameter_setting_value_set_handler.hpp=. Seed the codes, or state why a
handler checks a code no role can hold.

* Why

A handler that checks an unseeded code refuses every caller, and the failing
test turns the codegen suite red for every branch, so the local check gate
cannot be green until it is fixed. It was found raising PR #3814, which changes
no handler and no seed.
