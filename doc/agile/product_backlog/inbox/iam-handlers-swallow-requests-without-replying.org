#+title: IAM account handlers swallow requests without replying
#+description: Thirty-one declared iam request subjects subscribe a handler that returns without replying when the request does not decode or the session is missing, so a caller waits until it times out instead of receiving a refusal. Found by build/scripts/check_subject_coverage.py after it was made fail-closed: the earlier classifier counted an unanswered request as served. The worst case is iam.v1.accounts.put, where account_operations_handler logs "Failed to decode" and returns; the same shape appears in the account, party and password operations. Every entry point should answer with error_reply, as the generated handlers do.
