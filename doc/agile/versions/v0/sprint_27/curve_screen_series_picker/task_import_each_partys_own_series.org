* Result

The importer now looks a series up by its URI and the importing party. Two parties can import the same
market file, and each ends with its own series and its own declared shape.

*Cause.* The importer called =read_latest_by_uri= without a party. The series table is isolated by tenant
alone, so the lookup found another party's series and reused it. The importer then wrote the axes under
its own party, which closed the other party's axes row, and the party policy refused that. It was harmless
while the importer wrote only tenant-isolated rows. The axes became party-isolated on 2026-10-08 and the
import began declaring shapes on 2026-10-09, both in this story's earlier tasks, and my import tests ran with
no party, so none of them could see it. The lookup already took an optional party, and the feed ingest loop
passed it.

*The fix.* One call passes the context's party to the lookup. A context with no party looks across the
tenant, as before. The test ran red first, with the exact error from the shell, and green after.

*A test-isolation finding.* The scoped test helper shares one tenant across tests, so a surface imported by
one test is still there for the next. The second test failed red for that reason. Each test that writes a
surface uses a pair of its own.

*On the running stack.* The import that failed under Acme Corporation Plc now succeeds, and Plc lists the six
surfaces and reads one's evolution.
