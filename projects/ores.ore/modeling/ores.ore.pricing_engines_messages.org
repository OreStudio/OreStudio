#+brief: Export, preview and import the ORE pricing engine configuration.

#+updated: 2026-10-27

A pricing engine configuration is one ORE document, =pricingengine.xml=, whose
root element is =PricingEngines=. The export writes it from one configuration
and answers with the file, as the currencies' export answers with
=currencyconfig.xml=. The ORE service reads the configuration through
analytics' own messages, under the caller's delegated session, and never
touches analytics' tables.

The export is read-only: it writes no row and records no history.

The preview and the import are the other half of the pair, in the shape the
currencies' pair established: =preview_<document>_import= parses a file and
says what the import would do, and =import_<document>= writes with the person's
choices. The preview writes nothing, and both need write on the configuration,
because the preview is the first step of a write.

Every =Product= becomes a product row and every =Parameter= a parameter row
scoped to the element that carried it, exactly as the exporter writes them, so
the document comes back product for product and setting for setting. Three
things a file may state have no row of their own, and the preview names each:

- a product type the vocabulary does not hold — the row is still written,
  because the tables hold any type code, but a person is told the screen cannot
  offer the type back;
- an attribute or element the tables have no column for — the row is written
  without it and the element is named;
- a row the file states twice, in one owner and scope — the first stands and
  the rest are named, because a document that states one setting twice cannot
  be saved (analytics refuses a repeated setting), so silence would be a
  refused write the person could not act on.

The difference is stated as rows: added, changed and removed. A row's =key= is
its identity within the configuration — the type of its product and which
product of that type it is, then the scope and the name of a setting — so a
choice names a row rather than a position in a list.

Only removed rows ask a question. A file that omits a row usually omits it by
accident, so every removed row is kept unless the person says otherwise, and
the import request carries the keys of the removed rows that were kept. An
added or changed row has no choice: the file's value is the one the person
reviewed.

The names of the operation, of its request and of its response follow the
record screen standard's =ore.v1.ops.export_<document>= (RS-ORE-06). The file
name is not stated here: it is the =name_pattern= of the file type row whose
=configuration_type_code= is =pricing_engines=, in the direction ORE Studio
reads and of the kind that is a document, so the table and not the code names
the file (RS-ORE-01).

* Physical space

The shell commands are switched off for the same reason as the ORE import's: the
component has no part under =projects/ores.shell=.
