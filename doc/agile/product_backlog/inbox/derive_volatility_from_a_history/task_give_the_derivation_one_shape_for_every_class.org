* Acceptance

- A derivation kind is a descriptor and a module. The descriptor states the method and its version, the transform, the coordinates a quote is named by, the smile model, the projection and the method note.
- The emitter, the batch runner and the page take the descriptor and never branch on the asset class. A class with no descriptor cannot be derived, and the refusal names the piece it lacks.
- The FX derivation and the interest rate derivation both register a descriptor, and neither is special-cased in the runner, the emitter or the page.
- Adding a class is a descriptor and a module, and the task states how many places name the class afterwards. That number is the measure of the pattern, and it must not grow with the class.
- The pattern does not pretend the methodology is shared: each module keeps its own projection and its own smile, and the descriptor only says which they are.

* Notes

- The lift merged as =f306a1152c= cut the engine where the class stops being named, with three parameters: the transform, the coordinates and the smile model. This task makes those three a declared shape rather than a convention each caller keeps.
- The stored method and version already exist as an identity for a series; the descriptor is where the emitter reads them, so the two cannot disagree.
- The FX derivation is the first descriptor to write, because it exists and its tests pin its numbers. A pattern with one implementation behind it is a guess, so the interest rate descriptor is written in the same task and the pattern is stated only when both fit.
