One value of a list a product states, keyed to the list's role and the value's
ordinal.

A worst-of basket swap states an initial price per basket member and a
knock-out and a fixed trigger level per determination date. Each list is a
list of plain numbers in the document, so each value is a row of its own rather
than a column of the product, and the role names the list it belongs to.

** Custom repository methods

The trade read path fetches the instrument values of many instruments at
once, and no generated read covers that: the generated reads address one key
group at a time. The batch read below is one statement over the instrument
set.

*** read_by_instruments_batch
:PROPERTIES:
:ID: 4E7DCE8E-2DE0-4045-920F-0597ED0EA485
:END:

Reads every current instrument value of the given instruments, in one statement. An empty input
reads nothing.

#+begin_src cpp :name implementation :implements F2EB1914-5E94-42CA-9C77-46BDB364BF9E
std::vector<domain::instrument_value>
instrument_value_repository::read_by_instruments_batch(
    const context& ctx, const std::vector<std::string>& trade_ids) {
    if (trade_ids.empty())
        return {};
    static constexpr auto max = db_timestamp::max();
    const auto tid = ctx.tenant_id().to_string();
    const auto query = query_builder::read<std::vector<instrument_value_entity>> |
                       query_builder::where("tenant_id"_c == tid &&
                             "trade_id"_c.in(trade_ids) && "valid_to"_c == max) |
                       query_builder::order_by("trade_id"_c, "value_role"_c, "sequence_number"_c);
    return query_builder::execute_read_query<instrument_value_entity,
                                             domain::instrument_value>(
        ctx,
        query,
        [](const auto& entities) { return instrument_value_mapper::map(entities); },
        lg(),
        "Reading instrument values for multiple instruments.");
}
