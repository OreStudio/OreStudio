#+brief: The bond issue: the terms of one ISIN (security_id), the stable row every instrument of the family references.
#+entity_singular: bond_issue
#+entity_plural: bond_issues
#+entity_title: Bond Issue
#+created: 2026-09-09
#+updated: 2026-09-12

One row per bond issue (ISIN), the stable row every instrument of the
family references. The columns map from =bondReferenceDatum=
(referencedata.xsd lines 97-113): security_id, issuer, the three curve
identifiers, the six fields beside them, issue date, settlement days and
calendar. Only =IssuerId= is required by that schema; every other
element is optional, so every other column is nullable and an absent
element is stored as NULL rather than as an empty string or a zero.

The bond's coupon terms are not here. ORE states them on =legData=
alone -- =bondReferenceDatum= carries no coupon rate, coupon frequency,
day counter or currency -- and the security's legs are
=bond_issue_leg= and its children, so the leg holds them once and this
row is not a second copy.

=face_value= is the issue's per-unit value and repeats the first leg's
notional. It stays because a row set that holds an issue and no legs
still has to export a leg, and it is what that leg's notional is built
from.

Two columns come from the trade's own copy of the datum and not from
=bondReferenceDatum=: =payer= and =credit_risk= are =bondData='s top-level
members (instruments.xsd lines 404 and 406), which the reference datum
does not state. They live here because =bondData= is the trade's copy of
the issue's terms and every other member of it is already mapped to this
row, so leaving the two out would drop them from the round trip.

** payer
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

The payer the document states for the bond itself, when it states one.

=bondData= carries a top-level =Payer= beside each leg's own, and the two
are separate elements: this column is the datum's, and
=ores.trading.bond_issue_leg.payer= is the leg's. =bondReferenceDatum=,
which the issue otherwise models, states neither.

** credit_risk
:PROPERTIES:
:type:     text
:cpp_type: std::optional<std::string>
:nullable: true
:END:

The credit-risk flag the document states for the issue, when it states one.

=bondData='s =CreditRisk= is ORE's loose =bool=, whose thirteen spellings
include the empty element the schema writes for true, so the column holds
the spelling as text the way =end_of_month= does. =bondReferenceDatum=
states no such element.

** Checks

Each check holds only for a value the document stated. An absent value
is NULL, and a NULL comparison passes, so an issue that states no face
value is admitted while a stated non-positive one is not. The
empty-string checks went with the columns that needed them: absence is
now NULL, not an empty string.

|---------------------------------------|
| "face_value" > 0                      |
| "price_type" is null or "price_type" in ('Clean', 'Dirty') |

* Delete cascade

The rows a bond issue owns. Each is keyed by the issue, so the delete rule
closes them when the issue goes. The issue goes only when its last
instrument does (=bond_instrument='s =:cascade_orphan:= on =issue_id=), so a
shared issue and its legs are not taken from an instrument still holding
them.
