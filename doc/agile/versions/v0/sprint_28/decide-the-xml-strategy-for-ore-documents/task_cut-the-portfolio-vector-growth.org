* Goal

Reading a portfolio spends 32.70% of its instructions in the trade vector's realloc_append and 19.29% in the trade move constructor (callgrind, import_portfolio_all_ore_example_files_can_be_parsed, 4.03 billion instructions in total, binary built from PR 3565). The generated append_to in xml/generated/portfolio.cpp calls emplace_back with no size hint, so each regrowth moves every trade already read. Cut that cost.

* Notes

Not decided, and the first step is to choose by measurement:

- Reserve a size. The binder does not know the child count ahead, so this needs
  a hint from the scanner or a heuristic reserve on the first append.
- Make the move cheap. The profile shows a large =memset= under the append, so
  default construction of a =trade= may cost as much as the move.
- Change the container for the repeated child, for example to a deque, which
  never moves an element. That changes the generated record type and every
  reader of it.

The same =append_to= template serves every repeated child, so a change there
touches all 13 tables. Prove the drift check and the corpus tests after it.
