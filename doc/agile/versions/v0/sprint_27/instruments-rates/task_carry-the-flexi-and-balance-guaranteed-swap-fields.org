* Acceptance

- FlexiSwap stores OptionLongShort and its lower notional bounds, and the export writes them.
- BalanceGuaranteedSwap stores ReferenceSecurity, its tranches with their notionals, and the tranche schedule, and the export writes them.
- Both products re-read after export, and neither appears in the corpus gate's known export gaps.
- The inbox capture for this work is removed.

* Plan

1. *Name what the schema requires.* =flexiSwapData= requires
   =OptionLongShort= and the lower notional bounds. =bgSwapData= requires
   =ReferenceSecurity= and =Tranches=, and a =Tranches= block holds tranches
   (description, security id, seniority, dated notionals) and a schedule.
2. *Model each as the family's pattern.* A product's own scalar goes on its
   fact table; a list goes in a child table keyed by the trade and the
   ordinal, as =callable_swap_call_date= is. A schedule goes in the shared
   =instrument_schedule= rows under a new owner role, so no schedule table
   is repeated.
   - =flexi_swap_instrument= is a new fact table, because a flexi swap
     stored a =vanilla_swap_instrument= row with no fields of its own.
   - =flexi_swap_lower_notional= holds one notional per row, with its block
     ordinal and currency.
   - =balance_guaranteed_swap_instrument= gains =reference_security=.
   - =balance_guaranteed_swap_tranche= and
     =balance_guaranteed_swap_tranche_notional= hold the tranches.
   - =instrument_schedule= accepts the owner role =tranches=.
3. *Wire them.* Generate the stacks, add them to the header's delete cascade
   and the catalogue's child list, seed the permissions, register the
   handlers, extend the carrier, the batch mapper, the export read and the
   import write.
4. *Map both ways.* Forward and reverse mappers in the ORE mapper, the
   exporter dispatch, and round-trip cases with literal values.

* Result

FlexiSwap and BalanceGuaranteedSwap now import, store and export every
element the ORE schema requires. Neither is a known export gap.

- *FlexiSwap.* A new fact table holds =OptionLongShort=. The lower notional
  bounds are rows of =flexi_swap_lower_notional=, one per notional, with the
  block's ordinal and currency, so the export regroups them into the blocks the
  document stated. A flexi swap used to store an empty vanilla swap row.
- *BalanceGuaranteedSwap.* The fact table gains =reference_security=. The
  tranches are rows of =balance_guaranteed_swap_tranche= and their dated
  notionals are rows of =balance_guaranteed_swap_tranche_notional=. The
  tranche schedule reuses the shared =instrument_schedule= rows under the new
  owner role =tranches=, so no schedule table is repeated.
- *The path.* The carrier, the batch mapper, the export read, the import write,
  the handlers, the permissions and the ORE mapper both ways all carry the new
  rows. The mapper cases check literal values from the two corpus documents.
- *A table name is shorter than the convention.* The generator cuts derived
  identifiers at 63 characters but the C++ entity keeps the full table name, so
  the conventional name for the tranche notionals would have made the SQL and
  the entity disagree. The table is =ores_trading_bg_swap_tranche_notionals_tbl=
  and the model says why. The mismatch is a generator defect and is not fixed
  here.
- The inbox capture for this work is removed.

Not done: the reverse mappers rebuild each leg's schedule from the header
dates, as the other reverse mappers do, so the leg schedules of these two
documents are not byte-equal to the source. The ER diagrams are not
regenerated. No end-to-end ORE import ran against a live service.
