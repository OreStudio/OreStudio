* Acceptance

- parse_cnb_czeonia skips a row whose rate cell is empty.
- A rate cell that holds text other than a number still refuses the file.
- A test holds rows as the bank wrote them in 2019.

* Plan

1. Fetch the bank's yearly files for 2016 to 2026 and find the rows the parser
   refuses: 2018, 2019 and 2020 hold 142 days with volume 0 and an empty rate.
2. Add a test with rows as the bank wrote them in 2019, and see it fail.
3. Skip a row whose rate cell is empty. Keep the refusal of a rate that is not a
   number.
4. Run the refresh on a fresh environment and compare the stored fixings with
   the bank's files.

* Notes

- The refresh window reaches back over the years 2018 to 2020, so before the
  fix every refresh failed and no CZEONIA fixing was ever stored. The CZK curve
  then reported that no series publishes its overnight rate, which is the CZK
  note in the IR calibration coverage story.
- On a fresh environment the CZK curve starts before the first CNB refresh
  lands, so it keeps its fixed rate until the synthetic service starts again.
  The story "Make a fresh environment ready quickly" covers that start order.
- The same run logged a failed refresh of =bcb-cdi=; that is a separate source.

* Result

The CNB adapter reads a CZEONIA row with an empty rate as a day with no fixing.
Every yearly file from 2016 to 2026 now parses, and a fresh environment stores
2367 CZEONIA fixings that match the bank's files day for day. The CZK curve
starts from the CZEONIA fixing. A rate that is present but not a number still
refuses the file.
