* Goal

compass pr merge refuses a branch that lacks commits of its base unless --force is given, so a merge result nobody checked, such as new templates beside old generated output, does not reach main by accident.

* Acceptance

- =compass pr merge= counts the commits of the base the PR's head lacks, and
  refuses with a reason when there are any; =--force= merges anyway and
  prints the reason.
- When GitHub cannot say, the merge warns and is not blocked.
- The merge skill and recipe list the guard.

* Notes

- Why: on 2026-11-21 main went red twice after merges whose branches were
  behind it. #4975 last took main five hours before #4979 changed the
  templates and merged 31 seconds before #4986, so main held new templates
  beside old generated output; the check inventory race with #4980 was the
  same. ORE runs no checks on a pull request, and the local gate checks a
  branch against its own merge base, so nothing checked the merged tree
  until the Compass check on main.
- The product owner chose a guard that --force overrides, not a hard
  refusal: sometimes a stale branch is meant to merge.
