* Result

Delivered the native Windows ORE package and reproducible build/package workflow, native service launcher and developer recipe, MSVC portability fixes, Windows-compatible filesystem tests, and Linux runner disk improvements. The pinned engine revision is 3d75a69087911a7e2cf1e6882da7bc27135c0762; the package uses the same executable/args manifest contract as Linux and declares x64-windows in its package metadata.

The local Windows installation completed a pricing batch of 15 jobs across five workers after the native environment handoff fix. This fleet exercise predates the upstream merge; it is not presented as a full fleet test of the merged branch. Package numerical and Linux parity reports are committed under external/ore/packages/.

Shared SQL and password hashing/verification remain identical to upstream f8adc1abcc. A fresh current-main test baseline was populated with synthetic accounts and cloned once. The rebuilt IAM service passed three schema checks with ORES_REQUIRE_SCHEMA_MATCH=1, accepted the existing human and service passwords, issued valid signed JWTs and rejected incorrect passwords. Account and credential snapshots were unchanged. The clone was never recreated or reseeded; the live installation was untouched.

The broad local gate was attempted with --exclude-heavy to preserve the installed database and services. Its POSIX launchers and venv paths are not usable on this native Windows host, so it did not pass. Focused native checks and the linked Linux build evidence are reported separately. The Windows nightly at 43e2ad9d50 failed before compilation in upstream's unchanged embedded-XSD seed: CRLF content violates its recorded byte count. The owner explicitly requested that this upstream fix remain outside this PR. Migration of the old local database and the full merged application/fleet gate remain unverified.

Focused final pre-submission checks: 112 Windows launcher, venv, adapter, Boost, catalogue and template-parity tests passed under the working Git Bash environment; all six package failure-path tests and documentation validation for all 39 components passed. The initial sandboxed invocation could not launch Git Bash; the same tests passed outside that restricted launcher. Upstream PR #4458 separately addresses the Windows CRLF nightly failure.
