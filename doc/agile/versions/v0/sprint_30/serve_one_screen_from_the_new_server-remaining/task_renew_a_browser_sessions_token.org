* Acceptance

- A cookie session whose token nears its expiry is renewed through iam.v1.ops.refresh, once, however many requests arrive together.
- A refresh IAM refuses ends the session and clears the cookie, as a maximum session age does.
- Tests prove the renewal, the single flight and the refusal.
- The local gate is green.

* Plan

Found on 2026-11-11 while reading the BFF's session for the session routes.
IAM mints an access token that lives =iam.token.access_lifetime_seconds=, 1800
by default. The BFF's client answered a service's =token_expired= by calling
=iam.v1.ops.refresh= with the token, keeping the new one, and retrying, with
one refresh shared by concurrent callers. The C++ gateway keeps the token in
its session store and never renews it, and =forwarding= answers a lapsed
session as a 401, so a browser session ends at its first expiry.

The gateway's session path is in =ores.http.api=, which knows no NATS, so the
renewal is a callback the application gives the session store, run before the
token expires rather than after a refusal, on a worker and not the I/O thread.

** What was built

- =session_store= gains =token_renewal= (renewed, refused, unavailable), the
  =token_renewer= callback, and =begin_renewal= / =end_renewal=, a claim one
  request holds while it renews, so a burst renews once.
- =http_session= renews a cookie session's token once three quarters of its
  life have passed, on both cookie paths, through the worker pool. The requests
  that arrive meanwhile go on with the current token, which is still valid. A
  refusal closes the session, so the request answers 401 and clears the cookie;
  a renewal that cannot be made keeps the current token for a later request.
- =session_renewal= in the IAM part sends =iam.v1.ops.refresh= with the
  session's token as Authorization, which is where IAM reads it, reads a refusal
  from =X-Error= or the answer, and verifies the new token before it is used.
  The application gives it to the server.
- The BFF renewed after a service refused an expired token and retried; the
  gateway renews before expiry, so no request is refused and retried.

* Result

A browser session in the C++ gateway keeps working past its first token: the
gateway renews the token through IAM once three quarters of its life have
passed, once however many requests arrive together, and a refusal ends the
session and clears the cookie. Tests prove the renewal, the single flight, the
refusal and a renewal that cannot be made, through the real server.
