writes. No model changes: the models are already current, and the six headers

include without the member. That is the template's shape on main, these six are
its only instances, and changing it is a separate question about the template
rather than drift in trading.

* Notes

The drift is one commit's miss, not a hand edit. =177a2d6196= added
=#include <chrono>= to the domain class header template, gated on
=has_audit_columns=, and regenerated the components under the gate. Six trading
instrument headers were left as they were.

The gate's registry lists =trading-cpp=, so =check_component_drift.py --all= has
been red on main since that commit. Nothing else noticed: the include is
harmless where it is missing, because these headers compile through
=audit_record.hpp=, which brings =<chrono>= with it. The gate is what makes it
visible, and only when it is run.

The six headers are the only generated domain headers in the tree that carry
=<chrono>= without naming =std::chrono::=. Every one of them carries
=audit_record audit=, whose member is emitted by the =has_audit_group= branch
that does not spell the timestamp; the include is emitted by the
=has_audit_columns= branch above it, which does not know about the group. No
other component has the shape, so the template's over-inclusion has exactly
these six instances. Whether the template should exclude them is left open.
