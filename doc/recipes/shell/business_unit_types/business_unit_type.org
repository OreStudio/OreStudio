#+title: How do I run the business_unit_types commands from the shell?
#+description: Every command the business_unit_types submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:business_unit_types:

This file documents the business_unit_types resource at the shell, one section per command. Every command is a subcommand of =business_unit_types=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 6889E08A-4873-5090-9BE7-C707507814DC
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
business_unit_types list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =refdata.v1.business_unit_types.list=.

#+name: business_unit_types-list
#+begin_src ores-shell :tangle business_unit_types-list.ores :exports none
business_unit_types list --limit 1
#+end_src

:ID: B14F4265-C30B-5047-9F26-2F4ADB8C0822

** =add=
:PROPERTIES:
:ID: DE1EF07F-3DF8-5229-BFAF-BE741828E665
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
business_unit_types add <id> <coding_scheme_code> <code> <name> <level> <description> <reason> <commentary>
#+end_example

** =set=
:PROPERTIES:
:ID: B6A0AC83-DF73-5D6E-96D0-C00614E31723
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:

#+begin_example
business_unit_types set <id> <coding_scheme_code> <code> <name> <level> <description> <reason> <commentary> [--version <n>]
#+end_example

It is addressed at =refdata.v1.business_unit_types.put=.
