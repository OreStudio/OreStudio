CLI/file parsing into options. =component-service= profile.

A service that adds a command-line option of its own supplies it from its
model, in two blocks on its =component_overview.org=:

- =<<paste:F98CC722-3E53-4B86-90E7-69EC5D25702E>>= — the whole
  =options_description= construction. Block name =service_app_config_option_decl=.
  Supplying it replaces the default =od= line, so a service that declares its
  own options never has the default one built as well.
- =<<paste:691CE3AB-6788-4E1C-8E8A-948CE6534C75>>= — assignments from the
  parsed variables onto =options r=, emitted after the standard ones. Block
  name =service_app_config_assignment=.

The option's member on the struct is a third block, on the
[[id:2DDED1C4-8943-4841-BD60-E541C5086F40][config_options_header]] archetype.

See the [[id:C4E8A91F-3B7D-4F2E-85A6-1D9C7E3B2F4A][Template variable reference]] for the complete list of available
variables and their semantics.

std::optional<options>
parser::parse(const std::vector<std::string>& arguments,
    std::ostream& info, std::ostream& err) const {

    try {
        return parse_arguments(arguments, info);
    } catch(const parser_exception& e) {
        err << usage_error_msg << e.what() << std::endl
            << more_information << std::endl;
        BOOST_THROW_EXCEPTION(e);
    } catch (const boost::program_options::error& e) {
        err << usage_error_msg << e.what() << std::endl
            << more_information << std::endl;
        BOOST_THROW_EXCEPTION(parser_exception(e.what()));
    }
}
