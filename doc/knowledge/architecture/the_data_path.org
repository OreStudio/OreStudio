* Summary

The data path is how a service reaches the database and how ticks reach the
store and the parties, designed to carry one hundred thousand feeds on one
machine that runs ten environments. A service holds a few long-lived
connections, a transaction carries its own tenant context, repositories work
inside an open transaction, statements are typed and prepared once, and every
store error says whether a retry can succeed. Handlers run on a bounded pool.
Ticks are stored once for each source, written in bulk by lanes, and kept in a
bounded, compressed window. The environments share the instance through a
pooler, the compute grid is woken rather than polled, and every queue and
session reports its own numbers.

This page orders the cluster. Read it top to bottom when changing how a
service talks to the store; read one page when changing one piece.
