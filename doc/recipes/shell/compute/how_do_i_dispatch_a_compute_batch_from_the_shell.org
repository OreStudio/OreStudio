#+title: How do I dispatch a compute batch from the shell?
#+description: Upload an input tarball once as the batch input bundle, and dispatch one job per job count from the shell.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:compute:batch:
#+created: 2026-08-11
#+updated: 2026-08-11

The compute grid verbs live in the shell's =compute= menu. They talk
to the ~ores.compute~ service over NATS; the domain shapes and table
renderers come from ~ores.compute.api~.

* Question

How do I dispatch a compute batch from the shell?

* Answer

Log in as the system super admin, then run =compute dispatch-batch= with the batch external reference, the job count, the app version id and the input =tar.gz= tarball. The command uploads the tarball verbatim (as the Qt UI does), marks the batch dispatched, and saves one workunit per job. Each save dispatches to the grid: the backend creates the result rows and publishes the assignments.

#+name: dispatch-compute-batch
#+begin_src ores-shell :exports none
connect $ORES_NATS_URL
login super_admin@localhost Secure-Password-123
compute dispatch-batch $BATCH_REF $JOB_COUNT $APP_VERSION_ID $INPUT_TARBALL
logout
exit
#+end_src

#+begin_src sh :noweb yes :results output :wrap example
./ores.shell ${log_args} ${connect_args} << 'EOF'
<<dispatch-compute-batch>>
EOF
#+end_src

The upload runs once: every workunit in the batch shares the same
input bundle, stored as =input/{batch_id}.tar.gz=.
