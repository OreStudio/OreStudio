#+title: A held LLM agent write is claimed (state applying) before or…
#+description: A held LLM agent write is claimed (state applying) before ores.http replays it and finished (applied or failed) after. If ores.http stops between the two, the row stays applying, its approval request stays approved, and nothing applies or fails it: the person sees an approved write that never happened. A sweep should mark a write that has been applying for longer than a replay can take as failed, with the reason interrupted, and fail its request, never replay it again, since the replay may have applied before the crash. The rows are per tenant behind row-level security, so the sweep needs a tenant-crossing read the gateway does not have today. Raised by the review of PR 5054.
