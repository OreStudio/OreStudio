For background on what the generator is and what it generates, see

* Question

How do I run the ORE Studio C++ code generator?

* Answer

** Everything that changed (preferred)

compass-ng regenerates every output whose model, template or other input
changed, writes nothing else, and formats C++ and TypeScript as the committed
tree is formatted. A warm run with no change takes a few seconds. Preview with
diff, which writes nothing, then write with generate:

#+begin_src sh
./compass.sh diff
./compass.sh generate
#+end_src

A new model file needs no step of its own: =generate= finds it and writes its
outputs.

** One model or one template

=--scope= limits a run to the outputs of the units that read one file, a model
or a template, and to what they feed:

#+begin_src sh
./compass.sh diff --scope projects/ores.refdata/modeling/ores.refdata.country.org
./compass.sh generate --scope projects/ores.refdata/modeling/ores.refdata.country.org
#+end_src

=./compass.sh codegen generate= and =codegen regenerate= also run
=compass-ng generate=, or =compass-ng diff= with =--dry-run=; their other
arguments no longer narrow the run. The Python generator they used to call is
deleted: it rewrote every file it rendered.

* Script

=./compass.sh generate= and =diff= forward to compass-ng through =cmd_compass_ng=
in [[proj:projects/ores.compass/src/compass.py][=compass.py=]], and =cmd_codegen= in the same file forwards the older verbs.

* Tested by

Run =./compass.sh codegen regenerate --component refdata --address ores.cpp
--dry-run= and verify it runs =compass-ng diff=.
