* Result

build_tree now places every row: a child already placed is not descended into
again, and every row left unreached by the roots is promoted to a root in input
order, so a parent cycle no longer vanishes from the forest. The generated
hierarchy function's ancestors and descendants CTEs carry the path they have
walked and stop when a row repeats; refdata, synthetic and workspace-cpp were
regenerated from the template.

Verified: ores.utility.tests passes, 7 test cases and 29 assertions, including
a two-row ring and a self-parented row; a new pgTAP test builds a real party
cycle and the function returns both rows and terminates, both from the given
node and from the root walk, 2 of 2 passing; SQL hygiene is clean and refdata
regeneration shows no drift.
