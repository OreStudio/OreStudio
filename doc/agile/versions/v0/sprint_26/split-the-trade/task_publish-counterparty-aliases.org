* Acceptance

- Counterparty aliases are a DQ artefact type, keyed to each counterparty's LEI, with a publish function that writes them as counterparty identifiers of the tenant's counterparty holding that LEI.
- ore.counterparty_aliases holds the 23 sample aliases, depends on gleif.lei_counterparties.small, and is an optional member of the base bundle that acme_demo opts into.
- CP maps onto the same bank as CPTY, so the netting set NS, which both use, belongs to one counterparty.
- Build, ctest, pgTAP and the local check set pass.

* Plan

The system tenant got its ORE aliases from an inline insert in the ORE sample
publication script. A provisioned tenant never runs that script: it gets
reference data only through DQ bundles. So the aliases become a DQ artefact.

- Add the staging model =ores.dq.counterparty_alias= (id_value, id_scheme, lei,
  description) with the artefact staging only profile, and generate it.
- Add the artefact type =counterparty_aliases=, which targets
  =refdata_counterparty_identifiers_tbl= through
  =refdata.v1.counterparty-aliases.publish-from-dq=.
- Add =ores_refdata_publish_counterparty_aliases_from_dq_fn=. A counterparty id
  differs per tenant, so the alias names its counterparty by LEI, and the
  function joins through the tenant's LEI identifier. An alias already held,
  and an alias whose LEI has no counterparty in the tenant, are skipped.
- Move the 23 aliases into the dataset =ore.counterparty_aliases=. It depends on
  =gleif.lei_counterparties.small=, is an optional member of =base=, and
  =acme_demo= opts in to it. The system tenant publishes it through the same
  function.
- Remap =CP= from HSBC onto JPMorgan Chase, the bank of =CPTY=: both use the
  netting set =NS=, and a netting set belongs to one counterparty.

* Result

ORE counterparty aliases are now a DQ artefact type. A provisioned tenant gets
them through the =base= bundle. After the ACME provisioning recipe, the ACME
tenant resolves all 23 ORE names onto 11 GLEIF banks, and =CP= and =CPTY= name
the same counterparty (JPMorgan Chase Bank). The dataset
=ore.counterparty_aliases= depends on =gleif.lei_counterparties.small=, so a
publication orders the counterparties before the aliases. pgTAP covers the
resolution, the shared bank of =CP= and =CPTY=, a second publish that writes
nothing, and an alias whose LEI the tenant lacks.
