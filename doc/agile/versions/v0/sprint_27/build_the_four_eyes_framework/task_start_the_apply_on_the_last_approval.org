* Acceptance

- A kind names the workflow that applies its requests, or none.
- The decision that approves the last part starts that workflow with the request, once.
- A request of a kind that names none stays approved and starts nothing.
- The refdata.book_change kind names the book apply workflow.

* Plan

(Implementation strategy. Written when work starts; key decisions
are distilled into the parent story's =* Decisions= at close, but the
plan itself stays — it is the historical record of what we did.)

- Add a nullable =apply_workflow_type= column to the approval kind. The kind is the typed place that says which workflow applies a request, and the inbox reads it without knowing what the request changes.
- Fix one shape for the workflow's request, ={"request_id": "<id>"}=, so the inbox starts any kind's workflow. The book apply workflow already reads that shape.
- Build the start message in one pure function, so it has tests. The run's id comes from the request's id alone, so a second start names the same run and the engine leaves it alone.
- Start the workflow from the decision that moves a request to approved, forwarding the approver's token so the run is attributed to them.
- Seed the book change kind with =book_apply_workflow=.

* Notes

- A failure to publish the start is logged and is not the decision. The request stays approved with no run behind it. The task "Retry a stopped apply until the window ends" now also finds such requests and starts them.
- The engine already recognises a repeated start by the run's id and leaves the first run alone, so a redelivered decision cannot apply a request twice.
- The role request kind names no workflow, so it starts nothing and its reconciliation is unchanged.
- The start is not tested against a running engine, as no other start is. The message and the seeded kinds are tested.

* Result

The decision that approves the last part of a request starts the workflow its kind names.

- =apply_workflow_type= is a nullable column of the approval kind. =refdata.book_change= names =book_apply_workflow=, and =iam.role_grant= names none.
- =apply_start_of= builds the start message from the kind and the request: the type, the tenant, the request as target, ={"request_id": ...}= as the request, and a run id derived from the request id alone.
- The decide handler publishes it when a request moves to approved, forwarding the approver's token, and logs a failure without undoing the decision.

Evidence: the four new cases pass with the whole =ores.inbox.core.tests= binary (43 cases, 220 assertions), and the whole =ores.refdata.core.tests= binary passes (359 cases, 4799 assertions). The BFF tests (526) and the web typecheck pass with the regenerated wire types. The cmake source, handler permission, test case reachability, pasted block symbol, populate reference and derived-model checks pass, the strict ER parse is clean and the diagrams match, and the catalogue drift sweep is clean.

Not done here: a test against a running engine, and the repair for an approved request whose start was lost, which is in the retry task.
