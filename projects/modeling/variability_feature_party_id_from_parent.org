* Effect

Derive =party_id= from the parent row inside the insert trigger. The struct
names the parent table (=parent_table=), the column of the entity that
references it (=parent_column=) and the message the existence check raises
(=parent_error_message=). The trigger reads =party_id= from the parent row that
is current in the entity's tenant and ignores whatever the caller sent. A
parent that does not exist raises the message with SQLSTATE 23503.

It is the general form of =party_id_from_book_id=, which derives the party and
the portfolio from a book. Use it when an entity belongs to a row that already
states the owning legal entity, such as a CSA that belongs to a netting set.
The party then cannot differ from the parent's, because the caller never
supplies it.

A model that uses this feature also sets =:seed_parent_party_id: true= on the
foreign key that names the parent, and lists its own =party_id= foreign key
first. The generated eventing integration test then seeds the parent under the
entity's own party. Without the property the test seeds the parent under a fresh
party, the trigger stores that party, and the test cannot read back the row it
wrote.

* Structural consequence

None for the column set. It assumes a =party_id= column already exists. The
column is not in the entity's write message, because the caller does not
supply it.
