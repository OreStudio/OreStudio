* Acceptance

- The anchor model is ores.trading.trade, keeping its org id, and every file it generates is renamed with it.
- Table, functions, triggers, policies, subjects, permissions and hand-written code use trade and trades; no trade_anchor identifier remains outside history.
- The round trip stays at in-scope lost 0 with every envelope as stated; build, ctest, pgTAP under RLS and the local check set pass.

* Plan

- List the anchor model's 30 generated files with =codegen generate
  --dry-run= and delete them, then rename the model to
  =ores.trading.trade.org=, keeping its org id so every link holds.
- Rename every identifier with one script
  (=scratchpad/rename_anchor.py=): =trade_anchors= to =trades=,
  =trade_anchor= to =trade=, =TradeAnchors= to =Trades= and =TradeAnchor=
  to =Trade=, over every tracked file except the agile history and the
  kanban fixtures. Prose that calls the trade's immutable row its anchor
  keeps the word, because it names the concept, not the entity.
- Regenerate the trade component, refresh the CMake lists and the ER
  diagram, and rename the pgTAP test with the table.
- The wide trade is gone, so no name collides: its files, table, subjects
  and functions were deleted with it, and the =trading::trades:*=
  permissions the booking already checks are the ones the entity's own
  handler now checks.
