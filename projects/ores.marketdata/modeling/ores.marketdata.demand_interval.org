A demand interval is a fact about usage. It records that one item was in the demand set of a party, and
so was published by the source that served the party, from one time to another. Demand is a control
signal for the adapter and a billing fact for the vendor: a live adapter pays for the items in the set.

The service opens an interval when an item enters the demand of a party and closes it when the item
leaves, or when the party stops being served by the source.

*** read_latest_all_tenants
:PROPERTIES:
:ID: 17E88264-9127-4474-9FEA-0CD0D79D1CEB

Reads the latest demand intervals across all tenants. The service that meters usage reads the intervals
that are open for every party, so it cannot filter on one tenant. Queries only on
=valid_to == max=.

#+begin_src cpp :name implementation :implements F2EB1914-5E94-42CA-9C77-46BDB364BF9E
std::vector<domain::demand_interval>
demand_interval_repository::read_latest_all_tenants(context ctx) {
    static const auto max(make_timestamp(MAX_TIMESTAMP, lg()));
    const auto query = query_builder::read<std::vector<demand_interval_entity>> |
                       query_builder::where("valid_to"_c == max.value()) |
                       query_builder::order_by("id"_c);

    return query_builder::execute_read_query<demand_interval_entity, domain::demand_interval>(
        ctx,
        query,
        [](const auto& entities) { return demand_interval_mapper::map(entities); },
        lg(),
        "Reading latest demand intervals across all tenants");
}
