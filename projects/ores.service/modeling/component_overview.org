* Summary

=ores.service= is the shared infrastructure every ORE Studio NATS
backend service is built on. It owns no domain type and no wire type of
its own. What it owns is the envelope around them: the service lifecycle
that fetches the JWKS key with backoff, builds a JWT verifier, registers
the handlers and drains on shutdown; the host envelope that parses the
arguments, starts the logging lifecycle and runs the application; the
per-request database context built from the validated JWT; and the
handler helpers that stamp server-authoritative fields, check
permissions, reply and decode.

The component is model-free. It carries no entity, junction or operation
model, so nothing in it is generated, it appears in no SQL or shell
output, and every file is hand-written.

The two runners are the reason the component exists. Before them, each
service carried its own copy of the same fifty-line host body and the
same startup sequence, and two of them had silently drifted from the
canonical shape. A service now writes only its own registration call and
its own domain logic. Every =.service= binary and the tools that share
the host envelope (=ores.shell=, =ores.http.server=,
=ores.compute.wrapper=) are callers.

The component is protocol-adjacent rather than protocol-owning. It reads
the workflow step command headers that =ores.workflow= declares, and it
publishes the workflow and telemetry messages those components model, but
it declares no subject and produces no protocol header of its own.

* Facets

- =config/= — =standard_service_options=, the one place a domain service
  builds and parses the shared common/logging/database/NATS option set,
  and =standard_options=, the struct it reads them into. It is also the
  single call site for
  =nats_configuration::register_shared_domain()=.
- =messaging/= — the handler surface. =handler_helpers.hpp= holds
  =stamp=, =has_permission=, =reply=, =error_reply=, =decode= and
  =log_handler_entry=; =workflow_helpers.hpp= holds the workflow step
  context, the step idempotency check and the step-completion publishers.
- =service/= — the lifecycle itself: =run= for a database-backed service,
  =run_signing= for a service that mints its own tokens, =run_host_async=
  and =run_host_sync= for the process envelope, =make_request_context= for
  the JWT-to-context step, =heartbeat_publisher= for liveness,
  =notify_systemd_ready= for the readiness notification, and =exit_code=
  for the process exit contract.

* Inputs

- A connected NATS client and a database context per service.
- The JWKS public key fetched from IAM, or the service's own RSA private
  key for the signing lifecycle.
- Inbound NATS messages: their subject, headers and payload bytes.
- The process environment: =NOTIFY_SOCKET= for the readiness
  notification, and the option environment variables the parser reads.
- Command-line arguments and the parsed options of the calling tool.

* Outputs

- A registered, ready and gracefully draining NATS service, with the
  subscription count logged.
- A per-request =ores::database::context= scoped to the JWT's tenant,
  party, roles and workspace.
- A =READY=1= notification to systemd where =NOTIFY_SOCKET= is set.
- Heartbeat messages on the telemetry service's subject.
- Step-completion events on the workflow engine's subject.
- A process exit status drawn from =exit_code=.

* Dependencies

- =ores.nats= — the client, the wire codec, the message type, the JWKS
  fetch and the standard header names.
- =ores.security= — JWT verification and signing.
- =ores.database= — the per-request context type.
- =ores.workflow.api= — the step-completion event, the step query
  protocol and the header names its step commands carry.
- =ores.telemetry.core= — the logging lifecycle manager the host envelope
  starts.
- =ores.platform= — the shutdown-signal set and the environment access
  the readiness notification reads.
- =ores.logging= — the logger every helper in the component writes to.
- =ores.utility= — tenant ids, the program-options helpers and the
  streaming operators the host envelope logs with.
