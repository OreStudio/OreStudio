* Notes

- *The screen carries no "not available" panel, because the gaps it stated are
  closed.* The prototype drew four gaps: no read named a party, set-default had
  no route, the default could not be cleared, and the association read had no
  client wrapper. The group's server tasks closed all four, so the accepted
  screen is drawn whole. The only state left is a party the server cannot name,
  which is drawn as a stated gap because the read can still return one.
- *The acting party and the switch come from the route, not the session
  context.* A screen that reaches for =useSession= cannot be rendered in the
  suite's static markup, and the screens here are renders of what they are
  given. The shell now carries =onSwitchParty= beside =onSignOut=, which is the
  same shape: the session owns the action, the route hands it to the screen.
- *The identity panel falls back rather than failing.* The shell already reads
  the signed-in person's own account for its menu, and this is the same query,
  so both share one answer. A member who may not hold the account read keeps
  the username the session states; the panel is not the screen's error.
- *The account menu, not the area menu, is the entry point.* The journey says a
  member opens *Where I work* from their own name, so it sits with Profile,
  Access and Security rather than in the areas across the header.
