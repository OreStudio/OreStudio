proposed recording both as accepted exceptions. The standard refuses that:
"An item that is merely unfinished is not an exception; it is unfinished
work, and the component waits." An exception is for a check that cannot pass
where the work is done. Neither of these is that, so both are finished
instead.

   verdict with the evidence. A verdict of "not applicable" is recorded with
   its reason, never skipped.

   live fleet with =check_shell_recipes.py=, which is the script the item's
   own evidence names. Record every command that cannot run and the reason.
   The eight execution-step commands cannot answer from the shell because
   their handlers return in silence when the workflow headers are absent;
   that is a recorded reason, and the item allows it.
3. Close V08. Give =report_input_bundle_repository.cpp= a database test, and
   record the reason for every remaining source file that no test names.
   The item asks for a test *or* a recorded reason, so the composition and
   entry-point files are closed by their reason.
4. Take no exception. Both items are made to pass, so the registry entry
   needs no =ACCEPTED_EXCEPTIONS= change.
