#+title: How do I run the pricing_model_products commands from the shell?
#+description: Every command the pricing_model_products submenu answers, with the script each one exports into the shell's script library.
#+type: recipe
#+level: cross
#+filetags: :recipe:shell:pricing_model_products:

This file documents the pricing_model_products resource at the shell, one section per command. Every command is a subcommand of =pricing_model_products=, and every section exports its own script into =projects/ores.shell/scripts/library/=. Loading a script runs that one command, so a failure names the command it came from.

* Commands

** =list=
:PROPERTIES:
:ID: 3F19FF8C-F22D-551B-9E39-91021A44C4AA
:END:

Reads one page of the collection. Nothing addresses it but the caller's tenant, so it is the read that shows what exists.


The command is shaped like this:

#+begin_example
pricing_model_products list [--offset <n>] [--limit <n>] [--order <field>] [--desc]
#+end_example

It is addressed at =analytics.v1.pricing_model_products.list=.

#+name: pricing_model_products-list
#+begin_src ores-shell :tangle pricing_model_products-list.ores :exports none
pricing_model_products list --limit 1
#+end_src

** =get=
:PROPERTIES:
:ID: D7147BBC-E23A-5D1E-A8A4-340867BE1D10
:END:

Reads the one row its key addresses. A key states every identifying column, so a partial key is refused rather than answered with an arbitrary row.


The command is shaped like this:

#+begin_example

#+end_example

It is addressed at =analytics.v1.pricing_model_products.get=.

#+name: pricing_model_products-get
#+begin_src ores-shell :tangle pricing_model_products-get.ores :exports none
pricing_model_products get __none__
#+end_src

** =add=
:PROPERTIES:
:ID: 485F4CD7-707C-5DD1-A987-7F62F6C94204
:END:

Writes a row. The change states that the row must not exist, so a create that collides with an existing row is refused rather than replacing it. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved.


The command is shaped like this:

#+begin_example
pricing_model_products add <id> <pricing_model_config_id> <pricing_engine_type_code> <model> <engine> <reason> <commentary>
#+end_example

It is addressed at =analytics.v1.pricing_model_products.put=.

** =set=
:PROPERTIES:
:ID: 3E60D9AF-5255-5E5B-8AC3-5CDD2B34A56C
:END:

Writes a row. The change states no precondition, so it replaces whatever row the key already addresses. The change carries a reason and a commentary, which the server records on it so the row's history says why it moved. Passing --version makes the write conditional on the version the caller last read.


The command is shaped like this:
