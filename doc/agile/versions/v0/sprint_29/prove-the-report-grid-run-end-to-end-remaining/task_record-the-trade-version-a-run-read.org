* Result

A failed trade's error row says the version the run read.

The trading export response now carries the version of every trade it wrote.
The gather passes that manifest through the workflow, the bundle keeps it as
=trade_versions= (jsonb), and the recorder looks the failing trade up in it. A
trade found there gets =subject_version=, and =subject_as_of= is the date the
instance priced at. A trade the manifest does not name records with both null,
because a missing manifest is a fact about the run and not a reason to lose the
error.

Proven on instance =ea7bcf57=. The run failed on market data and recorded 24
trade rows, eight trades read three times each. Every row carries
=subject_version= 5 and =subject_as_of= 2026-05-05, the instance's priced date,
and all eight manifest entries equal the stored version of their trade.

The bound worth knowing: every trade in that report's books is at version 5, so
the run shows one version repeated and the per-trade lookup is held by the unit
tests rather than by two differing values in one run.
