* Goal

=complete_structure= writes a =structures= row and one =structure_members= row for each leg, and takes the legs live. The structure has no book, no trade date and no state of its own, so it is not a trade and cannot be a row. The composite trade it should be is never written: the demonstration holds five composite trade ids whose rows are all closed, and none of them has a booking or a state.

This task makes the completion write the package as a composite trade: one trade row whose instrument is the composite, one booking that states its book and date, one state, and one leg row for each component trade. The unit already holds the leg checks and the take-live step, so it holds these too. It writes no structure row.

The composite book and date are the deal own, taken once at completion from the legs: the book they share and the earliest trade date among them. A completion whose legs sit in different books is refused, because a package is booked in one book. The composite state is live, because completion is what takes a deal live. The structure counterparty is the composite counterparty.

* Acceptance

- One completion writes one composite trade, its booking, its state and one leg for each component, in one transaction.
- A completion of legs in different books writes nothing and says why.
- A completion writes no =structures= row and no =structure_members= row.
- The composite reads back through =trades=, =trade_bookings= and =trade_states= with its book, date and state, and its legs name the component trades.
- A second completion of the same package is refused as already made.

  composite trade is not booked and carries no state, so it cannot be a blotter

  already carries it, the screen already names it, and the row it becomes keeps
  that name.
