* Overview

A trade's operational state follows a finite state machine. This document
describes that machine: the states a trade can be in, the events that cause
transitions between them, and the taxonomy of activity types used for P&L
attribution and reporting.

[[id:DCF3C3CD-23E5-4F45-AE9C-CA91CC7F3B08][Trade status FSM implementation]] covers how the machine is held
in the database.

* Trade Status

The /trade status/ is the operational state of a trade at a given
moment. It answers the question: /what state is this trade in right
now?/

Status drives whether a trade is included in risk and P&L (only =live=
trades), what operations are permissible on it, and how it is filtered
for reporting and reconciliation.

It is one of three things a lifecycle discussion routinely conflates.
[[id:584EC77C-9BA2-4200-9112-FBA1B6A2190D][Trade activity]] covers the second, an event that happened to a trade,
and [[id:03C12558-69AC-4925-AAE1-85FFF75B10BA][trade classification]] covers the third, what the trade is.

* The Trade Lifecycle

[[proj:doc/knowledge/domain/trade_status_lifecycle.png]]

| State | Description | Initial | Terminal |
|-------+-------------+---------+----------|
| =booked= | Recorded in our books. | Yes | No |
| =authorised= | Operations has checked the booking and released it. | No | No |
| =live= | Contributing to risk and P&L. | No | No |
| =expired= | Contract ceased naturally: expired, matured, exercised. | No | Yes |
| =cancelled= | Removed from the book. | No | Yes |

| From | To | Event | Notes |
|------+----+-------+-------|
| (initial) | =booked= | Book | Any trade-creating activity. |
| =booked= | =authorised= | Authorise | Operations checks the booking and releases it. |
| =authorised= | =live= | Activate | Enters risk and P&L. |
| =live= | =expired= | Expire / Mature / Exercise | Contract ceases naturally. |
| =booked= | =cancelled= | Cancel | Cancelled before authorisation. |
| =authorised= | =cancelled= | Cancel | Cancelled before activation. |
| =live= | =cancelled= | Cancel / Terminate | Cancelled or terminated while active. |
| =booked=, =authorised=, =live= | unchanged | Amend | A change to the deal; see below. |

** Amendment leaves the state unchanged

A trade may be amended at any point before it reaches a terminal
state, and amending does not move it. A live trade that is amended
stays live; a booked trade that is amended stays booked.

What an amendment does produce is a version. [[id:8BC3A226-6DD8-49C8-959A-F1AAC97A3F97][Deal versioning]] covers
what a version is and how the internal and external versions move,
and [[id:584EC77C-9BA2-4200-9112-FBA1B6A2190D][trade activity]] classifies which amendments are economic,
which are confirmable, and which are real.

A change that cannot be made in place is not an amendment. Cancelling
and rebooking produces two trades, each with its own lifecycle, and is
covered under the forms an amendment takes.

** Confirmation is a separate lifecycle

Confirmation does not appear in this lifecycle. A trade carries risk
from the moment it is released into the book, whether or not its terms
have been confirmed, so a pending client trade is managed from the
start and an unconfirmed trade is a counterparty risk rather than an
inactive one.

A trade therefore carries two statuses. =trade_status= is the state
above. =confirmation_status= is a state in the confirmation lifecycle,
which [[id:74721BF2-2290-4AA7-8871-E215DA04351F][confirmations]] covers, and which
[[id:03C12558-69AC-4925-AAE1-85FFF75B10BA][trade classification]] decides the starting point of.

| Trade | =trade_status= | =confirmation_status= |
|-------+----------------+-----------------------|
| Client swap, just booked | =booked= | =unconfirmed= |
| Client swap, in the book, paperwork outstanding | =live= | =unconfirmed= |
| Client swap, fully papered | =live= | =confirmed= |
| Desk transfer between our own books | =live= | =not_required= |
| Matured client swap | =expired= | =confirmed= |

The second row is the one a single status cannot express.

** Authorisation moves no version

Authorisation is a control rather than a term of the deal, so it moves
no version: a version produced by authorising would itself require
authorisation, without end. It is a statement about a version rather
than a change to the trade.

It is nonetheless a state here, because an unauthorised trade exists
and contributes to nothing, which is a fact about where the trade has
got to. [[id:A9E9D1EF-5879-4488-87C8-BDD914C3B502][Authorisation]] covers the control and
[[id:785C68A0-DD94-404A-BF16-57814554DA12][the authorisation queue]] the screen it happens on.
