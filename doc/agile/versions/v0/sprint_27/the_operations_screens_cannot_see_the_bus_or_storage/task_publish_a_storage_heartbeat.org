* Notes

The roster derives each service's state from its heartbeat, so a service that
never publishes one reads as =missing= however healthy it is. The screen
reported =ores.storage.service= and =ores.web.service= that way while
=compass services status= showed 24 of 24 running.

Storage is a plain omission: every other compiled service builds a
=heartbeat_publisher= in its =on_started= callback. There is no storage-specific
reason to skip it.

=ores.web.service= is a different case and is left alone. It is the Node BFF; it
has no heartbeat mechanism at all, and whether the roster should list a service
that cannot report is a question about the roster rather than about the web
service.

=ores.storage/service/src/app/application.cpp= carries an
=AUTO-GENERATED FILE= header naming =cpp_service_app_application.cpp.mustache=,
but that template — and the org source it tangles from,
=ores.cpp.service-app.application_impl.org= — is still the =service is not yet
implemented= stub. It cannot produce the file that is checked in, and
=storage-cpp= is not in the drift registry. The file is hand-maintained in fact,
so it is edited directly here, as its siblings must have been.
