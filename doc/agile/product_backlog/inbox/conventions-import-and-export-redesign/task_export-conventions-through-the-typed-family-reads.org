* Goal

The conventions export reads each family through its own generated list request, with the party and one as_of on every page. ores.ore no longer builds requests by hand, picks the first array of an untyped reply, or filters the party itself.

* Acceptance

- run_configuration_operations.cpp holds no rfl::Generic and builds no request by hand.
- Every page of every family carries the same as_of, so an import that commits between pages does not appear in the export.
- The party filter runs in refdata, not in ores.ore.
- A conventions file imported and exported unchanged produces the file it started from.
