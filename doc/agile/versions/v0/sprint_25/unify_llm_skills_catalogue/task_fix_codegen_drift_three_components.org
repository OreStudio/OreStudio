* Goal

The checked-in generated code and the generator disagree, and nothing
reports it.

Found while fixing a compiler warning: the table renderers are generated
from =cpp_domain_type_table.cpp.mustache=, so a one-line template change
was the right fix. Regenerating =marketdata= produced exactly that one
line in five files. Regenerating =analytics-cpp=, =refdata= and
=scheduler-cpp= produced 116 changed files with 1112 insertions and 756
deletions, and created 24 files that had never been committed —
registrars, protocol headers, presentation and generator directories,
eventing integration tests.

None of that was the template change. It is the accumulated difference
between what was committed at some point in the past and what the
generator emits today, and it sat invisible because nothing regenerates
those components in CI.

The danger is specific rather than theoretical. Anyone making a
legitimate template change to these components has to choose between
shipping a 1100-line diff they did not author and not making the change
at all. That is what happened here: the drift was reverted and the task
it surfaced in shipped without it.

=trade= is a fourth component with the same disagreement, and it is the
one that shows what the drift costs. Its committed
=trade_generator.cpp= declares a =counter= that nothing reads. The
model gives =trade= a uuid primary key, no natural keys and no
=:unique:= column, so all three disjuncts of =needs_counter= are false
and the current generator emits no counter at all. The declaration is a
leftover from a generator the model no longer describes.

The compiler found it once =-Wall= was on, and the warnings task
silenced it with =[[maybe_unused]]= rather than by regeneration,
because regenerating =trade= is not a one-line diff: the emitted code
is flat where the committed code uses field groups, and it lands in
namespace =generators= where the committed code uses =generator=. It
would not compile against the domain type as it stands. That
=[[maybe_unused]]= should come back out when this task regenerates the
component; it marks drift rather than an intentional declaration.

* Result

Two of the three components are cleared and one cannot be cleared this
way. The premise that all three were the same kind of problem was
wrong, and that is the substantive finding.

=analytics-cpp= is done and has joined the enforced registry. 23 files
changed and 12 were materialized that had never been committed. Almost
all of it was the generator being right and the tree being stale: the
SQL create scripts gain change-reason validation and replace
=current_timestamp= with =clock_timestamp=, which fixes a
same-transaction multi-write colliding with itself; the drop scripts
gain their licence header; services gain braces and generators gain
the maybe_unused marker.

One difference was substantive, and it is the reason this task
insisted on understanding each one. The combo sort lambda in
=PricingEngineTypeDetailDialog= was hand-edited to return a constant
while the generator emits the code field, so regenerating blindly
would have reverted the hand-edit. Neither form was right.
=sort_key_of= takes an =int= and =instrument_code::code= is a
=std::string=, so the generated form does not compile — proved by
compiling it rather than argued. The hand-edit made it compile by
sorting on a constant, which disables ordering. The model was the
defect: it named =code= as =combo_sort_field= where every other dialog
names an integer column, so it now names =display_order=, the column
24 other dialogs use. The result compiles and sorts.

The 12 untracked files are the history-provider registrars and
eventing integration tests, a family =iam= already carries committed.
Committing them needed the eventing dependency their tests use, which
the analytics test target did not link.

=refdata= needed nothing. It joined the registry between this task
being filed and being worked, and regenerates clean.

=scheduler-cpp= is not a drift clear, and is filed separately as
[[id:294FFF1A-E70B-489A-B7A3-40F57528B46E][Resync the job_definition model with its hand-written code]]. Its
model carries a warning against regenerating any facet of it, and the
warning is correct: the model's =tenant_id=, =schedule_expression= and
=is_active= column shapes do not match the hand-written struct, so
regenerating emits =std::string= where the code has a
=cron_expression= value type and =int= where it has a =bool=. That is
wrong types rather than wrong formatting, and accepting it would
regress the code in order to clear a diff. The model needs correcting
first, which is a modelling task rather than a regeneration.

Acceptance is met for =analytics-cpp= and =refdata= and not for
=scheduler-cpp=. The registry criterion is met for the two that can
join it: eight components are now enforced. The criterion that the
gate runs in CI was met by the preceding task.
