* Acceptance

- ores.storage.api is a compiled library, not an INTERFACE library.
- The objects model opts in to the wire codec, and the generated bytes match reflect-cpp's in a test.
- The storage service, shell and clients build and their tests pass.

* Plan

The objects protocol stayed on the reflect-cpp fallback because
=ores.storage.api= was header-only. An INTERFACE library cannot hold the
generated codec sources, so the opt-in failed to link in the shell work (#4378).
The user decided to make the part a compiled library.

1. Remove =#+header_only: true= from the api model, and link =ores.utility=
   =PUBLIC=, because the protocol header declares the codec specialisations.
2. Opt the objects model in to the wire codec and regenerate =ores.cpp= and
   =ores.cmake=. The shell object commands follow the gate from #4378.
3. Move the two hand-written HTTP body reads in =raw_storage_commands.cpp= from
   =rfl::json::read= to the generated codec.
4. Add =codec_wire_bytes_tests.cpp= to the api tests: every message's default,
   and filled messages, against reflect-cpp's JSON and MessagePack.

The storage service needs no hand edit. Its handler decodes through the wire
codec, which takes the generated specialisation once the protocol header
declares it.
