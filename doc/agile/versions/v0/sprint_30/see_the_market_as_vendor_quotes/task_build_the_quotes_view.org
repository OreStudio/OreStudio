* Plan

The screen is the signed-off prototype, variant C: a source rail with /All
vendors/, two layouts (every datum, by series), the asset class codes table as
the class filter with the instrument type under it, and the /All quotes/ panel of
the picked row. The routes are in =ores.http= only, under =/cpp= (product owner).

1. *The quote board* (=ores.http= marketdata). One subscription to
   =marketdata.v1.ops.market_tick.>=, through an injected subscriber as
   =feed_tick_buffers= has, so a test feeds it by hand. It keeps the latest quote
   of each datum on each feed: provider, feed, source name, URI, value, previous
   value, observation time, and a board sequence number. The feed is read from
   the subject's tokens. A cap bounds it. Each quote is labelled once, from its
   URI read by the codec: the instrument type, the asset class code through
   =asset_class_for_authority()=, the series URI and its words, and the point.
2. *The routes.*
   - =GET /api/marketdata/quotes/feeds=: =list_watchable_feeds= for display,
     forwarded as the caller, with each feed's source name and last tick from the
     board, and the asset class codes with their names for the filter.
   - =GET /api/marketdata/quotes?after=<sequence>=: the board's quotes after the
     sequence, of the feeds the caller may watch, asked again on every read, and
     the board's sequence now. The screen polls it; the first read is the whole
     board.
   - =GET /api/marketdata/quotes/history?provider=&series=&from=&to=:
     =get_provider_ticks= for display, forwarded as the caller.
   The entitlement answer is injectable, so a test states it.
3. *The screen* (=ores.web=): Market data, then Quotes. It calls the routes under
   =/cpp=, polls the board each second, and draws the rail, the filters, the two
   layouts and the All quotes panel with its chart, as the prototype does.
4. *Tests.* The board: a quote replaces the previous one of its datum and feed,
   the sequence orders reads, the cap holds, a subject it cannot read is ignored.
   The routes: a caller sees only the feeds its answer holds, the system answer
   sees all, /after/ returns only newer quotes, history refuses a missing series.
   The screen: its tests in the web package.
5. *The fleet.* Check with a party and with the system tenant, and see the vol
   quotes of a latent surface among the quotes.

* Result

- =ores.http= holds the quote board (=quote_board=): one subscription to every feed
  subject and the latest quote of each datum on each feed, labelled once from its
  URI. Three routes read it (=quote_routes=): the feeds the caller may watch for
  display, the board's quotes of those feeds after a sequence, and one point of a
  provider's series over a span; every read asks =list_watchable_feeds= as the
  caller. The BFF answers the same three routes with the same shapes from a board
  of its own (=bff/src/quotes.ts=), labelling each quote from its URI with the
  field roles and the asset class that =describe_oresmd_schema= now states for
  each instrument type.
- The screen, Market data then Quotes, is the signed-off variant C: the source rail
  with /All vendors/, the asset class codes table as the class filter with the
  instrument type under it, every datum or by series, and the /All quotes/ panel
  with each vendor's last hour. It asks through =baseFor('quotes')=.
- Checked on the running fleet as Acme Corporation Plc: four feeds on the rail
  (bloomberg, ice, tradeweb, derived; demo in a later session), quotes of FX spot,
  IR pillars and FX option vols from Bloomberg, ICE and Tradeweb, updating in
  place, and the /All quotes/ panel of AUD/USD with Bloomberg and Demo and their
  lines. A Playwright check (=packages/harness/tests/quotes.spec.ts=) drives it
  through a Vite server whose =/api= and =/cpp= both reach =ores.http=.
- Tests: =ores.http.marketdata.tests= 44 cases (10 new); the web package 2598 tests
  (8 new); its type check and Prettier pass.
- Not checked here: the system tenant's view, which needs the super administrator's
  login.
