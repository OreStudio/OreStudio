* Result
=service_error= now has a unit of its own: the constructor and an out-of-line
destructor live in =projects/ores.service/src/messaging/service_error.cpp=, which
makes the shared library own the vtable and export the members its consumers
import. The Linux build shows the constructor (C1/C2) and destructor (D0/D1) as
defined exports, which are the symbols LNK1120 named on both Windows legs.

The projection test lost a =value_of= lambda that its case never calls, which
clang warned about on every build.

An audit of all 3,418 exported classes found four more with no translation unit:
=awaitable_body_source= and =body_source= in =ores.http.api=,
=repository_exception= in =ores.database= and =tenant_provisioning_service= in
=ores.iam.core=. They are captured rather than fixed here.
