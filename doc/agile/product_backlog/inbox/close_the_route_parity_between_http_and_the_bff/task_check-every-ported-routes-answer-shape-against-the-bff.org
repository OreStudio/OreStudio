* Plan

The shapes are recorded rather than compared live both ways: the BFF is being
retired, and a check that needs both servers cannot run once it is gone. So the
BFF is asked once, into a corpus that is committed beside the script, and the
check replays the same requests against the gateway. The BFF is not needed to
run the check.

** What a shape is

A shape states member names, nesting and types, and no value. Three facts about
the data are not facts about the answer and are dropped: a member that is null
in every row of a page (it is still that member), a member that is null in one
row and set in another (the type the other rows state is the answer's), and an
array no row filled (it states nothing about an element). A bare array where the
BFF answered an object is a difference, and so is a member the gateway leaves
out, because those are the two bugs that started this task.

** Which pairs are compared

The inventory pairs each address the BFF answered with the gateway route that
replaced it, with each parameter written the same way through the two spellings.
A pair is compared or skipped with a reason, and the reason is in the corpus:
an address that names a path parameter names no record to read, and a write
would change the data. A pair the corpus does not name fails the check, so a
route ported later is captured or excused rather than forgotten.

** The gate

The check stands beside the consumer check in the heavy phase, because it needs
the gateway up, and it fails rather than skips when the gateway does not answer:
a check that says "nothing to do" when it cannot see what it checks silently
stops checking.

** The differences it found

- =GET /api/structures= answered =["kinds":[Package,Swap]=: the page's kinds were
  written through =array_of=, which joins already-written JSON, so the answer was
  not JSON at all and no client could parse it. Fixed here.
- =GET /api/marketdata/public-rates/coverage= answers no series where the BFF
  answers 142, because the gateway reads the durable fixings table and the
  deployment holds none. That is a question about which store the coverage
  belongs to, so it is captured rather than guessed at.
- Seven differences are recorded in the exceptions file with the reason each
  stays: the operations routes' permission model, two status mappings for the
  same code, a nullable member the codec writes where the BFF omitted it, and
  two counts the gateway states that the BFF did not.

* Notes

- The corpus is captured from the BFF this environment runs, so it holds the
  shapes of the data that environment holds: a member that only appears when a
  row exists is recorded as an empty array, and the check reads that as no
  evidence either way. That is the honest limit of a shape recorded once.
- The BFF's =/api/events= never answered inside two minutes and is recorded as
  failed rather than skipped. Whatever it streams, the gateway answers a closed
  connection, and neither is compared.
- The check compares a *session's* view, signed in as the seeded tenant
  administrator, which is the account the harness and every other script use.
  A route that needs an installation-wide grant is compared as that account
  sees it, which is why the operations routes' answers differ.

* Result

The gate now compares every paired route's answer with the shape the BFF gave.
It covers 309 pairs: 109 are replayed against the gateway and compared, and the
rest are recorded as skipped with their reason, so no pair is unaccounted for
and a route ported later must be captured or excused. The BFF's shapes are
recorded once into a corpus beside the script, and the check needs only the
gateway, which is why it can run after the BFF is gone.

It found a route whose answer was not JSON at all: the structures page wrote its
kinds through a helper that joins already-written JSON, so =Package= and =Swap=
went out unquoted. That is fixed here. It also found that the public rates
coverage answers no series where the BFF answered 142, because the gateway reads
the durable fixings table and this deployment holds none; that is captured, not
guessed at. Seven further differences are recorded with the reason each stays:
the operations routes' permission model, two status mappings for one code, a
nullable member where the BFF omitted it, and two counts the gateway adds.

What is proved: the shapes and the comparison, by 12 cases; the sweep itself,
against the running fleet, twice — once as the pair count and once as the empty
report after the exceptions were recorded. What is not: the 200 skipped pairs,
which name a path parameter or write, and the BFF's =/api/events=, which never
answered.

** See also

-* The other half: the parameters a screen sends

A route also differs from the BFF in the query it takes. ores.http refuses a
parameter a read does not declare, which tells a person their query did nothing,
while the BFF ignored it. That is the better rule, and it breaks a screen whose
call states a parameter the port did not declare: a series' observations refused
the as_of a chosen day states, a report's runs refused a search, and each looked
like a fault in the screen. The sweep therefore compares both: the members an
answer states, and the parameters a route takes, against what the screens send.
