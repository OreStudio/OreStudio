* Acceptance

- The write control for the note is withheld from every role but the super administrator.
- The page shows loading, empty, error and refused states in words, and its page and filters live in the address.

* Plan

Two BFF routes and one page.

- =GET /api/operations/grid/app-versions/:id= reads the version, its app's name, its
  packages joined to their platforms, and the versions of its app, newest first. It
  states =may_write=, true for an operator in system administration.
- =PUT /api/operations/grid/app-versions/:id/release-note= writes the note through the
  generated put, with the version the editor read and the change reason
  =common.non_material_update=. Any role but the operator is refused before a call
  goes out. A stale version is refused as a conflict.
- =GridAppVersionPage.tsx= draws the build, the note (a line that starts with "## "
  is a heading and a line that starts with "- " is an item), the packages with a
  warning when there are none, and the other versions. The job page's release panel
  now states the engine and wrapper version.

* Notes

- The generated read has no filter by app, so the page reads the catalogue's versions
  and keeps those of the app. A catalogue holds a handful per app.
- A change needs a seeded change reason. =common.correction= is not one, and the first
  write failed on it. The note edit uses =common.non_material_update=.
- =compute publish-package= states Min RAM MB as 0 when it republishes, so a version
  seeded with 512 shows 0 after a republish. This is older than the task.
- A tenant administrator reads the system tenant's versions, because the model makes
  them visible to every tenant, and cannot write them.
