* Plan

Three units, each a state a reviewer can check on its own.

** Unit 1 — the journey and provisioning architecture, and the TypeScript standard

This is the unit that unblocks the story. It carries the standard because
the story writes TypeScript from its first task onward, and a convention
recorded after the code it governs is a convention nobody followed.

1. *Write the [[id:CDE625E2-96AE-4644-9921-282339925F3E][TypeScript Clean
   Standard]].* The
   [[id:7B477025-132E-4B20-80B4-D8C9420880B8][Component Clean Standard]] governs
   C++ only, and =ores.web= now has an interface to build. The standard
   is the sibling checklist for the TypeScript in the tree: the full
   strictness set, no unchecked escape hatch, parse at the boundary,
   exhaustive unions, one-way dependencies, no floating promise, and one
   gate per item. Every item names the check that proves it, and the
   items whose check does not exist yet say so, because the gap is the
   work. Its first audit is recorded in the standard itself. Point the
   [[id:7B477025-132E-4B20-80B4-D8C9420880B8][Component Clean Standard]]
   at it in the same change, so that the reader of either finds the
   other; the two standards answer the same question for different
   languages.
2. [[id:DDCB8562-405D-4D16-8C82-0144CBAB3612][Decide the bootstrap workflow
   catalogue]]: mark item 5, the journey entity, and item 6, the shell
   journey commands, as superseded, with a pointer to the decision that
   supersedes them. Items 1 to 4 and 7 stand.
3. [[id:D602E114-F896-42CA-893A-841AD6FC3221][User Journeys]] and
   [[id:CA94C762-B0C8-40E7-85CE-D4C6355023CC][Document type: user_journey]]: the
   list, detail and history primitives were deleted by =e47043269f= and
   do not exist. Say what replaces them.
4. The three setup journeys: re-measure every =* Operations and

* Result

The task is documentation only and it is done, in three commits. The story's
"waiting on" sentence is discharged: every page the first implementation task
reads is now true against the tree.

Unit 1 corrected the journey and provisioning architecture. The sprint 25
catalogue's journey entity and shell journey commands are superseded, with a
pointer to the decision that supersedes them. The deleted list, detail and
history primitives are marked gone from the three pages that still claimed
them. The IAM page states the seed profile contract and drops the retired
desktop client from the client list. The plans doc marks the login-triggered
wizards superseded. The three setup journeys are re-measured row by row: the
retired get-active candidate is gone, the generic =iam.v1.tenants.provision=
replaces both retired provision subjects, the two progress reads exist and are
subscribed, =iam.v1.system.reset-tenant= discards a half-provisioned tenant,
and the party journey's provision-party request exists but does not match the
journey.

Unit 2 corrected the ores.web pages that anchor the wire types: the decision
record no longer denies the generator, its output location and its operation
model are right, the component overview loses two dependencies the component
does not have, and the README names commands that exist.

Unit 3 corrected the pages whose subject is the removed desktop client: the UX
language describes the journey screen, the two icon pages match the 68 assets
that exist, Entity Addressing stops contradicting itself, the history diff
architecture keeps its server half and marks its client half historical, and
the sign-up journey names the route that exists.

Four defects the work found are filed as captures rather than fixed here,
because each is a code change in another component or in the implementation
that follows. The shell recipes for the two retired subjects are deliberately
not edited: they are generated, and they change in the task that removes the
subjects.
