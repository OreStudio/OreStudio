* What

external/ore/tools/update_ore_samples.sh computes the tree_sha256 of a vendored
directory by passing the paths through sort before hashing them. sort follows the
locale, so the digest in external/ore/xsd/manifest.json is the en_GB order of the
paths, and the same files give another digest under the C locale.

* Why

The digest is meant to be reproducible from a re-sync of the same commit, and
the ORE file seed check relies on it to prove the vendored schemas were not
edited. The check reproduces it by calling sort the same way, which holds only on
a machine with the same collation. Ordering the paths by bytes, with LC_ALL=C in
the script, makes the digest the same everywhere; the manifests then need
regenerating once.
