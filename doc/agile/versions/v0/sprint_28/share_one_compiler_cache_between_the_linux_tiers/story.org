#+title: Story: Share one compiler cache between the Linux tiers
#+description: The continuous and nightly Linux jobs compile the same variants with the same settings: both pass code_coverage=1 on the two debug variants and neither passes anything extra on release, and the differences between the two workflows cannot change a compile line. The memory check adds valgrind to the test step, the build group only names the CDash track, and the package flag only picks between the all and package build targets. The cache keys were scoped per workflow when the flags did differ, and that now stores the same objects twice: the same four Linux variants cost up to eight entries, and the 10 GB cap pays for the duplicates instead of for the gcc variants. Remove the workflow scope so both tiers restore and replace one entry per variant.

* Decisions

- *The scope was added for a difference that no longer exists.* The two tiers
  were scoped apart because the Nightly debug builds passed =code_coverage= and
  the Continuous ones did not, so a shared entry held objects the other could
  not use. Continuous now passes coverage on debug too, so the difference is
  gone and the two compile the same variant identically.
- *Only =code_coverage= can move a compile line, and it now matches.* The
  remaining differences between the tiers are the CDash =build_group=, which
  names a track; =with_memcheck=, which sets up valgrind for the test step and
  appears nowhere in the build; and =package=, which chooses between the =all=
  and =package= build targets and so compiles the same objects. =code_coverage=
  is on for debug and absent for release in both workflows.
- *Pruning to this run's key is still right when the prefix is shared.* Both
  tiers prune the same prefix, so whichever runs last leaves the newest entry
  and the other tier's entry is replaced rather than lost. One entry per variant
  is the goal, not one per variant per tier.
- *The legacy entries become the live cache again.* Reverting the prefix makes
  =sccache-linux-clang-debug-ninja-38745724092= and its release sibling match
  the primary restore key, so they are used once more and then replaced by the
  first save that lands. That is why nothing had to be deleted to free space.
