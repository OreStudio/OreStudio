The ORE-level run settings that risk report definitions of a party share: the base currency, the market data of the run and the folders and log file of the package. The engine settings are not here. They are a named configuration of their own, =engine_settings=, that the definition binds in its own slot. A report definition binds this configuration through report_configurations, in the slot of configuration type risk_report_config, as it binds its pricing engines. The analytics it runs, and their parameters, are rows of configuration_analytic and configuration_analytic_parameter. Portfolio and book scope live in separate temporal junction tables keyed by this row.

#+begin_src cpp :name body :implements F2EB1914-5E94-42CA-9C77-46BDB364BF9E
std::optional<domain::risk_report_config>
risk_report_config_repository::find_by_definition_id(context ctx,
                                                     const std::string& definition_id) {

    BOOST_LOG_SEV(lg(), debug) << "Finding risk_report_config by definition_id: " << definition_id;

    static constexpr auto max = db_timestamp::max();
    const auto tid = ctx.tenant_id().to_string();
    const auto bound =
        query_builder::read<std::vector<binding_entity>> |
        query_builder::where("tenant_id"_c == tid && "report_definition_id"_c == definition_id &&
              "configuration_type_code"_c == std::string("risk_report_config") &&
              "valid_to"_c == max);

    const auto bindings = query_builder::execute_read_query<binding_entity, binding_entity>(
        ctx,
        bound,
        [](const auto& entities) { return entities; },
        lg(),
        "Finding the risk report config binding");
    if (bindings.empty())
        return std::nullopt;

    const auto query = query_builder::read<std::vector<risk_report_config_entity>> |
                       query_builder::where("tenant_id"_c == tid &&
                             "configuration_id"_c == bindings.front().configuration_id &&
                             "valid_to"_c == max);

    auto results = query_builder::execute_read_query<risk_report_config_entity, domain::risk_report_config>(
        ctx,
        query,
        [](const auto& entities) { return risk_report_config_mapper::map(entities); },
        lg(),
        "Finding risk_report_config by definition_id");

    if (results.empty())
        return std::nullopt;
    return results.front();
}

* Physical space

The messaging, eventing and history surface is deliberately not generated
yet. Nothing writes a risk report config today: the only consumer is
=report_execution_handler=, which reads one through
=find_by_definition_id= and never saves. Generating the surface would add a
NATS handler, a sub-registrar, a history provider registrar, an event
registrar and a service that no composition point calls.

=ores.reporting/core/src/messaging/registrar.cpp= is a hand-written fan-out,
not a per-entity registrar aggregator, so a generated registrar has nowhere
to join. It builds each =*_handler= directly. Its siblings
=report_definition=, =report_instance=, =report_type= and
=concurrency_policy= already carry two orphaned families on main: the four
=*_registrar= classes and the four =*_history_provider_registrar= classes.
Nothing calls either family. The measurement and the repair are their own
task; this model does not add a fifth orphan.

The =*_event_registrar= family is composed, so it is not part of the finding.
=ores.reporting/service/src/app/application.cpp= calls all four
=register_*_event_mapping= functions.

The data layer — domain, generator, entity, mapper, repository — plus the
SQL schema is generated.
