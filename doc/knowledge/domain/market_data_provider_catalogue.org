#+title: Every source belongs to a provider in the catalogue

* Summary

A provider is a vendor, an exchange, a broker or a reference set, and it owns
a namespace of ids. The catalogue holds the providers, their sources, their
vendor instruments and their mappings. It lives in =ores.marketdata=. The
system tenant owns it, and every tenant can read it.

* Detail

** The provider row

| Column | Meaning |
|--------+---------|
| =code= | The provider code in lower case, such as =bloomberg=, =lseg=, =ice=, =ore= or =demo= |
| =name= | The provider as a person knows it |
| =kind= | =data_vendor=, =exchange=, =broker= or =reference= |
| =description= | What the provider supplies |
| =display_order= | The order screens list providers in |

The name carries no mark of any source kind. Bloomberg is Bloomberg whether the
source is live or simulated. The kind is a property of the source. See
[[id:C6D75337-0EA6-40F0-8E8B-52737558851D][The source kind]].

** What else the catalogue holds

- Sources of each provider. See [[id:C6D75337-0EA6-40F0-8E8B-52737558851D][The source kind]].
- Vendor instruments of each provider. See [[id:5297997A-5175-43E9-861B-2A11D003CD35][A vendor instrument is an id scheme, an id and a field]].
- Mappings from vendor instruments to internal items. See [[id:BAE0F052-CCA6-43FB-A139-03518CE2D929][The mapping belongs to the provider and not to the source]].
- Rate cards of the sources. See [[id:1B8A3DB7-006A-4E14-AC11-57FA3741222D][A rate card on the source turns usage into a bill the platform shares]].

** Who owns it and who reads it

The system tenant and the system party own all catalogue rows. Row-level
security lets every tenant read them, and only the system tenant writes them.
A party therefore sees every provider and source and can look up what each
source is.

** How it is installed

The system bundle installs the catalogue. See [[id:922C155B-6733-4D2B-A675-A7361A5BDC63][A system bundle installs the catalogue and the simulator installs its own universe]].

** Two views of one provider

A provider can have many sources at once. Bloomberg can have =bloomberg-a=
and =bloomberg-b=. A source name says the provider and the instance, and never the kind. A party subscribes to the provider and the route picks the
source. See [[id:31BCA3F8-31AD-49C2-9B6B-F2312EE7DECB][A party takes a provider's feeds through a subscription]] and [[id:37B27CA8-9F44-4A61-9B02-3EAABD8C3818][A party routes to exactly one source for each provider]].
