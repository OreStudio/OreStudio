* Goal

So far the exported ACME run configurations validate against the ORE schemas, and nothing has run them. A document can validate and still fail in the engine, for example for a missing output name, a missing market data key or an analytic that needs a file the package lacks. Run the exported package of one report for each kind of analytic through the engine, and record what fails. Market data comes from the feeds and trades are out of scope, so the first runs may use the sample data of the ORE examples.

* Acceptance

- An exported package for each analytic kind in use (portfolio details, npv, cashflow, curves, credit curves, calibration, sensitivity, exposure simulation, XVA, SA-CCR) runs in the engine, or the failure is recorded with its cause.
- Each failure is traced to the configuration, the export or the missing data, and a task or a fix follows.
- The check is repeatable by a command, so that a change to the configuration is run again.

* Plan

1. Find how the compute grid runs ORE and whether an engine binary is available to a developer.
2. Run the exported package of the simplest analytics first: portfolio details, npv and curves, against the sample data of the ORE examples.
3. Add the analytics one at a time, and record each failure with its cause: configuration, export or missing data.
4. Turn the runs into one command that can be repeated after a change.
