* Goal

Two things, in order:

1. Wire the existing, currently-unused =cpp_nats_changed_event=,
   =cpp_nats_event_registrar.hpp/cpp= templates into the codegen
   generator, behind a per-entity opt-in flag, so an entity's
   changed-event struct and event-registrar wiring can be generated
   instead of hand-crafted (as they are today even for
   =business_unit=, despite the templates already existing).
2. Add a new test facet that generates the "write entity, observe its
   NATS entity-changed notification" integration test proven by hand
   in =business_unit_eventing_integration_tests.cpp=, so every
   eventing-enabled entity gets this regression coverage for free.

* Acceptance

- A new per-entity model flag (e.g. =has_nats_eventing=) controls
  whether the changed-event/event-registrar files are generated for
  that entity; default false, so no currently-hand-crafted entity's
  files are touched by turning this on.
- Generating with the flag on for a *fresh* entity (no hand-crafted
  eventing files yet) produces a compiling, working
  changed_event.hpp + event_registrar.hpp/cpp, wired into the
  component's central =event_registrar.cpp= the same way
  =business_unit='s hand-crafted version is today.
- Proven end-to-end against a real trading entity that currently has
  zero eventing wiring (e.g. =fx_variance_swap_instrument=) — not
  against =business_unit=, whose hand-crafted files must not be
  clobbered/diverged-from silently.
- The new integration-test facet generates a Catch2 test file
  matching the shape of
  =business_unit_eventing_integration_tests.cpp=, parameterised per
  entity (repository include, generator include, party-scoping
  helper reuse, entity_singular/plural, primary-key id-list field),
  wired into the component's tests =component_files.cmake=.
- =regenerate_cmake_component_files.py= picks up the new generated
  test file with no manual CMakeLists edits beyond the one-time
  eventing-lib link additions already done for
  =ores.refdata.core.tests=.
- Second regen pass on every touched entity produces zero further
  diff (standard codegen drift check).
- Full build + affected ctest suites green before PR.
