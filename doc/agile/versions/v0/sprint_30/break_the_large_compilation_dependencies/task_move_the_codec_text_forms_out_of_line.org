* Goal

The codec chain parses the inline text forms in every translation unit that encodes or decodes a protocol message. This task moves those definitions into a .cpp and declares them, so a consumer parses the declarations and not the forms, and protocol_codec.hpp and json_codec.hpp stop reaching text_form.hpp.

* Plan

=codec/text_form.hpp= costs 4.99 s and sits under 715 objects. Most of
that is not the forms themselves: the header defines eight concrete
specialisations inline, and each definition needs a header the
declaration does not.

| Include | Cost | Needed by |
|---------+------+-----------|
| =decimal.hpp= | 4.03 s | the decimal form's body, and nothing else in the header |
| =boost/asio/ip/address.hpp= | 2.81 s | =make_address=, in the address form's body |
| =boost/lexical_cast.hpp= | 1.94 s | the uuid form's body |
| =<filesystem>= | 1.94 s | the path form names =std::filesystem::path= |
| =<format>= | 1.49 s | the date form's body |
| =datetime.hpp= | | the date and instant forms' bodies |
| =magic_enum/magic_enum.hpp= | 0.77 s | the enumerator form |
| =boost/uuid/uuid_io.hpp= | | =to_string=, in the uuid form's body |

A specialisation of =text_form= is a class, so its members can be
declared here and defined in a =.cpp=. Only the concrete forms can move:
the enumerator form is a partial specialisation over any enumerated type, so
it stays in the header with =magic_enum=, and it is where the codec's
instantiation is.

* The move

The eight concrete forms — string, path, tenant id, date, decimal, address,
instant and uuid — keep their =wire_name= and their declarations here, and
their bodies move to =src/codec/text_form.cpp=. The header forward-declares
the four types whose definitions it no longer needs to name them in a
declaration: =ores::utility::decimal::decimal=,
=ores::utility::uuid::tenant_id=, =boost::uuids::uuid= and
=boost::asio::ip::address=. A declaration may name an incomplete type in a
parameter and return, and the caller always has the definition because it
built the value.

=<filesystem>= stays: =std::filesystem::path= cannot be forward-declared
portably. =<chrono>= stays, because both chrono forms take a type
=<chrono>= already completes.

* The cost, stated

A call to a text form is now a call across a translation unit instead of an
inline expansion, on the path a JSON or MessagePack message takes for every
value that travels as text. The call is a few nanoseconds against the
serialise and the round trip around it, and it buys the parse time back for
every object that encodes a message without touching a decimal.

* How it is verified

=evidence/header_cost.py headers= measures the cost of a header by compiling
a translation unit that includes only it, with the build's own flags. The
before and after numbers come from that instrument on the same tree, using
a copy of the old header beside the new one so neither measurement depends
on the other. The reach numbers, which are what the rebuild side cares
about, come from =evidence/header_blast_radius.py=.

* Notes

The analysis said to move the forms out of line and that this would drop the
header's cost. It was right about the mechanism and silent about the price,
which turned out to be three builds:

1. The first build failed in 119 places because 540 generated event headers
   call =boost::lexical_cast<boost::uuids::uuid>= and were taking the uuid's
   stream operators from =text_form.hpp= through the codec header. The
   archetype had never named them. Fixed in the archetype and regenerated.
2. The second failed on =compute_telemetry_handler.hpp=, which uses
   =ores::platform::time::datetime= through two =using= declarations and no
   include. Five other hand-written files were borrowing =datetime=,
   =uuid_io=, =lexical_cast=, =<format>= or =<filesystem>= the same way.
3. The third failed at the link: the forms were out of line in a library built
   with hidden visibility and nothing exported them. Each specialisation now
   carries =ORES_UTILITY_EXPORT=.

Each failure was a place where a header used something it never included, and
the chain it borrowed from is the chain this task cut. The same debt exists
wherever a header includes a definition it only names, which is what the
forward-declaration check in this story guards against.

A fourth finding, from the third build: four operation models state a
timestamp among their message fields and their generated protocol headers
carried =std::chrono= with no =<chrono>=. Their model's =* Includes= block is
where that belongs, so the four models name it and the headers are
regenerated.

* What it costs at run time

A text conversion is now a call across a translation unit instead of an inline
expansion, on the path every JSON and MessagePack message takes. No benchmark
was run: the call is a few nanoseconds against the parse and the round trip
around it, and the alternative was 4.95 s of parse per object across 648
objects.

* What is left

=json_codec.hpp= costs 12.76 s and is the largest header in the codec chain;
it includes yyjson, the text forms and the wire fields. Nothing in this task
touched it, and it is the next candidate if the chain is measured again.

* Result

The eight concrete text forms are declared in =text_form.hpp= and defined in
=src/codec/text_form.cpp=, each carrying the library's export macro. The header
forward-declares the decimal and the address, keeps a uuid and a tenant id
complete, and keeps the enumerator form with =magic_enum= because a template
cannot move.

=text_form_fwd.hpp= carries the primary template declaration and
=protocol_codec.hpp= takes it, so the envelope's three specialisations no longer
drag the general form behind them.

On the built tree =text_form.hpp= falls from 7.29 s to 2.22 s and
=protocol_codec.hpp= from 4.13 s to 0.70 s; =text_form.hpp= reaches 648 objects
instead of 792 and =decimal.hpp= 499 instead of 811, so 312 objects stopped
parsing the decimal chain. About 7650 object-seconds, roughly two hours of
compile CPU for a full build.

Three things had to be fixed to get there, all of them transitive includes the
cut exposed: 540 generated event headers now name the uuid's stream operators,
four operation models name =<chrono>=, and the forms are exported from the
library.
